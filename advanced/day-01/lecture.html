2. ECMAScript, TC39 и редакции

Страница MDN JavaScript technologies overview напоминает: «JavaScript» в браузере — это ядро языка, ECMAScript, и Web API: DOM, события, таймеры. Схему «ядро и окружение» мы видели на дне 1 Essentials; теперь у ядра появляется документ.

Ядро стандартизирует комитет TC39 организации Ecma International. Документ называется ECMA-262. По MDN, в него входят:

  • синтаксис: правила разбора, ключевые слова, управление потоком, литералы объектов;
  • обработка ошибок: throw, try...catch, свои виды Error;
  • типы и прототипное наследование;
  • встроенные объекты: JSON, Math, методы массивов, parseInt;
  • строгий режим, система модулей и базовая модель памяти.

Рядом живёт второй документ того же комитета — ECMA-402, интернационализация: сравнение строк, форматы чисел и дат. Его разделы мы читали на дне 25 курса 2, а целиком он займёт модуль A7.

Редакции и предложения

Новая редакция выходит раз в год. До шестой их называли по номерам — ES3, ES5, потом по году: ES6 и ES2015 — одно и то же. Курс ссылается на редакцию 2026 года, tc39.es/ecma262/2026/, а не на живой текст tc39.es/ecma262/, который правят постоянно: ссылки урока не должны уезжать.

Новое приходит через предложения с четырьмя стадиями; движки обычно реализуют их на третьей или четвёртой. Поэтому Chrome 156 знает Temporal из курса 2 и объявление using из дня 25, а в тексте ECMA-262 2026 года их нет. Предложение — ещё не стандарт, даже если браузер его умеет.

Сомневаетесь, стандарт ли это, — найдите раздел. Нет его в ECMA-262 2026 — значит, это предложение, расширение браузера или Web API; MDN помечает такие страницы плашками «Experimental» и «Non-standard».

4. Что реализация обязана и что может

Глава 2 — договор между стандартом и движком. Перескажем её по пунктам.

  • Обязана поддерживать всё, что описано в стандарте, и читать исходный текст по последней версии Unicode.
  • Если даёт средства для разных языков и стран, обязана делать их по ECMA-402.
  • Может добавлять свои типы, объекты и свойства, в том числе к стандартным объектам, и даже свой синтаксис.
  • Не может делать то, что перечислено в разделе 17.1 как запрещённые расширения, и не может переопределять то, что стандарт не отдал ей сам.

Пункт «может добавлять» мы встречали: Error.captureStackTrace и Error.stackTraceLimit из дня 26 курса 2 — законные расширения V8.

Что Chrome что-то умеет, ещё не значит, что это язык: расширение одного браузера в другом может не работать.

5. Хозяин и реализация

Обзор главы 4 начинается с важной фразы: в стандарте нет средств ни для ввода данных, ни для вывода результатов. Ввод и вывод даёт окружение, в котором работает программа. Проверим поиском по тексту редакции 2026 года: слов console, setTimeout и alert в нём нет ни разу. Раздел 4.1 перечисляет, что даёт браузер: окна, диалоги, историю, куки, события страницы.

Раздел 4.2 различает, кому стандарт что поручает. Слова пригодятся на весь курс:

6. Язык в обзоре: объекты и строгий вариант

Раздел 4.3 — неформальный обзор, стандартом не считается. Язык построен на объектах; объект — набор свойств с атрибутами вроде «можно ли записать» (день 5 курса 2). Синтаксис похож на Java, но свободнее: тип переменной не объявляют, функцию можно вызвать раньше, чем она написана.

Раздел 4.3.1 подчёркивает: объекты ECMAScript не основаны на классах, как в C++ или Java. В нём есть рисунок: конструктор CF, его прототип CFp и пять объектов cf1…cf5. У каждого объекта свои свойства q1 и q2, а свойство CFP1 прототипа общее для всех пятерых. Свойства самого конструктора, P1 и P2, объектам не видны. Перепишем рисунок кодом:

function CF(q1, q2) {
  this.q1 = q1;
  this.q2 = q2;
}
CF.prototype.CFP1 = "общее";            // свойство прототипа CFp
CF.P1 = "у конструктора";               // свойство самого CF

const cf1 = new CF(1, 2);
console.log(cf1.q1, cf1.CFP1, Object.hasOwn(cf1, "CFP1"), cf1.P1);
1 общее false undefined

Это цепочка прототипов дня 7 курса 2. Раздел добавляет, что class (с ES2015) — короткая запись того же образца.

Раздел 4.3.2 — строгий вариант языка. Его выбирают для отдельной единицы текста — скрипта, модуля, функции, — поэтому ограничения местные: строгий файл не меняет соседний. Точные правила — раздел 11.2.2, завтра; список ограничений — приложение C, день 3 курса 2.

8. Как устроен раздел и как его найти

Номер раздела удобен для разговора, но в следующей редакции может сдвинуться. Надёжнее якорь — часть адреса после #: #sec-array.prototype.includes. Редакция 2026 года — одна большая страница (в нашей копии — 7,5 МБ), так что работает и обычный поиск по странице.

Раздел абстрактной операции начинается с подписи и шапки. Вот как выглядит 7.1.5 ToIntegerOrInfinity в пересказе:

  • Подпись: ToIntegerOrInfinity ( argument ) — имя и параметры. Необязательные параметры пишутся в квадратных скобках: [ , fromIndex ].
  • Шапка: принимает значение языка и возвращает либо обычное завершение с целым числом или бесконечностью, либо завершение-бросок. По шапке сразу видно, может ли операция бросить ошибку.
  • Шаги: пронумерованный список. У этой операции их пять: превратить в число, NaN и нули дать как 0, бесконечности оставить, остальное — отбросить дробную часть.
  • Примечания (Note) — пояснения, которые стандартом не считаются; рамки Normative Optional и Legacy — из раздела 4.

Найти раздел помогает таблица «Specifications» внизу страниц MDN (с дня 1 курса 2); вопрос о синтаксисе — главы 13–16 оглавления. Дальше — от имени к имени: каждое имя операции в тексте — ссылка на её определение.

9. Шаги алгоритма

Раздел 5.2 объясняет, как читать шаги. Алгоритмы описывают, что должно получиться, а не как это сделать: движок может считать по-своему, лишь бы результат совпадал.

В спецификацииЧто значитПохоже в JavaScript
1. … a. … i. …шаги и подшаги; уровни: цифры, буквы, римские цифрывложенные блоки
Let x be …завести имя для значенияlet x = …

Две тонкости. Let x be y не копирует, а даёт второе имя тому же, как const b = a для объекта; копию стандарт называет прямо: «Let x be a copy of y». А Assert — подсказка читателю, требований не добавляет, и движок вправе её не проверять.

Попробуем записать в этом стиле свою функцию — average из дня 14 Essentials, средний балл:

  1. Let count be the number of elements of marks.
  2. If count = 0, return 0.
  3. Let sum be 0.
  4. For each element mark of marks, do
    1. Set sum to sum + mark.
  5. Return sum / count.

Шаг 2 — ранний выход: при пустом списке до деления дело не доходит. В Essentials он был записан тернарным оператором numbers.length === 0 ? 0 : …. Такие ранние выходы встретятся в разделе 13, и от их места зависит, вызовется ли код соседних шагов.

10. Порядок вычисления

Раздел 5.2.1 — маленький, но важный. Сложное выражение в шаге читается слева направо и изнутри наружу. Шаг «Return A(B(), C.[[D]]) + E(F())» означает шесть шагов подряд: вычислить B(), потом взять C.[[D]], вызвать A, потом F(), потом E, и только в конце сложить. Это правило записи алгоритмов, но сам язык ведёт себя так же: операнды вычисляются слева направо, что бы ни говорил приоритет операторов.

const show = (n) => {
  console.log("вычислили", n);
  return n;
};
console.log(show(1) + show(2) * show(3));
вычислили 1
вычислили 2
вычислили 3
7

Приоритет решил, что 2 умножается на 3, но операнды вычислены по порядку записи: приоритет говорит, что с чем соединить, а не что считать раньше. Подробно — день 10.

11. Операции и ранние ошибки

В шагах встречаются два рода операций.

Абстрактные операции (раздел 5.2.2) — именованные алгоритмы с параметрами: ToNumber(x), IsLessThan(x, y, LeftFirst); их вызывают из других алгоритмов, как функции. Запись O.[[Get]](P) — операция-метод, внутренний метод объекта (день 14).

Операции по грамматике — syntax-directed operations, раздел 5.2.3, — это отдельный алгоритм для каждого правила грамматики. «Return Evaluation of Block» значит: вычислить блок по правилу, которым он записан. Главная такая операция — Evaluation (день 8).

Раздел 5.2.4 называет алгоритмы, которые работают во время выполнения, семантикой выполнения. Раздел 5.2.5 — статическая семантика: правила, которые не выразить грамматикой. Среди них есть особые — правила ранних ошибок. Их реализация обязана проверить до первого вычисления скрипта или модуля. Нарушено хоть одно — не выполняется ни одна строка:

console.log("начало");
let mark = 4;
let mark = 5;
// Uncaught SyntaxError: Identifier 'mark' has already been declared

«начало» так и не напечатано: ошибка найдена до выполнения. Повтор let запрещает правило ранней ошибки, а не шаг выполнения. Другой <script> той же страницы при этом работает: единица проверки — один скрипт.

12. Completion Record: знаки ? и !

Как алгоритм сообщает об ошибке? Не исключением, а значением. Каждая операция, которая может закончиться необычно, возвращает Completion Record — запись с полями [[Type]], [[Value]] и [[Target]]. Тип — один из пяти: normal, break, continue, return, throw. Все, кроме normal, называются внезапными (abrupt). Подробно запись разберём на дне 4, сегодня — как она читается в шагах (раздел 5.2.4 и его подразделы).

  • «Throw a TypeError exception» — вернуть запись throw с новым TypeError.
  • Return true — вернуть запись normal со значением true: обёртку стандарт ставит сам.
  • ? Операция() — развернуть запись: если она внезапная, немедленно вернуть её тому, кто вызвал нас; если обычная — взять [[Value]] и идти дальше.
  • ! Операция() — утверждение, что запись обычная, и взять её значение. Знак ! ставят там, где ошибки быть не может.

Смоделируем знак ? на JavaScript: пусть функции возвращают записи, а не бросают исключения.

const normal = (value) => ({ type: "normal", value });
const thrown = (value) => ({ type: "throw", value });

function toNumberRecord(x) {                           // как ToNumber: у символа — ошибка
  if (typeof x === "symbol") return thrown(new TypeError("Cannot convert a Symbol value to a number"));
  return normal(Number(x));
}

function doubleRecord(x) {                             // шаг «Let n be ? ToNumber(x).»
  const record = toNumberRecord(x);
  if (record.type !== "normal") return record;         // ? — внезапную запись вернуть как есть
  const n = record.value;                              // ? — у обычной взять [[Value]]
  return normal(n * 2);
}

console.log(doubleRecord("21"));
console.log(doubleRecord(Symbol("id")).type);
{type: 'normal', value: 42}
throw

Три строки на каждый ? — поэтому стандарт и придумал знак. В настоящем JavaScript запись throw, которую каждый ? отдаёт выше, вы видите как исключение, «пролетающее» сквозь вызовы до ближайшего catch.

Правило чтения: перечислите шаги со знаком ? — это все места, где алгоритм может остановиться с ошибкой. Где ? нет, ошибки этого шага до вас не дойдёт.

13. Читаем вместе: Array.prototype.includes

Возьмём метод, которым пользуемся с дня 19 Essentials и который мерили против Set на дне 15 курса 2, — 23.1.3.16 Array.prototype.includes ( searchElement [ , fromIndex ] ). Пересказ его 11 шагов:

1

Let O be ? ToObject(this). Превратить this в объект; у null и undefined — ошибка.

2

Let len be ? LengthOfArrayLike(O). Прочитать length и привести к целому.

3

If len = 0, return false. Пустой — сразу «нет».

4

Let n be ? ToIntegerOrInfinity(fromIndex); шаг 5 — Assert, что без fromIndex получится 0.

6

Шаги 6–9: n = +∞ — вернуть false; n = −∞ — начать с 0; неотрицательное n — начать с него; отрицательное — с len + n, но не меньше 0.

10

Repeat, while k < len: взять элемент ? Get(O, ! ToString(𝔽(k))); если SameValueZero с искомым — вернуть true; k увеличить на 1.

11

Return false.

Знаки уже говорят многое. Ошибка возможна в шагах 1, 2, 4 и при чтении элемента в шаге 10. А ! ToString(𝔽(k)) — превращение номера в строку-ключ: из числа строка получается всегда, поэтому !. Проверим шаги 4 и 6–9:

const nums = [1, 2, 3];
console.log(nums.includes(3, -1), nums.includes(1, -1));             // шаг 9: k = len + n
console.log(nums.includes(3, Infinity), nums.includes(1, -Infinity)); // шаги 6 и 7
console.log(nums.includes(2, "1"), nums.includes(3, 2.9));           // шаг 4: ToIntegerOrInfinity

false true
true true

Строка "1" стала числом 1, а 2.9 — числом 2: дробную часть шаг 4 отбросил. По примечанию 3, в отличие от indexOf, includes сравнивает через SameValueZero и читает через Get даже пропущенные элементы:

console.log([NaN].includes(NaN), [NaN].indexOf(NaN));             // SameValueZero против ===
console.log([, 1].includes(undefined), [, 1].indexOf(undefined)); // дырка: Get даёт undefined
true -1
true -1

Теперь шаги 1–3 и порядок. Примечание 2 говорит, что метод нарочно «общий»: this не обязан быть массивом. Объект с length и геттерами покажет, в каком порядке шаг 10 читает элементы и где он останавливается:

14. Числа и значения спецификации

Раздел 5.2.6 вводит несколько видов чисел. Математические значения — настоящие вещественные числа, без округлений; если вид не указан, имеются в виду они. Number — числа формата IEEE 754, помечаются индексом 𝔽: +0𝔽, -∞𝔽. BigInt помечаются индексом ℤ. Переходы между видами стандарт всегда пишет явно: 𝔽(x) — Number для математического значения, ℝ(x) — математическое значение числа. Шаг 10 в includes так и написан: номер k — математическое целое, перед превращением в ключ его делают Number: 𝔽(k).

Зачем столько видов? Потому что Number — не математика. Стандарт считает «как в математике», а в Number переходит явно, в одном месте. Там и появляется округление. Пример — разница между математическим «modulo» из раздела 5.2.6 и оператором % языка:

console.log(-7 % 3, 7 % -3);              // % языка: знак делимого
console.log(((-7 % 3) + 3) % 3);          // «-7 modulo 3» из 5.2.6: знак делителя
console.log(0.1 + 0.2, 0.1 + 0.2 === 0.3); // Number — не математика
-1 1
2
0.30000000000000004 false

Когда алгоритм пишет «modulo», это не %: знак результата разный, и при переносе шагов в код здесь легко ошибиться. Там же определены floor, truncate (им пользуется ToIntegerOrInfinity) и интервалы, в которых −0 меньше +0, а NaN не входит ни в какой.

Раздел 5.2.7 — обозначения значений: значения языка набраны жирным — true, "hello", — а исходный текст — моноширинным шрифтом. В наших пересказах жирное выделение означает то же самое.

Раздел 5.2.8 — тождество. У одних значений оно есть: два объекта с одинаковыми свойствами — всё равно два разных объекта. У других нет: число 5 — это просто 5, где бы оно ни встретилось. С языковой точки зрения тождество проверяет SameValue. Тонкое место — символы:

console.log(Symbol.for("cards") === Symbol.for("cards"), Symbol("cards") === Symbol("cards"));
true false

Symbol() каждый раз даёт новое значение с собственным тождеством (день 11 курса 2). А Symbol.for из реестра раздел 5.2.8 описывает отдельно: для спецификации у такого символа тождество есть, а для языка — нет. Его может получить по ключу любой код, как строку, — поэтому, например, такой символ нельзя сделать ключом WeakMap (день 14 курса 2).

15. «Карточки 2.0»: <= соседа по шагам

Вернёмся ко второму вопросу. В классе колоды соседа из дня 35 метод due отбирал карточки так:

// deck.js соседа, день 35 курса 2 — только этот метод
due(today) {
  return this.cards.filter((c) => !this.progress.has(c.id) || this.progress.get(c.id).next <= today);
}

И next, и today — Temporal.PlainDate. Повторим поломку отдельно и сравним с правильным способом из дня 22 курса 2:

const today = Temporal.PlainDate.from("2026-10-28");
const next = Temporal.PlainDate.from("2026-11-01");
try {
  console.log(next <= today);
} catch (e) {
  console.log(`${e.name}: ${e.message}`);
}
console.log(Temporal.PlainDate.compare(next, today) <= 0);
TypeError: Do not use Temporal.PlainDate.prototype.valueOf; use Temporal.PlainDate.prototype.compare for comparison.
false

Прочитаем путь ошибки по сегодняшним соглашениям. Вычисление <= — раздел 13.10.1: вычислить левый и правый операнды, затем шаг Let r be ? IsLessThan(rVal, lVal, false). Неожиданно: a <= b спрашивает «верно ли, что b < a?», и ответ переворачивает. Флаг false нужен, чтобы операнды всё равно превращались слева направо — правило раздела 10. Дальше по знакам ?:

Сначала превращается левый операнд, next. У даты нет метода Symbol.toPrimitive, поэтому ToPrimitive передаёт работу OrdinaryToPrimitive с подсказкой number, а та первым вызывает valueOf. А valueOf у дат Temporal всегда бросает TypeError, и текст ошибки сам подсказывает выход — compare. Каждый ? по дороге вверх возвращает запись throw дальше — до catch, а без него — до консоли. Порядок «сначала valueOf» виден на любом объекте:

const mark = {
  valueOf() { console.log("valueOf"); return 4; },
  toString() { console.log("toString"); return "четыре"; },
};
console.log(mark <= 5);               // подсказка number: сначала valueOf
console.log(`оценка ${mark}`);         // подсказка string: сначала toString
console.log(null <= 0, null < 0, null == 0);
valueOf
true
toString
оценка четыре
true false false

Последняя строка — следствие «переворота» из 13.10.1: null <= 0 — это «не (0 < null)», null становится нулём, и ответ — true. А == идёт по своему алгоритму из дня 6 курса 2 и даёт false.

А строки дат? У строки ToPrimitive ничего не делает, и IsLessThan сравнивает строки по 16-битным кодам. В формате «ГГГГ-ММ-ДД» это совпадает с порядком дат, но однозначный месяц — "2026-9-1" — порядок ломает (задание 9 дня 22 курса 2). Подробно — день 5.

16. Что будет завтра

Сегодня мы читали алгоритмы. Но у спецификации есть и вторая половина — грамматика: правила, по которым текст программы вообще становится программой. Завтра, на дне 2, разберём, как записаны грамматики (раздел 5.1), что такое исходный текст и виды кода (глава 11) и первые разделы лексической грамматики: пробелы, переводы строк, комментарии, имена и ключевые слова (глава 12). // implementation-defined / -approximated — реализация; host-defined — хозяин (прил. D)

// порядок: слева направо, изнутри наружу — и в языке тоже
// ? Op() — внезапную запись вернуть выше, иначе взять [[Value]]
// ! Op() — здесь ошибки не бывает
// ранние ошибки — до первой строки скрипта: не выполнится ничего

// includes: 1 ? ToObject · 2 ? LengthOfArrayLike · 3 len = 0 → false · 4 ? fromIndex
//           10 ? Get + SameValueZero — NaN находит, дырки читает как undefined
// a <= b — это «не (b < a)»: IsLessThan → ToPrimitive → valueOf первым
// Temporal: сравнивать через compare, а не <
  1. Что из этого определяет ECMA-262, а что — браузер: Array.prototype.includes, setTimeout, JSON.parse, document?
    Ответ includes и JSON.parse — стандарт, это встроенные объекты и методы. setTimeout и document — хозяин: в тексте ECMA-262 их нет, их определяет стандарт HTML.
  2. Чем implementation-defined отличается от implementation-approximated?
    Ответ В первом случае реализация решает сама, без рекомендаций, — как разбор строки «12.10.2026». Во втором стандарт называет идеал, а реализация к нему приближается, — как синус в Math.sin.
  3. Что значит знак ? перед вызовом операции в шаге алгоритма? А !?
    Ответ ?: если операция вернула внезапную запись (например, throw), немедленно вернуть её вызвавшему; иначе взять значение записи. !: запись обычная наверняка, взять значение — ошибки здесь не бывает.
  4. Почему [].includes(1, from) не вызвал valueOf у from, а [5].includes(5, from) вызвал?
    Ответ Шаг 3 (len = 0 → вернуть false) стоит раньше шага 4, где превращается fromIndex. У пустого массива алгоритм заканчивается на шаге 3.
  5. Почему next <= today с датами Temporal бросает TypeError, а со строками дат работает?
    Ответ <= вызывает IsLessThan, тот — ToPrimitive для каждого операнда. У объекта даты это OrdinaryToPrimitive с подсказкой number, которая первым вызывает valueOf, а valueOf дат Temporal бросает ошибку; каждый ? отдаёт её выше. Строки — уже примитивы: их IsLessThan сравнивает посимвольно.
