## Разминка

<Task title="1. Самый длинный кусок" level="easy" time="7">
<Goal>делить текст на токены по правилу главы 12.</Goal>

Запишите токены каждой строки списка и предскажите, какие из них синтаксическая грамматика
примет. Потом проверьте.

```js
const lines = ["a+++b", "a+++++b", "a+ ++b", "x>>>=1", "c??=5", "ready?.5:0"];
for (const line of lines) console.log(line, parse(`let a = 1, b = 2, x = 8, c, ready; ${line};`));
```

<Criteria>
- у каждой строки токены записаны до запуска, через пробел;
- для строки с ошибкой объяснено, почему лексер её разделил без жалоб, а дерево не сложилось;
- объяснено, что изменил пробел в `a+ ++b`.
</Criteria>
</Task>

<Task title="2. Пробел для языка" level="easy" time="7">
<Goal>сверять таблицы 30 и 31 с поведением Chrome.</Goal>

Предскажите четыре столбца для каждого символа: разбирается ли он в коде вместо пробела,
совпадает ли с `\s`, снимает ли его `trim` и считает ли его пробельным Unicode.

```js
const codes = [0x09, 0xA0, 0xFEFF, 0x3000, 0x2028, 0x85, 0x200B, 0x180E];
for (const code of codes) {
  const ch = String.fromCharCode(code);
  console.log(code.toString(16), parse("let" + ch + "x = 1;") === "разобрано",
    /\s/.test(ch), ch.trim() === "", /\p{White_Space}/u.test(ch));
}
```

<Criteria>
- для каждого символа названа строка таблицы 30 или 31, которая его пускает, или сказано, что его нет ни в одной;
- найдены два символа, где язык и Unicode расходятся в разные стороны, и для каждого
  процитирована строка раздела 12.2 (таблица 30 или примечание 2);
- объяснено, почему второй и третий столбцы всегда равны, и найден символ — не пробел, для
  которого первый столбец всё равно `true` (подсказка: раздел 11 лекции).
</Criteria>
</Task>

## Основные задания

<Task title="4. Где кончается токен" level="medium" time="12">

const variants = [

<Task title="5. Невидимый символ" level="medium" time="12">
<Goal>найти символы, которые глаз не видит, и решить, что с ними сделает язык.</Goal>

Код, скопированный со страницы, падает с `Invalid or unexpected token`, а ошибки не видно.
Напишите `invisible(code)`: для каждого символа из `\p{White_Space}` или
`\p{Cf}`, кроме обычного пробела и LF, — объект `{ at, code, kind }`, где
`kind` — «пробел» (таблица 30), «перевод строки» (таблица 31) или «не пробел».

<Example>
```js
const NBSP = String.fromCharCode(0xA0), NEL = String.fromCharCode(0x85), ZWJ = String.fromCharCode(0x200D);
invisible("let" + NBSP + "x = 1;");     // [{ at: 3, code: "U+00A0", kind: "пробел" }]
invisible("let x = 1;" + NEL);          // [{ at: 10, code: "U+0085", kind: "не пробел" }]
invisible("a" + ZWJ + "b;\tb");          // [{ at: 1, code: "U+200D", kind: "не пробел" }, { at: 4, code: "U+0009", kind: "пробел" }]
invisible("let x = 1;\nx;").length;     // 0
```
</Example>

<Criteria>
- кодовые точки таблиц не перечислены вручную, кроме четырёх переводов строки;
- все четыре строки примера дают то, что в комментариях;
- для каждого «не пробела» примера записано, что скажет Chrome, если символ стоит в коде, и
  найден случай, где ошибки нет, а программа всё равно другая.
</Criteria>
</Task>

<Task title="6. «Карточки 2.0»: поле через точку" level="medium" time="14">
<Goal>применить правило IdentifierName к данным проекта.</Goal>

В редакторе колод учитель сам называет поля карточки, а редактор подсказывает, как прочитать
поле в коде. Напишите `accessor(name)`: если имя поля годится после точки, —
`card.имя`, иначе — `card["имя"]` (строку соберите через
`JSON.stringify`).

<Example>
```js
accessor("word");        // "card.word"
accessor("ýyl");         // "card.ýyl"
accessor("if");          // "card.if"
accessor("aýdym-saz");   // 'card["aýdym-saz"]'
accessor("2nji");        // 'card["2nji"]'
accessor("");            // 'card[""]'
```
</Example>

<Criteria>
- все шесть строк примера дают то, что в комментариях;
- каждый ответ проверен в Chrome: `parse("const card = {}; " + accessor(n) + ";")`;
- объяснено, почему `card.if` можно, а `let if` нельзя: разница
  IdentifierName и Identifier, первые абзацы 12.7.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Свой лексер" level="hard" time="10">
<Goal>перенести правила главы 12 в код.</Goal>

Напишите `tokens(code)` для маленькой части языка: имена, числа из цифр с точкой,
знаки пунктуации из 12.8 и `/`. Пробелы, переводы строк и оба вида комментариев
пропускаются; на любом другом символе — `SyntaxError`. Строк, шаблонов и регулярок нет.

<Example>
```js
tokens("a+++b");                 // ["a", "++", "+", "b"]
tokens("x >>>= 1 /* сдвиг */");     // ["x", ">>>=", "1"]
tokens("ready?.5:0");            // ["ready", "?", ".5", ":", "0"]
tokens("card?.step ?? 1");       // ["card", "?.", "step", "??", "1"]
tokens("ýyl // год");            // ["ýyl"]
tokens("const step = this.progress.get(id)?.step ?? 1;").length;   // 16
```
</Example>

<Hint>
Знаки отсортируйте по длине, самые длинные — первыми. `?.` берите, только если
дальше не цифра. Имя — регулярка MDN из раздела 11 лекции.
</Hint>

<Criteria>
- шесть строк примера дают то, что в комментариях;
- на `"a+++++b"` лексер ошибки не бросает: записано, где тогда ошибка появится;
- символ U+0085 в тексте даёт `SyntaxError`, а U+00A0 — нет.
</Criteria>
</Task>

<Task title="9. Незнакомый раздел: пролог директив" level="hard" time="10">
<Goal>прочитать раздел, который на лекции был кратко.</Goal>

Прочитайте раздел [11.2.1
Directive Prologues and the Use Strict Directive](https://tc39.es/ecma262/2026/#sec-directive-prologues-and-the-use-strict-directive) и предскажите строку вывода: какие функции
строгие.

```js
function a() { "use strict"; return this; }
function b() { "salam"; "use strict"; return this; }
function c() { let x; "use strict"; return this; }
function d() { "use" + " strict"; return this; }
function e() { ("use strict"); return this; }
function f() { "use\x20strict"; return this; }
function g() { 'use strict'
  return this; }
console.log([a, b, c, d, e, f, g].map((fn) => fn() === undefined).join(" "));
```

<Criteria>
- семь предсказаний записаны до запуска, у каждого — фраза раздела, которая решает;
- объяснено, почему у `b` директива работает, хотя стоит второй;
- для `g` найдено в разделе, откуда берётся точка с запятой.
</Criteria>
</Task>
