2. null, true, false — и чем не являются undefined и −1

Разделы 12.9.1 и 12.9.2 — по одной строке: NullLiteral :: null и BooleanLiteral :: true false. Это зарезервированные слова, и имён из них не сделать. А вот undefined, NaN и Infinity литералами не являются — это свойства глобального объекта, то есть обычные имена:

const parse = (code) => {
  try {
    new Function(code);
    return "разобрано";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(parse("let null = 1;"), parse("let true = 1;"));
console.log((function () { let undefined = 5; return undefined; })());
console.log(parse("-2 ** 2"));
console.log((-2) ** 2);
SyntaxError: Unexpected token 'null' SyntaxError: Unexpected token 'true'
5
SyntaxError: Unary operator used immediately before exponentiation expression. Parenthesis must be used to disambiguate operator precedence
4

Помощник parse — вчерашний: new Function в try. Внутри функции имя undefined можно занять своей переменной — так никто не пишет, но язык разрешает. На верхнем уровне скрипта нельзя: у глобального объекта уже есть свойство undefined, которое нельзя перенастроить, и скрипт не начнётся:

console.log("начало");
let undefined = 5;
Uncaught SyntaxError: Identifier 'undefined' has already been declared

Вторая половина первого блока — про знак. В грамматике числового литерала минуса нет: -2 — это два токена, унарный минус и литерал 2. Поэтому -2 ** 2 — не «минус два в квадрате», а неясность, которую язык запрещает: минус к основанию или ко всему выражению? Скобки снимают вопрос.

3. Числа: формы записи

Раздел 12.9.3 перечисляет формы числового литерала. Десятичный — с дробной частью и порядком после e; три недесятичных — с приставкой; и BigInt — целое с буквой n:

console.log(0b101, 0o17, 0xFF, 0XA);
console.log(5e1, 175e-2, .5, 5., 1E3);
console.log(123n, 0x1Fn, typeof 1n);
5 15 255 10
50 1.75 0.5 5 1000
123n 31n bigint

Буквы приставок и порядка — любого регистра: 0X, 0B, 0O, E. Целую часть можно опустить (.5), дробную тоже (5.). А суффикс n по грамматике стоит только после целого: правила DecimalBigIntegerLiteral не знают ни точки, ни порядка.

В конце раздела — правило, которое объясняет старую загадку: сразу после числового литерала не может стоять начало имени или цифра. Пример стандарта — 3in: это ошибка, а не 3 и in.

const parse = (code) => {
  try {
    new Function(code);
    return "разобрано";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(parse("3in [1]"), parse("1.toString()"));
console.log(1..toString(), 1 .toString(), (1).toString());
console.log(parse("1.5n"), parse("0755n"));
SyntaxError: Invalid or unexpected token SyntaxError: Invalid or unexpected token
1 1 1
SyntaxError: Invalid or unexpected token SyntaxError: Invalid or unexpected token

В 1.toString() лексер берёт самый длинный кусок — 1., число с пустой дробной частью, — и сразу за ним видит букву t. В 1..toString() первая точка ушла в число, вторая — обращение к методу. Пробел или скобки тоже разделяют число и точку.

4. Разделитель _ и параметр [Sep]

Длинное число легче читать с разделителем: 1_000_000. В грамматике он — NumericLiteralSeparator :: _, а место ему отводит параметр [Sep] — тот самый механизм параметров из раздела 5.1.5 (день 2). Правило цифр с разделителем:

DecimalDigits[Sep] ::
    DecimalDigit
    DecimalDigits[?Sep] DecimalDigit
    [+Sep] DecimalDigits[+Sep] NumericLiteralSeparator DecimalDigit

Разделитель стоит только между двумя цифрами: слева — цифры, справа — одна цифра. Отсюда все ограничения сразу: не в начале, не в конце, не два подряд, не рядом с точкой, e и приставкой. Разрешён он и в недесятичных записях, и в порядке, и в BigInt:

console.log(1_000_000, 1_050.95, 0b1010_0001, 0xA0_B0_C0, 1e1_0, 1_000n);

5. От записи к значению

Подраздел 12.9.3.2 определяет MV (mathematical value) — точное математическое значение записи; разделители при подсчёте пропускаются. Подраздел 12.9.3.3, NumericValue, превращает его в значение языка. Для BigInt — точно. Для Number — в ближайшее 64-битное число, где после MAX_SAFE_INTEGER целые «слипаются» (день 21 курса 2): сначала RoundMVResult, которая разрешает реализации отбросить цифры после двадцатой значащей, потом 𝔽 — округление до ближайшего Number.

console.log(9007199254740993, 9007199254740993n);
console.log(0x20000000000001, 2 ** 53 + 1);
console.log(1e400, 5e-325);
9007199254740992 9007199254740993n
9007199254740992 9007199254740992
Infinity 0

Число 253 + 1 записано правильно, но такого Number нет: ближайший — 253. Ошибки при этом нет — литерал всегда что-то значит. Слишком большое становится Infinity, слишком маленькое — нулём. С BigInt такого не бывает: n на конце — и все цифры на месте.

Старая восьмеричная запись

Грамматика 12.9.3 хранит и запись первых редакций: ноль впереди. Если все остальные цифры меньше 8 — это восьмеричное число (LegacyOctalIntegerLiteral), если есть 8 или 9 — десятичное с ведущим нулём. Подраздел 12.9.3.1 делает обе формы ранней ошибкой в строгом коде — это мы видели на дне 3 курса 2:

const parse = (code) => {
  try {
    new Function(code);
    return "разобрано";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(010, 08, 0777, 0888);
console.log(parse('"use strict"; 010'));
console.log(parse('"use strict"; 08'));
8 8 511 888
SyntaxError: Octal literals are not allowed in strict mode.
SyntaxError: Decimals with leading zeros are not allowed in strict mode.

Одна и та же привычка «дописать ноль для красоты» даёт 0777 = 511 и 0888 = 888. Поэтому восьмеричное пишут явно — 0o777, — а BigInt с нулём впереди (0755n) грамматика не принимает вовсе.

6. Строки: что можно написать прямо

Раздел 12.9.4, примечание 1: в строке прямо можно написать любую кодовую точку, кроме закрывающей кавычки, обратной косой черты \, CR и LF. Любую — значит и неразрывный пробел, и LS с PS. Вчера мы видели, что LS — перевод строки, но правило строки впускает его отдельной строкой грамматики (<LS>, <PS>), а LF и CR — нет:

const parse = (code) => {
  try {
    new Function(code);
    return "разобрано";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const LS = String.fromCharCode(0x2028), LF = String.fromCharCode(10);
console.log(parse('"a' + LF + 'b"'));
console.log(parse('"a' + LS + 'b"'), new Function('return "a' + LS + 'b"')().length);
console.log("a\
b");
SyntaxError: Invalid or unexpected token
разобрано 3
ab

Последняя строка — продолжение строки (LineContinuation): обратная косая и сразу перевод строки. В значение не попадает ни то ни другое — получилось «ab». Пробел после \ всё ломает: это уже escape пробела, а за ним — запрещённый LF. Примечание 2 раздела советует: нужен перевод строки в значении — пишите \n.

Значение строки — UTF-16, как на дне 20 курса 2: кодовая точка из основной плоскости — один элемент, остальные — два.

8. Регулярное выражение: лексер ищет конец

Раздел 12.9.5 говорит прямо: правила литерала регулярки нужны лексеру, чтобы найти её конец. Тело — до косой черты, которая не экранирована и не стоит внутри класса […]; флаги — символы имени. Что внутри, проверит потом отдельная, строгая грамматика регулярок (22.2.1, день 17 курса 2).

const parse = (code) => {
  try {
    new Function(code);
    return "разобрано";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(/[/]/.test("/"), /a\/b/.test("a/b"));
const vowels = () => /[aeiou]/g;
console.log(vowels() === vowels(), /a/ === /a/);
console.log(parse("/a/xyz"), String(new RegExp("")));
true true
false false
SyntaxError: Invalid regular expression flags /(?:)/

Каждое вычисление литерала создаёт новый объект — функция vowels возвращает разные регулярки, и их lastIndex не мешают друг другу. /a/xyz лексер принял (флаги — буквы), а ранняя ошибка отвергла. Пустой регулярки литералом не написать: // начинает комментарий, и сам RegExp печатает пустую как /(?:)/.

9. Шаблон — несколько токенов

Раздел 12.9.6: шаблон без подстановок — один токен NoSubstitutionTemplate. С подстановками — несколько: TemplateHead от ` до ${, TemplateMiddle от } до следующего ${ и TemplateTail от } до закрывающей `; между ними — обычные токены выражений. Вчерашняя цель InputElementTemplateTail нужна как раз для того, чтобы } после выражения прочитать как начало середины или хвоста.

Три отличия шаблона от строки. Переводы строк в нём разрешены, а пара CR LF превращается в один LF — и в значении, и в «сыром» тексте. Знак $ без { — обычный символ. И неверный escape в тегированном шаблоне — не ошибка (NotEscapeSequence): готовое значение будет undefined, а сырой текст сохранится — на этом держится String.raw дня 20 курса 2.

  try {
    new Function(code);
    return "разобрано";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};

console.log(new Function("return `a" + CR + LF + "b`")().length);
console.log(`цена: $5, ${2 + 3}`, `a${1}b${2}c`);

В первой строке шаблон из «a», CR, LF и «b» дал строку из трёх элементов: CR LF стал одним LF. Файл, сохранённый в Windows, даёт в шаблонах те же строки, что и файл из Linux.

10. Вставка точки с запятой: три правила

Раздел 12.10: большинство инструкций по грамматике кончаются точкой с запятой, но в некоторых случаях её можно не писать — язык «вставит» её в поток токенов. Случаи перечислены в 12.10.1, и их ровно три. Важное слово — offending token: токен, который не подходит ни одному правилу грамматики в этом месте.

Пройдём по примерам раздела 12.10.2:

const parse = (code) => {
  try {
    new Function(code);
    return "разобрано";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(parse("{ 1 2 } 3"));
console.log(parse("{ 1\n2 } 3"));
console.log(parse("for (a; b) {}"));
console.log(parse("if (a > b)\nelse c = d"));
console.log(parse("do {} while (false) let x = 1"));
SyntaxError: Unexpected number
разобрано
SyntaxError: Unexpected token ')'
SyntaxError: Unexpected token 'else'
разобрано

В { 1 2 } 3 токен 2 не подходит, но перед ним нет перевода строки — ошибка. С переводом строки правило 1 ставит ; перед 2, ещё одну — перед }, а правило 2 — в конце: { 1 ;2 ;} 3;. В заголовке for вставка запрещена. В if перед else точка с запятой стала бы пустой инструкцией — тоже нельзя. А после ) конца do-while её ставят даже на той же строке.

12. Перевод строки, который запрещён

Правило 3 работает в обратную сторону: токен подходит, но перед ним перевод строки там, где грамматика пишет [no LineTerminator here] (день 2, раздел 3). Таких правил немного, их список — в примечании к 12.10.1: постфиксные ++ и --, continue, break, return, throw, yield, стрелка => и async. У большинства операнд необязателен — и перевод строки тихо отрезает его (12.10.3.2):

let a, b = 1, c = 1
a = b
++c
console.log(a, b, c)
1 1 2

Пример 12.10.2: ++ на новой строке — уже не постфикс к b, а префикс к c. С return то же — это «Мары» с дня 3 Essentials и вчерашний return /*⏎*/ 5. Генератор ведёт себя так же:

function* gen() {
  yield
  5
}
console.log([...gen()])
(1) [undefined]

У continue и break отрезается метка — и становится обычным выражением на следующей строке:

outer: for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (j === 1) continue
    outer
  }
}
Uncaught ReferenceError: outer is not defined

Метка outer — не переменная, и на первом же шаге строка outer падает. Там, где операнд обязателен, вставка даёт ошибку разбора, и это даже лучше — ошибка видна сразу:

const parse = (code) => {
  try {
    new Function(code);
    return "разобрано";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(parse("throw\nnew Error('нет карточки')"));
console.log(parse("const sum = (a, b)\n=> a + b"));
console.log(parse("class Card { step = 1\n*steps() {} }"));
SyntaxError: Illegal newline after throw
SyntaxError: Unexpected token '=>'
SyntaxError: Unexpected token '{'

Последний особый случай — async. Это не зарезервированное слово (день 2), поэтому после перевода строки оно становится просто именем:

async
function load() { return 1; }
console.log("не дойдёт");
Uncaught ReferenceError: async is not defined

13. Висячие запятые

Страница MDN Trailing commas: запятая после последнего элемента списка разрешена везде, где список значений может продолжаться, — в литералах массивов и объектов, в параметрах и аргументах функций, в деструктуризации, в именованных импортах и экспортах и в import(). И почти везде она ничего не меняет. Зачем она: строку в конец многострочного списка добавляют, не трогая предыдущую, и в истории правок меняется одна строка, а не две.

function f(p,) {}
console.log([1, 2, 3,].length, [1, 2, 3, , ,].length, f.length);
console.log(((a, b,) => a + b)(1, 2,), Math.max(10, 20,));
const { word, step, } = { word: "kitap", step: 2 };
console.log(word, step, Object.keys([1, , 3]));
3 5 1
3 20
kitap 2 (2) ['0', '2']

Исключение — массив: одна висячая запятая ничего не значит, но каждая следующая добавляет дырку, и [1, 2, 3, , ,] длиной 5. Дырка — не undefined, а отсутствие свойства: у [1, , 3] только ключи «0» и «2». Длина функции от запятой не меняется.

Запрещена запятая там, где после неё ничего быть не может, и в пустом списке:

const parse = (code) => {
  try {
    new Function(code);
    return "разобрано";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
for (const code of ["f(,)", "function f(...p,) {}", "const [a, ...b,] = [1, 2, 3];", "[1, , ]", "({ a: 1,, })"]) {
  console.log(code, "→", parse(code));
}
f(,) → SyntaxError: Unexpected token ','
function f(...p,) {} → SyntaxError: Rest parameter must be last formal parameter
const [a, ...b,] = [1, 2, 3]; → SyntaxError: Rest element must be last element
[1, , ] → разобрано
({ a: 1,, }) → SyntaxError: Unexpected token ','

После остаточного параметра запятая — ошибка (день 14 Essentials): «остаток» по смыслу последний. Две запятые подряд в массиве — дырка, в объекте — ошибка. А JSON, который похож на литералы, но живёт по своей грамматике, висячих запятых не знает совсем (день 23 Essentials, день 31 курса 2):

try {
  JSON.parse("[1, 2, 3, ]");
} catch (e) {
  console.log(`${e.name}: ${e.message}`);
}
console.log(/^x{2}$/.test("xxx"), /^x{2,}$/.test("xxx"));
SyntaxError: Unexpected token ']', "[1, 2, 3, ]" is not valid JSON
false true

Вторая строка — единственное место, где запятая в конце меняет смысл: в квантификаторе регулярки {2} — ровно два, а {2,} — два и больше. В модулях запятая разрешена в import { a, b, } from "…" и export { a, b, }, а в import("./x.js",) — потому что у import() есть второй аргумент, параметры загрузки (день 31 курса 2).

14. «Карточки 2.0»: шаблон и строка без точки с запятой

Возьмём строку счётчика из render «Карточек 2.0» (день 33 курса 2):

// main.js, день 33 курса 2 — строки render
const cards = deck.due(today);
counter.textContent = `На сегодня: ${cards.length} из ${deck.size}`;

Теперь представим, что сосед пишет без точек с запятой, а следом за счётчиком добавил асинхронную загрузку колоды — функцию, вызываемую сразу (день 29 курса 2):

const counter = { textContent: "" }, cards = [1, 2, 3], deck = { size: 8 }
counter.textContent = `На сегодня: ${cards.length} из ${deck.size}`
(async () => {
  console.log("загрузка")
})()
Uncaught TypeError: cards.lengthdeck.size is not a function

Строка с ( не дала вставить точку с запятой: шаблон стал функцией, которую вызвали со стрелкой в аргументе. Загрузка не началась, счётчик не обновился, а сообщение V8 склеило подстановки шаблона и сбивает с толку. Лечится одним знаком — в конце предыдущей строки или, как советует MDN для стиля без точек с запятой, в начале опасной:

const counter = { textContent: "" }, cards = [1, 2, 3], deck = { size: 8 }
counter.textContent = `На сегодня: ${cards.length} из ${deck.size}`
;(async () => {
  console.log("загрузка", counter.textContent)
})()
загрузка На сегодня: 3 из 8

В «Карточках 2.0» точки с запятой стоят везде, и этот вопрос не возникал. Но чужой код, примеры из интернета, склейка файлов — места, где пять опасных начал строки встречаются.

// литералы: null true false — слова; undefined NaN Infinity — имена; -2 — два токена
// числа: 0b 0o 0x, .5 5. 1e3, n — только у целых; после числа не буква и не цифра: 1..toString()
// _ — только между цифрами: 1_000, 0xA0_B0; в Number("1_000") и \u{…} нельзя ([~Sep])
// значение: точное MV → ближайший Number; 9007199254740993 → 9007199254740992, с n — точно
// 010 — 8, 08 — 8, в строгом коде — SyntaxError; пишите 0o10

// строка: нельзя прямо — своя кавычка, \, CR, LF; LS и PS можно; \ в конце строки — продолжение
// escape: \n \t \0 \x41 B \u{1F600}; \z — просто z; \7 — старое, в строгом коде ошибка
// регулярка: лексер ищет конец; каждое вычисление — новый объект; пустая — /(?:)/
// шаблон с ${} — голова, середина, хвост; CR LF → LF; в тегированном неверный escape — undefined

// ; вставляется: 1) токен не подходит и перед ним перевод строки, или это }, или ) конца do-while
//                2) конец текста; 3) перевод строки на [no LineTerminator here]: return⏎ ++ => async
// не вставляется: пустой инструкцией и в заголовке for; перед строкой с ( [ ` + - /
// висячая запятая: массивы, объекты, параметры, аргументы, деструктуризация, import/export
// нельзя: f(,), после ...rest, в JSON; [1, , ,] — дырки; x{2,} — уже другой квантификатор
  1. Почему 1.toString() — ошибка, а 1..toString() — нет?
    Ответ Лексер берёт самый длинный кусок: 1. — число, и сразу за ним буква, а после числового литерала не может стоять начало имени (12.9.3). Во втором случае первая точка ушла в число, вторая — обращение к методу.
  2. Где можно поставить _ в 0xA0B0n и где нельзя?
    Ответ Только между двумя шестнадцатеричными цифрами: 0xA0_B0n, 0xA_0_B_0n. Нельзя после 0x, перед n и два подряд.
  3. Почему 9007199254740993 печатается как 9007199254740992?
    Ответ Точное значение записи (MV) превращается в ближайший Number, а 253 + 1 в 64 битах не помещается. С суффиксом n значение точное.
  4. Строка программы начинается с [, а предыдущая кончается без точки с запятой. Что будет?
    Ответ Точку с запятой не вставят: [ подходит грамматике как обращение к свойству предыдущего выражения. Две строки склеятся, а внутри скобок запятые станут оператором запятая.
  5. Где висячая запятая — ошибка, а где меняет смысл?
    Ответ Ошибка — в пустом списке (f(,)), после остаточного параметра или элемента и в JSON. Меняет смысл — в массиве каждая запятая после первой (дырка) и в квантификаторе регулярки: {2,} — «два и больше».
