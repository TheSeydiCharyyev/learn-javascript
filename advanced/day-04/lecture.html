1. Два вида типов

Модуль A2 начинается с главы 6 — ECMAScript Data Types and Values. Первая её фраза: у каждого значения, с которым работают алгоритмы, есть тип, и других типов, кроме описанных в главе, нет. Типы делятся на два вида. Типы языка (раздел 6.1) — значения, которыми программист пользуется прямо: их восемь — Undefined, Null, Boolean, String, Symbol, Number, BigInt и Object. Типы спецификации (6.2) — служебные значения алгоритмов; в переменную их не положить.

На дне 5 Essentials мы читали страницу MDN JavaScript data types and data structures — это пересказ раздела 6.1. Знакомый оператор typeof отвечает на вопрос о типе, но не совсем словами главы 6:

const values = [undefined, null, true, "kitap", Symbol("id"), 2026, 2026n, {}, () => {}];
console.log(values.map((v) => typeof v).join(" "));
undefined object boolean string symbol number bigint object function

Расхождений два. Для null — «object», хотя тип Null отдельный: алгоритм typeof так и записан — «если val — null, вернуть "object"». И «function» — не тип: функция по главе 6 — это Object, у которого есть внутренний метод [[Call]] (раздел 7). Оператор смотрит на этот метод.

2. Undefined, Null, Boolean, String, Symbol

Разделы 6.1.1–6.1.5 короткие. У Undefined и Null ровно по одному значению, у Boolean — два. String — не «текст», а последовательность 16-битных элементов длиной до 253 − 1; что это UTF-16, предполагают только операции, которые текст толкуют (день 20 курса 2). Одинокая половинка пары — тоже законная строка. Symbol — значения, которые годятся в ключи свойств, но не строки; каждый символ уникален, а описание хранит внутренний слот [[Description]].

console.log("😀".length, [..."😀"].length, "\uD800".length, "\uD800".isWellFormed());
console.log(Symbol("id") === Symbol("id"), Symbol("id").description, Symbol().description);
console.log(Symbol.for("id") === Symbol.for("id"), typeof Symbol.iterator);
2 1 1 false
false id undefined
true symbol

Эмодзи — один символ на экране, но два элемента строки; «😀» по кодовым точкам — один. Предел длины 253 − 1 — это то, что разрешает стандарт; реализация ставит свой, намного меньше: в Chrome "x".repeat(2 ** 30) бросает RangeError: Invalid string length. Различие «стандарт / реализация» с дня 1 работает и здесь.

Два одинаковых описания — два разных символа. Symbol.for не нарушает правила: он берёт символ из общего реестра, и второй вызов возвращает тот же. Symbol.iterator — один из встроенных символов (6.1.5.1), которыми алгоритмы находят протоколы, — их мы видели на дне 11 курса 2.

3. Number: 2⁶⁴ − 2⁵³ + 3 значения

Раздел 6.1.6 вводит два числовых типа, а подраздел 6.1.6.1 считает значения Number точно: 264 − 253 + 3. Это числа двойной точности IEEE 754, только все 253 − 2 разных NaN стандарта IEEE язык видит как один NaN. Кроме NaN — две бесконечности и конечные числа, среди которых два нуля, +0 и −0. Все целые по модулю до 253 представимы точно.

console.log(2n ** 64n - 2n ** 53n + 3n);
console.log(Object.is(NaN, 0 / 0), Object.is(0, -0), 0 === -0, 1 / -0);
console.log(9007199254740993, 9007199254740995, 2 ** 53 + 2);
console.log(1.7976931348623158e308, 1.7976931348623159e308);
18437736874454810627n
true false true -Infinity
9007199254740992 9007199254740996 9007199254740994
1.7976931348623157e+308 Infinity

Число посчитано BigInt'ом — Number столько цифр точно не удержит. Object.is (день 6 курса 2) различает нули и не различает NaN — это операция Number::sameValue. Последняя строка показывает фразу, которой спецификация пользуется сотни раз: «the Number value for x» — ближайший Number, а при равенстве — тот, у которого чётная мантисса. Поэтому 253 + 1 уходит вниз, к …992, а 253 + 3 — вверх, к …996: оба соседа на одном расстоянии, побеждает чётный.

У правила есть край. В набор, из которого выбирается ближайший, раздел добавляет два значения, которых в Number нет, — ±21024; если ближе всего оказалось одно из них, результат — бесконечность. Поэтому запись чуть больше Number.MAX_VALUE ещё округляется к нему, а следующая по величине — уже Infinity: ошибки «переполнения» в языке нет.

4. BigInt и таблица числовых операций

Подраздел 6.1.6.2: BigInt — целое любого размера, для побитовых операций — дополнительный код, где у отрицательного числа слева бесконечно много единиц. Таблица 2 раздела 6.1.6 перечисляет операции: каждый оператор вызывает пару Number::… или BigInt::… — Number::add для x + y, BigInt::divide для x / y и так далее. Столбец «Result» говорит, какие из них могут вернуть внезапную запись (день 1): у Number — ни одна, у BigInt — деление, остаток, степень и беззнаковый сдвиг.

const attempt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(attempt(() => 1n + 1));
console.log(attempt(() => 2n ** -1n));
console.log(attempt(() => 1n / 0n));
console.log(5n / 2n, -5n / 2n, -5n % 3n, Number(2n ** 64n));
TypeError: Cannot mix BigInt and other types, use explicit conversions
RangeError: Exponent must be positive
RangeError: Division by zero
2n -2n -2n 18446744073709552000

Под таблицей — объяснение первой ошибки: типы не переводятся друг в друга без потерь, поэтому неявного перевода между Number и BigInt нет. Number теряет точность, BigInt — дробную часть; переводить нужно явно, Number(…) или BigInt(…). Отрицательная степень дала бы дробь — поэтому RangeError; V8 пишет «must be positive», хотя ноль разрешён: 2n ** 0n — 1n. Деление и остаток отбрасывают дробь к нулю, и знак остатка — как у делимого. Беззнакового сдвига у BigInt нет вовсе: при бесконечных единицах слева «беззнакового» результата не бывает — о сдвигах день 6.

5. Object: свойства и ключи

Раздел 6.1.7: объект — набор свойств. Свойство бывает данных (ключ, значение и атрибуты) или аксессором (ключ, одна или две функции и атрибуты). Ключ свойства — строка или символ, других нет; пустая строка — тоже ключ. Среди строк раздел выделяет целочисленный индекс (от 0 до 253 − 1) и индекс массива — до 232 − 2. Только индексы массива двигают его length:

console.log(Object.keys({ 1: "a", [Symbol("s")]: 2, "": 3 }));
const a = [], b = [], c = [];
a[4294967294] = 1;
b[4294967295] = 1;
c["-0"] = 1;
console.log(a.length, b.length, c.length, Object.keys(c));
(2) ['1', '']
4294967295 0 0 (1) ['-0']

Числовой ключ 1 стал строкой «1», символ в Object.keys не попал (день 11 курса 2), пустая строка — попала. 4294967294 = 232 − 2 — последний индекс массива, длина стала 232 − 1. На единицу больше — уже обычное свойство, длина 0. Примечание раздела отдельно оговаривает «-0»: это не индекс вовсе, просто строка из двух символов.

8. Типы спецификации: Enum, List, Record

Раздел 6.2: типы спецификации — мета-значения, которые описывают работу языка. Раздел прямо говорит: они не обязаны соответствовать чему-то в движке, и их нельзя сохранить в свойство или переменную.

Enum (6.2.1) — имена вроде normal, return, throw: ничего, кроме имени, у них нет. List (6.2.2) — упорядоченный список, пишется в угловых кавычках: «1, 2», пустой — «»; так передаются, например, аргументы вызова: Function.prototype.apply, проверив функцию, строит из похожего на массив объекта List операцией CreateListFromArrayLike и только потом вызывает. Record — набор именованных полей, похожий на литерал объекта: { [[Field1]]: 42, [[Field2]]: false }. Set и Relation (6.2.3) нужны модели памяти (день 23) и не имеют отношения к объекту Set.

9. Completion Record

На дне 1 мы разворачивали знаки ? и ! и уже пользовались записями. Раздел 6.2.4 даёт им определение: Completion Record объясняет, как значения и управление проходят через программу, — особенно break, continue, return и throw, которые уводят выполнение в другое место. Таблица 7 — три поля:

Запись типа normal — обычная, любая другая — внезапная (abrupt). Подразделы 6.2.4.1–6.2.4.3 — сокращения: NormalCompletion(v), ThrowCompletion(e), ReturnCompletion(v). Вот какие записи дают знакомые инструкции:

Вызываемые объекты спецификации возвращают только обычную запись или throw — return до вызывающего не доходит, он превращается в обычное значение. А [[Value]] бывает пустым, empty: так завершаются инструкции без значения — var x = 3;, пустая ;. Подраздел 6.2.4.4 UpdateEmpty заполняет пустое значение, если оно пустое, и не трогает, если нет.

10. Значение завершения в консоли

Обычно значения завершения не видны, но консоль DevTools их показывает: после ввода она печатает [[Value]] записи, которой закончился весь ввод. Введите строки по одной:

Инструкции if и блок отдают значение последней инструкции внутри. Цикл — значение последнего шага: 20. var x = 3; завершается пустым значением, и список инструкций сохраняет предыдущее, 2. А if (false) {} возвращает не пустое, а undefined — алгоритм if заканчивается UpdateEmpty(…, undefined), и 1 затирается. finally со своим обычным завершением значение try не меняет. break l несёт метку в [[Target]], помеченный блок её узнаёт и превращает запись в обычную с последним значением, 3. Консоль печатает строки в кавычках — так она отличает их от чисел.

11. return и finally

Алгоритм try...finally (14.15.3) в три шага: вычислить блок — запись B; вычислить finally — запись F; если F обычная, вернуть B, иначе — F. Значит, внезапное завершение finally побеждает всё, что было в try, — и return, и даже ошибку:

function f() { try { return "из try"; } finally { return "из finally"; } }
function g() { try { throw new Error("пропала"); } finally { return "ошибки нет"; } }
function h() { for (const n of [1, 2, 3]) { try { return n; } finally { continue; } } return "дошли"; }
function k() { try { return "из try"; } finally { console.log("finally выполнен"); } }
console.log(f(), "|", g(), "|", h());
console.log(k());
из finally | ошибки нет | дошли
finally выполнен
из try

Это та «странность», о которой предупреждал день 11 Essentials: return в finally побеждает. Теперь видно, что это не исключение из правила, а само правило — три шага алгоритма. В h запись continue из finally отменила return, цикл дошёл до конца, и функция вернула «дошли». А k — обычный случай: finally выполнился (строка напечатана раньше результата), завершился обычной записью, и итогом осталась запись return из try. Поэтому finally годится для уборки — закрыть, остановить, напечатать, — а return, break и continue в нём не пишут.

12. Reference Record

Раздел 6.2.5: Reference Record — это «ссылка» на имя или свойство, ещё не превращённая в значение. Её получает левая часть присваивания, аргумент typeof и delete, имя функции при вызове. Поля по таблице 8:

ПолеЧто там
[[Base]]значение (для свойства), Environment Record (для переменной) или unresolvable — имя не нашлось
[[ReferencedName]]имя: строка, символ, Private Name — или пока любое значение, до ToPropertyKey
[[Strict]]создана ли ссылка в строгом коде
[[ThisValue]]для super.x — this на момент создания, иначе empty

Две главные операции — GetValue (прочитать) и PutValue (записать). Их шаги объясняют вещи, которые раньше приходилось запоминать:

const attempt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(typeof nope, attempt(() => nope));
function leak() { leaked = 1; }
leak();
console.log(globalThis.leaked, attempt(() => { "use strict"; strictLeak = 1; }));
console.log(attempt(() => { "use strict"; Math.PI = 3; }));
console.log(attempt(() => { "use strict"; "kitap".x = 1; }));
console.log(delete nope, delete Math.PI);
undefined ReferenceError: nope is not defined
1 ReferenceError: strictLeak is not defined
TypeError: Cannot assign to read only property 'PI' of object '#<Object>'
TypeError: Cannot create property 'x' on string 'kitap'
true false

typeof сначала проверяет: ссылка не разрешилась — «undefined» (день 5 Essentials называл это «особой добротой»). Простое nope идёт через GetValue, а её шаг 2 — ReferenceError: так вчерашний continue⏎outer упал на имени outer. PutValue в нестрогом коде записывает ненайденное имя в глобальный объект — отсюда «утечка» leaked (день 3 курса 2), а в строгом бросает. Поле [[Strict]] решает и судьбу неудачной записи: [[Set]] вернул false, и только строгий код превращает это в TypeError. То же со свойством строки: [[Base]] — примитив, PutValue делает из него временный объект (ToObject), пишет в него и выбрасывает. Примечание к PutValue оговаривает, что этот объект снаружи не виден, — в нестрогом коде запись просто пропадает. delete для ненайденного имени возвращает true, а для ненастраиваемого свойства — false.

13. Откуда берётся this при вызове

Вызов f() вычисляет f и смотрит, что получилось (EvaluateCall, 13.3.6.2). Если это Reference Record на свойство, this берётся из него операцией GetThisValue — то есть из [[Base]]. Если ссылку уже превратили в значение, this взять неоткуда:

const card = { word: "kitap", show() { return this === card; } };
console.log(card.show(), (card.show)(), card["show"](), card?.show());
console.log((0, card.show)(), (card.show = card.show)(), [card.show][0]());
const { show } = card;
console.log(show());
true true true true
false false false
false

Скобки ( … ) возвращают то, что вернуло выражение внутри, — ссылку, и this сохраняется. Оператор запятая и присваивание вызывают GetValue — остаётся голая функция; этот приём (0, card.show)() мы видели на дне 2 курса 2. [card.show][0] — тоже ссылка, но на свойство «0» массива, и this — массив. Деструктуризация кладёт в show значение. И ещё одно следствие раздела 7: метод, записанный коротко, — функция без [[Construct]], и new card.show() бросает TypeError: card.show is not a constructor.

Четвёртое поле, [[ThisValue]], нужно для super: метод родителя ищется в прототипе, а this должен остаться нашим объектом:

class Card { label() { return this.word; } }
class TurkmenCard extends Card { word = "kitap"; label() { return "tk: " + super.label(); } }
console.log(new TurkmenCard().label());
tk: kitap

15. «Карточки 2.0»: метод know без колоды

Кнопка «Знаю» в «Карточках 2.0» (день 34 курса 2) зовёт метод колоды так:

// main.js, день 34 курса 2 — кнопка «Знаю»
const word = current();
if (word === null) return;
opened.get(chosen).know(word.id, today);

Выражение opened.get(chosen).know даёт Reference Record: [[Base]] — колода, которую вернул get, [[ReferencedName]] — «know», [[Strict]] — true, ведь модули строгие. Вызов берёт this из [[Base]]. Попробуем «упростить» код — сохранить метод в переменную или отдать его прямо в forEach:

class Deck {
  #cards = new Map([[1, "kitap"]]);
  #progress = new Map();
  know(id) {
    if (!this.#cards.has(id)) throw new Error(`в колоде нет карточки ${id}`);
    this.#progress.set(id, 2);
    return this.#progress.size;
  }
}
const deck = new Deck();
const attempt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(deck.know(1));
const know = deck.know;
console.log(attempt(() => know(1)));
console.log(attempt(() => [1].forEach(deck.know)));
console.log(know.call(deck, 1), deck.know.bind(deck)(1), [1].map((id) => deck.know(id)).length);
1
TypeError: Cannot read properties of undefined (reading '#cards')
TypeError: Cannot read properties of undefined (reading '#cards')
1 1 1

В know лежит значение — функция, ссылки на колоду в нём нет. Код класса строгий, и this без объекта — undefined, а у него не прочитать #cards. forEach тоже получил голую функцию. Лечат тремя способами из последней строки: передать this явно (call), привязать (bind, день 2 курса 2) или обернуть в стрелку, где вызов снова идёт через ссылку deck.know. В «Карточках 2.0» выбран третий: обработчик кнопки — стрелка, и метод вызывается прямо на колоде.

// typeof null — "object", typeof функции — "function": так записан алгоритм typeof
// Number: 2^64 − 2^53 + 3 значения, один NaN, +0 и −0; ничья при округлении — к чётной мантиссе
// BigInt: точно, без неявного смешивания с Number; / % ** у BigInt могут бросить; ближайшее ±2^1024 — это ±Infinity
// ключ — строка или символ; индекс массива — до 2^32 − 2; "-0" — не индекс

// Completion Record: [[Type]] normal | break | continue | return | throw, [[Value]], [[Target]]
// консоль печатает [[Value]] итоговой записи: if (true) { 5 } → 5; var — пусто, if — undefined
// try...finally: обычная F — итог B; внезапная F (return, break, continue, throw) — итог F
// Reference Record: [[Base]] (значение | Environment Record | unresolvable), [[ReferencedName]], [[Strict]], [[ThisValue]]
// typeof ненайденного — "undefined"; GetValue ненайденного — ReferenceError; PutValue — глобальное свойство или ошибка
// this при вызове — из [[Base]] ссылки; (0, obj.m)(), const m = obj.m — ссылки нет
  1. Почему typeof null — «object», хотя тип Null отдельный?
    Ответ Так записан алгоритм typeof (13.5.3.1): «если val — null, вернуть "object"». Ответ оператора — это его таблица, а не название типа из главы 6.
  2. Почему 2 ** 53 + 1 === 2 ** 53, а 2n ** 53n + 1n — нет?
    Ответ 253 + 1 не представимо в Number, и «the Number value for x» выбирает соседа с чётной мантиссой — 253. BigInt хранит целые любого размера точно.
  3. Что напечатает консоль на ввод 1; if (false) {} и почему не 1?
    Ответ undefined: инструкция if завершается UpdateEmpty(…, undefined) и её значение не пустое, поэтому оно заменяет 1. С var x = 3; было бы 1 — у неё значение пустое.
  4. Почему return в finally отменяет ошибку из try?
    Ответ Алгоритм try...finally возвращает запись блока, только если finally завершился обычно. Запись return внезапная — она и становится итогом, а запись throw из блока отбрасывается.
  5. Почему (card.show)() сохраняет this, а (0, card.show)() — нет?
    Ответ Скобки возвращают Reference Record, и вызов берёт this из её [[Base]]. Оператор запятая вызывает GetValue: остаётся функция без ссылки на объект.
