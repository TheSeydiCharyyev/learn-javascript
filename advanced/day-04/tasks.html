Разминка

1. Какой это тип
Легко7 мин

отличать тип языка от ответа typeof.

Для каждого значения назовите тип по разделу 6.1, потом предскажите строку вывода.

const items = [null, () => {}, class {}, new Map(), Symbol.iterator, -0, NaN, 10n ** 20n, "", Object(1)];
console.log(items.map((v) => typeof v).join(" "));
  • для всех десяти значений записан тип из восьми;
  • отмечены места, где typeof говорит не то, что тип, и для каждого — шаг 13.5.3.1;
  • объяснено, почему у Object(1) тип Object, хотя внутри — число 1.
2. Что напечатает консоль
Легко7 мин

предсказывать значение завершения по Completion Record.

Вводите строки в консоль по одной. Предскажите каждый ответ до ввода.

// в консоли: вводите по одной строке
1; 2; 3
if (false) { 1 } else { 2 }
for (const n of [1, 2, 3]) { if (n === 2) break; n * 10; }
while (true) { 4; break; }
x: { 5; if (true) break x; 6; }
"kitap"; const y = 1;
  • шесть предсказаний записаны до ввода;
  • для цикла объяснено, почему он дал не 10: какое значение получил пустой break, пройдя через if (14.6.2);
  • помеченный блок сравнён с l: { 3; break l; } из лекции: записана запись break с её [[Target]] и объяснено, почему там 3, а здесь нет.

Основные задания

4. Девять способов позвать метод
Средне12 мин

видеть, где вызов получает Reference Record, а где — голое значение.

Предскажите девять строк: где метод увидит свою колоду, а где нет.

const deck = { cards: ["kitap", "suw"], size() { return this === deck ? this.cards.length : "без колоды"; } };
const calls = [
  () => deck.size(),
  () => (deck.size)(),
  () => (deck.size || null)(),
  () => (0, deck.size)(),
  () => (deck.size = deck.size)(),
  () => deck["si" + "ze"](),
  () => (true ? deck.size : null)(),
  () => deck?.size(),
  () => (deck?.size)(),
];
calls.forEach((call, i) => console.log(i + 1, call()));
  • для каждого вызова записано, что вернуло выражение перед (): Reference Record или значение;
  • для «без колоды» назван оператор, который вызвал GetValue (раздел 13 с номером);
  • для вызова 9 найдено в 13.2.9.2, почему скобки вокруг цепочки не мешают.
5. typeof и delete необъявленного
Средне12 мин

предсказывать typeof, delete и GetValue по полю [[Base]].

const tryIt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(tryIt(() => typeof nope), tryIt(() => typeof (nope)), tryIt(() => typeof nope.x));
console.log(tryIt(() => delete nope), tryIt(() => delete nope.x));
console.log(tryIt(() => { var kept = 1; return delete kept; }), tryIt(() => { globalThis.gone = 1; return delete gone; }));
console.log(tryIt(() => { typeof later; let later = 1; }));
  • для каждого выражения записан [[Base]] ссылки: значение, Environment Record или unresolvable;
  • объяснено, почему typeof nope.x бросает, хотя typeof nope — нет;
  • объяснено, почему последняя строка — ошибка: имя later нашлось, но его привязка ещё не готова, и typeof спасает только от unresolvable.
6. «Карточки 2.0»: методы, которые не теряют колоду
Средне14 мин

применить Reference Record и атрибуты свойств к коду проекта.

Напишите bound(obj): объект с теми же методами, что у obj по цепочке прототипов, но привязанными к obj через bind, — их можно отдавать в forEach и addEventListener. Конструктор и аксессоры не брать.

class Deck {
  #seen = 0;
  know() { this.#seen++; return this.#seen; }
  get seen() { return this.#seen; }
}
const deck = new Deck();
const { know } = bound(deck);
[1, 2, 3].forEach(know);
deck.seen;                              // 3
Object.keys(bound(deck)).join(" ");     // "know"
typeof bound(deck).seen;                // "undefined"
  • все три строки примера дают то, что в комментариях;
  • методы найдены через Object.getPrototypeOf, а аксессор отсеян по дескриптору — у него нет value;
  • объяснено через Reference Record, почему [1, 2, 3].forEach(deck.know) без bound бросает.
7. Кто победил в finally
Средне12 мин

проходить алгоритм 14.15.3 по записям B, C и F.

const log = [];
function a() { try { log.push("try"); return "a"; } finally { log.push("finally"); } }
function b() { try { throw new Error("b"); } catch (e) { return e.message; } finally { log.push("b-finally"); } }
function c() { for (;;) { try { break; } finally { log.push("c-finally"); } } return "c"; }
function d() { try { return "try"; } finally { try { throw new Error("внутри"); } catch {} } }
function e() { label: try { return "e"; } finally { break label; } return "после метки"; }
console.log(a(), b(), c(), d(), e());
console.log(log.join(" "));
  • для каждой функции выписаны записи B, C (если есть) и F и та, что стала итогом;
  • для d объяснено, почему ошибка внутри finally не изменила итог;
  • для e найдено, где запись break с меткой превратилась в обычную.

8. Список инструкций по записям
Сложно10 мин

перенести UpdateEmpty и правило списка инструкций в код.

Запись — объект { type, value, target }, пустое значение — символ EMPTY. Напишите updateEmpty(record, value) по 6.2.4.4 и evaluateList(records): свернуть записи инструкций, как список инструкций (14.2.2), — каждая следующая через UpdateEmpty с прежним значением, на первой внезапной остановиться.

const EMPTY = Symbol("empty");
const n = (value) => ({ type: "normal", value, target: EMPTY });
evaluateList([n(1), n(EMPTY), n(2)]).value;                                 // 2
evaluateList([n(1), n(EMPTY)]).value;                                       // 1
evaluateList([n(1), { type: "break", value: EMPTY, target: "x" }]).value;   // 1
evaluateList([n(1), { type: "throw", value: "ошибка", target: EMPTY }, n(3)]).type;   // "throw"
evaluateList([]).value === EMPTY;                                           // true
  • все пять строк примера дают то, что в комментариях;
  • ответы задания 2 повторены записями: 1; 2; 3 и помеченный блок;
  • объяснено, почему третья строка вернула 1, а не пусто, хотя break пуст.
9. Незнакомый раздел: FromPropertyDescriptor
Сложно10 мин

прочитать алгоритм, которого не было на лекции.

Прочитайте подраздел 6.2.6.4 FromPropertyDescriptor — он делает из записи Property Descriptor обычный объект для Object.getOwnPropertyDescriptor. Предскажите четыре строки.

const o = { word: "kitap", get size() { return 2; } };
Object.defineProperty(o, "id", { value: 7, enumerable: false });
for (const key of ["word", "size", "id", "nope"]) {
  const d = Object.getOwnPropertyDescriptor(o, key);
  console.log(key, d === undefined ? "нет свойства" : Object.keys(d).join(" "));
}
  • предсказаны порядок ключей и их набор, у каждой строки — шаги 6.2.6.4, которые их дали;
  • объяснено, почему у size есть ключ set, хотя сеттера нет;
  • найдено, какой шаг возвращает undefined для nope.
