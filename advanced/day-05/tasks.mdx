# День 5. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Открыты спецификация, [tc39.es/ecma262/2026/](https://tc39.es/ecma262/2026/), и консоль Chrome. Код пишем в папке `day-05` курса 3. Каждое предсказание — до запуска, каждое «почему» — с номером раздела и шага.</Subtitle>

## Разминка

<Task title="1. Дюжина значений, три операции" level="easy" time="7">
<Goal>считать `+x`, `String(x)` и `!!x` по таблицам главы 7.</Goal>

Это практика плана дня: таблицы 7.1.4, 7.1.17 и 7.1.2. Для массивов и объекта ответ начинается с ToPrimitive
— вспомните, какую подсказку даёт каждая из трёх операций. Предскажите двенадцать строк, по три ответа в каждой.

```js
const values = [undefined, null, true, "", " 7 ", "0x10", "1e2", [], [3], [1, 2], {}, -0];
for (const v of values) console.log(+v, JSON.stringify(String(v)), !!v);
```

<Criteria>
- все 36 ответов записаны до запуска;
- для массивов и объекта записан путь: ToPrimitive, какой метод, что дальше;
- найдено значение, у которого `+x` и `!!x` «спорят» (число 0, но истинно), и объяснено почему.
</Criteria>
</Task>

<Task title="2. Кто позвал valueOf" level="easy" time="7">
<Goal>предсказывать подсказку ToPrimitive по оператору.</Goal>

Предскажите десять строк: результат и журнал вызовов. Подсказку каждого оператора ищите в его алгоритме:
умножение зовёт ToNumeric, сложение — ToPrimitive без подсказки, шаблон — ToString, ключ — ToPropertyKey.

```js
const log = [];
const step = { valueOf() { log.push("valueOf"); return 2; }, toString() { log.push("toString"); return "шаг"; } };
const exprs = [() => step * 3, () => `${step}`, () => step + 1, () => step + "!", () => [step, step].join("-"),
  () => Object.keys({ [step]: true })[0], () => step == "2", () => step > 1, () => Number(step), () => String(step)];
exprs.forEach((f, i) => {
  log.length = 0;
  const result = f();
  console.log(i + 1, result, log.join(" "));
});
```

<Criteria>
- для каждого выражения записаны подсказка (`string`, `number` или нет) и метод;
- объяснено, почему `step + "!"` дал «2!», а не «шаг!»;
- объяснено, почему `join` позвал `toString` дважды.
</Criteria>
</Task>

<Task title="3. Строки-числа" level="easy" time="6">
<Goal>различать сравнение строк и сравнение чисел.</Goal>

Предскажите три строки. Помните: IsLessThan сравнивает строки, только если строками стали *обе*
стороны, а `==` переводит строку в число уже при одной числовой.

```js
console.log("2" > "12", 2 > "12", "2" > 12, "abc" < "abd", "Z" < "a", "10" == 10, "10" === 10);
console.log(["10", "9", "1", "100"].sort().join(), ["10", "9", "1", "100"].sort((a, b) => a - b).join());
console.log("1" < "1.0", "1.0" == 1, "  1  " == 1, "1e1" == 10);
```

<Criteria>
- предсказаны все шестнадцать значений;
- для каждого `<` и `>` отмечено, какая ветка IsLessThan сработала: строки или числа;
- объяснено, почему функция `(a, b) => a - b` сортирует строки как числа.
</Criteria>
</Task>

## Основные задания

<Task title="4. Лестница == по шагам" level="medium" time="12">
<Goal>проходить IsLooselyEqual (7.2.13) по ступеням.</Goal>

Для каждой пары запишите цепочку ступеней до ответа, потом проверьте.

```js
const pairs = [[[], false], [[1], "1"], [null, 0], [undefined, ""], ["", 0], [{}, "[object Object]"],
  [0n, ""], [NaN, NaN], [[null], ""], [true, "1"]];
pairs.forEach(([x, y], i) => console.log(i + 1, x == y));
```

<Criteria>
- для каждой пары — номера ступеней по порядку и промежуточные значения;
- объяснено, почему `null == 0` ложно, хотя `+null` — 0;
- для пары 7 найден шаг, который вызвал StringToBigInt, и записано, что он вернул.
</Criteria>
</Task>

<Task title="5. Свой ToPrimitive" level="medium" time="12">
<Goal>перенести 7.1.1 и 7.1.1.1 в код.</Goal>

Напишите `ordinaryToPrimitive(obj, hint)` и `toPrimitive(input, hint)`: не объект —
вернуть как есть, без подсказки — как `"number"`. Свой метод `Symbol.toPrimitive` не
проверяйте — это день 17.

<Example>
```js
const mark = { valueOf() { return 5; }, toString() { return "пять"; } };
toPrimitive(mark, "number");     // 5
toPrimitive(mark, "string");     // "пять"
toPrimitive(mark);               // 5
toPrimitive([1, 2], "number");   // "1,2"
toPrimitive(7, "string");        // 7
toPrimitive({ valueOf() { return {}; }, toString() { return "x"; } }, "number");   // "x"
```
</Example>

<Criteria>
- все шесть строк примера дают то, что в комментариях;
- метод вызывается, только если он функция (IsCallable), и с `this` — самим объектом;
- на `{ valueOf() { return {}; }, toString() { return {}; } }` бросается `TypeError`, как у `+x`.
</Criteria>
</Task>

<Task title="6. «Карточки 2.0»: номер карточки из разметки" level="medium" time="14">
<Goal>превращать «сырые» значения в ключ `Map` без тихих ошибок.</Goal>

Номер карточки приходит из `dataset`, `localStorage` или JSON — строкой или числом.
Напишите `cardId(raw)`: целое число от 1 или строка, которая записана ровно как такое число, —
вернуть число; всё остальное — `null`. Это защита от тихой ошибки из раздела 15 лекции: строка
«1» не находит в `Map` ключ 1, а неверный номер лучше заметить сразу, чем получить
`undefined`.

<Example>
```js
cardId(1);        // 1
cardId("12");     // 12
cardId("012");    // null
cardId(" 12 ");   // null
cardId("1e1");    // null
cardId("");       // null
cardId(true);     // null
cardId(2.5);      // null
```
</Example>

<Criteria>
- все восемь строк примера дают то, что в комментариях;
- объяснено, почему одного `+raw` мало: найдены три значения из примера, на которых он ошибается;
- проверка строки сравнена с CanonicalNumericIndexString (7.1.21): что у них общего и где разница.
</Criteria>
</Task>

<Task title="7. IsLessThan с журналом" level="medium" time="12">
<Goal>проходить 7.2.12 по шагам, включая LeftFirst.</Goal>

Каждый объект записывает свою букву, когда у него просят значение. Предскажите две строки: пять ответов и
порядок, в котором объекты отдали значения.

```js
const order = [];
const v = (name, value) => ({ valueOf() { order.push(name); return value; } });
const results = [v("a", "10") < v("b", "9"), v("c", 10) > v("d", "9"), v("e", NaN) >= v("f", 1),
  v("g", "x") < v("h", 1n), v("i", 2n) > v("j", "1")];
console.log(results.join(" "));
console.log(order.join(" "));
```

<Criteria>
- предсказаны пять ответов и порядок десяти букв;
- для каждого сравнения названа ветка IsLessThan и то, что вернула операция до оператора (может быть
  `undefined`);
- объяснено, почему `>=` с NaN — `false`, хотя «не меньше» звучит как `true`.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Свой IsLooselyEqual" level="hard" time="10">
<Goal>перенести лестницу 7.2.13 в код.</Goal>

Напишите `looseEqual(x, y)` по восьми ступеням, без `==` внутри. Можно
`===`, `Number`, `BigInt` и ToPrimitive из задания 5 (без подсказки).

<Example>
```js
const pairs = [[[], false], [null, 0], [undefined, null], ["1", 1n], [1n, 1], [{}, "[object Object]"],
  [NaN, NaN], [0n, ""], [Symbol.iterator, "x"], [1n, 1.5], ["1.5", 1n]];
pairs.every(([x, y]) => looseEqual(x, y) === (x == y));   // true
looseEqual([], ![]);    // true
looseEqual("x", 1n);    // false
```
</Example>

<Criteria>
- все три строки примера дают то, что в комментариях;
- каждая ступень — отдельная проверка с номером шага в комментарии;
- найдено значение, на котором ваш вариант разойдётся с `==` (подсказка: дата и
  `Symbol.toPrimitive`), и объяснено почему.
</Criteria>
</Task>

<Task title="9. Незнакомый раздел: StringIntegerLiteral" level="hard" time="10">
<Goal>прочитать грамматику, которой не было на лекции.</Goal>

Прочитайте подраздел [7.1.14.1
StringIntegerLiteral Grammar](https://tc39.es/ecma262/2026/#sec-stringintegerliteral-grammar) — по ней `BigInt` разбирает строки — и предскажите, что вернёт
каждая строка или какую ошибку бросит.

```js
const strings = [" 0b11 ", "-0x1F", "+12", "-0", "", "1_000", "Infinity", "1e3", "12n", "0o17"];
for (const s of strings) {
  try {
    console.log(JSON.stringify(s), String(BigInt(s)));
  } catch (e) {
    console.log(JSON.stringify(s), e.name);
  }
}
```

<Criteria>
- предсказаны десять ответов, у каждого — правило грамматики, которое его разрешает или запрещает;
- сравнено с грамматикой числовых строк A.6 (день 2): какие строки она принимает, а эта — нет;
- объяснено, почему `"-0"` дал `0`, а не «минус ноль».
</Criteria>
</Task>
