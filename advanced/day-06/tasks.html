Разминка

1. ToInt32 и ToUint32 вручную
Легко7 мин

проходить шаги 7.1.6 и 7.1.7 без компьютера.

Для каждого значения предскажите v | 0 (ToInt32) и v >>> 0 (ToUint32). Строки и массив сначала проходят ToNumber — день 5.

const values = [7.9, -7.9, 2 ** 31 - 1, 2 ** 31 + 1, 2 ** 32 + 7, -1, "0b101", " 3 ", [8], null, NaN, -Infinity];
values.forEach((v, i) => console.log(i + 1, v | 0, v >>> 0));
  • все 24 ответа записаны до запуска;
  • для значений 2 и 4 записаны шаги 3–5 с промежуточными числами;
  • названо правило: при каких v два ответа совпадают и почему.
2. Разряды на бумаге
Легко7 мин

считать &, |, ^ и ~ по таблице истинности NumberBitwiseOp.

Запишите оба числа столбиком в двоичном виде и проходите пары разрядов. Для отрицательных вспомните: −x — это перевёрнутое x плюс 1.

const a = 0b1100, b = 0b1010;
console.log(a & b, a | b, a ^ b, ~a, a & ~b, (a ^ b) ^ b);
console.log(-1 & 255, -256 | 15, ~-8, 5 ^ -1, 12 & -12, -7 & 1, -7 % 2);
  • предсказаны тринадцать значений, к каждому — столбик разрядов;
  • объяснено, почему (a ^ b) ^ b всегда возвращает a, а x ^ -1 — то же, что ~x;
  • найдено, что оставляет от числа x & -x, и проверено ещё на двух числах.
3. Сдвиги и приоритет
Легко6 мин

расставлять скобки по грамматике 13.9–13.13 и считать сдвиги.

Сначала перепишите каждое выражение со всеми скобками, которые подразумевает грамматика, потом считайте.

console.log(3 << 2 + 1, (3 << 2) + 1, 1 << 31 >> 31, 1 << 31 >>> 31, -1 >>> 28);
console.log(8 >> 1 === 4, 8 & 4 === 4, (8 & 4) === 4, 6 & 3 || 9, 2 | 1 && 0);
console.log(5 << 32, 5 >> -1, -5 >>> 30, 0xCC000000 >> 24, 0xCC000000 >>> 24, (0x1B2A3C >> 8) & 0xFF);
  • все шестнадцать выражений переписаны со скобками и предсказаны;
  • объяснено, почему 8 & 4 === 4 и (8 & 4) === 4 ошибаются по-разному;
  • для 5 >> -1 записан настоящий счётчик сдвига и шаг 6.1.6.1.10, который его дал.

Основные задания

4. Своя семья ToIntN
Средне12 мин

перенести 7.1.6–7.1.11 в две функции с числом разрядов.

Шесть разделов главы 7 отличаются только числом разрядов. Напишите toUintN(x, bits) и toIntN(x, bits) для 8, 16 и 32 разрядов, без побитовых операторов: ToNumber, особые значения, отбросить дробь, modulo (не %), знак.

toIntN(300, 8);        // 44
toIntN(200, 8);        // -56
toUintN(-1, 16);       // 65535
toIntN(32768, 16);     // -32768
toIntN(3e9, 32);       // -1294967296
toUintN(-9, 32);       // 4294967287
toIntN(-2.9, 8);       // -2
toIntN(NaN, 16);       // 0
toUintN("0x1FF", 8);   // 255
  • все девять строк примера дают то, что в комментариях;
  • на двенадцати значениях задания 1 toIntN(v, 32) совпадает с v | 0, а toUintN(v, 32) — с v >>> 0;
  • объяснено, почему для 64 разрядов спецификация берёт BigInt (ToBigInt64), а не Number: найдите, чему равно 2 ** 63 + 1 === 2 ** 63.
5. Права в группе курса
Средне12 мин

работать с флажками в одном числе.

Права ученика хранятся числом, каждому праву — свой разряд. Напишите пять функций: grant(r, ...flags) ставит флажки, revoke(r, ...flags) снимает, toggle(r, flag) переключает, has(r, flag) проверяет, names(r, table) возвращает имена поставленных флажков в порядке таблицы. Функции не меняют r, а возвращают новое число.

const R = { VIEW: 1 << 0, ANSWER: 1 << 1, EDIT: 1 << 2, SHARE: 1 << 3 };
let r = grant(0, R.VIEW, R.ANSWER);
r;                       // 3
has(r, R.EDIT);          // false
r = grant(r, R.EDIT);
r = revoke(r, R.ANSWER);
r;                       // 5
names(r, R);             // ["VIEW", "EDIT"]
toggle(r, R.SHARE);      // 13
revoke(r, R.SHARE);      // 5
  • все шесть проверяемых строк примера дают то, что в комментариях;
  • снятие написано через & ~; найдено, что даст «снятие» вычитанием r - R.VIEW у числа 0b0110, где VIEW не стоит;
  • проверено, что has и names работают и с 32-м флажком 1 << 31, хотя число с ним отрицательное.
6. «Карточки 2.0»: неделя занятий
Средне14 мин

хранить семь «да или нет» в одном числе и сдвигать его по дням.

Под колодой хотим показать полоску из семи кружков: в какие из последних семи дней ученик нажимал «Знаю». Храним её одним числом рядом с прогрессом: разряд 0 — сегодня, разряд 6 — шесть дней назад. Напишите mark(week) — отметить сегодня, nextDay(week) — наступил новый день (всё сдвигается, самый старый день уходит), streak(week) — сколько дней подряд, считая с сегодняшнего, count(week) — сколько дней из семи.

mark(0b0000000);      // 1
mark(0b0000110);      // 7
nextDay(0b1000001);   // 2       — самый старый день уходит
streak(0b0010111);    // 3
streak(0b1111110);    // 0       — сегодня занятия не было
count(0b1010101);     // 4
  • все шесть строк примера дают то, что в комментариях;
  • объяснено, что получится без маски в nextDay и почему через месяц число перестанет быть «неделей»;
  • сравнена длина записи в localStorage: JSON.stringify(week) против массива из семи true/false.
7. Что вычисляет void
Средне12 мин

проходить 13.5.2.1 по шагам и видеть GetValue.

Предскажите три строки. Для каждого void решите: что вычисляется, зовёт ли GetValue геттер и где void заканчивается по приоритету.

const log = [];
const deck = { get size() { log.push("size"); return 3; } };
const results = [void deck.size, void (deck.size + 1), void 1 + 1, typeof void 0, void 0 === undefined, [1, 2].map((x) => void x).length];
console.log(results.join("|"), log.join(" "));
try {
  void missing;
} catch (e) {
  console.log(e.name, typeof missing);
}
console.log((() => void log.push("x"))(), log.length);
  • предсказаны три строки целиком, вместе с журналом;
  • объяснено, почему в первой строке два пустых места и откуда NaN;
  • для void missing и typeof missing названы шаги 13.5.2.1 и 13.5.3.1, которые дают разный исход.

8. Сдвиги без сдвигов
Сложно10 мин

перенести 6.1.6.1.9–6.1.6.1.11 в код.

Напишите shl(x, y), sar(x, y) и shr(x, y) — свои <<, >> и >>> — без побитовых операторов, на своих ToInt32 и ToUint32 (задание 4): сдвиг на k — умножение или деление на 2k.

const xs = [9, -9, 1, -1, 2 ** 31 - 1, 3e9, 0.5, -2.5, "12"];
const ys = [0, 1, 2, 31, 32, 33, -1, 1.9];
xs.every((x) => ys.every((y) => shl(x, y) === x << y && sar(x, y) === x >> y && shr(x, y) === x >>> y));   // true
shl(1, 31);   // -2147483648
sar(-9, 2);   // -3
shr(-9, 2);   // 1073741821
  • все четыре строки примера дают то, что в комментариях;
  • объяснено, почему в sar нужен Math.floor, а не Math.trunc, и почему в shl результат ещё раз проходит ToInt32;
  • объяснено, почему умножение на 231 здесь не теряет точности, хотя произведение больше 253.
9. Незнакомый раздел: BigIntBitwiseOp
Сложно10 мин

прочитать алгоритм, который на лекции был одной фразой.

Прочитайте 6.1.6.2.17 BigIntBitwiseOp и BinaryAnd, BinaryOr, BinaryXor (6.1.6.2.14–16). Напишите bigOp(op, x, y) по его шагам, только арифметикой BigInt: без &, |, ^, ~ и сдвигов.

const pairs = [[12n, 10n], [-1n, 255n], [-256n, 15n], [5n, -2n], [-9n, -4n], [0n, -1n], [2n ** 70n + 3n, -(2n ** 40n)]];
pairs.every(([x, y]) => bigOp("&", x, y) === (x & y) && bigOp("|", x, y) === (x | y) && bigOp("^", x, y) === (x ^ y));   // true
String(bigOp("&", -1n, 255n));   // "255"
String(bigOp("|", -256n, 15n));   // "-241"
  • все три строки примера дают то, что в комментариях;
  • объяснено, почему для «x modulo 2» не годится x % 2n: что даёт -9n % 2n;
  • на паре -9n, -4n показано, что делает последний шаг с примечанием «This extends the sign».
