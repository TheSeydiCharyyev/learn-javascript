1. Мост между кодом и внутренними методами

На дне 4 мы видели внутренние методы объектов: [[Get]], [[Set]], [[DefineOwnProperty]], [[Call]] и другие. Встроенные функции зовут их не напрямую, а через операции разделов 7.3 (над объектами) и 7.4 (над итераторами). Каждая операция — короткая обёртка: вызвать внутренний метод и добавить проверку — «функция ли это», «удалось ли», «объект ли вернулся». Это словарь, на котором написана вся глава встроенных объектов: прочитав сегодня полсотни коротких алгоритмов, вы будете читать алгоритм любого метода как обычный текст.

Подробно разберём шесть операций — Get, Set, Call, Construct и записи итераторов 7.4.1, — а остальные увидим в опытах. Все 55 — в справочнике в конце, у каждой отмечено, где мы её уже встречали.

2. Get и GetV: кто получатель

Get(O, P) (7.3.2) — один шаг: O.[[Get]](P, O). Второй аргумент — получатель (receiver), он станет this геттера, даже если геттер найден в прототипе. GetV(V, P) (7.3.3) делает то же для любого значения: ищет свойство в обёртке ToObject (день 5), но получателем передаёт само значение, без обёртки.

Object.defineProperty(String.prototype, "kindStrict", { get() { "use strict"; return typeof this; }, configurable: true });
Object.defineProperty(String.prototype, "kindSloppy", { get() { return typeof this; }, configurable: true });
console.log("kitap".kindStrict, "kitap".kindSloppy);
delete String.prototype.kindStrict;
delete String.prototype.kindSloppy;
const base = { get who() { return this.name; } };
const child = { __proto__: base, name: "child" };
console.log(child.who, base.who);
string object
child undefined

Строгий геттер получил строку «как есть» — это и есть получатель GetV. Нестрогий завернул её в объект сам: так нестрогие функции поступают с примитивным this (день 2 курса 2). Вторая строка — получатель при наследовании: геттер живёт в base, а this у него — child. Встроенный прототип мы меняли только ради опыта и сразу вернули на место.

3. Set и флажок Throw

Set(O, P, V, Throw) (7.3.4) зовёт O.[[Set]](P, V, O). Внутренний метод не бросает ошибку, а отвечает true или false. Что делать с false, решает флажок: Throw = true — TypeError. Присваивание a[0] = 9 идёт мимо Set, через PutValue (день 4), и там бросает только строгий код. А встроенные функции зовут Set с true — и бросают всегда, в строгом коде и в нестрогом:

const attempt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const a = Object.freeze([1, 2]);
a[0] = 9;
console.log(a[0], attempt(() => a.push(3)));
console.log(attempt(() => Object.assign(a, { 0: 9 })));
console.log(attempt(() => a.pop()));
console.log(attempt(() => Object.defineProperty(a, "x", { value: 1 })));
1 TypeError: Cannot add property 2, object is not extensible
TypeError: Cannot assign to read only property '0' of object '[object Array]'
TypeError: Cannot delete property '1' of [object Array]
TypeError: Cannot define property x, object is not extensible

Скрипт нестрогий, и a[0] = 9 молча не сработал. push и Object.assign зовут Set с true. Тот же приём у семейства «…OrThrow»: pop удаляет последний элемент через DeletePropertyOrThrow, Object.defineProperty — через DefinePropertyOrThrow. Имя операции подсказывает поведение: «OrThrow» — ответ false превращается в ошибку.

4. Запись против определения

Свойство можно записать — Set, [[Set]]: он идёт по цепочке прототипов, находит сеттер и зовёт его, натыкается на унаследованное свойство только для чтения и отказывает. А можно определить — CreateDataProperty (7.3.5), [[DefineOwnProperty]]: собственное свойство-значение на самом объекте, прототип не спрашивается. Первое делает присваивание, второе — литералы, spread, поля классов и Object.defineProperty.

const attempt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const proto = Object.freeze({ step: 1 });
const card = Object.create(proto);
card.step = 2;
console.log(card.step, Object.hasOwn(card, "step"));
console.log(attempt(() => Object.assign(Object.create(proto), { step: 4 })));
Object.defineProperty(card, "step", { value: 3, writable: true, enumerable: true, configurable: true });
console.log(card.step, Object.hasOwn(card, "step"), { ...proto, step: 5 }.step);
1 false
TypeError: Cannot assign to read only property 'step' of object '#<Object>'
3 true 5

Унаследованное свойство только для чтения запрещает записать своё свойство с тем же именем — шаги OrdinarySetWithOwnDescriptor (10.1.9.2): у найденного в прототипе свойства [[Writable]] — false, ответ false. Но определить его можно. Практика дня — кто что вызывает, если у получателя есть сеттер, а у источника — геттер:

const log = [];
class Card {
  set word(v) { log.push("set " + v); }
}
const source = { get word() { log.push("get word"); return "kitap"; }, extra: 1 };
const a = Object.assign(new Card(), source);
console.log(Object.keys(a), log.join(" | "));
log.length = 0;
const b = { ...source };
console.log(Object.keys(b), Object.getOwnPropertyDescriptor(b, "word").value, log.join(" | "));
(1) ['extra'] get word | set kitap
(2) ['word', 'extra'] kitap get word

Геттер источника вызвали оба: и Object.assign (20.1.2.1), и spread читают через Get. Дальше пути расходятся: Object.assign пишет через Set — и сеттер класса проглотил слово, своего свойства word у a нет; spread определяет — в b лежит обычное значение «kitap». Самый неожиданный сеттер — унаследованный __proto__ (день 7 курса 2). Вспомните JSON с таким ключом из дня 31 курса 2:

const data = JSON.parse('{"__proto__": {"admin": true}, "name": "Aman"}');
const viaAssign = Object.assign({}, data);
const viaSpread = { ...data };
console.log(viaAssign.admin, Object.keys(viaAssign), viaSpread.admin, Object.keys(viaSpread));
true (1) ['name'] undefined (2) ['__proto__', 'name']

Object.assign записал ключ «__proto__» через Set — сработал сеттер из Object.prototype, и у нового объекта сменился прототип: он «стал админом». Spread определил обычное свойство с таким именем. Копируя чужие данные, выбирайте spread.

5. CopyDataProperties: spread и остаток

Spread в литерале объекта и остаток в деструктуризации (Essentials, день 22) — одна операция, CopyDataProperties (7.3.25). Её шаги: null и undefined — ничего не копировать; остальное — ToObject; ключи — в порядке [[OwnPropertyKeys]] (сначала индексы, день 4); каждое собственное перечисляемое свойство, кроме исключённых, — Get и CreateDataPropertyOrThrow. Символы тоже копируются.

const log = [];
const src = { b: 1, 2: "two", a: 1, [Symbol("s")]: 1, get g() { log.push("g"); return 0; } };
Object.defineProperty(src, "hidden", { value: 1, enumerable: false });
const { a, ...rest } = src;
console.log(Object.keys(rest), Object.getOwnPropertySymbols(rest).length, "hidden" in rest, log.join());
console.log({ ...null, ..."ab", ...[7] });
(3) ['2', 'b', 'g'] 1 false g
{0: 7, 1: 'b'}

Ключ a исключён — его забрала деструктуризация. Индекс «2» стал первым, неперечисляемый hidden пропущен, геттер вызван один раз и превратился в значение. ...null — пусто, строка раскладывается на индексы, а массив [7] записал свой индекс 0 поверх «a».

6. Call, Invoke и GetMethod

Call(F, V, argumentsList) (7.3.13): нет списка — пустой; IsCallable(F) ложно — TypeError; иначе F.[[Call]](V, argumentsList), где V — this. Invoke(V, P) (7.3.20) — GetV и Call: взять метод у значения и вызвать на нём же. GetMethod(V, P) (7.3.10) — для «необязательных» методов: undefined и null означают «метода нет», а любое другое не-функциональное значение — TypeError.

const attempt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(attempt(() => [1, 2].map(5)));
console.log(attempt(() => [...{ [Symbol.iterator]: 5 }]));
console.log(attempt(() => [...{ [Symbol.iterator]: null }]));
console.log(attempt(() => [...{ [Symbol.iterator]() { return 5; } }]));
console.log([{ toLocaleString() { return "a"; } }, { toLocaleString() { return "b"; } }].toLocaleString());
console.log(JSON.stringify({ toJSON: 5, a: 1 }));
TypeError: number 5 is not a function
TypeError: {(intermediate value)} is not iterable
TypeError: {(intermediate value)} is not iterable
TypeError: Result of the Symbol.iterator method is not an object
a,b
{"toJSON":5,"a":1}

map проверяет колбэк IsCallable до первого вызова. Для Symbol.iterator спецификация различает два случая: null — «метода нет», 5 — «метод не функция», но V8 пишет одно и то же сообщение. Метод вернул не объект — ошибку бросает GetIteratorFromMethod (раздел 12). toLocaleString массива зовёт Invoke у каждого элемента. А JSON.stringify берёт toJSON через Get и молча пропускает не-функцию — у него свои шаги, без GetMethod.

7. Construct и newTarget

Construct(F, argumentsList, newTarget) (7.3.14): F.[[Construct]](argumentsList, newTarget); без newTarget — это просто new F(...argumentsList), как сказано в примечании. Третий аргумент нужен наследованию: super() зовёт Construct родителя, но передаёт newTarget наследника — это и есть new.target (день 10 курса 2), и прототип объекта берётся у него.

const log = [];
class Deck { constructor() { log.push(new.target.name); } }
class SchoolDeck extends Deck {}
new Deck();
new SchoolDeck();
class Words extends Array {}
const w = Words.from(["a", "b"]);
console.log(log.join(" "), w instanceof Words, w.map((x) => x) instanceof Words, w.length);
class MyPromise extends Promise {}
console.log(MyPromise.resolve(1).then((x) => x) instanceof MyPromise);
Deck SchoolDeck true true 2
true

Конструктор Deck выполнился оба раза, но во втором new.target — SchoolDeck. Words.from зовёт Construct от this, то есть от Words. map наследника создаёт наследника через ArraySpeciesCreate (10.4.2.3), а then наследника Promise — через SpeciesConstructor (7.3.22): она смотрит constructor объекта и его Symbol.species (день 17).

8. freeze и isFrozen по шагам

Object.freeze (день 6 курса 2) — это SetIntegrityLevel(O, frozen) (7.3.15): [[PreventExtensions]], а потом каждому ключу DefinePropertyOrThrow с configurable: false, и только свойствам-значениям ещё writable: false. У аксессора нет [[Writable]] — его сеттер продолжает работать. TestIntegrityLevel (7.3.16) проверяет обратное: объект нерасширяемый и ни одного настраиваемого или записываемого свойства.

const log = [];
const frozen = Object.freeze({ set word(v) { log.push(v); }, get word() { return "kitap"; } });
frozen.word = "galam";
console.log(log.join(), frozen.word, Object.isFrozen(frozen), Object.getOwnPropertyDescriptor(frozen, "word").configurable);
console.log(Object.isFrozen({}), Object.isFrozen(Object.preventExtensions({})), Object.isFrozen(Object.preventExtensions({ a: 1 })));
galam kitap true false
false true false

Сеттер «замороженного» объекта получил «galam». А пустой нерасширяемый объект — уже замороженный: проверять у него нечего, и TestIntegrityLevel отвечает true.

9. OrdinaryHasInstance

instanceof (день 7 курса 2) сначала ищет у правой стороны метод Symbol.hasInstance через GetMethod, а у функций он ведёт в OrdinaryHasInstance(C, O) (7.3.21): у привязанной функции — проверить её цель; иначе взять Get(C, "prototype") и идти по цепочке прототипов O, сравнивая SameValue (день 5).

function Card() {}
const c = new Card();
const Bound = Card.bind(null);
console.log(c instanceof Card, c instanceof Bound, Object.create(Card.prototype) instanceof Card);
Card.prototype = {};
console.log(c instanceof Card);
true true true
false

instanceof не спрашивает, кто создал объект, — только чей prototype лежит в цепочке сейчас. Замените свойство prototype — и старый объект перестаёт быть «экземпляром».

10. Поля и приватные элементы

Когда конструктор доходит до своего тела (у наследника — после super()), InitializeInstanceElements (7.3.33) добавляет сначала приватные методы, потом поля по порядку объявления. Публичное поле — DefineField (7.3.32), а внутри — CreateDataPropertyOrThrow. Значит, поле класса определяется, а не записывается:

const log = [];
class Base { set word(v) { log.push("setter " + v); } }
class Card extends Base { word = "kitap"; }
class Card2 extends Base { constructor() { super(); this.word = "galam"; } }
const c1 = new Card(), c2 = new Card2();
console.log(Object.keys(c1), Object.keys(c2), log.join());
(1) ['word'] (0) [] setter galam

Поле обошло сеттер родителя, присваивание в конструкторе — нет. Приватные элементы живут в отдельном списке объекта: PrivateElementFind ищет в нём, PrivateFieldAdd добавляет и бросает, если элемент уже есть, PrivateGet и PrivateSet бросают, если его нет (день 9 курса 2). Трюк: родитель, чей конструктор возвращает чужой объект, позволяет «приклеить» приватное поле к любому объекту — но только один раз:

const attempt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
class Stamp extends class { constructor(o) { return o; } } {
  #id = 1;
  static has(o) { return #id in o; }
  static id(o) { return o.#id; }
}
const plain = {};
new Stamp(plain);
console.log(Stamp.has(plain), Stamp.id(plain), attempt(() => new Stamp(plain)));
console.log(attempt(() => Stamp.id({})));
class Box { #m() {} static set(o) { o.#m = 1; } }
console.log(attempt(() => Box.set(new Box())));
true 1 TypeError: Cannot initialize #id twice on the same object
TypeError: Cannot read private member #id from an object whose class did not declare it
TypeError: Private method '#m' is not writable

Хозяин вправе запретить такое приклеивание для своих объектов: перед добавлением PrivateFieldAdd спрашивает HostEnsureCanAddPrivateElement (7.3.29). Chrome 156 разрешает его даже для window и location.

11. GroupBy по шагам

Object.groupBy (Essentials, день 21) и Map.groupBy (день 14 курса 2) — две обёртки над одной операцией GroupBy(items, callback, keyCoercion) (7.3.35). Её шаги: RequireObjectCoercible, IsCallable колбэка, GetIterator — значит, подойдёт любой перебираемый объект, не только массив; дальше цикл: IteratorStepValue, Call(callback, undefined, «value, k»), ключ — ToPropertyKey для объекта или CanonicalizeKeyedCollectionKey для Map (−0 → +0, день 5), и AddValueToKeyedGroup (7.3.34) — найти группу по SameValue или завести новую. Практика дня — пройти это с журналом:

const attempt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const log = [];
function* cards() {
  try {
    yield { word: "kitap", deck: "school" };
    yield { word: "alma", deck: "food" };
    yield { word: "galam", deck: "school" };
  } finally {
    log.push("finally");
  }
}
const groups = Object.groupBy(cards(), (card, i) => {
  log.push(i + ":" + card.word);
  return card.deck;
});
console.log(log.join(" "), Object.getPrototypeOf(groups), Object.keys(groups));
log.length = 0;
console.log(attempt(() => Object.groupBy(cards(), (card) => { if (card.deck === "food") throw new Error("стоп"); return card.deck; })), log.join(" "));
console.log(Object.keys(Object.groupBy([1, "1", 1.0, -0, 0], (x) => x)), Map.groupBy([1, "1", -0, 0], (x) => x).size);
0:kitap 1:alma 2:galam finally null (2) ['school', 'food']
Error: стоп finally
(2) ['0', '1'] 3

Колбэк получил элемент и номер, группы появились в порядке первой встречи. Результат Object.groupBy — объект без прототипа: так написан 20.1.2.13, чтобы ключ «toString» не спорил с наследством. Ошибка в колбэке не бросила генератор открытым: шаг IfAbruptCloseIterator закрыл его, и finally выполнился. Последняя строка — разница двух видов ключей: для объекта 1, «1» и 1.0 — один ключ «1», а для Map число и строка — разные ключи, нули слились в один.

12. Записи итераторов

Перебор в спецификации держится на Iterator Record (7.4.1) — записи из трёх полей: [[Iterator]] — сам итератор, [[NextMethod]] — его метод next, [[Done]] — закончен ли он. Запись создаёт GetIterator: GetMethod (Symbol.iterator), вызов, проверка «объект ли», и GetIteratorDirect — next читается один раз, при создании записи.

Подсмотрим порядок шагов — объект результата с геттерами записывает каждое чтение:

const log = [];
const steps = {
  [Symbol.iterator]() {
    log.push("@@iterator");
    let n = 0;
    return {
      next() {
        log.push("next " + n);
        n++;
        return {
          get done() { log.push("done"); return n > 2; },
          get value() { log.push("value"); return n; },
        };
      },
    };
  },
};
for (const x of steps) log.push("body " + x);
console.log(log.join(" | "));
@@iterator | next 0 | done | value | body 1 | next 1 | done | value | body 2 | next 2 | done

Это шаги IteratorStepValue (7.4.10): IteratorNext, потом IteratorComplete — чтение done, и только если не готово — IteratorValue. На последнем шаге value не читали вовсе. А next, однажды прочитанный, уже не меняется:

const it = { n: 0, next() { return { value: ++this.n, done: this.n > 3 }; }, [Symbol.iterator]() { return this; } };
const seen = [];
for (const x of it) {
  seen.push(x);
  it.next = () => ({ done: true });
}
console.log(seen.join(" "));
1 2 3

Подмена it.next в теле цикла ничего не изменила: цикл зовёт [[NextMethod]] записи. И два правила о результате: done проходит через ToBoolean, а результат-не-объект — ошибка:

const attempt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const counter = (doneAt) => ({ [Symbol.iterator]() { let i = 0; return { next() { i++; return { value: i, done: doneAt(i) }; } }; } });
console.log([...counter((i) => (i > 2 ? "нет" : 0))].join(), [...counter(() => new Boolean(false))].length);
console.log(attempt(() => [...{ [Symbol.iterator]() { return { next() { return 5; } }; } }]));
1,2 0
TypeError: Iterator result 5 is not an object

Строка «нет» истинна — перебор кончился на третьем шаге; объект new Boolean(false) тоже истинен (день 5) — перебор кончился сразу.

13. Закрытие итератора

Если цикл выходит раньше конца, IteratorClose (7.4.11) зовёт return итератора — так генератор выполняет свой finally (день 12 курса 2). Шаги: GetMethod return — нет метода, ничего не делать; вызвать; если тело цикла бросило — вернуть его ошибку, что бы ни случилось в return; иначе — return обязан вернуть объект.

const attempt = (f) => {
  try {
    return String(f());
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const log = [];
const make = (ret) => ({
  [Symbol.iterator]() {

Во втором цикле return вернул 5 — ошибка. В третьем вернул то же 5, но тело уже бросило «тело», и оно важнее. Деструктуризация [first] взяла один элемент, итератор не кончился — она тоже закрыла его: всего четыре вызова. Для for await...of (день 29 курса 2) то же делает AsyncIteratorClose.

15. «Карточки 2.0»: поиск повторов

На дне 33 курса 2 мы искали карточки с одинаковым номером в разных файлах колод одной строкой:

// tests.js, день 33 курса 2 — поиск повторов
const twins = [...Map.groupBy(cards, (c) => c.id)].filter(([, list]) => list.length > 1);

Прочитаем её операциями главы 7. GroupBy: GetIterator массива, на каждом шаге Call колбэка и AddValueToKeyedGroup. Spread [...map]: GetIterator Map и IteratorStepValue до конца — пары «ключ, список». filter: Call для каждой пары, а деструктуризация [, list] внутри — свой GetIterator у каждой пары. Ключи Map — CanonicalizeKeyedCollectionKey, без перевода в строку. Что, если в одном файле номер записан числом, а в другом — строкой?

const cards = [{ id: 3, word: "lesson" }, { id: "3", word: "water" }, { id: 4, word: "book" }];
const twins = [...Map.groupBy(cards, (c) => c.id)].filter(([, list]) => list.length > 1);
const twinsObj = Object.entries(Object.groupBy(cards, (c) => c.id)).filter(([, list]) => list.length > 1);
console.log(twins.length, twinsObj.length, JSON.stringify(twinsObj.map(([id, list]) => [id, list.map((c) => c.word)])));
0 1 [["3",["lesson","water"]]]

Map.groupBy повтора не нашёл: 3 и «3» для него разные ключи — та же развилка, что на дне 5 с dataset. А прогресс «Карточек» хранится в Map по номеру, значит, и там эти карточки разные. Проверка честная: она ищет повторы ровно так, как их увидит прогресс. Object.groupBy перевёл ключи ToPropertyKey и нашёл «повтор», которого для Map нет. Выбирая операцию, выбираешь и правило ключей.

// Set(O, P, V, Throw): [[Set]] отвечает false, Throw = true — TypeError; встроенные функции всегда с true
// «…OrThrow»: false → TypeError (push, pop, Object.assign, defineProperty на замороженном)
// запись (Set): присваивание, Object.assign — сеттеры и прототип; определение: литерал, spread, поле класса
// CopyDataProperties: свои перечисляемые, с символами, порядок [[OwnPropertyKeys]], Get у источника
// Call: IsCallable, потом [[Call]](this, args); Invoke = GetV + Call; GetMethod: null и undefined — «нет»
// Construct(F, args, newTarget): super() передаёт newTarget наследника — new.target
// freeze: нерасширяемый + configurable false + writable false (у аксессоров сеттер жив)

// поле класса — DefineField (определение); this.x = в конструкторе — запись
// GroupBy: GetIterator, Call(cb, undefined, «v, k»), ключ ToPropertyKey (объект) или как есть (Map)

// Iterator Record: [[Iterator]], [[NextMethod]] (читается один раз), [[Done]]
// шаг: next() → объект? → ToBoolean(done) → value; досрочный выход — return(), ошибка тела важнее
  1. Почему a[0] = 9 у замороженного массива в нестрогом коде молчит, а a.push(3) бросает?
    Ответ Присваивание идёт через PutValue, а он бросает только в строгом коде. push зовёт Set с флажком Throw = true, и отказ [[Set]] становится TypeError.
  2. Чем Object.assign({}, src) отличается от { ...src }?
    Ответ Оба читают источник через Get. Object.assign записывает через Set — работают сеттеры получателя и его прототипов, в том числе __proto__. Spread определяет свойства через CreateDataPropertyOrThrow — всегда собственные свойства-значения.
  3. Почему сеттер родителя не сработал для поля класса word = "kitap"?
    Ответ Поле добавляет DefineField через CreateDataPropertyOrThrow — это определение собственного свойства, прототип не спрашивают. Сеттер вызвало бы только присваивание this.word = ….
  4. Что произойдёт, если в теле for...of заменить next у итератора?
    Ответ Ничего: GetIteratorDirect прочитал next один раз и сохранил в [[NextMethod]], цикл зовёт сохранённый.
  5. Когда for...of вызывает return итератора и чья ошибка побеждает?
    Ответ При досрочном выходе — break, return, ошибка в теле; при естественном конце — нет. Если тело бросило, побеждает ошибка тела; иначе return обязан вернуть объект, иначе TypeError.
