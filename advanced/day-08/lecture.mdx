## 1. Операции по дереву разбора {#sdo}

Модуль «Типы и абстрактные операции» закончен; начинается модуль «Выполнение кода». Его первый инструмент —
[синтаксически управляемые операции](https://tc39.es/ecma262/2026/#sec-syntax-directed-operations)
(глава 8). На дне 1 мы видели их определение (5.2.2): операция задана *кусками* — для каждого правила
грамматики свой алгоритм, — и выполняется над узлом дерева разбора (день 2). Если для правила вида «A : B» кусок
не написан, операция просто передаётся вниз, к B. Главе 8 принадлежат общие операции; остальные разбросаны по
главам языка, рядом со своими правилами.

Операции бывают двух сортов. **Статические** (Static Semantics) отвечают на вопросы о тексте —
какие имена объявлены, есть ли внутри `super`, — и работают до выполнения: на них построены ранние
ошибки. **Выполнения** (Runtime Semantics) — это Evaluation и его помощники, они работают с
окружениями и значениями.

## 2. Evaluation и статическая семантика {#evaluation}

[Evaluation](https://tc39.es/ecma262/2026/#sec-evaluation) (8.1) — главная операция выполнения:
она возвращает Completion Record (день 4). Раздел 8.1 пуст и только объясняет, что куски Evaluation стоят по всей
спецификации, сразу после своих правил: Evaluation сложения — в 13.8, `if` — в 14.6. Статические
операции проверяют текст до того, как выполнится хоть одна строка. Это видно, если разобрать код, не запуская
его, — помощник `parse` из дня 2:

```js
const parse = (code) => {
  try {
    new Function(code);
    return "ok";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(parse('console.log("раз"); let a; let a;'));
console.log(parse('console.log("раз"); null.x;'));
```

<ResultBox>
SyntaxError: Identifier 'a' has already been declared\
ok
</ResultBox>

Первая строка — ранняя ошибка, её нашла статическая семантика; второй код синтаксически верен, а ошибка
`null.x` случится только при выполнении. Слово «раз» не напечатано ни там, ни там:
`new Function` только разбирает тело. Помните: `parse` проверяет код как *тело
функции*, а не как скрипт, — в разделах 6 и 9 это будет важно.

## 3. BoundNames: какие имена объявлены {#bound}

[Анализ областей](https://tc39.es/ecma262/2026/#sec-syntax-directed-operations-scope-analysis)
(8.2) начинается с [BoundNames](https://tc39.es/ecma262/2026/#sec-static-semantics-boundnames)
(8.2.1): список имён, которые связывает объявление. Для `let x = 1` — «x», для деструктуризации — все
имена шаблона, для функции — её имя, для параметров — все имена параметров. Повтор в списке — первая ранняя
ошибка:

```js
const parse = (code) => {
  try {
    new Function(code);
    return "ok";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(parse("let [a, a] = [];"), "|", parse("let { x, y: x } = {};"));
console.log(parse("(function (a, { b: a }) {})"), "|", parse("(function (a, a) {})"));
```

<ResultBox>
SyntaxError: Identifier 'a' has already been declared | SyntaxError: Identifier 'x' has already been declared\
SyntaxError: Duplicate parameter name not allowed in this context | ok
</ResultBox>

| Объявление | BoundNames |
| --- | --- |
| `let { a, b: [c, ...d] } = o;` | «a, c, d» — ключ `b` не имя |
| `function f(x, { y } = {}, ...z) {}` | «f»; у списка параметров — «x, y, z» |
| `class Card {}` | «Card» |
| `import x, { y as z } from "./m.js";` | «x, z» — местные имена, а не внешние |
| `export default function () {}` | «\*default\*» — служебное имя |

Последняя строка — из примечания к 8.2.1: так спецификация называет безымянный экспорт по умолчанию, из кода
это имя не увидеть. А последний ответ опыта неожиданный: два параметра `a` в нестрогой функции с
простым списком параметров разрешены — наследие старого языка, о нём в разделе 12.
[IsConstantDeclaration](https://tc39.es/ecma262/2026/#sec-static-semantics-isconstantdeclaration)
(8.2.3) отвечает, константа ли объявление (`const` — да, `let` и функции — нет), а
[DeclarationPart](https://tc39.es/ecma262/2026/#sec-static-semantics-declarationpart) (8.2.2) выдаёт
сам узел объявления.

## 4. Лексические имена и имена var {#lexvar}

Две главные операции раздела собирают имена всего тела.
[LexicallyDeclaredNames](https://tc39.es/ecma262/2026/#sec-static-semantics-lexicallydeclarednames)
(8.2.4) — имена `let`, `const`, `class` и функций *этого* блока: во
вложенные блоки она не заглядывает. [VarDeclaredNames](https://tc39.es/ecma262/2026/#sec-static-semantics-vardeclarednames)
(8.2.6) — имена `var`, и она, наоборот, проходит сквозь блоки, `if`, циклы и
`try` до границы функции или скрипта. Рядом живут
[LexicallyScopedDeclarations](https://tc39.es/ecma262/2026/#sec-static-semantics-lexicallyscopeddeclarations)
и [VarScopedDeclarations](https://tc39.es/ecma262/2026/#sec-static-semantics-varscopeddeclarations)
(8.2.5, 8.2.7) — те же списки, но из самих объявлений, а не из имён: по ним создаются привязки.

<Scheme src="scheme-lexvar.svg">Куда попадают имена: var поднимается до функции, let остаётся в блоке</Scheme>

На этих списках стоят ранние ошибки блока ([14.2.1](https://tc39.es/ecma262/2026/#sec-block-static-semantics-early-errors)):
повтор в LexicallyDeclaredNames — ошибка; имя, которое есть и в LexicallyDeclaredNames, и в VarDeclaredNames
блока, — ошибка. У функции ([15.2.1](https://tc39.es/ecma262/2026/#sec-function-definitions-static-semantics-early-errors))
добавляется третье правило: имя параметра не может повториться среди лексических имён тела.

Списки нужны и при выполнении. [Evaluation
блока](https://tc39.es/ecma262/2026/#sec-block-runtime-semantics-evaluation) (14.2.2) при каждом входе создаёт новое окружение и зовёт
[BlockDeclarationInstantiation](https://tc39.es/ecma262/2026/#sec-blockdeclarationinstantiation) — она
заводит в нём привязки по LexicallyScopedDeclarations. Имена `var` создаются один раз на всю функцию
или скрипт. Отсюда разница замыканий (день 1 курса 2) в цикле:

```js
const byLet = [];
const byVar = [];
for (var i = 0; i < 3; i++) {
  let copy = i;
  var shared = i;
  byLet.push(() => copy);
  byVar.push(() => shared);
}
console.log(byLet.map((f) => f()).join(), byVar.map((f) => f()).join());
```

<ResultBox>
0,1,2 2,2,2
</ResultBox>

Три прохода тела — три окружения блока и три разных `copy`; `shared` — одна привязка на
всех, и все три стрелки видят её последнее значение.

## 5. Повторные объявления {#redeclare}

Практика дня — повторные объявления `let` и `var` в одном блоке и в разных. Сначала
предскажите каждую строку по двум правилам 14.2.1 и третьему из 15.2.1:

```js
const parse = (code) => {
  try {
    new Function(code);
    return "ok";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const cases = ["let x; let x;", "let x; var x;", "var x; var x;", "var x; { let x; }", "{ let x; } { let x; }",
  "{ var x; } let x;", "switch (1) { case 1: let a; break; case 2: let a; }", "try {} catch (e) { let e; }",
  "try {} catch (e) { var e; }", "for (let i = 0; i < 1; i++) { let i; }", "(function (p) { let p; })", "(function (p) { var p; })"];
for (const c of cases) console.log(c, "→", parse(c));
```

<ResultBox>
let x; let x; → SyntaxError: Identifier 'x' has already been declared\
let x; var x; → SyntaxError: Identifier 'x' has already been declared\
var x; var x; → ok\
var x; \{ let x; \} → ok\
\{ let x; \} \{ let x; \} → ok\
\{ var x; \} let x; → SyntaxError: Identifier 'x' has already been declared\
switch (1) \{ case 1: let a; break; case 2: let a; \} → SyntaxError: Identifier 'a' has already been declared\
try \{\} catch (e) \{ let e; \} → SyntaxError: Identifier 'e' has already been declared\
try \{\} catch (e) \{ var e; \} → ok\
for (let i = 0; i \< 1; i++) \{ let i; \} → ok\
(function (p) \{ let p; \}) → SyntaxError: Identifier 'p' has already been declared\
(function (p) \{ var p; \}) → ok
</ResultBox>

Повтор `var` безвреден: VarDeclaredNames могут повторяться. `{ var x; } let x;` — ошибка,
хотя `var` во вложенном блоке: VarDeclaredNames проходит сквозь блок и встречает лексический
`x` наверху. Все ветки `switch` — один блок, поэтому две `let a` в разных
`case` сталкиваются. `catch (e) { var e; }` разрешено приложением B (день 31). А
`let i` в теле цикла живёт в своём блоке, отдельно от `let i` заголовка.

## 6. Функции наверху — как var {#toplevel}

Четыре операции 8.2.8–8.2.11 —
[TopLevelLexicallyDeclaredNames](https://tc39.es/ecma262/2026/#sec-static-semantics-toplevellexicallydeclarednames),
[TopLevelLexicallyScopedDeclarations](https://tc39.es/ecma262/2026/#sec-static-semantics-toplevellexicallyscopeddeclarations),
[TopLevelVarDeclaredNames](https://tc39.es/ecma262/2026/#sec-static-semantics-toplevelvardeclarednames),
[TopLevelVarScopedDeclarations](https://tc39.es/ecma262/2026/#sec-static-semantics-toplevelvarscopeddeclarations)
— нужны для верхнего уровня тела функции и скрипта. Примечание к 8.2.8 говорит главное: на верхнем уровне
объявления функций считаются как `var`, а не как лексические. В блоке — наоборот. А модуль пользуется
обычными LexicallyDeclaredNames, и там функция — лексическое имя:

```js
const parse = (code) => {
  try {
    new Function(code);
    return "ok";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(parse("function f() {} var f;"), "|", parse("{ function f() {} var f; }"));
console.log(parse("{ function f() {} function f() {} }"), "|", parse("'use strict'; { function f() {} function f() {} }"));
import("data:text/javascript,function f(){} var f;").catch((e) => console.log("модуль:", `${e.name}: ${e.message}`));
```

<ResultBox>
ok | SyntaxError: Identifier 'f' has already been declared\
ok | SyntaxError: Identifier 'f' has already been declared\
модуль: SyntaxError: Identifier 'f' has already been declared
</ResultBox>

Одна и та же пара «`function f` и `var f`» верна наверху функции и ошибочна в блоке и в
модуле. Вторая строка — исключение из 14.2.1: в браузере, в нестрогом коде, повтор в блоке разрешён, если оба
имени — объявления функций (снова приложение B). Модуль загружен из адреса `data:` — так проще всего
проверить текст модуля без файла (динамический `import()` — день 31 курса 2).

## 7. Откуда «подъём» {#hoisting}

«Подъём» (Essentials, дни 4 и 12) — не перестановка строк, а следствие этих списков. Перед тем как выполнять
тело, движок создаёт привязки: для имён из VarDeclaredNames — со значением `undefined`, для
лексических — без значения (мёртвая зона), а для объявлений функций сразу зовёт
[InstantiateFunctionObject](https://tc39.es/ecma262/2026/#sec-runtime-semantics-instantiatefunctionobject)
(8.6.1) — функция готова до первой строки. Сами шаги этого создания — FunctionDeclarationInstantiation и
GlobalDeclarationInstantiation — дни 12 и 13.

```js
console.log(typeof later, typeof ready, ready(), typeof nowhere);
var later = 1;
function ready() { return "готова"; }
try {
  console.log(early);
} catch (e) {
  console.log(`${e.name}: ${e.message}`);
}
let early = 1;
```

<ResultBox>
undefined function готова undefined\
ReferenceError: Cannot access 'early' before initialization
</ResultBox>

`later` есть, но пока `undefined`; `ready` — уже функция; `nowhere`
не объявлено нигде — `typeof` не бросает (день 4). А `early` есть в списке, но ещё без
значения — ReferenceError мёртвой зоны.

## 8. Метки {#labels}

Раздел [8.3](https://tc39.es/ecma262/2026/#sec-syntax-directed-operations-labels) — три проверки
меток (Essentials, день 10): [ContainsDuplicateLabels](https://tc39.es/ecma262/2026/#sec-static-semantics-containsduplicatelabels)
— одна метка внутри другой с тем же именем;
[ContainsUndefinedBreakTarget](https://tc39.es/ecma262/2026/#sec-static-semantics-containsundefinedbreaktarget)
— `break` на метку, которой нет вокруг;
[ContainsUndefinedContinueTarget](https://tc39.es/ecma262/2026/#sec-static-semantics-containsundefinedcontinuetarget)
— `continue` на метку, которая стоит не на цикле.

```js
const parse = (code) => {
  try {
    new Function(code);
    return "ok";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const cases = ["a: a: ;", "a: { b: ; } a: ;", "break nope;", "a: { break a; }", "a: { continue a; }",
  "a: for (;;) { continue a; }", "a: for (;;) { (() => { break a; }); }"];
for (const c of cases) console.log(c, "→", parse(c));
```

<ResultBox>
a: a: ; → SyntaxError: Label 'a' has already been declared\
a: \{ b: ; \} a: ; → ok\
break nope; → SyntaxError: Undefined label 'nope'\
a: \{ break a; \} → ok\
a: \{ continue a; \} → SyntaxError: Illegal continue statement: 'a' does not denote an iteration statement\
a: for (;;) \{ continue a; \} → ok\
a: for (;;) \{ (() => \{ break a; \}); \} → SyntaxError: Undefined label 'a'
</ResultBox>

Две метки `a` подряд, а не одна в другой, — не повтор. `break` выходит из любого
помеченного блока, `continue` — только к циклу. Последняя строка: метки не видны сквозь границу
функции, даже стрелки.

## 9. Contains: super и new.target {#contains}

[Contains](https://tc39.es/ecma262/2026/#sec-syntax-directed-operations-contains) (8.5) отвечает,
есть ли в узле данный символ грамматики. По умолчанию — обход всех детей, но
[8.5.1](https://tc39.es/ecma262/2026/#sec-static-semantics-contains) делает два исключения:
внутрь определений функций он не заглядывает (примечание 1), а стрелку проходит насквозь, если ищут
`this`, `new.target` или `super`. На этом стоят ранние ошибки «`super`
вне метода» и «`new.target` вне функции»:

```js
const parse = (code) => {
  try {
    new Function(code);
    return "ok";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
console.log(parse("class A extends B { constructor() { () => super(); } }"), "|", parse("class A extends B { constructor() { function g() { super(); } } }"));
console.log(parse("class A { constructor() { super(); } }"), "|", parse("new.target"));
const script = document.createElement("script");
script.textContent = "new.target";
document.body.append(script);
```

<ResultBox>
ok | SyntaxError: 'super' keyword unexpected here\
SyntaxError: 'super' keyword unexpected here | ok\
Uncaught SyntaxError: Failed to execute 'append' on 'Element': new.target expression is not allowed here
</ResultBox>

`super()` в стрелке внутри конструктора наследника законен: стрелка прозрачна. В обычной вложенной
функции — нет. `new.target` в `parse` прошёл — ведь это тело функции, а настоящий скрипт с
той же строкой не разобрался (Chrome сообщает об этом от имени `append`, который его вставил). [ComputedPropertyContains](https://tc39.es/ecma262/2026/#sec-static-semantics-computedpropertycontains)
(8.5.2) — то же, но только по вычисляемым ключам класса.

## 10. Вывод имени функции {#naming}

Раздел [8.4](https://tc39.es/ecma262/2026/#sec-syntax-directed-operations-function-name-inference)
объясняет свойство `name` (день 4 курса 2). Четыре проверки:
[IsFunctionDefinition](https://tc39.es/ecma262/2026/#sec-static-semantics-isfunctiondefinition) — это
определение функции или класса (скобки вокруг не мешают);
[HasName](https://tc39.es/ecma262/2026/#sec-static-semantics-hasname) — у него есть своё имя;
[IsAnonymousFunctionDefinition](https://tc39.es/ecma262/2026/#sec-isanonymousfunctiondefinition) — первое
без второго; [IsIdentifierRef](https://tc39.es/ecma262/2026/#sec-static-semantics-isidentifierref) — слева
просто имя, а не `obj.x`. Если безымянное определение стоит там, где известно имя,
[NamedEvaluation](https://tc39.es/ecma262/2026/#sec-runtime-semantics-namedevaluation) (8.4.5) создаёт
функцию сразу с этим именем. Такие места: инициализатор `let`, `const`, `var`;
присваивание `=`, `&&=`, `||=`, `??=` простому имени; ключ в
литерале; значение по умолчанию в деструктуризации и у параметра; поле класса. Практика дня — дюжина имён:

```js
const arrow = () => {};
const expr = function () {};
const named = function inner() {};
const paren = (function () {});
const obj = { method() {}, prop: () => {}, ["co" + "mputed"]: () => {}, [Symbol("tag")]: () => {}, get size() { return 1; } };
let byOr;
byOr ||= () => {};
const { fromDefault = () => {} } = {};
class Card { static #hidden() {} static field = () => {}; static hiddenName() { return Card.#hidden.name; } }
const symbolKey = Object.getOwnPropertySymbols(obj)[0];
const show = (list) => list.map((f) => JSON.stringify(f.name)).join(" ");
console.log(show([arrow, expr, named, paren]));
console.log(show([obj.method, obj.prop, obj.computed, obj[symbolKey], Object.getOwnPropertyDescriptor(obj, "size").get]));
console.log(show([byOr, fromDefault, Card.field, arrow.bind(null)]), Card.hiddenName());
```

<ResultBox>
"arrow" "expr" "inner" "paren"\
"method" "prop" "computed" "\[tag\]" "get size"\
"byOr" "fromDefault" "field" "bound arrow" #hidden
</ResultBox>

Своё имя важнее: `inner`, а не `named`. Скобки пропускают имя дальше — так написан
первый кусок NamedEvaluation. Вычисляемый ключ дал «computed», символ — описание в скобках, геттер — приставку
«get», приватный метод — «#hidden». Приставки и скобки добавляет
[SetFunctionName](https://tc39.es/ecma262/2026/#sec-setfunctionname) (10.2.9), а «bound» — `bind`
(дни 2 и 4 курса 2).

Ещё одно место с именем — `export default`: для безымянного определения шаги
[16.2.3.7](https://tc39.es/ecma262/2026/#sec-exports-runtime-semantics-evaluation) зовут NamedEvaluation
с именем «default». Проверим на модулях из адресов `data:`:

```js
const sources = ["export default () => {}", "export default function () {}", "export default class {}", "export default (0, function () {})"];
Promise.all(sources.map((code) => import(`data:text/javascript,${code}`)))
  .then((modules) => console.log(modules.map((m) => JSON.stringify(m.default.name)).join(" ")));
```

<ResultBox>
"default" "default" "default" ""
</ResultBox>

## 11. Где имени не будет {#noname}

Достаточно нарушить одно из условий. Запятая и `||` — уже не определение функции, а другое
выражение: IsFunctionDefinition ложно. `obj.later =` — слева не простое имя: IsIdentifierRef ложно.
Аргумент вызова и элемент массива — не места с именем.

```js
const comma = (0, function () {});
const either = null || function () {};
const obj = {};
obj.later = function () {};
const list = [function () {}];
let reassigned = function () {};
reassigned = () => {};
const D = class { static name = "мой"; };
const show = (all) => all.map((f) => JSON.stringify(f.name)).join(" ");
console.log(show([comma, either, obj.later, list[0], reassigned]), D.name);
console.log(JSON.stringify(Object.getOwnPropertyDescriptor(comma, "name")), JSON.stringify(new Function().name));
```

<ResultBox>
"" "" "" "" "reassigned" мой\
\{"value":"","writable":false,"enumerable":false,"configurable":true\} "anonymous"
</ResultBox>

Повторное присваивание `reassigned = () => {}` — тоже место с именем, и новая стрелка получила
«reassigned». Статическое поле `name` класса заменило выведенное имя. Безымянная функция всё равно
имеет своё свойство `name` — пустую строку, только для чтения. А `new Function` по своим
шагам называет функцию «anonymous».

## 12. Привязки и параметры {#binding}

Раздел [8.6](https://tc39.es/ecma262/2026/#sec-syntax-directed-operations-miscellaneous) собирает
операции, которым не нашлось другого места.
[BindingInitialization](https://tc39.es/ecma262/2026/#sec-runtime-semantics-bindinginitialization) (8.6.2)
кладёт значение в имена шаблона, а для массивного шаблона зовёт
[IteratorBindingInitialization](https://tc39.es/ecma262/2026/#sec-runtime-semantics-iteratorbindinginitialization)
(8.6.3) — с GetIterator и IteratorClose дня 7. Примечания к обеим говорят о старом случае: если окружения нет,
значение пишется через PutValue — так у `var` и у параметров нестрогих функций, где имена могут
повторяться:

```js
const parse = (code) => {
  try {
    new Function(code);
    return "ok";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
function sloppy(a, a) { return a; }
console.log(sloppy(1, 2), "|", parse("'use strict'; function s(a, a) {}"));
console.log(parse("function s(a, [a]) {}"), "|", parse("(a, a) => 1"));
```

<ResultBox>
2 | SyntaxError: Duplicate parameter name not allowed in this context\
SyntaxError: Duplicate parameter name not allowed in this context | SyntaxError: Duplicate parameter name not allowed in this context
</ResultBox>

Второй `a` перезаписал первый — побеждает последний. Строгий код, сложный список параметров и
стрелки повторов не разрешают.

## 13. Куда можно присваивать {#targets}

[AssignmentTargetType](https://tc39.es/ecma262/2026/#sec-static-semantics-assignmenttargettype) (8.6.4)
решает, можно ли присваивать выражению: *simple* — имя и обращение к свойству, *invalid* —
остальное, и ранняя ошибка. Есть третий ответ — *web-compat*: вызов функции в нестрогом коде браузера. Это
необязательная часть стандарта из приложения B ([B.3.9
Runtime Errors for Function Call Assignment Targets](https://tc39.es/ecma262/2026/#sec-runtime-errors-for-function-call-assignment-targets), приложение — день 31): старые сайты писали `f() = 1` в ветках, которые не
выполнялись, и ранняя ошибка сломала бы их целиком.

```js
const parse = (code) => {
  try {
    new Function(code);
    return "ok";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const cases = ["1 = 2;", "a?.b = 1;", "(a) = 1;", "(a, b) = 1;", "a++ = 1;", "[a, b] = [1, 2];", "f() = 1;", "'use strict'; f() = 1;"];
for (const c of cases) console.log(c, "→", parse(c));
const log = [];
const f = () => { log.push("f вызвана"); return {}; };
try {
  f() = 1;
} catch (e) {
  console.log(`${e.name}: ${e.message}`, "|", log.join());
}
```

<ResultBox>
1 = 2; → SyntaxError: Invalid left-hand side in assignment\
a?.b = 1; → SyntaxError: Invalid left-hand side in assignment\
(a) = 1; → ok\
(a, b) = 1; → SyntaxError: Invalid left-hand side in assignment\
a++ = 1; → SyntaxError: Invalid left-hand side in assignment\
\[a, b\] = \[1, 2\]; → ok\
f() = 1; → ok\
'use strict'; f() = 1; → ok\
ReferenceError: Invalid left-hand side in assignment | f вызвана
</ResultBox>

Скобки вокруг имени не мешают, запятая — мешает. `f() = 1` разобран, а при выполнении шаг 13.15.2
сначала вычислил левую часть — `f` вызвана, — и только потом бросил ReferenceError. Предпоследняя строка
— расхождение Chrome с текстом: по 8.6.4 в строгом коде вызов — *invalid*, то есть ранняя ошибка, а
Chrome 156 и здесь откладывает ошибку до выполнения. Текст стандарта и реализация не всегда совпадают (день 1).

## 14. PropName и const {#propname}

[PropName](https://tc39.es/ecma262/2026/#sec-static-semantics-propname) (8.6.5) — имя свойства,
известное по тексту: у `a: 1` и `"a": 1` — «a», у вычисляемого `[k]: 1` — пусто.
На нём держится единственная ранняя ошибка о повторе ключей в литерале объекта: двух
`__proto__: значение` (день 7 курса 2). А `const` без значения ловит грамматика объявления; присваивание
константе — уже ошибка выполнения:

```js
const parse = (code) => {
  try {
    new Function(code);
    return "ok";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const cases = ["({ __proto__: a, __proto__: b })", "({ __proto__: a, '__proto__': b })", "({ __proto__: a, ['__proto__']: b })",
  "({ __proto__, __proto__: b })", "({ a: 1, a: 2 })", "const c;"];
for (const c of cases) console.log(c, "→", parse(c));
const fixed = 1;
try {
  fixed = 2;
} catch (e) {
  console.log(`${e.name}: ${e.message}`);
}
```

<ResultBox>
(\{ \_\_proto\_\_: a, \_\_proto\_\_: b \}) → SyntaxError: Duplicate \_\_proto\_\_ fields are not allowed in object literals\
(\{ \_\_proto\_\_: a, '\_\_proto\_\_': b \}) → SyntaxError: Duplicate \_\_proto\_\_ fields are not allowed in object literals\
(\{ \_\_proto\_\_: a, \['\_\_proto\_\_'\]: b \}) → ok\
(\{ \_\_proto\_\_, \_\_proto\_\_: b \}) → ok\
(\{ a: 1, a: 2 \}) → ok\
const c; → SyntaxError: Missing initializer in const declaration\
TypeError: Assignment to constant variable.
</ResultBox>

Строка в кавычках — та же запись «ключ: значение» с PropName «\_\_proto\_\_». У вычисляемого ключа PropName
пустой, а сокращённая запись `{ __proto__ }` хоть и даёт «\_\_proto\_\_», но правило
[13.2.5.1](https://tc39.es/ecma262/2026/#sec-object-initializer-static-semantics-early-errors) считает
только записи «ключ: значение». Обе создают обычное свойство, а не меняют прототип. Повтор обычного ключа
`a` разрешён — побеждает последний.

## 15. «Карточки 2.0»: имена в main.js {#cards}

В `main.js` «Карточек 2.0» (день 33 курса 2) рядом стоят оба вида функций:

```js
// main.js, день 33 курса 2 — заглушки и слушатели
function render() {
async function openDeck() {
knowButton.addEventListener("click", () => {
```

Прочитаем их операциями главы 8. `main.js` — модуль, поэтому `render` и
`openDeck` — лексические имена: второй `render` или `var render` в том же файле
— ранняя ошибка. Но привязка функции создаётся со значением ещё до первой строки модуля (InstantiateFunctionObject
при его подготовке), поэтому слушатели могут звать `render`, объявленную ниже. А сами слушатели —
стрелки в аргументе вызова: места с именем нет, и `name` у них пустой. Проверим то же на модели:

```js
const listeners = [];
const listen = (type, handler) => listeners.push(handler);
listen("click", () => {});
const onKnow = () => {};
listen("click", onKnow);
console.log(listeners.map((h) => JSON.stringify(h.name)).join(" "), render.name, typeof render);
function render() {}
```

<ResultBox>
"" "onKnow" render function
</ResultBox>

Безымянный слушатель работе не мешает, но убрать его через `removeEventListener` нечем: нужна та
же функция, а она нигде не сохранена. Если слушателя придётся снимать или искать при отладке, дайте ему имя
константой, как `onKnow`.

<Selfcheck>
1. Почему `{ var x; } let x;` — ошибка, а `var x; { let x; }` — нет?
   <Answer>VarDeclaredNames проходит сквозь блок, и `x` из `var` попадает в список верхнего
   уровня, где уже есть лексический `x`. Во втором случае `let x` — в своём блоке,
   а в этом блоке нет `var x`.</Answer>
2. Почему `function f() {} var f;` допустимо наверху функции, но не в блоке и не в модуле?
   <Answer>На верхнем уровне тела функции и скрипта объявления функций считаются как `var` (8.2.8), и
   повтор двух var-имён разрешён. В блоке и в модуле функция — лексическое имя, и встреча с
   `var` того же имени — ранняя ошибка.</Answer>
3. Какое `name` у `(0, function () {})`, присвоенной константе, и почему?
   <Answer>Пустая строка. Выражение с запятой — не определение функции, IsFunctionDefinition ложно, и
   NamedEvaluation не вызывается.</Answer>
4. Почему `super()` в стрелке внутри конструктора наследника законен, а во вложенной функции — нет?
   <Answer>Contains не заглядывает внутрь функций, но стрелку проходит насквозь, если ищут `super`,
   `this` или `new.target`. Значит, `super()` в стрелке «принадлежит»
   конструктору, а во вложенной функции — ей самой, и там он запрещён.</Answer>
5. Что произойдёт при `f() = 1` в нестрогом коде?
   <Answer>Код разберётся: у вызова AssignmentTargetType web-compat. При выполнении левая часть вычислится —
   `f` будет вызвана, — и потом ReferenceError.</Answer>
</Selfcheck>
