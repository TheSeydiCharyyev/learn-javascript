1. Модель выполнения

Вчера — что спецификация знает о коде до запуска. Сегодня — в чём код выполняется. Курс 2 (день 28) показал «один поток и две очереди» и оставил на потом страницу MDN JavaScript execution model. Она — главный материал дня вместе с главой 9 спецификации.

Выполнение — работа двух программ: движка (в Chrome — V8) и хозяина — браузера со стандартом HTML (день 1). Каждого самостоятельного исполнителя JavaScript стандарт зовёт агентом. У агента три структуры данных: куча объектов, очередь заданий (в HTML — цикл событий) и стек контекстов выполнения — тот самый стек вызовов. Агент похож на поток; внутри него живёт один или несколько реалмов — по одному на глобальный объект.

2. Реалм

Раздел 9.3: прежде чем выполниться, всякий код связан с реалмом. Реалм — набор встроенных объектов, глобальное окружение и весь код, загруженный в нём. В спецификации это Realm Record с полями таблицы 19:

ПолеЧто хранит
[[AgentSignifier]]какой агент владеет реалмом
[[Intrinsics]]встроенные объекты: %Array%, %Object.prototype% — те, что в знаках процента (день 4)
[[GlobalObject]] и [[GlobalEnv]]глобальный объект и глобальная запись окружения (день 3 курса 2)
[[TemplateMap]]массивы строк тегированных шаблонов — раздел 6
[[LoadedModules]]модули, которые загрузил import(), когда нет активного скрипта
[[HostDefined]]место для данных хозяина

В вебе реалм и глобальный объект — один к одному: у каждого окна, рамки iframe и фонового потока свой. Рамка без адреса открывает пустую страницу того же источника, что и наша, и к её глобальному объекту есть доступ — contentWindow:

const frame = document.createElement("iframe");
document.body.append(frame);
const other = frame.contentWindow;
console.log(other === window, other.Array === Array, other.Object.prototype === Object.prototype);
console.log(typeof other.Array, typeof other.document, other.globalThis === other);
false false false
function object true

Всё встроенное в рамке — своё: другой Array, другой Object.prototype, свой globalThis. Курс 2 уже встречал это мельком: на дне 26 ошибка из рамки не прошла instanceof Error. Теперь видно почему.

3. Два реалма: instanceof и Array.isArray

Практика плана. Массив создан конструктором рамки и попал на страницу:

const frame = document.createElement("iframe");
document.body.append(frame);
const other = frame.contentWindow;
const list = other.Array.of(1, 2, 3);
const fake = Object.create(Array.prototype);
console.log(list instanceof Array, list instanceof other.Array, Array.isArray(list));
console.log(fake instanceof Array, Array.isArray(fake), Object.prototype.toString.call(list));
const error = new other.Error("из рамки");
console.log(error instanceof Error, Error.isError(error));
false true true
true false [object Array]
false true

instanceof ведёт в OrdinaryHasInstance (день 7): ищет в цепочке list объект Array.prototype нашего реалма, а цепочка ведёт к Array.prototype рамки. Array.isArray зовёт IsArray (7.2.2), а та спрашивает сам объект: экзотический ли это массив (день 15), — реалм тут ни при чём. Поэтому подделка с чужим прототипом проходит instanceof и не проходит isArray. Так же устроен Error.isError: клеймо [[ErrorData]] вместо цепочки (день 26 курса 2). Вывод: данные, которые могли прийти из другого окна, проверяют Array.isArray и Error.isError, а не instanceof.

4. Текущий реалм

Реалм выполняемого контекста называется текущим (current Realm Record, раздел 9.4). Каждая функция помнит реалм, где создана, — поле [[Realm]], — и её вызов создаёт контекст с этим реалмом, кто бы её ни вызвал. Встроенные функции тоже: шаги BuiltinCallOrConstruct (10.3.3) берут F.[[Realm]]. Значит, объекты и ошибки создаёт реалм той функции, что работает сейчас:

const frame = document.createElement("iframe");
document.body.append(frame);
const other = frame.contentWindow;
const makeList = other.Function("return [1, 2];");
const whoIsThis = other.Function("return this;");
console.log(makeList() instanceof Array, makeList() instanceof other.Array, whoIsThis() === other);
try {
  other.Function("null.x;")();
} catch (e) {
  console.log(e instanceof TypeError, e instanceof other.TypeError);
}
try {
  other.Array.prototype.map.call(null);
} catch (e) {
  console.log(e instanceof TypeError, e instanceof other.TypeError);
}
false true true
false true
false true

other.Function — конструктор рамки, и функции из него принадлежат рамке. Литерал [1, 2] внутри берёт %Array.prototype% текущего реалма — рамки. this нестрогой функции, вызванной без объекта, — OrdinaryCallBindThis (10.2.1.2): глобальное this реалма функции, а не того, кто звал. Обе ошибки TypeError — рамки: и брошенная её кодом, и брошенная её встроенным map. Вот и обещанный ответ дня 4: %Array% — объект текущего реалма, а не то, что лежит в переменной Array.

5. Чей массив вернёт map

На дне 7 была операция GetFunctionRealm (7.3.24) — реалм функции (у привязанной — её цели). Главное её место — ArraySpeciesCreate (10.4.2.3). Её зовут map, filter, slice, splice, concat, flat и flatMap: результат делается конструктором исходного массива. Но с исключением: если этот конструктор — %Array% другого реалма, он отбрасывается, и массив создаётся в текущем реалме.

const frame = document.createElement("iframe");
document.body.append(frame);
const other = frame.contentWindow;
const list = other.Array.of(1, 2, 3);
const own = list.map((x) => x * 2);
const borrowed = Array.prototype.map.call(list, (x) => x * 2);
console.log(own instanceof Array, own instanceof other.Array);
console.log(borrowed instanceof Array, borrowed instanceof other.Array);
console.log([...list] instanceof Array, Array.from(list) instanceof Array);
false true
true false
true true

list.map — метод рамки (он из цепочки list): текущий реалм — рамка, конструктор — её же Array, реалмы совпали — массив рамки. Array.prototype.map.call — метод страницы: текущий реалм — страница, а конструктор — %Array% рамки, и шаг 4 подменяет его обычным массивом страницы. Примечание к 10.4.2.3 объясняет зачем: так браузеры вели себя исторически, и стандарт сохранил это ради совместимости. Spread и Array.from конструктор исходного массива не спрашивают вовсе.

6. Как рождается реалм

Новый реалм создаёт хозяин — как правило, для каждого окна, рамки и новой страницы в них — операцией InitializeHostDefinedRealm (9.3.1):

  1. новая Realm Record и CreateIntrinsics (9.3.2) — все встроенные объекты заново, по таблице 6;
  2. метка агента и пустой [[TemplateMap]];
  3. новый контекст выполнения (Function и ScriptOrModule — null) — на стек;
  4. глобальный объект и значение this верхнего уровня: свои даёт хозяин (браузер — Window), иначе — обычный объект;
  5. глобальное окружение и SetDefaultGlobalBindings (9.3.3) — свойства главы 19 на глобальном объекте; потом — свойства хозяина (document, setTimeout).

Шаг 4 браузер использует так: глобальный объект — Window, а this и contentWindow — посредник WindowProxy (стандарт HTML), который переживает переход рамки на другую страницу. Проверим:

const frame = document.createElement("iframe");
document.body.append(frame);
const w = frame.contentWindow;
const OldArray = w.Array;
w.mark = "старый";
frame.addEventListener("load", () => {
  console.log(w === frame.contentWindow, w.Array === OldArray, w.mark, w.document.body.textContent);
});
frame.srcdoc = "<p>новая страница</p>";
true false undefined новая страница

Ссылка w та же, но за ней уже другой реалм: новый Array, нет свойства mark. Атрибуты свойств из шага 5 тоже заданы текстом главы 19:

const attrs = (name) => {
  const d = Object.getOwnPropertyDescriptor(globalThis, name);
  return `${name}: ${d.writable} ${d.enumerable} ${d.configurable}`;
};
console.log(attrs("NaN"), "|", attrs("globalThis"), "|", attrs("Array"));
NaN = 1;
console.log(NaN);
NaN: false false false | globalThis: true false true | Array: true false true
NaN

NaN, Infinity и undefined заперты: запись в нестрогом коде молча не срабатывает. А Array и globalThis переписать можно — поэтому алгоритмы и говорят о %Array% реалма, а не о том, что сейчас лежит в переменной.

Последнее поле реалма — [[TemplateMap]]. Тегированный шаблон (день 3) передаёт тегу массив строк, и GetTemplateObject (13.2.8.4, день 10) хранит его по месту в коде: одно место — один и тот же замороженный массив при каждом вычислении.

const tag = (strings) => strings;
const first = () => tag`a${1}b`;
const second = () => tag`a${1}b`;
console.log(first() === first(), first() === second(), Object.isFrozen(first()));
true false true

Одинаковый текст в двух местах — два разных массива. Поэтому тег может запоминать разобранный шаблон в WeakMap по массиву строк (день 14 курса 2). А у каждого реалма такие массивы свои.

7. Контекст выполнения

Контекст выполнения (9.4) — устройство спецификации, которым она следит за выполнением кода. В агенте в каждый момент выполняется не больше одного контекста — выполняемый (running execution context), он всегда на вершине стека контекстов. Новый контекст создаётся, когда управление уходит в код, не связанный с текущим: вызов функции, запуск скрипта или модуля. Что в нём лежит:

КомпонентЧто это
code evaluation stateвсё, чтобы приостановить и продолжить код
Functionвыполняемая функция; у скрипта и модуля — null
Realmреалм кода — текущий реалм
ScriptOrModuleскрипт или модуль, откуда код
LexicalEnvironment, VariableEnvironmentгде искать имена и где лежат var (только у кода ECMAScript)
PrivateEnvironmentприватные имена ближайшего класса (день 9 курса 2)
Generatorгенератор — только у контекста генератора

Раздел заканчивается важной фразой: код не может напрямую ни получить контекст, ни увидеть его. Видны только следствия. Пример MDN — три контекста друг на друге:

Увидеть похожее можно через стек вызовов ошибки: свойство stack не входит в стандарт, это строка V8, но кадры в ней — те же вызовы. Помощник stack оставляет от неё имена функций, а кадр верхнего уровня (у него вместо имени адрес) называет «скрипт»:

const stack = () => new Error().stack.split("\n").slice(2)
  .map((line) => line.trim().slice(3).split(" (")[0])
  .map((name) => (name.includes("://") ? "скрипт" : name)).join(" ← ");
function foo(b) {
  const a = 10;
  console.log(stack());
  return a + b + 11;
}
function bar(x) {
  const y = 3;
  return foo(x * y);
}
const baz = bar(7);
console.log(baz);
foo ← bar ← скрипт
42

Шаги MDN: контекст скрипта, над ним bar(7) с x и y, над ним foo(21). Каждый return снимает верхний контекст; кончился скрипт — стек пуст.

8. Стек в отладчике

Вторая практика плана — тот же стек в отладчике Chrome. Поставьте в foo инструкцию debugger, откройте DevTools (F12) и перезагрузите страницу: выполнение остановится на этой строке. Без открытых DevTools debugger ничего не делает.

function foo(b) {
  const a = 10;
  debugger;
  return a + b + 11;
}
function bar(x) {
  const y = 3;
  return foo(x * y);
}
const baz = bar(7);
console.log(baz);
42

Названия панелей — по английскому интерфейсу DevTools. На вкладке Sources справа панель Call Stack показывает три строки: foo, bar и (anonymous) — так отладчик называет кадр верхнего уровня скрипта, у которого Function — null. Верхняя строка — выполняемый контекст. Панель Scope — окружения выбранного кадра: раскрыт Local (this: Window, a: 10, b: 21), ниже свёрнуты Script и Global. Script — имена let, const и class верхнего уровня (здесь baz), Global — глобальный объект Window: две половины глобальной записи окружения (день 3 курса 2). Щёлкните в Call Stack по bar — Scope покажет его x и y. Помните: это кадры движка, а не сами контексты спецификации, но устроены они по ним.

9. Генераторы и хвостовые вызовы

Обычно контексты ходят по стеку «последним пришёл — первым ушёл». Раздел 9.4 оговаривает исключения, и первое — генераторы (день 12 курса 2). Вызов gen() создаёт контекст и сразу его приостанавливает; генератор хранит его у себя (компонент Generator). Каждый next() кладёт этот контекст на стек поверх того, кто позвал, а yield снимает:

const stack = () => new Error().stack.split("\n").slice(2)
  .map((line) => line.trim().slice(3).split(" (")[0])
  .map((name) => (name.includes("://") ? "скрипт" : name)).join(" ← ");
function* gen() {
  console.log("1:", stack());
  yield;
  console.log("2:", stack());
}
const g = gen();
function first() { g.next(); }
function second() { g.next(); }
first();
second();
1: gen ← gen.next ← first ← скрипт
2: gen ← gen.next ← second ← скрипт

Один и тот же контекст gen оба раза лежит на вершине, но под ним разные вызовы. Между ними видна и встроенная функция next: у неё тоже свой контекст (10.3.3). async-функция устроена так же: await снимает её контекст, а продолжение возвращает его на стек в новом задании (день 28 курса 2).

Второе исключение MDN — хвостовые вызовы (15.10, день 12). Если функция только возвращает результат вызова, стандарт требует заменить её контекст, а не положить новый сверху. Требование — лишь для строгого кода (IsInTailPosition), а пример MDN нестрогий. V8 не выполняет его и в строгом — по MDN, хвостовые вызовы есть только в Safari:

"use strict";
function sum(n, total) {
  if (n === 0) return total;
  return sum(n - 1, total + n);
}
console.log(sum(1000, 0));
try {
  sum(100000, 0);
} catch (e) {
  console.log(`${e.name}: ${e.message}`);
}
500500
RangeError: Maximum call stack size exceeded

Третий сюжет MDN — замыкания: функция при создании запоминает окружение выполняемого контекста, и привязки живут дольше самого контекста (день 1 курса 2).

10. ResolveBinding: имя ищется от контекста

ResolveBinding (9.4.2) — первый шаг каждого имени в коде: его зовут вычисление идентификатора, объявления let, const, var, деструктуризация и заголовки for. Шаги короткие: взять LexicalEnvironment выполняемого контекста, узнать, строгий ли код, и вернуть GetIdentifierReference — поиск по цепочке [[OuterEnv]] (день 1 курса 2). Результат — Reference Record (день 4). Значит, имя ищется от того места, где написан код, и в его реалме, а не там, откуда вызвали.

Если имя не нашлось, ссылка «неразрешимая». Чтение даёт ReferenceError, а запись решает PutValue (6.2.5.6): в строгом коде — ReferenceError, в нестрогом — свойство глобального объекта, которого вернёт GetGlobalObject (9.4.6), то есть объект текущего реалма. PutValue — единственное место, откуда её зовут.

var label = "страница";
const frame = document.createElement("iframe");
document.body.append(frame);
const other = frame.contentWindow;
const script = other.document.createElement("script");
script.textContent = 'var label = "рамка"; function who() { return label; }';
other.document.body.append(script);
console.log(other.who(), other.who.call({ label: "объект" }), label);
other.Function("leak = 1;")();
console.log(typeof window.leak, other.leak);
try {
  other.Function("'use strict'; strictLeak = 1;")();
} catch (e) {
  console.log(`${e.name}: ${e.message}`);
}
рамка рамка страница
undefined 1
ReferenceError: strictLeak is not defined

who объявлена скриптом рамки, и label для неё — переменная рамки, хоть зови её со страницы, хоть с другим this: имя — не свойство. Забытый let в функции рамки создал свойство у окна рамки, а не у нашего.

11. Откуда this и new.target

GetThisEnvironment (9.4.3) идёт от LexicalEnvironment выполняемого контекста по [[OuterEnv]] и останавливается на первой записи окружения, у которой HasThisBinding отвечает «да». Отвечают по-разному сами записи раздела 9.1: у записи блока — нет; у записи функции — да, кроме стрелки (её this «лексический», день 2 курса 2); у глобальной — да, поэтому цикл всегда кончается (примечание к 9.4.3); у записи модуля — да, и там this — undefined.

ResolveThisBinding (9.4.4) — найти запись и спросить у неё GetThisBinding; её зовёт только вычисление слова this. Знак ? в её шаге не случаен: запись функции бросает ReferenceError, пока this не связан, — в конструкторе наследника до super() (9.1.1.3.3). GetNewTarget (9.4.5) идёт тем же путём и берёт поле [[NewTarget]] — поэтому new.target в стрелке означает new.target внешней функции. Тот же обход нужен super.

12. Задания

Раздел 9.5. Задание (Job) — Abstract Closure без параметров (день 4), которое начинает вычисление, когда никакого другого нет. Ставит задания хозяин, и стандарт требует от него немногого:

  • задание запускается, только когда в агенте нет выполняемого контекста и стек пуст; хозяин может сделать подготовку и уборку, но после неё стек снова пуст;
  • в агенте выполняется одно задание за раз, и начатое доходит до конца раньше, чем начнётся другое, — MDN зовёт это «run-to-completion»;
  • задание само разбирается со своими ошибками и всегда кончается нормально; поэтому ошибка в then становится отказом промиса, а не обрывает очередь.

Ставят задания четыре хука хозяина. HostEnqueuePromiseJob (9.5.5) — для промисов: его зовут PerformPromiseThen, TriggerPromiseReactions и resolve с thenable (день 28 курса 2). Задания идут в порядке постановки; хуку передают реалм — по примечанию, обычно реалм обработчика через GetFunctionRealm, — и хозяин запоминает активный скрипт или модуль, чтобы восстановить их к началу задания. HostEnqueueGenericJob (9.5.4) — без ограничений по порядку, HostEnqueueTimeoutJob (9.5.6) — «не раньше чем через столько-то миллисекунд»; обоих в стандарте зовёт только Atomics.waitAsync (день 22). Четвёртый хук — для FinalizationRegistry (день 24).

Заметьте: setTimeout в ECMAScript нет вовсе — таймеры, события и загрузку описывает HTML. А примечание 1 к 9.5 разрешает хозяину ставить задания промисов выше прочих — браузер так и делает, отсюда микрозадачи и задачи HTML (страница MDN «Microtask guide»). Пример MDN с двумя then и долгим циклом:

Гонки между then нет: каждое задание выполняется целиком, и вывод всегда 1 и 2. Таймер с нулём ждал 200 мс — скрипт не отдавал поток. Обратная сторона — долгое задание замораживает страницу; совет MDN — резать работу на короткие задания.

then сразу, а не при постановке задания, заворачивает функцию в JobCallback Record (9.5.1) — HostMakeJobCallback (9.5.2); браузер кладёт туда служебные данные HTML. Вызывает её HostCallJobCallback (9.5.3) — обязательно обычным Call.

14. Агенты

Раздел 9.6: агент — набор контекстов выполнения, их стек, выполняемый контекст, запись агента (Agent Record) и исполняющий поток. Всё, кроме потока, — только его. Поток могут делить агенты, которые не умеют блокироваться (браузеры порой ведут так несвязанные вкладки). Поля записи агента:

15. Кластеры, прогресс и чужое окно

Кластер агентов (9.7) — наибольшее множество агентов, которые могут общаться через общую память (SharedArrayBuffer, дни 22–23). Каждый агент — ровно в одном кластере. У всех агентов кластера одинаковые [[LittleEndian]] и [[IsLockFree…]] и разные [[Signifier]]. Остановить надолго часть кластера нельзя: кто-то застрянет на блокировке, которую держит спящий. Агента убили снаружи — гибнет весь кластер (так в вебе, по MDN). Окно и его выделенный worker — один кластер; окно и service worker, окно и рамка чужого источника — разные.

9.8 Forward Progress: агент «продвигается», когда делает шаг вычисления, и «заблокирован», когда синхронно и бесконечно ждёт внешнего события, — а заблокироваться может только агент с [[CanBlock]]. Гарантии: незаблокированный агент со своим потоком когда-нибудь продвинется; из агентов с общим потоком продвинется хотя бы один; агент блокирует другого только явным API (Atomics.wait, день 22). await — не блокировка: он отдаёт поток.

Чужое окно бывает и в нашей вкладке. Рамка с атрибутом sandbox без allow-same-origin получает непрозрачный источник — для страницы она как сайт другого домена:

  1. Почему instanceof Array для массива из рамки — false, а Array.isArray — true?
    Ответ instanceof ищет в цепочке прототипов Array.prototype нашего реалма, а у массива рамки в цепочке Array.prototype рамки. IsArray смотрит, экзотический ли это массив, — от реалма это не зависит.
  2. В каком реалме окажется результат Array.prototype.map.call(listFromFrame, f) и почему?
    Ответ В реалме страницы. map страницы работает в её реалме; ArraySpeciesCreate видит, что constructor — %Array% другого реалма, отбрасывает его и создаёт обычный массив текущего реалма.
  3. Почему this в стрелке внутри конструктора наследника бросает ReferenceError до super()?
    Ответ GetThisEnvironment проходит запись стрелки (у неё нет this) и останавливается на записи конструктора. GetThisBinding этой записи бросает ReferenceError, пока this не связан, а связывает его только super().
  4. Что лежит на стеке под обработчиком then, когда он начинает работу?
    Ответ Ничего: по разделу 9.5 задание начинается, только когда стек пуст. Тот, кто вызвал then, давно закончил своё задание.
  5. Где в ECMAScript определён setTimeout и кто зовёт HostEnqueueTimeoutJob?
    Ответ Нигде: таймеры описывает стандарт HTML. HostEnqueueTimeoutJob в тексте 2026 зовёт только Atomics.waitAsync — для своего таймаута.
