1. Глава 13 и приоритет

Глава 13 идёт от самых «крепких» выражений к самым «слабым»: идентификаторы и литералы, доступ и вызов, ++, унарные, **, * / %, + -, сдвиги, сравнения, равенство, побитовые, логические, ?:, присваивание, запятая. Это и есть таблица приоритетов: отдельной таблицы в стандарте нет, приоритет задаёт грамматика. * «сильнее» +, потому что правило сложения стоит из умножений: f() + g() * h() разбирается как f() + (g() * h()). Но порядок вычисления задают шаги Evaluation, и они почти всегда идут слева направо.

2. Порядок вычисления

Практика плана. Сложение и умножение считаются шагами EvaluateStringOrNumericBinaryExpression (13.15.4): вычислить левый операнд, GetValue, вычислить правый, GetValue, применить операцию. Присваивание (13.15.2) тоже начинает слева: сначала ссылка-цель, потом правая часть. Предскажите четыре строки:

const log = [];
const f = () => { log.push("f"); return 1; };
const g = () => { log.push("g"); return 2; };
const h = () => { log.push("h"); return 3; };
console.log(f() + g() * h(), log.join(" "));
const a = [];
let i = 0;
a[i++] = i;
console.log(JSON.stringify(a), i);
let x = 1;
x += (x = 10, 5);
console.log(x);
let obj = { name: "старый" };
const keep = obj;
obj.v = (obj = { name: "новый" }, 1);
console.log(keep.v, obj.v);
7 f g h
[1] 1
6
1 undefined

Вызовы шли по порядку f, g, h, хотя умножение — раньше сложения. В a[i++] = i ключ 0 вычислен до правой части, а она видит уже i = 1. x += … прочитал x = 1 до того, как правая часть записала 10. Последняя строка: ссылка obj.v запомнила старый объект как [[Base]] — новое значение переменной obj её не трогает.

3. Доступ к свойству

Примечание 13.3.2: obj.name — то же, что obj["name"]. Шаги обеих форм: вычислить объект, GetValue, и дальше 13.3.4 берёт имя как строку, а 13.3.3 вычисляет выражение в скобках и кладёт значение в Reference Record как есть. ToPropertyKey (день 5) сделает позже GetValue или PutValue; примечание к 13.3.3 говорит прямо: в a[b] = c — только после вычисления c. И ссылка с [[Base]] null создаётся спокойно — бросает уже GetValue:

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
const log = [];
const key = { toString() { log.push("ключ"); return "k"; } };
const o = {};
o[key] = (log.push("правая"), 1);
console.log(log.join(" "), Object.keys(o).join());
const calls = [];
const name = () => { calls.push("имя вычислено"); return "x"; };
console.log(attempt(() => null[name()]), "|", calls.join());
правая ключ k
TypeError: Cannot read properties of null (reading 'x') | имя вычислено

Chrome 156 следует тексту: toString ключа — после правой части. А null[name()] сначала вычислил имя и только потом упал.

4. Вызов функции

Вызов (13.3.6): вычислить то, что слева от скобок, — ссылку ref, взять значение func, и всё отдать EvaluateCall (13.3.6.2). Её шаги:

  1. this из ссылки: свойство — GetThisValue, имя — WithBaseObject окружения (не undefined только внутри with, день 31); не ссылка — undefined (день 4);
  2. вычислить аргументы — ArgumentListEvaluation;
  3. func не объект или не вызываемый — TypeError;
  4. хвостовая позиция — PrepareForTailCall (день 12); Call.

Шаг 2 стоит раньше шага 3: аргументы считаются даже для того, что вызвать нельзя. Отдельный случай — прямой eval (день 13). А что станет с this = undefined внутри нестрогой функции, решает уже её [[Call]] — OrdinaryCallBindThis дня 9.

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
const log = [];
const arg = () => { log.push("аргумент"); return 1; };
const obj = {};
console.log(attempt(() => obj.missing(arg())), "|", log.join());
console.log(attempt(() => obj.a.b()), "|", attempt(() => obj["x" + 1]()));
TypeError: obj.missing is not a function | аргумент
TypeError: Cannot read properties of undefined (reading 'b') | TypeError: obj[("x" + 1)] is not a function

Вызов в тексте ошибки V8 печатает по разобранному коду, со своими скобками: obj[("x" + 1)]. Вторая ошибка другая: obj.a.b упал раньше вызова — на GetValue ссылки с [[Base]] undefined.

5. new и аргументы

new (13.3.5) идёт шагами EvaluateNew так же, как вызов: вычислить конструктор, GetValue, аргументы — и только потом проверить IsConstructor. Аргументы (13.3.8) считаются слева направо, а spread берёт итератор (день 7) и зовёт next, пока не придёт done:

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
const log = [];
const notCtor = () => {};
console.log(attempt(() => new notCtor(log.push("аргумент"))), "|", log.join());
const steps = [];
const pair = { [Symbol.iterator]() { let i = 0; return { next() { steps.push("next"); return i < 2 ? { value: ++i, done: false } : { done: true }; } }; } };
console.log(Math.max(...pair, 0), steps.join(" "));
const order = [];
const a = (v) => { order.push(v); return v; };
console.log(Math.max(a(1), ...[a(2), a(3)], a(4)), order.join(" "));
TypeError: notCtor is not a constructor | аргумент
2 next next next
4 1 2 3 4

У стрелки нет [[Construct]] (день 4), но ошибка пришла уже после аргумента. Spread трижды позвал next: два значения и done. Литерал внутри spread вычислился на своём месте, и общий порядок не нарушен.

6. Необязательная цепочка

13.3.9: цепочка начинается с ?. и тянется до конца выражения доступа и вызовов. Evaluation цепочки (13.3.9.1): вычислить основу, GetValue; если undefined или null — вернуть undefined за всю цепочку. Иначе ChainEvaluation (13.3.9.2) проходит звенья теми же операциями, что обычный доступ и вызов (13.3.3, 13.3.4, EvaluateCall), и передаёт дальше ссылку — поэтому this у obj.m?.() сохраняется. Практика плана — где обрывается obj?.a.b:

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
const log = [];
const f = () => { log.push("f"); return "a"; };
const obj = { a: null, m() { return this === obj; } };
console.log(null?.a.b, undefined?.[f()], log.join() || "f не вызвана");
console.log(attempt(() => obj?.a.b), obj.a?.b, obj?.a?.b);
console.log(obj.m?.(), (obj?.m)(), obj.nope?.(), delete null?.a);
const x = null;
console.log(x?.y.z.w, "|", attempt(() => (x?.y).z));
undefined undefined f не вызвана
TypeError: Cannot read properties of null (reading 'b') undefined undefined
true true undefined true
undefined | TypeError: Cannot read properties of undefined (reading 'z')

x?.y.z.w — одна цепочка, и её оборвала первая проверка. В (x?.y).z скобки закончили цепочку: получилось undefined, и .z — уже обычный доступ. Скобки вокруг obj?.m ссылку не теряют (день 4), поэтому this сохранился.

Где ?. нельзя

Грамматика 13.3.9 и ранние ошибки не пускают цепочку туда, где она бессмысленна:

const parse = (code) => {
  try {
    new Function(code);
    return "ok";
  } catch (e) {
    return `${e.name}: ${e.message}`;
  }
};
const cases = ["a?.b = 1", "a?.b++", "new a?.b()", "a?.b`x`", "delete a?.b"];
for (const c of cases) console.log(c, "→", parse(c));
a?.b = 1 → SyntaxError: Invalid left-hand side in assignment
a?.b++ → SyntaxError: Invalid left-hand side expression in postfix operation
new a?.b() → SyntaxError: Invalid optional chain from new expression
a?.b`x` → SyntaxError: Invalid tagged template on optional chain
delete a?.b → ok

Записать в «может быть, нет» нельзя: AssignmentTargetType цепочки — invalid (день 8). new и тег шаблона цепочку не принимают (ошибка тега — день 20 курса 2). А delete — можно: при null он получит undefined вместо ссылки и вернёт true.

7. ++, унарные операторы и **

13.4: x++ — ссылка, GetValue, ToNumeric (день 5), запись значения на 1 больше, а результат — старое значение после ToNumeric. Ранняя ошибка 13.4.1 — только для цели invalid: f()++ в нестрогом коде браузера разбирается (web-compat, день 8) и падает при выполнении. Унарные +, -, ! (13.5.4–13.5.7) — ToNumber, ToNumeric и ToBoolean. А у ** (13.6) грамматика запрещает унарный оператор слева без скобок: неясно, что имели в виду.

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
let s = "5";
console.log(s++, s, typeof s);
const c = 1;
console.log(attempt(() => c++), "|", attempt(() => new Function("-2 ** 2")));
console.log((-2) ** 2, -(2 ** 2), 2 ** 3 ** 2, +"", -"x", !"");
5 6 number
TypeError: Assignment to constant variable. | SyntaxError: Unary operator used immediately before exponentiation expression. Parenthesis must be used to disambiguate operator precedence
4 -4 512 0 NaN true

s++ вернул число 5, а не строку «5»: старое значение уже прошло ToNumeric. ** — правоассоциативный: 2 ** 3 ** 2 = 2 ** 9. Через геттер и сеттер видно, что ++ читает и пишет по одному разу:

const log = [];
const o = { get n() { log.push("get"); return "5"; }, set n(v) { log.push(`set ${typeof v} ${v}`); } };
const old = o.n++;
console.log(old, typeof old, "|", log.join(", "));
5 number | get, set number 6

Сеттер получил число 6, а не строку «51»: ++ — не += 1 со склейкой, а ToNumeric и Number::add.

8. delete

13.5.1, шаги Evaluation:

  1. не ссылка (delete 1) — true;
  2. неразрешимая ссылка — true (бывает только в нестрогом коде);
  3. свойство: super.x — ReferenceError; иначе ToObject, ToPropertyKey, [[Delete]]; false в строгом коде — TypeError;
  4. имя в окружении — DeleteBinding записи окружения.

Ранние ошибки 13.5.1.1: в строгом коде delete имя — SyntaxError, и правило применяется сквозь скобки, delete ((x)) тоже. Приватное поле удалить нельзя никогда. Практика плана — обычный и строгий код:

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
var v = 1;
implicit = 2;
let l = 3;
console.log(delete v, delete implicit, typeof implicit, delete l, delete 1, delete "x".length);
const arr = [1, 2, 3];
console.log(delete arr[1], JSON.stringify(arr), arr.length);
console.log(attempt(() => { "use strict"; const o = Object.freeze({ a: 1 }); return delete o.a; }));
console.log(attempt(() => new Function("'use strict'; delete ((x));")));
class B { m() {} }
class C extends B { m() { return attempt(() => delete super.m); } }
console.log(new C().m());
false true undefined false true false
true [1,null,3] 3
TypeError: Cannot delete property 'a' of #<Object>
SyntaxError: Delete of an unqualified identifier in strict mode.
ReferenceError: Unsupported reference to 'super'

var v на верхнем уровне — ненастраиваемое свойство окна: false. «Утёкшая» implicit — обычное свойство: удалена. let l живёт в декларативной части глобальной записи, и её DeleteBinding отвечает false. Удалённый элемент массива оставляет дыру, длина та же.

9. typeof

13.5.3: вычислить операнд; неразрешимая ссылка — «undefined» (день 4); иначе GetValue и ответ по типу. У объекта два вопроса: есть слот [[IsHTMLDDA]] — «undefined» (необязательная часть для браузеров, document.all, день 6 курса 2); есть [[Call]] — «function»; иначе «object».

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
console.log(typeof document.all, typeof class {}, typeof Math.max, typeof Math, typeof null);
console.log(attempt(() => { typeof tdz; let tdz = 1; }));
console.log(attempt(() => typeof undeclared?.x));
undefined function function object object
ReferenceError: Cannot access 'tdz' before initialization
ReferenceError: undeclared is not defined

Класс — «function»: у него есть [[Call]], хотя без new его не вызвать. Math — объект без [[Call]]. Две ошибки — из шага GetValue: tdz нашлось, но ещё без значения; а в undeclared?.x операндом typeof служит вся цепочка, и её первый шаг — GetValue основы. Защита typeof работает, только если операнд — само имя.

10. Сложение

13.8.1 ведёт в ApplyStringOrNumericBinaryOperator (13.15.3). Для +: ToPrimitive обоих без подсказки (день 5: Date тогда выбирает строку); если хоть один — строка, склеить строки. Иначе ToNumeric обоих; разные числовые типы — TypeError; дальше операция по таблице: Number::add или BigInt::add. Примечание 2: здесь «или», а в IsLessThan — «и» (день 5).

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
const d = new Date(0);
console.log(typeof (d + 1), typeof (d - 1), [1] + [2], 1 + null, "1" + 1n);
console.log(attempt(() => 1n + 1), "|", attempt(() => Symbol() + ""));
const log = [];
const left = { valueOf() { log.push("левый valueOf"); return 1; } };
const right = { [Symbol.toPrimitive](hint) { log.push(`правый ${hint}`); return "R"; } };
console.log(left + right, "|", log.join(", "));
string number 12 1 11
TypeError: Cannot mix BigInt and other types, use explicit conversions | TypeError: Cannot convert a Symbol value to a string
1R | левый valueOf, правый default

"1" + 1n — «11»: строка проверяется раньше типов чисел. Отсутствие подсказки Symbol.toPrimitive видит как «default». Вычитание (13.8.2) идёт той же операцией, но строк не склеивает: d - 1 — число.

11. Сравнения: кто первым

13.10.1: < зовёт IsLessThan(левый, правый, LeftFirst = true), а > — IsLessThan(правый, левый, LeftFirst = false): операнды меняются местами, чтобы хватило одного алгоритма. Флаг LeftFirst (день 5) возвращает порядок: ToPrimitive левого операнда всё равно первым. <= — «не (правый < левый)», и undefined от NaN даёт false. in требует объект справа, а #x in obj — проверка клейма приватного поля (день 9 курса 2).

const log = [];
const L = { valueOf() { log.push("левый"); return 1; } };
const R = { valueOf() { log.push("правый"); return 2; } };
L > R;
console.log(log.join(" "));
class Box { #v = 1; static has(o) { return #v in o; } }
console.log(Box.has(new Box()), Box.has({}), NaN < 1, NaN >= 1, null < 1);
левый правый
true false false false true

Без флага > первым привёл бы правый операнд. NaN ломает и <, и >=: IsLessThan вернул undefined, и оба шага дали false — поэтому >= не то же, что «не <». null < 1: ToNumber(null) — 0.

12. InstanceofOperator

13.10.2: правая часть не объект — TypeError; есть метод %Symbol.hasInstance% — вызвать и привести ответ к Boolean; иначе не вызываемая — TypeError; иначе OrdinaryHasInstance (день 7). Статический метод мы видели (день 11 курса 2). Но заметьте: метод есть у каждой функции — в Function.prototype, — и он ненастраиваемый и только для чтения. Шаги 4–5, по примечанию, — для совместимости, и дойти до них можно, только убрав прототип:

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
function F() {}
const f = new F();
F[Symbol.hasInstance] = () => false;
console.log(f instanceof F, Object.hasOwn(F, Symbol.hasInstance));
Object.defineProperty(F, Symbol.hasInstance, { value: () => false });
console.log(f instanceof F);
function G() {}
const g = new G();
Object.setPrototypeOf(G, null);
console.log(typeof G[Symbol.hasInstance], g instanceof G);
console.log(attempt(() => f instanceof 1), "|", attempt(() => f instanceof {}));
true false
false
undefined true
TypeError: Right-hand side of 'instanceof' is not an object | TypeError: Right-hand side of 'instanceof' is not callable

Присваивание F[Symbol.hasInstance] молча не сработало: унаследованное свойство только для чтения запрещает и своё (OrdinarySetWithOwnDescriptor, день 7). defineProperty создаёт своё — и оно сработало. У G без прототипа метода нет, и instanceof дошёл до шага 5.

13. Логические операторы и ?:

13.13: && и || возвращают не true/false, а один из операндов, и правую часть считают, только если она нужна. ?? смотрит лишь на null и undefined. Грамматика не даёт смешать ?? с && и || без скобок: иначе неясно, что раньше. ?: (13.14) приводит условие ToBoolean и считает одну ветку.

const parse = (code) => { try { new Function(code); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const log = [];
const t = (v) => { log.push(JSON.stringify(v)); return v; };
console.log(t(0) || t("") || t("да"), t(1) && t(null) && t(2), t(0) ?? t(5));
console.log(log.join(" "));
console.log(parse("a ?? b || c"), "|", parse("(a ?? b) || c"), "|", document.all ? "есть" : "нет");
да null 0
0 "" "да" 1 null 0
SyntaxError: Unexpected token '||' | ok | нет

t(2) и t(5) не вызваны: правая часть не понадобилась. document.all в условии ложен — ToBoolean тоже знает о [[IsHTMLDDA]].

14. Присваивание

Три формы 13.15.2 — по шагам:

Шаги видны через геттер и сеттер:

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
const log = [];
const obj = { get v() { log.push("get"); return 1; }, set v(x) { log.push(`set ${x}`); } };
obj.v ||= 5;
obj.v &&= 6;
obj.v += 1;
console.log(log.join(", "));
const c = 1;
console.log(attempt(() => { c ||= 2; return c; }), "|", attempt(() => { c &&= 2; }));
let r;
console.log((r = 5) + 1, r);
get, get, set 6, get, set 2
1 | TypeError: Assignment to constant variable.
6 5

||= с истинным значением даже не позвал сеттер, и константа c пережила c ||= 2 без ошибки: записи не было (замороженный объект дня 6 курса 2 — тот же шаг). Значение выражения присваивания — правая часть: (r = 5) + 1 — 6. Ранние ошибки 13.15.1 у форм разные: f() = 1 и f() += 1 в нестрогом коде браузера разбираются (web-compat, день 8), а f() ||= 1 — SyntaxError: логическим формам нужна цель simple.

Ошибки записи в строгом коде

Примечание к 13.15.2 перечисляет, когда запись в строгом коде бросает: ссылка неразрешима — ReferenceError; свойство только для чтения, аксессор без сеттера, новое свойство у нерасширяемого объекта — TypeError. В нестрогом коде все четыре записи молча пропадают; первую и последнюю показал день 4, вот остальные:

"use strict";
const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
const ro = Object.defineProperty({}, "x", { value: 1, writable: false });

15. Деструктурирующее присваивание

13.15.5: если слева литерал объекта или массива, грамматика перечитывает его как шаблон (AssignmentPattern); ранние ошибки 13.15.5.1 требуют, чтобы каждая цель была simple. DestructuringAssignmentEvaluation: у объекта — RequireObjectCoercible, у массива — GetIterator и IteratorClose, если итератор не кончился (день 7). Для каждого свойства сначала вычисляется цель, потом читается свойство, потом умолчание (только при undefined) и запись.

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
const log = [];
const target = { set x(v) { log.push(`запись x=${v}`); } };

({ a: t().x } = source);
console.log(log.join(", "));
console.log(attempt(() => { ({} = null); }), "|", attempt(() => { [] = {}; }));

({ d1 = "умолчание", d2 = "умолчание" } = { d1: null, d2: undefined });

Даже пустой шаблон {} проверяет null, а пустой [] берёт итератор.

16. Тег шаблона — тоже вызов

13.3.11: tag`…` вычисляется как вызов — ссылка на тег и EvaluateCall, с тем же this, что у obj.f(). Первый аргумент — массив строк из GetTemplateObject (день 9), за ним подстановки, вычисленные до вызова.

Запятая потеряла ссылку, как у обычного вызова (день 4). А «1 is not a function» — та же проверка EvaluateCall.

Литерал регулярного выражения (13.2.7) при каждом вычислении создаёт новый объект, а шаблон (13.2.8) — нет (день 9). __proto__: в литерале объекта (13.2.5) задаёт прототип. Ещё три раздела знакомы по другим дням. super.m() (13.3.7): MakeSuperPropertyReference строит ссылку, где [[Base]] — прототип [[HomeObject]] метода (GetSuperBase), а [[ThisValue]] — текущий this (день 4); метод ищется выше, а работает с нашим объектом. Мета-свойства (13.3.12): new.target — GetNewTarget (день 9), import.meta — сведения о модуле (день 31 курса 2). import() (13.3.10) отсчитывает адрес от активного скрипта или модуля — GetActiveScriptOrModule (день 9).

Соберём день в одном составном присваивании. Помощник v записывает имя и отдаёт значение; предскажите лог:

19. «Карточки 2.0»: current по шагам

  1. Почему f() + g() * h() вызывает f первой, хотя умножение «главнее»?
    Ответ Приоритет задаёт форму дерева: умножение — правый операнд сложения. А шаги сложения (13.15.4) сначала вычисляют левый операнд, потом правый — внутри него g и h.
  2. Где обрывается obj?.a.b, если obj есть, а obj.a — null?
    Ответ Нигде: проверка 13.3.9.1 смотрит только на obj. Цепочка пойдёт дальше, и .b от null бросит TypeError. Защитить звено — obj?.a?.b.
  3. Что вернёт delete для var-переменной и для «утёкшей» глобальной в нестрогом коде?
    Ответ false и true: var создаёт ненастраиваемое свойство окна, а присваивание необъявленному имени — обычное свойство, которое удаляется.
  4. Почему F[Symbol.hasInstance] = … не меняет instanceof?
    Ответ F наследует этот метод от Function.prototype, а там он только для чтения. Такое унаследованное свойство запрещает присваиванием создать своё; нужен defineProperty или статический метод класса.
  5. Сколько раз по тексту 2026 вызовется toString ключа в o[key] += 1 и сколько в Chrome 156?
    Ответ По тексту — один: GetValue записывает готовый ключ в ту же ссылку, и PutValue его не приводит. Chrome 156 вызывает второй раз при записи.
