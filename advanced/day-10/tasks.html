День 10. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Открыты спецификация, tc39.es/ecma262/2026/, и консоль Chrome. Код пишем в папке day-10 курса 3. Помощники attempt и parse — из лекции. Каждое предсказание — до запуска, каждое «почему» — с номером раздела и шага.

Разминка

1. Порядок лога
Легко7 мин

отличать приоритет и ассоциативность от порядка вычисления.

const log = [];
const v = (name, value) => { log.push(name); return value; };
const run = (f) => { log.length = 0; const r = f(); return `${log.join("")}=${r}`; };
const obj = { m(a, b) { return a + b; } };
console.log(run(() => v("a", 1) - v("b", 2) - v("c", 3)), run(() => v("a", 2) ** v("b", 3) ** v("c", 2)));
console.log(run(() => v("o", obj)[v("k", "m")](v("a", 1), v("b", 2))), run(() => v("a", null)?.[v("k", "x")]));
console.log(run(() => (v("a", 1) < v("b", 2) ? v("c", "да") : v("d", "нет"))), run(() => v("a", 0) && v("b", 1)));
  • предсказаны шесть строк, у каждой — шаг, который решил порядок;
  • объяснено, почему у правоассоциативного ** лог всё равно «abc»;
  • для ?.[…] и && найдено, какой шаг не дал вычислить ключ и правую часть.
2. delete в двух режимах
Легко7 мин

проходить шаги 13.5.1.2 и ранние ошибки 13.5.1.1.

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
const parse = (code) => { try { new Function(code); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
var g = 1;
const o = Object.defineProperty({ a: 1 }, "fixed", { value: 2 });
console.log(delete o.a, delete o.fixed, delete o.none, delete g, delete globalThis.g);
console.log(attempt(() => { "use strict"; return delete o.fixed; }), "|", attempt(() => { "use strict"; return delete o.none; }));
console.log(parse("'use strict'; delete o;"), "|", parse("'use strict'; delete (o).a;"), "|", parse("delete o;"));
  • предсказаны три строки, у каждого ответа — шаг 13.5.1.2 или правило 13.5.1.1;
  • объяснено, почему delete g и delete globalThis.g идут разными шагами, а ответ один;
  • объяснено, почему delete (o).a в строгом коде разрешён, а delete (o) — нет.

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };

Основные задания

4. Своё сложение
Средне12 мин

перенести ветку + раздела 13.15.3 в код.

Напишите add(a, b) без оператора + для строк: ToPrimitive обоих (готовый toPrimitive ниже), строка с любой стороны — склейка шаблонной строкой (она зовёт ToString и для символа бросает); иначе ToNumeric обоих, разные числовые типы — TypeError, и только тогда + двух чисел одного типа.

const toPrimitive = (x) => {
  if (x === null || (typeof x !== "object" && typeof x !== "function")) return x;
  const exotic = x[Symbol.toPrimitive];
  if (exotic !== undefined) return exotic.call(x, "default");
  for (const name of ["valueOf", "toString"]) {
    const result = typeof x[name] === "function" ? x[name]() : x;
    if (result === null || (typeof result !== "object" && typeof result !== "function")) return result;
  }
  throw new TypeError("Cannot convert object to primitive value");
};
console.log(toPrimitive(new Date(0)) === new Date(0).toString(), toPrimitive([1, 2]));
const attempt = (f) => { try { return f(); } catch (e) { return e.name; } };
add(1, 2);                              // 3
add("1", 2);                            // "12"
add([1], [2]);                          // "12"
add(null, true);                        // 1
Number.isNaN(add(undefined, 1));        // true
typeof add(1n, 2n);                     // "bigint"
attempt(() => add(1n, 1));              // "TypeError"
attempt(() => add(Symbol(), ""));       // "TypeError"
  • все восемь строк примера дают то, что в комментариях;
  • шаги идут в порядке 13.15.3: 1.a–1.c, потом ToNumeric и SameType;
  • на десяти парах значений ответ совпадает с a + b языка, включая "1" + 1n.
5. Своя InstanceofOperator
Средне12 мин

пройти 13.10.2 и найти, когда до OrdinaryHasInstance вообще доходит дело.

Напишите instanceOf(v, target) по шагам 13.10.2: не объект — TypeError; метод Symbol.hasInstance (как GetMethod: undefined и null — «нет метода», не функция — TypeError) — вызвать и привести к Boolean; не функция — TypeError; иначе своя ordinaryHasInstance: не объект слева — false, prototype не объект — TypeError, дальше вверх по цепочке прототипов.

const attempt = (f) => { try { return f(); } catch (e) { return e.name; } };
class Even { static [Symbol.hasInstance](n) { return n % 2 === 0; } }
function F() {}
const f = new F();
const G = function () {};
const g = new G();
Object.setPrototypeOf(G, null);
instanceOf(f, F);                                   // true
instanceOf(2, Even);                                // true
instanceOf(f, { [Symbol.hasInstance]: () => 1 });   // true
instanceOf(g, G);                                   // true
attempt(() => instanceOf(f, {}));                   // "TypeError"
attempt(() => instanceOf(f, 1));                    // "TypeError"
  • все шесть строк примера дают то, что в комментариях;
  • объяснено, почему для instanceOf(f, F) ваша ordinaryHasInstance не вызывается вовсе, а для instanceOf(g, G) — вызывается;
  • для {} и 1 назван шаг, который бросил.
6. Своя необязательная цепочка
Средне12 мин

перенести 13.3.9.1 и ChainEvaluation на модель.

Цепочка — основа и список звеньев: ["get", ключ] или ["call", аргументы]; ?. стоит только перед первым звеном. Напишите chain(base, links): основа null или undefined — undefined за всю цепочку; дальше звенья по очереди, как обычный доступ и вызов: доступ к свойству null — TypeError, вызов получает this — объект, у которого взяли функцию.

const attempt = (f) => { try { return f(); } catch (e) { return e.name; } };
chain(null, [["get", "a"], ["get", "b"]]);                                   // undefined
chain({ a: { b: 2 } }, [["get", "a"], ["get", "b"]]);                        // 2
attempt(() => chain({ a: null }, [["get", "a"], ["get", "b"]]));             // "TypeError"
chain({ n: 5, m() { return this.n; } }, [["get", "m"], ["call", []]]);      // 5
attempt(() => chain({}, [["get", "nope"], ["call", []]]));                   // "TypeError"
  • все пять строк примера дают то, что в комментариях;
  • проверка null — одна, перед циклом, как в 13.3.9.1;
  • каждая строка совпадает с тем же выражением языка: null?.a.b, obj?.m() и другие.
7. «Карточки 2.0»: нет колоды или нет карточки
Средне10 мин

различать undefined и null там, где ?? их склеивает.

current() дня 34 курса 2 возвращает null в двух разных случаях: колода не загрузилась (цепочка дала undefined) и карточек на сегодня нет (cardAt вернул null). Напишите currentWord(opened, chosen, position): слово карточки, «колода не загружена» или «на сегодня всё», — и не зовите cardAt, если колоды нет.

const opened = new Map([["home", { cardAt: (p) => (p < 2 ? { word: "window" } : null) }]]);
currentWord(opened, "home", 0);     // "window"
currentWord(opened, "home", 5);     // "на сегодня всё"
currentWord(opened, "food", 0);     // "колода не загружена"
  • все три строки примера дают то, что в комментариях;
  • объяснено, почему ?? null в current() склеивает оба случая (13.13.1);
  • в своём main.js надпись на экране различает эти случаи.

8. Своя ссылка: ключ один раз
Сложно10 мин

повторить GetValue и PutValue и увидеть находку лекции на модели.

Ссылка — объект { base, name }. Напишите ref(base, name), getValue(r) и putValue(r, value): основа null или undefined — TypeError; имя не строка и не символ — String(name) и записать готовый ключ обратно в ссылку, как 6.2.5.5. И compoundAdd(r, rhs) по шагам +=: прочитать, вызвать rhs(), сложить, записать.

const attempt = (f) => { try { return f(); } catch (e) { return e.name; } };
let conversions = 0;
const key = { toString() { conversions++; return "k"; } };
const o = { k: 1 };
compoundAdd(ref(o, key), () => 1);
o.k;                                  // 2
conversions;                          // 1
attempt(() => getValue(ref(null, "x")));   // "TypeError"
  • все три проверяемые строки примера дают то, что в комментариях;
  • тот же код с o[key] += 1 в Chrome 156 даёт conversions 2 — сравнено и объяснено;
  • назван шаг compoundAdd, где ссылка уже хранит готовый ключ.
9. Незнакомые разделы: ключ и остаток в шаблоне
Сложно10 мин

прочитать разделы деструктуризации, которых не было на лекции.

Прочитайте 13.15.5.3 PropertyDestructuringAssignmentEvaluation и 13.15.5.4 RestDestructuringAssignmentEvaluation и предскажите строку.

const log = [];
const source = { get a() { log.push("чтение a"); return 1; }, get b() { log.push("чтение b"); return 2; } };
const key = () => { log.push("ключ"); return "a"; };
let x, rest;
({ [key()]: x, ...rest } = source);
console.log(x, JSON.stringify(rest), log.join(", "));
  • предсказана строка, у каждого слова лога — операция, которая его записала;
  • найдено, откуда остаток знает, что a уже взят (список excludedNames);
  • назван шаг, где остаток читает b: CopyDataProperties (день 7).
