1. Глава 15

Глава 15 — функции и классы. Примечание к ней: всё, что здесь описано, создаёт функцию-объект (10.2, день 14). Разделы главы устроены одинаково: ранние ошибки, операция Instantiate… («создать функцию») и Evaluation. Каждая Instantiate… зовёт OrdinaryFunctionCreate (10.2.3): прототип функции, исходный текст, параметры, тело, режим this (lexical-this у стрелок), окружение и приватное окружение. Остальное решают добавки: SetFunctionName (день 8), MakeConstructor ([[Construct]] и prototype) и MakeMethod ([[HomeObject]] для super):

Третья и четвёртая колонки — MakeConstructor: его зовут только function и класс. Из обещанной вчера FunctionDeclarationInstantiation сегодня — окружения параметров (целиком — день 14), а OrdinaryCallBindThis дня 9 объяснит стрелки.

2. Списки параметров

15.1. Параметры идут через запятую, остаток ...rest — последним; каждый параметр — имя или шаблон (как у let, день 11), с умолчанием или без. Раздел задаёт четыре статические операции:

  • IsSimpleParameterList (15.1.3) — только имена, без умолчаний, шаблонов и остатка;
  • HasInitializer (15.1.4) — есть ли умолчание;
  • ContainsExpression (15.1.2) — есть ли в списке код: умолчание или вычисляемый ключ. У шаблона { a } кода нет;
  • ExpectedArgumentCount (15.1.5) — параметры до первого умолчания или остатка; OrdinaryFunctionCreate делает из него length (день 4 курса 2).

Ранние ошибки 15.1.1: повтор имён — только в простом списке нестрогой функции (день 8). Там же и arguments, связанный с параметрами (день 4 курса 2).

const lengths = [function (a, b) {}, function (a, b = 1, c) {}, function (...rest) {}, function ({ a, b }, [c]) {}, (a, b = a) => {}, function (a, { b } = {}, c) {}];
console.log(lengths.map((f) => f.length).join(" "));
function mapped(a) { a = "новое"; return arguments[0]; }
function pattern({ a }) { arguments[0] = null; return a; }
console.log(mapped("старое"), pattern({ a: 1 }));

c после умолчания в счёт не идёт — примечание 15.1.5 называет такие параметры необязательными; шаблон считается одним. У pattern список не простой, и запись в arguments[0] до a не дошла.

3. Окружение параметров

Значения параметрам раздаёт FunctionDeclarationInstantiation (10.2.11) — её зовёт EvaluateFunctionBody (15.2.3) до первой инструкции тела. Шаги про окружения:

  1. привязки имён параметров — пока без значений, и рядом arguments (у стрелок его нет);
  2. IteratorBindingInitialization (день 8): аргументы раскладываются слева направо, умолчания вычисляются сейчас, в этом окружении;
  3. ContainsExpression ложно — имена var тела ложатся туда же;
  4. истинно — для var тела создаётся новое окружение, и var с именем параметра получает его значение;
  5. функции тела — в окружении var; let и const — ещё ниже (у строгой функции — там же).

Примечание к шагу 4: замыкания из списка параметров не должны видеть объявлений тела. (У нестрогой функции с кодом в параметрах есть ещё окружение — для eval в умолчаниях, день 13.)

var x = "внешний";
function one(a = () => x) { var x = "тело"; return a(); }
function two(a = () => x, x = "параметр") { var x = "тело"; return [a(), x].join(" / "); }
function three(x) { var x; return x; }
function four(x = "умолчание") { var x; return x; }
console.log(one(), "|", two(), "|", three("аргумент"), "|", four());
внешний | параметр / тело | аргумент | умолчание

one — задание 9 дня 8 по шагам: var x лёг правее стрелки, и она нашла внешний x. В two стрелка видит параметр, а тело пишет в копию. У three окружение одно (день 11). four — шаг 4: копия получила значение параметра.

4. Что видят умолчания

Практика плана. Из шагов выше: умолчание видит параметры левее, внешние имена, this и arguments. Не видит параметры правее (мёртвая зона), var, let и функции тела. Считается при каждом вызове и только для undefined — как в шаблонах дня 11. Предскажите:

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
function order(a = b, b = 1) { return a + b; }
function sees(a, b = a * 2, c = typeof inner) { function inner() {} return [a, b, c].join(); }
function counter(n = ++counter.calls) { return n; }
counter.calls = 0;
console.log(attempt(() => order()), "|", order(5), "|", sees(3));
console.log(counter(), counter(), counter(10), counter(undefined), counter(null));
function who(a = this === globalThis, n = arguments.length) { return [a, n].join(); }
console.log(who(), who.call("строка", undefined, undefined, 3));
ReferenceError: Cannot access 'b' before initialization | 6 | 3,6,undefined
1 2 10 3 null
true,0 false,3

inner ещё не создана, когда считается c. Счётчик вырос трижды: 10 и null — не undefined. В последней строке this — обёртка строки (OrdinaryCallBindThis дня 9).

5. Генераторы и async-функции

Разделы 15.5, 15.6, 15.8 и 15.9 повторяют 15.2–15.4 с тремя отличиями: свой прототип функции (первый блок дня); prototype генераторов создан без MakeConstructor, а у async-функций его нет; и порядок. EvaluateGeneratorBody (15.5.2) сначала выполняет FunctionDeclarationInstantiation, потом создаёт объект-генератор: параметры считаются при вызове, а не при первом next(), и ошибка в них бросается сразу; так же у async-генератора (15.6.2). У async-функции (15.8.4) и async-стрелки (15.9.3) этот шаг завёрнут в Completion: ошибка отклоняет промис, который функция вернёт.

const log = [];
function* gen(x = log.push("умолчание генератора")) { log.push("тело генератора"); yield x; }
const it = gen();
log.push("генератор создан");
it.next();
console.log(log.join(" → "));
const boom = (where) => { throw new Error("умолчание " + where); };
const tryCall = (f) => {
  try {
    const r = f();
    if (r instanceof Promise) { r.catch(() => {}); return "вернула отклонённый промис"; }
    return "вернула объект";
  } catch (e) { return "бросила сразу: " + e.message; }
};
console.log(tryCall(function* (x = boom("генератора")) {}));
console.log(tryCall(async function* (x = boom("async-генератора")) {}));
console.log(tryCall(async function (x = boom("async-функции")) {}));
console.log(tryCall(async (x = boom("async-стрелки")) => {}));

бросила сразу: умолчание async-генератора

вернула отклонённый промис

.catch() на результате поймает ошибку умолчания у async-функции, но не у async-генератора: тот бросает раньше, чем вернул объект. Отсюда и ранние ошибки: yield и await в параметрах запрещены — параметры считаются раньше, чем функция сможет приостановиться (примечание 2 к 15.5). А объект, который вернул генератор, наследует от gen.prototype, поэтому gen() instanceof gen — true, хотя new gen() бросает.

6. Объявление функции

15.2. Объявление создают заранее, при входе в функцию, скрипт или блок (FunctionDeclarationInstantiation, GlobalDeclarationInstantiation дня 13, BlockDeclarationInstantiation дня 11), поэтому его Evaluation (15.2.6) — пустое значение. Создаёт функцию InstantiateOrdinaryFunctionObject (15.2.4): OrdinaryFunctionCreate с %Function.prototype%, non-lexical-this и окружением, где стоит объявление, — это и есть замыкание (день 1 курса 2); SetFunctionName (у export default function () {} — "default"); MakeConstructor (10.2.5) — [[Construct]] и prototype с constructor внутри.

Тело выполняет EvaluateFunctionBody (15.2.3): FunctionDeclarationInstantiation, инструкции, в конце — return undefined. Ранние ошибки 15.2.1: параметр не повторяется в let тела (в var — можно), в строгом коде нет функций eval и arguments, нет super, а "use strict" (FunctionBodyContainsUseStrict, 15.2.2) — только при простом списке (день 3 курса 2).

7. Выражение функции и его имя

InstantiateOrdinaryFunctionExpression (15.2.5). Безымянное выражение получает имя от того, кому его присвоили, — NamedEvaluation дня 8. У именованного между внешним окружением и функцией встаёт окружение funcEnv с одной неизменяемой привязкой — именем функции. Флаг strict у неё false: запись в имя в нестрогом коде молча пропадает, в строгом — TypeError (у const флаг true, и та бросает всегда, день 11). Класс устроен похоже, но привязок имени у объявления две:

8. Стрелочные функции

15.3. Перед => нельзя переводить строку; тело-выражение не может начинаться с {, поэтому объект берут в скобки. Повтор имён параметров запрещён всегда (15.3.1). InstantiateArrowFunctionExpression (15.3.4) отличается от функции двумя аргументами: lexical-this и нет MakeConstructor. Примечание: своих arguments, super, this и new.target у стрелки нет, они ищутся снаружи. Механика — день 9: OrdinaryCallBindThis для lexical сразу возвращается, и ResolveThisBinding идёт мимо окружения стрелки наружу. Тело-выражение выполняет EvaluateConciseBody (15.3.3): FunctionDeclarationInstantiation, и значение сразу уходит в ReturnCompletion.

9. Методы

15.4 — методы объектов и классов, геттеры и сеттеры. DefineMethod (15.4.4): вычислить ключ, OrdinaryFunctionCreate — и MakeMethod вместо MakeConstructor. Функция запоминает [[HomeObject]], объект с методом, — отсюда работает super (день 10 курса 2); [[Construct]] ей не дали — new нельзя. MethodDefinitionEvaluation (15.4.5) кладёт метод с флагом enumerable, который ей передали: литерал объекта (13.2.5) — true, класс (15.7.13) — false. Имя геттера — с приставкой: SetFunctionName (closure, propKey, "get").

10. Классы: ранние ошибки

15.7. Класс — голова extends и тело: методы, поля, статические блоки, static и пустые ;; класс — всегда строгий код. Тело раскладывают ClassElementKind (15.7.2), ConstructorMethod (15.7.3), NonConstructorElements (15.7.5) и IsStatic (15.7.4): конструктор отдельно, остальное по порядку. Прочие операции работают на ранние ошибки 15.7.1 — один constructor, приватные имена без повторов, #имя только в своём классе, без arguments в полях. Предскажите, что пропустит разбор:

11. ClassDefinitionEvaluation по шагам

ClassDefinitionEvaluation (15.7.14) — главный алгоритм дня. День 8 курса 2 пересказал его четырьмя шагами, теперь — по тексту:

  1. окружение classEnv; у класса с именем — неизменяемая привязка имени без значения;
  2. приватное окружение: по Private Name на каждое #имя тела;
  3. extends вычисляется в classEnv (имя класса — в мёртвой зоне); не конструктор и не null — TypeError, prototype родителя не объект и не null — тоже;
  4. proto, будущий prototype, с родителем Parent.prototype (без extends — Object.prototype);
  5. конструктор F: свой — DefineMethod, MakeClassConstructor (без new — TypeError), MakeConstructor с незаписываемым prototype; своего нет — встроенный по умолчанию;
  6. в proto — неперечисляемое constructor = F;
  7. элементы по порядку — ClassElementEvaluation (15.7.13): метод ложится в proto или в F, у поля вычисляется только ключ, значение и статический блок становятся скрытыми функциями;
  8. привязка имени класса получает значение F;
  9. статические приватные методы — на F, затем статические поля и блоки по порядку, вперемешку;
  10. поля экземпляра ([[Fields]]) ждут каждого new (InitializeInstanceElements, день 7).

12. Практика: порядок создания класса

Практика плана. say пишет в журнал и возвращает значение. Предскажите обе строки:

const log = [];
const say = (text, value) => { log.push(text); return value; };
class Base { static base = say("static base", 0); }
class Card extends say("extends", Base) {
  [say("ключ метода", "show")]() {}
  word = say("поле word", "kitap");
  static [say("ключ static", "count")] = say("значение static", 0);
  static { say("блок: " + this.name); }
  [say("ключ поля", "id")] = say("поле id", 1);
  constructor() { super(); say("тело конструктора"); }
}
say("класс готов");
console.log(log.join(" → "));
log.length = 0;
new Card();
console.log(log.join(" → "));
static base → extends → ключ метода → ключ static → ключ поля → значение static → блок: Card → класс готов
поле word → поле id → тело конструктора

Первая строка — шаги 3, 7 и 9. static base — это создание Base целиком. Затем extends, потом элементы по порядку: три ключа вычислены, значения полей и блок отложены. После шага 8 — статические элементы по порядку: значение count, затем блок, где this.name — уже "Card". Вторая строка — new: после super() на объект встали поля экземпляра, потом выполнился остаток тела.

13. Имя класса и extends

У объявления класса две привязки имени (схема раздела 7): внутренняя в classEnv, неизменяемая, и внешняя — её ставит BindingClassDeclarationEvaluation (15.7.15) как let. У выражения класса (15.7.16) — только внутренняя; значение она получает на шаге 8.

14. Конструктор по умолчанию

Если своего constructor нет, шаг 5 создаёт встроенную функцию с длиной 0 и именем класса. Её шаги: без new — TypeError; у наследника — Construct родителя с теми же аргументами и NewTarget; у базового — объект с прототипом из NewTarget; потом поля экземпляра. Примечание: наследник ведёт себя почти как constructor(...args) { super(...args); }, но такой текст зовёт итератор массива (spread в вызове), а встроенная функция — нет. Это видно, если подменить итератор:

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
class A { constructor(...args) { this.args = args.join(); } }
class Implicit extends A {}
class Explicit extends A { constructor(...args) { super(...args); } }
const original = Array.prototype[Symbol.iterator];
const calls = [];
Array.prototype[Symbol.iterator] = function () { calls.push("итератор"); return original.call(this); };
const i1 = new Implicit(1, 2);
const n1 = calls.length;
const e1 = new Explicit(1, 2);
const n2 = calls.length - n1;
Array.prototype[Symbol.iterator] = original;
console.log(i1.args, n1, "|", e1.args, n2);

У явного конструктора итератор позвали один раз — для super(...args); остаток ...args в параметрах собирается без итератора. toString вернул текст всего класса: шаг 5 записал его в [[SourceText]] конструктора.

15. Поля и статические блоки

ClassFieldDefinitionEvaluation (15.7.10): ключ вычисляется сразу, а инициализатор становится функцией без параметров с MakeMethod; её [[HomeObject]] — proto или сам класс. По примечанию, коду эта функция не доступна, но видна по поведению: в инициализаторе есть this и super. Статический блок — ClassStaticBlockDefinitionEvaluation (15.7.11): тоже скрытая функция, её зовут на шаге 9 с this = F. Тело выполняет EvaluateClassStaticBlockBody (15.7.12) через FunctionDeclarationInstantiation — у блока своё окружение, и var из него не выходит:

class Base { static greeting = "привет"; }

  static reply = super.greeting + " от наследника";
  self = this;
  static { var local = "в блоке"; this.local = local; }
}
const c = new Child();
console.log(Child.reply, c.self === c, Child.local, typeof local);
class Counter {

super.greeting нашёл свойство родителя: [[HomeObject]] инициализатора — Child, его прототип — Base (день 10 курса 2). Стрелка в next взяла this инициализатора — класс — и считает от 10, добавленных блоком.

16. Хвостовые вызовы

15.10. День 9 показал: хвостовой вызов по стандарту занимает место текущего контекста, а V8 этого не делает. Кто решает, что вызов хвостовой? IsInTailPosition (15.10.1): строгий код, тело функции или стрелки — не генератора и не async; дальше HasCallInTailPosition (15.10.2) по дереву тела. Её спрашивают вызов, необязательная цепочка и тег шаблона (13.3); ответ true — EvaluateCall выполняет PrepareForTailCall (15.10.3) и освобождает контекст. Её же зовут встроенные call и apply.

Практика плана: рекурсия глубиной 10⁶ в хвостовой позиции и та же задача циклом — длина списка из миллиона звеньев:

Вызов size(node.next, total + 1) хвостовой по всем правилам, но Chrome кладёт на стек каждый контекст (по MDN, Safari — нет). Цикл — та же функция, переписанная механически: параметры стали переменными, хвостовой вызов — присваиванием и переходом к началу.

17. «Карточки 2.0»: шаблон в параметрах Card

Конструктор Card «Карточек 2.0» разбирает объект шаблоном прямо в списке параметров:

// card.js, день 33 курса 2 — конструктор Card
  constructor({ id, word, translation }) {
    if (!Number.isInteger(id)) throw new CardsError(`у карточки «${word}» нет номера`);

Сторож стоит в теле, а шаблон разбирается раньше — в FunctionDeclarationInstantiation (раздел 3). Если в файле колоды на месте удалённой карточки остался null, до сторожа очередь не дойдёт. Модель и исправление — принять объект целиком и разобрать после проверки:

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
class CardsError extends Error { constructor(message, options) { super(message, options); this.name = "CardsError"; } }
class Card {
  constructor({ id, word }) {
    if (!Number.isInteger(id)) throw new CardsError(`у карточки «${word}» нет номера`);
  }
}
class SafeCard {
  constructor(data) {
    if (typeof data !== "object" || data === null) throw new CardsError(`карточка — не объект: ${data}`);
    const { id, word } = data;
    if (!Number.isInteger(id)) throw new CardsError(`у карточки «${word}» нет номера`);
  }
}
for (const data of [{ word: "kitap" }, null, undefined]) console.log(attempt(() => new Card(data)), "|", attempt(() => new SafeCard(data)));

  1. Почему function one(a = () => x) { var x = "тело"; return a(); } возвращает внешний x?
    Ответ В параметрах есть код (ContainsExpression), поэтому FunctionDeclarationInstantiation кладёт var x тела в новое окружение. Стрелка создана в окружении параметров, его [[OuterEnv]] — внешнее: тела она не видит.
  2. Чему равен length у function (a, b = 1, c) {} и почему?
    Ответ 1. ExpectedArgumentCount считает параметры до первого умолчания; c после него считается необязательным.
  3. Чем отличается ошибка в умолчании у function* и у async function?
    Ответ EvaluateGeneratorBody выполняет FunctionDeclarationInstantiation с ? — генератор бросает прямо при вызове. EvaluateAsyncFunctionBody заворачивает её в Completion и отклоняет промис, который функция возвращает.
  4. Почему запись в имя внутри выражения function rename() { rename = 0; } молчит, а A = 1 в методе класса A бросает?
    Ответ Обе привязки неизменяемые, но у выражения функции strict = false, и в нестрогом коде запись просто пропадает. Код класса всегда строгий, а привязка имени класса создана со strict = true — TypeError.
  5. В каком порядке выполнятся ключ метода, значение статического поля, ключ поля экземпляра и статический блок, если они стоят в тексте именно так?
    Ответ Ключ метода, ключ поля (шаг 7, по порядку текста), затем значение статического поля и блок (шаг 9, тоже по порядку). Значение поля экземпляра — только при new.
  6. Хвостовые ли вызовы в return f() + 1 и в try { return f(); } catch { return g(); }?
    Ответ f() + 1 — нет: после вызова ещё сложение. В try вызов f — нет, g в catch — да (если нет finally).
