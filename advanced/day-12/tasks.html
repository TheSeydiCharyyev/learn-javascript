Разминка

1. Что видят умолчания
Легко7 мин

проходить окружения FunctionDeclarationInstantiation.

const attempt = (f) => { try { return String(f()); } catch (e) { return e.name; } };
var tag = "снаружи";
function a(x = tag, y = x + "!") { var tag = "тело"; return [x, y].join(" "); }
function b(x = () => tag) { let tag = "let тела"; return x(); }
function c(x = inner()) { function inner() { return "внутри"; } return x; }
console.log(a(), "|", b(), "|", attempt(c));
function d(first, second = first.length, { third = second * 2 } = {}) { return [second, third].join(); }
console.log(d("abc"), "|", d("abc", null), "|", d("abc", undefined, { third: 0 }));
  • предсказаны две строки;
  • для b и c названо окружение, куда легли let tag и inner, и почему умолчание его не видит;
  • объяснено, откуда пустое место во втором ответе d.

Основные задания

4. Свой разбор списка параметров
Средне12 мин

перенести 15.1.2–15.1.5 в код.

Список — массив строк, как их пишут в скобках, шаблоны без вложений. Напишите paramInfo(list) → { length, simple, code }: length — параметры до первого умолчания верхнего уровня или остатка (ExpectedArgumentCount), simple — только имена (IsSimpleParameterList), code — есть = где угодно или вычисляемый ключ [ внутри { } (ContainsExpression). Подсказка: перед поиском = замените каждое {…} и […] одним символом.

paramInfo(["a", "b"]);                 // { length: 2, simple: true, code: false }
paramInfo(["a", "b = 1", "c"]);        // { length: 1, simple: false, code: true }
paramInfo(["{ a = 1 }", "[b]"]);       // { length: 2, simple: false, code: true }
paramInfo(["{ a }", "...rest"]);       // { length: 1, simple: false, code: false }
paramInfo(["{ [key]: a }"]);           // { length: 1, simple: false, code: true }
  • все пять строк примера дают то, что в комментариях;
  • для каждого списка length совпал с new Function(...list, "").length, а simple — с тем, принимает ли new Function(...list, '"use strict"');
  • объяснено, почему { a = 1 } идёт в length: HasInitializer у шаблона.
5. Своя FunctionDeclarationInstantiation
Средне14 мин

построить окружения параметров и тела на модели.

Окружение — объект, внешнее — его прототип (Object.create(outer)): поиск по цепочке прототипов играет роль [[OuterEnv]]. Параметр — [имя, умолчание], умолчание — функция от окружения параметров; тело — { vars, run }. Напишите instantiate(outer, params, args, body) по шагам раздела 3 лекции: окружение параметров и значения слева направо (умолчание — для undefined); есть хоть одно умолчание — для vars новое окружение с копией значения одноимённого параметра, нет — vars в том же окружении; ответ — body.run(окружение тела).

const outer = { x: "внешний" };
instantiate(outer, [["a", (s) => () => s.x]], [], { vars: ["x"], run: (s) => { s.x = "тело"; return s.a(); } });   // "внешний"
instantiate(outer, [["a", (s) => () => s.x], ["x", () => "параметр"]], [], { vars: ["x"], run: (s) => { s.x = "тело"; return [s.a(), s.x].join(" / "); } });   // "параметр / тело"
instantiate(outer, [["x"]], ["аргумент"], { vars: ["x"], run: (s) => s.x });   // "аргумент"
instantiate(outer, [["x", () => "умолчание"]], [], { vars: ["x"], run: (s) => s.x });   // "умолчание"
  • все четыре строки примера дают то, что в комментариях;
  • те же четыре случая, записанные настоящими функциями one…four лекции, дают те же ответы;
  • объяснено, почему стрелка из умолчания читает окружение параметров, а не тела.
6. Хвостовая рекурсия без стека
Средне12 мин

получить хвостовой вызов там, где движок его не делает.

Хвостовой вызов можно заменить возвратом «отложенного вызова» — стрелки () => f(…). Напишите trampoline(f): функцию, которая вызывает f и, пока результат — функция, вызывает его. Каждый вызов кончается раньше следующего, и стек не растёт.

function sumTo(n, acc = 0) { return n === 0 ? acc : () => sumTo(n - 1, acc + n); }
const sum = trampoline(sumTo);
sum(3);       // 6
sum(1e6);     // 500000500000
  • обе строки примера дают то, что в комментариях;
  • та же сумма строгой рекурсией sumRec(n, acc) даёт RangeError на 10⁶, а циклом — тот же ответ; объяснено, почему у sumRec нельзя acc = 0;
  • названо, какую функцию trampoline не сможет вернуть как значение.
7. «Карточки 2.0»: Card.fromList
Средне12 мин

сторожить аргумент до разбора и сообщать, какая карточка сломана.

Перепишите Card из раздела 17 лекции: constructor(data) сначала проверяет, что data — объект (иначе CardsError «не объект: …»), потом разбирает его и проверяет поля, как в дне 33 курса 2. Добавьте статический метод fromList(list): карточки через new this(item), а ошибку карточки — в CardsError «карточка N из M: …» с cause.

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
class CardsError extends Error { constructor(message, options) { super(message, options); this.name = "CardsError"; } }
const two = Card.fromList([{ id: 1, word: "kitap", translation: "книга" }, { id: 2, word: "galam", translation: "ручка" }]);
two.map((c) => c.word).join();                                                          // "kitap,galam"
attempt(() => Card.fromList([{ id: 1, word: "kitap", translation: "книга" }, null]));   // "CardsError: карточка 2 из 2: не объект: null"
Card.length;                                                                             // 1
  • все три строки примера дают то, что в комментариях;
  • у ошибки списка cause — CardsError самой карточки;
  • class BigCard extends Card {}: BigCard.fromList создаёт BigCard — объяснено, чему равен this в статическом методе.

Со звёздочкой

8. Свой ClassDefinitionEvaluation
Сложно12 мин

повторить порядок 15.7.14 без слова class.

Элемент — { kind, isStatic, key, value }: kind — "method", "field" или "block", key() вычисляет ключ, value — метод, функция значения поля или тело блока. Напишите createClass(elements) по шагам 5–10 раздела 11 лекции: функция F (без new — TypeError, при new — поля экземпляра по порядку); элементы по порядку — метод сразу в F.prototype или в F, у поля только ключ; потом статические поля и блоки по порядку с this = F.

const log = [];
const say = (t, v) => { log.push(t); return v; };
const Card = createClass([
  { kind: "method", key: () => say("ключ метода", "show"), value() { return "метод"; } },
  { kind: "field", key: () => say("ключ поля", "word"), value: () => say("поле", "kitap") },
  { kind: "field", isStatic: true, key: () => say("ключ static", "count"), value: () => say("значение static", 0) },
  { kind: "block", value() { say("блок"); this.ready = true; } },
]);
log.join(", ");     // "ключ метода, ключ поля, ключ static, значение static, блок"
new Card().word;    // "kitap"
Card.ready;         // true
  • все три строки примера дают то, что в комментариях;
  • настоящий class с теми же четырьмя элементами пишет тот же журнал;
  • названы шаги 15.7.14, которых в модели нет, и видимое отличие: Object.keys(Card.prototype).
9. Незнакомый раздел: arguments в поле
Сложно8 мин

прочитать раздел, который на лекции был одной строкой справочника.

Прочитайте 15.7.9 ContainsArguments и предскажите пять ответов разбора.

const parse = (code) => { try { new Function(code); return "ok"; } catch (e) { return e.name; } };
console.log(["class A { x = function () { return arguments; }; }", "class A { x = () => arguments; }", "class A { x = { m() { return arguments; } }; }",
