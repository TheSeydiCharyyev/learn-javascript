## Основные задания

<Task title="4. Свой разбор списка параметров" level="medium" time="12">
<Goal>перенести 15.1.2–15.1.5 в код.</Goal>

Список — массив строк, как их пишут в скобках, шаблоны без вложений. Напишите
`paramInfo(list)` → `{ length, simple, code }`: `length` — параметры до первого
умолчания *верхнего уровня* или остатка (ExpectedArgumentCount), `simple` — только имена
(IsSimpleParameterList), `code` — есть `=` где угодно или вычисляемый ключ `[`
внутри `{ }` (ContainsExpression). Подсказка: перед поиском `=` замените каждое
`{…}` и `[…]` одним символом.

<Example>
```js
paramInfo(["a", "b"]);                 // { length: 2, simple: true, code: false }
paramInfo(["a", "b = 1", "c"]);        // { length: 1, simple: false, code: true }
paramInfo(["{ a = 1 }", "[b]"]);       // { length: 2, simple: false, code: true }
paramInfo(["{ a }", "...rest"]);       // { length: 1, simple: false, code: false }
paramInfo(["{ [key]: a }"]);           // { length: 1, simple: false, code: true }
```
</Example>

<Criteria>
- все пять строк примера дают то, что в комментариях;
- для каждого списка `length` совпал с `new Function(...list, "").length`, а
  `simple` — с тем, принимает ли `new Function(...list, '"use strict"')`;
- объяснено, почему `{ a = 1 }` идёт в `length`: HasInitializer у шаблона.
</Criteria>
</Task>

<Task title="5. Своя FunctionDeclarationInstantiation" level="medium" time="14">
<Goal>построить окружения параметров и тела на модели.</Goal>

Окружение — объект, внешнее — его прототип (`Object.create(outer)`): поиск по цепочке прототипов
играет роль \[\[OuterEnv\]\]. Параметр — `[имя, умолчание]`, умолчание — функция от окружения
параметров; тело — `{ vars, run }`. Напишите `instantiate(outer, params, args, body)` по
шагам раздела 3 лекции: окружение параметров и значения слева направо (умолчание — для `undefined`);
есть хоть одно умолчание — для `vars` новое окружение с копией значения одноимённого параметра, нет —
`vars` в том же окружении; ответ — `body.run(окружение тела)`.

<Example>
```js
const outer = { x: "внешний" };
instantiate(outer, [["a", (s) => () => s.x]], [], { vars: ["x"], run: (s) => { s.x = "тело"; return s.a(); } });   // "внешний"
instantiate(outer, [["a", (s) => () => s.x], ["x", () => "параметр"]], [], { vars: ["x"], run: (s) => { s.x = "тело"; return [s.a(), s.x].join(" / "); } });   // "параметр / тело"
instantiate(outer, [["x"]], ["аргумент"], { vars: ["x"], run: (s) => s.x });   // "аргумент"
instantiate(outer, [["x", () => "умолчание"]], [], { vars: ["x"], run: (s) => s.x });   // "умолчание"
```
</Example>

<Criteria>
- все четыре строки примера дают то, что в комментариях;
- те же четыре случая, записанные настоящими функциями `one`…`four` лекции, дают
  те же ответы;
- объяснено, почему стрелка из умолчания читает окружение параметров, а не тела.
</Criteria>
</Task>

<Task title="6. Хвостовая рекурсия без стека" level="medium" time="12">
<Goal>получить хвостовой вызов там, где движок его не делает.</Goal>

Хвостовой вызов можно заменить возвратом «отложенного вызова» — стрелки `() => f(…)`. Напишите
`trampoline(f)`: функцию, которая вызывает `f` и, пока результат — функция, вызывает его.
Каждый вызов кончается раньше следующего, и стек не растёт.

<Example>
```js
function sumTo(n, acc = 0) { return n === 0 ? acc : () => sumTo(n - 1, acc + n); }
const sum = trampoline(sumTo);
sum(3);       // 6
sum(1e6);     // 500000500000
```
</Example>

<Criteria>
- обе строки примера дают то, что в комментариях;
- та же сумма строгой рекурсией `sumRec(n, acc)` даёт RangeError на 10⁶, а циклом — тот же
  ответ; объяснено, почему у `sumRec` нельзя `acc = 0`;
- названо, какую функцию `trampoline` не сможет вернуть как значение.
</Criteria>
</Task>

const attempt = (f) => { try { return String(f()); } catch (e) { return `${e.name}: ${e.message}`; } };
class CardsError extends Error { constructor(message, options) { super(message, options); this.name = "CardsError"; } }

## Со звёздочкой

<Task title="8. Свой ClassDefinitionEvaluation" level="hard" time="12">
<Goal>повторить порядок 15.7.14 без слова `class`.</Goal>

Элемент — `{ kind, isStatic, key, value }`: `kind` — `"method"`,
`"field"` или `"block"`, `key()` вычисляет ключ, `value` — метод,
функция значения поля или тело блока. Напишите `createClass(elements)` по шагам 5–10 раздела 11
лекции: функция F (без `new` — TypeError, при `new` — поля экземпляра по порядку);
элементы по порядку — метод сразу в `F.prototype` или в F, у поля только ключ; потом статические поля и
блоки по порядку с `this` = F.

<Example>
```js
const log = [];
const say = (t, v) => { log.push(t); return v; };
const Card = createClass([
  { kind: "method", key: () => say("ключ метода", "show"), value() { return "метод"; } },
  { kind: "field", key: () => say("ключ поля", "word"), value: () => say("поле", "kitap") },
  { kind: "field", isStatic: true, key: () => say("ключ static", "count"), value: () => say("значение static", 0) },
  { kind: "block", value() { say("блок"); this.ready = true; } },
]);
log.join(", ");     // "ключ метода, ключ поля, ключ static, значение static, блок"
new Card().word;    // "kitap"
Card.ready;         // true
```
</Example>

<Criteria>
- все три строки примера дают то, что в комментариях;
- настоящий `class` с теми же четырьмя элементами пишет тот же журнал;
- названы шаги 15.7.14, которых в модели нет, и видимое отличие: `Object.keys(Card.prototype)`.
</Criteria>
</Task>
