1. Глава 10: обычные и экзотические

Глава 10 — как ведут себя объекты. День 4 показал таблицу 4: одиннадцать внутренних методов у любого объекта. Обычный объект — тот, у кого все они взяты из 10.1, а у функции ещё [[Call]] и [[Construct]] из 10.2 или 10.3. Остальные — экзотические: массив, строка, arguments, связанная функция — завтра, Proxy — день 16. Экзотическим объект делает хотя бы один свой метод: у массива — [[DefineOwnProperty]] (из-за length), у связанной функции — [[Call]] и [[Construct]]. Поэтому всё сегодняшнее — правила по умолчанию, от которых экзотика отступает.

У обычного объекта два слота: [[Prototype]] и [[Extensible]]. Вступление 10.1 сводит наследование к четырём правилам — день 7 курса 2 видел их на опыте:

2. Прототип, расширяемость, in и delete

Шесть методов 10.1 — по строке: [[GetPrototypeOf]] (10.1.1) и [[IsExtensible]] (10.1.3) читают слот; [[PreventExtensions]] (10.1.4) ставит false и отвечает true; [[HasProperty]] (10.1.7) — своё свойство или вопрос прототипу; [[Delete]] (10.1.10) удаляет только configurable, на остальное отвечает false. Интереснее [[SetPrototypeOf]] (10.1.2): тот же прототип — true сразу; нерасширяемый объект — false; потом идёт по цепочке нового прототипа и отвечает false, если встретит сам объект, — цикла не будет. False превращают в TypeError вызывающие: Object.setPrototypeOf и сеттер __proto__.

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const a = {}, b = Object.create(a);
console.log(run(() => Object.setPrototypeOf(a, b)), "|", run(() => { a.__proto__ = b; }));
const closed = Object.preventExtensions({ x: 1 });
console.log(Object.isExtensible(closed), run(() => Object.setPrototypeOf(closed, {})), run(() => Object.setPrototypeOf(closed, Object.prototype)));
console.log("x" in Object.create(closed), delete closed.x, delete Object.seal({ y: 1 }).y, delete Object.prototype);

Прежний прототип нерасширяемому поставить можно: шаг «тот же — true» стоит раньше проверки. А preventExtensions не мешает удалять: [[Delete]] смотрит только на configurable. Поиск цикла останавливается и на объекте с необычным [[GetPrototypeOf]] — у Proxy (день 16) свою цепочку обычный метод не проверяет.

3. [[GetOwnProperty]] и полный дескриптор

[[GetOwnProperty]] (10.1.5) зовёт OrdinaryGetOwnProperty: нет своего свойства — undefined; есть — новый дескриптор со всеми полями его вида: value и writable или get и set, плюс enumerable и configurable. Дескриптор — копия: правка её не трогает свойство.

[[DefineOwnProperty]] (10.1.6) читает текущий дескриптор, узнаёт расширяемость и отдаёт всё ValidateAndApplyPropertyDescriptor (10.1.6.3). Создавая свойство, она берёт недостающие поля по умолчанию — false и undefined:

const o = {};
Object.defineProperty(o, "x", { value: 1 });
o.y = 2;
console.log(JSON.stringify(Object.getOwnPropertyDescriptor(o, "x")), JSON.stringify(Object.getOwnPropertyDescriptor(o, "y")));
{"value":1,"writable":false,"enumerable":false,"configurable":false} {"value":2,"writable":true,"enumerable":true,"configurable":true}

Присваивание создаёт свойство иначе: CreateDataProperty (день 7) передаёт все три флага true — правило дня 5 курса 2.

Дескриптор, который передают в defineProperty, — обычный объект. ToPropertyDescriptor (6.2.6.5) читает его поля через HasProperty и Get, значит, и унаследованные. Аксессор вместе с value — TypeError ещё до [[DefineOwnProperty]]:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const o = {};
Object.defineProperty(o, "x", Object.create({ value: 7, enumerable: true }));
console.log(o.x, Object.keys(o).length, "|", run(() => Object.defineProperty(o, "y", { get() {}, value: 1 })));
7 1 | TypeError: Invalid property descriptor. Cannot both specify accessors and a value or writable attribute, #<Object>

4. ValidateAndApplyPropertyDescriptor по шагам

10.1.6.3:

  1. своего свойства нет: объект нерасширяемый — false; иначе создать свойство из полей Desc и умолчаний;
  2. в Desc нет полей — true, ничего не меняется;
  3. свойство не configurable: нельзя сделать его configurable, сменить enumerable, сменить вид (данные ↔ аксессор), заменить get или set; у незаписываемого — нельзя writable: true и значение, которое не SameValue прежнему;
  4. иначе применить: смена вида сохраняет enumerable и configurable, остальное берётся из Desc.

Каждое «нельзя» — false, Object.defineProperty делает из него TypeError (DefinePropertyOrThrow). Правила дня 5 курса 2 — это шаг 3:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const p = {};
Object.defineProperty(p, "y", { value: 1, writable: true });
console.log(run(() => Object.defineProperty(p, "y", { value: 2 })), run(() => Object.defineProperty(p, "y", { writable: false })), run(() => Object.defineProperty(p, "y", { writable: true })), run(() => Object.defineProperty(p, "y", { value: 2 })));
const q = {};
Object.defineProperty(q, "n", { value: NaN });
Object.defineProperty(q, "z", { value: 0 });
console.log(run(() => Object.defineProperty(q, "n", { value: NaN })), run(() => Object.defineProperty(q, "z", { value: -0 })), run(() => Object.defineProperty(q, "z", { enumerable: true })), run(() => Object.defineProperty(q, "z", {})));
ok ok TypeError: Cannot redefine property: y ok
ok TypeError: Cannot redefine property: z TypeError: Cannot redefine property: z ok

Неудаляемое записываемое свойство можно закрыть на запись, открыть обратно — нет. Тот же NaN проходит, −0 вместо +0 — нет: сравнение по SameValue. Примечание к шагу: разные NaN SameValue считает равными, хотя их можно различить по битам (DataView, день 21), — поэтому шаг отвечает сразу и ничего не записывает.

Шаг 4 у configurable свойства: смена вида сохраняет enumerable и configurable, а value и writable пропадают. Object.freeze — SetIntegrityLevel (7.3.15): [[PreventExtensions]], потом каждому своему ключу [[DefineOwnProperty]] с configurable: false, у данных — ещё writable: false; seal — только configurable:

5. [[Get]] и Receiver

[[Get]] (10.1.8), OrdinaryGet(O, P, Receiver): своё свойство данных — его значение; аксессор — геттер, вызванный с this = Receiver (нет геттера — undefined); своего нет — тот же [[Get]] у прототипа с тем же Receiver, прототип null — undefined. Receiver — объект, с которого начали:

const base = { get who() { return this.name; }, name: "base" };
const child = Object.create(base);
child.name = "child";
console.log(child.who, base.who);
child base

super.x (день 10 курса 2) — тот же [[Get]], только поиск начинается с прототипа [[HomeObject]], а Receiver — this метода.

Receiver бывает и примитивом. Для "abc".kind GetValue (6.2.5.5) берёт обёртку только для поиска, а Receiver оставляет строкой: строгий геттер видит примитив, нестрогий — обёртку (OrdinaryCallBindThis, день 9). У [[Set]] примитив в Receiver — это шаг «Receiver не объект — false» из следующего раздела:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
Object.defineProperty(String.prototype, "kind", { get() { "use strict"; return typeof this; }, configurable: true });
Object.defineProperty(String.prototype, "sloppyKind", { get() { return typeof this; }, configurable: true });
console.log("abc".kind, "abc".sloppyKind, "|", run(() => { "use strict"; "abc".x = 1; }), run(() => { "abc".x = 1; }));
string object | TypeError: Cannot create property 'x' on string 'abc' ok

6. [[Set]] по шагам

[[Set]] (10.1.9), OrdinarySet: взять свой дескриптор и отдать OrdinarySetWithOwnDescriptor (10.1.9.2):

  1. своего нет — спросить [[Set]] прототипа с тем же Receiver; прототипа нет — считать, что нашлось записываемое свойство данных;
  2. нашлись данные: незаписываемые — false; Receiver не объект — false; у Receiver своё свойство: аксессор или незаписываемое — false, иначе [[DefineOwnProperty]] с одним полем value; своего нет — CreateDataProperty у Receiver;
  3. нашёлся аксессор: нет сеттера — false; иначе вызвать сеттер с this = Receiver, true.

Отсюда override mistake дня 7 курса 2: незаписываемое свойство прототипа не даёт завести своё. А «одно поле value» значит: остальные флаги своего свойства остаются прежними:

const h = {};
Object.defineProperty(h, "hidden", { value: 1, writable: true });
h.hidden = 2;
console.log(JSON.stringify(Object.keys(h)), h.hidden, JSON.stringify(Object.getOwnPropertyDescriptor(h, "hidden")));
[] 2 {"value":2,"writable":true,"enumerable":false,"configurable":false}

super.x = v: когда Receiver — не O

При обычном присваивании Receiver и есть объект, у которого искали. Разойтись они могут в super.x = v: [[Set]] зовётся у прототипа [[HomeObject]], а Receiver — this. Тогда работает проверка своего свойства Receiver из шага 2:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
class A {}
A.prototype.x = 1;
class B extends A { write() { super.x = 5; } }
const viaAccessor = new B();
Object.defineProperty(viaAccessor, "x", { get() { return "своё"; }, configurable: true });
const viaFixed = new B();
Object.defineProperty(viaFixed, "x", { value: "своё", writable: false, configurable: true });
console.log(run(() => viaAccessor.write()), "|", run(() => viaFixed.write()));
TypeError: Cannot redefine property: x | TypeError: Cannot assign to read only property 'x' of object '#<B>'

У A.prototype x записываемый, поэтому решает своё свойство this: аксессор и незаписываемое — false, а код класса строгий. Текст V8 в первом случае — «Cannot redefine», хотя по шагам до [[DefineOwnProperty]] дело не дошло.

7. Практика: сеттер в прототипе

Практика плана: запись в свойство, у которого сеттер в прототипе. Присваивание идёт по [[Set]] и находит сеттер. Поле класса — нет: поля определяются, а не присваиваются (DefineField → CreateDataPropertyOrThrow, день 7), и сеттер прототипа не видят:

const log = [];
class Model { set title(v) { log.push(`сеттер: ${v}`); } get title() { return "из геттера"; } }
class Plain extends Model { constructor() { super(); this.title = "присваивание"; } }
class Field extends Model { title = "поле"; }
const plain = new Plain(), field = new Field();
console.log(log.join(", "), Object.hasOwn(plain, "title"), plain.title, Object.hasOwn(field, "title"), field.title);
сеттер: присваивание false из геттера true поле

У field своё свойство данных закрыло аксессор модели: следующее field.title = … найдёт его на шаге 2 и сеттер не позовёт. Модели, которая проверяет запись сеттером, поле наследника с тем же именем отключает проверку.

Так же расходятся Object.assign (20.1.2.1: Set для каждого ключа) и spread в литерале (CopyDataProperties: CreateDataPropertyOrThrow):

const log = [];
class Model { set title(v) { log.push(`сеттер: ${v}`); } }
const viaAssign = Object.assign(new Model(), { title: "assign" });
const viaSpread = { __proto__: Model.prototype, ...{ title: "spread" } };
console.log(log.join(), Object.hasOwn(viaAssign, "title"), Object.hasOwn(viaSpread, "title"));
сеттер: assign false true

8. Практика: порядок ключей

[[OwnPropertyKeys]] (10.1.11), OrdinaryOwnPropertyKeys: сначала индексы массива по возрастанию, потом остальные строки в порядке создания, потом символы в порядке создания. Индекс массива — каноническая запись целого от 0 до 2³² − 2 (6.1.7). Практика плана:

const sym = Symbol("s");
const keys = { b: 1, 2: 1, [sym]: 1, a: 1, 1: 1, "-1": 1, "01": 1, 4294967295: 1, 4294967294: 1, 1.5: 1 };
console.log(Object.getOwnPropertyNames(keys).join(" "), "|", Object.getOwnPropertySymbols(keys).length);
const seen = [];
for (const k in keys) seen.push(k);
console.log(Object.keys(keys).join(" ") === seen.join(" "), JSON.stringify(keys));
const arr = ["a"];
arr.x = 1;
arr[5] = "f";
console.log(Object.keys(arr).join(" "));
1 2 4294967294 b a -1 01 4294967295 1.5 | 1
true {"1":1,"2":1,"4294967294":1,"b":1,"a":1,"-1":1,"01":1,"4294967295":1,"1.5":1}
0 5 x

"-1", "01" и "1.5" — не канонические целые, а 4294967295 = 2³² − 1 уже не индекс: все четыре встали по времени создания. Индексы сортируются как числа: 2 раньше 10, хотя строка "10" меньше строки "2". У массива то же правило. Object.keys, for-in (порядок с прототипами — день 11) и JSON.stringify берут ключи у одного [[OwnPropertyKeys]].

10. Как создаётся объект

Четыре операции 10.1.12–10.1.15. OrdinaryObjectCreate(proto) — пустой обычный объект с этим прототипом; примечание: слово «обычный» — обещание, что методы ему потом не заменят, экзотические объекты создаёт напрямую MakeBasicObject. OrdinaryCreateFromConstructor — то же для new, а прототип выбирает GetPrototypeFromConstructor: свойство prototype конструктора, а если там не объект — встроенный прототип реалма конструктора. Объект создан вызовом из нашего окна, а прототип у него — Object.prototype рамки: примечание 10.1.14 берёт его у реалма конструктора (день 9). Последняя строка — RequireInternalSlot: прототип Date у объекта есть, слота [[DateValue]] нет.

11. Функция: слоты таблицы 25

10.2: функция — обычный объект с [[Call]] и слотами таблицы 25: [[Environment]] (окружение, где создана), [[PrivateEnvironment]], [[FormalParameters]], [[ECMAScriptCode]], [[ConstructorKind]] (base или derived), [[Realm]], [[ScriptOrModule]], [[ThisMode]] (lexical, strict, global — день 9), [[Strict]], [[HomeObject]], [[SourceText]] (toString — день 4 курса 2), [[Fields]] и [[PrivateMethods]] класса, [[ClassFieldInitializerName]], [[IsClassConstructor]]. Слоты ставятся при создании и потом не меняются:

const base = { hi() { return "base"; } };
const obj = { __proto__: base, hi() { return "obj+" + super.hi(); } };
const other = { __proto__: { hi() { return "other"; } }, hi: obj.hi };
console.log(other.hi());

const one = makeCounter(), two = makeCounter();

Метод переехал в other, но super ищет от своего [[HomeObject]] — obj. У двух стрелок одно тело и разные [[Environment]] — тот слот, который обещал день 1 курса 2. [[SourceText]] — ровно текст из кода, его и отдаёт toString:

12. [[Call]] по шагам

[[Call]] (10.2.1):

  1. PrepareForOrdinaryCall: новый контекст (день 9) с реалмом функции и новым окружением функции;
  2. класс ([[IsClassConstructor]]) — TypeError, созданная уже в контексте вызываемого, то есть в его реалме;
  3. OrdinaryCallBindThis (день 9): lexical — ничего, strict — как есть, global — undefined и null дают globalThis, примитив — обёртку;
  4. OrdinaryCallEvaluateBody: EvaluateBody, внутри — FunctionDeclarationInstantiation (раздел 15) и тело;
  5. контекст снять; return — его значение, иначе — undefined (а throw — дальше).
const frame = document.createElement("iframe");

13. [[Construct]] по шагам

[[Construct]] (10.2.2) зависит от [[ConstructorKind]]:

  1. base: this = OrdinaryCreateFromConstructor(newTarget) — прототип берётся у того, кого вызвали через new;
  2. PrepareForOrdinaryCall(F, newTarget); у base — привязать this и поставить поля (InitializeInstanceElements, день 7);
  3. тело;
  4. вернули объект — он и результат; иначе base отдаёт this; derived: вернули не undefined — TypeError, иначе this из окружения — без super() там пусто, ReferenceError.
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
function Base() { this.a = 1; return 42; }
function Swap() { this.a = 1; return { swapped: true }; }
class Derived extends Object { constructor() { super(); return 1; } }
class NoSuper extends Object { constructor() {} }
console.log(new Base().a, new Swap().swapped, run(() => new Derived()), "|", run(() => new NoSuper()));
class P { constructor() { this.kind = new.target.name; } }
class Q extends P {}
const q = new Q();
console.log(q.kind, Object.getPrototypeOf(q) === Q.prototype);
1 true TypeError: Derived constructors may only return object or undefined | ReferenceError: Must call super constructor in derived class before accessing 'this' or returning from derived constructor
Q true

Объект для Q создал [[Construct]] базового P, но прототип взял у newTarget — Q. Поля производного класса ставит сам super() (13.3.7.1): Construct родителя, BindThisValue, потом InitializeInstanceElements — поэтому они появляются после тела родителя и до строки, что идёт за super() (день 12, задание 3).

14. Имя, длина и prototype

Разделы 10.2.3–10.2.10 — как функция собирается (день 12): OrdinaryFunctionCreate — объект со слотами таблицы 25, [[Call]] и length; MakeConstructor — [[Construct]] и prototype; MakeClassConstructor — [[IsClassConstructor]]; MakeMethod — [[HomeObject]]; DefineMethodProperty — свойство-метод; SetFunctionName — name: символ даёт «[описание]» или пустую строку, приставка пишется через пробел. У name и length флаги одни: незаписываемые, неперечисляемые, удаляемые.

const s = Symbol("знак");

Имя класс получает до своих элементов, а name удаляемое — и статический метод с этим именем его заменяет (DefineMethodProperty).

Chrome против текста: caller и arguments

AddRestrictedFunctionProperties (10.2.4) CreateIntrinsics зовёт для Function.prototype: caller и arguments — аксессоры, у которых и геттер, и сеттер — %ThrowTypeError% (10.2.4.1): одна безымянная функция длины 0, которая бросает всегда. Её же получает callee у arguments строгой функции.

const c = Object.getOwnPropertyDescriptor(Function.prototype, "caller");
const thrower = Object.getOwnPropertyDescriptor((function () { "use strict"; return arguments; })(), "callee").get;
function sloppy() { return sloppy.caller === outer; }
function outer() { return sloppy(); }
console.log(c.get === thrower, c.get === c.set, JSON.stringify([c.get.name, thrower.name]), outer());
false false ["get caller",""] true

По тексту первые три значения были бы true true ["",""], а outer() бросил бы TypeError — и строки не было бы вовсе. Chrome 156 ставит свои аксессоры: у строгой функции они бросают, у нестрогой во время вызова отдают того, кто её вызвал. MDN называет это нестандартным и устаревшим (страницы Function.prototype.caller и arguments — день 31).

15. FunctionDeclarationInstantiation целиком

10.2.11 обещали дни 12 и 13: окружения параметров и тела — раздел 3 дня 12, окружение для eval в умолчаниях — день 13. Все шаги:

  1. собрать имена: параметры, есть ли повторы, простой ли список, есть ли код; имена var, лексические, функции тела — с конца, из одноимённых побеждает последняя;
  2. нужен ли arguments: нет у стрелки, при параметре с этим именем и — если в параметрах нет кода — при функции или let с этим именем в теле;
  3. привязки параметров и arguments: связанный у нестрогого простого списка, иначе нет;
  4. значения параметров слева направо; при повторах — без окружения, как присваивание, последний побеждает;
  5. var тела: без кода в параметрах — в то же окружение, и var с именем параметра сохраняет его значение;
  6. приложение B — функции в блоках (день 31); лексические имена — без значения; функции тела — сразу объектами, поверх параметров.
function dup(a, a) { return a; }
function shadowParam(x) { function x() {} return typeof x; }
function copyVar(x) { var x; return x; }
function argsFn() { function arguments() {} return typeof arguments; }
function argsParam(arguments) { return arguments; }
function argsLet() { let arguments = "let"; return arguments; }
console.log(dup(1, 2), shadowParam(1), copyVar(5), argsFn(), argsParam("параметр"), argsLet());
2 function 5 function параметр let

Функция тела записана последней и закрыла параметр x. В трёх последних объект arguments не создавался вовсе — шаг 2. Повтор имён шаг 4 допускает только у нестрогого простого списка: в строгом коде или с умолчанием это ранняя ошибка «Duplicate parameter name not allowed in this context» (день 8).

16. Встроенные функции

10.3: встроенная функция — тоже обычный объект, но со слотами [[Realm]], [[InitialName]] (его печатает toString, 20.2.3.5) и [[Async]]. Её [[Call]] и [[Construct]] (10.3.1–10.3.2) идут в BuiltinCallOrConstruct (10.3.3): контекст без ScriptOrModule и выполнение «по описанию функции». [[Construct]] есть только у описанных как конструктор. CreateBuiltinFunction (10.3.4) ставит length и name, но не prototype:

17. «Карточки 2.0»: геттер без сеттера

Карточка «Карточек 2.0» отдаёт поля только геттерами:

// card.js, день 33 курса 2 — геттеры Card
  get id() {
    return this.#id;
  }
  get word() {
    return this.#word;
  }

Модель — что будет с записью в word (модули строгие, поэтому и модель строгая):

"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
class Card { #word; constructor(word) { this.#word = word; } get word() { return this.#word; } }
const card = new Card("kitap");
console.log(run(() => { card.word = "galam"; }), card.word);
Object.defineProperty(card, "word", { value: "galam" });
console.log(card.word, JSON.stringify(card), JSON.stringify({ ...new Card("suw") }));
TypeError: Cannot set property word of #<Card> which has only a getter kitap
galam {} {}

Присваивание дошло по цепочке до аксессора без сеттера — false, в строгом коде TypeError. А defineProperty по [[Set]] не ходит: карточка расширяемая, и ValidateAndApplyPropertyDescriptor создаёт своё свойство, закрывающее геттер. JSON.stringify и { ...card } пусты: своих перечисляемых ключей нет — геттеры в прототипе, поля приватные. Закрыть дыру можно Object.freeze(this) в конце конструктора — но у этого есть цена:

"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
class Card { #word; constructor(word) { this.#word = word; Object.freeze(this); } get word() { return this.#word; } }
class BigCard extends Card { level = 2; }
const card = new Card("kitap");
console.log(run(() => Object.defineProperty(card, "word", { value: "galam" })), card.word, "|", run(() => new BigCard("suw")));
TypeError: Cannot define property word, object is not extensible kitap | TypeError: Cannot define property level, object is not extensible

Шаг 1 ValidateAndApplyPropertyDescriptor: своего нет, объект нерасширяемый — false. Но та же проверка ловит и поле наследника: поля BigCard ставятся после super(), когда карточка уже заморожена. Приватному полю заморозка не мешает: #word — не свойство, [[DefineOwnProperty]] его не касается.

  1. Почему obj.fixed = "своё" не создаёт своего свойства, если fixed в прототипе незаписываемый?
    Ответ OrdinarySetWithOwnDescriptor находит дескриптор данных в прототипе с writable: false и сразу отвечает false — до создания свойства у Receiver.
  2. Можно ли неудаляемому записываемому свойству сменить значение? А сделать его незаписываемым и обратно?
    Ответ Значение и writable: false — да; writable: true после этого — нет: шаг 3 ValidateAndApplyPropertyDescriptor.
  3. В каком порядке Object.keys выдаст ключи { b: 1, 10: 1, a: 1, 2: 1 }?
    Ответ 2, 10, b, a: сначала индексы по возрастанию, потом строки по времени создания.
  4. Почему поле title = "поле" наследника не вызывает сеттер title из класса родителя?
    Ответ Поле определяется через CreateDataPropertyOrThrow, то есть [[DefineOwnProperty]], а сеттер ищет только [[Set]].
  5. Что вернёт new F(), если F — обычная функция и делает return 42? А производный класс с return 42?
    Ответ Обычная (base) отдаст this, примитив не важен. Производный — TypeError: вернуть можно только объект или undefined.
  6. Почему геттер, найденный в прототипе, видит в this объект-наследник, а не прототип?
    Ответ [[Get]] прототипа вызван с тем же Receiver, с которого начали, и OrdinaryGet зовёт геттер с this = Receiver.
  7. Зачем [[Call]] создаёт TypeError для класса уже после PrepareForOrdinaryCall?
    Ответ Чтобы ошибка была из реалма класса: в calleeContext текущий реалм — реалм функции.
