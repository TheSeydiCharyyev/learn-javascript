1. Метапрограммирование: цель, обработчик, ловушки

Учебник MDN Meta programming начинает с трёх слов. Цель (target) — объект, который прокси заменяет. Обработчик (handler) — объект с функциями-ловушками (traps). Инварианты — правила, которые ловушки не могут нарушить. Раздел 10.5 говорит то же языком дня 15: прокси — экзотический объект, у которого все внутренние методы свои, со слотами [[ProxyTarget]] и [[ProxyHandler]]. Таблица 29 сводит каждый метод к имени ловушки — это таблица 4 дня 4, и «Proxy перехватывает ровно эти вызовы»:

Внутренний методЛовушкаВнутренний методЛовушка
[[GetPrototypeOf]]getPrototypeOf[[HasProperty]]has
[[SetPrototypeOf]]setPrototypeOf[[Get]]get
[[IsExtensible]]isExtensible[[Set]]set
[[PreventExtensions]]preventExtensions[[Delete]]deleteProperty
[[GetOwnProperty]]getOwnPropertyDescriptor[[OwnPropertyKeys]]ownKeys
[[DefineOwnProperty]]defineProperty[[Call]], [[Construct]]apply, construct

Нет ловушки — операция уходит к цели. Пустой обработчик даёт прокси, который пересылает всё:

const target = { word: "kitap" };
const proxy = new Proxy(target, {});
proxy.level = 1;
console.log(proxy.word, target.level, proxy === target, Object.keys(proxy).join(), "word" in proxy, delete proxy.word, target.word);
kitap 1 false word,level true true undefined

Запись, удаление и ключи дошли до цели, но прокси — другой объект: proxy === target — false.

2. ProxyCreate и конструктор Proxy

28.2: конструктор Proxy (28.2.1, страница MDN Proxy() constructor) без new бросает TypeError, а с new зовёт ProxyCreate (10.5.15):

  1. цель или обработчик не объект — TypeError;
  2. MakeBasicObject со слотами [[ProxyHandler]] и [[ProxyTarget]], методы — из 10.5;
  3. [[Call]] — только если цель вызываемая, [[Construct]] — только если цель конструктор (как у связанной функции, день 15);
  4. записать цель и обработчик.
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const fnProxy = new Proxy(function f() {}, {});
const arrowProxy = new Proxy(() => {}, {});
const objProxy = new Proxy({}, { apply() { return 1; } });
console.log(typeof fnProxy, typeof objProxy, Array.isArray(new Proxy([], {})), Object.prototype.toString.call(new Proxy([], {})), Object.prototype.toString.call(fnProxy));
console.log(run(() => objProxy()), "|", run(() => new arrowProxy()), "|", run(() => Proxy({}, {})), "|", run(() => new Proxy(1, {})));
console.log(Proxy.prototype, Proxy.length, Object.getPrototypeOf(Proxy) === Function.prototype, Object.getOwnPropertyNames(Proxy).join());
function object true [object Array] [object Function]
TypeError: objProxy is not a function | TypeError: arrowProxy is not a constructor | TypeError: Constructor Proxy requires 'new' | TypeError: Cannot create proxy with a non-object as target or handler
undefined 2 true length,name,revocable

Ловушка apply не делает объект вызываемым: [[Call]] ставит ProxyCreate по цели, а не по обработчику. IsArray (день 9) смотрит сквозь прокси на цель — поэтому прокси массива и в toString «Array». У конструктора нет prototype: по 28.2.2 у прокси нет своего [[Prototype]], который нужно было бы инициализировать, — его отдаёт цель или ловушка.

3. Общая схема внутреннего метода

Все тринадцать методов 10.5 устроены одинаково:

  1. ValidateNonRevokedProxy (10.5.14): цель null — прокси отозван, TypeError;
  2. взять ловушку: GetMethod(handler, имя) — undefined или null значит «нет», не функция — TypeError;

4. get и [[Get]] по шагам

Ловушка get получает (target, key, receiver). [[Get]] (10.5.8) после общих шагов зовёт её и только потом смотрит на цель: свой дескриптор P у цели неудаляемый и это незаписываемые данные — ответ обязан быть SameValue значению; это аксессор без геттера — ответ обязан быть undefined. Во всех остальных случаях ловушка вольна отвечать что угодно.

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const target = {};
Object.defineProperty(target, "fixed", { value: 1, writable: false, configurable: false });
Object.defineProperty(target, "noGetter", { set(v) {}, configurable: false });
Object.defineProperty(target, "soft", { value: 1, writable: false, configurable: true });
const proxy = new Proxy(target, { get(t, key) { return key === "soft" ? 2 : 3; } });
console.log(run(() => proxy.fixed), "|", run(() => proxy.noGetter), "|", proxy.soft, proxy.anything);
const honest = new Proxy(target, { get(t, key) { return key === "fixed" ? 1 : undefined; } });
console.log(honest.fixed, honest.noGetter);
TypeError: 'get' on proxy: property 'fixed' is a read-only and non-configurable data property on the proxy target but the proxy did not return its actual value (expected '1' but got '3') | TypeError: 'get' on proxy: property 'noGetter' is a non-configurable accessor property on the proxy target and does not have a getter function, but the trap did not return 'undefined' (got '3') | 2 3
1 undefined

soft тоже незаписываемое, но удаляемое — сверки нет. Порядок «сначала ловушка, потом цель» видно, если целью взять другой прокси с журналом: его getOwnPropertyDescriptor зовётся после ловушки внешнего.

const log = [];
const target = new Proxy({}, { getOwnPropertyDescriptor(t, key) { log.push("цель: " + String(key)); return Object.getOwnPropertyDescriptor(t, key); } });
const proxy = new Proxy(target, { get(t, key) { log.push("ловушка: " + String(key)); return 42; } });
console.log(proxy.x, log.join(" → "));
42 ловушка: x → цель: x

5. Receiver, приватные поля и слоты

Третий аргумент get — Receiver (день 14): объект, с которого начали поиск. Если прокси стоит в цепочке прототипов, Receiver — наследник. Пересылка t[key] этот Receiver теряет: геттер цели получает this = цель. Правильная пересылка с Receiver — Reflect.get, день 17.

const target = { name: "цель", get who() { return this.name; } };
const proxy = new Proxy(target, { get(t, key, receiver) { return key === "receiver" ? receiver : t[key]; } });
const child = Object.create(proxy);
child.name = "наследник";
console.log(child.receiver === child, child.who, Object.create(target, { name: { value: "наследник" } }).who);
true цель наследник

Обратная беда у пустого обработчика: он пересылает с Receiver = прокси, и геттер цели получает this = прокси. У прокси нет приватных полей класса (страница MDN Proxy, пример «No private field forwarding») и внутренних слотов: Map.prototype.get проверяет [[MapData]] у this — та же ошибка, что у {} на дне 4. Здесь t[key] как раз спасает:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
class Secret { #code = "123"; get code() { return this.#code; } }
const plain = new Proxy(new Secret(), {});
const fixed = new Proxy(new Secret(), { get(t, key) { return t[key]; } });
console.log(run(() => plain.code), "|", fixed.code);
console.log(run(() => new Proxy(new Map([[1, "kitap"]]), {}).get(1)), "|", run(() => new Proxy(new Map(), {}).size));
TypeError: Cannot read private member #code from an object whose class did not declare it | 123
TypeError: Method Map.prototype.get called on incompatible receiver #<Map> | TypeError: Method get Map.prototype.size called on incompatible receiver #<Map>

Для методов t[key] мало: proxy.get(1) достаёт метод через ловушку, но вызывает его с this = прокси. MDN предлагает отдавать обёртку, которая вызывает метод на цели. Вывод: прокси прозрачен для свойств, но не для приватных полей и слотов. И не для тождества: Set, WeakMap и includes сравнивают объекты по SameValue и SameValueZero (день 5), а прокси — другой объект:

const target = { word: "kitap" };
const proxy = new Proxy(target, {});
const seen = new Set([target]);
const notes = new WeakMap([[target, "заметка"]]);
console.log(seen.has(proxy), notes.get(proxy), notes.get(target), [target].includes(proxy), Object.is(proxy, target));
false undefined заметка false false

Кто раздаёт прокси вместо объектов, должен раздавать его везде — иначе одна и та же карточка окажется в двух видах.

6. Практика: значения по умолчанию

Ловушка get отвечает и за свойства, которых нет. Счётчик слов без проверок «а было ли»:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const counts = new Proxy({}, { get(t, key) { return key in t ? t[key] : 0; } });
for (const w of ["kitap", "galam", "kitap"]) counts[w] += 1;
console.log(counts.kitap, counts.galam, counts.suw, JSON.stringify(counts), run(() => String(counts)), run(() => `${counts}`));
const safe = new Proxy({}, { get(t, key) { return typeof key === "symbol" || key in t ? t[key] : 0; } });
console.log(String(safe), safe.kitap);
2 1 0 {"kitap":2,"galam":1} TypeError: number 0 is not a function TypeError: number 0 is not a function
[object Object] 0

Ловушка отвечает и на вопросы, которые задаёт сам язык. ToPrimitive (день 5) спрашивает Symbol.toPrimitive, получает 0, а GetMethod считает: не undefined и не функция — TypeError. JSON.stringify спрашивает toJSON, получает 0 и просто его пропускает — повезло. Правило: символы и служебные имена отдавать цели.

7. set: false и Receiver

Ловушка set получает (target, key, value, receiver) и отвечает true или false. [[Set]] (10.5.9) приводит ответ к булеву; false — это «не вышло»: строгий код бросает TypeError (PutValue, день 4), нестрогий молчит. Но Object.assign пишет через Set с флагом «бросать» (день 7) — ему всё равно, строгий ли код.

"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const proxy = new Proxy({}, { set(t, key, value) { if (key.startsWith("_")) return false; t[key] = value; return true; } });
console.log(run(() => { proxy.word = "kitap"; }), run(() => { proxy._secret = 1; }), Object.keys(proxy).join());
ok TypeError: 'set' on proxy: trap returned falsish for property '_secret' word

Receiver у set — тот, кому присваивают. Прокси в прототипе: child.x = 1 по OrdinarySetWithOwnDescriptor (день 14) доходит до [[Set]] прокси с Receiver = child. Обычный объект на этом месте создал бы x у child, а пересылка t[key] = value пишет в цель:

"use strict";
const log = [];
const proto = new Proxy({}, { set(t, key, value, receiver) { log.push(String(key) + (receiver === child ? " receiver=child" : "")); t[key] = value; return true; } });
const child = Object.create(proto);
child.x = 1;
console.log(log.join(), Object.hasOwn(child, "x"), Object.keys(Object.getPrototypeOf(child)).join());
x receiver=child false x

8. Практика: объект с проверкой записи

Журнал оценок дня 16 курса 2 проверял оценку в сеттере класса. Прокси проверяет любое имя:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const scores = new Proxy({}, {
  set(t, key, value) {
    if (!Number.isInteger(value) || value < 1 || value > 5) throw new RangeError(`оценка ${String(key)}: ${value} — нужна от 1 до 5`);
    t[key] = value;
    return true;
  },
});
scores.Aýna = 5;
console.log(run(() => { scores.Merdan = 7; }), "|", run(() => { scores.Merdan = "5"; }), "|", JSON.stringify(scores));
console.log(run(() => Object.defineProperty(scores, "Merdan", { value: 7, enumerable: true })), JSON.stringify(scores));
RangeError: оценка Merdan: 7 — нужна от 1 до 5 | RangeError: оценка Merdan: 5 — нужна от 1 до 5 | {"Aýna":5}
ok {"Aýna":5,"Merdan":7}

Бросить из ловушки можно своей ошибкой — она дойдёт до вызывающего как есть. Но defineProperty идёт мимо [[Set]], к [[DefineOwnProperty]] (день 14), и семёрка прошла. Проверка записи — это две ловушки: set и defineProperty.

9. has и deleteProperty

has ловит in, deleteProperty — delete. Оба отвечают булевым; false у delete в строгом коде — TypeError, как у set. Спрячем ключи с подчёркиванием:

"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const hidden = new Proxy({ word: "kitap", _id: 7 }, {
  has(t, key) { return !String(key).startsWith("_") && key in t; },
  deleteProperty(t, key) { if (String(key).startsWith("_")) return false; delete t[key]; return true; },
});
console.log("word" in hidden, "_id" in hidden, hidden._id, run(() => delete hidden._id), Object.keys(hidden).join());
true false 7 TypeError: 'deleteProperty' on proxy: trap returned falsish for property '_id' word,_id

in ключа не видит, а чтение и Object.keys видят: у каждой операции своя ловушка, и прятать надо во всех. Инварианты [[HasProperty]] (10.5.7) и [[Delete]] (10.5.10): нельзя спрятать или «удалить» неудаляемое свойство цели и любое свойство нерасширяемой цели. Прокси в прототипе получает has только за тем, чего нет у наследника: обычный [[HasProperty]] (день 14) сначала смотрит своё свойство.

const log = [];
const proto = new Proxy({ shared: 1 }, { has(t, key) { log.push(String(key)); return key in t; } });
const child = Object.create(proto);
child.own = 1;
console.log("own" in child, "shared" in child, "nope" in child, log.join());
true true false shared,nope

10. ownKeys и виртуальные ключи

ownKeys отдаёт массив ключей. [[OwnPropertyKeys]] (10.5.11) берёт его через CreateListFromArrayLike: только строки и символы, без повторов; в списке обязаны быть все неудаляемые ключи цели, а у нерасширяемой цели — ровно её ключи. Подводный камень: Object.keys потом спрашивает дескриптор каждого ключа (день 14) и выбрасывает те, у которых его нет.

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const virtual = new Proxy({}, { ownKeys() { return ["a", "b"]; } });
const withDesc = new Proxy({}, { ownKeys() { return ["a", "b"]; }, getOwnPropertyDescriptor(t, key) { return { value: key.toUpperCase(), enumerable: true, configurable: true }; } });
console.log(Object.getOwnPropertyNames(virtual).join(), "|", Object.keys(virtual).length, "|", Object.keys(withDesc).join());
console.log(run(() => Object.keys(new Proxy({}, { ownKeys() { return ["a", "a"]; } }))), "|", run(() => Object.keys(new Proxy({}, { ownKeys() { return [1]; } }))));
a,b | 0 | a,b
TypeError: 'ownKeys' on proxy: trap returned duplicate entries | TypeError: 1 is not a valid property name

getOwnPropertyNames берёт список как есть, Object.keys — только ключи с перечисляемым дескриптором. Виртуальным ключам нужна вторая ловушка — getOwnPropertyDescriptor. Дескриптор обязан быть configurable: true — неудаляемое свойство, которого у цели нет, запрещает 10.5.5.

11. Практика: журнал всех операций

День 14 обещал увидеть таблицу «код — метод» вживую. Приём: обработчик — сам прокси. GetMethod читает у него имя ловушки, наша get записывает это имя и отвечает undefined — «ловушки нет», и операция честно уходит к цели:

const log = [];
const handler = new Proxy({}, { get(h, trap) { log.push(trap); return undefined; } });
const watch = (f) => { log.length = 0; f(new Proxy({ x: 1 }, handler)); return [...new Set(log)].join(", "); };
console.log("keys:", watch((p) => Object.keys(p)));
console.log("in:", watch((p) => "x" in p));
console.log("for...in:", watch((p) => { for (const k in p); }));
console.log("spread:", watch((p) => ({ ...p })));
console.log("JSON:", watch((p) => JSON.stringify(p)));
console.log("assign:", watch((p) => Object.assign(p, { y: 2 })));
keys: ownKeys, getOwnPropertyDescriptor
in: has
for...in: ownKeys, getPrototypeOf, getOwnPropertyDescriptor
spread: ownKeys, getOwnPropertyDescriptor, get
JSON: get, ownKeys, getOwnPropertyDescriptor
assign: set, getOwnPropertyDescriptor, defineProperty

for...in идёт и в прототип (EnumerateObjectProperties, день 11). JSON первым делом спрашивает toJSON. Последняя строка — Receiver в деле: ловушки set нет, [[Set]] цели вызван с Receiver = прокси, и OrdinarySetWithOwnDescriptor (день 14) спрашивает у Receiver дескриптор и определяет свойство на нём — то есть снова через прокси.

12. apply и construct

apply получает (target, thisArg, args) — [[Call]] (10.5.12) складывает аргументы в массив. construct получает (target, args, newTarget), и [[Construct]] (10.5.13) требует от неё объект.

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const calls = [];
const add = new Proxy(function add(a, b) { return a + b; }, {
  apply(target, thisArg, args) { calls.push(args.join("+")); return target(...args); },
});
console.log(add(1, 2), add.call(null, 3, 4), add.apply(null, [5, 6]), calls.join(" "));
class Card { constructor(word) { this.word = word; } }
const Logged = new Proxy(Card, { construct(target, args, newTarget) { return { made: args[0], same: newTarget === Logged }; } });
const Bad = new Proxy(Card, { construct() { return 1; } });
console.log(JSON.stringify(new Logged("kitap")), "|", run(() => new Bad("suw")), "|", run(() => Logged("x")));
3 7 11 1+2 3+4 5+6
{"made":"kitap","same":true} | TypeError: 'construct' on proxy: trap returned non-object ('1') | TypeError: Class constructor Card cannot be invoked without 'new'

call и apply функции тоже доходят до [[Call]] прокси. newTarget у new Logged — сам прокси. Вызов класса без new: ловушки apply нет — Call(Card), и класс бросает (день 14). Прокси класса можно наследовать: super() зовёт [[Construct]] прокси с newTarget наследника (SuperCall, день 14). Ловушка его получает — и легко теряет:

const seen = [];
class Card { constructor(word) { this.word = word; } }
const Watched = new Proxy(Card, { construct(target, args, newTarget) { seen.push(newTarget.name); return new target(...args); } });
class BigCard extends Watched { level = 2; }
const big = new BigCard("suw");
console.log(seen.join(), big instanceof BigCard, big.level, JSON.stringify(big));
BigCard false 2 {"word":"suw","level":2}

new target(...) взял прототип у Card: объект — не BigCard, хотя поле level встало (его ставит [[Construct]] наследника на то, что вернул super()). Та же беда, что у модели bind в задании 4 дня 15: передать чужой newTarget умеет только Reflect.construct (день 17).

getOwnPropertyDescriptor по шагам 10.5.5

Самый строгий из методов. Ответ ловушки — объект или undefined; undefined нельзя, если у цели свойство неудаляемое или цель нерасширяема. Объект проходит ToPropertyDescriptor и CompletePropertyDescriptor — недостающие поля становятся false и undefined, как у defineProperty (день 14). Потом IsCompatiblePropertyDescriptor с дескриптором цели и два правила: объявить свойство неудаляемым можно, только если оно неудаляемое у цели, а неудаляемым и незаписываемым — только если оно у цели такое же.

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };

const fake = new Proxy({}, { getOwnPropertyDescriptor() { return { value: 1, configurable: false }; } });
console.log(run(() => Object.getOwnPropertyDescriptor(nc, "id")), "|", run(() => Object.getOwnPropertyDescriptor(fake, "x")), "|", run(() => Object.getOwnPropertyDescriptor(new Proxy({}, { getOwnPropertyDescriptor() { return 1; } }), "x")));

Свойства kitap у цели нет, а дескриптор есть — цель расширяема, и это законно. Последнее правило защищает обещание «незаписываемое не изменится»: если цель ещё может переписать id, прокси не вправе назвать его вечным.

14. Практика: нарушение инварианта

Зачем всё это. Инварианты 6.1.7.3 обещают, например, что неудаляемое свойство не исчезнет, а нерасширяемый объект не обрастёт новыми. На этих обещаниях стоит Object.freeze: код, получивший замороженный объект, не перепроверяет его. Прокси, которому это позволено нарушить, сломал бы все такие гарантии — поэтому 10.5 сверяет ответы ловушек с целью. Цель с неудаляемым id и обработчик-лжец:

15. Proxy.revocable и отзыв

Proxy.revocable (28.2.2.1, страница MDN Proxy.revocable()): ProxyCreate и встроенная функция revoke без имени и параметров, со слотом [[RevocableProxy]]. Отзыв ставит прокси обе ссылки в null и забывает прокси сам — второй вызов ничего не делает.

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const { proxy, revoke } = Proxy.revocable({ word: "kitap" }, {});
console.log(proxy.word, typeof revoke, revoke.length, JSON.stringify(revoke.name), Object.keys(Proxy.revocable({}, {})).join());
revoke();
revoke();
console.log(typeof proxy, run(() => proxy.word), "|", run(() => Array.isArray(proxy)), "|", run(() => Object.keys(proxy)), "|", run(() => "word" in proxy));
kitap function 0 "" proxy,revoke
object TypeError: Cannot perform 'get' on a proxy that has been revoked | TypeError: Cannot perform 'IsArray' on a proxy that has been revoked | TypeError: Cannot perform 'ownKeys' on a proxy that has been revoked | TypeError: Cannot perform 'has' on a proxy that has been revoked

Зачем отзыв: дать чужому коду доступ на время — модулю, обработчику, окну — и забрать его, не трогая сам объект. Задание дня 9 спрашивало, что сделает GetFunctionRealm с отозванным прокси: ValidateNonRevokedProxy, TypeError. Увидеть её можно через ArraySpeciesCreate дня 15: отозванный прокси функции всё ещё конструктор, и шаг 2 спрашивает его реалм.

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const { proxy: ctor, revoke } = Proxy.revocable(function Words() {}, {});
const list = ["kitap"];
list.constructor = ctor;
revoke();
console.log(run(() => list.map((w) => w)), "|", typeof ctor);
const { proxy: fn, revoke: off } = Proxy.revocable(function () {}, {});
off();
console.log(run(() => fn()), "|", run(() => new fn()));
TypeError: Cannot perform 'undefined' on a proxy that has been revoked | function
TypeError: Cannot perform 'apply' on a proxy that has been revoked | TypeError: Cannot perform 'construct' on a proxy that has been revoked

Текст V8: «Cannot perform 'undefined'»

Поведение совпадает с текстом 2026 — TypeError из GetFunctionRealm. Но V8 подставляет в сообщение имя операции, а у GetFunctionRealm его нет, и в тексте вышло 'undefined'. По одному сообщению такую ошибку не узнать: это не ловушка get, а проверка реалма.

16. «Карточки 2.0»: настройки без опечаток

Добавим «Карточкам 2.0» настройки: сколько карточек в день и звук. Опечатка settings.perday у обычного объекта молча даёт undefined, а при записи — новое бесполезное свойство. Прокси делает из опечатки ошибку (модули строгие — модель тоже):

"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const settings = new Proxy({ perDay: 10, sound: true }, {
  get(t, key) {
    if (typeof key === "string" && !(key in t)) throw new ReferenceError(`нет настройки «${key}»`);
    return t[key];
  },
  set(t, key, value) {
    if (!(key in t)) throw new ReferenceError(`нет настройки «${String(key)}»`);
    if (typeof value !== typeof t[key]) throw new TypeError(`${String(key)}: нужен ${typeof t[key]}`);
    t[key] = value;
    return true;
  },
});
settings.perDay = 20;
console.log(settings.perDay, run(() => settings.perday), "|", run(() => { settings.perday = 5; }), "|", run(() => { settings.perDay = "5"; }));
console.log(run(() => JSON.stringify(settings)), "|", "toString" in settings, run(() => String(settings)));
20 ReferenceError: нет настройки «perday» | ReferenceError: нет настройки «perday» | TypeError: perDay: нужен number
ReferenceError: нет настройки «toJSON» | true ok

Опечатки пойманы, тип проверен. Но сохранить настройки нельзя: JSON.stringify спрашивает toJSON (журнал раздела 11), а для нашей ловушки это «опечатка». String прошёл: Symbol.toPrimitive — символ, а toString найден оператором in в прототипе. Исправление — в задании: служебные имена языка пропускать. Страж опечаток — классика прокси, но каждая ловушка обязана помнить, какие вопросы задаёт сам язык.

17. Что будет завтра

Сегодня ловушки пересылали цели через t[key] и key in t — и теряли Receiver. Завтра, на дне 17, — Reflect: по функции на каждый внутренний метод, с теми же аргументами, что у ловушек, и встроенные символы, через которые язык спрашивает объект о себе.

  1. Почему new Proxy({}, { apply() {} })() — TypeError, хотя ловушка apply есть?
    Ответ [[Call]] ставит ProxyCreate, только если цель вызываемая. У обычного объекта [[Call]] нет, и ловушку некому вызвать.
  2. Когда get обязана вернуть значение цели?
    Ответ Когда у цели своё неудаляемое незаписываемое свойство данных. У неудаляемого аксессора без геттера — обязана вернуть undefined. В остальных случаях — что угодно.
  3. Почему Object.keys пуст у прокси, чья ownKeys отдаёт ["a", "b"]?
    Ответ Object.keys спрашивает дескриптор каждого ключа; у цели свойств нет, ловушки getOwnPropertyDescriptor нет — дескрипторы undefined, ключи отброшены.
  4. Прокси с set, которая проверяет значение. Как записать в него непроверенное?
    Ответ Object.defineProperty: он идёт к [[DefineOwnProperty]], мимо [[Set]]. Нужна ещё ловушка defineProperty.
  5. Почему геттер цели, вызванный через Object.create(proxy).who, видит в this цель, если ловушка пишет return t[key]?
    Ответ t[key] — новый [[Get]] у цели с Receiver = цель. Receiver наследника пришёл в ловушку третьим аргументом и не использован.
  6. Что сделает typeof у отозванного прокси функции? А вызов?
    Ответ typeof — «function»: [[Call]] у прокси остался. Вызов — TypeError из ValidateNonRevokedProxy.
  7. Зачем 10.5 сверяет ответы ловушек с целью?
    Ответ Чтобы прокси не нарушал инварианты 6.1.7.3: неудаляемое не исчезает и не меняет вида, нерасширяемый объект не получает новых свойств. На них держатся freeze и seal.
