## 1. Метапрограммирование: цель, обработчик, ловушки {#meta}

Учебник MDN [Meta programming](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Meta_programming)
начинает с трёх слов. *Цель* (target) — объект, который прокси заменяет. *Обработчик* (handler) —
объект с функциями-*ловушками* (traps). *Инварианты* — правила, которые ловушки не могут нарушить.
Раздел [10.5](https://tc39.es/ecma262/2026/#sec-proxy-object-internal-methods-and-internal-slots)
говорит то же языком дня 15: прокси — экзотический объект, у которого *все* внутренние методы свои, со слотами
\[\[ProxyTarget\]\] и \[\[ProxyHandler\]\]. Таблица 29 сводит каждый метод к имени ловушки — это таблица 4 дня 4, и «Proxy
перехватывает ровно эти вызовы»:

| Внутренний метод | Ловушка | Внутренний метод | Ловушка |
| --- | --- | --- | --- |
| \[\[GetPrototypeOf\]\] | `getPrototypeOf` | \[\[HasProperty\]\] | `has` |
| \[\[SetPrototypeOf\]\] | `setPrototypeOf` | \[\[Get\]\] | `get` |
| \[\[IsExtensible\]\] | `isExtensible` | \[\[Set\]\] | `set` |
| \[\[PreventExtensions\]\] | `preventExtensions` | \[\[Delete\]\] | `deleteProperty` |
| \[\[GetOwnProperty\]\] | `getOwnPropertyDescriptor` | \[\[OwnPropertyKeys\]\] | `ownKeys` |
| \[\[DefineOwnProperty\]\] | `defineProperty` | \[\[Call\]\], \[\[Construct\]\] | `apply`, `construct` |

Нет ловушки — операция уходит к цели. Пустой обработчик даёт прокси, который пересылает всё:

```js
const target = { word: "kitap" };
const proxy = new Proxy(target, {});
proxy.level = 1;
console.log(proxy.word, target.level, proxy === target, Object.keys(proxy).join(), "word" in proxy, delete proxy.word, target.word);
```

<ResultBox>
kitap 1 false word,level true true undefined
</ResultBox>

Запись, удаление и ключи дошли до цели, но прокси — другой объект: `proxy === target` — false.

## 2. ProxyCreate и конструктор Proxy {#create}

[28.2](https://tc39.es/ecma262/2026/#sec-proxy-objects): конструктор
[Proxy](https://tc39.es/ecma262/2026/#sec-proxy-constructor) (28.2.1, страница MDN
[Proxy() constructor](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy))
без `new` бросает TypeError, а с `new` зовёт
[ProxyCreate](https://tc39.es/ecma262/2026/#sec-proxycreate) (10.5.15):

1. цель или обработчик не объект — TypeError;
2. MakeBasicObject со слотами \[\[ProxyHandler\]\] и \[\[ProxyTarget\]\], методы — из 10.5;
3. \[\[Call\]\] — только если цель вызываемая, \[\[Construct\]\] — только если цель конструктор (как у связанной функции,
   день 15);
4. записать цель и обработчик.

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const fnProxy = new Proxy(function f() {}, {});
const arrowProxy = new Proxy(() => {}, {});
const objProxy = new Proxy({}, { apply() { return 1; } });
console.log(typeof fnProxy, typeof objProxy, Array.isArray(new Proxy([], {})), Object.prototype.toString.call(new Proxy([], {})), Object.prototype.toString.call(fnProxy));
console.log(run(() => objProxy()), "|", run(() => new arrowProxy()), "|", run(() => Proxy({}, {})), "|", run(() => new Proxy(1, {})));
console.log(Proxy.prototype, Proxy.length, Object.getPrototypeOf(Proxy) === Function.prototype, Object.getOwnPropertyNames(Proxy).join());
```

<ResultBox>
function object true \[object Array\] \[object Function\]\
TypeError: objProxy is not a function | TypeError: arrowProxy is not a constructor | TypeError: Constructor Proxy requires 'new' | TypeError: Cannot create proxy with a non-object as target or handler\
undefined 2 true length,name,revocable
</ResultBox>

Ловушка `apply` не делает объект вызываемым: \[\[Call\]\] ставит ProxyCreate по цели, а не по обработчику.
IsArray (день 9) смотрит сквозь прокси на цель — поэтому прокси массива и в `toString` «Array». У
конструктора нет `prototype`: по 28.2.2 у прокси нет своего \[\[Prototype\]\], который нужно было бы
инициализировать, — его отдаёт цель или ловушка.

## 3. Общая схема внутреннего метода {#scheme}

Все тринадцать методов 10.5 устроены одинаково:

1. [ValidateNonRevokedProxy](https://tc39.es/ecma262/2026/#sec-validatenonrevokedproxy) (10.5.14):
   цель null — прокси отозван, TypeError;
2. взять ловушку: GetMethod(handler, имя) — undefined или null значит «нет», не функция — TypeError;
3. нет ловушки — тот же метод у цели;
4. есть — Call(ловушка, handler, «target, …»): `this` ловушки — обработчик;
5. сверить ответ с целью по инвариантам 6.1.7.3 (день 4) — в одних методах сверка есть, в других нет.

<Scheme src="scheme-scheme.svg">Внутренний метод прокси: ловушка или цель, потом сверка с целью</Scheme>

```js
const handler = {};
const proxy = new Proxy({ x: 1 }, handler);
const before = proxy.x;
handler.get = () => "из ловушки";
console.log(before, proxy.x, proxy.y);
delete handler.get;
console.log(proxy.x);
```

<ResultBox>
1 из ловушки из ловушки\
1
</ResultBox>

## 4. get и \[\[Get\]\] по шагам {#get}

Ловушка [get](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/get)
получает `(target, key, receiver)`. [\[\[Get\]\]](https://tc39.es/ecma262/2026/#sec-proxy-object-internal-methods-and-internal-slots-get-p-receiver)
(10.5.8) после общих шагов зовёт её и только *потом* смотрит на цель: свой дескриптор P у цели неудаляемый и
это незаписываемые данные — ответ обязан быть SameValue значению; это аксессор без геттера — ответ обязан быть
undefined. Во всех остальных случаях ловушка вольна отвечать что угодно.

<Scheme src="scheme-get.svg">10.5.8: ответ ловушки сверяется с неудаляемыми свойствами цели</Scheme>

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const target = {};
Object.defineProperty(target, "fixed", { value: 1, writable: false, configurable: false });
Object.defineProperty(target, "noGetter", { set(v) {}, configurable: false });
Object.defineProperty(target, "soft", { value: 1, writable: false, configurable: true });
const proxy = new Proxy(target, { get(t, key) { return key === "soft" ? 2 : 3; } });
console.log(run(() => proxy.fixed), "|", run(() => proxy.noGetter), "|", proxy.soft, proxy.anything);
const honest = new Proxy(target, { get(t, key) { return key === "fixed" ? 1 : undefined; } });
console.log(honest.fixed, honest.noGetter);
```

<ResultBox>
TypeError: 'get' on proxy: property 'fixed' is a read-only and non-configurable data property on the proxy target but the proxy did not return its actual value (expected '1' but got '3') | TypeError: 'get' on proxy: property 'noGetter' is a non-configurable accessor property on the proxy target and does not have a getter function, but the trap did not return 'undefined' (got '3') | 2 3\
1 undefined
</ResultBox>

`soft` тоже незаписываемое, но удаляемое — сверки нет. Порядок «сначала ловушка, потом цель» видно,
если целью взять другой прокси с журналом: его `getOwnPropertyDescriptor` зовётся после ловушки
внешнего.

```js
const log = [];
const target = new Proxy({}, { getOwnPropertyDescriptor(t, key) { log.push("цель: " + String(key)); return Object.getOwnPropertyDescriptor(t, key); } });
const proxy = new Proxy(target, { get(t, key) { log.push("ловушка: " + String(key)); return 42; } });
console.log(proxy.x, log.join(" → "));
```

<ResultBox>
42 ловушка: x → цель: x
</ResultBox>

## 5. Receiver, приватные поля и слоты {#receiver}

Третий аргумент `get` — Receiver (день 14): объект, с которого начали поиск. Если прокси стоит в
цепочке прототипов, Receiver — наследник. Пересылка `t[key]` этот Receiver теряет: геттер цели получает
`this` = цель. Правильная пересылка с Receiver — `Reflect.get`, день 17.

```js
const target = { name: "цель", get who() { return this.name; } };
const proxy = new Proxy(target, { get(t, key, receiver) { return key === "receiver" ? receiver : t[key]; } });
const child = Object.create(proxy);
child.name = "наследник";
console.log(child.receiver === child, child.who, Object.create(target, { name: { value: "наследник" } }).who);
```

<ResultBox>
true цель наследник
</ResultBox>

Обратная беда у пустого обработчика: он пересылает с Receiver = прокси, и геттер цели получает
`this` = прокси. У прокси нет приватных полей класса (страница MDN
[Proxy](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy), пример
«No private field forwarding») и внутренних слотов: `Map.prototype.get` проверяет \[\[MapData\]\] у
`this` — та же ошибка, что у `{}` на дне 4. Здесь `t[key]` как раз спасает:

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
class Secret { #code = "123"; get code() { return this.#code; } }
const plain = new Proxy(new Secret(), {});
const fixed = new Proxy(new Secret(), { get(t, key) { return t[key]; } });
console.log(run(() => plain.code), "|", fixed.code);
console.log(run(() => new Proxy(new Map([[1, "kitap"]]), {}).get(1)), "|", run(() => new Proxy(new Map(), {}).size));
```

<ResultBox>
TypeError: Cannot read private member #code from an object whose class did not declare it | 123\
TypeError: Method Map.prototype.get called on incompatible receiver #\<Map> | TypeError: Method get Map.prototype.size called on incompatible receiver #\<Map>
</ResultBox>

Для методов `t[key]` мало: `proxy.get(1)` достаёт метод через ловушку, но вызывает его с
`this` = прокси. MDN предлагает отдавать обёртку, которая вызывает метод на цели. Вывод: прокси
прозрачен для свойств, но не для приватных полей и слотов. И не для тождества: `Set`,
`WeakMap` и `includes` сравнивают объекты по SameValue и SameValueZero (день 5), а прокси —
другой объект:

```js
const target = { word: "kitap" };
const proxy = new Proxy(target, {});
const seen = new Set([target]);
const notes = new WeakMap([[target, "заметка"]]);
console.log(seen.has(proxy), notes.get(proxy), notes.get(target), [target].includes(proxy), Object.is(proxy, target));
```

<ResultBox>
false undefined заметка false false
</ResultBox>

Кто раздаёт прокси вместо объектов, должен раздавать его везде — иначе одна и та же карточка окажется в двух
видах.

## 6. Практика: значения по умолчанию {#defaults}

Ловушка `get` отвечает и за свойства, которых нет. Счётчик слов без проверок «а было ли»:

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const counts = new Proxy({}, { get(t, key) { return key in t ? t[key] : 0; } });
for (const w of ["kitap", "galam", "kitap"]) counts[w] += 1;
console.log(counts.kitap, counts.galam, counts.suw, JSON.stringify(counts), run(() => String(counts)), run(() => `${counts}`));
const safe = new Proxy({}, { get(t, key) { return typeof key === "symbol" || key in t ? t[key] : 0; } });
console.log(String(safe), safe.kitap);
```

<ResultBox>
2 1 0 \{"kitap":2,"galam":1\} TypeError: number 0 is not a function TypeError: number 0 is not a function\
\[object Object\] 0
</ResultBox>

Ловушка отвечает и на вопросы, которые задаёт сам язык. ToPrimitive (день 5) спрашивает
`Symbol.toPrimitive`, получает 0, а GetMethod считает: не undefined и не функция — TypeError.
`JSON.stringify` спрашивает `toJSON`, получает 0 и просто его пропускает — повезло. Правило:
символы и служебные имена отдавать цели.

## 7. set: false и Receiver {#set}

Ловушка [set](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/set)
получает `(target, key, value, receiver)` и отвечает true или false. \[\[Set\]\] (10.5.9) приводит ответ к
булеву; false — это «не вышло»: строгий код бросает TypeError (PutValue, день 4), нестрогий молчит. Но
`Object.assign` пишет через Set с флагом «бросать» (день 7) — ему всё равно, строгий ли код.

```js
"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const proxy = new Proxy({}, { set(t, key, value) { if (key.startsWith("_")) return false; t[key] = value; return true; } });
console.log(run(() => { proxy.word = "kitap"; }), run(() => { proxy._secret = 1; }), Object.keys(proxy).join());
```

<ResultBox>
ok TypeError: 'set' on proxy: trap returned falsish for property '\_secret' word
</ResultBox>

Receiver у `set` — тот, кому присваивают. Прокси в прототипе: `child.x = 1` по
OrdinarySetWithOwnDescriptor (день 14) доходит до \[\[Set\]\] прокси с Receiver = `child`. Обычный объект на
этом месте создал бы `x` у `child`, а пересылка `t[key] = value` пишет в цель:

```js
"use strict";
const log = [];
const proto = new Proxy({}, { set(t, key, value, receiver) { log.push(String(key) + (receiver === child ? " receiver=child" : "")); t[key] = value; return true; } });
const child = Object.create(proto);
child.x = 1;
console.log(log.join(), Object.hasOwn(child, "x"), Object.keys(Object.getPrototypeOf(child)).join());
```

<ResultBox>
x receiver=child false x
</ResultBox>

## 8. Практика: объект с проверкой записи {#validate}

Журнал группы дня 16 курса 2 проверял оценку в методе `addMark`. Прокси проверяет запись под любым
именем:

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const scores = new Proxy({}, {
  set(t, key, value) {
    if (!Number.isInteger(value) || value < 1 || value > 5) throw new RangeError(`оценка ${String(key)}: ${value} — нужна от 1 до 5`);
    t[key] = value;
    return true;
  },
});
scores.Aýna = 5;
console.log(run(() => { scores.Merdan = 7; }), "|", run(() => { scores.Merdan = "5"; }), "|", JSON.stringify(scores));
console.log(run(() => Object.defineProperty(scores, "Merdan", { value: 7, enumerable: true })), JSON.stringify(scores));
```

<ResultBox>
RangeError: оценка Merdan: 7 — нужна от 1 до 5 | RangeError: оценка Merdan: 5 — нужна от 1 до 5 | \{"Aýna":5\}\
ok \{"Aýna":5,"Merdan":7\}
</ResultBox>

Бросить из ловушки можно своей ошибкой — она дойдёт до вызывающего как есть. Но `defineProperty`
идёт мимо \[\[Set\]\], к \[\[DefineOwnProperty\]\] (день 14), и семёрка прошла. Проверка записи — это две ловушки:
`set` и [defineProperty](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/defineProperty).

## 9. has и deleteProperty {#has}

[has](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/has)
ловит `in`, [deleteProperty](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/deleteProperty)
— `delete`. Оба отвечают булевым; false у `delete` в строгом коде — TypeError, как у
`set`. Спрячем ключи с подчёркиванием:

```js
"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const hidden = new Proxy({ word: "kitap", _id: 7 }, {
  has(t, key) { return !String(key).startsWith("_") && key in t; },
  deleteProperty(t, key) { if (String(key).startsWith("_")) return false; delete t[key]; return true; },
});
console.log("word" in hidden, "_id" in hidden, hidden._id, run(() => delete hidden._id), Object.keys(hidden).join());
```

<ResultBox>
true false 7 TypeError: 'deleteProperty' on proxy: trap returned falsish for property '\_id' word,\_id
</ResultBox>

`in` ключа не видит, а чтение и `Object.keys` видят: у каждой операции своя ловушка, и
прятать надо во всех. Инварианты \[\[HasProperty\]\] (10.5.7) и \[\[Delete\]\] (10.5.10): нельзя спрятать или «удалить»
неудаляемое свойство цели и любое свойство нерасширяемой цели. Прокси в прототипе получает `has` только
за тем, чего нет у наследника: обычный \[\[HasProperty\]\] (день 14) сначала смотрит своё свойство.

```js
const log = [];
const proto = new Proxy({ shared: 1 }, { has(t, key) { log.push(String(key)); return key in t; } });
const child = Object.create(proto);
child.own = 1;
console.log("own" in child, "shared" in child, "nope" in child, log.join());
```

<ResultBox>
true true false shared,nope
</ResultBox>

## 10. ownKeys и виртуальные ключи {#ownkeys}

[ownKeys](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/ownKeys)
отдаёт массив ключей. \[\[OwnPropertyKeys\]\] (10.5.11) берёт его через CreateListFromArrayLike: только строки и символы,
без повторов; в списке обязаны быть все неудаляемые ключи цели, а у нерасширяемой цели — ровно её ключи.
Подводный камень: `Object.keys` потом спрашивает дескриптор каждого ключа (день 14) и выбрасывает те, у
которых его нет.

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const virtual = new Proxy({}, { ownKeys() { return ["a", "b"]; } });
const withDesc = new Proxy({}, { ownKeys() { return ["a", "b"]; }, getOwnPropertyDescriptor(t, key) { return { value: key.toUpperCase(), enumerable: true, configurable: true }; } });
console.log(Object.getOwnPropertyNames(virtual).join(), "|", Object.keys(virtual).length, "|", Object.keys(withDesc).join());
console.log(run(() => Object.keys(new Proxy({}, { ownKeys() { return ["a", "a"]; } }))), "|", run(() => Object.keys(new Proxy({}, { ownKeys() { return [1]; } }))));
```

<ResultBox>
a,b | 0 | a,b\
TypeError: 'ownKeys' on proxy: trap returned duplicate entries | TypeError: 1 is not a valid property name
</ResultBox>

`getOwnPropertyNames` берёт список как есть, `Object.keys` — только ключи с перечисляемым
дескриптором. Виртуальным ключам нужна вторая ловушка — `getOwnPropertyDescriptor`. Дескриптор
обязан быть configurable: true — неудаляемое свойство, которого у цели нет, запрещает 10.5.5.

## 11. Практика: журнал всех операций {#journal}

День 14 обещал увидеть таблицу «код — метод» вживую. Приём: обработчик — сам прокси. GetMethod читает у него имя
ловушки, наша `get` записывает это имя и отвечает undefined — «ловушки нет», и операция честно уходит к
цели:

```js
const log = [];
const handler = new Proxy({}, { get(h, trap) { log.push(trap); return undefined; } });
const watch = (f) => { log.length = 0; f(new Proxy({ x: 1 }, handler)); return [...new Set(log)].join(", "); };
console.log("keys:", watch((p) => Object.keys(p)));
console.log("in:", watch((p) => "x" in p));
console.log("for...in:", watch((p) => { for (const k in p); }));
console.log("spread:", watch((p) => ({ ...p })));
console.log("JSON:", watch((p) => JSON.stringify(p)));
console.log("assign:", watch((p) => Object.assign(p, { y: 2 })));
```

<ResultBox>
keys: ownKeys, getOwnPropertyDescriptor\
in: has\
for...in: ownKeys, getPrototypeOf, getOwnPropertyDescriptor\
spread: ownKeys, getOwnPropertyDescriptor, get\
JSON: get, ownKeys, getOwnPropertyDescriptor\
assign: set, getOwnPropertyDescriptor, defineProperty
</ResultBox>

`for...in` идёт и в прототип (EnumerateObjectProperties, день 11). `JSON` первым делом
спрашивает `toJSON`. Последняя строка — Receiver в деле: ловушки `set` нет, \[\[Set\]\] цели
вызван с Receiver = прокси, и OrdinarySetWithOwnDescriptor (день 14) спрашивает у Receiver дескриптор и определяет
свойство на нём — то есть снова через прокси.

## 12. apply и construct {#call}

[apply](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/apply)
получает `(target, thisArg, args)` — \[\[Call\]\] (10.5.12) складывает аргументы в массив.
[construct](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/construct)
получает `(target, args, newTarget)`, и \[\[Construct\]\] (10.5.13) требует от неё объект.

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const calls = [];
const add = new Proxy(function add(a, b) { return a + b; }, {
  apply(target, thisArg, args) { calls.push(args.join("+")); return target(...args); },
});
console.log(add(1, 2), add.call(null, 3, 4), add.apply(null, [5, 6]), calls.join(" "));
class Card { constructor(word) { this.word = word; } }
const Logged = new Proxy(Card, { construct(target, args, newTarget) { return { made: args[0], same: newTarget === Logged }; } });
const Bad = new Proxy(Card, { construct() { return 1; } });
console.log(JSON.stringify(new Logged("kitap")), "|", run(() => new Bad("suw")), "|", run(() => Logged("x")));
```

<ResultBox>
3 7 11 1+2 3+4 5+6\
\{"made":"kitap","same":true\} | TypeError: 'construct' on proxy: trap returned non-object ('1') | TypeError: Class constructor Card cannot be invoked without 'new'
</ResultBox>

`call` и `apply` функции тоже доходят до \[\[Call\]\] прокси. newTarget у `new Logged`
— сам прокси. Вызов класса без `new`: ловушки `apply` нет — Call(Card), и класс бросает (день
14). Прокси класса можно наследовать: `super()` зовёт \[\[Construct\]\] прокси с newTarget наследника
(SuperCall, день 14). Ловушка его получает — и легко теряет:

```js
const seen = [];
class Card { constructor(word) { this.word = word; } }
const Watched = new Proxy(Card, { construct(target, args, newTarget) { seen.push(newTarget.name); return new target(...args); } });
class BigCard extends Watched { level = 2; }
const big = new BigCard("suw");
console.log(seen.join(), big instanceof BigCard, big.level, JSON.stringify(big));
```

<ResultBox>
BigCard false 2 \{"word":"suw","level":2\}
</ResultBox>

`new target(...)` взял прототип у `Card`: объект — не `BigCard`, хотя поле
`level` встало (его ставит \[\[Construct\]\] наследника на то, что вернул `super()`). Та же беда,
что у модели `bind` в задании 4 дня 15: передать чужой newTarget умеет только
`Reflect.construct` (день 17).

## 13. Остальные шесть ловушек {#six}

| Ловушка | Что ловит | Главный инвариант |
| --- | --- | --- |
| [getPrototypeOf](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/getPrototypeOf) | `Object.getPrototypeOf`, `instanceof`, `isPrototypeOf` | объект или null; цель нерасширяема — её прототип |
| [setPrototypeOf](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/setPrototypeOf) | `Object.setPrototypeOf`, `__proto__ =` | цель нерасширяема — true только для её прототипа |
| [isExtensible](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/isExtensible) | `Object.isExtensible` | ответ цели, без вариантов |
| [preventExtensions](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/Proxy/preventExtensions) | `preventExtensions`, `freeze`, `seal` | true — только если цель уже нерасширяема |

Пока цель расширяема, `getPrototypeOf` может лгать `instanceof`. После
`preventExtensions` — уже нет:

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const fake = new Proxy({}, { getPrototypeOf() { return Array.prototype; } });
console.log(fake instanceof Array, Array.isArray(fake), Array.prototype.isPrototypeOf(fake), Object.getPrototypeOf(fake) === Array.prototype);
Object.preventExtensions(fake);
console.log(run(() => fake instanceof Array), "|", run(() => Object.isExtensible(new Proxy({}, { isExtensible() { return false; } }))));
```

<ResultBox>
true false true true\
TypeError: 'getPrototypeOf' on proxy: proxy target is non-extensible but the trap did not return its actual prototype | TypeError: 'isExtensible' on proxy: trap result does not reflect extensibility of proxy target (which is 'true')
</ResultBox>

`instanceof` поверил (OrdinaryHasInstance идёт по \[\[GetPrototypeOf\]\], день 7), IsArray — нет: она
смотрит на цель. `preventExtensions` без ловушки ушёл к цели.

### getOwnPropertyDescriptor по шагам 10.5.5 {#gopd}

Самый строгий из методов. Ответ ловушки — объект или undefined; undefined нельзя, если у цели свойство
неудаляемое или цель нерасширяема. Объект проходит ToPropertyDescriptor и *CompletePropertyDescriptor* —
недостающие поля становятся false и undefined, как у `defineProperty` (день 14). Потом
IsCompatiblePropertyDescriptor с дескриптором цели и два правила: объявить свойство неудаляемым можно, только если
оно неудаляемое у цели, а неудаляемым и незаписываемым — только если оно у цели такое же.

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const p = new Proxy({}, { getOwnPropertyDescriptor(t, key) { return { value: key.length, configurable: true }; } });
console.log(JSON.stringify(Object.getOwnPropertyDescriptor(p, "kitap")));
const target = {};
Object.defineProperty(target, "id", { value: 7, writable: true, configurable: false });
const nc = new Proxy(target, { getOwnPropertyDescriptor(t, key) { return { value: 7, writable: false, configurable: false }; } });
const fake = new Proxy({}, { getOwnPropertyDescriptor() { return { value: 1, configurable: false }; } });
console.log(run(() => Object.getOwnPropertyDescriptor(nc, "id")), "|", run(() => Object.getOwnPropertyDescriptor(fake, "x")), "|", run(() => Object.getOwnPropertyDescriptor(new Proxy({}, { getOwnPropertyDescriptor() { return 1; } }), "x")));
```

<ResultBox>
\{"value":5,"writable":false,"enumerable":false,"configurable":true\}\
TypeError: 'getOwnPropertyDescriptor' on proxy: trap reported non-configurable and non-writable for property 'id' which is non-configurable, writable in the proxy target | TypeError: 'getOwnPropertyDescriptor' on proxy: trap reported non-configurability for property 'x' which is either non-existent or configurable in the proxy target | TypeError: 'getOwnPropertyDescriptor' on proxy: trap returned neither object nor undefined for property 'x'
</ResultBox>

Свойства `kitap` у цели нет, а дескриптор есть — цель расширяема, и это законно. Последнее правило
защищает обещание «незаписываемое не изменится»: если цель ещё может переписать `id`, прокси не вправе
назвать его вечным.

## 14. Практика: нарушение инварианта {#invariants}

Зачем всё это. Инварианты 6.1.7.3 обещают, например, что неудаляемое свойство не исчезнет, а нерасширяемый
объект не обрастёт новыми. На этих обещаниях стоит `Object.freeze`: код, получивший замороженный объект,
не перепроверяет его. Прокси, которому это позволено нарушить, сломал бы все такие гарантии — поэтому 10.5 сверяет
ответы ловушек с целью. Цель с неудаляемым `id` и обработчик-лжец:

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const target = {};
Object.defineProperty(target, "id", { value: 7, configurable: false, writable: true });
const liar = new Proxy(target, {
  has() { return false; },
  ownKeys() { return []; },
  getOwnPropertyDescriptor() { return undefined; },
  deleteProperty() { return true; },
  defineProperty() { return true; },
});
console.log(run(() => "id" in liar));
console.log(run(() => Object.keys(liar)));
console.log(run(() => Object.getOwnPropertyDescriptor(liar, "id")));
console.log(run(() => delete liar.id));
console.log(run(() => Object.defineProperty(liar, "x", { value: 1, configurable: false })));
console.log(run(() => Object.preventExtensions(new Proxy({}, { preventExtensions() { return true; } }))));
```

<ResultBox>
TypeError: 'has' on proxy: trap returned falsish for property 'id' which exists in the proxy target as non-configurable\
TypeError: 'ownKeys' on proxy: trap result did not include 'id'\
TypeError: 'getOwnPropertyDescriptor' on proxy: trap returned undefined for property 'id' which is non-configurable in the proxy target\
TypeError: 'deleteProperty' on proxy: trap returned truish for property 'id' which is non-configurable in the proxy target\
TypeError: 'defineProperty' on proxy: trap returned truish for defining non-configurable property 'x' which is either non-existent or configurable in the proxy target\
TypeError: 'preventExtensions' on proxy: trap returned truish but the proxy target is extensible
</ResultBox>

У записи свои два правила 10.5.9: незаписываемое неудаляемое — только прежнее значение, аксессор без сеттера —
никак:

```js
"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const target = {};
Object.defineProperty(target, "fixed", { value: 1, writable: false, configurable: false });
Object.defineProperty(target, "noSetter", { get() { return 1; }, configurable: false });
const proxy = new Proxy(target, { set() { return true; } });
console.log(run(() => { proxy.fixed = 2; }), "|", run(() => { proxy.fixed = 1; }), "|", run(() => { proxy.noSetter = 1; }));
```

<ResultBox>
TypeError: 'set' on proxy: trap returned truish for property 'fixed' which exists in the proxy target as a non-configurable and non-writable data property with a different value | ok | TypeError: 'set' on proxy: trap returned truish for property 'noSetter' which exists in the proxy target as a non-configurable and non-writable accessor property without a setter
</ResultBox>

Тексты V8 называют нарушенное правило почти словами примечаний к 10.5 (у аксессора — неточно, «non-writable
accessor»). Сверяется только то, что расходится с *неудаляемыми* свойствами и нерасширяемостью цели: всё
удаляемое ловушка вправе подменять. Проверку без объекта — IsCompatiblePropertyDescriptor из задания 4 дня 14 —
зовут 10.5.5, 10.5.6 и, как видели вчера, строка (10.4.3.2).

## 15. Proxy.revocable и отзыв {#revoke}

[Proxy.revocable](https://tc39.es/ecma262/2026/#sec-proxy.revocable) (28.2.2.1, страница MDN
[Proxy.revocable()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Proxy/revocable)):
ProxyCreate и встроенная функция `revoke` без имени и параметров, со слотом \[\[RevocableProxy\]\]. Отзыв
ставит прокси обе ссылки в null и забывает прокси сам — второй вызов ничего не делает.

<Scheme src="scheme-revoke.svg">Отзыв рвёт обе связи прокси и связь revoke с прокси</Scheme>

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const { proxy, revoke } = Proxy.revocable({ word: "kitap" }, {});
console.log(proxy.word, typeof revoke, revoke.length, JSON.stringify(revoke.name), Object.keys(Proxy.revocable({}, {})).join());
revoke();
revoke();
console.log(typeof proxy, run(() => proxy.word), "|", run(() => Array.isArray(proxy)), "|", run(() => Object.keys(proxy)), "|", run(() => "word" in proxy));
```

<ResultBox>
kitap function 0 "" proxy,revoke\
object TypeError: Cannot perform 'get' on a proxy that has been revoked | TypeError: Cannot perform 'IsArray' on a proxy that has been revoked | TypeError: Cannot perform 'ownKeys' on a proxy that has been revoked | TypeError: Cannot perform 'has' on a proxy that has been revoked
</ResultBox>

Зачем отзыв: дать чужому коду доступ на время — модулю, обработчику, окну — и забрать его, не трогая сам объект.
Задание дня 9 спрашивало, откуда берёт реалм задание thenable, если `then` — отозванный прокси.
[GetFunctionRealm](https://tc39.es/ecma262/2026/#sec-getfunctionrealm) бросает TypeError
(ValidateNonRevokedProxy), но NewPromiseResolveThenableJob эту ошибку ловит и берёт текущий реалм — примечание
поясняет: чтобы было где создать ошибку, когда вызов `then` бросит; промис отклоняется этой TypeError.
Саму ошибку GetFunctionRealm видно через ArraySpeciesCreate дня 15: отозванный прокси функции всё ещё
конструктор, и шаг 2 спрашивает его реалм.

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const { proxy: ctor, revoke } = Proxy.revocable(function Words() {}, {});
const list = ["kitap"];
list.constructor = ctor;
revoke();
console.log(run(() => list.map((w) => w)), "|", typeof ctor);
const { proxy: fn, revoke: off } = Proxy.revocable(function () {}, {});
off();
console.log(run(() => fn()), "|", run(() => new fn()));
```

<ResultBox>
TypeError: Cannot perform 'undefined' on a proxy that has been revoked | function\
TypeError: Cannot perform 'apply' on a proxy that has been revoked | TypeError: Cannot perform 'construct' on a proxy that has been revoked
</ResultBox>

### Текст V8: «Cannot perform 'undefined'» {#v8-text}

Поведение совпадает с текстом 2026 — TypeError из GetFunctionRealm. Но V8 подставляет в сообщение имя
операции, а у GetFunctionRealm его нет, и в тексте вышло `'undefined'`. По одному сообщению такую ошибку
не узнать: это не ловушка `get`, а проверка реалма.

## 16. «Карточки 2.0»: настройки без опечаток {#cards}

Добавим «Карточкам 2.0» настройки: сколько карточек в день и звук. Опечатка `settings.perday` у
обычного объекта молча даёт undefined, а при записи — новое бесполезное свойство. Прокси делает из опечатки
ошибку (модули строгие — модель тоже):

```js
"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const settings = new Proxy({ perDay: 10, sound: true }, {
  get(t, key) {
    if (typeof key === "string" && !(key in t)) throw new ReferenceError(`нет настройки «${key}»`);
    return t[key];
  },
  set(t, key, value) {
    if (!(key in t)) throw new ReferenceError(`нет настройки «${String(key)}»`);
    if (typeof value !== typeof t[key]) throw new TypeError(`${String(key)}: нужен ${typeof t[key]}`);
    t[key] = value;
    return true;
  },
});
settings.perDay = 20;
console.log(settings.perDay, run(() => settings.perday), "|", run(() => { settings.perday = 5; }), "|", run(() => { settings.perDay = "5"; }));
console.log(run(() => JSON.stringify(settings)), "|", "toString" in settings, run(() => String(settings)));
```

<ResultBox>
20 ReferenceError: нет настройки «perday» | ReferenceError: нет настройки «perday» | TypeError: perDay: нужен number\
ReferenceError: нет настройки «toJSON» | true ok
</ResultBox>

Опечатки пойманы, тип проверен. Но сохранить настройки нельзя: `JSON.stringify` спрашивает
`toJSON` (журнал раздела 11), а для нашей ловушки это «опечатка». `String` прошёл:
`Symbol.toPrimitive` — символ, а `toString` найден оператором `in` в прототипе.
Исправление — в задании: служебные имена языка пропускать. Страж опечаток — классика прокси, но каждая ловушка
обязана помнить, какие вопросы задаёт сам язык.

<Cheatsheet>
```js
// new Proxy(target, handler): методы — свои; нет ловушки — тот же метод у цели
// [[Call]] и [[Construct]] — по цели: ловушка apply у объекта не делает его функцией
// общая схема: отозван? → GetMethod(handler) → ловушка или цель → сверка с неудаляемым и нерасширяемостью
// get(target, key, receiver), set(target, key, value, receiver): t[key] теряет Receiver — Reflect, день 17
// set/deleteProperty/defineProperty вернули false: строгий код — TypeError; Object.assign бросает всегда
// Object.keys = ownKeys + дескриптор каждого ключа: виртуальным ключам нужен getOwnPropertyDescriptor
// ловушка get отвечает и языку: Symbol.toPrimitive, toJSON, then — отдавать цели
// приватные поля и внутренние слоты на прокси не переходят
// Proxy.revocable: revoke() — цель и обработчик null, любая операция — TypeError
```
</Cheatsheet>

<Selfcheck>
1. Почему `new Proxy({}, { apply() {} })()` — TypeError, хотя ловушка `apply` есть?
   <Answer>\[\[Call\]\] ставит ProxyCreate, только если цель вызываемая. У обычного объекта \[\[Call\]\] нет, и
   ловушку некому вызвать.</Answer>
2. Когда `get` обязана вернуть значение цели?
   <Answer>Когда у цели своё неудаляемое незаписываемое свойство данных. У неудаляемого аксессора без геттера —
   обязана вернуть undefined. В остальных случаях — что угодно.</Answer>
3. Почему `Object.keys` пуст у прокси, чья `ownKeys` отдаёт `["a", "b"]`?
   <Answer>`Object.keys` спрашивает дескриптор каждого ключа; у цели свойств нет, ловушки
   `getOwnPropertyDescriptor` нет — дескрипторы undefined, ключи отброшены.</Answer>
4. Прокси с `set`, которая проверяет значение. Как записать в него непроверенное?
   <Answer>`Object.defineProperty`: он идёт к \[\[DefineOwnProperty\]\], мимо \[\[Set\]\]. Нужна ещё
   ловушка `defineProperty`.</Answer>
5. Почему геттер цели, вызванный через `Object.create(proxy).who`, видит в `this`
   цель, если ловушка пишет `return t[key]`?
   <Answer>`t[key]` — новый \[\[Get\]\] у цели с Receiver = цель. Receiver наследника пришёл в ловушку
   третьим аргументом и не использован.</Answer>
6. Что сделает `typeof` у отозванного прокси функции? А вызов?
   <Answer>`typeof` — «function»: \[\[Call\]\] у прокси остался. Вызов — TypeError из
   ValidateNonRevokedProxy.</Answer>
7. Зачем 10.5 сверяет ответы ловушек с целью?
   <Answer>Чтобы прокси не нарушал инварианты 6.1.7.3: неудаляемое не исчезает и не меняет вида, нерасширяемый
   объект не получает новых свойств. На них держатся `freeze` и `seal`.</Answer>
</Selfcheck>
