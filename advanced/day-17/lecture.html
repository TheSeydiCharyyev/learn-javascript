1. Глава 28 и объект Reflect

Глава 28 Reflection собирает то, чем код смотрит на объекты и меняет их поведение: 28.1 — объект Reflect, 28.2 — Proxy (день 16), 28.3 — объекты пространства имён модуля (день 15). Раздел 28.1 описывает Reflect семью пунктами: это %Reflect%, обычный объект с прототипом %Object.prototype%, и он не функция — нет ни [[Call]], ни [[Construct]]. Страница MDN Reflect сравнивает его с Math: все свойства статические.

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
console.log(typeof Reflect, String(Reflect), Object.getPrototypeOf(Reflect) === Object.prototype, Object.getOwnPropertyNames(Reflect).length);
console.log(run(() => Reflect()), "|", run(() => new Reflect()));
const d = Object.getOwnPropertyDescriptor(Reflect, "get");
console.log(d.writable, d.enumerable, d.configurable, Reflect.get.length, Reflect.construct.length, Reflect.set.length);
object [object Reflect] true 13
TypeError: Reflect is not a function | TypeError: Reflect is not a constructor
true false true 2 2 3

Тринадцать функций — записываемые и удаляемые, но не перечисляемые, как все встроенные методы, — и строка «Reflect» под %Symbol.toStringTag% (28.1.14). У get, construct и set последний аргумент необязательный, поэтому length на единицу меньше. Каждая функция делает одно: проверяет аргументы и зовёт внутренний метод цели. Вот она, таблица 29 дня 16, с третьим столбцом:

Имена и аргументы функций Reflect совпадают с ловушками. MDN называет это главным применением Reflect: «default forwarding behavior in Proxy handler traps».

2. Булево вместо исключения

Внутренние методы отвечают булевым (день 14): получилось или нет. Object.defineProperty превращает false в TypeError (DefinePropertyOrThrow, день 7), присваивание в строгом коде — тоже (PutValue). Reflect отдаёт ответ метода как есть, и в строгом коде тоже:

"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const frozen = Object.freeze({ word: "kitap" });
console.log(Reflect.defineProperty(frozen, "x", { value: 1 }), run(() => Object.defineProperty(frozen, "x", { value: 1 })));
console.log(Reflect.set(frozen, "word", "suw"), run(() => { frozen.word = "suw"; }));
console.log(Reflect.deleteProperty(frozen, "word"), run(() => delete frozen.word));
console.log(Reflect.setPrototypeOf(frozen, null), run(() => Object.setPrototypeOf(frozen, null)));
console.log(Object.getPrototypeOf(1) === Number.prototype, run(() => Reflect.getPrototypeOf(1)), Object.isExtensible(1), run(() => Reflect.isExtensible(1)));
false TypeError: Cannot define property x, object is not extensible
false TypeError: Cannot assign to read only property 'word' of object '#<Object>'
false TypeError: Cannot delete property 'word' of #<Object>
false TypeError: #<Object> is not extensible
true TypeError: Reflect.getPrototypeOf called on non-object false TypeError: Reflect.isExtensible called on non-object

Вторая разница — в первом шаге. Каждая функция 28.1.3–28.1.13 начинает с «If target is not an Object, throw a TypeError exception». Object.getPrototypeOf сначала зовёт ToObject, и у единицы находится Number.prototype, а Object.isExtensible для примитива просто отвечает false. Выходит, Reflect строг к аргументам и честен в ответе: ошибку даёт неверная цель, а не отказ метода.

3. ownKeys и порядок ключей

Reflect.ownKeys (28.1.10) — это [[OwnPropertyKeys]] и CreateArrayFromList: все свои ключи одним массивом, строки и символы, перечисляемые и нет. Порядок задаёт OrdinaryOwnPropertyKeys (день 14): индексы по возрастанию, потом строки в порядке создания, потом символы.

const tag = Symbol("tag");
const card = { word: "kitap", 2: "b", [tag]: 1, 1: "a" };
Object.defineProperty(card, "hidden", { value: true, enumerable: false });
console.log(Reflect.ownKeys(card).map(String).join(" "));
console.log(Object.keys(card).join(" "), "|", Object.getOwnPropertyNames(card).join(" "), "|", Object.getOwnPropertySymbols(card).map(String).join(" "));
class Lesson { static day = 17; }
console.log(Reflect.ownKeys([7, 8]).join(" "), "|", Reflect.ownKeys(Lesson).join(" "), "|", Reflect.ownKeys(() => {}).join(" "));
1 2 word hidden Symbol(tag)
1 2 word | 1 2 word hidden | Symbol(tag)
0 1 length | length name prototype day | length name

Object.keys берёт только перечисляемые строки, getOwnPropertyNames — все строки, getOwnPropertySymbols — только символы; ownKeys — объединение двух последних в порядке [[OwnPropertyKeys]]. Символ tag создан раньше hidden, но стоит после: символы всегда в конце. У массива свой length, у класса — length, name, prototype и статическое поле, у стрелки prototype нет.

4. get и set: Receiver

Reflect.get (28.1.5) и Reflect.set (28.1.12) принимают необязательный receiver; нет его — «Set receiver to target». Это Receiver дня 14: на нём вызывают геттер и сеттер, на нём OrdinarySetWithOwnDescriptor создаёт свойство. MDN пишет о нём так: «The value of this provided for the call to target if a getter is encountered».

const card = { word: "kitap", get title() { return this.word.toUpperCase(); }, set title(v) { this.word = v.toLowerCase(); } };
const other = { word: "galam" };
console.log(Reflect.get(card, "title"), Reflect.get(card, "title", other), card.title);
console.log(Reflect.set(card, "title", "SUW", other), other.word, card.word);
const plain = {};
console.log(Reflect.set({ x: 1 }, "x", 2, plain), plain.x, Reflect.set({ x: 1 }, "x", 2, 5), Reflect.set(Object.freeze({ x: 1 }), "x", 2, plain));
KITAP GALAM KITAP
true suw kitap
true 2 false false

Геттер и сеттер title взяли this = other: прочитали и переписали чужое слово, а card не изменился. В третьей строке свойство x нашлось у цели, а записалось в plain. Receiver-примитив — false (шаг «If Receiver is not an Object, return false»), незаписываемое свойство цели — тоже false, даже если пишут в другой объект.

5. Практика: прокси с верной пересылкой

На дне 16 ловушки пересылали через t[key] и теряли Receiver: наследник прокси получал геттер с this = цель, а запись через прокси в прототипе попадала в цель. Те же два примера с Reflect:

const target = { name: "цель", get who() { return this.name; } };
const lost = new Proxy(target, { get(t, key) { return t[key]; } });
const right = new Proxy(target, { get(t, key, receiver) { return Reflect.get(t, key, receiver); } });
const a = Object.create(lost);
const b = Object.create(right);
a.name = "наследник";
b.name = "наследник";
console.log(a.who, b.who);
const proto = new Proxy({}, { set(t, key, value, receiver) { return Reflect.set(t, key, value, receiver); } });
const child = Object.create(proto);
child.x = 1;
console.log(Object.hasOwn(child, "x"), Object.keys(Object.getPrototypeOf(child)).length);
цель наследник
true 0

Ловушка получила receiver последним аргументом и отдала его дальше — больше ничего не нужно. А раз имена и аргументы совпадают, ловушки можно не писать по одной. Обработчик-прокси дня 16 отвечает на каждое имя ловушки функцией, которая записывает имя и зовёт функцию Reflect с тем же именем:

const log = [];
const handler = new Proxy({}, { get(h, trap) { return (...args) => { log.push(trap); return Reflect[trap](...args); }; } });
const p = new Proxy({ x: 1 }, handler);
p.y = 2;
console.log(Object.keys(p).join(), "y" in p, delete p.x, JSON.stringify(p));
console.log(log.join(", "));
x,y true true {"y":2}
set, getOwnPropertyDescriptor, defineProperty, ownKeys, getOwnPropertyDescriptor, getOwnPropertyDescriptor, has, deleteProperty, get, ownKeys, getOwnPropertyDescriptor, get

Журнал дня 16 подменял ответ «ловушки нет», этот — пересылает каждую операцию и видит всю цепочку. p.y = 2 — это set, а за ним getOwnPropertyDescriptor и defineProperty: Reflect.set передал Receiver = прокси, и OrdinarySetWithOwnDescriptor спросил и определил свойство на нём, то есть снова через ловушки. JSON.stringify начинает с get (toJSON) и заканчивает get значения y.

6. apply: аргументы списком

Reflect.apply (28.1.1): цель не вызываемая — TypeError; аргументы — CreateListFromArrayLike, то есть любой объект с length; потом Call. Зачем он, если есть Function.prototype.apply? Метод apply ищут у самой функции, и его можно подменить — поэтому на днях 15 и 16 мы писали Function.prototype.apply.call(f, …). Reflect.apply короче:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
function show(a, b) { return `${this.name}: ${a}, ${b}`; }
show.apply = () => "подменённый apply";
console.log(show.apply({ name: "x" }, [1, 2]), "|", Reflect.apply(show, { name: "kitap" }, [1, 2]), "|", Reflect.apply(Math.max, null, { length: 2, 0: 3, 1: 7 }));
console.log(Math.max.apply(null), run(() => Reflect.apply(Math.max, null)), "|", run(() => Reflect.apply({}, null, [])));
подменённый apply | kitap: 1, 2 | 7
-Infinity TypeError: CreateListFromArrayLike called on non-object | TypeError: Function.prototype.apply was called on #<Object>, which is an object and not a function

Разница в мелочи: Function.prototype.apply без массива зовёт функцию без аргументов (Math.max() — −∞), а Reflect.apply требует объект. Текст V8 о невызываемой цели упоминает Function.prototype.apply, хотя звали Reflect.apply: у V8 общее сообщение.

7. construct и newTarget

Reflect.construct (28.1.2) — [[Construct]] с newTarget по выбору: нет третьего аргумента — сама цель; оба обязаны быть конструкторами. MDN: это «the only way to construct a target function with a specific new.target value». На дне 16 ловушка construct звала new target(...) и теряла newTarget наследника. С Reflect.construct:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
class Card { constructor(word) { this.word = word; this.made = new.target.name; } }
const Watched = new Proxy(Card, { construct(target, args, newTarget) { return Reflect.construct(target, args, newTarget); } });
class BigCard extends Watched { level = 2; }
const big = new BigCard("suw");
console.log(big instanceof BigCard, big.made, JSON.stringify(big));
class Other {}
const mixed = Reflect.construct(Card, ["kitap"], Other);
console.log(mixed.word, mixed.made, mixed instanceof Other, mixed instanceof Card);
console.log(run(() => Reflect.construct(() => {}, [])), "|", run(() => Reflect.construct(Card, [], () => {})), "|", run(() => Reflect.construct(Card)));
true BigCard {"word":"suw","made":"BigCard","level":2}
kitap Other true false
TypeError: () => {} is not a constructor | TypeError: () => {} is not a constructor | TypeError: CreateListFromArrayLike called on non-object

Внутри Card new.target — BigCard, и объект — BigCard. Вторая строка — то, что без Reflect не сделать: код конструктора Card, а прототип — Other, потому что OrdinaryCreateFromConstructor берёт prototype у newTarget (день 14). Так закрывается и задание 4 дня 15: модель bind теряла newTarget наследника, а с Reflect — нет.

function myBind(target, boundThis, ...boundArgs) {
  return function bound(...args) {
    if (new.target === undefined) return Reflect.apply(target, boundThis, [...boundArgs, ...args]);
    return Reflect.construct(target, [...boundArgs, ...args], new.target === bound ? target : new.target);
  };
}
class Point { constructor(x, y) { this.x = x; this.y = y; } }
const OnAxis = myBind(Point, null, 0);
class Sub extends OnAxis {}
console.log(new Sub(5) instanceof Sub, new Sub(5).y, new OnAxis(5) instanceof Point);
true 5 true

9. Symbol.toPrimitive

ToPrimitive (7.1.1, день 5) первым шагом делает GetMethod(input, %Symbol.toPrimitive%). Метод есть — его зовут с подсказкой «default», «number» или «string», и ответ обязан быть примитивом. Страница MDN Symbol.toPrimitive показывает объект, который на каждую подсказку отвечает своим. Цена:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const price = { amount: 12, [Symbol.toPrimitive](hint) { return hint === "number" ? this.amount : hint === "string" ? `${this.amount} манат` : "цена"; } };
console.log(+price, `${price}`, price + "", price * 2, [price] + "", price == "цена");
console.log(run(() => +{ [Symbol.toPrimitive]() { return {}; } }), "|", run(() => `${{ [Symbol.toPrimitive]: 1 }}`));
12 12 манат цена 24 12 манат true
TypeError: Cannot convert object to primitive value | TypeError: number 1 is not a function

Унарный плюс и умножение просят число, шаблон и [price] + "" (через join и ToString) — строку, а бинарный плюс и == подсказки не дают — это «default». Метод вернул объект — TypeError шага 1.b.vi; не функция — TypeError из GetMethod.

Примечание к 7.1.1: из встроенных объектов свой метод есть только у Date и Symbol. Дата — единственная, кто считает «default» строкой (21.4.4.45), поэтому d + 1 — строка, а d - 1 — число:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const d = new Date(2026, 10, 3);
console.log(typeof (d + 1), typeof (d - 1), d[Symbol.toPrimitive]("number") === d.getTime(), d[Symbol.toPrimitive]("default") === String(d), run(() => d[Symbol.toPrimitive]("число")));
const s = Symbol("kitap");
const dd = Object.getOwnPropertyDescriptor(Symbol.prototype, Symbol.toPrimitive);
console.log(Object(s)[Symbol.toPrimitive]() === s, Symbol.prototype[Symbol.toPrimitive].name, dd.writable, dd.configurable, run(() => Object(s) + ""));
string number true true TypeError: Invalid hint: число
true [Symbol.toPrimitive] false true TypeError: Cannot convert a Symbol value to a string

Метод даты — OrdinaryToPrimitive с порядком по подсказке; чужая подсказка — TypeError. Symbol.prototype[Symbol.toPrimitive] (20.4.3.5) подсказку не смотрит и отдаёт символ из обёртки, поэтому обёртка + строка падает так же, как сам символ. У обоих методов writable: false, но configurable: true: заменить можно только через defineProperty.

10. Symbol.toStringTag

Object.prototype.toString (20.1.3.6, день 15) сначала выбирает тег по слотам: Array, Arguments, Function, Error, Boolean, Number, String, Date, RegExp, иначе Object. Потом читает Get(O, %Symbol.toStringTag%), и если там строка — она идёт в ответ. У Map, Promise, Math, JSON, Reflect, символов, генераторов и BigInt такая строка лежит в прототипе или в самом объекте (Symbol.toStringTag, раздел «Built-in toStringTag symbols»):

const tag = (x) => Object.prototype.toString.call(x);
console.log(tag(new Map()), tag(Promise.resolve()), tag(Math), tag(JSON), tag(Reflect), tag(Symbol()), tag(function* () {}()), tag(1n));
class Deck { get [Symbol.toStringTag]() { return "Deck"; } }
const arr = [];
arr[Symbol.toStringTag] = "Колода";
console.log(tag(new Deck()), String(new Deck()), tag(arr), Array.isArray(arr), tag({ [Symbol.toStringTag]: 42 }), tag(new Proxy([], {})));
[object Map] [object Promise] [object Math] [object JSON] [object Reflect] [object Symbol] [object Generator] [object BigInt]
[object Deck] [object Deck] [object Колода] true [object Object] [object Array]

Своему классу хватает одного геттера. Строка побеждает даже тег по слотам: массив с тегом «Колода» остаётся массивом, но toString его уже не узнаёт. Поэтому примечание к 20.1.3.6 и предупреждает, что toString «does not provide a reliable type testing mechanism». Тег не строка — молча берётся тег по слотам. Прокси массива — Array: IsArray смотрит сквозь прокси (день 16).

11. Symbol.species

Array[Symbol.species] (23.1.2.6) — геттер, который отдаёт this, поэтому у наследника Deck он отдаёт Deck. ArraySpeciesCreate (день 15) берёт constructor объекта, а у него — Symbol.species, и map наследника создаёт наследника. Свой статический геттер меняет ответ:

class Deck extends Array { static get [Symbol.species]() { return Array; } }
const d = Deck.from(["kitap", "galam"]);
console.log(d instanceof Deck, d.map((w) => w).constructor.name, d.filter(Boolean) instanceof Deck, d.slice() instanceof Deck, Deck.of(1) instanceof Deck);
const desc = Object.getOwnPropertyDescriptor(Array, Symbol.species);
console.log(typeof desc.get, desc.set, desc.get.name, desc.get.call(Deck) === Deck);
true Array false false true
function undefined get [Symbol.species] true

map, filter и slice отдали Array, а Deck.of — Deck: of и from создают через this, без species. Страница MDN Symbol.species объясняет зачем: species — «a protocol about how instances should be copied», и производному объекту не всегда нужны методы наследника. Промисы делают то же через SpeciesConstructor (7.3.22, день 7): then и finally берут constructor, у него — species; undefined или null — конструктор по умолчанию.

class Lesson extends Promise { static get [Symbol.species]() { return Promise; } }
const l = Lesson.resolve(1);
console.log(l instanceof Lesson, l.then((x) => x) instanceof Lesson, l.then((x) => x).constructor.name, l.finally(() => {}) instanceof Lesson);
class Lazy extends Promise { static get [Symbol.species]() { return null; } }
console.log(Lazy.resolve(1).then((x) => x).constructor.name);

12. Практика: своя проверка instanceof

InstanceofOperator (13.10.2): правый операнд не объект — TypeError; есть метод %Symbol.hasInstance% — ToBoolean от его ответа; иначе правый операнд обязан быть вызываемым, и работает OrdinaryHasInstance (день 7). Курс 2 показал метод для знакомства, а теперь — проверка, которой нужен не прототип, а свойство значения:

Обычной функции метод не присвоить: все функции наследуют Function.prototype[%Symbol.hasInstance%] (20.2.3.6), а он незаписываемый и неудаляемый. Нестрогий код молчит, строгий бросает — OrdinarySetWithOwnDescriptor (день 14) отказывает при незаписываемом свойстве в прототипе. Примечание объясняет зачем: иначе подменённый метод раскрыл бы цель связанной функции. Своё свойство — через defineProperty или static в классе, а прежний ответ даёт вызов метода Function.prototype. Объекту с методом [[Call]] не нужен: шаг с символом стоит раньше проверки IsCallable.

13. Символы методов строк и IsRegExp

Пять символов — match, matchAll, replace, search, split — разобраны на дне 19 курса 2: метод строки спрашивает аргумент о символе и отдаёт работу ему. Сегодня — обратная сторона, IsRegExp (7.2.6). Регулярка ли аргумент, решает не слот, а Get(argument, %Symbol.match%): есть ответ — ToBoolean от него, нет — слот [[RegExpMatcher]].

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const re = /a/g;
console.log(RegExp(re) === re, new RegExp(re) === re, run(() => "kitap".replaceAll(/a/, "_")), "|", "kitap".replaceAll(re, "_"));
const fake = { [Symbol.match]: true, source: "a", flags: "g", constructor: RegExp };

RegExp(re) без new отдаёт тот же объект, если IsRegExp — true и его constructor — RegExp; подделка с Symbol.match: true проходит тот же шаг. includes, startsWith и endsWith отказываются от регулярок, replaceAll и matchAll требуют флаг g. Сами методы лежат в RegExp.prototype под пятью символами (страницы MDN Symbol.match, Symbol.replace и соседние).

14. isConcatSpreadable и unscopables

IsConcatSpreadable (23.1.3.2.1): concat раскрывает аргумент, если Get по %Symbol.isConcatSpreadable% даёт true, а без ответа — если это массив. Так подобие массива раскрывается, а массив можно оставить целым:

const pair = { length: 2, 0: "kitap", 1: "galam", [Symbol.isConcatSpreadable]: true };
const solid = ["suw"];
solid[Symbol.isConcatSpreadable] = false;
const r = [1].concat(pair, solid, [2]);
console.log(r.length, r[1], Array.isArray(r[3]), r[3][0]);
const u = Array.prototype[Symbol.unscopables];

Symbol.unscopables спрашивает только инструкция with. Array.prototype[Symbol.unscopables] (23.1.3.41) — объект без прототипа с именами методов, появившихся с ES2015: старый код внутри with (array) не увидит их вместо своих переменных. Прототип null — совет MDN «Avoid using a non-null-prototype object»: иначе невидимыми стали бы и имена из Object.prototype. Сам with — день 31, там и проверим.

16. «Карточки 2.0»: колода со своими символами

Соберём всё в колоде: тег Deck для отладки, число карточек для сравнений, подпись для строк и species, чтобы map отдавал простые слова без методов колоды:

class Deck extends Array {
  static get [Symbol.species]() { return Array; }
  get [Symbol.toStringTag]() { return "Deck"; }
  [Symbol.toPrimitive](hint) { return hint === "number" ? this.length : `колода из ${this.length}`; }
}
const deck = Deck.from(["kitap", "galam", "suw"]);
console.log(String(deck), `${deck}`, +deck, deck > 2, Object.prototype.toString.call(deck), deck + "!");
const words = deck.map((w) => w.toUpperCase());
console.log(words instanceof Deck, Array.isArray(words), JSON.stringify(words), JSON.stringify(deck));

false true ["KITAP","GALAM","SUW"] ["kitap","galam","suw"]

String и шаблон дают подсказку «string», унарный плюс и > — «number», а deck + "!" — «default», и метод отдал подпись. map вернул Array. JSON.stringify видит обычный массив: ни тег, ни toPrimitive в JSON не участвуют.

  1. Почему Reflect.defineProperty на замороженном объекте отвечает false, а Object.defineProperty бросает?
    Ответ Оба зовут [[DefineOwnProperty]], и тот отвечает false. Object.defineProperty идёт через DefinePropertyOrThrow, который превращает false в TypeError; Reflect отдаёт ответ как есть.
  2. Что даёт третий аргумент Reflect.get?
    Ответ Receiver: с ним как с this вызывают найденный геттер. Нет аргумента — Receiver = цель.
  3. Чем ловушка get(t, key, receiver) { return Reflect.get(t, key, receiver); } лучше return t[key]?
    Ответ t[key] — новый [[Get]] с Receiver = цель: геттер получает this = цель, и наследник прокси теряется. Reflect.get передаёт Receiver, пришедший в ловушку.
  4. Как создать объект кодом конструктора Card, но с прототипом Other?
    Ответ Reflect.construct(Card, args, Other): OrdinaryCreateFromConstructor берёт prototype у newTarget, а код выполняет Card.
  5. Почему у даты d + 1 — строка, а d - 1 — число?
    Ответ Бинарный плюс зовёт ToPrimitive без подсказки — «default», и метод Date.prototype[Symbol.toPrimitive] считает её строкой. Минус просит число.
  6. Почему обычной функции нельзя присвоить F[Symbol.hasInstance] = …?
    Ответ Функция наследует Function.prototype[%Symbol.hasInstance%], а он незаписываемый: присваивание отклоняется (в строгом коде — TypeError). Своё свойство — через defineProperty или static в классе.
  7. Зачем наследнику Array свой Symbol.species?
    Ответ Чтобы map, filter, slice и другие копирующие методы создавали не наследника, а другой класс — обычно Array: ArraySpeciesCreate берёт species у constructor.
