1. Встроенные объекты: стандарт и реализация

День 1 оставил на сегодня четыре термина. Стандартный объект (4.4.11) — тот, чьё поведение описывает этот стандарт. Встроенный (4.4.12) — тот, кого даёт реализация ещё до программы; примечание: стандартные встроенные описаны здесь, а реализация может добавить свои. Встроенная функция (4.4.35) — например parseInt и Math.exp, встроенный конструктор (4.4.36) — Object и Function; хозяин может дать и такие, которых в стандарте нет.

Глава 18 задаёт общие правила для всех встроенных: прототип функции — %Function.prototype%, прототип прототипа — %Object.prototype%, [[Extensible]] — true, у каждой функции слот [[Realm]] (день 9). Функция хозяина выглядит так же:

console.log(typeof parseInt, Object.getPrototypeOf(parseInt) === Function.prototype, Object.isExtensible(Math), Object.getPrototypeOf(Map.prototype) === Object.prototype);
console.log(typeof setTimeout, Object.getPrototypeOf(setTimeout) === Function.prototype, setTimeout.name, setTimeout.length, "prototype" in setTimeout);
function true true true
function true setTimeout 1 false

setTimeout описан не в ECMA-262, а в стандарте HTML, но по 4.4.12 это тоже встроенная функция: её дал хозяин, и правила у неё те же. Слот [[Realm]] значит, что встроенные у каждого реалма свои:

const frame = document.body.appendChild(document.createElement("iframe"));
const other = frame.contentWindow;
console.log(other.parseInt === parseInt, other.parseInt("7"), Object.getPrototypeOf(other.parseInt) === other.Function.prototype, other.Math === Math, [] instanceof other.Array);
false 7 true false false

У рамки свои parseInt, Math и Array, и прототип её функций — её же Function.prototype. Поэтому массив из одного окна не instanceof Array другого, а Array.isArray (день 9) его узнаёт.

2. length встроенной функции

Правило главы 18: length — число обязательных параметров в заголовке раздела; необязательные (в квадратных скобках) и остаточные не считаются. Примечание 2 разбирает заголовок «Array.prototype.map (callback [, thisArg])»: длина — 1. Но «unless otherwise specified» — и у части функций длина записана отдельно:

const lengths = [Array.prototype.map, Array.prototype.push, Array.from, Math.max, parseInt, JSON.stringify, Object.assign, Promise.all, String.prototype.padStart, Reflect.set, Map, Date].map((f) => `${f.name}:${f.length}`);
console.log(lengths.join(" "));
const d = Object.getOwnPropertyDescriptor(Math.max, "length");
console.log(d.value, d.writable, d.enumerable, d.configurable);
map:1 push:1 from:1 max:2 parseInt:2 stringify:3 assign:2 all:1 padStart:1 set:3 Map:0 Date:7
2 false false true

У Math.max (...args) по правилу вышел бы 0, у push (...items) — тоже 0, у Date с одними необязательными — 0; спецификация отдельно пишет 2, 1 и 7. Атрибуты length — незаписываемое, но удаляемое. Длина конструктора — тоже по заголовку:

console.log([Promise, RegExp, Proxy, Error, Array.prototype.concat, Object.prototype.hasOwnProperty].map((f) => `${f.name}:${f.length}`).join(" "));
Promise:1 RegExp:2 Proxy:2 Error:1 concat:1 hasOwnProperty:1

«Promise (executor)», «RegExp (pattern, flags)», «Proxy (target, handler)» — все параметры обязательны; «Error (message [, options])» и «concat (...items)» дают 1 по общему правилу. Незаписываемое, но удаляемое — значит, присвоить нельзя, а переопределить и удалить можно:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
console.log(run(() => { "use strict"; parseInt.length = 5; }), "|", Object.defineProperty(parseInt, "length", { value: 5 }).length, parseInt.bind(null, "10").length, delete parseInt.length, parseInt.length, Object.hasOwn(parseInt, "length"));
TypeError: Cannot assign to read only property 'length' of function 'function parseInt() { [native code] }' | 5 4 true 0 false

bind посчитал длину от новой: 5 − 1 = 4 (день 15). После удаления length берётся из прототипа — у Function.prototype он 0.

3. name встроенной функции

name — имя функции в спецификации, для свойства — его ключ. Геттер и сеттер получают префикс «get» и «set» (параметр prefix у CreateBuiltinFunction, 10.3.4), у ключа-символа имя записано явно, а анонимные функции получают пустую строку:

const getter = (o, k) => Object.getOwnPropertyDescriptor(o, k).get.name;
console.log(getter(Map.prototype, "size"), "|", getter(RegExp.prototype, "flags"), "|", RegExp.prototype[Symbol.split].name, "|", Array.prototype[Symbol.iterator].name, Array.prototype[Symbol.iterator] === Array.prototype.values);
console.log(JSON.stringify(Promise.withResolvers().resolve.name), JSON.stringify(Proxy.revocable({}, {}).revoke.name), Math.max.bind(null).name);
get size | get flags | [Symbol.split] | values true
"" "" bound max

Array.prototype[Symbol.iterator] назван «values»: спецификация кладёт под символ ту же функцию, что и под values. Функции resolve промиса и revoke прокси анонимны (у revoke это видел день 16), а bind добавляет «bound » сам (день 15). Ещё три имени:

console.log(Object.getOwnPropertyDescriptor(Object.prototype, "__proto__").get.name, JSON.stringify(Function.prototype.name), Symbol.prototype[Symbol.toPrimitive].name);
get __proto__ "" [Symbol.toPrimitive]

Сам Function.prototype — тоже встроенная функция, и у неё name — пустая строка (20.2.3).

4. Лишние и недостающие аргументы

Глава 18: недостающие аргументы ведут себя как undefined, но считаются «not present», и алгоритм вправе это различить. Лишние вычисляются и отбрасываются, и реализация не может бросить TypeError только за то, что их передали:

console.log(parseInt("10", 2, "лишний"), "kitap".at(), [5, 7].indexOf(), Math.max(), [1, , 3].includes());
console.log([1, 2].reduce((a, b) => a + b), [1, 2].reduce((a, b) => a + b, undefined), isNaN(new Date(undefined)), isNaN(new Date()));
2 k -1 -Infinity true
3 NaN true false

Первая строка — правило «как undefined»: at() — индекс 0, indexOf() ищет undefined, includes() находит его в дыре. Вторая — «not present»: reduce проверяет «If initialValue is present», и явный undefined — уже начальное значение; Date смотрит число аргументов. Примечание 1 советует реализациям добавлять новые функции, а не новые параметры старым.

5. Конструктор или нет

Встроенная функция, не названная конструктором, не имеет [[Construct]] и свойства prototype. У конструктора один алгоритм на [[Call]] и [[Construct]], и различает их проверка «NewTarget is undefined»:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
console.log(run(() => new Math.max()), "|", run(() => new parseInt()), "|", "prototype" in Math.max, "prototype" in Map, Object.hasOwn(Array.prototype.map, "prototype"));
console.log(typeof Date(), typeof new Date(), Array(2).length, run(() => Map()), "|", run(() => Promise()));
TypeError: Math.max is not a constructor | TypeError: parseInt is not a constructor | false true false
string object 2 TypeError: Constructor Map requires 'new' | TypeError: Promise constructor cannot be invoked without 'new'

Без new Date отдаёт строку, Array работает как с new, а Map и Promise бросают — это первый шаг их алгоритмов. Symbol (день 17) — наоборот: бросает с new.

6. Атрибуты свойств

Последние абзацы главы 18: любое другое свойство данных глав 19–28 — записываемое, неперечисляемое, удаляемое; аксессор — неперечисляемый и удаляемый, а если описан только геттер, сеттер — undefined. Исключения записаны отдельно: Math.PI, NaN.

const flags = (o, k) => { const d = Object.getOwnPropertyDescriptor(o, k); return [d.writable, d.enumerable, d.configurable].join(); };
console.log(flags(Math, "max"), flags(Math, "PI"), flags(globalThis, "parseInt"), flags(globalThis, "NaN"), flags(Math.max, "name"));
console.log(Object.keys(Math).length, Object.getOwnPropertyNames(Math).length > 40, JSON.stringify(Object.getOwnPropertyDescriptor(Map.prototype, "size"), (k, v) => (typeof v === "function" ? v.name : v)));
true,false,true false,false,false true,false,true false,false,false false,false,true
0 true {"get":"get size","enumerable":false,"configurable":true}

Поэтому Object.keys(Math) пуст, а for...in по встроенным ничего не находит: всё неперечисляемое. В JSON дескриптора нет set — он undefined. Отсюда и старое правило не дописывать методы в Array.prototype присваиванием: такое свойство перечисляемое, и for...in по любому массиву его покажет, а метод самой спецификации — никогда.

7. Глава 17: что реализации нельзя

Глава 17 делит ошибки на ранние (до выполнения скрипта — SyntaxError разбора, день 13) и ошибки выполнения и разрешает хозяину расширять синтаксис, добавлять типы, объекты, свойства и функции — «except as restricted in 17.1». 17.1 перечисляет запреты: своих caller и arguments нет у строгих функций, стрелок, методов, генераторов, классов, встроенных и связанных функций; caller никогда не отдаёт строгую функцию; методы ECMA-402 не расширять; в модулях — без HTML-подобных комментариев <!-- приложения B.1.1.

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
function sloppy() {}
function strict() { "use strict"; }
console.log(Object.getOwnPropertyNames(sloppy).join(), "|", Object.getOwnPropertyNames(() => {}).join(), "|", Object.getOwnPropertyNames(class {}).join());
function who() { return who.caller; }
function callerSloppy() { return who(); }
function callerStrict() { "use strict"; return who(); }
console.log(callerSloppy() === callerSloppy, callerStrict(), run(() => strict.caller));
length,name,prototype | length,name | length,name,prototype
true null TypeError: 'caller', 'callee', and 'arguments' properties may not be accessed on strict mode functions or the arguments objects for calls to them

Chrome не дал своего caller даже нестрогой функции: он аксессор на Function.prototype. По 10.2.4 его геттер должен быть %ThrowTypeError%, но в Chrome он отвечает для нестрогих функций — на строгую вызывающую null, как требует 17.1. Это наследие, разберём на дне 31.

Ранние ошибки и ошибки выполнения

Глава 17 запрещает и обратное: считать ранней ошибку, которой нет в разделах «Static Semantics: Early Errors», «even if the compiler can prove that a construct cannot execute without error». Код в eval проверяется при вызове, и это видно:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
console.log(run(() => eval("if (false) { 1 + ; }")), "|", run(() => eval("if (false) { null.x; }")), "|", run(() => eval("null.x")));
console.log(run(() => eval("'use strict'; if (false) { delete kitap; }")), "|", run(() => new Function("return 1 +")));
SyntaxError: Unexpected token ';' | ok | TypeError: Cannot read properties of null (reading 'x')
SyntaxError: Delete of an unqualified identifier in strict mode. | SyntaxError: Unexpected token '}'

Ветка if (false) не выполнится никогда, но синтаксис и правило строгого режима для delete — ранние ошибки, и код не запускается. null.x там же — заведомая ошибка, но она ошибка выполнения: пока ветка не выполнена, её нет.

8. Глобальный объект

Глава 19: глобальный объект создаётся до любого контекста выполнения (у каждого реалма свой, день 9), у него нет ни [[Construct]], ни [[Call]], прототип задаёт хозяин, и у него могут быть свойства хозяина — «including a property whose value is the global object itself».

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
console.log(run(() => globalThis()), "|", run(() => new globalThis()), "|", globalThis === window, window === self, window.window === window);
const chain = [];
for (let o = Object.getPrototypeOf(globalThis); o !== null; o = Object.getPrototypeOf(o)) chain.push(Object.prototype.toString.call(o));
console.log(chain.join(" → "));
TypeError: globalThis is not a function | TypeError: globalThis is not a constructor | true true true
[object Window] → [object WindowProperties] → [object EventTarget] → [object Object]

В браузере window, self и globalThis — один объект, а цепочку из Window.prototype, WindowProperties и EventTarget.prototype построил хозяин. Прототип у window сменить нельзя (день 15).

Глобальный объект — только один из двух слоёв глобального окружения (день 13): var и объявления функций становятся его свойствами, а let, const и классы живут в отдельной записи:

var a = 1;
let b = 2;
function f() {}
console.log(globalThis.a, globalThis.b, "b" in globalThis, typeof globalThis.f, b);
1 undefined false function 2

9. globalThis, Infinity, NaN, undefined

19.1 — четыре значения. globalThis (19.1.1) — [[GlobalThisValue]] глобального окружения реалма, записываемое и удаляемое. Infinity, NaN и undefined (19.1.2–19.1.4, термины 4.4.26 и 4.4.27 дня 1) — незаписываемые и неудаляемые:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
undefined = 1;
NaN = 2;
var Infinity = 3;
console.log(undefined, NaN, Infinity, globalThis.undefined === void 0, (() => { let undefined = 5; return undefined; })());
console.log(run(() => { "use strict"; undefined = 1; }));
undefined NaN Infinity true 5
TypeError: Cannot assign to read only property 'undefined' of object '#<Window>'

Нестрогое присваивание молчит, строгое бросает (OrdinarySetWithOwnDescriptor, день 14). var Infinity разрешён: GlobalDeclarationInstantiation (день 13) не мешает var с именем существующего свойства, а запись в него снова молча не проходит. Внутри функции undefined — обычное имя. Но let на верхнем уровне скрипта — нет:

let undefined = 5;
console.log("не дойдёт");
Uncaught SyntaxError: Identifier 'undefined' has already been declared

HasRestrictedGlobalProperty видит неудаляемое свойство глобального объекта, и весь скрипт не выполняется. А вот globalThis — обычное удаляемое свойство, и после удаления имени больше нет:

console.log(delete globalThis.globalThis, typeof globalThis, delete window.undefined, typeof undefined);
true undefined false undefined

Сам глобальный объект никуда не делся — пропало только свойство, через которое его находят; window остался. undefined удалить нельзя: delete отвечает false.

Зачем вообще понадобилось имя globalThis, объясняет страница MDN globalThis: «Historically, accessing the global object has required different syntax in different JavaScript environments» — в браузере window, self или frames, в воркере только self, в Node.js — global. И важная оговорка раздела «HTML and the WindowProxy»: в браузере globalThis — не сам глобальный объект, а прокси вокруг него. Поэтому 19.1.1 и говорит о [[GlobalThisValue]]: значение задаёт хозяин.

10. Практика: стандарт и хозяин в globalThis

19.1–19.4 дают глобальному объекту 59 свойств: 4 значения, 9 функций, 42 конструктора и 4 объекта. ECMA-402 добавляет Intl, приложение B — escape и unescape (день 31). Всё остальное положили хозяин и сама программа:

var kitap = 1;
const own = Object.getOwnPropertyNames(globalThis);
const std = ["globalThis", "Infinity", "NaN", "undefined", "eval", "isFinite", "isNaN", "parseFloat", "parseInt", "decodeURI", "decodeURIComponent", "encodeURI", "encodeURIComponent", "Math", "JSON", "Reflect"];
console.log(own.length > 900, std.every((k) => own.includes(k)), own.includes("Intl"), own.includes("document"), own.includes("kitap"));
const where = (k) => { const d = Object.getOwnPropertyDescriptor(globalThis, k); return `${k}:${d.enumerable ? "e" : "-"}${d.configurable ? "c" : "-"}`; };
console.log(["parseInt", "Math", "Map", "Intl", "alert", "setTimeout", "document", "console", "kitap"].map(where).join(" "));
true true true true true
parseInt:-c Math:-c Map:-c Intl:-c alert:ec setTimeout:ec document:e- console:-c kitap:e-

Своих свойств у window больше девятисот, из них стандарту принадлежат шесть десятков. Отличить помогают атрибуты: у ECMA-262 и ECMA-402 — «-c» по главе 18. Операции хозяина (alert, setTimeout) перечисляемые, document ещё и неудаляемый, а пространство имён console выглядит как стандартное — его выдаёт только то, что в 19.1–19.4 его нет. var kitap стал свойством «e-»: var верхнего уровня даёт неудаляемое свойство окна (день 13; в тексте спецификации это CreateGlobalVarBinding).

Хозяин кладёт имена и в прототип. Элемент с id становится глобальным именем — его отдаёт объект WindowProperties из цепочки раздела 8:

const box = document.body.appendChild(document.createElement("div"));
box.id = "deck";
const named = Object.getPrototypeOf(Object.getPrototypeOf(window));
console.log(typeof deck, deck === box, "deck" in window, Object.hasOwn(window, "deck"), Object.hasOwn(named, "deck"), Object.prototype.toString.call(named));
object true true false true [object WindowProperties]

Своего свойства deck у window нет — имя нашлось в прототипе. Это и есть «host-defined behaviour instead of throwing an error (such as ReferenceError)» из главы 17: без хозяина deck было бы ReferenceError.

11. isFinite, isNaN, parseFloat

19.2 — девять функций: eval (день 13), четыре числовые и четыре для URI. Глобальные isFinite и isNaN (19.2.2, 19.2.3) начинают с ToNumber, а методы Number — нет; примечание к isNaN советует надёжную проверку X !== X. parseFloat (19.2.4) берёт самый длинный префикс, который подходит под StrDecimalLiteral:

console.log(isNaN("kitap"), Number.isNaN("kitap"), isFinite("12"), Number.isFinite("12"), isNaN(undefined), isNaN(null));
console.log(parseFloat("  3.5e2px"), parseFloat(".5"), parseFloat("Infinity!"), parseFloat("0x10"), parseFloat("1_000"), Number("1_000"));
true false true false true false
350 0.5 Infinity 0 1 NaN

У parseFloat нет шестнадцатеричной записи и разделителей _: префикс «0» и «1». Infinity — часть StrDecimalLiteral, поэтому распознан. Методы Number — не всегда двойники:

console.log(Number.parseInt === parseInt, Number.parseFloat === parseFloat, Number.isNaN === isNaN, Number.isFinite === isFinite);
true true false false

Number.parseInt и Number.parseFloat — те же функции %parseInt% и %parseFloat% (раздел 21.1.2 так и пишет), а Number.isNaN и Number.isFinite — новые, без ToNumber.

12. parseInt по шагам

19.2.5: строку — ToString и TrimString (пробелы и переводы строк, в том числе неразрывный пробел и BOM, день 2); знак «-» запомнить, «+» или «-» снять; основание — ToInt32 (день 6); дальше — по схеме:

console.log(parseInt("  -0x1F"), parseInt("0x1F", 16), parseInt("0x1F", 10), parseInt("-0"), Object.is(parseInt("-0"), -0), parseInt("12px"), parseInt(""), parseInt("z", 36), parseInt("Z", 36), parseInt(" ﻿7"));
-31 31 0 -0 true 12 NaN 35 35 7

Знак снимают раньше префикса, поэтому «-0x1F» — −31. С основанием 10 префикс не снимается, и цифры кончаются на «x»: 0. Буквы цифр — без учёта регистра. Рядом с parseFloat и Number (ToNumber, день 5) разница видна на одних входах:

const inputs = ["", " ", "12px", "0x10", "1e3", "0b101", "\t7\n", "1_000"];
console.log(inputs.map((s) => `${JSON.stringify(s)}: ${parseInt(s)} ${parseFloat(s)} ${Number(s)}`).join(" | "));
"": NaN NaN 0 | " ": NaN NaN 0 | "12px": 12 12 NaN | "0x10": 16 0 16 | "1e3": 1 1000 1000 | "0b101": 0 0 5 | "\t7\n": 7 7 7 | "1_000": 1 1 NaN

Number читает строку целиком (StringNumericLiteral): пустая — 0, хвост — NaN, зато знает 0x и 0b. Два разборщика читают префикс: parseInt — только целое с 0x, parseFloat — десятичную запись с экспонентой. Разделителей _ не знает никто из трёх.

13. Практика: загадки parseInt

Ловушку map(parseInt) мы видели в Essentials (день 20): map передаёт индекс вторым аргументом. Теперь — шагами 19.2.5:

(3) [1, NaN, NaN] (4) [10, NaN, 2, 3]

Индекс 0 — шаг 9: R = 10. Индекс 1 — шаг 8: меньше 2, NaN. «3» при R = 2 — первая же цифра чужая, Z пусто. Во второй строке работает шаг 1: ToString(0.0000005) — «5e-7», ToString(1e21) — «1e+21», а null в системе 36 — это слово «null». 4294967298 после ToInt32 — 2, −0 — 0, то есть 10. Третья строка — та же ToString: Infinity становится словом «Infinity», и в системе 19 из него годна только первая буква: «I» — 18, «n» — уже 23. Для длинных чисел шаг 13 разрешает реализации заменить цифры после двадцатой нулями: тридцать цифр всё равно не помещаются в Number точно, и ответ — ближайшее число.

14. Функции URI: Encode и Decode

19.2.6: encodeURI и decodeURI — для целого адреса, зарезервированные знаки они оставляют; encodeURIComponent и decodeURIComponent — для его части (Essentials, день 31). Все четыре сводятся к Encode и Decode:

«ASCII word characters» из Encode — буквы, цифры и подчёркивание, поэтому _ не кодируется. 16. «Карточки 2.0»: настройки из ссылки

Колодой делятся ссылкой: настройки лежат в её части после «?». Разберём их функциями дня — с явным основанием 10 и с перехватом URIError:

function readSettings(query) {
  const out = {};
  for (const pair of query.replace(/^\?/, "").split("&")) {
    const [key, value = ""] = pair.split("=");
    try { out[decodeURIComponent(key)] = decodeURIComponent(value.replaceAll("+", " ")); } catch (e) { out[key] = e.name; }
  }
  return out;
}
const s = readSettings("?perDay=20&deck=%D0%BA%D0%B8%D1%82%D0%B0%D0%BF&level=0x10&bad=%E0%A4%A");
console.log(JSON.stringify(s), parseInt(s.perDay, 10), parseInt(s.level, 10), parseInt(s.level), Number(s.level));
const link = "?deck=" + encodeURIComponent("kitap & galam") + "&perDay=" + 20;
console.log(link, readSettings(link).deck);
{"perDay":"20","deck":"китап","level":"0x10","bad":"URIError"} 20 0 16 16
?deck=kitap%20%26%20galam&perDay=20 kitap & galam

Сломанная часть не роняет разбор. «0x10» с основанием 10 — 0, без основания — 16: явное основание защищает от шестнадцатеричных сюрпризов. encodeURIComponent закодировал «&» внутри значения, иначе он разрезал бы пару. Плюс вместо пробела — правило HTML-форм, а не ECMAScript: страница MDN encodeURIComponent пишет «for application/x-www-form-urlencoded, spaces are to be replaced by +», а decodeURIComponent("a+b") плюс не трогает, поэтому readSettings меняет его сама. Хозяин браузера даёт для всего этого готовый URLSearchParams, но это уже не ECMAScript.

// свойства глав 19–28: writable, не enumerable, configurable (кроме записанных особо)

// язык берёт %Promise%, %Map% и других у реалма, а не из глобальных свойств
  1. Почему Array.prototype.map.length — 1, а Math.max.length — 2?
    Ответ По правилу главы 18 считаются обязательные параметры: у map — callback (thisArg необязателен). У max (...args) по правилу вышел бы 0, но спецификация записала длину 2 отдельно.
  2. Чем [1, 2].reduce(f) отличается от [1, 2].reduce(f, undefined)?
    Ответ Недостающий аргумент «not present»: reduce без него берёт первый элемент. Явный undefined — начальное значение, и первое сложение даёт NaN.
  3. Почему new Math.max() — TypeError, а Date() работает?
    Ответ Math.max не назван конструктором — у него нет [[Construct]]. Date — конструктор с одним алгоритмом на вызов и new: при NewTarget undefined он отдаёт строку.
  4. Почему let undefined = 5 на верхнем уровне скрипта — SyntaxError, а в функции — нет?
    Ответ undefined — неудаляемое свойство глобального объекта, и HasRestrictedGlobalProperty запрещает лексическое объявление с таким именем. В функции это обычное локальное имя.
  5. Что вернёт parseInt("0x1F", 10) и почему?
    Ответ 0: при R = 10 префикс не снимается (stripPrefix — false), цифры кончаются на «x», Z = «0».
  6. Почему encodeURIComponent("\uD83D") — URIError, а encodeURIComponent("😀") — нет?
    Ответ CodePointAt у одиночной старшей половинки ставит [[IsUnpairedSurrogate]] — Encode бросает. Эмодзи — пара половинок, одна кодовая точка, четыре байта UTF-8.
  7. Если перезаписать глобальный Promise, что вернёт асинхронная функция?
    Ответ Настоящий промис: язык создаёт его из %Promise% реалма, а не через глобальное свойство.
