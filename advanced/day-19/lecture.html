1. Проект вместо новой темы

Новых разделов сегодня нет: модуль «Объекты изнутри» разобрал, как прокси перехватывает внутренние методы, и это знание работает на приложение. На дне 29 Essentials и дне 16 курса 2 каждый слушатель сам звал render(): забыл вызов — страница показывает старое. Сегодня данные лежат в наблюдаемом хранилище: прокси замечает каждое изменение и сам заказывает перерисовку — так устроена реактивность во фреймворках.

Собираем доску заданий группы. Группа JS-1 делает «Карточки 2.0», и каждое задание проекта — карточка в колонке «Надо», «Делаю» или «Готово».

3. Главная схема

На дне 16 курса 2 слушатель звал метод класса, а потом render(). Теперь слушатель только пишет в state. Запись проходит через ловушку прокси: ловушка проверяет значение, кладёт его в цель через Reflect и зовёт notify(). Сам notify не рисует: он планирует одну микрозадачу, и подписчики — render и сохранение — работают, когда весь код слушателя закончился.

Какие ловушки для этого нужны — вопрос разделов 4–8, и ответ спецификации неочевиден.

4. Первая модель: set и deleteProperty

Первая мысль: запись — это set, удаление — deleteProperty. Модель — observe: зовёт onChange после каждой операции и пересылает через Reflect с receiver (день 17):

"use strict";
function observe(obj, onChange) {
  return new Proxy(obj, {
    set(target, key, value, receiver) {
      const ok = Reflect.set(target, key, value, receiver);
      onChange(key);
      return ok;
    },
    deleteProperty(target, key) {
      const ok = Reflect.deleteProperty(target, key);
      onChange(key);
      return ok;
    },
  });
}
const changes = [];
const state = observe({ filter: "" }, (key) => changes.push(key));
state.filter = "Аман";
state.note = "черновик";
delete state.note;
Object.defineProperty(state, "filter", { value: "Мерет" });
console.log(changes.join(", "), state.filter);
filter, note, note Мерет

Запись, новое свойство и удаление замечены, а Object.defineProperty прошёл мимо: «Мерет» записан, журнал молчит. Это видел раздел 8 дня 16 — [[DefineOwnProperty]] идёт мимо [[Set]] — и сделал вывод: «проверка записи — это две ловушки». Проверим его на уведомлениях.

5. Одна дверь: defineProperty

Добавим ловушку defineProperty с тем же onChange — и одно присваивание даст два уведомления: от defineProperty, потом от set. Почему, покажет журнал дня 17 — обработчик-прокси, который записывает имя каждой ловушки и зовёт Reflect с тем же именем:

"use strict";
const log = [];
const spy = (obj) => new Proxy(obj, new Proxy({}, {
  get: (h, trap) => (...args) => { log.push(`${trap} ${String(args[1])}`); return Reflect[trap](...args); },
}));
const state = spy({ filter: "" });
state.filter = "Аман";
console.log(log.join(", "));
set filter, getOwnPropertyDescriptor filter, defineProperty filter

Одно присваивание — три ловушки. Путь по шагам:

PutValue (6.2.5.6, шаг 3.d) зовёт [[Set]] прокси с получателем-прокси. Ловушка set журнала отдаёт его в Reflect.set (28.1.12, шаг 4), дальше — OrdinarySet (10.1.9.1) и OrdinarySetWithOwnDescriptor (10.1.9.2) у цели. А они работают с получателем: шаг 2.c спрашивает его [[GetOwnProperty]], шаг 2.h (для нового свойства — 2.d.ii, CreateDataProperty 7.3.5) зовёт его [[DefineOwnProperty]]. Получатель — прокси, и оба вызова снова идут через ловушки. День 14 проходил эти шаги на обычном объекте.

Вывод: любая запись через прокси с верным получателем кончается в его [[DefineOwnProperty]] (10.5.6), туда же идёт Object.defineProperty. Это одна дверь на все изменения: уведомлять — только в ней и в deleteProperty. Ловушка set не нужна: без неё 10.5.9 на шаге 6.a сам зовёт [[Set]] цели с тем же получателем. Пример на странице MDN handler.defineProperty() это показывает: присваивание proxy._secret = … падает в ловушке defineProperty, хотя в списке перехватов присваивания нет — только «any other operation that invokes the [[DefineOwnProperty]] internal method».

"use strict";

  return new Proxy(obj, {

      const ok = Reflect.defineProperty(target, key, desc);
      onChange(key);
      return ok;
    },
    deleteProperty(target, key) {
      const ok = Reflect.deleteProperty(target, key);
      onChange(key);
      return ok;
    },
  });
}

Четыре изменения — четыре уведомления, каждое по разу. Ответ дню 16: для записи хватает одной ловушки, если получатель верный.

6. Вложенные объекты: обёртка при чтении

Запись state.tasks[0].status = "done" идёт уже не в прокси: state.tasks вернул сам массив цели. Значит, всё прочитанное из хранилища надо отдавать обёрнутым — ловушка get, как lend задания 8 дня 16, только без отзыва:

"use strict";
const proxies = new WeakMap();
const changes = [];
const handler = {
  get(target, key, receiver) {
    const value = Reflect.get(target, key, receiver);
    return typeof value === "object" && value !== null ? wrap(value) : value;
  },
  defineProperty(target, key, desc) {
    changes.push(key);
    return Reflect.defineProperty(target, key, desc);
  },
};
function wrap(obj) {
  if (!proxies.has(obj)) proxies.set(obj, new Proxy(obj, handler));
  return proxies.get(obj);
}
const state = wrap({ tasks: [{ title: "Разметка", status: "todo" }] });
state.tasks[0].status = "done";
console.log(changes.join(", "), state.tasks === state.tasks, Array.isArray(state.tasks));
status true true

Обёртка нужна только объектам: функции вроде push отдаются как есть и вызываются с this = прокси, так что все записи метода идут через ловушки. WeakMap даёт объекту один прокси — иначе state.tasks === state.tasks было бы false (раздел 14 покажет, чем это кончается) — и не держит в памяти удалённое задание (курс 2, день 14). А Array.isArray видит массив сквозь прокси: IsArray (7.2.2, шаг 3) смотрит в цель, и JSON.stringify сохранит tasks массивом.

Хранилище получит два уведомления: индекс 3 и length. Длину поднял уже первый define — [[DefineOwnProperty]] массива при записи за концом (10.4.2.1, шаг 2.k; день 15), — а шаг 6 пишет то же 4: изменилось ли значение, никто не проверяет. Ключи в ловушках — строки или символы: "3", а не 3 (ToString 7.1.17 в шаге 5.a; у присваивания tasks[3] = … — ToPropertyKey 7.1.19).

Удаление тяжелее. splice(0, 1) у массива из четырёх переносит каждое следующее задание на шаг назад (23.1.3.31, шаги 16.b.iii.1–2: Get, потом Set), удаляет последний индекс (шаг 16.d.i) и пишет length (шаг 20) — пять уведомлений. И подвох: Get на шаге 16.b.iii.1 прошёл через нашу get и вернул обёртку, а Set записал её в массив-цель. При следующем чтении прокси обернут ещё раз, и слоёв с каждым удалением больше: в Chrome после трёх удалений первого задания запись в последнее проходит четыре ловушки defineProperty вместо одной. Поэтому store.js держит вторую WeakMap, прокси → цель, и перед записью меняет обёртку на цель.

8. Одна перерисовка на пачку изменений

«✕» у первого из четырёх заданий — пять уведомлений, а пользователь увидит только последний вариант. Поэтому notify не зовёт подписчиков сразу, а планирует одну микрозадачу:

"use strict";
let notes = 0, renders = 0, planned = false;
function notify() {
  notes++;
  if (planned) return;
  planned = true;
  Promise.resolve().then(() => {
    planned = false;
    renders++;
    console.log("перерисовка", renders, "после", notes, "уведомлений");
  });
}
const tasks = new Proxy(["Разметка", "Модуль", "Тесты"], {
  defineProperty(target, key, desc) { notify(); return Reflect.defineProperty(target, key, desc); },
  deleteProperty(target, key) { notify(); return Reflect.deleteProperty(target, key); },
});
tasks.push("Сохранение");
tasks.splice(0, 1);
console.log("код закончился, перерисовок:", renders);
код закончился, перерисовок: 0
перерисовка 1 после 7 уведомлений

Флажок planned пускает в очередь одну задачу на все уведомления. У выполненного промиса then сразу отдаёт задание хозяину — PerformPromiseThen (27.2.5.4.1) → HostEnqueuePromiseJob (9.5.5), — и браузер выполнит его, когда закончится текущий код (день 9; курс 2, день 28). Перерисовка видит итог: новое и удалённое задание — одним кадром. Обратная сторона: сразу после записи страница ещё старая.

9. store.js целиком

Выводы разделов 4–8 — в одном модуле; проверка значений — там же, где уведомление, в defineProperty. У каждого необычного места — номер раздела:

// store.js — наблюдаемое хранилище: Proxy (10.5) и Reflect (28.1)
export function createStore(data, allowed = {}) {
  const proxies = new WeakMap();   // цель → прокси: у объекта один прокси (день 16, задание 8)
  const targets = new WeakMap();   // прокси → цель: splice пишет назад прочитанное (23.1.3.31, шаг 16.b.iii)
  const listeners = new Set();
  let planned = false;

  function notify() {
    if (planned) return;
    planned = true;
    Promise.resolve().then(() => {   // микрозадача (27.2.5.4.1 → 9.5.5): после всего текущего кода
      planned = false;
      for (const listener of listeners) listener();
    });
  }

  function check(target, key, value) {
    const name = String(key);   // символ в шаблонной строке — TypeError (7.1.17, шаг 2)
    if (Object.hasOwn(target, key) && typeof value !== typeof target[key]) {
      throw new TypeError(`${name}: нужен ${typeof target[key]}, а пришёл ${typeof value}`);
    }
    if (Object.hasOwn(allowed, key) && !allowed[key].includes(value)) {
      throw new RangeError(`${name}: можно только ${allowed[key].join(", ")}`);
    }
  }

  const handler = {
    get(target, key, receiver) {
      const value = Reflect.get(target, key, receiver);   // receiver станет this геттера (10.1.8.1, шаг 7)
      return typeof value === "object" && value !== null ? wrap(value) : value;   // функции — как есть
    },
    // ловушки set нет: obj.key = value приходит сюда (10.5.9, шаг 6.a → 10.1.9.2, шаги 2.d.ii и 2.h)
    defineProperty(target, key, desc) {
      if ("value" in desc) {
        check(target, key, desc.value);
        if (targets.has(desc.value)) desc = { ...desc, value: targets.get(desc.value) };   // в цель — без обёртки
      }
      const ok = Reflect.defineProperty(target, key, desc);
      if (ok) notify();
      return ok;   // false → TypeError в строгом коде (6.2.5.6, шаг 3.e)
    },
    deleteProperty(target, key) {
      const ok = Reflect.deleteProperty(target, key);
      if (ok) notify();
      return ok;
    },
  };

  function wrap(obj) {
    if (!proxies.has(obj)) {
      const proxy = new Proxy(obj, handler);
      proxies.set(obj, proxy);
      targets.set(proxy, obj);
    }
    return proxies.get(obj);
  }

  return {
    state: wrap(data),
    subscribe(listener) {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
  };
}

Проверка типа — как в настройках дня 16: у существующего свойства новое значение того же typeof. Для полей с перечнем — у нас статус — второй аргумент allowed. TypeError — не тот тип, RangeError — не то значение; так же делит ошибки пример Validation на странице MDN Proxy. String(key) — потому что ключ бывает символом. Чего проверка не видит: объект через push приходит одной записью индекса, его поля не проверяются. subscribe возвращает отписку. Проверка шага — временный main.js:

13. Разбор: перенос молчит, удаление работает

Захотели видеть в консоли каждую запись и добавили в handler ловушку set:

// store.js — в handler добавили ловушку (с ошибкой)
set(target, key, value) {
  console.log("запись", key, value);
  return Reflect.set(target, key, value);
},

Шаг 1. Что не так? В консоли «запись status doing», а карточка стоит на месте. Не появляется и новое задание, молчит фильтр. А «✕» работает — и показывает все пропущенные изменения разом.

Шаг 2. Почему? Reflect.set без четвёртого аргумента делает получателем цель (28.1.12, шаг 3.a), и шаги 2.c и 2.h из 10.1.9.2 идут к обычному объекту-цели, мимо прокси (правая часть схемы раздела 5). defineProperty записи не видит, notify молчит. Удаление идёт своей ловушкой deleteProperty, она уведомляет, и render рисует цель, где уже лежат все «тихие» записи. Так же пишет значение пример Validation со страницы MDN Proxy — obj[prop] = value внутри set: для одного объекта это верно, для хранилища — нет.

Шаг 3. Чиним. Ловушке — четвёртый параметр receiver, и его же — в Reflect.set(target, key, value, receiver).

  1. Почему хранилищу не нужна ловушка set?
    Ответ Без неё [[Set]] прокси зовёт [[Set]] цели с тем же получателем (10.5.9, шаг 6.a), и OrdinarySetWithOwnDescriptor записывает значение через [[DefineOwnProperty]] получателя, то есть через ловушку defineProperty. Туда же идёт Object.defineProperty.
  2. Какие ловушки проходит state.tasks.push(x) и сколько будет уведомлений?
    Ответ get push, get length, потом для индекса и для length — set, getOwnPropertyDescriptor, defineProperty. Уведомлений два: индекс и length.
  3. Зачем обёртки хранятся в WeakMap?
    Ответ Чтобы у объекта был один прокси: иначе каждое чтение даёт новый, indexOf не находит задание, и splice(-1, 1) удаляет последнее. WeakMap не держит в памяти удалённые задания.
  4. Почему после пяти уведомлений перерисовка одна?
    Ответ notify только ставит одну микрозадачу (флажок planned), а браузер выполняет её, когда текущий код закончился. Подписчики видят уже итоговое состояние.
  5. Ловушка set пересылает Reflect.set(target, key, value). Что сломается?
    Ответ Получателем станет цель (28.1.12, шаг 3.a), и шаги 2.c и 2.h пойдут к цели напрямую. Ловушка defineProperty не увидит записи, страница не обновится.
