# День 19. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Проект — в папке `board`: `index.html`, `store.js` и `main.js` из лекции, запуск через Live Server. Каждую доработку делайте в копии папки. Копии на одном Live Server делят `localStorage`: перед каждым заданием — `localStorage.clear()` и обновить страницу.</Subtitle>

## Разминка

<Task title="1. Хранилище из консоли" level="easy" time="7">
<Goal>проверить хранилище и его проверки до доработок.</Goal>

Доска открыта, в консоли — `board`.

<Criteria>
- `Object.keys(board)` — `['title', 'filter', 'nextId', 'tasks']`;
  `board.tasks === board.tasks` и `Array.isArray(board.tasks)` — `true`;
  названо, что в `store.js` отвечает за каждое `true`;
- записаны тексты ошибок `board.tasks[0].id = "1"` и
  `board.tasks[0].status = "готово"`; объяснено, какая проверка сработала в каждом случае;
- после `delete board.filter` в консоли «Uncaught (in promise) TypeError: Cannot read
  properties of undefined (reading 'toLowerCase')», а колонка «Надо» опустела; объяснено, откуда
  «in promise» и почему пуста только одна колонка;
- `board.filter = ""` вернула доску; объяснено, почему проверка типа эту запись не
  остановила бы и с числом.
</Criteria>
</Task>

<Task title="2. Сколько уведомлений" level="easy" time="6">
<Goal>отличать работу хранилища от работы страницы.</Goal>

Первая строка `notify` — `console.count("notify")`, первая строка `render` —
`console.count("render")`. На свежей доске по порядку: «→» у «Проверки tests.js», «✕» у «Разметка
страницы», новое задание формой, «аман» в фильтре по буквам.

<Criteria>
- при загрузке — `render: 1`, а `notify` не сработал ни разу; объяснено почему;
- «→» — одно уведомление и одна перерисовка; «✕» у первой из четырёх — пять уведомлений и одна
  перерисовка;
- форма — три уведомления: названы три записи;
- «аман» — четыре уведомления и четыре перерисовки; объяснено, почему здесь перерисовок столько же,
  сколько уведомлений.
</Criteria>
</Task>

## Основные задания

<Task title="4. Сортировка в колонке" level="medium" time="12">
<Goal>показывать в другом порядке, не трогая данные.</Goal>

В каждой колонке карточки идут по имени того, кто делает, а у одного человека — по названию задания.

<Hint>
Порядок — дело показа. В `render` после `filter` —
[toSorted](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/toSorted)
(«the copying version of the sort() method») со сравнением
`a.who.localeCompare(b.who, "ru") || a.title.localeCompare(b.title, "ru")`.
</Hint>

<Criteria>
- в «Надо» — «Сохранение storage.js — Аман», потом «Проверки tests.js — Мерет»; после «→» у
  «Сохранение storage.js» в «Делаю» — «Модуль card.js», потом «Сохранение storage.js»;
- `board.tasks.map((t) => t.id).join()` — по-прежнему `"1,2,3,4"`, а
  `console.count` в `notify` из задания 2 при загрузке не сработал;
- в копии `render` начинается с `if (++n > 50) throw new Error("стоп");` и
  `state.tasks.sort(…)` (`let n = 0` — над функцией): консоль сразу показала
  «Uncaught (in promise) Error: стоп»; объяснено, почему без ограничителя круг перерисовок не
  кончился бы.
</Criteria>
</Task>

<Task title="5. Поля нового задания" level="medium" time="12">
<Goal>проверять не только запись, но и записанный объект.</Goal>

Сейчас `board.tasks.push({ id: 9, title: "x", who: "y", status: "готово" })` проходит: хранилище
видит запись индекса, а не поля объекта. Пусть `check` проверяет и поля значения-объекта.

<Hint>
В начале `check`: если значение — объект, пройти `Object.entries(value)` и вызвать
`check(value, k, v)` для каждого поля. Рекурсия дойдёт и до вложенных объектов.
</Hint>

Испорченные руками данные для третьего критерия — три строки в консоли:

```js
const data = JSON.parse(JSON.stringify(board));
data.tasks[0].status = "готово";
localStorage.setItem("board-js-1", JSON.stringify(data));
```

<Criteria>
- `push` с «готово» — `RangeError: status: можно только todo, doing, done`,
  `board.tasks.length` — 4, карточек — 4;
- форма, стрелки и «✕» работают без ошибок, хотя `splice` при переносе записывает задания
  целиком;
- после трёх строк в консоли и обновления страницы доска открылась без ошибки: «Заданий: 4 · готово: 0»,
  карточек 3; объяснено, почему проверка это пропустила.
</Criteria>
</Task>

<Task title="6. Пауза сохранения" level="medium" time="12">
<Goal>пользоваться отпиской.</Goal>

Рядом с фильтром — флажок «Не сохранять». Пока он включён, доска не пишет в `localStorage`;
выключили — сразу сохраняет текущее состояние.

<Hint>
`subscribe` возвращает отписку: `let stopSaving = subscribe(save)`. Флажок включили —
`stopSaving()`; выключили — подписаться снова и сразу вызвать `save()`.
</Hint>

<Criteria>
- флажок включён, «✕» у «Разметка страницы», обновление — «Разметка страницы» на месте;
- флажок включён, «✕», флажок выключен, обновление — «Разметки страницы» нет;
- с включённым флажком доска перерисовывается как обычно; объяснено, почему отписка одного подписчика
  не трогает другого;
- `subscribe(save)` дважды подряд — `save` зовётся один раз за изменение, а первая
  же отписка снимает его совсем; объяснено, при чём здесь `Set`.
</Criteria>
</Task>

<Task title="7. Подписка на поля" level="medium" time="14">
<Goal>звать подписчика, только когда изменилось нужное.</Goal>

`subscribe(listener, keys)`: второй аргумент необязателен — список ключей. Подписчик со списком
зовётся, только если в пачке изменений есть один из его ключей. Каждый подписчик получает массив изменённых
ключей; подписчики без списка зовутся, как раньше.

<Hint>
`notify(key)` копит ключи в `Set`, микрозадача отдаёт их массивом и чистит
`Set`. `listeners` — `Map`: подписчик → список или `null`.
</Hint>

<Criteria>
- `subscribe(() => console.log("фильтр:", state.filter), ["filter"])`: «аман» по буквам —
  четыре строки, «→», «✕» и форма — ни одной;
- подписчик без списка получил за «→» — `["status"]`, за «✕» у первой из четырёх —
  `["0", "1", "2", "3", "length"]`, за форму после этого — `["3", "length", "nextId"]`;
- подписчик на `["title"]` сработал и от `board.title = "JS-2"`, и от
  `board.tasks[0].title = "x"`; объяснено почему и что нужно, чтобы различать их.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Отменить" level="hard" time="10">
<Goal>построить историю изменений на подписчике.</Goal>

Кнопка «Отменить» возвращает задания и `nextId` на одно действие назад. При загрузке и когда
отменять нечего, она неактивна.

<Hint>
Подписчик кладёт снимок `JSON.stringify({ tasks: state.tasks, nextId: state.nextId })` в массив,
если он отличается от последнего; первый снимок — при загрузке. Отмена убирает последний снимок и записывает
предыдущий в `state`.
</Hint>

<Criteria>
- при загрузке «Отменить» неактивна (`disabled`);
- задание «Тесты» (Сапар), «→» у него, «✕» у «Разметка страницы», «аман» в фильтре и обратно пусто —
  три «Отменить» возвращают первую доску, кнопка снова неактивна;
- после этого новое задание снова получает номер 5;
- объяснено, почему само восстановление не попадает в историю и почему без сравнения с последним
  снимком отменяется только одно действие, а дальше «Отменить» ничего не меняет.
</Criteria>
</Task>

<Task title="9. Три жалобы" level="hard" time="10">
<Goal>искать ошибку хранилища от симптома.</Goal>

Одноклассник прислал свою доску и три жалобы:

- «Один щелчок „✕“ — и `console.count("render")` вырос на пять, хотя доска правильная».
- «Удалил задание, обновил страницу — пустая страница, в консоли SyntaxError: "\[object Object\]" is not valid
  JSON».
- «Набрал в фильтре „аман“, обновил страницу — поле пустое, а на доске только задания Амана».

От проекта лекции его доска отличается в этих местах:

```js
// store.js — notify
function notify() {
  Promise.resolve().then(() => {
    for (const listener of listeners) listener();
  });
}

// main.js — сохранение
subscribe(() => localStorage.setItem(SAVED, state));

// main.js — первый показ, без строки filter.value = state.filter;
render();
```

<Hint>
Начните с вопроса «что в `localStorage`?»: `localStorage.getItem("board-js-1")`.
</Hint>

<Criteria>
- каждая жалоба воспроизведена и сопоставлена со своим фрагментом;
- объяснено, почему без флажка `planned` перерисовок пять, а доска всё равно верная;
- показано, что в `localStorage` лежит `"[object Object]"`, и объяснено, откуда эта
  строка: ToString ([7.1.17](https://tc39.es/ecma262/2026/#sec-tostring), шаг 10) превращает
  объект через ToPrimitive;
- все три исправлены; объяснено, почему после исправления второй жалобы страница пустая до
  `localStorage.clear()`.
</Criteria>
</Task>
