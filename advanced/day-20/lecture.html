ArrayBuffer и типизированные массивы

Курс 3, Advanced. Модуль «Двоичные данные и модель памяти» — первый день. 45 минут.

  • отличать буфер — байты — от вида, который читает их как числа, и читать один буфер тремя видами;

1. Буфер и вид

Файл, картинка, пакет из сети — это байты, а не числа и строки. Для них в языке два слоя, и учебник MDN JavaScript typed arrays называет их буфером и видом. Буфер — ArrayBuffer: кусок памяти заданной длины, у которого нет доступа к байтам. Вид — типизированный массив: он смотрит на байты буфера и читает их как числа нужного размера. На один буфер можно смотреть разными видами сразу.

В спецификации буферы — глава 25 (Structured Data), виды — глава 23 (Indexed Collections), рядом с обычными массивами. Память буфера — Data Block из раздела 6.2.9, который день 4 обещал этому дню.

2. ArrayBuffer: байты без доступа

Конструктор ArrayBuffer(length, options) (25.1.4.1) — четыре шага. Шаг 1: без new — TypeError. Шаг 2: длина проходит ToIndex дня 5 — целое от 0 до 253 − 1, иначе RangeError. Шаг 3 читает maxByteLength из options (раздел 13). Шаг 4 — AllocateArrayBuffer (25.1.3.1): новый Data Block, все байты — нули.

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const buf = new ArrayBuffer(8);
console.log(buf.byteLength, buf[0], Object.keys(buf).length, buf.resizable, buf.maxByteLength, buf.detached);
console.log(run(() => ArrayBuffer(8)), "|", run(() => new ArrayBuffer(-1)), "|", run(() => new ArrayBuffer(2 ** 53)));
console.log(new ArrayBuffer("3").byteLength, new ArrayBuffer(2.9).byteLength, new ArrayBuffer().byteLength, Object.prototype.toString.call(buf));
8 undefined 0 false 8 false
TypeError: Constructor ArrayBuffer requires 'new' | RangeError: Invalid array buffer length | RangeError: Invalid array buffer length
3 2 0 [object ArrayBuffer]

buf[0] — undefined: буфер — обычный объект без свойств-индексов, байты лежат во внутреннем слоте [[ArrayBufferData]]. ToIndex срезает дробь и превращает строку в число, поэтому "3" и 2.9 проходят. У фиксированного буфера maxByteLength равна byteLength.

3. Один буфер — три вида

Вид создаётся над буфером: new Uint16Array(buffer) — на весь буфер, new Uint32Array(buffer, 4, 1) — со смещения 4 байта, один элемент. Схема раздела 1 — в коде:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const buf = new ArrayBuffer(8);
const bytes = new Uint8Array(buf);
const words = new Uint16Array(buf);
const tail = new Uint32Array(buf, 4, 1);
bytes[0] = 1;
bytes[1] = 2;
bytes[4] = 255;
console.log(words[0], words.length, tail[0], tail.byteOffset, tail.length);
words[3] = 0xABCD;
console.log(bytes.join(" "), tail[0]);
console.log(run(() => new Uint16Array(buf, 1)), "|", run(() => new Uint32Array(buf, 4, 2)), "|", run(() => new Uint16Array(new ArrayBuffer(3))));
513 4 255 4 1
1 2 0 0 255 0 205 171 2882339071
RangeError: start offset of Uint16Array should be a multiple of 2 | RangeError: Invalid typed array length: 2 | RangeError: byte length of Uint16Array should be a multiple of 2

words[0] собран из байтов 1 и 2 как 1 + 2 × 256 = 513: младший байт лежит первым. Это порядок байтов машины, и стандарт его не задаёт — день 21 научится выбирать его явно. Запись 0xABCD через words[3] легла в байты 6 и 7 — 205 и 171, — и tail её увидел. Три RangeError — шаги 3, 9.b.ii и 9.a.i раздела InitializeTypedArrayFromArrayBuffer (23.2.5.1.3): смещение кратно размеру элемента, вид не длиннее буфера, буфер без длины делится на размер элемента.

Целые виды берут остаток от деления на 28, 216 или 232 (300 → 44, −5 → 251 в байте без знака), дробь отбрасывают. Знаковые читают старший бит как минус. 5. ToUint8 и ToUint8Clamp по шагам

ToUint8 (7.1.11): шаг 2 — бесконечность и NaN дают 0, шаг 3 отбрасывает дробь, шаг 4 берёт остаток от деления на 28. ToUint8Clamp (7.1.12) — иначе: шаг 2 NaN → 0, шаг 4 зажимает значение между 0 и 255, а шаги 5–9 округляют, причём ровно половину — к чётному:

console.log(Uint8ClampedArray.of(0.5, 1.5, 2.5, 3.5, 254.5, 255.5, 300, -5, NaN, Infinity).join(" "));
console.log(Uint8Array.of(0.5, 1.5, 2.5, 255.9, 256, -1, NaN, Infinity).join(" "));
0 2 2 4 254 255 255 0 0 255
0 1 2 255 0 255 0 0

0.5 → 0, 1.5 → 2, 2.5 → 2, 3.5 → 4: Math.round дал бы 1, 2, 3, 4. У Uint8Array 255.9 → 255, 256 → 0, а бесконечность — 0, у Uint8ClampedArray — 255. Насыщение придумано для цвета: яркость 300 должна стать 255, а не 44. Пиксели картинок в браузере приходят именно в этом виде — курс 4.

6. Индексы по 10.4.5

День 15 разобрал массив — экзотический объект, у которого особый [[DefineOwnProperty]]. Типизированный массив (10.4.5) экзотичнее: у него восемь своих внутренних методов, и шесть из них, получив ключ, начинают одинаково. Если ключ — строка, CanonicalNumericIndexString (7.1.21) спрашивает: число ли это в своей обычной записи? "-0" — да (−0), "1.5" — да, "01" — нет. Числовой ключ никогда не становится обычным свойством: IsValidIntegerIndex (10.4.5.16) пропускает только целое, не −0 и меньше длины, а остальное просто не существует.

"use strict";
const ta = new Uint8Array(2);
ta[5] = 7; ta["-0"] = 7; ta["1.5"] = 7; ta["01"] = 7; ta.foo = 7;
console.log(ta[5], ta["-0"], ta["1.5"], ta["01"], Object.keys(ta).join(), 5 in ta, "-0" in ta, "01" in ta);
let calls = 0;
ta[10] = { valueOf() { calls++; return 1; } };
console.log(calls, ta.length, Object.getOwnPropertyDescriptor(ta, 0));
undefined undefined undefined 7 0,1,01,foo false false true
1 2 {value: 0, writable: true, enumerable: true, configurable: true}

Четыре записи молча пропали даже в строгом режиме, а "01" и foo стали обычными свойствами. Интереснее calls: запись за концом ничего не записала, но valueOf вызвала. [[Set]] (10.4.5.6, шаг 1.b.i.1) отдаёт значение TypedArraySetElement (10.4.5.18), а тот сначала превращает его в число (шаги 1–2) и только потом проверяет индекс (шаг 3).

7. Что вид не разрешает

Свойство-индекс всегда записываемое, перечисляемое и настраиваемое — дескриптор из шага 1.b.iii [[GetOwnProperty]]. Но удалить его или закрепить нельзя:

"use strict";
const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const ta = new Uint8Array(2);
console.log(run(() => { delete ta[0]; }), "|", run(() => { delete ta[5]; }), "|", run(() => Object.defineProperty(ta, 0, { value: 9, configurable: false })));
console.log(run(() => Object.freeze(ta)), "|", run(() => Object.freeze(new Uint8Array(0))), "|", run(() => Object.defineProperty(ta, 1, { value: 300 })), ta[1]);
TypeError: Cannot delete property '0' of [object Uint8Array] | ok | TypeError: Cannot redefine property: 0
TypeError: Cannot freeze array buffer views with elements | ok | ok 44

[[Delete]] (10.4.5.7): существующий индекс — false (шаг 1.b.ii), и строгий режим бросает; несуществующий — true. [[DefineOwnProperty]] (10.4.5.4) отвечает false на configurable: false (шаг 1.b.ii) и на writable: false (шаг 1.b.v) — поэтому freeze падает на первом же индексе, а пустой вид замораживается. Значение defineProperty идёт через тот же TypedArraySetElement: 300 → 44.

8. %TypedArray% — общий родитель

Двенадцать конструкторов наследуют одной функции — %TypedArray% (23.2.1). Глобального имени у неё нет, а вызов бросает всегда — это единственный шаг её алгоритма. Методы живут на её прототипе (23.2.3), а у прототипа каждого вида — только constructor и BYTES_PER_ELEMENT (23.2.7):

Девяти методов массива у вида нет — все они меняют длину или склеивают массивы, а длина вида задана буфером. Взамен — четыре геттера и два метода. toString — та же функция, что у массива (23.2.3.34): она зовёт join.

9. Конструктор: пять форм

TypedArray(...args) (23.2.5.1) смотрит на первый аргумент: нет аргументов — длина 0 (шаг 5); другой вид — копия с преобразованием (7.b); буфер — вид над ним (7.c); итерируемое — список (7.d.iii), иначе «похожее на массив» (7.d.iv); число — длина через ToIndex (шаг 9). Плюс статические from(source, mapper) и of(...items) (23.2.2):

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
console.log(new Int16Array().length, new Int16Array(3).join(), new Int16Array([1, 2, 70000]).join(), new Int16Array(new Uint8Array([200, 255])).join(), new Int16Array(new Set([5, 6])).join(), new Int16Array({ length: 2, 0: 9 }).join());
console.log(Uint8Array.from("123").join(), Uint8Array.from([1, 2, 3], (x) => x * 100).join(), Int8Array.of(127, 128, -129).join(), run(() => new Uint8Array(-1)), "|", run(() => Uint8Array(2)));
0 0,0,0 1,2,4464 200,255 5,6 9,0
1,2,3 100,200,44 127,-128,127 RangeError: Invalid typed array length: -1 | TypeError: Constructor Uint8Array requires 'new'

70000 в Int16Array — 4464: остаток от 65536. Копия Uint8Array в Int16Array переводит значения, а не байты: 200 и 255 так и остались. from со строкой перебирает символы, и каждый проходит ToNumber. mapper работает до записи, поэтому 300 стало 44.

11. set: копия с преобразованием

set(source, offset) (23.2.3.26) кладёт массив или другой вид в этот вид с позиции offset:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const t = new Uint8Array(6);
t.set([1, 2, 300], 1);
console.log(t.join(), "|", run(() => t.set([1, 2], 5)));
const same = Uint8Array.of(1, 2, 3, 4, 5, 6);
same.set(same.subarray(0, 4), 2);
console.log(same.join());
const w = new Uint16Array(2);
w.set(Uint8Array.of(255, 1));
console.log(w.join(), new Uint8Array(w.buffer).join(), run(() => new Int8Array(1).set(BigInt64Array.of(1n))));
0,1,2,44,0,0 | RangeError: offset is out of bounds
1,2,1,2,3,4
255,1 255,0,1,0 TypeError: Cannot mix BigInt and other types, use explicit conversions

Не влезло — RangeError раньше любой записи. Источник и цель на одном буфере перекрываются, и SetTypedArrayFromTypedArray (23.2.3.26.2) на шаге 19 сначала копирует источник, поэтому вышло 1,2,1,2,3,4, а не 1,2,1,2,1,2. Разные виды копируются значениями (шаг 24), одинаковые — байтами (шаг 23). Числа и BigInt смешать нельзя (шаг 17).

12. subarray против slice

const src = Uint8Array.of(1, 2, 3, 4, 5);
const sub = src.subarray(1, 3);
const sl = src.slice(1, 3);
sub[0] = 20;
sl[1] = 30;
console.log(src.join(), sub.join(), sl.join(), sub.buffer === src.buffer, sl.buffer === src.buffer, sub.byteOffset);
const ab = src.buffer.slice(1, 3);
console.log(ab.byteLength, new Uint8Array(ab).join(), ArrayBuffer.isView(sub), ArrayBuffer.isView(ab), Object.hasOwn(sub, "length"));
1,20,3,4,5 20,3 2,30 true false 1
2 20,3 true false false

subarray (23.2.3.30) ничего не копирует: шаги 14–17 строят новый вид на тот же буфер со смещением, и запись через sub видна в src. slice выделяет новый буфер и копирует, так же как ArrayBuffer.prototype.slice (25.1.6.7) копирует байты. buffer, byteOffset, byteLength и length — не свойства вида, а геттеры прототипа: они читают внутренние слоты. ArrayBuffer.isView (25.1.5.1) спрашивает ровно об одном — есть ли у объекта слот [[ViewedArrayBuffer]].

Species работает и у буфера, и у видов: slice наследника ArrayBuffer отдаёт наследника, map, filter, slice и subarray наследника Uint8Array — тоже. А toSorted, toReversed и with берут конструктор прямо из таблицы 70 (TypedArrayCreateSameType, 23.2.4.2) и отдают Uint8Array.

13. Изменяемый буфер

Раздел 25.1.2 делит буферы на фиксированные и изменяемые; изменяемый получается, если передать maxByteLength. resize (25.1.6.6) создаёт новый блок и копирует, сколько влезет (шаги 10–15); больше максимума — RangeError (шаг 6). Вид без длины на изменяемом буфере следит за длиной (23.2.5.1.3, шаг 8), вид с длиной — нет:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const rab = new ArrayBuffer(4, { maxByteLength: 8 });
const track = new Uint8Array(rab);
const fixed = new Uint8Array(rab, 0, 4);
const tail = new Uint8Array(rab, 2, 2);
rab.resize(8);
track[7] = 9;
tail[0] = 5;
console.log(rab.byteLength, track.length, fixed.length, track.join());
rab.resize(3);
console.log(track.length, fixed.length, fixed[0], tail.length, run(() => fixed.fill(1)));
rab.resize(4);
console.log(fixed.length, tail.join(), track.join());
console.log(run(() => rab.resize(9)), "|", run(() => new ArrayBuffer(4).resize(2)), "|", run(() => Object.preventExtensions(track)));
8 8 4 0,0,5,0,0,0,0,9
3 0 undefined 0 TypeError: Cannot perform %TypedArray%.prototype.fill on a detached or out-of-bounds ArrayBuffer
4 5,0 0,0,5,0
RangeError: ArrayBuffer.prototype.resize: Invalid length parameter | TypeError: Method ArrayBuffer.prototype.resize called on incompatible receiver #<ArrayBuffer> | TypeError: Cannot prevent extensions

IsTypedArrayOutOfBounds (10.4.5.14, шаг 9): вид кончается дальше буфера — он за границей. Такой вид не исчез: длина 0, чтение — undefined, методы бросают (ValidateTypedArray, шаг 4), а после роста буфера всё возвращается. resize у фиксированного буфера — TypeError: шаг 2 ищет слот [[ArrayBufferMaxByteLength]]. Вид, который может вырасти, нельзя сделать нерасширяемым: [[PreventExtensions]] (10.4.5.1, шаг 2). Раздел 25.1.8 советует брать maxByteLength поменьше и не больше 1 ГиБ: удачный конструктор не обещает, что удастся каждый resize.

14. transfer и отсоединённый буфер

transfer(newLength) переносит байты в новый буфер, а старый отсоединяет. ArrayBufferCopyAndDetach (25.1.3.3): шаг 5 — уже отсоединённый бросает; шаги 6–7 — transfer сохраняет изменяемость, transferToFixedLength — нет; шаг 13 копирует; шаг 15 — DetachArrayBuffer:

const run = (f) => { try { f(); return "ok"; } catch (e) { return `${e.name}: ${e.message}`; } };
const buf = new ArrayBuffer(4);
const view = new Uint8Array(buf);
view[0] = 42;
const moved = buf.transfer();
console.log(buf.detached, buf.byteLength, view.length, view[0], moved.byteLength, new Uint8Array(moved)[0]);
view[0] = 1;
console.log(view[0], run(() => view.fill(1)), "|", run(() => new Uint8Array(buf)), "|", run(() => buf.transfer()));
const bigger = moved.transfer(8);
console.log(bigger.byteLength, new Uint8Array(bigger).join(), moved.detached);
console.log(new ArrayBuffer(2, { maxByteLength: 4 }).transfer().resizable, new ArrayBuffer(2, { maxByteLength: 4 }).transferToFixedLength().resizable);

undefined TypeError: Cannot perform %TypedArray%.prototype.fill on a detached or out-of-bounds ArrayBuffer | TypeError: Cannot perform Construct on a detached ArrayBuffer | TypeError: Cannot perform ArrayBuffer.prototype.transfer on a detached ArrayBuffer

Отсоединённый буфер — пустая оболочка: длина 0, а у вида IsValidIntegerIndex отвечает «нет» уже на шаге 1, так что чтение даёт undefined, запись пропадает. Зачем отдавать буфер? Чтобы у байтов был один владелец: передал — больше не трогаешь. Браузер так передаёт буферы в потоки-исполнители (курс 4), а память перенос может вообще не копировать — примечание шага 14 разрешает «zero-copy move».

15. «Карточки 2.0»: счётчики в байтах

Сколько раз ученик знал каждое слово — по байту на карточку. Какой вид взять?

const words = ["kitap", "galam", "suw"];
const known = new Uint8Array(words.length);
const streak = new Uint8ClampedArray(words.length);
for (let i = 0; i < 300; i++) { known[0]++; streak[0]++; }
console.log(known[0], streak[0]);
const saved = JSON.stringify(Array.from(known));
const back = Uint8Array.from(JSON.parse(saved));
console.log(saved, back instanceof Uint8Array, back.join(), JSON.stringify(known));
44 255
[44,0,0] true 44,0,0 {"0":44,"1":0,"2":0}

После 300 ответов Uint8Array перешёл через 255 и показывает 44 — ученик «разучился». Для счётчика нужен Uint8ClampedArray: он остановится на 255. Сохранять — через Array.from: сам вид JSON.stringify превращает в объект с ключами.

  1. Что окажется в Uint8Array и Uint8ClampedArray после записи 300, −5 и 2.5?
    Ответ Uint8Array — 44, 251, 2: ToUint8 отбрасывает дробь и берёт остаток от 256. Uint8ClampedArray — 255, 0, 2: ToUint8Clamp зажимает и округляет половину к чётному.
  2. Почему ta[10] = obj у вида длины 2 вызывает obj.valueOf, хотя ничего не пишет?
    Ответ TypedArraySetElement (10.4.5.18) сначала превращает значение в число (шаги 1–2) и только потом проверяет индекс (шаг 3).
  3. Чем subarray отличается от slice?
    Ответ subarray — новый вид на тот же буфер, запись видна в обоих; slice — копия в новом буфере.
  4. Что видит вид new Uint8Array(rab, 0, 4), когда изменяемый буфер сжали до 3 байтов?
    Ответ Он за границей (10.4.5.14): длина 0, чтение — undefined, методы бросают TypeError. После роста буфера до 4 байтов вид снова работает.
  5. Что остаётся от буфера после transfer()?
    Ответ Отсоединённая оболочка: detached — true, byteLength — 0, виды на нём пусты, а slice, transfer и конструктор вида бросают.
