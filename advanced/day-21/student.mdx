# День 21. DataView, порядок байтов, Float16 и base64

<Subtitle>Выжимка лекции: DataView и порядок байтов, GetViewValue и SetViewValue по шагам, Float32 и Float16, base64 и hex.</Subtitle>

## Главное

<Definition>
`DataView` (25.3) — объект над буфером, который читает и пишет числа любого типа с любого байта. Порядок байтов
задаёт последний аргумент метода, без него — big-endian, старший байт первым. Вид дня 20 читает весь буфер одним
типом и всегда порядком машины. `Float16Array` — вид таблицы 70 на два байта. base64 и hex — методы одного
`Uint8Array` (23.3).
</Definition>

## DataView и порядок байтов

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return e.name; } };
const buf = new ArrayBuffer(4);
const dv = new DataView(buf);
dv.setUint16(0, 0x0102);
dv.setUint16(2, 0x0102, true);
console.log(new Uint8Array(buf).join(" "), dv.getUint16(0), dv.getUint16(2), dv.getUint16(2, true));   // 1 2 2 1 258 513 258 — без аргумента старший байт первым; true — младший
console.log(new Uint16Array(buf).join(" "), dv.getUint16(0, "false"), dv.getUint16(1), dv[0], ArrayBuffer.isView(dv));   // 513 258 513 514 undefined true — вид читает порядком машины; строка "false" истинна; с нечётного байта можно; индексов нет
console.log(run(() => dv.getUint32(1)), run(() => new DataView(new Uint8Array(4))), run(() => new DataView(new ArrayBuffer(8)).setBigInt64(0, 1)));   // RangeError TypeError TypeError — не помещается до конца; нужен буфер, а не вид; BigInt — только BigInt
```

| Что проверяется | GetViewValue (25.3.1.5) | SetViewValue (25.3.1.6) |
| --- | --- | --- |
| смещение через ToIndex | шаг 3 | шаг 3 |
| значение — в число (ToNumber или ToBigInt) | — | шаги 4–5 |
| порядок через ToBoolean | шаг 4 | шаг 6 |
| буфер отсоединён или вид за его границей — `TypeError` | шаг 8 | шаг 10 |
| число не помещается до конца вида — `RangeError` | шаг 11 | шаг 13 |
| чтение или запись с этим порядком | шаг 13 | шаг 15 |

<Remember>
Без последнего аргумента `DataView` пишет и читает big-endian — MDN
[DataView](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/DataView):
«DataView defaults to big-endian read and write, but most platforms use little-endian». Порядок проходит ToBoolean:
`"false"` и `[]` дают little-endian, поэтому порядок из настроек превращать в булево самому. Вид берёт
порядок из поля \[\[LittleEndian\]\] агента (GetValueFromBuffer, шаг 8). Конструктор принимает только буфер; без длины
`DataView` берёт остаток буфера, а у изменяемого — следит за ним. За границей буфера `DataView` бросает даже на
`byteLength`, а вид притворяется пустым. Методов 22: `get…` и `set…` для каждого типа таблицы 70, кроме
`Uint8Clamped`.
</Remember>

## Числа с плавающей точкой

```js
const dv = new DataView(new ArrayBuffer(4));
dv.setFloat32(0, 0.1);
console.log(dv.getFloat32(0), Math.fround(0.1), new Uint8Array(dv.buffer).join(" "));   // 0.10000000149011612 0.10000000149011612 61 204 204 205 — 0.1 не помещается в 23 бита дроби
console.log(Float16Array.of(0.1, 2049, 2051, 65519, 65520, 1e-8).join(" "));   // 0.0999755859375 2048 2052 65504 Infinity 0 — после 2048 шаг 2, половина к чётному; предел 65504
console.log(Math.f16round(1.1), Float16Array.BYTES_PER_ELEMENT, Object.is(Float16Array.of(-0)[0], -0));   // 1.099609375 2 true — то же округление без вида; −0 сохраняется
```

| Формат | Байт | Бит дроби | Значащих цифр | Наибольшее | Округлить |
| --- | --- | --- | --- | --- | --- |
| float16 | 2 | 10 | около 3 | 65504 | `Math.f16round` |
| float32 | 4 | 23 | около 7 | ≈ 3.4 × 10<sup>38</sup> | `Math.fround` |
| float64 (Number) | 8 | 52 | около 16 | ≈ 1.8 × 10<sup>308</sup> | само число |

<Remember>
Запись дроби округляет по правилу «половина — к чётному» (NumericToRawBytes, 25.1.3.17; `Math.f16round` — 21.3.2.18,
шаги 4–5). Число больше предела становится бесконечностью, слишком маленькое — нулём. Байты NaN выбирает
реализация: Chrome пишет float32 NaN как 127 192 0 0. Нули −0 и +0 различаются старшим битом. Правильные байты, прочитанные не тем порядком, дают мусор без всякой ошибки.
</Remember>

## base64 и hex

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return e.name; } };
const u = Uint8Array.of(0xFB, 0xFF, 0x01);
console.log(u.toBase64(), u.toBase64({ alphabet: "base64url", omitPadding: true }), u.toHex(), Uint8Array.fromHex("FBff01").join());   // +/8B -_8B fbff01 251,255,1 — три байта — четыре знака; hex пишется строчными, читается любой
console.log(Uint8Array.fromBase64("AQ").join(), run(() => Uint8Array.fromBase64("AQ", { lastChunkHandling: "strict" })), run(() => Uint8Array.fromBase64("AR==", { lastChunkHandling: "strict" })), run(() => Uint8Array.fromHex("abc")), run(() => Uint8Array.fromBase64(1)));   // 1 SyntaxError SyntaxError SyntaxError TypeError — «loose» прощает; «strict» — нет; hex нечётной длины; не строка
const into = new Uint8Array(4);
console.log(JSON.stringify(into.setFromBase64("AQIDBAUG")), into.join(), typeof Uint8ClampedArray.prototype.toBase64);   // {"read":4,"written":3} 1,2,3,0 undefined — пишется только целый кусок; методы есть только у Uint8Array
const into2 = new Uint8Array(4);
console.log(run(() => into2.setFromBase64("AQID*")), into2.join());   // SyntaxError 1,2,3,0 — разобранное записано до ошибки
```

| Параметр | Где | Значения | По умолчанию |
| --- | --- | --- | --- |
| `alphabet` | все методы base64 | `"base64"`, `"base64url"` («-» и «\_» вместо «+» и «/») | `"base64"` |
| `omitPadding` | `toBase64` | `true` — без «=» в конце | `false` |
| `lastChunkHandling` | `fromBase64`, `setFromBase64` | `"loose"`, `"strict"`, `"stop-before-partial"` | `"loose"` |

<Remember>
Ошибки разбора — `SyntaxError`: знак не из алфавита, неполный кусок или лишние биты в «strict», hex нечётной длины
или со знаком не из «0–9a–fA–F». Не строка или не `Uint8Array` — `TypeError`. Пробелы и переводы
строк base64 пропускает. «AR==» и «AQ==» в «loose» дают один и тот же байт — сравнивать байты, а не строки.
`setFromBase64` и `setFromHex` пишут с начала массива и отвечают `{ read, written }`; при ошибке
успетое уже записано (23.3.2.1, шаги 19–20). «Карточки 2.0»: заголовок — через `DataView`, ссылка —
base64url без «=».
</Remember>
