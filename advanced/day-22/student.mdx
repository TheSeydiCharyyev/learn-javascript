# День 22. SharedArrayBuffer и Atomics

<Subtitle>Выжимка лекции: изоляция страницы, общий буфер и второй поток, гонка и неделимые операции, wait, waitAsync и notify.</Subtitle>

## Главное

<Definition>
`SharedArrayBuffer` (25.2) — буфер, блок байтов которого видят сразу несколько агентов: `postMessage` отдаёт потоку
новый объект над тем же блоком. Его конструктор виден только на изолированной странице. `Atomics` (25.4) —
неделимые операции над ячейками целых видов и способ подождать другой поток: `wait`, `waitAsync`, `notify`.
`Worker` — Web API курса 4, здесь он только инструмент.
</Definition>

## Общий буфер

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return e.name; } };
console.log(crossOriginIsolated, typeof SharedArrayBuffer);   // true function — страница изолирована заголовками
const g = new SharedArrayBuffer(4, { maxByteLength: 8 });
const all = new Uint8Array(g);
g.grow(6);
console.log(g.byteLength, all.length, g.growable, g instanceof ArrayBuffer);   // 6 6 true false — вырос, вид без длины следит; не наследник ArrayBuffer
console.log(run(() => g.grow(5)), run(() => new SharedArrayBuffer(4).grow(8)), run(() => SharedArrayBuffer(4)), "transfer" in g);   // RangeError TypeError TypeError false — только больше; у неизменяемого нет слота максимума; без new нельзя; переноса нет
```

| | `ArrayBuffer` | `SharedArrayBuffer` |
| --- | --- | --- |
| длина | `resize` — в обе стороны | `grow` — только больше |
| перенос, отсоединение | `transfer`, `detached` | нет никогда (25.2.6) |
| `postMessage` | копия или перенос | новый объект, тот же блок |
| `slice` | новый буфер | новый общий буфер со своим блоком |

<Remember>
Общая память требует изоляции — MDN
[SharedArrayBuffer](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/SharedArrayBuffer):
«To use shared memory your document must be in a secure context and cross-origin isolated». Заголовки
`Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Embedder-Policy: require-corp` — в `.vscode/settings.json`
папки проекта, в `liveServer.settings.headers`; после правки Live Server перезапустить. Без них
`SharedArrayBuffer` не определён, а `Atomics` есть всегда. У растущего буфера стандарт выделяет блок сразу под
максимум (25.2.2.1, шаги 6–7), поэтому `maxByteLength` берут поменьше.
</Remember>

## Неделимые операции

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return e.name; } };
const u8 = new Uint8Array(new SharedArrayBuffer(2));
console.log(Atomics.add(u8, 0, 300), u8[0], Atomics.sub(u8, 1, 1), u8[1]);   // 0 44 0 255 — вернул старое; байт обрезал 300 до 44; 0 − 1 даёт 255
const i32 = new Int32Array(new SharedArrayBuffer(8));
console.log(Atomics.store(i32, 0, 2.7), Atomics.compareExchange(i32, 0, 2, 9), Atomics.compareExchange(i32, 0, 2, 5), Atomics.load(i32, 0));   // 2 2 9 9 — store вернул 2: это 2.7 после ToIntegerOrInfinity; первая замена удалась, вторая нет
console.log(run(() => Atomics.add(new Float32Array(new SharedArrayBuffer(4)), 0, 1)), run(() => Atomics.load(i32, 2)), Atomics.isLockFree(4));   // TypeError RangeError true — только целые виды; индекс внутри вида; для 4 байт всегда true
```

| Метод | Что кладёт в ячейку | Что возвращает |
| --- | --- | --- |
| `add`, `sub`, `and`, `or`, `xor` | результат действия | старое значение |
| `exchange` | новое значение | старое значение |
| `compareExchange` | новое, если старое равно ожидаемому | старое значение |
| `load` | ничего | значение (`seq-cst`) |
| `store` | новое значение | значение после ToIntegerOrInfinity |

<Remember>
`counts[0]++` из двух потоков теряет прибавления: это три действия — прочитать, прибавить, записать, — и между ними
другой поток пишет своё. `Atomics.add` делает всё одним шагом (AtomicReadModifyWrite, 25.4.3.17, шаг 7). Годятся
только целые виды без насыщения (25.4.3.1, шаг 4.b): не `Float32Array`, не `Uint8ClampedArray`. Обычный доступ
к ячейке — порядок `unordered`, атомарный — `seq-cst`, подробно — день 23. Замок — `compareExchange(s, i, 0, 1)`
в петле, пока не вернёт 0, и `Atomics.store(s, i, 0)` на выходе. `Atomics.pause` есть в Chrome, а в
ECMA-262 2026 его нет. Насыщающий счётчик — петля «прочитать, проверить, попробовать заменить».
</Remember>

## Ожидание

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return e.name; } };
const a = new Int32Array(new SharedArrayBuffer(4));
console.log(run(() => Atomics.wait(a, 0, 0)), Atomics.waitAsync(a, 0, 1).value, Atomics.waitAsync(a, 0, 0, 0).value);   // TypeError not-equal timed-out — странице спать нельзя; значение не то; нулевой срок
const r = Atomics.waitAsync(a, 0, 0);
console.log(r.async, Atomics.notify(a, 0), Atomics.notify(a, 0), await r.value);   // true 1 0 ok — разбудили одного; очередь пуста
```

| | `wait` | `waitAsync` |
| --- | --- | --- |
| где | только во втором потоке | и на странице |
| значение не то | `"not-equal"` | `{ async: false, value: "not-equal" }` |
| срок 0 или меньше | `"timed-out"` | сразу `{ async: false, value: "timed-out" }` |
| разбудил `notify` | `"ok"` | обещание выполнится с `"ok"` |
| срок вышел | `"timed-out"` | обещание выполнится с `"timed-out"` |

<Remember>
Обе — одна операция DoWait (25.4.3.14): шаги 1, 3, 4 — вид `Int32Array` или `BigInt64Array`, общий буфер, индекс;
шаги 8–11 — срок (`NaN` — бесконечный, отрицательный — ноль); шаг 12 — `wait` на странице бросает, даже когда
значение не совпало. MDN [Atomics.wait()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Atomics/wait):
`"ok"` приходит «regardless of whether the expected value has changed» — значение проверяют сами, в петле.
`notify` будит первых в очереди и возвращает их число. Chrome против текста: обещание `waitAsync`, разбуженное своим
же потоком, по 25.4.3.12 (шаг 3.b) выполняется сразу, а Chrome выполняет его отдельной задачей — после уже
поставленного таймера. Ждите само обещание, а не такты.
</Remember>

1. Предскажите вывод `Atomics.add(u16, 0, 70000)`, `u16[0]`, `Atomics.exchange(u16, 1, -1)`, `u16[1]`,
   `Atomics.store(u16, 1, -1)` и снова `u16[1]` для `const u16 = new Uint16Array(new SharedArrayBuffer(4))`.
   Почему `store` вернул не то, что лежит в ячейке? Назовите шаг 25.4.11.
2. Предскажите `Atomics.isLockFree(n)` в Chrome для n от 1 до 8. Какие из восьми ответов гарантирует стандарт
   (25.4.8), а какие берутся из записи агента?
3. В `a = new Int32Array(new SharedArrayBuffer(4))` лежит 0. Предскажите `Atomics.waitAsync(a, 0, "0", NaN).async`,
   `Atomics.waitAsync(a, 0, 0, -1).value`, `Atomics.waitAsync(a, 0, 2 ** 32).async` и
   `Atomics.waitAsync(a, 0, 2 ** 32 + 1).value`, а также что бросит `Atomics.waitAsync(a, 0, 0n)` и
   `Atomics.waitAsync(new BigInt64Array(new SharedArrayBuffer(8)), 0, 0)`. Какие шаги DoWait это решают?
4. Прочитайте на MDN [Atomics.notify()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Atomics/notify):
   метод «will return 0 on non-shared ArrayBuffer objects», а `count` по умолчанию — `Infinity`. Три вызова
   `waitAsync` ждут на `a[0]`. Предскажите `Atomics.notify(new Int32Array(4), 0)`, что бросит
   `Atomics.notify(new Int16Array(new SharedArrayBuffer(4)), 0)`, затем `Atomics.notify(a, 0, 2.9)` и
   `Atomics.notify(a, 0, Infinity)`. Какие шаги 25.4.15 за это отвечают?
</Homework>
