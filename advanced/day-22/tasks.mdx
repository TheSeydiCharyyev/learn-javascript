## Разминка

<Task title="1. Буфер и его копии" level="easy" time="7">
<Goal>видеть, какие объекты делят блок байтов, а какие — нет.</Goal>

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return e.name; } };
const g = new SharedArrayBuffer(2, { maxByteLength: 6 });
const a = new Uint8Array(g);
const b = new Uint8Array(g, 0, 2);
a[0] = 1;
const c = g.slice(0, 1);
g.grow(4);
console.log(g.byteLength, a.length, b.length, c.byteLength, new Uint8Array(c)[0], c.growable);
console.log(run(() => g.grow(3)), run(() => g.grow(7)), run(() => new SharedArrayBuffer(2, { maxByteLength: 1 })), run(() => c.grow(2)), Object.prototype.toString.call(c));
```

<Criteria>
- предсказаны две строки;
- объяснено, почему `a` выросла, а `b` — нет, и почему копия `c` хранит 1, но не растёт;
- для четырёх ошибок назван шаг `grow` (25.2.5.3) или AllocateSharedArrayBuffer (25.2.2.1).
</Criteria>
</Task>

<Task title="2. Что вернёт Atomics" level="easy" time="7">
<Goal>предсказывать старое значение и обрезку числа.</Goal>

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return e.name; } };
const i8 = new Int8Array(new SharedArrayBuffer(4));
console.log(Atomics.add(i8, 0, 127), Atomics.add(i8, 0, 1), i8[0], Atomics.store(i8, 1, 200), i8[1]);
console.log(Atomics.or(i8, 3, 5), Atomics.and(i8, 3, 6), Atomics.xor(i8, 3, 3), i8[3], run(() => Atomics.add(i8, -1, 1)), run(() => Atomics.load(new Uint8ClampedArray(new SharedArrayBuffer(1)), 0)));
```

<Criteria>

- объяснено, почему второй `add` вернул 127, а в ячейке −128, и почему `store` вернул 200, а лежит −56

</Criteria>
</Task>

const run = (f) => { try { f(); return "ok"; } catch (e) { return e.name; } };

## Основные задания

<Task title="4. Насыщающий счётчик и максимум" level="medium" time="12">
<Goal>собирать свои неделимые операции из compareExchange.</Goal>

Напишите `bumpTo(ta, i, limit)` — атомарно прибавить 1, но не выше `limit`, и вернуть новое значение — и
`atomicMax(ta, i, x)` — положить большее из старого и `x` и вернуть старое. Обе — петлёй `load` и
`compareExchange` (раздел 9 лекции), без `Atomics.add` и замка.

<Example>
```js
const c = new Uint8Array(new SharedArrayBuffer(2));
for (let k = 0; k < 300; k++) bumpTo(c, 0, 255);
c[0];                       // 255
bumpTo(c, 1, 2);            // 1
bumpTo(c, 1, 2);            // 2
const m = new Int32Array(new SharedArrayBuffer(4));
atomicMax(m, 0, 5);         // 0
atomicMax(m, 0, 9);         // 5
m[0];                       // 9
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- в двух потоках по 100 000 вызовов `bumpTo(s, 0, 150000)` дают ровно 150 000, а `atomicMax` со
  случайными числами из обоих потоков оставляет в ячейке наибольшее из всех;
- объяснено, как версия «`load`, сравнить, `store`» проскочит предел, а `compareExchange` — нет: по MDN
  [Atomics.compareExchange()](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Atomics/compareExchange)
  «if the value had been updated by another thread in the meantime, the write would fail»;
- объяснено, почему `bumpTo` над `Uint8ClampedArray` не сработает (25.4.3.1, шаг 4.b).
</Criteria>
</Task>

<Task title="5. Замок с проверкой" level="medium" time="12">
<Goal>делать замок, который ловит лишний unlock.</Goal>

Напишите `makeLock(s, i)` — замок над ячейкой `s[i]` (0 — свободно, 1 — занято): `tryLock()` захватывает
без ожидания и отвечает `true` или `false`, `lock()` ждёт в петле с `Atomics.pause()`, `unlock()`
освобождает, а у свободного замка бросает `Error("замок свободен")`.

<Example>
```js
const run = (f) => { try { return f(); } catch (e) { return e.name + ": " + e.message; } };
const s = new Int32Array(new SharedArrayBuffer(4));
const l = makeLock(s, 0);
l.tryLock();                // true
l.tryLock();                // false
l.unlock();                 // undefined
run(() => l.unlock());      // "Error: замок свободен"
l.lock();                   // undefined
s[0];                       // 1
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- в практике лекции (раздел 14) с `makeLock` вместо `lock` и `unlock` счётчик под замком — ровно 400 000,
  а `++` рядом, без замка, — меньше;
- объяснено, почему `unlock` — это `compareExchange(s, i, 1, 0)`, а не `Atomics.store(s, i, 0)`, и почему
  `lock()` на странице — плохая мысль.
</Criteria>
</Task>

<Task title="6. Ждать условия" level="medium" time="12">
<Goal>ждать значения в ячейке, не замораживая страницу.</Goal>

Напишите `async waitUntil(s, i, predicate, ms = Infinity)`: ждёт через `waitAsync`, пока `predicate`
от значения ячейки не станет истинным, и возвращает значение; не дождались за `ms` мс — `null` (раздел 13 лекции).

<Example>
```js
const s = new Int32Array(new SharedArrayBuffer(4));
setTimeout(() => { Atomics.store(s, 0, 1); Atomics.notify(s, 0); }, 20);
setTimeout(() => { Atomics.store(s, 0, 3); Atomics.notify(s, 0); }, 40);
await waitUntil(s, 0, (v) => v >= 3);             // 3
await waitUntil(s, 0, (v) => v > 100, 0);         // null
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- `notify` без `store` через 20 мс ожидание не заканчивает: значение приходит со `store` через 60 мс;
- объяснено, почему в `waitAsync` передаётся увиденное значение, а не нужное (DoWait, шаг 20), и какой шаг
  отвечает на срок 0 без обещания.
</Criteria>
</Task>

<Task title="7. «Карточки 2.0»: проверка колоды в фоне" level="medium" time="14">
<Goal>следить за работой второго потока со страницы.</Goal>

Поток `checker.js` после каждой карточки пишет в общий буфер число ошибок (ячейка 1) и проверенных (ячейка 0)
и будит ждущих:

```js file="checker.js"
onmessage = (e) => {
  const s = new Int32Array(e.data.shared);
  for (const card of e.data.deck) {
    for (let k = 0; k < 200000; k++);
    if (card.answer !== card.right) Atomics.add(s, 1, 1);
    Atomics.add(s, 0, 1);
    Atomics.notify(s, 0);
  }
};
```

Напишите для страницы `async watchProgress(s, total, onStep)`: зовёт `onStep(done, errors)`, когда `done`
вырос, и выполняется, когда `done` дошёл до `total`; ждёт через `waitAsync`.

<Example>
```js
const s = new Int32Array(new SharedArrayBuffer(8));
const seen = [];
for (let k = 1; k <= 3; k++) setTimeout(() => { if (k === 2) Atomics.add(s, 1, 1); Atomics.add(s, 0, 1); Atomics.notify(s, 0); }, k * 20);
await watchProgress(s, 3, (done, errors) => seen.push(done + "/" + errors));   // undefined
seen.join(" ");                                                                 // "1/0 2/1 3/1"
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- с потоком `checker.js` и колодой из 50 карточек `onStep` получает только растущие `done`, последний вызов —
  «50/8», и он ровно один;
- объяснено, почему `onStep` может пропустить значения `done` и почему поток прибавляет ошибку раньше, чем
  `done` (строго — день 23).
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Семафор" level="hard" time="10">
<Goal>пускать не больше n участников сразу.</Goal>

Семафор — замок на `n` мест. Напишите `makeSemaphore(s, i, n)`: в `s[i]` — сколько мест свободно;
`acquire()` — обещание, которое занимает место, когда оно есть (ждёт через `waitAsync`); `release()`
освобождает место и будит одного.

<Example>
```js
const s = new Int32Array(new SharedArrayBuffer(4));
const sem = makeSemaphore(s, 0, 2);
const order = [];
for (const name of ["А", "Б", "В", "Г"]) sem.acquire().then(() => order.push(name));
await new Promise((r) => setTimeout(r, 20));
order.join("");          // "АБ"
sem.release();
await new Promise((r) => setTimeout(r, 20));
order.join("");          // "АБВ"
sem.release();
sem.release();
await new Promise((r) => setTimeout(r, 20));
order.join("");          // "АБВГ"
s[0];                    // 1
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- объяснено, почему после двух `release` подряд в ячейке 1, а не 2;
- объяснено, почему `acquire` берёт место через `compareExchange`, а не `Atomics.sub`, и почему ждёт значения 0
  (DoWait, шаг 20).
</Criteria>
</Task>

<Task title="9. Незнакомый раздел: slice и Symbol.species" level="hard" time="10">
<Goal>читать алгоритм, который заранее не разбирали.</Goal>

Прочитайте SharedArrayBuffer.prototype.slice
([25.2.5.6](https://tc39.es/ecma262/2026/#sec-sharedarraybuffer.prototype.slice)), шаги 14–19, вместе с
get SharedArrayBuffer \[ %Symbol.species% \] (25.2.4.2) и предскажите:

```js
const run = (f) => { try { f(); return "ok"; } catch (e) { return e.name; } };
class Big extends SharedArrayBuffer {}
const big = new Big(4);
console.log(big.slice(1).constructor.name, Big[Symbol.species] === Big, SharedArrayBuffer[Symbol.species] === SharedArrayBuffer);
const fake = new SharedArrayBuffer(4);
fake.constructor = { [Symbol.species]: function () { return new ArrayBuffer(8); } };
console.log(run(() => fake.slice(0, 2)));
fake.constructor = { [Symbol.species]: function () { return fake; } };
console.log(run(() => fake.slice(0, 2)));
fake.constructor = { [Symbol.species]: function (n) { return new SharedArrayBuffer(n - 1); } };
console.log(run(() => fake.slice(0, 2)));
fake.constructor = { [Symbol.species]: function (n) { return new SharedArrayBuffer(n + 3); } };
console.log(fake.slice(0, 2).byteLength, run(() => SharedArrayBuffer.prototype.slice.call(new ArrayBuffer(4))));
```

<Criteria>
- предсказаны пять строк;
- для каждой ошибки назван шаг 25.2.5.6, который бросил;
- объяснено, почему `big.slice(1)` — `Big`, хотя своего `slice` у `Big` нет, и зачем шаг 18.
</Criteria>
</Task>
