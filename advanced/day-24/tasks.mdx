# День 24. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Открыты спецификация, [tc39.es/ecma262/2026/](https://tc39.es/ecma262/2026/), и консоль Chrome. Код пишем в папке дня 22 рядом с `gc.js` лекции (раздел 3): блок с `nextGC()` — это `main.js`, после запуска нажмите «Collect garbage». Каждое «почему» — с номером раздела и шага (9.9–9.13, глава 26).</Subtitle>

## Разминка

<Task title="1. Кто переживёт сборку" level="easy" time="7">
<Goal>видеть достижимость глазами сборщика.</Goal>

```js
import { nextGC } from "./gc.js";
const box = { items: [] };
const strong = new Map();
let a = { n: "a" }, b = { n: "b" }, c = { n: "c" }, d = { n: "d" }, e = { n: "e" };
box.items.push(b);
const seen = new WeakSet([c]);
const owners = new WeakMap([[d, { owner: d }]]);
strong.set("e", e);
const ra = new WeakRef(a), rb = new WeakRef(b), rc = new WeakRef(c), rd = new WeakRef(d), re = new WeakRef(e);
a = b = c = d = e = null;
await nextGC();
console.log([ra, rb, rc, rd, re].map((r) => r.deref()?.n ?? "-").join(" "));
```

<Criteria>
- предсказана строка;
- для каждой буквы назван путь от корня или правило, почему его нет: массив в живом объекте и `Map` держат,
  `WeakSet` и ключ `WeakMap` — нет (9.9.2, заметка 5);
- объяснено, почему значение `{ owner: d }` не удержало `d`, хотя ссылается на него.
</Criteria>
</Task>

<Task title="2. Ответы unregister" level="easy" time="6">
<Goal>проходить register и unregister по шагам.</Goal>

```js
const registry = new FinalizationRegistry(() => {});
const card = {}, other = {}, token = {};
registry.register(card, "a", token);
registry.register(other, "b", token);
registry.register(card, "c");
console.log(registry.unregister(token), registry.unregister(token), registry.unregister(card), registry.unregister({}));
```

<Criteria>
- предсказана строка;
- для каждого вызова назван шаг 26.2.3.3: сколько ячеек убрано и почему;
- объяснено, почему `unregister(card)` ответил `false`, хотя ячейка с целью `card` в реестре есть (26.2.3.2,
  шаг 5.b).
</Criteria>
</Task>

<Task title="3. Что можно держать слабо" level="easy" time="7">
<Goal>применять CanBeHeldWeakly ко всем слабым структурам.</Goal>

const run = (f) => { try { f(); return "ok"; } catch (e) { return e.name; } };
const sym = Symbol("s"), reg = Symbol.for("r");
console.log(run(() => new WeakRef(sym)), run(() => new WeakRef(reg)), run(() => new WeakSet().add(Symbol.asyncIterator)), run(() => new WeakMap().set(reg, 1)), run(() => new FinalizationRegistry(() => {}).register({}, 1, reg)), run(() => new WeakRef(new String("s"))), run(() => new WeakRef("s")));

<Criteria>

- для каждого значения назван шаг 9.13 (1, 2 или 3);
- объяснено, почему `new String("s")` держать слабо можно, а `"s"` — нет, и почему `Symbol.asyncIterator`

</Criteria>
</Task>

## Основные задания

<Task title="4. «Карточки 2.0»: кэш с запасом" level="medium" time="12">
<Goal>держать слабо, но не отдавать сборщику то, что нужно прямо сейчас.</Goal>

Напишите `makeCache(load, keep = 0)`: как кэш раздела 15 лекции, но последние `keep` разных значений, которые
отдал `get`, кэш держит сильно (массив `recent`), остальные — только через `WeakRef`. `size` — число записей в
`Map`.

<Example>
```js
import { nextGC } from "./gc.js";
let loads = 0;
const cache = makeCache((word) => { loads++; return { word }; }, 1);
cache.get("kitap").word;      // "kitap"
cache.get("galam").word;      // "galam"
loads;                        // 2
await nextGC();
cache.get("galam").word;      // "galam" — последнюю держим сильно
loads;                        // 2
cache.get("kitap").word;      // "kitap" — её убрали, загрузили снова
loads;                        // 3
cache.size;                   // 2
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- с `keep = 0` кэш ведёт себя как в разделе 15 лекции: после сборки — новая загрузка, запись одна;
- объяснено, зачем сильная часть: без неё карточку, которую показали секунду назад, первая же сборка уберёт;
- `has` нигде не проверяется (лекция, раздел 14).
</Criteria>
</Task>

<Task title="5. Сколько карточек освобождено" level="medium" time="10">
<Goal>считать уборку реестром и понимать, что это оценка снизу.</Goal>

Напишите `makeTracker()` с методами `track(obj, id)` — следить за объектом, `freed()` — номера убранных по
возрастанию, `alive()` — сколько ещё не убрано.

<Example>
```js
import { nextGC } from "./gc.js";
const tracker = makeTracker();
let cards = Array.from({ length: 5 }, (_, i) => ({ id: i }));
cards.forEach((card) => tracker.track(card, card.id));
const kept = cards[2];
cards = null;
await nextGC();
await new Promise((r) => setTimeout(r, 50));
tracker.freed();              // [0, 1, 3, 4]
tracker.alive();              // 1
kept.id;                      // 2
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- 1000 карточек, оставлены первые 10, слежка через `forEach` — `freed().length` равно 990; через `for…of` на
  верхнем уровне модуля — может быть 989: объяснено почему (лекция, раздел 16);
- объяснено, почему `alive()` — оценка «не меньше чем», а не точное число (9.9.1).
</Criteria>
</Task>

<Task title="6. Страховка для close()" level="medium" time="14">
<Goal>использовать реестр для некритичной уборки рядом с явной.</Goal>

Напишите `openConnection(name, log)`: объект с полем `name` и методом `close()`. `close()` пишет в `log` строку
«закрыто: name» — один раз, сколько бы его ни вызывали. Если соединение бросили, не закрыв, реестр пишет
«утечка: name». Закрытое соединение реестр не трогает: снимите регистрацию в `close()`.

<Example>
```js
import { nextGC } from "./gc.js";
const log = [];
let first = openConnection("kitap", log), second = openConnection("galam", log);
first.close();
first.close();
log.join();                   // "закрыто: kitap"
first = null;
second = null;
await nextGC();
await new Promise((r) => setTimeout(r, 50));
log.join();                   // "закрыто: kitap,утечка: galam"
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- сохранённое значение реестра не ссылается на само соединение — объяснено, что будет иначе (лекция, раздел 11);
- объяснено, почему в функции реестра можно писать в журнал, но нельзя закрывать настоящее соединение (9.9.3,
  заметка 1; MDN: «It should only be used for cleanup — and non-critical cleanup»);
- назван шаг 26.2.3.3, который убирает ячейку в `close()`, и что служит токеном.
</Criteria>
</Task>

<Task title="7. Слабые подписчики" level="medium" time="14">
<Goal>хранить слушателей так, чтобы список не держал их в памяти.</Goal>

Напишите `makeEmitter()`: `on(listener)` — запомнить объект с методом `handle(msg)` через `WeakRef`;
`emit(msg)` — выбросить из списка пустые `WeakRef`, вызвать `handle` у живых и вернуть их число; `size` — длина
списка.

<Example>
```js
import { nextGC } from "./gc.js";
const emitter = makeEmitter();
const got = [];
let a = { handle: (m) => got.push("a:" + m) }, b = { handle: (m) => got.push("b:" + m) };
emitter.on(a);
emitter.on(b);
emitter.emit("salam");        // 2
b = null;
await nextGC();
emitter.emit("sag bol");      // 1
got.join();                   // "a:salam,b:salam,a:sag bol"
emitter.size;                 // 1
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- подписчик, которого никто не держит, — `emitter.on({ handle: … })` прямо в вызове — после сборки пропадает:
  объяснено, почему это ловушка и когда нужен явный `off`;
- объяснено, почему в `emit` можно звать `deref()` дважды подряд для одного подписчика и не бояться
  `undefined` во второй раз (9.11).
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Одна загрузка на слово" level="hard" time="12">
<Goal>соединить кэш на WeakRef с общими обещаниями.</Goal>

Напишите `cachedOnce(getter)`: асинхронный кэш, как второй `cached` MDN, но без щели раздела 14 и с одной
загрузкой на ключ: пока слово грузится, другие вызовы `get` получают то же обещание. Неудачная загрузка в кэше не
остаётся.

<Example>
```js
let loads = 0;
const get = cachedOnce(async (word) => { loads++; await new Promise((r) => setTimeout(r, 10)); return { word }; });
const [x, y] = await Promise.all([get("kitap"), get("kitap")]);
x === y;                      // true
loads;                        // 1
(await get("kitap")) === x;   // true
loads;                        // 1
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- оба значения отпущены, после `nextGC()` два `get("kitap")` сразу — одна новая загрузка, один и тот же объект;
- `getter`, который в первый раз бросает: первый `get` отклонён, второй загружает заново;
- объяснено, зачем проверка `deref()` в функции реестра, хотя одновременных загрузок одного слова теперь нет.
</Criteria>
</Task>

<Task title="9. Незнакомый раздел: функция очистки бросает" level="hard" time="8">
<Goal>читать алгоритм, который заранее не разбирали.</Goal>

Прочитайте CleanupFinalizationRegistry ([9.12](https://tc39.es/ecma262/2026/#sec-cleanup-finalization-registry))
и HostEnqueueFinalizationRegistryCleanupJob (9.9.4.1). Предскажите по стандарту, что возможно, затем запустите:

```js
import { nextGC } from "./gc.js";
const calls = [];
const registry = new FinalizationRegistry((held) => {
  calls.push(held);
  if (calls.length === 1) { queueMicrotask(() => calls.push("микрозадача")); throw new Error("сбой"); }
});
let a = {}, b = {}, c = {};
registry.register(a, "a");
registry.register(b, "b");
registry.register(c, "c");
a = b = c = null;
await nextGC();
await new Promise((r) => setTimeout(r, 100));
console.log(calls.join());
```

<Criteria>
- предсказано, в каком порядке стандарт разрешает вызывать функцию для трёх ячеек (шаг 3.a), и сверено с Chrome;
- объяснено по шагу 3.c (знак `?`) и шагу 2 раздела 9.9.4.1, что происходит после ошибки и откуда в консоли
  «Uncaught Error: сбой»;
- объяснено, почему «микрозадача» стоит между первым и вторым вызовом, а без `throw` — после всех трёх
  (проверьте).
</Criteria>
</Task>
