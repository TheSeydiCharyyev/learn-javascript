# День 27. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Открыты спецификация [tc39.es/ecma402/2026](https://tc39.es/ecma402/2026/) и консоль Chrome. Код пишем в папке дня 22: блок — это main.js. Каждое «почему» — с номером раздела и шага ECMA-402 (10, 15).</Subtitle>

## Разминка

<Task title="1. Конструктор и опции" level="easy" time="7">
<Goal>предсказывать, что конструктор Locale сделает с тегом и опциями.</Goal>

```js
const run = (f) => { try { return String(f()); } catch (e) { return e.name; } };
console.log(run(() => new Intl.Locale("iw-SU", { script: "Hebr" })), run(() => new Intl.Locale("tk", { language: "uz", region: "AF" })), run(() => new Intl.Locale("tk-TM-u-hc-h12-ca-persian", { hourCycle: "h23" })));
console.log(run(() => new Intl.Locale("tk", { variants: "" })), run(() => new Intl.Locale("tk", { calendar: "ab" })), run(() => new Intl.Locale({ toString: () => "ru-RU" })), run(() => new Intl.Locale(undefined)));
```

<Criteria>
- предсказаны обе строки;
- для каждого вызова назван шаг 15.1.1 или 15.1.2, который дал ответ;
- объяснено, откуда в первом теге регион `RU`: у старого кода SU список замен, и если вероятного региона языка в нём
  нет, берётся первая замена (приложение C UTS #35).
</Criteria>
</Task>

<Task title="2. maximize и minimize" level="easy" time="6">
<Goal>видеть, какие части тега выводятся одна из другой.</Goal>

```js
const pair = (t) => { const l = new Intl.Locale(t); return l.maximize().baseName + "/" + l.minimize().baseName; };
console.log(pair("tk-Arab"), pair("az-IR"), pair("und-AF"), pair("en-Latn-GB"), pair("ru-Cyrl-RU-u-nu-latn"));
console.log(new Intl.Locale("zh").maximize().baseName, new Intl.Locale("zh-MO").maximize().baseName, new Intl.Locale("zh-Hant-HK").minimize().baseName, new Intl.Locale("uz-Arab-AF").minimize().baseName);
```

<Criteria>
- предсказаны обе строки;
- для `und-AF` объяснено, почему язык — `fa`, а для `zh-MO` — почему письменность `Hant`;
- объяснено, куда пропало `-u-nu-latn` (15.5.1) и почему у `zh-Hant-HK` остался регион, а не письменность.
</Criteria>
</Task>

<Task title="3. Ёж и уровни сравнения" level="easy" time="7">
<Goal>раскладывать различия строк по уровням таблицы 4.</Goal>

```js
const c = (o) => new Intl.Collator("ru", o);
const words = ["Ёж", "ёж", "еж", "Еж", "ежи"];
console.log(words.toSorted(c().compare).join(" "), "|", words.toSorted(c({ caseFirst: "upper" }).compare).join(" "));
console.log(["base", "accent", "case", "variant"].map((s) => words.filter((w) => c({ sensitivity: s }).compare(w, "еж") === 0).length).join(" "));
```

<Criteria>
- предсказаны обе строки;
- каждое число второй строки объяснено строкой таблицы 4 раздела 10.3.3.2; например, для `accent` таблица говорит:
  «Characters with the same base letter compare as unequal only if they differ in accents and/or other diacritic
  marks, regardless of differences in case»;
- объяснено, почему «ёж» стоит после обоих «еж», хотя регистр у них разный.
</Criteria>
</Task>

## Основные задания

<Task title="4. «Карточки 2.0»: неделя расписания" level="medium" time="12">
<Goal>собирать неделю региона из getWeekInfo и названий дней.</Goal>

Напишите `weekDays(tag, lang)`: краткие названия дней недели региона тега на языке `lang` — с первого дня недели
этого региона, выходные отмечены `*`. Названия берите у `DateTimeFormat` с `weekday: "short"`.

<Example>
```js
weekDays("tk-TM", "ru").join(" ");             // "пн вт ср чт пт сб* вс*"
weekDays("fa-IR", "ru").join(" ");             // "сб вс пн вт ср чт пт*"
weekDays("en-US", "en").join(" ");             // "Sun* Mon Tue Wed Thu Fri Sat*"
weekDays("tk-TM-u-fw-sun", "ru")[0];           // "вс*"
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- номера дней — по ISO 8601, как в таблице 27 раздела 15.5.17: понедельник — 1, воскресенье — 7;
- объяснено, почему в последней строке неделя началась с воскресенья (шаг 5 раздела 15.5.17) и почему выходные при
  этом не изменились.
</Criteria>
</Task>

<Task title="5. Список учеников" level="medium" time="12">
<Goal>сортировать по двум ключам двумя коллаторами.</Goal>

Напишите `sortStudents(list)`: элементы — `{ name, group }`; сначала по классу (`"2А"` раньше `"10Б"`), внутри класса —
по фамилии по-русски. Исходный массив не меняйте.

<Example>
```js
const list = [{ name: "Ёлкин", group: "10Б" }, { name: "Абаев", group: "2А" }, { name: "елкин", group: "10Б" }, { name: "Чарыев", group: "2А" }, { name: "Ершов", group: "1В" }, { name: "Елкин", group: "10Б" }];
sortStudents(list).map((s) => s.group + " " + s.name).join(", ");   // "1В Ершов, 2А Абаев, 2А Чарыев, 10Б елкин, 10Б Елкин, 10Б Ёлкин"
list[0].name;                                                        // "Ёлкин"
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- оба коллатора созданы один раз, а не на каждое сравнение: `localeCompare` по разделу 20.1.1 строит новый
  `Collator` при каждом вызове, и его примечание 1 напоминает: «The localeCompare method itself is not directly
  suitable as an argument to Array.prototype.sort because the latter requires a function of two arguments»;
- проверено, что с `localeCompare` без `numeric` класс `"10Б"` встаёт первым, и объяснено почему.
</Criteria>
</Task>

<Task title="6. Что известно о регионе" level="medium" time="13">
<Goal>узнавать язык, письмо, пояса, часы и выходные по коду региона.</Goal>

Напишите `regionInfo(region)`: из тега `und-<region>` через `maximize` верните объект
`{ language, script, zones, hours, weekend }` — язык, письменность, пояса, первый из циклов часов и выходные.

<Example>
```js
regionInfo("TM");                    // { language: "tk", script: "Latn", zones: ["Asia/Ashgabat"], hours: "h23", weekend: [6, 7] }
regionInfo("AF");                    // { language: "fa", script: "Arab", zones: ["Asia/Kabul"], hours: "h23", weekend: [4, 5] }
regionInfo("KZ").language;           // "ru"
regionInfo("XX").zones;              // []
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- объяснено, почему для Казахстана вероятный язык — русский: Add Likely Subtags берёт данные CLDR, а не
  государственный язык;
- для `XX` объяснено, откуда язык `en` и почему поясов нет (15.5.13: «The list is empty if no time zones are commonly
  used in region»).
</Criteria>
</Task>

<Task title="7. Туркменский коллатор" level="medium" time="13">
<Goal>собирать сравнение и равенство для языка, которого нет в Intl.</Goal>

Напишите `makeTurkmen()`: возвращает объект с `compare(a, b)` — порядок по туркменскому алфавиту
`abçdeäfghijžklmnňoöprsştuüwyýz`, регистр решает `Collator`, — и `equals(a, b)` — равенство без учёта регистра, но
с учётом знаков: «ä» и «a» в туркменском — разные буквы.

<Example>
```js
const tk = makeTurkmen();
["Ýyl", "yz", "äpet", "Et"].toSorted(tk.compare).join(" ");    // "Et äpet yz Ýyl"
tk.equals("ÄPET", "äpet");                                     // true
tk.equals("äpet", "apet");                                     // false
tk.equals("Ýyl", "yyl");                                       // false
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- объяснено, почему для `equals` не годится `sensitivity: "base"`: у русского коллатора «ä» и «a», «ý» и «y» — одна
  основа, — а `accent` годится;
- `compare` и `equals` создают коллаторы один раз, при вызове `makeTurkmen`.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Свой minimize" level="hard" time="12">
<Goal>собирать Remove Likely Subtags из maximize.</Goal>

Напишите `myMinimize(tag)` без `minimize`: расширьте тег через `maximize`, а потом пробуйте короткие теги — язык,
язык с регионом, язык с письменностью — и верните первый, который расширяется в то же самое; не нашлось — полный.

<Example>
```js
myMinimize("zh-Hant-TW");            // "zh-TW"
myMinimize("ru-Cyrl-TM");            // "ru-TM"
myMinimize("sr-Latn-RS");            // "sr-Latn"
myMinimize("uz-Arab-AF");            // "uz-AF"
["tk-Latn-TM", "en-Latn-US", "zh-Hans-CN", "az-Cyrl-AZ", "pa-Arab-PK", "tk-Arab-IR"].every((t) => myMinimize(t) === new Intl.Locale(t).minimize().baseName);   // true
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- объяснено, почему «язык с регионом» пробуют раньше «языка с письменностью» и что вышло бы для `zh-Hant-TW` при
  обратном порядке;
- объяснено, почему `tk-Arab-IR` не сокращается.
</Criteria>
</Task>

<Task title="9. Незнакомый раздел: регион из ключей rg и sd" level="hard" time="8">
<Goal>читать алгоритм, который заранее не разбирали.</Goal>

Прочитайте RegionPreference ([15.5.8](https://tc39.es/ecma402/2026/#sec-regionpreference)) и CanonicalUnicodeSubdivision
(15.5.7) и предскажите:

```js
const info = (t) => { const l = new Intl.Locale(t); return l.getHourCycles().join() + " " + l.getWeekInfo().firstDay + " " + l.getCalendars()[0]; };
console.log(info("en-US"), "|", info("en-US-u-rg-gbzzzz"), "|", info("en-u-sd-gbsct"), "|", info("ar-u-rg-irzzzz"));
console.log(new Intl.Locale("en-US-u-rg-gbzzzz").region, String(new Intl.Locale("en-u-rg-tmzzzz").getTimeZones()), new Intl.Locale("en-u-rg-gb").toString());
```

<Criteria>
- предсказаны обе строки;
- для каждого тега первой строки назван шаг 15.5.8, который дал регион, и сказано, где сработало перекрытие `rg`;
- объяснено, почему `region` остался `US`, почему `getTimeZones` не видит `rg` (15.5.13) и почему `rg-gb` — не
  значение ключа, а два ключа.
</Criteria>
</Task>
