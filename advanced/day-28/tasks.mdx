# День 28. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Открыты спецификация [tc39.es/ecma402/2026](https://tc39.es/ecma402/2026/) и консоль Chrome. Код пишем в папке дня 22: блок — это main.js. Каждое «почему» — с номером раздела и шага ECMA-402 (14, 17, 18).</Subtitle>

## Разминка

<Task title="1. Категории и цифры" level="easy" time="7">
<Goal>предсказывать категорию по тому, как число будет напечатано.</Goal>

```js
const run = (f) => { try { return f(); } catch (e) { return e.name; } };
const pr = new Intl.PluralRules("ru");
console.log([0, 1, 11, 21, 101, 112, 1.0, 2.5].map((n) => pr.select(n)).join(" "));
console.log(new Intl.PluralRules("ru", { maximumSignificantDigits: 1 }).select(21), new Intl.PluralRules("ru", { minimumIntegerDigits: 3 }).select(1), new Intl.PluralRules("ru", { roundingMode: "floor", maximumFractionDigits: 0 }).select(1.9), run(() => pr.select(1n)), pr.select("2e1"));
```

<Criteria>
- предсказаны обе строки;
- для каждого числа второй строки назван вид, в котором его напечатает шаг 4 раздела 17.5.2, — проверьте тем же
  `NumberFormat` с теми же опциями;
- объяснено, почему `1n` бросает в Chrome, хотя по 16.5.16 не должен.
</Criteria>
</Task>

<Task title="2. Списки и итераторы" level="easy" time="6">
<Goal>видеть, что ListFormat перебирает и какой шаблон берёт.</Goal>

```js
const run = (f) => { try { return f(); } catch (e) { return e.name; } };
const lf = new Intl.ListFormat("ru", { type: "disjunction" });
console.log(lf.format(["чай"]), "|", lf.format(["чай", "кофе"]), "|", lf.format(new Map([["a", 1]]).keys()), "|", run(() => lf.format(new Map([["a", 1]]))), "|", JSON.stringify(lf.format("")));
console.log(new Intl.ListFormat("en", { type: "unit", style: "narrow" }).format(["5 lb", "12 oz"]), "|", new Intl.ListFormat("de").format(["A", "B", "C"]), "|", run(() => new Intl.ListFormat("ru", { type: "or" })));
```

<Criteria>
- предсказаны обе строки;
- для одного элемента назван шаг 14.5.2, после которого шаблон не нужен;
- объяснено, почему `Map` бросает, а её `keys()` — нет (14.5.5, шаг 4.c), и чем пустая строка отличается от `undefined`.
</Criteria>
</Task>

```js
const auto = new Intl.RelativeTimeFormat("ru", { numeric: "auto" });

```

<Criteria>

</Task>

## Основные задания

<Task title="4. «Карточки 2.0»: сколько карточек на сегодня" level="medium" time="12">
<Goal>подписывать диапазон чисел правильной формой слова.</Goal>

Напишите `countLabel(min, max, lang)`: «5–7 карточек» по-русски и «1–2 cards» по-английски. Форму диапазона даёт
`selectRange`, а равные концы пишутся одним числом.

<Example>
```js
countLabel(5, 7, "ru");              // "5–7 карточек"
countLabel(2, 4, "ru");              // "2–4 карточки"
countLabel(1, 21, "ru");             // "1–21 карточка"
countLabel(3, 3, "ru");              // "3 карточки"
countLabel(1, 2, "en");              // "1–2 cards"
countLabel(1, 1, "en");              // "1 card"
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- объяснено, почему «1–21 карточка»: русскую форму диапазона решает его конец (17.5.3 — данные языка);
- проверено, что `selectRange(1, 1)` у английского в Chrome — `other`, и объяснено, почему равные концы лучше
  отдать `select` (шаг 4 раздела 17.5.4).
</Criteria>
</Task>

<Task title="5. «и ещё 2 темы»" level="medium" time="12">
<Goal>собирать короткий список из ListFormat и PluralRules.</Goal>

Напишите `shortList(items, max, lang)`: если элементов больше `max`, показать первые `max`, а последним элементом
списка — «ещё N тем» с правильной формой (по-английски — `N more`).

<Example>
```js
const topics = ["еда", "школа", "город", "дом", "цвет", "время"];
shortList(topics.slice(0, 5), 3, "ru");                            // "еда, школа, город и ещё 2 темы"
shortList(topics.slice(0, 4), 3, "ru");                            // "еда, школа, город и ещё 1 тема"
shortList(topics, 1, "ru");                                        // "еда и ещё 5 тем"
shortList(topics.slice(0, 2), 3, "ru");                            // "еда и школа"
shortList(["food", "school", "city", "home", "color"], 3, "en");   // "food, school, city, and 2 more"
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- «ещё N» — такой же элемент списка, как остальные: союз ставит шаблон \[\[End\]\] или \[\[Pair\]\], а не код;
- число в «ещё N» — строка: `format` чисел не принимает (14.5.5).
</Criteria>
</Task>

<Task title="6. Число в скобках" level="medium" time="13">
<Goal>менять число в готовой фразе, не разбирая строку.</Goal>

Напишите `highlight(value, unit, lang)`: результат `RelativeTimeFormat` с `numeric: "auto"`, где число целиком взято в
квадратные скобки. Берите `formatToParts`: у частей числа есть `unit`, у остальных — нет.

<Example>
```js
highlight(-21, "day", "ru");         // "[21] день назад"
highlight(2.5, "hours", "ru");       // "через [2,5] часа"
highlight(3, "quarter", "en");       // "in [3] quarters"
highlight(-1, "day", "ru");          // "вчера"
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- «2,5» — одни скобки, хотя частей числа три: `integer`, `decimal`, `fraction` (MakePartsList, 18.5.3);
- объяснено, почему у «вчера» скобок нет (шаг 7.a раздела 18.5.2).
</Criteria>
</Task>

<Task title="7. Свой ListFormat для туркменского" level="medium" time="13">
<Goal>повторять CreatePartsFromList для языка, которого нет в Chrome.</Goal>

Напишите `makeList({ pair, start, middle, end })`: возвращает функцию, которая собирает список по шаблонам, как
14.5.2, — с конца. Шаблоны — строки с `{0}` и `{1}`; 14.2.3 требует: «Each template string must contain the
substrings "\{0\}" and "\{1\}" exactly once».

<Example>
```js
const tk = makeList({ pair: "{0} we {1}", start: "{0}, {1}", middle: "{0}, {1}", end: "{0} we {1}" });
tk(["Aman", "Meret", "Sapar", "Ogulgerek"]);   // "Aman, Meret, Sapar we Ogulgerek"
tk(["Aman", "Meret"]);                         // "Aman we Meret"
tk([]);                                        // ""
tk(["{1}", "$&", "y"]);                        // "{1}, $& we y"
const ru = makeList({ pair: "{0} и {1}", start: "{0}, {1}", middle: "{0}, {1}", end: "{0} и {1}" });
[0, 1, 2, 3, 4, 5].every((k) => ru(["А", "Б", "В", "Г", "Д"].slice(0, k)) === new Intl.ListFormat("ru").format(["А", "Б", "В", "Г", "Д"].slice(0, k)));   // true
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- шаблон для каждого шага выбран, как в шаге 7 раздела 14.5.2: у первого элемента — `start`, у предпоследнего — `end`;
- объяснено, почему `p.replace("{0}", a).replace("{1}", b)` ломается на `["{1}", "x", "y"]` и на `"$&"`, а
  DeconstructPattern (14.5.1) — нет: он делит шаблон на части, а не ищет текст.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Точный select" level="hard" time="12">
<Goal>обходить ToNumber в select там, где важны все цифры.</Goal>

Напишите `selectExact(value)` для русского: у целых (`BigInt` или строка из цифр) категорию решают две последние
цифры — `one`: последняя 1, но не 11; `few`: 2–4, но не 12–14; иначе `many`. Всё остальное отдайте
`Intl.PluralRules`.

<Example>
```js
selectExact(21n);                                  // "one"
selectExact("1000000000000000000001");             // "one"
selectExact(1000000000000000000012n);              // "many"
selectExact("22");                                 // "few"
selectExact(1.5);                                  // "other"
Array.from({ length: 300 }, (_, n) => n).every((n) => selectExact(n) === new Intl.PluralRules("ru").select(n));   // true
```
</Example>

<Criteria>
- все строки примера дают то, что в комментариях;
- проверено, что `new Intl.PluralRules("ru").select("1000000000000000000001")` в Chrome — `many`, и объяснено, почему
  (16.5.16, шаг 3, против ToNumber);
- сказано, откуда правило: примечание 2 к 17.2.3 — «It is recommended that implementations use the locale data
  provided by the Common Locale Data Repository».
</Criteria>
</Task>

<Task title="9. Незнакомый раздел: короткие стили" level="hard" time="8">
<Goal>читать данные и шаг, которые заранее не разбирали.</Goal>

Прочитайте, какие поля бывают в данных `RelativeTimeFormat`
([18.2.3](https://tc39.es/ecma402/2026/#sec-Intl.RelativeTimeFormat-internal-slots)), и шаг 6 раздела 18.5.2, и
предскажите:

```js
const f = (style, v, u, numeric = "always") => new Intl.RelativeTimeFormat("ru", { style, numeric }).format(v, u);
console.log(["long", "short", "narrow"].map((s) => f(s, 3, "day")).join(" | "), "|", f("narrow", -1, "day", "auto"), "|", f("short", 1, "week", "auto"));
console.log(["long", "short", "narrow"].map((s) => new Intl.RelativeTimeFormat("en", { style: s }).format(1, "month")).join(" | "), "|", new Intl.RelativeTimeFormat("ru", { numberingSystem: "native" }).resolvedOptions().numberingSystem);
```

<Criteria>
- предсказаны обе строки;
- для `short` и `narrow` назван ключ поля, которое ищет шаг 6, и сказано, что будет, если его нет; 18.2.3: «Additional
  fields may exist with the previous names concatenated with the strings "-narrow" or "-short"»;
- объяснено, почему фраза «вчера» есть и в `narrow`, и почему `native` превратился в `latn`;
- сравнено с примером MDN для `narrow` («in 1 mo.»): страница честно пишет «The narrow style could be similar to the
  short style for some locales», но у английского Chrome 158 они уже разные.
</Criteria>
</Task>
