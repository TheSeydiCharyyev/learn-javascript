# Day 1. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Everything is done in the browser console.</Subtitle>

## Warm-up

<Task title="1. The console as a calculator" level="easy" time="7">
<Goal>open the console and make sure code runs.</Goal>

Open the console with <Kbd>F12</Kbd>, the *Console* tab. Calculate:

- how many seconds there are in a day;
- how many minutes there are in a school year of 9 months with 30 days each;
- how much 7 notebooks at 12 manat each and 3 pens at 5 manat each cost.

<Hint>
Multiplication is the star `*`, addition is `+`. Parentheses work as in
math: `(7 * 12) + (3 * 5)`. You do not need `console.log`: the console
shows the result by itself.
</Hint>

<Criteria>
- each answer is found with one line in the console;
- the results are written down in the notebook.
</Criteria>
</Task>

<Task title="2. The first message" level="easy" time="6">
<Goal>call a function and see the result.</Goal>

Run three lines in the console: a window with a greeting, your name printed in the console,
and the current year printed in the console.

<Example>
```js
alert("Salam!");
console.log("Murad");
console.log(2026);
```
</Example>

<Hint>
Text goes in quotes, a number is written without them. While the `alert` window is open,
the page waits: close it with the “OK” button.
</Hint>

<Criteria>
- the window appeared and closed with the button;
- both lines are visible in the console.
</Criteria>
</Task>

<Task title="3. Adding strings" level="easy" time="7">
<Goal>see the difference between a number and a string.</Goal>

Run these lines and explain to your neighbor why the results are different:

```js
2 + 3;
"2" + "3";
"Mary" + " " + 2026;
```

<Hint>
Quotes turn a value into text. Text is not added up but joined.
</Hint>

<Criteria>
- what each line printed is written down;
- the explanation takes one sentence.
</Criteria>
</Task>

## Main tasks

<Task title="4. Three layers on a live website" level="medium" time="15">
<Goal>tell HTML, CSS and JavaScript apart on a real page.</Goal>

Open any website you know and find three things on it:

1. something described in HTML (text, an image, a button);
2. something set in CSS (color, size, position);
3. something JavaScript does (it changes without reloading the page: a menu, a slider, a cart, search).

<Hint>
The sign of JavaScript at work is a change without a reload: the browser’s reload button did not
spin, and the page address did not change.
</Hint>

<WriteBox>
the name of the website, three examples and one sentence on how you understood that this is JavaScript at work.
</WriteBox>

<Criteria>
- there is an example for each of the three layers;
- the JavaScript example really changes without a reload.
</Criteria>
</Task>

<Task title="5. What runs the code" level="medium" time="12">
<Goal>remember the pair “browser — engine”.</Goal>

Fill in a table in your notebook: Chrome, Firefox, Safari, Edge, Node.js — and the engine of each.
Then answer in writing: why does the same code work in all browsers? And the other way round: why does
`typeof document` give `"object"` in the browser console, but `"undefined"` in Node.js?

<Hint>
The answer is connected with the word “standard”. Remember what the standard of the language is called.
</Hint>

<Criteria>
- the table is filled in completely;
- the answer contains the word ECMAScript;
- it is explained that `document` is not part of the language core but something the browser adds.
</Criteria>
</Task>

<Task title="6. Searching the documentation" level="medium" time="13">
<Goal>learn to find the answer on MDN, not in a random article.</Goal>

Find the MDN pages of three functions: `alert`, `prompt`, `console.table`.
For each one, write down what it does and what it returns.

<Example>
The search query: *mdn console table*. The first link leads to developer.mozilla.org.
</Example>

<Criteria>
- three pages are found, and the address of each starts with developer.mozilla.org;
- for each function there is a line “what it does”;
- it is found that `prompt` returns text, and `null` after Cancel.
</Criteria>
</Task>

<Task title="7. A dialog with the user" level="medium" time="10">
<Goal>build a small program from two functions.</Goal>

Write a program in the console: ask for a name, then greet the person by name and say
how many letters the name has.

<Hint>
The length of a text is found like this: `name.length`. Day 16 covers it in detail.
</Hint>

<Criteria>
- the program asks for a name and shows a greeting;
- the greeting contains the number of letters;
- for “Cancel”, the text of the red line in the console is written down and explained: `prompt`
  returns `null` after Cancel, and `null` has no length.
</Criteria>
</Task>

## Starred tasks

<Task title="8. What the browser can and cannot do" level="hard" time="10">
<Goal>check the limits we talked about in the lecture.</Goal>

Run these lines in the console and explain what happened in each case:

```js
document.title;
navigator.language;
navigator.geolocation;
```

<Hint>
The first line reads the tab title. The third one does not ask for the location by itself — it only gives
a tool that will ask for permission later.
</Hint>

<Criteria>
- for each line it is written down what it returned;
- it is explained why the browser did not show your location at once.
</Criteria>
</Task>

<Task title="9. A mini research: when features were born" level="hard" time="10">
<Goal>see that the language grows while old code keeps working.</Goal>

At the bottom of every MDN page there is a browser support table. Find the year when it became possible
to write `const`, and the year for `let`. Write down in which edition of the standard
they appeared.

<Criteria>
- the year and the edition are named (hint: it is the big update of 2015);
- a conclusion is made: what happens to old code written before that.
</Criteria>
</Task>
