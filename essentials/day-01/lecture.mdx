## 1. Что такое JavaScript {#what}

**JavaScript — это язык программирования.** На нём пишут инструкции, которые компьютер выполняет
по порядку, сверху вниз. Инструкция может быть простой: «посчитай 2 + 2», «покажи надпись», «возьми текст из поля
ввода». Из таких мелких шагов собираются большие программы: интернет-магазин, чат, игра, редактор фотографий.

Главное отличие от HTML и CSS в одном слове: **поведение**. HTML описывает, что на странице есть.
CSS описывает, как это выглядит. JavaScript описывает, что происходит, когда человек нажимает, вводит, прокручивает,
ждёт ответа сервера.

<Analogy>
Представьте кафе. HTML — это столы, стулья и меню: что физически стоит в зале. CSS — оформление: цвет стен,
шрифт в меню, форма официантов. JavaScript — это сам официант: он принимает заказ, уносит его на кухню,
приносит еду, считает счёт. Без официанта кафе выглядит красиво, но ничего не происходит.
</Analogy>

Вы уже видели работу JavaScript сотни раз, просто не знали, что это он:

- **лента, которая подгружается сама.** Вы прокручиваете вниз, и появляются новые записи —
  страница не перезагружалась, значит, данные запросил код;
- **корзина интернет-магазина.** Нажали «купить» — число товаров в углу изменилось мгновенно;
- **проверка формы.** Ввели телефон не в том формате и сразу получили красную подпись,
  ещё до отправки;
- **тёмная тема.** Нажали на переключатель — цвета поменялись и запомнились до следующего раза;
- **карта.** Тянете её пальцем, она подгружает новые куски и ставит метки.

Общее у всех примеров одно: **страница изменилась без перезагрузки**. Это самый простой признак,
по которому можно узнать работу JavaScript, даже не заглядывая в код.

Проверьте на этой самой странице: откройте консоль клавишей <Kbd>F12</Kbd>
(вкладка *Console*), вставьте строку и нажмите <Kbd>Enter</Kbd>:

```js
document.querySelector("h1").textContent = "Я поменял заголовок!";
```

Заголовок урока сменился без перезагрузки. Обновите страницу — он вернётся: код менял
страницу только в браузере, файл на сервере остался прежним.

Вот программа из одной строки. Она показывает окно с надписью:

```js
alert("Привет, Мары!");
```

А эта программа спрашивает имя и здоровается:

```js
const name = prompt("Как вас зовут?");
alert("Здравствуйте, " + name + "!");
```

Здесь уже видно три вещи, которые мы будем разбирать весь курс: значение («Мары», имя человека),
переменная `name` — коробочка с именем, куда значение положили, и функция `alert` —
готовая команда, которой пользуются, написав её имя и скобки.

### Почему этот язык учат первым

Языков программирования сотни. JavaScript берут первым по трём практическим причинам.
**Ничего не нужно устанавливать**: браузер уже стоит на компьютере. **Результат
видно сразу**: написали строку — страница изменилась, и ошибки находятся быстрее.
**Он нужен работе**: любой сайт — это HTML, CSS и JavaScript.

## 2. Что значит «язык программирования» {#program}

Компьютер не понимает человеческий язык. Он умеет выполнять очень простые операции: сложить два числа,
сравнить их, положить значение в память, взять его обратно. Язык программирования — это посредник.
Мы пишем понятные нам слова, а программа-переводчик превращает их в операции процессора.

У любого языка есть **синтаксис** — правила записи. В русском языке после «который» ставят запятую,
а предложение заканчивают точкой. В JavaScript строку кода заканчивают точкой с запятой, текст берут в кавычки,
а аргументы функции — в круглые скобки. Нарушите правило — программа не выполнится, и браузер скажет об этом
сообщением об ошибке. Это не страшно: ошибки видят все, включая тех, кто пишет код двадцать лет.

Второе важное слово — **по порядку**. Инструкции выполняются сверху вниз, одна за другой.
Разберём программу из четырёх строк по шагам:

```js
const price = 12;        // 1
const count = 7;         // 2
const total = price * count;  // 3
console.log(total);      // 4
```

<Step n="1">
Заводим коробочку с именем `price` и кладём в неё число 12. Слово `const`
означает «это значение менять не будем».
</Step>

<Step n="2">
Заводим вторую коробочку `count` со значением 7.
</Step>

<Step n="3">
Считаем `12 * 7`. Важно: сначала вычисляется правая часть, и только потом результат
кладётся в коробочку `total`. Компьютер к этому моменту уже знает, что лежит в `price`
и `count`, потому что строки 1 и 2 выполнились раньше.
</Step>

<Step n="4">
Показываем результат: в консоли появляется `84`.
</Step>

Поменяйте строки местами — и программа сломается. Поставим вывод первой строкой в файле
`app.js`:

```js
console.log(total);            // ReferenceError: Cannot access 'total' before initialization
const price = 12;
const count = 7;
const total = price * count;
```

Движок прочитал файл целиком и знает, что имя `total` в нём есть, но значение
в него ещё не положили. В консоли новой вкладки сообщение короче — *total is not defined*,
а смысл тот же: на этой строке значения ещё нет. Подробно разберём на дне 4. Главная мысль видна уже сейчас:
компьютер не догадывается, он выполняет ровно то, что написано, и ровно в том порядке.

<Analogy>
Программа — это рецепт. «Налить воду, вскипятить, насыпать чай, накрыть» — порядок важен, шаги простые,
и каждый шаг понятен сам по себе. Компьютер — очень быстрый, очень точный и абсолютно бестолковый повар:
он не поймёт «ну ты сделай как обычно», зато выполнит подробный рецепт миллион раз без единой ошибки.
</Analogy>

Из чего складывается любая программа, независимо от языка:

| Кирпичик | Что это | Пример | Когда разбираем |
| --- | --- | --- | --- |
| значения | числа, текст, «да / нет» | `12`, `"чай"`, `true` | день 5 |
| переменные | именованные коробочки для значений | `const price = 12;` | день 4 |
| операции | что со значениями делают | `price * count` | дни 6–7 |
| условия | выбор пути | `if (age > 18) { ... }` | день 9 |
| циклы | повторение | `for (...) { ... }` | день 10 |
| функции | кусок программы с именем | `console.log(...)` | дни 12–14 |

Эти шесть кирпичиков есть почти в каждом языке программирования. Выучив их один раз на JavaScript,
вы будете узнавать их в Python, Java и любом другом языке — поменяются только детали записи.

Вот все шесть в одной маленькой программе. Читать её построчно пока не нужно — узнайте
кирпичики по комментариям:

```js
const prices = [12, 5, 8];            // значения и переменная
let sum = 0;
for (const price of prices) {         // цикл: по очереди для каждой цены
  if (price > 6) {                    // условие: только цены больше 6
    sum = sum + price;                // операция
  }
}
console.log(sum);                     // 20 — функция вывела результат
```

## 3. Три слоя страницы: HTML, CSS, JavaScript {#layers}

Любая веб-страница собрана из трёх слоёв. Они работают вместе, но отвечают за разное.

<Scheme src="scheme-layers.svg">Одна и та же кнопка: HTML её создаёт, CSS красит, JavaScript заставляет работать</Scheme>

Слои можно снимать по одному. Выключите CSS — страница станет некрасивой, но текст останется.
Выключите JavaScript — страница останется красивой, но кнопки перестанут что-либо делать.
Уберите HTML — не останется ничего.

Снимите CSS с этой самой страницы — одной строкой в консоли:

```js
document.querySelectorAll('link[rel="stylesheet"], style').forEach((el) => el.remove());
```

Цвета, шрифты и отступы исчезнут, а весь текст останется на месте: содержимое живёт в HTML.
Обновите страницу — оформление вернётся.

Посмотрим на одну кнопку во всех трёх слоях. HTML создаёт кнопку и место для счётчика:

```html
<button id="btn">Купить</button>
<span id="count">0</span>
```

CSS решает, как она выглядит:

```html
<style>
  #btn {
    background: #f59e0b;
    color: white;
    border-radius: 8px;
    padding: 10px 20px;
  }
</style>
```

А JavaScript отвечает на нажатие:

```js
let count = 0;

document.getElementById("btn").addEventListener("click", function () {
  count = count + 1;
  document.getElementById("count").textContent = count;
});
```

Этот код мы разберём построчно на днях 24 и 27, а сейчас обратите внимание на структуру: есть переменная,
которая хранит число, и есть реакция на событие — «когда нажали, сделай вот это». Почти любой интерфейс
в интернете устроен именно так.

<TryIt>
Найдите на любимом сайте элемент, который меняется без перезагрузки: лайк, звёздочку, счётчик корзины.
Подумайте, какая переменная за ним стоит и какое событие её меняет. Это и есть мышление программиста.
</TryIt>

<Why>
Новички часто пытаются «сделать всё на JavaScript»: рисуют кнопки кодом, задают цвета кодом. Так тоже можно,
но страница становится медленной и непонятной. Правило простое: что можно показать в HTML и покрасить в CSS —
делайте в HTML и CSS. JavaScript берите тогда, когда нужно действие.
</Why>

## 4. Где выполняется код и кто его выполняет {#engine}

Написанный код — это просто текст в файле. Чтобы он заработал, нужен исполнитель. В браузере такой исполнитель
называется **движок JavaScript**. Браузер читает HTML, находит в нём код и отдаёт его движку.
Движок разбирает текст, превращает его в понятные процессору команды и выполняет.

<Scheme src="scheme-engine.svg">Код проходит этот путь каждый раз, когда вы открываете страницу</Scheme>

### Как движок понимает код

Внутри движка код проходит три стадии. Знать их наизусть не нужно, но понимать полезно: это объясняет,
почему одни ошибки видны сразу, а другие только во время работы программы.

<Step n="1">
**Разбор.** Движок читает текст и проверяет правила записи. Если забыта скобка,
программа не запустится вообще — это *синтаксическая* ошибка, её видно до выполнения.
</Step>

<Step n="2">
**Перевод во внутренние команды.** Текст превращается в набор простых инструкций,
понятных движку.
</Step>

<Step n="3">
**Выполнение.** Инструкции выполняются по очереди. Здесь вылезают ошибки,
которые нельзя было заметить заранее: обратились к имени, которого нет, или вызвали как функцию то,
что функцией не является.
</Step>

Раньше говорили, что JavaScript — «интерпретируемый» язык: код выполняется по строчке, без подготовки.
Сегодня это неточно. Современные движки следят, какие куски кода выполняются часто, и на ходу переводят их
в машинные команды — такой приём называется JIT-компиляцией. Поэтому один и тот же цикл при втором проходе
может работать заметно быстрее, чем при первом.

<FunFact>
Имя V8 — как у мощного автомобильного двигателя с восемью цилиндрами. Первая версия движка
вышла вместе с браузером Chrome в 2008 году.
</FunFact>

У каждого браузера свой движок, но все они выполняют один и тот же язык:

| Браузер | Движок |
| --- | --- |
| Chrome, Edge, Opera, Яндекс.Браузер | V8 |
| Firefox | SpiderMonkey |
| Safari | JavaScriptCore |

Движок V8 умеет работать и без браузера. Так появился **Node.js** — программа, которая запускает
JavaScript прямо в системе. Поэтому сегодня на этом языке пишут не только страницы:

- сайты и веб-приложения — в браузере;
- серверы, которые отдают данные этим сайтам, — на Node.js;
- приложения для телефонов — React Native;
- программы для компьютера — Electron (так сделаны VS Code, Discord, Slack);
- скрипты для таблиц, ботов, автоматизации.

За этими строчками — будущий выбор профессии. В браузере работает то, что человек видит:
магазины, личные кабинеты, игры, — этим занимается фронтенд-разработчик, и этому посвящён наш курс.
Сервер отдаёт страницам данные; кто пишет и страницу, и сервер, — фулстек-разработчик.

<RealWorld>
Один язык на всех уровнях — это экономия. Человек, который выучил JavaScript для страницы, может написать
и простой сервер к ней, не изучая второй язык с нуля.
</RealWorld>

### Язык и окружение

Как один язык работает и в браузере, и на сервере? MDN объясняет так: у JavaScript есть
**ядро** — числа, строки, функции, `Math`, `JSON`, — одинаковое везде.
А **окружение**, в котором запущен код, добавляет к ядру своё: браузер — страницу, окна
и события, Node.js — файлы и сервер.

<Scheme src="scheme-engine-2.svg">Ядро одно, окружения разные: каждое добавляет к языку свои возможности</Scheme>

Это легко проверить. В консоли браузера:

```js
typeof document;   // "object" — страница есть
typeof process;    // "undefined" — такого в браузере нет
```

А вот файл `hello.js`, запущенный в Node.js командой `node hello.js`:

```js
console.log(2 + 3);
console.log(typeof document);   // страницы нет
console.log(typeof process);    // зато есть процесс Node.js
console.log(Math.max(3, 7, 2)); // ядро то же, что в браузере
```

```plain-out
5
undefined
object
7
```

Числа и `Math` работают одинаково — это ядро. `document` даёт только
браузер, `process` — только Node.js. В курсе мы пишем для браузера, поэтому пользуемся
и ядром, и возможностями страницы.

## 5. Откуда взялся язык {#history}

История языка объясняет его странности. Некоторые решения, которые сегодня кажутся нелогичными, появились
потому, что язык делали в спешке, а потом двадцать лет не могли сломать совместимость с уже написанными сайтами.

<Timeline>
<Event year="1995">
Брендан Айк в компании Netscape пишет первую версию языка примерно за десять дней. Название придумали
маркетологи: тогда была популярна Java, и слово «JavaScript» помогало продавать.
</Event>

<Event year="1997">
Язык описывают в стандарте, чтобы все браузеры понимали его одинаково. Стандарт называется
**ECMAScript**: имя JavaScript к тому времени принадлежало одной компании.
</Event>

<Event year="1996–2001">
«Война браузеров». Microsoft выпускает свой вариант языка — JScript. Один и тот же код работает
в Netscape и не работает в Internet Explorer, и наоборот. Разработчики пишут страницы по два раза
и вставляют проверки «а какой у вас браузер».
</Event>

<Event year="2005–2008">
Появляются библиотеки вроде jQuery, которые прячут различия браузеров за одной командой.
Тогда же взлетает подход, при котором страница подгружает данные без перезагрузки: почта, карты,
ленты новостей начинают работать как настоящие программы.
</Event>

<Event year="2009">
Появляется Node.js: тот же язык начинает работать вне браузера. С этого момента один человек может
написать и страницу, и сервер к ней.
</Event>

<Event year="2015">
Большое обновление ES2015: современные возможности, которыми мы будем пользоваться весь курс
(`let`, `const`, стрелочные функции, классы).
</Event>

<Event year="Каждый год">
Новая редакция стандарта выходит летом: ES2016, ES2017 и так далее. Язык не переписывают заново,
а добавляют возможности так, чтобы старый код продолжал работать.
</Event>
</Timeline>

Кто решает, что войдёт в язык? Комитет **TC39** — представители браузерных компаний и крупных
разработчиков. Любое предложение проходит четыре стадии: идея, описание, черновик с реализацией, готовая
возможность. Пока предложение не дошло до последней стадии, им лучше не пользоваться в учебном коде:
оно может измениться.

Из-за требования совместимости в языке остались вещи, которые сегодня считаются ошибками дизайна:
например, `var` с его странными правилами видимости или `==`, который сравнивает
«примерно». Их не убирают, потому что миллионы старых страниц перестали бы работать. Вместо этого добавили
правильные замены: `let` и `const` вместо `var`, `===` вместо
`==`. Мы сразу будем учиться писать по-современному, а про старое расскажем, чтобы вы понимали
чужой код.

Как выглядит это «примерно», видно в консоли (подробно — на дне 7):

```js
0 == "";    // true — «примерно»: пустую строку превратили в число 0
0 === "";   // false — строго: число и строка не равны
```

<FunFact>
Первое имя языка было Mocha, второе — LiveScript, и только третье — JavaScript. Сегодня официальное имя
стандарта — ECMAScript, но в жизни все говорят «JavaScript», а версии называют по году: «это появилось в ES2020».
</FunFact>

## 6. JavaScript и Java — разные языки {#java}

<Mistake>
«JavaScript — это сокращённая Java» — самое частое заблуждение новичков. Общего у них только четыре буквы
в названии и немного похожий вид скобок. Это разные языки с разной историей, разными правилами и разными
задачами: на Java пишут банковские системы и приложения для Android, на JavaScript — страницы и серверы для них.
Спросить на собеседовании «а какая между ними разница» — обычное дело, и ответ «никакой» сразу заметен.
</Mistake>

|  | JavaScript | Java |
| --- | --- | --- |
| Появился | 1995, Netscape | 1995, Sun Microsystems |
| Где работает | браузер, сервер (Node.js) | виртуальная машина Java, Android |
| Объявление типа | не требуется: `let x = 5;` | обязательно: `int x = 5;` |
| Запуск | браузер выполняет текст сразу | сначала сборка, потом запуск |
| Типичная задача | интерфейс сайта, веб-сервер | банковская система, приложение Android |

Главное различие из таблицы видно в трёх строках. В JavaScript тип не объявляют, и в одну
переменную можно положить сначала число, потом текст:

```js
let x = 5;
x = "пять";   // JavaScript не против
x;            // "пять"
```

В Java такая программа не соберётся: `incompatible types: String cannot be converted to int` —
переменная, объявленная как `int`, хранит только целые числа.

## 7. Что язык умеет в браузере и что ему запрещено {#can}

Код на странице работает не в пустоте: он живёт внутри вкладки браузера. Вкладка даёт ему много возможностей,
но держит в рамках — иначе любой сайт мог бы навредить вашему компьютеру.

| Умеет | Не умеет |
| --- | --- |
| менять текст и оформление страницы | читать и записывать любые файлы на диске |
| реагировать на клики, ввод, прокрутку | запускать программы на компьютере |
| запрашивать данные с сервера и показывать их | свободно читать данные чужого сайта в другой вкладке |
| сохранять данные в браузере и помнить их после перезагрузки | включать камеру или узнавать место без вашего разрешения |

Правая колонка — не недостаток языка, а защита. Всё, что касается вашего компьютера, браузер разрешает только
через явный вопрос: «Сайт просит доступ к камере. Разрешить?». Файл с компьютера сайт получит только тогда,
когда вы сами выберете его в окне выбора файла.

Левая колонка — по строке на возможность:

```js
document.body.append("Эту строку добавил код");   // менять страницу: строка внизу
```

```js
document.addEventListener("click", () => console.log("щёлк"));   // реагировать: щёлкните по странице
```

```js
localStorage.setItem("город", "Мары");   // сохранить в браузере
localStorage.getItem("город");            // "Мары" — и после перезагрузки тоже
```

Проверим это прямо сейчас. Откройте консоль на любой странице и выполните:

```js
document.title;              // заголовок вкладки — читается свободно
document.title = "Мой сайт"; // и меняется: посмотрите на вкладку
navigator.language;          // язык браузера, например "ru-RU"
screen.width;                // ширина экрана в точках
```

Страница разрешила прочитать и даже изменить свой заголовок. Теперь попробуйте узнать местоположение:

```js
navigator.geolocation.getCurrentPosition(function (pos) {
  console.log(pos.coords.latitude, pos.coords.longitude);
});
```

Браузер не выдаст координаты молча — сверху появится вопрос «Разрешить доступ к вашей геопозиции?».
Пока человек не нажмёт «Разрешить», код не получит ничего. Так же устроены камера, микрофон и уведомления.

<Important>
Отсюда важное правило безопасности: не выполняйте в консоли код, который вам прислали незнакомые люди
«чтобы получить подарок». Вы выполняете его от имени открытой страницы — например, своей почты
или банка. Браузер защищает вас от чужих сайтов, но не от вас самих.
</Important>

Ещё одно ограничение называется «правило одного источника»: код одной страницы не может свободно читать
содержимое другой. Иначе вкладка с игрой прочитала бы вашу переписку в соседней вкладке. Данные с чужого
сервера страница получает только с его разрешения — разберём это на дне 31, когда дойдём до `fetch`.

## 8. Первые строки кода {#first}

Подробно про инструменты будет завтра, на дне 2. Сегодня достаточно знать: в каждом браузере есть
**консоль** — окно, где можно написать строку кода и сразу увидеть результат. Открывается
клавишей <Kbd>F12</Kbd>, вкладка *Console*.

Консоль — черновик программиста: в ней проверяют одну мысль — «а что вернёт этот метод?».
Испортить ничего нельзя: всё, что код поменял на странице, пропадёт после обновления.

| Действие | Как |
| --- | --- |
| открыть консоль | <Kbd>F12</Kbd>, затем вкладка Console |
| выполнить строку | <Kbd>Enter</Kbd> |
| перенести строку, не выполняя | <Kbd>Shift</Kbd> + <Kbd>Enter</Kbd> |
| повторить предыдущую команду | стрелка <Kbd>↑</Kbd> |
| очистить консоль | <Kbd>Ctrl</Kbd> + <Kbd>L</Kbd> или `console.clear()` |

Попробуйте эти строки прямо на лекции:

```js
2 + 2 * 2;                 // 6 — приоритет как в математике
"Мары" + " " + 2026;       // "Мары 2026" — строки складываются
console.log("Работает!");  // выводит текст в консоль
```

У первых двух строк нет `console.log`, а результат всё равно виден: консоль сама
показывает значение последнего выражения. MDN сравнивает её с `console.log`, обёрнутым
вокруг каждой строки. Отсюда и загадочное `undefined` после вывода:

```js
3 + 5;               // 8 — значение выражения
console.log(3 + 5);  // печатает 8, а ниже консоль пишет undefined: console.log ничего не возвращает
```

Консоль — хороший калькулятор, и не только для чисел:

```js
10 / 3;      // 3.3333333333333335
0.1 + 0.2;   // 0.30000000000000004 — дроби считаются не идеально точно, день 6
```

```js
"Мары".length;          // 4 — букв в слове
"мары".toUpperCase();   // "МАРЫ"
```

<TryIt>
Откройте консоль и посчитайте, сколько минут в неделе. Подсказка: `60 * 24 * 7`.
Если получилось 10080 — всё верно, вы только что выполнили свою первую программу.
</TryIt>

### Несколько строк сразу

Если строка не закончена — например, вы набрали `function greet() {` и нажали
<Kbd>Enter</Kbd>, — консоль не выполняет её, а ждёт продолжения. Перенести строку
можно и самому: <Kbd>Shift</Kbd> + <Kbd>Enter</Kbd>.

```js
function greet() {
  return "Салам!";
}
greet();   // "Салам!"
```

Первый пример учебника MDN — тоже в несколько строк. Скопируйте его в консоль целиком:

```js
(function () {
  "use strict";
  /* Start of your code */
  function greetMe(yourName) {
    alert(`Hello ${yourName}`);
  }

  greetMe("World");
  /* End of your code */
})();
```

Появится окно *Hello World*. Обёртку `(function () { … })();` MDN советует
ставить вокруг кода в консоли, чтобы опыты не мешали друг другу. Что она значит, разберём на
дне 13, строку `"use strict"` — на дне 4.

Код можно писать и в файле. Тогда его подключают к странице одной строкой:

```html
<script src="app.js" defer></script>
```

Файл `app.js` лежит рядом со страницей, а слово `defer` говорит браузеру: «сначала
покажи страницу, потом выполняй код». Так делают почти всегда.

Полностью маленький проект выглядит так. Два файла в одной папке:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Первая страница</title>
  <script src="app.js" defer></script>
</head>
<body>
  <h1 id="hello">Здравствуйте!</h1>
</body>
</html>
```

```js
// app.js
const title = document.getElementById("hello");
title.textContent = "Салам, Мары!";
console.log("Код выполнился");
```

Откройте страницу в браузере — заголовок поменяется ещё до того, как вы успеете его прочитать.
Разбирать `getElementById` мы будем на дне 24, сейчас достаточно увидеть связку: HTML создал
заголовок, JavaScript его изменил.

```js
// тот же app.js, но <script src="app.js"> стоит в <head> без defer:
// Uncaught TypeError: Cannot set properties of null (setting 'textContent')
```

<Mistake>
Если написать `<script src="app.js">` без `defer` в самом начале страницы,
код выполнится раньше, чем появится заголовок, и `getElementById` вернёт `null`.
Отсюда классическая ошибка новичка: *Cannot set properties of null*. Лечится одним словом
`defer`.
</Mistake>

Кодировка `UTF-8` в шапке — обязательна, иначе кириллица и туркменские буквы
`ä`, `ň`, `ö`, `ü`, `ý`, `ž`
превратятся в набор знаков вопроса.

## 9. Когда что-то идёт не так {#errors}

Ошибка — это не наказание, а сообщение. Браузер пишет, что именно он не понял и в какой строке.
Научиться читать эти сообщения важнее, чем заучивать методы: ошибки будут сопровождать вас всю работу.

Три сообщения, которые встретятся в первую неделю:

| Сообщение | Что значит | Что делать |
| --- | --- | --- |
| `Uncaught ReferenceError: total is not defined` | использовано имя, которого нет | проверить, объявлена ли переменная и не опечатались ли в имени |
| `Uncaught SyntaxError: Unexpected token` | нарушены правила записи | искать лишнюю или пропущенную скобку, кавычку, запятую |
| `Uncaught TypeError: x is not a function` | вызвали как функцию то, что функцией не является | проверить имя метода: `console.lg`, `getElementByID` |

Сообщение об ошибке читают с конца: последняя строка говорит, где именно споткнулся движок.
В консоли рядом с ошибкой стоит имя файла и номер строки — нажмите на него, и браузер покажет это место.

```js
console.log(summa);   // ReferenceError: summa is not defined — такого имени нет
```

```js
const summa = 10;
console.log(summa);   // 10 — объявили имя, и ошибка ушла
```

```js
console.lg("тест");   // TypeError: console.lg is not a function — опечатка в имени метода
consol.log("тест");   // ReferenceError: consol is not defined — опечатка в первом слове
```

Во второй паре опечатки похожи, а ошибки разные. В `consol.log` движок споткнулся
раньше — на неизвестном имени `consol`, поэтому до «не функция» дело не дошло.

```js
// alert("привет);   → SyntaxError: Invalid or unexpected token — кавычка не закрыта
alert("привет");      // так правильно
```

<ProTip>
Не бойтесь сломать код: браузер нельзя испортить неверной строкой. Пробуйте, читайте ошибку, правьте.
Копируйте текст ошибки в поиск целиком — чаще всего первый же ответ объясняет причину.
</ProTip>

## 10. Документация: MDN и спецификация {#docs}

Программист не держит все методы в голове. Он помнит, что метод есть, и умеет быстро найти описание.
Главный справочник по языку — **MDN Web Docs**. Там два больших раздела:

- **Guide** — учебник: объясняет темы по порядку, с примерами;
- **Reference** — справочник: отдельная страница на каждый метод, свойство и оператор.

Есть ещё **спецификация ECMAScript** — документ, по которому пишут сами браузеры. Она написана
сухим языком для разработчиков движков. Читать её мы начнём в курсе 2, когда появятся вопросы вида
«а почему оно работает именно так».

### Как читать страницу справочника

Страница метода в Reference устроена одинаково: короткое описание, потом раздел
*Syntax*. Вот он у `Math.max`, дословно:

```js
Math.max()
Math.max(value1)
Math.max(value1, value2)
Math.max(value1, value2, /* …, */ valueN)
```

Это не код для запуска, а шаблон: метод можно вызвать без значений, с одним, с двумя и с
любым количеством. Дальше идут разделы *Parameters* — что передавать, *Return
value* — что вернётся, и *Examples*. Проверим шаблон в консоли:

```js
Math.max(3, 7, 2);   // 7 — самое большое из переданных
Math.max();          // -Infinity — так и написано в Return value: «если значений нет»
```

<ProTip>
Ищите не в поиске вообще, а так: «mdn» плюс название метода. Запрос *mdn array map* приведёт прямо
на нужную страницу справочника. Английский в документации простой и повторяющийся, привыкаешь за неделю.
</ProTip>

## 11. Как устроен этот курс {#course}

Курс идёт три месяца: понедельник, среда, пятница, по три урока в день. Первый урок — лекция,
второй и третий — практика. Дома вы перечитываете конспект и делаете домашнее задание.

У каждого дня три страницы, и у них разные задачи:

| Страница | Когда пользоваться | Что внутри |
| --- | --- | --- |
| Лекция | на уроке и потом, как книга | объяснения, схемы, примеры, справочник темы, шпаргалка, вопросы для проверки |
| Конспект | дома, перед следующим занятием | сжатая выжимка на одну страницу и домашнее задание |
| Задания | уроки 2 и 3 | задачи от разминки до задач со звёздочкой, с критериями и подсказками |

Обратите внимание на два блока, которые будут в каждой лекции. **Справочник дня** — таблица
со всеми методами темы и ссылками на документацию: по ней удобно искать через месяц, когда вы забудете
название метода. **Шпаргалка** — тот же материал в виде короткого кода, который можно
переписать в тетрадь.

Курс Essentials — первый из четырёх. Дальше идут Intermediate (как язык устроен внутри),
Advanced (язык по спецификации) и Web APIs (возможности браузера). Всё вместе покрывает документацию
целиком, поэтому в лекциях вы часто увидите пометку «подробно разберём в курсе 2» — это не отговорка,
а ссылка на конкретное место.

### Что понадобится для занятий

- **Браузер** — Chrome, Firefox или Edge. Подойдёт любой современный, он уже стоит
  на компьютере;
- **редактор кода** — VS Code, бесплатный. Ставим на дне 2;
- **тетрадь и ручка** — да, всерьёз. Схемы, шпаргалки и разбор ошибок от руки
  запоминаются лучше;
- **папка для работ** — заведите одну папку и складывайте туда все файлы курса,
  по папке на день.

### Как спрашивать, чтобы вам помогли

Вопрос «у меня не работает» не имеет ответа. Полезный вопрос состоит из четырёх частей:
что вы хотели сделать, какой код написали, что получилось и что ожидали получить. Текст ошибки
из консоли копируйте целиком — в нём обычно и есть ответ.

<Highlight>
Главный совет на три месяца: **печатайте код руками**, не копируйте. Пальцы запоминают
синтаксис быстрее головы, а ошибки, которые вы делаете при наборе, — это и есть учёба.
Скопированный код учит нулю.
</Highlight>

## 12. Словарь первого дня {#words}

Эти слова будут звучать на каждом занятии. Выпишите их в тетрадь — к ним удобно возвращаться.

| Слово | Что означает |
| --- | --- |
| код | текст программы, написанный по правилам языка |
| инструкция | одна команда программы; обычно одна строка |
| синтаксис | правила записи: где скобки, кавычки, точка с запятой |
| значение | данные, с которыми работает программа: число, текст, «да / нет» |
| переменная | имя, за которым закреплено значение |
| функция | кусок программы с именем; вызывается с круглыми скобками |
| вызвать функцию | написать её имя со скобками: `alert("текст")` |
| аргумент | значение, которое передают функции в скобках |
| вернуть значение | отдать результат туда, откуда функцию вызвали |
| консоль | окно браузера для выполнения кода и вывода сообщений |
| движок | программа, которая выполняет JavaScript |
| DevTools | инструменты разработчика в браузере, открываются по <Kbd>F12</Kbd> |
| ошибка | сообщение движка о том, что он не смог выполнить код |
| спецификация | документ, который описывает язык для создателей браузеров |

<Cheatsheet>
- **HTML** — что есть на странице, **CSS** — как выглядит,
  **JavaScript** — что происходит.
- Код выполняет **движок**: V8 в Chrome, SpiderMonkey в Firefox, JavaScriptCore в Safari.
- Вне браузера язык запускает **Node.js**.
- Стандарт языка называется **ECMAScript**, новая редакция выходит каждый год.
- Консоль открывается клавишей <Kbd>F12</Kbd> и сама показывает значение
  последнего выражения; `undefined` после `console.log` — это его «ничего».
- Ядро языка одинаково везде; `document` даёт браузер, `process` — Node.js.
- `ReferenceError` — нет такого имени, `TypeError` — не функция,
  `SyntaxError` — нарушены правила записи.
- Файл со скриптом подключают так: `<script src="app.js" defer></script>`
</Cheatsheet>

3. Может ли сайт без вашего ведома прочитать файл с рабочего стола?
   <Answer>Нет. Браузер запрещает доступ к файлам. Сайт получит файл только если вы сами выберете его
   в окне выбора файла.</Answer>
4. Где искать описание незнакомого метода?
   <Answer>В справочнике MDN: запрос вида «mdn» плюс имя метода.</Answer>
5. Что означает ошибка `Uncaught ReferenceError: summa is not defined`?
   <Answer>Использовано имя `summa`, которого движок не знает: переменная не объявлена
   или в имени опечатка.</Answer>
6. Почему после `console.log(3 + 5)` консоль пишет ещё и `undefined`?
   <Answer>Консоль показывает значение каждого выражения. `console.log` печатает 8,
   но сам ничего не возвращает — это «ничего» консоль и показывает как `undefined`.</Answer>
7. Почему `consol.log("тест")` даёт `ReferenceError`, а
   `console.lg("тест")` — `TypeError`?
   <Answer>В первом случае неизвестно само имя `consol`. Во втором имя
   `console` есть, но у него нет метода `lg`, и вызвать его как
   функцию нельзя.</Answer>
8. Зачем в теге `<script>` пишут `defer`?
   <Answer>Чтобы код выполнился после того, как браузер построит страницу. Иначе скрипт не найдёт
   элементы и получит `null`.</Answer>
