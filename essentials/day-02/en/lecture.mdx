## 1. What you need for work {#tools}

Yesterday we wrote code right in the browser console. That is handy for one line, but you cannot build a program
that way: close the tab and everything is gone. Today we set up the workplace we will live in for three months.

You need three things, and all of them are free:

| Tool | What for | Where to get it |
| --- | --- | --- |
| Browser | runs the code and shows the result | already installed: Chrome, Firefox, Edge |
| Code editor | to write and keep files | VS Code, code.visualstudio.com |
| A folder for your work | so that files do not get lost | you create it yourself, for example `D:\js-course` |

<Why>
Why not write code in Word or Notepad? Word adds invisible formatting to the text, and the browser
will not understand such a file. Notepad does not spoil code, but it does not help either: no highlighting,
no hints, no bracket checks. A code editor saves hours.
</Why>

## 2. The VS Code editor {#vscode}

VS Code is the most widely used editor for JavaScript. It is free, works on Windows, macOS
and Linux and, funnily enough, is itself written in JavaScript.

### Installation

<Step n="1">
Open `code.visualstudio.com` and click the big Download button. The site detects
your system by itself.
</Step>

<Step n="2">
Run the downloaded file. During installation, tick “Add to PATH” and “Open with Code” —
they let you open a folder in the editor with a right click.
</Step>

<Step n="3">
Open the editor and install the **Live Server** extension right away.
Extensions are installed from the left panel, the icon with squares.
</Step>

### How the window is laid out

<Scheme src="scheme-vscode.svg">Project files on the left, code on the right, the terminal at the bottom</Scheme>

A few keys that pay off on the very first day:

| Keys | What they do |
| --- | --- |
| <Kbd>Ctrl</Kbd> + <Kbd>S</Kbd> | save the file |
| <Kbd>Ctrl</Kbd> + <Kbd>Z</Kbd> | undo the last action |
| <Kbd>Ctrl</Kbd> + <Kbd>/</Kbd> | comment out a line |
| <Kbd>Alt</Kbd> + <Kbd>↑</Kbd> / <Kbd>↓</Kbd> | move a line up or down |
| <Kbd>Ctrl</Kbd> + <Kbd>D</Kbd> | select the next occurrence of the same word |
| <Kbd>Ctrl</Kbd> + <Kbd>F</Kbd> | find in the file |

<ProTip>
Turn on autosave: the menu File → Auto Save. Half of the “why doesn’t it work” questions in the first lessons
are solved by the fact that the file simply was not saved.
</ProTip>

### Three editor features that save time

**Autocomplete.** Start typing `cons` and the editor suggests
`console`; after the dot it shows a list of methods: `log`, `table`,
`warn`. You choose with the arrows and confirm with <Kbd>Tab</Kbd>. This is not only
faster but also protects you from typos like `consol`.

**A page template.** Create an empty `index.html`, type an exclamation
mark and press <Kbd>Tab</Kbd> — the editor expands a complete skeleton of an HTML page. This trick
is called Emmet, and it can also expand abbreviations like `ul>li*3` into a ready list.

**Formatting.** <Kbd>Shift</Kbd> + <Kbd>Alt</Kbd> +
<Kbd>F</Kbd> fixes the indentation in the whole file. Code with even indentation reads faster,
and bracket mistakes are visible at once.

<Analogy>
An editor is not a “fancy notepad” but a workshop. You can hold a hammer in your hand, but a workbench,
a vise and good light make the work different. In the first days the hints seem to get in the way;
a week later you will miss them.
</Analogy>

## 3. The first project: a folder and two files {#project}

A project is an ordinary folder. Let us agree from day one to keep order: a separate folder for each day
of the course, with clear file names inside.

<Scheme src="scheme-project.svg">The smallest project: a page and a script file in one folder</Scheme>

The file `index.html` is the page itself:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Day 2</title>
  <script src="app.js" defer></script>
</head>
<body>
  <h1>Checking the tools</h1>
</body>
</html>
```

Let us take this markup apart — it will be in every project from now on:

| Line | What for |
| --- | --- |
| `<!DOCTYPE html>` | tells the browser: this is a modern page |
| `<html lang="en">` | the wrapper of the whole page; the language helps search engines and translators |
| `<head>` | the service part: encoding, tab title, connected files |
| `<meta charset="UTF-8">` | the encoding; without it letters outside basic Latin turn into question marks |
| `<title>` | the text on the browser tab |
| `<script src="app.js" defer>` | connects the code file |
| `<body>` | the visible part of the page |

Tags come in pairs: an opening `<h1>` and a closing `</h1>`.
One pair can contain others — that is how a tree appears, which we will work with on day 24.
The course does not require deep knowledge of HTML, but you should be able to write these seven lines from memory.

The file `app.js` is the code:

```js
console.log("File connected");
```

### Comments

A comment is text for a person that the browser skips. There are two forms:

```js
// a one-line comment: up to the end of the line

/*
  a multi-line one:
  handy for explanations of several sentences
*/

const price = 12;   // it can also go at the end of a line
```

Comments are used for two things: to explain *why* something is done this way (what the code does is usually
visible anyway), and to switch a line off temporarily without deleting it. The second one will be needed all the time
in the lessons: <Kbd>Ctrl</Kbd> + <Kbd>/</Kbd> turns a line into a comment and back.

```js
console.log("first");
// console.log("second");   — switched off, the browser skips it
console.log("third");
// in the console: first, third
```

Open the page and press <Kbd>F12</Kbd> — the text “File connected” should appear
in the console. If it is not there, the script did not connect: check the file name, the folder and the
`<script>` line.

<Mistake>
A file name whose first letters are typed on the Cyrillic keyboard (<code><span lang="ru">арр</span>.js</code>) looks exactly like
`app.js`, but it will never be found. Capital letters are trickier: on Windows
`App.js` and `app.js` are one file, and Live Server serves it under either name.
But on many servers on the internet these are different names, and a page that worked for you will
break there. Name files in Latin letters, in lowercase, without spaces.
</Mistake>

### Three ways to put code on a page

Code can be written right in the markup, or it can be moved to a file. The difference matters, so let us look at all
three ways at once — you will meet all of them in other people’s examples.

```html
<!-- 1. Right in the markup: fine for one line -->
<script>
  console.log("I live inside the page");
</script>

<!-- 2. An external file at the end of body: the old way -->
<script src="app.js"></script>

<!-- 3. An external file with defer in head: this is how we do it -->
<script src="app.js" defer></script>
```

| Way | Plus | Minus |
| --- | --- | --- |
| in the markup | nothing to connect | code is mixed with layout and cannot be reused |
| a file at the end of `body` | the markup is already there | the browser reaches the script last |
| a file with `defer` | downloads at once, runs after the markup | you have to remember the word `defer` |

### How the browser loads a page

<Scheme src="scheme-project-2.svg">A script with defer downloads in parallel and runs when the page is built</Scheme>

Without `defer`, the browser meets `<script>` in the head, stops building
the page, downloads the file and runs it. The headings and buttons do not exist yet at that moment, so code
that looks for them finds nothing. Hence the course rule: **an external file, in `head`,
with the word `defer`**.

## 4. Why a page is opened through a server {#server}

You can open a page by double-clicking the file. Then the address bar shows `file:///D:/...`.
That is enough for the first lessons, but later the limits begin: the browser does not let such a page
load data and modules — for security reasons.

That is why people install the **Live Server** extension: right-click `index.html` →
“Open with Live Server”. The page opens at `http://127.0.0.1:5500`, that is,
from a small server on your own computer.

|  | Double click | Live Server |
| --- | --- | --- |
| Address | `file:///…` | `http://127.0.0.1:5500` |
| Refresh after saving | by hand, <Kbd>F5</Kbd> | by itself |
| Loading data, modules | the browser forbids it | works |

You can ask the page itself how it was opened:

```js
location.href;   // "http://127.0.0.1:5500/index.html" — opened through Live Server
// after a double click it would be: "file:///C:/Users/…/index.html"
```

<Highlight>
Get used to opening the project through Live Server from the start. Then on day 31, when we start getting data
from a server, you will not have to relearn anything.
</Highlight>

### What the address 127.0.0.1:5500 means

The address `127.0.0.1` always means “my own computer”. It also has a name made of words,
`localhost`. The number after the colon is the **port**, that is, the number of the door
behind which a particular program listens. By default Live Server sits at door 5500.

That is why a page opened this way behaves like a real website, although it needs no internet.
You can open it from this computer, and also from a phone on the same Wi-Fi network, by the computer’s
address in the network; we will use this on day 35. If the port is taken by another program, Live Server takes a neighbor —
5501, 5502, and the address in the browser changes.

<Mistake>
A classic mix-up of the first days: the page is opened with a double click (`file:///`),
and a student edits the file and waits for the page to refresh by itself. It will not. First look at the address
bar: if there is no `127.0.0.1` there, Live Server is not running.
</Mistake>

## 5. Developer tools {#devtools}

The developer tools (DevTools) open with <Kbd>F12</Kbd> or with
<Kbd>Ctrl</Kbd> + <Kbd>Shift</Kbd> + <Kbd>I</Kbd>,
and straight on the console tab with <Kbd>Ctrl</Kbd> + <Kbd>Shift</Kbd> +
<Kbd>J</Kbd>. It is a separate panel with tabs. Today we need two of them, but it is worth knowing about four.

| Tab | What for | When you will need it |
| --- | --- | --- |
| Elements | the page markup and styles; you can change them right there | days 24–26 |
| Console | the program output and running code | today and always |
| Sources | script files, breakpoints, step-by-step execution | today, in the second half |
| Network | requests to the server: what went out and what came back | day 31 |

<ProTip>
The panel can be docked on the right, at the bottom or moved to a separate window: the three dots in the corner of DevTools →
Dock side. On a small laptop a separate window is more convenient.
</ProTip>

### The Elements tab: touch the page with your hands

Open Elements and click any heading on the page. Its styles appear on the right, and the text itself
can be changed with a double click right in the markup. The page is redrawn at once.

It is important to understand: these changes are **temporary**. You are editing not the file but what is
shown in the browser right now. Reload the page and everything comes back. But you can check an idea in a second: what if
the heading were red? What if the picture were removed?

<TryIt>
Open this lecture, switch to Elements, find the heading of the day and change its text to your name.
Then press <Kbd>F5</Kbd> and make sure the file is not damaged.
</TryIt>

### Phone mode

DevTools has an icon with a phone and a tablet (<Kbd>Ctrl</Kbd> +
<Kbd>Shift</Kbd> + <Kbd>M</Kbd>). It shows the page as it will look
on a phone and lets you choose the screen size.

For our course this is especially important: students read the notes and tasks on a phone more often than at
a computer. Every time you do something with a page, check it in this mode —
the habit will save you a lot of rework.

### The Sources tab: your files

This is where all the files the page loaded live. On the left is the file tree, in the middle the code, on the right
the debugging panel, which we will come back to at the end of the lecture. The main thing to know now: if your
`app.js` is not here, it did not connect.

## 6. The console: printing data {#console}

The `console` object is a set of commands for output. The best known of them is `log`,
but the others save time too.

```js
console.log("an ordinary message");
console.info("information");
console.warn("a warning");   // a yellow line
console.error("an error");   // a red line
```

The difference between them is not only the color. The console has a filter by levels: you can show only errors
and warnings and hide ordinary messages. In a big program this is a lifesaver.

If you pass `console.error` not a string but an error object, the console also shows the place
where the error was created:

```js
console.error(new Error("file not found"));
// Error: file not found
//     at <anonymous>:1:15   — line 1, character 15 of what you typed into the console
```

`log` takes any number of values separated by commas and prints them in a row:

```js
const name = "Aman";
const marks = [5, 4, 5];

console.log("Student:", name, "marks:", marks);
// Student: Aman marks: (3) [5, 4, 5]
```

<Mistake>
Do not join values with a plus without a reason: `console.log("marks: " + marks)` turns the array
into the string `"5,4,5"`, and you lose the chance to expand it in the console. A comma is better than a plus.
</Mistake>

### Tables and objects

When there is a lot of data, ordinary output turns into a mess. The `console.table` method draws a real
table:

```js
const students = [
  { name: "Aman", mark: 5 },
  { name: "Meret", mark: 4 },
  { name: "Gülnar", mark: 5 },
];

console.table(students);
```

We will study objects on day 21, but you can use the table right now: it shows arrays and lists
of objects equally well. MDN calls the first column `(index)` — that is the row number.
For a simple array the second column holds the values themselves:

```js
console.table(["bread", "tea"]);   // two rows: 0 — bread, 1 — tea
```

When there are too many columns, list only the ones you need as the second argument:

```js
console.table(students, ["name"]);   // a table with only the name column
```

The `console.dir` method shows a value as a tree of properties. For ordinary data there is almost no
difference from `log`, but for a page element the difference is big: `log` shows the markup,
and `dir` shows all the properties of the object.

```js
console.log(document.body);   // markup
console.dir(document.body);   // the object's properties
```

### The trap of expanding objects

When you print an object or an array to the console, a triangle appears next to it: you can expand it and look at
the contents. But there is a subtlety that costs beginners hours.

```js
const cart = ["bread"];
console.log(cart);     // in the console: ["bread"] — but expand it later...
cart.push("tea");      // ...and you will see two elements
```

The console shows not a snapshot taken at the moment of output but the live object: the contents are loaded
when you expand the line. If the array changed later, you will see the new state and decide
that the code worked wrong.

How to get an honest snapshot:

```js
console.log(cart.join(", "));        // a string — it will not change
console.log(structuredClone(cart));  // a copy of the object
console.table(cart);                 // the table is drawn at once
console.log(JSON.parse(JSON.stringify(cart)));   // the way MDN advises: a copy through JSON, day 23
```

### Substitutions: neat output

Values can be inserted into an output string with special signs. They are called substitutions:

```js
const name = "Aman";
const mark = 5;

console.log("Student %s got %d", name, mark);
// Student Aman got 5

console.log("%cImportant message", "color: white; background: #f59e0b; padding: 2px 8px;");
```

| Sign | What it inserts |
| --- | --- |
| `%s` | text |
| `%d` or `%i` | a whole number |
| `%f` | a fractional number |
| `%o` | an object |
| `%c` | a style for the text that follows |

Each substitution takes the next value from the list. An example based on MDN:

```js
for (let i = 0; i < 3; i++) {
  console.log("Hello, %s! Call number %d.", "Aman", i + 1);
}
// Hello, Aman! Call number 1.
// Hello, Aman! Call number 2.
// Hello, Aman! Call number 3.
```

Libraries use the `%c` trick to highlight their messages with color. Sometimes it is used for a warning
in the console: “do not paste other people’s code here” — exactly what we talked about yesterday.

### What the console itself can do

Besides the methods of the `console` object, a few commands of the browser itself work in the console.
You cannot write them in a file — only in the console:

| Command | What it does |
| --- | --- |
| `$0` | the element selected right now in the Elements tab |
| `$_` | the result of the previous line |
| `copy(value)` | copies the value to the clipboard |
| arrow <Kbd>↑</Kbd> | repeat the previous command |
| <Kbd>Shift</Kbd> + <Kbd>Enter</Kbd> | a new line without running |

```js
2 + 2;     // 4
$_ * 10;   // 40 — $_ remembers the result of the previous line
```

## 7. Groups, time and counters {#groups}

Three tools that beginners usually do not know about, and they solve three common tasks.

### Groups: fold away the extra

```js
console.group("Checking marks");
console.log("Aman: 5");
console.log("Meret: 4");
console.groupEnd();

console.groupCollapsed("Details");  // the group starts folded
console.log("a long list...");
console.groupEnd();
```

Groups nest inside each other, and every open group shifts messages to the right.
An example based on MDN:

```js
console.log("outside");
console.group("First group");
console.log("inside the first");
console.group("Second group");
console.log("inside the second");
console.warn("still in the second");
console.groupEnd();
console.log("back in the first");
console.groupEnd();
console.log("back outside");
```

Each `groupEnd` closes one group — the last one opened. Forget it, and all
the following messages end up inside.

### Time: how long it took

```js
console.time("counting");
let sum = 0;
for (let i = 0; i < 1000000; i++) {
  sum = sum + i;
}
console.timeLog("counting");   // an intermediate mark
console.timeEnd("counting");   // counting: 5.2 ms
```

The name in quotes links the start and the end. The time in the example is just a sample: every computer
and every run has its own. MDN shows a funny measurement: how long a person thinks before clicking “OK”.

```js
console.time("answer");
alert("Click OK");
console.timeLog("answer");   // answer: … ms — how long the first window lasted
alert("And once more");
console.timeEnd("answer");   // answer: … ms — all together
```

There can be several measurements at the same time if the names are different:

```js
console.time("all");
console.time("loop");
for (let i = 0; i < 100000; i++) {}
console.timeEnd("loop");   // loop: … ms
console.timeEnd("all");    // all: … ms — a bit more, “loop” is inside it
```

The console notices a typo in the name by itself:

```js
console.timeEnd("no such timer");   // a yellow warning: Timer 'no such timer' does not exist
```

### Counters: how many times we got here

```js
function greet(name) {
  console.count("greet calls");
  console.log("Hello, " + name);
}

greet("Aman");    // greet calls: 1
greet("Meret");   // greet calls: 2
console.countReset("greet calls");
```

This helps when a function is called more often than you expected — a common cause of a “slow” page.
Without a name the counter is called `default`, and each name has its own count:

```js
console.count();           // default: 1
console.count();           // default: 2
console.count("button");   // button: 1
```

```js
console.countReset("button");
console.count("button");   // button: 1 — the count started over
```

### Checks and the call trace

```js
const age = 15;
console.assert(age >= 18, "age is under 18");   // prints only if the condition is false

console.trace();     // shows where this line was called from
console.clear();     // clear the console
```

`assert` stays silent while the condition is true and writes a red line when it is false:

```js
console.assert(2 + 2 === 4, "math is broken");   // silence: the condition is true
console.assert(2 + 2 === 5, "this cannot happen");   // a red line “this cannot happen”
```

`trace` is useful when a line can be reached in different ways. An example based on MDN:

```js
function outer() {
  function inner() {
    console.trace();
  }
  inner();
}
outer();
// console.trace, and below it the chain: inner, outer — who called whom
```

Two more methods you will meet in other people’s code: `console.debug` — the same as `log`,
but at the “verbose” level, and `console.dirxml` — markup output as a tree. You do not have to use them,
but it helps to recognize them.

### Which method to choose

When there are many methods, a reverse table helps — from the task to the method:

| You need to… | Method |
| --- | --- |
| look at a value | `console.log` |
| see a whole list of objects | `console.table` |
| look at the properties of a page element | `console.dir` |
| find out how many times a line ran | `console.count` |
| find out how long the work took | `console.time` and `console.timeEnd` |
| check a condition silently | `console.assert` |
| find out who called a line | `console.trace` |
| hide details | `console.groupCollapsed` |
| point out trouble | `console.warn`, `console.error` |

## 8. Debugging: debugger and breakpoints {#debug}

Printing to the console is not the only way to understand what is going on. A program can be **stopped**
at the right line so that you can look around: what values are in the variables right now.

The first way is the word `debugger` right in the code:

```js
const price = 12;
const count = 7;

debugger;   // the program stops here if DevTools are open

const total = price * count;
console.log(total);
```

Open the page with DevTools open — execution freezes on this line, and a list of variables
with their values appears on the right. Then the buttons work: continue, step forward, step into a function.

The second way is more convenient: the **Sources** tab, open your file and click a line number.
A blue marker appears — this is a **breakpoint**. It needs no code and disappears
after the browser is closed.

A breakpoint in Sources has two useful variants — both through a right click on the line number.
A **conditional** one (*Add conditional breakpoint*) stops only when the condition
is true: in a loop of a hundred steps you can stop right at the one you need, for example at
`i === 57`. A **logpoint** (*Add logpoint*) stops nothing
but prints to the console what you write into it — like `console.log`, only without editing
the file.

<Important>
Do not forget to remove `debugger` from the code before you show your work. A line left
in the project will stop the program for everyone who opens the page with the developer tools.
</Important>

### Walkthrough: the average does not add up

The function should calculate the average of three marks, 5, 4 and 3 — that is 4. But it gives something else:

```js
function average(marks) {
  let sum = 0;
  for (let i = 1; i < marks.length; i++) {
    sum = sum + marks[i];
  }
  return sum / marks.length;
}
average([5, 4, 3]);   // 2.3333333333333335 — but we expected 4
```

There is no need to guess which line is to blame. Put `debugger;` as the first line inside the
loop and call the function again. At the first stop the Scope panel shows `i: 1` and
`sum: 0`: the loop started at index 1, and the first mark, the five, did not get into the sum.
We fix the start of the loop to `let i = 0` and remove `debugger`:

```js
// the same function, but the loop starts with let i = 0
average([5, 4, 3]);   // 4
```

Loops come in detail on day 10, but the technique is worth remembering now: stop, look at the
values and compare them with what you expected.

### Debugger buttons

When the program is stopped, control buttons appear at the top of the panel. There are four, and all of them are needed:

| Button | What it does | When to press it |
| --- | --- | --- |
| ▶ Resume | run on until the next stop | you have looked — go on |
| ↷ Step over | run the current line as a whole | an ordinary walk through the program |
| ↧ Step into | go inside a function | you suspect the function |
| ↥ Step out | finish the function and come back | you went into the wrong place |

To the right of the buttons there are three useful lists. **Scope** — the variables visible at this place,
with their current values. **Watch** — expressions you asked to follow: add
`price * count` there, and you will see the result at every step. **Call Stack** — the chain of calls:
which function called which to get here.

<Why>
Why this, if there is `console.log`? Printing to the console shows one value at one point.
The debugger shows all the variables at once and lets you walk through the program step by step. When an error
is unclear, the debugger finds it in a minute, while with “logs” you can search for it for an hour.
</Why>

## 9. What to do when “nothing works” {#trouble}

A sequence of steps that solves nine problems out of ten in the first week:

<Step n="1">
**Look at the console.** A red line says what is wrong and on which line.
</Step>

<Step n="2">
**Check that the file is saved.** In VS Code an unsaved file is marked with a dot
on its tab.
</Step>

<Step n="3">
**Reload the page and clear the cache:** <Kbd>Ctrl</Kbd> +
<Kbd>F5</Kbd>. Browsers like to show an old version of a file.
</Step>

<Step n="4">
**Make sure the script is connected.** Put
`console.log("the file works")` as the first line. No message — the problem is in connecting, not in the code.
</Step>

<Step n="5">
**Read the file name and the path letter by letter.** An extra space or a Cyrillic
«<span lang="ru">с</span>» instead of a Latin «c» — and the file will not be found.
</Step>

### How to see that a file is not found

There is an exact way to check the connection: the **Network** tab. Open it and reload
the page — a list of everything the browser requested appears. Look for the `app.js` line:

| Status | What it means | What to do |
| --- | --- | --- |
| `200` | the file is found and loaded | all is well; the problem is in the code itself |
| `404` | there is no file at this path | check the name and the folder |
| no line at all | the browser did not even request it | check the `<script>` line in the markup |

These three states cover almost all connection problems. Once you get used to looking at Network,
you will stop guessing.

A missing file is also visible in the console — as two red lines:

```js
// in index.html they wrote apps.js instead of app.js:
// Failed to load resource: the server responded with a status of 404 (Not Found)
// Refused to execute script from 'http://127.0.0.1:5500/apps.js' because its MIME type ('text/html') is not executable, and strict MIME type checking is enabled.
```

The first line says there is no file, the answer is 404. The second says that instead of the file Live Server sent a
“not found” page, and the browser refused to run it as a script. When you see this pair, check the file name in
`<script>`.

You can ask the page itself which address it tried to load:

```js
document.scripts[0].src;   // "http://127.0.0.1:5500/apps.js" — there it is, the typo
document.scripts.length;   // 2 — Live Server added the second script itself to refresh the page
```

<FunFact>
The number 404 became known far beyond programming: it is printed on T-shirts and written
on “nothing found” pages. It is just a server response code: “I have no such address”.
</FunFact>

<Cheatsheet>
```js
console.log("text", value);       // ordinary output
console.warn("careful");          // in yellow
console.error("it broke");        // in red
console.table(array);             // as a table

console.group("section");         // a group
console.groupEnd();

console.time("label");            // time measurement
console.timeEnd("label");

console.count("got here");        // a counter
console.trace();                  // who called this line
console.assert(condition, "text"); // if the condition is false
console.clear();                  // clear

debugger;                         // stop here
```

Connecting a script: `<script src="app.js" defer></script>` in `<head>`.
</Cheatsheet>

<Selfcheck>
1. How is `console.warn` different from `console.log`?
   <Answer>In color and level: warnings can be filtered in the console separately from ordinary messages.</Answer>
2. How do you show a list of students with their marks nicely?
   <Answer>`console.table(students)` — it prints a table with columns.</Answer>
3. Why do you need Live Server if a page opens with a double click?
   <Answer>It refreshes the page by itself and opens it at an `http://` address, not
   `file://`: otherwise the browser forbids loading data and modules.</Answer>
4. What does the `debugger` line do?
   <Answer>It stops execution at this place if the developer tools are open,
   and lets you look at the values of the variables.</Answer>
5. What is the first thing to do when “nothing works”?
   <Answer>Look at the console and read the error text, then check that the file is saved.</Answer>
</Selfcheck>
