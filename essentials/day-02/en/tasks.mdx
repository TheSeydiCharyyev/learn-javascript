# Day 2. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Today there is a lot of hands-on work: we install the editor, build a project and learn the console. Keep all files in the folder `day-02`.</Subtitle>

## Warm-up

<Task title="1. The workplace" level="easy" time="7">
<Goal>install the editor and create the course folder.</Goal>

Install VS Code and the Live Server extension. Create a course folder and inside it a folder
`day-02`. Open it in the editor: File → Open Folder.

<Criteria>
- the folder name `day-02` is visible in the left panel of the editor;
- the Live Server extension is installed;
- autosave is on (File → Auto Save).
</Criteria>
</Task>

<Task title="2. A page and a script" level="easy" time="7">
<Goal>connect a script file to a page.</Goal>

Create `index.html` and `app.js`. On the page — the heading “Day 2” and the script
connected with `defer`. In the script — the output “File connected”. Open the page through Live Server.

<Criteria>
- the address bar shows `http://127.0.0.1:5500`, not `file:///`;
- the text is visible in the console;
- after changing the text and saving, the page refreshed by itself.
</Criteria>
</Task>

<Task title="3. Four message levels" level="easy" time="6">
<Goal>see the difference between log, info, warn and error.</Goal>

Print one message with each of the four methods. Then find the level filter in the console
and leave only errors and warnings.

<Hint>
The level filter is a drop-down list above the console messages, to the right of the search box.
</Hint>

<Criteria>
- four messages are printed;
- the filter managed to hide ordinary messages;
- the color of each level is written down.
</Criteria>
</Task>

## Main tasks

<Task title="4. A table of marks" level="medium" time="13">
<Goal>show a list of data in a readable way.</Goal>

Make a list of five students with marks and print it in two ways: with an ordinary
`console.log` and with `console.table`. Compare which is easier to read.

<Example>
```js
const students = [
  { name: "Aman", mark: 5 },
  { name: "Meret", mark: 4 },
];
console.table(students);
```
</Example>

<Criteria>
- the table has five rows and two columns;
- a conclusion is written down: in which case a table is more convenient than ordinary output.
</Criteria>
</Task>

<Task title="5. Groups of messages" level="medium" time="13">
<Goal>bring order to long output.</Goal>

Print a timetable for three days: each day is its own group with three subjects inside.
Make one of the days folded from the start.

<Hint>
A folded group is opened with `console.groupCollapsed` and closed the same way —
with `console.groupEnd`.
</Hint>

<Criteria>
- three groups with three lines each;
- one group is folded when the page opens;
- the groups open and fold with a click.
</Criteria>
</Task>

<Task title="6. Measuring time" level="medium" time="12">
<Goal>measure instead of guessing.</Goal>

Measure the time of two loops: one of a hundred thousand steps and one of ten million. Print both results
and compare them. Inside the loop, add the numbers into a variable.

<Example>
```js
console.time("small");
let sum = 0;
for (let i = 0; i < 100000; i++) { sum = sum + i; }
console.timeEnd("small");
```
</Example>

<Criteria>
- both measurements are printed with different label names;
- it is written down how many times slower the second loop is;
- it is explained why the time differs a little between runs.
</Criteria>
</Task>

<Task title="7. A call counter" level="medium" time="12">
<Goal>find out how many times a piece of code runs.</Goal>

Write a greeting function that calls `console.count` inside. Call it
five times with different names, then reset the counter and call it twice more.

<Criteria>
- the counter reached 5, was reset and started counting again;
- it is written down what the console says if you reset a counter that did not exist yet;
- `console.countReset` is used.
</Criteria>
</Task>

## Starred tasks

<Task title="8. Stop and look around" level="hard" time="10">
<Goal>work with a breakpoint.</Goal>

Write code that calculates the cost of a purchase: price, quantity, discount. Put a breakpoint
before the total is calculated — by clicking the line number in the Sources tab. Reload the page and look at the
values of the variables. Then walk through the program step by step to the end.

<Hint>
The control buttons are above the list of variables: resume, step over a line, step into.
</Hint>

<Criteria>
- the program stops at the right line;
- the values of all variables at the moment of the stop are written down;
- the same is repeated with the word `debugger` in the code, and then the line is removed.
</Criteria>
</Task>

<Task title="9. Break it and fix it" level="hard" time="10">
<Goal>learn to read errors and the order of steps when something breaks.</Goal>

Break your project in three ways, one at a time, each time writing down the error text from the console
and how you found it:

1. change the file name in the connection to `apps.js`;
2. write `consol.log("test")`, without the final “e”;
3. remove the closing quote in a string.

<Criteria>
- the error text is written down for each breakage;
- it is noted on which line the browser found the problem;
- the project works again after all three fixes;
- the name `App.js` with a capital letter is checked separately, and it is written down why it
  worked on Windows.
</Criteria>
</Task>
