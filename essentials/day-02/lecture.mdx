## 1. Что нужно для работы {#tools}

Вчера мы писали код прямо в консоли браузера. Это удобно для одной строки, но программу так не соберёшь:
закрыли вкладку — всё пропало. Сегодня заведём рабочее место, в котором будем жить три месяца.

Нужны три вещи, и все они бесплатные:

| Инструмент | Зачем | Где взять |
| --- | --- | --- |
| Браузер | выполняет код и показывает результат | уже установлен: Chrome, Firefox, Edge |
| Редактор кода | писать и хранить файлы | VS Code, code.visualstudio.com |
| Папка для работ | чтобы файлы не терялись | создаёте сами, например `D:\js-kurs` |

<Why>
Почему нельзя писать код в Word или в «Блокноте»? Word добавляет в текст невидимое оформление, и браузер
такой файл не поймёт. «Блокнот» кода не портит, но и не помогает: нет подсветки, нет подсказок,
нет проверки скобок. Редактор кода экономит часы.
</Why>

## 2. Редактор VS Code {#vscode}

VS Code — самый распространённый редактор для JavaScript. Он бесплатный, работает на Windows, macOS
и Linux и, что забавно, сам написан на JavaScript.

### Установка

<Step n="1">
Откройте `code.visualstudio.com` и нажмите большую кнопку Download. Сайт сам определит
вашу систему.
</Step>

<Step n="2">
Запустите скачанный файл. При установке поставьте галочки «Add to PATH» и «Open with Code» —
они позволят открывать папку в редакторе правой кнопкой мыши.
</Step>

<Step n="3">
Откройте редактор и сразу поставьте два расширения: **Live Server**
и **Russian Language Pack**, если нужен русский интерфейс. Расширения ставятся
из левой панели, значок с квадратиками.
</Step>

### Как устроено окно

<Scheme src="scheme-vscode.svg">Слева файлы проекта, справа код, снизу терминал</Scheme>

Несколько клавиш, которые окупятся в первый же день:

| Клавиши | Что делают |
| --- | --- |
| <Kbd>Ctrl</Kbd> + <Kbd>S</Kbd> | сохранить файл |
| <Kbd>Ctrl</Kbd> + <Kbd>Z</Kbd> | отменить последнее действие |
| <Kbd>Ctrl</Kbd> + <Kbd>/</Kbd> | закомментировать строку |
| <Kbd>Alt</Kbd> + <Kbd>↑</Kbd> / <Kbd>↓</Kbd> | переместить строку вверх или вниз |
| <Kbd>Ctrl</Kbd> + <Kbd>D</Kbd> | выделить следующее такое же слово |
| <Kbd>Ctrl</Kbd> + <Kbd>F</Kbd> | найти в файле |

<ProTip>
Включите автосохранение: меню File → Auto Save. Половина вопросов «почему не работает» на первых занятиях
решается тем, что файл просто не сохранён.
</ProTip>

### Три возможности редактора, которые экономят время

**Автодополнение.** Начните печатать `cons` — редактор предложит
`console`, затем после точки покажет список методов: `log`, `table`,
`warn`. Выбирается стрелками, подтверждается <Kbd>Tab</Kbd>. Это не только быстрее,
но и защищает от опечаток вроде `consol`.

**Заготовка страницы.** Создайте пустой `index.html`, напечатайте восклицательный
знак и нажмите <Kbd>Tab</Kbd> — редактор развернёт полный каркас HTML-страницы. Этот приём
называется Emmet, и он же умеет разворачивать сокращения вроде `ul>li*3` в готовый список.

**Форматирование.** <Kbd>Shift</Kbd> + <Kbd>Alt</Kbd> +
<Kbd>F</Kbd> выравнивает отступы во всём файле. Код с ровными отступами читается быстрее,
а ошибки со скобками видно сразу.

<Analogy>
Редактор — это не «продвинутый блокнот», а мастерская. Молоток можно держать в руке, но верстак,
тиски и хорошее освещение делают работу другой. Первые дни кажется, что подсказки мешают;
через неделю без них будет неудобно.
</Analogy>

## 3. Первый проект: папка и два файла {#project}

Проект — это обычная папка. Договоримся с первого дня держать порядок: на каждый день курса своя папка,
внутри понятные имена файлов.

<Scheme src="scheme-project.svg">Минимальный проект: страница и файл со скриптом в одной папке</Scheme>

Файл `index.html` — это сама страница:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>День 2</title>
  <script src="app.js" defer></script>
</head>
<body>
  <h1>Проверка инструментов</h1>
</body>
</html>
```

Разберём эту разметку по частям — дальше она будет в каждом проекте:

| Строка | Зачем |
| --- | --- |
| `<!DOCTYPE html>` | говорит браузеру: это современная страница |
| `<html lang="ru">` | обёртка всей страницы; язык нужен поиску и переводчику |
| `<head>` | служебная часть: кодировка, заголовок вкладки, подключения |
| `<meta charset="UTF-8">` | кодировка; без неё кириллица превратится в знаки вопроса |
| `<title>` | надпись на вкладке браузера |
| `<script src="app.js" defer>` | подключение файла с кодом |
| `<body>` | видимая часть страницы |

Теги пишутся парами: открывающий `<h1>` и закрывающий `</h1>`.
Внутри одной пары могут лежать другие — так получается дерево, с которым мы будем работать на дне 24.
Глубокого знания HTML курс не требует, но эти семь строк надо уметь написать по памяти.

Файл `app.js` — код:

```js
console.log("Файл подключён");
```

### Комментарии

Комментарий — это текст для человека, который браузер пропускает. Две формы:

```js
// однострочный комментарий: до конца строки

/*
  многострочный:
  удобен для пояснений в несколько предложений
*/

const price = 12;   // можно и в конце строки
```

Комментариями пользуются для двух вещей: объяснить, *почему* сделано так (что делает код, обычно
и так видно), и временно отключить строку, не удаляя её. Второе на занятиях пригодится постоянно:
<Kbd>Ctrl</Kbd> + <Kbd>/</Kbd> превращает строку в комментарий и обратно.

```js
console.log("первая");
// console.log("вторая");   — отключена, браузер её пропустит
console.log("третья");
// в консоли: первая, третья
```

Откройте страницу, нажмите <Kbd>F12</Kbd> — в консоли должна появиться надпись
«Файл подключён». Если её нет, значит, скрипт не подключился: проверьте имя файла, папку и строку
`<script>`.

<Mistake>
Имя файла, в котором первые буквы русские (`арр.js`), выглядит точно как
`app.js`, но не найдётся никогда. С большими буквами коварнее: на Windows
`App.js` и `app.js` — один файл, и Live Server отдаст его под любым именем.
А на многих серверах в интернете это разные имена, и страница, которая работала у вас, там
сломается. Называйте файлы латиницей, маленькими буквами, без пробелов.
</Mistake>

### Три способа положить код на страницу

Код можно написать прямо в разметке, а можно вынести в файл. Разница важная, поэтому разберём все три
способа сразу — в чужих примерах встретятся все.

```html
<!-- 1. Прямо в разметке: годится для одной строки -->
<script>
  console.log("я живу внутри страницы");
</script>

<!-- 2. Внешний файл в конце body: старый способ -->
<script src="app.js"></script>

<!-- 3. Внешний файл с defer в head: так делаем мы -->
<script src="app.js" defer></script>
```

| Способ | Плюс | Минус |
| --- | --- | --- |
| в разметке | ничего не надо подключать | код мешается с вёрсткой, его нельзя переиспользовать |
| файл в конце `body` | разметка уже готова | браузер добирается до скрипта последним |
| файл с `defer` | скачивается сразу, выполняется после разметки | нужно помнить про слово `defer` |

### Как браузер загружает страницу

<Scheme src="scheme-project-2.svg">Скрипт с defer скачивается параллельно, а выполняется, когда страница построена</Scheme>

Без `defer` браузер, встретив `<script>` в шапке, останавливает построение
страницы, скачивает файл и выполняет его. Заголовков и кнопок в этот момент ещё нет, поэтому код,
который их ищет, ничего не находит. Отсюда правило курса: **внешний файл, в `head`,
со словом `defer`**.

## 4. Почему страницу открывают через сервер {#server}

Страницу можно открыть двойным щелчком по файлу. В адресной строке тогда будет `file:///D:/...`.
Для первых уроков этого хватает, но дальше начнутся ограничения: браузер запрещает такой странице
загружать данные и модули — из соображений безопасности.

Поэтому ставят расширение **Live Server**: правой кнопкой по `index.html` →
«Open with Live Server». Страница откроется по адресу `http://127.0.0.1:5500`, то есть
с маленького сервера на вашем же компьютере.

|  | Двойной щелчок | Live Server |
| --- | --- | --- |
| Адрес | `file:///…` | `http://127.0.0.1:5500` |
| Обновление после сохранения | вручную, <Kbd>F5</Kbd> | сама |
| Загрузка данных, модули | браузер запрещает | работает |

Как открыта страница, можно спросить у неё самой:

```js
location.href;   // "http://127.0.0.1:5500/index.html" — открыта через Live Server
// после двойного щелчка было бы: "file:///C:/Users/…/index.html"
```

<Highlight>
Привыкайте сразу открывать проект через Live Server. Тогда на дне 31, когда мы начнём получать данные
с сервера, ничего не придётся переучивать.
</Highlight>

### Что означает адрес 127.0.0.1:5500

Адрес `127.0.0.1` — это всегда «мой собственный компьютер». У него есть и словесное имя,
`localhost`. Число после двоеточия — **порт**, то есть номер двери, за которой
слушает конкретная программа. Live Server по умолчанию садится на дверь 5500.

Поэтому страница, открытая так, ведёт себя как настоящий сайт, хотя никакого интернета не требует.
Открыть её можно с этого компьютера, а ещё — с телефона в той же сети Wi-Fi, по адресу
компьютера в сети; этим мы воспользуемся на дне 35. Если порт занят другой программой, Live Server возьмёт соседний —
5501, 5502, и адрес в браузере изменится.

<Mistake>
Классическая путаница первых дней: страница открыта двойным щелчком (`file:///`),
а студент правит файл и ждёт, что она обновится сама. Не обновится. Сначала посмотрите в адресную
строку: если там нет `127.0.0.1`, значит, Live Server не запущен.
</Mistake>

Инструменты разработчика (DevTools) открываются клавишей <Kbd>F12</Kbd> или сочетанием
<Kbd>Ctrl</Kbd> + <Kbd>Shift</Kbd> + <Kbd>I</Kbd>,
а сразу на вкладке консоли — <Kbd>Ctrl</Kbd> + <Kbd>Shift</Kbd> +
<Kbd>J</Kbd>. Это отдельная панель с вкладками. Сегодня нам нужны две, но знать стоит про четыре.

| Вкладка | Для чего | Когда пригодится |

### Вкладка Elements: потрогать страницу руками

Откройте Elements и щёлкните по любому заголовку на странице. Справа появятся его стили, а сам текст
можно изменить двойным щелчком прямо в разметке. Страница сразу перерисуется.

Важно понимать: эти изменения **временные**. Вы правите не файл, а то, что сейчас показано
в браузере. Обновите страницу — всё вернётся. Зато можно за секунду проверить идею: а если заголовок сделать
красным? А если убрать картинку?

<TryIt>
Откройте эту лекцию, включите Elements, найдите заголовок дня и поменяйте его текст на своё имя.
Затем нажмите <Kbd>F5</Kbd> и убедитесь, что файл не пострадал.
</TryIt>

### Режим телефона

В DevTools есть значок с телефоном и планшетом (<Kbd>Ctrl</Kbd> +
<Kbd>Shift</Kbd> + <Kbd>M</Kbd>). Он показывает страницу так, как её увидят
с телефона, и позволяет выбрать размер экрана.

Для нашего курса это особенно важно: конспекты и задания студенты чаще читают с телефона, а не за
компьютером. Каждый раз, когда вы что-то делаете со страницей, проверяйте её в этом режиме —
привычка сэкономит много переделок.

### Вкладка Sources: ваши файлы

Здесь лежат все файлы, которые загрузила страница. Слева дерево файлов, посередине — код, справа —

## 6. Консоль: вывод данных {#console}

Объект `console` — это набор команд для вывода. Самая известная из них — `log`,
но остальные тоже экономят время.

```js
console.log("обычное сообщение");
console.info("информация");
console.warn("предупреждение");   // жёлтая строка
console.error("ошибка");          // красная строка
```

Разница между ними не только в цвете. В консоли есть фильтр по уровням: можно показать только ошибки
и предупреждения, спрятав обычные сообщения. В большой программе это спасает.

Если передать в `console.error` не строку, а объект ошибки, консоль покажет ещё и место,
где ошибку создали:

```js
console.error(new Error("не нашли файл"));
// Error: не нашли файл
//     at <anonymous>:1:15   — строка 1, символ 15 того, что вы ввели в консоль
```

`log` принимает сколько угодно значений через запятую и печатает их подряд:

```js
const name = "Аман";
const marks = [5, 4, 5];

console.log("Ученик:", name, "оценки:", marks);
// Ученик: Аман оценки: (3) [5, 4, 5]
```

<Mistake>
Не склеивайте значения плюсом без нужды: `console.log("оценки: " + marks)` превратит массив
в строку `"5,4,5"`, и вы потеряете возможность раскрыть его в консоли. Запятая лучше плюса.
</Mistake>

### Таблицы и объекты

Когда данных много, обычный вывод превращается в кашу. Метод `console.table` рисует настоящую
таблицу:

```js
const students = [
  { name: "Аман", mark: 5 },
  { name: "Мерет", mark: 4 },
  { name: "Гүлнар", mark: 5 },
];

console.table(students);
```

Объекты мы будем разбирать на дне 21, но пользоваться таблицей можно уже сейчас: она одинаково хорошо
показывает и массивы, и списки объектов. Первый столбец MDN называет `(index)` — это номер
строки. У простого массива второй столбец — сами значения:

```js
console.table(["хлеб", "чай"]);   // две строки: 0 — хлеб, 1 — чай
```

Когда столбцов слишком много, вторым аргументом перечисляют только нужные:

```js
console.table(students, ["name"]);   // таблица только со столбцом name
```

Метод `console.dir` показывает значение как дерево свойств. Для обычных данных разницы
с `log` почти нет, а вот для элемента страницы разница большая: `log` покажет разметку,
а `dir` — все свойства объекта.

```js
console.log(document.body);   // разметка
console.dir(document.body);   // свойства объекта
```

### Ловушка с раскрытием объектов

Когда в консоль выводят объект или массив, рядом появляется треугольник: его можно раскрыть и посмотреть
содержимое. Но есть тонкость, из-за которой новички теряют часы.

```js
const cart = ["хлеб"];
console.log(cart);     // в консоли: ["хлеб"]  — но раскройте позже...
cart.push("чай");      // ...и увидите два элемента
```

Консоль показывает не снимок, сделанный в момент вывода, а живой объект: содержимое подтягивается,
когда вы раскрываете строку. Если массив изменился позже, вы увидите уже новое состояние и решите,
что код сработал не так.

Как получить честный снимок:

```js
console.log(cart.join(", "));        // строка — уже не изменится
console.log(structuredClone(cart));  // копия объекта
console.table(cart);                 // таблица рисуется сразу
console.log(JSON.parse(JSON.stringify(cart)));   // способ, который советует MDN: копия через JSON, день 23
```

### Подстановки: аккуратный вывод

В строку вывода можно вставить значения через специальные знаки. Их называют подстановками:

```js
const name = "Аман";
const mark = 5;

console.log("Ученик %s получил %d", name, mark);
// Ученик Аман получил 5

console.log("%cВажное сообщение", "color: white; background: #f59e0b; padding: 2px 8px;");
```

| Знак | Что вставляет |
| --- | --- |
| `%s` | текст |
| `%d` или `%i` | целое число |
| `%f` | дробное число |
| `%o` | объект |
| `%c` | стиль для следующего текста |

Каждая подстановка забирает следующее значение из списка. Пример по мотивам MDN:

```js
for (let i = 0; i < 3; i++) {
  console.log("Привет, %s! Вызов номер %d.", "Аман", i + 1);
}
// Привет, Аман! Вызов номер 1.
// Привет, Аман! Вызов номер 2.
// Привет, Аман! Вызов номер 3.
```

Приём с `%c` используют библиотеки, чтобы выделять свои сообщения цветом. Иногда им
предупреждают в консоли: «не вставляйте сюда чужой код» — как раз то, о чём мы говорили вчера.

### Что ещё умеет сама консоль

Кроме методов объекта `console`, в консоли работают несколько команд самого браузера.
В файле их писать нельзя — только в консоли:

| Команда | Что делает |
| --- | --- |
| `$0` | элемент, выбранный сейчас во вкладке Elements |
| `$_` | результат предыдущей строки |
| `copy(значение)` | копирует значение в буфер обмена |
| стрелка <Kbd>↑</Kbd> | повторить предыдущую команду |
| <Kbd>Shift</Kbd> + <Kbd>Enter</Kbd> | перенос строки без выполнения |

```js
2 + 2;     // 4
$_ * 10;   // 40 — $_ помнит результат предыдущей строки
```

## 7. Группы, время и счётчики {#groups}

Три инструмента, о которых новички обычно не знают, а они решают три частые задачи.

### Группы: свернуть лишнее

```js
console.group("Проверка оценок");
console.log("Аман: 5");
console.log("Мерет: 4");
console.groupEnd();

console.groupCollapsed("Подробности");  // группа сразу свёрнута
console.log("длинный список...");
console.groupEnd();
```

Группы вкладываются друг в друга, и каждая открытая группа сдвигает сообщения вправо.
Пример по мотивам MDN:

```js
console.log("снаружи");
console.group("Первая группа");
console.log("внутри первой");
console.group("Вторая группа");
console.log("внутри второй");
console.warn("всё ещё во второй");
console.groupEnd();
console.log("снова в первой");
console.groupEnd();
console.log("снова снаружи");
```

Каждый `groupEnd` закрывает одну группу — последнюю открытую. Забыли его — все
следующие сообщения окажутся внутри.

### Время: сколько выполнялось

```js
console.time("подсчёт");
let sum = 0;
for (let i = 0; i < 1000000; i++) {
  sum = sum + i;
}
console.timeLog("подсчёт");   // промежуточная отметка
console.timeEnd("подсчёт");   // подсчёт: 5.2 ms
```

Имя в кавычках связывает начало и конец. Время в примере — для образца: у каждого компьютера
и каждого запуска своё. MDN показывает забавный замер: сколько человек думает, прежде чем нажать «OK».

```js
console.time("ответ");
alert("Нажмите OK");
console.timeLog("ответ");   // ответ: … ms — сколько длилось первое окно
alert("И ещё раз");
console.timeEnd("ответ");   // ответ: … ms — всё вместе
```

Замеров может быть несколько одновременно, если имена разные:

```js
console.time("всё");
console.time("цикл");
for (let i = 0; i < 100000; i++) {}
console.timeEnd("цикл");   // цикл: … ms
console.timeEnd("всё");    // всё: … ms — чуть больше, внутри него и «цикл»
```

Опечатку в имени консоль заметит сама:

```js
console.timeEnd("нет такого");   // жёлтое предупреждение: Timer 'нет такого' does not exist
```

### Счётчики: сколько раз сюда зашли

```js
function greet(name) {
  console.count("вызовов greet");
  console.log("Привет, " + name);
}

greet("Аман");    // вызовов greet: 1
greet("Мерет");   // вызовов greet: 2
console.countReset("вызовов greet");
```

Это выручает, когда функция вызывается чаще, чем вы ожидали, — частая причина «тормозов» на странице.
Без имени счётчик называется `default`, а у каждого имени счёт свой:

```js
console.count();           // default: 1
console.count();           // default: 2
console.count("кнопка");   // кнопка: 1
```

```js
console.countReset("кнопка");
console.count("кнопка");   // кнопка: 1 — счёт начался заново
```

### Проверки и след вызовов

```js
const age = 15;
console.assert(age >= 18, "возраст меньше 18");   // выведет, только если условие ложно

console.trace();     // покажет, откуда вызвали эту строку
console.clear();     // очистить консоль
```

`assert` молчит, пока условие верно, и пишет красную строку, когда оно ложно:

```js
console.assert(2 + 2 === 4, "математика сломалась");   // тишина: условие верно
console.assert(2 + 2 === 5, "так не бывает");          // красная строка «так не бывает»
```

`trace` полезен, когда до строки можно дойти разными путями. Пример по мотивам MDN:

```js
function outer() {
  function inner() {
    console.trace();
  }
  inner();
}
outer();
// console.trace, а под ним цепочка: inner, outer — кто кого вызвал
```

Ещё два метода вы встретите в чужом коде: `console.debug` — то же, что `log`,
но на уровне «подробности», и `console.dirxml` — вывод разметки деревом. Пользоваться ими
необязательно, но узнавать полезно.

### Какой метод выбрать

Когда методов много, помогает обратная таблица — от задачи к методу:

| Нужно… | Метод |
| --- | --- |
| посмотреть значение | `console.log` |
| увидеть список объектов целиком | `console.table` |
| посмотреть свойства элемента страницы | `console.dir` |
| узнать, сколько раз выполнилась строка | `console.count` |
| узнать, сколько длилась работа | `console.time` и `console.timeEnd` |
| молча проверять условие | `console.assert` |
| узнать, кто вызвал строку | `console.trace` |
| спрятать подробности | `console.groupCollapsed` |
| выделить беду | `console.warn`, `console.error` |

## 8. Отладка: debugger и точки останова {#debug}

Вывод в консоль — не единственный способ понять, что происходит. Программу можно **остановить**
в нужной строке и осмотреться: какие значения в переменных прямо сейчас.

Первый способ — слово `debugger` прямо в коде:

```js
const price = 12;
const count = 7;

debugger;   // здесь программа остановится, если открыты DevTools

const total = price * count;
console.log(total);
```

Откройте страницу с открытыми DevTools — выполнение замрёт на этой строке, а справа появится список
переменных с их значениями. Дальше работают кнопки: продолжить, шаг вперёд, зайти внутрь функции.

Второй способ удобнее: вкладка **Sources**, открываете свой файл и щёлкаете по номеру строки.
Появится синий маркер — это **точка останова**. Кода она не требует и после закрытия браузера
исчезает.

У точки останова в Sources есть два полезных варианта — оба через правую кнопку по номеру строки.
**Условная** (*Add conditional breakpoint*) останавливает, только когда верно
условие: в цикле на сто шагов можно остановиться сразу на нужном, например при
`i === 57`. **Точка журнала** (*Add logpoint*) ничего не останавливает,
а печатает в консоль то, что вы в неё впишете, — как `console.log`, только без правки
файла.

<Important>
Не забывайте убирать `debugger` из кода перед тем, как показывать работу. Строка, оставленная
в проекте, будет останавливать программу у каждого, кто откроет страницу с инструментами разработчика.
</Important>

### Разбор: средний балл не сходится

Функция должна считать среднее трёх оценок, 5, 4 и 3, — это 4. А выходит другое:

```js
function average(marks) {
  let sum = 0;
  for (let i = 1; i < marks.length; i++) {
    sum = sum + marks[i];
  }
  return sum / marks.length;
}
average([5, 4, 3]);   // 2.3333333333333335 — а ждали 4
```

Гадать, какая строка виновата, не нужно. Поставьте `debugger;` первой строкой внутри
цикла и вызовите функцию снова. На первой остановке панель Scope покажет `i: 1` и
`sum: 0`: цикл начался с индекса 1, и первая оценка, пятёрка, в сумму не попала.
Исправляем начало цикла на `let i = 0`, убираем `debugger`:

```js
// та же функция, но цикл начинается с let i = 0
average([5, 4, 3]);   // 4
```

Циклы подробно разберём на дне 10, а приём стоит запомнить уже сейчас: остановиться, посмотреть на
значения и сравнить их с тем, что ожидали.

### Кнопки отладчика

Когда программа остановлена, сверху панели появляются кнопки управления. Их четыре, и все нужны:

| Кнопка | Что делает | Когда нажимать |
| --- | --- | --- |
| ▶ Продолжить | выполнять дальше до следующей остановки | посмотрели — идём дальше |
| ↷ Шаг через | выполнить текущую строку целиком | обычный проход по программе |
| ↧ Шаг внутрь | зайти внутрь функции | подозреваете функцию |
| ↥ Шаг наружу | доделать функцию и вернуться | зашли не туда |

Справа от кнопок три полезных списка. **Scope** — переменные, которые видны в этом месте,
с текущими значениями. **Watch** — выражения, за которыми вы попросили следить: добавьте туда
`price * count`, и увидите результат на каждом шаге. **Call Stack** — цепочка вызовов:
какая функция вызвала какую, чтобы попасть сюда.

<Why>
Зачем это, если есть `console.log`? Вывод в консоль показывает одно значение в одной точке.
Отладчик показывает все переменные сразу и позволяет идти по программе шаг за шагом. Когда ошибка
непонятная, отладчик находит её за минуту, а «логами» её можно искать час.
</Why>

### Как хранить файлы курса

Договоримся о порядке с самого начала, чтобы через месяц не искать «тот файл с массивами»:

```plain-out
js-kurs/
  day-01/
    index.html
    app.js
  day-02/
    index.html
    app.js
  projects/
    todo/        — мини-проект дня 29
    catalog/     — мини-проект дня 32
```

Раз в неделю копируйте всю папку курса на флешку или в облако. Потерянный код — обычная история
у начинающих, а восстановить его неоткуда.

## 9. Что делать, если «ничего не работает» {#trouble}

Порядок действий, который решает девять проблем из десяти на первой неделе:

<Step n="1">
**Посмотрите в консоль.** Красная строка — там написано, что не так и в какой строке.
</Step>

<Step n="2">
**Проверьте, сохранён ли файл.** В VS Code несохранённый файл помечен точкой
на вкладке.
</Step>

<Step n="3">
**Обновите страницу с очисткой кеша:** <Kbd>Ctrl</Kbd> +
<Kbd>F5</Kbd>. Браузер любит показывать старую версию файла.
</Step>

<Step n="4">
**Убедитесь, что скрипт подключён.** Поставьте первой строкой
`console.log("файл работает")`. Нет надписи — проблема в подключении, а не в коде.
</Step>

<Step n="5">
**Прочитайте имя файла и путь по буквам.** Лишний пробел или русская «с»
вместо латинской «c» — и файл не найдётся.
</Step>

### Как увидеть, что файл не найден

Есть точный способ проверить подключение: вкладка **Network**. Откройте её и обновите
страницу — появится список всего, что браузер запросил. Ищите строку `app.js`:

| Статус | Что значит | Что делать |
| --- | --- | --- |
| `200` | файл найден и загружен | всё в порядке, проблема в самом коде |
| `404` | файла по такому пути нет | проверить имя и папку |
| строки нет совсем | браузер его и не запрашивал | проверить строку `<script>` в разметке |

Эти три состояния покрывают почти все проблемы с подключением. Привыкнув смотреть Network,
вы перестанете гадать.

Ненайденный файл видно и в консоли — двумя красными строками:

```js
// в index.html написали apps.js вместо app.js:
// Failed to load resource: the server responded with a status of 404 (Not Found)
// Refused to execute script from 'http://127.0.0.1:5500/apps.js' because its MIME type ('text/html') is not executable, and strict MIME type checking is enabled.
```

Первая строка — файла нет, ответ 404. Вторая — вместо файла Live Server прислал страницу «не
найдено», и браузер отказался выполнять её как скрипт. Увидели эту пару — проверяйте имя файла в
`<script>`.

Какой адрес страница пыталась загрузить, можно спросить у неё самой:

```js
document.scripts[0].src;   // "http://127.0.0.1:5500/apps.js" — вот она, опечатка
document.scripts.length;   // 2 — второй скрипт вставил сам Live Server, чтобы обновлять страницу
```

<FunFact>
Число 404 стало известно далеко за пределами программирования: его печатают на футболках и пишут
на страницах «ничего не найдено». Это просто код ответа сервера: «такого адреса у меня нет».
</FunFact>
