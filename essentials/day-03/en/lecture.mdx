## 1. Why we need an overview {#why}

Before a journey people look at a map. Not to learn every turn by heart, but to understand
where they are and what comes next. Today’s lesson is such a map: we will walk through **the whole language
in forty-five minutes**, from numbers to asynchronous code, and at every stop we will note which day
of the course comes back to it seriously.

<Important>
**You do not need to remember anything today.** If after the lecture you can say: “I have seen this word,
it is about objects, and we will study it on day 21” — the lesson is a complete success. Every topic below will get
its own day and its own tasks.
</Important>

Why do it this way at all? Because learning a language bit by bit without seeing the whole is hard. You will write
`let` on day 4 and not know why `const` is next to it. You will see the word
`return` on day 12 and not understand where the value is returned to. The map removes this worry: you already know
that the house will be finished, and you simply lay the bricks one by one.

The overview has a second benefit. You will meet real code not in textbook order but in any order:
in someone else’s project, in an answer on a forum, in an example on MDN. There you will see arrow functions, classes
and `await` all at once. A person who has seen the map reads such code calmly: “this is a function, this is an
object, and this I have not studied yet — fine, not today”. A person without the map closes the page.

<Why>
JavaScript is a **multi-paradigm dynamic language**. The two scary words mean this.
“Multi-paradigm” — one task can be solved in several styles: a simple chain of commands, with
objects, with functions that pass values to each other. “Dynamic” — the type belongs to the value,
not to the variable, and it is checked while the program runs, not in advance.
</Why>

## 2. What a program is made of {#parts}

Any JavaScript program is built from four things. There is nothing else in it.

| Building block | What it is | Example |
| --- | --- | --- |
| **Value** | data on its own | `5`, `"Mary"`, `true` |
| **Expression** | something that is calculated into one value | `2 + 2`, `marks.length` |
| **Statement** | one action of the program | `let x = 5;` |
| **Block** | several statements in curly braces | `{ ... }` |

The difference between an expression and a statement matters more than it seems. **An expression answers with a value,
a statement performs an action.** It is easy to check: an expression can stand to the right of the equals sign,
a statement cannot.

```js
const a = 2 + 2;          // 2 + 2 is an expression, it can be assigned
const b = if (x) { 1 };   // SyntaxError — if is a statement, it has no value
```

In some languages (for example, in Rust) a condition is itself an expression and returns a value.
In JavaScript it is not: `if`, `for`, `while` are statements. When a value
depending on a condition is needed after all, the ternary operator is used; we will meet it on day 7.

The program runs from top to bottom, statement after statement. The engine does not look ahead and does not choose
what to run first — it goes through the lines in a row until the lines run out or an error happens.

## 3. Values: eight types {#types}

Everything a program works with is values. And every value belongs to one of **eight
types**: seven simple ones (they are called *primitives*) and one complex one — the object.

<Scheme src="scheme-types.svg">The eight types of the language. A function is an object too, just one that can be called</Scheme>

### Numbers

JavaScript has no separate “whole” and “fractional” numbers: there is one `Number` type for everything.
That is why division behaves differently from what you are used to at school and in other languages:

```js
console.log(3 / 2);       // 1.5, not 1
console.log(0.1 + 0.2);   // 0.30000000000000004
```

The second line surprises everyone. Fractional numbers are stored in memory approximately — just as 1/3 cannot be
written exactly as a decimal fraction, 0.1 cannot be written exactly in binary. This is not a JavaScript bug; this is how
fractional numbers work in almost all languages. On day 17 we will learn to live with it: money is counted in cents, and
the result is rounded.

Numbers can be written in different ways, and all four forms below give the same value, 503:

```js
console.log(0b111110111);   // binary
console.log(0o767);         // octal
console.log(0x1f7);         // hexadecimal
console.log(5.03e2);        // 5.03 × 10²
```

There is also a second number type — `BigInt`, for very large whole numbers. It is written with the letter
`n` at the end: `9007199254740993n`. You cannot mix `BigInt` with ordinary numbers
in one expression. We will not need it in Essentials; it is covered in course 2.

Two special number values stand apart: `Infinity` (you get it when
dividing by zero) and `NaN` — “not a number”. `NaN` appears when a calculation makes no sense,
for example when you try to turn a word into a number. And it is contagious: any operation with `NaN` gives
`NaN`.

```js
console.log(10 / 0);          // Infinity
console.log(Number("salam")); // NaN
console.log(NaN + 5);         // NaN — the infection spreads
console.log(NaN === NaN);     // false — the only value not equal to itself
```

### Strings

A string is text: a sequence of Unicode characters. That means a string can hold Latin and Cyrillic letters,
Turkmen letters and Chinese characters, without any settings.

```js
console.log("Salam, dünýä!");
console.log('Single quotes work too');
console.log("Mary".length);   // 4 — the length of the string
console.log("Mary"[0]);       // "M" — a character by its number
```

There is no separate “character” type in the language: one character is a string of length 1. Strings are
**immutable**: none of their methods spoil the original; they return a new string. In detail — day 16.

Strings can be joined with a plus, but a **template literal** is much more convenient — in backticks,
with insertions `${...}`:

```js
const age = 25;
console.log("I am " + age + " years old.");   // joining with a plus
console.log(`I am ${age} years old.`);        // a template literal reads better
```

### The boolean type, null and undefined

The boolean type `Boolean` has exactly two values: `true` and `false`.
But *any* value can be put into a condition — the language turns it into “yes” or “no” by itself. The rule
is short and worth writing down in your notebook:

<Important>
Only six values are **falsy**: `false`, `0`,
the empty string `""`, `NaN`, `null` and `undefined`.
**Everything else is truthy**, including the string `"0"`, the empty array `[]`
and the empty object `{}`.
</Important>

The last two values on the list are confused all the time. `undefined` means “there is no value, and nobody
put one”: this happens when a variable is declared without a value, when you ask for a property an object does not have,
or when a function returned nothing. `null` means “empty on purpose”: a value the programmer put
there to say “this is empty”.

```js
let x;
console.log(x);              // undefined — we forgot to put a value
const found = null;          // null — we put emptiness on purpose
```

The seventh primitive is `Symbol`, a key value that is guaranteed not to match anything.
It is needed for subtle things like your own iteration protocols; its place is course 2.

### How to find out the type

Since the type belongs to the value, you can ask for it. There is the `typeof` operator for that:

```js
typeof 42;          // "number"
typeof "Mary";      // "string"
typeof true;        // "boolean"
typeof undefined;   // "undefined"
typeof { };         // "object"
typeof [1, 2];      // "object"  — an array is an object too
typeof console.log; // "function"
typeof null;        // "object"  — an old mistake of the language that was never fixed
```

The last two lines are what `typeof` is criticized for. It does not tell an array from an object,
and for `null` it answers `"object"`: this mistake was made in 1995, and it can no longer
be fixed — too many old websites would break. How to get around both, we will see on day 5,
and `Array.isArray` we will meet on day 19.

## 4. Variables: three words {#vars}

A value on its own is useless — it needs to be put somewhere and given a name. There are three words for that:
`let`, `const` and `var`.

```js
let count = 0;        // the value will change
count = 1;            // this is allowed

const city = "Mary";  // the value must not change
city = "Ashgabat";    // TypeError: Assignment to constant variable.

var old = 1;          // an old word; we do not write it in new code
```

The rule for the whole course is simple: **by default we write `const`, and if the value will
change — `let`**. The word `var` is left over from the nineties, behaves unexpectedly,
and is not used in new code.

<Mistake>
`const` forbids **reassignment**, not changing the contents.
An object under `const` can be changed piece by piece:

```js
const user = { name: "Aman" };
user.name = "Meret";   // works, no error
user = { };            // but this is a TypeError
```
</Mistake>

One more feature: the type belongs to the value, not to the variable. The same variable holds a number today
and a string tomorrow, and the language does not mind:

```js
let value = 1;
value = "now a string";   // no error — the language is dynamic
```

This is both freedom and a source of mistakes: nobody will warn you that the variable holds something other than
what you expected. Hence the habit of experienced programmers to name variables so that the name tells the type:
`marks` is a list, `count` is a number, `isReady` is “yes / no”.
In detail — day 4; types and `typeof` — day 5.

## 5. Operators: what is done with values {#ops}

Operators are signs that do something with values. The arithmetic ones look like in math:
`+`, `-`, `*`, `/`, `%` (the remainder of division)
and `**` (power). Each has a short form with assignment, and `++` and `--`
increase and decrease by one.

```js
let x = 10;
x += 5;                // the same as x = x + 5 — now 15
x++;                   // one more — now 16
console.log(x % 3);    // 1 — the remainder of 16 divided by 3
console.log(2 ** 10);  // 1024
```

The plus works not only with numbers: if at least one operand is a string, it **joins**.
Hence the famous trap everyone stumbles on:

```js
console.log("3" + 4 + 5);   // "345" — a string on the left, everything became a string
console.log(3 + 4 + "5");   // "75"  — first 3 + 4 = 7, then joining
```

Values are compared with the operators `<`, `>`, `<=`,
`>=`, and for equality in two different ways, and this is essential:

<Compare>
<Wrong label="== loose">
```js
123 == "123";  // true
1 == true;     // true
```

first converts the types to each other, then compares. The result is often unexpected.
</Wrong>

<Right label="=== strict">
```js
123 === "123"; // false
1 === true;    // false
```

compares both the value and the type. Always predictable. We write only this.
</Right>
</Compare>

Both have a negative pair: `!=` and `!==`. The course rule:
**always `===` and `!==`**.

The logical operators are `&&` (“and”), `||` (“or”) and `!` (“not”).
They work not only with `true` and `false` but with the “truthiness” of any value,
and — an important detail — they return not “yes / no” but one of the original values:

```js
const a = 0 && "Salam";      // 0       — zero is falsy, we look no further
const b = "Salam" || "dünýä"; // "Salam" — the first truthy one
```

This is called *short-circuit evaluation*: the second operand is calculated only if needed.
The property is used to put in a fallback value: `const name = input || "Guest";`.
Days 6, 7 and 8 cover operators in full, together with the precedence table.

## 6. Grammar: how the language reads your text {#grammar}

The grammar of JavaScript is similar to the grammar of C and Java, but a few rules are worth learning right away — they
explain half of the errors of the first week.

**Names.** The name of a variable or a function can consist of letters, digits, `_`
and `$`, but it cannot start with a digit. The letters can be any letters, including non-Latin ones; technically
you can write names in another alphabet, but it is not customary, and we will not do it. You cannot use
*reserved words*: `let`, `class`, `return`,
`new` and a few dozen more.

**Case matters.** `name`, `Name` and `NAME` are
three different variables. This is the reason for half of the beginners’ “is not defined” messages.

**Comments.** There are two kinds, and the engine ignores both:

```js
// a one-line comment — up to the end of the line

/* a multi-line
   comment */
```

**The semicolon.** Formally it is optional: the engine puts it in by itself — this is called
*automatic semicolon insertion*. But it does so by its own rules, and sometimes they differ
from your intentions. The classic case:

```js
function getCity() {
  return
    "Mary";      // the engine never gets here
}
console.log(getCity());   // undefined
```

The engine saw `return` followed by the end of the line — and put a semicolon right after
`return`. The function returned `undefined`, and the string “Mary” stayed unreachable.
Hence the course rule: **we put semicolons ourselves**, and the value after `return`
goes on the same line.

## 7. Program flow: conditions, loops, errors {#flow}

By default a program goes from top to bottom. Control structures let it turn off this path:
run a piece of code not always, run it many times or catch a failure.

A **condition** is `if` and `else`; they can be chained:

```js
if (score >= 90) {
  grade = 5;
} else if (score >= 75) {
  grade = 4;
} else {
  grade = 3;
}
```

There is no separate word `elif` as in Python: `else if` is just an
`else` with one `if` inside.

When there are many branches and all of them compare the same value, instead of a ladder of `else if`
people use `switch`:

```js
switch (action) {
  case "add":
    addItem();
    break;
  case "remove":
    removeItem();
    break;
  default:
    console.log("unknown command");
}
```

The word `break` is required here: without it execution “falls through” into the next branch
and goes on down the list. `switch` compares strictly, with `===`. We study it
on day 9.

**Loops.** There are five, each for its own case:

| Loop | When you need it | Day |
| --- | --- | --- |
| `for` | you know how many times to repeat | 10 |
| `while` | repeat while a condition is true | 10 |
| `do...while` | the same, but the body runs at least once | 10 |
| `for...of` | go through the values of an array or a string | 11 |
| `for...in` | go through the property names of an object | 11 |

```js
for (let i = 0; i < 5; i++) {
  console.log(i);          // 0, 1, 2, 3, 4
}

const marks = [5, 4, 5];
for (const mark of marks) {
  console.log(mark);       // 5, 4, 5 — each mark in turn
}
```

**Errors.** When the engine cannot do something, it “throws” an error, and the program
stops. To prevent this, the dangerous part is wrapped in `try...catch`:

```js
const text = "{ broken";           // the text arrived broken
try {
  const data = JSON.parse(text);
} catch (e) {
  console.error("Could not parse:", e);
}
```

You throw your own error with the word `throw`. There are several ready-made kinds of errors — `TypeError`,
`RangeError`, `SyntaxError` — and in a minute we will learn to tell them apart by the message.
Working with `try...catch` is day 11.

## 8. Objects and arrays {#objects}

An **object** is a set of “name — value” pairs. The name is called a *key* or a
*property*. In other languages such a thing is called a dictionary, a hash or an associative array.

```js
const student = {
  name: "Gülnar",
  age: 17,
  marks: [5, 4, 5],
};

console.log(student.name);       // "Gülnar" — with a dot
console.log(student["age"]);     // 17       — with brackets
student.city = "Mary";           // a property can be added at any moment
```

Square brackets are needed when the property name is in a variable or is calculated. An object has no shape
set in advance: properties are added, removed and changed whenever you like.

An **array** is, strictly speaking, an object too, just a special one: it has numeric keys
and the magic property `length`, which keeps track of the length by itself.

```js
const a = ["dog", "cat", "hen"];
console.log(a.length);     // 3
console.log(a[90]);        // undefined — beyond the end there is no error, just “nothing”
a.push({ });               // you can put anything in, even an object
```

Since an array is an object, you can assign it any index, even with a gap. The language will not object, but
you should not do this:

```js
const a = ["dog", "cat", "hen"];
a[100] = "fox";
console.log(a.length);   // 101 — the length followed the largest index
console.log(a);          // (101) ['dog', 'cat', 'hen', empty × 97, 'fox']
```

Between the third element and the hundredth there are ninety-seven empty places. Such an array is called
*sparse*, and the engine stops treating it as an array and switches to a slow
way of storing it. The rule is simple: **fill an array without gaps**, and add to the end
with the `push` method.

<Important>
**Objects and arrays are passed by reference.** A variable holds not the object itself
but the “address” where it lies. That is why two objects that look the same are never equal,
and a copy of the variable is not a copy of the object:

```js
const me = { };
const stillMe = me;
me.x = 1;
console.log(stillMe.x);      // 1 — there is only one object
console.log({ } === { });    // false — different objects
```
</Important>

This one line is the source of the most annoying mistakes at work: “but I copied the array, why did the original
change?”. We study it on day 19, and the ways to copy honestly on day 22.

## 9. Functions {#functions}

A function is a piece of a program with a name that can be called as many times as you like. Together with objects it is
the main thing code is built from.

```js
function add(x, y) {
  const total = x + y;
  return total;
}

console.log(add(2, 3));   // 5
```

A few rules that surprise people coming from other languages:

- a function can be called with **any number of arguments**. Too few — the missing ones become
  `undefined`; extra ones are simply ignored;
- if there is no `return` or it is empty, the function returns `undefined`;
- variables declared inside are not visible outside.

```js
add();          // NaN — this is undefined + undefined
add(2, 3, 4);   // 5   — nobody asked for the four
```

A function does not have to have a name. A nameless function is put into a variable or passed to another function.
The short form of such a function is the **arrow function**:

```js
const sum = function (a, b) { return a + b; };   // a function expression
const sum2 = (a, b) => a + b;                    // an arrow function: shorter and without return
```

Functions in JavaScript are **full values**. They are put into variables, passed as
arguments, returned from other functions and even stored in arrays. This is what “functions are first-class
objects” means, and half of the language’s techniques stand on it:

```js
const babies = ["dog", "cat"].map((name) => `baby ${name}`);
// ["baby dog", "baby cat"]
```

### What else parameters can do

Since any number of arguments can be passed, the language gives three ways to handle this. All three
appear in the course, and you will see all three in other people’s code this very week.

```js
// 1. A default value — if the argument was not passed
function greet(name = "Guest") {
  return `Salam, ${name}!`;
}
greet();           // "Salam, Guest!"

// 2. Rest parameters — collect “all the others” into an array
function avg(...numbers) {
  let sum = 0;
  for (const n of numbers) sum += n;
  return sum / numbers.length;
}
avg(2, 3, 4, 5);   // 3.5

// 3. Spreading an array into a list of arguments — the reverse operation
const marks = [5, 4, 3];
avg(...marks);     // the same as avg(5, 4, 3)
```

The language has no named arguments as in Python. But they are imitated: you pass one object
and take it apart right away — this is called destructuring.

```js
function area({ width, height }) {
  return width * height;
}
area({ width: 2, height: 3 });   // 6 — you can see which number is which
```

Default values and rest parameters — day 14; destructuring and `...` —
day 22.

Finally, a function can be declared inside another function, and the inner one sees the variables of the outer one.
This is where closures grow from — a big topic of course 2. For us days 12–15 are enough: declaration, parameters,
`return`, arrow functions, default values.

## 10. Classes, modules, asynchronous code {#ahead}

In Essentials we only name three big parts of the language. It is important to know that they exist: you will meet them
in any code written by others.

### Classes

A class is a template for making objects of the same kind. The syntax looks like Java:

```js
class Person {
  constructor(name) {
    this.name = name;
  }
  sayHello() {
    return `Hello, I am ${this.name}!`;
  }
}

const p = new Person("Meret");
console.log(p.sayHello());
```

Behind classes in JavaScript there is the prototype mechanism — its own, not like the one in Java or C++.
All of this is covered in course 2.

### Asynchronous code

JavaScript is single-threaded: at any moment exactly one line of code runs. But waiting for an answer
from the server while standing still is not possible — the page would freeze. That is why long operations are started, and
the result is received later. There are three ways to write this:

```js
// 1. A callback function — the oldest way
setTimeout(() => console.log("a second passed"), 1000);

// 2. A promise
fetch(url).then((response) => console.log(response.status));

// 3. async / await — the same, but it reads from top to bottom
async function load() {
  const response = await fetch(url);
  console.log(response.status);
}
```

All three appear on days 30 and 31, at the end of the course. The most important thing now: **you cannot
“just take” the result of an asynchronous value right away** — you get it when it arrives.

### Modules

When there is one file, everything is simple. When there are ten, the code is split into modules and connected with the words
`import` and `export`:

```js
// only in a module; in the console — SyntaxError: Cannot use import statement outside a module
import { average } from "./math.js";

export const city = "Mary";
```

Modules are course 2. In Essentials we get by with one or two script files connected to the page.

## 11. The language and its host {#runtime}

There is a division without which there will be confusion later. **The language itself** is numbers, strings,
objects, functions, `if` and `for`. It is described in the ECMAScript specification and is the same
everywhere. But the language itself has *neither input nor output*: it can calculate, but it can neither show
the result nor ask the user.

<Scheme src="scheme-runtime.svg">The core of the language is the same everywhere. Everything that goes “outside” comes from the runtime</Scheme>

The runtime environment is called the *host* or the *runtime*. The browser is one host, Node.js is
another. Even `console.log`, which we write in every lesson, was not invented by the language but by the environment:
the browser gives it.

<RealWorld>
Hence a practical conclusion. If an example from the internet does not work in your browser, first of all
ask: was it written for Node.js? `require`, `fs.readFile`,
`process.argv` will never work in the browser — and not because you did something wrong.
</RealWorld>

## 12. The first complete program {#program}

Now let us put everything listed above into one working program. Two files in one folder — as on day 2.
The program calculates the average mark and shows it on the page.

The file `index.html`:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Report card</title>
  <script src="app.js" defer></script>
</head>
<body>
  <h1>Report card for the week</h1>
  <p id="result">Calculating...</p>
</body>
</html>
```

The file `app.js`:

```js
const student = {
  name: "Aman",
  marks: [5, 4, 5, 3, 5],
};

function average(numbers) {
  let sum = 0;
  for (const n of numbers) {
    sum += n;
  }
  return sum / numbers.length;
}

const score = average(student.marks);

let verdict;
if (score >= 4.5) {
  verdict = "excellent";
} else if (score >= 3.5) {
  verdict = "good";
} else {
  verdict = "needs work";
}

const line = `${student.name}: average mark ${score.toFixed(2)} — ${verdict}`;
console.log(line);
document.getElementById("result").textContent = line;
```

<ResultBox>
Aman: average mark 4.40 — good
</ResultBox>

Twenty-seven lines — and the whole of today’s overview fits into them. Look at what they are made of:

| Line | What it is from the overview | Day |
| --- | --- | --- |
| `const student = { ... }` | an object and a constant declaration | 4, 21 |
| `marks: [5, 4, 5, 3, 5]` | an array of numbers | 19 |
| `function average(numbers)` | a function with a parameter | 12 |
| `let sum = 0;` | a variable that will change | 4 |
| `for (const n of numbers)` | a loop over the values of an array | 11 |
| `sum += n;` | an assignment operator with an action | 6 |
| `return sum / numbers.length;` | returning a value and division | 12 |
| `if / else if / else` | a condition with three branches | 9 |
| `` `${student.name}: ...` `` | a template literal | 16 |
| `score.toFixed(2)` | a number method: two digits after the decimal point | 17 |
| `document.getElementById(...)` | an ability of the browser, not of the language | 24 |

Type both files by hand (do not copy!) and open `index.html`. Then change

Check that the number in the parentheses of `toFixed(2)` controls the number of digits after the decimal point.
</TryIt>

## 13. How to read an error message {#errors}

The program will break — that is normal, and it will break every day. The difference between a beginner
and an experienced programmer is not that the second one has no errors, but that they *read* them.
A message in the console is always built the same way and always answers three questions: what kind of error it is, what exactly
is wrong and where it happened.

<Scheme src="scheme-errors.svg">Start reading from the end: first where, then what</Scheme>

The most valuable part here is the last one. **The address `app.js:27:47` in the console is clickable**:
the browser opens the file and puts the cursor exactly at that place. Beginners do not notice it and search for the error with their
eyes through the whole file.

There are only a few kinds of errors, and the kind already tells you where to look:

| Kind | What happened | Where to look |
| --- | --- | --- |
| `SyntaxError` | the text breaks the rules of the language | parentheses, quotes, commas — usually one line above the one named |
| `ReferenceError` | there is no such name | a typo in the name, or the variable is declared further down |
| `TypeError` | the value cannot do what is asked of it | there is `null` or `undefined` there, or something that is not a function was called |
| `RangeError` | a number is outside the allowed limits | array length, `toFixed(101)`, endless recursion |

<Mistake>
A `SyntaxError` breaks **the whole file at once**, before the first line runs.
If it seems that “the script did not connect at all”, first check whether there is a red
`SyntaxError` in the console. One unclosed parenthesis turns off the whole program.
</Mistake>

There is a second, trickier category: the code ran, there is no error, but the result is wrong. Here
the console is silent, and what helps is what we studied yesterday: `console.log` in suspicious places,
breakpoints and `debugger`.

<ProTip>
Break the program on purpose. Remove `defer` from `<script>`, write
`avarage` instead of `average`, delete a closing parenthesis — and read
what the browser says. Fifteen minutes of such play save hours later. This is exactly what we will do
in practice.
</ProTip>

<Summary>
The language consists of **values** of eight types, **variables** that give
values names, **operators** that do something with values,
**control structures** that change the flow of the program, and **functions**
that collect all this into named pieces. Objects and arrays keep values in groups and are passed
by reference. Classes, modules and asynchronous code are built on top of the same things. And input and output are given to the language
not by the language itself but by the environment: the browser or Node.js.
</Summary>

## 15. Common mistakes of the day {#mistakes}

| Mistake | Why | How to do it right |
| --- | --- | --- |
| `0.1 + 0.2 === 0.3` | fractions are stored approximately | compare with a tolerance or count in cents |
| `"3" + 4` instead of 7 | a plus with a string joins | `Number("3") + 4` |
| `if (x = 5)` | `=` assigns instead of comparing | `if (x === 5)` |
| the value on the line after `return` | the engine put a semicolon by itself | write the value on the same line |
| `average` without parentheses | you got the function itself, not the result | `average(marks)` |
| `<script src="app.js">` without `defer` | the code ran before the markup | add `defer` |

<Selfcheck>
1. How many types of values does the language have, and which of them is not a primitive?
   <Answer>Eight. Seven primitives — `Number`, `BigInt`, `String`,
   `Boolean`, `Symbol`, `Undefined`, `Null` —
   and the object. Arrays and functions are objects too.</Answer>
2. How is `null` different from `undefined`?
   <Answer>`undefined` means no value was put: the variable was declared without a value, the property does not exist,
   the function returned nothing. `null` means the programmer put emptiness on purpose.</Answer>
3. What does `console.log("3" + 4 + 5)` print, and why?
   <Answer>`"345"`. There is a string on the left, so the plus joins: first `"34"`,
   then `"345"`. And `3 + 4 + "5"` gives `"75"`.</Answer>
4. Why is `console.log` not considered part of the language?
   <Answer>The language itself can neither take input nor give output. `console` comes from the runtime:
   the browser or Node.js. `document`, `fetch` and
   `alert` work the same way.</Answer>
5. The console says `Uncaught TypeError: ... at app.js:27:47`. What do you do first?
   <Answer>Click `app.js:27:47` — the browser opens the file at line 27. Then look at
   which value ended up there: with a `TypeError` it is usually `null`
   or `undefined`.</Answer>
</Selfcheck>
