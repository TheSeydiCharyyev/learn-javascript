# Day 3. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder `day-03` with the files `index.html` and `app.js`.</Subtitle>

## Warm-up

<Task title="1. Who is of which type" level="easy" time="6">
<Goal>see that the type belongs to the value.</Goal>

Open the console and ask `typeof` about each value in the list. Write the result down
in your notebook in two columns: the value and the answer.

```js
42        "Mary"        true        undefined        null
{ }       [1, 2]        console.log        10 / 0        "5" * 2
```

<Criteria>
- all ten answers are written down;
- the answers that differ from what you expected are marked — there are at least two;
- for each such answer there is one sentence: what you expected and what you got.
</Criteria>
</Task>

<Task title="2. Six liars" level="easy" time="7">
<Goal>remember the list of falsy values through practice, not by heart.</Goal>

Check each value with `Boolean(...)` and write down separately the ones that gave
`false`.

```js
const values = [0, 1, -1, "", " ", "0", [], { }, null, undefined, NaN];
```

<Hint>
There are six falsy values, but this list has fewer — some of the traps are truthy, although they look empty.
</Hint>

<Criteria>
- an answer is written down for each value;
- all the falsy ones in the list are found;
- it is explained why `"0"` and `[]` are truthy.
</Criteria>
</Task>

<Task title="3. Predict first" level="easy" time="7">
<Goal>catch yourself on the traps of the plus and of comparison.</Goal>

First write down in your notebook what you think each line prints. Only then check
in the console and mark where you were wrong.

```js
"3" + 4 + 5
3 + 4 + "5"
"10" - 5
123 == "123"
123 === "123"
0.1 + 0.2 === 0.3
```

<Criteria>
- the predictions are written down *before* the check;
- the real answers are next to them;
- for each difference there is one sentence — why it is so.
</Criteria>
</Task>

<Task title="7. Take apart someone else’s code" level="medium" time="11">
<Goal>recognize parts of the language in unfamiliar code — the main skill of the day.</Goal>

Copy this code into your notebook and label eight things on it: an object, an array, a function declaration,
a function parameter, a variable that changes, a loop over values, a condition, a template literal.

```js
const shop = {
  name: "Bereket",
  prices: [12, 40, 7.5],
};

function total(list) {
  let sum = 0;
  for (const price of list) {
    sum += price;
  }
  return sum;
}

const bill = total(shop.prices);

if (bill > 50) {
  console.log(`${shop.name}: expensive, ${bill.toFixed(2)} manat`);
} else {
  console.log(`${shop.name}: fine`);
}
```

<Criteria>
- all eight labels are in place;
- without running it, it is written down what the program prints;
- the answer is checked by running it and matches.
</Criteria>
</Task>

## Starred tasks

<Task title="8. Hunting four bugs" level="hard" time="10">
<Goal>go the whole way of debugging: from a dead file to the right number.</Goal>

This code has four bugs. Type it into a new file, run it and fix them **one at a time**,
reloading the page each time. For each one, write down the kind of error and what you did.

```js
const marks = [5, 4, 3, 5];

function average(numbers) {
  let sum = 0;
  for (const n of numbers) {
    sum += numbers;
  }
  return
    sum / numbers.length;
}

const score = Average(marks);
console.log("Average mark: " + score.toFixed(2);
```

<Hint>
The bugs show themselves in turn, and that is no accident: while the file has a
`SyntaxError`, not a single line runs. The fourth bug gives no message
at all — it gives itself away with a wrong answer.
</Hint>

<Criteria>
- all four bugs are found;
- for the first three the kind of error is named, for the fourth — why the browser stayed silent;
- the fixed program prints “Average mark: 4.25”;
- the order in which the bugs showed up is written down.
</Criteria>
</Task>
