1. Зачем нужен обзор

Перед дорогой смотрят на карту. Не для того, чтобы выучить наизусть каждый поворот, а чтобы понимать, где вы находитесь и что будет дальше. Сегодняшний урок — такая карта: мы пройдём по всему языку за сорок пять минут, от чисел до асинхронного кода, и на каждой остановке отметим, в какой день курса мы туда вернёмся всерьёз.

Не нужно ничего запоминать сегодня. Если после лекции вы скажете: «я видел это слово, оно про объекты, и разбирать будем на дне 21» — урок удался полностью. Каждая тема ниже получит свой отдельный день и свои задания.

Зачем вообще так делать? Затем, что учить язык по кусочкам, не видя целого, тяжело. Вы напишете let на дне 4 и не будете знать, зачем рядом есть const. Увидите на дне 12 слово return и не поймёте, куда возвращается значение. Карта снимает эту тревогу: вы уже знаете, что дом достроится, и просто кладёте кирпичи по одному.

У обзора есть и вторая польза. Настоящий код вы будете встречать не по порядку учебника, а как попало: в чужом проекте, в ответе на форуме, в примере на MDN. Там сразу будут и стрелочные функции, и классы, и await. Человек, который видел карту, читает такой код спокойно: «вот это функция, вот это объект, вот это я ещё не проходил — ничего, не сегодня». Человек без карты закрывает страницу.

JavaScript — мультипарадигменный динамический язык. Два страшных слова означают вот что. «Мультипарадигменный» — одну задачу можно решить несколькими стилями: простой цепочкой команд, через объекты, через функции, которые передают друг другу значения. «Динамический» — тип есть у значения, а не у переменной, и проверяется он во время работы программы, а не заранее.

2. Из чего состоит программа

Любая программа на JavaScript собирается из четырёх вещей. Больше ничего в ней нет.

КирпичикЧто этоПример
Значениеданные сами по себе5, "Мары", true
Выражението, что вычисляется в одно значение2 + 2, marks.length
Инструкцияодно действие программыlet x = 5;
Блокнесколько инструкций в фигурных скобках{ ... }

Разница между выражением и инструкцией важнее, чем кажется. Выражение отвечает значением, инструкция выполняет действие. Проверить просто: выражение можно поставить справа от знака равенства, инструкцию — нельзя.

const a = 2 + 2;          // 2 + 2 — выражение, его можно присвоить
const b = if (x) { 1 };   // SyntaxError — if это инструкция, значения у неё нет

В некоторых языках (например, в Rust) условие само является выражением и возвращает значение. В JavaScript это не так: if, for, while — инструкции. Когда значение по условию всё-таки нужно, берут тернарный оператор, с ним познакомимся на дне 7.

Программа выполняется сверху вниз, инструкция за инструкцией. Движок не заглядывает вперёд и не выбирает, что ему выполнить сначала, — он идёт по строкам подряд, пока строки не кончатся или пока не случится ошибка.

3. Значения: восемь типов

Всё, с чем работает программа, — это значения. И каждое значение принадлежит одному из восьми типов: семи простых (их называют примитивами) и одному сложному — объекту.

Числа

В JavaScript нет отдельно «целых» и отдельно «дробных» чисел: тип Number один на всё. Поэтому деление ведёт себя не так, как привыкли в школе и в других языках:

console.log(3 / 2);       // 1.5, а не 1
console.log(0.1 + 0.2);   // 0.30000000000000004

Вторая строка удивляет всех. Дробные числа хранятся в памяти приближённо — примерно как 1/3 нельзя точно записать десятичной дробью, так и 0.1 нельзя точно записать двоичной. Это не ошибка JavaScript, так устроены дробные числа почти во всех языках. На дне 17 научимся с этим жить: деньги считают в копейках, а результат округляют.

Числа умеют записываться по-разному, и все четыре записи ниже дают одно и то же значение 503:

console.log(0b111110111);   // двоичная запись
console.log(0o767);         // восьмеричная
console.log(0x1f7);         // шестнадцатеричная
console.log(5.03e2);        // 5.03 × 10²

Есть и второй числовой тип — BigInt, для очень больших целых чисел. Его пишут с буквой n на конце: 9007199254740993n. Смешивать BigInt с обычными числами в одном выражении нельзя. В Essentials он нам не понадобится, разбирать будем в курсе 2.

Отдельно стоят два особых числовых значения: Infinity (бесконечность — получается при делении на ноль) и NaN — «не число». NaN появляется, когда вычисление бессмысленно, например при попытке превратить в число слово. И он заразен: любое действие с NaN даёт NaN.

console.log(10 / 0);          // Infinity
console.log(Number("салам")); // NaN
console.log(NaN + 5);         // NaN — зараза расползается
console.log(NaN === NaN);     // false — единственное значение, не равное самому себе

Строки

Строка — это текст: последовательность символов Unicode. Значит, в строку можно положить и кириллицу, и туркменские буквы, и китайские иероглифы, без всяких настроек.

console.log("Салам, dünýä!");
console.log('Одинарные кавычки тоже подходят');
console.log("Мары".length);   // 4 — длина строки
console.log("Мары"[0]);       // "М" — символ по номеру

Отдельного типа «символ» в языке нет: один символ — это строка длиной 1. Строки неизменяемы: все их методы не портят оригинал, а возвращают новую строку. Подробно — день 16.

Склеивать строки можно плюсом, но гораздо удобнее шаблонной строкой — в обратных кавычках, со вставками ${...}:

const age = 25;
console.log("Мне " + age + " лет.");   // склейка плюсом
console.log(`Мне ${age} лет.`);        // шаблонная строка — читается лучше

Логический тип, null и undefined

Логический тип Boolean имеет ровно два значения: true и false. Но в условие можно поставить любое значение — язык сам превратит его в «да» или «нет». Правило короткое и его стоит выписать в тетрадь:

Ложными считаются только шесть значений: false, 0, пустая строка "", NaN, null и undefined. Всё остальное — истина, включая строку "0", пустой массив [] и пустой объект {}.

Два последних значения из списка постоянно путают. undefined — «значения нет, и никто его не клал»: так получается, когда переменную объявили без значения, спросили несуществующее свойство объекта или функция ничего не вернула. null — «пусто нарочно»: значение, которое программист поставил сам, чтобы сказать «здесь пусто».

let x;
console.log(x);              // undefined — забыли положить
const found = null;          // null — положили пустоту намеренно

Седьмой примитив — Symbol, значение-ключ, которое гарантированно ни с чем не совпадёт. Он нужен для тонких вещей вроде собственных протоколов перебора; его место — курс 2.

Как узнать тип

Раз тип принадлежит значению, его можно спросить. Для этого есть оператор typeof:

typeof 42;          // "number"
typeof "Мары";      // "string"
typeof true;        // "boolean"
typeof undefined;   // "undefined"
typeof { };         // "object"
typeof [1, 2];      // "object"  — массив это тоже объект
typeof console.log; // "function"
typeof null;        // "object"  — старая ошибка языка, её не стали исправлять

Две последние строки — то, за что typeof ругают. Массив от объекта он не отличает, а для null отвечает "object": это ошибка, допущенная в 1995 году, и исправить её уже нельзя — сломается слишком много старых сайтов. Как обходить обе, разберём на дне 5, а Array.isArray встретим на дне 19.

4. Переменные: три слова

Значение само по себе бесполезно — его нужно куда-то положить и дать имя. Для этого есть три слова: let, const и var.

let count = 0;        // значение будет меняться
count = 1;            // так можно

const city = "Мары";  // значение меняться не должно
city = "Ашхабад";     // TypeError: Assignment to constant variable.

var old = 1;          // старое слово; в новом коде не пишем

Правило на весь курс простое: по умолчанию пишем const, а если значение будет меняться — let. Слово var осталось с девяностых, ведёт себя неожиданно, и в новом коде его не используют.

const запрещает переприсваивание, а не изменение содержимого. Объект под const менять по частям можно: 
const user = { name: "Аман" };
user.name = "Мерет";   // работает, ошибки нет
user = { };            // а вот это TypeError

Ещё одна особенность: тип принадлежит значению, а не переменной. Одна и та же переменная сегодня хранит число, а завтра строку, и язык не возражает:

let value = 1;
value = "теперь строка";   // ошибки нет — язык динамический

Это одновременно свобода и источник ошибок: никто не предупредит, что в переменной оказалось не то, что вы ждали. Отсюда привычка опытных программистов называть переменные так, чтобы имя говорило о типе: marks — список, count — число, isReady — «да / нет». Подробный разбор — день 4, типы и typeof — день 5.

5. Операторы: что делают со значениями

Операторы — это знаки, которые что-то делают со значениями. Арифметические выглядят как в математике: +, -, *, /, % (остаток от деления) и ** (степень). У каждого есть краткая форма с присваиванием, а ++ и -- увеличивают и уменьшают на единицу.

let x = 10;
x += 5;                // то же самое, что x = x + 5 — теперь 15
x++;                   // на единицу больше — теперь 16
console.log(x % 3);    // 1 — остаток от деления 16 на 3
console.log(2 ** 10);  // 1024

Плюс работает не только с числами: если хотя бы один операнд — строка, он склеивает. Отсюда знаменитая ловушка, на которой спотыкается каждый:

console.log("3" + 4 + 5);   // "345" — слева строка, всё стало строкой
console.log(3 + 4 + "5");   // "75"  — сначала 3 + 4 = 7, потом склейка

Сравнивают значения операторами <, >, <=, >=, а на равенство — двумя разными способами, и вот это принципиально:

== нестрогое
123 == "123";  // true
1 == true;     // true

сначала приводит типы друг к другу, потом сравнивает. Результат часто неожиданный.

=== строгое
123 === "123"; // false
1 === true;    // false

сравнивает и значение, и тип. Всегда предсказуемо. Пишем только так.

У обоих есть отрицательная пара: != и !==. Правило курса: всегда === и !==.

Логические операторы — && («и»), || («или») и ! («не»). Работают они не только с true и false, а с «истинностью» любого значения, и — важная деталь — возвращают не «да / нет», а одно из исходных значений:

const a = 0 && "Салам";      // 0      — ноль ложный, дальше не смотрим
const b = "Салам" || "dünýä"; // "Салам" — первое истинное

Это называется короткое замыкание: второй операнд вычисляется только если понадобится. Свойство используют, чтобы подставить запасное значение: const name = input || "Гость";. Дни 6, 7 и 8 разбирают операторы целиком, вместе с таблицей приоритета.

6. Грамматика: как язык читает ваш текст

Грамматика JavaScript похожа на грамматику C и Java, но несколько правил стоит узнать сразу — они объясняют половину ошибок первой недели.

Имена. Имя переменной или функции может состоять из букв, цифр, _ и $, но не может начинаться с цифры. Буквы — любые, в том числе кириллица; писать имена по-русски технически можно, но не принято, и мы так делать не будем. Нельзя брать зарезервированные слова: let, class, return, new и ещё несколько десятков.

Регистр имеет значение. name, Name и NAME — три разные переменные. Это причина половины сообщений «is not defined» у новичков.

Комментарии. Их два вида, и оба игнорируются движком:

// однострочный комментарий — до конца строки

/* многострочный
   комментарий */

Точка с запятой. Формально она необязательна: движок расставляет её сам — это называется автоматической вставкой точки с запятой. Но делает он это по своим правилам, и иногда они расходятся с вашими намерениями. Классический случай:

function getCity() {
  return
    "Мары";      // сюда движок уже не дойдёт
}
console.log(getCity());   // undefined

Движок увидел return, а дальше конец строки — и поставил точку с запятой сразу после return. Функция вернула undefined, а строка «Мары» осталась недостижимой. Поэтому правило курса: точку с запятой ставим сами, а значение после return пишем на той же строке.

7. Ход программы: условия, циклы, ошибки

По умолчанию программа идёт сверху вниз. Управляющие конструкции позволяют свернуть с этого пути: выполнить кусок кода не всегда, выполнить его много раз или перехватить сбой.

Условие — if и else, их можно сцеплять:

if (score >= 90) {
  grade = 5;
} else if (score >= 75) {
  grade = 4;
} else {
  grade = 3;
}

Отдельного слова elif, как в Python, в языке нет: else if — это просто else, внутри которого один if.

Когда веток много и все они сравнивают одно и то же значение, вместо лестницы из else if берут switch:

switch (action) {
  case "добавить":
    addItem();
    break;
  case "удалить":
    removeItem();
    break;
  default:
    console.log("не знаю такой команды");
}

Слово break здесь обязательно: без него выполнение «проваливается» в следующую ветку и идёт дальше по списку. Сравнивает switch строго, через ===. Разбираем на дне 9.

Циклы. Их пять, и каждый для своего случая:

ЦиклКогда нуженДень
forизвестно, сколько раз повторить10
whileповторять, пока условие верно10
do...whileто же, но тело выполнится хотя бы раз10
for...ofпройти по значениям массива или строки11
for...inпройти по именам свойств объекта11
 
for (let i = 0; i < 5; i++) {
  console.log(i);          // 0, 1, 2, 3, 4
}

const marks = [5, 4, 5];
for (const mark of marks) {
  console.log(mark);       // 5, 4, 5 — каждая оценка по очереди
}

Ошибки. Когда движок не может что-то сделать, он «бросает» ошибку, и программа останавливается. Чтобы этого не случилось, опасный участок оборачивают в try...catch:

const text = "{ испорчено";        // текст пришёл испорченным
try {
  const data = JSON.parse(text);
} catch (e) {
  console.error("Разобрать не вышло:", e);
}

Свою ошибку бросают словом throw. Готовых видов ошибок несколько — TypeError, RangeError, SyntaxError, — и через минуту мы научимся их различать по сообщению. Работа с try...catch — день 11.

8. Объекты и массивы

Объект — это набор пар «имя — значение». Имя называют ключом или свойством. В других языках такое называют словарём, хешем или ассоциативным массивом.

const student = {
  name: "Гүлнар",
  age: 17,
  marks: [5, 4, 5],
};

console.log(student.name);       // "Гүлнар" — через точку
console.log(student["age"]);     // 17       — через скобки
student.city = "Мары";           // свойство можно добавить в любой момент

Квадратные скобки нужны, когда имя свойства лежит в переменной или вычисляется. У объекта нет заранее заданной формы: свойства добавляют, удаляют и меняют когда угодно.

Массив — это, строго говоря, тоже объект, просто особый: у него числовые ключи и волшебное свойство length, которое само следит за длиной.

const a = ["ит", "pişik", "towuk"];
console.log(a.length);     // 3
console.log(a[90]);        // undefined — за границей не ошибка, а «ничего»
a.push({ });               // класть можно что угодно, даже объект

Раз массив — объект, ему можно назначить любой индекс, даже с пропуском. Язык не возразит, но так делать не стоит:

const a = ["ит", "pişik", "towuk"];
a[100] = "tilki";
console.log(a.length);   // 101 — длина подтянулась за самым большим индексом
console.log(a);          // (101) ['ит', 'pişik', 'towuk', empty × 97, 'tilki']

Между третьим элементом и сотым — девяносто семь пустых мест. Такой массив называют разреженным, и движок перестаёт работать с ним как с массивом, переключаясь на медленный способ хранения. Правило простое: заполняйте массив подряд, а добавляйте в конец методом push.

Объекты и массивы передаются по ссылке. Переменная хранит не сам объект, а «адрес», по которому он лежит. Поэтому два одинаковых с виду объекта никогда не равны, а копия переменной — это не копия объекта: 
const me = { };
const stillMe = me;
me.x = 1;
console.log(stillMe.x);      // 1 — объект-то один
console.log({ } === { });    // false — разные объекты

Эта одна строчка — источник самых обидных ошибок в работе: «я же скопировал массив, почему изменился оригинал?». Разбираем на дне 19, а способы честно копировать — на дне 22.

9. Функции

Функция — кусок программы с именем, который можно вызвать сколько угодно раз. Вместе с объектами это главное, из чего собирают код.

function add(x, y) {
  const total = x + y;
  return total;
}

console.log(add(2, 3));   // 5

Несколько правил, которые удивляют пришедших из других языков:

  • функцию можно вызвать с любым числом аргументов. Не хватило — недостающие станут undefined; лишние просто игнорируются;
  • если return нет или он пустой, функция возвращает undefined;
  • переменные, объявленные внутри, снаружи не видны.
add();          // NaN — это undefined + undefined
add(2, 3, 4);   // 5   — четвёрку никто не спросил

Имя у функции необязательно. Безымянную функцию кладут в переменную или передают в другую функцию. Короткая запись такой функции — стрелочная:

const sum = function (a, b) { return a + b; };   // функция-выражение
const sum2 = (a, b) => a + b;                    // стрелочная: короче и без return

Функции в JavaScript — полноценные значения. Их кладут в переменные, передают аргументами, возвращают из других функций и даже хранят в массивах. Это и есть «функции — объекты первого класса», и на этом стоит половина приёмов языка:

const babies = ["ит", "pişik"].map((name) => `kiçi ${name}`);
// ["kiçi ит", "kiçi pişik"]

Что ещё умеют параметры

Раз аргументов можно передать сколько угодно, язык даёт три способа с этим управляться. Все три встретятся в курсе, и все три вы увидите в чужом коде уже на этой неделе.

// 1. Значение по умолчанию — если аргумент не передали
function greet(name = "Гость") {
  return `Салам, ${name}!`;
}
greet();           // "Салам, Гость!"

// 2. Остаточные параметры — собрать «все остальные» в массив
function avg(...numbers) {
  let sum = 0;
  for (const n of numbers) sum += n;
  return sum / numbers.length;
}
avg(2, 3, 4, 5);   // 3.5

// 3. Разворот массива в список аргументов — обратная операция
const marks = [5, 4, 3];
avg(...marks);     // то же самое, что avg(5, 4, 3)

Именованных аргументов, как в Python, в языке нет. Но их подделывают: передают один объект и тут же разбирают его на части — это называется деструктуризацией.

function area({ width, height }) {
  return width * height;
}
area({ width: 2, height: 3 });   // 6 — видно, где какое число

Значения по умолчанию и остаточные параметры — день 14, деструктуризация и ... — день 22.

Наконец, функцию можно объявить внутри другой функции, и вложенная увидит переменные внешней. Отсюда растут замыкания — большая тема курса 2. Нам же хватит дней 12–15: объявление, параметры, return, стрелочные функции, значения по умолчанию.

10. Классы, модули, асинхронность

Три большие части языка мы в Essentials только назовём. Знать, что они есть, важно: вы встретите их в любом чужом коде.

Классы

Класс — это шаблон, по которому делают однотипные объекты. Запись похожа на Java:

class Person {
  constructor(name) {
    this.name = name;
  }
  sayHello() {
    return `Салам, мен ${this.name}!`;
  }
}

const p = new Person("Мерет");
console.log(p.sayHello());

Под классами в JavaScript скрывается механизм прототипов — свой, не такой, как в Java или C++. Всё это разбирается в курсе 2.

Асинхронность

JavaScript однопоточный: в один момент времени выполняется ровно одна строка кода. Но ждать ответа сервера, стоя на месте, нельзя — иначе страница замрёт. Поэтому долгие операции запускают, а результат получают позже. Способов записать это три:

// 1. Функция обратного вызова — самый старый способ
setTimeout(() => console.log("прошла секунда"), 1000);

// 2. Промис
fetch(url).then((response) => console.log(response.status));

// 3. async / await — то же самое, но читается сверху вниз
async function load() {
  const response = await fetch(url);
  console.log(response.status);
}

Все три встретятся на днях 30 и 31, в конце курса. Самое важное сейчас: у асинхронного значения нельзя «просто взять» результат сразу — его получают, когда он придёт.

Модули

Когда файл один, всё просто. Когда их десять, код делят на модули и связывают словами import и export:

// только в модуле; в консоли — SyntaxError: Cannot use import statement outside a module
import { average } from "./math.js";

export const city = "Мары";

Модули — курс 2. В Essentials мы обходимся одним-двумя файлами скриптов, подключёнными к странице.

11. Язык и его хозяин

Есть разделение, без которого дальше будет путаница. Сам язык — это числа, строки, объекты, функции, if и for. Он описан в спецификации ECMAScript и одинаков везде. Но у самого языка нет ни ввода, ни вывода: он умеет считать, но не умеет ни показать результат, ни спросить пользователя.

Среду выполнения называют хозяином или рантаймом. Браузер — один хозяин, Node.js — другой. Даже console.log, который мы пишем на каждом уроке, придуман не языком, а средой: его даёт браузер.

Отсюда практический вывод. Если пример из интернета не работает у вас в браузере, первым делом спросите: а не для Node.js ли он написан? require, fs.readFile, process.argv в браузере не заработают никогда — не потому, что вы что-то сделали не так.

12. Первая программа целиком

Теперь соберём всё перечисленное в одну работающую программу. Два файла в одной папке — как на дне 2. Программа считает средний балл и выводит его на страницу.

Файл index.html:

<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Табель</title>
  <script src="app.js" defer></script>
</head>
<body>
  <h1>Табель за неделю</h1>
  <p id="result">Считаем...</p>
</body>
</html>

Файл app.js:

const student = {
  name: "Аман",
  marks: [5, 4, 5, 3, 5],
};

function average(numbers) {
  let sum = 0;
  for (const n of numbers) {
    sum += n;
  }
  return sum / numbers.length;
}

const score = average(student.marks);

let verdict;
if (score >= 4.5) {
  verdict = "отлично";
} else if (score >= 3.5) {
  verdict = "хорошо";
} else {
  verdict = "надо подтянуть";
}

const line = `${student.name}: средний балл ${score.toFixed(2)} — ${verdict}`;
console.log(line);
document.getElementById("result").textContent = line;
Аман: средний балл 4.40 — хорошо

Двадцать семь строк — и в них уместился весь сегодняшний обзор. Посмотрите, из чего они собраны:

Наберите обе страницы руками (не копируйте!) и откройте index.html. Затем поменяйте оценки в массиве так, чтобы получилось «отлично», и так, чтобы получилось «надо подтянуть». Проверьте, что число в скобках toFixed(2) управляет количеством знаков после запятой.

13. Как читать сообщение об ошибке

Программа сломается — это нормально, и ломаться она будет каждый день. Разница между новичком и опытным программистом не в том, что у второго нет ошибок, а в том, что он их читает. Сообщение в консоли устроено одинаково и всегда отвечает на три вопроса: что за ошибка, что именно не так и где это случилось.

Самое ценное здесь — последняя часть. Адрес app.js:27:47 в консоли кликается: браузер откроет файл и поставит курсор ровно в то место. Новички это место не замечают и ищут ошибку глазами по всему файлу.

Видов ошибок немного, и по виду уже понятно, куда смотреть:

ВидЧто произошлоКуда смотреть
SyntaxError текст не по правилам языка скобки, кавычки, запятые — обычно строкой выше указанной
ReferenceError такого имени нет опечатка в имени или переменная объявлена ниже
TypeError значение не умеет того, что от него хотят там null или undefined, либо вызвали не функцию
RangeError число вне допустимых пределов длина массива, toFixed(101), бесконечная рекурсия
SyntaxError ломает весь файл сразу, ещё до выполнения первой строки. Если кажется, что «скрипт вообще не подключился», — сначала посмотрите, нет ли в консоли красного SyntaxError. Одна незакрытая скобка отключает программу целиком.

Есть и вторая, более коварная категория: код выполнился, ошибки нет, а результат неправильный. Здесь консоль молчит, и помогает то, что мы разбирали вчера: console.log в подозрительных местах, точки останова и debugger.

Ломайте программу нарочно. Уберите defer из <script>, напишите avarage вместо average, сотрите закрывающую скобку — и прочитайте, что скажет браузер. Пятнадцать минут такой игры экономят потом часы. Именно это мы и сделаем на практике.

// TypeError: ... at app.js:27:47  →  вид, текст, файл:строка:столбец
  1. Сколько в языке типов значений и какой из них не примитив?
    Ответ Восемь. Семь примитивов — Number, BigInt, String, Boolean, Symbol, Undefined, Null — и объект. Массивы и функции тоже объекты.
  2. Чем null отличается от undefined?
    Ответ undefined — значение не клали: переменную объявили без значения, свойства нет, функция ничего не вернула. null — пустоту поставил программист намеренно.
  3. Что выведет console.log("3" + 4 + 5) и почему?
    Ответ "345". Слева строка, поэтому плюс склеивает: сначала "34", потом "345". А 3 + 4 + "5" даст "75".
  4. Почему console.log не считается частью языка?
    Ответ Сам язык не умеет ни вводить, ни выводить. console даёт среда выполнения: браузер или Node.js. Так же устроены document, fetch, alert.
  5. В консоли написано Uncaught TypeError: ... at app.js:27:47. Что делать первым?
    Ответ Щёлкнуть по app.js:27:47 — браузер откроет файл на строке 27. Затем посмотреть, какое значение там оказалось: при TypeError это обычно null или undefined.
