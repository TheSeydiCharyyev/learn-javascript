# Day 4. Variables

<Subtitle>A summary of the lecture: three declaration words, scope, the dead zone, six errors.</Subtitle>

## The main points

<Definition>
A **variable** is a name that a value is attached to. It has three properties:
a **name** (what it is called), **mutability** (can another value be put in)
and a **lifetime** (from which line to which line it exists).
</Definition>

<KeyPoint>
The rule of choice for the whole course: write `const`; if the value has to be replaced, change it
to `let`. Never write `var`, but you must be able to read it.
</KeyPoint>

## Three words

|  | `const` | `let` | `var` |
| --- | --- | --- | --- |
| replace the value | no | yes | yes |
| an initializer is needed | yes | no | no |
| visible only in the block | yes | yes | no |
| declare again | no | no | yes, silently |
| access before declaration | error | error | `undefined` |
| gets into `globalThis` | no | no | yes |

## Declaration

```js
let score = 42;   // let score is the declaration, = 42 is the initializer
let empty;        // undefined
// const total;   → SyntaxError: Missing initializer in const declaration

let first = 1, second = first + 1;   // a list: second sees first, second = 2
let x = y = 5;          // a trap: y became an accidental global
```

## const holds the name, not the contents

```js
const city = "Mary";
// city = "Ashgabat";   → TypeError: Assignment to constant variable.

const basket = ["bread"];
basket.push("tea");     // works — we change the contents, not the name
const user = { n: 1 };
user.n = 2;             // works too
```

<Remember>
The variable holds not the object but the address of the object. `const` forbids changing the address,
but does not forbid coming to it and rearranging the things inside.
</Remember>

## Where a variable is visible

```js
if (true) { let b = 1; var c = 2; }
// console.log(b);   → ReferenceError: b is not defined — let did not leave the block
console.log(c);   // 2 — var does not know about the block

let s = 1;
{ let s = 2; }    // shadowing: a different variable
console.log(s);   // 1

for (const n of [1, 2, 3]) { }   // for...of — const
for (let i = 0; i < 3; i++) { }  // an ordinary for — let
```

<Remember>
Visibility goes only inward: from inside a block you see the outer variables, from outside you do not see the inner ones.
If you need a value after a block, declare it with `let` **before** the block, and inside
only assign.
</Remember>

## Access before declaration

```js
// in app.js:
console.log(m);  var m = 1;   // undefined — the declaration is hoisted, the value is not
typeof nothingAtAll;          // "undefined" — the name does not exist at all, and that is not an error

// console.log(n);  let n = 1;   → ReferenceError: Cannot access 'n' before initialization
// { typeof i; let i = 10; }     → ReferenceError: Cannot access 'i' before initialization
```

The dead zone lasts from the opening brace of the block to the line of the declaration.

## Six errors of the day

| Code | Message in Chrome |
| --- | --- |
| `const x = 1; x = 2;` | `TypeError: Assignment to constant variable.` |
| `const x;` | `SyntaxError: Missing initializer in const declaration` |
| `var = 5;` | `SyntaxError: Unexpected token '='` |
| `console.log(a); let a = 1;` | `ReferenceError: Cannot access 'a' before initialization` |
| `"use strict"; b = 5;` | `ReferenceError: b is not defined` |
| `const o = Object.freeze({ x: 1 }); o.x = 2;` | `TypeError: Cannot assign to read only property 'x' of object '#<Object>'` |

`SyntaxError` — not a single line ran; look for a brace or a quote.
`ReferenceError` and `TypeError` — on the way, so everything before them has run.
The last two rows of the table fire only in strict mode.

## An undeclared variable

```js
let total = 0;
totl = total + 5;     // a typo: a global was silently created
console.log(total);   // 0, but we expected 5 — and not a single message
```

<NoteBox>
**Names.** Case matters: `userName` and `username` are different
variables. We write with the letters a–z: ordinary ones — `camelCase`, settings — `MAX_SCORE`,
“yes / no” — `isReady`, lists — in the plural.
\
**Traps.** `if (true) let a = 1;` is a SyntaxError; braces are needed.
An extra `;` after `for (...)` closes the loop. Nested `/* */`
give a puzzling “Invalid regular expression”.
</NoteBox>
