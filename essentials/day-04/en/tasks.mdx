# Day 4. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–2 are done in the console, the rest in the folder `day-04`.</Subtitle>

## Warm-up

<Task title="1. const or let" level="easy" time="6">
<Goal>learn to choose the declaration word by meaning.</Goal>

For each quantity, write a declaration line and choose `const` or `let`.
Next to it, in one word — why.

- the name of your city;
- a counter of correct answers in a game;
- the number of days in a week;
- the current temperature outside;
- a list of subjects in the timetable, to which one more will be added later.

<Hint>
The last item is a trap. Ask yourself: does the name change or the contents?
</Hint>

<Criteria>
- five declaration lines are written;
- the reason for the choice is given for each;
- the list of subjects is declared with `const` — and it is explained why this does not stop you
  from adding subjects.
</Criteria>
</Task>

<Task title="2. What const forbids" level="easy" time="7">
<Goal>see the border between the name and the contents with your own eyes.</Goal>

Run the lines one at a time and write down what the console answered: a value or an error.

```js
const city = "Mary";
city = "Ashgabat";

const marks = [5, 4];
marks.push(3);
marks[0] = 2;
marks = [1];

const user = { name: "Aman" };
user.name = "Meret";
user.age = 17;
user = { };
```

<Criteria>
- the result is written down for each line;
- all three lines that give an error are found;
- the general rule is put into one sentence.
</Criteria>
</Task>

<Task title="3. Predict first: visible or not" level="easy" time="7">
<Goal>catch the difference between `let` and `var` before running.</Goal>

First write down in your notebook what each `console.log` prints. Then check
in `app.js`, one fragment at a time: an error stops the file, and the following lines
will not run.

```js
// 1
if (true) {
  let a = 1;
  var b = 2;
}
console.log(b);
console.log(a);

// 2
console.log(c);
var c = 3;

// 3
console.log(d);
let d = 4;
```

<Criteria>
- the predictions are written down *before* the check;
- the real answers are next to them, the differences are marked;
- it is explained why two lines gave different errors.
</Criteria>
</Task>

<Task title="6. The variable escaped from the block" level="medium" time="13">
<Goal>learn to fix the most common scope mistake.</Goal>

This code does not work. Find the cause, fix it in two different ways and decide which is better.

```js
const temperature = 31;

if (temperature > 30) {
  const advice = "stay at home";
} else {
  const advice = "you can go out";
}

console.log(`Today it is ${temperature} degrees: ${advice}`);
```

<Hint>
There are exactly two ways, and they are opposite: either **move the declaration up** above the block,
or **move the use down** into the block. In the second case the output line
will have to be written twice.
</Hint>

<Criteria>
- the kind of error and its cause are named;
- both fixes work;
- in the first fix you had to take `let` — it is explained why
  `const` does not fit here;
- in the second fix `const` stayed — it is explained why it is allowed now;
- it is written down which fix you would keep and why.
</Criteria>
</Task>

## Starred tasks

<Task title="8. A silent typo" level="hard" time="10">
<Goal>see why an undeclared variable is dangerous and learn to catch it.</Goal>

This code gives no errors but calculates wrongly. Run it, find the cause, fix it.

```js
let summa = 0;
const prices = [10, 20, 30];

for (const price of prices) {
  sumaa = summa + price;
}

console.log("Total:", summa);
```

Then do two experiments: type `globalThis.sumaa` in the console, and then put
`"use strict";` as the first line of the file and run it again.

<Criteria>
- it is named what exactly the program prints and what it should print;
- it is written down what `globalThis.sumaa` answered and where this variable came from;
- it is written down what changed after `"use strict";` — with the exact text of the error;
- a conclusion is made: why a typo in a name is harder to find than a syntax error.
</Criteria>
</Task>

<Task title="9. Four traps" level="hard" time="10">
<Goal>bring together everything that behaves unexpectedly today.</Goal>

For each fragment **first** write down a prediction, then check it
and explain the difference in one sentence.

```js
// 1
let n = 0;
for (let i = 0; i < 3; i++);
  n++;
console.log(n);

// 2
let x = y = 5;
console.log(globalThis.y);

// 3
for (var a of [1, 2, 3]);
console.log(a);

// 4
const frozen = Object.freeze({ value: 1 });
frozen.value = 99;
console.log(frozen.value);
```

<Hint>
None of the four gives an error in normal mode. That is exactly why they are dangerous: the program
“works”, but the result is wrong.
</Hint>

<Criteria>
- the predictions are written down before running;
- for each fragment the cause is named: an empty statement, an undeclared variable,
  the scope of `var`, a frozen object;
- the fourth fragment is checked once more with `"use strict";`, the difference is written down;
- the first fragment is rewritten so that it prints 3.
</Criteria>
</Task>
