# Day 5. Data types

<Subtitle>A summary of the lecture: eight types, `typeof`, `null` and `undefined`, `NaN`, conversions and checks.</Subtitle>

## The main points

<Definition>
JavaScript is **dynamic** — the type belongs to the value, not to the variable.
And it is **weakly typed** — when different types meet, the language converts them by itself,
without an error. All of today’s oddities come from this.
</Definition>

<KeyPoint>
The seven primitives are **immutable** — they can only be replaced whole.
The object is the only mutable type and the only one passed by reference.
</KeyPoint>

## typeof

```js
typeof 42;            // "number"      typeof "Mary";   // "string"
typeof true;          // "boolean"     typeof undefined; // "undefined"
typeof 9n;            // "bigint"      typeof Symbol();  // "symbol"
typeof { };           // "object"      typeof function(){}; // "function"

typeof null;          // "object"   ← a mistake of the language from 1995
typeof [1, 2];        // "object"   ← an array is not told apart
typeof notDeclared;   // "undefined" — the only operator that does not fail
```

<Remember>
There are exactly eight answers; the list is closed. We check `null` with `=== null`,
an array with `Array.isArray()`.
</Remember>

## null and undefined

|  | `null` | `undefined` |
| --- | --- | --- |
| meaning | empty on purpose | there is no value |
| who puts it | the programmer | the language |
| `typeof` | `"object"` | `"undefined"` |
| `+ 1` | `1` | `NaN` |
| `Number()` | `0` | `NaN` |

```js
null == undefined;    // true
null === undefined;   // false
x == null;            // a handy “empty” check: catches both
```

The language puts in `undefined` in four cases: `let x;`, a property that does not exist,
a function without `return`, a missing argument. There is no error in any of them.

## NaN

```js
typeof NaN;           // "number" — it is a number value
NaN === NaN;          // false — the only one not equal to itself
NaN > 1;  NaN < 1;    // both false — any comparison is false

Number.isNaN(x);      // the right check
isNaN("salam");       // true — converts to a number first, be careful
Number.isNaN("salam");// false
```

<Remember>
`NaN` is contagious: any operation with it gives `NaN`. Check a number that came
from the user right away, not at the end of the calculation.
</Remember>

## Infinity

```js
1 / 0;                 // Infinity — division by zero is not an error
Number.MAX_VALUE * 2;  // Infinity
Infinity - Infinity;   // NaN
42 / -0;               // -Infinity — there are two zeros, +0 and -0
```

## Conversions

| Value | `Number()` | `String()` | `Boolean()` |
| --- | --- | --- | --- |
| `"12px"` | `NaN` | `"12px"` | `true` |
| `""` | `0` | `""` | `false` |
| `null` | `0` | `"null"` | `false` |
| `undefined` | `NaN` | `"undefined"` | `false` |
| `[]` | `0` | `""` | `true` |

<Remember>
There are six falsy values: `false`, `0` (zero in any form: both `-0` and
`0n`), `""`, `NaN`, `null`, `undefined`. Everything else is truthy — including `"0"`,
`[]` and `{}`.
\
`new Boolean(false)` is an object, and it is **truthy**.
We write `Boolean`, `Number` and `String` without `new`.
</Remember>

## A cheat sheet of checks

{/* ahead-ok: day 7 */}

```js
typeof x === "number" && !Number.isNaN(x)   // a number
typeof x === "string"                       // a string
typeof x === "function"                     // a function
Array.isArray(x)                            // an array
typeof x === "object" && x !== null && !Array.isArray(x)   // an object
x === null;   x === undefined;   x == null  // emptiness
!x                                          // any falsy value — careful, zero too!
```

## Two errors

```js
// ReferenceError: score is not defined   — there is no name
// TypeError: Cannot read properties of undefined (reading 'marks')
//                                        — the name exists, the value is wrong
```

<NoteBox>
**How to fix a `TypeError`.** The message names the property in parentheses:
`(reading 'marks')`. The culprit is not it but what is **left of the dot**.
In a chain `a.b.c.d`, the text `(reading 'd')` means that `a.b.c`
turned out to be empty. Go left and look for where the emptiness came from.
</NoteBox>
