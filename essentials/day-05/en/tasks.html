Day 5. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-05.

Warm-up

1. The typeof table
Easy6 min

see all the answers of typeof with your own eyes.

Ask typeof about each value and write down the answer. Then mark the two places where the answer does not match the real type of the value.

const values = [42, 9007199254740993n, "Mary", true, Symbol("id"),
  undefined, null, { }, [1, 2], function () { }, new Date()];
  • all eleven answers are written down;
  • null and the array are marked, with an explanation of how the answer is wrong;
  • it is written down how many different answers there are in total.
2. Three conversions
Easy7 min

remember what each conversion function gives.

Fill in a table: apply Number(), String() and Boolean() to each value.

const values = ["42", "12px", "", "0", null, undefined, [], [5], { }];
Two answers in the Number() column are zero where you would expect NaN. Find them.
  • the 9 × 3 table is filled in;
  • both cases where Number() gives 0 are found;
  • it is explained why Boolean([]) is true.
3. Predict first: truthy or falsy
Easy7 min

learn the six falsy values through practice.

First write down a prediction for each line in your notebook, then check.

Boolean(0)
Boolean("0")
Boolean("")
Boolean(" ")
Boolean([])
Boolean({ })
Boolean(NaN)
Boolean(-1)
Boolean(null)
!!"false"
  • the predictions are written down before the check;
  • the real answers are next to them, the differences are marked;
  • all the falsy values in the list are written out — there should be four;
  • it is explained what !! does.

Main tasks

4. Hunting NaN
Medium12 min

learn to catch NaN with the right check.

Run each expression and write down whether you got NaN. Then check each result in three ways: === NaN, isNaN() and Number.isNaN().

Number("salam")
Math.sqrt(-1)
0 * Infinity
Infinity - Infinity
7 * "blabla"
"5" * 2
new Date("blabla").getTime()
a table: expression → result → the three check answers.

Then a second experiment. Apply both functions not to the result but to the values themselves:

isNaN("salam");          Number.isNaN("salam");
isNaN(undefined);        Number.isNaN(undefined);
isNaN("42");             Number.isNaN("42");
  • the expression that does not give NaN is found;
  • it is shown that === NaN never works;
  • it is noted that on the results of the first table isNaN() and Number.isNaN() agreed everywhere;
  • in the second experiment all the cases where they differ are found and explained: one function converts the value to a number first, the other does not;
  • a conclusion is made about which check to write in code.
5. A type-describing function
Medium14 min

collect all of today’s checks into one working function.

Write a function describe(value) that returns a string with the real type of the value. It must correctly tell apart: a number, NaN, a string, a boolean, null, undefined, an array, an object, a function.

describe(42);        // "number"
describe(NaN);       // "not a number (NaN)"
describe(null);      // "null"
describe([1, 2]);    // "array"
describe({ });       // "object"
The order of checks matters. Check null before typeof === "object", and NaN inside the number branch.
  • all nine cases are told apart correctly;
  • describe(null) does not return “object”;
  • describe(NaN) does not return “number”;
  • the function is checked on all nine values, the results are written down.
6. Input checks in the “Report card”
Medium13 min

apply type checks to a real program.

Copy the folder day-04 to day-05 and add a function parseMark(input): it takes a string and returns a number from 2 to 5, or null if the input is not valid.

Check it on the list and write down what came back for each value:

const inputs = ["5", "five", "", "  4  ", "10", "3.5", null];
One of these values turns into a number although it looks empty, and another gives a number outside the range of marks. The function must filter out both situations.
  • an answer is written down for all seven values;
  • "" does not pass as a mark — it is explained why this is not obvious;
  • "10" does not pass;
  • invalid input gives exactly null, not undefined — it is explained why this difference matters.
7. Go left of the dot
Medium11 min

learn to read a TypeError and find the real line of the error.

Run it and fix it. For each error write down: the text of the message, which property is in the parentheses and on which line the real cause is.

const group = {
  name: "IT-1",
  students: [
    { name: "Aman", marks: [5, 4] },
  ],
};

console.log(group.students[0].marks.length);
console.log(group.students[1].marks.length);
console.log(group.teacher.name);
console.log(group.name.lenght);
The fourth line is a special case: it does not fail. Think about why, and what this says about typos in property names.
  • the exact error text is written down for the two failing lines;
  • for each one it is named what exactly turned out to be empty left of the dot;
  • it is explained why the last line does not fail and what it prints;
  • the code is fixed so that no line fails.

Starred tasks

8. Zero, emptiness and nothing
Hard10 min

see why the short check !x can be a mistake.

The function should say “enter your age” only if the age was not passed. It works wrongly. Find on which value, and fix it.

function checkAge(age) {
  if (!age) {
    return "enter your age";
  }
  return `age: ${age}`;
}

console.log(checkAge(17));
console.log(checkAge(0));
console.log(checkAge(null));
console.log(checkAge(undefined));
console.log(checkAge(""));
  • the value on which the function lies is named;
  • it is explained what the list of six falsy values has to do with it;
  • the function is fixed, and checkAge(0) gives “age: 0”;
  • it is written down what checkAge("") returns now and whether that is right.
9. Five type traps
Hard10 min

bring together everything that behaves differently from how it looks today.

For each fragment first write down a prediction, then check it and explain the difference in one sentence.

// 1
console.log(typeof null === "object" && null.length);

// 2
const flag = new Boolean(false);
if (flag) {
  console.log("yes");
} else {
  console.log("no");
}

// 3
console.log(null + 1, undefined + 1);

// 4
console.log(isNaN("salam"), Number.isNaN("salam"));

// 5
let word = "Mary";
word[0] = "C";
console.log(word);
One of the five fragments throws an error; the other four quietly give an unexpected result. Find which one, and why.
  • the predictions are written down before running;
  • the only fragment with an error is found, its kind is named;
  • for the other four the cause is named: a wrapper, the conversion of null, the difference between the NaN checks, the immutability of strings;
  • fragment 5 is rewritten so that it gives “Cary”.
