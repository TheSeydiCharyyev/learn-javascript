- `null` and the array are marked, with an explanation of how the answer is wrong;
- it is written down how many different answers there are in total.

## Main tasks

<Task title="4. Hunting NaN" level="medium" time="12">
<Goal>learn to catch `NaN` with the right check.</Goal>

Run each expression and write down whether you got `NaN`. Then check each
result in three ways: `=== NaN`, `isNaN()` and `Number.isNaN()`.

{/* ahead-ok: day 17 */}

```js
Number("salam")
Math.sqrt(-1)
0 * Infinity
Infinity - Infinity
7 * "blabla"
"5" * 2
new Date("blabla").getTime()
```

<WriteBox>
a table: expression → result → the three check answers.
</WriteBox>

Then a second experiment. Apply both functions not to the result but to the values themselves:

```js
isNaN("salam");          Number.isNaN("salam");
isNaN(undefined);        Number.isNaN(undefined);
isNaN("42");             Number.isNaN("42");
```

<Criteria>
- the expression that does **not** give `NaN` is found;
- it is shown that `=== NaN` never works;
- it is noted that on the results of the first table `isNaN()`
  and `Number.isNaN()` agreed everywhere;
- in the second experiment all the cases where they differ are found and explained:
  one function converts the value to a number first, the other does not;
- a conclusion is made about which check to write in code.
</Criteria>
</Task>

<Task title="5. A type-describing function" level="medium" time="14">
<Goal>collect all of today’s checks into one working function.</Goal>

Write a function `describe(value)` that returns a string with the real type
of the value. It must correctly tell apart: a number, `NaN`, a string, a boolean,
`null`, `undefined`, an array, an object, a function.

<Example>
```js
describe(42);        // "number"
describe(NaN);       // "not a number (NaN)"
describe(null);      // "null"
describe([1, 2]);    // "array"
describe({ });       // "object"
```
</Example>

<Hint>
The order of checks matters. Check `null` **before**
`typeof === "object"`, and `NaN` inside the number branch.
</Hint>

<Criteria>
- all nine cases are told apart correctly;
- `describe(null)` does not return “object”;
- `describe(NaN)` does not return “number”;
- the function is checked on all nine values, the results are written down.
</Criteria>
</Task>

<Task title="7. Go left of the dot" level="medium" time="11">

## Starred tasks

<Task title="8. Zero, emptiness and nothing" level="hard" time="10">
<Goal>see why the short check `!x` can be a mistake.</Goal>

The function should say “enter your age” only if the age was not passed. It works
wrongly. Find on which value, and fix it.

```js
function checkAge(age) {
  if (!age) {
    return "enter your age";
  }
  return `age: ${age}`;
}

console.log(checkAge(17));
console.log(checkAge(0));
console.log(checkAge(null));
console.log(checkAge(undefined));
console.log(checkAge(""));
```

<Criteria>
- the value on which the function lies is named;
- it is explained what the list of six falsy values has to do with it;
- the function is fixed, and `checkAge(0)` gives “age: 0”;
- it is written down what `checkAge("")` returns now and whether that is right.
</Criteria>
</Task>

<Task title="9. Five type traps" level="hard" time="10">
<Goal>bring together everything that behaves differently from how it looks today.</Goal>

For each fragment **first** write down a prediction, then check it
and explain the difference in one sentence.

{/* ahead-ok: day 7 */}

```js
// 1
console.log(typeof null === "object" && null.length);

// 2
const flag = new Boolean(false);
if (flag) {
  console.log("yes");
} else {
  console.log("no");
}

// 3
console.log(null + 1, undefined + 1);

// 4
console.log(isNaN("salam"), Number.isNaN("salam"));

// 5
let word = "Mary";
word[0] = "C";
console.log(word);
```

<Hint>
One of the five fragments throws an error; the other four quietly give an unexpected result.
Find which one, and why.
</Hint>

<Criteria>
- the predictions are written down before running;
- the only fragment with an error is found, its kind is named;
- for the other four the cause is named: a wrapper, the conversion of `null`,
  the difference between the `NaN` checks, the immutability of strings;
- fragment 5 is rewritten so that it gives “Cary”.
</Criteria>
</Task>
