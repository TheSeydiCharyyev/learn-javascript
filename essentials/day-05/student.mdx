# День 5. Типы данных

<Subtitle>Выжимка лекции: восемь типов, `typeof`, `null` и `undefined`, `NaN`, превращения и проверки.</Subtitle>

## Главное

<Definition>
JavaScript **динамический** — тип принадлежит значению, а не переменной.
И **слабо типизированный** — при встрече разных типов язык приводит их сам,
без ошибки. Отсюда все сегодняшние странности.
</Definition>

<KeyPoint>
Семь примитивов **неизменяемы** — их можно только заменить целиком.
Объект — единственный изменяемый тип и единственный, что передаётся по ссылке.
</KeyPoint>

## typeof

```js
typeof 42;            // "number"      typeof "Мары";   // "string"
typeof true;          // "boolean"     typeof undefined; // "undefined"
typeof 9n;            // "bigint"      typeof Symbol();  // "symbol"
typeof { };           // "object"      typeof function(){}; // "function"

typeof null;          // "object"   ← ошибка языка 1995 года
typeof [1, 2];        // "object"   ← массив не отличается
typeof neObyavlena;   // "undefined" — единственный оператор, что не падает
```

<Remember>
Ответов ровно восемь, список закрытый. `null` проверяем через `=== null`,
массив — через `Array.isArray()`.
</Remember>

## null и undefined

|  | `null` | `undefined` |
| --- | --- | --- |
| смысл | пусто намеренно | значения нет |
| кто кладёт | программист | язык |
| `typeof` | `"object"` | `"undefined"` |
| `+ 1` | `1` | `NaN` |
| `Number()` | `0` | `NaN` |

```js
null == undefined;    // true
null === undefined;   // false
x == null;            // удобная проверка «пусто»: ловит оба
```

Язык подставляет `undefined` в четырёх случаях: `let x;`, несуществующее
свойство, функция без `return`, пропущенный аргумент. Ошибки при этом нет.

## NaN

```js
typeof NaN;           // "number" — это числовое значение
NaN === NaN;          // false — единственное, не равное себе
NaN > 1;  NaN < 1;    // оба false — любое сравнение ложно

Number.isNaN(x);      // правильная проверка
isNaN("салам");       // true — сначала превращает в число, осторожно
Number.isNaN("салам");// false
```

<Remember>
`NaN` заразен: любое действие с ним даёт `NaN`. Число, пришедшее
от пользователя, проверяйте сразу, а не в конце расчёта.
</Remember>

## Infinity

```js
1 / 0;                 // Infinity — деление на ноль не ошибка
Number.MAX_VALUE * 2;  // Infinity
Infinity - Infinity;   // NaN
42 / -0;               // -Infinity — нулей два, +0 и -0
```

## Превращения

| Значение | `Number()` | `String()` | `Boolean()` |
| --- | --- | --- | --- |
| `"12px"` | `NaN` | `"12px"` | `true` |
| `""` | `0` | `""` | `false` |
| `null` | `0` | `"null"` | `false` |
| `undefined` | `NaN` | `"undefined"` | `false` |
| `[]` | `0` | `""` | `true` |

<Remember>
Ложных шесть: `false`, `0` (ноль в любом виде: и `-0`, и
`0n`), `""`, `NaN`, `null`, `undefined`. Всё остальное истинно — в том числе `"0"`,
`[]` и `{}`.
\
`new Boolean(false)` — объект, и он **истинен**.
`Boolean`, `Number`, `String` пишем без `new`.
</Remember>

## Шпаргалка проверок

{/* ahead-ok: день 7 */}

```js
typeof x === "number" && !Number.isNaN(x)   // число
typeof x === "string"                       // строка
typeof x === "function"                     // функция
Array.isArray(x)                            // массив
typeof x === "object" && x !== null && !Array.isArray(x)   // объект
x === null;   x === undefined;   x == null  // пустота
!x                                          // любое ложное — осторожно, ноль тоже!
```

## Две ошибки

```js
// ReferenceError: schet is not defined   — имени нет
// TypeError: Cannot read properties of undefined (reading 'marks')
//                                        — имя есть, значение не то
```

<NoteBox>
**Как чинить `TypeError`.** Сообщение называет свойство в скобках:
`(reading 'marks')`. Виновато не оно, а то, что **слева от точки**.
В цепочке `a.b.c.d` запись `(reading 'd')` означает, что пустым оказалось
`a.b.c`. Идите влево и ищите, откуда там взялась пустота.
</NoteBox>
