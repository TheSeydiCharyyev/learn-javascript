## Warm-up

<Task title="1. Plus or joining" level="easy" time="6">
<Goal>catch the difference between addition and joining.</Goal>

```js
2 + 3
"2" + 3
2 + "3"
1 + 2 + "3"
"1" + 2 + 3
"10" - 5
"10" * 2
true + true
```

<Criteria>
- the predictions are written down *before* the check;
- the real answers are next to them, the differences are marked;
- it is explained why two lines with the same numbers gave different results.
</Criteria>
</Task>

<Task title="2. The remainder in practice" level="easy" time="7">
<Goal>master `%` on simple tasks.</Goal>

Calculate in the console and write down the answers:

- whether the number 2026 is even;
- the last digit of 2026;
- the last two digits of 2026;
- how many full weeks there are in 100 days and how many days are left;
- `10 % 0` — what you get.

<Hint>
Full weeks are division with the fractional part dropped: `Math.floor(100 / 7)`.
</Hint>

<Criteria>

- for the weeks both numbers are shown — the whole ones and the remainder;
- it is explained why `10 % 0` gives exactly this result.
</Criteria>
</Task>

<Task title="3. Postfix versus prefix" level="easy" time="7">
<Goal>see what each form returns.</Goal>

Run each fragment on fresh variables and write down both values.

```js
let i = 5;
const a = i++;
console.log(a, i);

let j = 5;
const b = ++j;
console.log(b, j);

let k = 5;
k++;
console.log(k);
```

<Criteria>
- the values are written down for all three fragments;
- it is explained why the form does not matter in the third fragment;
- it is written down what `const c = 1; c++;` gives and why.
</Criteria>
</Task>

## Main tasks

<Task title="4. Time from seconds" level="medium" time="13">
<Goal>apply division and the remainder together.</Goal>

Write a function `formatTime(sec)` that turns a number of seconds into a string
of the form “h:mm:ss”. Check it on the values 65, 600, 3725 and 0.

<Example>
```js
formatTime(3725);   // "1:02:05"
formatTime(65);     // "0:01:05"
```
</Example>

<Hint>
Hours are `Math.floor(sec / 3600)`. Minutes are `Math.floor(sec / 60) % 60`.
Seconds are `sec % 60`. A leading zero can be added with a condition or with
`String(m).padStart(2, "0")`.
</Hint>

<Criteria>
- all four values give the right answer;
- minutes and seconds are printed with a leading zero;
- it is written down what division is responsible for and what the remainder is responsible for;
- it is checked that `formatTime(0)` does not break.
</Criteria>
</Task>

<Task title="5. The bill for an order" level="medium" time="13">
<Goal>build a formula from several steps without mixing up the order.</Goal>

An item costs 1200, 3 of them are bought, there is a 10% discount, then 5% tax on the resulting sum.
Calculate the total, splitting the calculation into named steps and printing each one.

Then answer two questions by changing the code:

- how much it comes to if the tax is calculated **before** the discount, not after;
- how much it comes to without any discount.

<WriteBox>
three sums and a conclusion: whether the order “discount — tax” affects the total.
</WriteBox>

<Criteria>
- the calculation is split into at least three steps with clear names;
- each step is printed to the console;
- all three sums are calculated;
- a conclusion about the order is made and backed up by numbers.
</Criteria>
</Task>

<Task title="6. A carousel both ways" level="medium" time="12">
<Goal>use the remainder for a circular counter and fix going backward.</Goal>

There is an array `["Mon", "Tue", "Wed", "Thu", "Fri"]` and a variable `i = 0`.
Write two lines: one moves `i` forward around the circle, the other backward.
Check that a step back from `i = 0` gives the last day, not an error.

<Hint>
Forward is simple. Backward, `(i - 1) % n` does not work — check what it returns
and remember the formula from section 6 of the lecture.
</Hint>

<Criteria>
- a step forward from “Fri” gives “Mon”;
- a step back from “Mon” gives “Fri”;
- it is written down what the naive version `(i - 1) % 5` returns when i = 0;
- it is explained why `arr[-1]` is not an error but `undefined`.
</Criteria>
</Task>

## Starred tasks

<Task title="8. Take care of the pennies" level="hard" time="10">
<Goal>see the problem of fractional precision and get around it.</Goal>

Run these and write down the results:

```js
0.1 + 0.2
0.1 + 0.2 === 0.3
(0.1 + 0.2).toFixed(2)
Math.abs((0.1 + 0.2) - 0.3) < Number.EPSILON
Math.round(1.005 * 100) / 100
0.1 * 3
```

Then calculate the cost of three items in two ways — with fractional numbers and with whole numbers
(in tenge, dividing only for output) — for two prices: **12 manat 50 tenge**
and **1 manat 10 tenge**. Compare the results in both cases.

<Hint>
For one of the two prices both ways give the same thing, for the other they do not. This is
the most interesting part: the error does not always appear, which means it is hard to catch with tests.
</Hint>

<Criteria>
- all six results are written down;
- it is explained why `Math.round(1.005 * 100)` gives something other than expected;
- both versions of the calculation are written for both prices — four numbers;
- the price on which the ways differed is named;
- a conclusion is made about how to store money and why “it works for me anyway”
  is a bad argument.
</Criteria>
</Task>

<Task title="9. Six traps" level="hard" time="10">
<Goal>bring together everything that behaves unexpectedly today.</Goal>

For each fragment **first** write down a prediction, then check it —
each fragment separately — and explain the difference in one sentence.

```js
// 1
let x = 10;
x += "5";
console.log(x, typeof x);

// 2
console.log(-10 % 3);

// 3
console.log(2 ** 3 ** 2);

// 4
console.log(-2 ** 2);

// 5
let y = 5;
if (y = 0) { console.log("entered"); }
console.log(y);

// 6
console.log([] + [], [] + { });
```

<Hint>
One fragment will not run at all. The other five quietly give an unexpected result —
that is more dangerous.
</Hint>

<Criteria>
- the predictions are written down before running;
- the only fragment with an error is found, its kind and text are written down;
- for the other five the cause is named: joining in `+=`, the sign of the remainder,
  the right associativity of exponentiation, assignment in a condition, the conversion of objects;
- fragments 3, 4 and 5 are rewritten so that they do what is expected of them.
</Criteria>
</Task>
