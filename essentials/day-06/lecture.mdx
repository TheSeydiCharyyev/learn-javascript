## 1. Что такое оператор {#what}

Оператор — знак, который что-то делает со значениями. Значения, к которым он применяется,
называются **операндами**.

```js
2 + 3
// 2 и 3 — операнды, + — оператор, всё вместе — выражение
```

Операторов в языке много, и делятся они по числу операндов:

| Вид | Сколько операндов | Пример |
| --- | --- | --- |
| бинарный | два, оператор в середине | `2 + 3`, `a * b` |
| унарный | один | `-5`, `+"42"`, `i++` |
| тернарный | три | `a ? b : c` — день 7 |

Всего операторов в языке около полусотни, и они разбиты на группы. Вот вся карта — чтобы вы
представляли, где мы находимся:

| Группа | Примеры | Где разбираем |
| --- | --- | --- |
| арифметические | `+ - * / % **` | **сегодня** |
| присваивания | `= += -= ++ --` | **сегодня** |
| сравнения | `=== == < > <= >=` | день 7 |
| логические | `&& \|\| ! ??` | день 7 |
| условный (тернарный) | `a ? b : c` | день 7 |
| работа со свойствами | `. [ ] ?. delete in` | дни 21–22 |
| побитовые | `& \| ^ << >>` | курс 3 |
| прочие | `typeof instanceof new ...` | по своим темам |

Сегодня разбираем первые две строки. Полную таблицу всех операторов с приоритетами соберём
на дне 8 — тогда будет понятно, что с чем считается раньше.

## 2. Пять арифметических операторов {#five}

Основных пять, и четыре из них вы знаете со школы:

| Оператор | Что делает | Пример | Результат |
| --- | --- | --- | --- |
| `+` | сложение *или* склейка строк | `2 + 3` | `5` |
| `-` | вычитание | `7 - 2` | `5` |
| `*` | умножение | `3 * 4` | `12` |
| `/` | деление | `10 / 4` | `2.5` |
| `%` | **остаток** от деления | `10 % 3` | `1` |

Пятый — единственный новый. `%` — это не проценты, как думают все в первый раз,
а остаток от деления. К нему мы ещё вернёмся отдельным разделом: он окажется самым полезным
из пяти.

Есть и шестой, редкий: `**` — возведение в степень. О нём тоже поговорим.

## 3. Плюс: два оператора в одном {#plus}

Знак `+` в JavaScript делает **две разные вещи**, и от этого больше
всего путаницы у новичков. Правило движка такое:

<Scheme src="scheme-plus.svg">Плюс сначала смотрит на типы и только потом решает, что делать</Scheme>

```js
2 + 3;          // 5    — оба числа, сложение
"а" + "б";      // "аб" — обе строки, склейка
2 + "3";        // "23" — одна строка, значит склейка
"2" + 3;        // "23" — неважно, с какой стороны
```

Коварство в том, что операторы выполняются **слева направо**, и одно и то же
выражение с переставленными частями даёт разное:

```js
1 + 2 + "3";    // "33"  — сначала 1+2=3, потом склейка с "3"
"1" + 2 + 3;    // "123" — сразу склейка, и дальше всё склеивается
```

<Mistake>
Самый частый случай в работе: значение из поля ввода **всегда строка**,
даже если пользователь набрал цифры.

```js
const a = "10";     // из поля ввода
const b = "5";
console.log(a + b);          // "105" — а мы ждали 15
console.log(Number(a) + Number(b));   // 15 — правильно
```

Лечится тем, что мы разбирали вчера: превратите в число *на входе*, и дальше считайте спокойно.
</Mistake>

С вчерашними особыми значениями плюс ведёт себя так:

```js
true + true;       // 2   — логические превращаются в 1 и 0
null + 1;          // 1   — null становится нулём
undefined + 1;     // NaN — undefined не превращается ни во что
```

### А что с объектами

Объект и массив плюс тоже примет — и выдаст что-нибудь странное. Заранее предупреждаем, потому
что эти результаты часто видят в консоли и пугаются:

```js
[] + [];          // ""                 — два пустых массива дали пустую строку
[1, 2] + [3];     // "1,23"             — каждый стал строкой и склеился
[] + { };         // "[object Object]"
"" + { a: 1 };    // "[object Object]"
```

Логика тут есть. Плюс не умеет работать с объектами, поэтому сначала превращает каждый операнд
в примитив. Массив при этом становится строкой из своих элементов через запятую — `[1,2]`
даёт `"1,2"`, а пустой массив даёт пустую строку. Обычный объект превращаться толком
не умеет и выдаёт `"[object Object]"`.

<Important>
`[object Object]` в выводе — **верный признак того, что вы вывели объект
там, где ждали текст**. Значит, где-то забыли взять у объекта нужное свойство.
Чтобы посмотреть, что внутри, выводите объект отдельным аргументом:
`console.log("данные:", obj)` — так консоль покажет его содержимое.
</Important>

Отсюда же практический совет из документации MDN: **не превращайте в строку
через `"" + x`**. Для объектов эта запись работает не так, как шаблонная строка,
и разница иногда кусается. Пишите `String(x)` или `` `${x}` ``.

## 4. Минус, умножение, деление {#others}

Остальные четыре оператора проще: у них выбора нет, они **всегда считают числами**.
Поэтому строку они молча превращают в число:

```js
"10" - 5;    // 5   — строка стала числом
"10" * 2;    // 20
"10" / 2;    // 5
"a" - 1;     // NaN — превратить не вышло
```

<Important>
Отсюда несимметричность, на которой спотыкаются все: `"10" + 5` даёт
`"105"`, а `"10" - 5` даёт `5`. Плюс перегружен склейкой,
остальные — нет.
</Important>

У деления две особенности, которые мы уже видели на дне 5:

```js
10 / 3;    // 3.3333333333333335 — целых и дробных отдельно нет
10 / 0;    // Infinity — деление на ноль не ошибка
0 / 0;     // NaN — а вот это уже неопределённость
```

### Особые значения в арифметике

Вчера мы разобрали `NaN`, `Infinity`, `null`
и `undefined`. Вот как они ведут себя со всеми пятью операторами — эту таблицу полезно
один раз прочитать целиком:

| x | `x + 2` | `x - 2` | `x * 2` | `x / 2` | `x % 2` |
| --- | --- | --- | --- | --- | --- |
| `NaN` | `NaN` | `NaN` | `NaN` | `NaN` | `NaN` |
| `Infinity` | `Infinity` | `Infinity` | `Infinity` | `Infinity` | `NaN` |
| `null` | `2` | `-2` | `0` | `0` | `0` |
| `undefined` | `NaN` | `NaN` | `NaN` | `NaN` | `NaN` |
| `true` | `3` | `-1` | `2` | `0.5` | `1` |
| `""` | `2` | `-2` | `0` | `0` | `0` |
| `"5"` | **`"52"`** | `3` | `10` | `2.5` | `1` |

Три вывода из таблицы.

**Первый.** Строка `"5"` — единственная строка в таблице, и только
в колонке `+` она выбивается: там склейка, везде остальное — число 5. Это та же
несимметричность плюса.

**Второй.** `null` и пустая строка ведут себя как ноль, а
`undefined` — как `NaN`. Практически это значит: пропущенное значение
отравит весь расчёт `NaN`, а вот забытое `null` тихо посчитается как ноль
и даст неверное число без единого сообщения. Второе опаснее.

**Третий.** `NaN` заразен во всех пяти колонках. Если он попал в расчёт,
дальше всё будет `NaN` — и искать надо самое первое место, где он появился, а не то,
где вы его заметили.

## 5. Остаток: самый полезный {#remainder}

Оператор `%` возвращает **остаток** от деления. Делим 10 на 3: получается
3 целых и 1 в остатке, — вот эту единицу он и вернёт.

```js
10 % 3;    // 1   — 3 * 3 = 9, остаётся 1
7 % 7;     // 0   — разделилось нацело
5 % 10;    // 5   — делимое меньше делителя, весь он в остатке
5.5 % 2;   // 1.5 — с дробями тоже работает
10 % 0;    // NaN — делить на ноль тут нельзя
```

<Why>
Почему `10 / 0` даёт `Infinity`, а `10 % 0` — `NaN`?
У деления ответ осмысленный: чем меньше делитель, тем больше частное, и в пределе получается
бесконечность. А у остатка такого предела нет: разложить 10 предметов «по нулю» нельзя ни разу,
и вопрос «сколько осталось» смысла не имеет. Поэтому язык честно отвечает «не число».
</Why>

<Scheme src="scheme-remainder.svg">Деление отвечает «сколько целых», остаток — «сколько не поместилось»</Scheme>

Выглядит как школьная мелочь, но на практике `%` используют постоянно. Вот четыре приёма,
которые стоит записать в тетрадь.

### Чётность

```js
const n = 7;

if (n % 2 === 0) {
  console.log("чётное");
} else {
  console.log("нечётное");   // сюда
}
```

Число чётное ровно тогда, когда остаток от деления на 2 равен нулю. Этим красят строки таблицы
через одну, раздают карты по очереди, делят на команды.

### Последняя цифра

```js
1234 % 10;    // 4 — последняя цифра
1234 % 100;   // 34 — две последние
```

### Круговой счётчик

Самый ценный приём. Нужно, чтобы счётчик дошёл до конца и начал сначала — карусель картинок,
дни недели, ход игрока по кругу:

```js
const days = ["пн", "вт", "ср"];
let i = 0;

for (let k = 0; k < 7; k++) {
  console.log(days[i]);
  i = (i + 1) % days.length;   // 0, 1, 2, 0, 1, 2, 0...
}
// пн вт ср пн вт ср пн
```

Без остатка пришлось бы писать условие «если дошли до конца, сбросить в ноль». С остатком это
одна строка, которая никогда не выйдет за границы массива.

### Время из секунд

Четвёртый приём, и он объединяет остаток с делением. Задача: секунды превратить в часы, минуты
и секунды. Встречается в каждом таймере и плеере.

```js
const total = 3725;   // секунд

const hours = Math.floor(total / 3600);        // 1   — сколько целых часов
const minutes = Math.floor(total / 60) % 60;   // 2   — минуты без часов
const seconds = total % 60;                    // 5   — секунды без минут

console.log(`${hours}:${minutes}:${seconds}`);   // "1:2:5"
```

Схема всегда одна и та же: **деление отвечает «сколько целых», остаток — «сколько
осталось»**. Поделили на 3600 — узнали часы; взяли остаток от 60 — отсекли всё крупное
и оставили только минуты.

Вывод `"1:2:5"` читается плохо — обычно добавляют ведущие нули методом
`padStart` (день 16), и получается привычное `"1:02:05"`.
`Math.floor`, который тут округляет вниз, разберём на дне 18; пока достаточно знать,
что он отбрасывает дробную часть.

## 6. Остаток от отрицательных {#negative}

А вот тут начинается то, что путает даже опытных. Посмотрите:

```js
10 % 3;     // 1
-10 % 3;    // -1  ← минус!
10 % -3;    // 1
-10 % -3;   // -1
```

**Знак результата совпадает со знаком делимого** — того, что слева. Знак делителя
не влияет вообще.

<Why>
В школьной математике есть операция «по модулю», и она работает иначе: там знак результата
берётся от *делителя*. То есть −10 по модулю 3 равно 2, а не −1. В одних языках
(Python, Perl) знак `%` означает модуль, в других (JavaScript, C, Java) — остаток.
Одинаковый знак, разный смысл — вот почему код, переписанный с Python буква в букву, иногда
считает не то.
</Why>

Если нужен именно модуль — всегда неотрицательный результат, — есть готовая формула:

```js
const mod = (n, d) => ((n % d) + d) % d;

mod(-10, 3);   // 2  — а не -1
mod(10, 3);    // 1  — для положительных то же самое
```

<Mistake>
Где это по-настоящему кусается — в круговом счётчике, если идти **назад**:

```js
let i = 0;
(i - 1) % 3;              // -1 — и arr[-1] даст undefined
((i - 1) % 3 + 3) % 3;    // 2 — правильный переход в конец
```

Карусель, которая ломается на кнопке «назад», — классическая ошибка первого проекта.
</Mistake>

## 7. Степень {#power}

Оператор `**` возводит в степень:

```js
2 ** 10;    // 1024
2 ** 0.5;   // 1.4142135623730951 — дробная степень это корень
9 ** 0.5;   // 3
```

У него два поведения, отличных от всех остальных операторов.

**Первое: он правоассоциативный.** Все прочие операторы считаются слева направо,
а этот — справа налево:

```js
2 ** 3 ** 2;      // 512, потому что это 2 ** (3 ** 2) = 2 ** 9
(2 ** 3) ** 2;    // 64 — если нужно иначе, ставьте скобки
```

**Второе: с унарным минусом язык требует скобок.** Не молча выбирает порядок,
а отказывается выполнять код:

```js
-2 ** 2;
// SyntaxError: Unary operator used immediately before exponentiation expression.
// Parenthesis must be used to disambiguate operator precedence

(-2) ** 2;    // 4   — «минус два в квадрате»
-(2 ** 2);    // -4  — «минус от двух в квадрате»
```

Это редкий и приятный случай: вместо того чтобы дать неверный ответ, язык заставляет вас
сказать точнее. Запомните `SyntaxError` с длинным словом `Parenthesis` —
лечится он одними скобками.

## 8. Унарные плюс и минус {#unary}

Плюс и минус бывают и с одним операндом. Минус меняет знак — это понятно. А вот унарный плюс
делает кое-что полезное: он **превращает значение в число**.

```js
+"42";        // 42  — короткая запись Number("42")
+true;        // 1
+"";          // 0
+"abc";       // NaN
+null;        // 0
+undefined;   // NaN

-"42";        // -42 — минус тоже превращает, заодно меняя знак
-true;        // -1
```

То есть `+x` — это то же самое, что `Number(x)`, только короче.
Запись распространённая, узнавать её надо. Но в своём коде лучше писать `Number(x)`:
одинокий плюс перед переменной легко не заметить при чтении.

Где унарный плюс действительно уместен — короткие места, где смысл и так ясен. Например,
дата: `+new Date()` даёт число миллисекунд, и эту запись пишут все:

{/* ahead-ok: день 17 */}

```js
const t = +new Date();   // число, а не объект даты
typeof t;                // "number"
```

<Mistake>
Не перепутайте унарный плюс с бинарным. Разница в том, сколько значений вокруг знака:

```js
const a = "5";
const b = "3";

console.log(+a + +b);   // 8   — два унарных плюса, потом сложение
console.log(a + b);     // "53" — один бинарный плюс, склейка
```

Запись `+a + +b` выглядит как опечатка, но она верна. Именно поэтому
в учебном коде лучше `Number(a) + Number(b)`.
</Mistake>

## 9. Присваивание — это выражение {#assign}

Знак `=` кладёт значение в переменную. Но важнее другое: **присваивание само
является выражением** и возвращает то, что присвоило.

```js
let x;
console.log(x = 5);   // 5 — выражение вернуло присвоенное значение
```

Из этого следует цепочка, которую вы будете встречать в чужом коде:

```js
let p, q, r;
p = q = r = 7;        // всем троим по 7
console.log(p, q, r); // 7 7 7
```

Работает справа налево: сначала `r = 7` вернуло 7, потом это 7 ушло в `q`,
потом в `p`. Только помните ловушку дня 4: если `q` и `r`
не объявлены, они молча станут глобальными.

Присваивать можно не только переменной. Слева от `=` может стоять всё, во что
значение помещается, — свойство объекта или элемент массива:

```js
const user = { };
user.name = "Аман";        // свойству объекта

const marks = [5, 4, 3];
marks[0] = 2;              // элементу массива

user.count = 5;
user.count += 1;           // составное присваивание тоже работает
marks[0]++;                // и инкремент
```

Заметьте: объект и массив объявлены через `const`, и это не мешает — на дне 4 разбирали,
почему. Константа держит имя, а не содержимое.

Есть ещё одна форма присваивания — **деструктуризация**, когда за раз разбирают
объект или массив на несколько переменных:

{/* ahead-ok: день 22 */}

```js
const [first, second] = [5, 4];      // first = 5, second = 4
const { name } = { name: "Аман" };   // name = "Аман"
```

Приём удобный и очень частый в настоящем коде. Разбираем его на дне 22, а сейчас достаточно
узнавать запись в глаза.

<Mistake>
Раз присваивание — выражение, его можно случайно поставить в условие вместо сравнения:

```js
let x = 5;

if (x = 0) {          // присвоили ноль! и условие стало ложным
  console.log("не выведется");
}
console.log(x);       // 0 — переменную испортили
```

Одна палочка вместо трёх — и программа тихо работает неправильно. Сравнение разбираем
завтра, а правило запомните сегодня: **в условии должно стоять `===`**.
</Mistake>

## 10. Составное присваивание {#compound}

У каждого арифметического оператора есть короткая пара с присваиванием:

| Кратко | Полная запись | Пример | Было 10, стало |
| --- | --- | --- | --- |
| `x += 5` | `x = x + 5` | сложение | `15` |
| `x -= 5` | `x = x - 5` | вычитание | `5` |
| `x *= 2` | `x = x * 2` | умножение | `20` |
| `x /= 4` | `x = x / 4` | деление | `2.5` |
| `x %= 3` | `x = x % 3` | остаток | `1` |
| `x **= 2` | `x = x ** 2` | степень | `100` |

Чаще всего встречается `+=` — им накапливают сумму:

```js
let sum = 0;
for (const mark of [5, 4, 5]) {
  sum += mark;        // короче, чем sum = sum + mark
}
console.log(sum);     // 14
```

<Mistake>
`+=` наследует от плюса и склейку строк. Если справа окажется строка, число
превратится в текст, и дальше всё поедет:

```js
let x = 10;
x += "5";
console.log(x);          // "105"
console.log(typeof x);   // "string" — переменная сменила тип
```

Именно так ломаются счётчики, складывающие значения из полей ввода.
</Mistake>

## 11. Инкремент и декремент {#incdec}

Прибавить единицу нужно так часто, что для этого есть отдельный оператор: `++`.
И парный ему `--`, чтобы вычесть.

```js
let i = 5;
i++;              // то же, что i += 1 и что i = i + 1
console.log(i);   // 6
```

Пока просто. Но у этих операторов есть **две формы**, и они различаются тем,
что возвращают.

<Scheme src="scheme-incdec.svg">Разница видна, только если результат куда-то используется</Scheme>

```js
let i = 5;
const a = i++;           // a = 5, i = 6
console.log(a, i);       // 5 6

let j = 5;
const b = ++j;           // b = 6, j = 6
console.log(b, j);       // 6 6
```

<Important>
Если результат никуда не идёт — а так в 95% случаев, — **разницы нет**.
Строка `i++;` сама по себе делает ровно то же, что `++i;`. Поэтому
в цикле `for (let i = 0; i < 5; i++)` можно писать любую форму: счётчик
увеличится одинаково.
</Important>

Совет практический: **не смешивайте инкремент с другими действиями в одной строке**.
Такие выражения читаются плохо, и ошибиться легко даже специалисту:

```js
let x = 1;
console.log(x++ + ++x);   // 4 — но кто это разберёт с первого взгляда?
```

Декремент `--` устроен точно так же, только вычитает. Его классическое место —
обратный отсчёт:

{/* ahead-ok: день 10 */}

```js
let lives = 3;

while (lives > 0) {
  console.log(lives);
  lives--;
}
// 3 2 1
```

Циклы разберём на дне 10, но идея видна: пока жизней больше нуля, показываем число и отнимаем
одну. Без декремента пришлось бы писать `lives = lives - 1`.

Две мелочи напоследок. `++` работает только с тем, куда можно присвоить, — поэтому
на константе он падает с ошибкой из дня 4. И он превращает значение в число:

```js
const c = 1;
c++;             // TypeError: Assignment to constant variable.

let s = "5";
s++;
console.log(s, typeof s);   // 6 "number" — строка стала числом
```

## 12. Порядок действий {#order}

Как и в математике, умножение и деление выполняются раньше сложения и вычитания:

```js
2 + 3 * 4;      // 14, а не 20
(2 + 3) * 4;    // 20 — скобки меняют порядок
```

Вот порядок для сегодняшних операторов, сверху — то, что выполняется раньше:

| Очередь | Операторы |
| --- | --- |
| 1 | `( )` — скобки |
| 2 | `++`, `--`, унарные `+` и `-` |
| 3 | `**` — степень (справа налево) |
| 4 | `*`, `/`, `%` |
| 5 | `+`, `-` |
| 6 | `=`, `+=` и остальные присваивания (справа налево) |

<ProTip>
Не заучивайте таблицу — **ставьте скобки**. Выражение `(a + b) / 2`
читается однозначно и вам, и коллеге, и вам же через полгода. Полная таблица приоритетов
со всеми операторами языка будет на дне 8, и её тоже не придётся учить наизусть.
</ProTip>

### Собираем формулу

Самая частая ошибка с приоритетом — среднее арифметическое. Сравните:

```js
const a = 5, b = 4, c = 3;

a + b + c / 3;      // 10 — сначала 3/3=1, потом 5+4+1. Неверно!
(a + b + c) / 3;    // 4  — верно
```

Деление выполнилось раньше сложения, и получилось совсем не то. Ошибка тихая: числа похожи
на правдоподобные, никто не ругается.

Теперь задача посложнее — такую вы встретите в первом же проекте с корзиной.
*Товар стоит 1200, берут 3 штуки, скидка 10%, потом налог 5%. Сколько платить?*

Соблазн — записать одной строкой. Не поддавайтесь: разбейте на шаги, дайте каждому имя,
и формула станет проверяемой:

```js
const price = 1200;
const count = 3;
const discount = 10;    // проценты
const tax = 5;          // проценты

const subtotal = price * count;                          // 3600
const afterDiscount = subtotal - (subtotal * discount) / 100;   // 3240
const total = afterDiscount + (afterDiscount * tax) / 100;      // 3402

console.log(`К оплате: ${total.toFixed(2)}`);   // "К оплате: 3402.00"
```

Три строки вместо одной, зато каждую можно вывести в консоль и проверить отдельно. И если
завтра выяснится, что налог считается от суммы *до* скидки, править придётся одну строку,
а не разгадывать длинное выражение.

<Important>
Обратите внимание на `(subtotal * discount) / 100`. Скобки тут не обязательны —
умножение и деление и так идут слева направо. Но они говорят читателю: «сначала посчитали
величину скидки, потом перевели в проценты». **Скобки ставят не только для движка,
но и для человека.**
</Important>

## 13. Дробная точность и деньги {#precision}

Вернёмся к тому, что видели на дне 3 и оставили «на потом». Потом наступило:

```js
0.1 + 0.2;                 // 0.30000000000000004
0.1 + 0.2 === 0.3;         // false
```

Причина не в JavaScript. Дробные числа хранятся в двоичном виде, а 0.1 в двоичной системе —
бесконечная дробь, ровно как 1/3 в десятичной. Её приходится обрезать, и крошечная погрешность
накапливается. Так устроено почти во всех языках.

Что с этим делать — зависит от задачи.

**Для показа** достаточно округлить. Метод `toFixed(n)` возвращает
строку с нужным числом знаков:

```js
(0.1 + 0.2).toFixed(2);   // "0.30" — строка, для вывода
```

**Для денег** надёжнее считать в самых мелких единицах — в тенге, копейках,
центах — то есть целыми числами, и делить только в конце:

```js
const price = 1250;        // 12 манат 50 тенге, храним в тенге
const count = 3;
const total = price * count;          // 3750 — целое, без погрешности
console.log(`${total / 100} манат`);  // "37.5 манат"
```

<Mistake>
Округление тоже умеет удивлять — по той же причине:

```js
Math.round(1.005 * 100) / 100;   // 1, а не 1.01
```

Потому что `1.005 * 100` на самом деле равно 100.49999999999999. Это ещё один
довод в пользу целых: там, где важна каждая копейка, дробям доверять нельзя.
`Math.round` разберём на дне 18.
</Mistake>

**Для сравнения** дробных чисел есть третий приём. Раз точного равенства не добиться,
проверяют, что числа отличаются меньше чем на крошечную величину. Эта величина в языке уже есть —
`Number.EPSILON`:

```js
console.log(Number.EPSILON);   // 2.220446049250313e-16 — очень маленькое число

0.1 + 0.2 === 0.3;                              // false
Math.abs((0.1 + 0.2) - 0.3) < Number.EPSILON;   // true — «практически равны»
```

Читается так: «модуль разницы меньше погрешности — значит, считаем равными».
`Math.abs` берёт число без знака, чтобы не важно было, какое из двух больше.

Итого три способа, и выбирают по задаче:

| Задача | Приём |
| --- | --- |
| показать пользователю | `toFixed(2)` — округлить до строки |
| считать деньги | хранить в целых, делить только при выводе |
| сравнить два дробных | разница меньше `Number.EPSILON` |

## 14. «Табель»: считаем по-настоящему {#tabel}

Доработаем программу так, чтобы она использовала сегодняшние операторы. Добавим сумму, процент
и раскраску строк через одну.

```js
const MAX_MARK = 5;
const student = {
  name: "Аман",
  marks: [5, 4, 5, 3, 5, 4],
};

let sum = 0;
for (const mark of student.marks) {
  sum += mark;                       // накопление через +=
}

const count = student.marks.length;
const average = sum / count;
const percent = (average / MAX_MARK) * 100;

console.log(`Оценок: ${count}`);
console.log(`Сумма: ${sum}`);
console.log(`Средний балл: ${average.toFixed(2)}`);
console.log(`Это ${percent.toFixed(0)}% от максимума`);

// строки через одну — так красят длинные таблицы
for (let i = 0; i < count; i++) {
  let stripe = "";
  if (i % 2 !== 0) {
    stripe = "  (серая строка)";
  }
  console.log(`${i + 1}. ${student.marks[i]}${stripe}`);
}
```

<ResultBox>
```plain-out
Оценок: 6
Сумма: 26
Средний балл: 4.33
Это 87% от максимума
1. 5
2. 4  (серая строка)
3. 5
4. 3  (серая строка)
5. 5
6. 4  (серая строка)
```
</ResultBox>

Здесь работают все сегодняшние операторы. Разберём по строкам, какой за что отвечает:

| Строка | Оператор | Зачем |
| --- | --- | --- |
| `sum += mark;` | `+=` | накопить сумму, не переписывая `sum = sum + mark` |
| `sum / count` | `/` | среднее арифметическое |
| `(average / MAX_MARK) * 100` | `/` и `*` | доля от максимума в процентах; скобки — для читателя |
| `i % 2 !== 0` | `%` | чётность: красим строки через одну |
| `i++` | `++` | двигаем счётчик цикла |
| `i + 1` | `+` | нумерация для человека — с единицы, а не с нуля |
| `average.toFixed(2)` | — | округлить для показа, чтобы не было 4.333333 |

Обратите внимание на последнюю строку таблицы и на предпоследнюю. `toFixed(2)` нужен
ровно потому, что `26 / 6` даёт 4.333333333333333 — дробь, которую никто не хочет видеть
в табеле. А `i + 1` — потому что массивы считают с нуля, а люди с единицы, и это
расхождение придётся переводить в каждом выводе списка.

Раскраска строк через одну устроена так: заводим пустую пометку, и если номер нечётный —
кладём в неё текст. Обратите внимание, что `stripe` объявлена через `let`
и **до** `if`, а не внутри него: иначе, как мы разбирали на дне 4,
она не дожила бы до строки вывода.

Завтра вы увидите, что такую запись «выбрать одно из двух значений» умеют сокращать до одной
строки — но сначала нужен вчерашний и сегодняшний материал.

## 15. Частые ошибки дня {#mistakes}

| Ошибка | Почему | Как правильно |
| --- | --- | --- |
| `"10" + 5` вместо 15 | плюс со строкой склеивает | `Number("10") + 5` |
| `x += "5"` в счётчике | переменная станет строкой | превращать в число на входе |
| `%` приняли за проценты | это остаток от деления | проценты — `x / 100 * p` |
| `(i - 1) % n` для хода назад | даёт −1, знак от делимого | `((i - 1) % n + n) % n` |
| `-2 ** 2` | язык требует скобок | `(-2) ** 2` или `-(2 ** 2)` |
| `if (x = 5)` | присвоили вместо сравнения | `if (x === 5)` |
| `0.1 + 0.2 === 0.3` | дроби хранятся приближённо | считать в целых, округлять для показа |

<Selfcheck>
1. Что выведут `"10" + 5` и `"10" - 5` и почему по-разному?
   <Answer>`"105"` и `5`. Плюс перегружен склейкой строк: если хоть один
   операнд строка, он склеивает. Минус такой перегрузки не имеет и всегда превращает
   операнды в числа.</Answer>
2. Чему равно `-10 % 3` и от чего зависит знак?
   <Answer>`-1`. Знак результата совпадает со знаком делимого — того, что слева.
   Знак делителя не влияет. Для всегда положительного результата нужна формула
   `((n % d) + d) % d`.</Answer>
3. `let i = 5; const a = i++;` — чему равны `a` и `i`?
   <Answer>`a` равно 5, `i` равно 6. Постфиксная форма сначала отдаёт
   старое значение и только потом увеличивает. С `++i` оба были бы 6.</Answer>
4. Почему `-2 ** 2` не работает?
   <Answer>Язык не берётся угадывать, что имелось в виду — «минус два в квадрате» или
   «минус от двух в квадрате», — и требует скобок: `(-2) ** 2` даёт 4,
   `-(2 ** 2)` даёт −4.</Answer>
5. Как сделать так, чтобы счётчик `i` шёл по кругу 0, 1, 2, 0, 1, 2?
   <Answer>`i = (i + 1) % 3;` Остаток от деления на длину никогда не выйдет
   за границы массива.</Answer>
</Selfcheck>
