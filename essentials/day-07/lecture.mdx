## 1. Зачем сравнивать {#why}

Вчера программа считала. Но пока она не умеет **решать**: делать одно в одном
случае и другое в другом. Для этого нужны два набора операторов.

- **сравнения** — отвечают на вопрос «да или нет»: `===`,
  `!==`, `<`, `>`, `<=`,
  `>=`;
- **логические** — соединяют несколько ответов в один:
  `&&`, `||`, `!`.

```js
const age = 20;
const hasTicket = true;

age >= 18;                  // true  — одно условие
age >= 18 && hasTicket;     // true  — два условия сразу
```

Сами условия `if` мы подробно разберём на дне 9. Сегодня — то, что внутри круглых
скобок: как получить «да» или «нет» и как их складывать.

## 2. Строгое сравнение: === и !== {#strict}

Начнём с главного оператора курса. **Три знака равенства** проверяют, что значения
одинаковы *и* одного типа:

```js
5 === 5;         // true
5 === "5";       // false — число и строка, разные типы
"a" === "a";     // true
true === 1;      // false
null === null;   // true

5 !== "5";       // true  — парный !== отвечает наоборот: «не равны»
5 !== 5;         // false
```

Правило `===` простое и целиком помещается в две строки:

<Important>
**Разные типы — сразу `false`, ничего не превращая.**
Одинаковые типы — сравниваем значения. Для объектов «одинаковое значение» означает
**тот же самый объект**, а не такой же по содержимому (день 3).
</Important>

```js
const a = { name: "Аман" };
const b = { name: "Аман" };
const c = a;

a === b;   // false — два разных объекта, пусть и одинаковых на вид
a === c;   // true  — это одно и то же

[1, 2, 3] === [1, 2, 3];   // false — с массивами то же: это два разных массива
```

И `==` тут не спасёт — он ведёт себя точно так же. Так как же сравнить два объекта
*по содержимому*? Честного способа в языке нет, поэтому пользуются обходными:

```js
const a = { name: "Аман", age: 17 };
const b = { name: "Аман", age: 17 };

JSON.stringify(a) === JSON.stringify(b);   // true — превратили оба в строки

[1, 2, 3].join() === [1, 2, 3].join();     // true — то же для массивов
```

<Mistake>
У приёма с `JSON.stringify` есть подвох: он сравнивает **текст**,
а значит, порядок свойств важен.

```js
JSON.stringify({ x: 1, y: 2 }) === JSON.stringify({ y: 2, x: 1 });   // false
```

Объекты одинаковые, а ответ отрицательный. Для настоящего сравнения по содержимому пишут
отдельную функцию, которая обходит все свойства, — это курс 2. `JSON` разберём
на дне 23.
</Mistake>

## 3. Нестрогое ==: как оно работает {#loose}

Оператор из **двух** знаков равенства ведёт себя иначе: если типы разные,
он сначала приводит значения друг к другу и только потом сравнивает.

<Scheme src="scheme-loose.svg">Оба оператора отвечают «да» или «нет», но приходят к ответу по-разному</Scheme>

Звучит удобно: не надо думать о типах. На деле правил приведения больше десяти, и запомнить
их никто не может. Вот что получается:

| Сравнение | `==` | `===` |
| --- | --- | --- |
| `1` и `"1"` | `true` | `false` |
| `0` и `false` | `true` | `false` |
| `0` и `""` | `true` | `false` |
| `""` и `false` | `true` | `false` |
| `null` и `undefined` | `true` | `false` |
| `null` и `0` | `false` | `false` |
| `[]` и `false` | `true` | `false` |
| `[1]` и `1` | `true` | `false` |
| `NaN` и `NaN` | `false` | `false` |

Разберите две строки из середины. `null == undefined` — `true`, это
единственное полезное свойство `==`, мы говорили о нём на дне 5. А вот
`null == 0` — `false`, хотя `null` в арифметике ведёт себя как ноль.
Логики тут нет, просто отдельное правило.

## 4. Почему == нельзя доверять {#nontransitive}

Самый сильный довод против `==` — не длина таблицы, а вот эти три строки:

```js
"0" == 0;     // true
"" == 0;      // true
"0" == "";    // false   ← ???
```

<Important>
Если `A` равно `B`, а `B` равно `C`, то логика
требует, чтобы `A` равнялось `C`. У `==` это правило
**не работает**. Такое свойство называется отсутствием транзитивности,
и оно означает простую вещь: `==` — это не равенство. Это набор правил,
которые иногда похожи на равенство.
</Important>

Почему так вышло: `"0"` и `0` сравниваются как числа — строка становится
нулём. `""` и `0` — тоже как числа, пустая строка тоже становится нулём.
А `"0"` и `""` — обе строки, типы совпали, приводить нечего, и они
сравниваются посимвольно. Три пары, три разных правила.

<ProTip>
Правило курса, без исключений: **пишем только `===` и `!==`**.
Единственное место, где `==` уместен, — проверка «пусто» сразу на `null`
и `undefined`: `value == null`. Но и её многие предпочитают писать
длинно и явно.
</ProTip>

Читать `==` вы всё равно должны уметь: в старом коде и в чужих примерах он
встречается постоянно. Увидели — насторожились и проверили, что там за типы.

## 5. Больше и меньше {#order}

Четыре оператора порядка работают привычно. Важное отличие от равенства: у них **нет
строгой версии**. Оператора `>==` не существует. Они всегда приводят
операнды — как минус и умножение вчера:

```js
5 > 3;      // true
5 < 3;      // false
5 >= 5;     // true
5 <= 4;     // false

"10" > 9;     // true  — строка стала числом
"10" > "9";   // false ← а тут обе строки!
```

Последняя строка — ловушка дня. Если **оба** операнда строки, они сравниваются
как строки, а не как числа. И тогда `"10"` оказывается меньше `"9"`,
потому что символ `"1"` идёт раньше символа `"9"`.

<Mistake>
Где это кусается: значения из полей ввода — строки. Сравнили две «цифры» напрямую и получили
бессмыслицу.

```js
const a = "10";   // из поля ввода
const b = "9";

if (a > b) { console.log("больше"); }   // не выведется!
if (Number(a) > Number(b)) { }          // а так правильно
```
</Mistake>

Вот как ведут себя разные типы в сравнении по порядку — таблицу полезно один раз прочитать:

| Сравнение | Результат | Почему |
| --- | --- | --- |
| `"10" > 9` | `true` | строка стала числом 10 |
| `"10" > "9"` | `false` | обе строки — посимвольно |
| `true > 0` | `true` | `true` стало 1 |
| `null > 0` | `false` | `null` стало 0, а 0 не больше 0 |
| `null >= 0` | `true` | зато 0 равно 0 |
| `"a" > 1` | `false` | строка не стала числом — получился `NaN` |
| `"a" < 1` | `false` | и обратное тоже ложно! |

Две последние строки — та же история, что с `NaN` в дне 5. Слово `"a"`
в число не превращается, получается `NaN`, а любое сравнение с ним ложно. Поэтому
и «больше», и «меньше» отвечают «нет» одновременно.

## 6. Сравнение строк {#strings}

Раз строки сравниваются, надо знать как. Правило: **посимвольно, по коду символа
в таблице Unicode**, слева направо до первого различия.

```js
"a" < "b";        // true  — a идёт раньше b
"abc" < "abd";    // true  — первые два совпали, третий решил
"abc" < "abcd";   // true  — что короче и совпадает, то меньше

"Z" < "a";             // true  — заглавная Z раньше строчной a
"яблоко" < "Яблоко";   // false — строчная я позже заглавной Я
```

Последние две строки — неприятные. В таблице Unicode заглавные латинские буквы идут
**раньше** строчных, а кириллица — после всей латиницы.

Значит, если так отсортировать список фамилий, «Яшаров» окажется выше «абдыев». Для настоящей
сортировки текста есть `localeCompare`, который знает про алфавиты и регистр, —
разберём его в курсе 2 вместе с сортировкой.

<Analogy>
Сравнение строк устроено как порядок слов в словаре: смотрим первую букву, при совпадении —
вторую, и так далее. Разница только в том, что «алфавит» у компьютера свой: сначала цифры,
потом заглавные латинские, потом строчные латинские, потом всё остальное.
</Analogy>

## 7. Странности null и NaN {#quirks}

Два значения ведут себя в сравнениях не как все. Про них надо знать, чтобы не потерять
полдня на отладке.

**`NaN` не равен ничему, включая себя** — мы это разбирали на дне 5.
Добавим к этому: любое сравнение с ним тоже ложно.

```js
NaN === NaN;   // false
NaN !== NaN;   // true  ← единственное значение, не равное себе
NaN > 1;       // false
NaN < 1;       // false
NaN >= NaN;    // false
```

Обратите внимание на третью и четвёртую строки. Обычно из «не больше» следует «меньше или
равно» — с `NaN` это не так. Проверять на него надо только
`Number.isNaN()`.

**А вот `null` противоречит сам себе:**

```js
null == 0;    // false — «не равен нулю»
null > 0;     // false — «не больше нуля»
null >= 0;    // true  ← но «больше или равен»!
```

<Why>
Как так вышло. У `==` для `null` есть **отдельное правило**:
он равен только `null` и `undefined`, и никаких превращений не делается.
А операторы порядка такого правила не имеют — они честно превращают `null`
в число, то есть в 0, и сравнивают. Получается, что `>=` сравнивает
`0 >= 0` и отвечает «да», а `==` до чисел вообще не доходит.
Два разных механизма на одно и то же значение.
</Why>

Практический вывод: **не подставляйте `null` в сравнения по порядку**.
Сначала проверьте, что значение вообще есть, потом сравнивайте.

## 8. Три логических оператора {#logic}

Одного условия обычно мало. Логические операторы соединяют несколько:

| Оператор | Название | Отвечает «да», когда |
| --- | --- | --- |
| `&&` | И | верны **оба** условия |
| `\|\|` | ИЛИ | верно **хотя бы одно** |
| `!` | НЕ | условие **неверно** |

```js
const age = 20;
const hasTicket = true;

age >= 18 && hasTicket;    // true  — и то, и другое
age < 18 || hasTicket;     // true  — хотя бы одно
!hasTicket;                // false — переворачиваем
```

Оператор `!` стоит особняком: он унарный, берёт одно значение и **всегда**
возвращает настоящее `true` или `false` — в отличие от двух других.
Работает он по правилу шести ложных значений из дня 5:

```js
!true;        // false
!0;           // true  — ноль ложный, перевернули
!"текст";     // false — непустая строка истинна
![];          // false — пустой массив тоже истинен!
!undefined;   // true
```

Отсюда и приём с двойным отрицанием, который мы видели на дне 5: `!!x` — это
способ получить из любого значения честное `true` или `false`.
Первое `!` переворачивает, второе возвращает обратно:

```js
const hasName = !!student.name;   // true, если имя непустое
typeof hasName;                   // "boolean" — ровно то, что хотели
```

Вот таблица истинности — её стоит один раз выписать в тетрадь и больше к ней не возвращаться:

| a | b | `a && b` | `a \|\| b` | `!a` |
| --- | --- | --- | --- | --- |
| `true` | `true` | `true` | `true` | `false` |
| `true` | `false` | `false` | `true` | `false` |
| `false` | `true` | `false` | `true` | `true` |
| `false` | `false` | `false` | `false` | `true` |

<Mistake>
Человеческий язык обманывает. «Оценка не 2 и не 1» на русском звучит с союзом «и»,
а в коде это:

```js
mark !== 2 && mark !== 1;   // верно

mark !== 2 || mark !== 1;   // ВСЕГДА true — бессмысленно
```

Вторая строка истинна всегда: любое число не равно хотя бы одному из двух. Когда пишете
условие с «не», проверьте его на крайних значениях.
</Mistake>

### Что считается раньше

В одном выражении может встретиться и арифметика, и сравнение, и логика. Порядок такой,
сверху — то, что выполняется раньше:

| Очередь | Операторы |
| --- | --- |
| 1 | `( )` — скобки |
| 2 | `!` — отрицание |
| 3 | арифметика: `* / %`, затем `+ -` |
| 4 | сравнение: `< > <= >=` |
| 5 | равенство: `=== !== == !=` |
| 6 | `&&` |
| 7 | `\|\|` и `??` |
| 8 | тернарный оператор, затем присваивания |

Из этого следует хорошая новость: **скобки вокруг сравнений не нужны**. Строка
`1 + 2 === 3 && 2 > 1` работает как ожидается — сначала арифметика, потом
сравнения, потом `&&`.

И одна ловушка: **`&&` связывает крепче, чем `||`**.

```js
true || false && false;      // true  — читается как true || (false && false)
(true || false) && false;    // false — а вот так уже иначе
```

<Mistake>
В жизни это выглядит так. Хотели «админ или владелец, и при этом публично»:

```js
isAdmin || isOwner && isPublic;      // на самом деле: isAdmin || (isOwner && isPublic)
(isAdmin || isOwner) && isPublic;    // а хотели это
```

Разница вылезет не сразу: при `isAdmin = true` и `isPublic = true` обе строки дадут `true`,
и ошибку заметят только когда непубличный админ получит доступ. **Смешиваете
`&&` и `||` — ставьте скобки всегда**, даже когда
они не нужны движку.
</Mistake>

### Как правильно перевернуть условие

Ошибка выше — частный случай общего правила. Когда отрицают составное условие, союз
**меняется на противоположный**:

| Было | Стало после отрицания |
| --- | --- |
| `!(a && b)` | `!a \|\| !b` — «и» стало «или» |
| `!(a \|\| b)` | `!a && !b` — «или» стало «и» |

На словах это очевидно, если проговорить. «Неправда, что пришёл и заплатил» означает
«не пришёл *или* не заплатил» — достаточно одного промаха. А «неправда, что пришёл
или позвонил» означает «не пришёл *и* не позвонил» — не сделал ни того, ни другого.

```js
const canEnter = age >= 18 && hasTicket;

// не может войти — два способа записать одно и то же
!canEnter;
age < 18 || !hasTicket;
```

<ProTip>
На практике лучший приём — **не переворачивать вовсе**. Дайте условию имя
и отрицайте имя: `!canEnter` читается мгновенно, а
`!(age >= 18 && hasTicket)` приходится разбирать. Это же правило спасает
от ошибки с «не 2 и не 1»: назовите условие `isBadMark` — и путаться станет негде.
</ProTip>

### Сравнение с несколькими значениями

Частая задача: проверить, что значение — одно из нескольких. Пока условий два-три, пишут
через `||`:

```js
const day = "сб";
const isWeekend = day === "сб" || day === "вс";   // true
```

Когда вариантов больше, такая цепочка становится длинной. Тогда берут массив и спрашивают,
есть ли значение в нём:

```js
const isWeekend = ["сб", "вс"].includes(day);   // true
```

Метод `includes` разберём на дне 19 вместе с массивами. Показываю его сейчас,
чтобы вы узнали приём, когда увидите: длинная цепочка `||` из одинаковых сравнений —
почти всегда признак, что просится массив.

## 9. && и || возвращают не true и false {#values}

Вот деталь, которая отличает JavaScript от школьной логики и которую надо понять как следует.
Операторы `&&` и `||` **возвращают один из операндов**,
а не `true` или `false`.

```js
1 && "салам";       // "салам" — а не true
0 && "салам";       // 0       — а не false
"Аман" || "Гость";  // "Аман"
"" || "Гость";      // "Гость"

1 && 2 && 3;                    // 3      — все истинные, отдал последний
null || 0 || "" || "последний";   // "последний" — все ложные, отдал последний
```

Правило такое:

- `&&` возвращает **первое ложное** значение, а если все
  истинные — последнее;
- `||` возвращает **первое истинное** значение, а если все
  ложные — последнее.

«Истинное» и «ложное» здесь — те самые шесть ложных значений из дня 5. Оператор
`!`, в отличие от двух других, всегда возвращает настоящее `true`
или `false`:

```js
!0;          // true
!"текст";    // false
!![];        // true — двойное отрицание даёт логическое значение
```

### Зачем это нужно знать

Может показаться, что разница между «вернуть `true`» и «вернуть сам операнд» —
придирка. Но именно на ней стоят два приёма из следующего раздела, а ещё она объясняет
вот такой результат:

```js
const result = "" || 0;
console.log(result);          // 0     — а не false
console.log(typeof result);   // "number"
```

Оба операнда ложные, поэтому `||` вернул последний — число 0. Если вы ждали
`false` и дальше сравнили результат с `false` через `===`,
условие не сработает. Когда нужно именно логическое значение, приведите его явно:

```js
const ok = Boolean("" || 0);   // false
const ok2 = !!("" || 0);       // false — то же самое короче
```

И помните про шесть ложных значений из дня 5: в условии любое значение сначала превращается
в «да» или «нет» по тому же правилу. Поэтому `if ([])` выполнится, а
`if ("")` — нет.

## 10. Короткое замыкание {#shortcircuit}

Из предыдущего правила следует важное: **второй операнд вычисляется не всегда**.
Если ответ уже ясен по первому, до второго дело не доходит.

<Scheme src="scheme-shortcircuit.svg">Правая часть выполняется, только если она может повлиять на ответ</Scheme>

```js
function log() {
  console.log("меня вызвали");
  return true;
}

false && log();   // ничего не напечатает — до log() не дошли
true || log();    // тоже ничего
true && log();    // "меня вызвали"
```

На этом построены два приёма, которые встречаются в каждом проекте.

### Запасное значение

```js
const name = input || "Гость";
```

Если `input` истинный — берём его. Если пустой, `null` или
`undefined` — подставляем «Гость». Одна строка вместо четырёх строк условия.

### Защита от пустоты

```js
const title = user && user.name;
```

Если `user` — `null`, до `user.name` дело не дойдёт, и мы
не получим `TypeError` из дня 5. Приём рабочий, но сегодня для этого есть запись
получше — необязательная цепочка `user?.name`, её разберём на дне 22.

### Действие по условию

Третий приём вы тоже встретите, и о нём стоит сказать отдельно — не потому что он хорош,
а потому что его любят сокращать:

```js
isReady && sendReport();   // вызовет sendReport() только если isReady истинно
```

Работает это ровно по тому же правилу: левая часть ложна — до правой не дошли. Запись короткая,
но **в учебном коде так писать не надо**. Здесь `&&` используют
не для того, для чего он придуман: результат выражения никому не нужен, нужно побочное действие.
Читателю приходится догадываться, что это условие, а не вычисление.

```js
if (isReady) {
  sendReport();
}
```

Три строки вместо одной, зато намерение видно сразу. То же правило мы применим к тернарному
оператору в разделе 12: **оператор выбирает значение, `if` выполняет
действия**.

## 11. ?? вместо || {#nullish}

У приёма с `||` есть изъян, и он серьёзный. `||` подставляет запасное
значение для **всех шести** ложных значений — включая `0` и пустую строку.
А это часто законные данные.

```js
const count = 0;
const shown = count || 10;
console.log(shown);   // 10 — а пользователь просил показать 0!
```

Для этого и придумали оператор `??` — «нулевое слияние». Он подставляет запасное
значение **только для `null` и `undefined`**:

<Scheme src="scheme-nullish.svg">Разница ровно в четырёх значениях: `0`, `""`, `false` и `NaN`</Scheme>

```js
0 || 10;          // 10   — ноль ложный, подставили запасное
0 ?? 10;          // 0    — ноль это значение, оставили

"" || "Гость";    // "Гость"
"" ?? "Гость";    // ""   — пустая строка тоже значение

null ?? 10;       // 10
undefined ?? 10;  // 10
false ?? 10;      // false
```

<ProTip>
Как выбирать. Спросите себя: **«ноль и пустая строка — это нормальные данные
или их тоже надо заменить?»** Количество товара, счёт в игре, температура — данные,
берите `??`. Имя пользователя, которое не должно быть пустым, — тут
`||` уместнее.
</ProTip>

Одна тонкость: `??` **нельзя смешивать** с `&&`
и `||` без скобок. Язык отказывается угадывать порядок — как вчера со степенью:

```js
// null || undefined ?? "foo";   → SyntaxError: Unexpected token '??'
(null || undefined) ?? "foo";   // "foo" — со скобками работает
```

## 12. Тернарный оператор {#ternary}

Последний оператор дня — единственный в языке, у которого **три** операнда.
Он выбирает одно из двух значений:

```js
условие ? значение_если_да : значение_если_нет
```

Вчера мы писали так:

```js
let stripe = "";
if (i % 2 !== 0) {
  stripe = "  (серая строка)";
}
```

А с тернарным оператором то же самое помещается в одну строку — и переменную можно объявить
через `const`:

```js
const stripe = i % 2 !== 0 ? "  (серая строка)" : "";
```

Разница принципиальная и идёт из дня 3: `if` — это **инструкция**,
она значения не возвращает, поэтому переменную приходится объявлять заранее пустой.
А тернарный оператор — **выражение**, его результат можно сразу присвоить.

```js
const age = 20;
const status = age >= 18 ? "взрослый" : "ребёнок";
console.log(`Статус: ${status}`);      // "Статус: взрослый"

// прямо внутри шаблонной строки тоже можно
console.log(`Билетов: ${count} ${count === 1 ? "штука" : "штук"}`);
```

Тернарники можно вкладывать друг в друга — так записывают лестницу из нескольких веток:

```js
const score = 85;
const grade = score >= 90 ? "5"
  : score >= 75 ? "4"
  : "3";
console.log(grade);   // "4"
```

<Mistake>
Вкладывать больше двух-трёх раз не стоит — читать такое невозможно. И не используйте тернарный
оператор ради действий: он создан выбирать значение, а не выполнять команды.

```js
// плохо: результат никому не нужен, это просто два действия
isReady ? console.log("готово") : console.log("ждём");

// хорошо
if (isReady) {
  console.log("готово");
} else {
  console.log("ждём");
}
```
</Mistake>

Когда что выбирать — правило простое:

| Задача | Чем пишем |
| --- | --- |
| выбрать **значение** из двух | тернарный оператор |
| выполнить **действия** по условию | `if...else` |
| значение нужно прямо внутри строки | тернарный оператор |
| в ветке больше одной строки | `if...else` |
| веток больше трёх | `if...else if` или `switch` (день 9) |

Формулировка, которая помогает решить за секунду: **если вы ставите результат справа
от `=` или внутри `${ }` — берите тернарный оператор. Если результат
никуда не идёт — берите `if`.**

## 13. Оператор запятая {#comma}

Есть в языке и такой оператор: он вычисляет несколько выражений подряд и возвращает
**последнее**.

```js
const x = (1, 2, 3);
console.log(x);   // 3 — первые два вычислились и пропали
```

В обычном коде он не нужен, и специально его почти не пишут. Встретится он вам практически
в одном месте — в заголовке цикла, когда надо вести два счётчика сразу:

```js
for (let i = 0, j = 5; i < j; i++, j--) {
  console.log(i, j);
}
// 0 5
// 1 4
// 2 3
```

Обратите внимание: запятая в `let i = 0, j = 5` — это **не** оператор
запятая, а разделитель списка объявлений из дня 4. А вот `i++, j--` — уже он.

## 14. «Табель»: проверяем оценки {#tabel}

Доведём программу до состояния, когда она не ломается на плохих данных. Сегодня добавим три
вещи: отбрасывание негодных оценок, запасное имя и вердикт тернарником.

```js
const MIN_MARK = 2;
const MAX_MARK = 5;
const MIN_EXCELLENT = 4.5;
const MIN_GOOD = 3.5;

const student = {
  name: "",                                  // имя не заполнили
  marks: [5, 4, 5, 3, 5, 4, 9, 1],           // 9 и 1 — мусор
};

const displayName = student.name || "Без имени";

let sum = 0;
let count = 0;
let excellent = 0;
let skipped = 0;

for (const mark of student.marks) {
  if (mark >= MIN_MARK && mark <= MAX_MARK) {
    sum += mark;
    count++;
    if (mark === MAX_MARK) {
      excellent++;
    }
  } else {
    skipped++;
  }
}

const average = count > 0 ? sum / count : 0;

const verdict = average >= MIN_EXCELLENT ? "отлично"
  : average >= MIN_GOOD ? "хорошо"
  : "надо подтянуть";

console.log(`${displayName}: ${average.toFixed(2)} — ${verdict}`);
console.log(`Засчитано ${count}, отброшено ${skipped}, пятёрок ${excellent}`);
```

<ResultBox>
Без имени: 4.33 — хорошо\
Засчитано 6, отброшено 2, пятёрок 3
</ResultBox>

Три места стоит разобрать отдельно.

**`mark >= MIN_MARK && mark <= MAX_MARK`** — проверка
диапазона. Обратите внимание, что записать её «по-математически» как `2 <= mark <= 5`
нельзя: язык посчитает это слева направо и получит бессмыслицу. Диапазон всегда пишут двумя
сравнениями через `&&`.

**`count > 0 ? sum / count : 0`** — защита от деления на ноль.
Если бы все оценки оказались мусором, `count` был бы нулём, и `sum / count`
дало бы `0 / 0`, то есть `NaN` из дня 5. Одна проверка — и программа
выдаёт честный ноль вместо заразного `NaN`.

**`student.name || "Без имени"`** — запасное значение. Здесь
`||` уместнее, чем `??`: пустое имя надо заменить так же, как отсутствующее.
А вот если бы мы подставляли запасное значение для *количества* оценок, понадобился бы
`??` — иначе честный ноль заменился бы на запасное число.

Обратите внимание и на то, чего в программе **нет**. Нигде не встречается
`==`: все сравнения строгие. Нигде не сравниваются значения разных типов: оценки
пришли числами и сравниваются с числами. И ни одно условие не длиннее одной строки —
как только оно начинает расти, его выносят в именованную переменную.

<TryIt>
Поменяйте в массиве все оценки на негодные — например, `[9, 1, 0]` — и запустите.
Программа должна сказать «0.00 — надо подтянуть», а не `NaN`. Затем уберите
защиту `count > 0 ?` и посмотрите, что будет.
\
\
Второй опыт: замените `student.name || "Без имени"` на
`student.name ?? "Без имени"` и запустите снова. Имя пропадёт — разберитесь,
почему, и решите, какой оператор тут правильный.
</TryIt>

### Как писать условия, которые читаются

Напоследок — три приёма, которые отличают понятный код от каши. Они не про синтаксис,
а про привычки, и начинать их стоит сразу.

**Первый: давайте условиям имена.** Длинное условие внутри `if`
приходится разгадывать. То же условие с именем читается как предложение:

<Compare>
<Wrong label="Трудно">
```js
if (mark >= 2 && mark <= 5
    && mark !== 0) {
  // ...
}
```
</Wrong>

<Right label="Понятно">
```js
const isValidMark =
  mark >= 2 && mark <= 5;

if (isValidMark) {
  // ...
}
```
</Right>
</Compare>

**Второй: пишите условия утвердительно.** Двойное отрицание — самый быстрый
способ запутать читателя, включая себя:

```js
if (!isNotReady) { }    // «если не не готов» — сколько секунд вы это разбирали?
if (isReady) { }        // вот так
```

Поэтому и имена дают утвердительные: `isReady`, а не `isNotReady`;
`hasTicket`, а не `missingTicket`. Отрицание всегда можно поставить
снаружи — одно, а не два.

**Третий: сравнивайте значения одного типа.** Если оба операнда — числа,
все сегодняшние ловушки исчезают разом. Не будет ни `"10" > "9"`, ни
`null >= 0`, ни `"a" < 1`. Превращайте данные в нужный тип
*на входе*, как мы делали на дне 5, — и сравнения станут скучными и предсказуемыми.

<Important>
Заметьте, что все три приёма ничего не добавляют программе: она работала бы и без них.
Они экономят **ваше время** — то, которое иначе уйдёт на поиск ошибки в условии
через месяц. Условия ломаются тихо: программа не падает, а просто идёт не по той ветке.
</Important>

## 15. Частые ошибки дня {#mistakes}

| Ошибка | Почему | Как правильно |
| --- | --- | --- |
| `if (x = 5)` | одна палочка присваивает | `if (x === 5)` |
| `==` вместо `===` | приводит типы, правил больше десяти | всегда `===` и `!==` |
| `"10" > "9"` | обе строки — сравнение посимвольное | `Number(a) > Number(b)` |
| `2 <= mark <= 5` | считается слева направо, всегда истинно | `mark >= 2 && mark <= 5` |
| `x !== 1 \|\| x !== 2` | всегда истинно | `x !== 1 && x !== 2` |
| `count \|\| 10` для числа | честный ноль заменится на 10 | `count ?? 10` |
| `x === NaN` | всегда `false` | `Number.isNaN(x)` |

Сегодня мы научились получать «да» и «нет». Завтра, на дне 8, закроем тему операторов:

<Selfcheck>
1. Почему `"0" == 0` и `"" == 0` истинны, а `"0" == ""` — нет?
   <Answer>В первых двух парах типы разные, поэтому строка превращается в число, и обе дают 0.
   В третьей паре обе строки — типы совпали, превращать нечего, и они сравниваются
   посимвольно. Это и есть отсутствие транзитивности у `==`.</Answer>
2. Что вернёт `0 || 10` и что вернёт `0 ?? 10`?
   <Answer>`10` и `0`. `||` считает ноль ложным и подставляет
   запасное; `??` реагирует только на `null` и
   `undefined`, поэтому оставляет честный ноль.</Answer>
3. Почему `"10" > "9"` даёт `false`?
   <Answer>Оба операнда строки, поэтому сравнение идёт посимвольно: `"1"` идёт
   в таблице раньше `"9"`, и на первом же символе ответ готов.
   Нужно `Number("10") > Number("9")`.</Answer>
4. Как правильно проверить, что оценка в диапазоне от 2 до 5?
   <Answer>`mark >= 2 && mark <= 5`. Запись `2 <= mark <= 5`
   считается слева направо: сначала получится `true` или `false`,
   потом это сравнится с 5 — и результат будет бессмысленным.</Answer>
5. Что напечатает `false && console.log("привет")` и почему?
   <Answer>Ничего. Левый операнд ложный, значит, ответ `&&` уже известен,
   и правая часть не вычисляется вовсе. Это короткое замыкание.</Answer>
</Selfcheck>
