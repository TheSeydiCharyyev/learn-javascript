# День 8. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 делаем в консоли, дальше — в папке `day-08`.</Subtitle>

## Разминка

<Task title="1. Таблица приведения" level="easy" time="7">
<Goal>увидеть все три направления на одних и тех же значениях.</Goal>

Для каждого значения посчитайте `String()`, `Number()`
и `Boolean()`. Заполните таблицу 8 × 3.

```js
const values = ["0", " ", "", [0], [null], [1, 2], null, undefined];
```

<Hint>
Три значения дадут в колонке `Number()` ноль, хотя выглядят пустыми
или непохожими на ноль. Найдите их.
</Hint>

<Criteria>
- таблица заполнена до проверки в консоли;
- все 24 значения сверены;
- отмечены все случаи, где `Number()` дал 0;
- объяснено, почему `Boolean("0")` и `Boolean([])` истинны.
</Criteria>
</Task>

<Task title="2. Одно значение, пять контекстов" level="easy" time="6">
<Goal>почувствовать, что результат зависит от места, а не от значения.</Goal>

Возьмите `const x = [];` и выполните пять строк. Для каждой запишите результат
и **в какой тип** превратился массив.

```js
x ? "истина" : "ложь";
`${x}`;
x + 1;
x - 1;
x == false;
```

<Criteria>
- пять результатов записаны;
- для каждого указано направление приведения;
- объяснено, почему `x + 1` и `x - 1` дали разное.
</Criteria>
</Task>

<Task title="3. Кто считается первым" level="easy" time="7">
<Goal>проверить таблицу приоритетов на практике.</Goal>

Сначала предскажите, потом проверьте. Для каждой строки запишите **порядок шагов**.

```js
2 + 3 * 4;
(2 + 3) * 4;
10 - 5 - 2;
2 ** 3 ** 2;
1 + 2 === 3 && 2 > 1;
true || false && false;
```

<Criteria>
- предсказания записаны до проверки;
- для каждой строки выписан порядок действий по шагам;
- найдены две строки, где порядок оказался не слева направо;
- объяснено, почему последняя строка даёт `true`.
</Criteria>
</Task>

## Основные задания

<Task title="4. Маршрут сравнения" level="medium" time="12">
<Goal>разобрать механизм `==` до конца.</Goal>

Для каждой пары распишите маршрут в три строки: какие типы, что во что превратилось,
какой итог.

```js
"0" == 0;
"" == 0;
"0" == "";
true == 1;
"1" == true;
null == 0;
[] == false;
```

<WriteBox>
для каждой пары: типы → после приведения → результат.
</WriteBox>

<Hint>
Пара `"1" == true` проходит **два** превращения:
сначала `true` становится числом, потом строка. Проследите оба шага.
</Hint>

<Criteria>
- маршрут расписан для всех семи пар;
- найдена пара, где приведения не было вовсе, и объяснено почему;
- найдена пара, где превращений было два;
- записано, что даст `===` для каждой пары.
</Criteria>
</Task>

<Task title="5. Проверка на границе" level="medium" time="14">
<Goal>написать функцию, после которой в программе ходят только годные данные.</Goal>

Напишите `toMark(input)`: принимает строку из поля ввода, возвращает число
от 2 до 5 или `null`, если ввод негодный. Проверьте на списке:

```js
const inputs = ["4", "  5  ", "", "  ", "пять", "9", "3.5", "4px"];
```

<Hint>
Порядок проверок важен. Пустоту ловите **до** `Number()` —
иначе пустая строка станет нулём и попадёт в проверку диапазона с неверным сообщением.
</Hint>

<Criteria>
- все восемь значений проверены, ответы записаны;
- `""` и `"  "` дают `null`;
- `"4px"` даёт `null` — записано, что дал бы
  `parseInt` и почему тут он не подходит;
- записан порядок проверок и объяснено, что сломается при перестановке.
</Criteria>
</Task>

  const sum = a + b;

console.log(name);

<Hint>

<Task title="7. «Табель»: чистим ввод" level="medium" time="12">
<Goal>применить приведение к настоящим данным из формы.</Goal>

Скопируйте папку `day-07` в `day-08`. Замените массив оценок
на «сырой», как из полей ввода, и разберите его:

```js
const raw = ["5", "4", "", "  3  ", "пять", "9", "5"];
```

Программа должна собрать два списка: принятые оценки (числами) и отброшенные —
с указанием причины для каждой.

<Criteria>
- приняты ровно четыре оценки, все числа, а не строки;
- у каждой отброшенной записана своя причина: пусто, не число, вне диапазона;
- `"  3  "` принимается — объяснено почему;
- проверено через `typeof`, что в списке принятых лежат числа;
- средний балл считается только по принятым.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Number или parseInt" level="hard" time="10">
<Goal>понять, когда какая функция превращения подходит.</Goal>

Заполните таблицу: для каждой строки посчитайте `Number()`,
`parseInt()` и `parseFloat()`.

```js
const strings = ["42", "42px", "px42", "", "  7  ", "3.9", "1e3"];
```

Затем решите две задачи и объясните выбор функции:

- пользователь вводит возраст в поле — нужно проверить, что введено число;
- из строки `"16px"`, полученной из стилей страницы, нужно достать 16.

<Criteria>
- таблица 7 × 3 заполнена;
- найдены все строки, где функции разошлись;
- для обеих задач выбрана функция и объяснён выбор;
- записано, что будет, если в первой задаче взять `parseInt`,
  а пользователь введёт `"18лет"`.
</Criteria>
</Task>

<Task title="9. Шесть ловушек" level="hard" time="10">
<Goal>собрать вместе всё, что сегодня ведёт себя неожиданно.</Goal>

Для каждого фрагмента **сначала** запишите предсказание, потом проверьте
и объясните расхождение одним предложением.

```js
// 1
const input = "";
console.log(Number(input), Number.isNaN(Number(input)));

// 2
console.log([5] + 1, [5] - 1);

// 3
const student = { name: "Аман" };
console.log("Студент: " + student);

// 4
console.log(typeof 1 + 1);

// 5
console.log(true || false && false);

// 6
console.log("" == 0, "0" == 0, "0" == "");
```

<Hint>
Ни один фрагмент не выдаёт ошибку — все шесть тихо возвращают не то, что кажется.
Именно поэтому приведение типов и опасно.
</Hint>

<Criteria>
- предсказания записаны до запуска;
- для каждого названа причина: пустая строка как ноль, ToPrimitive у массива,
  объект в строковом контексте, приоритет `typeof`, приоритет
  `&&`, маршруты `==`;
- фрагменты 3 и 4 переписаны так, чтобы выводили ожидаемое;
- для фрагмента 1 написана правильная проверка пустого ввода.
</Criteria>
</Task>
