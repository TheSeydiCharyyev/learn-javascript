# Day 9. Conditions

<Subtitle>A summary of the lecture: `if`, the `else if` ladder, `switch`, `break` and fall-through.</Subtitle>

## The main points

<Definition>
**Branching** is a fork: the program looks at a condition and chooses a road.
**Exactly one** branch runs, after which the program goes on as
usual.
</Definition>

<KeyPoint>
We put curly braces **always**, even for one line. Without them
`if` takes exactly one statement, and everything else always runs —
and the indentation hides it.
</KeyPoint>

## if and the ladder

```js
const mark = 4;

if (mark === 5) {
  console.log("excellent");
} else if (mark === 4) {
  console.log("good");
} else {
  console.log("the rest");
}
```

A ladder is checked **from top to bottom** and stops at the first branch
that fits. That is why **the strictest** condition goes on top.

<Remember>
`if (score >= 50) ... else if (score >= 90)` — with 95 the first branch works,
and a top student gets a three. The lower ones never work.
</Remember>

## Checking at the boundaries

```js
// for the threshold 90 we check three values
function isFive(score) {
  return score >= 90;
}
isFive(89);   // false
isFive(90);   // true — exactly on the boundary
isFive(91);   // true

// a hole between branches
const score = 90;
let g;
if (score > 90) { g = "5"; } else if (score < 90) { g = "4"; }
g;            // undefined — 90 did not get anywhere
```

Mistakes live **at the edges** of ranges; in the middle everything usually works.
For strings the edge is `""` and `"   "`, for arrays — an empty one, for input —
`null` and `undefined`.

## What counts as a condition

```js
const name = "Aman";
const marks = [];

if (name) { console.log("has a name"); }         // a non-empty string is true
if (marks.length) { console.log("has marks"); }  // 0 is false, will not be printed

// falsy are only: false 0 "" NaN null undefined
```

<Remember>
`if (count)` and `if (count !== undefined)` differ on zero
and the empty string. If zero is legitimate data (a counter, a temperature), write an exact
check.
</Remember>

## Untangling nesting

```js
const isLoggedIn = true;
const hasTicket = true;
const user = { age: 20 };

// 1. join with &&
if (isLoggedIn && hasTicket) { console.log("come in"); }

// 2. an early exit — refusals first (on one line, braces may be left out)
function check(mark) {
  if (mark === undefined) return "invalid";
  if (mark < 2 || mark > 5) return "invalid";
  return "valid";
}
check(7);     // "invalid"

// 3. give the condition a name
const isAdult = user !== null && user.age >= 18;
if (isAdult) { console.log("adult"); }
```

## switch

```js
const mark = 4;
let word;

switch (mark) {
  case 5:
    word = "excellent";
    break;          // forgot it — it falls through into the next branch!
  case 4:
    word = "good";
    break;
  default:
    word = "unknown";
}
word;               // "good"

const day = "Sun";
switch (day) {
  case "Sat":
  case "Sun":       // grouping: shared code for two values
    word = "day off";
    break;
  default:
    word = "working day";
}
word;               // "day off"
```

<Remember>
A `case` is an **entry label**, not a separate branch. A match
says where to start; only `break` stops it. The comparison is done
with `===`, without type conversion.
</Remember>

## Three traps of switch

```js
// 1. the whole switch is ONE block:
// case 1: let a = 1; break; case 2: let a = 2;
//   → SyntaxError: Identifier 'a' has already been declared
// cured by giving the branch its own { }:
const x = 2;
switch (x) {
  case 1: { let a = 1; break; }
  case 2: { let a = 2; break; }
}

// 2. default does not have to be last — but put it last
// 3. ranges cannot be checked with switch — you need an else if ladder
```

## What to choose

| Task | With what |
| --- | --- |
| two branches, one check | `if...else` |
| ranges, complex conditions | an `else if` ladder |
| one value, enumerable options | `switch` |
| choose a value, not perform actions | `? :` (day 7) |

<NoteBox>
**Common mistakes.** `if (x = 5)` assigns. A wide condition above
a narrow one makes the lower branches dead. A forgotten `break` lets execution fall through further.
A ladder without a last branch silently returns `undefined`.
\
**`try...catch`** (day 11) is not a replacement for checks. What can be
checked with a condition, check with a condition.
</NoteBox>
