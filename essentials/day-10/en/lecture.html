1. Why repeat

Yesterday the program learned to choose a road. Today it will learn to walk the same road many times.

Imagine you need to print the marks of six students. Without a loop it looks like this:

const marks = [5, 4, 3, 5, 2, 4];

console.log(marks[0]);
console.log(marks[1]);
console.log(marks[2]);
console.log(marks[3]);
console.log(marks[4]);
console.log(marks[5]);

Six almost identical lines. And if there are thirty students? And if their number is not known in advance — as in a real program, where data comes from a server? You cannot copy lines.

for (let i = 0; i < marks.length; i++) {
  console.log(marks[i]);
}

Three lines, and the number of marks no longer matters: six or three thousand. A loop is a way to write an action once and run it many times.

A loop and branching together give the program everything it needs: it can choose and it can repeat. Technically this is enough to express any algorithm — everything else in the language exists for convenience, not for new possibilities.

2. The for loop and its three parts

The most common loop. Its header has three parts separated by semicolons:

for (let i = 0; i < 5; i++) {
  console.log(i);
}
// 0 1 2 3 4
PartNameWhen it runs
let i = 0startonce, before the loop
i < 5conditionbefore each pass
i++stepafter each pass
{ ... }bodywhile the condition is true

The variable i is called the counter. The name is short and traditional — it comes from the word index. For nested loops people take j, k. This is one of the rare cases where a one-letter name is considered good style: everyone knows that i in a loop is a counter.

The counter is declared with let, not const — it changes on every step. We covered this on day 4: const i in an ordinary for gives a TypeError on the very first i++.

And it is declared in the header, not outside. Then it lives only inside the loop and does not get in the way of the rest of the code: 
for (let i = 0; i < 3; i++) { }
console.log(i);   // ReferenceError: i is not defined

for (var k = 0; k < 3; k++) { }
console.log(k);   // 3 — var leaks outside, day 4

3. How for runs

The order of the steps is worth following in full once — after that it will become obvious.

Remember the main thing: the step runs after the body, not before. That is why on the first pass i is zero, not one.

And the second important detail: the condition is checked before the body. If it is false right away, the body will not run even once:

for (let i = 10; i < 3; i++) {
  console.log("we never get here");
}

4. Four forms of the counter

The for header can be written in different ways. Here are four forms that cover almost all tasks.

Forward through an array — the most common one:

const marks = [5, 4, 3, 5, 2, 4];

for (let i = 0; i < marks.length; i++) {
  console.log(marks[i]);
}

Backward — when you need to go from the end:

for (let i = marks.length - 1; i >= 0; i--) {
  console.log(marks[i]);
}

Notice two details: the start is length - 1, because the indexes end one before the length, and the condition is >= 0, not > 0, otherwise the element at index zero is skipped.

Every other one — the step does not have to be one:

for (let i = 0; i < 10; i += 2) {
  console.log(i);   // 0 2 4 6 8
}

With two counters — using the comma operator from day 7:

for (let i = 0, j = 5; i < j; i++, j--) {
  console.log(i, j);   // 0 5 / 1 4 / 2 3
}
A condition with <= instead of < is the classic off-by-one mistake: 
for (let i = 0; i <= marks.length; i++) {
  console.log(marks[i]);   // the last one printed will be undefined!
}
If the array has six elements, the indexes go from 0 to 5. With i = 6 you get marks[6] — and there is no such element, so we get the undefined from day 5. Remember the rule of day 9: mistakes live at the edges.

Five techniques that cover almost everything

Loop tasks look varied, but they come down to a few building blocks. Learn these five — and most exercises will start to look alike.

An accumulator. We create a variable before the loop and add to it on every step:

let sum = 0;
for (let i = 0; i < marks.length; i++) {
  sum += marks[i];
}
console.log(sum);   // 23

A counter. The same, but we count not the values but how many times a condition was true:

let fives = 0;
for (let i = 0; i < marks.length; i++) {
  if (marks[i] === 5) {
    fives++;
  }
}
console.log(fives);   // 2

A maximum. We keep “the best so far” and update it if we find a better one:

let max = marks[0];              // we start with the first element
for (let i = 1; i < marks.length; i++) {   // and with the second index
  if (marks[i] > max) {
    max = marks[i];
  }
}
console.log(max);   // 5
Starting the maximum at zero — let max = 0; — is fine only if you are sure that all the numbers are positive. For temperatures or a balance it gives a wrong answer: the maximum of [-5, -2, -9] comes out as 0, although there is no such value in the data.

The safe version is to start with -Infinity (day 5): nothing is smaller, so the very first element replaces it. True, on an empty array you will get -Infinity, and with marks[0] — undefined. Both answers are strange, so it is better to cut off an empty array in advance.

A flag. We check whether there is at least one matching element. As soon as we find it, we exit:

let hasFail = false;
for (let i = 0; i < marks.length; i++) {
  if (marks[i] === 2) {
    hasFail = true;
    break;         // no need to search further
  }
}

Building a string. The same accumulator, only we add text:

let line = "";
for (let i = 0; i < marks.length; i++) {
  line += marks[i];
  if (i < marks.length - 1) {
    line += ", ";
  }
}
console.log(line);   // "5, 4, 3, 5, 2, 4"

The condition i < marks.length - 1 is needed so that a comma does not hang after the last element. On day 19 we will learn the join method, which does this in one line — but it is still useful to understand the mechanism.

A fair warning for the future. In real code all five techniques above are written shorter — with array methods and other techniques that we will cover on days 18–22: 
marks.reduce((a, b) => a + b, 0);      // 23 — the sum
marks.filter((m) => m === 5).length;   // 2 — fives
Math.max(...marks);                    // 5 — the maximum
marks.includes(2);                     // true — there is a two
marks.join(", ");                      // "5, 4, 3, 5, 2, 4"
Five lines instead of thirty. A question arises: why learn loops then?

Because array methods are the same loops inside. If you do not understand how an accumulator works, you will not understand reduce. If you do not understand break, you will not understand why find stops and filter does not. And because not every task fits a ready-made method: as soon as the logic gets a little more complex, you will come back to an ordinary loop.

So the order is this: first loops by hand — today and tomorrow, then arrays and their methods — days 19 and 20. The second will be easy if the first has sunk in.

5. The while loop

When the number of repetitions is not known in advance, people take while. It has only a condition:

let i = 0;

while (i < 3) {
  console.log(i);
  i++;
}
// 0 1 2

The same result as with for, but the parts are spread out: the start is before the loop, the step is inside the body. That is exactly why for is more convenient for going through with a counter: everything is in one line and you will not forget anything.

while is good where there is no step as such, only a stop condition:

let balance = 1000;
let months = 0;

while (balance >= 150) {
  balance -= 150;
  months++;
}

console.log(`Enough for ${months} months`);   // 6

How many times the loop will run is not known in advance — that is the answer to the task.

6. The do...while loop

The third loop differs in one thing: the condition is checked after the body. So the body will run at least once, even if the condition is false from the very start.

while — 0 times
let i = 10;

while (i < 3) {
  console.log(i);
  i++;
}
// will not run even once
do...while — 1 time
let i = 10;

do {
  console.log(i);
  i++;
} while (i < 3);
// runs once: 10

Notice the semicolon after while (i < 3); — here it is needed, unlike in an ordinary loop and in if.

Where this comes in handy: when an action has to be done first, and then you decide whether to repeat it. The classic case is asking the user until they enter it correctly:

let n;

do {
  n = Number(prompt("Enter a number from 1 to 10"));
} while (!(n >= 1 && n <= 10));   // NaN will not get through either

You have to ask in any case — so it is do...while. With an ordinary while you would have to ask once before the loop and a second time inside it.

The condition is written with “not”: we repeat while the number has not got into the range. The form “less than 1 or greater than 10” would let NaN through — with it both comparisons are false, and “abc” would pass for an answer.

This loop is noticeably rarer than the other two. You need to know it, but you will rarely have to write it.

Any for can be rewritten with while and the other way around — it is one and the same mechanism in a different wrapper. People choose by what is easier to read. If there is a counter and a step in the header, for will gather them into one line. If there is no counter, while will not make you invent one.

8. The infinite loop

The main danger of loops: if the condition never becomes false, the program hangs.

// do not run this — the tab will hang
let i = 0;

while (i < 3) {
  console.log(i);
  // forgot i++!
}

i will stay zero forever, the condition will stay true forever, and the browser will hang. The tab will stop responding, and after a few seconds the browser will offer to close it.

If a tab has hung, close it and look at three things in the loop:
  1. does the variable that stands in the condition change;
  2. does it change in the right direction (i-- instead of i++ is an infinite loop too);
  3. is the stop condition reachable at all (i !== 10 with the step i += 3 will never work: 0, 3, 6, 9, 12…).

The third point is the most insidious, because the variable does change and the loop looks like it works:

// do not run this — the tab will hang
for (let i = 0; i !== 10; i += 3) {   // 0, 3, 6, 9, 12, 15... past 10
  console.log(i);
}

That is why loop conditions use < and >, not !==: they stop the loop even if the counter jumps over the boundary.

Sometimes an infinite loop is needed — when the exit is hidden inside the body:

while (true) {
  const answer = prompt("Type “stop”");
  if (answer === "stop") {
    break;   // here it is, the exit
  }
}

This form is legitimate but requires attention: if there is no break in the body, you have written a hang.

How to catch a hang

Debugging an infinite loop is awkward: the tab does not respond, the console does not work, you cannot look at anything. So the approach is the opposite — do not let the loop hang.

The technique is simple: add a safety counter that will forcibly cut everything off.

let i = 0;
let guard = 0;        // a safety net

while (i < 5) {
  guard++;
  if (guard > 1000) {
    console.error("looks like an infinite loop, i =", i);
    break;
  }

  console.log(i);
  // forgot i++ — but the program will not hang
}

A thousand passes run instantly, and instead of a hang you get an honest message and the value of the counter — which shows right away that it did not change.

The safety net is added temporarily, for debugging, and removed once the cause is found. You should not leave it in working code: it hides the problem instead of solving it.

The second way is debugger from day 2. Put it as the first line of the body, and the browser will stop on every pass: you can look at the values and press “Resume” one pass at a time. For a loop that turns three times incorrectly, this is faster than any console.log.

9. break: exit early

You know the word break from yesterday. In a loop it means the same — “exit the nearest construct”, only now that construct is a loop:

for (let i = 0; i < 10; i++) {
  if (i === 3) {
    break;
  }
  console.log(i);
}
// 0 1 2 — exited at three

The main use is searching. You found what you were looking for, there is no need to go further:

const marks = [5, 4, 3, 2, 5];
let firstFail = -1;

for (let i = 0; i < marks.length; i++) {
  if (marks[i] === 2) {
    firstFail = i;
    break;        // found the first two, the rest are not needed
  }
}

console.log(firstFail);   // 3

Notice -1 as “not found”. This is an old convention, and it is built into the language: the indexOf method from day 19 answers in exactly the same way.

break in a switch inside a loop

We mentioned this yesterday — here is what it looks like. break exits the nearest construct. If there is a switch inside a loop, a break inside it exits only the switch, and the loop goes on:

const commands = ["go", "go", "stop", "go"];

for (const cmd of commands) {
  switch (cmd) {
    case "stop":
      console.log("STOP");
      break;              // exits only the switch!
    default:
      console.log(cmd);
  }
}
// go, go, STOP, go — the loop went to the end

The “stop” command did not stop the loop — the last “go” ran anyway. If you need to break out of the loop itself, the simplest way is to set a flag and check it after the switch:

let stopped = false;

for (const cmd of commands) {
  switch (cmd) {
    case "stop":
      stopped = true;
      break;
    default:
      console.log(cmd);
  }

  if (stopped) {
    break;               // but this one exits the loop
  }
}
// go, go — and that is all

The second way is a label on the loop, see section 13. Both work; a flag usually reads more clearly.

10. continue: skip a pass

And this word is new. continue does not exit the loop but stops the current pass and starts the next one.

for (let i = 0; i < 8; i++) {
  if (i % 2 === 0) {
    continue;      // we skip the even ones
  }
  console.log(i);
}
// 1 3 5 7

In practice continue is used to filter out what is not needed at the start of the body and then write the main work without nesting. Compare:

With nesting
for (const mark of marks) {
  if (mark >= 2 && mark <= 5) {
    sum += mark;
    count++;
  }
}
With continue
for (const mark of marks) {
  if (mark < 2 || mark > 5) {
    continue;
  }
  sum += mark;
  count++;
}

On two lines the difference is small, but when there are ten lines of useful work and three checks, the right version reads noticeably better. This is the same early exit that we covered yesterday for functions.

11. The continue trap in while

But here continue bites. Remember the scheme: it skips the rest of the body and goes to the step. In a for loop the step is written in the header, so it will run. But in while the step lies inside the body — and if continue stands before it, there will be no step:

// do not run this — the tab will hang
let i = 0;

while (i < 5) {
  if (i === 2) {
    continue;     // i++ below never runs — an infinite loop!
  }
  console.log(i);
  i++;
}

The program will print 0 and 1, reach two and hang forever.

Hence a practical rule: continue gets along with for and is dangerous in while. If you really need continue in while, do not forget to make the step before it: 
let i = 0;

while (i < 5) {
  const current = i;
  i++;                    // the step right away, at the very start
  if (current === 2) {
    continue;             // now it is safe
  }
  console.log(current);
}
It looks clumsy — and that is one more argument for taking for.

A loop over a string

An array is not the only thing you can loop over. A string also has length and access by index — we saw this on day 5 — so it is iterated in exactly the same way:

const word = "Mary";

for (let i = 0; i < word.length; i++) {
  console.log(word[i]);   // M a r y
}

Hence two tasks that appear in every textbook. Reverse a string:

let reversed = "";
for (let i = word.length - 1; i >= 0; i--) {
  reversed += word[i];
}
console.log(reversed);   // "yraM"

Count how many times a character occurs:

const text = "Salam, dünýä!";
let count = 0;

for (let i = 0; i < text.length; i++) {
  if (text[i] === "a") {
    count++;
  }
}
console.log(count);   // 2
Strings have a caveat worth knowing in advance. The length is counted not in letters but in UTF-16 code units. For Cyrillic, Latin and Turkmen letters there is no difference, but emoji and some rare characters take two positions, and a loop by index will cut them in half. There will be an example on day 16, and a detailed breakdown in course 2.

12. Nested loops

A loop inside a loop is a common thing. The classic example is a multiplication table:

for (let i = 2; i <= 3; i++) {
  let row = "";
  for (let j = 1; j <= 4; j++) {
    row += `${i}x${j}=${i * j}  `;
  }
  console.log(row);
}
// 2x1=2  2x2=4  2x3=6  2x4=8
// 3x1=3  3x2=6  3x3=9  3x4=12

How to read it: the inner loop runs through completely on each step of the outer one. The outer one made one step — the inner one did all four. In total the body of the inner one ran 2 × 4 = 8 times.

Hence an important consequence: nested loops multiply the work. Two loops over 1000 elements are a million passes. Three are a billion, and the program will hang for real, not because of a mistake. With nesting deeper than two levels, it is worth stopping to think whether there is another way.

The counters of nested loops must be different: i, j, k. If you take the same one, the inner loop will spoil the counter of the outer one.

Nested loops are needed where the data is two-dimensional: the rows and columns of a table, the cells of a board, all pairs from a list. Here is the second typical task — all pairs of students, who is on a team with whom:

const names = ["Aman", "Meret", "Gülnar"];

for (let i = 0; i < names.length; i++) {
  for (let j = i + 1; j < names.length; j++) {
    console.log(`${names[i]} and ${names[j]}`);
  }
}
// Aman and Meret
// Aman and Gülnar
// Meret and Gülnar

Notice j = i + 1, not j = 0. This way the inner loop starts with the element after the current one — and the pairs do not repeat. With j = 0 you would get nine lines instead of three, including “Aman and Aman” and the repeat “Meret and Aman”.

Nested loops work like the hour and minute hands of a clock. While the hour hand moves one mark, the minute hand makes a full turn. The outer loop is the hours, the inner one is the minutes: for each step of the outer one, the inner one runs through completely.

13. Labels

There is one task that an ordinary break does not solve: exiting both nested loops at once. An ordinary break exits only the inner one.

For this a loop is given a name — a label:

outer: for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (i === 1 && j === 1) {
      break outer;     // we exit the OUTER loop
    }
    console.log(`${i}${j}`);
  }
}
// 00 01 02 10

A label is just a name with a colon in front of a loop. With continue it works the same way: continue outer starts the next pass of the outer loop.

outer: for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (j === 1) {
      continue outer;   // drop the inner one, go to the next i
    }
    console.log(`${i}${j}`);
  }
}
// 00 10 20
Labels are rare in real code, and that is good: code with them is hard to read. There is almost always a simpler way — move the nested loops into a function and exit with return (day 12). You need to know labels to understand other people’s code; it is better not to write them if you can avoid it.

Three errors of the day

All of them are syntax errors and are related to break, continue and labels:

What was writtenThe message in Chrome
break outside a loop and switchSyntaxError: Illegal break statement
continue outside a loopSyntaxError: Illegal continue statement: no surrounding iteration statement
break nowhere — there is no such labelSyntaxError: Undefined label 'nowhere'

All three are syntax errors, which means that by the rule of day 8 they switch off the whole file. They almost always appear in the same way.

The first two — when someone else’s code is being edited and break or continue accidentally ends up outside after braces are moved around. It is useful to remember that break is legal in two places: in any loop and in switch. And continue — only in a loop; in switch it makes no sense.

The third is a simple typo in a label name, or an attempt to refer to a label that is declared in another place. A label is visible only to the loop it stands in front of, and to what is inside that loop.

14. The “Report card”: loops at work

Let us put the day together in a program. The for and while loops and both ways of control work here.

const MIN_MARK = 2;
const MAX_MARK = 5;

const marks = [5, 4, 9, 3, 5, 0, 4, 5];

// 1. for with continue — we pick the valid marks
const valid = [];
let skipped = 0;

for (let i = 0; i < marks.length; i++) {
  const mark = marks[i];

  if (mark < MIN_MARK || mark > MAX_MARK) {
    skipped++;
    continue;
  }

  valid.push(mark);
}

// 2. for — we add up what we picked
let sum = 0;

for (let i = 0; i < valid.length; i++) {
  sum += valid[i];
}

console.log(`Counted ${valid.length}, skipped ${skipped}, sum ${sum}`);

// 3. for with break — we look for the first two
let firstFail = -1;

for (let i = 0; i < valid.length; i++) {
  if (valid[i] === MIN_MARK) {
    firstFail = i;
    break;
  }
}

if (firstFail === -1) {
  console.log("No twos");
} else {
  console.log(`The first two is mark number ${firstFail + 1}`);
}

// 4. while — how many first marks give half of the sum
let half = 0;
let taken = 0;

while (half < sum / 2) {
  half += valid[taken];
  taken++;
}

console.log(`Half of the sum comes from the first ${taken} marks (got ${half} of ${sum})`);
Counted 6, skipped 2, sum 26
No twos
Half of the sum comes from the first 4 marks (got 17 of 26)

Notice two places.

The first loop does not count but picks. It puts the valid marks into a separate array valid, and all the following loops already work with it. This is done on purpose: if you calculate the sum over one array and search in another, the numbers will stop matching. We will cover the push method on day 19; for now it is enough to know that it adds to the end.

The fourth loop is while, not for, because the number of passes is not known in advance: that is the answer to the task. And the step taken++ is in the body — in while there is no other way.

Three experiments.

The first. Remove taken++ from the fourth loop. It seems that the loop will become infinite — but it will stop. Explain why, and where “the first 0 marks (got 15 of 26)” in the output comes from. Then put the step back.

The second. Change continue in the first loop to break and explain why the count became 2 and the sum 9.

The third. Replace 3 with 2 in the array and check what number the third loop prints. A hint: it counts by valid, not by marks — the numbers will shift.

The for...of and for...in loops from the same chapter are covered on day 11.

const arr = [5, 4, 3];

for (let i = 0; i < arr.length; i++) { }        // start; condition; step
// the condition is checked BEFORE the body, the step runs AFTER it
for (let i = arr.length - 1; i >= 0; i--) { }   // backward
for (let i = 0; i < 10; i += 2) { }             // every other one
for (let i = 0, j = 5; i < j; i++, j--) { }     // two counters

let i = 0;
while (i < 3) { i++; }        // the step is in the body — do not forget it!
i;                            // 3

let j = 10;
do { j++; } while (j < 3);    // at least once; the semicolon is needed
j;                            // 11

for (let k = 0; k < 10; k++) {
  if (k === 3) { break; }         // exit the whole loop
  if (k % 2 === 0) { continue; }  // skip the pass, go to the step
  console.log(k);                 // 1
}

// continue in while BEFORE the step = an infinite loop
// i <= arr.length = an extra pass with undefined
// i !== 10 with the step += 3 = it will not stop
// break outside a loop and switch → SyntaxError: Illegal break statement

outer: for (let a = 0; a < 3; a++) {   // a label
  for (let b = 0; b < 3; b++) {
    if (b === 1) { break outer; }      // exit the outer one
  }
}

// nested loops multiply the work: 1000 x 1000 = a million
  1. In what order do the parts of for run on the first pass?
    Answer The start (once) → the condition → the body → the step → the condition → the body → the step… The step runs after the body, so on the first pass the counter equals its start value.
  2. How is do...while different from while?
    Answer The condition is checked after the body, so the body runs at least once, even if the condition is false from the very start. In the same situation while runs zero times.
  3. Why does continue in while often give an infinite loop?
    Answer Because in while the step lies inside the body. continue skips the rest of the body — together with the step. The counter does not change, and the condition does not become false.
  4. What does the loop for (let i = 0; i <= arr.length; i++) print for an array of three elements?
    Answer Four values: three elements and undefined. The indexes end at length - 1, and the condition <= lets in an extra pass.
  5. How do you exit two nested loops at once?
    Answer Put a label before the outer loop and write break with that label. An ordinary break exits only the inner one. But more often nested loops are moved into a function and exited with return.
