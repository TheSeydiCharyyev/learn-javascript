# Day 10. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder `day-10`.</Subtitle>

<Hint>
**Before you start.** Today it is easy to hang the browser. If a tab stops responding,
close it and open it again — nothing terrible has happened. While debugging,
add a safety net: `guard++; if (guard > 1000) break;`
</Hint>

## Warm-up

<Task title="1. One result, three loops" level="easy" time="7">
<Goal>see that the three loops are one mechanism.</Goal>

Print the numbers from 1 to 10 in three ways: `for`, `while`
and `do...while`. The output must be the same.

<Criteria>
- all three loops are written and give the same output;
- in `for` the counter is declared in the header with `let`;
- it is written down where the start, the condition and the step are in each version;
- there is a semicolon after `do...while`.
</Criteria>
</Task>

<Task title="2. First predict: how many times" level="easy" time="6">
<Goal>catch the difference between `while` and `do...while` and the off-by-one mistake.</Goal>

For each fragment predict how many lines it prints. Then check.

```js
// A
let i = 10;
while (i < 3) { console.log(i); i++; }

// B
let j = 10;
do { console.log(j); j++; } while (j < 3);

// C
const arr = [7, 8, 9];
for (let k = 0; k <= arr.length; k++) { console.log(arr[k]); }

// D
for (let n = 5; n > 0; n--) { console.log(n); }
```

<Criteria>
- four predictions are written down before the check;
- it is explained why B prints one line more than A;
- in fragment C the extra value is found, and it is explained where it comes from;
- fragment C is fixed.
</Criteria>
</Task>

<Task title="3. break versus continue" level="easy" time="7">
<Goal>see the difference on the same loop.</Goal>

Run the loop twice — with `break` and with `continue` — and write down
both outputs.

```js
for (let i = 0; i < 6; i++) {
  if (i === 3) {
    break;      // then replace it with continue
  }
  console.log(i);
}
```

<Criteria>
- both outputs are written down;
- what each word does is explained in your own words;
- it is written down which of the two runs the step `i++` and which does not;
- what `continue` prints with the condition `i % 2 === 0`
  is predicted and checked.
</Criteria>
</Task>

## Main tasks

<Task title="4. Five techniques" level="medium" time="14">
<Goal>master the building blocks that most loop tasks are made of.</Goal>

For the array `[5, 4, 3, 5, 2, 4]` write five separate loops:

1. the sum of all marks;
2. how many fives there are;
3. the highest mark;
4. whether there is at least one two (exit as soon as you find it);
5. the string “5, 4, 3, 5, 2, 4” without a comma at the end.

<Hint>
In the “maximum” technique start with `arr[0]`, and the counter with `i = 1`.
Think about why `let max = 0` is a bad idea, and give an example of an array
where it gives a wrong answer.
</Hint>

<Criteria>
- all five loops work and give the right answers;
- the “flag” technique has a `break`;
- the string has no comma after the last element;
- an example of an array where `let max = 0` is wrong is written down.
</Criteria>
</Task>

<Task title="5. A multiplication table" level="medium" time="12">
<Goal>write a nested loop and understand how it turns.</Goal>

Print the multiplication table from 2 to 9: one line per number, and in each line all
the products from 1 to 10.

<Example>
```js
2x1=2  2x2=4  2x3=6  ...  2x10=20
3x1=3  3x2=6  3x3=9  ...  3x10=30
```
</Example>

<Hint>
Build the line in a variable inside the outer loop, and print it after the inner one —
otherwise each product will go on its own line.
</Hint>

<Criteria>
- exactly 8 lines are printed;
- the counters are different: `i` and `j`;
- it is calculated and written down how many times the body of the inner loop ran;
- it is written down what changes if you swap the loops.
</Criteria>
</Task>

<Task title="6. Catch the hang" level="medium" time="12">
<Goal>learn to find the cause of an infinite loop without hanging the browser.</Goal>

In each fragment the loop will not stop. **First** add a safety net of 1000 passes
to each one, and only then run it. Find the cause and fix it.

```js
// A
let i = 0;
while (i < 5) {
  console.log(i);
}

// B
for (let i = 0; i !== 10; i += 3) {
  console.log(i);
}

// C
let n = 5;
while (n > 0) {
  console.log(n);
  n++;
}

// D
let k = 0;
while (k < 5) {
  if (k === 2) { continue; }
  console.log(k);
  k++;
}
```

<Criteria>
- a safety net is added to all four before the first run;
- the cause is named for each: does not change, does not reach, goes in the wrong direction,
  the step is skipped;
- all four are fixed and stop;
- for fragment D it is explained why `continue` is more dangerous here
  than in `for`.
</Criteria>
</Task>

<Task title="7. The “Report card”: loops at work" level="medium" time="12">
<Goal>put the day together in the course program.</Goal>

Copy the folder `day-09` to `day-10`. Take the array
`[5, 4, 9, 3, 5, 0, 4, 5]` and make four loops:

- `for` with `continue` — pick the valid marks (from 2 to 5)
  into a new array and count the skipped ones;
- `for` — the sum of the picked marks;
- `for` with `break` — the number of the first two, or “no twos”;
- `while` — how many first marks give half of the sum.

<Hint>
All the loops after the first one work with the **picked** array, not
with the original one. Otherwise the numbers will stop matching. Adding to an array is done with `push`.
</Hint>

<Criteria>
- all four loops work;
- counted 6, skipped 2, sum 26;
- the fourth loop is exactly `while`, and it is explained why;
- it is checked: replacing `3` with `2` in the original array changes
  the answer of the third loop — it is written down to which number, and why it does not match
  the place of the two in the original array.
</Criteria>
</Task>

## Starred tasks

<Task title="8. Pairs without repeats" level="hard" time="10">
<Goal>figure out how the start value of the inner counter changes everything.</Goal>

For the array `["Aman", "Meret", "Gülnar", "Sapar"]` print all the pairs
“who is on a team with whom”. The pairs “Aman and Meret” and “Meret and Aman” are one pair,
and a person cannot be in a pair with themselves.

First write the version with `j = 0` and count the lines, then fix it
to `j = i + 1` and count again.

<Criteria>
- both versions are written, and the number of lines is counted for each;
- the right version has exactly 6 pairs;
- it is explained where the difference in the number of lines comes from;
- a formula is written down: how many pairs you get for an array of `n` names.
</Criteria>
</Task>

<Task title="9. Six traps" level="hard" time="10">
<Goal>bring together everything that behaves unexpectedly today.</Goal>

For each fragment **first** write down a prediction, then check it
and explain the difference in one sentence. Two fragments hang — they need a safety net.

```js
// 1
const arr = [7, 8, 9];
for (let i = 0; i <= arr.length; i++) { console.log(arr[i]); }

// 2
for (let i = arr.length - 1; i > 0; i--) { console.log(arr[i]); }

// 3
for (var v = 0; v < 3; v++) { }
console.log(v);

// 4
for (let l = 0; l < 3; l++) { }
console.log(typeof l);

// 5
let m = 0;
while (m < 3) { if (m === 1) continue; m++; }

// 6
for (let i = 0; i !== 10; i += 3) { }
```

<Hint>
Fragments 2 and 4 do not hang, but they give something other than what it seems: in one an element gets lost,
in the other a variable does. Fragments 5 and 6 are the ones that hang.
</Hint>

<Criteria>
- the predictions are written down before running;
- both hanging fragments are found, and a safety net is added to them before running;
- for fragments 3 and 4 the difference between `var` and `let`
  is explained with a reference to day 4;
- fragments 1, 2, 5 and 6 are rewritten so that they do what is expected of them.
</Criteria>
</Task>
