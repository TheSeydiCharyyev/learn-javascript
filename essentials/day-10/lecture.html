1. Зачем повторять

Вчера программа научилась выбирать дорогу. Сегодня научится ходить по одной дороге много раз.

Представьте, что надо вывести оценки шести студентов. Без цикла это выглядит так:

const marks = [5, 4, 3, 5, 2, 4];

console.log(marks[0]);
console.log(marks[1]);
console.log(marks[2]);
console.log(marks[3]);
console.log(marks[4]);
console.log(marks[5]);

Шесть почти одинаковых строк. А если студентов тридцать? А если их число заранее неизвестно — как в настоящей программе, где данные приходят с сервера? Копировать строки нельзя.

for (let i = 0; i < marks.length; i++) {
  console.log(marks[i]);
}

Три строки, и число оценок больше не имеет значения: хоть шесть, хоть три тысячи. Цикл — это способ написать действие один раз, а выполнить много.

Цикл и ветвление вместе дают программе всё, что нужно: она умеет выбирать и умеет повторять. Технически этого достаточно, чтобы выразить любой алгоритм — всё остальное в языке существует ради удобства, а не ради новых возможностей.

2. Цикл for и три его части

Самый частый цикл. В заголовке у него три части, разделённые точками с запятой:

for (let i = 0; i < 5; i++) {
  console.log(i);
}
// 0 1 2 3 4
ЧастьНазваниеКогда выполняется
let i = 0началоодин раз, перед циклом
i < 5условиеперед каждым проходом
i++шагпосле каждого прохода
{ ... }телопока условие истинно

Переменную i называют счётчиком. Имя короткое и традиционное — от английского index. Для вложенных циклов берут j, k. Это один из редких случаев, когда однобуквенное имя считается хорошим стилем: все знают, что i в цикле — счётчик.

Счётчик объявляют через let, а не const — он меняется на каждом шаге. Мы разбирали это на дне 4: const i в обычном for даёт TypeError на первом же i++.

И объявляют его в заголовке, а не снаружи. Тогда он живёт только внутри цикла и не мешает остальному коду: 
for (let i = 0; i < 3; i++) { }
console.log(i);   // ReferenceError: i is not defined

for (var k = 0; k < 3; k++) { }
console.log(k);   // 3 — var вылезает наружу, день 4

3. Как выполняется for

Порядок шагов стоит один раз проследить полностью — дальше он станет очевидным.

Запомните главное: шаг выполняется после тела, а не до. Поэтому на первом проходе i равен нулю, а не единице.

И вторая важная деталь: условие проверяется перед телом. Если оно ложно сразу, тело не выполнится ни разу:

for (let i = 10; i < 3; i++) {
  console.log("сюда не попадём");
}

4. Четыре формы счётчика

Заголовок for можно писать по-разному. Вот четыре формы, которые покрывают почти все задачи.

Вперёд по массиву — самая частая:

const marks = [5, 4, 3, 5, 2, 4];

for (let i = 0; i < marks.length; i++) {
  console.log(marks[i]);
}

Назад — когда надо пройти с конца:

for (let i = marks.length - 1; i >= 0; i--) {
  console.log(marks[i]);
}

Обратите внимание на две детали: начало length - 1, потому что индексы кончаются на единицу раньше длины, и условие >= 0, а не > 0, иначе нулевой элемент пропустится.

Через один — шаг не обязан быть единицей:

for (let i = 0; i < 10; i += 2) {
  console.log(i);   // 0 2 4 6 8
}

С двумя счётчиками — через оператор запятая из дня 7:

for (let i = 0, j = 5; i < j; i++, j--) {
  console.log(i, j);   // 0 5 / 1 4 / 2 3
}
Условие с <= вместо < — классическая ошибка «на единицу»: 
for (let i = 0; i <= marks.length; i++) {
  console.log(marks[i]);   // последним выведет undefined!
}
Если в массиве шесть элементов, индексы идут от 0 до 5. При i = 6 получится marks[6] — а такого нет, и мы получим undefined из дня 5. Помните правило дня 9: ошибки живут на краях.

Пять приёмов, которые покрывают почти всё

Задачи на циклы выглядят разнообразно, но сводятся к нескольким заготовкам. Выучите эти пять — и большинство упражнений станут похожими друг на друга.

Накопитель. Заводим переменную до цикла и добавляем к ней на каждом шаге:

let sum = 0;
for (let i = 0; i < marks.length; i++) {
  sum += marks[i];
}
console.log(sum);   // 23

Счётчик. То же самое, но считаем не значения, а сколько раз выполнилось условие:

let fives = 0;
for (let i = 0; i < marks.length; i++) {
  if (marks[i] === 5) {
    fives++;
  }
}
console.log(fives);   // 2

Максимум. Храним «лучшее пока» и обновляем, если нашли лучше:

let max = marks[0];              // начинаем с первого элемента
for (let i = 1; i < marks.length; i++) {   // и со второго индекса
  if (marks[i] > max) {
    max = marks[i];
  }
}
console.log(max);   // 5
Начинать максимум с нуля — let max = 0; — можно только если вы уверены, что все числа положительные. Для температур или баланса это даст неверный ответ: максимум из [-5, -2, -9] получится 0, хотя такого значения в данных нет.

Безопасный вариант — начать с -Infinity (день 5): меньше него ничего нет, поэтому первый же элемент его заменит. Правда, на пустом массиве вы получите -Infinity, а с marks[0] — undefined. Оба ответа странные, так что пустой массив лучше отсечь заранее.

Флаг. Проверяем, есть ли хоть один подходящий элемент. Как только нашли — выходим:

let hasFail = false;
for (let i = 0; i < marks.length; i++) {
  if (marks[i] === 2) {
    hasFail = true;
    break;         // дальше искать незачем
  }
}

Сборка строки. Тот же накопитель, только складываем текст:

let line = "";
for (let i = 0; i < marks.length; i++) {
  line += marks[i];
  if (i < marks.length - 1) {
    line += ", ";
  }
}
console.log(line);   // "5, 4, 3, 5, 2, 4"

Условие i < marks.length - 1 нужно, чтобы запятая не повисла после последнего элемента. На дне 19 мы узнаем метод join, который делает это одной строкой, — но понимать механизм всё равно полезно.

Честное предупреждение на будущее. Все пять приёмов выше в настоящем коде пишут короче — через методы массива и другие приёмы, которые мы разберём на днях 18–22: 
marks.reduce((a, b) => a + b, 0);      // 23 — сумма
marks.filter((m) => m === 5).length;   // 2 — пятёрки
Math.max(...marks);                    // 5 — максимум
marks.includes(2);                     // true — есть двойка
marks.join(", ");                      // "5, 4, 3, 5, 2, 4"
Пять строк вместо тридцати. Возникает вопрос: зачем тогда учить циклы?

Затем, что методы массива — это те же циклы внутри. Не поняв, как работает накопитель, вы не поймёте reduce. Не поняв break, не поймёте, почему find останавливается, а filter — нет. И затем, что не всякая задача ложится в готовый метод: как только логика чуть сложнее, вы вернётесь к обычному циклу.

Так что порядок такой: сначала циклы руками — сегодня и завтра, потом массивы и их методы — дни 19 и 20. Второе будет лёгким, если первое улеглось.

5. Цикл while

Когда число повторений заранее неизвестно, берут while. У него только условие:

let i = 0;

while (i < 3) {
  console.log(i);
  i++;
}
// 0 1 2

Тот же результат, что у for, но части разнесены: начало — до цикла, шаг — внутри тела. Именно поэтому для перебора по счётчику удобнее for: там всё в одной строке и ничего не забудешь.

while хорош там, где шага как такового нет, а есть условие остановки:

let balance = 1000;
let months = 0;

while (balance >= 150) {
  balance -= 150;
  months++;
}

console.log(`Хватит на ${months} месяцев`);   // 6

Сколько раз выполнится цикл — заранее неизвестно, это и есть ответ задачи.

6. Цикл do...while

Третий цикл отличается одним: условие проверяется после тела. Значит, тело выполнится хотя бы раз, даже если условие ложно с самого начала.

while — 0 раз
let i = 10;

while (i < 3) {
  console.log(i);
  i++;
}
// не выполнится ни разу
do...while — 1 раз
let i = 10;

do {
  console.log(i);
  i++;
} while (i < 3);
// выполнится один раз: 10

Обратите внимание на точку с запятой после while (i < 3); — здесь она нужна, в отличие от обычного цикла и if.

Где это пригождается: когда действие надо сделать, а потом решить, повторять ли. Классический случай — спросить у пользователя, пока не введёт правильно:

let n;

do {
  n = Number(prompt("Введите число от 1 до 10"));
} while (!(n >= 1 && n <= 10));   // NaN тоже не пройдёт

Спросить надо в любом случае — значит, do...while. С обычным while пришлось бы спрашивать один раз до цикла и второй раз внутри.

Условие записано через «не»: повторяем, пока число не попало в диапазон. Запись «меньше 1 или больше 10» пропустила бы NaN — с ним оба сравнения ложны, и «abc» сошло бы за ответ.

Встречается этот цикл заметно реже двух других. Знать его надо, писать придётся редко.

Последняя строка — то, чем мы уже пользовались в «Табеле», не разбирая. Завтра дойдут руки и до неё.

Любой for можно переписать через while и наоборот — это один и тот же механизм в разной обёртке. Выбирают по тому, что удобнее читать. Если в заголовке есть счётчик и шаг — for соберёт их в одну строку. Если счётчика нет — while не заставит его выдумывать.

8. Вечный цикл

Главная опасность циклов: если условие никогда не станет ложным, программа зависнет.

// не запускайте — вкладка зависнет
let i = 0;

while (i < 3) {
  console.log(i);
  // i++ забыли!
}

i навсегда останется нулём, условие навсегда останется истинным, и браузер повиснет. Вкладка перестанет отвечать, и через несколько секунд браузер предложит её закрыть.

Если вкладка зависла — закройте её и посмотрите на три вещи в цикле:
  1. меняется ли переменная, которая стоит в условии;
  2. меняется ли она в нужную сторону (i-- вместо i++ — тоже вечный цикл);
  3. достижимо ли условие остановки вообще (i !== 10 при шаге i += 3 не сработает никогда: 0, 3, 6, 9, 12…).

Третий пункт коварнее всех, потому что переменная меняется и цикл выглядит рабочим:

// не запускайте — вкладка зависнет
for (let i = 0; i !== 10; i += 3) {   // 0, 3, 6, 9, 12, 15... мимо 10
  console.log(i);
}

Поэтому в условиях цикла пишут < и >, а не !==: они остановят цикл, даже если счётчик перепрыгнул границу.

Бывает и нужный вечный цикл — когда выход спрятан внутри тела:

while (true) {
  const answer = prompt("Введите «стоп»");
  if (answer === "стоп") {
    break;   // вот он, выход
  }
}

Такая запись законна, но требует внимания: если в теле нет break, вы написали зависание.

Как ловить зависание

Отлаживать вечный цикл неудобно: вкладка не отвечает, консоль не работает, посмотреть ничего нельзя. Поэтому подход обратный — не дать циклу зависнуть.

Приём простой: добавить страховочный счётчик, который принудительно всё оборвёт.

let i = 0;
let guard = 0;        // страховка

while (i < 5) {
  guard++;
  if (guard > 1000) {
    console.error("похоже на вечный цикл, i =", i);
    break;
  }

  console.log(i);
  // i++ забыли — но программа не зависнет
}

Тысяча проходов выполнится мгновенно, а вместо зависания вы получите честное сообщение и значение счётчика — по которому сразу видно, что он не менялся.

Страховку ставят временно, на время отладки, и убирают, когда причина найдена. Оставлять её в рабочем коде не надо: она прячет проблему вместо того, чтобы её решать.

Второй способ — debugger из дня 2. Поставьте его первой строкой тела, и браузер остановится на каждом проходе: можно смотреть значения и нажимать «дальше» по одному шагу. Для цикла, который крутится три раза неправильно, это быстрее любых console.log.

9. break: выйти досрочно

Слово break вы знаете со вчерашнего дня. В цикле оно означает то же самое — «выйти из ближайшей конструкции», только теперь это цикл:

for (let i = 0; i < 10; i++) {
  if (i === 3) {
    break;
  }
  console.log(i);
}
// 0 1 2 — на тройке вышли

Главное применение — поиск. Нашли что искали, дальше идти незачем:

const marks = [5, 4, 3, 2, 5];
let firstFail = -1;

for (let i = 0; i < marks.length; i++) {
  if (marks[i] === 2) {
    firstFail = i;
    break;        // нашли первую двойку, остальные не нужны
  }
}

console.log(firstFail);   // 3

Обратите внимание на -1 как «не нашли». Это давнее соглашение, и в языке оно встроено: метод indexOf из дня 19 отвечает ровно так же.

break в switch внутри цикла

Вчера мы об этом упомянули — вот как это выглядит. break выходит из ближайшей конструкции. Если внутри цикла стоит switch, то break внутри него выйдет только из switch, а цикл продолжится:

const commands = ["идти", "идти", "стоп", "идти"];

for (const cmd of commands) {
  switch (cmd) {
    case "стоп":
      console.log("СТОП");
      break;              // выходит только из switch!
    default:
      console.log(cmd);
  }
}
// идти, идти, СТОП, идти — цикл дошёл до конца

Команда «стоп» не остановила цикл — последнее «идти» всё равно выполнилось. Если нужно прервать именно цикл, самый простой способ — поставить флаг и проверить его после switch:

let stopped = false;

for (const cmd of commands) {
  switch (cmd) {
    case "стоп":
      stopped = true;
      break;
    default:
      console.log(cmd);
  }

  if (stopped) {
    break;               // а вот этот выходит уже из цикла
  }
}
// идти, идти — и всё

Второй способ — метка на цикле, о ней в разделе 13. Оба работают; флаг обычно читается понятнее.

10. continue: пропустить проход

А это слово новое. continue не выходит из цикла, а прекращает текущий проход и начинает следующий.

for (let i = 0; i < 8; i++) {
  if (i % 2 === 0) {
    continue;      // чётные пропускаем
  }
  console.log(i);
}
// 1 3 5 7

На практике continue используют, чтобы отсеять ненужное в начале тела и дальше писать основную работу без вложенности. Сравните:

Через вложенность
for (const mark of marks) {
  if (mark >= 2 && mark <= 5) {
    sum += mark;
    count++;
  }
}
Через continue
for (const mark of marks) {
  if (mark < 2 || mark > 5) {
    continue;
  }
  sum += mark;
  count++;
}

На двух строках разница невелика, но когда полезной работы десять строк, а проверок три — правый вариант читается заметно лучше. Это тот же ранний выход, что мы разбирали вчера для функций.

11. Ловушка continue в while

А вот здесь continue кусается. Помните схему: он пропускает остаток тела и идёт к шагу. В цикле for шаг записан в заголовке, поэтому выполнится. А в while шаг лежит внутри тела — и если continue стоит до него, шага не будет:

// не запускайте — вкладка зависнет
let i = 0;

while (i < 5) {
  if (i === 2) {
    continue;     // i++ ниже никогда не выполнится — вечный цикл!
  }
  console.log(i);
  i++;
}

Программа напечатает 0 и 1, дойдёт до двойки и зависнет навсегда.

Отсюда практическое правило: continue дружит с for и опасен в while. Если очень нужен continue в while — не забудьте сделать шаг до него: 
let i = 0;

while (i < 5) {
  const current = i;
  i++;                    // шаг сразу, в самом начале
  if (current === 2) {
    continue;             // теперь безопасно
  }
  console.log(current);
}
Выглядит громоздко — и это ещё один довод взять for.

Цикл по строке

Массив — не единственное, по чему ходят циклом. У строки тоже есть length и доступ по индексу — мы видели это на дне 5, — значит, она перебирается точно так же:

const word = "Мары";

for (let i = 0; i < word.length; i++) {
  console.log(word[i]);   // М а р ы
}

Отсюда две задачи, которые встречаются в каждом учебнике. Перевернуть строку:

let reversed = "";
for (let i = word.length - 1; i >= 0; i--) {
  reversed += word[i];
}
console.log(reversed);   // "ыраМ"

Посчитать, сколько раз встретился символ:

const text = "Салам, dünýä!";
let count = 0;

for (let i = 0; i < text.length; i++) {
  if (text[i] === "а") {
    count++;
  }
}
console.log(count);   // 2
У строк есть оговорка, о которой стоит знать заранее. Длина считается не в буквах, а в единицах кодировки UTF-16. Для кириллицы, латиницы и туркменских букв разницы нет, а вот эмодзи и некоторые редкие символы занимают две позиции, и цикл по индексу разрежет их пополам. Пример будет на дне 16, подробный разбор — в курсе 2.

12. Вложенные циклы

Цикл внутри цикла — обычное дело. Классический пример, таблица умножения:

for (let i = 2; i <= 3; i++) {
  let row = "";
  for (let j = 1; j <= 4; j++) {
    row += `${i}x${j}=${i * j}  `;
  }
  console.log(row);
}
// 2x1=2  2x2=4  2x3=6  2x4=8
// 3x1=3  3x2=6  3x3=9  3x4=12

Как это читать: внутренний цикл прокручивается целиком на каждый шаг внешнего. Внешний сделал один шаг — внутренний отработал все четыре. Всего тело внутреннего выполнилось 2 × 4 = 8 раз.

Отсюда важное следствие: вложенные циклы перемножают работу. Два цикла по 1000 элементов — это миллион проходов. Три — миллиард, и программа зависнет уже по-настоящему, не из-за ошибки. С вложенностью глубже двух уровней стоит остановиться и подумать, нет ли другого способа.

Счётчики у вложенных циклов должны быть разными: i, j, k. Если взять один и тот же, внутренний цикл будет портить счётчик внешнего.

Вложенные циклы нужны там, где данные двумерные: строки и столбцы таблицы, клетки поля, все пары из списка. Вот вторая типовая задача — все пары студентов, кто с кем в команде:

const names = ["Аман", "Мерет", "Гүлнар"];

for (let i = 0; i < names.length; i++) {
  for (let j = i + 1; j < names.length; j++) {
    console.log(`${names[i]} и ${names[j]}`);
  }
}
// Аман и Мерет
// Аман и Гүлнар
// Мерет и Гүлнар

Обратите внимание на j = i + 1, а не j = 0. Так внутренний цикл начинает с элемента после текущего — и пары не повторяются. С j = 0 получилось бы девять строк вместо трёх, включая «Аман и Аман» и повтор «Мерет и Аман».

Вложенные циклы устроены как часовая и минутная стрелки. Пока часовая проходит одно деление, минутная делает полный оборот. Внешний цикл — часы, внутренний — минуты: на каждый шаг внешнего внутренний прокручивается целиком.

13. Метки

Есть одна задача, которую обычный break не решает: выйти сразу из обоих вложенных циклов. Обычный break выходит только из внутреннего.

Для этого циклу дают имя — метку:

outer: for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (i === 1 && j === 1) {
      break outer;     // выходим из ВНЕШНЕГО цикла
    }
    console.log(`${i}${j}`);
  }
}
// 00 01 02 10

Метка — это просто имя с двоеточием перед циклом. С continue она работает так же: continue outer начинает следующий проход внешнего цикла.

outer: for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (j === 1) {
      continue outer;   // бросаем внутренний, идём к следующему i
    }
    console.log(`${i}${j}`);
  }
}
// 00 10 20
Метки в настоящем коде встречаются редко, и это хорошо: код с ними читается тяжело. Почти всегда есть способ проще — вынести вложенные циклы в функцию и выйти через return (день 12). Знать метки нужно, чтобы понимать чужой код; писать — по возможности не стоит.

Три ошибки дня

Все они синтаксические и связаны с break, continue и метками:

Что написалиСообщение в Chrome
break вне цикла и switchSyntaxError: Illegal break statement
continue вне циклаSyntaxError: Illegal continue statement: no surrounding iteration statement
break nowhere — метки нетSyntaxError: Undefined label 'nowhere'

Все три — синтаксические, а значит, по правилу дня 8 отключают весь файл целиком. Появляются они почти всегда одинаково.

Первые две — когда правят чужой код и break или continue случайно оказываются снаружи после перестановки скобок. Полезно помнить, что break законен в двух местах: в любом цикле и в switch. А continue — только в цикле, в switch он бессмыслен.

Третья — обычная опечатка в имени метки или попытка сослаться на метку, которая объявлена в другом месте. Метка видна только тому циклу, перед которым стоит, и тому, что внутри него.

14. «Табель»: циклы в деле

Соберём день в программе. Здесь работают циклы for и while и оба способа управления.

const MIN_MARK = 2;
const MAX_MARK = 5;

const marks = [5, 4, 9, 3, 5, 0, 4, 5];

// 1. for с continue — отбираем годные оценки
const valid = [];
let skipped = 0;

for (let i = 0; i < marks.length; i++) {
  const mark = marks[i];

  if (mark < MIN_MARK || mark > MAX_MARK) {
    skipped++;
    continue;
  }

  valid.push(mark);
}

// 2. for — складываем то, что отобрали
let sum = 0;

for (let i = 0; i < valid.length; i++) {
  sum += valid[i];
}

console.log(`Засчитано ${valid.length}, пропущено ${skipped}, сумма ${sum}`);

// 3. for с break — ищем первую двойку
let firstFail = -1;

for (let i = 0; i < valid.length; i++) {
  if (valid[i] === MIN_MARK) {
    firstFail = i;
    break;
  }
}

if (firstFail === -1) {
  console.log("Двоек нет");
} else {
  console.log(`Первая двойка — оценка номер ${firstFail + 1}`);
}

// 4. while — сколько первых оценок дают половину суммы
let half = 0;
let taken = 0;

while (half < sum / 2) {
  half += valid[taken];
  taken++;
}

console.log(`Половину суммы дают первые ${taken} оценки (набрали ${half} из ${sum})`);
Засчитано 6, пропущено 2, сумма 26
Двоек нет
Половину суммы дают первые 4 оценки (набрали 17 из 26)

Обратите внимание на два места.

Первый цикл не считает, а отбирает. Он складывает годные оценки в отдельный массив valid, и все следующие циклы работают уже с ним. Так сделано нарочно: если считать сумму по одному массиву, а искать по другому, числа перестанут сходиться. Метод push мы разберём на дне 19, пока достаточно знать, что он добавляет в конец.

Четвёртый цикл — while, а не for, потому что число проходов заранее неизвестно: это и есть ответ задачи. И шаг taken++ стоит в теле — в while иначе никак.

Три опыта.

Первый. Уберите taken++ из четвёртого цикла. Кажется, что цикл станет вечным, — но он остановится. Объясните почему и откуда в выводе «первые 0 оценки (набрали 15 из 26)». Затем верните шаг.

Второй. Поменяйте continue в первом цикле на break и объясните, почему засчитано стало 2, а сумма — 9.

Третий. Замените в массиве 3 на 2 и проверьте, какой номер напечатает третий цикл. Подсказка: он считает по valid, а не по marks, — номера сдвинутся.

Циклы for...of и for...in из этой же главы разбираются на дне 11.

const arr = [5, 4, 3];

for (let i = 0; i < arr.length; i++) { }        // начало; условие; шаг
// условие проверяется ДО тела, шаг выполняется ПОСЛЕ
for (let i = arr.length - 1; i >= 0; i--) { }   // назад
for (let i = 0; i < 10; i += 2) { }             // через один
for (let i = 0, j = 5; i < j; i++, j--) { }     // два счётчика

let i = 0;
while (i < 3) { i++; }        // шаг в теле — не забыть!
i;                            // 3

let j = 10;
do { j++; } while (j < 3);    // хотя бы один раз; точка с запятой нужна
j;                            // 11

for (let k = 0; k < 10; k++) {
  if (k === 3) { break; }         // выйти из цикла целиком
  if (k % 2 === 0) { continue; }  // пропустить проход, идти к шагу
  console.log(k);                 // 1
}

// continue в while ДО шага = вечный цикл
// i <= arr.length = лишний проход с undefined
// i !== 10 при шаге += 3 = не остановится
// break вне цикла и switch → SyntaxError: Illegal break statement

outer: for (let a = 0; a < 3; a++) {   // метка
  for (let b = 0; b < 3; b++) {
    if (b === 1) { break outer; }      // выход из внешнего
  }
}

// вложенные циклы перемножают работу: 1000 x 1000 = миллион
  1. В каком порядке выполняются части for на первом проходе?
    Ответ Начало (один раз) → условие → тело → шаг → условие → тело → шаг… Шаг выполняется после тела, поэтому на первом проходе счётчик равен начальному значению.
  2. Чем do...while отличается от while?
    Ответ Условие проверяется после тела, поэтому тело выполнится хотя бы раз, даже если условие ложно с самого начала. У while в такой ситуации — ноль раз.
  3. Почему continue в while часто даёт вечный цикл?
    Ответ Потому что шаг в while лежит внутри тела. continue пропускает остаток тела — вместе с шагом. Счётчик не меняется, условие не становится ложным.
  4. Что напечатает цикл for (let i = 0; i <= arr.length; i++) по массиву из трёх элементов?
    Ответ Четыре значения: три элемента и undefined. Индексы кончаются на length - 1, а условие <= пускает лишний проход.
  5. Как выйти сразу из двух вложенных циклов?
    Ответ Поставить метку перед внешним циклом и написать break метка. Обычный break выходит только из внутреннего. Но чаще вложенные циклы выносят в функцию и выходят через return.
