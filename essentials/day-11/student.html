День 11. Перебор и ошибки

Выжимка лекции: for...of, for...in, try...catch, throw.

Главное

for...of даёт значения — для массивов и строк. for...in даёт имена свойств — для объектов. Разница в одном слове, результат совсем разный.
Ключи из for...in — всегда строки, даже для массива. Поэтому i + 1 даст "01", а не 1.

for...of

for (const mark of marks) { }     // значения массива
for (const letter of "Мары") { }  // символы строки

// объявляем через const: на каждом проходе НОВАЯ переменная
// break и continue работают как обычно
// индекса нет — если нужен, берите обычный for
for...of не работает с объектом, числом, null и undefined: TypeError: x is not iterable. Последние два — самая частая причина падения на реальных данных.

Если нужен номер

for (let i = 0; i < marks.length; i++) { }          // проще всего
for (const [i, mark] of marks.entries()) { }        // день 22; entries — курс 2

for...in

const user = { name: "Аман", age: 17 };

for (const key in user) {
  console.log(key, user[key]);    // значение — через скобки, не через точку
}

// или то же самое надёжнее:
for (const key of Object.keys(user)) { }   // день 21
Три ловушки for...in на массиве: ключи строками, видит лишние свойства (arr.meta), пропускает дырки в разреженном массиве. Правило: for...in — для объектов, for...of — для массивов.

try...catch...finally

try {
  JSON.parse(text);
} catch (e) {
  e.name;      // "SyntaxError"
  e.message;   // текст
  e.stack;     // где
} finally {
  // выполняется ВСЕГДА — прибраться
}

try { /* … */ } catch { /* … */ }   // без параметра — можно
При ошибке остаток try не выполняется — управление прыгает в catch немедленно. return в finally перебивает return из try — так не пишут.

throw

throw new Error("текст");           // не throw "текст"!
throw new TypeError("не число");
throw new RangeError("вне диапазона");

if (e instanceof RangeError) { /* своё */ } else { throw e; }   // чужое пробрасываем

Брошенная ошибка поднимается вверх по цепочке вызовов, пока не встретит catch. Остаток всех пройденных функций не выполнится. try ставят там, где знают, что делать с ошибкой, — не обязательно рядом с опасной строкой.

throw или return null

СитуацияЧем сообщать
«не нашлось», плохой ввод — так бываетreturn null
нарушен договор функции — так быть не должноthrow
Где нужен try: JSON.parse, запрос к серверу, хранилище браузера, чужая библиотека, своя функция с throw. Всё остальное — деление, свойства, преобразования — проверяется if.
Пустой catch — почти всегда ошибка: программа делает вид, что всё хорошо. try внутри цикла, а не вокруг него, иначе первая ошибка оборвёт перебор.
  1. Для массива [5, 4, 3] напишите for...of и for...in. Выведите значение и typeof — запишите, чем отличаются.
  2. Переберите объект { name: "Аман", age: 17, city: "Мары" } двумя способами: for...in и Object.keys с for...of.
  3. Напишите safeParse(text): возвращает объект или null, если строка не разбирается. Проверьте на правильном и испорченном JSON.
  4. Напишите checkAge(age), которая бросает TypeError для не-числа и RangeError для отрицательного. Поймайте обе и различите через instanceof.
