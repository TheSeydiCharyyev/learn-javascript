# День 11. Перебор и ошибки

<Subtitle>Выжимка лекции: `for...of`, `for...in`, `try...catch`, `throw`.</Subtitle>

## Главное

<Definition>
`for...of` даёт **значения** — для массивов и строк.
`for...in` даёт **имена свойств** — для объектов.
Разница в одном слове, результат совсем разный.
</Definition>

<KeyPoint>
Ключи из `for...in` — всегда **строки**, даже для массива.
Поэтому `i + 1` даст `"01"`, а не 1.
</KeyPoint>

## for...of

```js
for (const mark of marks) { }     // значения массива
for (const letter of "Мары") { }  // символы строки

// объявляем через const: на каждом проходе НОВАЯ переменная
// break и continue работают как обычно
// индекса нет — если нужен, берите обычный for
```

<Remember>
`for...of` **не работает** с объектом, числом, `null`
и `undefined`: `TypeError: x is not iterable`. Последние два —
самая частая причина падения на реальных данных.
</Remember>

## Если нужен номер

```js
for (let i = 0; i < marks.length; i++) { }          // проще всего
for (const [i, mark] of marks.entries()) { }        // день 22; entries — курс 2
```

## for...in

```js
const user = { name: "Аман", age: 17 };

for (const key in user) {
  console.log(key, user[key]);    // значение — через скобки, не через точку
}

// или то же самое надёжнее:
for (const key of Object.keys(user)) { }   // день 21
```

<Remember>
**Три ловушки `for...in` на массиве:** ключи строками, видит
лишние свойства (`arr.meta`), пропускает дырки в разреженном массиве.
Правило: `for...in` — для объектов, `for...of` — для массивов.
</Remember>

## Пять циклов

| Цикл | Когда |
| --- | --- |
| `for` | нужен индекс, шаг не единица, идём назад |
| `for...of` | просто пройти по массиву или строке |
| `for...in` | свойства объекта |
| `while` | число проходов неизвестно |
| `do...while` | хотя бы один раз |

## try...catch...finally

```js
try {
  JSON.parse(text);
} catch (e) {
  e.name;      // "SyntaxError"
  e.message;   // текст
  e.stack;     // где
} finally {
  // выполняется ВСЕГДА — прибраться
}

try { /* … */ } catch { /* … */ }   // без параметра — можно
```

<Remember>
При ошибке **остаток `try` не выполняется** — управление прыгает
в `catch` немедленно. `return` в `finally` перебивает
`return` из `try` — так не пишут.
</Remember>

## throw

```js
throw new Error("текст");           // не throw "текст"!
throw new TypeError("не число");
throw new RangeError("вне диапазона");

if (e instanceof RangeError) { /* своё */ } else { throw e; }   // чужое пробрасываем
```

Брошенная ошибка **поднимается вверх по цепочке вызовов**, пока не встретит
`catch`. Остаток всех пройденных функций не выполнится. `try` ставят
там, где знают, что делать с ошибкой, — не обязательно рядом с опасной строкой.

## throw или return null

| Ситуация | Чем сообщать |
| --- | --- |
| «не нашлось», плохой ввод — так бывает | `return null` |
| нарушен договор функции — так быть не должно | `throw` |

<NoteBox>
**Где нужен `try`:** `JSON.parse`, запрос к серверу,
хранилище браузера, чужая библиотека, своя функция с `throw`. Всё остальное —
деление, свойства, преобразования — проверяется `if`.
\
**Пустой `catch`** — почти всегда ошибка: программа делает вид,
что всё хорошо. **`try` внутри цикла**, а не вокруг него, иначе
первая ошибка оборвёт перебор.
</NoteBox>
