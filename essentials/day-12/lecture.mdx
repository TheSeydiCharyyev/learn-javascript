## 1. Зачем функции {#why}

Мы писали функции с третьего дня — в «Табеле» их накопилось уже несколько. Сегодня наконец
разберём, как они устроены.

Функция решает три задачи сразу.

**Первая — не повторяться.** Один и тот же расчёт в трёх местах — это три места,
где придётся править, если формула изменится. И три шанса забыть одно из них.

**Вторая — дать имя действию.** Строка `const valid = selectValid(marks);`
читается как предложение. Пять строк цикла с условием на её месте потребуют разбора.

**Третья — разделить задачу на части.** Большую программу целиком в голове
не удержать. Программу из десяти функций по пять строк — вполне: думаешь об одной, остальные
просто работают.

<Analogy>
Функция — как кнопка на приборе. Чтобы включить свет, вы не думаете о проводке —
вы нажимаете выключатель. Тот, кто делал выключатель, думал о проводке один раз.
Хорошая функция устроена так же: снаружи понятное имя, внутри — подробности,
о которых можно забыть.
</Analogy>

## 2. Объявление и вызов {#declare}

Самая простая форма выглядит так:

```js
function greet(name) {
  return `Салам, ${name}!`;
}

console.log(greet("Аман"));   // "Салам, Аман!"
```

Разберём по частям:

| Часть | Название | Что делает |
| --- | --- | --- |
| `function` | ключевое слово | говорит «дальше функция» |
| `greet` | имя | по нему её вызывают |
| `(name)` | параметры | что функция принимает |
| `{ ... }` | тело | что она делает |
| `return` | возврат | что она отдаёт |

<Important>
Объявить функцию и вызвать её — **две разные вещи**. Объявление ничего
не выполняет, оно только заводит имя. Работа начинается при вызове — когда после имени
стоят **круглые скобки**.

```js
greet;          // функция как значение, ничего не произошло
greet("Аман");  // вот теперь вызвали
```

Забытые скобки — одна из самых частых ошибок, и коварна она тем, что не падает:
вы просто получаете саму функцию вместо результата.
</Important>

## 3. Параметры и аргументы {#params}

Два слова, которые постоянно путают, хотя разница простая:

- **параметр** — имя в объявлении. Их пишут один раз;
- **аргумент** — значение при вызове. Их подставляют каждый раз новые.

```js
function add(x, y) {     // x и y — параметры
  return x + y;
}

add(2, 3);               // 2 и 3 — аргументы
add(10, 20);             // а тут другие
```

<Scheme src="scheme-params.svg">Вызов передаёт значения, функция даёт им свои имена и возвращает результат</Scheme>

Последняя строка схемы важна: **связь идёт по порядку, а не по именам**.
Вызов `add(y, x)` с переменными `x = 2` и `y = 3`
передаст 3 в параметр `x` — совпадение имён ничего не значит.

<Mistake>
Отсюда классическая ошибка — перепутанный порядок аргументов:

```js
function divide(a, b) {
  return a / b;
}

divide(2, 10);   // 0.2 — а хотели 5
```

Ошибки нет, программа работает, число неверное. С двумя числами это заметно, а вот
`createUser("Мары", "Аман")` вместо `createUser("Аман", "Мары")`
можно не заметить неделю. Лечится либо очень понятными именами, либо передачей
объекта вместо списка — приём из дня 22.
</Mistake>

## 4. Когда аргументов не столько {#count}

Язык не проверяет, сколько аргументов вы передали. Хоть больше, хоть меньше — вызов
состоится:

```js
function add(x, y) {
  return x + y;
}

add(2, 3);        // 5
add(2, 3, 4);     // 5   — лишний аргумент молча выброшен
add(2);           // NaN — y оказался undefined, 2 + undefined
add();            // NaN
```

Недостающие параметры получают `undefined` — то самое из дня 5. И дальше всё
зависит от того, что с ними делают: в арифметике получится `NaN`, в строке —
слово «undefined», в условии — ложь.

<Important>
Это одна из главных особенностей языка: **вызов с неверным числом аргументов
не является ошибкой**. Ни предупреждения, ни сообщения — только странный
результат позже. Поэтому важные функции проверяют свои аргументы сами:

```js
function add(x, y) {
  if (typeof x !== "number" || typeof y !== "number") {
    throw new TypeError("add ждёт два числа");
  }
  return x + y;
}
```

Это вчерашний `throw` в его типичном применении: функция сообщает, что
нарушен её договор.
</Important>

Узнать, сколько параметров объявлено, можно через свойство `length`:

```js
console.log(add.length);   // 2
```

### Когда параметров становится много

С двумя параметрами порядок помнится. С пятью — уже нет, и вызов превращается в загадку:

```js
createStudent("Аман", "Мары", 17, 5, true);
// кто из них что? третий — возраст или класс?
```

Плюс к этому: чтобы передать пятый аргумент, придётся передать и все предыдущие, даже если
они не нужны.

Решение — **передать один объект вместо списка**:

```js
createStudent({
  name: "Аман",
  city: "Мары",
  age: 17,
  grade: 5,
  isActive: true,
});
```

Теперь у каждого значения есть подпись, порядок перестал иметь значение, а ненужные поля
можно просто не писать. Внутри функции их достают как свойства:

```js
function createStudent(options) {
  console.log(options.name, options.age);
  return options;
}
```

Есть и более короткая запись — **деструктуризация прямо в параметрах**,
которую мы встречали на дне 3:

```js
function createStudent({ name, age }) {
  console.log(name, age);          // сразу как отдельные переменные
}
```

<ProTip>
Практическое правило: **до трёх параметров — обычный список, дальше — объект**.
Особенно если среди них есть логические значения: `true` в вызове
не говорит читателю ничего, а `isActive: true` говорит всё.
</ProTip>

Объекты разберём на дне 21, деструктуризацию — на дне 22. Способы принять любое число
аргументов и задать значения по умолчанию — на дне 14.

## 5. return: отдать результат {#return}

Функция обычно что-то считает — и результат надо отдать наружу. Это делает
`return`:

```js
function double(n) {
  return n * 2;
}

const result = double(21);   // 42
```

Возвращать можно что угодно: число, строку, логическое значение, массив, объект и даже
другую функцию.

```js
function makeStudent(name, marks) {
  return { name: name, marks: marks };   // вернули объект
}
```

А вот чего **нельзя** — вернуть несколько значений через запятую. Для этого
собирают массив или объект:

```js
function stats(numbers) {
  return { count: numbers.length, sum: 10 };   // так
}
```

## 6. Что будет без return {#noreturn}

Функция без `return` тоже работает — просто возвращает `undefined`:

```js
function log(message) {
  console.log(message);
  // return нет
}

const x = log("привет");
console.log(x);   // undefined
```

И это нормально: не всякая функция должна что-то отдавать. Есть два сорта функций,
и различать их полезно:

| Сорт | Что делает | Пример |
| --- | --- | --- |
| считает и возвращает | не меняет ничего снаружи | `average`, `verdict` |
| делает действие | выводит, меняет страницу, сохраняет | `console.log`, `showError` |

Первый сорт удобнее: его легко проверить — дал значения, сравнил результат. Второй нужен,
чтобы программа хоть что-то делала. Плохо, когда функция смешивает оба и при этом называется
так, будто только считает.

<Compare>
<Wrong label="Смешала">
```js
function average(marks) {
  let sum = 0;
  for (const m of marks) {
    sum += m;
  }
  const avg = sum / marks.length;
  console.log("средний:", avg);
  return avg;
}
```

Имя обещает только расчёт, а функция ещё и печатает. Вызвали её в цикле
по сотне студентов — получили сто строк в консоли, которых никто не просил.
</Wrong>

<Right label="Разделила">
```js
function average(marks) {
  let sum = 0;
  for (const m of marks) {
    sum += m;
  }
  return sum / marks.length;
}

console.log("средний:", average(marks));
```

Считает — функция, печатает — тот, кто вызвал. Теперь `average`
годится и для вывода, и для расчёта, и для проверки.
</Right>
</Compare>

Действие внутри функции называют **побочным эффектом**: что-то изменилось
снаружи, помимо возвращённого значения. Вывод в консоль, запись на страницу, изменение
внешней переменной — всё это побочные эффекты.

<ProTip>
Правило, к которому стоит привыкать: **функция либо считает, либо действует**.
Смешивать можно, но тогда и имя должно об этом говорить —
`calculateAndShowAverage`. А если в имени появилось «и», вспомните правило
из раздела 12: работ стало больше одной.
</ProTip>

<Mistake>
Пустой `return` — тоже `undefined`. И тут прячется ловушка
с переносом строки, про которую мы говорили ещё на дне 3:

```js
function getCity() {
  return
    "Мары";
}
getCity();   // undefined!
```

Движок поставил точку с запятой сразу после `return` — сработала автоматическая
вставка из дня 3. **Значение пишут на той же строке, что и `return`.**
</Mistake>

## 7. return выходит немедленно {#exit}

Важное свойство: `return` не просто отдаёт значение — он **заканчивает
функцию прямо здесь**. Всё, что ниже, не выполнится:

```js
function check(mark) {
  console.log("проверяю");
  return mark >= 2;
  console.log("сюда не дойдём");   // мёртвый код
}
```

Обратите внимание: это **не ошибка**. Программа работает, просто последняя
строка бессмысленна. Firefox покажет в консоли предупреждение
«unreachable code after return statement», Chrome промолчит вовсе.

Зато из этого свойства растёт приём, который мы видели на дне 9, — **ранний
выход**. Отсеиваем всё плохое сверху, а полезную работу пишем без вложенности:

<Compare>
<Wrong label="Через else">
```js
function grade(score) {
  if (score >= 90) {
    return "5";
  } else {
    if (score >= 75) {
      return "4";
    } else {
      return "3";
    }
  }
}
```
</Wrong>

<Right label="С ранним выходом">
```js
function grade(score) {
  if (score >= 90) return "5";
  if (score >= 75) return "4";
  return "3";
}
```
</Right>
</Compare>

Справа `else` не нужен вовсе: если первый `return` сработал,
до второго дело не дойдёт. Читается как список правил сверху вниз.

<ProTip>
В таком виде однострочные `if` без фигурных скобок допустимы — это
единственное исключение из правила дня 9. Работает оно потому, что тело состоит ровно
из одного `return` и дописать туда вторую строку просто не получится
незаметно. Если сомневаетесь — ставьте скобки, хуже не будет.
</ProTip>

вчера поднималась ошибка. Только теперь по ней идут не ошибки, а результаты.

## 8. Что внутри, то внутри {#scope}

Переменные, объявленные в функции, снаружи не видны. Это область видимости функции
из дня 4:

```js
function calculate() {
  const secret = 42;
  return secret;
}

calculate();
console.log(secret);   // ReferenceError: secret is not defined
```

А вот наружу функция смотрит свободно — видит всё, что объявлено вокруг неё:

```js
const TAX = 0.05;

function withTax(price) {
  return price + price * TAX;   // TAX видна, она снаружи
}
```

Направление одностороннее: **внутрь видно, наружу нет**. Мы это уже
формулировали на дне 4; теперь понятно, зачем: функция получается замкнутой коробкой,
о содержимом которой остальной программе знать не нужно.

<Important>
Отсюда правило хорошей функции: **всё, что ей нужно, она получает через
параметры**, а не берёт из внешних переменных. Такую функцию можно перенести
в другой файл, и она продолжит работать. Функция, которая лезет наружу за данными,
привязана к своему месту.
\
\
Исключение — константы-настройки вроде `TAX` или `MAX_MARK`:
их берут снаружи, и это нормально.
</Important>

### Параметр — своя переменная функции

Параметр — новая переменная внутри функции, в которую при вызове положили значение
аргумента. Даже если её имя совпадает с внешней переменной, это другая переменная:

```js
let count = 1;

function addOne(count) {
  count = count + 1;   // меняется параметр — переменная самой функции
  return count;
}

addOne(count);   // 2
count;           // 1 — внешняя переменная не изменилась
```

С массивами и объектами тоньше: в параметр попадает ссылка, и если функция поменяет
содержимое массива, это будет видно снаружи. Подробно — на дне 19.

## 9. Вызов до объявления {#hoisting}

Мы разбирали это на дне 4, но теперь тема на своём месте. Функция, объявленная словом
`function`, поднимается **целиком** — её можно вызвать выше того
места, где она написана:

```js
console.log(greet("Аман"));   // работает!

function greet(name) {
  return `Салам, ${name}!`;
}
```

Это свойство даёт свободу в расположении кода: можно сначала написать основную логику,
а вспомогательные функции вынести вниз файла. Многие так и делают — главное сверху,
подробности снизу.

А вот функция, положенная в переменную, подчиняется правилам переменной и так не умеет:

```js
hi();                        // ReferenceError: Cannot access 'hi' before initialization
const hi = function () { };
```

Так пишет Chrome, когда эти строки стоят в файле. В консоли сообщение короче —
`hi is not defined`, но смысл тот же: на этой строке значения ещё нет.

Формы записи функций разберём завтра, на дне 13.

## 10. Функция — это значение {#value}

Мы говорили об этом на дне 3: функция — не особая конструкция языка, а **обычное
значение**, просто такое, которое умеют вызывать. Значит, с ней можно делать всё
то же, что с числом или строкой:

```js
function add(a, b) { return a + b; }

const sum = add;             // положить в переменную
console.log(sum(2, 3));      // 5 — работает под новым именем

const ops = [add];           // положить в массив
console.log(ops[0](2, 3));   // 5

console.log(typeof add);     // "function"
console.log(add.name);       // "add" — у функции есть имя
console.log(add.length);     // 2 — и число параметров
```

И самое важное следствие: функцию можно **передать в другую функцию**:

```js
function twice(fn, value) {
  return fn(fn(value));
}

function increment(n) { return n + 1; }

console.log(twice(increment, 5));   // 7
```

Функция `twice` не знает, что именно она вызывает, — ей передали.
У такой переданной функции есть название: её зовут **колбэком**
(от английского *callback*, «обратный вызов»). Слово вы услышите постоянно,
и означает оно ровно это: функция, которую передали, чтобы её вызвали.

Вот как колбэк выглядит в настоящем коде — это методы массива, которые мы разберём
на дне 20:

```js
const marks = [5, 4, 3, 5];

const doubled = marks.map(double);            // вызовет double для каждого
const fives = marks.filter(isFive);           // оставит те, где isFive вернул true

function double(n) { return n * 2; }
function isFive(n) { return n === 5; }
```

Метод `map` не знает, что делать с числами, — он умеет только обойти массив
и собрать результаты. Что именно делать, решает переданная функция. Так один метод годится
для любой задачи.

То же самое в обработчиках событий — день 27:

{/* ahead-ok: день 27 */}

```js
button.addEventListener("click", handleClick);   // передали, а вызовут потом

function handleClick() {
  console.log("нажали");
}
```

<Mistake>
Главная ловушка с колбэками — **лишние скобки**. Передавать надо саму
функцию, а не результат её вызова:
{/* ahead-ok: день 27 */}

```js
button.addEventListener("click", handleClick);     // правильно: передали функцию
button.addEventListener("click", handleClick());   // ошибка: вызвали сразу,
                                                   // а передали undefined
```

Во второй строке функция выполнится *немедленно*, ещё до всякого нажатия,
а обработчиком станет то, что она вернула. Если это `undefined` — при нажатии
не случится ничего.
</Mistake>

## 11. Как называть функции {#naming}

Правила для имён те же, что на дне 4, но есть свои договорённости.

| Что делает функция | Как называть | Пример |
| --- | --- | --- |
| совершает действие | глагол | `showError`, `saveData` |
| что-то вычисляет и возвращает | `get`, `calc`, существительное | `getAverage`, `average` |
| отвечает «да / нет» | `is`, `has`, `can` | `isValidMark`, `hasErrors` |
| создаёт и возвращает объект | `create`, `make` | `createStudent` |

<ProTip>
Проверка на хорошее имя: **можно ли по одному имени сказать, что функция вернёт,
не заглядывая внутрь?** `isValidMark(9)` — очевидно
`true` или `false`. `check(9)` — непонятно:
вернёт ответ, бросит ошибку, выведет сообщение?
\
\
И второй признак: **если в имени есть «и» — функция делает слишком много**.
`validateAndSave` просится разделиться на две.
</ProTip>

## 12. Разбиваем задачу на функции {#split}

Главный навык дня — не синтаксис, а умение разделить задачу. Правило простое:
**одна функция — одна работа**.

Как понять, что работа одна? Три признака.

**Первый: имя описывает всё, что делает функция**, без союза «и».

**Второй: функцию можно описать одним предложением.** Если объяснение
занимает абзац — внутри спрятаны несколько функций.

**Третий: функция помещается на экран.** Жёсткого предела нет, но если
приходится прокручивать, чтобы увидеть её целиком, стоит поискать, что вынести.

<Compare>
<Wrong label="Одна функция на всё">
```js
function processMarks(marks) {
  const valid = [];
  for (const m of marks) {
    if (m >= 2 && m <= 5) {
      valid.push(m);
    }
  }
  let sum = 0;
  for (const m of valid) {
    sum += m;
  }
  const avg = sum / valid.length;
  let v;
  if (avg >= 4.5) v = "отличник";
  else v = "хорошист";
  return `${avg} — ${v}`;
}
```
</Wrong>

<Right label="Четыре функции">
```js
function isValidMark(m) {
  return m >= 2 && m <= 5;
}

function selectValid(marks) { /* … */ }

function average(numbers) { /* … */ }

function verdict(avg) { /* … */ }

function report(marks) {
  const valid = selectValid(marks);
  const avg = average(valid);
  return `${avg} — ${verdict(avg)}`;
}
```
</Right>
</Compare>

Справа кода формально больше. Зато последняя функция читается как оглавление: отобрать,
посчитать, оценить. И каждую часть можно проверить отдельно — `average([5, 4])`
должна дать 4.5, и это видно за секунду.

<Scheme src="scheme-split.svg">Разделение не убирает работу — оно делает каждую часть проверяемой</Scheme>

### Как разделять на практике

Разбивать заранее сложно — обычно сначала пишут как получится, а потом выносят. Вот порядок,
который работает.

**Шаг 1: найдите в коде комментарии.** Если вы написали
`// отбираем годные`, а ниже пять строк — это готовая функция, и имя у неё
уже придумано.

**Шаг 2: найдите повторы.** Два похожих куска — повод вынести их в одну
функцию с параметром, который их различает.

**Шаг 3: найдите вложенность.** Цикл внутри цикла внутри условия — почти
всегда признак, что внутренняя часть просится наружу.

```js
// было: цикл с условием внутри цикла
for (const student of students) {
  let sum = 0;
  for (const mark of student.marks) {
    if (mark >= 2 && mark <= 5) {
      sum += mark;
    }
  }
  console.log(sum);
}

// стало: внутренность вынесена
for (const student of students) {
  console.log(sumValid(student.marks));
}
```

Внешний цикл стал на четыре строки короче и читается сразу. А `sumValid` теперь
можно вызвать где угодно ещё.

<ProTip>
Частый вопрос: не будет ли программа работать медленнее, если разбить её на много функций?
Практически — нет. Вызов функции стоит ничтожно мало, а движки браузеров умеют
подставлять короткие функции прямо в место вызова. **Разбивайте ради
понятности**; на скорости это не скажется.
</ProTip>

## 13. Рекурсия и её предел {#recursion}

Функция может вызвать саму себя. Это называется **рекурсией**:

```js
function factorial(n) {
  if (n <= 1) {
    return 1;          // условие выхода
  }
  return n * factorial(n - 1);
}

console.log(factorial(5));   // 120
```

Работает это так: `factorial(5)` ждёт `factorial(4)`, тот ждёт
`factorial(3)` и так до единицы. Потом результаты возвращаются обратно, перемножаясь.

<Important>
У любой рекурсии **обязано быть условие выхода**, и оно должно достигаться.
Иначе вызовы будут громоздиться друг на друга, пока не кончится место:

```js
function forever() {
  return forever();
}
forever();   // RangeError: Maximum call stack size exceeded
```

Это вчерашний вечный цикл в новой одежде. Хорошая новость: в отличие от цикла, браузер
тут не зависает — он честно падает с ошибкой примерно через десять тысяч вызовов.
</Important>

В Essentials рекурсия почти не понадобится: всё, что мы делаем, проще записать циклом.
Знать её нужно, потому что она незаменима для древовидных данных — например, для обхода
страницы, с которым мы столкнёмся на дне 24.

## 14. Семь ошибок дня {#errors}

| Что написали | Сообщение в Chrome | Когда |
| --- | --- | --- |
| `const n = 5; n();` | `TypeError: n is not a function` | при работе |
| `obj.go()`, а метода нет | `TypeError: obj.go is not a function` | при работе |
| `function f(1) { }` | `SyntaxError: Unexpected number` | до запуска |
| `function f(a b) { }` | `SyntaxError: Unexpected identifier 'b'` | до запуска |
| `function () { }` как объявление | `SyntaxError: Function statements require a function name` | до запуска |
| `console.log(1, 2;` | `SyntaxError: missing ) after argument list` | до запуска |
| рекурсия без выхода | `RangeError: Maximum call stack size exceeded` | при работе |

Плюс восьмое — не ошибка, а предупреждение: **код после `return`**.
Firefox напишет «unreachable code after return statement», Chrome не скажет ничего.
Программа работает, просто часть кода мертва.

<Mistake>
Отдельно про `x is not a function` — это **самое частое сообщение**
при работе с функциями, и причин у него три:

1. опечатка в имени: `consle.log`, `toUperCase`;
2. обращение к тому, чего нет: `obj.method` вернуло `undefined`,
   а `undefined` вызвать нельзя;
3. имя занято чем-то другим: переменная затёрла функцию.

По правилу дня 5 смотрите **влево от скобок**: сообщение называет то,
что оказалось не функцией.
</Mistake>

Отдельный случай — функция, которой не дали обязательный аргумент. Язык это не проверяет,
но некоторые встроенные функции проверяют сами:

```js
Object.create();
// TypeError: Object prototype may only be an Object or null: undefined
```

Firefox в таком случае скажет понятнее: «Object.create requires at least 1 argument».
Как мы уже видели на днях 4 и 8, **формулировки у браузеров разные**,
а страницы MDN озаглавлены по версии Firefox.

Свои функции можно научить тому же — проверять и сообщать понятно:

```js
function makeReport(name, marks) {
  if (name === undefined || marks === undefined) {
    throw new TypeError("makeReport требует два аргумента: имя и оценки");
  }
  // ...
}

makeReport("Аман");
// TypeError: makeReport требует два аргумента: имя и оценки
```

Сравните с тем, что было бы без проверки: функция дошла бы до цикла по
`undefined` и упала с `TypeError: marks is not iterable` —
сообщением из вчерашнего дня, по которому не сразу поймёшь, что аргумент просто забыли.

Такая проверка нужна не каждой функции — только тем, которые вызывают из многих мест
или отдают другим людям. Внутренним помощникам вроде `countFives` она
ни к чему.

## 15. «Табель»: собираем из функций {#tabel}

Перепишем программу так, чтобы каждая часть стала отдельной функцией. Это и есть главное
упражнение дня.

```js
const MIN_MARK = 2;
const MAX_MARK = 5;

function isValidMark(mark) {
  return typeof mark === "number"
    && !Number.isNaN(mark)
    && mark >= MIN_MARK
    && mark <= MAX_MARK;
}

function selectValid(marks) {
  const valid = [];
  for (const mark of marks) {
    if (isValidMark(mark)) {
      valid.push(mark);
    }
  }
  return valid;
}

function average(numbers) {
  if (numbers.length === 0) {
    return 0;                     // защита от деления на ноль
  }
  let sum = 0;
  for (const n of numbers) {
    sum += n;
  }
  return sum / numbers.length;
}

function verdict(avg) {
  if (avg >= 4.5) return "отличник";
  if (avg >= 3.5) return "хорошист";
  if (avg >= 2.5) return "троечник";
  return "надо подтянуть";
}

function countFives(marks) {
  let n = 0;
  for (const mark of marks) {
    if (mark === MAX_MARK) {
      n++;
    }
  }
  return n;
}

function makeReport(name, marks) {
  const valid = selectValid(marks);
  const avg = average(valid);

  return `${name}: ${valid.length} из ${marks.length} оценок, `
    + `средний ${avg.toFixed(2)} — ${verdict(avg)}, `
    + `пятёрок ${countFives(valid)}`;
}

console.log(makeReport("Аман", [5, 4, 9, 3, 5, 0, 4, 5]));
console.log(makeReport("Мерет", [3, 3, 4]));
console.log(makeReport("Гүлнар", [9, 0, "пять"]));
console.log(makeReport("Сапар", [5, 5, 4, 5]));
```

<ResultBox>
Аман: 6 из 8 оценок, средний 4.33 — хорошист, пятёрок 3\
Мерет: 3 из 3 оценок, средний 3.33 — троечник, пятёрок 0\
Гүлнар: 0 из 3 оценок, средний 0.00 — надо подтянуть, пятёрок 0\
Сапар: 4 из 4 оценок, средний 4.75 — отличник, пятёрок 3
</ResultBox>

Сравните с тем, что было вчера. Раньше все строки шли подряд и работали с одним студентом.
Теперь программа обрабатывает четверых одной строкой на каждого — **потому что логика
вынесена в функции**. Это и есть та выгода, ради которой всё затевалось.

Заметьте и другое: четыре студента подобраны так, что **каждая ветка
`verdict` хоть раз сработала**. Это не случайность — так и проверяют
функции с несколькими ветками. Если какая-то ветка не выполнилась ни разу, вы не знаете,
работает ли она.

Обратите внимание на четыре решения.

**`isValidMark` возвращает `true` или `false`** —
имя с `is` обещает именно это. Внутри — одно длинное условие, вынесенное из цикла
по правилу дня 7.

**`average` защищена от пустого массива.** Без первой строки
`0 / 0` дало бы `NaN` — как у Гүлнар, у которой ни одной годной оценки.
Одна проверка, и вместо заразного `NaN` честный ноль.

**`verdict` написана ранним выходом** — четыре строки вместо
лестницы с `else`.

**`makeReport` ничего не считает сама** — только собирает строку
из результатов. Она читается как оглавление программы.

<TryIt>
Три опыта.
\
\
**Первый.** Вызовите каждую функцию отдельно и проверьте:
`isValidMark(9)`, `average([5, 4])`, `verdict(4.5)`,
`countFives([5, 5, 4])`. Так проверяют функции — по одной.
\
\
**Второй.** Уберите из `average` проверку на пустой массив
и посмотрите, что напечатается для Гүлнар.
\
\
**Третий.** Поменяйте местами первые две ветки в `verdict`
и найдите студента, у которого изменился вердикт. Он ровно один — объясните,
почему остальных трёх перестановка не затронула.
</TryIt>

```js
add(2, 3, 4);   // 5   лишние молча выброшены

function f() { return        // ЛОВУШКА: точка с запятой вставится

// ранний выход вместо лестницы else
function grade(s) {

  if (s >= 75) return "4";

// область: внутрь видно, наружу нет

greet();  function greet() { }   // работает — поднимается целиком

```

<Selfcheck>
1. Чем параметр отличается от аргумента?
   <Answer>Параметр — имя в объявлении функции, пишется один раз. Аргумент — значение
   при вызове, каждый раз новое. Связываются они по порядку, а не по именам.</Answer>
2. Что вернёт `add(2)`, если функция объявлена как `add(x, y)`?
   <Answer>`NaN`. Недостающий параметр `y` получит
   `undefined`, а `2 + undefined` даёт `NaN`.
   Ошибки при этом не будет — язык не проверяет число аргументов.</Answer>
3. Почему код после `return` не выполняется и является ли это ошибкой?
   <Answer>`return` завершает функцию немедленно. Это не ошибка: программа
   работает, просто часть кода мертва. Firefox покажет предупреждение,
   Chrome промолчит.</Answer>
4. Почему `greet()` работает до объявления, а `hi()` — нет?
   <Answer>Объявление через `function` поднимается целиком, вместе с телом.
   Функция в переменной подчиняется правилам переменной и попадает в мёртвую зону
   из дня 4.</Answer>
5. Как понять, что функция делает слишком много?
   <Answer>Три признака: в имени есть союз «и»; объяснить её одним предложением
   не получается; она не помещается на экран. Любого из трёх достаточно,
   чтобы поискать, что вынести.</Answer>
</Selfcheck>
