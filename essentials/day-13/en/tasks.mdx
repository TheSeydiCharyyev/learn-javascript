# Day 13. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder `day-13`.</Subtitle>

## Warm-up

<Task title="1. One function, three forms" level="easy" time="6">
<Goal>write the same thing in three ways.</Goal>

The function “returns the square of a number”. Write it:

- as a declaration with `function`;
- as a function expression;
- as an arrow function, as short as possible.

Call each one and print the `.name` of each.

<Criteria>
- all three work and give the same result;
- the arrow function has no extra parentheses and no `return`;
- the second and third have a semicolon at the end — it is explained why;
- the three values of `.name` are written down.
</Criteria>
</Task>

<Task title="2. Shorten to the limit" level="easy" time="7">
<Goal>go through all the steps of shortening.</Goal>

Shorten each function as much as the language allows. Write down all the
intermediate forms.

```js
const a = function (n) { return n + 1; };
const b = function (x, y) { return x * y; };
const c = function () { return "hello"; };
const d = function (n) { const m = n * 2; return m + 1; };
```

<Criteria>
- all the intermediate forms are written down for each one;
- `b` and `c` kept their parentheses — it is explained why;
- `d` kept its block — it is explained why;
- all four are checked with a call after shortening.
</Criteria>
</Task>

<Task title="3. Predict first: what is returned" level="easy" time="7">
<Goal>catch the traps of curly braces.</Goal>

Predict the result of each call, then check.

```js
const f1 = (n) => n * 2;
const f2 = (n) => { n * 2; };
const f3 = (n) => { return n * 2; };
const f4 = () => { a: 1 };
const f5 = () => ({ a: 1 });

console.log(f1(5), f2(5), f3(5), f4(), f5());
```

<Criteria>
- five predictions are written down before checking;
- it is explained why `f2` and `f4` give
  `undefined`;
- it is written down how `{` in `f4` differs from `{`
  in `f5`;
- the rule about curly braces is stated in one sentence.
</Criteria>
</Task>

## Main tasks

<Task title="4. Hoisting in practice" level="medium" time="12">
<Goal>see three different outcomes of the same code.</Goal>

Type three files; in each one the call stands **before** the definition. Write down
what happened.

```js
// file A
add(2, 3);
function add(a, b) { return a + b; }
```

```js
// file B
add(2, 3);
const add = (a, b) => a + b;
```

```js
// file C
add(2, 3);
var add = function (a, b) { return a + b; };
```

<Criteria>
- for all three the result or the exact text of the error is written down;
- it is explained why B and C have **different** kinds of error;
- it is explained why A works — with a reference to day 4;
- it is written down which of the three you would choose and why.
</Criteria>
</Task>

<Task title="5. Unfold and fold" level="medium" time="13">
<Goal>learn to read dense code with arrows.</Goal>

Unfold this line into separate named functions — so that the result
does not change:

```js
const result = marks.filter(m => m >= 4).map(m => m * 10);
```

Then the other way around: fold this code into one line with arrows.

```js
function isLow(m) {
  return m < 3;
}
function toText(m) {
  return "mark " + m;
}
const low = marks.filter(isLow);
const texts = low.map(toText);
```

<Criteria>
- both tasks are done, the results match the original ones;
- checked on the array `[5, 4, 3, 5, 2]`, the results are written down;
- it is written down which version of each task reads better and why;
- it is explained why there are no parentheses after the name in `filter(isLow)`.
</Criteria>
</Task>

<Task title="6. Choose the form" level="medium" time="12">
<Goal>apply the rule of choice to real cases.</Goal>

For each task choose a form and explain the choice in one sentence.
Then write it.

1. the function `calculateTotal`, 15 lines, called from four places;
2. the check “the mark is greater than 3” to pass into `filter`;
3. the method `getName` of the object `student`;
4. a button click handler, three lines;
5. a function that must be called at the start of the file and written at the end.

<Criteria>
- a form is chosen and explained for all five;
- in item 3 the chosen form is **not** an arrow — the reason is named;
- in item 5 a declaration is chosen — the reason is named;
- all five are written and work.
</Criteria>
</Task>

<Task title="7. The “Report card” on arrows" level="medium" time="13">

## Starred tasks

<Task title="8. Hide the counter" level="hard" time="10">
<Goal>build an immediately invoked function and understand what it is for.</Goal>

Write `counter` with an IIFE: the counter variable is hidden inside,
and only `inc`, `dec` and `get` are available outside.

<Example>
```js
counter.inc();
counter.inc();
counter.dec();
counter.get();        // 1
typeof count;         // "undefined" — the variable cannot be reached
```
</Example>

<Hint>
The IIFE returns an object with three arrow functions. The variable is declared
inside the function, before `return`.
</Hint>

<Criteria>
- all three methods work;
- `typeof count` outside gives `"undefined"`;
- it is checked that the counter cannot be spoiled directly;
- it is explained why this is better than an ordinary variable next to the functions.
</Criteria>
</Task>

<Task title="9. Six traps" level="hard" time="10">
<Goal>bring together everything that behaves unexpectedly today.</Goal>

For each fragment **first** write down a prediction, then check
and explain the difference in one sentence.

{/* ahead-ok: course 2 */}

```js
// 1
const f = (n) => { n * 2; };
console.log(f(5));

// 2
const g = () => { a: 1 };
console.log(g());

// 3
const h = (a)
  => a + 1;
console.log(h(1));

// 4
const add = n, m => n + m;

// 5
const obj = { name: "Aman", say: () => this.name };
console.log(obj.say());

// 6
const count = () => arguments.length;
console.log(count(1, 2, 3));
```

<Hint>
There are three errors, but they are different. Two fragments are a `SyntaxError`: they break
**the whole file**, move them out separately. One more crashes only when called.
The remaining three quietly give something other than it seems.
</Hint>

<Criteria>
- the predictions are written down before running;
- all three errors are found, the text of each one is written down;
- it is explained how the two `SyntaxError`s differ from the third error
  in their consequences;
- for fragment 4 it is explained why the message is not about the arrow;
- for fragment 5 it is written down what your browser printed — and noted
  that the result depends on the environment;
- for the rest the cause is named: the braces switch off the return, a block instead of an object,
  a line break before the arrow, no `this`, no `arguments`;
- fragments 1, 2, 3 and 4 are rewritten correctly.
</Criteria>
</Task>
