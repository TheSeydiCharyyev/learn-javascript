1. Три способа записать одно и то же

Вчера мы писали функции одним способом. Сегодня узнаем ещё два — и все три делают ровно одно:

// 1. Объявление — вчерашнее
function add(a, b) {
  return a + b;
}
// 2. Функция-выражение
const add = function (a, b) {
  return a + b;
};
// 3. Стрелочная функция
const add = (a, b) => a + b;

Все три вызываются одинаково — add(2, 3) — и все три возвращают 5. Зачем тогда три?

Затем, что у них разное поведение в мелочах, и каждая форма удобнее в своём месте. Вот вся разница на одной картинке — к ней мы будем возвращаться весь урок:

Разберём по очереди, а в конце соберём правило выбора.

Главное, что стоит понять сегодня: вторая и третья формы — это не «объявление функции», а обычное присваивание. Справа от = стоит значение, которое кладут в переменную. Мы говорили на дне 12, что функция — это значение; вот прямое следствие.

2. Функция-выражение

Возьмём вчерашнее объявление и уберём имя. Получится анонимная функция — функция без имени:

// function (a, b) {
//   return a + b;
// }
// → SyntaxError: Function statements require a function name

Сама по себе она не работает — мы видели эту ошибку вчера. Но если поставить её справа от =, всё в порядке:

const add = function (a, b) {
  return a + b;
};

add(2, 3);   // 5

Это и называется функцией-выражением: функция стоит там, где язык ждёт значение. Обратите внимание на точку с запятой в конце — она нужна, потому что это обычное присваивание, а не объявление.

Где такая форма встречается чаще всего — там, где функцию сразу куда-то передают:

button.addEventListener("click", function () {
  console.log("нажали");
});

Функцию не кладут в переменную вообще — она нужна только здесь и сейчас. Имя ей ни к чему.

Зачем она нужна сегодня

Резонный вопрос: если есть стрелки, которые короче, зачем вообще функция-выражение? Три ответа.

Первый — старый код. Стрелки появились в 2015 году, а JavaScript к тому моменту было двадцать лет. Всё, что написано до, использует эту форму, и читать такой код вам придётся постоянно.

Второй — методы объектов. Как мы увидим в разделе 11, стрелка методом быть не может, а функция-выражение — вполне:

const student = {
  name: "Аман",
  say: function () { return this.name; },   // работает
  sayShort() { return this.name; },         // короткая запись того же
};

Вторая строка — сокращённая запись метода, которая появилась тогда же, когда и стрелки. Её и используют сегодня; разберём вместе с объектами на дне 21.

Третий — когда нужно имя. Именованная функция-выражение из раздела 8 даёт то, чего у стрелок нет совсем.

3. Стрелочная функция

Третья форма появилась в 2015 году и быстро стала самой частой. Она получается из функции-выражения в два шага: убрать слово function и поставить стрелку => между параметрами и телом.

Самое полезное тут — неявный возврат. Если тело состоит из одного выражения, фигурные скобки и слово return не пишут: результат возвращается сам.

const double = (n) => n * 2;
const isFive = (n) => n === 5;
const greet = (name) => `Салам, ${name}!`;

Одна строка вместо трёх — вот почему стрелки так прижились.

4. Как сокращать

Сокращать можно не всегда. Вот все правила разом:

СлучайЗаписьСкобки у параметров
один простой параметрn => n * 2можно убрать
несколько параметров(a, b) => a + bобязательны
нет параметров() => 42обязательны
значение по умолчанию(n = 1) => nобязательны

Теперь про тело. Оно бывает двух видов, и тут легко ошибиться:

const f = (n) => n * 2;              // короткое тело: возврат подразумевается
const g = (n) => { return n * 2; };  // блок: return писать обязательно
const h = (n) => { n * 2; };         // блок без return — вернёт undefined!
Третья строка — самая частая ошибка новичков со стрелками. Как только появились фигурные скобки, неявный возврат выключается: скобки означают «тут будет несколько инструкций», и язык ждёт явного return.

Проверка простая: есть { после стрелки — должен быть return.

Потренируемся переводить. Вот одна функция во всех допустимых формах:

ЗаписьВерно?Почему
(n) => n * 2дакороткое тело, неявный возврат
n => n * 2даодин простой параметр — скобки не нужны
(n) => { return n * 2; }даблок с явным возвратом
(n) => { n * 2; }нетвернёт undefined
(n) => return n * 2;нетSyntaxError: return только в блоке
const f = n, m => n + m;нетдва параметра — скобки обязательны

Последняя строка заслуживает пояснения: ошибка там не та, которую ждёшь.

// const add = n, m => n + m;   → SyntaxError: Missing initializer in const declaration
const add = (n, m) => n + m;    // два параметра — только в скобках

Язык не увидел стрелочную функцию с двумя параметрами — он увидел список объявлений из дня 4: сначала const add = n, потом через запятую m => n + m. И пожаловался на второе: у m нет значения, а const без значения объявить нельзя.

Это типичная история с пропущенными скобками: сообщение говорит совсем не о том, что вы сделали не так. Увидели непонятный SyntaxError рядом со стрелкой — первым делом проверьте скобки у параметров.

Блок нужен, когда тело не помещается в одно выражение:

const sum = (numbers) => {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
};

5. Ловушка с возвратом объекта

Отдельный случай, на котором спотыкаются все. Попробуем вернуть объект коротким телом:

const makeStudent = (name) => { name: name };

console.log(makeStudent("Аман"));   // undefined

Ошибки нет, а результата тоже нет. Почему: язык увидел { сразу после стрелки и решил, что это блок кода, а не объект. А name: внутри блока он принял за метку — ту самую из дня 10. Блок ничего не вернул, получился undefined.

Лечится скобками вокруг объекта:

const makeStudent = (name) => ({ name: name });

console.log(makeStudent("Аман"));   // { name: "Аман" }

Круглые скобки говорят: «дальше выражение, а не блок». Это тот же оператор группировки из дня 8, просто в неожиданном применении.

Если формулировка «скобки вокруг объекта» не запоминается, есть запасной вариант — писать блоком с явным return: 
const makeStudent = (name) => {
  return { name: name };
};
Длиннее на две строки, зато ни одной ловушки.

6. Почему объявление можно вызвать раньше

Вчера мы приняли это как факт. Теперь разберём механизм — он простой, если вспомнить день 4.

Выражение — нельзя
add(2, 3);
// ReferenceError:
// Cannot access 'add'
// before initialization

const add = (a, b) => a + b;
Объявление — можно
add(2, 3);   // 5, работает

function add(a, b) {
  return a + b;
}

Сообщение слева — то, что пишет Chrome, когда код стоит в файле. В консоли оно короче: add is not defined. Объяснение целиком в дне 4. Объявление через function поднимается вместе с телом — к моменту вызова функция уже готова. А функция-выражение, стрелочная или нет, — это обычная переменная: до строки объявления она в мёртвой зоне.

Если такую функцию объявить через var, сообщение будет другим, но результат тот же:

add(2, 3);
// TypeError: add is not a function

var add = function (a, b) { return a + b; };

Имя add уже существует — var его поднял, — но в нём пока лежит undefined, а undefined вызвать нельзя. Отсюда TypeError вместо ReferenceError: вчерашняя ошибка «x is not a function» в новом виде.

7. Имена у безымянных функций

Анонимная функция технически без имени — но если положить её в переменную, имя всё-таки появится:

function named() { }
const myVar = function () { };
const arrowFn = () => { };

console.log(named.name);     // "named"
console.log(myVar.name);     // "myVar"   ← взялось от переменной
console.log(arrowFn.name);   // "arrowFn"

Язык подставляет имя переменной. Это не мелочь: имя видно в сообщениях об ошибках и в стеке вызовов — том самом из дня 11. Проверим на файле app.js: три функции бросают одну и ту же ошибку, а мы печатаем стек:

function named() { throw new Error("сломалось"); }
const anon = function () { throw new Error("сломалось"); };

try { named(); } catch (e) { console.log(e.stack); }
try { anon(); } catch (e) { console.log(e.stack); }
try { (function () { throw new Error("сломалось"); })(); } catch (e) { console.log(e.stack); }

Страница с этим файлом, открытая через Live Server, напечатает три стека. Первые строки у них такие:

at named (http://127.0.0.1:5500/app.js:1:26)   ← имя функции
at anon (http://127.0.0.1:5500/app.js:2:34)    ← имя взялось от переменной
at http://127.0.0.1:5500/app.js:6:28           ← имени нет вовсе

Числа после имени файла — строка и символ: 1:26 указывает на new Error в первой строке. У третьего стека вторая строка — снова строка 6, символ 54: место, где безымянную функцию вызвали. Без имени приходится искать по этим числам.

В первых двух случаях вы сразу видите, где искать. В третьем — только номер строки, а если функция передана в чужую библиотеку, то и строка будет чужая.

Отсюда практический вывод: имя стоит того, чтобы завести переменную. Колбэк в одну строку можно писать прямо на месте — там и без имени всё понятно. А вот функцию на десять строк лучше назвать, даже если она используется один раз: в тот день, когда она сломается, вы скажете себе спасибо.

Поэтому колбэк, переданный прямо на месте, лучше вынести в именованную переменную, если он длиннее строки:

В стеке — anonymous
button.addEventListener(
  "click",
  function () {
    // двадцать строк
  }
);
В стеке — handleClick
function handleClick() {
  // двадцать строк
}

button.addEventListener(
  "click", handleClick
);

8. Именованная функция-выражение

Есть и такая форма — функция-выражение, у которой всё-таки есть имя:

const outer = function inner() {
  return "результат";
};

console.log(outer());        // "результат"
console.log(outer.name);     // "inner"
console.log(typeof inner);   // "undefined" ← снаружи имени нет!

Имя inner видно только внутри самой функции. Снаружи его нет. Зачем такое нужно — ради рекурсии из дня 12: функция может позвать себя по этому имени, даже если переменную снаружи переименуют.

const factorial = function fact(n) {
  if (n <= 1) return 1;
  return n * fact(n - 1);   // зовём себя по внутреннему имени
};

Встречается эта форма редко. Знать её нужно, чтобы не растеряться, увидев в коде два имени подряд.

9. Где стрелки особенно хороши

Главная их область — короткие колбэки, которые мы разбирали вчера. Сравните одну и ту же цепочку:

Обычными функциями
marks
  .filter(function (m) {
    return m >= 3;
  })
  .map(function (m) {
    return m * 10;
  });
Стрелочными
marks
  .filter((m) => m >= 3)
  .map((m) => m * 10);

Справа видно, что делает код. Слева приходится продираться через function и return, чтобы увидеть то же самое. Методы filter и map разберём на дне 20, но запись вы уже узнаёте.

Отсюда практическое правило: чем короче функция, тем больше выигрыш от стрелки. Для однострочника выигрыш огромный, для функции на двадцать строк — никакого, там форма записи уже не важна.

Вот три места, где стрелки встречаются чаще всего. Все три мы пройдём в ближайшие недели, а запись вы узнаете уже сейчас.

Сортировка — день 20. Массив сам по себе сортируется странно, и функция сравнения обязательна:

[10, 9, 100].sort();                  // [10, 100, 9] — как строки!
[10, 9, 100].sort((a, b) => a - b);   // [9, 10, 100] — как числа

Отложенный вызов — день 30. Функция передаётся, чтобы её вызвали через время:

setTimeout(() => console.log("прошла секунда"), 1000);

Обработчик события — день 27:

button.addEventListener("click", () => {
  console.log("нажали");
});

Когда стрелки мешают

Обратная сторона краткости — код, который перестаёт читаться. Два признака, что вы перестарались.

Первый: стрелка внутри стрелки.

const add = (a) => (b) => (c) => a + b + c;
add(1)(2)(3);   // 6

Работает, но разобрать это с первого взгляда невозможно. Такой приём в языке есть, и ему даже придумали название, но в учебном коде его лучше не встречать.

Второй: вложенные тернарники в коротком теле.

const size = (n) => n > 10 ? n > 100 ? "очень много" : "много" : "мало";

Формально одно выражение, а прочитать без карандаша нельзя. Три ветки — это уже повод взять function с ранним выходом из дня 12.

Проверка, которая работает: помещается ли функция в одну строку, не заставляя щуриться? Если да — стрелка с коротким телом. Если нет — либо блок, либо обычное объявление. Краткость хороша до тех пор, пока экономит читателю время, а не отнимает.

10. Перенос строки и стрелка

Одна синтаксическая тонкость. Стрелка должна стоять на той же строке, что и параметры:

// const f = (a)
//   => a + 1;   → SyntaxError: Unexpected token '=>' — перенос строки перед стрелкой
const f = (a) => a + 1;   // стрелка на той же строке, что и параметры

А вот после стрелки переносить можно сколько угодно:

const f = (a) =>
  a + 1;              // работает

const g = (a) =>
  a > 10
    ? "много"
    : "мало";         // тоже работает

Причина — та же автоматическая вставка точки с запятой из дня 3, что ломает return с переносом. Правило простое: перенос после стрелки, не до.

11. Чего у стрелочных нет

Стрелочная функция — не просто короткая запись. У неё нет двух вещей, которые есть у обычной.

Первое: нет собственного this. Слово this мы разберём в курсе 2 — это ссылка на объект, в котором вызвана функция. Пока достаточно увидеть разницу:

const student = {
  name: "Аман",
  sayNormal() { return this.name; },        // "Аман"
  sayArrow: () => this.name,                // не сработает
};

Посмотрите на разницу внимательнее — она того стоит, потому что ошибка тихая:

const student = {
  name: "Аман",
  marks: [5, 4],

  sayNormal() { return `Я ${this.name}`; },     // "Я Аман"
  sayArrow: () => `Я ${this.name}`,             // "Я undefined"
};

Вторая строка не падает — она просто врёт. this.name в стрелочной функции указывает не на студента, и получается undefined из дня 5. Программа продолжит работать, а в отчёте окажется «Я undefined».

А иногда всё-таки падает — когда после this идёт ещё одно обращение:

const broken = {
  marks: [1, 2],
  count: () => this.marks.length,
};

broken.count();
// TypeError: Cannot read properties of undefined (reading 'length')

Это вчерашнее правило дня 5 в действии: смотрим влево от точки — this.marks оказалось undefined, а у undefined нет length.

Правило, которое пригодится сразу, ещё до изучения this: методом объекта стрелочную функцию не делают. Для методов берут короткую запись sayNormal() { ... } или function. Подробности — в курсе 2.

Второе: нет arguments. В обычной функции есть служебный объект со всеми переданными аргументами:

function countArgs() {
  return arguments.length;
}
countArgs(1, 2, 3);   // 3

const countArrow = () => arguments.length;
countArrow(1, 2, 3);  // ReferenceError: arguments is not defined

Потеря невелика: у arguments есть современная замена — остаточные параметры, которые мы разберём завтра. Они работают и в стрелочных.

И третье, попутно: стрелочную функцию нельзя вызвать через new. Что это значит, станет ясно в курсе 2 вместе с классами.

const F = () => { };
new F();   // TypeError: F is not a constructor

12. Функция, вызванная сразу

Раз функция-выражение — это значение, её можно вызвать прямо на месте, не давая имени:

(function () {
  console.log("выполнилась сразу");
})();

(() => {
  console.log("и эта тоже");
})();

Приём называется немедленно вызываемая функция. Разберём запись: функция в круглых скобках — чтобы язык понял, что это выражение, а не объявление, — и сразу вторая пара скобок, которая её вызывает.

Зачем это нужно было: до появления let и const единственным способом спрятать переменные от остальной программы была функция. Мы разбирали на дне 4, что var не знает про блоки, — а про функции знает.

(function () {
  var temp = "не виден снаружи";
})();

console.log(typeof temp);   // "undefined"

Сегодня для этого достаточно блока с const — как мы и делали на дне 4. Но в коде старше десяти лет такая конструкция встречается на каждом шагу, и узнавать её нужно.

У приёма есть и второе применение, которое живо до сих пор, — спрятать данные, оставив снаружи только доступ к ним:

const counter = (function () {
  let count = 0;                      // снаружи недоступен

  return {
    inc: () => ++count,
    get: () => count,
  };
})();

counter.inc();
counter.inc();
console.log(counter.get());     // 2
console.log(typeof count);      // "undefined" — до переменной не добраться

Функция выполнилась один раз и вернула объект с двумя стрелочными функциями. Переменная count осталась внутри — снаружи её не видно и не испортить, а менять можно только через inc.

Почему это работает: вложенные функции видят переменные внешней — мы отмечали это на днях 4 и 12. Такое свойство называется замыканием, и разбирается оно в курсе 2. Сегодня достаточно увидеть, что так делают, и понять зачем.

13. Что выбирать

ЗадачаФорма
обычная функция программыfunction — объявление
короткий колбэк в одну строкустрелочная
метод объектаfunction, не стрелочная
функция в переменной, которую могут заменитьстрелочная или выражение
нужно вызвать до объявлениятолько function

Единого мнения тут нет — команды договариваются по-разному, и спор этот идёт лет десять. Вот оба лагеря честно.

«Стрелки везде»
  • одна форма на весь файл — не надо выбирать;
  • короче на каждой функции;
  • нет сюрпризов с this;
  • невозможно случайно вызвать функцию до объявления — язык не даст.
«function для главного»
  • важные функции видно по слову function;
  • порядок в файле свободный: главное сверху, детали снизу;
  • методы объектов всё равно нельзя стрелками;
  • длинная стрелочная функция читается не лучше обычной.

Обратите внимание на последний довод слева: он серьёзнее, чем кажется. Если в файле нет ни одного объявления, то и ошибки «вызвал раньше, чем объявил» возникнуть не может — переменная просто не даст. Некоторые команды выбирают стрелки именно ради этого.

А довод справа про порядок в файле — обратная сторона той же медали. Когда функции объявлены через function, их можно расположить в любом порядке, и читатель увидит главное первым.

Договорённость нашего курса, чтобы код был единообразным: function для функций программы, стрелки для колбэков. Так самые важные функции видно с первого взгляда — по слову function, — а короткие вспомогательные не занимают лишних строк.

Главное — не смешивать без причины в одном файле. Читателю всё равно, какую форму вы выбрали; ему важно, чтобы выбор был один и тот же.

Как читать чужой код со стрелками

Главная сложность стрелок не в том, чтобы их писать, а в том, чтобы читать плотный чужой код. Вот приём, который помогает: разворачивайте мысленно обратно.

Увидели такое:

const top = marks.filter(m => m >= 4).map(m => m * 10);

Прочитайте по шагам, вставляя пропущенное:

  1. m => m >= 4 — это функция: берёт m, возвращает m >= 4;
  2. filter вызовет её для каждой оценки и оставит те, где вышло true;
  3. m => m * 10 — вторая функция: берёт m, возвращает m * 10;
  4. map заменит каждую оценку на результат.

То же самое в развёрнутом виде занимает девять строк:

function isTop(m) {
  return m >= 4;
}

function toPercent(m) {
  return m * 10;
}

const filtered = marks.filter(isTop);
const top = filtered.map(toPercent);

Никто так не пишет, но именно так надо читать, пока глаз не привык. Через пару недель разворачивать уже не понадобится.

Три места в стрелке, куда стоит смотреть в первую очередь:
  1. что слева от стрелки — это параметры, то есть что функция получает;
  2. есть ли { справа — если есть, ищите return внутри; если нет, возвращается всё выражение;
  3. куда её передают — filter, map, addEventListener: это говорит, кто и когда её вызовет.

14. «Табель»: три формы в деле

Перепишем вчерашнюю программу, выбирая форму под задачу.

const MIN_MARK = 2;
const MAX_MARK = 5;

// короткие проверки — стрелочные, в одну строку
const isValidMark = (mark) =>
  typeof mark === "number"
  && !Number.isNaN(mark)
  && mark >= MIN_MARK
  && mark <= MAX_MARK;

const isFive = (mark) => mark === MAX_MARK;

// тело не помещается в выражение — блок и явный return
const sum = (numbers) => {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
};

// одно выражение, но с условием — перенос после стрелки для читаемости
const average = (numbers) =>
  numbers.length === 0 ? 0 : sum(numbers) / numbers.length;

// функция программы с ветками — обычное объявление
function verdict(avg) {
  if (avg >= 4.5) return "отличник";
  if (avg >= 3.5) return "хорошист";
  if (avg >= 2.5) return "троечник";
  return "надо подтянуть";
}

function makeReport(name, marks) {
  const valid = marks.filter(isValidMark);     // передали функцию как значение
  const avg = average(valid);

  return `${name}: ${valid.length} из ${marks.length}, `
    + `средний ${avg.toFixed(2)} — ${verdict(avg)}, `
    + `пятёрок ${valid.filter(isFive).length}`;
}

console.log(makeReport("Аман", [5, 4, 9, 3, 5, 0, 4, 5]));
console.log(makeReport("Мерет", [3, 3, 4]));
console.log(makeReport("Гүлнар", [9, 0, "пять"]));
console.log(makeReport("Сапар", [5, 5, 4, 5]));
Аман: 6 из 8, средний 4.33 — хорошист, пятёрок 3
Мерет: 3 из 3, средний 3.33 — троечник, пятёрок 0
Гүлнар: 0 из 3, средний 0.00 — надо подтянуть, пятёрок 0
Сапар: 4 из 4, средний 4.75 — отличник, пятёрок 3

Числа те же, что вчера, — и это правильно: форма записи на поведение не влияет. Строка отчёта стала короче: слово «оценок» мы убрали. Изменилось и другое.

Цикл отбора исчез. Вместо восьми строк selectValid — marks.filter(isValidMark). Здесь работает вчерашний приём: функция передана как значение. Обратите внимание, что isValidMark написана без скобок — передаём саму функцию, а не результат.

Подсчёт пятёрок тоже стал строкой — valid.filter(isFive).length. Функция countFives больше не нужна.

А verdict осталась объявлением, потому что в ней четыре ветки и стрелка ничего бы не выиграла.

Три опыта.

Первый. Добавьте фигурные скобки в isFive: (mark) => { mark === MAX_MARK }. Запустите и объясните, почему пятёрок стало ноль у всех.

Второй. Перенесите verdict вниз файла, под вызовы console.log. Работает? А теперь сделайте её стрелочной и перенесите снова.

Третий. Напишите makeStudent, которая коротким телом возвращает объект { name, marks }. Сначала без круглых скобок, потом с ними.

16. Что будет завтра

Сегодня мы разобрали, как функцию записать. Завтра, на дне 14, вернёмся к тому, что она принимает: значения по умолчанию и остаточные параметры.

Обе темы закроют сегодняшние хвосты. Значения по умолчанию избавят от проверок «а если аргумент не передали» из дня 12. А остаточные параметры заменят arguments, которого у стрелочных нет.

Справочник дня
СтраницаЧто тамКак разбираем
Стрелочные функциисокращения, неявный возврат, чего у них нетподробно
Функция-выражениеанонимная и именованная; не поднимаетсяподробно

Сегодня в справочнике две строки: тема узкая, а всё остальное про функции уже стоит в справочниках дней 12 и 14.

function add(a, b) { return a + b; }            // объявление — поднимается
const sum = function (a, b) { return a + b; };  // выражение — нет
const plus = (a, b) => a + b;                   // стрелочная — нет

// сокращения
n => n * 2;          // один простой параметр — скобки можно убрать
(a, b) => a + b;     // несколько — скобки обязательны
() => 42;            // ноль параметров — скобки обязательны

(n) => n * 2;               // короткое тело: возврат подразумевается
(n) => { return n * 2; };   // блок: return ОБЯЗАТЕЛЕН
(n) => { n * 2; };          // блок без return → undefined!

() => ({ a: 1 });    // объект коротким телом — только в круглых скобках
() => { a: 1 };      // это БЛОК, вернёт undefined

// const f = (a)
//   => a;             → SyntaxError — перенос ДО стрелки нельзя

// у стрелочных НЕТ: своего this, arguments, new
// методом объекта стрелочную не делают

const outer = function inner() { };   // inner видно только внутри
myVar.name;                           // имя берётся от переменной

(function () { })();   // немедленно вызванная функция
(() => { })();

filter(isFive);    // передали функцию
filter(isFive());  // ОШИБКА: вызвали и передали результат
  1. Почему (n) => { n * 2 } возвращает undefined?
    Ответ Фигурные скобки превращают тело в блок, а в блоке неявный возврат не работает — нужен явный return. Без него функция возвращает undefined, как любая функция без return.
  2. Как коротким телом вернуть объект и почему именно так?
    Ответ () => ({ a: 1 }) — в круглых скобках. Без них язык читает { как начало блока, а a: как метку, и функция возвращает undefined.
  3. Почему объявление можно вызвать до его строки, а стрелочную нет?
    Ответ Объявление через function поднимается вместе с телом. Стрелочная функция — это значение в переменной, а переменная до строки объявления находится в мёртвой зоне из дня 4.
  4. Какие три вещи есть у обычной функции, но нет у стрелочной?
    Ответ Собственный this, объект arguments и возможность вызова через new. Первое — причина, по которой стрелку не делают методом объекта.
  5. В чём разница между filter(isFive) и filter(isFive())?
    Ответ Первое передаёт саму функцию, чтобы filter вызвал её для каждого элемента. Второе вызывает её немедленно и передаёт результат — скорее всего, undefined или ошибку.
