1. Три строки, которые надоели

На дне 12 мы выяснили: если аргумент не передать, параметр получит undefined. Иногда это то, что нужно, а чаще — источник NaN и странных строк:

function makeGreeting(name, greeting) {
  return greeting + ", " + name + "!";
}

makeGreeting("Аман", "Hoş geldiň");   // "Hoş geldiň, Аман!"
makeGreeting("Аман");                 // "undefined, Аман!"

Приветствие почти всегда одно и то же, и писать его при каждом вызове не хочется. Значит, нужно подставить его самим — если второго аргумента нет:

function makeGreeting(name, greeting) {
  if (greeting === undefined) {
    greeting = "Salam";
  }
  return greeting + ", " + name + "!";
}

makeGreeting("Аман");                 // "Salam, Аман!"
makeGreeting("Аман", "Hoş geldiň");   // "Hoş geldiň, Аман!"

Работает. Но три строки проверки написаны ради одного слова, и таких проверок в живом коде бывает по три-четыре подряд — на каждый необязательный параметр. Чтение функции начинается не с дела, а с формальностей.

Сегодня мы научимся писать то же самое одним знаком = прямо в заголовке функции. И заодно решим обратную задачу: что делать, когда аргументов, наоборот, сколько угодно и заранее неизвестно сколько.

2. Как записать умолчание

Значение по умолчанию ставится там же, где объявлен параметр — через =:

function makeGreeting(name, greeting = "Salam") {
  return greeting + ", " + name + "!";
}

makeGreeting("Аман");                 // "Salam, Аман!"
makeGreeting("Аман", "Hoş geldiň");   // "Hoş geldiň, Аман!"

Тело функции стало ровно тем, ради чего она написана. Проверка никуда не делась — её делает сам язык, просто теперь она не занимает место в коде.

Умолчания работают во всех трёх формах записи из вчерашнего дня:

function f1(n = 1) { return n; }            // объявление
const f2 = function (n = 1) { return n; };  // функция-выражение
const f3 = (n = 1) => n;                    // стрелочная
У стрелочной функции с умолчанием круглые скобки обязательны. Вчерашнее правило «один простой параметр — скобки можно убрать» на умолчания не распространяется:

const f = n = 1 => n;
// SyntaxError: Malformed arrow function parameter list

3. Что значит «не передали»

Здесь прячется главная тонкость дня. Умолчание срабатывает только на undefined — и больше ни на что. Ни null, ни пустая строка, ни ноль его не включают:

function test(num = 1) {
  return num;
}

test();            // 1        аргумента нет
test(undefined);   // 1        явный undefined — то же самое
test(null);        // null     умолчание НЕ сработало
test("");          // ""       умолчание НЕ сработало
test(0);           // 0        умолчание НЕ сработало
test(NaN);         // NaN      умолчание НЕ сработало

Логика простая: undefined в языке и означает «значения нет». Всё остальное — значения, пусть и пустые на вид. Если программист передал 0, он передал ноль, а не «ничего».

Таблица на все случаи — её стоит один раз прочитать целиком, потому что именно здесь рождаются самые непонятные ошибки:

Первые две строки одинаковы не случайно. Для языка «аргумента нет» и «аргумент равен undefined» — это одно и то же состояние, различить их внутри функции невозможно.

Из этого следует полезный приём: явный undefined — способ сказать «здесь возьми своё». Он пригодится в разделе 6, когда нужно пропустить один параметр и передать следующий.

Чем это отличается от старого приёма с ||

До 2015 года умолчание часто подставляли логическим ИЛИ из дня 7:

function test(num) {
  num = num || 1;   // старый приём
  return num;
}

test();      // 1   — похоже на правду
test(0);     // 1   — а вот это уже неправда!
test("");    // 1   — и это тоже

Оператор || смотрит не на «передали или нет», а на истинность. А ложными, как мы разбирали на дне 5, считаются и 0, и "", и NaN. Поэтому функция, которой честно передали ноль, молча получала единицу — ошибка, которую трудно заметить и ещё труднее найти.

Оператор ?? с того же дня 7 эту дыру закрывает: он реагирует только на null и undefined. Но сравните три записи:

function a(num) { num = num || 1; return num; }   // ломается на 0 и ""
function b(num) { num = num ?? 1; return num; }   // правильно, но в теле
function c(num = 1) { return num; }               // правильно и в заголовке

Третья версия лучше не только длиной. В ней видно с первого взгляда, что параметр необязательный, — не читая тело функции. Это и есть настоящая польза умолчаний: они документируют функцию.

Разница между ?? и умолчанием всё-таки есть: ?? подставит значение и для null, а умолчание — нет. Если в вашу функцию могут передать null и его надо считать за «ничего», умолчания одного не хватит.

4. Умолчание — это выражение

Справа от = можно писать не только готовое значение, а любое выражение — всё, что мы проходили с дня 6:

const CURRENT_YEAR = 2026;

function makeCard(name, year = CURRENT_YEAR, note = "оценок пока нет") {
  return name + " (" + year + "): " + note;
}

makeCard("Аман");         // "Аман (2026): оценок пока нет"
makeCard("Мерет", 2025);  // "Мерет (2025): оценок пока нет"

Можно даже вызвать другую функцию. И здесь важно понять когда это происходит:

function double(n) {
  return n * 2;
}

function calc(n, m = double(n)) {
  return n + m;
}

calc(3);      // 9   — double(3) вызвали, получили 6, 3 + 6
calc(3, 1);   // 4   — второй аргумент есть, double вообще не вызывали

Умолчание вычисляется в момент вызова и только если оно понадобилось. Не при объявлении функции, не один раз на всю программу — каждый раз заново.

Проще всего это увидеть на массиве:

function addMark(mark, marks = []) {
  marks.push(mark);
  return marks;
}

addMark(5);   // [5]
addMark(4);   // [4] — а не [5, 4]

Каждый вызов без второго аргумента создаёт новый пустой массив. Если нужен общий массив — его передают явно:

const amanMarks = [];
addMark(5, amanMarks);
addMark(4, amanMarks);
amanMarks;   // [5, 4]

Приём: обязательный параметр через умолчание

Раз умолчание — это выражение, которое выполняется при вызове, в него можно положить и throw из дня 11. Получится параметр, который нельзя забыть:

function required(paramName) {
  throw new TypeError("не передан обязательный аргумент: " + paramName);
}

function makeGreeting(name = required("name"), greeting = "Salam") {
  return greeting + ", " + name + "!";
}

makeGreeting("Аман");   // "Salam, Аман!"
makeGreeting();         // TypeError: не передан обязательный аргумент: name

Сравните с проверкой из дня 12: там мы писали if (name === undefined) throw ... в теле, здесь — одно слово в заголовке. И работает это ровно тогда, когда нужно: если имя передали, required даже не вызовется.

Приём не обязателен — многие пишут проверки в теле, и это тоже нормально. Но он хорошо показывает, что умолчание не обязано быть значением: это код, который запускается в нужный момент.

Проверьте в консоли, что умолчание действительно вычисляется каждый раз:

let calls = 0;
function next() { calls = calls + 1; return calls; }
function withCall(n = next()) { return n; }

Вызовите withCall() дважды и посмотрите на calls. Потом вызовите withCall(100) и посмотрите ещё раз. Сколько стало и почему?

5. Соседние параметры видны

В умолчании можно использовать параметры, которые объявлены левее:

function greet(name, greeting, message = greeting + " " + name) {
  return message;
}

greet("Аман", "Salam");                       // "Salam Аман"
greet("Аман", "Salam", "Doglan günüň gutly"); // "Doglan günüň gutly"

Удобно: третий параметр по умолчанию собирается из первых двух, но при желании его можно задать целиком.

А вот правее — нельзя. Параметры получают значения по очереди, слева направо, и того, до чего очередь не дошла, ещё не существует:

function bad(a = b, b = 2) {
  return [a, b];
}

bad();    // ReferenceError: Cannot access 'b' before initialization
bad(1);   // [1, 2] — работает, потому что умолчание для a не понадобилось

Обратите внимание: ошибка возникает не при объявлении функции, а при конкретном вызове — и только том, где умолчание пришлось вычислять. Это та же «мёртвая зона» из дня 4, просто в списке параметров.

6. Необязательные — в конец

Язык не запрещает поставить параметр с умолчанием первым. Но пользоваться такой функцией неудобно:

function f(x = 1, y) {
  return [x, y];
}

f();      // [1, undefined]
f(2);     // [2, undefined] — второй параметр задать не удалось

Аргументы раскладываются по местам, а не по именам. Чтобы добраться до y, придётся заполнить первое место — и вот тут пригодится приём из раздела 3:

f(undefined, 7);   // [1, 7] — сказали «для x возьми своё», задали y

Работает, но читается плохо: в вызове стоит слово, которое ничего не объясняет. Поэтому правило:

Параметры с умолчаниями ставят в конец списка, обязательные — в начало. Тогда любой необязательный параметр можно просто не писать.

Когда необязательных параметров становится много, даже это правило не спасает — вызов вида f(1, undefined, undefined, true) нечитаем. В таких случаях все настройки передают одним объектом; этот приём разберём на дне 22.

7. Чего в умолчании быть не может

Умолчания вычисляются до того, как начнёт работать тело функции. Поэтому из умолчания не видно того, что объявлено внутри:

function f(a = go()) {
  function go() {
    return "привет";
  }
  return a;
}

f();   // ReferenceError: go is not defined

Функция go здесь точно есть, и поднятие из дня 13 работает — но только внутри тела. Список параметров к этому моменту уже заполняется, а тела ещё нет.

Правило для практики простое: в умолчании ссылайтесь только на то, что снаружи функции или левее в списке параметров. Подробнее об областях видимости — в курсе 2.

8. Остаточный параметр

Теперь обратная задача. Функции надо принять сколько угодно аргументов: сложить любое число оценок, собрать список имён. Сколько именно — заранее неизвестно.

Для этого последний параметр помечают тремя точками. Он называется остаточным (rest parameter) и собирает в массив всё, что осталось:

function showArgs(first, second, ...others) {
  console.log(first, second, others);
}

showArgs("бир", "ики", "уч", "дёрт", "бяш");
// бир ики ["уч", "дёрт", "бяш"]

Главное свойство: остаточный параметр — всегда массив. Даже когда лишних аргументов один или ноль:

showArgs("бир", "ики", "уч");   // бир ики ["уч"]
showArgs("бир", "ики");         // бир ики []
showArgs("бир");                // бир undefined []

В последней строке видно обе сегодняшние темы сразу: обычный параметр без аргумента стал undefined, а остаточный — пустым массивом.

Теперь функцию можно написать так, как хочется её вызывать:

function sumAll(...numbers) {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
}

sumAll(5, 4, 5);   // 14
sumAll(5);         // 5
sumAll();          // 0

Внутри numbers — обычный массив, и for...of из дня 11 работает с ним как всегда.

9. Три правила остаточного

Правила короткие, и все три следуют из здравого смысла.

Первое: он последний. Остаточный параметр забирает всё до конца, так что стоять после него нечему:

// function replacer(match, ...groups, offset) { }   → SyntaxError: Rest parameter must be last formal parameter
function replacer(match, offset, ...groups) { }      // остаточный — последним

Второе: он один. Два «всех остальных» в одном списке не бывает — первый уже забрал всё:

// function f(...a, ...b) { }   → SyntaxError: Rest parameter must be last formal parameter
function f(a, ...b) { }         // один остаточный, остальные — обычные

Третье: у него не бывает умолчания. Оно бы никогда не сработало: даже без аргументов остаточный параметр — пустой массив, а не undefined:

// function f(...args = []) { }   → SyntaxError: Rest parameter may not have a default initializer
function f(...args) { }           // без аргументов args и так будет []

Есть и четвёртая мелочь: запятая после остаточного параметра тоже ошибка. В обычном списке висячая запятая разрешена, здесь — нет:

function f(a, b,) { }          // так можно
// function g(...args,) { }    → SyntaxError: Rest parameter must be last formal parameter
function g(...args) { }        // без запятой

10. Остаточный против arguments

Вчера мы видели служебный объект arguments: он есть в каждой обычной функции и содержит все переданные аргументы. Казалось бы, то же самое. Но разниц три, и все в пользу остаточного параметра.

Первая: остаточный — настоящий массив. arguments только похож на массив, а методов массива у него нет:

function withRest(...args) {
  return args.sort();
}
withRest(5, 3, 7, 1);   // [1, 3, 5, 7]

function withArguments() {
  return arguments.sort();
}
withArguments(5, 3, 7, 1);
// TypeError: arguments.sort is not a function

Проверить это можно прямо: Array.isArray для остаточного даёт true, для arguments — false.

Вторая: остаточный берёт только лишнее. Названные параметры в него не попадают, а в arguments попадает вообще всё:

function compare(a, b, ...rest) {
  return [arguments.length, rest.length];
}

compare(1, 2, 3, 4);   // [4, 2] — четыре аргумента, из них два лишних

Третья: остаточный работает в стрелочных функциях. Вчера мы выяснили, что arguments в стрелочной нет вообще:

const countArrow = (...args) => args.length;
countArrow(1, 2, 3);   // 3
Вот и обещанная вчера замена. arguments в новом коде не пишут: он не массив, не работает в стрелочных и путает тем, что включает названные параметры. Знать его нужно только для чтения старого кода.

Как переписать старый код

До 2015 года остаточных параметров не было, и arguments приходилось превращать в массив вручную. Эту строку вы встретите во многих старых файлах:

function oldSum() {
  const numbers = Array.prototype.slice.call(arguments);   // курс 2
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
}

oldSum(5, 4, 5);   // 14

Разбирать, что тут делает slice.call, сегодня не нужно — это курс 2. Достаточно узнавать конструкцию в лицо и понимать её смысл: «сделать из arguments нормальный массив». Современная запись делает то же самое и короче на две строки:

function newSum(...numbers) {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
}

newSum(5, 4, 5);   // 14

Правило переписывания: увидели arguments в начале функции — замените пустой список параметров на ...args, а все упоминания arguments на args. Если у функции есть и названные параметры, будьте внимательны: arguments включал их, а остаточный — нет.

11. Умолчания и остаточный вместе

В одном списке они уживаются — главное, соблюсти порядок:

function makeLine(name, sep = ": ", ...marks) {
  return name + sep + "оценок " + marks.length;
}

makeLine("Аман", " — ", 5, 4, 5);   // "Аман — оценок 3"
makeLine("Аман");                   // "Аман: оценок 0"

А если разделитель не нужен, а оценки нужны? Место занято, пропустить его нельзя — снова выручает явный undefined:

makeLine("Аман", undefined, 5, 4, 5);   // "Аман: оценок 3"

Это тот самый случай из раздела 6, когда вызов становится некрасивым. Здесь он ещё терпимый, но если необязательных параметров перед остаточным будет три, функцию лучше переделать.

12. Сколько параметров у функции

На дне 12 мы видели свойство length у функции: add.length — число объявленных параметров. С сегодняшними параметрами оно считает не всех:

function p1(a, b, c) { }
function p2(a, b = 1, c) { }
function p3(a, ...rest) { }

p1.length;   // 3
p2.length;   // 1  — счёт останавливается на первом умолчании
p3.length;   // 1  — остаточный не считается

Правило: length считает параметры до первого необязательного. То есть отвечает на вопрос «сколько аргументов эта функция требует обязательно».

В своём коде это свойство нужно редко, но в чужом оно встречается. Полезно знать, почему у функции с шестью параметрами length может быть единица.

13. Четыре ошибки про параметры

Все четыре — SyntaxError, то есть ломают весь файл ещё до запуска. Зато и находятся сразу.

Два параметра с одним именем

function add(x, x) {
  return x;
}
add(1, 2);   // 2 — работает?!

Это не опечатка в уроке: в обычном режиме, когда параметры простые, а функция не стрелочная, язык такое разрешает — ради очень старого кода. Второй x просто заслоняет первый, и добраться до первого аргумента уже нельзя.

Но стоит добавить что-нибудь современное — умолчание, остаточный параметр, строгий режим или стрелку — и это становится ошибкой:

// function add(x, x = 1) { }       → SyntaxError: Duplicate parameter name not allowed in this context
// function add(x, x, ...rest) { }   → та же SyntaxError
// const add = (x, x) => x;          → та же SyntaxError
function add(x, y = 1) { }          // имена разные — ошибки нет
Это второй случай в курсе, когда одна и та же запись то ошибка, то нет — первый был на дне 4 со строгим режимом. Правило для практики: одинаковых имён в параметрах не пишут никогда, даже там, где язык молчит.

Переобъявление параметра

Параметр — это уже объявленная переменная. Объявить её ещё раз через let или const нельзя:

// function f(arg) {
//   let arg = "foo";
// }
// → SyntaxError: Identifier 'arg' has already been declared

Если нужно изменить значение — просто присвойте, без let. Если нужна новая переменная — дайте ей другое имя:

function f(arg) {
  arg = "foo";        // так можно
}

function g(arg) {
  let bar = "foo";    // и так можно
}

Со старым var из дня 4 запрета нет — var arg = "foo" внутри такой функции работает. Ещё одна причина не пользоваться var: он молчит там, где let предупреждает.

Параметр после остаточного и умолчание у остаточного

Эти два мы разобрали в разделе 9. Вот все четыре ошибки вместе, с точными текстами:

ЗаписьТекст в ChromeКогда

14. «Табель»: оценки россыпью

Вчерашняя программа требовала передавать оценки массивом. Сегодня перепишем её так, чтобы оценки просто перечислялись, а имя стало необязательным.

const MIN_MARK = 2;
const MAX_MARK = 5;

const isValidMark = (mark) =>
  typeof mark === "number"
  && !Number.isNaN(mark)
  && mark >= MIN_MARK
  && mark <= MAX_MARK;

const isFive = (mark) => mark === MAX_MARK;

const sum = (numbers) => {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
};

const average = (numbers) =>
  numbers.length === 0 ? 0 : sum(numbers) / numbers.length;

// новое: пороги стали необязательными параметрами
function verdict(avg, excellent = 4.5, good = 3.5, pass = 2.5) {
  if (avg >= excellent) return "отличник";
  if (avg >= good) return "хорошист";
  if (avg >= pass) return "троечник";
  return "надо подтянуть";
}

// новое: имя по умолчанию, оценки — остаточным параметром
function makeReport(name = "без имени", ...marks) {
  const valid = marks.filter(isValidMark);
  const avg = average(valid);

  return `${name}: ${valid.length} из ${marks.length}, `
    + `средний ${avg.toFixed(2)} — ${verdict(avg)}, `
    + `пятёрок ${valid.filter(isFive).length}`;
}

console.log(makeReport("Аман", 5, 4, 9, 3, 5, 0, 4, 5));
console.log(makeReport("Мерет", 3, 3, 4));
console.log(makeReport("Гүлнар", 9, 0, "пять"));
console.log(makeReport("Сапар", 5, 5, 4, 5));
console.log(makeReport());
Аман: 6 из 8, средний 4.33 — хорошист, пятёрок 3
Мерет: 3 из 3, средний 3.33 — троечник, пятёрок 0
Гүлнар: 0 из 3, средний 0.00 — надо подтянуть, пятёрок 0
Сапар: 4 из 4, средний 4.75 — отличник, пятёрок 3
без имени: 0 из 0, средний 0.00 — надо подтянуть, пятёрок 0

Первые четыре строки совпали со вчерашними — и это правильная проверка: мы поменяли способ передачи данных, а не сами вычисления.

Квадратных скобок в вызовах больше нет. Раньше было makeReport("Аман", [5, 4, 9]), теперь — makeReport("Аман", 5, 4, 9). Функцию стало приятнее вызывать, а внутри marks остался тем же массивом, что и был.

Пороги вынесены в параметры. В разных школах шкала разная, и теперь её можно задать, не трогая код функции:

verdict(4.6);             // "отличник"      — обычная шкала
verdict(4.6, 4.8);        // "хорошист"      — строгая: отличник от 4.8
verdict(3.9, undefined, 4);  // "троечник"   — пропустили первый порог

Все вызовы внутри makeReport остались прежними — verdict(avg). Добавив умолчания, мы ничего не сломали: старый способ вызова продолжает работать. Это главная практическая польза умолчаний — функцию можно расширять, не переписывая её вызовы.

Последняя строка отчёта — результат makeReport() вообще без аргументов. Вчерашняя версия на таком вызове падала: marks был undefined, и Chrome писал TypeError: Cannot read properties of undefined (reading 'filter'). Теперь выходит честная пустая карточка.

Три опыта.

Первый. Поменяйте параметры местами: function makeReport(...marks, name = "без имени"). Запустите и запишите текст ошибки. Потом попробуйте дать остаточному умолчание: ...marks = [].

Второй. Вызовите makeReport("Аман", [5, 4, 3]) — с массивом, как вчера. Программа не упадёт; объясните, почему получилось «0 из 1».

Третий. В последней строке оценок нет вообще, а вердикт — «надо подтянуть». Это неправда. Добавьте в makeReport раннюю ветку для случая valid.length === 0 и проверьте, какие отчёты изменились: кроме последнего — отчёт Гүлнар, у неё тоже нет ни одной годной оценки. Аман, Мерет и Сапар остались прежними.

Разбор: куда делись оценки

Самая частая ошибка сегодняшнего дня — передать в остаточный параметр массив целиком. Программа не падает, и это худший вид ошибки: она молча врёт. Разберём её по шагам, как разбирают настоящие.

makeReport("Аман", [5, 4, 3]);
// "Аман: 0 из 1, средний 0.00 — надо подтянуть, пятёрок 0"

Шаг 1. Что в отчёте не так. Оценок передали три, а в знаменателе единица. Значит, дело не в проверке оценок, а в том, сколько их вообще дошло до функции.

Шаг 2. Смотрим, что внутри. Первым делом печатаем сам параметр — это самый быстрый способ проверить догадку:

function makeReport(name = "без имени", ...marks) {
  console.log(marks);   // [[5, 4, 3]]
  // ...
}

Шаг 3. Читаем вывод. Две пары скобок вместо одной: массив внутри массива. Остаточный параметр собрал аргументы в массив — а аргумент был один, и сам оказался массивом.

Шаг 4. Объясняем остальное. Значит, marks.length — это 1, отсюда «из 1». А typeof marks[0] — "object", и isValidMark честно отвергает единственный элемент: отсюда «0 из 1». Все числа отчёта сошлись — версия верна.

Шаг 5. Чиним. Либо перечисляем значения: makeReport("Аман", 5, 4, 3), либо, если оценки уже лежат в массиве, раскладываем его тремя точками в вызове — это день 22:

const marksArray = [5, 4, 3];
makeReport("Аман", ...marksArray);   // день 22, но работает уже сегодня

Порядок шагов тут важнее самой ошибки: увидели странное число — напечатали то, из чего оно считается, — объяснили все цифры, а не одну. Пока хоть одна цифра не объяснена, версия не доказана.

16. Что будет завтра

Новых страниц справочника завтра не будет. День 15 — смешанный: в каждом из трёх уроков немного разбора и много работы руками. Тема — как разбить задачу на функции: что выделять, какие параметры давать, где ставить умолчания.

Модуль «Функции» на этом закрывается, и с дня 16 начинается модуль про встроенные объекты: строки, числа, Math.

  1. Почему test(0) при function test(num = 1) вернёт 0, а не 1?
    Ответ Умолчание срабатывает только на undefined. Ноль — это значение, пусть и ложное при проверке. Именно поэтому умолчание надёжнее старого приёма num = num || 1, который на нуле ломается.
  2. Функция addMark(mark, marks = []) добавляет оценку в массив. Почему два вызова подряд без второго аргумента не накапливают оценки?
    Ответ Умолчание вычисляется при каждом вызове заново, а не один раз при объявлении. Каждый вызов создаёт новый пустой массив. Чтобы копить, массив передают явно.
  3. Что окажется в rest при вызове f(1), если функция объявлена как function f(a, b, ...rest)?
    Ответ Пустой массив []. Остаточный параметр — всегда массив, даже когда лишних аргументов нет. А b при этом станет undefined.
  4. Назовите три отличия остаточного параметра от arguments.
    Ответ Остаточный — настоящий массив с методами; он содержит только лишние аргументы, без названных; он работает в стрелочных функциях, где arguments нет вообще.
  5. Почему function add(x, x) иногда работает, а иногда даёт SyntaxError?
    Ответ В обычном режиме с простыми параметрами язык это разрешает ради старого кода: второй x заслоняет первый. Но в строгом режиме, в стрелочной функции или если в списке есть умолчание либо остаточный параметр — это ошибка. Писать так не стоит никогда.
