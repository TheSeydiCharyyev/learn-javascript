Day 15. Splitting a task into functions

A summary of the three parts: how to cut, how to debug, how to read someone else’s code.

Part 1. How to cut

A piece of code asks to become a function if: it can be named with one verb; you want to write a heading comment above it; it repeats; you want to check it separately.
You cut by meaning, not by length. “A function is no longer than twenty lines” is a bad rule.
BadGood
f, doIt, processcountPresent — verb + what
check(mark)isValidMark(mark) — checks start with is/has
average printsgetAverage returns, showAverage prints
“And” appeared in an honest name — there is more than one job. countAndPrint must be split: one counts, the other shows.
0–2 parameters are good, 3 is fine, 4 or more — the function does too much.
Return, do not print. And always the same type. 
// sum — the same as in the “Report card”
function showAverage(marks) { console.log(sum(marks) / marks.length); }
const a = showAverage([5, 4]);   // 4.5 in the console, but undefined in a

function getAverage(marks) { return sum(marks) / marks.length; }
const b = getAverage([5, 4]);    // 4.5 — you can keep working with this

Part 2. How to debug

Three places, in this order: input (is the input right) → body (is it calculated right) → output (is the output right). The body comes last. 
function countPresent(present) {
  console.log("in:", present);      // print the value WHOLE
  let came = 0;
  for (const p of present) {
    if (p === 1) { came += 1; }
  }
  console.log("out:", came);
  return came;
}

countPresent([1, 0, 1]);   // in: (3) [1, 0, 1]   out: 2
countPresent("101");       // in: 101             out: 0 ← no error, wrong answer
The most dangerous error is when the program does not crash but lies. Two prints at the boundaries catch it in half a minute.

The call stack

Shrink the input. It crashes or lies on a hundred students — try two, one, an empty list. The minimal call with the error fits in your head completely, and most often it turns out to be empty.

Part 3. How to read someone else’s code

The order of analysis: return (what the function is for) → parameters (the way they are used tells their type) → branches (what is taken, what is skipped) → the name is invented last and written in right away. 
function f(a, b) {                 // before
  let r = "";
  for (const x of a) {
    if (x.length > b) { r = r + x + " "; }
  }
  return r;
}

function longNames(names, minLength = 5) {   // after, in steps: names → tail → default
  let result = "";
  for (const name of names) {
    if (name.length > minLength) {
      if (result !== "") { result += ", "; }
      result += name;
    }
  }
  return result;
}
Edge cases of any unfamiliar function: empty input, “nothing fit”, “everything fit”, a call without arguments.
Rewrite in small steps: one step — one check; the answer must stay the same after each step.
  1. Take the “who came” program from section 1 of the lecture and cut it yourself, without peeking. Then compare your boundaries with section 3 and write down where they differed.
  2. Add printing at the boundaries to any three of your functions and run them. Write down what was printed, and remove the printing again.
  3. Remove return from sum in the “Report card” and run it. There will be no error — write down where the trouble shows in the reports, and explain its path: sum → average → makeReport.
  4. Find a function in your code from the past days whose name asks for “and”. Split it in two and check that the program works as before.
