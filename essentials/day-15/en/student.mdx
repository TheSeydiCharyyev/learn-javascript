# Day 15. Splitting a task into functions

<Subtitle>A summary of the three parts: how to cut, how to debug, how to read someone else’s code.</Subtitle>

## Part 1. How to cut

<Definition>
A piece of code asks to become a function if: it can be named with one verb; you want to write
a heading comment above it; it repeats; you want to check it separately.
</Definition>

<KeyPoint>
You cut **by meaning, not by length**. “A function is no longer than twenty lines” is
a bad rule.
</KeyPoint>

| Bad | Good |
| --- | --- |
| `f`, `doIt`, `process` | `countPresent` — verb + what |
| `check(mark)` | `isValidMark(mark)` — checks start with `is`/`has` |
| `average` prints | `getAverage` returns, `showAverage` prints |

<Remember>
**“And” appeared in an honest name — there is more than one job.**
`countAndPrint` must be split: one counts, the other shows.
\
0–2 parameters are good, 3 is fine, 4 or more — the function does too much.
\
Return, do not print. And always the same type.
</Remember>

```js
// sum — the same as in the “Report card”
function showAverage(marks) { console.log(sum(marks) / marks.length); }
const a = showAverage([5, 4]);   // 4.5 in the console, but undefined in a

function getAverage(marks) { return sum(marks) / marks.length; }
const b = getAverage([5, 4]);    // 4.5 — you can keep working with this
```

## Part 2. How to debug

<Definition>
Three places, in this order: **input** (is the input right) →
**body** (is it calculated right) → **output** (is the output right).
The body comes last.
</Definition>

```js
function countPresent(present) {
  console.log("in:", present);      // print the value WHOLE
  let came = 0;
  for (const p of present) {
    if (p === 1) { came += 1; }
  }
  console.log("out:", came);
  return came;
}

countPresent([1, 0, 1]);   // in: (3) [1, 0, 1]   out: 2
countPresent("101");       // in: 101             out: 0 ← no error, wrong answer
```

<Remember>
The most dangerous error is when the program **does not crash but lies**.
Two prints at the boundaries catch it in half a minute.
</Remember>

## The call stack

```plain-out
TypeError: numbers is not iterable
    at sum (http://127.0.0.1:5500/app.js:3:19)            ← where it CRASHED
    at averageMark (http://127.0.0.1:5500/app.js:10:10)
    at makeReport (http://127.0.0.1:5500/app.js:14:24)
    at http://127.0.0.1:5500/app.js:17:13                 ← where the CAUSE is
```

It is read from the bottom up. Go up the stack until you find your own line.

| What you see | What happened | Day |
| --- | --- | --- |
| `x is not a function` | something that is not a function was called | 12 |
| `undefined`, no error | `return` was forgotten | 12 |
| an arrow returned `undefined` | braces switched off the return | 13 |
| an argument “did not arrive” | the order of parameters is mixed up | 14 |

<Remember>
**Shrink the input.** It crashes or lies on a hundred students — try two,
one, an empty list. The minimal call with the error fits in your head completely, and most
often it turns out to be empty.
</Remember>

## Part 3. How to read someone else’s code

<Definition>
The order of analysis: **return** (what the function is for) → **parameters**
(the way they are used tells their type) → **branches** (what is taken, what is skipped)
→ the **name** is invented last and written in right away.
</Definition>

```js
function f(a, b) {                 // before
  let r = "";
  for (const x of a) {
    if (x.length > b) { r = r + x + " "; }
  }
  return r;
}

function longNames(names, minLength = 5) {   // after, in steps: names → tail → default
  let result = "";
  for (const name of names) {
    if (name.length > minLength) {
      if (result !== "") { result += ", "; }
      result += name;
    }
  }
  return result;
}
```

<NoteBox>
**Edge cases** of any unfamiliar function: empty input, “nothing
fit”, “everything fit”, a call without arguments.
\
**Rewrite in small steps:** one step — one check; the answer
must stay the same after each step.
</NoteBox>
