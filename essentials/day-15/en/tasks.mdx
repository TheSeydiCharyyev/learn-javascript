<Task title="2. Rename" level="easy" time="8">
<Goal>learn to see that a name lies.</Goal>

For each function invent the right name and explain what was wrong with the old one.
The bodies do not need changing.

```js
function data(marks) {
  return marks.length;
}

function check(mark) {
  return mark >= 2 && mark <= 5;
}

function average(marks) {
  console.log(sum(marks) / marks.length);
}

function doIt(names, marks) {
  return names.length === marks.length;
}
```

<Hint>
Two of the four return `true` or `false` — the names of such functions
start with `is` or `has`. One returns nothing,
and its name promises too much.
</Hint>

<Criteria>
- a new name and a reason are written down for all four;
- the two checks are named with `is` or `has`;
- for the third one it is explained why the name `average` deceives;
- it is written down what must change in the third one for the name `getAverage`
  to become honest.
</Criteria>
</Task>

<Task title="3. Split the “and”" level="medium" time="9">
<Goal>separate calculating and showing into different functions.</Goal>

function countAndPrint(present) {

Split it in two. Then show with calls what could not be done with the old version

<Hint>

</Criteria>

## Block 2 — after part 2 (25 minutes)

<Task title="4. The program lies, it does not crash" level="medium" time="8">
<Goal>find an error that nobody reports.</Goal>

This program prints `Good marks: 133%`. There is no error in the console.

```js
function countHigh(marks, limit) {
  let count = 0;
  for (const m of marks) {
    if (m > limit) {
      count += 1;
    }
  }
  return count;
}

function percentOf(part, total) {
  if (total === 0) {
    return 0;
  }
  return part / total * 100;
}

function report(marks, limit) {
  const high = countHigh(marks, limit);
  return "Good marks: " + percentOf(marks.length, high).toFixed(0) + "%";
}

console.log(report([5, 4, 3, 5], 3));
```

<Hint>
First calculate the right answer in your head: how many marks are greater than three, out of how many.
Then add printing at the boundaries to both functions and look at what leaves one
and arrives in the other.
</Hint>

<Criteria>
- the right answer is calculated by hand before running;
- the line with the error is found, the cause is named;
- the printing at the boundaries that shows it is presented;
- after the fix 75% is printed;
- it is explained why a percent over a hundred is a good reason to be alarmed.
</Criteria>
</Task>

<Task title="5. Read the call stack" level="medium" time="8">
<Goal>find the real cause by the chain of calls.</Goal>

Type it into a file exactly like this, with the empty lines — you will need the line numbers:

```js
function sumOf(numbers) {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
}

function averageOf(numbers) {
  return sumOf(numbers) / numbers.length;
}

function makeLine(name, numbers) {
  return name + ": " + averageOf(numbers).toFixed(1);
}

console.log(makeLine("Aman", [5, 4]));
console.log(makeLine("Meret"));
```

<Hint>
The first line of output will be correct, the second will crash. The stack is read from the bottom up:
the bottom line is your file, start from it.
</Hint>

<Criteria>
- the text of the error and the whole call stack from your console are written down;
- the line that must be fixed is named, and its number is written down;
- it is explained why `sumOf` does not need fixing, although it crashed exactly in it;
- the error is fixed, both lines are printed;
- it is written down what the stack will show if you write `makeLine("Meret", [])`
  instead of `makeLine("Meret")` — and why there is no error there anymore.
</Criteria>
</Task>

<Task title="6. Shrink the input" level="hard" time="9">
<Goal>bring an error down to the smallest call on which it is visible.</Goal>

The function must name the best student. On three students it answers
`Aman (5)`, although the five is Meret’s.

```js
function best(names, marks) {
  let bestName = names[0];
  let bestMark = marks[0];
  let i = 1;
  for (const name of names) {
    if (marks[i] > bestMark) {
      bestMark = marks[i];
      bestName = name;
    }
    i += 1;
  }
  return bestName + " (" + bestMark + ")";
}

console.log(best(["Aman", "Meret", "Gülnar"], [4, 5, 3]));
```

Shrink the input until the error becomes obvious, then fix it.

<Hint>
Try two students, then one, then empty lists. At some step
the answer will suddenly become right — and that is the most interesting place. Look at which
element of the list `marks[i]` is compared with on the first turn of the loop.
</Hint>

<Criteria>
- all the trial calls and their answers are written down;
- the smallest call on which the answer is still wrong is named;
- a call on which the answer is right is named, and it is explained why there is no error there;
- the error is fixed and checked on three, two and one student;
- it is written down what the fixed function does on empty lists, and it is decided
  whether that is good or not.
</Criteria>
</Task>

## Block 3 — after part 3 (25 minutes)

<Task title="7. Read without running" level="medium" time="8">
<Goal>take an unfamiliar function apart layer by layer and check the guess.</Goal>

```js
function g(a, b) {
  let c = 0;
  for (const x of a) {
    if (x >= b) {
      c += 1;
    }
  }
  return c / a.length * 100;
}
```

**First** write down: what the function returns, what types the parameters are,
what the branch does, what you would call it. Predict three calls — and only then run them.

```js
g([5, 4, 3, 5, 2], 4);
g([5, 4, 3, 5, 2], 6);
g([], 4);
```

<Hint>
Look at `return` first: there is division by the length and multiplication by a hundred —
this tells you right away what the answer is measured in. The third call is exactly the edge case
for which they are checked.
</Hint>

<Criteria>
- the analysis by four layers is written down before running;
- three predictions are written down before running;
- for the third call it is explained where its result comes from;
- meaningful names are invented for the function and both parameters.
</Criteria>
</Task>

<Task title="8. Rewrite in small steps" level="hard" time="9">
<Goal>put someone else’s function in order without breaking anything on the way.</Goal>

Take `g` from task 7 and rewrite it one step at a time, **running the three calls
from task 7 after each step** and comparing the answers.

1. only the names: of the function and both parameters;
2. the edge case from the third call — return `0` instead of `NaN`;
3. a default value for the threshold, so that a call with one argument works;
4. checking the edges once more: an empty list, a threshold above all marks, a threshold below all of them.

<Hint>
After step 2 the first two answers must stay the same — if they changed,
the emptiness check was put in the wrong place. Its place is before all the calculations.
</Hint>

<Criteria>
- after each step the answers of the three calls are written down;
- the answers of the first two calls did not change at any step;
- the third call gives `0` after step 2;
- a call with one argument works and gives an answer that can be explained;
- it is written down why rewriting everything at once is worse than in steps.
</Criteria>
</Task>
