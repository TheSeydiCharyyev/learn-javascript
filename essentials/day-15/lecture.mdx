## Часть 1, раздел 1. Программа одной кучей {#pile}

Вот рабочая программа. Она считает, сколько человек пришло на занятие, и называет тех,
кого нет. Всё правильно, всё работает:

```js
const names = ["Аман", "Мерет", "Гүлнар", "Сапар", "Огулджан"];
const present = [1, 0, 1, 1, 0];

let came = 0;
for (const p of present) {
  if (p === 1) {
    came += 1;
  }
}

let missing = "";
let i = 0;
for (const name of names) {
  if (present[i] === 0) {
    if (missing !== "") {
      missing += ", ";
    }
    missing += name;
  }
  i += 1;
}

const percent = came / names.length * 100;

console.log("Пришло " + came + " из " + names.length + " (" + percent.toFixed(0) + "%)");
if (missing !== "") {
  console.log("Нет: " + missing);
}
```

<ResultBox>
Пришло 3 из 5 (60%)\
Нет: Мерет, Огулджан
</ResultBox>

Двадцать восемь строк, и в них уже трудно ориентироваться. Попробуйте ответить, не перечитывая:
что делает переменная `i`? А `came` считается до или после
`missing`? Чтобы ответить, приходится читать всё подряд.

И это на пяти студентах. Добавьте сюда опоздания, два занятия в день, пропуски по болезни —
и программа станет нечитаемой. Причём сломать её будет легко, а найти поломку трудно:
**все переменные живут в одном месте и видят друг друга**.

## Часть 1, раздел 2. Где резать: четыре признака {#where}

Резать наугад бессмысленно. Есть четыре признака, по которым кусок кода просится
в отдельную функцию. Проверьте их на программе выше.

**Первый: кусок можно назвать одним глаголом.** «Посчитать пришедших»,
«собрать список отсутствующих», «перевести в проценты». Если для названия нужно предложение —
кусок ещё великоват.

**Второй: над куском хочется написать комментарий-заголовок.** Если рука тянется
поставить `// считаем, сколько пришло`, значит, вы уже придумали имя функции.
Комментарий стареет и врёт, а имя функции — нет.

**Третий: кусок повторяется.** Даже дважды. Третий раз копировать уже нельзя:
когда найдётся ошибка, её починят в одном месте из трёх.

**Четвёртый: кусок хочется проверить отдельно.** Если вы ловите себя на мысли
«а правильно ли тут считается процент», проверять придётся всю программу целиком —
или вынести процент в функцию и проверить её одну.

<Important>
Обратите внимание: ни один признак не про длину. «Функция не длиннее двадцати строк» —
плохое правило. Бывают честные функции на тридцать строк и бессмысленные на три.
**Режут не по длине, а по смыслу.**
</Important>

## Часть 1, раздел 3. Что получилось {#cut}

Приложим признаки к программе. Находится три куска с именами и один, который собирает
всё вместе:

```js
function countPresent(present) {
  let came = 0;
  for (const p of present) {
    if (p === 1) {
      came += 1;
    }
  }
  return came;
}

function listMissing(names, present) {
  let missing = "";
  let i = 0;
  for (const name of names) {
    if (present[i] === 0) {
      if (missing !== "") {
        missing += ", ";
      }
      missing += name;
    }
    i += 1;
  }
  return missing;
}

function percentOf(part, total) {
  if (total === 0) {
    return 0;
  }
  return part / total * 100;
}

function makeReport(names, present) {
  const came = countPresent(present);
  const missing = listMissing(names, present);
  const share = percentOf(came, names.length);

  let report = `Пришло ${came} из ${names.length} (${share.toFixed(0)}%)`;
  if (missing !== "") {
    report += `\nНет: ${missing}`;
  }
  return report;
}

console.log(makeReport(["Аман", "Мерет", "Гүлнар", "Сапар", "Огулджан"], [1, 0, 1, 1, 0]));
```

<ResultBox>
Пришло 3 из 5 (60%)\
Нет: Мерет, Огулджан
</ResultBox>

Результат тот же — это первое, что надо проверить после любого разрезания. Строк стало
больше, а читать стало легче: чтобы понять программу, теперь достаточно прочесть
`makeReport`. Три вызова в её начале — и в них видно всё устройство.

<Scheme src="scheme-cut.svg">Программа стала двухэтажной: сверху порядок действий, снизу сами действия</Scheme>

Есть и прямая выгода: `percentOf` теперь пригодится в любой другой программе,
а заодно получила проверку `total === 0`, которой в куче не было вовсе —
там просто никто не подумал про пустой список.

### Проверяем каждый кусок отдельно

Вот главная награда за разрезание, и её стоит получить сразу же. Раньше, чтобы
проверить подсчёт, надо было запускать всю программу и смотреть на итоговую строку.
Теперь каждую функцию можно позвать в консоли саму по себе:

```js
countPresent([1, 0, 1]);   // 2
countPresent([1, 1]);      // 2
countPresent([0, 0]);      // 0
countPresent([]);          // 0
```

Четыре вызова — и подсчёт проверен на всех случаях, какие бывают: часть пришла,
пришли все, не пришёл никто, списка нет вовсе. То же со сбором имён:

```js
listMissing(["Аман"], [0]);              // "Аман"
listMissing(["Аман"], [1]);              // ""
listMissing(["Аман", "Мерет"], [0, 0]);  // "Аман, Мерет"
```

Третий вызов проверяет то, что в куче проверить было труднее всего, — запятую
между именами. Она ставится **перед** именем и только если строка уже
не пуста; иначе отчёт начинался бы с запятой или кончался ею.

```js
percentOf(3, 5);   // 60
percentOf(5, 5);   // 100
percentOf(0, 0);   // 0   — и никакого NaN
```

Такую проверку делают не один раз при написании, а каждый раз, когда функцию правят:
полминуты ловят почти все поломки.

## Часть 1, раздел 4. Имя функции — это договор {#names}

Имя — единственное, что читают чаще всего. В теле функции оказываются раз в месяц,
а имя видят при каждом вызове. Поэтому договорённости такие.

**Имя начинается с глагола**, потому что функция — это действие:
`countPresent`, `makeReport`, `listMissing`.
Имя `data` или `report` — это имя переменной, а не функции.

**Проверки начинаются с `is` или `has`** и возвращают
только `true` или `false`. Мы так и писали:
`isValidMark`, `isFive`. Увидев `if (isValidMark(mark))`,
читатель понимает строку целиком и внутрь не заглядывает.

| Плохо | Хорошо | Почему |
| --- | --- | --- |
| `f`, `doIt`, `process` | `countPresent` | имя должно отвечать «что делает» |
| `average` печатает | `showAverage` печатает, `getAverage` возвращает | имя обещает результат — пусть возвращает |
| `check(mark)` | `isValidMark(mark)` | «проверить» и вернуть `true` — разные вещи |
| `getData2` | `getMarksOfMonth` | цифра в имени — признак, что не придумали смысл |

Имена на английском мы берём не из моды: все встроенные функции языка названы так же,
и код читается ровно. В комментариях пишите по-русски сколько угодно.

## Часть 1, раздел 5. Одна функция — одно дело {#one-thing}

Есть простая проверка: **если в честном имени функции появляется «и», дел больше
одного**. Вот функция, которая и считает, и печатает:

```js
function countAndPrint(present) {
  let came = 0;
  for (const p of present) {
    if (p === 1) {
      came += 1;
    }
  }
  console.log("Пришло: " + came);
  return came;
}
```

Работает. Но пользоваться ей неудобно: посчитать, не печатая, уже нельзя. А печать
в середине расчёта — это всегда мусор в консоли, когда программа подрастёт.

Разделение выглядит так: одна функция считает, другая показывает.

```js
const count = countPresent(present);
console.log("Пришло: " + count);
```

Второе следствие того же правила: **функция не должна тайком менять то, что ей
не принадлежит**. Сравните:

```js
let total = 0;

function addMark(mark) {
  total += mark;      // тайком меняет внешнюю переменную
}

function withMark(sumSoFar, mark) {
  return sumSoFar + mark;   // честно: что дали, то и вернула
}
```

Первую нельзя проверить в одиночку — нужен весь файл. Вторую можно вызвать в консоли
и сразу увидеть ответ. Функции, которые зависят только от своих параметров, потому
и удобны: у них нет предыстории.

## Часть 1, раздел 6. Сколько параметров и что возвращать {#params}

Про число параметров правило приблизительное, но полезное: **ноль, один, два —
хорошо; три — ещё нормально; четыре и больше — знак, что функция делает слишком много**.

```js
function makeLine(name, value, unit = "", prefix = "", suffix = "", total = 0) {
  let line = prefix + name + ": " + value + unit + suffix;
  if (total > 0) {
    line += " (" + (value / total * 100).toFixed(0) + "%)";
  }
  return line;
}

makeLine("Пришло", 3, undefined, undefined, "", 5);   // "Пришло: 3 (60%)"
```

Вызов нечитаем: два `undefined` и пустая строка нужны только чтобы добраться
до последнего параметра — ровно та беда, о которой мы говорили вчера. Две простые функции
вместо одной сложной решают дело:

```js
function line(name, value, unit = "") {
  return name + ": " + value + unit;
}

function withPercent(text, part, total) {
  if (total === 0) {
    return text;
  }
  return text + " (" + (part / total * 100).toFixed(0) + "%)";
}

line("Пришло", 3);                                 // "Пришло: 3"
withPercent(line("Пришло", 3, " чел."), 3, 5);     // "Пришло: 3 чел. (60%)"
```

Про возврат правил два. **Первое: возвращать, а не печатать.**
Печать — это конец пути, дальше с результатом ничего не сделать. `sum`
здесь та же, что в «Табеле»:

```js
function showAverage(marks) {
  console.log(sum(marks) / marks.length);
}

const a = showAverage([5, 4]);   // в консоли 4.5, а в a — undefined
a.toFixed(1);
// TypeError: Cannot read properties of undefined (reading 'toFixed')
```

```js
function getAverage(marks) {
  return sum(marks) / marks.length;
}

const b = getAverage([5, 4]);   // 4.5
b.toFixed(1);                   // "4.5"  — с результатом можно работать дальше
```

**Второе: возвращать всегда одно и то же по типу.** Если функция иногда
отдаёт число, а иногда строку «нет данных», каждый вызывающий обязан это помнить —
и однажды забудет. Лучше вернуть `0`, или пустую строку, или
`undefined`, но последовательно.

### Функция без возврата — тоже функция

Правило «возвращать, а не печатать» звучит так, будто `return` обязателен
всегда. Это не так. Бывают функции, у которых работа и есть показ:

```js
function showReport(names, present) {
  console.log(makeReport(names, present));
}
```

Она ничего не возвращает — и правильно, возвращать ей нечего. Разница вот в чём:
**`showReport` ничего не считает**, все расчёты остались
в `makeReport`. Плохо не «печатать», плохо «считать и печатать одновременно».

Так же устроены функции, меняющие страницу или сохраняющие данные (дни 25 и 31):
их результат — изменение снаружи.

А вот `undefined` случайный, от забытого `return`, — совсем
другое дело. Отличить одно от другого просто: **посмотрите на имя**.
Если имя обещает ответ (`get`, `count`, `make`,
`is`) — `return` обязан быть. Если имя обещает действие
(`show`, `print`, `save`) — не обязан.

## Часть 2, раздел 7. Три места, где ломается функция {#three-places}

Функция маленькая и замкнутая, поэтому искать в ней ошибку проще, чем в куче.
Мест всего три: **вход, тело, выход**. Порядок проверки — тот же.

<Scheme src="scheme-three-places.svg">Маршрут отладки функции. В тело лезут последним — чаще всего беда на границе</Scheme>

Порядок важен. Начинающие сразу лезут в тело и перечитывают цикл по десять раз, хотя
в половине случаев в функцию просто пришло не то, что ожидалось, — и тело ни при чём.

## Часть 2, раздел 8. Печать на границах {#borders}

Приём на каждый день: две строки `console.log` — в самом начале функции
и прямо перед `return`.

```js
function countPresent(present) {
  console.log("вошло:", present);
  let came = 0;
  for (const p of present) {
    if (p === 1) {
      came += 1;
    }
  }
  console.log("выходит:", came);
  return came;
}
```

Теперь вызов рассказывает о себе:

```js
countPresent([1, 0, 1]);
// вошло: (3) [1, 0, 1]
// выходит: 2
```

А вот что будет, если в функцию попала строка вместо массива:

```js
countPresent("101");
// вошло: 101
// выходит: 0     ← ошибки нет, а ответ неверный
```

Программа не упала. `for...of` из дня 11 честно перебрал строку по символам,
и каждый символ `"1"` сравнился с числом `1` через `===` —
строгое сравнение из дня 7 сказало «не равно». Итог: ноль.

<Important>
Это самый опасный вид ошибки: **программа не падает, а врёт**.
Падение видно сразу, враньё можно возить в проекте месяцами. Две печати на границах
ловят его за полминуты.
</Important>

Печатайте параметр целиком, а не его кусочек: `console.log("вошло:", present)`,
а не `console.log(present.length)`. Длина у строки тоже есть, и вы бы ничего
не заметили.

### Когда печатей становится много

Три-четыре печати ещё читаются. Тридцать — уже нет: в консоли столбик чисел, и неясно,
какое откуда. Спасают **метки** — первым аргументом всегда слово:

```js
const groups = [[1, 0, 1], [1, 1], [0, 0, 0]];
let n = 1;
for (const group of groups) {
  console.log("группа " + n + ":", group, "->", countPresent(group));
  n += 1;
}
```

<ResultBox>
вошло: (3) \[1, 0, 1\]\
выходит: 2\
группа 1: (3) \[1, 0, 1\] -> 2\
вошло: (2) \[1, 1\]\
выходит: 2\
группа 2: (2) \[1, 1\] -> 2\
вошло: (3) \[0, 0, 0\]\
выходит: 0\
группа 3: (3) \[0, 0, 0\] -> 0
</ResultBox>

Теперь видно и вход, и выход, и кто есть кто. Если данных много,
пригодится `console.table` из дня 2 — он раскладывает список в таблицу
и читается куда легче столбика.

Главное правило про отладочные печати: **убирайте их, как только нашли
ошибку**. Забытый `console.log` мешает искать следующую беду —
и портит впечатление в чужом проекте.

### Точка останова вместо печати

Печать — не единственный способ. В браузере есть отладчик: во вкладке
**Sources** можно щёлкнуть по номеру строки, и программа остановится
прямо на ней. Дальше видно все переменные разом, без единого `console.log`.

Слово `debugger`, о котором шла речь на дне 2, делает то же самое из кода:

```js
function countPresent(present) {
  debugger;        // здесь программа остановится, если открыт отладчик
  let came = 0;
  for (const p of present) {
    if (p === 1) {
      came += 1;
    }
  }
  return came;
}
```

Печать удобнее, когда значение меняется **много раз подряд**; точка
останова — когда надо рассмотреть **всё состояние сразу**. В курсе мы
обходимся печатью, но знать про вторую возможность стоит.

## Часть 2, раздел 9. Стек вызовов {#stack}

Когда функция всё-таки падает, браузер показывает не только ошибку, но и **цепочку
вызовов** — кто кого позвал. Читать её умеют не все, а стоит: она сразу говорит,
в каком месте искать.

```js
function sum(numbers) {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
}

function averageMark(marks) {
  return sum(marks) / marks.length;
}

function makeReport(name, marks) {
  return name + ": " + averageMark(marks).toFixed(2);
}

console.log(makeReport("Аман"));
```

Страница с этим `app.js`, открытая через Live Server, покажет в консоли:

```plain-out
TypeError: numbers is not iterable
    at sum (http://127.0.0.1:5500/app.js:3:19)
    at averageMark (http://127.0.0.1:5500/app.js:10:10)
    at makeReport (http://127.0.0.1:5500/app.js:14:24)
    at http://127.0.0.1:5500/app.js:17:13
```

Читается снизу вверх, как история: на строке 17 кто-то позвал `makeReport`,
та позвала `averageMark`, а та — `sum`, и вот там всё сломалось.

**Верхняя строка — место падения, нижняя — место причины.** Упало
в `sum`, но виновата не она: ей передали `undefined`, потому что
в самом низу, на строке 17, забыли второй аргумент. Чинить надо строку 17, а не
`sum`.

Отсюда правило чтения: **идите по стеку снизу вверх, пока не найдёте свою
строку**. Если верхние строки — это внутренности браузера или чужой библиотеки,
ошибка почти наверняка всё равно ваша: вы дали им не то.

## Часть 2, раздел 10. Четыре ошибки модуля в одном месте {#errors}

За три дня мы набрали четыре ошибки, которые повторяются чаще остальных. Вот они рядом,
чтобы узнавать их по одному взгляду.

| Что видно | Что произошло | Откуда |
| --- | --- | --- |
| `TypeError: x is not a function` | вызвали то, что функцией не является | день 12 |
| результат `undefined`, ошибки нет | забыли `return` | день 12 |
| стрелка вернула `undefined` | фигурные скобки выключили неявный возврат | день 13 |
| аргумент «не дошёл» | перепутан порядок параметров | день 14 |

**Первая** обычно значит, что в переменной лежит не функция, а её результат.
Одна лишняя пара скобок при сохранении — и дальше вызывать нечего:

```js
const found = countPresent([1, 0, 1]);   // в found лежит число 2
found();                                 // TypeError: found is not a function
```

Рядом живёт её близкая родственница — опечатка в имени. Текст другой, и это подсказка:
«не функция» значит «нашёл, но вызвать не могу», а «не определено» — «не нашёл вовсе»:

```js
countPresnt([1, 0, 1]);
// ReferenceError: countPresnt is not defined
```

Вторая из них — самая частая в модуле. Выглядит так:

```js
function countPresent(present) {
  let came = 0;
  for (const p of present) {
    if (p === 1) {
      came += 1;
    }
  }
}                          // ← return забыли

const answer = countPresent([1, 0, 1]);
console.log(answer);                      // undefined
console.log(percentOf(answer, 3));        // NaN
console.log(`Пришло ${answer} из 3`);     // "Пришло undefined из 3"
```

Обратите внимание, как ошибка расползается: сначала `undefined`, потом
`NaN`, потом слово «undefined» прямо в тексте отчёта. Увидев `NaN`
или «undefined» в готовой строке, **ищите забытый `return`**.

**Третья** — тот же забытый возврат, только у стрелочной функции,
где его легко не заметить. Фигурные скобки выключают неявный возврат:

```js
const isFive = (mark) => { mark === 5 };

isFive(5);                  // undefined, а не true
[5, 4, 5].filter(isFive);   // [] — ни одной пятёрки не нашлось
```

Беда в том, что `filter` не жалуется: `undefined` для него просто
«не подошло», и он честно отбирает пустой список. Убрать скобки — и всё встаёт на место:

```js
const isFive = (mark) => mark === 5;

[5, 4, 5].filter(isFive);   // [5, 5]
```

Четвёртая ошибка коварнее: программа не падает и ничего подозрительного не печатает.

```js
percentOf(3, 5);   // 60   — пришло 3 из 5
percentOf(5, 3);   // 166.66666666666669 — тот же вызов, аргументы местами
```

Никакой ошибки: оба аргумента — числа, деление работает. Спасает только проверка
на знакомых данных — если вы знаете, что ответ около 60, число больше ста сразу
бросится в глаза.

## Часть 2, раздел 11. Уменьшай вход {#minimal}

Последний приём отладки, самый сильный. Если функция падает или врёт на списке
из ста студентов, **не читайте список — уменьшайте его**.

Допустим, в `percentOf` забыли проверку `total === 0` — как
в куче из раздела 1. На полном журнале в отчётах где-то вылезает `NaN`:

```js
makeReport(["Аман", "Мерет"], [1, 1]);   // "Пришло 2 из 2 (100%)" — в порядке
makeReport(["Аман"], [1]);               // "Пришло 1 из 1 (100%)" — в порядке
makeReport([], []);                      // "Пришло 0 из 0 (NaN%)" — вот он
```

Самый маленький вызов, на котором беда ещё видна, и есть ваш случай. Дальше он
помещается в голове целиком: ноль разделить на ноль — `NaN`.

Чаще всего минимальный вызов с ошибкой оказывается именно пустым — `[]`,
`""`, `0`, вызов без аргументов. Почти любая функция, написанная
без оглядки, ломается на пустоте: деление на ноль, обращение к первому элементу
несуществующего списка, цикл, который ни разу не выполнился.

## Часть 3, раздел 12. Как читать незнакомую функцию {#read}

Половина работы программиста — чтение чужого кода: учебника, библиотеки, однокурсника,
себя полгода назад. Читать его подряд, строка за строкой, — самый медленный способ.
Есть порядок получше.

```js
function f(a, b) {
  let r = "";
  for (const x of a) {
    if (x.length > b) {
      r = r + x + " ";
    }
  }
  return r;
}
```

Имена ничего не говорят — так бывает часто. Разбираем по слоям.

<Scheme src="scheme-read.svg">Читаем не сверху вниз, а от результата к началу. Имя — итог разбора, а не его начало</Scheme>

Проверим догадку одним вызовом:

```js
const names = ["Аман", "Мерет", "Гүлнар", "Сапар", "Огулджан"];
f(names, 5);    // "Гүлнар Огулджан "
```

Сошлось: имена длиннее пяти букв, через пробел. «Мерет» и «Сапар» ровно по пять,
поэтому их нет — `>`, а не `>=`. Такие мелочи проверяют
вызовом, а не чтением.

### Если не понимается вообще

Бывает, что четыре слоя не помогают: код слишком запутан. Тогда работает грубый,
но надёжный приём — **запустить на самом маленьком входе, какой только
возможен**, и смотреть, что получится.

```js
function h(s, c) {
  let n = 0;
  for (const x of s) n += x === c ? 1 : 0;
  return n;
}

h("а", "а");     // 1
h("б", "а");     // 0
h("аба", "а");   // 2
```

Три вызова по одной-три буквы, и функция раскрылась: буква совпала — один,
не совпала — ноль, в «аба» две «а» — два. Значит, она считает, **сколько раз
буква встречается в строке**. Прочесть это из кода было можно, но так — быстрее
и надёжнее.

Приём тот же, что «уменьшай вход» из части 2, только цель другая: там искали ошибку,
здесь — смысл. Помогает одно и то же: пример должен помещаться в голове целиком.

## Часть 3, раздел 13. Крайние случаи {#edges}

Разобрали — теперь проверьте на краях. Четыре вызова, которые стоит сделать с любой
незнакомой функцией:

| Вызов | Что проверяем | Наш случай |
| --- | --- | --- |
| `f([], 5)` | пустой вход | `""` — хорошо |
| `f(names, 10)` | ничего не подошло | `""` — хорошо |
| `f(names, 0)` | подошло всё | все пять имён |
| `f()` | аргументов нет | `TypeError` — падает |

Три из четырёх в порядке, четвёртый падает. Это не обязательно плохо: функция, которую
зовут из одного места, имеет право рассчитывать на нормальный вход. Плохо другое —
**возвращаемая строка заканчивается лишним пробелом**, и это видно только
при внимательном взгляде:

```js
f(names, 5);              // "Гүлнар Огулджан " ← пробел в конце
f(names, 5).length;       // 16, а не 15
```

Такие хвосты вылезают потом в самом неудобном месте. Ловятся они просто: смотреть
на результат в кавычках, а не на глаз.

## Часть 3, раздел 14. Переписывание маленькими шагами {#rewrite}

Переписываем, и после каждого шага проверяем, что ответ не изменился. Шагов четыре.

**Шаг 1 — имена.** Ничего не трогаем, кроме слов. Ответ обязан остаться
прежним.

```js
function longNames(names, minLength) {
  let result = "";
  for (const name of names) {
    if (name.length > minLength) {
      result = result + name + " ";
    }
  }
  return result;
}
```

**Шаг 2 — чиним хвост.** Разделитель ставим не после элемента, а перед —
кроме самого первого. Приём тот же, что в `listMissing` из части 1.

```js
function longNames(names, minLength) {
  let result = "";
  for (const name of names) {
    if (name.length > minLength) {
      if (result !== "") {
        result += ", ";
      }
      result += name;
    }
  }
  return result;
}

longNames(names, 5);   // "Гүлнар, Огулджан" — без хвоста
```

**Шаг 3 — умолчание.** Пять букв — разумный порог по умолчанию, и вчерашний
день позволяет записать его в заголовке:

```js
function longNames(names, minLength = 5) {   // изменился только заголовок
  let result = "";
  for (const name of names) {
    if (name.length > minLength) {
      if (result !== "") {
        result += ", ";
      }
      result += name;
    }
  }
  return result;
}

longNames(names);      // "Гүлнар, Огулджан"
longNames(names, 3);   // "Аман, Мерет, Гүлнар, Сапар, Огулджан"
```

**Шаг 4 — проверка на краях ещё раз.** `longNames([])` даёт
пустую строку, `longNames(names, 100)` — тоже. Готово.

<Important>
Главное в этом разделе — **шаги, а не результат**. Соблазн переписать всё
разом велик, но тогда при первой же поломке непонятно, какое из пяти изменений
виновато. Один шаг — одна проверка.
</Important>

### Чек-лист: функция готова

Шесть вопросов, которые стоит задать своей функции, прежде чем считать её сделанной.
Пройдите их по `longNames` — она их проходит.

| Вопрос | Что проверяем |
| --- | --- |
| Имя говорит, что она делает? | глагол или `is`/`has`, без цифр и «и» |
| Дело одно? | в честном имени нет союза |
| Параметров не больше трёх? | иначе делится на две |
| Возвращает всегда один тип? | не число в одном случае и строка в другом |
| Работает на пустом входе? | `[]`, `""`, `0`, вызов без аргументов |
| Зависит только от параметров? | не читает и не меняет внешние переменные |

Последний вопрос — самый недооценённый. Функцию, которая зависит только от параметров,
можно проверить одним вызовом, перенести в другой файл и вызвать в любом порядке.
С той, что читает внешнюю переменную, так не выйдет:

```js
let minLength = 5;

function longNamesBad(names) {
  // порог берётся снаружи — вызов сам по себе ничего не значит
}

function longNames(names, minLength = 5) {
  // порог виден в вызове: longNames(names, 3)
}
```

Вторая версия к тому же документирует себя: по вызову `longNames(names, 3)`
видно всё, а по `longNamesBad(names)` — надо идти искать, чему сейчас
равен `minLength`.

## Часть 3, раздел 15. «Табель» целиком {#tabel}

Соберём программу курса в том виде, к которому её привёл весь модуль. Здесь есть всё
за четыре дня: объявления и `return` из дня 12, стрелки из дня 13, умолчания
и остаточный параметр из дня 14 — и сегодняшнее разделение по смыслу.

```js
const MIN_MARK = 2;
const MAX_MARK = 5;

// проверки — стрелочные, коротким телом
const isValidMark = (mark) =>
  typeof mark === "number"
  && !Number.isNaN(mark)
  && mark >= MIN_MARK
  && mark <= MAX_MARK;

const isFive = (mark) => mark === MAX_MARK;

// расчёты — каждый своей функцией
const sum = (numbers) => {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
};

const average = (numbers) =>
  numbers.length === 0 ? 0 : sum(numbers) / numbers.length;

function verdict(avg, excellent = 4.5, good = 3.5, pass = 2.5) {
  if (avg >= excellent) return "отличник";
  if (avg >= good) return "хорошист";
  if (avg >= pass) return "троечник";
  return "надо подтянуть";
}

// сборка отчёта — одна функция сверху
function makeReport(name = "без имени", ...marks) {
  const valid = marks.filter(isValidMark);

  if (valid.length === 0) {
    return `${name}: годных оценок нет`;
  }

  const avg = average(valid);
  return `${name}: ${valid.length} из ${marks.length}, `
    + `средний ${avg.toFixed(2)} — ${verdict(avg)}, `
    + `пятёрок ${valid.filter(isFive).length}`;
}

console.log(makeReport("Аман", 5, 4, 9, 3, 5, 0, 4, 5));
console.log(makeReport("Мерет", 3, 3, 4));
console.log(makeReport("Гүлнар", 9, 0, "пять"));
console.log(makeReport("Сапар", 5, 5, 4, 5));
console.log(makeReport("Огулджан"));
```

1. По каким признакам кусок кода просится в отдельную функцию?
   <Answer>Его можно назвать одним глаголом; над ним хочется написать
   комментарий-заголовок; он повторяется; его хочется проверить отдельно.
   Длина куска признаком не является.</Answer>
2. Функция вернула `undefined`, но ошибки в консоли нет. Что проверять первым?
   <Answer>Забытый `return`. У стрелочной функции — ещё и фигурные скобки,
   которые выключают неявный возврат. Дальше ошибка расползается:
   `undefined` превращается в `NaN` или в слово
   «undefined» внутри готовой строки.</Answer>
3. В каком порядке читается стек вызовов и что находится в его нижней строке?
   <Answer>Снизу вверх. Внизу — то место, откуда всё началось, обычно ваша строка
   и настоящая причина. Вверху — место, где программа упала, и оно часто
   ни в чём не виновато.</Answer>
4. Почему `console.log("вошло:", present)` лучше, чем
   `console.log(present.length)`?
   <Answer>Длина есть и у строки, и у массива, поэтому по одной длине не видно, что
   в функцию пришло не то. Печать значения целиком показывает и содержимое,
   и тип.</Answer>
5. В каком порядке разбирают незнакомую функцию?
   <Answer>Сначала `return` — он говорит, зачем функция нужна. Потом
   параметры: как их используют, такого они и типа. Потом ветки: что функция
   пропускает, а что берёт. Имя придумывают последним — и сразу вписывают в код.</Answer>
