# Day 16. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder `day-16`.</Subtitle>

## Warm-up

<Task title="1. The edges of a string" level="easy" time="6">
<Goal>see the difference between the three ways to take a character.</Goal>

Take your name and print:

- its length;
- the first character in three ways — `[0]`, `charAt(0)`, `at(0)`;
- the last character in two ways — through `length` and through `at(-1)`;
- what `[99]`, `charAt(99)` and `at(99)` return.

<Hint>
Print the last three results with labels:
`console.log("charAt:", name.charAt(99))`. An empty string will leave an empty place
after the label, `undefined` will be printed as a word.
</Hint>

<Criteria>
- all nine values are written down;
- it is named which of the three ways returned an empty string;
- it is explained why the last index is `length - 1`;
- it is written down what `at(-1)` returns for the empty string `""`.
</Criteria>
</Task>

<Task title="2. Predict first: slice or substring" level="easy" time="7">
<Goal>catch the differences between two similar methods.</Goal>

Predict all six results, then check.

```js
const word = "Turkmenistan";

word.slice(0, 4);
word.slice(4, 2);
word.slice(-6);

word.substring(0, 4);
word.substring(4, 2);
word.substring(-6);
```

<Hint>
One pair will match, two will differ. They will differ where the boundaries stand
“wrong”: the second is to the left of the first, or a negative one.
</Hint>

<Criteria>
- six predictions are written down before checking;
- both pairs that differed are found;
- for each one it is explained what `substring` did;
- it is written down which method you will write and why.
</Criteria>
</Task>

<Task title="3. Cleaning the input" level="easy" time="7">
<Goal>compare two names the way a person would.</Goal>

Write `sameName(a, b)`, which treats these pairs as the same:

```js
sameName("  AmAn ", "aman");      // true
sameName("Meret", "meret  ");     // true
sameName("Aman", "Meret");        // false
sameName("  ", "");               // true
sameName("Aman Meret", "AmanMeret");  // false
```

<Hint>
You have to bring **both** sides to one form, not just one. The last
pair reminds you that `trim` touches only the edges.
</Hint>

<Criteria>
- all five calls give what is written;
- it is explained why the fourth pair is `true`;
- it is explained why the fifth is `false`;
- it is written down what breaks if you clean only the first argument.
</Criteria>
</Task>

## Main tasks

<Task title="4. Search without traps" level="medium" time="12">
<Goal>understand why `indexOf` must not be put into a condition.</Goal>

```js
const text = "Aman Meret";

console.log(text.indexOf("Aman"), Boolean(text.indexOf("Aman")));
console.log(text.indexOf("Meret"), Boolean(text.indexOf("Meret")));
console.log(text.indexOf("Sapar"), Boolean(text.indexOf("Sapar")));
```

Run it and explain each of the three lines. Then write
`hasName(text, name)` in two ways — through `indexOf`
and through `includes` — and check it on all three names.

<Hint>
Two of the three `Boolean` results are wrong, and wrong
in different ways: in one case “found, but got false”, in the other “not found,
but got true”.
</Hint>

<Criteria>
- for all three lines it is written down what was printed and why;
- both situations where a condition would have lied are named;
- both versions of `hasName` are written and give the same answers;
- a check that the search is case-sensitive is added — with an example;
- it is written down which version you will keep in your code.
</Criteria>
</Task>

<Task title="5. Aligning columns" level="medium" time="13">
<Goal>build a table from strings without typing spaces by hand.</Goal>

Print a table of cities so that the numbers stand in an even column:

```js
const W = 10;

function row(city, people) {
  return city.padEnd(W) + String(people).padStart(8);
}

console.log(row("Mary", 126000));
console.log(row("Ashgabat", 1030000));
console.log(row("Turkmenabat", 253000));
```

One line will stick out of the column. Find it, explain the cause and fix it —
so that the table does not break when any new city is added.

<Hint>
`padEnd(10)` does nothing to a string that already has more than
ten characters. So the width cannot be chosen at random — it has to be calculated
from the longest name.
</Hint>

<Criteria>
- the line that stuck out and the cause are named;
- the width is calculated from the list, not written as a number;
- a fourth city with a long name is added — the table did not break;
- a header with the column titles is added, aligned the same way;
- under the header there is a line from `repeat` of the right width.
</Criteria>
</Task>

<Task title="6. A plus turns into a template" level="medium" time="12">
<Goal>learn to read and write template literals.</Goal>

Rewrite each string as a template literal and check that the result matches
to the character.

```js
const name = "Aman";
const count = 6;
const total = 8;
const avg = 4.333;

const a = name + ": " + count + " of " + total + ", average " + avg.toFixed(2);
const b = "Name: " + name.toUpperCase() + " (letters: " + name.length + ")";
const c = "Result: " + (avg >= 4.5 ? "excellent" : "good");
```

Then the other way around: write with pluses what you got in the template literal
with a line break from the lecture, and explain why it is inconvenient.

<Hint>
Inside `${}` you can write any expression — a method call,
arithmetic, the ternary operator. Parentheses around the ternary inside
`${}` are not needed.
</Hint>

<Criteria>
- all three strings are rewritten, the results are compared with the original ones;
- the second one uses both `toUpperCase` and `length`;
- in the third one the ternary operator stands inside `${}`;
- it is shown how to write a line break with pluses, and it is named why that is worse;
- it is written down where you will keep the plus and where you will switch to a template.
</Criteria>
</Task>

## Starred tasks

<Task title="8. Initials" level="hard" time="10">
<Goal>combine several methods in one task.</Goal>

Write `initials(fullName)`, which makes initials out of a full name.

<Example>
```js
initials("Gülnar Yklymowa");      // "G. Y."
initials("aman");                 // "A."
initials("  meret hojaýew  ");    // "M. H."
```

</Example>

Use only today’s methods: `trim`, `indexOf`,
`slice`, `at`, `toUpperCase`.

<Hint>

Here the pair `indexOf(" ")` and two `slice` calls replace it.
Think separately about what to do when there is no space at all.
</Hint>

<Criteria>
- all three examples give exactly what is written;
- the case without a space is handled by a separate branch;
- extra spaces at the edges do not break the result;
- it is checked on a name of three words — it is written down what came out,
  and it is decided whether that is acceptable;
- it is written down what `at(0)` and `charAt(0)` return for an empty
  name, and which of the two troubles is easier to notice.
</Criteria>
</Task>

</Task>
