1. Строка не меняется

Строки мы пишем с третьего дня: складываем, сравниваем, выводим. Сегодня узнаем, что у них есть два десятка встроенных умений — и почти все они понадобятся уже в проектах этого курса.

Начать надо с главного свойства, без которого половина методов выглядит странно. Строку нельзя изменить. Совсем. Попробуйте заменить первую букву:

const name = "аман";
name[0] = "А";

console.log(name);   // "аман" — ничего не изменилось

Ошибки нет, присваивание просто не сработало. В строгом режиме из дня 4 язык хотя бы скажет, в чём дело:

"use strict";
const name = "аман";
name[0] = "А";
// TypeError: Cannot assign to read only property '0' of string 'аман'
Это третий случай в курсе, когда поведение зависит от режима: в обычном — тишина, в строгом — ошибка. Первые два были на дне 4 (запись в необъявленную переменную) и на дне 14 (два параметра с одним именем).

Как же тогда «поменять» букву? Никак — собрать новую строку:

let firstName = "аман";
firstName = "А" + firstName.slice(1);

console.log(firstName);   // "Аман"

Отсюда правило, которое пригодится весь день: ни один метод строки не меняет саму строку. Все они возвращают новую, а старая остаётся как была. Поэтому результат метода обязательно надо куда-то положить, иначе он пропадёт:

let input = "  Аман  ";
input.trim();           // вернуло "Аман", но никуда не записали
console.log(input);     // "  Аман  " — как было

input = input.trim();   // вот так правильно
console.log(input);     // "Аман"

Отсюда — цепочки

У свойства «всегда возвращать новую строку» есть приятное следствие. Раз результат — тоже строка, у него сразу можно вызвать следующий метод. И ещё один. Получается цепочка:

"  АмАн  ".trim().toLowerCase();                       // "аман"
"  АмАн  ".trim().toLowerCase().at(0).toUpperCase();   // "А"

Читается слева направо, по шагам: взяли строку, отрезали пробелы, перевели в нижний регистр, взяли первый символ, подняли его в верхний. Каждый шаг делает новую строку и передаёт её дальше, а исходная остаётся нетронутой.

Четыре шага — и из грязного ввода получилась первая буква как надо. Такие цепочки в две-три ссылки пишут постоянно; длиннее четырёх делать не стоит, потому что читать становится трудно.

Важно только одно: порядок шагов меняет результат. Сравните:

"  Аман  ".slice(0, 4);          // "  Ам"   отрезали вместе с пробелами
"  Аман  ".trim().slice(0, 4);   // "Аман"   сначала почистили

2. Длина и символы

Длина — это свойство length, без скобок. Мы им уже пользовались для массивов; у строк оно считает символы:

"Аман".length;     // 4
"Гүлнар".length;   // 6
"".length;         // 0

Символы нумеруются с нуля, как всё в языке. Достать один символ можно тремя способами, и они немного разные:

const name = "Гүлнар";

name[0];         // "Г"
name.charAt(0);  // "Г"
name.at(0);      // "Г"

Разница между тремя способами видна на краях — когда символа по такому индексу нет:

Запросname[i]charAt(i)at(i)
символ есть"Г""Г""Г"
индекс 99undefined""undefined
индекс −1undefined"""р"
 
const name = "Гүлнар";

name.at(-1);                // "р"      последний символ
name[name.length - 1];      // "р"      то же самое, длиннее
name.charAt(99);            // ""       пустая строка, а не undefined!
name.at(99);                // undefined
charAt возвращает пустую строку там, где два других дают undefined. Это ловушка при проверке: if (name.charAt(99)) не сработает, потому что пустая строка ложна, — но и if (name.at(99)) не сработает по той же причине. Проверять надо длину.

И ещё одно, важное на будущее: length считает не «буквы», а единицы, из которых строка собрана внутри. Для букв любого алфавита это одно и то же, а для эмодзи — нет:

"Аман".length;   // 4
"🙂".length;     // 2 — один значок, а длина два

Пока просто запомните этот факт; подробный разбор — в курсе 2, где будет глава о кодировках.

3. Поиск куска

Три метода, которые отвечают на вопрос «есть ли это в строке».

const text = "Аман Мерет Аман";

text.indexOf("Аман");       // 0    первое совпадение
text.indexOf("Аман", 1);    // 11   искать начиная с позиции 1
text.lastIndexOf("Аман");   // 11   последнее совпадение
text.indexOf("Сапар");      // -1   не нашлось

indexOf отдаёт позицию, а если не нашёл — минус единицу. Не ноль, не undefined. Ноль здесь означает «нашёл в самом начале», и это вечный источник путаницы:

if (text.indexOf("Аман")) {      // ОШИБКА: 0 — это ложь
  console.log("нашлось");
}

if (text.indexOf("Аман") !== -1) {   // правильно
  console.log("нашлось");
}

Именно поэтому появился includes — он отвечает true или false, и путать нечего:

text.includes("Мерет");   // true
text.includes("мерет");   // false — регистр важен!
Поиск в строке различает большие и маленькие буквы. Это касается всех методов дня. Как с этим жить — в разделе 7.

Как найти все совпадения

Второй аргумент indexOf — «искать начиная отсюда» — нужен именно для этого. Сам по себе метод находит только первое совпадение, но если каждый раз сдвигать точку старта за найденное, получится обход всех:

const text = "Аман Мерет Аман Сапар Аман";
let from = 0;
let pos = text.indexOf("Аман", from);

while (pos !== -1) {
  console.log("нашли на позиции", pos);   // 0, потом 11, потом 22
  from = pos + 1;
  pos = text.indexOf("Аман", from);
}

Цикл while из дня 10 здесь уместнее for: заранее неизвестно, сколько будет оборотов. И обратите внимание на from = pos + 1 — без сдвига хотя бы на единицу поиск нашёл бы то же самое место снова, и цикл не кончился бы никогда.

4. Начало и конец

Частный случай поиска — проверить начало или конец строки. Для этого есть два метода с говорящими именами:

const text = "Аман Мерет Аман";

text.startsWith("Аман");     // true
text.endsWith("Аман");       // true
text.startsWith("Мерет");    // false
text.startsWith("Мерет", 5); // true — проверяем начиная с позиции 5

Второй аргумент у startsWith сдвигает точку отсчёта. У endsWith он работает иначе — задаёт, где считать концом строки.

Эти методы читаются лучше, чем indexOf(...) === 0, и именно поэтому их стоит предпочитать. Сравните две записи одного и того же:

const fileName = "index.html";

if (fileName.indexOf(".html") === fileName.length - 5) { }   // поди пойми
if (fileName.endsWith(".html")) { }                          // сразу ясно

5. Отрезаем: slice

Главный метод для вырезания куска. Берёт две границы: откуда и докуда, не включая.

const word = "Туркменистан";

word.slice(0, 4);   // "Турк"      с 0 по 4, четвёртый не входит
word.slice(4);      // "менистан"  без второй границы — до конца
word.slice(-6);     // "нистан"    отрицательная — считаем с конца

Удобно думать так: граница — это не символ, а промежуток между символами. Тогда slice(0, 4) читается как «от начала до промежутка номер 4», и длина результата получается ровно 4 − 0.

Если границы перепутаны местами, slice честно отдаёт пустую строку:

word.slice(4, 2);   // "" — вторая граница левее первой

Что будет на краях

slice никогда не падает и не жалуется на границы за пределами строки — он просто обрезает их до разумных. Это удобно и стоит знать наизусть:

word.slice(0, 100);   // "Туркменистан"  граница больше длины — до конца
word.slice(100);      // ""              начало за концом — пусто
word.slice(-100);     // "Туркменистан"  слишком далеко назад — с начала

word.slice(0, -1);    // "Туркмениста"   всё, кроме последнего
word.slice(-4, -1);   // "ста"           три символа перед последним

Отрицательной, как видно, может быть и вторая граница: приём «отрезать последний символ» пишут именно так.

ВызовЧто значит
slice(n)от n до конца
slice(0, n)первые n символов
slice(-n)последние n символов
slice(0, -n)всё, кроме последних n

Эти четыре записи закрывают почти все задачи на вырезание. Если понадобилось что-то посложнее — скорее всего, вы ищете не slice, а поиск из раздела 3.

6. substring и его странности

Есть второй метод для того же самого — substring. Работает почти так же, но в двух случаях ведёт себя неожиданно, и знать об этом надо, потому что в чужом коде он встречается часто.

const word = "Туркменистан";

word.substring(0, 4);    // "Турк"   — как slice
word.substring(4, 2);    // "рк"     — МЕНЯЕТ границы местами!
word.substring(-3, 4);   // "Турк"   — отрицательную считает нулём

7. Регистр

Два метода переводят строку в один регистр целиком:

"Аман".toUpperCase();   // "АМАН"
"АМАН".toLowerCase();   // "аман"

Главное их применение — не красота, а сравнение. Поиск и === различают регистр, а человек, который вводит имя, — нет:

const typed = "  АмАн  ";

typed === "Аман";                          // false
typed.trim().toLowerCase() === "аман";     // true

Отсюда общий приём: перед сравнением обе стороны приводят к одному виду. Обе — а не только одну, иначе сравнение всё равно развалится.

function sameName(a, b) {
  return a.trim().toLowerCase() === b.trim().toLowerCase();
}

sameName("  АмАн ", "аман");   // true

Разбор: почему имя не совпало

Это самая частая жалоба в программах с вводом: «я ввёл правильно, а оно не принимает». Разберём её по шагам — приёмом из дня 15.

const saved = "Аман";
const typed = "аман ";

typed === saved;   // false, а на экране строки выглядят одинаково

Шаг 1. Смотрим на границы строк. На глаз пробел в конце не виден, поэтому печатаем каждую строку в скобках — так видно, где она начинается и кончается:

console.log("[" + typed + "]", "[" + saved + "]");
// [аман ] [Аман]

Уже видно две разницы сразу: пробел справа и маленькая первая буква.

Шаг 2. Проверяем длины. Если строки «одинаковые», а длины разные — дело в невидимом символе:

typed.length;   // 5
saved.length;   // 4

Шаг 3. Чиним по одной причине за раз. Сначала пробел:

typed.trim() === saved;   // всё ещё false — значит, была и вторая причина

// шаг 4: теперь регистр
typed.trim().toLowerCase() === saved.toLowerCase();   // true

Обратите внимание на шаг 3: после первой починки сравнение всё ещё не работало. Это нормально и очень полезно — значит, причин было две, и если бы мы исправили обе разом, то не узнали бы об этом. Чинить по одной причине и проверять после каждой — та же привычка, что и в переписывании кода маленькими шагами.

Для турецкого у этих методов есть изъян: они не знают про букву ı без точки. "I".toLowerCase() даёт "i", хотя по правилам языка должно получиться "ı". Существует вариант с учётом языка — toLocaleLowerCase("tr"), — и он даёт правильный ответ, но разбирать его будем в курсе 2 вместе с основами Intl.

8. Чистим края

Пользователь почти всегда приносит лишние пробелы: скопировал с пробелом, нажал пробел перед отправкой. Три метода убирают их по краям — и только по краям:

const messy = "   Аман   ";

messy.trim();        // "Аман"
messy.trimStart();   // "Аман   "
messy.trimEnd();     // "   Аман"

Внутри строки пробелы остаются нетронутыми: "Аман Мерет".trim() так и останется с двумя пробелами в середине. Убирать их — задача для регулярных выражений из курса 2.

Правило простое: всё, что пришло от человека, сначала trim. Это одна из тех строк, которые пишут не задумываясь.

Что считается пробелом

«Пробелы» для trim — это не только сам пробел. Он убирает ещё и табуляцию \t, и перенос строки \n, и несколько редких символов, которые выглядят как пустое место. Среди них — неразрывный пробел, тот самый, что приходит из Word и с веб-страниц: его trim тоже снимает.

Но есть и символы, которые выглядят как пустота, а пробелом не считаются. Самый известный — «пробел нулевой ширины». Строка с ним после trim останется длиннее, чем кажется, и сравнение не сработает, хотя на экране всё выглядит одинаково.

Если имя не совпадает, а trim уже вызван, — сравните length обеих строк. Разница в длине при одинаковом виде значит, что внутри сидит невидимый символ, которого trim не знает. Убирать такие — задача для регулярных выражений из курса 2.

9. Дополняем до ширины

Обратная задача: сделать строку нужной длины, дописав символы. Слева — padStart, справа — padEnd.

"5".padStart(3, "0");      // "005"
"Аман".padEnd(10, ".");    // "Аман......"
"Аман".padEnd(10);         // "Аман      " — по умолчанию пробел

Первый аргумент — не «сколько добавить», а какой длины должен получиться результат. Если строка уже длиннее, не случится ничего:

"Туркменистан".padStart(5, "0");   // "Туркменистан" — без изменений

Добивка может быть из нескольких символов; тогда её повторяют и обрезают по месту:

"7".padStart(5, "ab");   // "abab7"

Главное применение — выровнять колонки в выводе, и именно им мы займёмся в разделе 15. Второе по частоте — числа с ведущими нулями: время, номера, коды.

const hours = 9;
const minutes = 5;

console.log(String(hours).padStart(2, "0") + ":" + String(minutes).padStart(2, "0"));
// "09:05"

10. Повторяем

Метод repeat повторяет строку заданное число раз. Чаще всего им рисуют разделительные линии:

"-".repeat(40);    // сорок дефисов
"ab".repeat(3);    // "ababab"
"ab".repeat(0);    // ""
"ab".repeat(3.5);  // "ababab" — дробное округляется вниз

У него две ошибки, и обе — RangeError, то есть «число вне допустимого диапазона»:

"abc".repeat(-1);
// RangeError: Invalid count value: -1

"abc".repeat(Infinity);
// RangeError: Invalid count value: Infinity

"abc".repeat(1e10);
// RangeError: Invalid string length — аргумент нормальный, строка не влезла

Разница между вторым и третьим сообщением стоит внимания: Invalid count value — «плохой аргумент», Invalid string length — «аргумент нормальный, но строка вышла слишком длинной». На MDN эти страницы озаглавлены по формулировкам Firefox и выглядят совсем иначе — в справочнике дня они помечены.

11. Склеиваем

Метод concat соединяет строки:

"Аман".concat(" ", "Мерет");   // "Аман Мерет"
"Аман" + " " + "Мерет";        // "Аман Мерет" — то же самое

Ровно то же делает обычный плюс из дня 6, и пишут почти всегда именно его.

Зачем тогда concat? Он принимает сколько угодно аргументов и иногда удобен, когда строки лежат в остаточном параметре из дня 14. Но в обычном коде договорённость такая: для двух-трёх кусков — плюс, для чего-то сложнее — шаблонная строка из следующего раздела.

12. Шаблонные строки

Вы видели их с третьего дня и пользовались, не разбирая. Пора разобрать. Шаблонная строка пишется в обратных кавычках, и внутрь неё можно вставлять значения через ${}:

const name = "Аман";
const avg = 4.333;

`${name}: средний ${avg.toFixed(2)}`;   // "Аман: средний 4.33"

Сравните с плюсом: name + ": средний " + avg.toFixed(2) — то же самое, но кавычки и пробелы внутри них приходится считать глазами.

Внутри ${} помещается любое выражение, а не только имя переменной: вызов метода, арифметика, даже тернарный оператор из дня 7.

`длина имени: ${name.length}, в верхнем: ${name.toUpperCase()}`;
// "длина имени: 4, в верхнем: АМАН"

`Итог: ${avg >= 4.5 ? "отлично" : "хорошо"}`;
// "Итог: хорошо"

Второе умение шаблонных строк — перенос строки прямо в тексте. В обычных кавычках так нельзя:

const multi = `Первая строка
Вторая строка`;

console.log(multi);
// Первая строка
// Вторая строка

Если внутри шаблонной строки нужен сам знак доллара с фигурной скобкой, его пишут в обычных кавычках и подставляют:

`фигурные скобки: ${"${не подставится}"}`;
// "фигурные скобки: ${не подставится}"

13. Коды символов

Каждый символ внутри — это число. Четыре метода переводят туда и обратно; в обычной работе они нужны редко, но знать их стоит.

"Аман".charCodeAt(0);        // 1040   код первого символа
"Аман".codePointAt(0);       // 1040   то же самое для обычных букв
String.fromCharCode(1040, 1084);   // "Ам"
String.fromCodePoint(128578);      // "🙂"

Разница между парами вылезает на тех же эмодзи, у которых length равен двум:

"🙂".charCodeAt(0);    // 55357  — половина значка, сама по себе бессмысленная
"🙂".codePointAt(0);   // 128578 — весь значок целиком

У fromCodePoint есть своя ошибка — когда номер не может быть кодом символа:

String.fromCodePoint(-1);
// RangeError: Invalid code point -1

String.fromCodePoint(3.14);
// RangeError: Invalid code point 3.14

14. Превращаем в строку

Три способа получить строку из чего угодно. Мы уже встречали их на дне 8, когда разбирали преобразование типов, — теперь смотрим со стороны строк.

String(5);           // "5"
String(null);        // "null"
String(undefined);   // "undefined"

(5).toString();      // "5"
(5).toString(2);     // "101" — в двоичной системе

"Аман".valueOf();    // "Аман"

Отличие только в краях: String() справляется с чем угодно, а toString() у null и undefined вызвать нельзя — получите TypeError. Поэтому в коде пишут String(x).

У toString есть бонус для чисел: второй аргумент — система счисления. А valueOf для обычной строки просто возвращает её саму и по-настоящему нужен только с «объектными строками», которые в этом курсе нам не встретятся.

15. «Табель»: выравниваем таблицу

До сих пор отчёт был просто строчками. Сегодняшние методы превращают его в таблицу с ровными колонками — и всё это без единого пробела, поставленного руками.

const MIN_MARK = 2;
const MAX_MARK = 5;
const NAME_WIDTH = 12;

const isValidMark = (mark) =>
  typeof mark === "number"
  && !Number.isNaN(mark)
  && mark >= MIN_MARK
  && mark <= MAX_MARK;

const isFive = (mark) => mark === MAX_MARK;

const sum = (numbers) => {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
};

const average = (numbers) =>
  numbers.length === 0 ? 0 : sum(numbers) / numbers.length;

function verdict(avg, excellent = 4.5, good = 3.5, pass = 2.5) {
  if (avg >= excellent) return "отличник";
  if (avg >= good) return "хорошист";
  if (avg >= pass) return "троечник";
  return "надо подтянуть";
}

// новое: шапка и строка таблицы
function makeHeader() {
  return "Имя".padEnd(NAME_WIDTH) + "Средн".padStart(6) + "Оц".padStart(4) + "  Вердикт";
}

function makeRow(name = "без имени", ...marks) {
  const valid = marks.filter(isValidMark);

  if (valid.length === 0) {
    return name.padEnd(NAME_WIDTH) + "нет годных оценок";
  }

  const avg = average(valid);
  return name.padEnd(NAME_WIDTH)
    + avg.toFixed(2).padStart(6)
    + String(valid.length).padStart(4)
    + "  " + verdict(avg);
}

const line = "-".repeat(40);

console.log(makeHeader());
console.log(line);
console.log(makeRow("Аман", 5, 4, 9, 3, 5, 0, 4, 5));
console.log(makeRow("Мерет", 3, 3, 4));
console.log(makeRow("Гүлнар", 9, 0, "пять"));
console.log(makeRow("Сапар", 5, 5, 4, 5));
console.log(makeRow("Огулджан", 4, 4, 5));
console.log(line);
Имя          Средн  Оц  Вердикт
----------------------------------------
Аман          4.33   6  хорошист
Мерет         3.33   3  троечник
Гүлнар      нет годных оценок
Сапар         4.75   4  отличник
Огулджан      4.33   3  хорошист
----------------------------------------

У первых четырёх числа те же, что вчера, — изменилась только подача. У «Огулджан» теперь есть оценки: 4, 4 и 5. Разберём, что где работает.

padEnd(12) для имени — дополняет справа, поэтому все имена начинаются в одной колонке. «Огулджан» длиной восемь, «Аман» длиной четыре, а отступ после них разный ровно настолько, чтобы следующая колонка совпала.

padStart(6) для среднего — дополняет слева, и числа выравниваются по правому краю, как в бухгалтерской таблице. Для чисел всегда так: единицы под единицами.

String(valid.length) — потому что padStart есть только у строк. Число сначала превращают в строку, и это ровно тот случай из раздела 14, ради которого String() и существует.

"-".repeat(40) — линия нужной ширины одной записью вместо сорока дефисов в кавычках.

Три опыта.

Первый. Поменяйте NAME_WIDTH на 6 и запустите. Что стало с колонками и почему виновата «Огулджан»? Как выбрать ширину так, чтобы таблица не развалилась на любых именах?

Второй. Замените padStart(6) на padEnd(6) у среднего балла. Сравните два вывода и объясните, почему для чисел принято выравнивание вправо.

Третий. Строка «нет годных оценок» ломает колонки. Сделайте так, чтобы она вставала в колонку «Вердикт», а в колонках «Средн» и «Оц» стояли прочерки.

Карта методов дня

Восемнадцать методов — много, если держать их списком. По делу они распадаются на четыре группы, и вопрос «какой метод взять» почти всегда решается выбором группы.

Чего сегодня не было

Три метода строк мы сознательно пропустили: split, replace и match. Они по-настоящему раскрываются вместе с регулярными выражениями, и разбирать их отдельно — только запутывать. Всё это — модуль I6 курса 2.

Завтра, на дне 17, берёмся за числа: Number, parseInt, toFixed, а во второй половине дня — первое знакомство с датами. toFixed мы, кстати, используем с третьего дня, ни разу не разобрав, — завтра этот долг закроется.

Где сегодняшнее встретится дальше

Этот день — из тех, что окупаются сразу. Строки лежат в основании всего, что мы будем делать дальше, и почти каждый следующий модуль опирается на сегодняшние методы.

// ОШИБКИ (все RangeError)
// "abc".repeat(-1)           → Invalid count value: -1
// "abc".repeat(1e10)         → Invalid string length
// String.fromCodePoint(-1)   → Invalid code point -1
  1. Почему text.trim() сама по себе ничего не исправляет?
    Ответ Строку изменить нельзя, поэтому все методы возвращают новую строку, а старая остаётся прежней. Результат надо присвоить: text = text.trim().
  2. Чем indexOf опасен в условии и что писать вместо него?
    Ответ Когда кусок найден в самом начале, indexOf возвращает 0, а ноль в условии — ложь. Нужно сравнивать с −1 явно (!== -1) или пользоваться includes.
  3. Что вернёт "Туркменистан".slice(4, 2) и что — substring(4, 2)?
    Ответ slice вернёт пустую строку, потому что вторая граница левее первой. substring молча поменяет границы местами и вернёт "рк". Поэтому в курсе мы пишем slice.
  4. Что означает число 3 в вызове "5".padStart(3, "0")?
    Ответ Длину результата, а не количество добавляемых символов. Получится "005" — три символа всего. Если строка уже длиннее трёх, метод не изменит ничего.
  5. Почему "АмАн".trim() не поможет сравнить имя с тем, что ввёл пользователь?
    Ответ trim убирает только пробелы по краям, а регистр оставляет. Для сравнения нужно привести к одному регистру обе стороны: a.trim().toLowerCase() === b.trim().toLowerCase().
