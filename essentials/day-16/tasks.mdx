# День 16. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 делаем в консоли, дальше — в папке `day-16`.</Subtitle>

## Разминка

<Task title="1. Края строки" level="easy" time="6">
<Goal>увидеть разницу между тремя способами взять символ.</Goal>

Возьмите своё имя и выведите:

- его длину;
- первый символ тремя способами — `[0]`, `charAt(0)`, `at(0)`;
- последний символ двумя способами — через `length` и через `at(-1)`;
- что вернут `[99]`, `charAt(99)` и `at(99)`.

<Hint>
Последние три результата выводите с метками:
`console.log("charAt:", name.charAt(99))`. Пустая строка оставит после
метки пустое место, `undefined` напечатается словом.
</Hint>

<Criteria>
- все девять значений записаны;
- названо, какой из трёх способов вернул пустую строку;
- объяснено, почему последний индекс — это `length - 1`;
- записано, что вернёт `at(-1)` для пустой строки `""`.
</Criteria>
</Task>

<Task title="2. Сначала предскажи: slice или substring" level="easy" time="7">
<Goal>поймать различия двух похожих методов.</Goal>

Предскажите все шесть результатов, потом проверьте.

```js
const word = "Туркменистан";

word.slice(0, 4);
word.slice(4, 2);
word.slice(-6);

word.substring(0, 4);
word.substring(4, 2);
word.substring(-6);
```

<Hint>
Одна пара совпадёт, две разойдутся. Разойдутся там, где границы стоят
«неправильно»: вторая левее первой или отрицательная.
</Hint>

<Criteria>
- шесть предсказаний записаны до проверки;
- найдены обе пары, которые разошлись;
- для каждой объяснено, что сделал `substring`;
- записано, какой метод вы будете писать и почему.
</Criteria>
</Task>

<Task title="3. Чистим ввод" level="easy" time="7">
<Goal>сравнить два имени так, как это сделал бы человек.</Goal>

Напишите `sameName(a, b)`, которая считает эти пары одинаковыми:

```js
sameName("  АмАн ", "аман");      // true
sameName("Мерет", "мерет  ");     // true
sameName("Аман", "Мерет");        // false
sameName("  ", "");               // true
sameName("Аман Мерет", "АманМерет");  // false
```

<Hint>
Приводить к одному виду надо **обе** стороны, а не одну. Последняя
пара напоминает, что `trim` трогает только края.
</Hint>

<Criteria>
- все пять вызовов дают то, что написано;
- объяснено, почему четвёртая пара — `true`;
- объяснено, почему пятая — `false`;
- записано, что сломается, если чистить только первый аргумент.
</Criteria>
</Task>

## Основные задания

<Task title="4. Поиск без ловушек" level="medium" time="12">
<Goal>понять, почему `indexOf` нельзя ставить в условие.</Goal>

```js
const text = "Аман Мерет";

console.log(text.indexOf("Аман"), Boolean(text.indexOf("Аман")));
console.log(text.indexOf("Мерет"), Boolean(text.indexOf("Мерет")));
console.log(text.indexOf("Сапар"), Boolean(text.indexOf("Сапар")));
```

Запустите и объясните каждую из трёх строк. Потом напишите
`hasName(text, name)` двумя способами — через `indexOf`
и через `includes` — и проверьте на всех трёх именах.

<Hint>
Два из трёх результатов `Boolean` — неправильные, и неправильные
по-разному: один случай «нашли, а получилось false», другой «не нашли,
а получилось true».
</Hint>

<Criteria>
- для всех трёх строк записано, что вывелось и почему;
- названы обе ситуации, где условие соврало бы;
- обе версии `hasName` написаны и дают одинаковые ответы;
- добавлена проверка, что поиск различает регистр, — с примером;
- записано, какую версию вы оставите в своём коде.
</Criteria>
</Task>

<Task title="5. Выравниваем колонки" level="medium" time="13">
<Goal>собрать таблицу из строк, не ставя пробелы руками.</Goal>

Напечатайте таблицу городов так, чтобы числа стояли ровной колонкой:

```js
const W = 10;

function row(city, people) {
  return city.padEnd(W) + String(people).padStart(8);
}

console.log(row("Мары", 126000));
console.log(row("Ашхабад", 1030000));
console.log(row("Туркменабат", 253000));
```

Одна строка выбьется из колонки. Найдите её, объясните причину и почините —
так, чтобы таблица не ломалась при добавлении любого нового города.

<Hint>
`padEnd(10)` ничего не сделает со строкой, в которой уже больше
десяти символов. Значит, ширину нельзя выбирать наугад — её надо вычислить
по самому длинному названию.
</Hint>

<Criteria>
- названа строка, которая выбилась, и причина;
- ширина вычисляется по списку, а не записана числом;
- добавлен четвёртый город с длинным именем — таблица не сломалась;
- добавлена шапка с заголовками колонок, выровненная так же;
- под шапкой линия из `repeat` нужной ширины.
</Criteria>
</Task>

<Task title="6. Плюс превращается в шаблон" level="medium" time="12">
<Goal>научиться читать и писать шаблонные строки.</Goal>

Перепишите каждую строку на шаблонную и проверьте, что результат совпал
до символа.

```js
const name = "Аман";
const count = 6;
const total = 8;
const avg = 4.333;

const a = name + ": " + count + " из " + total + ", средний " + avg.toFixed(2);
const b = "Имя: " + name.toUpperCase() + " (букв: " + name.length + ")";
const c = "Итог: " + (avg >= 4.5 ? "отлично" : "хорошо");
```

Потом наоборот: запишите плюсами то, что получилось в шаблонной строке
с переносом из лекции, и объясните, почему это неудобно.

<Hint>
Внутри `${}` можно писать любое выражение — вызов метода,
арифметику, тернарный оператор. Скобки вокруг тернарного внутри
`${}` не нужны.
</Hint>

<Criteria>
- все три строки переписаны, результаты сверены с исходными;
- во второй использованы и `toUpperCase`, и `length`;
- в третьей тернарный оператор стоит внутри `${}`;
- показано, как записать перенос строки плюсами, и названо, чем это хуже;
- записано, где вы оставите плюс, а где перейдёте на шаблон.
</Criteria>
</Task>

<Task title="7. «Табель»: таблица с шапкой" level="medium" time="13">
<Goal>применить выравнивание к программе курса.</Goal>

Скопируйте папку `day-15` в `day-16` и превратите отчёт
в таблицу:

- `makeHeader()` — шапка с колонками «Имя», «Средн», «Оц», «Вердикт»;
- `makeRow(name, ...marks)` — строка таблицы вместо прежней фразы;
- имя — `padEnd`, числа — `padStart`;
- линия из `repeat` под шапкой и в конце.

<Criteria>
- числа совпали со вчерашними — сверено построчно;
- колонки ровные на всех пяти студентах;
- объяснено, зачем понадобился `String()` перед
  `padStart`;
- строка «нет годных оценок» не ломает колонки;
- записано, какую ширину имени вы выбрали и почему.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Инициалы" level="hard" time="10">
<Goal>собрать несколько методов в одну задачу.</Goal>

Напишите `initials(fullName)`, которая из полного имени делает инициалы.

<Example>
```js
initials("Гүлнар Ыклымова");      // "Г. Ы."
initials("аман");                 // "А."
initials("  мерет ходжаев  ");    // "М. Х."
```
</Example>

Пользуйтесь только сегодняшними методами: `trim`, `indexOf`,
`slice`, `at`, `toUpperCase`.

<Hint>
Метода, который режет строку по пробелам, у нас ещё нет — он в курсе 2.
Здесь его заменяет пара `indexOf(" ")` и два `slice`.
Отдельно подумайте, что делать, когда пробела нет вовсе.
</Hint>

<Criteria>
- все три примера дают ровно то, что написано;
- случай без пробела обработан отдельной веткой;
- лишние пробелы по краям не ломают результат;
- проверено на имени из трёх слов — записано, что получилось,
  и решено, устраивает ли это;
- записано, что вернут `at(0)` и `charAt(0)` для пустого
  имени и какую из двух бед легче заметить.
</Criteria>
</Task>

<Task title="9. Четыре подвоха" level="hard" time="10">
<Goal>получить все ошибки дня и поймать самую тихую из них.</Goal>

Для каждого фрагмента сначала запишите предсказание, потом проверьте.

```js
// 1
let name = "аман";
name[0] = "А";
console.log(name);

// 2
console.log("abc".repeat(-1));

// 3
console.log("abc".repeat(1e10));

// 4
console.log(String.fromCodePoint(-1));
```

Потом добавьте первой строкой файла `"use strict";` и запустите
фрагмент 1 ещё раз.

<Hint>
Три фрагмента падают, один — нет. Тот, который не падает, и есть самый опасный:
он молча делает не то, что написано. Фрагменты 2, 3 и 4 запускайте по отдельности.
</Hint>

<Criteria>
- записаны предсказания до запуска;
- для трёх падающих записан точный текст ошибки из своей консоли;
- названо, чем сообщения фрагментов 2 и 3 отличаются по смыслу;
- для фрагмента 1 записаны оба поведения — с `"use strict"`
  и без;
- фрагмент 1 переписан так, чтобы имя действительно начиналось с большой
  буквы.
</Criteria>
</Task>
