# Day 17. Numbers and first dates

<Subtitle>A summary of the lecture: turn into a number, check, round, put a date.</Subtitle>

## From a string to a number

<Definition>
`Number()` is strict — either the whole string is a number, or `NaN`.
`parseInt` and `parseFloat` read from the left as much as they can.
</Definition>

| String | `Number` | `parseInt` | `parseFloat` |
| --- | --- | --- | --- |
| `"4.5"` | 4.5 | **4** | 4.5 |
| `"42px"` | **NaN** | 42 | 42 |
| `"px42"` | NaN | NaN | NaN |
| `""` | **0** | NaN | NaN |

<KeyPoint>
For data from a form we take `Number()`: it honestly reports garbage instead
of silently reading half of it.
</KeyPoint>

```js
parseInt("1010", 2);   // 10  — state the base explicitly
const day = "08";
parseInt(day, 10);     // 8   — this is how reliable code is written
```

## Checks

```js
Number.isNaN("abc");     // false — an honest check
isNaN("abc");            // true  — the old one, first turns it into a number
Number.isFinite("42");   // false
isFinite("42");          // true  — also the old one
Number.isInteger(4);     // true  — the best check of “an integer arrived”
const x = Number("five");
x === NaN;               // false — ALWAYS, this is not how you check
```

<Remember>
In new code — only the checks **with the `Number.` prefix**.
The old `isNaN` and `isFinite` quietly convert the argument.
</Remember>

## Rounding

```js
(4.333).toFixed(2);   // "4.33" — this is a STRING, not a number
(7).toFixed(2);       // "7.00"
(1.005).toFixed(2);   // "1.00" — not "1.01"

0.1 + 0.2;            // 0.30000000000000004
0.1 + 0.2 === 0.3;    // false
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON;   // true
```

Fractions are stored approximately — this is a property of binary notation, not of the language. So
money and marks are kept in integers, and a fraction is shown only at the output.

## Constants and numeral systems

```js
Number.MAX_SAFE_INTEGER;   // 9007199254740991 — the limit of exact integers
Number.EPSILON;            // 2.220446049250313e-16 — a threshold for comparing fractions

(255).toString(16);   // "ff"
parseInt("ff", 16);   // 255
// (255).toString(1)  → RangeError: toString() radix argument must be between 2 and 36
```

## Dates

<Definition>
A date inside is one number: milliseconds since 1 January 1970. That is why dates can be
subtracted.
</Definition>

```js
Date.now();                               // now, a number
const d = new Date(2026, 8, 22, 14, 5);   // 22 September 2026, 14:05

d.getFullYear();   // 2026
d.getMonth();      // 8  — SEPTEMBER, months from zero!
d.getDate();       // 22
d.getHours();      // 14
d.getMinutes();    // 5

const start = new Date(2026, 8, 1);
const end = new Date(2026, 8, 22);
(end.getTime() - start.getTime()) / (1000 * 60 * 60 * 24);   // 21 — the difference in days
```

<Remember>
**Months are numbered from zero**, and days from one. January is 0,
September is 8, December is 11. Month 12 moves into the next year.
</Remember>

```js
d.toLocaleDateString("en-GB");   // "22/09/2026"
d.toLocaleTimeString("en-GB");   // "14:05:00"

const bad = new Date("not a date");
String(bad);                     // "Invalid Date"
bad.getTime();                   // NaN
!Number.isNaN(bad.getTime());    // false — this is how a date is checked
```

<NoteBox>
**Three errors of the day, all `RangeError`:** a base outside 2…36,
too many digits in `toFixed`, `toISOString` of an invalid
date (`Invalid time value`).
\
**Not today:** parsing strings with a date, UTC methods, setters,
the modern replacement `Temporal` and date output settings through
`Intl` — all of this is course 2.
</NoteBox>
