# Day 17. Tasks

## Warm-up

<Task title="1. Fifteen cells" level="easy" time="6">
<Goal>see the three ways of conversion side by side.</Goal>

Fill in the table: five strings through three functions. Predict first, then check.

```js
const values = ["42", "4.5", "42px", "px42", ""];

// for each one: Number(v), parseInt(v), parseFloat(v)
```

<Hint>
Zero and `NaN` look different in the console, but in a table they are easy
to mix up. If in doubt, check with `Number.isNaN`. `typeof`
will not help here: the type of `NaN` is `"number"` too.
</Hint>

<Criteria>
- all fifteen cells are filled in;
- the string where `parseInt` differed from the other two is found;
- the string where `Number` gives 0 and the others `NaN` is found;
- it is written down which function you will take for data from a form and why.
</Criteria>
</Task>

<Task title="2. Predict first: which check" level="easy" time="7">
<Goal>tell the old and the new checks apart.</Goal>

```js
isNaN("abc");            isNaN("42");            isNaN(NaN);
Number.isNaN("abc");     Number.isNaN("42");     Number.isNaN(NaN);
isFinite("42");          Number.isFinite("42");  Number.isFinite(1 / 0);
```

<Hint>
All the differences come down to one thing: the functions without the `Number.` prefix
first turn the argument into a number, and the ones with the prefix do not.
</Hint>

<Criteria>
- nine predictions are written down before checking;
- all the pairs where the answers differed are found;
- the difference between the two families is stated in one sentence;
- it is explained why `Number.isFinite(1 / 0)` gives `false`.
</Criteria>
</Task>

<Task title="5. Money in fractions" level="medium" time="13">
<Goal>see the error with your own eyes and get around it.</Goal>

```js
const prices = [10.10, 20.20, 30.30];

let sum = 0;
for (const p of prices) {
  sum += p;
}

console.log(sum);
console.log(sum === 60.6);
```

It did not come out right. Rewrite the counting so that the comparison with `60.6`
gives `true` — counting in kopecks. Then compare three ways:
in fractions, with `toFixed` and in kopecks.

<Hint>
In kopecks means multiplying each price by 100, rounding to an integer, adding,
and dividing back only when printing. Rounding to an integer is
`Math.round` from day 6.
</Hint>

<Criteria>
- the exact value printed by the first version is written down;
- the version in kopecks gives `true` in the comparison;
- it is shown that `toFixed(2)` shows the value correctly but does not help with comparing —
  it is explained why;
- the rule is written down in one line: where to store, where to round;
- it is checked on three more prices with kopecks.
</Criteria>
</Task>

## Starred tasks

<Task title="8. How many days are left" level="hard" time="10">
<Goal>calculate a difference of dates and run into time.</Goal>

Write `daysBetween(from, to)` and check it on four pairs.

<Example>
```js
daysBetween(new Date(2026, 8, 22), new Date(2026, 11, 25));   // 94
daysBetween(new Date(2026, 11, 25), new Date(2026, 8, 22));   // -94
daysBetween(new Date(2026, 8, 22), new Date(2026, 8, 22));    // 0
daysBetween(new Date(2026, 8, 22, 14, 5), new Date(2026, 11, 25));   // ?
```
</Example>

<Hint>
The last pair will give a non-integer number, and that is correct: the first date has a time,
and the second one has midnight. Think about what is needed here — rounding or resetting
the time, and why the answer depends on the task.
</Hint>

<Criteria>
- the first three pairs give exactly what is written;
- for the fourth the exact number is written down and it is explained where the fraction comes from;
- a solution for the fractional case is proposed, the choice is explained;
- a check for an invalid date is added — the function must not return
  `NaN` silently;
- it is written down what the function returns if the order of the arguments is mixed up.
</Criteria>
</Task>
