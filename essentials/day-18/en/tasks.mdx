# Day 18. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder `day-18`.</Subtitle>

## Warm-up

<Task title="1. Twelve cells" level="easy" time="6">
<Goal>see the four kinds of rounding side by side, including on negatives.</Goal>

Fill in the table: three numbers through four ways. Predict first, then check.

```js
const values = [4.5, -4.1, -4.5];

// for each one: Math.round, Math.floor, Math.ceil, Math.trunc
```

<Hint>
Two cells will almost certainly differ from your prediction, and both are in the rows
with a minus. Think about what “down” means for a negative number.
</Hint>

<Criteria>
- all twelve cells are filled in;
- both rows where `floor` and `trunc` differed are found;
- it is explained why `Math.round(-4.5)` gives −4, not −5;
- it is written down which method you will take to “just drop the kopecks”.
</Criteria>
</Task>

<Task title="2. Predict first: max and min" level="easy" time="7">
<Goal>catch three unexpected answers.</Goal>

```js
Math.max(3, 7, 5);
Math.min(3, 7, 5);
Math.max();
Math.min();
Math.max(3, NaN, 5);
Math.max([3, 7, 5]);
```

<Hint>
The last four answers will surprise you. For the two with arguments the cause is the same: the function
got something other than you thought. For the two empty calls it is in what
`Math.max` and `Math.min` start counting from.
</Hint>

<Criteria>
- six predictions are written down before checking;
- it is explained why `Math.max()` gives `-Infinity`;
- it is explained why an array gives `NaN`;
- a loop is written that finds the maximum of an array through `Math.max`;
- it is checked that the loop works on an array of one element.
</Criteria>
</Task>

<Task title="3. Rolling a die" level="easy" time="7">
<Goal>write the formula of a random integer and check its boundaries.</Goal>

Write `randomInt(min, max)` and make 20 rolls of
`randomInt(1, 6)`. Then answer three questions, checking them with code:

- does 0 or 7 ever come out;
- do fractional values come out;
- what `randomInt(5, 5)` returns.

<Hint>
Twenty rolls are too few to see a skew, but enough to catch going out of bounds.
To check the boundaries make a loop of 10,000 rolls
with an “out of range” counter.
</Hint>

<Criteria>
- the formula is written down and works;
- over 10,000 rolls the “out of range” counter stayed at zero;
- it is written down what `randomInt(5, 5)` returned and why;
- it is explained why the formula has `+ 1`.
</Criteria>
</Task>

## Main tasks

<Task title="4. Rounding to a step" level="medium" time="12">
<Goal>master the technique “divide, round, multiply”.</Goal>

The price is `1234.567`. Get:

- to integers, to tens, to hundreds;
- down to a multiple of five;
- up to a multiple of fifty;
- to two digits after the point — **as a number**, not a string.

Then write `roundTo(value, step)`, which does all this in one
function, and check it on all six cases.

<Hint>
The last case is the step `0.01`. On 1234.567 it will come out right, but
`roundTo(0.7, 0.1)` will give an unexpected tail — look at what happens
when multiplying by a fractional step, and remember yesterday.
</Hint>

<Criteria>
- all six values are obtained and written down;
- `roundTo` works with the steps 1, 10, 100, 5, 50;
- for the step `0.01` and for `roundTo(0.7, 0.1)` it is written down
  what came out, and it is explained why;
- it is shown how the result differs from `toFixed(2)` —
  with `typeof`;
- a parameter “how to round” with a default value is added.
</Criteria>
</Task>

<Task title="5. A frequency counter" level="medium" time="13">
<Goal>prove with a counter that there is an error, although the program works.</Goal>

Compare two formulas over 60,000 rolls each, counting how many times
each outcome came out:

```js
Math.round(Math.random() * 6);              // version A
Math.floor(Math.random() * 6) + 1;          // version B
```

<Hint>
It is handy to count in an object: `counts[n] = (counts[n] || 0) + 1`.
Compare not the exact numbers — they are different for everyone — but the ratio between
the edge and the middle bars.
</Hint>

<Criteria>
- both frequency tables are obtained and written down;
- it is named how many outcomes each version has;
- it is written down roughly how many times less often the edges of version A come out than the middle;
- the cause is explained through the scheme from section 8 of the lecture;
- it is written down why such an error is not visible on 20 rolls.
</Criteria>
</Task>

<Task title="6. Guess the number" level="medium" time="12">
<Goal>build a game and check it without a single click.</Goal>

Write `checkGuess(guess, secret)`, which answers “higher”, “lower”,
“you got it!” or “this is not an integer”. Check all four branches.

Then write `stepsToGuess(secret)`, which plays against itself,
naming the middle of the remaining segment each time, and returns the number of moves.

<Hint>
The middle of the segment is `Math.floor((low + high) / 2)`. After each move
one of the ends moves: if the middle is less than the secret number, the new lower
end is `mid + 1`.
</Hint>

<Criteria>
- all four branches of `checkGuess` are checked with calls;
- `stepsToGuess` works for all numbers from 1 to 100;
- the worst case is found — how many moves and for which numbers;
- it is written down how many moves are needed for the range 1…1000, and it is checked with code;
- it is explained why the number of moves is about how many times the number can be divided
  in half.
</Criteria>
</Task>

## Starred tasks

<Task title="8. Geometry on the page" level="hard" time="10">
<Goal>combine four methods in one task.</Goal>

Write three functions and check them on the data from the example:

<Example>
```js
circleArea(5);              // 78.54   the area of a circle, to hundredths
circleLength(5);            // 31.42   the length of a circle
distance(0, 0, 3, 4);       // 5       the distance between points

```
</Example>

Round the results to hundredths **as a number**, not a string.

<Hint>

of the coordinates. Rounding to hundredths as a number is the technique from section 4 of the lecture.
</Hint>

<Criteria>
- all four calls give what is written;
- the rounding returns a number — checked with `typeof`;
- a shared function for rounding to hundredths is moved out;
- a function “the sine of an angle in degrees” is added and checked on 0, 30, 90;
- for 30 degrees the exact result before rounding is written down, and it is explained
  where the nines came from.
</Criteria>
</Task>

<Task title="9. Five catches" level="hard" time="10">
<Goal>bring together everything that behaves unexpectedly today.</Goal>

For each fragment first write down a prediction, then check
and explain the difference in one sentence.

```js
// 1
console.log(Math.floor(-4.1), Math.trunc(-4.1));

// 2
const marks = [3, 5, 4];
console.log(Math.max(marks));

// 3
console.log(Math.sin(90));

// 4
console.log(Math.round(4.6).toFixed(2));

// 5
console.log(typeof Math.sumPrecise);
```

<Hint>
Not one fragment crashes — all five quietly give something other than it seems. The fifth
depends on where you run it: in the browser and in Node the answer may
differ.
</Hint>

<Criteria>
- the predictions are written down before running;
- for all five it is written down what was printed, and the cause is named;
- fragments 1–4 are rewritten correctly;
- for fragment 5 it is written down what you got, and a conclusion is drawn whether
  this method can be used;
- it is written down which of the five catches is the most dangerous in a real program
  and why.
</Criteria>
</Task>
