## 1. Что такое массив {#what}

**Массив — это список значений, у которых есть порядок.** Одно имя — много значений.
Вместо пяти переменных `student1`, `student2`, `student3` держат один массив
`students` и обращаются к элементам по номеру.

Номер называется **индексом** и начинается с нуля. Это не прихоть языка: так считают почти во всех
языках программирования, потому что индекс означает «сколько шагов от начала».

Зачем это нужно, видно на простом примере. Представьте, что в классе 30 учеников и надо хранить их оценки.
Без массива пришлось бы завести тридцать переменных:

```js
const mark1 = 5;
const mark2 = 4;
const mark3 = 5;
// ... и так тридцать раз
```

А дальше начинается беспомощность: как посчитать средний балл? Как найти лучшую оценку? Как добавить
тридцать первого ученика? Каждый раз придётся править код руками. С массивом всё это делается несколькими
строками, а число учеников вообще перестаёт иметь значение:

```js
const marks = [5, 4, 5, 3, 4, 5];
console.log(marks.length);   // сколько всего — 6
```

Массивы — самая частая структура данных в работе. Вот что ими хранят каждый день:

- товары в корзине интернет-магазина;
- сообщения в чате, по порядку прихода;
- дела в списке задач;
- оценки, цены, температуры — любые ряды чисел;
- элементы, найденные на странице: все кнопки, все картинки (день 24).

<Scheme src="scheme-what.svg">Пять элементов, индексы от 0 до 4. Длина массива — 5, индекс последнего — 4</Scheme>

```js
const fruits = ["алма", "армыт", "üzüm", "erik", "hurma"];

console.log(fruits[0]);        // "алма"    — первый
console.log(fruits[4]);        // "hurma"   — пятый
console.log(fruits.length);    // 5         — сколько всего
console.log(fruits[5]);        // undefined — такого нет
```

<Analogy>
Массив — это полка с пронумерованными ячейками. Номер ячейки вы называете сами: «дай то, что лежит
в ячейке 2». Если такой ячейки нет, вам не кричат об ошибке — просто отвечают «ничего»
(`undefined`).
</Analogy>

## 2. Четыре способа создать массив {#create}

```js
// 1. Литерал — так пишут в 95% случаев
const marks = [5, 4, 5, 3];

// 2. Пустой массив, который заполним позже
const basket = [];

// 3. Array.of — из перечисленных значений
const one = Array.of(7);        // [7]

// 4. Array.from — из чего-то похожего на список
const letters = Array.from("Мары");   // ["М", "а", "р", "ы"]
```

<Mistake>
`new Array(7)` создаёт не массив с числом 7, а **пустой массив длиной 7**.
Поэтому `Array.of(7)` и `new Array(7)` дают разное:

```js
Array.of(7);      // [7]        — один элемент
new Array(7);     // [пусто × 7] — семь пустых мест
new Array(2.5);   // RangeError: Invalid array length
```

Вывод: пишите литерал `[7]` или `Array.of(7)`, а `new Array` не используйте.
</Mistake>

`Array.from` пригодится не только со строкой. Ей передают любой «похожий на список» объект:
список найденных на странице элементов, набор букв, результат `Set`. С этим мы встретимся
на дне 24 и в курсе 2.

## 3. Доступ к элементам и length {#access}

```js
const days = ["duşenbe", "şenbe", "ýekşenbe"];

days[1] = "sişenbe";     // заменили элемент
console.log(days);       // ["duşenbe", "sişenbe", "ýekşenbe"]

console.log(days.at(-1));           // "ýekşenbe" — последний
console.log(days[days.length - 1]); // то же самое, но длиннее

days.length = 2;         // длину можно изменить — массив обрежется
console.log(days);       // ["duşenbe", "sişenbe"]
```

Метод `at` удобен именно отрицательными числами: `at(-1)` — последний,
`at(-2)` — предпоследний. С положительными он работает как обычные скобки.

<ProTip>
Присваивание в несуществующий индекс не ошибка: `arr[10] = 1` растянет массив до 11 элементов,
а пустые места заполнит «дырами». Дыры ведут себя странно в некоторых методах, поэтому так лучше не делать —
добавляйте через `push`.
</ProTip>

### Дыры в массиве

MDN называет их «пустыми местами» (*empty slots*). Дыра — не `undefined`, а
отсутствие элемента вовсе. Появляется она тремя способами:

```js
const a = [1, 2, , , 5];   // две запятые подряд — две дыры
const b = [1, 2];
b[4] = 5;                  // записали дальше конца: дыры на местах 2 и 3
const c = [1, 2];
c.length = 5;              // удлинили через length: три дыры в конце
b.length;                  // 5
```

При чтении дыра неотличима от `undefined`. А вот методы поиска видят её
по-разному — как с `NaN` в разделе 6:

```js
const arr = [1, , 3];
arr[1];                    // undefined
arr.includes(undefined);   // true — includes считает дыру за undefined
arr.indexOf(undefined);    // -1 — indexOf дыры пропускает
```

Вывод прежний: не создавайте дыр. Добавляйте через `push`, а массив одинаковых
значений заполняйте методом `fill` из раздела 8.

### Перебрать массив по индексам

Раз у каждого элемента есть номер, по массиву можно пройти обычным циклом с дня 10. Счётчик начинается
с нуля и идёт, пока он меньше длины:

```js
const marks = [5, 4, 3];

for (let i = 0; i < marks.length; i++) {
  console.log(i + ": " + marks[i]);
}
// 0: 5
// 1: 4
// 2: 3
```

Условие `i < marks.length`, а не `i <= marks.length` — потому что последний
индекс на единицу меньше длины. Ошибка на единицу здесь настолько частая, что у неё есть имя: «ошибка
смещения на один». Признак — последний элемент `undefined`:

```js
for (let i = 0; i <= marks.length; i++) {   // ошибка: <= вместо <
  console.log(i + ": " + marks[i]);
}
// 0: 5
// 1: 4
// 2: 3
// 3: undefined — лишний шаг: индекса 3 в массиве нет
```

Если номера не нужны, короче писать `for...of`:

```js
for (const mark of marks) {
  console.log(mark);
}
```

А на дне 20 появятся методы `forEach` и `map`, после которых обычные циклы
для массивов почти перестают быть нужны.

## 4. Добавить и удалить: push, pop, shift, unshift {#ends}

Четыре метода работают с концами массива. Их легко запомнить парами: два работают с хвостом,
два — с головой.

<Scheme src="scheme-ends.svg">Все четыре метода меняют исходный массив</Scheme>

```js
const queue = ["Аман", "Мерет"];

queue.push("Гүлнар");      // в конец
console.log(queue);        // ["Аман", "Мерет", "Гүлнар"]

const last = queue.pop();  // с конца, возвращает убранное
console.log(last);         // "Гүлнар"

queue.unshift("Сапар");    // в начало
console.log(queue);        // ["Сапар", "Аман", "Мерет"]

const first = queue.shift(); // с начала
console.log(first);        // "Сапар"
```

| Метод | Где работает | Что возвращает |
| --- | --- | --- |
| `push(x)` | конец | новую длину |
| `pop()` | конец | убранный элемент |
| `unshift(x)` | начало | новую длину |
| `shift()` | начало | убранный элемент |

<Why>
Зачем помнить, что возвращает метод? Потому что это определяет, как его пишут.
`const x = arr.pop()` — осмысленно: забрали элемент. А `const x = arr.push(1)`
почти всегда ошибка: в `x` окажется длина массива, а человек ждал сам массив.
</Why>

### Стек и очередь

Из этих четырёх методов складываются две схемы, у которых в программировании есть имена.
**Стек** — «последним пришёл, первым ушёл»: кладут и забирают с одного конца, как
тарелки в стопке. Так устроена кнопка «Отменить» в редакторе:

```js
const history = [];
history.push("написал заголовок");
history.push("добавил картинку");
history.push("поменял цвет");

history.pop();   // "поменял цвет" — отменяется последнее действие
history;         // ["написал заголовок", "добавил картинку"]
```

**Очередь** — «первым пришёл, первым ушёл»: добавляют в конец, забирают из
начала, как очередь в кассу:

```js
const line = ["Аман", "Мерет"];
line.push("Гүлнар");   // встала в конец
line.shift();          // "Аман" — обслужили первого
line;                  // ["Мерет", "Гүлнар"]
```

Когда в задаче звучит «отменить последнее» — это стек, `push` и `pop`.
«Обработать по порядку поступления» — очередь, `push` и `shift`.

## 5. Кусочки: slice и splice {#slice}

Два метода с похожими именами и разной судьбой. `slice` вырезает копию и оставляет оригинал
в покое. `splice` оперирует сам массив: удаляет, вставляет, заменяет.

<Scheme src="scheme-slice.svg">Одна буква в названии — и совсем другое поведение</Scheme>

```js
const letters = ["a", "b", "c", "d"];

const part = letters.slice(1, 3);   // с 1 по 3, не включая 3
console.log(part);                  // ["b", "c"]
console.log(letters);               // ["a", "b", "c", "d"] — цел

const copy = letters.slice();       // копия всего массива
const tail = letters.slice(-2);     // ["c", "d"] — два с конца

letters.splice(1, 2, "X");          // с индекса 1 удалить 2, вставить "X"
console.log(letters);               // ["a", "X", "d"] — изменился
```

<Important>
Запомните разницу через слово: **slice** — «отрезать кусочек себе», оригинал остался.
**splice** — «вырезать из оригинала», оригинал изменился. Если перепутать, ошибка появится
не там, где написали, а позже — когда кто-то другой возьмёт испорченный массив.
</Important>

`splice` умеет всё сразу: удалять, вставлять и заменять.

```js
const list = ["çaý", "suw"];

list.splice(1, 0, "süýt");   // ничего не удалять, вставить на место 1
console.log(list);           // ["çaý", "süýt", "suw"]

list.splice(0, 1);           // удалить один элемент с начала
console.log(list);           // ["süýt", "suw"]
```

Три аргумента `splice` читаются так: **с какого места**, **сколько удалить**,
**что вставить**. Третий аргумент необязателен, и вставить можно сразу несколько значений:

```js
const week = ["пн", "пт"];
week.splice(1, 0, "вт", "ср", "чт");
console.log(week);   // ["пн", "вт", "ср", "чт", "пт"]
```

Самая частая задача — **удалить элемент по значению**, а не по номеру. Прямого метода для этого
нет, поэтому делают в два шага: найти индекс, потом вырезать.

```js
const names = ["Аман", "Мерет", "Гүлнар"];

const i = names.indexOf("Мерет");
if (i !== -1) {
  names.splice(i, 1);
}
console.log(names);   // ["Аман", "Гүлнар"]
```

Проверка `i !== -1` обязательна. Без неё, если имени в списке нет, `indexOf` вернёт
`-1`, и `splice(-1, 1)` удалит последний элемент — не тот, который хотели.

Оба метода понимают отрицательные индексы: счёт идёт с конца.

```js
const a = ["a", "b", "c", "d"];

a.slice(-2);      // ["c", "d"] — два последних
a.slice(1, -1);   // ["b", "c"] — без первого и последнего
a.slice();        // копия всего массива
```

<ProTip>
Запомните `slice(-3)` — «последние три». Это самый частый приём в реальных задачах:
показать три последних сообщения, пять последних покупок, десять последних записей.
</ProTip>

## 6. Поиск: indexOf, lastIndexOf, includes {#search}

```js
const marks = [5, 4, 5, 3];

console.log(marks.indexOf(5));      // 0  — первое совпадение
console.log(marks.lastIndexOf(5));  // 2  — последнее совпадение
console.log(marks.indexOf(2));      // -1 — не нашли
console.log(marks.includes(3));     // true
console.log(marks.includes(2));     // false
```

<Mistake>
Частая ошибка — проверять найденное так: `if (marks.indexOf(5))`. Если элемент стоит первым,
`indexOf` вернёт `0`, а `0` для условия означает «нет». Проверяйте явно:
`if (marks.indexOf(5) !== -1)` или просто используйте `includes`.
</Mistake>

У обоих методов есть второй, необязательный аргумент — с какого места искать. Это выручает, когда нужно
найти все совпадения по очереди:

```js
const letters = ["a", "b", "a", "c", "a"];

console.log(letters.indexOf("a"));      // 0
console.log(letters.indexOf("a", 1));   // 2 — ищем начиная с индекса 1
console.log(letters.indexOf("a", 3));   // 4
```

И одно различие, о котором помнят не все: `includes` умеет находить `NaN`,
а `indexOf` — нет. Причина в том, что `NaN` не равен даже сам себе, а
`indexOf` сравнивает именно на равенство.

```js
const nums = [1, NaN, 3];

console.log(nums.includes(NaN));   // true
console.log(nums.indexOf(NaN));    // -1 — «не нашёл»
```

Искать объекты в массиве этими методами тоже не получится: два одинаковых с виду объекта — разные
значения. Для таких поисков есть `find`, и он будет на дне 20.

## 7. Склеить и разделить: concat, join {#join}

```js
const a = [1, 2];
const b = [3, 4];

const all = a.concat(b);      // [1, 2, 3, 4] — новый массив
console.log(a);               // [1, 2] — не изменился

const names = ["Аман", "Мерет", "Гүлнар"];
console.log(names.join(", "));  // "Аман, Мерет, Гүлнар" — получилась строка
console.log(names.join(""));    // "АманМеретГүлнар"
```

`join` превращает массив в строку — это нужно каждый раз, когда список нужно показать человеку.
Обратное действие, превращение строки в массив, делает метод `split`: его разберём в курсе 2
вместе с регулярными выражениями.

Несколько деталей про `join`, которые экономят время:

```js
const a = ["хлеб", "чай", "масло"];

a.join();            // "хлеб,чай,масло"   — без аргумента через запятую
a.join(", ");        // "хлеб, чай, масло" — так показывают человеку
a.join(" → ");       // "хлеб → чай → масло"
a.join("");          // "хлебчаймасло"     — склеить без разделителя
[].join(", ");       // ""                 — пустой массив даёт пустую строку
```

Есть и автоматическое превращение: если массив попадает туда, где ждут строку, вызывается
`toString`, а он работает как `join()` без аргумента.

```js
console.log("Список: " + [1, 2, 3]);   // "Список: 1,2,3"
console.log([1, 2, 3].toString());     // "1,2,3"
```

`concat` принимает не только массивы, но и отдельные значения, и умеет склеивать несколько
сразу:

```js
const a = [1, 2];

a.concat(3);            // [1, 2, 3]
a.concat([3], [4, 5]);  // [1, 2, 3, 4, 5]
console.log(a);         // [1, 2] — оригинал не изменился
```

<ProTip>
На дне 22 появится более короткая запись того же: `[...a, ...b]`. Она читается легче,
поэтому в современном коде `concat` встречается реже. Но знать его нужно: в чужом коде
он попадается постоянно.
</ProTip>

## 8. Меняющие и копирующие методы {#mutate}

Это главная мысль всего дня. Одни методы **меняют** массив, к которому их применили.
Другие оставляют его в покое и **возвращают новое значение**. Путаница между ними —
источник самых неприятных ошибок в реальных проектах.

<Compare>
<Wrong label="Меняют исходный массив">
`push`, `pop`, `shift`, `unshift`,
`splice`, `reverse`, `fill`, `copyWithin`

```js
const a = [3, 1, 2];
a.reverse();
console.log(a); // [2, 1, 3]
```
</Wrong>

<Right label="Возвращают новое, оригинал цел">
`slice`, `concat`, `join`, `at`,
`includes`, `indexOf`, `with`, `toReversed`,
`toSpliced`

```js
const a = [3, 1, 2];
const b = a.toReversed();
console.log(a); // [3, 1, 2]
console.log(b); // [2, 1, 3]
```
</Right>
</Compare>

Новые методы `toReversed`, `toSpliced` и `with` появились в языке
недавно: это «вежливые» версии старых. `with(0, "X")` возвращает копию, где на месте 0 стоит
`"X"`, а оригинал не трогает.

```js
const marks = [5, 4, 3];
marks.with(1, 5);        // [5, 5, 3] — копия, где на месте 1 стоит 5
marks.toSpliced(1, 1);   // [5, 3] — копия без элемента с индексом 1
marks;                   // [5, 4, 3] — оригинал цел
```

Ещё два метода из левой колонки. `fill` заполняет кусок массива одним значением,
`copyWithin` копирует кусок массива на другое место внутри него же. Оба меняют сам
массив:

```js
const seats = ["свободно", "свободно", "свободно", "свободно"];
seats.fill("занято", 1, 3);          // ["свободно", "занято", "занято", "свободно"]
[1, 2, 3, 4, 5].copyWithin(0, 3);    // [4, 5, 3, 4, 5] — элементы с 3 скопированы в начало
```

Второй и третий аргументы `fill` — те же «с какого места» и «до какого, не
включая», что у `slice`. `copyWithin` в обычных задачах почти не
встречается, но узнавать его стоит.

## 9. Массив — это ссылка {#ref}

Это самая важная идея дня и одновременно самая частая причина непонятных ошибок. Когда вы кладёте массив
в переменную, туда попадает **не сам массив, а ссылка на него** — как адрес дома, а не сам дом.

```js
const a = [1, 2, 3];
const b = a;        // скопировали ссылку, а не массив

b.push(4);

console.log(b);     // [1, 2, 3, 4] — ожидаемо
console.log(a);     // [1, 2, 3, 4] — а вот это сюрприз
```

Массив в памяти один, а имён у него два. Изменили через `b` — увидели и в `a`.
С числами и строками такого не бывает: они копируются целиком.

<Scheme src="scheme-ref.svg">Присваивание копирует ссылку, а не содержимое</Scheme>

Как сделать настоящую копию:

```js
const a = [1, 2, 3];

const copy1 = a.slice();      // копия через slice
const copy2 = [...a];         // копия через spread — разберём на дне 22
const copy3 = Array.from(a);  // копия через Array.from

copy1.push(4);
console.log(a);       // [1, 2, 3] — оригинал цел
```

<Important>
Слово `const` не запрещает менять массив. Оно запрещает только присвоить переменной
*другое* значение. Поэтому `const a = [1]; a.push(2);` работает,
а `const a = [1]; a = [2];` — ошибка *Assignment to constant variable*.
</Important>

Из той же идеи следует ещё одно правило: массивы нельзя сравнивать знаком равенства.

```js
console.log([1, 2] === [1, 2]);   // false — это два разных массива
const a = [1, 2];
const b = a;
console.log(a === b);             // true — одна и та же ссылка

// сравнить содержимое можно так (для простых значений):
console.log(a.join() === [1, 2].join());  // true
```

<Mistake>
Ошибка, которую делают все: передали массив в функцию, функция сделала `sort` или
`splice` — и у вызывающего кода данные испортились. Правило простое: если функция не обязана
менять массив, пусть работает с копией. Об этом подробно поговорим в курсе 2.
</Mistake>

### Разбор: функция испортила чужой массив

Функция должна вернуть три последних сообщения переписки. Автор вспомнил `splice`:
удалить всё, кроме трёх последних, и вернуть результат.

```js
function lastThree(list) {
  list.splice(0, list.length - 3);   // удалить всё, кроме трёх последних
  return list;
}

const messages = ["привет", "как дела?", "хорошо", "пока", "до завтра"];
lastThree(messages);   // ["хорошо", "пока", "до завтра"] — ответ верный
messages;              // ["хорошо", "пока", "до завтра"] — а переписка пропала
```

Ответ функции верный, поэтому ошибку не видно сразу. Она всплывёт позже, когда кто-то захочет
показать всю переписку. Причина — `splice` меняет тот самый массив, который передали:
ссылка одна. Исправление — копирующий метод, и это как раз «последние три» из раздела 5:

```js
function lastThree(list) {
  return list.slice(-3);   // копия трёх последних, оригинал цел
}
```

## 10. Что быстрее: push или unshift {#speed}

Методы, которые работают с концом массива (`push`, `pop`), выполняются мгновенно:
элемент добавляется или убирается на месте. Методы, которые работают с началом (`unshift`,
`shift`), вынуждены сдвинуть все остальные элементы: у каждого меняется индекс.

| Метод | Что происходит | Цена |
| --- | --- | --- |
| `push`, `pop` | работа с последним элементом | дёшево всегда |
| `unshift`, `shift` | сдвиг всех элементов | тем дороже, чем длиннее массив |

На списке из десяти элементов разницы не заметить. Замерим на ста тысячах — `console.time`
из дня 2. Вставьте блок в консоль целиком: если печатать по строке, в замер попадёт и время,
пока вы набираете следующую.

```js
const big = [];
console.time("push");
for (let i = 0; i < 100000; i++) big.push(i);
console.timeEnd("push");      // у нас — 1–3 мс

const big2 = [];
console.time("unshift");
for (let i = 0; i < 100000; i++) big2.unshift(i);
console.timeEnd("unshift");   // у нас — около 500 мс
```

Числа у вас будут другие, но разница — в сотни раз. С `pop` и `shift`
то же самое. Поэтому, если нужно
собрать длинный список, добавляйте в конец через `push`, а если очередь должна обрабатываться
с начала, лучше запомнить позицию, чем каждый раз двигать массив.

## 11. Массив внутри массива {#nested}

Элементом массива может быть другой массив. Так хранят таблицы: строки внутри строк.

```js
const schedule = [
  ["duşenbe", "алгебра", "физика"],
  ["sişenbe", "история", "химия"],
];

console.log(schedule.length);      // 2 — две строки
console.log(schedule[0][2]);       // "физика" — первая строка, третий предмет
console.log(schedule[1][0]);       // "sişenbe"
```

Обращение идёт по двум индексам: сначала строка, потом элемент внутри неё. Перебирать такие массивы
удобнее циклами, которые мы разбирали на дне 10, а красиво выводить — методами с дня 20.

## 12. Проверка: Array.isArray {#isarray}

```js
console.log(typeof [1, 2]);        // "object" — бесполезно
console.log(Array.isArray([1, 2])); // true
console.log(Array.isArray("абв"));  // false
```

Оператор `typeof` для массива отвечает `"object"`, потому что массив —
это особый вид объекта. Поэтому для проверки есть отдельный метод `Array.isArray`.

Пригодится это чаще, чем кажется. Данные с сервера приходят по-разному: иногда список, иногда одно
значение. Проверка помогает не сломаться:

```js
function show(data) {
  if (Array.isArray(data)) {
    console.log("список из " + data.length + " элементов");
  } else {
    console.log("одно значение: " + data);
  }
}

show([1, 2, 3]);   // список из 3 элементов
show("привет");    // одно значение: привет
```

## 13. Какой метод выбрать {#choose}

Когда методов много, помогает обратная таблица: не «что делает метод», а «что мне нужно».

| Мне нужно… | Метод |
| --- | --- |
| добавить в конец | `push` |
| забрать последний | `pop` |
| добавить в начало | `unshift` |
| забрать первый | `shift` |
| взять кусок, не портя оригинал | `slice` |
| удалить или вставить в середину | `splice` |
| узнать, есть ли значение | `includes` |
| узнать, на каком месте значение | `indexOf` |
| сделать из списка строку | `join` |
| соединить два списка | `concat` |
| перевернуть | `reverse`, копию — `toReversed` |
| скопировать массив | `slice()` или `Array.from` |
| заменить один элемент в копии | `with` |
| заполнить одинаковыми значениями | `fill` |
| проверить, массив ли это | `Array.isArray` |

Методов перебора — `forEach`, `map`, `filter`, `reduce` —
в этой таблице нет намеренно: им посвящён весь следующий день.

### Массивы и строки похожи больше, чем кажется

На дне 16 мы разбирали строки. Сравните: многое называется одинаково и работает одинаково.

| Что нужно | Строка | Массив |
| --- | --- | --- |
| длина | `"Мары".length` → 4 | `[1,2,3].length` → 3 |
| элемент по номеру | `"Мары"[0]` → "М" | `[1,2,3][0]` → 1 |
| последний | `"Мары".at(-1)` → "ы" | `[1,2,3].at(-1)` → 3 |
| кусок | `"Мары".slice(0, 2)` → "Ма" | `[1,2,3].slice(0, 2)` → \[1,2\] |
| поиск | `"Мары".includes("ар")` | `[1,2,3].includes(2)` |

Главное отличие: **строку изменить нельзя**. Любой метод строки возвращает новую строку,
а исходная остаётся. У массива же половина методов меняет его на месте. Поэтому
`"абв".toUpperCase()` надо куда-то присвоить, а `arr.push(1)` — не надо.

## 14. Всё вместе: корзина покупок {#cart}

Соберём из методов дня маленькую настоящую программу. Она ведёт корзину: добавляет товары, убирает
ненужное, считает и показывает список.

```js
const cart = [];

// покупатель кладёт товары
cart.push("хлеб");
cart.push("чай");
cart.push("масло");
console.log(cart.length + " товара в корзине");   // 3 товара в корзине

// передумал насчёт чая: сначала найти, потом убрать
const index = cart.indexOf("чай");
if (index !== -1) {
  cart.splice(index, 1);
}
console.log(cart);                 // ["хлеб", "масло"]

// проверка перед добавлением, чтобы не задваивать
if (!cart.includes("хлеб")) {
  cart.push("хлеб");
}

// показать покупателю
console.log("В корзине: " + cart.join(", "));     // В корзине: хлеб, масло

// сохранить историю, не испортив корзину
const history = cart.slice();
cart.length = 0;                   // очистили корзину
console.log(cart);                 // []
console.log(history);              // ["хлеб", "масло"] — история цела
```

В этой программе работают восемь приёмов дня: `push`, `length`,
`indexOf`, `splice`, `includes`, `join`, `slice`
и присваивание в `length`. Примерно так же выглядит настоящий код корзины в магазине —
только вместо строк там объекты с ценой и количеством, а их мы разберём на дне 21.

## 15. Частые ошибки дня {#mistakes}

| Ошибка | Почему | Как правильно |
| --- | --- | --- |
| `arr[arr.length]` вместо последнего | индексы кончаются на `length - 1` | `arr.at(-1)` |
| `if (arr.indexOf(x))` | для первого элемента индекс 0 = «ложь» | `if (arr.includes(x))` |
| `const b = a` как «копия» | копируется ссылка, массив один | `const b = a.slice()` |
| `new Array(7)` как «массив с числом 7» | получается семь пустых мест | `[7]` или `Array.of(7)` |
| `splice` там, где нужен `slice` | испортили исходные данные | сначала спросите себя: оригинал трогаем? |
| `arr1 === arr2` для сравнения | сравниваются ссылки, а не содержимое | `arr1.join() === arr2.join()` |

### Пустой массив

Отдельно стоит запомнить, что возвращают методы, когда массив пуст:

```js
const empty = [];
empty.pop();        // undefined — убирать нечего, но и ошибки нет
empty.shift();      // undefined
empty.at(-1);       // undefined
empty.indexOf(1);   // -1
empty.slice(1);     // []
empty.join(", ");   // ""
```

Ни один из них не бросает ошибку — все возвращают «ничего». Поэтому ошибка всплывает дальше,
там, где с этим «ничего» пытаются работать:

```js
empty.pop().toUpperCase();   // TypeError: Cannot read properties of undefined (reading 'toUpperCase')
```

Если массив может оказаться пустым, проверяйте `length` до того, как забирать элемент.

Отдельно про ошибку `RangeError: Invalid array length`. Она появляется, когда длине массива
пытаются задать невозможное значение: дробное, отрицательное или слишком большое.

```js
new Array(-1);       // RangeError: Invalid array length
const a = [1, 2];
a.length = 2.5;      // RangeError: Failed to set the 'length' property on 'Array': Invalid array length
```

При записи в `length` Chrome пишет сообщение длиннее, но конец у него тот же —
по нему ошибку и узнают.

<Selfcheck>
1. Что вернёт `[10, 20, 30].length` и какой индекс у элемента `30`?
   <Answer>3 и 2. Длина считается с единицы, индекс — с нуля.</Answer>
2. Чем `slice(1, 3)` отличается от `splice(1, 3)`?
   <Answer>`slice` возвращает копию элементов с 1 по 2 и не трогает массив.
   `splice(1, 3)` удаляет из массива три элемента начиная с индекса 1.</Answer>
3. Что вернёт `Array.of(3)`, а что `new Array(3)`?
   <Answer>`[3]` — массив из одного числа. И пустой массив длиной 3.</Answer>
4. Почему опасно писать `if (arr.indexOf(x))`?
   <Answer>Если `x` стоит первым, индекс равен 0, а ноль в условии означает «нет».
   Нужно `!== -1` или `includes`.</Answer>
5. Кнопка «Отменить» убирает последнее действие. Это стек или очередь и какие методы нужны?
   <Answer>Стек: действия добавляют через `push`, отменяют через `pop` —
   последним пришло, первым ушло.</Answer>
6. Чем дыра в массиве отличается от `undefined` и как это видно?
   <Answer>Дыра — отсутствие элемента. При чтении даёт `undefined`, но
   `indexOf(undefined)` её пропускает и возвращает `-1`, а
   `includes(undefined)` находит.</Answer>
7. Как перевернуть массив, не испортив оригинал?
   <Answer>`const b = a.toReversed();` или `const b = a.slice().reverse();`</Answer>
</Selfcheck>
