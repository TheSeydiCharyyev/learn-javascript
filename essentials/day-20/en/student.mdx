# Day 20. Iterating arrays

<Subtitle>A summary of the lecture: do something with each one, build a new list, fold into one.</Subtitle>

## The main points

<Definition>
Each method is given a function, and it calls it for each element. The choice of method
is settled by one question: **what should come out**.
</Definition>

| Needed | Method | Returns |
| --- | --- | --- |
| just an action | `forEach` | `undefined` |
| a list of the same length | `map` | an array |
| a shorter list | `filter` | an array |
| the first suitable one | `find` / `findIndex` | an element / a position or −1 |
| yes or no | `some` / `every` | `true` / `false` |
| one value | `reduce` | anything |

```js
const marks = [5, 4, 3];
marks.forEach((value, index, array) => { });   // the callback gets THREE arguments

marks.map((m) => m * 10);       // [50, 40, 30]  — the same length
marks.filter((m) => m >= 4);    // [5, 4]        — shorter
marks.filter((m) => m >= 4).map((m) => m * 10);   // [50, 40] — a chain
```

<KeyPoint>
`forEach` returns nothing, and you cannot exit it: `break` is
an error, `return` works like `continue`. If you need to exit early,
take `find`, `some` or an ordinary loop.
</KeyPoint>

## The map(parseInt) trap

```js
["1", "2", "3"].map(Number);     // [1, 2, 3]
["1", "2", "3"].map(parseInt);   // [1, NaN, NaN]
["10", "10", "10"].map(parseInt); // [10, NaN, 2]
```

<Remember>
The index gets into the second parameter of `parseInt` — the numeral system.
**Pass by name only functions with one argument**; in other
cases write an arrow: `map((s) => parseInt(s, 10))`.
</Remember>

## Search and checks

```js
marks.find((m) => m < 4);        // 3          or undefined
marks.findIndex((m) => m < 4);   // 2          or -1
marks.findLast((m) => m >= 4);   // 4 — from the end; there is also findLastIndex

marks.some((m) => m === 5);      // true — there is at least one
marks.every((m) => m >= 2);      // true — all fit

[].some(() => true);    // false
[].every(() => false);  // true — “vacuous truth”
```

## reduce

```js
marks.reduce((sum, mark) => sum + mark, 0);   // 12
//            accumulated  element          initial value

const names = ["Aman", "Meret", "Sapar"];
names.reduce((line, name) => line + name + "; ", "");   // "Aman; Meret; Sapar; "
marks.reduce((best, m) => Math.max(best, m));           // 5 — the maximum

// [].reduce((a, b) => a + b)   → TypeError: Reduce of empty array with no initial value
```

<Remember>
**Always write the initial value.** It protects against an empty list
and sets the type of the result. The exception is when an empty list certainly will not get there,
as in `maxOf` from the “Report card”.
</Remember>

## Sorting

```js
const nums = [10, 9, 100, 2];

nums.sort();                    // [10, 100, 2, 9] — AS STRINGS
nums;                           // [10, 100, 2, 9] — and the array is REARRANGED

nums.sort((a, b) => a - b);     // [2, 9, 10, 100] — ascending
nums.sort((a, b) => b - a);     // [100, 10, 9, 2] — descending
nums.toSorted((a, b) => a - b); // [2, 9, 10, 100] — a copy, the original is intact
```

```js
[[1, 2], [3, [4]]].flat();               // [1, 2, 3, [4]]
[1, 2, 3].flatMap((n) => [n, n * 10]);   // [1, 10, 2, 20, 3, 30]
[1, 2, 3, 4].flatMap((n) => n % 2 === 0 ? [n * 10] : []);   // [20, 40]
```

<NoteBox>
**Two errors of the day:** `Reduce of empty array with no initial value`
(the text is the same in all browsers) and `The comparison function must be either
a function or undefined` — when something that is not a function was passed to `sort`.
\
**A chain is several passes.** On a hundred elements it does not matter;
readability almost always matters more than speed.
</NoteBox>
