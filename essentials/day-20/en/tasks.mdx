# Day 20. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder `day-20`.</Subtitle>

## Warm-up

<Task title="1. A loop becomes a method" level="easy" time="6">
<Goal>replace three familiar loops with methods.</Goal>

```js
const marks = [5, 4, 3, 5, 2];

// A — how many times shorter?
const big = [];
for (const m of marks) { big.push(m * 10); }

// B
const good = [];
for (const m of marks) { if (m >= 4) { good.push(m); } }

// C
let total = 0;
for (const m of marks) { total += m; }
```

<Hint>
Each loop turns into exactly one method. Look at what comes out
at the end: a list of the same length, a shorter list or one number.
</Hint>

<Criteria>
- all three are rewritten, the results match the original ones;
- for each one it is named why exactly this method was chosen;
- it is written down how many lines there were and how many there are now;
- it is checked that `marks` did not change after all three.
</Criteria>
</Task>

<Task title="2. Predict first: what is returned" level="easy" time="7">
<Goal>catch six non-obvious answers.</Goal>

```js
const marks = [5, 4, 3];

marks.forEach((m) => m * 10);
marks.map((m) => m >= 4);
marks.findIndex((m) => m === 5);
marks.find((m) => m > 9);
[].every((m) => false);
[].some((m) => true);
```

<Hint>
The first answer is not an array. The third is a number that would behave as
false in a condition. The fifth contradicts common sense but is mathematically right.
</Hint>

<Criteria>
- six predictions are written down before checking;
- it is explained why `forEach` returned something other than an array;
- it is explained how `find` differs from `findIndex`
  in the “not found” case;
- it is explained why `[].every(...)` gives `true`;
- it is written down how to check `findIndex` safely in a condition.
</Criteria>
</Task>

<Task title="3. The trap with parseInt" level="easy" time="7">

</Task>

## Main tasks

<Task title="4. A chain of methods" level="medium" time="12">
<Goal>put several steps into one expression.</Goal>

Given a “dirty” list of marks. Get from it, with one chain per item:

```js
const raw = [5, 4, 3, 5, 2, 9, 0, 4];
```

- the sum of the valid marks (from 2 to 5);
- the average of the valid ones, rounded to hundredths;
- the list of the valid ones multiplied by 10;
- how many fives there are among them — in two ways: through `filter`
  and through `reduce`.

<Hint>
It is handy to select the valid ones once into a separate variable instead of filtering again
in each item. The average is the sum divided by the length, but dividing by zero is not allowed.
</Hint>

<Criteria>
- all four results are obtained and written down;
- both versions of counting fives give the same number;
- it is written down which of the two versions reads better and why;
- protection against an empty list is added — it is shown what broke without it;
- it is explained why filtering earlier pays off more than filtering later.
</Criteria>
</Task>

<Task title="5. sort for real" level="medium" time="13">
<Goal>see both dangers of `sort` with your own eyes.</Goal>

```js

console.log(nums.sort());
console.log(nums);
```

Explain both outputs. Then sort the list in four ways — ascending,
descending, without touching the original with two different techniques — and each time print
the source array.

<Hint>
There are two ways not to spoil the original: make a copy before sorting
or take a method that makes the copy itself. Both were in the lecture.
</Hint>

<Criteria>
- it is explained why 100 ended up between 10 and 2;
- it is explained why `nums` changed;
- all four ways are shown, the original is printed after each one;
- an array of words is sorted, and it is explained why the words with a capital letter
  came first;
- it is written down which way you will write by default.
</Criteria>
</Task>

## Starred tasks

<Task title="8. Everything through reduce" level="hard" time="10">
<Goal>understand reduce well enough to build the other methods with it.</Goal>

Build with `reduce` three things that are usually done with other
methods, and compare them with the originals:

<Example>
```js
myMap([5, 4, 3], (m) => m * 10);      // [50, 40, 30]
myFilter([5, 4, 3], (m) => m >= 4);   // [5, 4]
myCount([5, 4, 5], (m) => m === 5);   // 2
```
</Example>

<Hint>
The initial value of the first two is an empty array. Inside the function the element
is added with `push`, and the accumulator must be returned — otherwise
at the next step it will be `undefined`.
</Hint>

<Criteria>
- all three functions are written and give the same results as the built-in ones;
- compared with `map`, `filter` and
  `filter().length`;
- it is explained why the function has `return acc`;
- it is shown what happens if you remove it;
- it is written down which of the three variants you would keep in real code
  and why.
</Criteria>
</Task>

<Task title="9. Six catches" level="hard" time="10">
<Goal>bring together everything that behaves unexpectedly today.</Goal>

```js
// 1
const doubled = [5, 4].forEach((m) => m * 2);
console.log(doubled);

// 2
console.log([].reduce((a, b) => a + b));

// 3
const nums = [10, 9, 100, 2];
console.log(nums.sort(), nums);

// 4
console.log(["5", "10", "15"].map(parseInt));

// 5
const marks = [5, 4, 3];
if (marks.findIndex((m) => m === 5)) { console.log("there is a five"); }

// 6
console.log([3, 1].sort("ascending"));
```

<Hint>
Two fragments crash, four do not. Fragment 5 prints nothing, although there is a five
in the array — and this is the most harmful kind of error. Run the fragments one at a time:
one that crashes stops everything below it.
</Hint>

<Criteria>
- the predictions are written down before running;
- for the two that crash the exact text of the error from your console is written down;
- it is explained why fragment 5 stayed silent;
- all six are rewritten correctly;
- it is written down which two catches are more dangerous than the others and why.
</Criteria>
</Task>
