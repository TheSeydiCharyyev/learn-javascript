1. Цикл, который стал методом

Вчера мы складывали, резали и искали в массиве. Сегодня научимся проходить его целиком — и получать из него новый результат.

Делать это мы умеем с одиннадцатого дня, циклом:

const marks = [5, 4, 3, 5, 2];

const doubled = [];
for (const mark of marks) {
  doubled.push(mark * 10);
}

doubled;   // [50, 40, 30, 50, 20]

Четыре строки, из которых по делу — одна. Остальное — заготовка массива, цикл и push, и эта заготовка одинакова всегда. Язык позволяет её не писать:

const doubled = marks.map((mark) => mark * 10);

doubled;   // [50, 40, 30, 50, 20]

Одна строка, и в ней осталось только существенное: что делаем с каждым элементом. Так устроены все методы сегодняшнего дня — каждому передают функцию, и он зовёт её для каждого элемента. Функцию как значение мы передавали ещё на дне 12, а записывать её стрелкой научились на дне 13; сегодня оба умения наконец работают вместе.

2. forEach — сделать с каждым

Самый простой: выполняет функцию для каждого элемента и ничего не возвращает.

const marks = [5, 4, 3];

marks.forEach((mark) => {
  console.log("оценка: " + mark);
});
// оценка: 5
// оценка: 4
// оценка: 3

Он — полная замена for...of, и у него есть два отличия, о которых надо знать заранее.

Первое: он ничего не возвращает. Совсем — всегда undefined:

const result = marks.forEach((mark) => mark * 10);

result;   // undefined — а не [50, 40, 30]

Это самая частая ошибка новичка: взять forEach там, где нужен map. Правило простое: если результат нужен — берите не forEach.

Второе: из него нельзя выйти досрочно. break в нём — синтаксическая ошибка, а return прерывает только текущий вызов функции, то есть работает как continue:

marks.forEach((mark) => {
  if (mark === 4) {
    return;        // это «пропустить», а не «выйти»
  }
  console.log(mark);
});
// 5
// 3

Поэтому там, где нужно остановиться на первом же найденном, берут find из раздела 7 или обычный цикл с break.

Когда всё-таки цикл

Методы удобнее в большинстве случаев, но обычный for...of не устарел. Он остаётся лучше в трёх ситуациях:

// 1. нужно выйти досрочно
for (const mark of marks) {
  if (mark === 2) {
    console.log("нашли двойку, дальше не смотрим");
    break;
  }
}

Вторая ситуация — когда на каждом шаге нужны два соседних элемента или шаг не равен единице: методы перебора всегда идут по одному и по порядку. Третья — когда на каждом шаге надо дождаться ответа сервера: forEach ждать не умеет, а обычный цикл — умеет. Как ждать ответа, покажет день 31.

Во всех остальных случаях метод короче и честнее: по его имени сразу видно, что происходит, а по for — только после чтения тела.

Разбор: почему отчёт пустой

Так выглядит ошибка «взял forEach вместо map» в настоящей программе. Разберём её по шагам, приёмом из дня 15.

const lines = marks.forEach((m) => "оценка: " + m);

console.log(lines.join("; "));
// TypeError: Cannot read properties of undefined (reading 'join')

Шаг 1. Читаем ошибку. Она не про join, а про то, у чего его вызвали: «нельзя прочитать свойства у undefined». Значит, lines — это undefined.

Шаг 2. Проверяем догадку. Печатаем саму переменную, а не её свойства:

console.log(lines);   // undefined

Шаг 3. Смотрим, кто её создал. Справа от = стоит forEach, а он всегда возвращает undefined. Функция внутри честно собирала строки — но их никто не принимал.

Шаг 4. Чиним. Нужен метод, который собирает результаты:

const lines = marks.map((m) => "оценка: " + m);

lines.join("; ");   // "оценка: 5; оценка: 4; оценка: 3"

Обратите внимание на шаг 1: сообщение указывало на join, а виновата была строка выше. Это обычное дело — ошибка проявляется там, где значение используют, а не там, где его создали. Стек вызовов и печать переменной доводят до настоящей причины за полминуты.

3. Три аргумента колбэка

Функция, которую мы передаём, получает не один аргумент, а три — просто обычно нужен только первый:

marks.forEach((value, index, array) => {
  console.log(value, index, array.length);
});
// 5 0 3
// 4 1 3
// 3 2 3

Второй аргумент — индекс — выручает, когда рядом лежит второй массив с теми же позициями. Приём знаком с пятнадцатого дня, где имена и посещаемость шли парой:

const items = ["хлеб", "чай", "масло"];
const prices = [3.5, 12, 25];

const cheap = items.filter((item, index) => prices[index] < 10);

cheap;   // ["хлеб"]

Третий аргумент — сам массив — нужен совсем редко, и его почти всегда можно не писать. Лишние параметры указывать не обязательно: ещё на дне 12 мы видели, что лишние аргументы функция молча отбрасывает.

4. map — собрать новый массив

Берёт каждый элемент, пропускает через функцию и складывает результаты в новый массив. Длина всегда та же — сколько было, столько и станет.

const marks = [5, 4, 3];

marks.map((m) => m * 10);          // [50, 40, 30]
marks.map((m) => m >= 4);          // [true, true, false]
marks.map((m) => "оценка " + m);   // ["оценка 5", "оценка 4", "оценка 3"]

marks;   // [5, 4, 3] — исходный массив цел

Обратите внимание на две вещи. Первая: тип может смениться — из чисел получились булевы значения, потом строки. Вторая: исходный массив не меняется, как и у строковых методов дня 16.

Отсюда правило выбора между map и forEach:

map — когда из списка нужно сделать другой список. forEach — когда нужно что-то сделать: напечатать, сохранить, показать на странице. Если после forEach вы собираете результат в отдельный массив через push — вам нужен map.

5. Ловушка map(parseInt)

Раз функцию можно передать по имени, напрашивается короткая запись. И вот тут язык ставит подножку:

["1", "2", "3"].map(Number);     // [1, 2, 3]      — работает
["1", "2", "3"].map(parseInt);   // [1, NaN, NaN]  — что?!

Разгадка в разделе 3: map передаёт функции три аргумента. Number принимает один и лишние игнорирует, а у parseInt второй параметр — система счисления из дня 17. Получается вот что:

parseInt("1", 0);   // 1    ноль означает «система по умолчанию»
parseInt("2", 1);   // NaN  системы счисления с основанием 1 не бывает
parseInt("3", 2);   // NaN  в двоичной системе цифры 3 нет

Ещё нагляднее на одинаковых строках:

["10", "10", "10"].map(parseInt);   // [10, NaN, 2]

Третий элемент — двойка, потому что parseInt("10", 2) читает «10» как двоичное число. Программа не падает, массив получается, и половина значений — мусор.

Правило на каждый день: передавайте по имени только те функции, которые принимают ровно один аргумент. В остальных случаях пишите стрелку явно — map((s) => parseInt(s, 10)). Одна лишняя пара скобок надёжнее красивой краткости.

6. filter — оставить подходящие

Вызывает функцию для каждого элемента и оставляет те, для которых она вернула true. Мы пользуемся им с двенадцатого дня, теперь разберём устройство.

const marks = [5, 4, 3, 5, 2];

marks.filter((m) => m >= 4);       // [5, 4, 5]
marks.filter((m) => m === 5);      // [5, 5]
marks.filter((m) => m > 100);      // []  — пустой массив, не undefined

Результат короче или такой же длины, но элементы в нём те же самые — filter ничего не меняет, только отбирает. Если нужно и отобрать, и изменить, методы соединяют цепочкой:

marks
  .filter((m) => m >= 4)
  .map((m) => m * 10);        // [50, 40, 50]

Читается сверху вниз, как список шагов: взяли оценки, оставили хорошие, умножили на десять. Каждый шаг отдаёт новый массив следующему — ровно как цепочки строковых методов из дня 16.

Порядок в цепочке важен и по смыслу, и по скорости: фильтровать лучше раньше, чтобы дальше работать с коротким списком.

Цепочка по шагам

Посмотрим на полную цепочку из трёх методов — она встретится в заданиях. Список «грязный»: в нём есть и девятка, и ноль, которых в оценках быть не может.

const raw = [5, 4, 3, 5, 2, 9, 0, 4];

const total = raw
  .filter((m) => m >= 2 && m <= 5)   // 6 элементов из 8
  .map((m) => m * 10)                // те же 6, но в десять раз больше
  .reduce((sum, m) => sum + m, 0);   // одно число

total;   // 230

Видно и главное свойство цепочки: длина меняется только на filter. map сохраняет её, reduce убирает вовсе. По этому признаку цепочку легко читать даже в чужом коде.

7. find и findIndex

filter находит всех подходящих. Когда нужен только первый, берут find — он останавливается сразу, как нашёл:

const marks = [5, 4, 3, 5, 2];

marks.find((m) => m < 4);        // 3    сам элемент
marks.findIndex((m) => m < 4);   // 2    его позиция

marks.find((m) => m > 9);        // undefined
marks.findIndex((m) => m > 9);   // -1

Разница в «не нашли» — как у вчерашних indexOf и at: тот, кто ищет позицию, отдаёт -1, а тот, кто ищет значение, — undefined. И та же ловушка: ноль — правильная позиция, поэтому findIndex в условии сравнивают с -1 явно.

Есть и зеркальная пара, которая идёт с конца:

marks.findLast((m) => m >= 4);        // 5   последняя хорошая оценка
marks.findLastIndex((m) => m >= 4);   // 3   её позиция

8. some и every

Два метода отвечают одним словом «да» или «нет»:

const marks = [5, 4, 3, 5, 2];

marks.some((m) => m === 5);    // true   есть хотя бы одна пятёрка
marks.every((m) => m >= 2);    // true   все оценки не ниже двойки
marks.every((m) => m === 5);   // false  не все пятёрки

Оба останавливаются, как только ответ ясен: some — на первом подходящем, every — на первом неподходящем. На длинных списках это заметно быстрее, чем считать всех через filter.

А вот поведение на пустом массиве удивляет:

[].some((m) => true);    // false
[].every((m) => false);  // true   — даже с заведомо ложной проверкой!

Логика такая: «есть ли хоть один подходящий» среди ничего — нет, не найдётся. «Все ли подходят» среди ничего — да, ведь ни один не нарушил. Математики называют это «истинно от пустоты», и с этим надо просто согласиться. На практике помнить стоит одно: перед every проверяйте, что список не пуст, если пустой список для вас не «всё в порядке».

9. reduce — свернуть в одно

Самый мощный и самый пугающий метод дня. Он проходит массив и накапливает один результат: сумму, максимум, строку — что угодно.

const marks = [5, 4, 3];

const total = marks.reduce((sum, mark) => sum + mark, 0);

total;   // 12

У функции два параметра: накопленное значение и очередной элемент. Второй аргумент самого reduce — с чего начать.

Накапливать можно не только числа. Начальное значение задаёт тип результата:

const names = ["Аман", "Мерет", "Сапар"];

names.reduce((line, name) => line + name + "; ", "");
// "Аман; Мерет; Сапар; "

marks.reduce((best, mark) => Math.max(best, mark), 0);
// 5 — максимум, как на дне 18, но без цикла

reduce умеет и считать по условию — тогда накапливается не сумма, а количество:

marks.reduce((count, mark) => mark === 5 ? count + 1 : count, 0);   // 1
marks.filter((mark) => mark === 5).length;                          // 1 — то же

Вторая запись короче и понятнее, и в обычном коде берут именно её. Первая полезна, когда за один проход надо посчитать сразу несколько вещей, — но такие случаи редки, и читаемость важнее экономии на проходах.

Есть и зеркальный reduceRight — он идёт с конца. Нужен редко, но разницу видно сразу:

["а", "б", "в"].reduce((a, b) => a + b);        // "абв"
["а", "б", "в"].reduceRight((a, b) => a + b);   // "вба"

10. reduce на пустом массиве

Начальное значение можно не писать — тогда reduce возьмёт первый элемент как стартовый. Обычно результат тот же:

[5, 4, 3].reduce((a, b) => a + b, 0);   // 12
[5, 4, 3].reduce((a, b) => a + b);      // 12 — тоже

Но на пустом массиве брать нечего, и это единственная ошибка дня:

[].reduce((a, b) => a + b);
// TypeError: Reduce of empty array with no initial value

[].reduce((a, b) => a + b, 0);   // 0 — с начальным значением всё в порядке
Пишите начальное значение всегда. Оно защищает от пустого списка, задаёт тип результата и делает код понятнее: по reduce(..., 0) сразу видно, что считается число, а по reduce(..., "") — что строка.

Это тот же разговор, что был на дне 18 про Math.max() без аргументов: у «свёртки пустого списка» нет естественного ответа, и его приходится назначать самому.

11. sort и почему он опасен

Метод сортирует массив. И делает две вещи, которых от него не ждут.

Первое: он меняет исходный массив, а не возвращает копию — единственный такой среди методов сегодняшнего дня:

const nums = [10, 9, 100, 2];

nums.sort();
nums;        // [10, 100, 2, 9] — исходный массив переставлен!

Второе: без подсказки он сравнивает как строки. Поэтому 100 оказалось между 10 и 2 — по алфавиту «100» идёт раньше «2», ведь сравниваются первые символы.

То же с русскими словами: сначала все слова с большой буквы, потом с маленькой, потому что сравниваются коды символов:

["чай", "Хлеб", "масло"].sort();
// ["Хлеб", "масло", "чай"]
Оба свойства вместе дают классическую беду: вы вызвали sort «просто посмотреть», а массив в другом месте программы уже переставлен — и числа в нём в неправильном порядке. Ошибка находится долго, потому что виноватая строка выглядит безобидно.

12. Сравнение по правилу

Чтобы сортировать по-своему, sort передают функцию сравнения. Она получает два элемента и возвращает число: отрицательное — первый раньше, положительное — второй раньше, ноль — всё равно.

const nums = [10, 9, 100, 2];

nums.slice().sort((a, b) => a - b);   // [2, 9, 10, 100]   по возрастанию
nums.slice().sort((a, b) => b - a);   // [100, 10, 9, 2]   по убыванию

Вычитание работает как раз потому, что знак разности и есть нужный ответ: если a меньше, разность отрицательная.

Обратите внимание на slice() перед sort — это копия из вчерашнего дня, чтобы не испортить оригинал. У приёма есть современная замена:

const sorted = nums.toSorted((a, b) => a - b);

sorted;   // [2, 9, 10, 100]
nums;     // [10, 9, 100, 2] — цел

Если передать в sort не функцию, будет ошибка — вторая и последняя в сегодняшнем справочнике:

[3, 1].sort("не функция");
// TypeError: The comparison function must be either a function or undefined: не функция

13. flat и flatMap

Вчера мы видели массивы внутри массивов. flat разворачивает их в один уровень:

[[1, 2], [3, [4]]].flat();           // [1, 2, 3, [4]]  — на один уровень
[[1, 2], [3, [4]]].flat(2);          // [1, 2, 3, 4]    — на два
[1, [2, [3, [4]]]].flat(Infinity);   // [1, 2, 3, 4]    — на любую глубину

flatMap — это map, после которого сразу делается flat на один уровень. Он нужен, когда из одного элемента получается несколько:

[1, 2, 3].flatMap((n) => [n, n * 10]);   // [1, 10, 2, 20, 3, 30]

Вложенные массивы редко создают нарочно — чаще они получаются сами, когда каждый элемент превращается в список. Именно для такого случая и придуман flatMap.

И есть красивый приём: если вернуть пустой массив, элемент просто исчезнет. Получается фильтр и карта одним проходом:

[1, 2, 3, 4].flatMap((n) => n % 2 === 0 ? [n * 10] : []);
// [20, 40]

14. Какой метод выбрать

Методов много, но выбор всегда решается одним вопросом: что должно получиться.

И одно предупреждение про цепочки. Каждый метод проходит массив целиком, поэтому filter().map().reduce() — это три прохода вместо одного. На сотне элементов разницы нет никакой; на сотне тысяч стоит задуматься. Читаемость почти всегда важнее, и оптимизируют такое только тогда, когда замерили и убедились.

15. Корзина и «Табель»

Вчерашняя корзина обещала научиться считать. Учим — теми же данными, что были вчера, плюс массив цен на тех же позициях:

const items = ["хлеб", "чай", "масло"];
const prices = [3.5, 12, 25];

const round2 = (x) => Math.round(x * 100) / 100;

// общая стоимость
const total = prices.reduce((sum, price) => sum + price, 0);
total;   // 40.5

// только дешёвые товары — через индекс
const cheap = items.filter((item, index) => prices[index] < 10);
cheap;   // ["хлеб"]

// цены с наценкой
const withTax = prices.map((price) => round2(price * 1.1));
withTax;   // [3.85, 13.2, 27.5]

// по возрастанию, не трогая оригинал
prices.toSorted((a, b) => a - b);   // [3.5, 12, 25]

// есть ли дорогие
prices.some((price) => price > 20);   // true

// строка для покупателя
items.map((item, index) => item + " — " + prices[index] + " м").join("; ");
// "хлеб — 3.5 м; чай — 12 м; масло — 25 м"

Всё, что вчера требовало цикла, уложилось в одну строку на задачу. Два параллельных массива — приём рабочий, но неудобный: стоит перепутать порядок в одном из них, и цены разъедутся с товарами. Завтра, на дне 21, мы наконец сложим название и цену в один объект, и индексы станут не нужны.

«Табель»: циклы схлопываются

Теперь вернёмся к сквозной программе. Её помощники писались циклами на днях 15 и 18 — сегодня каждый из них становится одной строкой.

const MIN_MARK = 2;
const MAX_MARK = 5;
const NAME_WIDTH = 12;

const toMark = (raw) => Number(String(raw).trim());
const isValidMark = (m) => Number.isInteger(m) && m >= MIN_MARK && m <= MAX_MARK;

// было — цикл с накоплением, стало — одна строка
const sum = (numbers) => numbers.reduce((total, n) => total + n, 0);

const average = (numbers) =>
  numbers.length === 0 ? 0 : sum(numbers) / numbers.length;

const maxOf = (numbers) => numbers.reduce((best, n) => Math.max(best, n));
const minOf = (numbers) => numbers.reduce((worst, n) => Math.min(worst, n));

function verdict(avg, excellent = 4.5, good = 3.5, pass = 2.5) {
  if (avg >= excellent) return "отличник";
  if (avg >= good) return "хорошист";
  if (avg >= pass) return "троечник";
  return "надо подтянуть";
}

function makeHeader() {
  return "Имя".padEnd(NAME_WIDTH) + "Средн".padStart(6) + "Мин".padStart(5)
    + "Макс".padStart(5) + "%".padStart(7) + "  Вердикт";
}

function makeRow(name = "без имени", ...raw) {
  const marks = raw.map((r) => toMark(r));
  const valid = marks.filter(isValidMark);

  if (valid.length === 0) {
    return name.padEnd(NAME_WIDTH) + "нет годных оценок";
  }

  const avg = average(valid);
  const percent = Math.round(valid.length / marks.length * 100);

  return name.padEnd(NAME_WIDTH)
    + avg.toFixed(2).padStart(6)
    + String(minOf(valid)).padStart(5)
    + String(maxOf(valid)).padStart(5)
    + (percent + "%").padStart(7)
    + "  " + verdict(avg);
}

console.log(line);

console.log(makeRow("Мерет", "3", 3, 4));
console.log(makeRow("Гүлнар", 9, 0, "пять"));
console.log(makeRow("Сапар", 5, 5, "4", 5));
console.log(makeRow("Огулджан", "4.5", 4, 5));

Вывод не изменился ни на символ — и это главная проверка переписывания, о которой шла речь на дне 15. Изменилось другое: из программы исчезли все циклы. Четыре цикла for превратились в три строки с reduce и одну с map.

Обратите внимание на maxOf: у него нет начального значения, и это осознанно. Первый элемент и есть естественный старт для максимума, а пустой список сюда не дойдёт — выше стоит ранняя ветка. Зато в sum ноль указан обязательно: его как раз могут позвать с пустым списком.

И ещё одна деталь: raw.map((r) => toMark(r)) написано стрелкой, а не коротким raw.map(toMark). Второй вариант здесь сработал бы — toMark принимает один аргумент, — но привычка из раздела 5 надёжнее.

Три опыта.

Первый. Замените raw.map((r) => toMark(r)) на raw.map(toMark) и убедитесь, что отчёт не изменился. Потом замените toMark на parseInt — и объясните получившийся отчёт.

Второй. Уберите 0 из sum и запустите. Почему отчёт не сломался? Теперь вызовите sum([]) напрямую.

Третий. Добавьте колонку «пятёрок» через filter и length, а потом получите то же число через reduce. Какая версия читается лучше?

Что будет завтра

День 21 — объекты. Сегодняшние два параллельных массива — товары отдельно, цены отдельно — превратятся в один список, где у каждого товара есть и название, и цена. Индексы для связи больше не понадобятся, а filter и map останутся ровно теми же.

Заодно станет понятнее и sort: сортировать список объектов по цене или по имени — самая обычная задача, и функция сравнения там пишется почти так же, как сегодня.

arr.forEach((x) => console.log(x));   // результата нет, break нельзя

["1", "2", "3"].map((s) => parseInt(s, 10));   // [1, 2, 3] — правильно

  1. Чем map отличается от forEach?
    Ответ map собирает результаты в новый массив той же длины, forEach ничего не возвращает. Если после forEach вы складываете результат в отдельный массив через push — вам нужен map.
  2. Почему ["1", "2", "3"].map(parseInt) даёт [1, NaN, NaN]?
    Ответ map передаёт функции три аргумента, и индекс попадает во второй параметр parseInt — систему счисления. Получается parseInt("2", 1) и parseInt("3", 2), а таких чисел в этих системах нет.
  3. Что вернёт [].every((x) => false) и почему?
    Ответ true. Проверять нечего, значит, ни один элемент правило не нарушил. Если пустой список для вас не «всё в порядке» — проверяйте длину отдельно.
  4. Зачем в reduce указывать начальное значение?
    Ответ Оно защищает от ошибки на пустом массиве, задаёт тип результата и делает код понятнее. Без него [].reduce(...) бросает TypeError: Reduce of empty array with no initial value.
  5. Две причины, по которым nums.sort() опасен.
    Ответ Он переставляет исходный массив, а не возвращает копию; и без функции сравнения сортирует как строки, поэтому 100 оказывается раньше 2. Обе беды снимает toSorted((a, b) => a - b).
