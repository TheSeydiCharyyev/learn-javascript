# День 20. Перебор массивов

<Subtitle>Выжимка лекции: сделать с каждым, собрать новый список, свернуть в одно.</Subtitle>

## Главное

<Definition>
Каждому методу передают функцию, и он зовёт её для каждого элемента. Выбор метода
решается одним вопросом: **что должно получиться**.
</Definition>

| Нужно | Метод | Вернёт |
| --- | --- | --- |
| просто действие | `forEach` | `undefined` |
| список той же длины | `map` | массив |
| список короче | `filter` | массив |
| первый подходящий | `find` / `findIndex` | элемент / позиция или −1 |
| да или нет | `some` / `every` | `true` / `false` |
| одно значение | `reduce` | что угодно |

```js
const marks = [5, 4, 3];
marks.forEach((value, index, array) => { });   // колбэк получает ТРИ аргумента

marks.map((m) => m * 10);       // [50, 40, 30]  — длина та же
marks.filter((m) => m >= 4);    // [5, 4]        — короче
marks.filter((m) => m >= 4).map((m) => m * 10);   // [50, 40] — цепочка
```

<KeyPoint>
`forEach` ничего не возвращает, и выйти из него нельзя: `break` —
ошибка, `return` работает как `continue`. Нужен досрочный
выход — берите `find`, `some` или обычный цикл.
</KeyPoint>

## Ловушка map(parseInt)

```js
["1", "2", "3"].map(Number);     // [1, 2, 3]
["1", "2", "3"].map(parseInt);   // [1, NaN, NaN]
["10", "10", "10"].map(parseInt); // [10, NaN, 2]
```

<Remember>
Индекс попадает во второй параметр `parseInt` — систему счисления.
**По имени передавайте только функции с одним аргументом**; в остальных
случаях пишите стрелку: `map((s) => parseInt(s, 10))`.
</Remember>

## Поиск и проверки

```js
marks.find((m) => m < 4);        // 3          или undefined
marks.findIndex((m) => m < 4);   // 2          или -1
marks.findLast((m) => m >= 4);   // 4 — с конца; есть и findLastIndex

marks.some((m) => m === 5);      // true — есть хотя бы один
marks.every((m) => m >= 2);      // true — все подходят

[].some(() => true);    // false
[].every(() => false);  // true — «истинно от пустоты»
```

## reduce

```js
marks.reduce((sum, mark) => sum + mark, 0);   // 12
//            накопленное  элемент          начальное значение

const names = ["Аман", "Мерет", "Сапар"];
names.reduce((line, name) => line + name + "; ", "");   // "Аман; Мерет; Сапар; "
marks.reduce((best, m) => Math.max(best, m));           // 5 — максимум

// [].reduce((a, b) => a + b)   → TypeError: Reduce of empty array with no initial value
```

<Remember>
**Начальное значение пишите всегда.** Оно защищает от пустого списка
и задаёт тип результата. Исключение — когда пустой список заведомо не дойдёт,
как в `maxOf` из «Табеля».
</Remember>

## Сортировка

```js
const nums = [10, 9, 100, 2];

nums.sort();                    // [10, 100, 2, 9] — КАК СТРОКИ
nums;                           // [10, 100, 2, 9] — и массив ПЕРЕСТАВЛЕН

nums.sort((a, b) => a - b);     // [2, 9, 10, 100] — по возрастанию
nums.sort((a, b) => b - a);     // [100, 10, 9, 2] — по убыванию
nums.toSorted((a, b) => a - b); // [2, 9, 10, 100] — копия, оригинал цел
```

```js
[[1, 2], [3, [4]]].flat();               // [1, 2, 3, [4]]
[1, 2, 3].flatMap((n) => [n, n * 10]);   // [1, 10, 2, 20, 3, 30]
[1, 2, 3, 4].flatMap((n) => n % 2 === 0 ? [n * 10] : []);   // [20, 40]
```

<NoteBox>
**Две ошибки дня:** `Reduce of empty array with no initial value`
(текст одинаков во всех браузерах) и `The comparison function must be either
a function or undefined` — когда в `sort` передали не функцию.
\
**Цепочка — это несколько проходов.** На сотне элементов неважно;
читаемость почти всегда важнее скорости.
</NoteBox>
