# День 20. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 делаем в консоли, дальше — в папке `day-20`.</Subtitle>

## Разминка

<Task title="1. Цикл становится методом" level="easy" time="6">
<Goal>заменить три знакомых цикла на методы.</Goal>

```js
const marks = [5, 4, 3, 5, 2];

// А — во сколько раз короче?
const big = [];
for (const m of marks) { big.push(m * 10); }

// Б
const good = [];
for (const m of marks) { if (m >= 4) { good.push(m); } }

// В
let total = 0;
for (const m of marks) { total += m; }
```

<Hint>
Каждый цикл превращается ровно в один метод. Посмотрите, что получается
на выходе: список той же длины, список короче или одно число.
</Hint>

<Criteria>
- все три переписаны, результаты совпали с исходными;
- для каждого названо, почему выбран именно этот метод;
- записано, сколько строк было и сколько стало;
- проверено, что `marks` после всех трёх не изменился.
</Criteria>
</Task>

<Task title="2. Сначала предскажи: что вернётся" level="easy" time="7">
<Goal>поймать шесть неочевидных ответов.</Goal>

```js
const marks = [5, 4, 3];

marks.forEach((m) => m * 10);
marks.map((m) => m >= 4);
marks.findIndex((m) => m === 5);
marks.find((m) => m > 9);
[].every((m) => false);
[].some((m) => true);
```

<Hint>
Первый ответ не массив. Третий — число, которое в условии повело бы себя как
ложь. Пятый противоречит здравому смыслу, но математически верен.
</Hint>

<Criteria>
- шесть предсказаний записаны до проверки;
- объяснено, почему `forEach` вернул не массив;
- объяснено, чем `find` отличается от `findIndex`
  в случае «не нашлось»;
- объяснено, почему `[].every(...)` даёт `true`;
- записано, как безопасно проверить `findIndex` в условии.
</Criteria>
</Task>

<Task title="3. Ловушка с parseInt" level="easy" time="7">
<Goal>разобрать ошибку, которая не падает.</Goal>

```js
console.log(["1", "2", "3"].map(Number));
console.log(["1", "2", "3"].map(parseInt));
console.log(["10", "10", "10"].map(parseInt));
```

Объясните вторую и третью строки. Потом проверьте догадку, вызвав
`parseInt` напрямую с двумя аргументами.

<Hint>
Вспомните, сколько аргументов `map` передаёт функции, и какой
у `parseInt` второй параметр.
</Hint>

<Criteria>
- все три результата записаны;
- догадка проверена тремя прямыми вызовами `parseInt`;
- объяснено, почему третий элемент в последней строке равен двум;
- записаны два правильных способа получить `[1, 2, 3]`;
- сформулировано правило про передачу функций по имени.
</Criteria>
</Task>

## Основные задания

<Task title="4. Цепочка методов" level="medium" time="12">
<Goal>собрать несколько шагов в одну запись.</Goal>

Дан «грязный» список оценок. Получите из него, одной цепочкой на каждый пункт:

```js
const raw = [5, 4, 3, 5, 2, 9, 0, 4];
```

- сумму годных оценок (от 2 до 5);
- средний балл годных, округлённый до сотых;
- список годных, умноженных на 10;
- сколько среди них пятёрок — двумя способами: через `filter`
  и через `reduce`.

<Hint>
Годные удобно отобрать один раз в отдельную переменную, а не фильтровать заново
в каждом пункте. Среднее — это сумма, делённая на длину, но делить на ноль нельзя.
</Hint>

<Criteria>
- все четыре результата получены и записаны;
- обе версии подсчёта пятёрок дают одинаковое число;
- записано, какая из двух версий читается лучше и почему;
- добавлена защита от пустого списка — показано, что ломалось без неё;
- объяснено, почему фильтровать выгоднее раньше, чем позже.
</Criteria>
</Task>

<Task title="5. sort по-настоящему" level="medium" time="13">
<Goal>увидеть обе опасности `sort` своими глазами.</Goal>

```js
const nums = [10, 9, 100, 2];

console.log(nums.sort());
console.log(nums);
```

Объясните оба вывода. Потом отсортируйте список четырьмя способами — по возрастанию,
по убыванию, не трогая оригинал двумя разными приёмами — и каждый раз печатайте
исходный массив.

<Hint>
Не испортить оригинал можно двумя способами: сделать копию перед сортировкой
или взять метод, который копию делает сам. Оба были в лекции.
</Hint>

<Criteria>
- объяснено, почему 100 оказалось между 10 и 2;
- объяснено, почему `nums` изменился;
- все четыре способа показаны, после каждого напечатан оригинал;
- отсортирован массив слов и объяснено, почему слова с большой буквы
  оказались впереди;
- записано, какой способ вы будете писать по умолчанию.
</Criteria>
</Task>

<Task title="6. Корзина считает" level="medium" time="12">
<Goal>довести вчерашнюю корзину до обещанного.</Goal>

```js
const items = ["хлеб", "чай", "масло"];
const prices = [3.5, 12, 25];
```

Посчитайте и выведите:

- общую стоимость;
- названия товаров дешевле 10 манатов;
- цены с наценкой 10 процентов, округлённые до копеек;
- цены по возрастанию, не испортив оригинал;
- строку вида `«хлеб — 3.5 м; чай — 12 м; масло — 25 м»`.

<Hint>
Массивы связаны позициями, поэтому там, где нужны и название, и цена,
понадобится второй аргумент колбэка — индекс.
</Hint>

<Criteria>
- все пять результатов получены;
- общая стоимость посчитана через `reduce` с начальным значением;
- для фильтра по цене использован индекс — объяснено зачем;
- после сортировки исходный массив цен не изменился — проверено печатью;
- добавлен товар в оба массива, и все пять пунктов пересчитаны без правок кода.
</Criteria>
</Task>

- проверено, что `maxOf([])` бросает ошибку, и записан её текст;

## Со звёздочкой

<Task title="8. Всё через reduce" level="hard" time="10">
<Goal>понять reduce настолько, чтобы собрать им остальные методы.</Goal>

Соберите через `reduce` три вещи, которые обычно делают другими
методами, и сверьте с оригиналами:

<Example>
```js
myMap([5, 4, 3], (m) => m * 10);      // [50, 40, 30]
myFilter([5, 4, 3], (m) => m >= 4);   // [5, 4]
myCount([5, 4, 5], (m) => m === 5);   // 2
```
</Example>

<Hint>
Начальное значение у первых двух — пустой массив. Внутри функции элемент
добавляют через `push` и обязательно возвращают накопитель — иначе
на следующем шаге он окажется `undefined`.
</Hint>

<Criteria>
- все три функции написаны и дают те же результаты, что встроенные;
- сверено с `map`, `filter` и
  `filter().length`;
- объяснено, зачем в функции стоит `return acc`;
- показано, что случится, если его убрать;
- записано, какой из трёх вариантов вы бы оставили в настоящем коде
  и почему.
</Criteria>
</Task>

<Task title="9. Шесть подвохов" level="hard" time="10">
<Goal>собрать вместе всё, что сегодня ведёт себя неожиданно.</Goal>

```js
// 1
const doubled = [5, 4].forEach((m) => m * 2);
console.log(doubled);

// 2
console.log([].reduce((a, b) => a + b));

// 3
const nums = [10, 9, 100, 2];
console.log(nums.sort(), nums);

// 4
console.log(["5", "10", "15"].map(parseInt));

// 5
const marks = [5, 4, 3];
if (marks.findIndex((m) => m === 5)) { console.log("пятёрка есть"); }

// 6
console.log([3, 1].sort("по возрастанию"));
```

<Hint>
Два фрагмента падают, четыре — нет. Фрагмент 5 не выведет ничего, хотя пятёрка
в массиве есть, — и это самый вредный вид ошибки. Запускайте фрагменты по одному:
упавший остановит всё, что ниже.
</Hint>

<Criteria>
- предсказания записаны до запуска;
- для двух падающих записан точный текст ошибки из своей консоли;
- объяснено, почему фрагмент 5 промолчал;
- все шесть переписаны правильно;
- записано, какие два подвоха опаснее остальных и почему.
</Criteria>
</Task>
