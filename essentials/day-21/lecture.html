1. Зачем объект

Вчера корзина жила в двух массивах: названия отдельно, цены отдельно. Связывал их только порядок.

const items = ["хлеб", "чай", "масло"];
const prices = [3.5, 12, 25];

Работать так можно, но опасно. Стоит отсортировать один массив и забыть про второй — и цены разъедутся с товарами, а программа даже не пожалуется. Каждая операция, которой нужны и название, и цена, требует индекса, и индексы приходится таскать через все функции.

Объект решает это в лоб: связанные данные лежат вместе, и у каждого есть имя.

const item = { name: "хлеб", price: 3.5 };

item.name;    // "хлеб"
item.price;   // 3.5

Отсюда правило выбора, которое работает почти всегда: много однотипного — массив, разнородное про один предмет — объект. Оценки студента — массив, сам студент — объект. А список товаров — это массив объектов, и именно так устроены почти все данные в вебе.

2. Литерал и доступ к свойствам

Объект записывают в фигурных скобках, пары «имя: значение» через запятую. Имена называются ключами, а пара целиком — свойством.

const student = {
  name: "Аман",
  age: 17,
  city: "Мары",
};

Висячая запятая после последнего свойства разрешена и даже полезна: добавляя новую строку, вы не трогаете предыдущую.

Читают свойства двумя способами:

student.name;       // "Аман"    через точку
student["name"];    // "Аман"    через квадратные скобки

Точка короче и читается лучше — её и пишут по умолчанию. Но у неё есть ограничение: после точки стоит имя, записанное буквально. Если ключ лежит в переменной, точка не поможет:

const key = "age";

student.key;     // undefined — искали свойство с именем «key»
student[key];    // 17        — а вот теперь взяли по значению переменной

И последнее про чтение: несуществующее свойство не ошибка. Объект честно отвечает undefined:

student.phone;   // undefined — свойства нет, но программа работает

Короткая запись свойства

Очень часто имя свойства совпадает с именем переменной, из которой берётся значение. Для такого случая есть сокращение:

const name = "Аман";
const age = 17;

const long = { name: name, age: age };   // длинно
const short = { name, age };             // то же самое

long.name === short.name;   // true — объекты одинаковые по содержимому

Обе записи дают одинаковый объект. Вторая встречается постоянно — особенно там, где объект собирают из параметров функции:

function makeStudent(name, marks) {
  return { name, marks };
}

makeStudent("Мерет", [4, 5]);   // { name: "Мерет", marks: [4, 5] }

Сокращение работает только при точном совпадении имён. Если свойство должно называться иначе, чем переменная, двоеточие возвращается.

3. Когда скобки обязательны

Квадратные скобки нужны в трёх случаях, и все три встречаются регулярно.

Первый — ключ в переменной, мы только что видели. Так перебирают объект и так читают поля, имя которых приходит извне.

Второй — ключ не похож на имя переменной: с пробелом, с дефисом, начинающийся с цифры:

const settings = {
  "цвет фона": "белый",
  "font-size": 14,
};

settings["цвет фона"];   // "белый"
settings["font-size"];   // 14
// settings.font-size    → ReferenceError: size is not defined — язык прочёл это как вычитание

Третий — числовой ключ. Числа в ключах превращаются в строки, поэтому обе записи ведут к одному свойству:

const marks = { 3: "удовлетворительно", 5: "отлично" };

marks[5];     // "отлично"
marks["5"];   // "отлично" — то же самое свойство

У числовых ключей есть побочный эффект, о котором стоит знать заранее: они всегда идут первыми и по возрастанию, в каком бы порядке вы их ни написали.

Object.keys({ b: 1, 2: 2, a: 3, 1: 4 });
// ["1", "2", "b", "a"] — сначала числа по порядку, потом остальные как написаны

4. Добавить, изменить, удалить

Объект, в отличие от строки, меняется свободно:

const student = { name: "Аман", age: 17 };

student.age = 18;          // изменили
student.group = "1-А";     // добавили — свойства не было, теперь есть
delete student.name;       // удалили

student;   // { age: 18, group: "1-А" }

Обратите внимание: объект объявлен через const, и это не мешает. const запрещает менять саму переменную — то есть положить в неё другой объект, — но не содержимое. То же самое было с массивами на дне 19.

Оператор delete возвращает true — и делает это даже тогда, когда удалять было нечего:

delete student.нетТакого;   // true, хотя свойства и не было

Поэтому по его результату ничего не проверяют. А присваивать undefined вместо удаления — не то же самое: свойство останется, просто с пустым значением. Разницу видно в следующем разделе.

5. Три способа спросить «а есть ли»

Вопрос «есть ли у объекта такое свойство» решается тремя способами, и они отвечают на немного разные вопросы.

const student = { name: "Аман", phone: undefined };

student.phone !== undefined;        // false — но свойство-то есть!
"phone" in student;                 // true
Object.hasOwn(student, "phone");    // true

Первый способ путает «свойства нет» и «свойство есть, но пустое». Обычно это неважно, а иногда — принципиально: в настройках «не задано» и «задано как пусто» могут значить разное.

Разница между вторым и третьим тоньше. in находит и унаследованные свойства — те, что достались объекту от языка:

"toString" in student;                 // true  — достался от языка
Object.hasOwn(student, "toString");    // false — своего такого нет

Откуда берётся toString, мы разберём в курсе 2 вместе с прототипами. Пока достаточно правила:

Спрашиваете про свои данные — берите Object.hasOwn. Он отвечает ровно на тот вопрос, который вы задаёте, и не находит лишнего. Оператор in оставьте для случаев, когда унаследованное тоже важно.

Когда разница между «нет свойства» и «свойство пустое» важна на практике? Чаще всего — в настройках. Если пользователь ничего не выбрал, подставляют умолчание; а если он выбрал «ничего», это его осознанный выбор, и умолчание подставлять нельзя:

const settings = { theme: undefined };

// неправильно: «выбрал пусто» и «не выбирал» смешались
const theme1 = settings.theme ?? "светлая";   // "светлая" в обоих случаях

// правильно: сначала спрашиваем, задавал ли вообще
const theme2 = Object.hasOwn(settings, "theme")
  ? settings.theme
  : "светлая";

theme2;   // undefined — пользователь выбрал «ничего», и мы это сохранили

Случай редкий, но показательный: ?? и hasOwn отвечают на разные вопросы, и подменять один другим можно только тогда, когда вы уверены, что undefined в данных не бывает.

6. Перебор: keys, values, entries

Три функции превращают объект в массив — и дальше работают все вчерашние методы.

const student = { name: "Аман", age: 17, city: "Мары" };

Object.keys(student);     // ["name", "age", "city"]
Object.values(student);   // ["Аман", 17, "Мары"]
Object.entries(student);  // [["name", "Аман"], ["age", 17], ["city", "Мары"]]

Самое частое применение — перебрать свойства:

Object.keys(student).forEach((key) => {
  console.log(key + ": " + student[key]);
});
// name: Аман
// age: 17
// city: Мары

С entries получается ещё короче, если взять деструктуризацию из завтрашнего дня. Пока обойдёмся индексами пары:

Object.entries(student).forEach((pair) => {
  console.log(pair[0] + ": " + pair[1]);
});

И полезная мелочь: у объекта нет length. Сколько в нём свойств, считают так:

Object.keys(student).length;   // 3

Объект как словарь

До сих пор объект был «одним предметом с разными свойствами». Есть и вторая роль: справочник, где ключ — это данные, а не заранее известное имя поля.

const verdicts = { 5: "отлично", 4: "хорошо", 3: "удовлетворительно", 2: "плохо" };

verdicts[4];             // "хорошо"
verdicts[9] ?? "нет такой оценки";   // ключа нет — подставили своё

Это замена длинной цепочке if или switch из дня 9: вместо пяти веток — одна строка. А оператор ?? из дня 7 закрывает случай «такого ключа нет».

Вторая типичная работа словаря — считать повторения. Ключом становится само значение:

const marks = [5, 4, 3, 5, 2, 5];
const counts = {};

for (const mark of marks) {
  counts[mark] = (counts[mark] ?? 0) + 1;
}

counts;      // { 2: 1, 3: 1, 4: 1, 5: 3 }
counts[5];   // 3

Приём знаком по дню 18, где мы так же считали исходы бросков кубика. Теперь понятно, что там был обычный объект-словарь.

7. for...in и почему его не любят

Цикл for...in из дня 11 перебирает ключи объекта напрямую:

for (const key in student) {
  console.log(key, student[key]);
}

Выглядит короче, чем Object.keys(...).forEach(...), но в современном коде его пишут редко. Причин две.

Первая: он заглядывает в унаследованное. Как и оператор in, он может выдать свойства, которых вы не добавляли, — если объект получил их откуда-то ещё. С Object.keys такого не бывает никогда.

Вторая: он возвращает ключ, а не значение, и результат нельзя сразу передать в map или filter. А Object.keys отдаёт обычный массив, с которым можно делать что угодно:

Object.keys(student)
  .filter((key) => key !== "age")
  .map((key) => key + " = " + student[key]);
// ["name = Аман", "city = Мары"]

8. Объединение: Object.assign

Копирует свойства из одного объекта в другой. Первый аргумент — куда, остальные — откуда:

const defaults = { city: "Мары", group: "1-А" };
const given = { name: "Аман", city: "Ашхабад" };

Object.assign({}, defaults, given);
// { city: "Ашхабад", group: "1-А", name: "Аман" }

Это тот самый приём «настройки по умолчанию», о котором шла речь на дне 14: общие значения кладут первыми, а то, что задал пользователь, — последним, и оно перекрывает остальное. Обратите внимание на {} первым аргументом.

Object.assign меняет свой первый аргумент. Если написать Object.assign(defaults, given), испортится defaults — и все, кто им пользуется. Первым аргументом почти всегда ставят пустой объект.

Тем же способом делают копию объекта:

const copy = Object.assign({}, student);

copy.age = 18;
student.age;   // 17 — оригинал цел

Завтра, на дне 22, появится более короткая запись того же самого — через три точки.

9. Объект — это ссылка

Здесь начинается то, о чём мы говорили для массивов на дне 19, и для объектов оно работает точно так же. В переменной лежит не сам объект, а ссылка на него.

const a = { x: 1 };
const b = a;      // не копия! та же самая ссылка

b.x = 2;
a.x;              // 2 — изменили «через b», а увидели «в a»

То же касается передачи в функцию: функция получает ссылку и может изменить объект вызывающего. Мы обсуждали это на дне 15 как повод не менять чужое тайком.

10. Вложенные объекты

Значением свойства может быть что угодно — число, строка, массив, другой объект:

const student = {
  name: "Аман",
  marks: [5, 4, 3],
  address: { city: "Мары", street: "Мир" },
};

student.marks[0];           // 5
student.address.city;       // "Мары"
student.marks.length;       // 3

Читается слева направо, шаг за шагом. Но у вложенности есть неприятное следствие для копий:

const copy = Object.assign({}, student);

copy.address.city = "Ашхабад";
student.address.city;   // "Ашхабад" — оригинал тоже изменился!
Object.assign делает поверхностную копию: копируются сами свойства, а вложенные объекты остаются общими. Верхний уровень независим, всё, что глубже, — нет. Это одна из самых коварных ошибок в работе с данными, потому что на плоских объектах она никак не проявляется.

Разбор: почему изменилась цена в оригинале

Вот как это выглядит в работе. Товар с вложенной ценой, копия — и неожиданность:

const product = { name: "чай", price: { value: 12, currency: "м" } };

const copy = Object.assign({}, product);
copy.price.value = 15;

product.price.value;   // 15 — а трогали только копию!

Шаг 1. Проверяем, точно ли копия отдельная. Меняем свойство верхнего уровня — и убеждаемся, что тут всё в порядке:

copy.name = "зелёный чай";
product.name;   // "чай" — верхний уровень независим

Шаг 2. Значит, дело во вложенном. Сравниваем не значения, а сами объекты — тот ли это объект:

copy.price === product.price;   // true — один и тот же объект!

Шаг 3. Чиним. Копируем вложенный объект отдельно:

const copy = Object.assign({}, product, {
  price: Object.assign({}, product.price),
});

Обратите внимание на шаг 2: сравнение через === для объектов отвечает не «одинаковы ли они», а «тот ли это самый объект». Два объекта с одинаковым содержимым не равны друг другу — и это отдельная ловушка, которая встретится в проектах.

Как делать копию «на всю глубину» одной командой, разберём в курсе 2. В этом курсе нам хватит правила: если у объекта есть вложенные объекты, копировать его через assign недостаточно.

11. Методы объекта

Функция, лежащая в свойстве, называется методом. Пишут их короткой записью — без слова function и без двоеточия:

const student = {
  name: "Аман",
  marks: [5, 4],

  addMark(mark) {
    this.marks.push(mark);   // курс 2
  },

  count() {
    return this.marks.length;   // курс 2
  },
};

student.addMark(3);
student.count();   // 3

Слово this внутри метода означает «тот объект, у которого метод вызвали». Устроено оно сложнее, чем кажется, и полный разбор ждёт в курсе 2 — вместе с причиной, по которой методом нельзя делать стрелочную функцию (об этом говорили на дне 13).

Пока запомните две вещи: метод записывают короткой формой и к своим свойствам обращаются через this.

Методы удобны тем, что данные и действия над ними лежат в одном месте. Сравните два подхода к одной задаче:

// данные отдельно, функции отдельно
function addStudent(list, student) { list.push(student); }
function countStudents(list) { return list.length; }

const students = [];
addStudent(students, { name: "Аман" });
countStudents(students);   // 1

// данные и действия вместе
const group = {
  title: "1-А",
  students: [],
  add(student) { this.students.push(student); },   // курс 2
  size() { return this.students.length; },         // курс 2
};

group.add({ name: "Аман" });
group.size();   // 1

Во втором варианте не нужно каждый раз передавать список — метод знает, с чем работает. Именно из этой идеи выросли классы, которые разбирают в курсе 2.

Есть и обратная сторона: объект с методами труднее проверять и копировать, а в этом курсе нам почти всегда хватает простых объектов с данными и отдельных функций. Так устроен и «Табель», и корзина.

12. fromEntries и groupBy

Object.fromEntries делает обратное entries — собирает объект из массива пар:

Object.fromEntries([["a", 1], ["b", 2]]);   // { a: 1, b: 2 }

Вместе они дают приём «переделать объект»: разобрали на пары, обработали вчерашними методами, собрали обратно.

Object.groupBy — новее и полезнее. Он раскладывает массив по группам и отдаёт объект, где ключ — название группы:

const marks = [5, 4, 3, 5, 2];

Object.groupBy(marks, (m) => m % 2 === 0 ? "чётные" : "нечётные");
// { нечётные: [5, 3, 5], чётные: [4, 2] }

Метод совсем свежий — как Math.sumPrecise из дня 18, его может не оказаться в старом браузере. Проверять так же: typeof Object.groupBy. В задании со звёздочкой мы соберём такой же группировщик сами, через reduce, — и он заработает где угодно.

"use strict";

// TypeError: Cannot create property 'x' on number '1'

Без строгого режима то же присваивание молча не сработает, и n.x останется undefined. Так же ведёт себя и удаление защищённого свойства: в строгом режиме TypeError: Cannot delete property 'x' of #<Object>, в обычном — тишина.

Это уже четвёртый и пятый случаи в курсе, когда поведение зависит от режима. Первые три были на днях 4, 14 и 16.

14. Корзина на объектах

Возвращаемся к корзине. Теперь товар — один объект, а корзина — массив объектов:

const cart = [
  { name: "хлеб", price: 3.5 },
  { name: "чай", price: 12 },
  { name: "масло", price: 25 },
];

// общая стоимость
cart.reduce((sum, item) => sum + item.price, 0);   // 40.5

// дешёвые товары — никаких индексов
cart.filter((item) => item.price < 10);
// [{ name: "хлеб", price: 3.5 }]

// только названия
cart.map((item) => item.name);   // ["хлеб", "чай", "масло"]

// по цене и по имени
cart.toSorted((a, b) => a.price - b.price).map((i) => i.name);
// ["хлеб", "чай", "масло"]

cart.toSorted((a, b) => a.name < b.name ? -1 : 1).map((i) => i.name);
// ["масло", "хлеб", "чай"]

// строка для покупателя
cart.map((i) => i.name + " — " + i.price + " м").join("; ");
// "хлеб — 3.5 м; чай — 12 м; масло — 25 м"

Сравните с вчерашним вариантом: индексы исчезли отовсюду. Фильтр больше не лезет во второй массив, сортировка не рискует разорвать пару, а добавить товару третье свойство — количество, скидку, штрихкод — можно, не трогая ни одной из этих строк.

И сортировка по имени стала возможной вообще: вчера она переставила бы названия, оставив цены на месте.

15. «Табель»: студент стал объектом

Та же перемена в сквозной программе. Раньше имя и оценки приходили в makeRow отдельными аргументами; теперь студент — объект, а весь список — массив объектов.

const MIN_MARK = 2;
const MAX_MARK = 5;
const NAME_WIDTH = 12;

const toMark = (raw) => Number(String(raw).trim());
const isValidMark = (m) => Number.isInteger(m) && m >= MIN_MARK && m <= MAX_MARK;

const sum = (numbers) => numbers.reduce((total, n) => total + n, 0);
const average = (numbers) =>
  numbers.length === 0 ? 0 : sum(numbers) / numbers.length;
const maxOf = (numbers) => numbers.reduce((best, n) => Math.max(best, n));
const minOf = (numbers) => numbers.reduce((worst, n) => Math.min(worst, n));

function verdict(avg, excellent = 4.5, good = 3.5, pass = 2.5) {
  if (avg >= excellent) return "отличник";
  if (avg >= good) return "хорошист";
  if (avg >= pass) return "троечник";
  return "надо подтянуть";
}

// новое: данные и код разошлись окончательно
const students = [
  { name: "Аман", marks: [5, "4", " 9 ", 3, 5, 0, "4", 5] },
  { name: "Мерет", marks: ["3", 3, 4] },
  { name: "Гүлнар", marks: [9, 0, "пять"] },
  { name: "Сапар", marks: [5, 5, "4", 5] },
  { name: "Огулджан", marks: ["4.5", 4, 5] },
];

function makeHeader() {
  return "Имя".padEnd(NAME_WIDTH) + "Средн".padStart(6) + "Мин".padStart(5)
    + "Макс".padStart(5) + "%".padStart(7) + "  Вердикт";
}

function makeRow(student) {
  const name = student.name ?? "без имени";
  const marks = (student.marks ?? []).map((r) => toMark(r));
  const valid = marks.filter(isValidMark);

  if (valid.length === 0) {
    return name.padEnd(NAME_WIDTH) + "нет годных оценок";
  }

  const avg = average(valid);
  const percent = Math.round(valid.length / marks.length * 100);

  return name.padEnd(NAME_WIDTH)
    + avg.toFixed(2).padStart(6)
    + String(minOf(valid)).padStart(5)
    + String(maxOf(valid)).padStart(5)
    + (percent + "%").padStart(7)
    + "  " + verdict(avg);
}

const line = "-".repeat(56);

console.log(makeHeader());
console.log(line);
students.map(makeRow).forEach((row) => console.log(row));

Данные отделились от кода. Раньше студенты жили в вызовах console.log; теперь это список, который легко заменить — хоть на данные с сервера из дня 31. Ни одна функция при этом не изменится.

makeRow принимает один аргумент вместо остаточного списка. Поэтому её можно передать в map прямо по имени — и это как раз безопасный случай из вчерашнего разбора: функция берёт один параметр, лишние аргументы map ей не мешают.

Оператор ?? из дня 7 подставляет значения, если свойства нет вовсе. Проверьте: makeRow({}) не упадёт и вернёт строку, где после «без имени» стоит «нет годных оценок».

Три опыта.

Первый. Добавьте студентам свойство group и выведите только тех, кто из «1-А», не меняя makeRow.

Второй. Отсортируйте список по имени, а потом по числу оценок. Что пришлось поменять в программе? А что пришлось бы менять вчера, до объектов?

Третий. Сделайте копию списка через students.map((s) => Object.assign({}, s)) и добавьте оценку одному студенту в копии. Проверьте оригинал и объясните результат.

  1. Когда для доступа к свойству нужны квадратные скобки?
    Ответ Когда ключ лежит в переменной, когда он не похож на имя переменной (пробел, дефис) и когда он числовой. Во всех остальных случаях точка короче и читается лучше.
  2. Чем "x" in obj отличается от Object.hasOwn(obj, "x")?
    Ответ in находит и унаследованные свойства — например, toString, которого вы не добавляли. hasOwn отвечает только про свои. Для своих данных берут hasOwn.
  3. Что не так с Object.assign(defaults, given)?
    Ответ Первый аргумент меняется, то есть defaults будет испорчен для всех, кто им пользуется. Первым аргументом ставят пустой объект: Object.assign({}, defaults, given).
  4. Почему после Object.assign({}, student) правка copy.address.city меняет и оригинал?
    Ответ Копия поверхностная: скопировались сами свойства, а вложенный объект address остался общим — обе переменные ссылаются на него. Верхний уровень независим, всё глубже — нет.
  5. Как проверить, что объект пустой?
    Ответ Object.keys(obj).length === 0. Проверка if (obj) не работает: любой объект, даже пустой, истинен.
