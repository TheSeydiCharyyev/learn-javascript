## 1. Зачем объект {#why}

Вчера корзина жила в двух массивах: названия отдельно, цены отдельно. Связывал
их только порядок.

```js
const items = ["хлеб", "чай", "масло"];
const prices = [3.5, 12, 25];
```

Работать так можно, но опасно. Стоит отсортировать один массив и забыть про второй —
и цены разъедутся с товарами, а программа даже не пожалуется. Каждая операция, которой
нужны и название, и цена, требует индекса, и индексы приходится таскать через все
функции.

Объект решает это в лоб: **связанные данные лежат вместе, и у каждого есть
имя**.

```js
const item = { name: "хлеб", price: 3.5 };

item.name;    // "хлеб"
item.price;   // 3.5
```

<Scheme src="scheme-why.svg">Одни и те же данные. Слева их связывает только позиция, справа — сама структура</Scheme>

Отсюда правило выбора, которое работает почти всегда: **много однотипного —
массив, разнородное про один предмет — объект**. Оценки студента — массив,
сам студент — объект. А список товаров — это массив
объектов, и именно так устроены почти все данные в вебе.

## 2. Литерал и доступ к свойствам {#literal}

Объект записывают в фигурных скобках, пары «имя: значение» через запятую. Имена
называются **ключами**, а пара целиком — **свойством**.

```js
const student = {
  name: "Аман",
  age: 17,
  city: "Мары",
};
```

Висячая запятая после последнего свойства разрешена и даже полезна: добавляя новую
строку, вы не трогаете предыдущую.

Читают свойства двумя способами:

```js
student.name;       // "Аман"    через точку
student["name"];    // "Аман"    через квадратные скобки
```

Точка короче и читается лучше — её и пишут по умолчанию. Но у неё есть ограничение:
**после точки стоит имя, записанное буквально**. Если ключ лежит
в переменной, точка не поможет:

```js
const key = "age";

student.key;     // undefined — искали свойство с именем «key»
student[key];    // 17        — а вот теперь взяли по значению переменной
```

И последнее про чтение: **несуществующее свойство не ошибка**. Объект
честно отвечает `undefined`:

```js
student.phone;   // undefined — свойства нет, но программа работает
```

### Короткая запись свойства

Очень часто имя свойства совпадает с именем переменной, из которой берётся значение.
Для такого случая есть сокращение:

```js
const name = "Аман";
const age = 17;

const long = { name: name, age: age };   // длинно
const short = { name, age };             // то же самое

long.name === short.name;   // true — объекты одинаковые по содержимому
```

Обе записи дают одинаковый объект. Вторая встречается постоянно — особенно там,
где объект собирают из параметров функции:

```js
function makeStudent(name, marks) {
  return { name, marks };
}

makeStudent("Мерет", [4, 5]);   // { name: "Мерет", marks: [4, 5] }
```

Сокращение работает только при точном совпадении имён. Если свойство должно
называться иначе, чем переменная, двоеточие возвращается.

## 3. Когда скобки обязательны {#brackets}

Квадратные скобки нужны в трёх случаях, и все три встречаются регулярно.

**Первый — ключ в переменной**, мы только что видели. Так перебирают
объект и так читают поля, имя которых приходит извне.

**Второй — ключ не похож на имя переменной**: с пробелом, с дефисом,
начинающийся с цифры:

```js
const settings = {
  "цвет фона": "белый",
  "font-size": 14,
};

settings["цвет фона"];   // "белый"
settings["font-size"];   // 14
// settings.font-size    → ReferenceError: size is not defined — язык прочёл это как вычитание
```

**Третий — числовой ключ.** Числа в ключах превращаются в строки,
поэтому обе записи ведут к одному свойству:

```js
const marks = { 3: "удовлетворительно", 5: "отлично" };

marks[5];     // "отлично"
marks["5"];   // "отлично" — то же самое свойство
```

У числовых ключей есть побочный эффект, о котором стоит знать заранее:
**они всегда идут первыми и по возрастанию**, в каком бы порядке
вы их ни написали.

```js
Object.keys({ b: 1, 2: 2, a: 3, 1: 4 });
// ["1", "2", "b", "a"] — сначала числа по порядку, потом остальные как написаны
```

## 4. Добавить, изменить, удалить {#change}

Объект, в отличие от строки, меняется свободно:

```js
const student = { name: "Аман", age: 17 };

student.age = 18;          // изменили
student.group = "1-А";     // добавили — свойства не было, теперь есть
delete student.name;       // удалили

student;   // { age: 18, group: "1-А" }
```

Обратите внимание: объект объявлен через `const`, и это не мешает.
`const` запрещает менять **саму переменную** — то есть положить
в неё другой объект, — но не содержимое. То же самое было с массивами на дне 19.

Оператор `delete` возвращает `true` — и делает это даже тогда,
когда удалять было нечего:

```js
delete student.нетТакого;   // true, хотя свойства и не было
```

Поэтому по его результату ничего не проверяют. А присваивать `undefined`
вместо удаления — не то же самое: свойство останется, просто с пустым значением.
Разницу видно в следующем разделе.

## 5. Три способа спросить «а есть ли» {#missing}

Вопрос «есть ли у объекта такое свойство» решается тремя способами, и они отвечают
на немного разные вопросы.

```js
const student = { name: "Аман", phone: undefined };

student.phone !== undefined;        // false — но свойство-то есть!
"phone" in student;                 // true
Object.hasOwn(student, "phone");    // true
```

Первый способ путает «свойства нет» и «свойство есть, но пустое». Обычно это неважно,
а иногда — принципиально: в настройках «не задано» и «задано как пусто» могут значить
разное.

Разница между вторым и третьим тоньше. `in` находит и **унаследованные**
свойства — те, что достались объекту от языка:

```js
"toString" in student;                 // true  — достался от языка
Object.hasOwn(student, "toString");    // false — своего такого нет
```

Откуда берётся `toString`, мы разберём в курсе 2 вместе с прототипами.
Пока достаточно правила:

<Important>
**Спрашиваете про свои данные — берите `Object.hasOwn`.**
Он отвечает ровно на тот вопрос, который вы задаёте, и не находит лишнего.
Оператор `in` оставьте для случаев, когда унаследованное тоже важно.
</Important>

Когда разница между «нет свойства» и «свойство пустое» важна на практике?
Чаще всего — в настройках. Если пользователь ничего не выбрал, подставляют умолчание;
а если он выбрал «ничего», это его осознанный выбор, и умолчание подставлять нельзя:

```js
const settings = { theme: undefined };

// неправильно: «выбрал пусто» и «не выбирал» смешались
const theme1 = settings.theme ?? "светлая";   // "светлая" в обоих случаях

// правильно: сначала спрашиваем, задавал ли вообще
const theme2 = Object.hasOwn(settings, "theme")
  ? settings.theme
  : "светлая";

theme2;   // undefined — пользователь выбрал «ничего», и мы это сохранили
```

Случай редкий, но показательный: `??` и `hasOwn` отвечают
на разные вопросы, и подменять один другим можно только тогда, когда вы уверены,
что `undefined` в данных не бывает.

## 6. Перебор: keys, values, entries {#iterate}

Три функции превращают объект в массив — и дальше работают все вчерашние методы.

```js
const student = { name: "Аман", age: 17, city: "Мары" };

Object.keys(student);     // ["name", "age", "city"]
Object.values(student);   // ["Аман", 17, "Мары"]
Object.entries(student);  // [["name", "Аман"], ["age", 17], ["city", "Мары"]]
```

<Scheme src="scheme-iterate.svg">Объект превращается в массив, и вчерашние методы снова в деле</Scheme>

Самое частое применение — перебрать свойства:

```js
Object.keys(student).forEach((key) => {
  console.log(key + ": " + student[key]);
});
// name: Аман
// age: 17
// city: Мары
```

С `entries` получается ещё короче, если взять деструктуризацию
из завтрашнего дня. Пока обойдёмся индексами пары:

```js
Object.entries(student).forEach((pair) => {
  console.log(pair[0] + ": " + pair[1]);
});
```

И полезная мелочь: **у объекта нет `length`**. Сколько
в нём свойств, считают так:

```js
Object.keys(student).length;   // 3
```

### Объект как словарь

До сих пор объект был «одним предметом с разными свойствами». Есть и вторая роль:
**справочник, где ключ — это данные**, а не заранее известное имя поля.

```js
const verdicts = { 5: "отлично", 4: "хорошо", 3: "удовлетворительно", 2: "плохо" };

verdicts[4];             // "хорошо"
verdicts[9] ?? "нет такой оценки";   // ключа нет — подставили своё
```

Это замена длинной цепочке `if` или `switch` из дня 9:
вместо пяти веток — одна строка. А оператор `??` из дня 7 закрывает случай
«такого ключа нет».

Вторая типичная работа словаря — считать повторения. Ключом становится само значение:

```js
const marks = [5, 4, 3, 5, 2, 5];
const counts = {};

for (const mark of marks) {
  counts[mark] = (counts[mark] ?? 0) + 1;
}

counts;      // { 2: 1, 3: 1, 4: 1, 5: 3 }
counts[5];   // 3
```

Приём знаком по дню 18, где мы так же считали исходы бросков кубика. Теперь понятно,
что там был обычный объект-словарь.

## 7. `for...in` и почему его не любят {#forin}

Цикл `for...in` из дня 11 перебирает ключи объекта напрямую:

```js
for (const key in student) {
  console.log(key, student[key]);
}
```

Выглядит короче, чем `Object.keys(...).forEach(...)`, но в современном коде
его пишут редко. Причин две.

**Первая: он заглядывает в унаследованное.** Как и оператор `in`,
он может выдать свойства, которых вы не добавляли, — если объект получил их откуда-то
ещё. С `Object.keys` такого не бывает никогда.

**Вторая: он возвращает ключ, а не значение**, и результат нельзя сразу
передать в `map` или `filter`. А `Object.keys` отдаёт
обычный массив, с которым можно делать что угодно:

```js
Object.keys(student)
  .filter((key) => key !== "age")
  .map((key) => key + " = " + student[key]);
// ["name = Аман", "city = Мары"]
```

## 8. Объединение: `Object.assign` {#assign}

Копирует свойства из одного объекта в другой. Первый аргумент — куда, остальные —
откуда:

```js
const defaults = { city: "Мары", group: "1-А" };
const given = { name: "Аман", city: "Ашхабад" };

Object.assign({}, defaults, given);
// { city: "Ашхабад", group: "1-А", name: "Аман" }
```

Это тот самый приём «настройки по умолчанию», о котором шла речь на дне 14: общие
значения кладут первыми, а то, что задал пользователь, — последним, и оно перекрывает
остальное. Обратите внимание на `{}` первым аргументом.

<Mistake>
**`Object.assign` меняет свой первый аргумент.**
Если написать `Object.assign(defaults, given)`, испортится
`defaults` — и все, кто им пользуется. Первым аргументом почти всегда
ставят пустой объект.
</Mistake>

Тем же способом делают копию объекта:

```js
const copy = Object.assign({}, student);

copy.age = 18;
student.age;   // 17 — оригинал цел
```

Завтра, на дне 22, появится более короткая запись того же самого — через три точки.

## 9. Объект — это ссылка {#reference}

Здесь начинается то, о чём мы говорили для массивов на дне 19, и для объектов оно
работает точно так же. **В переменной лежит не сам объект, а ссылка на него.**

```js
const a = { x: 1 };
const b = a;      // не копия! та же самая ссылка

b.x = 2;
a.x;              // 2 — изменили «через b», а увидели «в a»
```

<Scheme src="scheme-reference.svg">Слева одна коробка и две наклейки, справа — две коробки</Scheme>

То же касается передачи в функцию: функция получает ссылку и может изменить объект
вызывающего. Мы обсуждали это на дне 15 как повод не менять чужое тайком.

## 10. Вложенные объекты {#nested}

Значением свойства может быть что угодно — число, строка, массив, другой объект:

```js
const student = {
  name: "Аман",
  marks: [5, 4, 3],
  address: { city: "Мары", street: "Мир" },
};

student.marks[0];           // 5
student.address.city;       // "Мары"
student.marks.length;       // 3
```

Читается слева направо, шаг за шагом. Но у вложенности есть неприятное следствие
для копий:

```js
const copy = Object.assign({}, student);

copy.address.city = "Ашхабад";
student.address.city;   // "Ашхабад" — оригинал тоже изменился!
```

<Mistake>
`Object.assign` делает **поверхностную копию**: копируются
сами свойства, а вложенные объекты остаются общими. Верхний уровень независим,
всё, что глубже, — нет. Это одна из самых коварных ошибок в работе с данными,
потому что на плоских объектах она никак не проявляется.
</Mistake>

### Разбор: почему изменилась цена в оригинале

Вот как это выглядит в работе. Товар с вложенной ценой, копия — и неожиданность:

```js
const product = { name: "чай", price: { value: 12, currency: "м" } };

const copy = Object.assign({}, product);
copy.price.value = 15;

product.price.value;   // 15 — а трогали только копию!
```

**Шаг 1. Проверяем, точно ли копия отдельная.** Меняем свойство верхнего
уровня — и убеждаемся, что тут всё в порядке:

```js
copy.name = "зелёный чай";
product.name;   // "чай" — верхний уровень независим
```

**Шаг 2. Значит, дело во вложенном.** Сравниваем не значения, а сами
объекты — тот ли это объект:

```js
copy.price === product.price;   // true — один и тот же объект!
```

**Шаг 3. Чиним.** Копируем вложенный объект отдельно:

```js
const copy = Object.assign({}, product, {
  price: Object.assign({}, product.price),
});
```

Обратите внимание на шаг 2: сравнение через `===` для объектов отвечает
не «одинаковы ли они», а **«тот ли это самый объект»**. Два объекта
с одинаковым содержимым не равны друг другу — и это отдельная ловушка, которая
встретится в проектах.

Как делать копию «на всю глубину» одной командой, разберём в курсе 2. В этом курсе
нам хватит правила: **если у объекта есть вложенные объекты, копировать его через
`assign` недостаточно**.

## 11. Методы объекта {#methods}

Функция, лежащая в свойстве, называется **методом**. Пишут их короткой
записью — без слова `function` и без двоеточия:

```js
const student = {
  name: "Аман",
  marks: [5, 4],

  addMark(mark) {
    this.marks.push(mark);   // курс 2
  },

  count() {
    return this.marks.length;   // курс 2
  },
};

student.addMark(3);
student.count();   // 3
```

Слово `this` внутри метода означает «тот объект, у которого метод вызвали».
Устроено оно сложнее, чем кажется, и полный разбор ждёт в курсе 2 — вместе с причиной,
по которой методом нельзя делать стрелочную функцию (об этом говорили на дне 13).

Пока запомните две вещи: **метод записывают короткой формой**
и **к своим свойствам обращаются через `this`**.

Методы удобны тем, что данные и действия над ними лежат в одном месте. Сравните
два подхода к одной задаче:

```js
// данные отдельно, функции отдельно
function addStudent(list, student) { list.push(student); }
function countStudents(list) { return list.length; }

const students = [];
addStudent(students, { name: "Аман" });
countStudents(students);   // 1

// данные и действия вместе
const group = {
  title: "1-А",
  students: [],
  add(student) { this.students.push(student); },   // курс 2
  size() { return this.students.length; },         // курс 2
};

group.add({ name: "Аман" });
group.size();   // 1
```

Во втором варианте не нужно каждый раз передавать список — метод знает, с чем
работает. Именно из этой идеи выросли классы, которые разбирают в курсе 2.

Есть и обратная сторона: объект с методами труднее проверять и копировать,
а в этом курсе нам почти всегда хватает простых объектов с данными и отдельных
функций. Так устроен и «Табель», и корзина.

## 12. `fromEntries` и `groupBy` {#from-group}

`Object.fromEntries` делает обратное `entries` — собирает объект
из массива пар:

```js
Object.fromEntries([["a", 1], ["b", 2]]);   // { a: 1, b: 2 }
```

Вместе они дают приём «переделать объект»: разобрали на пары, обработали вчерашними
методами, собрали обратно.

`Object.groupBy` — новее и полезнее. Он раскладывает массив по группам
и отдаёт объект, где ключ — название группы:

```js
const marks = [5, 4, 3, 5, 2];

Object.groupBy(marks, (m) => m % 2 === 0 ? "чётные" : "нечётные");
// { нечётные: [5, 3, 5], чётные: [4, 2] }
```

Метод совсем свежий — как `Math.sumPrecise` из дня 18, его может
не оказаться в старом браузере. Проверять так же: `typeof Object.groupBy`.
В задании со звёздочкой мы соберём такой же группировщик сами, через
`reduce`, — и он заработает где угодно.

## 13. Ошибки с объектами {#errors}

В справочнике дня девять страниц ошибок — больше, чем в любом другом дне курса.
Почти все они синтаксические: объект легко записать неправильно.

| Что написали | Текст в Chrome |
| --- | --- |
| `{ x = 5 }` | `SyntaxError: Invalid shorthand property initializer` |
| `{ a: 1, b: 2 c: 3 }` | `SyntaxError: Unexpected identifier 'c'` |
| `o.` без имени | `SyntaxError: Unexpected token ')'` |
| `[1, 2;` | `SyntaxError: Unexpected token ';'` |
| `{ __proto__: 1, __proto__: 2 }` | `SyntaxError: Duplicate __proto__ fields are not allowed in object literals` |
| `"x" in "строка"` | `TypeError: Cannot use 'in' operator to search for 'x' in строка` |
| `undefined.x` | `TypeError: Cannot read properties of undefined (reading 'x')` |

<Mistake>
Четыре верхние страницы на MDN озаглавлены иначе — «missing : after property id»,
«missing \} after property list», «missing name after . operator», «missing \] after
element list». Это формулировки Firefox, и они понятнее. Chrome в трёх случаях
из четырёх говорит «неожиданный токен» или «неожиданный идентификатор» и показывает место — ищите ошибку на строку выше.
</Mistake>

Две оставшиеся ошибки — не синтаксические, и обе **появляются только в строгом
режиме**:

```js
"use strict";
const n = 1;
n.x = 5;
// TypeError: Cannot create property 'x' on number '1'
```

Без строгого режима то же присваивание молча не сработает, и `n.x` останется
`undefined`. Так же ведёт себя и удаление защищённого свойства: в строгом
режиме `TypeError: Cannot delete property 'x' of #<Object>`,
в обычном — тишина.

Это уже четвёртый и пятый случаи в курсе, когда поведение зависит от режима. Первые
три были на днях 4, 14 и 16.

## 14. Корзина на объектах {#cart}

Возвращаемся к корзине. Теперь товар — один объект, а корзина — массив объектов:

```js
const cart = [
  { name: "хлеб", price: 3.5 },
  { name: "чай", price: 12 },
  { name: "масло", price: 25 },
];

// общая стоимость
cart.reduce((sum, item) => sum + item.price, 0);   // 40.5

// дешёвые товары — никаких индексов
cart.filter((item) => item.price < 10);
// [{ name: "хлеб", price: 3.5 }]

// только названия
cart.map((item) => item.name);   // ["хлеб", "чай", "масло"]

// по цене и по имени
cart.toSorted((a, b) => a.price - b.price).map((i) => i.name);
// ["хлеб", "чай", "масло"]

cart.toSorted((a, b) => a.name < b.name ? -1 : 1).map((i) => i.name);
// ["масло", "хлеб", "чай"]

// строка для покупателя
cart.map((i) => i.name + " — " + i.price + " м").join("; ");
// "хлеб — 3.5 м; чай — 12 м; масло — 25 м"
```

Сравните с вчерашним вариантом: **индексы исчезли отовсюду**. Фильтр
больше не лезет во второй массив, сортировка не рискует разорвать пару, а добавить
товару третье свойство — количество, скидку, штрихкод — можно, не трогая ни одной
из этих строк.

И сортировка по имени стала возможной вообще: вчера она переставила бы названия,
оставив цены на месте.

## 15. «Табель»: студент стал объектом {#tabel}

Та же перемена в сквозной программе. Раньше имя и оценки приходили в `makeRow`
отдельными аргументами; теперь студент — объект, а весь список — массив объектов.

```js
const MIN_MARK = 2;
const MAX_MARK = 5;
const NAME_WIDTH = 12;

const toMark = (raw) => Number(String(raw).trim());
const isValidMark = (m) => Number.isInteger(m) && m >= MIN_MARK && m <= MAX_MARK;

const sum = (numbers) => numbers.reduce((total, n) => total + n, 0);
const average = (numbers) =>
  numbers.length === 0 ? 0 : sum(numbers) / numbers.length;
const maxOf = (numbers) => numbers.reduce((best, n) => Math.max(best, n));
const minOf = (numbers) => numbers.reduce((worst, n) => Math.min(worst, n));

function verdict(avg, excellent = 4.5, good = 3.5, pass = 2.5) {
  if (avg >= excellent) return "отличник";
  if (avg >= good) return "хорошист";
  if (avg >= pass) return "троечник";
  return "надо подтянуть";
}

// новое: данные и код разошлись окончательно
const students = [
  { name: "Аман", marks: [5, "4", " 9 ", 3, 5, 0, "4", 5] },
  { name: "Мерет", marks: ["3", 3, 4] },
  { name: "Гүлнар", marks: [9, 0, "пять"] },
  { name: "Сапар", marks: [5, 5, "4", 5] },
  { name: "Огулджан", marks: ["4.5", 4, 5] },
];

function makeHeader() {
  return "Имя".padEnd(NAME_WIDTH) + "Средн".padStart(6) + "Мин".padStart(5)
    + "Макс".padStart(5) + "%".padStart(7) + "  Вердикт";
}

function makeRow(student) {
  const name = student.name ?? "без имени";
  const marks = (student.marks ?? []).map((r) => toMark(r));
  const valid = marks.filter(isValidMark);

  if (valid.length === 0) {
    return name.padEnd(NAME_WIDTH) + "нет годных оценок";
  }

  const avg = average(valid);
  const percent = Math.round(valid.length / marks.length * 100);

  return name.padEnd(NAME_WIDTH)
    + avg.toFixed(2).padStart(6)
    + String(minOf(valid)).padStart(5)
    + String(maxOf(valid)).padStart(5)
    + (percent + "%").padStart(7)
    + "  " + verdict(avg);
}

const line = "-".repeat(56);

console.log(makeHeader());
console.log(line);
students.map(makeRow).forEach((row) => console.log(row));
console.log(line);
```

```plain-out
Аман          4.33    3    5    75%  хорошист
Мерет         3.33    3    4   100%  троечник
Гүлнар      нет годных оценок
Сапар         4.75    4    5   100%  отличник
Огулджан      4.50    4    5    67%  отличник
--------------------------------------------------------
```

Числа те же, что на дне 20, — переписывание снова ничего не сломало. А устройство
программы изменилось сильно.

**Данные отделились от кода.** Раньше студенты жили в вызовах
`console.log`; теперь это список, который легко заменить — хоть на данные
с сервера из дня 31. Ни одна функция при этом не изменится.

**`makeRow` принимает один аргумент вместо остаточного списка.**
Поэтому её можно передать в `map` прямо по имени — и это как раз безопасный
случай из вчерашнего разбора: функция берёт один параметр, лишние аргументы
`map` ей не мешают.

**Оператор `??` из дня 7** подставляет значения, если свойства
нет вовсе. Проверьте: `makeRow({})` не упадёт и вернёт строку, где после
«без имени» стоит «нет годных оценок».

## 16. Частые ошибки и что завтра {#mistakes}

| Ошибка | Почему | Как правильно |
| --- | --- | --- |
| `obj.key`, когда ключ в переменной | после точки имя читается буквально | `obj[key]` |
| `obj.length` для числа свойств | у объекта нет `length` | `Object.keys(obj).length` |
| `Object.assign(defaults, given)` | портит первый аргумент | `Object.assign({}, defaults, given)` |
| копия через `assign` у вложенного объекта | копия поверхностная | копировать вложенное отдельно |
| `const b = a` как «копия» | копируется ссылка, не объект | `Object.assign({}, a)` |
| `if (obj)` как «объект не пустой» | пустой объект тоже истинен | `Object.keys(obj).length > 0` |
| `delete` и проверка его результата | он возвращает `true` почти всегда | проверять `Object.hasOwn` до или после |
| `{ x = 5 }` вместо `{ x: 5 }` | в литерале двоеточие, а не равно | `Invalid shorthand property initializer` подскажет |

### Что будет завтра

День 22 — деструктуризация, spread и необязательная цепочка. Все три родились
из сегодняшней темы: доставать свойства по именам одной строкой, копировать
и объединять объекты тремя точками вместо `Object.assign`, безопасно
обращаться к вложенным полям, которых может не быть.

Сегодняшний `student.address.city` — как раз случай для завтрашнего
`?.`: если адрес не заполнен, такая запись падает с

этого избегать.

<Cheatsheet>
```js
// ЛИТЕРАЛ И ДОСТУП
const student = { name: "Аман", age: 17 };
student.name;      // "Аман" — точка: имя буквально
student["name"];   // "Аман" — скобки: любое выражение
const key = "age";
student[key];      // 17 — ключ в переменной: ТОЛЬКО скобки
student.phone;     // undefined, а не ошибка

// СКОБКИ ОБЯЗАТЕЛЬНЫ: ключ в переменной, с пробелом, числовой
const settings = { "цвет фона": "белый" };
settings["цвет фона"];   // "белый"
const verdicts = { 5: "отлично" };
verdicts[5];             // "отлично"

// МЕНЯЕМ
student.age = 18;        // изменили
student.group = "1-А";   // добавили
delete student.name;     // удалили (вернёт true почти всегда)
// const объекту не мешает: запрещена смена ПЕРЕМЕННОЙ, не содержимого

// ЕСТЬ ЛИ СВОЙСТВО
const s = { phone: undefined };
s.phone !== undefined;       // false — путает «нет» и «пусто»
"phone" in s;                // true — включая унаследованные
Object.hasOwn(s, "phone");   // true — своё: БРАТЬ ЭТО

// ПЕРЕБОР
const obj = { name: "Аман", age: 17 };
Object.keys(obj);          // ["name", "age"]
Object.values(obj);        // ["Аман", 17]
Object.entries(obj);       // [["name", "Аман"], ["age", 17]]
Object.keys(obj).length;   // 2 — у объекта НЕТ length

// ОБЪЕДИНЕНИЕ И КОПИЯ
const defaults = { city: "Мары" };
const given = { city: "Ашхабад" };
Object.assign({}, defaults, given);    // { city: "Ашхабад" } — {} первым, иначе испортит defaults
const copy = Object.assign({}, obj);   // копия ПОВЕРХНОСТНАЯ

// ССЫЛКА
const a = { x: 1 };
const b = a;   // не копия! правка через b видна в a

// МЕТОДЫ
const o = { items: [], count() { return this.items.length; } };   // курс 2

// НОВОЕ
Object.fromEntries([["a", 1]]);                            // { a: 1 }
Object.groupBy([5, 4, 3], (m) => m >= 4 ? "ок" : "нет");   // { ок: [5, 4], нет: [3] } — совсем новый
```

<Selfcheck>
1. Когда для доступа к свойству нужны квадратные скобки?
   <Answer>Когда ключ лежит в переменной, когда он не похож на имя переменной
   (пробел, дефис) и когда он числовой. Во всех остальных случаях точка
   короче и читается лучше.</Answer>
2. Чем `"x" in obj` отличается от `Object.hasOwn(obj, "x")`?
   <Answer>`in` находит и унаследованные свойства — например,
   `toString`, которого вы не добавляли. `hasOwn`
   отвечает только про свои. Для своих данных берут `hasOwn`.</Answer>
3. Что не так с `Object.assign(defaults, given)`?
   <Answer>Первый аргумент меняется, то есть `defaults` будет испорчен
   для всех, кто им пользуется. Первым аргументом ставят пустой объект:
   `Object.assign({}, defaults, given)`.</Answer>
4. Почему после `Object.assign({}, student)` правка
   `copy.address.city` меняет и оригинал?
   <Answer>Копия поверхностная: скопировались сами свойства, а вложенный объект
   `address` остался общим — обе переменные ссылаются на него.
   Верхний уровень независим, всё глубже — нет.</Answer>
5. Как проверить, что объект пустой?
   <Answer>`Object.keys(obj).length === 0`. Проверка `if (obj)`
   не работает: любой объект, даже пустой, истинен.</Answer>
</Selfcheck>
