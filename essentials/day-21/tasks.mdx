# День 21. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 делаем в консоли, дальше — в папке `day-21`.</Subtitle>

## Разминка

<Task title="1. Из двух массивов в объекты" level="easy" time="6">
<Goal>почувствовать разницу между связью по порядку и связью внутри.</Goal>

```js
const items = ["хлеб", "чай", "масло"];
const prices = [3.5, 12, 25];
```

Соберите из них массив объектов вида `{ name, price }` — вручную,
не автоматически. Потом отсортируйте **только** массив
`prices` из исходных данных и объясните, что стало с соответствием.

<Hint>
Достаточно написать три объекта руками. Главное — потом сравнить два подхода
на одной и той же операции: сортировке.
</Hint>

<Criteria>
- массив объектов написан и выведен;
- показано, что после сортировки `prices` соответствие
  с `items` сломалось;
- показано, что сортировка массива объектов ничего не ломает;
- записано правило выбора «массив или объект» своими словами.
</Criteria>
</Task>

<Task title="2. Сначала предскажи: доступ и проверки" level="easy" time="7">
<Goal>поймать разницу между точкой, скобками и тремя проверками.</Goal>

```js
const student = { name: "Аман", phone: undefined };
const key = "name";

student.key;
student[key];
student.phone !== undefined;
"phone" in student;
Object.hasOwn(student, "phone");
Object.hasOwn(student, "toString");
"toString" in student;
Boolean({});
```

<Hint>
Первые две строки различаются одним символом и дают совершенно разное.
Две последние пары показывают, чем `in` отличается от
`hasOwn` и почему пустой объект — ловушка.
</Hint>

<Criteria>
- восемь предсказаний записаны до проверки;
- объяснено, почему `student.key` даёт `undefined`;
- объяснено, почему первая проверка про `phone` врёт;
- объяснено, откуда у объекта `toString`;
- записано, как правильно проверить, что объект пустой.
</Criteria>
</Task>

<Task title="3. keys, values, entries" level="easy" time="7">
<Goal>превратить объект в массив и обратно.</Goal>

```js
const prices = { хлеб: 3.5, чай: 12, масло: 25 };
```

Получите: список названий, список цен, список пар, количество товаров и общую
стоимость. Потом соберите из пар объект обратно и убедитесь, что он совпал
с исходным.

<Hint>
Общую стоимость считайте из `Object.values` вчерашним
`reduce`. Количество — это длина массива ключей: у объекта своего
`length` нет.
</Hint>

<Criteria>
- все пять значений получены;
- объект собран обратно через `Object.fromEntries`;
- записано, почему `prices.length` не работает;
- добавлен числовой ключ — и записано, где он оказался при переборе.
</Criteria>
</Task>

## Основные задания

<Task title="4. Настройки по умолчанию" level="medium" time="12">
<Goal>освоить объединение объектов и не испортить исходные данные.</Goal>

```js
const defaults = { city: "Мары", group: "1-А", year: 2026 };
const given = { name: "Аман", city: "Ашхабад" };
```

Соберите полные настройки так, чтобы заданное пользователем перекрывало
умолчания. Потом проверьте, что `defaults` не изменился — и покажите
вариант, в котором он **портится**.

<Hint>
Порядок аргументов решает, что перекрывает что. А первый аргумент решает,
какой объект пострадает.
</Hint>

<Criteria>
- результат содержит все четыре свойства, город — из `given`;
- `defaults` напечатан до и после — не изменился;
- показан вызов, который портит `defaults`, и объяснено почему;
- написана функция `makeSettings(given)` с умолчанием
  из дня 14;
- проверено, что `makeSettings()` без аргументов работает.
</Criteria>
</Task>

<Task title="5. Копия, которая не копия" level="medium" time="13">
<Goal>увидеть ссылку и поверхностную копию своими глазами.</Goal>

```js
const student = {
  name: "Аман",
  marks: [5, 4],
  address: { city: "Мары", street: "Мир" },
};
```

Проведите три опыта, каждый раз печатая оригинал:

1. `const b = student;` — измените `b.name`;
2. `const copy = Object.assign({}, student);` — измените
   `copy.name`;
3. у той же копии измените `copy.address.city` и добавьте оценку
   в `copy.marks`.

<Hint>
Третий опыт — главный. Верхний уровень копии независим, а вложенные объект
и массив остались общими. Массив здесь ведёт себя так же, как объект.
</Hint>

<Criteria>
- для всех трёх опытов записано состояние оригинала;
- объяснено, почему опыт 1 изменил оригинал, а опыт 2 — нет;
- объяснено, почему опыт 3 изменил оригинал в обоих случаях;
- предложен способ скопировать `address` отдельно —
  и проверено, что теперь оригинал цел;
- записано правило одной строкой: когда `assign` достаточно,
  а когда нет.
</Criteria>
</Task>

<Task title="6. Корзина без индексов" level="medium" time="12">
<Goal>переписать вчерашнюю корзину на объектах.</Goal>

```js
const cart = [
  { name: "хлеб", price: 3.5 },
  { name: "чай", price: 12 },
  { name: "масло", price: 25 },
];
```

Повторите все пять вычислений дня 20 — сумма, дешёвые товары, цены с наценкой,
сортировка, строка для покупателя — и сравните код с вчерашним.

Потом добавьте каждому товару количество и посчитайте стоимость с учётом него.

<Hint>
Ни в одном из пяти пунктов индекс больше не нужен. А добавление количества
не должно потребовать правок в уже написанных строках — если потребовало,
посмотрите, где вы завязались на структуру.
</Hint>

<Criteria>
- все пять результатов совпали со вчерашними;
- ни в одном колбэке не используется индекс;
- добавлена сортировка по названию — объяснено, почему вчера её было
  сделать трудно;
- количество добавлено, общая стоимость пересчитана;
- записано, сколько строк пришлось изменить при добавлении количества.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Свой groupBy" level="hard" time="10">
<Goal>собрать объект накоплением и сверить со встроенным методом.</Goal>

Напишите `myGroupBy(list, getKey)` через `reduce`
и проверьте на двух наборах данных.

<Example>
```js
myGroupBy([5, 4, 3, 5, 2], (m) => m % 2 === 0 ? "чётные" : "нечётные");
// { нечётные: [5, 3, 5], чётные: [4, 2] }

myGroupBy(cart, (item) => item.price < 10 ? "дёшево" : "дорого");
// { дёшево: [...], дорого: [...] }
```
</Example>

<Hint>
Накопитель — пустой объект. На каждом шаге проверьте, есть ли уже такой ключ
(`Object.hasOwn`), при необходимости заведите пустой массив
и не забудьте вернуть накопитель.
</Hint>

<Criteria>
- оба примера дают то, что написано;
- результат сверен с `Object.groupBy`;
- объяснено, зачем нужна проверка «есть ли уже такой ключ»;
- проверено на пустом списке — записано, что вернулось;
- записано, почему в накопителе объект, а не массив.
</Criteria>
</Task>

<Task title="9. Ошибки с объектами" level="hard" time="10">
<Goal>получить все ошибки дня и увидеть, где Chrome молчит.</Goal>

Каждый фрагмент — в отдельный файл: синтаксическая ошибка ломает файл целиком,
а упавшая строка останавливает всё, что ниже. Запишите точный текст ошибки
из своей консоли.

```js
// 1
const o = { x = 5 };

// 2
const o = { a: 1, b: 2 c: 3 };

// 3
const a = [1, 2;

// 4
console.log("x" in "строка");

// 5
const o = undefined;
console.log(o.x);

// 6 — сначала без "use strict", потом с ним
const n = 1;
n.x = 5;
console.log(n.x);
```

<Hint>
Фрагмент 6 — единственный, который ведёт себя по-разному: без строгого режима
он молчит, а ответ при этом неправильный. Сравните тексты ошибок 1–3
с заголовками страниц MDN из справочника дня.
</Hint>

<Criteria>
- для фрагментов 1–5 записан точный текст ошибки;
- отмечено, что тексты Chrome и заголовки MDN не совпадают,
  и названа причина;
- для фрагмента 6 записаны оба поведения;
- все шесть переписаны правильно;
- записано, какая из ошибок опаснее остальных, и почему.
</Criteria>
</Task>
