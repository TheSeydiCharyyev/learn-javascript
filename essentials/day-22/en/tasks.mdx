# Day 22. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder `day-22`.</Subtitle>

## Warm-up

<Task title="1. Take it apart" level="easy" time="6">
<Goal>write your first patterns for an array and an object.</Goal>

```js
const marks = [5, 4, 3, 2];
const student = { name: "Aman", age: 17, address: { city: "Mary" } };
```

With one line for each item, get: the first and the second mark; the third one,
skipping two; the first one and the rest; the name and the age; the city; the name under the name
`who`; the group with the default `"1-A"`.

<Hint>
Seven lines, each with exactly one `const`. For the city you will need
a nested pattern, for the group — an equals sign inside the curly braces.
</Hint>

<Criteria>
- all seven items are done with destructuring, without access by index
  or through a dot;
- the values are printed and matched the expected ones;
- it is written down why no variable `address` appeared
  when the city was taken apart;
- it is explained where the group came from, although the object does not have it.
</Criteria>
</Task>

<Task title="2. Predict first: what will you get" level="easy" time="7">
<Goal>catch the edges of destructuring.</Goal>

```js
const [a = 1] = [];
const [b = 1] = [undefined];
const [c = 1] = [null];
const { p = 10 } = { p: null };
const { q = 10 } = {};
const { r } = { r: undefined };
```

<Hint>
The rule is the same as for the default parameters from day 14: a default fires
on exactly one value. Two lines out of six check exactly that.
</Hint>

<Criteria>
- six predictions are written down before checking;
- the lines where the default did not fire are found, and the reason is named;
- it is explained how the last two lines differ;
- the rule is put into one sentence.
</Criteria>
</Task>

<Task title="3. Three dots in two roles" level="easy" time="7">
<Goal>learn to tell collecting from spreading.</Goal>

For each line write down what the three dots do — collect or spread —
and what you will get.

```js
function f(...args) { return args.length; }
f(...[1, 2, 3]);

const [head, ...tail] = [5, 4, 3];
const copy = [...tail];

const { name, ...others } = { name: "Aman", age: 17, city: "Mary" };
const merged = { ...others, group: "1-A" };

Math.max(...[3, 7, 5]);
[..."Mary"];
```

<Hint>
Look at the place: in a function declaration and to the left of the equals sign they collect;
in a call and inside square or curly brackets they spread.
</Hint>

<Criteria>
- the role and the result are given for all eight lines;
- the line where three dots appear in both roles one after another is found;
- it is explained why `Math.max([3, 7, 5])` without dots does not work;
- the rule for telling them apart is written down in your own words.
</Criteria>
</Task>

<Task title="6. Safe reading" level="medium" time="12">
<Goal>use `?.` where it is needed, and not where it is not.</Goal>

```js
const students = [
  { name: "Aman", address: { city: "Mary" } },
  { name: "Meret" },
  { name: "Gülnar", address: { city: "Ashgabat" }, greet() { return "salam"; } },
];
```

For each student print a line like `“Aman — Mary”`, putting in
“not given” if there is no city. Then call `greet` on all three —
so that the program does not crash.

<Hint>
For the city you will need both `?.` and `??` — they work
as a pair. For the method there is a separate form with parentheses.
</Hint>

<Criteria>
- all three lines are printed correctly;
- the `greet` call does not crash on any student;
- it is written down what the call returned for those who do not have the method;
- a place where `?.` is not needed is found, and it is explained why;
- it is shown what happens if you make a typo in a property name
  with `?.` — and the conclusion is written down.
</Criteria>
</Task>

## Starred tasks

<Task title="8. Rewrite someone else’s code" level="hard" time="10">
<Goal>use all three forms of the day at once.</Goal>

```js
const order = {
  id: 7,
  customer: { name: "Aman", phone: null },
  items: [{ name: "tea", price: 12 }, { name: "bread", price: 3.5 }],
};

function describe(order) {
  const id = order.id;
  const name = order.customer.name;
  const phone = order.customer && order.customer.phone
    ? order.customer.phone
    : "no phone";
  const total = order.items.reduce(function (sum, item) {
    return sum + item.price;
  }, 0);
  return "Order " + id + ": " + name + ", " + phone + ", total " + total;
}
```

Shorten the function using destructuring in the parameter, `??`,
arrows and a template string. The result must match to the character.

<Hint>
You can take the nested part apart right away: `{ customer: { name, phone } }`.
The phone check will be replaced by `??`, and inside `reduce`
a pattern for the element will come in handy.
</Hint>

<Criteria>
- the new version gives exactly the same string — checked by comparison;
- all three forms of the day are used;
- it is tested on an order without `customer` — what came out is written down;
- protection is added so that such an order does not crash the function;
- it is written down whether it became clearer, and which places you left as they were.
</Criteria>
</Task>
