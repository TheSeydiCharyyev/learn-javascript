1. Три записи, которые сокращают вчерашнее

Сегодня не будет новых возможностей — будут три короткие записи того, что мы уже умеем. В справочнике дня всего три страницы — меньше было только на днях 3 и 13. Зато эти записи встречаются в каждом современном файле, и без них чужой код не прочитать.

ЗаписьЧто делаетЧто заменяет
const { name } = student; деструктуризация const name = student.name;
{ ...defaults, ...given } spread Object.assign({}, defaults, given)
student.address?.city необязательная цепочка student.address && student.address.city

Все три родились из вчерашней темы: объект нужно разобрать на части, скопировать и безопасно прочитать. Разберём по очереди, а в конце соберём из них вчерашнюю корзину и сквозной «Табель» — и увидим, насколько короче станут обе программы.

Стоит сказать честно: ни одна из трёх записей не обязательна. Всё, что мы сегодня напишем, можно написать и вчерашними средствами — длиннее, но работать будет так же. Зачем тогда учить?

Причина в чтении. Эти записи встречаются чаще, чем вы будете их писать. Открыв любой современный проект, вы увидите их в первых же строках каждого файла, и без них код выглядит набором загадок. Так же было со стрелочными функциями на дне 13: сначала мы научились их узнавать, а уже потом полюбили писать.

И ещё одно: у всех трёх записей есть края, на которых они ведут себя неожиданно. Именно краям в этом уроке отведено больше всего места — сами записи осваиваются за десять минут.

2. Деструктуризация массива

Обычный способ достать элементы — по индексам:

const marks = [5, 4, 3];

const first = marks[0];
const second = marks[1];

Деструктуризация делает то же самое одной строкой. Слева от = ставят образец, похожий на массив, и язык раскладывает значения по местам:

const [first, second] = marks;

first;    // 5
second;   // 4

Обратите внимание: имена переменных любые. Массив не знает, что нулевой элемент — «первая оценка»; это решаете вы, когда пишете образец.

Отсюда и главное ограничение такой записи: она полезна там, где позиция что-то значит. Для списка оценок «первая» и «вторая» смысла почти не имеют, а вот для пары «ключ — значение» из Object.entries — имеют вполне, и там деструктуризация массива работает постоянно.

Если же позиции произвольны, разбирать массив по именам — верный способ запутаться: завтра данные придут в другом порядке, и все переменные поменяются местами молча.

3. Пропуски, умолчания, остаток

Если нужен не первый элемент, лишние позиции пропускают запятыми:

const [, , third] = marks;
third;   // 3

const [a, b, c, d = 0] = [5, 4, 3];
d;       // 0 — четвёртого элемента нет, взяли умолчание

Две запятые подряд означают «этот элемент мне не нужен» — выглядит странно, зато коротко. А умолчания работают по тому же правилу, что у параметров функции из дня 14: срабатывают только на undefined.

И тот же остаточный синтаксис: три точки собирают всё, что осталось, в новый массив:

const [head, ...tail] = marks;

head;   // 5
tail;   // [4, 3]

Правила у него те же, что у остаточного параметра: он последний и один. Это буквально та же конструкция, просто в другом месте.

4. Обмен значениями

Маленький приём, ради которого деструктуризацию часто и показывают первой. Поменять две переменные местами обычно нужно через третью:

let x = 1;
let y = 2;

let temp = x;
x = y;
y = temp;

С деструктуризацией — одна строка и без лишней переменной:

x = 1;
y = 2;
[x, y] = [y, x];

x;   // 2
y;   // 1

Приём мелкий, но показательный: он объясняет, как вообще устроено присваивание. Работает это потому, что правая часть вычисляется целиком до того, как начнётся присваивание. Сначала собирается массив [2, 1] из старых значений, и только потом он раскладывается обратно.

Перед такой строкой обязательно нужна точка с запятой на предыдущей. Иначе язык решит, что квадратная скобка продолжает предыдущее выражение, и получится ошибка. Это один из немногих случаев, когда её отсутствие реально мешает.

5. Деструктуризация объекта

С объектами то же самое, но соответствие идёт не по позиции, а по имени:

const student = { name: "Аман", age: 17, city: "Мары" };

const { name, age } = student;

name;   // "Аман"
age;    // 17

Порядок в образце не важен — важны имена. Поэтому const { age, name } = student даст ровно то же самое.

Свойства, которого нет, дают undefined — как и обычное чтение через точку. И здесь же работают умолчания:

const { group = "1-А", phone } = student;
group;   // "1-А" — свойства нет, взяли умолчание
phone;   // undefined

const { p = 10 } = { p: null };
p;       // null, а не 10 — умолчание на null не реагирует

6. Переименование и вложенность

Имя переменной можно сделать другим — через двоеточие:

const { name: studentName } = student;

studentName;   // "Аман"
// переменной name эта строка не создаёт — только studentName

Читается справа налево: «возьми свойство name и назови его studentName». Нужно это в двух случаях: когда имя занято другой переменной и когда имя свойства слишком общее — value, data, items.

Вложенные объекты разбираются так же, вложенным образцом:

const student = { name: "Аман", address: { city: "Мары" } };

const { address: { city } } = student;

city;   // "Мары"
Здесь address — не переменная, а путь. Переменная создалась только одна: city. Если нужны обе, пишут const { address, address: { city } } = student; — да, свойство указывают дважды.

И остаточный синтаксис для объектов: он собирает все свойства, которые вы не назвали:

const { name: n, ...others } = student;

n;        // "Аман"
others;   // { address: { city: "Мары" } }

7. В параметрах функции

Самое полезное применение. Вчерашний makeRow(student) начинался с распаковки:

function makeRow(student) {
  const name = student.name;
  const marks = student.marks;
  // ...
}

Образец можно поставить прямо в параметре — и две строки исчезнут:

function makeRow({ name, marks }) {
  // name и marks уже есть
}

Вместе с умолчаниями получается очень плотная запись:

function greet({ name, city = "не указан" }) {
  return name + " из " + city;
}

greet({ name: "Мерет" });   // "Мерет из не указан"

У такой функции есть и приятный побочный эффект: порядок аргументов перестаёт иметь значение. Это лекарство от беды дня 14, где вызов f(1, undefined, undefined, true) был нечитаем. Сравните:

// функция из дня 15 — какой аргумент что значит?
// makeLine("Пришло", 3, undefined, undefined, "", 5);
// её же версия с объектом (напишете в задании 4) — видно сразу:
// makeLine({ name: "Пришло", value: 3, total: 5 });

Так оформляют функции с четырьмя и более настройками. Так устроены и встроенные: на дне 25 встретится scrollIntoView({ behavior: "smooth" }).

8. В циклах и колбэках

Вчерашний перебор объекта был неуклюжим — пара приходила массивом, и к ней обращались по индексам:

const prices = { хлеб: 3.5, чай: 12, масло: 25 };

Object.entries(prices).forEach((pair) => {
  console.log(pair[0] + " = " + pair[1]);
});

Образец прямо в параметре колбэка решает дело:

Object.entries(prices).forEach(([key, value]) => {
  console.log(key + " = " + value);
});

То же в цикле for...of:

for (const [key, value] of Object.entries(prices)) {
  console.log(key + " = " + value);
}

И в методах над массивом объектов — вместо item.name сразу name:

const cart = [
  { name: "хлеб", price: 3.5 },
  { name: "чай", price: 12 },
  { name: "масло", price: 25 },
];

cart.map(({ name, price }) => name + " — " + price + " м");
// ["хлеб — 3.5 м", "чай — 12 м", "масло — 25 м"]

Это, пожалуй, самая частая деструктуризация в реальном коде: она встречается в каждом втором колбэке.

Когда не стоит разбирать

Короче не значит лучше. Если из объекта нужно одно поле, обычная точка читается проще:

cart.map((item) => item.price);                // одно поле — точка
cart.map(({ name, price }) => name + price);   // два и больше — образец

Второй случай — когда дальше в функции нужен весь объект целиком. Разобрав его на части, вы потеряете возможность передать его дальше, и придётся собирать обратно.

Третий — глубокая вложенность. Образец вида { a: { b: { c } } } читается тяжелее, чем обычная цепочка obj.a.b.c, и при этом не защищает от пустоты — падать будет так же.

Правило простое: деструктуризация должна убирать повторы. Если повторов нет — она только добавляет скобок. Посчитайте, сколько раз в функции пишется item.: два раза и больше — ставьте образец, один — оставьте точку.

9. Три ловушки деструктуризации

Первая: скобки при присваивании в существующие переменные. Если слева нет const, язык видит фигурную скобку и думает, что началось тело блока:

const obj = { score: 1 };
let score;
// { score } = obj;   → SyntaxError: Unexpected token '='

Лечится обёрткой в круглые скобки — язык понимает, что это выражение:

({ score } = obj);   // теперь работает
score;               // 1

Вторая: нельзя разбирать undefined и null. Обычное чтение через точку у них падало — и деструктуризация падает тоже, просто с другим текстом:

const { z } = undefined;
// TypeError: Cannot destructure property 'z' of 'undefined' as it is undefined.

const [w] = undefined;
// TypeError: undefined is not iterable

Защита — умолчание на весь образец:

function makeRow({ name, marks } = {}) {
  // теперь makeRow() без аргументов не упадёт
}

Третья: пустой объект не то же самое, что отсутствие свойств. Разбирая {}, вы получите undefined во всех переменных — и это не ошибка, а тихая пустота. Дальше она превратится в NaN или в слово «undefined» в отчёте, как мы видели на дне 15.

Эта третья ловушка коварнее первых двух именно потому, что не падает. Первые две сообщают о себе сразу: одна — синтаксической ошибкой при запуске, вторая — понятным TypeError. А разбор пустого объекта выглядит как успех, и разбираться приходится уже в отчёте, где вместо имени стоит слово «undefined».

Отсюда привычка, которую стоит завести сразу: ставя умолчание на весь образец, ставьте умолчания и на важные поля внутри. Тогда вместо тихой пустоты в программе окажется хоть что-то осмысленное — как «без имени» в нашем «Табеле».

10. Spread: копия и объединение

Те же три точки, но в другом месте, делают обратное: раскладывают готовый массив или объект на отдельные элементы.

const marks = [5, 4, 3];

[...marks];            // [5, 4, 3]   копия
[0, ...marks];         // [0, 5, 4, 3]
[...marks, ...[2, 1]]; // [5, 4, 3, 2, 1]  объединение

Копия настоящая — новый массив, а не вторая ссылка на старый:

[...marks] === marks;   // false — это разные массивы

С объектами то же самое, и это прямая замена вчерашнему Object.assign:

const defaults = { city: "Мары", group: "1-А" };
const given = { name: "Аман", city: "Ашхабад" };

const merged = { ...defaults, ...given };
// { city: "Ашхабад", group: "1-А", name: "Аман" }

Object.assign({}, defaults, given);   // то же самое, вчерашняя запись
Строку нельзя начинать литералом объекта: в файле { ...defaults }; даёт SyntaxError: Unexpected token '...' — язык прочёл фигурную скобку как начало блока. Поэтому результат всегда куда-то кладут или оборачивают в круглые скобки. С массивами такой беды нет.

Правило перекрытия прежнее: кто правее, тот и побеждает. Поэтому умолчания ставят первыми, а данные пользователя — последними.

И удобная мелочь — добавить одно свойство, не трогая остальные:

const withYear = { ...given, year: 2026 };   // копия плюс новое свойство
Копия по-прежнему поверхностная. Три точки копируют свойства верхнего уровня, а вложенные объекты остаются общими — ровно как у Object.assign вчера. Короче запись, а не глубже.

Чего нам всё ещё не хватает

Задача «скопировать объект целиком, вместе с вложенным» пока решается только вручную, уровень за уровнем:

const order = { id: 1, customer: { name: "Аман" } };

const shallow = { ...order };
shallow.customer.name = "Мерет";
order.customer.name;   // "Мерет" — оригинал пострадал

const deep = { ...order, customer: { ...order.customer } };
deep.customer.name = "Сапар";
order.customer.name;   // "Мерет" — а теперь цел

Работает, но только до первого лишнего уровня: если внутри customer окажется ещё один объект, придётся дописывать третью строку. Настоящее решение этой задачи появится завтра, вместе с JSON, — и там же выяснится, какой ценой.

11. Spread в вызове функции

Третье место для трёх точек — аргументы вызова. Тут они раскладывают массив на отдельные аргументы:

const marks = [5, 4, 3];

Math.max(marks);      // NaN — массив это ОДИН аргумент
Math.max(...marks);   // 5   — а теперь три аргумента

Это тот самый долг, оставшийся с дня 18: тогда максимум массива приходилось искать циклом, потому что Math.max не принимает список. Теперь принимает.

Работает и с нашими функциями с остаточным параметром из дня 14:

function sumAll(...numbers) {
  return numbers.reduce((total, n) => total + n, 0);
}

sumAll(...marks);   // 12

И с любой строкой — строка тоже перебирается, как мы видели на дне 15:

[..."Аман"];   // ["А", "м", "а", "н"]

12. Три точки в двух ролях

Одни и те же три точки делают противоположное — и путаница здесь обычное дело. Различить их просто: смотрите, где они стоят.

Проверить себя можно вопросом: эта строка описывает, что функция принимает, или что-то делает прямо сейчас? В первом случае три точки собирают, во втором — раскладывают.

Путаница обычно возникает в одном конкретном месте — когда обе роли стоят рядом:

function sumAll(...numbers) {      // собирает: аргументы → массив
  return numbers.reduce((total, n) => total + n, 0);
}

sumAll(...marks);                  // раскладывает: массив → аргументы

Две строки выглядят почти одинаково, а делают противоположное. Читать их надо так: в первой мы описываем функцию, во второй — зовём её. Описание принимает, вызов отдаёт.

И полезная мелочь: три точки в объявлении можно поставить только в конце, а в вызове и литерале — где угодно и сколько угодно раз. [...a, 0, ...b] — совершенно нормальная запись, а function f(...a, b) — ошибка из дня 14.

13. Необязательная цепочка

Вчера мы наткнулись на ошибку, которая портит жизнь при работе с чужими данными:

const student = { name: "Мерет" };   // адреса нет

student.address.city;
// TypeError: Cannot read properties of undefined (reading 'city')

Программа падает не на address — он честно даёт undefined, — а на попытке прочитать city у этого undefined.

Старое лекарство — проверка через && из дня 7:

const city = student.address && student.address.city;

Работает, но при трёх уровнях вложенности превращается в кашу. Вопросительный знак перед точкой делает то же самое коротко:

student.address?.city;   // undefined, без ошибки

Читается так: «если слева не null и не undefined — иди дальше; иначе весь результат undefined».

Знак появился в языке позже всего остального в этом курсе — в 2020 году, — и появился он не от хорошей жизни. Чем больше данных приходит извне, тем чаще оказывается, что нужного поля просто нет: пользователь не заполнил, сервер не прислал, старая запись создавалась по другим правилам. До ?. каждое такое место обрастало проверками, и код превращался в лес из &&.

Работает в трёх местах — перед точкой, перед скобками и перед вызовом:

const key = "name";

student?.name;        // "Мерет" — свойство
student?.[key];       // "Мерет" — свойство по переменной
student.greet?.();    // undefined — метода нет, вызова не было

Последняя форма особенно полезна для необязательных колбэков: если функцию не передали, вызова просто не будет.

И почти всегда рядом стоит ?? из дня 7 — он подставляет запасное значение:

const city = student.address?.city ?? "не указан";

city;   // "не указан"

14. Где ?. не поможет

Важно понимать границы. Вопросительный знак защищает только то, что стоит сразу после него. Дальше по цепочке защиты нет — если только не поставить его ещё раз:

const student = { name: "Мерет" };

student.address?.city;          // undefined — защитили
student.address?.city.length;   // undefined — тоже, цепочка оборвалась целиком

Вторая строка не падает по особой причине: как только ?. сработал, вся оставшаяся цепочка пропускается. Это называется коротким замыканием, и именно поэтому одного знака часто хватает.

А вот от чего ?. не спасает совсем:

СитуацияПоможет ли ?.
свойства нетда, вернёт undefined
объект null или undefinedда
опечатка в имени свойстванет — молча undefined

Разбор: почему у всех «не указан»

Вот случай, ради которого стоит быть осторожным. Программа работает, ошибок нет, а город не показывается ни у кого:

const students = [
  { name: "Аман", address: { city: "Мары" } },
  { name: "Мерет" },
];

students.map((s) => s.name + " — " + (s.adress?.city ?? "не указан"));
// ["Аман — не указан", "Мерет — не указан"]

Шаг 1. Замечаем странность. У Мерета города и правда нет, но у Амана он есть. Значит, дело не в данных, а в чтении.

Шаг 2. Печатаем сами данные. Не результат, а то, из чего он считается:

Object.keys(students[0]);   // ["name", "address"]

Шаг 3. Сравниваем с кодом. В объекте address, а в коде adress — одна буква «д» вместо двух. Опечатка.

Шаг 4. Понимаем, почему промолчало. s.adress — это undefined, ?. честно оборвал цепочку, а ?? подставил запасное значение. Все три конструкции отработали правильно — и вместе спрятали ошибку.

Object.hasOwn(students[0], "adress");    // false — вот и ответ
Object.hasOwn(students[0], "address");   // true

Без ?. программа упала бы сразу на первом студенте, и опечатка нашлась бы за секунду. Это и есть цена удобства.

Главная опасность — ставить ?. везде на всякий случай. Тогда опечатка в имени свойства и настоящая дыра в данных выглядят одинаково: везде тихий undefined, и падать программа перестаёт вовсе. Знак ставят там, где отсутствие поля — нормальная ситуация, а не там, где страшно.

15. «Табель» и корзина покороче

Начнём с корзины — вчерашний код заметно сокращается:

Теперь сквозная программа. Меняются две вещи: параметр makeRow становится образцом, а Math.min и Math.max наконец получают массив напрямую.

const MIN_MARK = 2;
const MAX_MARK = 5;
const NAME_WIDTH = 12;

const toMark = (raw) => Number(String(raw).trim());
const isValidMark = (m) => Number.isInteger(m) && m >= MIN_MARK && m <= MAX_MARK;

const sum = (numbers) => numbers.reduce((total, n) => total + n, 0);
const average = (numbers) =>
  numbers.length === 0 ? 0 : sum(numbers) / numbers.length;

function verdict(avg, excellent = 4.5, good = 3.5, pass = 2.5) {
  if (avg >= excellent) return "отличник";
  if (avg >= good) return "хорошист";
  if (avg >= pass) return "троечник";
  return "надо подтянуть";
}

const students = [
  { name: "Аман", marks: [5, "4", " 9 ", 3, 5, 0, "4", 5] },
  { name: "Мерет", marks: ["3", 3, 4] },
  { name: "Гүлнар", marks: [9, 0, "пять"] },
  { name: "Сапар", marks: [5, 5, "4", 5] },
  { name: "Огулджан", marks: ["4.5", 4, 5] },
];

function makeHeader() {
  return "Имя".padEnd(NAME_WIDTH) + "Средн".padStart(6) + "Мин".padStart(5)
    + "Макс".padStart(5) + "%".padStart(7) + "  Вердикт";
}

// новое: образец прямо в параметре, с умолчанием на весь объект
function makeRow({ name = "без имени", marks = [] } = {}) {
  const all = marks.map((r) => toMark(r));
  const valid = all.filter(isValidMark);

  if (valid.length === 0) {
    return name.padEnd(NAME_WIDTH) + "нет годных оценок";
  }

  const avg = average(valid);
  const percent = Math.round(valid.length / all.length * 100);

  // новое: maxOf и minOf больше не нужны
  return name.padEnd(NAME_WIDTH)
    + avg.toFixed(2).padStart(6)
    + String(Math.min(...valid)).padStart(5)
    + String(Math.max(...valid)).padStart(5)
    + (percent + "%").padStart(7)
    + "  " + verdict(avg);
}

console.log(line);

Числа снова те же. А вот кода стало заметно меньше.

Две функции исчезли целиком. maxOf и minOf писались циклом на дне 18 и через reduce на дне 20 — теперь они не нужны: Math.max(...valid) делает то же самое. Это и есть обещанный долг дня 18.

= {} в конце образца — защита из раздела 9. Без него вызов makeRow() без аргументов упал бы, причём с другим текстом, чем в разделе 9: когда в образце есть умолчания, Chrome пишет TypeError: Cannot read properties of undefined (reading 'name'). С ним он возвращает строку, где после «без имени» стоит «нет годных оценок».

Имя all вместо marks появилось не случайно: marks теперь занято переменной из образца. Мелочь, но именно такие мелочи ломают код при переписывании.

Стоит оглянуться на то, что произошло со сквозной программой за последнюю неделю. На дне 18 в ней было четыре цикла for. На дне 20 они превратились в reduce и map. Сегодня две функции исчезли совсем. Программа делает ровно то же, что и раньше, — и это проверяется одним взглядом на вывод.

При этом ни одно изменение не было «оптимизацией». Каждый раз мы просто брали инструмент, который появился в тот день, и смотрели, что он убирает. Так и растёт настоящий код: не переписыванием с нуля, а маленькими заменами, после каждой из которых программа работает.

И ещё одно наблюдение: данные в программе не менялись с дня 17. Те же пять студентов, те же оценки вперемешку числами и строками. Менялся только код вокруг них — и это правильный порядок вещей.

Три опыта.

Первый. Уберите = {} из параметра и вызовите makeRow(). Запишите текст ошибки и объясните, чем он отличается от обычного «свойства нет».

Второй. Добавьте студентам вложенное свойство address: { city }, но не всем. Выведите город через ?. и через ??, чтобы у остальных стояло «не указан».

Третий. Соберите копию списка через students.map((s) => ({ ...s })) и измените имя в копии. Потом измените оценку. Посмотрите на оригинал и объясните, почему результаты разные.

Что будет завтра

День 23 — JSON. Объект превращается в строку, строка — обратно в объект, и именно в таком виде данные путешествуют между программами и приходят с сервера. Тема небольшая, всего пять страниц справочника, но без неё не будет ни дня 31, ни второго мини-проекта.

А заодно закроется вопрос глубокой копии: у JSON есть приём, который решает задачу «скопировать объект вместе с вложенным» — с оговорками, о которых мы поговорим.

  1. Чем отличается деструктуризация массива от деструктуризации объекта?
    Ответ У массива соответствие по позиции, и имена переменных выбираете вы. У объекта — по имени свойства, и порядок в образце не важен.
  2. Зачем в function makeRow({ name } = {}) стоит = {}?
    Ответ Чтобы вызов без аргументов не упал. Разобрать undefined нельзя — будет TypeError: Cannot destructure property..., а с умолчанием разбирается пустой объект.
  3. Как по виду строки понять, три точки собирают или раскладывают?
    Ответ По месту. В объявлении функции и слева от = они собирают много значений в один массив. В вызове функции и внутри литералов [...] и {...} — раскладывают один список на отдельные значения.
  4. Что вернёт student.address?.city.length, если адреса нет?
    Ответ undefined, и ошибки не будет: как только ?. сработал, вся оставшаяся цепочка пропускается. Это короткое замыкание.
  5. Почему ?. не стоит ставить везде подряд?
    Ответ Он превращает опечатку в имени свойства в тихий undefined: программа перестаёт падать, но начинает врать. Ставят там, где отсутствие поля — нормальная ситуация.
