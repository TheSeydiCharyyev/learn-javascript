# День 22. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 делаем в консоли, дальше — в папке `day-22`.</Subtitle>

## Разминка

<Task title="1. Разобрать по частям" level="easy" time="6">
<Goal>написать первые образцы для массива и объекта.</Goal>

```js
const marks = [5, 4, 3, 2];
const student = { name: "Аман", age: 17, address: { city: "Мары" } };
```

Одной строкой на каждый пункт достаньте: первую и вторую оценку; третью,
пропустив две; первую и остаток; имя и возраст; город; имя под названием
`who`; группу с умолчанием `"1-А"`.

<Hint>
Семь строк, в каждой ровно один `const`. Для города понадобится
вложенный образец, для группы — знак равенства внутри фигурных скобок.
</Hint>

<Criteria>
- все семь пунктов сделаны деструктуризацией, без обращений по индексу
  и через точку;
- значения выведены и совпали с ожидаемыми;
- записано, почему при разборе города не появилась переменная
  `address`;
- объяснено, откуда взялась группа, которой в объекте нет.
</Criteria>
</Task>

<Task title="2. Сначала предскажи: что получится" level="easy" time="7">
<Goal>поймать края деструктуризации.</Goal>

```js
const [a = 1] = [];
const [b = 1] = [undefined];
const [c = 1] = [null];
const { p = 10 } = { p: null };
const { q = 10 } = {};
const { r } = { r: undefined };
```

<Hint>
Правило то же, что у параметров по умолчанию из дня 14: умолчание срабатывает
ровно на одном значении. Две строки из шести проверяют именно это.
</Hint>

<Criteria>
- шесть предсказаний записаны до проверки;
- найдены строки, где умолчание не сработало, и названа причина;
- объяснено, чем отличаются последние две строки;
- сформулировано правило одним предложением.
</Criteria>
</Task>

<Task title="3. Три точки в двух ролях" level="easy" time="7">
<Goal>научиться отличать сбор от раскладывания.</Goal>

Для каждой строки запишите, что делают три точки — собирают или раскладывают —
и что получится.

```js
function f(...args) { return args.length; }
f(...[1, 2, 3]);

const [head, ...tail] = [5, 4, 3];
const copy = [...tail];

const { name, ...others } = { name: "Аман", age: 17, city: "Мары" };
const merged = { ...others, group: "1-А" };

Math.max(...[3, 7, 5]);
[..."Мары"];
```

<Hint>
Смотрите на место: в объявлении функции и слева от знака равенства — собирают;
в вызове и внутри квадратных или фигурных скобок — раскладывают.
</Hint>

<Criteria>
- для всех восьми строк указана роль и результат;
- найдена строка, где три точки встречаются в обеих ролях подряд;
- объяснено, почему `Math.max([3, 7, 5])` без точек не работает;
- записано правило различения своими словами.
</Criteria>
</Task>

## Основные задания

<Task title="4. Функция с настройками" level="medium" time="12">
<Goal>заменить длинный список параметров одним объектом.</Goal>

Вот функция из дня 15, которой было неудобно пользоваться:

```js
function makeLine(name, value, unit = "", prefix = "", suffix = "", total = 0) {
  // ...
}

makeLine("Пришло", 3, undefined, undefined, "", 5);
```

Перепишите её так, чтобы она принимала один объект с теми же настройками
и умолчаниями. Покажите три вызова: полный, минимальный и с пропуском середины.

<Hint>
Образец ставят прямо в скобках параметра, умолчания пишут внутри него.
Не забудьте `= {}` в конце, если функцию можно звать вообще
без аргументов.
</Hint>

<Criteria>
- функция принимает один объект, все умолчания сохранены;
- три вызова написаны и дают правильные результаты;
- вызов без аргументов не падает — показано почему;
- объяснено, чем новый вызов читается лучше старого;
- записано, при каком числе параметров вы будете переходить на объект.
</Criteria>
</Task>

<Task title="5. Копии и объединения" level="medium" time="13">
<Goal>проверить, что копирует spread, а что нет.</Goal>

```js
const defaults = { city: "Мары", group: "1-А", theme: { color: "белый" } };
const given = { name: "Аман", city: "Ашхабад" };
```

Соберите итоговые настройки тремя точками. Потом проведите четыре проверки,
каждый раз печатая `defaults`:

1. измените `city` в результате;
2. измените `theme.color` в результате;
3. поменяйте порядок объектов в объединении;
4. добавьте свойство `year` к копии `given`.

<Hint>
Второй пункт — главный. Верхний уровень скопировался, а вложенный объект
`theme` остался общим: это та же поверхностная копия, что вчера
у `Object.assign`.
</Hint>

<Criteria>
- итоговые настройки собраны, город взят из `given`;
- для всех четырёх проверок записано состояние `defaults`;
- объяснено, почему пункт 1 не испортил оригинал, а пункт 2 испортил;
- показано, как скопировать `theme` отдельно;
- сравнён результат с `Object.assign` — записано, что одинаково.
</Criteria>
</Task>

<Task title="6. Безопасное чтение" level="medium" time="12">
<Goal>применить `?.` там, где нужно, и не применять, где нет.</Goal>

```js
const students = [
  { name: "Аман", address: { city: "Мары" } },
  { name: "Мерет" },
  { name: "Гүлнар", address: { city: "Ашхабад" }, greet() { return "salam"; } },
];
```

Для каждого студента выведите строку вида `«Аман — Мары»`, подставляя
«не указан», если города нет. Потом вызовите `greet` у всех троих —
так, чтобы программа не упала.

<Hint>
Для города понадобятся и `?.`, и `??` — они работают
в паре. Для метода есть отдельная форма со скобками.
</Hint>

<Criteria>
- все три строки выведены правильно;
- вызов `greet` не падает ни на одном студенте;
- записано, что вернул вызов у тех, у кого метода нет;
- найдено место, где `?.` не нужен, и объяснено почему;
- показано, что будет, если сделать опечатку в имени свойства
  с `?.` — и записан вывод.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Переписать чужой код" level="hard" time="10">
<Goal>применить все три записи дня разом.</Goal>

```js
const order = {
  id: 7,
  customer: { name: "Аман", phone: null },
  items: [{ name: "чай", price: 12 }, { name: "хлеб", price: 3.5 }],
};

function describe(order) {
  const id = order.id;
  const name = order.customer.name;
  const phone = order.customer && order.customer.phone
    ? order.customer.phone
    : "нет телефона";
  const total = order.items.reduce(function (sum, item) {
    return sum + item.price;
  }, 0);
  return "Заказ " + id + ": " + name + ", " + phone + ", итого " + total;
}
```

Сократите функцию, пользуясь деструктуризацией в параметре, `??`,
стрелками и шаблонной строкой. Результат обязан совпасть до символа.

<Hint>
Разбирать можно сразу вложенное: `{ customer: { name, phone } }`.
Проверку телефона заменит `??`, а внутри `reduce`
пригодится образец для элемента.
</Hint>

<Criteria>
- новая версия даёт ровно ту же строку — сверено сравнением;
- использованы все три записи дня;
- проверено на заказе без `customer` — записано, что вышло;
- добавлена защита, чтобы такой заказ не ронял функцию;
- записано, стало ли понятнее, и какие места вы оставили как были.
</Criteria>
</Task>

<Task title="9. Шесть подвохов" level="hard" time="10">
<Goal>собрать всё, что сегодня ведёт себя неожиданно.</Goal>

```js
// 1
let a;
{ a } = { a: 1 };

// 2
const { x } = undefined;

// 3
const obj = { inner: { n: 1 } };
const copy = { ...obj };
copy.inner.n = 99;
console.log(obj.inner.n);

// 4
const student = { name: "Мерет" };
console.log(student.adress?.city);

// 5
console.log(Math.max([3, 7, 5]));

// 6
const nums = [1, 2];
const [p, q] = [q, p];
```

<Hint>
Каждый фрагмент — в отдельный файл: первый ломает файл целиком ещё до запуска.
Фрагмент 4 содержит опечатку в слове «address» — и `?.` её прячет.
Фрагмент 6 выглядит как обмен из лекции, но обменивать там нечего.
</Hint>

<Criteria>
- предсказания записаны до запуска;
- для падающих записан точный текст ошибки;
- объяснено, почему фрагмент 4 не падает, хотя в нём ошибка;
- объяснено, что не так с фрагментом 6;
- все шесть переписаны правильно.
</Criteria>
</Task>
