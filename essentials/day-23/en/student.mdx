# Day 23. JSON

<Subtitle>A summary of the lecture: an object to a string, a string to an object, and what is lost on the way.</Subtitle>

## The main points

<Definition>
An object lives only in the memory of a running program. To save it or pass it on,
you need text — and that is what JSON is for.
</Definition>

```js
const student = { name: "Aman", marks: [5, 4] };
const text = JSON.stringify(student);   // object → string
const back = JSON.parse(text);          // string → a NEW object
```

<KeyPoint>
JSON is not JavaScript but a separate text format. All languages understand it,
and its rules are stricter.
</KeyPoint>

| In JavaScript | In JSON |
| --- | --- |
| `{ name: "Aman" }` | a key goes only in double quotes |
| `'Aman'` | single quotes are forbidden |
| `[1, 2, ]` | a trailing comma is forbidden |
| `// comment` | there are no comments |
| `undefined`, functions | do not exist |

## What is lost

```js
JSON.stringify({ fn() {}, undef: undefined, nan: NaN, ok: 1 });
// '{"nan":null,"ok":1}'  — the function and undefined disappeared, NaN became null

JSON.stringify([1, undefined, 3]);   // "[1,null,3]" — null in an array
JSON.stringify(undefined);           // undefined, not a string
```

<Remember>
**A date survives only half of the round trip.** `stringify`
writes it as a string, and `parse` leaves it a string:
`back.when.getFullYear()` crashes with
`TypeError: … is not a function`.
</Remember>

## Useful arguments

```js
const obj = { name: "Aman", age: 17, secret: "code" };
JSON.stringify(obj, null, 2);         // with indentation — for reading
JSON.stringify(obj, ["name", "age"]); // '{"name":"Aman","age":17}' — only the needed fields

const saved = '{"when":"2026-09-25"}';
JSON.parse(saved, (key, value) =>
  key === "when" ? new Date(value) : value);   // a reviver: when is a date again
```

## Errors

```js
JSON.parse("{a:1}");
// SyntaxError: Expected property name or '}' in JSON at position 1 (line 1 column 2)

JSON.parse("");
// SyntaxError: Unexpected end of JSON input

const a = {}; a.self = a;
JSON.stringify(a);
// TypeError: Converting circular structure to JSON
```

<Remember>
Chrome usually names the **position** of the error — a rare case when it is
clearer than Firefox, whose wordings the MDN page is written with. On “Unexpected token”
it shows the character itself instead of the position.
\
Other people’s data is parsed only inside `try/catch` from day 11.
</Remember>

## Comparing through JSON

```js
const a = { name: "Aman", age: 17 };
const c = { age: 17, name: "Aman" };   // the same data, a different order

JSON.stringify(a) === JSON.stringify(c);   // false!
```

The technique “compare the written forms instead of the objects” works only if you created both
objects the same way yourself: the written form depends on the order of the properties.

## A deep copy

```js
const clone = JSON.parse(JSON.stringify(obj));
```

It works because `parse` builds everything anew — no shared references
are left. The cost: methods, dates, `undefined` and cycles will not survive the round trip.
For simple data it is an excellent technique.

<NoteBox>
**Where you will meet it:** `localStorage` stores only strings
(day 31), a server response comes as text (day 31), settings files like
`package.json` are ordinary JSON.
\
**For debugging:** `console.log(JSON.stringify(obj, null, 2))`
shows a complex object whole.
</NoteBox>
