Day 23. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-23.

Warm-up

1. There and back
Easy6 min

go through the round trip and make sure the object is new.

const student = { name: "Aman", age: 17, marks: [5, 4] };

Write the object as a string, print the string and its length. Parse it back and check three things: whether the values match, whether it is the same object, and what JSON.stringify(JSON.parse(text)) === text returns.

“The same object” is checked with === — for objects it answers not “are they alike” but “is it one and the same box”.
  • the string and its length are written down;
  • the values after the round trip matched, while comparing the objects gave false;
  • it is explained why comparing the strings gave true;
  • it is written down what typeof returns for the string and for the result of parsing.
2. What is lost
Easy7 min

see all the losses of the format with your own eyes.

const tricky = {
  name: "Aman",
  fn() { return 1; },
  undef: undefined,
  nan: NaN,
  inf: Infinity,
  when: new Date(2026, 8, 25),
  nested: { ok: 1 },
};

console.log(JSON.stringify(tricky));
console.log(JSON.stringify([1, undefined, 3]));
console.log(JSON.stringify(undefined));
Compare how many properties there were and how many are left. The behavior in an object and in an array is different — and the reason for this difference is simple.
  • for all seven properties it is written down what happened to them;
  • it is explained why the array got a null instead of a gap;
  • it is written down what the third call returned and of what type it is;
  • after the round trip typeof back.when is checked and getFullYear is called — the error text is written down.
3. Fix the JSON
Easy7 min

learn to see violations of the format.

Each line is broken JSON. Find the error without running it, then check it by parsing and fix it.

const broken = [
  "{name: 'Aman'}",
  '{"marks": [5, 4,]}',
  "{'name': \"Aman\"}",
  '{"name": "Aman" "age": 17}',
  "{\"ok\": True}",
];
The fifth line has an error that is not from the lecture — look closely at the word. In JSON, as in JavaScript, it is written in lowercase letters.
  • the cause is named for all five before running;
  • the error text and the position are written down for each, and where Chrome does not name the position — the character it complains about;
  • all five are fixed and parse;
  • it is written down which three violations occur most often.

Main tasks

4. Parsing with protection
Medium12 min

make parsing safe for other people’s data.

Write parseOrDefault(text, fallback): it parses the string, and in case of any trouble returns the fallback value and writes a clear message to the console.

Test it on five inputs: correct JSON, broken JSON, an empty string, the string "undefined" and null.

It is worth filtering out the empty string and null before parse — otherwise an exception is spent on them where an ordinary check is enough.
  • all five inputs are handled without crashing the program;
  • for each it is written down what came back;
  • the error message includes the text from error.message;
  • it is explained why the empty string is checked separately;
  • a sixth input is added — correct JSON of an array — and it is checked that the function works with it too.
5. A deep copy
Medium13 min

compare three ways of copying on one object.

const order = {
  id: 1,
  customer: { name: "Aman", tags: ["vip"] },
  total: 40.5,
};

Make three copies — with { ...order }, with Object.assign({}, order) and with the JSON round trip. In each one change customer.name and add a tag to customer.tags, printing the original each time.

The first two ways give the same result — and this is the main observation of the task. The third one differs, and the reason is that parse builds the objects anew.
  • the state of the original is written down for all three ways;
  • it is named which two ways behave the same and why;
  • clone.customer === order.customer is checked for all three;
  • a method and a date are added to the object — it is written down what happened to them in the copy through JSON;
  • a conclusion is drawn: when the JSON round trip fits and when it does not.
6. Reading someone else’s JSON
Medium12 min

figure out unfamiliar data with code, not by eye.

const text = '{"items":[{"id":1,"tags":["a","b"]},{"id":2,"tags":[]}],"total":2}';

Without examining the string, find out with code: whether it is an object or an array; what fields it has; how many elements are inside items; what fields one element has; whether all elements have the same set of fields.

Then print the same data with indentation.

The last question is solved by comparing Object.keys of the elements — for example, with every from day 20.
  • all five questions are answered with code, not by reading;
  • the data is printed with indentation in one line of code;
  • the element with an empty array is found, and it is written down how it differs;
  • a third element with an extra field is added — the check “do all have the same fields” must notice it;
  • it is written down why such an analysis is needed in practice.
7. The “Report card” from a string
Medium13 min

separate computing from display, as it is done in the lecture.

Copy the folder day-22 to day-23 and rebuild it:

  • the students come as one JSON string and are parsed with JSON.parse;
  • makeReport(student) returns an object with numbers, not a string;
  • makeRow(report) turns the object into a table row;
  • the report on the first student is also printed as JSON with indentation.
  • the table matched day 22 to the character;
  • in the JSON string all keys are in double quotes — the program runs;
  • the report object is printed with indentation;
  • it is explained why the numbers cannot be got back out of a table row;
  • the whole list of reports is saved as a string and parsed back — it is checked that it matched.

Starred tasks

8. Your own storage
Hard10 min

build a “save — load” pair that never crashes.

The real browser storage will come on day 31, and for now replace it with an ordinary object that stores only strings.

const store = {};

save("students", [{ name: "Aman", marks: [5, 4] }]);
load("students");           // [{ name: "Aman", marks: [5, 4] }]
load("no such key", []);    // []
load("broken", []);         // [] and a message in the console
save puts a string in, load takes it out and parses it. Three cases to survive: there is no key, the string is empty, the string is broken.
  • all four calls from the example work;
  • broken data does not crash the program but returns the fallback value;
  • it is checked that the saved and the loaded objects are different;
  • saving an object with a date is added — it is written down what came back;
  • it is explained why the storage keeps strings and not objects.
9. Six catches
Hard10 min

gather everything that behaves unexpectedly today.

// 1
console.log(JSON.parse({ a: 1 }));

// 2
console.log(JSON.stringify("Aman").length);

// 3
const a = { name: "a" };
a.self = a;
console.log(JSON.stringify(a));

// 4
const o = { x: undefined, y: 1 };
console.log(Object.keys(JSON.parse(JSON.stringify(o))));

// 5
console.log(JSON.parse("2026-09-25"));

// 6
const d = { when: new Date(2026, 8, 25) };
console.log(JSON.parse(JSON.stringify(d)).when.getFullYear());
Four crash and two do not, so run the fragments one at a time. The second fragment does not crash, but the number will surprise you: count the letters in the word “Aman” and compare.
  • the predictions are written down before running;
  • for the ones that crash, the exact error text is written down;
  • it is explained where the length in the second fragment came from;
  • it is explained where the property in the fourth one went;
  • all six are rewritten correctly.
