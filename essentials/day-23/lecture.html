1. Зачем это нужно

Объект живёт в памяти программы. Пока программа работает, он доступен; как только страница закрылась — его нет. И передать его никуда нельзя: ни в файл, ни на сервер, ни в соседнюю вкладку.

Передавать умеют только текст. Значит, объект надо как-то записать строкой — так, чтобы потом собрать обратно. Именно это и делают две функции сегодняшнего дня.

const student = { name: "Аман", age: 17, marks: [5, 4] };

const text = JSON.stringify(student);
text;   // '{"name":"Аман","age":17,"marks":[5,4]}'

const back = JSON.parse(text);
back.name;   // "Аман" — снова обычный объект

Обратите внимание на подпись к схеме: после круга получается новый объект. Это свойство мы используем в разделе 10, когда будем делать глубокую копию.

И сразу предупреждение, к которому вернёмся не раз: круг не бесплатный. Объект в памяти богаче текста, и часть его содержимого через строку не проходит. Что именно теряется — разберём в разделе 4, и это главное, что нужно унести из сегодняшнего дня.

2. JSON — это текст

Сокращение расшифровывается как «JavaScript Object Notation» — запись объектов в стиле JavaScript. Но сам JSON не JavaScript, а отдельный формат текста, который понимают все языки: Python, Java, PHP, что угодно.

Правил у него немного, и они строже, чем в JavaScript:

В JavaScript можноВ JSON
{ name: "Аман" }ключ только в двойных кавычках: {"name": "Аман"}
{ 'name': 'Аман' }одинарные кавычки запрещены
[1, 2, ]висячая запятая запрещена
// комментарийкомментариев нет
undefined, функциине бывает
0x1F, 1_000только обычные числа

Зато всё остальное знакомо: объекты в фигурных скобках, массивы в квадратных, строки, числа, true, false, null. Шесть видов значений — и больше ничего.

Отсюда правило, которое сэкономит вам часы: увидев ошибку разбора, первым делом ищите одинарные кавычки, ключ без кавычек и лишнюю запятую. Это три причины из четырёх.

3. stringify: объект в строку

Берёт значение и возвращает его текстовую запись:

JSON.stringify({ name: "Аман", age: 17 });
// '{"name":"Аман","age":17}'

JSON.stringify([1, "два", true, null]);
// '[1,"два",true,null]'

typeof JSON.stringify({ a: 1 });   // "string"

Работает не только с объектами — с любым значением:

JSON.stringify(42);        // "42"
JSON.stringify("Аман");    // '"Аман"'  — кавычки стали частью строки!
JSON.stringify(true);      // "true"
JSON.stringify(null);      // "null"

Вторая строка удивляет: была строка — стала строка, но длиннее. Так и должно быть: в JSON текст записывается в кавычках, и кавычки — часть записи. Поэтому JSON.stringify("Аман").length равно шести, а не четырём.

4. Что теряется при записи

JSON умеет хранить шесть видов значений, а в JavaScript их больше. Всё лишнее при записи просто пропадает — без ошибки и без предупреждения.

const tricky = {
  fn() { return 1; },
  undef: undefined,
  nan: NaN,
  inf: Infinity,
  nested: { ok: 1 },
};

JSON.stringify(tricky);
// '{"nan":null,"inf":null,"nested":{"ok":1}}'

Сравните вход и выход: свойств было пять, осталось три. Функция и undefined исчезли целиком, а NaN и Infinity превратились в null — потому что в JSON таких чисел не бывает.

В массиве поведение другое: пропущенный элемент сдвинул бы остальные, поэтому вместо исчезновения подставляется null:

JSON.stringify([1, undefined, 3]);        // "[1,null,3]"
JSON.stringify([1, function () {}, 3]);   // "[1,null,3]"

И крайний случай: если само значение нельзя записать, stringify возвращает не строку, а undefined:

JSON.stringify(undefined);           // undefined, а не "undefined"
JSON.stringify(function () {});      // undefined

Отдельно про даты

Дата — самая коварная потеря, потому что выглядит как успех:

const order = { id: 1, when: new Date(2026, 8, 25, 14, 30) };

const back = JSON.parse(JSON.stringify(order));

typeof order.when;   // "object" — была дата
typeof back.when;    // "string" — стала строка!

Дата умеет записываться в строку, и stringify этим пользуется. Но обратного превращения нет: parse видит обычный текст и оставляет его текстом. Поэтому после круга дата ломается на первом же вызове метода:

back.when.getFullYear();
// TypeError: back.when.getFullYear is not a function

Как с этим быть — в разделе 12.

5. Красивый вывод

По умолчанию stringify пишет всё одной строкой — так короче для передачи. Для чтения человеком есть третий аргумент: отступ.

JSON.stringify({ a: 1, b: { c: 2 } }, null, 2);
{
  "a": 1,
  "b": {
    "c": 2
  }
}

Число означает количество пробелов; можно передать и строку — например, "\t" для табуляции. Второй аргумент пока ставим null, о нём — следующий раздел.

Отступы нужны только глазам: parse одинаково разберёт и сжатую запись, и красивую. Поэтому для передачи пишут без отступов, для показа и для файлов, которые правят руками, — с отступами.

6. Выбор полей

Второй аргумент решает, что попадёт в строку. Проще всего передать список нужных ключей:

const student = { name: "Аман", age: 17, secret: "код", marks: [5, 4] };

JSON.stringify(student, ["name", "marks"]);
// '{"name":"Аман","marks":[5,4]}'

Так убирают лишнее перед отправкой: пароли, служебные поля, тяжёлые куски, которые получателю не нужны.

Вместо списка можно передать функцию — она вызывается для каждого свойства и решает, что с ним делать. Вернуть undefined означает «выбросить»:

JSON.stringify(student, (key, value) =>
  key === "secret" ? undefined : value);
// '{"name":"Аман","age":17,"marks":[5,4]}'

В обычных задачах хватает списка; функция нужна, когда надо не выбросить поле, а изменить — округлить число, обрезать длинный текст.

7. parse: строка в объект

Обратная функция. Берёт текст и возвращает значение:

JSON.parse('{"a":1}');      // { a: 1 }
JSON.parse("[1,2,3]");      // [1, 2, 3]
JSON.parse("42");           // 42
JSON.parse('"Аман"');       // "Аман"

Обратите внимание на кавычки в примерах. Аргумент parse — это строка, и внутри неё лежит JSON. Отсюда двойной набор кавычек: одинарные снаружи — это JavaScript, двойные внутри — это JSON.

Здесь же самая частая ошибка новичка:

JSON.parse({ a: 1 });   // не то! аргумент должен быть строкой

Объект в parse передавать бессмысленно: он и так объект. Разбирать надо то, что пришло текстом — из файла, из сети, из хранилища браузера. Причём ошибка тут будет странная: аргумент сначала превратится в строку "[object Object]", и жаловаться разбор будет именно на неё.

8. Ошибки разбора

Если текст не годится, parse бросает SyntaxError. В Chrome сообщения подробные и указывают место — это редкий случай, когда он понятнее Firefox:

JSON.parse("{a:1}");
// SyntaxError: Expected property name or '}' in JSON at position 1 (line 1 column 2)

JSON.parse("{'a':1}");
// SyntaxError: Expected property name or '}' in JSON at position 1 (line 1 column 2)

JSON.parse('{"a":1,}');
// SyntaxError: Expected double-quoted property name in JSON at position 7 (line 1 column 8)

Три классические причины из раздела 2: ключ без кавычек, одинарные кавычки, висячая запятая. Во всех трёх случаях сообщение указывает позицию — номер символа, на котором разбор сломался.

Ещё две ошибки встречаются постоянно:

JSON.parse("");
// SyntaxError: Unexpected end of JSON input

JSON.parse("undefined");
// SyntaxError: "undefined" is not valid JSON

Первая — пустая строка; обычно значит, что данные не пришли вовсе. Вторая — попытка разобрать слово undefined: так бывает, когда в хранилище ничего не было, а результат всё равно отправили в parse.

На MDN эта страница озаглавлена «JSON.parse: unexpected character» и перечисляет полтора десятка формулировок — все от Firefox. Chrome говорит иначе и, что важнее, называет позицию. Если текст длинный, считайте символы от начала или ищите глазами именно там.

Поэтому разбор чужих данных почти всегда заворачивают в try из дня 11:

function parseOrNull(text) {
  try {
    return JSON.parse(text);
  } catch (error) {
    console.log("не разобралось:", error.message);
    return null;
  }
}

Разбор: почему пришло «undefined»

Самая частая ошибка разбора в настоящих программах выглядит загадочно: в строке, которую вы разбираете, вроде бы лежат данные, а сообщение говорит про слово undefined.

const store = {};   // хранилище, в котором пока пусто

JSON.parse(store.students);
// SyntaxError: "undefined" is not valid JSON

Шаг 1. Читаем сообщение буквально. Оно говорит не «данные плохие», а «строка "undefined" — не JSON». Значит, в разбор попало именно это слово.

Шаг 2. Смотрим, что передали.

store.students;          // undefined — ключа в хранилище нет
typeof store.students;   // "undefined"

Шаг 3. Понимаем превращение. JSON.parse ждёт строку, и если ему дали не строку, он сначала приводит аргумент к строке — по правилам дня 8. Из undefined получается текст "undefined", и вот его-то и не удаётся разобрать.

Шаг 4. Чиним проверкой до разбора:

const text = store.students;
const students = text ? JSON.parse(text) : [];

На дне 31 хранилище станет настоящим. Там пустой ключ даёт null, а JSON.parse(null) возвращает null без ошибки — зато записанный по ошибке undefined превратится ровно в эту строку "undefined". Пустое хранилище — нормальное состояние программы при первом запуске, и падать на нём она не должна.

9. Циклическая ссылка

Вторая ошибка дня — у stringify. Она случается, когда объект ссылается сам на себя:

const a = { name: "а" };
a.self = a;

JSON.stringify(a);
// TypeError: Converting circular structure to JSON

Записать такое нельзя в принципе: запись была бы бесконечной. Chrome к тому же подсказывает, какое именно свойство замыкает круг, — в сообщении есть строка вида «property 'self' closes the circle».

В учебных задачах цикл получается редко, а в настоящих — легко: два объекта ссылаются друг на друга, например студент знает свою группу, а группа — список студентов. Стоит попробовать сохранить такую структуру, и появится эта ошибка.

10. Глубокая копия через JSON

Вчера мы остановились на задаче, которую ни Object.assign, ни три точки не решают: скопировать объект вместе со всем, что внутри.

const deep = { id: 1, customer: { name: "Аман", tags: ["vip"] } };

const shallow = { ...deep };
shallow.customer.name = "Мерет";
deep.customer.name;   // "Мерет" — оригинал пострадал

Круг через JSON решает её в одну строку. Причина проста: parse строит всё заново, от самого верхнего объекта до последнего вложенного, и ни одна ссылка не остаётся общей.

const clone = JSON.parse(JSON.stringify(deep));

clone.customer.name = "Сапар";
clone.customer.tags.push("новый");

deep.customer.name;        // "Мерет" — не тронут
clone.customer === deep.customer;   // false — разные объекты

11. Цена этого приёма

Приём выглядит как волшебная палочка, но у него есть цена — ровно та, о которой шла речь в разделе 4. Копия переживёт круг только в том, что умеет записываться в JSON.

Что былоЧто станет после круга
строки, числа, true, nullкак были
массивы и вложенные объектыкак были, но новые
методы объектаисчезнут
undefined в свойствесвойство исчезнет
NaN, Infinitynull
Dateстрока
циклическая ссылкаTypeError

Поэтому правило такое: для простых данных — отличный приём, для объектов с методами и датами — нет. В нашем курсе данные как раз простые, так что пользоваться им можно смело.

У браузеров есть и честная глубокая копия — structuredClone. Она умеет и даты, и циклы. Но это не часть языка, а возможность браузера, поэтому ей место в курсе 4 вместе с остальными Web API.

Отдельно про числа

Числа через JSON проходят как есть — включая двоичную неточность из дня 17:

JSON.parse(JSON.stringify({ n: 0.1 + 0.2 })).n;   // 0.30000000000000004

А вот большие целые теряются, и это ловушка пострашнее. Граница та же, что на дне 17, — MAX_SAFE_INTEGER:

JSON.stringify({ id: 9007199254740993 });
// '{"id":9007199254740992}' — последняя цифра изменилась!

JSON.parse('{"id":"9007199254740993"}').id;
// "9007199254740993" — строкой сохранилось точно

Потеря происходит не в JSON, а в самом языке: такое число не помещается в тип number. Поэтому длинные идентификаторы — номера заказов, ключи из базы — передают строками. Увидев в чужом JSON "id": "12345" в кавычках, знайте: это не небрежность, а защита.

12. Оживление при разборе

Вернёмся к сломанной дате. У parse тоже есть второй аргумент — функция, которую зовут для каждого разобранного значения. Она может вернуть что-то своё:

const text = '{"id":1,"when":"2026-09-25"}';

const order = JSON.parse(text, (key, value) =>
  key === "when" ? new Date(value) : value);

order.when instanceof Date;   // true — снова настоящая дата

Приём называется «оживитель» (reviver). Он нужен именно там, где формат JSON беднее ваших данных: даты, большие числа, свои типы значений. Функция получает каждый ключ и каждое значение — включая вложенные, — и возвращает то, что должно оказаться в результате.

В простых программах его не пишут — проще хранить дату числом (getTime() из дня 17) и не иметь этой проблемы вовсе. Но узнавать в чужом коде стоит.

13. Где JSON встречается

Три места, и все три ждут нас в этом курсе.

ГдеЧто происходитКогда
хранилище браузера localStorage хранит только строки, поэтому объекты кладут через stringify день 31
ответ сервера fetch приносит текст, у ответа есть метод json() день 31
файлы настроек package.json и его родня — это обычный JSON с отступами в любом проекте

Есть и четвёртое место, менее очевидное: отладка. Когда объект сложный и в консоли сворачивается, console.log(JSON.stringify(obj, null, 2)) показывает его целиком и в понятном виде.

JSON как инструмент отладки

Про это стоит сказать подробнее, потому что приём экономит много времени. Когда в консоль печатают объект, браузер показывает его свёрнутым — и что-то показывает уже после того, как вы раскроете стрелочки. Хуже другое: раскрытый объект показывает текущее состояние, а не то, каким он был в момент печати.

const student = { name: "Аман", marks: [5, 4] };

console.log(student);                          // покажет объект «живым»
console.log(JSON.stringify(student));          // покажет снимок на этот момент
console.log(JSON.stringify(student, null, 2)); // то же, но читаемо

Разница видна, когда объект меняется дальше по программе: первая строка в консоли покажет уже изменённые данные, а вторая — те, что были. Для поиска «где именно испортилось» это решает дело.

Приём годится и для сравнения двух состояний: напечатали до, напечатали после, сравнили строки глазами. Главное помнить ограничение из раздела 4 — функции, даты и undefined в такой снимок не попадут.

Сравнение объектов — и почему это ловушка

Из дня 21 мы знаем: два объекта с одинаковым содержимым не равны друг другу. === спрашивает «та же ли это коробка», а не «одинаково ли внутри».

const a = { name: "Аман", age: 17 };
const b = { name: "Аман", age: 17 };

a === b;   // false

Отсюда популярный приём: сравнить не объекты, а их записи.

JSON.stringify(a) === JSON.stringify(b);   // true

Работает — но ровно до первого сюрприза. Запись зависит от порядка свойств, а порядок у одинаковых по смыслу объектов может отличаться:

const c = { age: 17, name: "Аман" };   // те же данные, другой порядок

JSON.stringify(a);   // '{"name":"Аман","age":17}'
JSON.stringify(c);   // '{"age":17,"name":"Аман"}'

JSON.stringify(a) === JSON.stringify(c);   // false!

Данные одинаковые, ответ отрицательный. И это не единственная беда: приём не заметит разницы между undefined и отсутствующим свойством, а на объекте с циклом просто упадёт.

Пользоваться этим приёмом можно только тогда, когда вы сами создали оба объекта одинаково — например, в проверке своего кода. Для чужих данных он неверен, и настоящее сравнение придётся писать самому, обходя свойства.

Размер и передача

Отступы удобны глазам, но дороги при передаче. Разница заметная:

const students = [
  { name: "Аман", marks: [5, 4, 9, 3, 5, 0, 4, 5] },
  { name: "Мерет", marks: [3, 3, 4] },
];

JSON.stringify(students).length;          // 76
JSON.stringify(students, null, 2).length; // 200

В два с половиной раза больше — и это на двух студентах. На тысяче записей разница в мегабайтах, а платит за неё тот, у кого медленный интернет.

Отсюда общее правило: по сети — без отступов, на экран и в файл, который правят руками, — с отступами. Всё, что уходит на сервер, пишут сжато.

14. «Табель» из сохранённых данных

Сегодня данные приходят к программе так, как они придут в настоящем проекте — одной строкой. Внутри неё тот же список студентов, но записанный по правилам JSON: все ключи в двойных кавычках, никаких комментариев.

const MIN_MARK = 2;
const MAX_MARK = 5;
const NAME_WIDTH = 12;

const toMark = (raw) => Number(String(raw).trim());
const isValidMark = (m) => Number.isInteger(m) && m >= MIN_MARK && m <= MAX_MARK;

const sum = (numbers) => numbers.reduce((total, n) => total + n, 0);
const average = (numbers) =>
  numbers.length === 0 ? 0 : sum(numbers) / numbers.length;

function verdict(avg, excellent = 4.5, good = 3.5, pass = 2.5) {
  if (avg >= excellent) return "отличник";
  if (avg >= good) return "хорошист";
  if (avg >= pass) return "троечник";
  return "надо подтянуть";
}

// новое: данные пришли строкой — как из файла или с сервера
const saved = `[

  { "name": "Мерет",    "marks": ["3", 3, 4] },
  { "name": "Гүлнар",   "marks": [9, 0, "пять"] },
  { "name": "Сапар",    "marks": [5, 5, "4", 5] },
  { "name": "Огулджан", "marks": ["4.5", 4, 5] }

const students = JSON.parse(saved);

// новое: считаем отчёт объектом, а показываем отдельно
function makeReport({ name = "без имени", marks = [] } = {}) {
  const all = marks.map((r) => toMark(r));
  const valid = all.filter(isValidMark);

  if (valid.length === 0) {
    return { name, ok: false };
  }

  const avg = average(valid);
  return {
    name,
    ok: true,
    average: Math.round(avg * 100) / 100,
    min: Math.min(...valid),
    max: Math.max(...valid),
    percent: Math.round(valid.length / all.length * 100),
    verdict: verdict(avg),
  };
}

function makeHeader() {
  return "Имя".padEnd(NAME_WIDTH) + "Средн".padStart(6) + "Мин".padStart(5)
    + "Макс".padStart(5) + "%".padStart(7) + "  Вердикт";
}

function makeRow(report) {
  if (!report.ok) {
    return report.name.padEnd(NAME_WIDTH) + "нет годных оценок";
  }
  return report.name.padEnd(NAME_WIDTH)
    + report.average.toFixed(2).padStart(6)
    + String(report.min).padStart(5)
    + String(report.max).padStart(5)
    + (report.percent + "%").padStart(7)
    + "  " + report.verdict;
}

С таблицей так не получилось бы: из выровненной строки числа обратно не достать. Это общее правило, которое пригодится в проектах: считайте в данных, форматируйте в самом конце.

Три опыта.

Первый. Сломайте JSON в saved тремя способами по очереди: уберите кавычки у одного ключа, поставьте одинарные, добавьте запятую после последнего студента. Запишите текст ошибки и позицию для каждого случая.

Второй. Сохраните весь отчёт строкой и разберите обратно. Сравните JSON.stringify(JSON.parse(text)) === text — и объясните результат.

Третий. Добавьте студенту свойство added: new Date(...), прогоните список через круг JSON и посмотрите, что стало с датой.

15. Как читать чужой JSON

Напоследок — приём, которым пользуются постоянно. Когда приходит незнакомый JSON (из документации, из ответа сервера, из чужого файла), разбираться в нём удобно не глазами, а кодом.

const incoming = '[{"name":"Аман","marks":[5,4]},{"name":"Мерет","marks":[3]}]';
const data = JSON.parse(incoming);

typeof data;              // "object" — объект или массив?
Array.isArray(data);      // true — значит, массив
data.length;              // 2 — сколько в нём элементов
Object.keys(data[0]);     // ["name", "marks"] — какие поля у одного элемента

Четыре строки — и структура понятна. Это то же самое чтение по слоям, что мы разбирали на дне 15 для чужих функций: сначала общая форма, потом подробности.

И полезная мелочь: если JSON пришёл одной длинной строкой, его легко сделать читаемым:

console.log(JSON.stringify(JSON.parse(incoming), null, 2));

Разобрали и тут же записали обратно, но уже с отступами. Тот же приём чинит и сжатые файлы настроек.

Порядок работы с чужими данными

Соберём всё сегодняшнее в один порядок действий — им пользуются каждый раз, когда данные приходят извне, и он же пригодится на дне 31.

function readList(text) {
  // 1. проверить, что вообще что-то пришло
  if (!text) {
    return [];
  }

  // 2. разобрать под защитой
  let data;
  try {
    data = JSON.parse(text);
  } catch (error) {
    console.log("данные сломаны:", error.message);
    return [];
  }

  // 3. проверить форму, а не только содержимое
  if (!Array.isArray(data)) {
    console.log("ожидали список, пришло:", typeof data);
    return [];
  }

  // 4. и только теперь работать
  return data.filter((item) => item && item.name);
}

readList("");                        // [] — пусто
readList("{");                       // [] и «данные сломаны: …»
readList("42");                      // [] и «ожидали список, пришло: number»
readList('[{"name":"Аман"}, {}]');   // [{ name: "Аман" }] — мусор отсеян

Четыре шага, и каждый закрывает свой случай: пусто, сломано, не та форма, мусор внутри. Пропустить можно любой — но тогда программа упадёт именно на нём, и обычно не у вас, а у пользователя.

Третий шаг стоит отметить отдельно. Успешный разбор не значит, что данные правильные. Строка "42" — совершенно законный JSON, и parse вернёт число вместо ожидаемого списка. Проверка формы стоит одной строки и снимает целый класс ошибок.

  1. Чем JSON отличается от литерала объекта в JavaScript?
    Ответ JSON — это текстовый формат, а не код. Ключи в нём только в двойных кавычках, одинарные кавычки, висячие запятые и комментарии запрещены, а undefined и функций не бывает вовсе.
  2. Что станет с функцией и с undefined при записи в JSON?
    Ответ В объекте свойство исчезнет целиком, без ошибки. В массиве на его месте окажется null — иначе сдвинулись бы остальные элементы.
  3. Почему после JSON.parse(JSON.stringify(order)) ломается order.when.getFullYear()?
    Ответ Дата записалась строкой, а parse оставил её строкой — у строки нет метода getFullYear. Лечится оживителем или хранением даты числом.
  4. Почему круг через JSON даёт настоящую глубокую копию?
    Ответ parse строит все объекты заново, от верхнего до самого вложенного, поэтому ни одна ссылка не остаётся общей. Цена — всё, что не записывается в JSON, теряется.
  5. Что делать, если JSON.parse бросил ошибку на данных от пользователя?
    Ответ Оборачивать разбор в try/catch и возвращать понятное значение по умолчанию. Чужие данные всегда могут прийти сломанными или не прийти вовсе.
