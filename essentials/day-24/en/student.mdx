# Day 24. DOM: finding elements

<Subtitle>A summary of the lecture: the page tree, searching by `id` and by selector, moving between neighbors.</Subtitle>

## The main points

<Definition>
**The DOM** is a tree of objects that the browser builds from HTML. JavaScript
changes not the file but this tree. The entrance to it is the variable `document`.
This is a feature of the browser, not of the language: Node has no `document`.
</Definition>

<KeyPoint>
We link the script with `defer`. Without it the code runs before the browser
finishes reading the markup, and `document.body` turns out to be `null`.
</KeyPoint>

```js
document.title;           // the text on the tab — it can also be changed
document.body.nodeName;   // "BODY" — the tag name in capital letters
document.body.nodeType;   // 1 — an element (3 — text, 9 — document)
```

## Find one element

```js
document.getElementById("title");     // id without a hash
document.querySelector("#title");     // the same element through a selector
document.querySelector(".student");   // a class — with a dot
document.querySelector("nope");       // null — not found, no error
```

| Selector | What it looks for |
| --- | --- |
| `li`, `.student`, `#list` | a tag, a class, an `id` |
| `li.absent` | a tag and a class together |
| `main p` | `p` at any depth inside `main` |
| `nav > a` | `a` directly inside `nav` |
| `li:not(.absent)` | all except |
| `header a, footer p` | one or the other |

<Remember>
Not found — `null`, and the error shows up one line below:
`Cannot read properties of null (reading '…')`. Look for the cause
in the line with the search: a typo, no `defer`, someone else’s page.
And a selector written wrongly (`"li..student"`) throws a
`SyntaxError` right away.
</Remember>

## Find all

```js
const items = document.querySelectorAll(".student");   // NodeList
items.length;   items[0];   items.item(0);

for (const li of items) { console.log(li); }   // going through — for...of
items.forEach((li) => console.log(li));        // or forEach

[...items].map((li) => li.nodeName);           // map — only on an array
```

Nothing found — an empty list with length 0, not `null`.
`for...in` does not suit a list: it also gives out `length`,
`item`, `forEach`.

<NoteBox>
The old methods `getElementsByClassName` and `getElementsByTagName`
return a **live** `HTMLCollection`: it follows
the page, but it has no `forEach`. `querySelectorAll` takes
a snapshot. Every element has its own `querySelector`: that is how you search inside
a container, for example `main.querySelectorAll("p")`.
</NoteBox>

## Moving through the tree

| All nodes | Only elements |
| --- | --- |
| `parentNode` | `parentElement` |
| `childNodes` | `children` |
| `firstChild` / `lastChild` | `firstElementChild` / `lastElementChild` |
| `previousSibling` / `nextSibling` | `previousElementSibling` / `nextElementSibling` |

<Remember>
Line breaks and indentation between tags are nodes too, text ones. That is why for a list of
five items `childNodes.length` is 11, and `firstChild` is
not the first item. **When you look for tags, take the transitions with the word
`Element`.** At the edge of the tree a transition returns `null`.
</Remember>

## Check and climb up

```js
const meret = document.querySelector(".absent");   // Meret

meret.matches(".absent");    // true — whether it fits the selector
meret.closest("main");       // the element itself or the nearest fitting ancestor
meret.closest("footer");     // null — there is no such ancestor
document.body.contains(meret);   // true — whether it lies inside
```

`closest` is more reliable than chains of `parentElement.parentElement`:
an extra wrapper in the markup will not break it.
