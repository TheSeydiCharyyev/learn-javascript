## Warm-up

<Task title="1. Three ways" level="easy" time="6">
<Goal>make sure that different ways of searching lead to one and the same object.</Goal>

Find the heading `h1` in three ways and put it into three variables:
with `getElementById`, with `querySelector` by `id`
and with `querySelector` by the selector `"header h1"`. Compare
them in pairs and print `nodeName`.

<Hint>
`===` for objects asks “is it the same box”. If all three
comparisons give `true`, then the tree has one heading, and there are many ways
to get to it.
</Hint>

<Criteria>
- three variables, three different ways of searching;
- all three comparisons gave `true`;
- it is written down what `nodeName` returned and why in capital letters;
- it is explained why the hash is not needed in `getElementById`
  but is required in a selector.
</Criteria>
</Task>

<Task title="2. How many of what" level="easy" time="7">
<Goal>learn to predict what a selector will find.</Goal>

First write down on paper how many elements each selector will find. Then check:

```js
const selectors = ["li", ".absent", "li:not(.absent)", "p", ".note", "nav a", "main *"];

selectors.forEach((sel) => {
  console.log(sel, document.querySelectorAll(sel).length);
});
```

<Hint>
`*` is any element, and `main *` is any element inside
`main`. Count with the tree scheme from the lecture; `main` itself
is not part of the answer.
</Hint>

<Criteria>
- the predictions are written down before running;
- the real answer is written down for all seven selectors;
- for every miss it is explained where the mistake was;
- an eighth selector that finds nothing is added — it is written down
  what `length` returned.
</Criteria>
</Task>

<Task title="3. Nodes and elements" level="easy" time="7">
<Goal>see the text nodes made of whitespace and find the pattern.</Goal>

```js
["#list", "nav", "footer", "header"].forEach((sel) => {
  const el = document.querySelector(sel);
  console.log(sel, el.childNodes.length, el.children.length);
});
```

Predict both numbers for each element, run the code and compare. Then print
`nodeName` of `firstChild` and of `firstElementChild`
for each of the four.

<Hint>
Look at the markup: each child stands on its own line. How many pieces
of “a line break plus indentation” are there around the five list items?
</Hint>

<Criteria>
- the predictions are written down before running;
- a formula linking the two numbers is found and checked on all four;
- it is written down that for all four `firstChild` is a text node;
- it is explained what changes if the list is written in one line without spaces.
</Criteria>
</Task>

## Main tasks

<Task title="4. Selectors" level="medium" time="12">
<Goal>pick a selector for a task and check that exactly what is needed was found.</Goal>

Create a page with a schedule:

```html
<section id="week">
  <h2>Schedule</h2>
  <ul class="days">
    <li class="day">Monday <span class="subject">JavaScript</span></li>
    <li class="day off">Tuesday</li>
    <li class="day">Wednesday <span class="subject">JavaScript</span> <span class="subject extra">HTML</span></li>
    <li class="day off">Thursday</li>
    <li class="day">Friday <span class="subject">JavaScript</span></li>
  </ul>
  <p class="note">Weekend — Saturday and Sunday</p>

```

For each item write one selector and check it with
`querySelectorAll(...).length`: all days (5), days off (2), working days (3),
all subjects (4), the extra subject (1), Wednesday’s subjects (2), the first and the last
day (1 each).

<Hint>
For working days `:not` comes in handy, for Wednesday — `:nth-child(3)`
and a space before the subject’s class. Check not only the number but also the elements themselves:
print the list to the console.
</Hint>

<Criteria>
- all eight selectors give exactly the stated number;
- each list is printed to the console and looked through;
- one selector is broken on purpose (two dots in a row) — the error text is written down;
- it is explained how `.day .subject` differs from `.day > .subject`
  and why here they find the same thing.
</Criteria>
</Task>

<Task title="6. Where the element lies" level="medium" time="12">
<Goal>answer questions about an element with `closest` and `matches`.</Goal>

Write `where(el)`: it returns `"header"`,
`"list"`, `"footer"` or `"other"` — depending
on where the element lies. Test it on the heading, on Meret, on the paragraph from the footer and on the paragraph
with the schedule.

<Example>
```js
where(document.querySelector("h1"));          // "header"
where(document.querySelector(".absent"));     // "list"
where(document.querySelector("footer p"));    // "footer"
where(document.getElementById("info"));       // "other"
```
</Example>

Then count those who were absent in two ways: with
`querySelectorAll(".absent")` and with an array of all `li`,
`filter` and `matches`.

<Hint>
`closest` returns an element or `null`, and in an `if`
condition an element is truthy, `null` is falsy. For
`filter`, first turn the list into an array.
</Hint>

<Criteria>
- all four checks gave the expected answer;
- it is explained why the paragraph with the schedule is “other”, although it is in `main`;
- both ways of counting gave 2;
- it is tested on a link from `nav` — what the function returned is written down.
</Criteria>
</Task>

## Starred tasks

<Task title="8. The path to an element" level="hard" time="10">
<Goal>go from an element to the root and write down the way.</Goal>

Write `path(el)`: it climbs from the element up to `body`
and returns the way as a string.

<Example>
```js
path(document.querySelector(".absent"));   // "BODY > MAIN > UL > LI"
path(document.querySelector("nav a"));     // "BODY > HEADER > NAV > A"
path(document.body);                       // "BODY"
```
</Example>

<Hint>
A `while` loop with `parentElement`: at each step the name
is added to the **beginning** of an array (`unshift` from day 19),
and at the end comes `join(" > ")`. Think about when the loop should stop.
</Hint>

<Criteria>
- all three examples give the stated answer;
- the function is tested on every list item — the way is the same for all;
- `depth(el)` is added — the number of steps to `body`;
- it is explained what happens if you pass an element from `head`,
  and how to fix it.
</Criteria>
</Task>
