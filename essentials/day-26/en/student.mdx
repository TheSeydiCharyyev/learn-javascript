# Day 26. Creating and removing elements

<Subtitle>A summary of the lecture: create, insert, move, copy, remove — and build a piece of the tree.</Subtitle>

## The main points

<Definition>
The order is always the same: **create, fill, insert**. A created element
lives in memory and is not visible on the page until it is inserted: `isConnected` is
`false`.
</Definition>

```js
const list = document.querySelector("#list");
const li = document.createElement("li");   // create
li.textContent = "Nazik";                    // fill — data only as text
li.classList.add("student");
list.append(li);                             // insert
```

## Where to insert

```js
const a = document.createElement("li");
const p = document.createElement("p");
const title = document.querySelector("#title");

list.append(a, "text");   // inside, at the end; nodes and strings, any number
list.prepend(a);          // inside, at the start
title.before(p);          // next to it, before the element
title.after(p);           // next to it, after the element
list.append(...[...list.children].reverse());   // an array of elements — with one call
```

<Remember>
`append` returns nothing: `const x = list.append(li)` gives
`undefined`. Everything that is not a node it turns into text — even `null`
and `undefined`. `before` and `after` on an element without a parent
silently do nothing.
</Remember>

## Move, copy, remove, replace

```js
list.prepend(list.lastElementChild);   // inserting an existing one — MOVING

const el = document.querySelector(".absent");
el.cloneNode(true);                     // a copy with the contents; without true — an empty shell
el.remove();                            // remove; the object stays in the variable

const old = document.querySelector(".absent");
old.replaceWith(el, "text");            // put something else in its place
```

<Remember>
A node cannot stand in two places: inserting takes it from the old one. If you need a copy —
`cloneNode(true)`, and change its `id` right away, otherwise the page will
have two identical ones.
</Remember>

<KeyPoint>
`for...of` over `list.children` with `remove` removes
every second one: the live collection shrinks on the way. To remove them all —
`querySelectorAll(...).forEach((x) => x.remove())`, to clear completely —
`list.textContent = ""`.
</KeyPoint>

## The old `Node` set

| Old | New |
| --- | --- |
| `parent.appendChild(node)` | `parent.append(node)` |
| `parent.insertBefore(node, ref)` | `ref.before(node)` |
| `parent.removeChild(node)` | `node.remove()` |
| `parent.replaceChild(newNode, oldNode)` | `oldNode.replaceWith(newNode)` |

The old methods are called on the parent, take one node, do not accept strings
(`appendChild("text")` — `TypeError`) and return the node.
`insertBefore(node, null)` inserts at the end. In `replaceChild`
the new one comes first, then the old one.

## Build and draw

```js
function toItem(name) {
  const li = document.createElement("li");   // we create from the top down…
  li.textContent = name;
  return li;                                 // …and give it back without inserting
}

function renderList(list, names) {
  list.textContent = "";                     // to redraw = to clear…
  list.append(...names.map(toItem));         // …and insert again, all at once
}
```

Children are attached to the parent from the bottom up, and the ready piece gets onto the page
once. For data `createElement` with `textContent` is safer than
`innerHTML` with a template string. Reordering is inserting in a new order:
`list.append(...[...list.children].reverse())`.

## Insertion errors

| What was done | What Chrome says |
| --- | --- |
| an ancestor was inserted into a descendant | `HierarchyRequestError: … The new child element contains the parent.` |
| `removeChild` not on the real parent | `NotFoundError: … is not a child of this node.` |
| `appendChild` with a string | `TypeError: … parameter 1 is not of type 'Node'.` |

The tree does not let you turn it into a non-tree: it has no circles.
The new methods spare you some of these errors — `el.remove()` knows its parent itself.
