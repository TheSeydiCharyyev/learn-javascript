# День 27. События

<Subtitle>Выжимка лекции: слушатели, объект события, всплытие, делегирование.</Subtitle>

## Главное

<Definition>
**Событие** — сообщение браузера «что-то произошло»: щелчок, клавиша,
конец загрузки. **Слушатель** — функция, которую браузер вызовет, когда
событие случится, и передаст ей **объект события**.
</Definition>

```js
button.addEventListener("click", (event) => {
  log.textContent = "Салам!";
});
```

<Remember>
Функцию **передают**, а не вызывают: `greet`, а не `greet()`.
Имя события — без `on` и маленькими буквами: `"click"`, а не
`"onclick"` или `"Click"`. Ошибки в этих случаях нет — щелчок
просто ничего не делает.
</Remember>

## Объект события

| Свойство | Что это |
| --- | --- |
| `type` | имя события: `"click"` |
| `target` | где случилось — самый глубокий элемент |
| `currentTarget` | где висит сработавший слушатель |
| `clientX`, `clientY` | точка щелчка в видимой части окна |
| `button` | кнопка мыши: 0 левая, 1 колесо, 2 правая |
| `key` | что напечатано: `"a"`, `"A"`, `"ф"`, `"Enter"` |
| `code` | какая клавиша физически: `"KeyA"` |
| `isTrusted` | от человека (`true`) или из кода (`false`) |

Правый щелчок не даёт `click` — только `mousedown`,
`mouseup`, `auxclick` и `contextmenu`. Клавиши приходят элементу в фокусе,
а без фокуса — `body`, поэтому клавиши страницы слушают у `document`.

## Всплытие и делегирование

Событие приходит на элемент и поднимается к предкам: `li` → `ul` →
`main` → `body` → `document` → `window`.
Поэтому хватает **одного слушателя на родителе**:

```js
list.addEventListener("click", (event) => {
  const li = event.target.closest("li");   // до пункта, даже если щёлкнули по <b> в нём
  if (!li) return;                         // щелчок мимо пунктов
  li.classList.toggle("star");
});
```

<KeyPoint>
Делегирование обслуживает и элементы, добавленные позже: слушатель висит на родителе.
Не всплывают `focus` и `blur` — их слушают на самом элементе.
</KeyPoint>

## Остановить и отменить

```js
const link = document.querySelector('a[href="#info"]');

link.addEventListener("click", (event) => {
  event.stopPropagation();   // дальше к предкам не пойдёт
  event.preventDefault();    // браузер не сделает своё: переход по ссылке, меню, отправку формы
});
```

Это разные вещи: `preventDefault` не мешает всплытию, `stopPropagation`
не отменяет действия браузера. Останавливать всплытие приходится редко: оно ломает
делегирование выше.

## Снять, загрузка, события из кода

```js
function greet(event) {
  console.log("нажали:", event.type);
}

button.removeEventListener("click", greet);    // только ТА ЖЕ функция
button.addEventListener("click", greet, { once: true });   // один раз
button.onclick = greet;                        // старый способ: место одно

document.addEventListener("DOMContentLoaded", () => {});   // дерево готово
window.addEventListener("load", () => {});                 // и картинки тоже

button.click();                                // щелчок из кода, isTrusted — false
button.dispatchEvent(new Event("hello", { bubbles: true }));
```

<Remember>
Анонимную стрелку не снять: написанная заново — это другая функция. Скрипту
с `defer` обёртка `DOMContentLoaded` не нужна: он и так выполняется
при готовом дереве. Слушатель, повешенный после события, не сработает: события не повторяются.
</Remember>

## Три тихие ошибки

| Написали | Что будет |
| --- | --- |
| `addEventListener("click", greet())` | `greet` сработала при загрузке, щелчок — ничего |
| `addEventListener("onclick", …)` | слушатель не сработает никогда |
| `removeEventListener` со стрелкой, написанной заново | слушатель остался |

У всех трёх одно общее: консоль молчит. Если кнопка «не работает», проверяйте их
первыми, а `getEventListeners(button)` в консоли Chrome покажет, какие
слушатели на самом деле висят на элементе.
