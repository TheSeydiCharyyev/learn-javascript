Day 28. Forms

A summary of the lecture: the values of fields, events, submitting and input validation.

Fields

// form, nameInput, present, message — from app.js, as in the lecture
// we typed “Ilýas”:
form.elements.name.value;        // "Ilýas" — always a string
form.elements.present.checked;   // true / false — the checkbox
form.elements.group.value;       // "JS-1" — the selected radio button of the group
form.elements.name.value = "";   // write from code
value is always a string: "5" + 1 gives "51". A number is Number(value), but Number("") and Number(" ") give 0, so an empty field is checked before converting. The text of a field is value, not textContent: for a field it is always empty.

Fields are found through form.elements by the name attribute. The short form.name is dangerous: a field named name covers the property of the form. The checked attribute in the markup is only the default state, the current one is in the property.

Field events

EventWhen it comesWhat for
inputon every change, on every letterrespond on the fly: a counter, search
changethe change is accepted: the field was left, a checkbox was clickedthe result: save, recalculate
submitthe form was submitted: with a button or Entercheck and process everything at once
resetthe form was resetremove messages
Writing from code (value = …, checked = …) causes no events. Need to recalculate — call the recalculation yourself.

Submitting and validation

form.addEventListener("submit", (event) => {
  event.preventDefault();                          // 1. otherwise a reload
  const name = form.elements.name.value.trim();    // 2. read and clean

  if (name === "") {                               // 3. one reason at a time
    message.textContent = "Enter a name";
    form.elements.name.focus();
    return;
  }

  message.textContent = `Added: ${name}`;          // 4. work with the data
  form.reset();                                    //    and clear the form
});
Listen for the form’s submit, not the button’s click: the form is also submitted by Enter in a field. A <button> without type inside a form is a submit button; buttons for other jobs get type="button". Without preventDefault the page reloads, and the data goes into the address: ?name=…&marks=….

The browser checks the required attribute itself: with an empty field the form is not submitted, and submit does not come. Rules like “marks from 2 to 5” are checked with code. An error is shown on the page and the field is highlighted with a class, and the highlight is removed in an input listener — as soon as the person starts fixing it.

Two techniques

// live search on the group page: hide those who do not match, on every letter
const search = document.querySelector("#search");
const items = document.querySelectorAll("#list li");

search.addEventListener("input", () => {
  const query = search.value.trim().toLowerCase();
  items.forEach((li) => {
    li.hidden = !li.textContent.toLowerCase().includes(query);
  });
});
// the whole form in one object, further on the code works only with it
const data = {
  name: form.elements.name.value.trim(),
  present: form.elements.present.checked,
};

Several marks in one field are taken apart by characters: [..."5 4 9"].filter((ch) => ch !== " ") gives ["5", "4", "9"]. The split method for this will appear in course 2.

Dialogs

alert("Saved");            // undefined
confirm("Delete?");        // true — OK, false — Cancel
prompt("Name?", "Guest");  // a string; "" — an empty OK; null — Cancel

Dialogs stop the page and look like a window of the browser. confirm fits before an irreversible action; input errors are better shown on the page. The answer of prompt is checked for null first of all.
