Day 28. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–5, 8 and 9 are done on the student form from the lecture (the folder day-28): take the markup and app.js from section 2 and add to <style> the rule .invalid { outline: 2px solid #b91c1c; }. Task 6 is done on the group page of the previous days, task 7 in the folder day-28/tabel.

Warm-up

1. The student form
Easy6 min

learn to read and write the values of fields.

In the console read through form.elements all the values of the form: the name, the marks, the checkbox, the group. Fill in the fields by hand, uncheck the checkbox, select JS-2 — read them again. Then write “Aman” into the name field from code.

For a checkbox you need checked, for a group of radio buttons — form.elements.group.value.
  • the values before and after filling in by hand are written down;
  • the typeof of the value of the marks field with “5” typed in is written down;
  • it is checked that after unchecking the checkbox the checked attribute stayed in the markup;
  • form.name is printed — it is explained what came back and why.
2. input and change
Easy7 min

see when each of the two events comes.

Add both listeners to the name field and to the checkbox: input and change. Each one writes the event name and the current value to the console. Type a name, leave the field with the Tab key, click the checkbox. Then change the values from code.

The value is handy to print through JSON.stringify — then both an empty string and spaces are visible.
  • it is written down how many times input came and how many times change when typing a five-letter name;
  • the order of the events on a click on the checkbox is written down;
  • it is checked that writing from code did not cause a single event;
  • it is explained which event to take for live search and which for saving a choice.
3. A letter counter
Easy7 min

respond to input on the fly.

Below the name field show “Letters: N”. If there are more than 20 letters, add “— too long” and highlight the field with the invalid class; as soon as there are 20 letters or fewer again, remove the highlight.

// typed “Oguljan Ilýasowna Berd”:
// Letters: 22 — too long, the field has the invalid class
One line controls the class both ways: toggle with the second argument from day 25.
  • the counter changes on every letter and on every deletion;
  • the highlight appears at the 21st letter and disappears when the extra ones are deleted;
  • it is written down whether spaces are counted, and decided whether they should be;
  • a name is written in from code — it is explained why the counter did not update.

Main tasks

4. Submitting without a reload
Medium12 min

intercept the submitting of a form and figure out what the browser does without us.

When the form is submitted, write “Added: name” on the page and clear the form. Check submitting with a click and with the Enter key in a field. Then temporarily remove preventDefault and look at the address of the page.

Listen for the form’s submit, not the button’s click. After submitting, one line clears the form — form.reset().
  • both ways of submitting — a click and Enter — give the message and do not reload the page;
  • without preventDefault the address the page got is written down, and it is explained where each part of it comes from;
  • a “Hint” button is added to the form — it is explained why it submits the form, and it is fixed with an attribute;
  • the message is reset together with the form — through the reset event.
5. Input validation
Medium13 min

check data one reason at a time and report an error clearly.

Before “Added”, check in order: the name is not empty; the name has at least 2 letters; marks are entered; every mark is a digit from 2 to 5. The error message is on the page, the field with the error is highlighted and gets the focus.

// empty                  → Enter a name
// “I”                    → The name is too short
// “Ilýas”, no marks      → Enter the marks
// “Ilýas”, “5 7”         → Marks are digits from 2 to 5
// “Ilýas”, “5 4”         → Added: Ilýas
Marks are the characters of the string without spaces, as in the lecture. The check “every” is every from day 20. Each error is handy to return as a string from a separate function check(), and an empty string means “all is well”.
  • all five lines of the example give the stated answer;
  • the highlight is removed as soon as the person starts fixing the field;
  • a name of only spaces counts as empty;
  • it is explained why the checks go one at a time, and why in exactly this order.
6. Live search
Medium12 min

respond to input by hiding and showing elements.

On the group page add a search field above the list and a paragraph below it. On every letter hide the students whose name does not contain what was typed, and write “Found: N”. If nobody was found — “Nobody found”.

trim, toLowerCase and includes from day 16 make the search ignore case and spaces; hide with the hidden property from day 25.
  • “a” leaves four, “man” — one, “  MERET” — Meret;
  • an empty field shows everyone again;
  • with zero found, “Nobody found” appears;
  • it is explained why input is used here and not change.
7. The “Report card” with a form
Medium13 min

add students through a form with validation.

Copy day-27/tabel into day-28/tabel and add:

  • above the table, a form: a name, marks separated by spaces, an “Add” button;
  • checks: an empty name, a repeated name, no marks — a message on the page and the focus in the field;
  • a new row through makeReport, makeRow and addDeleteButton, the total recalculated, the form cleared;
  • confirm before deleting a row.
  • “Ilýas”, “5 4 9” give a green row 4.50, 4, 5, 67% and the total “3 of 6”;
  • “  Aman ” is not added: “This student already exists”;
  • on Cancel in confirm the row stays;
  • makeReport has not changed in a single line;
  • it is explained why the check for a repeat protects deleting from day 27.

Starred tasks

8. The form there and back
Hard10 min

collect a form into an object and restore it from the object.

Write readForm(form), which returns an object with all the values of the form, and fillForm(form, data), which puts such an object back into the fields. Check the round trip: fill in → write as a JSON string → reset → parse the string → fillForm.

const saved = JSON.stringify(readForm(form));
// '{"name":"Ilýas","marks":"5 4 5","present":false,"group":"JS-2"}'
form.reset();
fillForm(form, JSON.parse(saved));   // the fields are as they were again, JS-2 included
The value of a group of radio buttons can be not only read but also written: form.elements.group.value = "JS-2" checks the right radio button.
  • after the round trip JSON.stringify(readForm(form)) === saved is true;
  • the checkbox and the radio button were restored;
  • it is written down which events came during fillForm, and it is explained why;
  • it is explained where this round trip will come in handy on day 31, when browser storage appears.
9. Six catches
Hard10 min

gather together everything that behaves unexpectedly today.

The marks field has “5” typed in, and in the prompt window someone will press “Cancel”.

form.elements.name.addEventListener("input", () => console.log("input!"));

console.log(form.elements.marks.value + 1);                    // 1
console.log(form.name);                                        // 2
form.elements.name.value = "Aman";                             // 3
console.log(form.elements.name.textContent);                   // 4
console.log(Number(form.elements.marks.value) + Number(""));   // 5
console.log(prompt("Name?").trim());                           // 6
The third line prints nothing itself — the question is whether the listener prints something. Only the sixth one crashes. In the fifth, one of the terms unexpectedly turns out to be zero.
  • the predictions are written down before running;
  • for the sixth, the exact text of the error is written down;
  • for each of the first five, it is explained where the answer came from;
  • all six are rewritten to do what the author apparently wanted.
