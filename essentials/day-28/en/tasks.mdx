## Warm-up

<Task title="1. The student form" level="easy" time="6">
<Goal>learn to read and write the values of fields.</Goal>

In the console read through `form.elements` all the values of the form: the name, the marks,
the checkbox, the group. Fill in the fields by hand, uncheck the checkbox, select JS-2 — read them again.
Then write “Aman” into the name field from code.

<Hint>
For a checkbox you need `checked`, for a group of radio buttons —
`form.elements.group.value`.
</Hint>

<Criteria>
- the values before and after filling in by hand are written down;
- the `typeof` of the value of the marks field with “5” typed in is written down;
- it is checked that after unchecking the checkbox the `checked` attribute stayed in the markup;
- `form.name` is printed — it is explained what came back and why.
</Criteria>
</Task>

<Task title="2. input and change" level="easy" time="7">
<Goal>see when each of the two events comes.</Goal>

Add both listeners to the name field and to the checkbox: `input` and `change`.
Each one writes the event name and the current value to the console. Type a name, leave the field
with the <Kbd>Tab</Kbd> key, click the checkbox. Then change the values from code.

<Hint>
The value is handy to print through `JSON.stringify` — then both an empty string
and spaces are visible.
</Hint>

<Criteria>
- it is written down how many times `input` came and how many times `change`
  when typing a five-letter name;
- the order of the events on a click on the checkbox is written down;
- it is checked that writing from code did not cause a single event;
- it is explained which event to take for live search and which for saving a choice.
</Criteria>
</Task>

<Task title="3. A letter counter" level="easy" time="7">
<Goal>respond to input on the fly.</Goal>

Below the name field show “Letters: N”. If there are more than 20 letters, add
“— too long” and highlight the field with the `invalid` class; as soon as
there are 20 letters or fewer again, remove the highlight.

<Example>
```js
// typed “Oguljan Ilýasowna Berd”:
// Letters: 22 — too long, the field has the invalid class
```
</Example>

<Hint>
One line controls the class both ways: `toggle` with the second
argument from day 25.
</Hint>

<Criteria>
- the counter changes on every letter and on every deletion;
- the highlight appears at the 21st letter and disappears when the extra ones are deleted;
- it is written down whether spaces are counted, and decided whether they should be;
- a name is written in from code — it is explained why the counter did not update.
</Criteria>
</Task>

## Main tasks

<Task title="4. Submitting without a reload" level="medium" time="12">
<Goal>intercept the submitting of a form and figure out what the browser does without us.</Goal>

When the form is submitted, write “Added: name” on the page and clear the form. Check
submitting with a click and with the <Kbd>Enter</Kbd> key in a field. Then temporarily
remove `preventDefault` and look at the address of the page.

<Hint>
Listen for the form’s `submit`, not the button’s `click`. After submitting,
one line clears the form — `form.reset()`.
</Hint>

<Criteria>
- both ways of submitting — a click and Enter — give the message and do not reload the page;
- without `preventDefault` the address the page got is written down, and it is explained
  where each part of it comes from;
- a “Hint” button is added to the form — it is explained why it submits the form,
  and it is fixed with an attribute;
- the message is reset together with the form — through the `reset` event.
</Criteria>
</Task>

<Task title="5. Input validation" level="medium" time="13">
<Goal>check data one reason at a time and report an error clearly.</Goal>

Before “Added”, check in order: the name is not empty; the name has at least 2 letters;
marks are entered; every mark is a digit from 2 to 5. The error message is on the page,
the field with the error is highlighted and gets the focus.

<Example>
```js
// empty                  → Enter a name
// “I”                    → The name is too short
// “Ilýas”, no marks      → Enter the marks
// “Ilýas”, “5 7”         → Marks are digits from 2 to 5
// “Ilýas”, “5 4”         → Added: Ilýas
```
</Example>

<Hint>
Marks are the characters of the string without spaces, as in the lecture. The check “every” is
`every` from day 20. Each error is handy to return as a string from a separate
function `check()`, and an empty string means “all is well”.
</Hint>

<Criteria>
- all five lines of the example give the stated answer;
- the highlight is removed as soon as the person starts fixing the field;
- a name of only spaces counts as empty;
- it is explained why the checks go one at a time, and why in exactly this order.
</Criteria>
</Task>

## Starred tasks

<Task title="8. The form there and back" level="hard" time="10">
<Goal>collect a form into an object and restore it from the object.</Goal>

Write `readForm(form)`, which returns an object with all the values of the
form, and `fillForm(form, data)`, which puts such an object back into
the fields. Check the round trip: fill in → write as a JSON string → `reset` →
parse the string → `fillForm`.

<Example>
```js
const saved = JSON.stringify(readForm(form));
// '{"name":"Ilýas","marks":"5 4 5","present":false,"group":"JS-2"}'
form.reset();
fillForm(form, JSON.parse(saved));   // the fields are as they were again, JS-2 included
```
</Example>

<Hint>
The value of a group of radio buttons can be not only read but also written:
`form.elements.group.value = "JS-2"` checks the right radio button.
</Hint>

<Criteria>
- after the round trip `JSON.stringify(readForm(form)) === saved` is `true`;
- the checkbox and the radio button were restored;
- it is written down which events came during `fillForm`, and it is explained why;
- it is explained where this round trip will come in handy on day 31, when browser storage appears.
</Criteria>
</Task>

<Task title="9. Six catches" level="hard" time="10">
<Goal>gather together everything that behaves unexpectedly today.</Goal>

The marks field has “5” typed in, and in the `prompt` window someone will press “Cancel”.

```js
form.elements.name.addEventListener("input", () => console.log("input!"));

console.log(form.elements.marks.value + 1);                    // 1
console.log(form.name);                                        // 2
form.elements.name.value = "Aman";                             // 3
console.log(form.elements.name.textContent);                   // 4
console.log(Number(form.elements.marks.value) + Number(""));   // 5
console.log(prompt("Name?").trim());                           // 6
```

<Hint>
The third line prints nothing itself — the question is whether the listener prints something.
Only the sixth one crashes. In the fifth, one of the terms unexpectedly turns out to be zero.
</Hint>

<Criteria>
- the predictions are written down before running;
- for the sixth, the exact text of the error is written down;
- for each of the first five, it is explained where the answer came from;
- all six are rewritten to do what the author apparently wanted.
</Criteria>
</Task>
