## 1. Страница спрашивает {#why}

До сих пор данные «Табеля» жили в коде: сначала в массивах, потом в строке JSON.
Добавить студента можно было только из консоли. Настоящая программа берёт данные
у человека, и главный способ для этого — **форма**: поля ввода, флажки,
переключатели и кнопка отправки.

Всё, что нужно для работы с формой, у нас уже есть: найти поле (день 24), показать
ошибку (день 25), добавить строку (день 26), ответить на щелчок (день 27). Сегодня
добавим три вещи: значения полей, события полей и отправку формы.

Полей в HTML много видов, и почти все — один тег `<input>` с разным
атрибутом `type`:

| `type` | Что это | Главное свойство |
| --- | --- | --- |
| `text` (или без `type`) | строка текста | `value` |
| `number`, `email`, `password`, `date` | текст с подсказками браузера | `value` |
| `checkbox` | флажок «да — нет» | `checked` |
| `radio` | переключатель, один из группы | `checked` |

## 2. Учебная анкета {#page}

```html
<form id="student-form">
  <label>Имя: <input name="name" placeholder="Например, Ильяс"></label>
  <label>Оценки: <input name="marks" placeholder="5 4 5"></label>
  <label><input type="checkbox" name="present" checked> был на занятии</label>
  <p>
    Группа:
    <label><input type="radio" name="group" value="JS-1" checked> JS-1</label>
    <label><input type="radio" name="group" value="JS-2"> JS-2</label>
  </p>
  <button>Добавить</button>
  <button type="reset">Очистить</button>
</form>
<p id="message"></p>
```

Несколько деталей разметки, которые важны для кода:

| В разметке | Зачем |
| --- | --- |
| `name="…"` | имя поля: по нему код находит поле, по нему же браузер отправляет данные |
| `<label>` вокруг поля | щелчок по подписи ставит курсор в поле или переключает флажок |
| `type="checkbox"`, `type="radio"` | флажок и переключатель; без `type` — текстовое поле |
| одинаковый `name="group"` | переключатели в одной группе: выбран только один |
| `<button>` без `type` | **отправляет форму** — об этом раздел 7 |
| `placeholder` | подсказка в пустом поле; это не значение |

У подписи есть и второй способ связаться с полем — атрибут `for` со значением
`id` поля. Так пишут, когда подпись и поле стоят в разных местах разметки:

```html
<label for="name-field">Имя:</label>
<input id="name-field" name="name">
```

Разметка анкеты — в `index.html`, а в `app.js` — четыре строки,
которые нужны во всех разделах:

```js
// app.js
const form = document.querySelector("#student-form");
const nameInput = form.elements.name;   // как находить поля — раздел 6
const present = form.elements.present;
const message = document.querySelector("#message");
```

Примеры разделов пишите в консоли. Примеры одного раздела продолжают друг друга,
а перед каждым новым разделом обновляйте страницу (<Kbd>F5</Kbd>): анкета
вернётся к исходному виду, а четыре переменные из `app.js` появятся снова.

## 3. `value`: значение поля {#value}

Поле ввода в DOM — объект `HTMLInputElement`, ещё один уровень родословной
из дня 25, ниже `HTMLElement`. Главное его свойство — `value`,
то, что сейчас набрано в поле:

```js
nameInput.value;          // "" — пока ничего не набрано
nameInput.placeholder;    // "Например, Ильяс" — подсказка, не значение
nameInput.value = "Аман"; // записать в поле из кода
```

Два правила, на которых держится вся работа с формами.

**`value` — всегда строка.** Даже если в поле набрали «5»,
это строка `"5"`, как всё, что мы читали со страницы на дне 25. Число из неё
делают через `Number` — подробнее в разделе 12.

**Запись из кода не вызывает событий.** `nameInput.value = "Аман"`
поменяет поле молча: ни `input`, ни `change` не придут. События
приходят только от действий человека. Если код меняет поле и должен что-то пересчитать,
пересчёт вызывают сами, той же функцией, что и слушатель.

У поля есть и свойство `type` — `"text"`, `"checkbox"`,
`"radio"` и десятки других: для чисел, дат, цветов, паролей. Все они — один
интерфейс `HTMLInputElement`, и для всех значение лежит в `value`,
строкой.

```js
form.elements.marks.type = "number";   // или type="number" прямо в разметке
form.elements.marks.value = 5;         // записали число…
form.elements.marks.value;             // "5" — …а прочитали строку
```

Поле для чисел не даст набрать буквы и покажет стрелки, но правило не меняет:
`value` и у него строка.

<Mistake>
Текст поля — это `value`, а не `textContent`. У
`<input>` нет детей, поэтому `textContent` у него всегда
пустая строка, что бы ни было набрано. Привычка из дня 25 здесь подводит.
</Mistake>

```js
nameInput.value = "Ильяс";
nameInput.textContent;   // "" — у поля нет текстовых детей
nameInput.value;         // "Ильяс"
```

## 4. `checked`: флажки и переключатели {#checked}

У флажка важно не значение, а **отмечен ли он**. Это свойство
`checked`, `true` или `false`:

```js
present.checked;               // true — в разметке стоит атрибут checked
// человек снял флажок:
present.checked;               // false
present.hasAttribute("checked");   // true — атрибут остался!
```

Последняя строка — тонкость из MDN. Атрибут `checked` в разметке задаёт
только состояние **по умолчанию**. Текущее состояние живёт в свойстве.
Это тот случай, когда атрибут и свойство из дня 25 расходятся: атрибут помнит, как было
в разметке, свойство — как сейчас.

И флажок, как текстовое поле, не сообщает о переменах, сделанных кодом:

```js
present.addEventListener("change", () => console.log("change"));
present.checked = false;   // флажок снят, но "change" не напечатано
```

Переключатели с одним `name` работают группой: выбрать можно только один.
Когда один становится `checked`, остальные сами становятся `false`.
Узнать выбранное значение группы проще всего через форму:

```js
form.elements.group.value;   // "JS-1"
// выбрали JS-2:
form.elements.group.value;   // "JS-2" — value отмеченного переключателя
```

## 5. `input` и `change` {#input-change}

У полей два главных события. Отличаются они тем, **когда** приходят.

<Scheme src="scheme-input-change.svg">input — «значение меняется», change — «значение изменено и принято»</Scheme>

`input` приходит **на каждое изменение** — на каждую букву,
стирание, вставку. `change` у текстового поля приходит **один раз**,
когда изменение «принято»: человек ушёл из поля. У флажка и переключателя
`change` приходит сразу при щелчке.

```js
nameInput.addEventListener("input", () => {
  message.textContent = `Букв: ${nameInput.value.length}`;
});
// набираем «Ильяс» — под формой по очереди: Букв: 1, 2, 3, 4, Букв: 5
```

Когда что брать: **`input` — когда страница должна отвечать
на ходу**: счётчик букв, живой поиск (раздел 13), подсказка под полем.
**`change` — когда важен итог**: сохранить выбор флажка,
пересчитать, когда поле заполнено. MDN советует для флажков и переключателей именно
`change`: `input` у них раньше приходил не во всех браузерах.

```js
present.addEventListener("change", () => {
  message.textContent = present.checked ? "Был на занятии" : "Пропустил занятие";
});
// щелчок по флажку: «Пропустил занятие», ещё щелчок — «Был на занятии»
```

## 6. Форма и её поля {#form}

Сама форма — объект `HTMLFormElement`. У него есть `elements` —
коллекция всех полей и кнопок формы, и в ней поле находится **по имени**:

```js
form.elements.name;      // <input name="name" …>
form.elements.marks;     // <input name="marks" …>
form.elements.present;   // флажок
form.elements.length;    // 7 — два поля, флажок, два переключателя и две кнопки
form.length;             // 7 — то же самое
```

Это удобнее `querySelector`: поле ищется только внутри этой формы, и имя
читается прямо в коде.

```js
for (const field of form.elements) {
  console.log(field.nodeName.toLowerCase(), field.type, field.name);
}
// input text name        input text marks       input checkbox present
// input radio group      input radio group      button submit      button reset

nameInput.form === form;   // true — каждое поле знает свою форму
```

Перебор полей пригодится, когда их много и с каждым нужно сделать одно и то же, —
например, снять со всех подсветку ошибки. Обратная ссылка `form` есть у каждого
поля: в слушателе поля по ней легко добраться до всей формы.

Почему же именно `form.elements.name`, а не короче — `form.name`?
MDN предупреждает о ловушке:

```js
form.name === form.elements.name;   // true — form.name вернул ПОЛЕ, а не имя формы!
```

Браузер делает поля формы ещё и её свойствами. Поле с именем `name`
перекрыло собственное свойство формы `name`. То же случится с полями
`id`, `action`, `method`. Правило MDN: **всегда
через `elements`** и никогда не называйте поле `"elements"`.
В «Табеле» мы на всякий случай назовём поле имени `student`.

## 7. Событие `submit` {#submit}

Когда форму отправляют, на **форме** — не на кнопке — приходит событие
`submit`. Слушают его у формы:

```js
form.addEventListener("submit", (event) => {
  event.preventDefault();   // главная строка — раздел 8
  console.log("отправка", form.elements.name.value);
});
```

Отправить форму можно тремя путями, и все три приводят к одному `submit`:

| Что сделал человек | Что произошло |
| --- | --- |
| щёлкнул `<button>` без `type` | `click` на кнопке, потом `submit` на форме |
| нажал <Kbd>Enter</Kbd> в текстовом поле | браузер «щёлкает» по первой кнопке отправки — те же `click` и `submit` |
| щёлкнул `<button type="submit">` | то же, что без `type` |

Поэтому отправку слушают через `submit` формы, а не через `click`
кнопки: слушатель щелчка пропустил бы <Kbd>Enter</Kbd>. Объект события здесь —
`SubmitEvent`, наследник `Event`.

MDN уточняет правило для <Kbd>Enter</Kbd>. Если в форме есть кнопка
отправки, <Kbd>Enter</Kbd> в текстовом поле всегда отправляет форму. Если
кнопки нет, отправка случится, только когда текстовое поле в форме одно. Форма поиска
из одного поля работает без кнопки, а анкета из двух полей без кнопки по
<Kbd>Enter</Kbd> не отправится.

```js
form.querySelector("button").addEventListener("click", () => console.log("click"));
form.addEventListener("submit", (event) => {
  event.preventDefault();
  console.log("submit", event.target.nodeName);
});
// щелчок по «Добавить»: click, «отправка …» из примера выше, потом submit FORM
// Enter в поле имени:   то же самое — браузер «щёлкнул» по кнопке сам
```

<Mistake>
`<button>` внутри формы **по умолчанию отправляет** её.
Кнопка «Показать подсказку» в форме без `type="button"` будет отправлять
форму при каждом щелчке. Кнопкам, которые не должны отправлять, пишут
`type="button"`.
</Mistake>

## 8. Разбор: страница перезагрузилась {#reload}

Написали слушатель `submit` без `preventDefault`:

```js
form.addEventListener("submit", () => {
  message.textContent = "Добавлено!";   // мелькнёт на долю секунды — и исчезнет
});
```

Заполнили форму, нажали «Добавить». Страница мигнула, поля опустели, в консоли пусто.

<Scheme src="scheme-reload.svg">Действие браузера по умолчанию у формы — отправить и перезагрузить. Мы его отменяем</Scheme>

**Шаг 1. Смотрим на адрес.** В конце появилось
`?name=…&marks=5+4+5&present=on&group=JS-1`. Это данные формы:
браузер собрал их по атрибутам `name` и отправил. Пробелы стали плюсами,
отмеченный флажок — словом `on`.

**Шаг 2. Понимаем, что случилось.** У `submit` есть действие
по умолчанию (день 27): отправить данные туда, куда указывает форма, и открыть
ответ как новую страницу. Адреса у нашей формы нет, поэтому браузер открыл ту же страницу
заново — с чистыми полями и нетронутым кодом. Всё, что успел сделать наш слушатель,
пропало вместе со старой страницей.

**Шаг 3. Чиним.** Первая строка любого слушателя `submit` —
`event.preventDefault()`. Обращаться к серверу без перезагрузки страницы
научимся на дне 31 — через `fetch`.

## 9. Своя проверка ввода {#validate}

Человек может нажать «Добавить», ничего не заполнив, или набрать одни пробелы.
Прежде чем работать с данными, их проверяют — и сообщают об ошибке **на странице**,
рядом с формой, а не в консоли, которой человек не видит.

```js
form.addEventListener("submit", (event) => {
  event.preventDefault();
  const name = form.elements.name.value.trim();   // пробелы по краям не считаются

  if (name === "") {
    message.textContent = "Введите имя";
    form.elements.name.focus();                   // курсор — туда, где ошибка
    return;
  }

  message.textContent = `Добавлен: ${name}`;
  form.reset();                                   // раздел 11
});
```

В этом коде — порядок, которого держатся все проверки.

<Step n="1" numberTag="span">
**Остановить браузер**:
`preventDefault` первой строкой, до всех проверок.
</Step>

<Step n="2" numberTag="span">
**Прочитать и очистить**:
`trim` из дня 16 — иначе «&nbsp;&nbsp;&nbsp;» пройдёт как имя.
</Step>

<Step n="3" numberTag="span">
**Проверить по одной причине
за раз**: нашли ошибку — написали понятное сообщение, поставили фокус в нужное поле
(`focus` из дня 27) и вышли через `return`.
</Step>

<Step n="4" numberTag="span">
**Только потом работать**
с данными — и очистить старое сообщение об ошибке.
</Step>

Какие проверки обычно нужны — от самых частых к редким:

| Проверка | Пример в коде |
| --- | --- |
| поле не пустое | `value.trim() === ""` |
| длина | `value.trim().length < 2` |
| число и его границы | `Number.isInteger(n) && n >= 2 && n <= 5` |
| нет повтора | `reports.some((r) => r.name === name)` |

Это тот же порядок, что для чужого JSON на дне 23: проверить, что пришло, и только
потом доверять. Данные из формы — самые чужие из всех: их набирает человек.

### Подсветить поле и снять подсветку

Сообщение под формой хорошо, но ещё лучше, когда видно само поле с ошибкой. Класс
из дня 25 — и правило в `<style>`:

```html
<style>
  .invalid { outline: 2px solid #b91c1c; }
</style>
```

```js
const nameField = form.elements.name;

form.addEventListener("submit", (event) => {
  event.preventDefault();
  if (nameField.value.trim() === "") {
    nameField.classList.add("invalid");
    message.textContent = "Введите имя";
    return;
  }
  message.textContent = "Готово";
});

nameField.addEventListener("input", () => {
  nameField.classList.remove("invalid");   // человек начал исправлять —
  message.textContent = "";                // ошибку убираем сразу
});
```

Второй слушатель — хороший тон: подсветка исчезает с первой набранной буквой,
а не висит до следующей отправки. Здесь `input` работает ровно для того,
для чего создан, — ответить на ходу.

## 10. Проверка браузера: `required` {#required}

Часть проверок браузер умеет сам. Атрибут `required` делает поле
обязательным:

```html
<input name="name" required>
```

```js
form.addEventListener("submit", () => console.log("submit"));
// поле с required пустое: щелчок по «Добавить» — в консоли тишина,
// а у поля подсказка браузера
```

Если такое поле пустое, браузер **не отправит форму**: покажет подсказку
у поля на языке браузера — «Заполните это поле» — и `submit` не наступит вовсе,
наш слушатель не вызовется. Похожие атрибуты есть для чисел, адресов почты, длины текста.

Встроенная проверка удобна, но не заменяет свою. Она не знает правил «Табеля»: что
оценки — цифры от 2 до 5, что имя не должно повторяться. Обычно их сочетают: простое —
атрибутами, остальное — кодом в `submit`. Подробно встроенную проверку
разбирает курс 4.

## 11. `reset`: вернуть как было {#reset}

Метод `form.reset()` возвращает все поля к значениям **по умолчанию** —
к тем, что записаны в разметке. То же делает кнопка `type="reset"`.

```js
form.elements.name.value = "Ильяс";
form.elements.present.checked = false;

form.reset();
form.elements.name.value;        // "" — в разметке значения не было
form.elements.present.checked;   // true — атрибут checked в разметке остался
form.elements.group.value;       // "JS-1"
```

Вот где пригождается разница атрибута и свойства из раздела 4: `reset`
восстанавливает то, что помнит **атрибут**. На форме при этом приходит
событие `reset`. После успешной отправки форму обычно очищают именно так —
одной строкой вместо обнуления каждого поля.

```js
form.addEventListener("reset", () => {
  message.textContent = "";   // вместе с полями убрать и сообщение
});
```

## 12. Разбор: оценка стала строкой {#numbers}

```js
const marksInput = form.elements.marks;   // набрали «5»

marksInput.value + 1;           // "51" — а ждали 6
Number(marksInput.value) + 1;   // 6
```

**Шаг 1.** Ответ — две цифры рядом. Это склейка строк (день 8), а не сложение.

**Шаг 2.** `value` — всегда строка (раздел 3). `"5" + 1`
склеивает.

**Шаг 3.** Число получают через `Number` при чтении — как с
`dataset` на дне 25. Но у `Number` есть свои сюрпризы для полей ввода:

```js
Number("");      // 0 — пустое поле стало нулём!
Number(" ");     // 0 — и поле из пробелов тоже
Number("5 ");    // 5 — пробелы по краям не мешают
Number("4,5");   // NaN — запятая не годится, нужна точка
Number("4.5");   // 4.5
```

Первые две строки опаснее всего: пустое поле не даст `NaN`, которое легко
заметить, а тихо превратится в оценку 0. Поэтому пустое поле проверяют **до**
перевода в число, отдельным условием. А запятую в дробях ставят по привычке — если поле
ждёт дробь, об этом стоит написать в подсказке `placeholder`.

### Несколько оценок в одном поле

В поле «Оценки» набирают несколько цифр через пробел: «5 4 9». Разбить строку по пробелам
умеет метод `split`, но это курс 2. У нас оценки однозначные, поэтому хватит
перебрать строку по символам — строки перебираются так с дня 11 — и выбросить пробелы:

```js
[..."5 4 9"].filter((ch) => ch !== " ");   // ["5", "4", "9"]
```

Получились строки, а не числа — и это то, что нужно. `makeReport` из дня 23
сама переводит каждую оценку в число и отбрасывает негодные: девятка не пройдёт
проверку, но будет учтена в проценте годных оценок.

А если человек поставит запятые — «5,4,5»? Запятые станут отдельными «оценками»:

```js
[..."5,4,5"].filter((ch) => ch !== " ");
// ["5", ",", "4", ",", "5"] — makeReport: средний 4.67, но годных только 60%

[..."5,4,5"].filter((ch) => ch !== " " && ch !== ",");
// ["5", "4", "5"] — годных 100%
```

Молча чинить такой ввод или сообщать об ошибке — решает программист. Главное —
заметить сам случай: проверка ввода начинается с вопроса «что ещё может набрать человек».
В «Табеле» оставим простой вариант и подскажем формат прямо в поле: «Оценки: 5 4 5».

### Вся форма — в один объект

Когда полей много, их удобно сразу собрать в объект — один на всю форму. С ним
дальше работает остальная программа, и его же можно сохранить или отправить как JSON
из дня 23:

```js
// заполнили: Ильяс, «5 4 9», флажок снят, JS-2
const data = {
  name: form.elements.name.value.trim(),
  marks: [...form.elements.marks.value].filter((ch) => ch !== " "),
  present: form.elements.present.checked,
  group: form.elements.group.value,
};

JSON.stringify(data);
// '{"name":"Ильяс","marks":["5","4","9"],"present":false,"group":"JS-2"}'
```

Это то же самое разделение, что «Табель» сделал на дне 23: форма отвечает за ввод,
объект — за данные, и дальше код работает только с объектом.

## 13. Живой поиск {#live}

Событие `input` позволяет странице отвечать на ходу. Добавим над списком
студентов из дня 24 поле поиска — и будем прятать тех, кто не подходит:

```html
<input id="search" placeholder="Поиск">
<p id="count"></p>
```

```js
const search = document.querySelector("#search");
const items = document.querySelectorAll("#list li");

search.addEventListener("input", () => {
  const query = search.value.trim().toLowerCase();
  items.forEach((li) => {
    li.hidden = !li.textContent.toLowerCase().includes(query);
  });
});
// «а» — Аман, Гүлнар, Сапар, Огулджан; «ман» — только Аман; «  МЕРЕТ» — Мерет
```

Можно показать и сколько нашлось. Абзац находим один раз, а две последние строки
ставим в конец того же слушателя:

```js
const count = document.querySelector("#count");   // абзац под полем поиска
const shown = [...items].filter((li) => !li.hidden).length;
count.textContent = `Найдено: ${shown}`;
```

Здесь сошлись три модуля. Строки из дня 16: `trim`, `toLowerCase`
и `includes` — поиск без учёта регистра и лишних пробелов. Поиск элементов
из дня 24 и `hidden` из дня 25. И `input` из сегодняшнего дня.
Пустой запрос показывает всех: пустую строку содержит любая строка.

## 14. `alert`, `confirm`, `prompt` {#dialogs}

У браузера есть три готовых окна-диалога. Все они **модальные**: пока окно
открыто, страница стоит, а код ждёт ответа.

<Scheme src="scheme-dialogs.svg">Три диалога браузера: сообщить, спросить «да или нет», спросить строку</Scheme>

```js
alert("Сохранено");               // undefined — окно с кнопкой OK
confirm("Удалить Мерет?");        // true — нажали OK, false — Отмена
prompt("Ваше имя?", "Гость");     // "Ильяс" — ввели; "" — OK с пустым полем; null — Отмена
```

У `prompt` три разных ответа, и различать их нужно по-разному: пустая строка —
человек согласился, но ничего не ввёл; `null` — отказался отвечать.
Второй аргумент — текст, который уже стоит в поле.

`confirm` почти всегда стоит прямо в условии:

```js
if (confirm("Очистить анкету?")) {
  form.reset();
}
```

А ответ `prompt` нужно проверить на `null` раньше всего остального,
иначе Отмена уронит программу:

```js
const answer = prompt("Как вас зовут?");
answer.trim();   // нажали Отмену: TypeError: Cannot read properties of null (reading 'trim')

const name = answer === null ? "" : answer.trim();   // так — безопасно
```

MDN советует пользоваться диалогами осторожно. Они останавливают всю страницу,
выглядят не как сайт, а как окно браузера, и браузер может вовсе их не показать —
например, если вкладка не активна. Поэтому:

| Диалог | Когда годится | Чем лучше заменить |
| --- | --- | --- |
| `alert` | быстрая проверка при отладке | сообщение на странице через `textContent` |
| `confirm` | подтверждение необратимого: удалить, стереть всё | для учебных проектов подходит как есть |
| `prompt` | почти никогда | поле в форме |

В «Табеле» `confirm` встанет перед удалением строки. Удаление не отменить,
а щелчок по кнопке «Удалить» легко сделать случайно — ровно тот случай, для которого
`confirm` и существует. Сообщения же об ошибках ввода «Табель» покажет на
странице, а не в `alert`.

## 15. «Табель» с формой {#tabel}

Теперь студента можно добавить без консоли. Над таблицей — форма, под ней — место
для сообщения об ошибке:

```html
<form id="add-form">
  <input name="student" placeholder="Имя">
  <input name="marks" placeholder="Оценки: 5 4 5">
  <button>Добавить</button>
</form>
<p id="form-error" class="error"></p>
```

```js
// без изменений: всё со дня 27 — расчёт, makeCells, классы, makeRow,
// addDeleteButton, updateSummary, слушатели tbody и Esc

// новое: оценки из строки «5 4 9» — по одной цифре, без пробелов
function parseMarks(text) {
  return [...text].filter((ch) => ch !== " ");
}

const form = document.querySelector("#add-form");
const error = document.querySelector("#form-error");

function fail(message, field) {
  error.textContent = message;
  field.focus();
}

form.addEventListener("submit", (event) => {
  event.preventDefault();                               // иначе страница перезагрузится
  const name = form.elements.student.value.trim();
  const marks = parseMarks(form.elements.marks.value);

  if (name === "") {
    fail("Введите имя", form.elements.student);
    return;
  }
  if (reports.some((r) => r.name === name)) {
    fail("Такой студент уже есть", form.elements.student);
    return;
  }
  if (marks.length === 0) {
    fail("Введите хотя бы одну оценку", form.elements.marks);
    return;
  }

  const report = makeReport({ name, marks });
  reports.push(report);
  tbody.append(addDeleteButton(makeRow(report)));
  updateSummary();

  error.textContent = "";
  form.reset();
  form.elements.student.focus();
});
```

Три проверки подряд делают одно и то же: пишут сообщение и ставят курсор в поле.
Это повторение вынесено в маленькую функцию `fail` — так же, как на дне 15
мы разбивали «Табель» на функции по смыслу. Каждая проверка стала короткой,
а сообщение и поле видны в одной строке.

И одна новая строка в слушателе `tbody` со дня 27 — подтверждение
перед удалением:

```js
tbody.addEventListener("click", (event) => {
  const row = event.target.closest("tr");
  if (event.target.closest(".delete")) {
    if (!confirm(`Удалить: ${row.dataset.name}?`)) return;   // новое
    const i = reports.findIndex((r) => r.name === row.dataset.name);
    reports.splice(i, 1);
    row.remove();
    updateSummary();
    return;
  }
  row.classList.toggle("selected");
});
```

через `findIndex`. Два Амана сломали бы удаление, поэтому форма их не пускает.
Проверка ввода защищает не только от ошибок человека, но и от ошибок в собственном коде.

А `makeReport` по-прежнему не менялась со дня 23. Форма — просто ещё один
источник данных, наравне со строкой JSON: расчёт не знает, откуда пришёл студент.

## 16. Частые ошибки и итоги модуля {#mistakes}

| Ошибка | Что увидите | Как правильно |
| --- | --- | --- |
| нет `preventDefault` в `submit` | страница перезагрузилась, данные в адресе | первой строкой слушателя |
| слушают `click` кнопки вместо `submit` | <Kbd>Enter</Kbd> не работает | `submit` на форме |
| `<button>` без `type` для другого дела | кнопка отправляет форму | `type="button"` |
| `value + 1` | `"51"` | `Number(value) + 1` |
| нет `trim` | имя из пробелов проходит проверку | `value.trim()` |
| `form.name`, `form.id` | вместо свойства формы — поле | `form.elements.…` |
| ждут `input` после записи из кода | событие не пришло | вызвать пересчёт самим |
| ошибка через `alert` | окно мешает, страница стоит | сообщение на странице |
| `prompt` без проверки `null` | ошибка при нажатии Отмены | проверить `null` первым |

<Selfcheck>
1. Почему `form.elements.marks.value + 1` дало `"51"`?
   <Answer>`value` всегда строка, и `+` со строкой склеивает.
   Нужно `Number(form.elements.marks.value) + 1`.</Answer>
2. Чем `input` отличается от `change` у текстового поля?
   <Answer>`input` приходит на каждое изменение, на каждую букву.
   `change` — один раз, когда человек ушёл из поля с изменённым значением.</Answer>
3. Почему отправку слушают на форме через `submit`, а не через
   `click` кнопки?
   <Answer>Форму отправляют и клавишей Enter в поле. `submit` приходит
   при любом способе отправки, а слушатель щелчка пропустил бы Enter.</Answer>
4. Что будет без `event.preventDefault()` в слушателе `submit`?
   <Answer>Браузер отправит данные и загрузит страницу заново: поля очистятся,
   всё сделанное кодом пропадёт, данные формы окажутся в адресе.</Answer>
5. Почему лучше `form.elements.name`, чем `form.name`?
   <Answer>Поля формы становятся и её свойствами. Поле с именем `name`
   перекрывает свойство формы `name` — и наоборот, путаница
   неизбежна. `elements` содержит только поля.</Answer>
6. Чем различаются ответы `prompt`: `""` и `null`?
   <Answer>`""` — нажали OK с пустым полем. `null` — нажали Отмену.</Answer>
</Selfcheck>
