# День 28. Формы

<Subtitle>Выжимка лекции: значения полей, события, отправка и проверка ввода.</Subtitle>

## Поля

```js
// form, nameInput, present, message — из app.js, как в лекции
// набрали «Ильяс»:
form.elements.name.value;        // "Ильяс" — всегда строка
form.elements.present.checked;   // true / false — флажок
form.elements.group.value;       // "JS-1" — выбранный переключатель группы
form.elements.name.value = "";   // записать из кода
```

<Remember>
`value` — всегда строка: `"5" + 1` даст `"51"`.
Число — `Number(value)`, но `Number("")` и `Number(" ")`
дают 0, поэтому пустое поле проверяют до перевода. Текст поля — `value`,
а не `textContent`: у поля он всегда пустой.
</Remember>

Поля находят через `form.elements` по атрибуту `name`. Короткое
`form.name` опасно: поле с именем `name` перекрывает свойство
формы. Атрибут `checked` в разметке — только состояние по умолчанию,
текущее — в свойстве.

## События полей

| Событие | Когда приходит | Для чего |
| --- | --- | --- |
| `input` | на каждое изменение, на каждую букву | ответить на ходу: счётчик, поиск |
| `change` | изменение принято: ушли из поля, щёлкнули флажок | итог: сохранить, пересчитать |
| `submit` | форму отправили: кнопкой или Enter | проверить и обработать всё сразу |
| `reset` | форму сбросили | убрать сообщения |

<KeyPoint>
Запись из кода (`value = …`, `checked = …`) событий не вызывает.
Нужно пересчитать — вызовите пересчёт сами.
</KeyPoint>

## Отправка и проверка

```js
form.addEventListener("submit", (event) => {
  event.preventDefault();                          // 1. иначе перезагрузка
  const name = form.elements.name.value.trim();    // 2. прочитать и очистить

  if (name === "") {                               // 3. одна причина за раз
    message.textContent = "Введите имя";
    form.elements.name.focus();
    return;
  }

  message.textContent = `Добавлен: ${name}`;       // 4. работа с данными
  form.reset();                                    //    и очистка формы
});
```

<Remember>
Слушают `submit` формы, а не `click` кнопки: форму отправляет и
Enter в поле. `<button>` без `type` внутри формы — кнопка
отправки; кнопкам для других дел пишут `type="button"`. Без
`preventDefault` страница перезагрузится, а данные уйдут в адрес:
`?name=…&marks=…`.
</Remember>

Атрибут `required` браузер проверит сам: с пустым полем форма не отправится,
и `submit` не придёт. Правила вроде «оценки от 2 до 5» проверяют кодом.
Ошибку показывают на странице и подсвечивают поле классом, а снимают подсветку в
слушателе `input` — как только человек начал исправлять.

## Два приёма

```js
// живой поиск на странице группы: прятать тех, кто не подходит, на каждую букву
const search = document.querySelector("#search");
const items = document.querySelectorAll("#list li");

search.addEventListener("input", () => {
  const query = search.value.trim().toLowerCase();
  items.forEach((li) => {
    li.hidden = !li.textContent.toLowerCase().includes(query);
  });
});
```

```js
// вся анкета — в один объект, дальше код работает только с ним
const data = {
  name: form.elements.name.value.trim(),
  present: form.elements.present.checked,
};
```

Несколько оценок в одном поле разбирают по символам: `[..."5 4 9"].filter((ch) => ch !== " ")`
даёт `["5", "4", "9"]`. Метод `split` для этого появится в курсе 2.

## Диалоги

```js
alert("Сохранено");        // undefined
confirm("Удалить?");       // true — OK, false — Отмена
prompt("Имя?", "Гость");   // строка; "" — пустой OK; null — Отмена
```

Диалоги останавливают страницу и выглядят как окно браузера. `confirm`
годится перед необратимым действием, ошибки ввода лучше показывать на странице.
Ответ `prompt` проверяют на `null` первым делом.
