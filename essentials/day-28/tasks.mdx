# День 28. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–5, 8 и 9 делаем на анкете из лекции (папка `day-28`): разметку и `app.js` возьмите из раздела 2 и добавьте в `<style>` правило `.invalid { outline: 2px solid #b91c1c; }`. Задание 6 — на странице группы из прошлых дней, задание 7 — в папке `day-28/tabel`.</Subtitle>

## Разминка

<Task title="1. Анкета" level="easy" time="6">
<Goal>научиться читать и писать значения полей.</Goal>

В консоли прочитайте через `form.elements` все значения анкеты: имя, оценки,
флажок, группу. Заполните поля руками, снимите флажок, выберите JS-2 — прочитайте снова.
Затем запишите в поле имени «Аман» из кода.

<Hint>
У флажка нужно `checked`, у группы переключателей —
`form.elements.group.value`.
</Hint>

<Criteria>
- записаны значения до и после ручного заполнения;
- записан `typeof` значения поля оценок, в которое набрано «5»;
- проверено, что после снятия флажка атрибут `checked` в разметке остался;
- выведено `form.name` — объяснено, что вернулось и почему.
</Criteria>
</Task>

<Task title="2. input и change" level="easy" time="7">
<Goal>увидеть, когда приходит каждое из двух событий.</Goal>

Повесьте на поле имени и на флажок оба слушателя: `input` и `change`.
Каждый пишет в консоль имя события и текущее значение. Наберите имя, уйдите из поля
клавишей <Kbd>Tab</Kbd>, щёлкните флажок. Потом смените значения из кода.

<Hint>
Значение в консоль удобно выводить через `JSON.stringify` — тогда видно
и пустую строку, и пробелы.
</Hint>

<Criteria>
- записано, сколько раз пришёл `input` и сколько `change`
  при наборе пятибуквенного имени;
- записан порядок событий при щелчке по флажку;
- проверено, что запись из кода не вызвала ни одного события;
- объяснено, какое событие взять для живого поиска, а какое — для сохранения выбора.
</Criteria>
</Task>

<Task title="3. Счётчик букв" level="easy" time="7">
<Goal>отвечать на ввод на ходу.</Goal>

Под полем имени показывайте «Букв: N». Если букв больше 20, дописывайте
«— слишком длинно» и подсвечивайте поле классом `invalid`; как только
букв снова 20 или меньше — подсветку снимайте.

<Example>
```js
// набрали «Огулджан Ильясовна Бер»:
// Букв: 22 — слишком длинно, у поля класс invalid
```
</Example>

<Hint>
Одна строка управляет классом в обе стороны: `toggle` со вторым
аргументом из дня 25.
</Hint>

<Criteria>
- счётчик меняется на каждую букву и на каждое стирание;
- подсветка появляется на 21-й букве и исчезает, когда стёрли лишнее;
- записано, считаются ли пробелы, и решено, нужно ли их считать;
- имя вписано из кода — объяснено, почему счётчик не обновился.
</Criteria>
</Task>

## Основные задания

<Task title="4. Отправка без перезагрузки" level="medium" time="12">
<Goal>перехватить отправку формы и разобраться, что делает браузер без нас.</Goal>

По отправке анкеты пишите на странице «Добавлен: имя» и очищайте форму. Проверьте
отправку щелчком и клавишей <Kbd>Enter</Kbd> в поле. Потом временно
уберите `preventDefault` и посмотрите на адрес страницы.

<Hint>
Слушайте `submit` формы, а не `click` кнопки. После отправки
форму очищает одна строка — `form.reset()`.
</Hint>

<Criteria>
- обе отправки — щелчком и Enter — дают сообщение и не перезагружают страницу;
- без `preventDefault` записан адрес, который получила страница, и объяснено,
  откуда в нём каждая часть;
- в форму добавлена кнопка «Подсказка» — объяснено, почему она отправляет форму,
  и исправлено атрибутом;
- вместе с формой сбрасывается и сообщение — через событие `reset`.
</Criteria>
</Task>

<Task title="5. Проверка ввода" level="medium" time="13">
<Goal>проверять данные по одной причине за раз и понятно сообщать об ошибке.</Goal>

Перед «Добавлен» проверяйте по порядку: имя не пустое; в имени хотя бы 2 буквы;
оценки введены; каждая оценка — цифра от 2 до 5. Сообщение об ошибке — на странице,
поле с ошибкой подсвечено и получает фокус.

<Example>
```js
// пусто                  → Введите имя
// «И»                    → Имя слишком короткое
// «Ильяс», без оценок    → Введите оценки
// «Ильяс», «5 7»         → Оценки — цифры от 2 до 5
// «Ильяс», «5 4»         → Добавлен: Ильяс
```
</Example>

<Hint>
Оценки — символы строки без пробелов, как в лекции. Проверка «каждая» — это
`every` из дня 20. Каждую ошибку удобно вернуть строкой из отдельной
функции `check()`, а пустая строка значит «всё хорошо».
</Hint>

<Criteria>
- все пять строк примера дают указанный ответ;
- подсветка снимается, как только человек начинает исправлять поле;
- имя из одних пробелов считается пустым;
- объяснено, почему проверки идут по одной и почему именно в таком порядке.
</Criteria>
</Task>

<Task title="6. Живой поиск" level="medium" time="12">
<Goal>отвечать на ввод, пряча и показывая элементы.</Goal>

На странице группы добавьте над списком поле поиска и абзац под ним. По каждой
букве прячьте студентов, в чьём имени нет набранного, и пишите «Найдено: N».
Если не нашлось никого — «Никого не нашли».

<Hint>
`trim`, `toLowerCase` и `includes` из дня 16 делают
поиск нечувствительным к регистру и пробелам; прятать — свойством `hidden`
из дня 25.
</Hint>

<Criteria>
- «а» оставляет четверых, «ман» — одного, «&nbsp;&nbsp;МЕРЕТ» — Мерет;
- пустое поле снова показывает всех;
- при нуле найденных появляется «Никого не нашли»;
- объяснено, почему здесь `input`, а не `change`.
</Criteria>
</Task>

<Task title="7. «Табель» с формой" level="medium" time="13">
<Goal>добавлять студентов через форму с проверкой.</Goal>

Скопируйте `day-27/tabel` в `day-28/tabel` и добавьте:

- над таблицей форму: имя, оценки через пробел, кнопка «Добавить»;
- проверки: пустое имя, повтор имени, нет оценок — сообщение на странице и фокус в поле;
- новую строку через `makeReport`, `makeRow` и `addDeleteButton`,
  итог пересчитан, форма очищена;
- `confirm` перед удалением строки.

<Criteria>
- «Ильяс», «5 4 9» дают зелёную строку 4.50, 4, 5, 67% и итог «3 из 6»;
- «&nbsp;&nbsp;Аман&nbsp;» не добавляется: «Такой студент уже есть»;
- при Отмене в `confirm` строка остаётся;
- `makeReport` не изменилась ни в одной строке;
- объяснено, почему проверка повтора защищает удаление со дня 27.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Форма туда и обратно" level="hard" time="10">
<Goal>собрать форму в объект и восстановить её из объекта.</Goal>

Напишите `readForm(form)`, которая возвращает объект со всеми значениями
анкеты, и `fillForm(form, data)`, которая раскладывает такой объект обратно
по полям. Проверьте круг: заполнить → записать строкой JSON → `reset` →
разобрать строку → `fillForm`.

<Example>
```js
const saved = JSON.stringify(readForm(form));
// '{"name":"Ильяс","marks":"5 4 5","present":false,"group":"JS-2"}'
form.reset();
fillForm(form, JSON.parse(saved));   // поля снова как были, включая JS-2
```
</Example>

<Hint>
Значение группы переключателей можно не только читать, но и записывать:
`form.elements.group.value = "JS-2"` отметит нужный переключатель.
</Hint>

<Criteria>
- после круга `JSON.stringify(readForm(form)) === saved` — `true`;
- флажок и переключатель восстановились;
- записано, какие события пришли во время `fillForm`, и объяснено почему;
- объяснено, где этот круг пригодится на дне 31, когда появится хранилище браузера.
</Criteria>
</Task>

<Task title="9. Шесть подвохов" level="hard" time="10">
<Goal>собрать вместе всё, что сегодня ведёт себя неожиданно.</Goal>

В поле оценок набрано «5», в окне `prompt` нажмут «Отмена».

```js
form.elements.name.addEventListener("input", () => console.log("input!"));

console.log(form.elements.marks.value + 1);                    // 1
console.log(form.name);                                        // 2
form.elements.name.value = "Аман";                             // 3
console.log(form.elements.name.textContent);                   // 4
console.log(Number(form.elements.marks.value) + Number(""));   // 5
console.log(prompt("Имя?").trim());                            // 6
```

<Hint>
Третья строка ничего не печатает сама — вопрос в том, напечатает ли что-то слушатель.
Падает только шестая. В пятой одно из слагаемых неожиданно оказывается нулём.
</Hint>

<Criteria>
- предсказания записаны до запуска;
- для шестой записан точный текст ошибки;
- для каждой из первых пяти объяснено, откуда взялся ответ;
- все шесть переписаны так, чтобы делать то, что, видимо, хотел автор.
</Criteria>
</Task>
