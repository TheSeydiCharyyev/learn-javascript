1. Проект вместо новой темы

Сегодня новых методов не будет. Пять дней модуля дали всё, чтобы собрать настоящее маленькое приложение, — и сегодня мы его соберём: список дел. Добавить дело, отметить сделанным, удалить, показать только нужные.

Список дел — классическое учебное приложение, и не случайно. В нём есть всё, из чего состоят большие программы: данные, их показ, ввод человека, проверка ввода и реакция на действия. Разберётесь, как устроен список дел, — поймёте, как устроены почта, магазин и чат.

Лекция идёт так, как стоит работать над любым проектом: сначала задание, потом данные, потом разметка, потом код — по одной возможности за раз. В конце — вся программа целиком и ошибки, которые почти наверняка встретятся в заданиях.

3. Сначала данные

Главное решение проекта принимают раньше разметки: как хранить данные. Дело — это текст и отметка «сделано». Значит, объект, а все дела — массив объектов:

let tasks = [
  { id: 1, text: "Повторить день 26", done: true },
  { id: 2, text: "Сделать задания дня 28", done: false },
  { id: 3, text: "Прочитать про события на MDN", done: false },
];
let nextId = 4;
let filter = "all";

Зачем каждому делу id, если есть текст? «Табель» на дне 27 удалял студента по имени и поэтому на дне 28 не пускал двух одинаковых. Дела же могут повторяться: «Купить хлеб» можно записать и дважды. id — номер, который дело получает один раз и не теряет никогда. Счётчик nextId хранит следующий свободный номер.

Третья переменная, filter, — тоже данные, хотя и не о делах: что сейчас показывать. "all", "active" или "done". Всё, что влияет на вид страницы, хранится в переменных, а не «на странице».

Все три объявлены через let: их будут менять. tasks при удалении заменяется новым массивом целиком (раздел 11), и с const это сломалось бы — об этом разбор в разделе 14.

Проверка шага. Положите в app.js пока только эти три переменные, откройте страницу и спросите консоль. На странице ещё пусто, но данные уже живут:

tasks.length;                          // 3
tasks[0].done;                         // true
tasks.filter((t) => !t.done).length;   // 2 — столько дел осталось

Так будем проверять каждый шаг: написали кусок — спросили консоль — пошли дальше. Ошибку, пойманную сразу, найти легко: она в последних нескольких строках.

4. Разметка

Разметка — пустая рама: в ней нет ни одного дела. Дела появятся кодом из данных.

<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Список дел</title>
  <style>
    .done span { text-decoration: line-through; color: gray; }
    .filters .active { font-weight: bold; }
    .error { color: #b91c1c; }
  </style>
  <script src="app.js" defer></script>
</head>
<body>
  <h1>Список дел</h1>
  <form id="new-task">
    <input name="text" placeholder="Что нужно сделать?">
    <button>Добавить</button>
  </form>
  <p id="error" class="error"></p>
  <p class="filters">
    <button data-filter="all">Все</button>
    <button data-filter="active">Активные</button>
    <button data-filter="done">Сделанные</button>
  </p>
  <ul id="tasks"></ul>
  <p>
    <span id="counter"></span>
    <button id="clear-done">Удалить сделанные</button>
  </p>
</body>
</html>

Всё знакомо. Кнопка «Добавить» внутри формы отправляет её (день 28). Кнопки-фильтры стоят вне формы, поэтому ничего не отправляют, а какой у каждой фильтр, хранит data-filter (день 25). Оформление — классами: сделанное дело зачёркнуто через класс done, выбранный фильтр выделен классом active. В коде не будет ни одного цвета.

В начале app.js элементы находятся один раз и кладутся в переменные — дальше код обращается к ним по именам:

const form = document.querySelector("#new-task");
const error = document.querySelector("#error");
const list = document.querySelector("#tasks");
const counter = document.querySelector("#counter");
const clearDone = document.querySelector("#clear-done");
const filters = document.querySelector(".filters");

Проверка шага: элементы нашлись, а список пуст — дел на странице никто ещё не создал.

filters.children.length;   // 3 — три кнопки-фильтра
list.children.length;      // 0

Если вместо числа пришла ошибка TypeError: Cannot read properties of null, значит, querySelector ничего не нашёл и вернул null. Сверьте селектор с разметкой: #tasks — это id, .filters — класс.

5. Главная схема

Вот идея, на которой держится вся программа, — и любая программа с интерфейсом:

Страница — картинка данных, и ничего больше. Слушатель никогда не трогает список на странице напрямую: он меняет массив tasks и зовёт render(), а та строит список заново. Правило из «Табеля» — «считаем в данных, форматируем в конце» — здесь стало правилом всей программы.

Почему так, а не «добавил дело — добавил пункт на страницу»? Потому что одно действие меняет сразу несколько мест: список, счётчик, кнопку «Удалить сделанные». Если каждый слушатель чинит эти места сам, рано или поздно один из них что-то забудет, и страница разойдётся с данными. Когда страницу строит одна функция, разойтись им негде.

6. Одно дело — один пункт

Сначала — функция, которая делает из одного объекта один пункт списка. Это makeItem из дня 26, только внутри теперь флажок, текст и кнопка:

function makeItem(task) {
  const li = document.createElement("li");
  const box = document.createElement("input");
  const text = document.createElement("span");
  const del = document.createElement("button");

  box.type = "checkbox";
  box.checked = task.done;
  text.textContent = task.text;       // данные — только текстом (день 25)
  del.textContent = "✕";
  del.classList.add("delete");

  li.append(box, " ", text, " ", del);   // строки " " — пробелы между частями
  li.dataset.id = task.id;               // пункт запоминает номер своего дела
  li.classList.toggle("done", task.done);
  return li;
}

Три строки здесь стоит отметить отдельно. box.type = "checkbox" делает поле флажком — свойство type из дня 28 работает и на запись. li.dataset.id = task.id — ниточка от пункта к данным: по ней слушатели найдут дело (раздел 9). А toggle со вторым аргументом ставит или снимает класс done одной строкой, смотря что в данных.

Функция ничего не вставляет на страницу — только создаёт и возвращает пункт. Так её легко проверить в консоли:

makeItem({ id: 7, text: "Проверка", done: false }).outerHTML;
// '<li data-id="7"><input type="checkbox"> <span>Проверка</span> <button class="delete">✕</button></li>'

У несделанного дела атрибута class нет вовсе: toggle с false ничего не добавил. А вот настоящее дело из данных, сделанное:

const item = makeItem(tasks[0]);
item.className;                        // "done"
item.dataset.id;                       // "1" — число 1 стало строкой
item.querySelector("input").checked;   // true

Запомните кавычки у "1": всё, что записано в dataset, лежит в разметке строкой. Через три раздела это станет важным.

7. render: страница из данных

function isVisible(task) {
  if (filter === "active") return !task.done;
  if (filter === "done") return task.done;
  return true;
}

function render() {
  list.textContent = "";                                   // 1. убрать старое
  list.append(...tasks.filter(isVisible).map(makeItem));   // 2. построить видимые

  const left = tasks.filter((t) => !t.done).length;       // 3. счётчик
  counter.textContent = `Осталось: ${left} из ${tasks.length}`;
  clearDone.hidden = tasks.every((t) => !t.done);          // 4. кнопка — если есть что удалять

  filters.querySelectorAll("button").forEach((b) => {      // 5. выделить текущий фильтр
    b.classList.toggle("active", b.dataset.filter === filter);
  });
}

render();   // первый показ при загрузке

render — сердце программы, и она целиком из знакомых кусков. «Перерисовать — значит очистить и вставить заново» — это renderList из дня 26. filter отбирает дела по текущему фильтру, map делает из каждого пункт, три точки раскладывают массив в append. Счётчик и кнопка считаются по всем делам, а не по видимым: «Осталось: 2 из 3» не зависит от фильтра.

every из дня 20 отвечает на вопрос «правда ли, что ни одно дело не сделано». Если да — кнопку «Удалить сделанные» прячем через hidden (день 25). У пустого массива every отвечает true, так что и для пустого списка кнопка спрятана.

Проверка шага — и главный опыт дня. Сначала убедимся, что показ совпадает с данными:

list.children.length;   // 3
counter.textContent;    // "Осталось: 2 из 3"
clearDone.hidden;       // false — одно дело сделано, кнопка видна

Теперь поменяем данные руками, прямо в консоли, и позовём render. Ни одного слушателя ещё нет, а страница уже умеет всё показать:

tasks[1].done = true;
render();
counter.textContent;          // "Осталось: 1 из 3"
list.children[1].className;   // "done" — второй пункт зачёркнут

Обновите страницу, чтобы вернуть исходные данные, и переключите фильтр тем же способом:

filter = "active";
render();
list.children.length;                     // 2
list.querySelector("span").textContent;   // "Сделать задания дня 28"

Вот что значит «страница — картинка данных». Слушатели, которые мы напишем дальше, будут делать ровно это: менять данные и звать render(). Осталось научить их понимать, что нажал человек.

8. Добавить дело

form.addEventListener("submit", (event) => {
  event.preventDefault();
  const text = form.elements.text.value.trim();

  if (text === "") {
    error.textContent = "Напишите, что нужно сделать";
    form.elements.text.focus();
    return;
  }
  if (text.length > 60) {
    error.textContent = "Слишком длинно: не больше 60 знаков";
    form.elements.text.focus();
    return;
  }

  tasks.push({ id: nextId, text, done: false });   // 1. изменить данные
  nextId++;
  error.textContent = "";
  form.reset();
  render();                                        // 2. перерисовать
});

Это слушатель submit из дня 28 почти без изменений: preventDefault, trim, проверки по одной, сообщение и фокус. Новое — две строки в середине: дело добавляется в данные, и счётчик номеров сдвигается. На страницу дело попадёт само — через render().

Запись { id: nextId, text, done: false } использует короткую форму из дня 21: text вместо text: text. После добавления в консоли видно, что изменились именно данные:

// добавили через форму «Купить тетрадь»:
tasks.length;             // 4
tasks.at(-1);             // {id: 4, text: 'Купить тетрадь', done: false}
nextId;                   // 5

9. От элемента к данным

Щёлкнули по флажку или по «✕» — слушатель получает элемент. А менять нужно объект в массиве. Мост между ними — data-id, который makeItem записала в каждый пункт:

function taskOf(element) {
  const id = Number(element.closest("li").dataset.id);
  return tasks.find((t) => t.id === id);
}

Четыре шага в двух строках. closest("li") поднимается от флажка или кнопки к пункту — день 24 и день 27. dataset.id — номер строкой: всё, что читается со страницы, строки (день 25). Number превращает строку в число, а find из дня 20 находит в массиве дело с этим номером.

const li = document.querySelector('li[data-id="2"]');

li.dataset.id;          // "2" — строка
taskOf(li).text;        // "Сделать задания дня 28"

Функция нужна двум слушателям — отметке и удалению, поэтому вынесена отдельно. Вернёт она тот же объект, что лежит в массиве, а не копию: изменить его свойство — значит изменить данные.

Почему без Number никак, видно в консоли:

"2" === 2;                            // false — строгое сравнение, день 7
tasks.find((t) => t.id === "2");      // undefined — такого дела нет
tasks.find((t) => t.id === 2).text;   // "Сделать задания дня 28"

10. Отметить сделанным

list.addEventListener("change", (event) => {
  if (!event.target.matches('input[type="checkbox"]')) return;
  taskOf(event.target).done = event.target.checked;
  render();
});

Слушатель один на весь список — делегирование из дня 27. Событие change всплывает, поэтому щелчок по любому флажку доходит до ul. Первая строка проверяет через matches (день 24), что изменился именно флажок: в пункте могут появиться и другие поля, например поле правки из задания со звёздочкой.

Флажок уже отметился сам, браузер это сделал. Наша задача — перенести его состояние в данные: done становится равным checked. Потом render() перестраивает список: пункт получает класс done и зачёркивается, счётчик уменьшается. Перерисовка нужна, даже когда видимый флажок уже стоит правильно: при фильтре «Активные» отмеченное дело должно исчезнуть из списка.

Проверка шага: щёлкните флажок у «Сделать задания дня 28» и спросите консоль.

tasks.find((t) => t.id === 2).done;   // true — отметка дошла до данных
counter.textContent;                  // "Осталось: 1 из 3"

11. Удалить

list.addEventListener("click", (event) => {
  if (!event.target.closest(".delete")) return;
  const task = taskOf(event.target);
  tasks = tasks.filter((t) => t !== task);
  render();
});

Удалить дело из данных — значит оставить все, кроме него. Это filter: новый массив без одного элемента. Поэтому tasks объявлен через let — переменной присваивается новый массив.

Сравнение t !== task сравнивает объекты — «та ли это коробка», день 21. Работает потому, что taskOf вернула тот самый объект из массива. Можно было бы сравнить и номера: t.id !== task.id.

Проверка шага: «✕» у «Повторить день 26».

tasks.map((t) => t.id);   // [2, 3]
list.children.length;     // 2

А почему не splice, как в «Табеле» на дне 27? Можно и так: найти позицию через findIndex и вырезать. Проверим в консоли на исходной странице:

const i = tasks.findIndex((t) => t.id === 2);
tasks.splice(i, 1);        // вырезает из того же массива
render();
tasks.map((t) => t.id);    // [1, 3]
list.children.length;      // 2

Работает, и так подошёл бы даже const: splice меняет тот же массив, а не присваивает переменной новый. Мы всё же взяли filter: он короче, и в нём нет позиции, с которой можно ошибиться, — а ошибиться очень легко, как покажет раздел 13.

12. Фильтры, очистка, Esc

Три оставшиеся возможности — по нескольку строк каждая. Фильтр меняет только переменную filter, а что показывать, решает isVisible внутри render:

filters.addEventListener("click", (event) => {
  const button = event.target.closest("button");
  if (!button) return;
  filter = button.dataset.filter;   // "all", "active" или "done" — из data-filter
  render();
});

Кнопка делает то же, что мы делали руками в разделе 7. Третий фильтр проверим тем же способом, на исходной странице:

filter = "done";
render();
list.children.length;                      // 1
list.querySelector("span").textContent;    // "Повторить день 26"
filters.querySelector(".active").textContent;   // "Сделанные" — выделена нужная кнопка

«Удалить сделанные» — тот же filter массива, что и одиночное удаление, только условие другое:

clearDone.addEventListener("click", () => {
  tasks = tasks.filter((t) => !t.done);
  render();
});

И Esc в поле ввода — слушатель keydown из дня 27 на самом поле: у поля есть фокус, значит, клавиши приходят ему.

form.elements.text.addEventListener("keydown", (event) => {
  if (event.key === "Escape") {
    form.reset();
    error.textContent = "";
  }
});

Обратите внимание, как мало кода нужно на каждую новую возможность. Слушатель меняет данные в одну строку и зовёт render — вся остальная работа уже сделана. Это главная выгода схемы из раздела 5: новые возможности добавлять дёшево.

Пять слушателей из шести устроены одинаково, и у них общий скелет. Шестой, на Esc, данных не касается: он чистит только поле, и render ему не нужен.

// скелет слушателя этой программы — шаблон, а не код для запуска
element.addEventListener("событие", (event) => {
  // 1. понять, что случилось: matches, closest, taskOf, проверка ввода
  // 2. изменить данные: tasks, filter или nextId
  render();   // 3. перерисовать — последней строкой
});

13. Разбор: удалилось не то

Частая первая версия удаления запоминает в пункте не id, а номер позиции — второй аргумент map:

// так НЕ надо
function makeItem(task, i) {

Шаг 1. Что удалилось? Не то, что нажали, а соседнее. Значит, номер указал не туда.

Шаг 2. Откуда номер? map нумеровал пункты видимого списка, а splice удаляет по номеру всего массива. В видимом списке «Прочитать…» — номер 1, а в массиве под номером 1 лежит «Сделать задания дня 28»: скрытое сделанное дело сдвинуло нумерацию. Консоль показывает это прямо — даже на исправной программе, при фильтре «Активные»:

tasks[1].text;                     // "Сделать задания дня 28" — второй в массиве

Шаг 3. Чиним. Позиция меняется от фильтра, удаления, сортировки. id — никогда. Поэтому связь «пункт — дело» строят только через постоянный номер, как в разделе 9.

15. Программа целиком

Соберём app.js в одном месте. Порядок частей — тот же, в котором мы их писали: данные, элементы, показ, действия, первый показ.

// 1. Данные — главное в программе. Страница только показывает их.
let tasks = [
  { id: 1, text: "Повторить день 26", done: true },
  { id: 2, text: "Сделать задания дня 28", done: false },
  { id: 3, text: "Прочитать про события на MDN", done: false },
];
let nextId = 4;
let filter = "all";

// 2. Элементы страницы — находим один раз
const form = document.querySelector("#new-task");
const error = document.querySelector("#error");
const list = document.querySelector("#tasks");
const counter = document.querySelector("#counter");
const clearDone = document.querySelector("#clear-done");
const filters = document.querySelector(".filters");

// 3. Показ: из данных — в элементы
function makeItem(task) {
  const li = document.createElement("li");
  const box = document.createElement("input");
  const text = document.createElement("span");
  const del = document.createElement("button");

  box.type = "checkbox";
  box.checked = task.done;
  text.textContent = task.text;
  del.textContent = "✕";
  del.classList.add("delete");

  li.append(box, " ", text, " ", del);
  li.dataset.id = task.id;
  li.classList.toggle("done", task.done);
  return li;
}

function isVisible(task) {
  if (filter === "active") return !task.done;
  if (filter === "done") return task.done;
  return true;
}

function render() {
  list.textContent = "";
  list.append(...tasks.filter(isVisible).map(makeItem));

  const left = tasks.filter((t) => !t.done).length;
  counter.textContent = `Осталось: ${left} из ${tasks.length}`;
  clearDone.hidden = tasks.every((t) => !t.done);

  filters.querySelectorAll("button").forEach((b) => {
    b.classList.toggle("active", b.dataset.filter === filter);
  });
}

// 4. Действия: меняют данные и зовут render()
form.addEventListener("submit", (event) => {
  event.preventDefault();
  const text = form.elements.text.value.trim();

  if (text === "") {
    error.textContent = "Напишите, что нужно сделать";
    form.elements.text.focus();
    return;
  }
  if (text.length > 60) {
    error.textContent = "Слишком длинно: не больше 60 знаков";
    form.elements.text.focus();
    return;
  }

  tasks.push({ id: nextId, text, done: false });
  nextId++;
  error.textContent = "";
  form.reset();
  render();
});

function taskOf(element) {
  const id = Number(element.closest("li").dataset.id);
  return tasks.find((t) => t.id === id);
}

list.addEventListener("change", (event) => {
  if (!event.target.matches('input[type="checkbox"]')) return;
  taskOf(event.target).done = event.target.checked;
  render();
});

list.addEventListener("click", (event) => {
  if (!event.target.closest(".delete")) return;
  const task = taskOf(event.target);
  tasks = tasks.filter((t) => t !== task);
  render();
});

filters.addEventListener("click", (event) => {
  const button = event.target.closest("button");
  if (!button) return;
  filter = button.dataset.filter;
  render();
});

clearDone.addEventListener("click", () => {
  tasks = tasks.filter((t) => !t.done);
  render();
});

form.elements.text.addEventListener("keydown", (event) => {
  if (event.key === "Escape") {
    form.reset();
    error.textContent = "";
  }
});

// 5. Первый показ
render();

16. Что дальше

У списка дел есть очевидный недостаток: обновили страницу — всё пропало, вернулись три исходных дела. Данные живут в переменных, а переменные исчезают вместе со страницей. Это починим на дне 31: localStorage сохранит массив строкой JSON (день 23), и при загрузке мы его прочитаем. Благодаря схеме из раздела 5 правка будет крошечной: сохранить данные в конце render, прочитать в начале программы.

localStorage.setItem("tasks", JSON.stringify(tasks));   // день 31: последняя строка render
tasks = JSON.parse(localStorage.getItem("tasks"));      // день 31: начало программы

Две строки — но с двумя подвохами, которые разберём на дне 31. При самом первом запуске сохранённого ещё нет, и вместо массива придёт null. А счётчик nextId тоже придётся восстанавливать — иначе новое дело получит номер, который уже занят.

Завтра, на дне 30, — таймеры и промисы: как сделать что-то не сейчас, а через секунду, и как ждать того, что приходит не сразу. Это подготовка к дню 31, когда данные начнут приходить из сети.

// ОДИН ОБЪЕКТ → ОДИН ЭЛЕМЕНТ
function makeItem(task) {
  const li = document.createElement("li");
  // … части, textContent для данных
  li.dataset.id = task.id;               // ниточка к данным

function render() {
  list.textContent = "";

  1. Почему слушатели меняют данные и зовут render, а не правят страницу сами?
    Ответ Одно действие меняет несколько мест страницы: список, счётчик, кнопки. Если их строит одна функция из данных, страница не может разойтись с данными. И новые возможности добавлять проще.
  2. Зачем делу id, если есть текст и позиция в массиве?
    Ответ Текст может повторяться, а позиция меняется от фильтра, удаления, сортировки. id дело получает один раз и не теряет — по нему пункт надёжно находит своё дело.
  3. Почему в taskOf нужен Number?
    Ответ dataset.id — строка, а в данных id число. "2" === 2 ложно, и find вернул бы undefined.
  4. Почему tasks объявлен через let?
    Ответ При удалении переменной присваивается новый массив из filter. С const это ошибка Assignment to constant variable.
  5. Счётчик «Осталось» считается по всем делам или по видимым? Почему?
    Ответ По всем: сколько осталось сделать, не зависит от того, какой фильтр выбран. Видимые нужны только для списка.
  6. Дело добавилось в tasks, а на странице его нет. Что проверить первым?
    Ответ Вызов render() в конце слушателя: данные верны, значит, страницу забыли перестроить.
