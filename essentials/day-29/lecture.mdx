## 1. Проект вместо новой темы {#why}

Сегодня новых методов не будет. Пять дней модуля дали всё, чтобы собрать настоящее
маленькое приложение, — и сегодня мы его соберём: **список дел**. Добавить
дело, отметить сделанным, удалить, показать только нужные.

Список дел — классическое учебное приложение, и не случайно. В нём есть всё, из чего
состоят большие программы: данные, их показ, ввод человека, проверка ввода и реакция
на действия. Разберётесь, как устроен список дел, — поймёте, как устроены почта,
магазин и чат.

| Что понадобится | Откуда |
| --- | --- |
| массив объектов, `filter`, `find`, `every` | дни 19–21 |
| `querySelector`, `closest`, `matches` | день 24 |
| `textContent`, `classList`, `dataset`, `hidden` | день 25 |
| `createElement`, `append` | день 26 |
| слушатели, делегирование | день 27 |
| форма, `submit`, `checked`, `change` | день 28 |

Лекция идёт так, как стоит работать над любым проектом: сначала задание, потом
данные, потом разметка, потом код — по одной возможности за раз. В конце — вся
программа целиком и ошибки, которые почти наверняка встретятся в заданиях.

## 2. Что должен уметь список {#spec}

Прежде чем писать код, записывают, что программа должна делать. Коротко и так, чтобы
каждый пункт можно было проверить:

| № | Возможность | Как проверить |
| --- | --- | --- |
| 1 | показать список дел | при загрузке видно три дела |
| 2 | добавить дело через форму | набрали, нажали Enter — дело в конце списка |
| 3 | не пускать пустое и слишком длинное | сообщение под формой, курсор в поле |
| 4 | отметить сделанным и снять отметку | флажок, текст зачёркнут |
| 5 | удалить дело | кнопка «✕» у каждого дела |
| 6 | показать все, активные или сделанные | три кнопки-фильтра |
| 7 | счётчик «Осталось: N из M» | меняется после каждого действия |
| 8 | удалить все сделанные разом | кнопка видна, только когда есть что удалять |
| 9 | Esc очищает поле ввода | набрали, нажали Esc — поле пустое |

Так же важно записать, чего программа **не** делает. Сохранения нет:
обновили страницу — список вернулся к исходным трём делам. Сохранять научимся на дне 31.
Правки текста дела тоже нет — это задание со звёздочкой.

## 3. Сначала данные {#data}

Главное решение проекта принимают раньше разметки: **как хранить данные**.
Дело — это текст и отметка «сделано». Значит, объект, а все дела — массив объектов:

```js
let tasks = [
  { id: 1, text: "Повторить день 26", done: true },
  { id: 2, text: "Сделать задания дня 28", done: false },
  { id: 3, text: "Прочитать про события на MDN", done: false },
];
let nextId = 4;
let filter = "all";
```

Зачем каждому делу `id`, если есть текст? «Табель» на дне 27 удалял студента
по имени и поэтому на дне 28 не пускал двух одинаковых. Дела же могут повторяться:
«Купить хлеб» можно записать и дважды. `id` — номер, который дело получает один раз
и не теряет никогда. Счётчик `nextId` хранит следующий свободный номер.

Третья переменная, `filter`, — тоже данные, хотя и не о делах: что сейчас
показывать. `"all"`, `"active"` или `"done"`. Всё, что
влияет на вид страницы, хранится в переменных, а не «на странице».

Все три объявлены через `let`: их будут менять. `tasks` при удалении
заменяется новым массивом целиком (раздел 11), и с `const` это сломалось бы —
об этом разбор в разделе 14.

Проверка шага. Положите в `app.js` пока только эти три переменные, откройте
страницу и спросите консоль. На странице ещё пусто, но данные уже живут:

```js
tasks.length;                          // 3
tasks[0].done;                         // true
tasks.filter((t) => !t.done).length;   // 2 — столько дел осталось
```

Так будем проверять каждый шаг: написали кусок — спросили консоль — пошли дальше.
Ошибку, пойманную сразу, найти легко: она в последних нескольких строках.

## 4. Разметка {#markup}

Разметка — пустая рама: в ней нет ни одного дела. Дела появятся кодом из данных.

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Список дел</title>
  <style>
    .done span { text-decoration: line-through; color: gray; }
    .filters .active { font-weight: bold; }
    .error { color: #b91c1c; }
  </style>
  <script src="app.js" defer></script>
</head>
<body>
  <h1>Список дел</h1>
  <form id="new-task">
    <input name="text" placeholder="Что нужно сделать?">
    <button>Добавить</button>
  </form>
  <p id="error" class="error"></p>
  <p class="filters">
    <button data-filter="all">Все</button>
    <button data-filter="active">Активные</button>
    <button data-filter="done">Сделанные</button>
  </p>
  <ul id="tasks"></ul>
  <p>
    <span id="counter"></span>
    <button id="clear-done">Удалить сделанные</button>
  </p>
</body>
</html>
```

Всё знакомо. Кнопка «Добавить» внутри формы отправляет её (день 28). Кнопки-фильтры
стоят вне формы, поэтому ничего не отправляют, а какой у каждой фильтр, хранит
`data-filter` (день 25). Оформление — классами: сделанное дело зачёркнуто
через класс `done`, выбранный фильтр выделен классом `active`.
В коде не будет ни одного цвета.

В начале `app.js` элементы находятся один раз и кладутся в переменные —
дальше код обращается к ним по именам:

```js
const form = document.querySelector("#new-task");
const error = document.querySelector("#error");
const list = document.querySelector("#tasks");
const counter = document.querySelector("#counter");
const clearDone = document.querySelector("#clear-done");
const filters = document.querySelector(".filters");
```

Проверка шага: элементы нашлись, а список пуст — дел на странице никто ещё не создал.

```js
filters.children.length;   // 3 — три кнопки-фильтра
list.children.length;      // 0
```

Если вместо числа пришла ошибка `TypeError: Cannot read properties of null`,
значит, `querySelector` ничего не нашёл и вернул `null`. Сверьте
селектор с разметкой: `#tasks` — это `id`, `.filters` — класс.

## 5. Главная схема {#idea}

Вот идея, на которой держится вся программа, — и любая программа с интерфейсом:

<Scheme src="scheme-idea.svg">Человек действует → слушатель меняет данные → render строит страницу из данных</Scheme>

Страница — **картинка данных**, и ничего больше. Слушатель никогда не трогает
список на странице напрямую: он меняет массив `tasks` и зовёт `render()`,
а та строит список заново. Правило из «Табеля» — «считаем в данных, форматируем в конце» —
здесь стало правилом всей программы.

Почему так, а не «добавил дело — добавил пункт на страницу»? Потому что одно действие
меняет сразу несколько мест: список, счётчик, кнопку «Удалить сделанные». Если каждый
слушатель чинит эти места сам, рано или поздно один из них что-то забудет, и страница
разойдётся с данными. Когда страницу строит одна функция, разойтись им негде.

## 6. Одно дело — один пункт {#item}

Сначала — функция, которая делает из одного объекта один пункт списка. Это
`makeItem` из дня 26, только внутри теперь флажок, текст и кнопка:

<Scheme src="scheme-item.svg">Каждое поле объекта превращается в свою часть пункта</Scheme>

```js
function makeItem(task) {
  const li = document.createElement("li");
  const box = document.createElement("input");
  const text = document.createElement("span");
  const del = document.createElement("button");

  box.type = "checkbox";
  box.checked = task.done;
  text.textContent = task.text;       // данные — только текстом (день 25)
  del.textContent = "✕";
  del.classList.add("delete");

  li.append(box, " ", text, " ", del);   // строки " " — пробелы между частями
  li.dataset.id = task.id;               // пункт запоминает номер своего дела
  li.classList.toggle("done", task.done);
  return li;
}
```

Три строки здесь стоит отметить отдельно. `box.type = "checkbox"` делает
поле флажком — свойство `type` из дня 28 работает и на запись.
`li.dataset.id = task.id` — ниточка от пункта к данным: по ней слушатели найдут
дело (раздел 9). А `toggle` со вторым аргументом ставит или снимает класс
`done` одной строкой, смотря что в данных.

Функция ничего не вставляет на страницу — только создаёт и возвращает пункт. Так её легко
проверить в консоли:

```js
makeItem({ id: 7, text: "Проверка", done: false }).outerHTML;
// '<li data-id="7"><input type="checkbox"> <span>Проверка</span> <button class="delete">✕</button></li>'
```

У несделанного дела атрибута `class` нет вовсе: `toggle` с
`false` ничего не добавил. А вот настоящее дело из данных, сделанное:

```js
const item = makeItem(tasks[0]);
item.className;                        // "done"
item.dataset.id;                       // "1" — число 1 стало строкой
item.querySelector("input").checked;   // true
```

Запомните кавычки у `"1"`: всё, что записано в `dataset`, лежит
в разметке строкой. Через три раздела это станет важным.

## 7. `render`: страница из данных {#render}

```js
function isVisible(task) {
  if (filter === "active") return !task.done;
  if (filter === "done") return task.done;
  return true;
}

function render() {
  list.textContent = "";                                   // 1. убрать старое
  list.append(...tasks.filter(isVisible).map(makeItem));   // 2. построить видимые

  const left = tasks.filter((t) => !t.done).length;       // 3. счётчик
  counter.textContent = `Осталось: ${left} из ${tasks.length}`;
  clearDone.hidden = tasks.every((t) => !t.done);          // 4. кнопка — если есть что удалять

  filters.querySelectorAll("button").forEach((b) => {      // 5. выделить текущий фильтр
    b.classList.toggle("active", b.dataset.filter === filter);
  });
}

render();   // первый показ при загрузке
```

<li><input type="checkbox" disabled /> <span>Сделать задания дня 28</span> <button type="button" disabled>✕</button></li>
<li><input type="checkbox" disabled /> <span>Прочитать про события на MDN</span> <button type="button" disabled>✕</button></li>
</ul>

Осталось: 2 из 3 &nbsp; <button type="button" disabled>Удалить сделанные</button>

`render` — сердце программы, и она целиком из знакомых кусков.
«Перерисовать — значит очистить и вставить заново» — это `renderList` из дня 26.
`filter` отбирает дела по текущему фильтру, `map` делает из каждого пункт,
три точки раскладывают массив в `append`. Счётчик и кнопка считаются по
**всем** делам, а не по видимым: «Осталось: 2 из 3» не зависит от фильтра.

`every` из дня 20 отвечает на вопрос «правда ли, что ни одно дело не сделано».
Если да — кнопку «Удалить сделанные» прячем через `hidden` (день 25). У пустого
массива `every` отвечает `true`, так что и для пустого списка кнопка спрятана.

Проверка шага — и главный опыт дня. Сначала убедимся, что показ совпадает с данными:

```js
list.children.length;   // 3
counter.textContent;    // "Осталось: 2 из 3"
clearDone.hidden;       // false — одно дело сделано, кнопка видна
```

Теперь поменяем данные руками, прямо в консоли, и позовём `render`.
Ни одного слушателя ещё нет, а страница уже умеет всё показать:

```js
tasks[1].done = true;
render();
counter.textContent;          // "Осталось: 1 из 3"
list.children[1].className;   // "done" — второй пункт зачёркнут
```

Обновите страницу, чтобы вернуть исходные данные, и переключите фильтр тем же способом:

```js
filter = "active";
render();
list.children.length;                     // 2
list.querySelector("span").textContent;   // "Сделать задания дня 28"
```

Вот что значит «страница — картинка данных». Слушатели, которые мы напишем дальше,
будут делать ровно это: менять данные и звать `render()`. Осталось научить
их понимать, что нажал человек.

## 8. Добавить дело {#add}

```js
form.addEventListener("submit", (event) => {
  event.preventDefault();
  const text = form.elements.text.value.trim();

  if (text === "") {
    error.textContent = "Напишите, что нужно сделать";
    form.elements.text.focus();
    return;
  }
  if (text.length > 60) {
    error.textContent = "Слишком длинно: не больше 60 знаков";
    form.elements.text.focus();
    return;
  }

  tasks.push({ id: nextId, text, done: false });   // 1. изменить данные
  nextId++;
  error.textContent = "";
  form.reset();
  render();                                        // 2. перерисовать
});
```

Это слушатель `submit` из дня 28 почти без изменений: `preventDefault`,
`trim`, проверки по одной, сообщение и фокус. Новое — две строки
в середине: дело добавляется **в данные**, и счётчик номеров сдвигается.
На страницу дело попадёт само — через `render()`.

Запись `{ id: nextId, text, done: false }` использует короткую форму из
дня 21: `text` вместо `text: text`. После добавления в консоли видно,
что изменились именно данные:

```js
// добавили через форму «Купить тетрадь»:
tasks.length;             // 4
tasks.at(-1);             // {id: 4, text: 'Купить тетрадь', done: false}
nextId;                   // 5
```

## 9. От элемента к данным {#find}

Щёлкнули по флажку или по «✕» — слушатель получает **элемент**. А менять
нужно **объект в массиве**. Мост между ними — `data-id`, который
`makeItem` записала в каждый пункт:

<Scheme src="scheme-find.svg">Четыре шага от щелчка до объекта в массиве</Scheme>

```js
function taskOf(element) {
  const id = Number(element.closest("li").dataset.id);
  return tasks.find((t) => t.id === id);
}
```

Четыре шага в двух строках. `closest("li")` поднимается от флажка или кнопки
к пункту — день 24 и день 27. `dataset.id` — номер строкой: всё, что читается
со страницы, строки (день 25). `Number` превращает строку в число, а
`find` из дня 20 находит в массиве дело с этим номером.

```js
const li = document.querySelector('li[data-id="2"]');

li.dataset.id;          // "2" — строка
taskOf(li).text;        // "Сделать задания дня 28"
```

Функция нужна двум слушателям — отметке и удалению, поэтому вынесена отдельно.
Вернёт она **тот же объект**, что лежит в массиве, а не копию: изменить его
свойство — значит изменить данные.

Почему без `Number` никак, видно в консоли:

```js
"2" === 2;                            // false — строгое сравнение, день 7
tasks.find((t) => t.id === "2");      // undefined — такого дела нет
tasks.find((t) => t.id === 2).text;   // "Сделать задания дня 28"
```

## 10. Отметить сделанным {#toggle}

```js
list.addEventListener("change", (event) => {
  if (!event.target.matches('input[type="checkbox"]')) return;
  taskOf(event.target).done = event.target.checked;
  render();
});
```

Слушатель один на весь список — делегирование из дня 27. Событие `change`
всплывает, поэтому щелчок по любому флажку доходит до `ul`. Первая строка
проверяет через `matches` (день 24), что изменился именно флажок: в пункте
могут появиться и другие поля, например поле правки из задания со звёздочкой.

Флажок уже отметился сам, браузер это сделал. Наша задача — перенести его состояние
в данные: `done` становится равным `checked`. Потом `render()`
перестраивает список: пункт получает класс `done` и зачёркивается, счётчик
уменьшается. Перерисовка нужна, даже когда видимый флажок уже стоит правильно: при
фильтре «Активные» отмеченное дело должно исчезнуть из списка.

Проверка шага: щёлкните флажок у «Сделать задания дня 28» и спросите консоль.

```js
tasks.find((t) => t.id === 2).done;   // true — отметка дошла до данных
counter.textContent;                  // "Осталось: 1 из 3"
```

## 11. Удалить {#delete}

```js
list.addEventListener("click", (event) => {
  if (!event.target.closest(".delete")) return;
  const task = taskOf(event.target);
  tasks = tasks.filter((t) => t !== task);
  render();
});
```

Удалить дело из данных — значит оставить все, кроме него. Это `filter`:
новый массив без одного элемента. Поэтому `tasks` объявлен через
`let` — переменной присваивается новый массив.

Сравнение `t !== task` сравнивает объекты — «та ли это коробка», день 21.
Работает потому, что `taskOf` вернула тот самый объект из массива. Можно было бы
сравнить и номера: `t.id !== task.id`.

Проверка шага: «✕» у «Повторить день 26».

```js
tasks.map((t) => t.id);   // [2, 3]
list.children.length;     // 2
```

А почему не `splice`, как в «Табеле» на дне 27? Можно и так: найти позицию
через `findIndex` и вырезать. Проверим в консоли на исходной странице:

```js
const i = tasks.findIndex((t) => t.id === 2);
tasks.splice(i, 1);        // вырезает из того же массива
render();
tasks.map((t) => t.id);    // [1, 3]
list.children.length;      // 2
```

Работает, и так подошёл бы даже `const`: `splice` меняет тот же
массив, а не присваивает переменной новый. Мы всё же взяли `filter`: он короче,
и в нём нет позиции, с которой можно ошибиться, — а ошибиться очень легко, как покажет
раздел 13.

## 12. Фильтры, очистка, Esc {#filters}

Три оставшиеся возможности — по нескольку строк каждая. Фильтр меняет только переменную
`filter`, а что показывать, решает `isVisible` внутри
`render`:

```js
filters.addEventListener("click", (event) => {
  const button = event.target.closest("button");
  if (!button) return;
  filter = button.dataset.filter;   // "all", "active" или "done" — из data-filter
  render();
});
```

Кнопка делает то же, что мы делали руками в разделе 7. Третий фильтр проверим тем же
способом, на исходной странице:

```js
filter = "done";
render();
list.children.length;                      // 1
list.querySelector("span").textContent;    // "Повторить день 26"
filters.querySelector(".active").textContent;   // "Сделанные" — выделена нужная кнопка
```

«Удалить сделанные» — тот же `filter` массива, что и одиночное удаление,
только условие другое:

```js
clearDone.addEventListener("click", () => {
  tasks = tasks.filter((t) => !t.done);
  render();
});
```

И <Kbd>Esc</Kbd> в поле ввода — слушатель `keydown` из дня 27
на самом поле: у поля есть фокус, значит, клавиши приходят ему.

```js
form.elements.text.addEventListener("keydown", (event) => {
  if (event.key === "Escape") {
    form.reset();
    error.textContent = "";
  }
});
```

Обратите внимание, как мало кода нужно на каждую новую возможность. Слушатель меняет
данные в одну строку и зовёт `render` — вся остальная работа уже сделана.
Это главная выгода схемы из раздела 5: новые возможности добавлять дёшево.

Пять слушателей из шести устроены одинаково, и у них общий скелет. Шестой, на
<Kbd>Esc</Kbd>, данных не касается: он чистит только поле, и
`render` ему не нужен.

```js
// скелет слушателя этой программы — шаблон, а не код для запуска
element.addEventListener("событие", (event) => {
  // 1. понять, что случилось: matches, closest, taskOf, проверка ввода
  // 2. изменить данные: tasks, filter или nextId
  render();   // 3. перерисовать — последней строкой
});
```

## 13. Разбор: удалилось не то {#bug-index}

Частая первая версия удаления запоминает в пункте не `id`, а номер позиции —
второй аргумент `map`:

```js
// так НЕ надо
function makeItem(task, i) {
  // … то же самое, плюс:
  li.dataset.index = i;
}

list.addEventListener("click", (event) => {
  if (!event.target.closest(".delete")) return;
  const index = Number(event.target.closest("li").dataset.index);
  tasks.splice(index, 1);
  render();
});
```

Пока фильтр «Все», всё работает, и ошибку легко не заметить. Добавим «Купить тетрадь»,
включим «Активные» и нажмём «✕» у «Прочитать про события на MDN»:

```js
// на экране при фильтре «Активные»:
// 0 Сделать задания дня 28 · 1 Прочитать про события на MDN · 2 Купить тетрадь
// щёлкнули «✕» у второго — index 1
tasks.map((t) => t.text);
// ["Повторить день 26", "Прочитать про события на MDN", "Купить тетрадь"]
// удалилось «Сделать задания дня 28», а нажатое дело осталось!
```

**Шаг 1. Что удалилось?** Не то, что нажали, а соседнее. Значит, номер
указал не туда.

**Шаг 2. Откуда номер?** `map` нумеровал пункты
**видимого** списка, а `splice` удаляет по номеру
**всего** массива. В видимом списке «Прочитать…» — номер 1, а в массиве под
номером 1 лежит «Сделать задания дня 28»: скрытое сделанное дело сдвинуло нумерацию.
Консоль показывает это прямо — даже на исправной программе, при фильтре «Активные»:

```js
filter = "active";
render();
tasks.filter(isVisible)[1].text;   // "Прочитать про события на MDN" — второй на экране
tasks[1].text;                     // "Сделать задания дня 28" — второй в массиве
```

**Шаг 3. Чиним.** Позиция меняется от фильтра, удаления, сортировки.
`id` — никогда. Поэтому связь «пункт — дело» строят только через постоянный
номер, как в разделе 9.

## 14. Разбор: три тихие ошибки {#bugs}

Ещё три ошибки встречаются в заданиях почти у всех. У каждой свой симптом.

### Флажок не отмечает дело

```js
// в taskOf забыли Number:
function taskOf(element) {
  return tasks.find((t) => t.id === element.closest("li").dataset.id);
}

// щелчок по флажку:
// TypeError: Cannot set properties of undefined (setting 'done')
```

`dataset.id` — строка `"2"`, а в данных число `2`.
Строгое сравнение из дня 7 их не считает равными, `find` ничего не находит
и возвращает `undefined` — ему и пытаемся записать `done`.
Коварство в том, что флажок на странице при этом отметился: браузер сделал своё, а
данные остались прежними.

### Дело добавилось, но его не видно

Забыли `render()` в конце слушателя. Ошибки нет, форма очистилась, а список
прежний. Повторим это в консоли: добавим дело в данные и не позовём `render`.

```js
tasks.push({ id: nextId, text: "Купить тетрадь", done: false });
nextId++;
tasks.length;            // 4 — в данных четыре дела
list.children.length;    // 3 — на странице три
render();
list.children.length;    // 4
```

Первый вопрос при любой странности такого приложения: **что в данных?**
Если данные верны, а страница нет, — не вызвали `render`.

### Удаление падает с ошибкой про константу

```js
const tasks = [ /* … */ ];

// щелчок по «✕»:
// TypeError: Assignment to constant variable.
```

Та самая ошибка из дня 4: `tasks = tasks.filter(…)` присваивает переменной
новый массив, а у `const` так нельзя. Решений два: объявить через
`let`, как у нас, или удалять изнутри тем же массивом — `splice`
по `findIndex`.

| Симптом | Причина | Где смотреть |
| --- | --- | --- |
| удалилось соседнее дело | номер позиции вместо `id` | что пишется в `dataset` |
| `Cannot set properties of undefined` | строка против числа в `find` | `Number` в `taskOf` |
| данные изменились, страница — нет | нет `render()` | конец слушателя |
| `Assignment to constant variable.` | `const` у меняющегося массива | объявление `tasks` |

## 15. Программа целиком {#whole}

Соберём `app.js` в одном месте. Порядок частей — тот же, в котором мы их
писали: данные, элементы, показ, действия, первый показ.

```js
// 1. Данные — главное в программе. Страница только показывает их.
let tasks = [
  { id: 1, text: "Повторить день 26", done: true },
  { id: 2, text: "Сделать задания дня 28", done: false },
  { id: 3, text: "Прочитать про события на MDN", done: false },
];
let nextId = 4;
let filter = "all";

// 2. Элементы страницы — находим один раз
const form = document.querySelector("#new-task");
const error = document.querySelector("#error");
const list = document.querySelector("#tasks");
const counter = document.querySelector("#counter");
const clearDone = document.querySelector("#clear-done");
const filters = document.querySelector(".filters");

// 3. Показ: из данных — в элементы
function makeItem(task) {
  const li = document.createElement("li");
  const box = document.createElement("input");
  const text = document.createElement("span");
  const del = document.createElement("button");

  box.type = "checkbox";
  box.checked = task.done;
  text.textContent = task.text;
  del.textContent = "✕";
  del.classList.add("delete");

  li.append(box, " ", text, " ", del);
  li.dataset.id = task.id;
  li.classList.toggle("done", task.done);
  return li;
}

function isVisible(task) {
  if (filter === "active") return !task.done;
  if (filter === "done") return task.done;
  return true;
}

function render() {
  list.textContent = "";
  list.append(...tasks.filter(isVisible).map(makeItem));

  const left = tasks.filter((t) => !t.done).length;
  counter.textContent = `Осталось: ${left} из ${tasks.length}`;
  clearDone.hidden = tasks.every((t) => !t.done);

  filters.querySelectorAll("button").forEach((b) => {
    b.classList.toggle("active", b.dataset.filter === filter);
  });
}

// 4. Действия: меняют данные и зовут render()
form.addEventListener("submit", (event) => {
  event.preventDefault();
  const text = form.elements.text.value.trim();

  if (text === "") {
    error.textContent = "Напишите, что нужно сделать";
    form.elements.text.focus();
    return;
  }
  if (text.length > 60) {
    error.textContent = "Слишком длинно: не больше 60 знаков";
    form.elements.text.focus();
    return;
  }

  tasks.push({ id: nextId, text, done: false });
  nextId++;
  error.textContent = "";
  form.reset();
  render();
});

function taskOf(element) {
  const id = Number(element.closest("li").dataset.id);
  return tasks.find((t) => t.id === id);
}

list.addEventListener("change", (event) => {
  if (!event.target.matches('input[type="checkbox"]')) return;
  taskOf(event.target).done = event.target.checked;
  render();
});

list.addEventListener("click", (event) => {
  if (!event.target.closest(".delete")) return;
  const task = taskOf(event.target);
  tasks = tasks.filter((t) => t !== task);
  render();
});

filters.addEventListener("click", (event) => {
  const button = event.target.closest("button");
  if (!button) return;
  filter = button.dataset.filter;
  render();
});

clearDone.addEventListener("click", () => {
  tasks = tasks.filter((t) => !t.done);
  render();
});

form.elements.text.addEventListener("keydown", (event) => {
  if (event.key === "Escape") {
    form.reset();
    error.textContent = "";
  }
});

// 5. Первый показ
render();
```

Проверим все девять пунктов задания из раздела 2 одним сценарием. Каждая ветка
программы сработала в нём хотя бы раз:

| --- | --- |
| открыли страницу | три дела, первое зачёркнуто; «Осталось: 2 из 3» |
| «Добавить» с пустым полем | «Напишите, что нужно сделать», курсор в поле |
| длинное дело, Enter | «Слишком длинно: не больше 60 знаков» |

### Крайние случаи

Сценарий выше — обычная работа. Теперь проверим края, как тестировщик: каждую строку
с чистой страницы.

| Что сделали | Что на странице | Почему |
| --- | --- | --- |
| пять пробелов, Enter | «Напишите, что нужно сделать» | `trim` оставил пустую строку |
| ровно 60 знаков / 61 знак | добавлено / «Слишком длинно…» | условие `> 60`: шестьдесят можно |
| дело `<b>жирно</b>` | так и написано, с угловыми скобками | `textContent` не разбирает разметку (день 25) |
| дело при фильтре «Сделанные» | в списке не появилось, «Осталось: 3 из 4» | новое дело активное, фильтр его прячет |
| удалили все три дела | «Осталось: 0 из 0», кнопки «Удалить сделанные» нет | `every` пустого массива — `true` |
| ошибка ввода, потом начали печатать | сообщение об ошибке висит | его снимают только отправка и <Kbd>Esc</Kbd> |

Первые три строки — программа ведёт себя правильно. Последняя и четвёртая — не ошибки,
но человек удивится: «добавил, а где?», «я же исправляю!». Такие места доводят до ума
в заданиях.

### Что общего с «Табелем»

Положите рядом «Табель» и список дел — это одна и та же программа с разными данными.

|  | «Табель» | Список дел |
| --- | --- | --- |
| данные | массив отчётов `reports` | массив дел `tasks` |
| один объект → один элемент | `makeRow` | `makeItem` |
| связь элемента с данными | `data-name` | `data-id` |
| ввод | форма с проверкой | форма с проверкой |
| действия | делегирование на `tbody` | делегирование на `ul` |
| итог | «Отличников: 2 из 5» | «Осталось: 2 из 3» |

Отличие одно, и оно важное: список дел перестраивает страницу целиком одной функцией,
а «Табель» дописывает и удаляет строки по месту. Для маленьких списков подходят оба
способа. Перестраивать всё проще и надёжнее, а по месту — быстрее, когда элементов тысячи.

## 16. Что дальше {#next}

У списка дел есть очевидный недостаток: обновили страницу — всё пропало, вернулись
три исходных дела. Данные живут в переменных, а переменные исчезают вместе со страницей.
Это починим на дне 31: `localStorage` сохранит массив строкой JSON (день 23),
и при загрузке мы его прочитаем. Благодаря схеме из раздела 5 правка будет крошечной:
сохранить данные в конце `render`, прочитать в начале программы.

```js
localStorage.setItem("tasks", JSON.stringify(tasks));   // день 31: последняя строка render
tasks = JSON.parse(localStorage.getItem("tasks"));      // день 31: начало программы
```

Две строки — но с двумя подвохами, которые разберём на дне 31. При самом первом
запуске сохранённого ещё нет, и вместо массива придёт `null`. А счётчик
`nextId` тоже придётся восстанавливать — иначе новое дело получит номер,
который уже занят.

Завтра, на дне 30, — **таймеры и промисы**: как сделать что-то не сейчас,
а через секунду, и как ждать того, что приходит не сразу. Это подготовка к дню 31,
когда данные начнут приходить из сети.

### Как расширять проект самим

| Идея | Что понадобится |
| --- | --- |
| правка текста двойным щелчком | `dblclick`, поле вместо текста, `replaceWith` (день 26) |
| «Отметить все» | `forEach` по данным и один `render` |
| поиск по делам | `input` и ещё одно условие в `isVisible` (день 28) |
| важные дела | поле `important` в объекте и класс в `makeItem` |

Каждая идея ложится в ту же схему: новое поле в данных, новая строчка в
`makeItem` или `isVisible`, новый слушатель, который меняет данные
и зовёт `render`. Все четыре — в сегодняшних заданиях.

<Selfcheck>
1. Почему слушатели меняют данные и зовут `render`, а не правят страницу сами?
   <Answer>Одно действие меняет несколько мест страницы: список, счётчик, кнопки. Если
   их строит одна функция из данных, страница не может разойтись с данными.
   И новые возможности добавлять проще.</Answer>
2. Зачем делу `id`, если есть текст и позиция в массиве?
   <Answer>Текст может повторяться, а позиция меняется от фильтра, удаления, сортировки.
   `id` дело получает один раз и не теряет — по нему пункт надёжно
   находит своё дело.</Answer>
3. Почему в `taskOf` нужен `Number`?
   <Answer>`dataset.id` — строка, а в данных `id` число.
   `"2" === 2` ложно, и `find` вернул бы `undefined`.</Answer>
4. Почему `tasks` объявлен через `let`?
   <Answer>При удалении переменной присваивается новый массив из `filter`.
   С `const` это ошибка `Assignment to constant variable.`</Answer>
5. Счётчик «Осталось» считается по всем делам или по видимым? Почему?
   <Answer>По всем: сколько осталось сделать, не зависит от того, какой фильтр выбран.
   Видимые нужны только для списка.</Answer>
6. Дело добавилось в `tasks`, а на странице его нет. Что проверить первым?
   <Answer>Вызов `render()` в конце слушателя: данные верны, значит,
   страницу забыли перестроить.</Answer>
</Selfcheck>
