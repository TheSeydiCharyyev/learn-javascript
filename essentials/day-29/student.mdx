# День 29. Мини-проект: список дел

<Subtitle>Выжимка лекции: как устроена программа и как проверить, что проект готов.</Subtitle>

## Пять частей программы

```js
// 1. Данные — всё, от чего зависит вид страницы
let tasks = [
  { id: 1, text: "Повторить день 26", done: true },
  // … у каждого дела id, text и done
];
let nextId = 4;
let filter = "all";

// 2. Элементы страницы — находим один раз
const list = document.querySelector("#tasks");

// 3. Показ: страница строится из данных
function render() {
  list.textContent = "";
  list.append(...tasks.filter(isVisible).map(makeItem));
  // счётчик и кнопки — тоже из данных, по всем делам
}

// 4. Действия: понять, что случилось → изменить данные → render()
// 5. Первый показ
render();
```

<KeyPoint>
Страница — картинка данных. Слушатель не правит список сам: он меняет
`tasks` или `filter` и зовёт `render()`. Одно действие
меняет сразу список, счётчик и кнопки — когда всё строит одна функция, страница не
разойдётся с данными.
</KeyPoint>

`makeItem(task)` делает из одного объекта один пункт и только возвращает его.
Данные — через `textContent`, класс — через `classList.toggle("done", task.done)`,
а в `data-id` пункт запоминает номер своего дела.

## От элемента к данным

```js
function taskOf(element) {
  const id = Number(element.closest("li").dataset.id);   // "2" → 2
  return tasks.find((t) => t.id === id);
}

// в слушателе click на списке — удалить нажатое дело:
const task = taskOf(event.target);
tasks = tasks.filter((t) => t !== task);   // все, кроме него; поэтому let
```

<Remember>
Всё, что лежит в `dataset`, — строки: без `Number` сравнение
`"2" === 2` ложно и `find` вернёт `undefined`.
Связь «пункт — дело» строят только через `id`: позиция в списке меняется
от фильтра и удаления, а `id` — никогда.
</Remember>

## Ошибки по симптомам

| Симптом | Причина |
| --- | --- |
| удалилось соседнее дело | в пункте номер позиции вместо `id` |
| `Cannot set properties of undefined` | строка против числа в `find` |
| данные изменились, страница — нет | забыли `render()` |
| `Assignment to constant variable.` | `const tasks`, а удаление присваивает новый массив |

При любой странности первый вопрос — **что в данных?** Спросите консоль:
`tasks`. Данные верны, а страница нет — ищите `render`.

## Чек-лист готовности

Проект готов, когда каждая строка проверена руками на чистой странице.

| Что проверить | Как |
| --- | --- |
| первый показ | три дела, первое зачёркнуто, «Осталось: 2 из 3» |
| добавление | дело в конце списка, без пробелов по краям, поле очистилось |
| проверка ввода | пустое и одни пробелы — сообщение; 60 знаков можно, 61 — нет |
| отметка | флажок зачёркивает и снимает зачёркивание, счётчик меняется |
| удаление | «✕» удаляет именно нажатое дело при любом фильтре |
| фильтры | выделен текущий; счётчик от фильтра не зависит |
| «Удалить сделанные» | видна, только когда есть что удалять |
| <Kbd>Esc</Kbd> | очищает поле и сообщение |
| текст с разметкой | `<b>` в деле виден как текст |
| консоль | нет ошибок; `tasks` совпадает со страницей после каждого действия |

## Как расширять

Любая доработка ложится в ту же схему: новое поле или переменная в данных
(`important`, `query`), строчка в `makeItem` или
`isVisible`, новый слушатель, который меняет данные и зовёт `render`.
Сохранения пока нет: обновили страницу — вернулись исходные дела. Его добавим на дне 31.
