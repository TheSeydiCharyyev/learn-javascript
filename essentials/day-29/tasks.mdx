<Task title="7. Важные дела" level="medium" time="13">
<Goal>провести новое поле данных через весь проект.</Goal>

У каждого дела появляется поле `important`; в исходных данных важное —
«Сделать задания дня 28». В пункте — кнопка «★»: щелчок делает дело важным или обычным.
Важные дела выделены жирным и стоят в списке первыми, в остальном порядок прежний.

<Example>
```js
// при загрузке пункты идут так: 2, 1, 3
// «★» у дела 3 → 2, 3, 1
// «★» у дела 2 → 3, 1, 2
tasks.map((t) => t.id);   // [1, 2, 3] — в данных порядок прежний
```
</Example>

<Hint>
Четыре места: данные (и новый объект в `submit`), `makeItem` (кнопка
и класс `important` через `toggle`), `render` (в один
`append` — сначала важные, потом остальные) и слушатель щелчка по
`.star`. Оформление: `.important span { font-weight: bold; }`.
</Hint>

<Criteria>
- порядок пунктов совпадает с примером на каждом шаге;
- новое дело появляется обычным и в конце списка;
- после двух щелчков из примера фильтр «Активные» показывает пункты 3, 2;
- объяснено, почему порядок на странице менялся, а в `tasks` — нет.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Правка двойным щелчком" level="hard" time="10">
<Goal>на время подменить часть пункта полем и вернуть правку в данные.</Goal>

Двойной щелчок по тексту дела заменяет его полем с тем же текстом, курсор в поле.
<Kbd>Enter</Kbd> сохраняет новый текст в данные, <Kbd>Esc</Kbd>
отменяет правку. Пустой текст и текст длиннее 60 знаков не сохраняются: поле остаётся.

<Hint>
Двойной щелчок — событие [`dblclick`](https://developer.mozilla.org/en-US/docs/Web/API/Element/dblclick_event),
его слушают так же, как `click`: на `ul`, с проверкой
`matches("span")`. Поле встаёт на место текста через `replaceWith`
из дня 26. Клавиши — слушатель `keydown` на `ul`; и после сохранения,
и для отмены хватит `render()`: он построит пункт заново.
</Hint>

<Criteria>
- «Повторить день 26» исправлено на «Повторить дни 26 и 27» — новый текст в
  `tasks[0].text`, дело по-прежнему сделано;
- <Kbd>Esc</Kbd> возвращает старый текст; пустой текст и 61 знак не сохраняются;
- двойной щелчок по флажку правку не открывает — записано, что стало с отметкой;
- объяснено, почему слушатель `change` из раздела 10 не путает поле правки с флажком;
- объяснено, куда девается начатая правка, если во время неё щёлкнуть фильтр.
</Criteria>
</Task>

<Task title="9. Три жалобы" level="hard" time="10">
<Goal>искать ошибку от симптома, начиная с вопроса «что в данных?».</Goal>

- «Добавил „Купить хлеб“ и „Купить сок“, отметил сок — зачеркнулся хлеб. Удалил сок — пропал хлеб».

От программы лекции его `app.js` отличается тремя строками в этих фрагментах.
Скопируйте папку `todo` из задания 3 в `todo-bugs`, внесите фрагменты
и воспроизведите каждую жалобу.

```js
// в слушателе submit
tasks.push({ id: nextId, text, done: false });
error.textContent = "";
form.reset();

// в render
const left = tasks.filter(isVisible).filter((t) => !t.done).length;
counter.textContent = `Осталось: ${left} из ${tasks.length}`;
clearDone.hidden = tasks.some((t) => t.done);
```

<Hint>
После двух добавлений спросите консоль `tasks.map((t) => t.id)`. Отметку и
удаление ведёт `taskOf`, а `find` возвращает первое подходящее.
</Hint>

<Criteria>
- каждая жалоба воспроизведена и сопоставлена со своей строкой;
- для первой записан вывод `tasks.map((t) => t.id)` и объяснено, почему
  ломаются и отметка, и удаление, хотя в их слушателях ошибок нет;
- все три строки исправлены, жалобы больше не повторяются;
