# Day 30. Timers and promises

<Subtitle>A summary of the lecture: timers, promises, chains and your own promise.</Subtitle>

## Timers

```js
const id = setTimeout(greet, 1000, "Aman");   // once, a second later; greet — without parentheses
clearTimeout(id);                             // changed our mind — cancel

const timerId = setInterval(tick, 100);       // every 100 ms until it is stopped
clearInterval(timerId);                       // stop
```

<Remember>
`setTimeout` does not wait: the code after it runs at once, and the timer’s function —
later, even with a delay of 0. The delay means “not earlier than”: while the browser is busy,
the timer waits. `setTimeout(greet("Aman"), 1000)` calls the function at once and
gives the timer `undefined`.
</Remember>

The number of a timer is data, just like everything else: it is kept in a variable outside
the function. A new message cancels the timer of the old one, otherwise that timer erases the new message too early.
A second “Start” does not start a second interval: before starting, check
`timerId !== null`; after stopping, write `timerId = null`.

## A promise

A promise is an object that promises a result later. At first it is waiting (*pending*),
then once it is fulfilled with a value (*fulfilled*) or rejected with an error
(*rejected*). The value is not taken directly, but with a function in `then`.

```js
later("5 4 9", 1000)
  .then((text) => [...text].filter((ch) => ch !== " "))   // return a value…
  .then((marks) => later(marks.length, 500))              // …or a promise: the chain will wait
  .then((count) => console.log(count))                    // after 1.5 s: 3
  .catch((err) => console.log(err.message))               // an error of any step above
  .finally(() => console.log("done"));                    // in any outcome
```

<KeyPoint>
`then` returns a new promise. What a step returned is what the next one gets: a value —
at once, a promise — when it is fulfilled, nothing — `undefined`. An error in any step
skips the remaining `then` steps and goes to `catch`. In a step with curly
braces do not forget `return`.
</KeyPoint>

## Your own promise

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

function loadSaved() {
  return new Promise((resolve, reject) => {
    setTimeout(resolve, 1000, saved);   // a second later — fulfill it with the string saved
  });
}
```

<Remember>
The executor starts at once, at the moment of `new`. Only the first call of
`resolve` or `reject` counts. From a timer a promise is rejected with
`reject(new Error("…"))`: an error thrown in a timer with `throw`
the promise will not see, and it will stay pending forever. Ready promises are
`Promise.resolve(x)` and `Promise.reject(err)`; even for them
`then` fires after the current code.
</Remember>

## Mistakes by their symptoms

| What you see | Cause |
| --- | --- |
| it fired at once, then nothing | parentheses: `setTimeout(f(), …)` |
| “Stop” does not stop | the number of the first interval was overwritten by the second |
| `setTimeout(...).then is not a function` | a timer returns a number, not a promise |
| `undefined` in the next step | no `return` |
| `Uncaught (in promise) Error` | no `catch` at the end of the chain |

## The “Report card” is loading

The data comes a second later from `loadSaved`: while it is not there — the label
“Loading…” and a hidden form; in `then` the rows are built, in `catch` —
an error message, in `finally` the label is hidden and the form comes back.
While there is no result, the program must not pretend that there is one.
