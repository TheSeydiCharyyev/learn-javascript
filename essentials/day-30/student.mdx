# День 30. Таймеры и промисы

<Subtitle>Выжимка лекции: таймеры, промисы, цепочки и свой промис.</Subtitle>

## Таймеры

```js
const id = setTimeout(greet, 1000, "Аман");   // один раз через секунду; greet — без скобок
clearTimeout(id);                             // передумали — отменить

const timerId = setInterval(tick, 100);       // каждые 100 мс, пока не остановят
clearInterval(timerId);                       // остановить
```

<Remember>
`setTimeout` не ждёт: код после него выполняется сразу, а функция таймера —
потом, даже с задержкой 0. Задержка значит «не раньше чем»: пока браузер занят,
таймер ждёт. `setTimeout(greet("Аман"), 1000)` вызывает функцию сразу, а
таймеру отдаёт `undefined`.
</Remember>

Номер таймера — такие же данные, как всё остальное: его хранят в переменной снаружи
функции. Новое сообщение отменяет таймер старого, иначе тот сотрёт новое раньше времени.
Второй «Старт» не запускает второй интервал: перед запуском проверяют
`timerId !== null`, после остановки пишут `timerId = null`.

## Промис

Промис — объект, который обещает результат потом. Сначала он ждёт (*pending*),
потом один раз выполняется со значением (*fulfilled*) или отклоняется с ошибкой
(*rejected*). Значение достают не напрямую, а функцией в `then`.

```js
later("5 4 9", 1000)
  .then((text) => [...text].filter((ch) => ch !== " "))   // вернуть значение…
  .then((marks) => later(marks.length, 500))              // …или промис: цепочка дождётся
  .then((count) => console.log(count))                    // через 1.5 с: 3
  .catch((err) => console.log(err.message))               // ошибка любого шага выше
  .finally(() => console.log("готово"));                  // в любом исходе
```

<KeyPoint>
`then` возвращает новый промис. Что вернул шаг, то получит следующий: значение —
сразу, промис — когда он выполнится, ничего — `undefined`. Ошибка в любом шаге
пропускает оставшиеся `then` и уходит в `catch`. В шаге с фигурными
скобками не забывайте `return`.
</KeyPoint>

## Свой промис

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

function loadSaved() {
  return new Promise((resolve, reject) => {
    setTimeout(resolve, 1000, saved);   // через секунду — выполнить со строкой saved
  });
}
```

<Remember>
Исполнитель запускается сразу, в момент `new`. Считается только первый вызов
`resolve` или `reject`. Из таймера отклоняют через
`reject(new Error("…"))`: ошибку, брошенную в таймере через `throw`,
промис не увидит и останется в ожидании навсегда. Готовые промисы —
`Promise.resolve(x)` и `Promise.reject(err)`; даже у них
`then` срабатывает после текущего кода.
</Remember>

## Ошибки по симптомам

| Что видно | Причина |
| --- | --- |
| сработало сразу, потом ничего | скобки: `setTimeout(f(), …)` |
| «Стоп» не останавливает | номер первого интервала затёрт вторым |
| `setTimeout(...).then is not a function` | таймер возвращает номер, а не промис |
| `undefined` в следующем шаге | нет `return` |
| `Uncaught (in promise) Error` | нет `catch` в конце цепочки |

## «Табель» загружается

Данные приходят через секунду из `loadSaved`: пока их нет — надпись
«Загрузка…» и спрятанная форма, в `then` строятся строки, в `catch` —
сообщение об ошибке, в `finally` надпись прячется, а форма возвращается.
Пока результата нет, программа не должна делать вид, что он есть.
