# День 30. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–5 и 9 делаем на странице секундомера из лекции (папка `day-30/timer`): разметка — из раздела 2, `app.js` — из разделов 2 и 6, помощники `wait`, `later` и `failLater` уже в нём. Задания 6 и 7 — в «Табеле» из раздела 15 вместе с исправлением формы (папка `day-30/tabel`), задание 8 — в копии списка дел дня 29 (папка `day-30/todo`).</Subtitle>

## Разминка

<Task title="1. Порядок вывода" level="easy" time="6">
<Goal>предсказывать, когда сработают таймеры.</Goal>

Не запуская, запишите, в каком порядке появятся буквы. Потом проверьте в консоли.

```js
console.log("А");
setTimeout(() => console.log("Б"), 200);
setTimeout(() => console.log("В"), 0);
console.log("Г");
setTimeout(() => console.log("Д"), 100);
```

<Hint>
Сначала выполняется весь обычный код, потом функции таймеров — по времени
срабатывания, а не по порядку строк.
</Hint>

<Criteria>
- порядок записан до запуска и сверен с консолью;
- объяснено, почему «В» с задержкой 0 не напечаталась сразу после «А»;
- в начало добавлена строка `const start = Date.now();`, а перед последней —
  `while (Date.now() - start < 300) {}`: записан новый порядок и объяснено,
  почему две буквы поменялись местами.
</Criteria>
</Task>

<Task title="2. Обратный отсчёт" level="easy" time="7">
<Goal>повторять действие и вовремя остановиться.</Goal>

В абзаце `message` показывайте 5, 4, 3, 2, 1 — по числу в секунду, а затем
«Время!». Интервал останавливает сам себя.

<Hint>
`clearInterval` можно вызвать внутри функции интервала: к этому моменту
номер уже лежит в переменной.
</Hint>

<Criteria>
- через 5 секунд на странице «Время!», через 10 — по-прежнему «Время!»;
- после остановки переменная со счётом равна 0 и больше не меняется;
- `clearInterval` на время убран — объяснено, почему на странице этого не
  видно, и доказано консолью, что интервал всё ещё работает.
</Criteria>
</Task>

<Task title="3. Первая цепочка" level="easy" time="7">
<Goal>получить результат промиса и обработать ошибку.</Goal>

Из `later("  мерет  ", 500)` получите в консоли «МЕРЕТ» цепочкой
из трёх `then`: убрать пробелы, перевести в верхний регистр, напечатать. Добавьте
`catch`, который печатает текст ошибки, и `finally` с «готово». Потом
замените `later` на `failLater("Сервер спит", 500)`.

<Hint>
Каждый шаг получает результат предыдущего и возвращает новый. `trim` и
`toUpperCase` — день 16.
</Hint>

<Criteria>
- промис из `later` записан в переменную: записано его состояние сразу и
  через полсекунды, и объяснено, почему значение в нём осталось с пробелами;
- с `failLater` напечатано «Сервер спит» и «готово», а первый `then`
  не выполнился — доказано строкой `console.log` внутри него;
- «готово» напечатано в обоих случаях.
</Criteria>
</Task>

## Основные задания

<Task title="4. Точный секундомер" level="medium" time="12">
<Goal>считать время по часам, а не по щелчкам таймера.</Goal>

Секундомер из раздела 6 считает щелчки интервала и потому отстаёт, когда браузер занят.
Перепишите его: на «Старт» запоминайте `Date.now()`, интервал только обновляет
часы, а время считается как разница. «Стоп» и новый «Старт» продолжают с того же места,
«Сброс» обнуляет.

<Hint>
Нужны две переменные: момент последнего «Старт» и сколько миллисекунд набежало до
прошлого «Стоп». На часах — их сумма, делённая на 1000, с `toFixed(1)`.
Второй «Старт» не должен запускать второй интервал — раздел 7.
</Hint>

<Criteria>
- «Старт», 2 секунды, «Стоп», пауза, «Старт», ещё секунда, «Стоп» — на часах 3.0;
- во время счёта браузер занят в консоли циклом из раздела 8 на секунду: через
  2 секунды после «Старт» старый секундомер показал около 1.1, а новый — около 2.1;
- повторный «Старт» на ходу ничего не ускоряет;
- объяснено, зачем интервал вообще нужен, если время берётся из `Date.now()`.
</Criteria>
</Task>

<Task title="5. Своя функция с промисом" level="medium" time="13">
<Goal>обернуть «данные придут позже» в промис — так, как это делает сервер.</Goal>

Напишите `loadStudent(name)`: через 500 мс промис выполняется объектом студента
из массива `group`, а если такого нет — отклоняется с ошибкой
«Нет студента: имя». Пробелы по краям имени не мешают. Потом напишите
`averageOf(name)`: она печатает средний балл с двумя знаками или текст ошибки,
а в конце в любом случае — «запрос закончен».

<Example>
```js
const group = [
  { name: "Аман", marks: [5, 4, 4] },
  { name: "Мерет", marks: [3, 3, 4] },
  { name: "Сапар", marks: [5, 5, 4, 5] },
];

averageOf("Мерет");   // через 500 мс: Мерет: 3.33, затем «запрос закончен»
averageOf("Ильяс");   // через 500 мс: Нет студента: Ильяс, затем «запрос закончен»
```
</Example>

<Hint>
Внутри `new Promise` — `setTimeout`, внутри таймера — `find`
из дня 20 и ровно один из двух вызовов: `resolve(student)` или
`reject(new Error(…))`. Среднее — через `reduce`.
</Hint>

<Criteria>
- оба примера дают указанное, а «&nbsp;&nbsp;Сапар&nbsp;» — «Сапар: 4.75»;
- `loadStudent("Мерет")` вызвана в консоли без `then` — записано
  состояние промиса сразу и через 500 мс;
- `reject` на время заменён на `throw` — записано, что показала
  консоль и в каком состоянии остался промис, объяснено почему;
- объяснено, чем `loadStudent` похожа на запрос к серверу, который будет на дне 31.
</Criteria>
</Task>

<Task title="6. «Табель»: подсветка и сообщение" level="medium" time="12">
<Goal>отличать таймеры, которые нужно отменять, от тех, которые не нужно.</Goal>

Новая строка, добавленная формой, две секунды подсвечена классом `new`, потом
подсветка снимается. Сообщение об ошибке формы исчезает через три секунды после
последней ошибки, а после успешного добавления — сразу.

<Hint>
У каждой новой строки свой таймер, и отменять его не нужно. У сообщения — один таймер
на всех: номер в переменной снаружи функции `fail` и `clearTimeout`
перед новым, как во `flash` из раздела 5. Оформление:
`.new { background: #fef08a; }`.
</Hint>

<Criteria>
- добавлен Ильяс, через секунду Айна: подсветка Ильяса гаснет через 2 секунды после
  его добавления, Айны — через 2 секунды после её;
- две ошибки с разницей в 2 секунды: вторая держится полные 3 секунды;
- успешное добавление сразу убирает сообщение;
- объяснено, почему строкам `clearTimeout` не нужен, а сообщению нужен.
</Criteria>
</Task>

<Task title="7. «Табель»: кнопка «Обновить»" level="medium" time="13">
<Goal>повторять загрузку и не ломать данные.</Goal>

Над формой — кнопка «Обновить». Она загружает данные заново, как при открытии страницы:
«Загрузка…», а через секунду — исходные пять студентов; добавленные формой пропадают,
потому что «сервер» о них не знает. Пока идёт загрузка, кнопка и форма спрятаны.

<Hint>
Вынесите цепочку из раздела 15 в функцию `load()` и вызывайте её при открытии
и по щелчку. Старое убирайте только в `then`, когда новые данные уже пришли:
`reports.splice(0)` очищает массив, `tbody.textContent = ""` — таблицу.
</Hint>

<Criteria>
- добавлен Ильяс («Отличников: 3 из 6»), «Обновить» — через секунду пять строк
  и «Отличников: 2 из 5»;
- во время загрузки кнопки и формы не видно, а старые строки на месте;
- если `loadSaved` отдаёт `saved.slice(0, 40)`, после «Обновить»
  в итоге ошибка, а шесть старых строк остались;
- объяснено, почему `reports` очищается через `splice`, а не
  присваиванием нового массива.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Отменить удаление" level="hard" time="10">
<Goal>дать пять секунд передумать.</Goal>

В списке дел после «✕» под списком появляется «Удалено: «текст» Отменить». Пять секунд
дело можно вернуть на прежнее место, потом сообщение исчезает. Новое удаление заменяет
прошлое: вернуть можно только последнее.

<Hint>
Удалённое — тоже данные: `let undo = null` или `{ task, index }`,
а сообщение показывает и прячет `render`. Позицию запомните через
`indexOf` до удаления, вернуть на место — `splice(index, 0, task)`
из дня 19.
</Hint>

<Criteria>
- «✕» у «Сделать задания дня 28», через 2 секунды «Отменить» — дело снова второе, с тем же `id` 2;
- без «Отменить» через 5 секунд сообщения нет, и вернуть дело нельзя;
- два удаления с разницей в 3 секунды: сообщение про второе, и держится оно 5 секунд от второго;
- удаление и возврат при фильтре «Активные» тоже работают.
</Criteria>
</Task>

<Task title="9. Шесть подвохов" level="hard" time="10">
<Goal>собрать вместе всё, что сегодня ведёт себя неожиданно.</Goal>

Каждая строка делает не то, что, видимо, хотел автор. Для каждой запишите предсказание:
что и когда появится в консоли.

```js
console.log(1, typeof setTimeout(() => {}, 0));                     // 1
setTimeout(console.log("2"), 100);                                  // 2
const p = later(3, 100);
console.log(p);                                                     // 3
p.then((x) => { x * 10; }).then((y) => console.log(y));             // 4
Promise.reject(new Error("пять")).finally(() => console.log("5"));  // 5
new Promise(() => {                                                 // 6
  setTimeout(() => { throw new Error("шесть"); }, 0);
}).catch(() => console.log("6: поймали"));
```

<Hint>
Ни одна строка не останавливает остальные: ошибка в одной не мешает следующим.
В двух строках ошибка так и останется непойманной.
</Hint>

<Criteria>
- предсказания записаны до запуска;
- для строк 5 и 6 записан точный текст красных сообщений в консоли;
- для каждой строки объяснено, откуда взялся результат;
- все шесть переписаны так, чтобы делать то, что хотел автор.
</Criteria>
</Task>
