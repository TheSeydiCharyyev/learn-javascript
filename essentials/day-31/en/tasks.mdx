# Day 31. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. We open everything through Live Server. Tasks 1–5 and 9 are done on the group page from the lecture (the folder `day-31/group`: `index.html`, `app.js`, `group.json` from section 2). Task 6 is done in the to-do list with saving from section 14 (the folder `day-31/todo`), tasks 7 and 8 in the “Report card” from section 15 (the folder `day-31/tabel`, with `students.json` next to it).</Subtitle>

## Warm-up

<Task title="1. The first request" level="easy" time="6">
<Goal>see a request and a response with your own eyes.</Goal>

In the console of the group page get the response to `fetch("group.json")` and study it:
the status, `ok`, the `content-type` header, the body as a string and as data. Find
the same request on the Network tab.

<Hint>
A header is read like this: `response.headers.get("content-type")`. Reading the body
a second time needs a new request — the body is read once.
</Hint>

<Criteria>
- the `status`, `ok` and `content-type` of the response are written down;
- the exact text of the error on a second `json()` on the same response is written down;
- the status and the body of the response are found on the Network tab;
- the page is opened with a double click — it is written down what the console showed for the same request.
</Criteria>
</Task>

<Task title="2. Three troubles" level="easy" time="7">
<Goal>tell a server error, a network failure and broken data apart.</Goal>

Cause three troubles in turn and for each one write down where it is visible: whether
`fetch` was rejected, what `ok` and `status` are, what `json()` gave,
which red line is in the console. The troubles: a typo in the file name; a stopped Live Server;
an extra comma after the last student in `group.json`.

<Hint>
After `group.json` is saved, Live Server reloads the page by itself — repeat
the request in the console anew. Do not forget to put the file back in order.
</Hint>

<Criteria>
- for each trouble a row of the table from section 6 of the lecture is filled in;
- for the extra comma the text of the `SyntaxError` is written down, and it is explained which character caused it;
- it is explained why `fetch` was not rejected on the typo.
</Criteria>
</Task>

<Task title="3. Storage in the console" level="easy" time="7">
<Goal>learn to write, read and look at storage.</Goal>

Make the visit counter from section 10 on the group page. Save a “student”
object through `JSON.stringify` and read it back. Print all the
keys of the storage to the console with a loop over `localStorage.length` and `key(i)`. Look at
all of this on the Application tab → Local Storage.

<Criteria>
- the counter grows with every reload of the page;
- the object after the round trip “write — read” is the same, the array of marks is in place;
- `sessionStorage` is checked in a new tab — it is written down what stayed in which storage;
- it is explained why the keys in the loop’s output are not necessarily in the order they were written.
</Criteria>
</Task>

## Main tasks

On the “Load” button show a list: the name and the average mark with two digits, and for whoever

</Task>

<Task title="5. A search that waits" level="medium" time="13">
<Goal>join the delayed timer of day 30, a request and an address with data.</Goal>

Add a search field. 300 ms after the last letter build the address
`group.json?name=…` with the typed text, show it on the page and send
the request. From the response keep those whose name contains what was typed, ignoring case, and
write “Found: N”. Live Server does not read the parameter and gives the whole file — a real
server would filter by itself, while we filter on the page.

<Hint>
A timer and `clearTimeout` — as in the autosave of day 30; the timer’s function
can be made `async`. Text goes into an address only through `encodeURIComponent`.
</Hint>

<Criteria>
- “ar” — Gülnar and Sapar, “Found: 2”, the address `group.json?name=ar`;
- “Sapar”, typed without pauses, — exactly one request on the Network tab;
- “Gülnar & Aman” — `%26` in the address, “Found: 0”;
- it is explained what the server would see if the text were put into the address without `encodeURIComponent`.
</Criteria>
</Task>

<Task title="6. The to-do list: the filter and “Start over”" level="medium" time="12">
<Goal>decide what to keep and where, and remove only your own.</Goal>

In the to-do list with saving from section 14 remember the filter too: after a reload
the selected one stays. Add a “Start over” button: it brings back the three example tasks

Move the three examples into a constant `EXAMPLES` and take a copy: `EXAMPLES.map((t) => ({ ...t }))`

</Hint>

<Criteria>
- “Active”, the page reloaded — “Active” is highlighted, there are two tasks in the list;
- after “Start over” — the three example tasks, “All”, `nextId` equals 4;
- a key of another project (for example, `group:visits` from task 3) is in place after “Start over”;
- it is explained why the filter is kept in `localStorage` or in `sessionStorage` — the choice is justified.
</Criteria>
</Task>

<Task title="9. Six catches" level="hard" time="10">
<Goal>gather together everything that behaves unexpectedly today.</Goal>

Run one line at a time in the console of the group page. For each one first write down
a prediction.

```js
const r = await fetch("grup.json"); console.log(r.ok, r.status);                       // 1
localStorage.setItem("marks", [5, 4]); console.log(localStorage.getItem("marks").length); // 2
async function f() { return 5; } console.log(f() + 1);                                  // 3
console.log(encodeURI("?q=a&b"));                                                       // 4
console.log(JSON.parse(localStorage.getItem("no")));                                    // 5
const data = (await fetch("group.json")).json; console.log(typeof data);                // 6
```

<Hint>
Not a single line fails with an error — and that is a catch too: a wrong value silently
goes on.
</Hint>

<Criteria>
- the predictions are written down before running;
- for each line it is explained where the answer came from;
- all six are rewritten to do what the author apparently wanted;
- it is explained why the lines with `await` work in the console, but not in `app.js`.
</Criteria>
</Task>
