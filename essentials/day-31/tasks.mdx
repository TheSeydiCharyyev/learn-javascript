# День 31. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Всё открываем через Live Server. Задания 1–5 и 9 — на странице группы из лекции (папка `day-31/group`: `index.html`, `app.js`, `group.json` из раздела 2). Задание 6 — в списке дел с сохранением из раздела 14 (папка `day-31/todo`), задания 7 и 8 — в «Табеле» из раздела 15 (папка `day-31/tabel`, рядом с ним — `students.json`).</Subtitle>

## Разминка

<Task title="1. Первый запрос" level="easy" time="6">
<Goal>увидеть запрос и ответ своими глазами.</Goal>

В консоли страницы группы получите ответ на `fetch("group.json")` и изучите его:
статус, `ok`, заголовок `content-type`, тело строкой и как данные. Найдите
этот же запрос на вкладке Network.

<Hint>
Заголовок читается так: `response.headers.get("content-type")`. Для второго
чтения тела нужен новый запрос — тело читается один раз.
</Hint>

<Criteria>
- записаны `status`, `ok` и `content-type` ответа;
- записан точный текст ошибки при втором `json()` на том же ответе;
- на вкладке Network найдены статус и тело ответа;
- страница открыта двойным щелчком — записано, что показала консоль при том же запросе.
</Criteria>
</Task>

<Task title="2. Три беды" level="easy" time="7">
<Goal>различать ошибку сервера, сбой сети и испорченные данные.</Goal>

Устройте по очереди три беды и для каждой запишите, где она видна: отклонился ли
`fetch`, какие `ok` и `status`, что дал `json()`,
какая красная строка в консоли. Беды: опечатка в имени файла; остановленный Live Server;
лишняя запятая после последнего студента в `group.json`.

<Hint>
После сохранения `group.json` Live Server сам обновит страницу — повторите
запрос в консоли заново. Не забудьте вернуть файл в порядок.
</Hint>

<Criteria>
- для каждой беды заполнена строка таблицы из раздела 6 лекции;
- для лишней запятой записан текст `SyntaxError` и объяснено, какой символ его вызвал;
- объяснено, почему при опечатке `fetch` не отклонился.
</Criteria>
</Task>

<Task title="3. Хранилище в консоли" level="easy" time="7">
<Goal>научиться записывать, читать и смотреть хранилище.</Goal>

Сделайте на странице группы счётчик посещений из раздела 10. Сохраните объект
«студент» через `JSON.stringify` и прочитайте обратно. Выведите в консоль все
ключи хранилища циклом по `localStorage.length` и `key(i)`. Посмотрите
всё это на вкладке Application → Local Storage.

<Criteria>
- счётчик растёт с каждым обновлением страницы;
- объект после круга «записать — прочитать» тот же, массив оценок на месте;
- `sessionStorage` проверен в новой вкладке — записано, что осталось в каком хранилище;
- объяснено, почему ключи в выводе цикла стоят не обязательно в порядке записи.
</Criteria>
</Task>

## Основные задания

<Task title="4. Список группы со средними" level="medium" time="12">
<Goal>получить данные с сервера и показать их на странице.</Goal>

По кнопке «Загрузить» покажите список: имя и средний балл с двумя знаками, а у кого
оценок нет — «нет оценок». Пока идёт загрузка — «Загрузка…» и кнопки не видно; при ошибке —
понятное сообщение.

<Example>
```js
// Аман — 4.33
// Мерет — 3.33
// Гүлнар — нет оценок
// Сапар — 4.75
// Огулджан — 4.50
```
</Example>

<Hint>
Возьмите слушатель из раздела 8 лекции и поменяйте только текст пункта. Среднее —
`reduce` из дня 20, делённый на число оценок; пустой массив проверьте до деления.
</Hint>

<Criteria>
- пять пунктов в точности как в примере;
- при опечатке в адресе — «Не удалось загрузить: Сервер ответил 404», и кнопка снова видна;
- при остановленном Live Server — «Не удалось загрузить: Failed to fetch»;
- объяснено, что получилось бы у Гүлнар без проверки пустого массива.
</Criteria>
</Task>

<Task title="5. Поиск, который ждёт" level="medium" time="13">
<Goal>соединить отложенный таймер дня 30, запрос и адрес с данными.</Goal>

Добавьте поле поиска. Через 300 мс после последней буквы соберите адрес
`group.json?name=…` с набранным текстом, покажите его на странице и отправьте
запрос. Из ответа оставьте тех, в чьём имени есть набранное без учёта регистра, и
напишите «Найдено: N». Live Server параметр не читает и отдаёт весь файл — настоящий
сервер отфильтровал бы сам, а мы фильтруем на странице.

<Hint>
Таймер и `clearTimeout` — как в автосохранении из дня 30; функцию таймера
можно сделать `async`. Текст в адрес — только через `encodeURIComponent`.
</Hint>

<Criteria>
- «ар» — Гүлнар и Сапар, «Найдено: 2», адрес `group.json?name=%D0%B0%D1%80`;
- «Сапар», набранный без пауз, — ровно один запрос на вкладке Network;
- «Гүлнар & Аман» — в адресе `%26`, «Найдено: 0»;
- объяснено, что увидел бы сервер, если бы текст вставили в адрес без `encodeURIComponent`.
</Criteria>
</Task>

<Task title="6. Список дел: фильтр и «Начать заново»" level="medium" time="12">
<Goal>решать, что и где хранить, и убирать только своё.</Goal>

В списке дел с сохранением из раздела 14 запоминайте ещё и фильтр: после обновления
остаётся выбранный. Добавьте кнопку «Начать заново»: она возвращает три дела для примера
и выбирает «Все».

<Hint>
Три примера вынесите в константу `EXAMPLES` и берите копию: `EXAMPLES.map((t) => ({ ...t }))`
— иначе отметки поменяют сами примеры. Свои ключи удаляют через `removeItem`, не через `clear()`.
</Hint>

<Criteria>
- «Активные», обновили страницу — выделена «Активные», в списке два дела;
- после «Начать заново» — три дела для примера, «Все», `nextId` равен 4;
- ключ другого проекта (например, `group:visits` из задания 3) после «Начать заново» на месте;
- объяснено, почему фильтр хранится в `localStorage` или в `sessionStorage` — выбор обоснован.
</Criteria>
</Task>

<Task title="7. «Табель»: кнопка «Сбросить»" level="medium" time="13">
<Goal>выбираться из испорченного хранилища без консоли.</Goal>

Над формой — кнопка «Сбросить». Она забывает сохранённое и заново загружает данные
с сервера, не обновляя страницу.

<Hint>
Удалить свой ключ, очистить `reports` через `splice(0)` и таблицу, снова
показать «Загрузка…» и вызвать `start()` из раздела 15. Сохранит её уже
`updateSummary`.
</Hint>

<Criteria>
- добавлен Ильяс, страница обновлена — шесть строк; «Сбросить» — пять строк и «Отличников: 2 из 5»;
- после «Сбросить» и обновления страницы по-прежнему пять строк;
- в хранилище записан `"[object Object]"` — «Табель» показывает ошибку, а «Сбросить» его чинит;
- объяснено, почему после «Сбросить» в хранилище снова есть ключ `tabel:reports`.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Черновик формы" level="hard" time="10">
<Goal>выбрать хранилище под задачу.</Goal>

Набранное в форме «Табеля» имя и оценки переживают обновление страницы, но в новой
вкладке форма пустая. После успешного добавления черновик забывается.

<Hint>
Одно событие `input` на всей форме ловит ввод в оба поля — оно всплывает
(день 27). Черновик — объект из двух строк через `JSON.stringify`.
</Hint>

<Criteria>
- набрали «Ильяс» и «5 4», обновили — поля заполнены;
- та же страница в новой вкладке — поля пустые;
- после «Добавить» и обновления поля пустые, а строк шесть;
- объяснено, почему здесь `sessionStorage`, а для отчётов — `localStorage`.
</Criteria>
</Task>

<Task title="9. Шесть подвохов" level="hard" time="10">
<Goal>собрать вместе всё, что сегодня ведёт себя неожиданно.</Goal>

Запускайте по строке в консоли страницы группы. Для каждой сначала запишите
предсказание.

```js
const r = await fetch("grup.json"); console.log(r.ok, r.status);                       // 1
localStorage.setItem("marks", [5, 4]); console.log(localStorage.getItem("marks").length); // 2
async function f() { return 5; } console.log(f() + 1);                                  // 3
console.log(encodeURI("?q=a&b"));                                                       // 4
console.log(JSON.parse(localStorage.getItem("нет")));                                   // 5
const data = (await fetch("group.json")).json; console.log(typeof data);                // 6
```

<Hint>
Ни одна строка не падает с ошибкой — и это тоже подвох: неверное значение молча
идёт дальше.
</Hint>

<Criteria>
- предсказания записаны до запуска;
- для каждой строки объяснено, откуда взялся ответ;
- все шесть переписаны так, чтобы делать то, что, видимо, хотел автор;
- объяснено, почему строки с `await` работают в консоли, но не в `app.js`.
</Criteria>
</Task>
