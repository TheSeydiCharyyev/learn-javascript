# Day 32. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 build the catalog from the lecture in the folder `day-32/catalog` stage by stage, checking each stage in the console. Tasks 4–8 are improvements of the same catalog: do them in turn, and after each one check that the old features did not break. Task 9 needs a copy of the folder after task 3. ## Main tasks

<Task title="4. Protecting storage" level="medium" time="12">
<Goal>not let broken storage break the page.</Goal>

First, on the finished catalog, write into storage in turn `"[object Object]"`
and `"5"` and reload the page — write down what happened. Then replace the reading of
the favorites with a function `readFavorites()`: if storage does not hold an array or it cannot be
parsed, it returns an empty array.

<Hint>
`JSON.parse` goes inside `try...catch` from day 11. Whether it is an array —
`Array.isArray` from day 19.
</Hint>

<Criteria>
- before the protection: with `"5"` the page says “Could not load the catalog: favorites.includes is not a function”, with `"[object Object]"` “Loading…” hangs;
- after the protection both cases give eight cards, and storage becomes `"[]"`;
- `"[99]"` stays in storage after the protection and gets in nobody’s way;
- it is explained why with `"5"` the error appeared in `#error`, and with `"[object Object]"` it did not.
</Criteria>
</Task>

<Task title="5. Sorting" level="medium" time="12">
<Goal>add one more choice and carry it through `render`.</Goal>

Below the genres — three buttons: “as in the catalog”, “newest first”, “by title”. The choice
is kept in the variable `sort` and works together with the search, the genre and the favorites.

<Hint>
In `render` first pick the visible ones, then sort a copy with
`toSorted` (day 20). Strings are compared with `<` (day 7):
`(a, b) => (a.title < b.title ? -1 : 1)`. For our titles this is enough;
sorting by all the rules of a language (capital letters, letters like é) is in course 2.
</Hint>

<Criteria>
- “by title” — the first is “Crime and Punishment”, the last is “War and Peace”;
- “newest first” — the first is “Harry Potter and the Philosopher's Stone”, the last is “The Captain's Daughter”;
- “newest first” and the genre “fantasy” — “Harry Potter…”, then “The Hobbit”;
- after sorting the order in `books` is the same — it is explained what would break with `sort` instead of `toSorted`.
</Criteria>
</Task>

</Task>

<Task title="9. Three complaints" level="hard" time="10">
<Goal>look for a mistake starting from the symptom.</Goal>

A classmate sent their catalog and three complaints:

- “‘hobbit’ is found, but ‘Hobbit’ is not.”
- “After every action there are more genre buttons.”
- “A star cannot be removed.”

Their `app.js` differs from the program of the lecture in the fragments below; besides,
the call of `makeGenreButtons` was removed from `load`. Put them into a copy of the catalog
and reproduce each complaint.

```js
// in the search listener
query = search.value.trim();

// in render, after the cards
makeGenreButtons();

// in the list listener
if (favorites.includes(id)) {
  favorites.filter((f) => f !== id);
} else {
  favorites.push(id);
}
```

<Hint>
For each complaint ask the console: `query`, `genres.children.length`,
`favorites`. The data will tell which line is to blame.
</Hint>

<Criteria>
- each complaint is reproduced and matched with its line;
- it is written down how many genre buttons there are after opening and after the first letter of the search;
- it is explained why `filter` without an assignment changes nothing;
- all three places are fixed, the complaints do not repeat any more.
</Criteria>
</Task>
