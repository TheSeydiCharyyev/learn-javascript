1. Четыре дня итогового проекта

2. Идея: как выбрать

Хорошая идея для итогового проекта отвечает четырём условиям. Есть список данных — книги, слова, блюда, события: их приложение показывает. Человек что-то делает — ищет, отмечает, выбирает. Что-то запоминается между загрузками. И вам самим интересно: два дня работы над скучной идеей тянутся вдвое дольше.

У первых шести данные приходят с сервера, как в каталоге дня 32. У двух последних данные создаёт сам человек, как в списке дел дня 29. Годится и то и другое. Можно взять идею из таблицы, можно придумать свою — лишь бы она прошла по четырём условиям.

Идея бывает и слишком маленькой. «Кнопка, которая показывает случайную цитату», — это упражнение, а не проект: в нём нет ни поиска, ни выбора, ни памяти. Добавьте к ней избранные цитаты и фильтр по автору — и получится проект.

3. Замысел одним предложением

Прежде чем расписывать детали, замысел проверяют одним предложением: кому приложение, что оно делает и зачем. Если в одно предложение не влезает — идея расплывчата или слишком велика.

«Карточки слов» — для школьника, который учит английский: показывают слово, по щелчку — перевод; школьник отмечает «знаю» или «повторить», а выученные слова больше не показываются, даже после обновления страницы.

В этом предложении уже спрятан почти весь план. «Показывают слово» — нужны данные и функция показа. «По щелчку — перевод» — слушатель и переменная «перевёрнута ли карточка». «Отмечает» — ещё два слушателя. «Даже после обновления» — хранилище. Каждое слово замысла станет строкой в таблице возможностей.

Для сравнения — замысел из другой строки таблицы идей: «Меню кафе — для посетителя, который выбирает обед: показывает блюда с ценами, ищет по названию, собирает заказ и считает сумму; заказ не пропадает, если случайно закрыть вкладку». Кому — посетителю; что — меню, поиск, заказ, сумма; зачем — выбрать обед. Все три части на месте.

4. Что должно уметь приложение

Возможности записывают таблицей, как на днях 29 и 32. Главное правило: у каждой строки есть способ проверки, который выполнит человек, ни разу не видевший ваш код.

№ВозможностьКак проверить
1загрузить слова с сервера«Загрузка…», затем первое слово
2сообщить об ошибке загрузкифайл переименован — понятный текст
3перевернуть карточкущелчок по карточке — перевод, ещё щелчок — слово
4«Знаю»слово исчезает из колоды, счётчик растёт
5«Повторить»показывается следующее слово, это вернётся позже
6выбрать темукнопки тем из данных, в колоде только слова темы
7счётчик «Выучено: N из M»меняется после каждого «Знаю»
8помнить выученноеобновили страницу — выученных слов в колоде нет
9начать сначалакнопка возвращает все слова

Две дополнительные строки не менее важны. Потом, если останется время: перемешать колоду, режим «перевод → слово». Не делает совсем: не добавляет слова (их меняет только владелец файла), не произносит их (это курс 4). Список «потом» — ваш запас: если на дне 35 останется час, будет что добавить, а если не останется, приложение всё равно готово.

5. Данные на сервере

Папка day-33/cards, открываем через Live Server. Данные — файл words.json, восемь слов трёх тем:

[
  { "id": 1, "word": "book", "translation": "книга", "topic": "школа" },
  { "id": 2, "word": "teacher", "translation": "учитель", "topic": "школа" },
  { "id": 3, "word": "lesson", "translation": "урок", "topic": "школа" },
  { "id": 4, "word": "bread", "translation": "хлеб", "topic": "еда" },
  { "id": 5, "word": "water", "translation": "вода", "topic": "еда" },
  { "id": 6, "word": "apple", "translation": "яблоко", "topic": "еда" },
  { "id": 7, "word": "house", "translation": "дом", "topic": "дом" },
  { "id": 8, "word": "window", "translation": "окно", "topic": "дом" }
]

Поля выбираем по таблице возможностей: word и translation нужны карточке, topic — кнопкам тем, id — хранилищу, чтобы запомнить выученные. Лишних полей нет: каждое чем-то пользуется. Данных для начала мало — восемь слов, — зато по ним удобно проверять всё руками. Дописать ещё сто можно в любой момент, код от этого не изменится.

Сколько данных нужно для начала? Столько, чтобы каждую возможность было чем проверить: не меньше двух тем (иначе выбирать нечего), в каждой несколько слов (иначе колода кончится за два щелчка), хотя бы одна тема меньше других. Шесть–десять объектов обычно хватает.

6. Проверить данные до кода

Файл данных пишут руками, а руки ошибаются. Поэтому данные проверяют сразу, пока в app.js нет ни строчки. Сначала посмотрим на них глазами — таблицей из дня 2:

const data = await (await fetch("words.json")).json();
console.table(data);   // таблица: восемь строк, столбцы id, word, translation, topic
data.length;           // 8

Глазами восемь строк проверить можно, сто — уже нет. Для этого есть console.assert из дня 2: он молчит, если условие верно, и выводит красную строку с пометкой Assertion failed и нашим текстом, если нет. Первая проверка — у каждого слова есть все четыре поля:

console.assert(
  data.every((w) => w.id && w.word && w.translation && w.topic),
  "у слова не хватает поля"
);
// тишина — все поля на месте

Вторая — номера не повторяются. Слово с номером стоит на своём месте, если findIndex находит этот номер впервые именно там:

console.assert(
  data.every((w, i) => data.findIndex((x) => x.id === w.id) === i),
  "номера повторяются"
);
// тишина — номера разные

Третья — какие темы есть и сколько в каждой слов. Приём «без повторов» из дня 32:

const names = [];
data.forEach((w) => {
  if (!names.includes(w.topic)) names.push(w.topic);
});
names;   // ["школа", "еда", "дом"]
names.map((t) => `${t}: ${data.filter((w) => w.topic === t).length}`);
// ["школа: 3", "еда: 3", "дом: 2"]

Пять минут таких проверок экономят час поисков потом. Ошибка в данных, найденная сейчас, — это правка одной строки в файле. Найденная на дне 35, она выглядит как ошибка в коде, и искать её будут в коде.

7. Разбор: данные «на глаз»

Вот тот же файл, набранный в спешке, — words-bad.json. На первый взгляд всё в порядке. Запустим те же проверки:

const bad = await (await fetch("words-bad.json")).json();
// те же две проверки console.assert — на bad вместо data:
// Assertion failed: у слова не хватает поля
// Assertion failed: номера повторяются
// а список тем:
// ["школа", "еда", "Еда", "дом"]

Шаг 1. Что не так? Две красные строки и лишняя тема. Какое именно слово без поля, подскажет find:

bad.find((w) => !w.translation);
// {id: 8, word: 'window', translation: '', topic: 'дом'}

Шаг 2. Три ошибки — три будущих симптома. Пустой перевод — карточка «window» перевернётся в пустоту. Повтор номера 5 у «water» и «apple» — «Знаю» у одного слова выучит оба: избранное и выученное хранят номера. «Еда» с большой буквы — лишняя кнопка темы, и в «еда» окажутся два слова вместо трёх. Когда функция deck из раздела 12 будет готова, оба симптома видны прямо в консоли:

words = bad;
learned = [5];                // «Знаю» у water
deck().map((w) => w.word);   // ["book", "teacher", "lesson", "bread", "house", "window"] — ушли два слова

learned = [];
topic = "еда";
deck().map((w) => w.word);   // ["bread", "apple"] — water спряталась в теме «Еда»

Шаг 3. Чиним — и оставляем сторожа. Исправить файл мало: завтра его поправят снова. Проверки переносим в сам app.js, в функцию, которая выполняется после каждой загрузки. Пока данные в порядке, она молчит:

function checkData() {
  console.assert(words.length > 0, "слов нет");
  console.assert(words.every((w) => w.id && w.word && w.translation && w.topic), "у слова не хватает поля");
  console.assert(words.every((w, i) => words.findIndex((x) => x.id === w.id) === i), "номера повторяются");
}

8. Где что живёт

Следующее решение — какие данные хранит программа и где. Метод тот же, что в каталоге: каждому виду данных — своё место.

ДанныеГдеПочему
словасервер: words.jsonобщие для всех, меняет владелец файла
выученныеlocalStorageличный прогресс, нужен и завтра

const KEY = "cards:learned";
let words = [];                                              // придут с сервера
let learned = JSON.parse(localStorage.getItem(KEY)) ?? [];   // номера выученных слов
let topic = "все";                                           // выбранная тема
let position = 0;                                            // какая карточка колоды сейчас
let flipped = false;                                         // виден ли перевод

Шесть строк — а в них уже записаны все решения таблицы. Переменные position и flipped сегодня не понадобятся, но объявить их стоит сейчас: так видно, что замысел целиком помещается в данные. Если для какой-то возможности не нашлось переменной — план не додуман. Проверка шага:

[words.length, learned, topic];   // [0, [], "все"]

9. Макет и рама страницы

Макет — рисунок будущей страницы. Карандаш и бумага подходят лучше любой программы: пять минут, и видно, что где стоит. Для «Карточек»:

Подписи справа — самое ценное в макете. У каждой части страницы видно, из каких данных она строится и какой слушатель её меняет. Часть без подписи — сигнал: для неё нет данных.

Макет рисуют узким, как экран телефона: на дне 35 приложение проверят именно на нём. Всё, что влезло в узкую колонку, на широком экране встанет само, а наоборот — нет.

10. Каркас: функции-заглушки

Теперь — список функций. Их не пишут целиком, а объявляют заглушками: имя, одна строка о том, что функция делает, и простейшее тело. Такой каркас показывает устройство всей программы ещё до того, как она заработала:

// колода: слова выбранной темы, которые ещё не выучены
function deck() {
  return [];   // заглушка — того же типа, что настоящий ответ
}

// кнопки тем из данных — как жанры на дне 32
function makeTopicButtons() {
  // день 34
}

// страница из данных
function render() {
  // день 33, раздел 12
}

async function load() {
  // день 33, раздел 12
}

load();

Каркас уже можно открыть в браузере: ошибок нет, просто ничего не происходит. А список функций становится списком задач: каждую заглушку предстоит заменить настоящим телом.

Так же объявляют и слушатели — по одному на каждую строку таблицы возможностей, где человек что-то делает. Внутри — комментарий-план в схеме дня 29: что поменять в данных и позвать render:

card.addEventListener("click", () => {
  // день 34: flipped = !flipped; render();
});
knowButton.addEventListener("click", () => {
  // день 34: номер карточки — в learned, сохранить, render();
});
againButton.addEventListener("click", () => {
  // день 34: position — на следующую карточку, render();
});

Щёлкните по карточке — ничего не случится, и ошибок нет: слушатель есть, тела пока нет. Зато комментарии уже записали решения, и на дне 34 останется перевести их в код.

Заглушка должна возвращать то же, что настоящая функция

Заглушка deck возвращает пустой массив, а не «ничего». Разница видна, как только другой код начнёт ею пользоваться. Вот заглушка без return и render, которой уже нужна длина колоды:

function deck() {
  // день 34
}
// на странице после загрузки:
// Не удалось загрузить слова: Cannot read properties of undefined (reading 'length')

Функция без return возвращает undefined (день 12), а у него длины нет. Заглушка, которая возвращает пустой массив, честно говорит «колода пока пуста», и всё, что стоит после неё, работает. Правило: заглушка возвращает значение того же типа — пустой массив, ноль, пустую строку.

11. Проверки до кода

Раз мы знаем, что должна делать deck, можно записать это проверками раньше, чем саму функцию. В консоли страницы с каркасом загрузим слова руками и спросим заглушку:

words = await (await fetch("words.json")).json();
console.assert(deck().length === 8, "в начале — все 8 слов");
learned = [1, 2];
console.assert(deck().length === 6, "выученные не попадают в колоду");
topic = "еда";
console.assert(deck().every((w) => w.topic === "еда"), "только слова темы");
console.assert(deck().length === 3, "в теме «еда» три слова");
// Assertion failed: в начале — все 8 слов
// Assertion failed: выученные не попадают в колоду
// Assertion failed: в теме «еда» три слова

Три красные строки из четырёх — и это хорошо: проверки видят, что функции ещё нет. Но почему молчит третья? Заглушка вернула пустой массив, а every у пустого массива всегда отвечает true — мы видели это на дне 20:

[].every((w) => w.topic === "еда");   // true — у пустого массива нечему не подойти

Проверка «все подходят» ничего не доказывает, если подходить некому. Поэтому рядом с ней стоит проверка длины: вместе они говорят «в колоде три слова, и все — про еду». Хорошие проверки подобраны так, чтобы заглушка их проваливала: иначе они не отличат готовую функцию от пустой.

Проверки, которые можно повторить

Набирать четыре проверки после каждой правки утомительно. Их складывают в функцию — в app.js, рядом с проверяемой. Функция меняет данные на время проверки и возвращает их как было:

function testDeck() {
  const oldLearned = learned;
  const oldTopic = topic;
  learned = [];
  topic = "все";
  console.assert(deck().length === 8, "в начале — все 8 слов");
  learned = [1, 2];
  console.assert(deck().length === 6, "выученные не попадают в колоду");
  topic = "еда";
  console.assert(deck().every((w) => w.topic === "еда"), "только слова темы");
  console.assert(deck().length === 3, "в теме «еда» три слова");
  learned = oldLearned;   // вернуть как было
  topic = oldTopic;
}

Теперь после любой правки deck достаточно набрать в консоли testDeck(). Проверки с числами «8», «6», «3» знают наши данные, поэтому запускают их на учебном words.json: добавите слов — поправьте и числа.

12. Первый рабочий шаг

Теперь заменяем заглушку настоящей функцией. Колода — слова, которых нет среди выученных и которые подходят по теме:

function deck() {
  return words.filter((w) => !learned.includes(w.id) && (topic === "все" || w.topic === topic));
}

Сохраним app.js — Live Server обновит страницу. load пока заглушка, поэтому слова снова загрузим руками и запустим проверки:

words = await (await fetch("words.json")).json();
testDeck();
[learned, topic, deck().length];   // [[], "все", 8] — проверки молчат, данные прежние

Ни одной красной строки, и testDeck вернула всё как было. А колода темы «еда» при выученных 1 и 2:

learned = [1, 2];
topic = "еда";
deck().map((w) => w.word);   // ["bread", "water", "apple"]

Осталось показать первое слово на странице. render пока минимальный: слово первой карточки колоды и счётчик. Переворот, кнопки и темы — задачи дня 34:

function render() {
  const cards = deck();
  card.textContent = cards.length > 0 ? cards[0].word : "Слов нет";
  counter.textContent = `Выучено: ${learned.length} из ${words.length}`;
}
async function load() {
  try {
    const response = await fetch("words.json");
    if (!response.ok) throw new Error(`сервер ответил ${response.status}`);
    words = await response.json();
    checkData();
    makeTopicButtons();
    render();
  } catch (err) {
    error.textContent = `Не удалось загрузить слова: ${err.message}`;
  } finally {
    loading.hidden = true;
  }
}

load — почти слово в слово из каталога дня 32, со сторожем checkData сразу после загрузки. Проверка шага после обновления страницы:

[card.textContent, counter.textContent, loading.hidden];
// ["book", "Выучено: 0 из 8", true]

И сразу проверим хранилище, хотя кнопки «Знаю» ещё нет. Запишем выученные руками:

localStorage.setItem("cards:learned", "[1, 2]");
// обновили страницу:
[card.textContent, counter.textContent];   // ["lesson", "Выучено: 2 из 8"]

«book» и «teacher» выучены, и колода начинается с третьего слова. Значит, чтение хранилища, колода и показ уже работают вместе, — а кнопке «Знаю» на дне 34 останется только записать номер.

Разбор: разметка и код не совпали

Частая ошибка первого шага — опечатка между index.html и app.js: в разметке id="card", а в коде querySelector("#cards").

card;   // null
// в консоли: Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')
// на странице: «Загрузка…» висит, текста ошибки нет

Ошибка всплыла не там, где сделана, а на первом использовании элемента — в каркасе слушателей из раздела 10. Он стоит вне функций, поэтому catch в load её не видит: скрипт просто останавливается, и до вызова load() дело не доходит. Отсюда и зависшая «Загрузка…». Проверка из раздела 9 — «ни одного null» — стоит сразу после поиска элементов именно поэтому: она ловит опечатку в той строке, где её сделали.

13. План задач на дни 34–35

Каркас готов, и каждая заглушка — задача. Остаётся расставить их по порядку и прикинуть время. На каждый день — 90 минут практики. План «Карточек»:

План — тоже данные, и сумму минут удобнее доверить коду, чем голове:

const plan = [
  { day: 34, task: "переворот карточки", minutes: 15 },
  { day: 34, task: "«Знаю» и «Повторить»", minutes: 25 },
  { day: 34, task: "кнопки тем", minutes: 20 },
  { day: 34, task: "сохранение выученных", minutes: 15 },
  { day: 34, task: "«Все выучены» и «Начать сначала»", minutes: 15 },
  { day: 35, task: "проверка на телефоне", minutes: 25 },
  { day: 35, task: "крайние случаи", minutes: 25 },
  { day: 35, task: "перемешать колоду", minutes: 20, later: true },
  { day: 35, task: "чтение чужого кода", minutes: 20 },
];
[34, 35].map((d) => plan.filter((t) => t.day === d).reduce((sum, t) => sum + t.minutes, 0));
// [90, 90] — оба дня помещаются

Поле later отмечает задачу из списка «потом». Если время начнёт кончаться, её выбрасывают первой, — и видно, сколько останется без неё:

plan.filter((t) => t.later).map((t) => t.task);   // ["перемешать колоду"]
plan.filter((t) => !t.later).reduce((sum, t) => sum + t.minutes, 0);   // 160 — запас 20 минут

Порядок задач выбран не случайно. Сначала то, без чего не проверить остальное: без переворота не понять, работает ли «Знаю». То, что можно выбросить, — в конце: если время кончится, пострадает «перемешать», а не «сохранение».

Минуты в плане — прикидка, а не обещание. В конце дня 34 запишите рядом, сколько ушло на деле, и поправьте план дня 35. Разница между «думал» и «вышло» — самое полезное, что можно узнать о себе за эти четыре дня: в следующий раз прикидка будет точнее.

14. Разбор: план, который не проверить

Первый план почти у всех выглядит так: «сделать карточки», «сделать красиво», «доделать всё». Беда не в словах, а в том, что ни одну задачу нельзя закрыть: неясно, когда она готова.

Так не надоТак надо
сделать карточкипереворот: щелчок — перевод, ещё щелчок — слово
сделать красивона телефоне шириной 360 пикселей нет прокрутки вбок
сохранение«Знаю» у «book», обновили — «book» в колоде нет
доделать всёкаждая строка таблицы возможностей проверена руками

Вторая частая беда — слишком большой замысел. Список желаний первого черновика «Карточек» выглядел так:

const wishes = [
  { task: "регистрация и вход", minutes: 120 },
  { task: "чат между учениками", minutes: 150 },
  { task: "рейтинг лучших", minutes: 60 },
  { task: "тёмная тема", minutes: 30 },
  { task: "карточки и переворот", minutes: 40 },
  { task: "сохранение выученных", minutes: 20 },
];
wishes.reduce((sum, t) => sum + t.minutes, 0);   // 420 — в 2,3 раза больше 180 минут двух дней

Проверьте свой замысел той же суммой: если план не помещается в 180 минут двух дней, режьте. Регистрация и чат требуют настоящего сервера — это уже не Essentials. Не качество — объём: сначала то, без чего приложение не работает, остальное — в «потом». Приложение из пяти возможностей, где всё работает, сильнее приложения из пятнадцати, где половина не доделана.

15. Что готово к концу дня

Проверка готовности дня 33 для вашего проекта — те же приёмы, что сегодня, одной пачкой в консоли:

console.assert(words.length > 0, "данные не загрузились");
console.assert(document.querySelector("#card") !== null, "нет рамы для главной части");
console.assert(typeof render === "function", "нет функции показа");
// тишина — день 33 закрыт

Для «Карточек» все три молчат. В вашем проекте имена будут свои, а смысл тот же: данные пришли, рама на месте, каркас есть. Ещё к концу дня должны быть записаны: одно предложение, таблица возможностей со списками «потом» и «не делает», таблица «где что живёт» и план задач с суммой минут.

Завтра, на дне 34, — реализация. Лекция доведёт «Карточки» по этому плану: переворот, «Знаю» и «Повторить», темы, сохранение. На практике вы делаете то же со своим проектом — по своему плану, задача за задачей, с проверкой после каждой.

  1. Каким четырём условиям отвечает хорошая идея итогового проекта?
    Ответ Есть список данных; человек что-то с ними делает; что-то запоминается между загрузками; самому интересно.
  2. Зачем замысел записывают одним предложением?
    Ответ Чтобы проверить, что идея ясна и не слишком велика. Каждое слово предложения потом становится строкой таблицы возможностей.
  3. Почему данные проверяют до первой строки кода?
    Ответ Ошибка в данных, найденная сразу, — правка одной строки файла. Найденная позже, она выглядит как ошибка в коде, и искать её будут не там.
  4. Почему заглушка deck возвращает [], а не ничего?
    Ответ Код, который ею пользуется, ждёт массив. undefined вместо массива даст ошибку Cannot read properties of undefined.
  5. Почему проверка deck().every((w) => w.topic === "еда") прошла на заглушке?
    Ответ every у пустого массива всегда true. Поэтому рядом нужна проверка длины — вместе они проваливаются на заглушке.
  6. Чем плоха задача «сделать красиво»?
    Ответ Её нельзя закрыть: неясно, когда она готова. Задачу записывают так, чтобы было видно, как её проверить: «на ширине 360 пикселей нет прокрутки вбок».
