## 1. Четыре дня итогового проекта {#why}

Все новые темы курса позади. Остались четыре дня, и за них каждый соберёт своё
приложение — от идеи до защиты. Мини-проекты дней 29 и 32 мы строили вместе по готовому
заданию. Теперь задание придумываете вы сами, и это главное умение, которое проверяет
итоговый проект.

| День | Что делаем | Что готово в конце |
| --- | --- | --- |
| 33 | замысел, данные, макет, каркас, план | страница показывает первые данные с сервера |
| 34 | реализация по плану | все возможности из таблицы работают |
| 35 | доработка, проверка на телефоне, чтение чужого кода | приложение, которое не стыдно показать |
| 36 | защита: показ и разбор решений | вы объясняете любую строку своего кода |

С чем выходить на защиту, известно заранее — цель видна с первого дня:

| На защите смотрят | Как это видно |
| --- | --- |
| работает то, что обещано | автор проходит таблицу возможностей строка за строкой |
| данные живут в данных | страница строится из массива, а не написана в разметке |
| код читается | функции названы по смыслу, есть `render`, слушатели меняют данные |
| автор понимает решения | объясняет любую строку и любой выбор хранилища |
| честность | сам называет, что не успел и почему |

Сегодняшняя лекция идёт на примере: мы вместе спланируем приложение «Карточки слов»
и сделаем в нём первый рабочий шаг. На днях 34–35 этот пример будет расти дальше — как
образец, — а вы тем временем будете строить своё. Весь путь дня:

<Scheme src="scheme-why.svg">Семь шагов от идеи к плану; код появляется только на шестом</Scheme>

Код появляется лишь на шестом шаге — и это не случайность. Ошибку в замысле
исправить стоит одну строку текста, ошибку в готовой программе — часы. Поэтому первые
полчаса итогового проекта уходят на решения, а не на набор.

## 2. Идея: как выбрать {#idea}

Хорошая идея для итогового проекта отвечает четырём условиям. **Есть список
данных** — книги, слова, блюда, события: их приложение показывает. **Человек
что-то делает** — ищет, отмечает, выбирает. **Что-то запоминается**
между загрузками. И **вам самим интересно**: два дня работы над скучной идеей
тянутся вдвое дольше.

| Идея | Данные | Что делает человек | Что помнит |
| --- | --- | --- | --- |
| карточки слов | слова с переводом | переворачивает, отмечает выученное | выученные |
| меню кафе | блюда и цены | ищет, собирает заказ | заказ |
| афиша | события и даты | фильтрует по дню, отмечает «пойду» | отметки |
| викторина | вопросы и ответы | отвечает на время | лучший результат |
| справочник | растения, животные, страны | ищет, фильтрует | избранное |
| расписание | уроки по дням | выбирает день, отмечает домашнее задание | отметки |
| трекер привычек | свои привычки | отмечает дни | всё |
| список покупок | свои товары | добавляет, отмечает купленное | список |

У первых шести данные приходят с сервера, как в каталоге дня 32. У двух последних
данные создаёт сам человек, как в списке дел дня 29. Годится и то и другое. Можно взять
идею из таблицы, можно придумать свою — лишь бы она прошла по четырём условиям.

Идея бывает и слишком маленькой. «Кнопка, которая показывает случайную цитату», — это
упражнение, а не проект: в нём нет ни поиска, ни выбора, ни памяти. Добавьте к ней
избранные цитаты и фильтр по автору — и получится проект.

## 3. Замысел одним предложением {#sentence}

Прежде чем расписывать детали, замысел проверяют одним предложением:
**кому** приложение, **что** оно делает и **зачем**.
Если в одно предложение не влезает — идея расплывчата или слишком велика.

<ResultBox>
«Карточки слов» — для школьника, который учит английский: показывают слово, по щелчку —
перевод; школьник отмечает «знаю» или «повторить», а выученные слова больше не
показываются, даже после обновления страницы.
</ResultBox>

В этом предложении уже спрятан почти весь план. «Показывают слово» — нужны данные и
функция показа. «По щелчку — перевод» — слушатель и переменная «перевёрнута ли карточка».
«Отмечает» — ещё два слушателя. «Даже после обновления» — хранилище. Каждое слово
замысла станет строкой в таблице возможностей.

Для сравнения — замысел из другой строки таблицы идей: «Меню кафе — для посетителя,
который выбирает обед: показывает блюда с ценами, ищет по названию, собирает заказ и
считает сумму; заказ не пропадает, если случайно закрыть вкладку». Кому — посетителю;
что — меню, поиск, заказ, сумма; зачем — выбрать обед. Все три части на месте.

## 4. Что должно уметь приложение {#spec}

Возможности записывают таблицей, как на днях 29 и 32. Главное правило: у каждой строки
есть способ проверки, который выполнит человек, ни разу не видевший ваш код.

| № | Возможность | Как проверить |
| --- | --- | --- |
| 1 | загрузить слова с сервера | «Загрузка…», затем первое слово |
| 2 | сообщить об ошибке загрузки | файл переименован — понятный текст |
| 3 | перевернуть карточку | щелчок по карточке — перевод, ещё щелчок — слово |
| 4 | «Знаю» | слово исчезает из колоды, счётчик растёт |
| 5 | «Повторить» | показывается следующее слово, это вернётся позже |
| 6 | выбрать тему | кнопки тем из данных, в колоде только слова темы |
| 7 | счётчик «Выучено: N из M» | меняется после каждого «Знаю» |
| 8 | помнить выученное | обновили страницу — выученных слов в колоде нет |
| 9 | начать сначала | кнопка возвращает все слова |

Две дополнительные строки не менее важны. **Потом, если останется время:**
перемешать колоду, режим «перевод → слово». **Не делает совсем:** не добавляет
слова (их меняет только владелец файла), не произносит их (это курс 4). Список «потом» —
ваш запас: если на дне 35 останется час, будет что добавить, а если не останется, приложение
всё равно готово.

## 5. Данные на сервере {#data}

Папка `day-33/cards`, открываем через Live Server. Данные — файл
`words.json`, восемь слов трёх тем:

```js
[
  { "id": 1, "word": "book", "translation": "книга", "topic": "школа" },
  { "id": 2, "word": "teacher", "translation": "учитель", "topic": "школа" },
  { "id": 3, "word": "lesson", "translation": "урок", "topic": "школа" },
  { "id": 4, "word": "bread", "translation": "хлеб", "topic": "еда" },
  { "id": 5, "word": "water", "translation": "вода", "topic": "еда" },
  { "id": 6, "word": "apple", "translation": "яблоко", "topic": "еда" },
  { "id": 7, "word": "house", "translation": "дом", "topic": "дом" },
  { "id": 8, "word": "window", "translation": "окно", "topic": "дом" }
]
```

Поля выбираем по таблице возможностей: `word` и `translation` нужны
карточке, `topic` — кнопкам тем, `id` — хранилищу, чтобы запомнить
выученные. Лишних полей нет: каждое чем-то пользуется. Данных для начала мало — восемь
слов, — зато по ним удобно проверять всё руками. Дописать ещё сто можно в любой момент,
код от этого не изменится.

Сколько данных нужно для начала? Столько, чтобы каждую возможность было чем проверить:
не меньше двух тем (иначе выбирать нечего), в каждой несколько слов (иначе колода
кончится за два щелчка), хотя бы одна тема меньше других. Шесть–десять объектов обычно
хватает.

## 6. Проверить данные до кода {#check-data}

Файл данных пишут руками, а руки ошибаются. Поэтому данные проверяют сразу, пока в
`app.js` нет ни строчки. Сначала посмотрим на них глазами — таблицей из дня 2:

```js
const data = await (await fetch("words.json")).json();
console.table(data);   // таблица: восемь строк, столбцы id, word, translation, topic
data.length;           // 8
```

Глазами восемь строк проверить можно, сто — уже нет. Для этого есть
`console.assert` из дня 2: он молчит, если условие верно, и выводит красную
строку с пометкой *Assertion failed* и нашим текстом, если нет. Первая проверка —
у каждого слова есть все четыре поля:

```js
console.assert(
  data.every((w) => w.id && w.word && w.translation && w.topic),
  "у слова не хватает поля"
);
// тишина — все поля на месте
```

Вторая — номера не повторяются. Слово с номером стоит на своём месте, если
`findIndex` находит этот номер впервые именно там:

```js
console.assert(
  data.every((w, i) => data.findIndex((x) => x.id === w.id) === i),
  "номера повторяются"
);
// тишина — номера разные
```

Третья — какие темы есть и сколько в каждой слов. Приём «без повторов» из дня 32:

```js
const names = [];
data.forEach((w) => {
  if (!names.includes(w.topic)) names.push(w.topic);
});
names;   // ["школа", "еда", "дом"]
```

```js
names.map((t) => `${t}: ${data.filter((w) => w.topic === t).length}`);
// ["школа: 3", "еда: 3", "дом: 2"]
```

Пять минут таких проверок экономят час поисков потом. Ошибка в данных, найденная
сейчас, — это правка одной строки в файле. Найденная на дне 35, она выглядит как ошибка
в коде, и искать её будут в коде.

## 7. Разбор: данные «на глаз» {#bad-data}

Вот тот же файл, набранный в спешке, — `words-bad.json`. На первый взгляд всё
в порядке. Запустим те же проверки:

```js
const bad = await (await fetch("words-bad.json")).json();
// те же две проверки console.assert — на bad вместо data:
// Assertion failed: у слова не хватает поля
// Assertion failed: номера повторяются
// а список тем:
// ["школа", "еда", "Еда", "дом"]
```

**Шаг 1. Что не так?** Две красные строки и лишняя тема. Какое именно
слово без поля, подскажет `find`:

```js
bad.find((w) => !w.translation);
// {id: 8, word: 'window', translation: '', topic: 'дом'}
```

**Шаг 2. Три ошибки — три будущих симптома.** Пустой перевод — карточка
«window» перевернётся в пустоту. Повтор номера 5 у «water» и «apple» — «Знаю» у одного слова
выучит оба: избранное и выученное хранят номера. «Еда» с большой буквы — лишняя кнопка
темы, и в «еда» окажутся два слова вместо трёх. Когда функция `deck` из
раздела 12 будет готова, оба симптома видны прямо в консоли:

```js
words = bad;
learned = [5];                // «Знаю» у water
deck().map((w) => w.word);   // ["book", "teacher", "lesson", "bread", "house", "window"] — ушли два слова

learned = [];
topic = "еда";
deck().map((w) => w.word);   // ["bread", "apple"] — water спряталась в теме «Еда»
```

**Шаг 3. Чиним — и оставляем сторожа.** Исправить файл мало: завтра его
поправят снова. Проверки переносим в сам `app.js`, в функцию, которая
выполняется после каждой загрузки. Пока данные в порядке, она молчит:

```js
function checkData() {
  console.assert(words.length > 0, "слов нет");
  console.assert(words.every((w) => w.id && w.word && w.translation && w.topic), "у слова не хватает поля");
  console.assert(words.every((w, i) => words.findIndex((x) => x.id === w.id) === i), "номера повторяются");
}
```

## 8. Где что живёт {#state}

Следующее решение — какие данные хранит программа и где. Метод тот же, что в каталоге:
каждому виду данных — своё место.

| Данные | Где | Почему |
| --- | --- | --- |
| слова | сервер: `words.json` | общие для всех, меняет владелец файла |
| выученные | `localStorage` | личный прогресс, нужен и завтра |
| тема, номер карточки, перевёрнута ли | переменные | нужны только сейчас |

```js
const KEY = "cards:learned";
let words = [];                                              // придут с сервера
let learned = JSON.parse(localStorage.getItem(KEY)) ?? [];   // номера выученных слов
let topic = "все";                                           // выбранная тема
let position = 0;                                            // какая карточка колоды сейчас
let flipped = false;                                         // виден ли перевод
```

Шесть строк — а в них уже записаны все решения таблицы. Переменные
`position` и `flipped` сегодня не понадобятся, но объявить их стоит
сейчас: так видно, что замысел целиком помещается в данные. Если для какой-то возможности
не нашлось переменной — план не додуман. Проверка шага:

```js
[words.length, learned, topic];   // [0, [], "все"]
```

## 10. Каркас: функции-заглушки {#skeleton}

Теперь — список функций. Их не пишут целиком, а объявляют **заглушками**:
имя, одна строка о том, что функция делает, и простейшее тело. Такой каркас показывает
устройство всей программы ещё до того, как она заработала:

```js
// колода: слова выбранной темы, которые ещё не выучены
function deck() {
  return [];   // заглушка — того же типа, что настоящий ответ
}

// кнопки тем из данных — как жанры на дне 32
function makeTopicButtons() {
  // день 34
}

// страница из данных
function render() {
  // день 33, раздел 12
}

async function load() {
  // день 33, раздел 12
}

load();
```

Каркас уже можно открыть в браузере: ошибок нет, просто ничего не происходит. А список
функций становится списком задач: каждую заглушку предстоит заменить настоящим телом.

Так же объявляют и слушатели — по одному на каждую строку таблицы возможностей, где
человек что-то делает. Внутри — комментарий-план в схеме дня 29: что поменять в данных
и позвать `render`:

```js
card.addEventListener("click", () => {
  // день 34: flipped = !flipped; render();
});
knowButton.addEventListener("click", () => {
  // день 34: номер карточки — в learned, сохранить, render();
});
againButton.addEventListener("click", () => {
  // день 34: position — на следующую карточку, render();
});
```

Щёлкните по карточке — ничего не случится, и ошибок нет: слушатель есть, тела пока нет.
Зато комментарии уже записали решения, и на дне 34 останется перевести их в код.

### Заглушка должна возвращать то же, что настоящая функция

Заглушка `deck` возвращает пустой массив, а не «ничего». Разница видна, как только
другой код начнёт ею пользоваться. Вот заглушка без `return` и
`render`, которой уже нужна длина колоды:

```js
function deck() {
  // день 34
}
// на странице после загрузки:
// Не удалось загрузить слова: Cannot read properties of undefined (reading 'length')
```

Функция без `return` возвращает `undefined` (день 12), а у него
длины нет. Заглушка, которая возвращает пустой массив, честно говорит «колода пока пуста»,
и всё, что стоит после неё, работает. Правило: **заглушка возвращает значение того
же типа** — пустой массив, ноль, пустую строку.

## 11. Проверки до кода {#tests}

Раз мы знаем, что должна делать `deck`, можно записать это проверками раньше,
чем саму функцию. В консоли страницы с каркасом загрузим слова руками и спросим
заглушку:

```js
words = await (await fetch("words.json")).json();
console.assert(deck().length === 8, "в начале — все 8 слов");
learned = [1, 2];
console.assert(deck().length === 6, "выученные не попадают в колоду");
topic = "еда";
console.assert(deck().every((w) => w.topic === "еда"), "только слова темы");
console.assert(deck().length === 3, "в теме «еда» три слова");
// Assertion failed: в начале — все 8 слов
// Assertion failed: выученные не попадают в колоду
// Assertion failed: в теме «еда» три слова
```

Три красные строки из четырёх — и это хорошо: проверки видят, что функции ещё нет.
Но почему молчит третья? Заглушка вернула пустой массив, а `every` у пустого
массива всегда отвечает `true` — мы видели это на дне 20:

```js
[].every((w) => w.topic === "еда");   // true — у пустого массива нечему не подойти
```

Проверка «все подходят» ничего не доказывает, если подходить некому. Поэтому рядом с
ней стоит проверка длины: вместе они говорят «в колоде три слова, и все — про еду».
Хорошие проверки подобраны так, чтобы **заглушка их проваливала**: иначе они
не отличат готовую функцию от пустой.

### Проверки, которые можно повторить

Набирать четыре проверки после каждой правки утомительно. Их складывают в функцию —
в `app.js`, рядом с проверяемой. Функция меняет данные на время проверки и
возвращает их как было:

```js
function testDeck() {
  const oldLearned = learned;
  const oldTopic = topic;
  learned = [];
  topic = "все";
  console.assert(deck().length === 8, "в начале — все 8 слов");
  learned = [1, 2];
  console.assert(deck().length === 6, "выученные не попадают в колоду");
  topic = "еда";
  console.assert(deck().every((w) => w.topic === "еда"), "только слова темы");
  console.assert(deck().length === 3, "в теме «еда» три слова");
  learned = oldLearned;   // вернуть как было
  topic = oldTopic;
}
```

Теперь после любой правки `deck` достаточно набрать в консоли
`testDeck()`. Проверки с числами «8», «6», «3» знают наши данные, поэтому
запускают их на учебном `words.json`: добавите слов — поправьте и числа.

## 12. Первый рабочий шаг {#first}

Теперь заменяем заглушку настоящей функцией. Колода — слова, которых нет среди
выученных и которые подходят по теме:

```js
function deck() {
  return words.filter((w) => !learned.includes(w.id) && (topic === "все" || w.topic === topic));
}
```

Сохраним `app.js` — Live Server обновит страницу. `load` пока
заглушка, поэтому слова снова загрузим руками и запустим проверки:

```js
words = await (await fetch("words.json")).json();
testDeck();
[learned, topic, deck().length];   // [[], "все", 8] — проверки молчат, данные прежние
```

Ни одной красной строки, и `testDeck` вернула всё как было. А колода темы
«еда» при выученных 1 и 2:

```js
learned = [1, 2];
topic = "еда";
deck().map((w) => w.word);   // ["bread", "water", "apple"]
```

Осталось показать первое слово на странице. `render` пока минимальный: слово
первой карточки колоды и счётчик. Переворот, кнопки и темы — задачи дня 34:

```js
function render() {
  const cards = deck();
  card.textContent = cards.length > 0 ? cards[0].word : "Слов нет";
  counter.textContent = `Выучено: ${learned.length} из ${words.length}`;
}
```

```js
async function load() {
  try {
    const response = await fetch("words.json");
    if (!response.ok) throw new Error(`сервер ответил ${response.status}`);
    words = await response.json();
    checkData();
    makeTopicButtons();
    render();
  } catch (err) {
    error.textContent = `Не удалось загрузить слова: ${err.message}`;
  } finally {
    loading.hidden = true;
  }
}
```

`load` — почти слово в слово из каталога дня 32, со сторожем
`checkData` сразу после загрузки. Проверка шага после обновления страницы:

```js
[card.textContent, counter.textContent, loading.hidden];
// ["book", "Выучено: 0 из 8", true]
```

И сразу проверим хранилище, хотя кнопки «Знаю» ещё нет. Запишем выученные руками:

```js
localStorage.setItem("cards:learned", "[1, 2]");
// обновили страницу:
[card.textContent, counter.textContent];   // ["lesson", "Выучено: 2 из 8"]
```

«book» и «teacher» выучены, и колода начинается с третьего слова. Значит, чтение
хранилища, колода и показ уже работают вместе, — а кнопке «Знаю» на дне 34 останется
только записать номер.

### Разбор: разметка и код не совпали

Частая ошибка первого шага — опечатка между `index.html` и `app.js`:
в разметке `id="card"`, а в коде `querySelector("#cards")`.

```js
card;   // null
// в консоли: Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')
// на странице: «Загрузка…» висит, текста ошибки нет
```

Ошибка всплыла не там, где сделана, а на первом использовании элемента — в каркасе
слушателей из раздела 10. Он стоит вне функций, поэтому `catch` в
`load` её не видит: скрипт просто останавливается, и до вызова
`load()` дело не доходит. Отсюда и зависшая «Загрузка…». Проверка из раздела 9 —
«ни одного `null`» — стоит сразу после поиска элементов именно поэтому: она
ловит опечатку в той строке, где её сделали.

## 13. План задач на дни 34–35 {#plan}

Каркас готов, и каждая заглушка — задача. Остаётся расставить их по порядку и прикинуть
время. На каждый день — 90 минут практики. План «Карточек»:

| День | Задача | Минут | Как проверить |
| --- | --- | --- | --- |
| 34 | переворот карточки | 15 | щелчок — перевод, ещё щелчок — слово |
| 34 | «Знаю» и «Повторить» | 25 | строки 4 и 5 таблицы возможностей |
| 34 | кнопки тем | 20 | строка 6 |
| 34 | сохранение выученных | 15 | строка 8 |
| 34 | «Все выучены» и «Начать сначала» | 15 | строка 9 и пустая колода |
| 35 | проверка на телефоне | 25 | всё видно и нажимается на узком экране |
| 35 | крайние случаи | 25 | таблица крайних случаев, как на дне 32 |
| 35 | перемешать колоду | 20 | из списка «потом» |
| 35 | чтение чужого кода | 20 | отзыв соседа учтён |

План — тоже данные, и сумму минут удобнее доверить коду, чем голове:

```js
const plan = [
  { day: 34, task: "переворот карточки", minutes: 15 },
  { day: 34, task: "«Знаю» и «Повторить»", minutes: 25 },
  { day: 34, task: "кнопки тем", minutes: 20 },
  { day: 34, task: "сохранение выученных", minutes: 15 },
  { day: 34, task: "«Все выучены» и «Начать сначала»", minutes: 15 },
  { day: 35, task: "проверка на телефоне", minutes: 25 },
  { day: 35, task: "крайние случаи", minutes: 25 },
  { day: 35, task: "перемешать колоду", minutes: 20, later: true },
  { day: 35, task: "чтение чужого кода", minutes: 20 },
];
```

```js
[34, 35].map((d) => plan.filter((t) => t.day === d).reduce((sum, t) => sum + t.minutes, 0));
// [90, 90] — оба дня помещаются
```

Поле `later` отмечает задачу из списка «потом». Если время начнёт
кончаться, её выбрасывают первой, — и видно, сколько останется без неё:

```js
plan.filter((t) => t.later).map((t) => t.task);   // ["перемешать колоду"]
plan.filter((t) => !t.later).reduce((sum, t) => sum + t.minutes, 0);   // 160 — запас 20 минут
```

Порядок задач выбран не случайно. Сначала то, без чего не проверить остальное: без
переворота не понять, работает ли «Знаю». То, что можно выбросить, — в конце: если время
кончится, пострадает «перемешать», а не «сохранение».

Минуты в плане — прикидка, а не обещание. В конце дня 34 запишите рядом, сколько
ушло на деле, и поправьте план дня 35. Разница между «думал» и «вышло» — самое полезное,
что можно узнать о себе за эти четыре дня: в следующий раз прикидка будет точнее.

## 14. Разбор: план, который не проверить {#bad-plan}

Первый план почти у всех выглядит так: «сделать карточки», «сделать красиво»,
«доделать всё». Беда не в словах, а в том, что ни одну задачу нельзя **закрыть**:
неясно, когда она готова.

| Так не надо | Так надо |
| --- | --- |
| сделать карточки | переворот: щелчок — перевод, ещё щелчок — слово |
| сделать красиво | на телефоне шириной 360 пикселей нет прокрутки вбок |
| сохранение | «Знаю» у «book», обновили — «book» в колоде нет |
| доделать всё | каждая строка таблицы возможностей проверена руками |

Вторая частая беда — **слишком большой замысел**. Список желаний первого
черновика «Карточек» выглядел так:

```js
const wishes = [
  { task: "регистрация и вход", minutes: 120 },
  { task: "чат между учениками", minutes: 150 },
  { task: "рейтинг лучших", minutes: 60 },
  { task: "тёмная тема", minutes: 30 },
  { task: "карточки и переворот", minutes: 40 },
  { task: "сохранение выученных", minutes: 20 },
];
wishes.reduce((sum, t) => sum + t.minutes, 0);   // 420 — в 2,3 раза больше 180 минут двух дней
```

Проверьте свой замысел той же суммой: если план не помещается в 180 минут двух дней,
режьте. Регистрация и чат требуют настоящего сервера — это уже не Essentials. Не качество — объём: сначала то, без чего приложение не
работает, остальное — в «потом». Приложение из пяти возможностей, где всё работает,
сильнее приложения из пятнадцати, где половина не доделана.
