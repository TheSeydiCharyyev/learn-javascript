# День 33. Итоговый проект: замысел и план

<Subtitle>Выжимка лекции: семь шагов от идеи к плану и что должно быть готово к концу дня.</Subtitle>

## Семь шагов

| Шаг | Что получается |
| --- | --- |
| идея | есть данные, действия человека, память; самому интересно |
| одно предложение | кому, что делает, зачем |
| возможности | таблица «что — как проверить», списки «потом» и «не делает» |
| данные | файл JSON и проверки через `console.assert` |
| макет | узкий рисунок, у каждой части подпись: из каких данных |
| каркас | рама, заглушки, слушатели с планом внутри, первый шаг |
| план | задачи по дням с минутами; сумма дня не больше 90 |

<KeyPoint>
Сначала решения, потом код. Ошибку в замысле исправить стоит одну строку текста, ошибку
в готовой программе — часы. Код появляется только на шестом шаге.
</KeyPoint>

## Данные проверяют до кода

```js
console.table(data);                                          // глазами
console.assert(data.every((w) => w.id && w.word), "не хватает поля");      // молчит, если всё верно
console.assert(data.every((w, i) => data.findIndex((x) => x.id === w.id) === i), "номера повторяются");
```

Такие проверки переносят в функцию-сторож `checkData` и зовут после каждой
загрузки: файл данных правят руками, и ошибка может появиться завтра. Повтор номера,
пустое поле, тема с заглавной буквы — каждая даст в приложении свой странный симптом.

## Каркас и проверки до кода

```js
function deck() {
  return [];   // заглушка — того же типа, что настоящий ответ
}
```

<Remember>
Заглушка без `return` отдаёт `undefined`, и код ниже упадёт с
`Cannot read properties of undefined`. Проверки для функции пишут до неё и
подбирают так, чтобы заглушка их проваливала: `every` на пустом массиве —
`true`, поэтому рядом всегда проверка длины. Проверки складывают в функцию,
которая возвращает данные как было, — её можно запускать после каждой правки.
</Remember>

Проверка «ни одного `null`» сразу после поиска элементов ловит опечатку в
селекторе там, где её сделали. Без неё скрипт упадёт на первом слушателе, и «Загрузка…»
повиснет без объяснений.

## Чек-лист готовности дня 33

| Что | Готово, когда |
| --- | --- |
| замысел | одно предложение; сосед пересказал его верно |
| возможности | 6–10 строк, у каждой проверка; есть «потом» и «не делает» |
| данные | файл или образец объекта; проверки молчат |
| где что живёт | таблица с причинами; переменные в `app.js` |
| макет | узкий, подписан, лежит в папке проекта |
| рама | элементы найдены, ни одного `null` |
| каркас | заглушки нужного типа, слушатели с планом, без красных строк |
| первый шаг | страница показывает первые данные; ошибка загрузки понятна |
| план | задачи с проверками и минутами; сумма дня не больше 90 |

Если замысел не помещается в 180 минут двух дней — режьте объём, а не качество.
Приложение из пяти работающих возможностей сильнее, чем из пятнадцати недоделанных.
