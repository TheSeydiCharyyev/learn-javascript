# Day 34. Tasks

<Subtitle>Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. ## Main tasks

<Task title="4. The first task of your plan" level="medium" time="12">
<Goal>start the implementation with the task the others rely on.</Goal>

Take the first task of day 34 in your project. If several listeners talk about
the same thing — the selected item, the current question, the chosen category — first
move it into a function, like `current`.

<Hint>
A function that only answers and changes nothing is easy to check in the console.
Let it return “there is nothing” as `null` instead of failing.
</Hint>

<Criteria>
- the task is checked the way it is written in the plan — by hand and in the console;
- the new function is checked in the console on at least two values, one of them “empty”;
- a copy of the project folder is made before the edit;
- the task and the real minutes are marked in the plan.
</Criteria>
</Task>

<Task title="5. The next tasks and a guard" level="medium" time="13">
<Goal>move by the plan and not break what is done.</Goal>

Do the next tasks of the plan one at a time. For the main function of your project create
a check function in the spirit of `testCurrent` — it changes the data for a while and puts it back.

<Hint>
A good check fails on a stub and is silent on the real code. Run it
after every task — even one that “has nothing to do with it”.
</Hint>

<Criteria>
- every closed task has a mark and minutes in the plan;
- the check function is silent, and after it is called the data is the same as before;
- at least once the check caught a breakage you did not notice by eye — or
  it is written down why there were none;
- in the listeners that change “the current one”, the dependent variables are reset.
</Criteria>
</Task>

<Task title="6. The empty state" level="medium" time="12">
<Goal>make “there is nothing” look as intended.</Goal>

Find all the places in your project where something can turn out empty: an empty list,
nothing found, everything done. For each one — a clear text, useless buttons hidden
and a guard in the listeners.

<Hint>
The rule of section 12: the button is hidden, and the listener is still guarded with the first line
`if (… === null) return;`.
</Hint>

<Criteria>
- all the empty states of the project are written out, for each one — how to reach it;
- each one has a clear text instead of emptiness;
- calling a listener from the console (`button.click()`) in the empty state gives no red lines;
- rows about the empty states are added to the feature table.
</Criteria>
</Task>

<Task title="7. Saving and checking by the table" level="medium" time="13">
<Goal>make sure that what was promised works in full.</Goal>

If your project has something to remember — writing at the end of `render`, reading at
the declaration. Then go through your feature table row by row, as at the defense, and
mark each one: works, works with a reservation, not done.

<Hint>
Reset the data, not the storage: `render` will rewrite the key by itself — the walkthrough
of section 13.
</Hint>

<Criteria>
- after a reload of the page what was saved is in place;
- the reset — if there is one — erases the data, and after a reload it does not come back;
- every row of the table has a mark, and a “with a reservation” row has the reservation itself;
- everything “not done” is moved to the plan of day 35 or to “later”.
</Criteria>
</Task>

## Starred tasks

<Task title="8. Three complaints about the “Cards”" level="hard" time="10">
<Goal>look for a mistake by its symptom.</Goal>

A classmate built the “Cards” and sent three complaints:

- “After the eighth ‘Again’ the card gets stuck, and there is red in the console.”
- “I pressed ‘I know’ on a flipped card — the next one showed the translation at once.”
- “‘Start over’ resets nothing, even after a reload.”

Their code differs from the program of section 14 in three places:

```js
// in current
return cards.length === 0 ? null : cards[position];

// in the “I know” listener — one line is missing
learned.push(current().id);
render();

// in the “Start over” listener
localStorage.removeItem(KEY);
```

<Hint>
For each complaint ask the data: `position`, `flipped`,
`learned` and storage.
</Hint>

<Criteria>
- each complaint is reproduced in a copy of the “Cards” and matched with its place;
- for the first one the exact text of the error from the console is written down;
- for the third one it is written down what is in `learned` and in storage after “Start over”;
- all three places are fixed, the complaints do not repeat.
</Criteria>
</Task>
