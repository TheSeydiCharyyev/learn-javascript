## 2. Открыть на телефоне {#phone}

На дне 2 мы разбирали адрес `127.0.0.1`: это всегда «мой собственный
компьютер». Если набрать его на телефоне, телефон будет искать страницу у себя — и не
найдёт. Нужен адрес компьютера в сети. Live Server отвечает не только на
`127.0.0.1`, но и на этот адрес, поэтому хватит трёх шагов.

<Step n="1" numberTag="span">
Телефон и компьютер — в одной сети Wi-Fi.
</Step>

<Step n="2" numberTag="span">
Узнать адрес компьютера: в командной строке Windows набрать `ipconfig`
и найти в разделе адаптера Wi-Fi строку, которая начинается с `IPv4`:
</Step>

```plain-out
Wireless LAN adapter Wi-Fi:
   …
   IPv4 Address. . . . . . . . . . . : 192.168.1.23
```

<Step n="3" numberTag="span">
На телефоне открыть тот же адрес, что в браузере компьютера, но вместо
`127.0.0.1` — число из `ipconfig`:
</Step>

```plain-out
http://192.168.1.23:5500/index.html
```

Если страница не открывается, причина
обычно в сети: телефон на мобильном интернете, а не в Wi-Fi, или сеть не пускает одно
устройство к другому. Запасной путь — из дня 2:
режим телефона в DevTools, <Kbd>Ctrl</Kbd> + <Kbd>Shift</Kbd> +
<Kbd>M</Kbd>, ширина 360. Он честно показывает вёрстку, но палец не заменит:
при первой возможности проверьте и на настоящем телефоне.

На телефоне смотрят не на код, а на четыре вещи:

| Смотрим | Хорошо, когда |
| --- | --- |
| текст | читается без увеличения пальцами |
| кнопки | большой палец попадает в нужную с первого раза |
| ширина | ничего не уходит за правый край, страница не ездит вбок |
| данные | самое длинное слово помещается в карточку |

## 3. Всё мелкое: строка viewport {#viewport}

Открываем «Карточки» в режиме телефона шириной 360 — и видим уменьшенную копию
компьютерной страницы: заголовок, кнопки и карточка раза в три мельче, чем ждали.
Спросим у страницы, какой ширины она себя считает. Свойство окна `innerWidth`
— ширина страницы в пикселях CSS:

```js
innerWidth;   // 980 — хотя экран шириной 360
```

Вот и разгадка. Мобильный браузер не знает, готова ли страница к узкому экрану, и на
всякий случай строит её как для экрана шириной 980, а потом уменьшает до 360 — почти в
три раза. Чтобы он так не делал, в `<head>` ставят одну строку:

```html
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

`width=device-width` — ширина страницы равна ширине экрана устройства;
`initial-scale=1.0` — при открытии ничего не уменьшать. Обновили:

```js
innerWidth;   // 360
```

<Scheme src="scheme-viewport.svg">Одна строка в `<head>` решает, для какой ширины строится страница</Scheme>

Откуда ошибка? Разметку «Карточек» мы написали на дне 33 и эту строку забыли, а на
компьютере разницы не видно. Во всех уроках курса она есть — проверьте через
<Kbd>Ctrl</Kbd> + <Kbd>U</Kbd>.

<Remember>
Первая проверка любого проекта на телефоне — есть ли в `<head>` строка
`<meta name="viewport" …>`. Без неё всё остальное проверять бесполезно:
размеры будут неправдой.
</Remember>

## 4. Под палец и под длинное слово {#fingers}

Текст стал нормальным, но кнопки остались маленькими. Свойство
`offsetHeight` возвращает высоту элемента в пикселях:

```js
document.querySelector("#know").offsetHeight;   // 21
```

Кнопка высотой 21 пиксель, а между «Знаю» и «Повторить» — 4 пикселя. Мышью попасть
легко, пальцем — нет: палец закрывает сразу обе. А промах здесь дорогой: «Знаю» убирает
слово из колоды. Лечится это не кодом, а стилем — шрифт крупнее, поля внутри шире,
отступ между кнопками больше:

```html
<style>
  button { font-size: 18px; padding: 10px 16px; margin: 0 8px 8px 0; }
</style>
```

```js
document.querySelector("#know").offsetHeight;   // 45 — вдвое с лишним выше
```

Правило `button` действует на все кнопки, и на созданные кодом кнопки тем
тоже. Промежуток стал 12 пикселей: 8 от `margin` и пробел между тегами.

### Самое длинное слово

Проверяют не только свои восемь слов, но и худшее, что может прийти. Поставим на время
в `words.json` вместо «window» очень длинное слово:
`{ "id": 8, "word": "internationalization", "translation": "интернационализация", "topic": "дом" }`.

Английское слово в карточку помещается. А вот перевод, открытый щелчком, упирается в
правую рамку и вылезает за неё: одно слово браузер не переносит, пока его не попросят.
Попросить можно одним свойством CSS в правиле `.card`:

```html
<style>
  .card { … font-size: 32px; cursor: pointer; overflow-wrap: anywhere; }
</style>
```

`overflow-wrap: anywhere` разрешает перенести слово в любом месте, если
целиком оно не помещается. Короткие слова это не трогает. После проверки верните
«window» на место.

<KeyPoint>
Проверка на телефоне — это проверка худшего: самый узкий экран, самый толстый палец,
самое длинное слово. Если худшее выглядит прилично, обычное — тем более.
</KeyPoint>

## 5. Крайние случаи {#edge}

Задача 2 — таблица крайних случаев, как на дне 32. Крайний случай — это данные, которых
автор не ждал: пустые, испорченные, устаревшие. У «Карточек» два источника данных — хранилище и файл `words.json`, и каждый может
прийти не таким. Хранилище портим из консоли, по одной строке, после каждой — обновить
страницу:

```js
localStorage.setItem("cards:learned", "[object Object]");
localStorage.setItem("cards:learned", "5");
localStorage.setItem("cards:learned", "[1, 2, 3, 4, 5, 6, 7, 8, 99]");
```

Откуда такое берётся в жизни? `"[object Object]"` — сохранили без
`JSON.stringify`, разбор 11 дня 31. Число — старая версия программы писала под
этим ключом другое, или кто-то поправил значение руками во вкладке Application. Номер 99 —
слово удалили из `words.json`, а в хранилище у того, кто учил раньше, номер
остался. Файл портим тоже по одному разу: переименовать, оставить в нём `[]`,
поставить лишнюю запятую после последнего слова.

| Случай | Что видно | Почему |
| --- | --- | --- |
| в хранилище `"[object Object]"` | «Загрузка…» висит, пустая рамка и кнопки | `JSON.parse` падает в первых строках, до `load()` дело не доходит |
| в хранилище `"5"` | «Не удалось загрузить слова: learned.includes is not a function» | число вместо массива; сообщение неправда — слова загрузились |
| номер 99, которого нет в файле | всё выучено, а счётчик — «Выучено: 9 из 8» | счётчик считает все номера, даже чужие |
| нет `words.json` | «…сервер ответил 404», под ним пустая рамка и кнопки | тренажёр виден, хотя слов нет |
| `words.json` — пустой `[]` | «Все слова темы выучены!», «Выучено: 0 из 0» | пустой файл неотличим от выученной колоды |
| лишняя запятая в `words.json` | текст ошибки «…is not valid JSON», пустая рамка и кнопки | ошибку поймали, но тренажёр виден |

Шесть случаев — шесть разных недоработок? Нет, причин всего три. Хранилище читается без
защиты — строки 1 и 2. Номера из хранилища не сверяются со словами — строка 3. Тренажёр
виден, даже когда слов нет, — строки 4–6. После случая 4 ещё хуже: щелчок по
«Повторить» рисует «Все слова темы выучены!» и «Выучено: 0 из 0» прямо под сообщением об
ошибке. Разберём первую причину по шагам, остальные исправим в разделе 7.

## 6. Разбор: испорченное хранилище {#bug-storage}

**Шаг 1. Прочитать красную строку.** В хранилище
`"[object Object]"`, обновили страницу:

```js
// Uncaught SyntaxError: "[object Object]" is not valid JSON
```

**Шаг 2. Найти место.** Под сообщением консоль печатает, где оно
случилось: `at JSON.parse`, а ниже — адрес, который кончается на
`app.js:4:20`. Это четвёртая строка:
`let learned = JSON.parse(localStorage.getItem(KEY)) ?? [];`.
Эта строка не внутри `try`, поэтому ошибка останавливает весь скрипт. Последняя
строка, `load();`, так и не выполняется — значит, никто не спрячет «Загрузка…».

**Шаг 3. Проверить догадку в консоли.**

```js
JSON.parse("[object Object]");    // SyntaxError: "[object Object]" is not valid JSON
JSON.parse("5");                  // 5 — это правильный JSON, но не массив
Array.isArray(JSON.parse("5"));   // false
```

Со строкой `"5"` ошибки при чтении нет. Она возникает позже, в `deck()`: у числа нет метода
`includes`. Но `deck()` вызывается из `render()`, а
`render()` — внутри `try` в `load`. Поэтому
`catch` пишет «Не удалось загрузить слова», хотя слова загрузились. Урок:
`catch` ловит любую ошибку внутри `try`, а не только ту, о которой
думал автор.

**Шаг 4. Исправить.** Чтение хранилища выносим в функцию, которая всегда
возвращает массив:

```js
function readLearned() {
  try {
    const saved = JSON.parse(localStorage.getItem(KEY));
    return Array.isArray(saved) ? saved : [];
  } catch {
    return [];
  }
}
```

```js
let learned = readLearned();   // вместо JSON.parse(…) ?? []
```

Три пути — один результат. Испорченная строка: `JSON.parse` бросает ошибку,
`catch` возвращает пустой массив. Не массив, например `5`:
`Array.isArray` отвечает `false`. Ключа ещё нет:
`getItem` вернёт `null`, `JSON.parse(null)` — тоже
`null`, это не массив. Поэтому `?? []` больше не нужен.

**Шаг 5. Проверить исправление** — тем же способом, каким нашли ошибку:

```js
// в хранилище было "[object Object]", обновили страницу:
[learned, localStorage.getItem("cards:learned")];   // [[], "[]"]
```

Программа начала с нуля, а хранилище починилось само: `render` записал туда
правильный пустой массив. Для `"5"` результат тот же.

## 7. Данные проверяют на входе {#input}

Исправление раздела 6 — частный случай общего правила. У программы есть места, где
данные входят снаружи: чтение хранилища и загрузка файла. **Проверяют их там, на
входе**, — тогда всему остальному коду можно доверять данным и не проверять их в
каждой функции. Хранилище уже проверяет `readLearned`. Осталось место, где
встречаются хранилище и файл, и сам файл.

### Номера, которых нет в файле

После загрузки слов оставляем в `learned` только номера, для которых есть
слово:

```js
learned = learned.filter((id) => words.some((w) => w.id === id));   // только номера из файла
```

```js
// в хранилище [1, 2, 3, 4, 5, 6, 7, 8, 99], обновили:
counter.textContent;                        // "Выучено: 8 из 8"
localStorage.getItem("cards:learned");      // "[1,2,3,4,5,6,7,8]" — 99 ушёл и оттуда
```

Можно было бы исправить сам счётчик и считать только знакомые номера. Но тогда чужой
номер остался бы в данных, и следующая функция снова споткнулась бы о него. Почистить один
раз на входе надёжнее, чем помнить о мусоре везде.

### Пустой файл и тренажёр без слов

Пустой файл — такая же ошибка загрузки, как 404: учить нечего. Значит, и путь у него
должен быть тот же — в `catch`, к понятному тексту:

```js
// в load, сразу после words = await response.json():
if (words.length === 0) throw new Error("в файле нет слов");
```

Раньше пустой файл ловила проверка `console.assert(words.length > 0, "слов нет")`
в `checkData`. Но `assert` пишет только в консоль — разработчику. Человек
с телефоном консоль не видит, он видел «Все слова темы выучены!». Теперь проверка стала
обработкой, и строку «слов нет» из `checkData` убираем: она больше никогда не
сработает.

Осталось, чтобы при любой ошибке загрузки не было видно рамки и кнопок. Обернём всё,
что нужно только со словами, в один блок и спрячем его:

```html
<div id="trainer" hidden>
  <p class="topics"></p>
  <div id="card" class="card"></div>
  <p>
    <button id="know">Знаю</button>
    <button id="again">Повторить</button>
  </p>
  <p id="counter"></p>
  <button id="reset">Начать сначала</button>
</div>
```

Показываем его последней строкой внутри `try`, когда всё уже удалось:

```js
render();
trainer.hidden = false;
```

Любая ошибка выше этой строки уходит в `catch`, и тренажёр остаётся
спрятанным. Прогоним таблицу раздела 5 ещё раз:

<ResultBox>
| Случай | Что видно теперь |
| --- | --- |
| `"[object Object]"` или `"5"` в хранилище | слово, «Выучено: 0 из 8»; в хранилище `"[]"` |
| номер 99 | «Выучено: 8 из 8» |
| нет `words.json` | только «Не удалось загрузить слова: сервер ответил 404» |
| пустой `[]` | только «Не удалось загрузить слова: в файле нет слов» |
| лишняя запятая | только «Не удалось загрузить слова: …is not valid JSON» |
</ResultBox>

При 404 в консоли остаётся красная строка `Failed to load resource` — её
пишет браузер о неудачном запросе. Программа ошибку обработала: человек видит понятный
текст.

## 8. Читаем чужой код {#review}

Третья задача — обмен с соседом: вы читаете его проект, он — ваш. Допустим, у соседа
тоже «Карточки», и почти всё как у нас. Отличаются чтение хранилища, показ и «Знаю»:

```js
let learned = JSON.parse(localStorage.getItem("cards:learned")) ?? [];
```

```js
function f() {
  let x = words.filter((w) => !learned.includes(w.id) && (topic === "все" || w.topic === topic));
  if (x.length == 0) {
    document.querySelector("#card").innerHTML = "Все слова темы выучены!";
    return;
  }
  document.querySelector("#card").innerHTML = flipped ? x[position % x.length].translation : x[position % x.length].word;
  document.querySelector("#counter").innerHTML = "Выучено: " + learned.length + " из " + words.length;
}
```

```js
knowButton.addEventListener("click", () => {
  let x = words.filter((w) => !learned.includes(w.id) && (topic === "все" || w.topic === topic));
  learned.push(x[position % x.length].id);
  localStorage.setItem("learned", JSON.stringify(learned));
  flipped = false;
  f();
});
```

Остальные слушатели у соседа такие же, как у нас, только вместо `render()`
везде `f()`. Как читать такой код, чтобы за 20 минут найти главное и не
утонуть в мелочах? В три прохода.

<Scheme src="scheme-review.svg">Сначала поведение, потом устройство, потом одна дорожка целиком</Scheme>

**Проход 1. Запустить, не читая код.** Пройти сценарий из раздела 15 дня 34
и записать всё странное. У соседа находится сразу четыре симптома: выбранная тема не
выделяется; после «Знаю» в пустеющей теме счётчик отстаёт; после обновления страницы
выученное пропадает; щелчок по «Знаю», когда тема уже выучена, даёт красную строку.

```js
// тема «дом», «Знаю» два раза — на карточке «Все слова темы выучены!»:
[learned, counter.textContent];   // [[7, 8], "Выучено: 1 из 8"]
```

**Проход 2. Карта.** Пробежать файл сверху вниз и записать: какие данные,
какие функции, какие слушатели. Здесь всплывает то, чего не видно при запуске: одна и та же
колода вычисляется в двух местах одинаковой длинной строкой.

**Проход 3. Одно действие целиком.** Берём «Знаю»: слушатель → новая
колода `x` → `learned.push` → `setItem("learned", …)` →
`f()`. На этом пути видны причины трёх симптомов. Запись идёт
под ключом `"learned"`, а чтение в первой строке — из
`"cards:learned"`:

```js
// та же тема «дом», «Знаю» два раза:
[localStorage.getItem("learned"), localStorage.getItem("cards:learned")];   // ["[7,8]", null]
```

Щелчок по «Знаю» на выученной теме: колода `x` пуста, кнопка не спрятана,
проверки нет. Остаток от деления на ноль — не число:

```js
0 % 0;     // NaN
[][NaN];   // undefined
// в консоли: Uncaught TypeError: Cannot read properties of undefined (reading 'id')
```

Вот что получилось после трёх проходов:

| Где | Что видно | Почему |
| --- | --- | --- |
| `f`, `return` | тема выучена, а счётчик отстаёт на одно слово | `return` стоит раньше строки со счётчиком |
| «Знаю», `setItem` | после обновления выученное пропало | пишет в `"learned"`, читает из `"cards:learned"` |
| «Знаю», `learned.push` | на выученной теме — красная строка | кнопка не спрятана, слушатель не защищён |
| `f` | выбранная тема не выделяется | класс `active` никто не переключает |
| `f` | «Начать сначала» не сохраняется | `f` не пишет в хранилище: после сброса там всё ещё `"[7,8]"` |

Это ошибки: их можно повторить, и они мешают человеку. Отдельно, ниже и короче,
записывают замечания к чтению: колода вычисляется в двух местах — поменяете правило в одном,
другое останется старым; имена `f` и `x` ничего не говорят;
`innerHTML` для данных — раздел 6 «Чужие данные и innerHTML» дня 25;
`==` вместо `===`.

### Как написать замечание

Замечание — не оценка, а инструкция, как увидеть то же, что видели вы: где, что сделал,
что увидел, что ожидал. Догадку о причине — в конце, как предположение:

```plain-out
f(), строка с return. Тема «дом», два раза «Знаю»: на карточке «Все слова темы
выучены!», а счётчик «Выучено: 1 из 8». Ожидал 2 из 8. Похоже, return срабатывает
раньше строки со счётчиком.
```

<Mistake>
Плохие замечания: «код непонятный», «я бы сделал по-другому», «всё переписать».
Их нельзя проверить, и по ним нечего исправлять. Замечание — о коде, а не о человеке, и
одно замечание — одна проблема. Исправляет автор: переписывать чужой проект за него не надо.
</Mistake>

## 10. Задача из «потом»: перемешать колоду {#shuffle}

Перемешивать будем так: идём с конца массива; для каждого места выбираем случайное
место среди ещё не тронутых — от начала до текущего включительно — и меняем их
содержимое местами. Этот способ называют перемешиванием Фишера — Йетса.

```js
function shuffle(list) {
  const result = [...list];
  for (let i = result.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    const temp = result[i];
    result[i] = result[j];
    result[j] = temp;
  }
  return result;
}
```

`Math.floor(Math.random() * (i + 1))` — случайное целое от 0 до
`i`, формула дня 18. Обмен через `temp`: без него первое
присваивание затёрло бы значение. Копия `[...list]` (день 22) — чтобы не
портить массив, который передали: функция возвращает новый, как `filter` и
`map`.

<Scheme src="scheme-shuffle.svg">Каждый шаг ставит на место одну клетку справа; случайные числа здесь — для примера</Scheme>

```js
shuffle(words).map((w) => w.id);   // например, [3, 7, 1, 8, 5, 2, 6, 4] — каждый раз другой
words.map((w) => w.id);            // [1, 2, 3, 4, 5, 6, 7, 8] — исходный массив не тронут
```

### Почему не `sort` со случайным ответом

В интернете часто советуют короче: `list.sort(() => Math.random() - 0.5)`.
Перемешивает? Посчитаем, как часто выпадает каждый порядок трёх чисел за 60 000 попыток:

```js
function count(mix) {
  const result = {};
  for (let k = 0; k < 60000; k++) {
    const key = mix([1, 2, 3]).join("");
    result[key] = (result[key] ?? 0) + 1;
  }
  return result;
}
count(shuffle);   // все шесть порядков — около 10 000
count((list) => [...list].sort(() => Math.random() - 0.5));
// "123" и "213" — около 15 000, остальные четыре — около 7 500
```

Числа у вас будут немного другие, но картина та же. `sort` рассчитан на
функцию сравнения, которая отвечает одинаково на один и тот же вопрос. Случайные ответы
путают его, и в Chrome два порядка из шести выпадают вдвое чаще остальных. Короче — не
значит правильно.
