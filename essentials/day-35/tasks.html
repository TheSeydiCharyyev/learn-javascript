День 35. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Разминка — на примере «Карточек»: скопируйте папку day-34/cards в day-35/cards и доведите её по лекции. Основные задания — в вашем проекте, как на дне 34: перед большой правкой — копия папки, после каждой задачи — проверка и отметка минут в plan.md. Всё открываем через Live Server.

Основные задания

4. Свой проект на телефоне
Средне12 мин

проверить худшее: узкий экран, палец, самые длинные данные.

Откройте свой проект на телефоне или в режиме телефона и пройдите четыре пункта раздела 2: текст, кнопки, ширина, данные. Всё, что выглядит не так, запишите, исправьте и проверьте снова.

Первая проверка — строка viewport в <head>. Для «данных» найдите самое длинное значение, какое может прийти в ваш проект, и поставьте его на время.
  • innerWidth равен ширине экрана, а не 980;
  • высота главных кнопок замерена до и после, между ними есть промежуток;
  • с самым длинным значением ничего не вылезает, document.documentElement.scrollWidth равен screen.width (не innerWidth: на телефоне он растёт вместе со страницей);
  • каждая находка записана в план с минутами: что было, что сделали.
5. Таблица крайних случаев
Средне13 мин

найти данные, которых вы не ждали, пока их не нашёл кто-то другой.

Выпишите все источники данных своего проекта: хранилище, файл, сервер, поле ввода. Для каждого придумайте, каким он может прийти не таким, — пустым, испорченным, устаревшим, — и вызовите каждый случай руками.

Хранилище портят из консоли через setItem, файл — переименованием, пустым [] и лишней запятой. После каждой порчи — обновить страницу.
  • в таблице не меньше пяти случаев: случай, как вызвать, что видно, почему;
  • каждый случай вызван руками, а не угадан;
  • для каждого записана красная строка из консоли, если она есть;
  • случаи сгруппированы по причинам: у скольких строк одна причина.
6. Данные на входе
Средне12 мин

исправить причины из задания 5, а не каждый симптом отдельно.

Для каждой причины найдите место, где данные входят в программу, и поставьте проверку туда: функцию чтения хранилища, проверку в загрузке, чистку данных, скрытый интерфейс до загрузки. Пройдите таблицу задания 5 ещё раз.

Хорошая функция чтения всегда возвращает данные нужного вида — как readLearned всегда возвращает массив. Пустое там, где его быть не должно, — такая же ошибка: throw, и её поймает тот же catch.
  • в таблице задания 5 появился столбец «что видно теперь», и в нём нет поломок;
  • красных строк нет, кроме тех, что пишет сам браузер о неудачном запросе;
  • записано, какие функции изменились, — в идеале только места входа;
  • функции-проверки дня 34 по-прежнему молчат.

Сначала ошибки, которые можно повторить, потом — замечания к чтению. Перед ответом на замечание к своему коду — повторите его сами.
  • соседу отправлено от трёх до пяти замечаний, каждое — где, что сделал, что увидел, что ожидал;

9. Упрощённое перемешивание
Сложно10 мин

проверить перемешивание счётом и объяснить, откуда перекос.

Одноклассник «упростил» shuffle: случайное место выбирается из всего массива, а не из ещё не тронутой части.

function simpleShuffle(list) {
  const result = [...list];
  for (let i = result.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * result.length);
    const temp = result[i];
    result[i] = result[j];
    result[j] = temp;
  }
  return result;
}

Посчитайте функцией count из раздела 10, как часто выпадает каждый порядок трёх чисел у shuffle и у simpleShuffle.

Для трёх чисел цикл делает два шага. Сколько вариантов у каждого шага в shuffle и сколько в simpleShuffle? Выпишите все пути на бумаге и посмотрите, какой порядок получается в конце каждого.
  • для обеих функций записаны все шесть чисел счёта;
  • названы порядки, которые у simpleShuffle выпадают чаще, и во сколько раз;
  • выписаны все пути обеих функций: сколько их и сколько приходится на каждый порядок;
  • объяснено, почему у shuffle перекоса нет.
