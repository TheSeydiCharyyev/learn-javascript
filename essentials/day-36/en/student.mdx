## Answers to questions

| Question | Move |
| --- | --- |
| “Where …?” | show the place in the code, do not retell it |
| “What if …?” | check it in the console in a minute |
| “Why not …?” | name the reason or “not checked — into ‘later’” |

<KeyPoint>
Not knowing the answer is not a mistake, making it up is. An experiment in the console leaves traces in
storage: after it — “Start over”.
</KeyPoint>

What the checks of the “Cards” showed: two words with one number leave together; two tabs
wipe out each other’s progress; on ten thousand words `learned.includes` becomes
noticeably slow (`Set` is in course 2); the shuffle stands after
`makeTopicButtons()`: if it is earlier, the topic buttons jump together with the words.

```js
function testInput() {
  const saved = localStorage.getItem(KEY);
  localStorage.setItem(KEY, "[object Object]");
  console.assert(readLearned().length === 0, "a broken string — an empty array");
  localStorage.setItem(KEY, "5");
  console.assert(readLearned().length === 0, "not an array — an empty array");
  localStorage.setItem(KEY, saved);   // put it back as it was
}
```

## The reviewer and grading

A good question is specific, it is answered with code or a check, and it is about the project, not about the
person. Feedback is one strong side with a place in the code and one suggestion that can
be checked. Grading is five criteria of 0–2 points each: works, phone, edge cases, code,
answers. Complexity and the number of lines are not graded.
