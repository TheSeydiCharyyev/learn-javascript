1. Как проходит защита

Сегодня лекция о том, как защищать, а уроки 2 и 3 — сами защиты. У каждого семь минут, и у них есть порядок. Запишем его так же, как записывали план, — данными:

const defense = [
  { part: "одна фраза", minutes: 0.5 },
  { part: "показ по сценарию", minutes: 3 },
  { part: "одно решение", minutes: 1 },
  { part: "одна ошибка", minutes: 1 },
  { part: "вопросы", minutes: 1.5 },
];
defense.reduce((sum, p) => sum + p.minutes, 0);   // 7
Math.floor(90 / 7);   // 12 — столько защит помещается в уроки 2 и 3

Если в группе больше двенадцати человек, преподаватель заранее скажет, как делится время. На защите три роли: докладчик; проверяющий — тот сосед, который читал проект на дне 35, он задаёт первый вопрос; хронометрист следит за минутами и показывает, когда часть кончилась.

Почему именно такой порядок? Слушатель сначала узнаёт, зачем это нужно, потом видит, что оно работает, и только потом — как устроено. А вопросы стоят в конце с отдельным временем, чтобы их не съел слишком длинный показ.

Хронометр в консоли

Хронометристу не нужны часы: у него есть массив defense и таймеры дня 30. Сначала посчитаем, на какой минуте начинается каждая часть:

function schedule(parts) {
  let start = 0;
  return parts.map((p) => {
    const at = start;
    start += p.minutes;
    return { part: p.part, at };
  });
}
schedule(defense).map((s) => s.at);   // [0, 0.5, 3.5, 4.5, 5.5]

Теперь на каждую минуту из расписания — свой setTimeout, и ещё один на конец:

schedule(defense).forEach((s) => {
  setTimeout(() => console.log(`${s.at} мин: ${s.part}`), s.at * 60 * 1000);
});
setTimeout(() => console.log("7 мин: время вышло"), 7 * 60 * 1000);
// в консоли по мере защиты:
// 0 мин: одна фраза
// 0.5 мин: показ по сценарию
// 3.5 мин: одно решение
// 4.5 мин: одна ошибка
// 5.5 мин: вопросы
// 7 мин: время вышло

Маленькая программа, но в ней полкурса: массив объектов, map с накоплением, шаблонная строка, таймеры. Запустите её перед каждой защитой — и никто не выйдет за свои семь минут незаметно.

2. Одна фраза

Первые полминуты — одна фраза: что это и для кого. Без слов «функция» и «массив» — их слушатель ещё не ждёт.

ФразаЧто не так
«Я сделал приложение на JavaScript с fetch и localStorage»о технике, а не о пользе
«Это карточки»непонятно, для кого и зачем
«Карточки — тренажёр английских слов по темам: показывают слово, по щелчку — перевод, и помнят, что вы уже выучили»хорошо: кто, что делает, чем полезен

Проверка фразы простая: после неё незнакомый человек может сказать, пригодится ли это ему. Техника появится в показе и в ответах на вопросы — там ей и место.

Удобная форма фразы — три части: что это, что оно делает, чем полезно. Для проектов, похожих на мини-проекты курса, она звучит так:

ПроектФраза
список дел, как на дне 29«Список дел на неделю: добавляешь задачу, отмечаешь сделанное, и ничего не теряется после закрытия страницы»
каталог, как на дне 32«Каталог книг: поиск по названию, фильтр по жанру и избранное, которое помнится»

3. Показ по сценарию

Показывают на телефоне, по сценарию, который прошли на дне 35. Перед защитой проект открыт по адресу компьютера в сети и стоит в начальном состоянии. Проще всего нажать свою же кнопку «Начать сначала». Если хочется из консоли — удалить ключ и сразу обновить страницу:

localStorage.removeItem("cards:learned");   // и сразу обновить страницу

Почему сразу? Пока страница открыта, learned живёт в памяти, а render записывает его в хранилище при каждом действии — разбор 13 дня 34:

// удалили ключ и нажали «Повторить», не обновляя страницу:
localStorage.getItem("cards:learned") !== null;   // true — render записал learned обратно

Что подготовить заранее

ЧтоЗачем
телефон заряжен, в той же сети Wi-Fi, адрес уже открытне тратить показ на набор адреса
проект в начальном состояниисчётчик «0 из 8», а не следы репетиции
на компьютере открыты код и консольна вопросы отвечают там: консоль телефона не видна
одна репетиция с часамиузнать, укладываетесь ли в семь минут

С третьей строкой связана ловушка. На телефоне проект открыт по адресу сети, а на компьютере — по 127.0.0.1. Для браузера это два разных сайта, и хранилище у каждого своё:

// на телефоне, по адресу сети, два раза «Знаю» — «Выучено: 2 из 8»
// на компьютере, по 127.0.0.1:
localStorage.getItem("cards:learned");   // "[]" или null — выученного с телефона здесь нет

Поэтому, если на вопрос нужно показать данные с телефона, откройте на компьютере тот же адрес сети, что и на телефоне. А лучше отвечать на «что будет, если» на чистой странице компьютера — опыты не испортят показ.

Во время показа показывают, а не рассказывают: действие — и что изменилось. «Нажимаю „Знаю“ — слово ушло, счётчик стал „1 из 8“». Начинают с главного сценария, крайние случаи — одним-двумя, если осталось время.

А если на показе что-то сломалось? Не прятать. Открыть консоль, прочитать красную строку вслух и спросить данные — шаги 1 и 2 таблицы «Если застряли» дня 34:

[words.length, learned, topic, position, flipped];   // [8, [], "все", 0, false] — на только что открытой странице

Спокойно разобранная ошибка на защите — тоже показ умения. Растерянность — нет.

4. Одно решение

Минута на одно место в коде, которым вы довольны. Рассказ строится из четырёх частей: что решали, как сделали, что было бы иначе, чем проверили. Пример для «Карточек» — текущую карточку вычисляем, а не храним:

function current() {
  const cards = deck();
  return cards.length === 0 ? null : cards[position % cards.length];
}

«Что было бы иначе» сильнее всего, если его показать. Допустим, колоду сохранили один раз — при загрузке и при смене темы:

let cards = [];   // колода, сохранённая заранее

function current() {
  return cards.length === 0 ? null : cards[position % cards.length];
}
// в load и в слушателе тем: cards = deck();

Открываем, первым выпало «teacher», нажимаем «Знаю» дважды:

card.textContent;      // "teacher" — слово выучено, но осталось на экране
learned;               // [2, 2] — один номер дважды
counter.textContent;   // "Выучено: 2 из 8" — счётчик считает одно слово за два
[deck().length, cards.length];   // [7, 8] — сохранённая колода устарела

Копия колоды устарела после первого же «Знаю». Функция current каждый раз строит колоду заново и поэтому не устаревает. Проверка, которая это сторожит, — testCurrent дня 35. Вот как это звучит за минуту:

«Текущую карточку я не храню, а вычисляю из колоды и позиции. Если колоду хранить, после „Знаю“ выученное слово остаётся на экране, а счётчик считает его дважды — я проверял. Правило сторожит testCurrent».

Второй пример: кнопки тем из данных

Кнопки тем можно было написать прямо в разметке — это короче и понятнее с первого взгляда:

<p class="topics">
  <button data-topic="все">все</button>
  <button data-topic="школа">школа</button>
  <button data-topic="еда">еда</button>
  <button data-topic="дом">дом</button>
</p>

Что было бы иначе, показывают так: в words.json добавляют слово новой темы — { "id": 9, "word": "street", "translation": "улица", "topic": "город" } — и смотрят на кнопки в обоих вариантах:

// кнопки в разметке:
[...topics.children].some((b) => b.textContent === "город");   // false — кнопки нет
// кнопки из данных, makeTopicButtons дня 34:
[...topics.children].some((b) => b.textContent === "город");   // true — появилась сама

В первом варианте слово «street» попадёт только в тему «все», а выбрать «город» нельзя: кнопку забыли дописать. Во втором кнопка появилась сама — темы берутся из тех же данных, что и слова. Решение звучит так: «Кнопки тем я строю из слов, поэтому новая тема в файле не требует правки разметки».

5. Одна ошибка

Ещё минута — история одной ошибки. Не любой, а той, что научила: где долго искали или где причина оказалась не там, где думали. Порядок рассказа — пять шагов:

Шаг«Карточки», день 35
1. симптом«Загрузка…» висит, слов нет
2. как нашликрасная строка в консоли и стек под ней
3. причинаJSON.parse вне try на испорченной строке в хранилище
4. исправлениеreadLearned, который всегда возвращает массив
5. как проверили, что не вернётсяфункция-проверка

Шаги 2 и 4 — это код, его и показывают:

// Uncaught SyntaxError: "[object Object]" is not valid JSON
//     at JSON.parse (<anonymous>)
//     at …/app.js:4:20
let learned = readLearned();   // вместо JSON.parse(…) ?? [] — всегда массив

Шаг 5 чаще всего пропускают, а он главный: он отличает «починил» от «починил навсегда». Ошибку превращают в проверку — как testDeck и testCurrent, только для входа данных:

function testInput() {
  const saved = localStorage.getItem(KEY);
  localStorage.setItem(KEY, "[object Object]");
  console.assert(readLearned().length === 0, "испорченная строка — пустой массив");
  localStorage.setItem(KEY, "5");
  console.assert(readLearned().length === 0, "не массив — пустой массив");
  localStorage.setItem(KEY, saved);   // вернуть как было
}
testInput();
localStorage.getItem("cards:learned");   // то же, что до проверки, — и тишина в консоли

Если кто-то однажды вернёт JSON.parse на старое место, проверка закричит раньше, чем «Загрузка…» повиснет у человека с телефоном.

6. Защита «Карточек» целиком

Сложим части вместе. Так могла бы звучать защита «Карточек» — слово в слово, с тем, что докладчик в это время делает руками:

ЧастьЧто говорят и делают
фраза«Карточки — тренажёр английских слов по темам: показывают слово, по щелчку перевод, и помнят, что вы уже выучили»
показтелефон в руке. «Открываю — слово случайное. Тап — перевод, ещё тап — слово. Выбираю тему „еда“. „Знаю“ три раза — тема выучена, кнопки спрятались, счётчик „3 из 8“. Обновляю — выученное на месте. „Начать сначала“ — всё сначала»
решение«Текущую карточку я не храню, а вычисляю. Если колоду хранить, выученное слово остаётся на экране — я проверял. Правило сторожит testCurrent»
ошибка«На дне 35 испорченная строка в хранилище вешала „Загрузку“. Стек показал четвёртую строку: JSON.parse вне try. Теперь чтение в readLearned, а testInput проверяет, что так не будет снова»
вопросына «что будет, если…» — консоль и проверка; на незнакомое — «не проверял, запишу в „потом“»

Обратите внимание, чего здесь нет: пересказа кода строка за строкой, извинений «я не успел», слов «ну вот как-то так». Всё время занято тем, что видно, и тем, что проверено. Свою защиту напишите так же — таблицей из пяти строк — и прочитайте вслух с часами: если выходит больше семи минут, резать начинают с показа, а не с вопросов.

7. Вопросы проверяющего

Вопросов на защите бывает три вида, и на каждый есть свой ход:

Главное правило: не знать ответ — не ошибка, выдумать — ошибка. На «что будет, если» у вас в руках консоль — проверка занимает меньше минуты. Разберём вопросы, которые на защите «Карточек» задают чаще всего.

«Где сохраняется выученное?»

Вопрос вида «где» — самый простой, если не пересказывать, а показать. Две строки, и обе видны в файле:

let learned = readLearned();                          // чтение — один раз, при старте
localStorage.setItem(KEY, JSON.stringify(learned));   // запись — в конце render, после каждого действия

Ответ: «Читаю один раз при старте, пишу в конце render — поэтому любое действие сохраняется само». Если ответ на «где» занимает дольше пяти секунд, значит, сохранение размазано по программе, — а это уже повод для вопроса «почему».

«Что будет, если у двух слов один номер?»

Не гадаем — проверяем. Добавим в words.json девятое слово с чужим номером: { "id": 7, "word": "door", "translation": "дверь", "topic": "дом" }. При загрузке в консоли — «номера повторяются»: сработала checkData дня 33.

counter.textContent;   // "Выучено: 0 из 9"
// тема «дом», «Повторить», пока не выпадет «door», и один раз «Знаю»:
deck().map((w) => w.word);   // ["window"] — ушли сразу два слова: door и house
counter.textContent;         // "Выучено: 1 из 9"

Ответ: «Номер — это имя слова для программы. Одно имя на два слова — и программа их путает. Предупреждение в консоли есть, а исправляют файл».

«А если открыть в двух вкладках?»

Вкладка B открыта раньше, в A два раза нажали «Знаю», потом в B — один раз:

// после двух «Знаю» во вкладке A:
JSON.parse(localStorage.getItem("cards:learned")).length;   // 2
// после одного «Знаю» во вкладке B:
JSON.parse(localStorage.getItem("cards:learned")).length;   // 1 — запись B затёрла A

Обновили A — «Выучено: 1 из 8», два слова пропали. Каждая вкладка держит свой learned в памяти и записывает его целиком, побеждает последняя запись. Честный ответ: «Не предусмотрено. Записал в „потом“». Это хороший ответ: проверенный, короткий, с планом.

«А если быстро нажать „Знаю“ десять раз?»

Пальцем так быстро не нажать, но консоль может: click() вызывает слушатель, как настоящий щелчок. Слов восемь, щелчков десять:

for (let i = 0; i < 10; i++) knowButton.click();
[learned.length, counter.textContent];   // [8, "Выучено: 8 из 8"] — лишние два щелчка ничего не сломали

Каждый щелчок выучил следующее слово, а два последних упёрлись в защиту if (current() === null) return; из дня 34 — красных строк нет. Ответ: «Кнопка на пустой колоде спрятана, а слушатель всё равно защищён — вот строка».

«А если слов будет десять тысяч?»

Сделаем десять тысяч слов прямо в консоли и замерим render с помощью console.time дня 2:

const big = [];
for (let i = 1; i <= 10000; i++) {
  big.push({ id: i, word: `word${i}`, translation: `слово${i}`, topic: "тест" });
}
words = big;
learned = [];
for (let i = 1; i <= 5000; i++) learned.push(i);
console.time("render");
render();
console.timeEnd("render");   // render: … ms — число своё у каждого компьютера и прогона

У нас в разных прогонах выходило от 5 до 114 мс: время зависит от компьютера и от того, что браузер делал до этого. Но откуда они берутся, понятно: deck() для каждого из десяти тысяч слов спрашивает learned.includes, а тот перебирает до пяти тысяч номеров. Для восьми слов этого не видно, для десяти тысяч — уже заметно. Ускорить можно коллекцией Set — её проходят в курсе 2:

const learnedSet = new Set(learned);                             // курс 2, модуль I5
big.filter((w) => !learnedSet.has(w.id)).length;                 // 5000 — тот же ответ, курс 2

В наших прогонах фильтр с includes занимал от 5 до 22 мс, а с Set — около миллисекунды и меньше. И важное после опыта: render записал в хранилище пять тысяч номеров. Обновите страницу — и увидите «Выучено: 8 из 8», потому что номера 1–8 тоже среди них. Опыты на настоящих данных оставляют следы: после них — «Начать сначала».

«Почему в хранилище номера, а не сами слова?»

JSON.stringify(learned).length;   // 17 — когда выучены все восемь
JSON.stringify(words).length;     // 487 — все слова целиком

Ответ из двух причин. Номера короче. И главное: если в файле исправят перевод, прогресс не сломается — номер тот же, а слово каждый раз берётся свежим из файла. Слова живут в одном месте, в words.json, а хранилище помнит только, какие из них выучены.

«Почему перемешивание стоит после кнопок, а не сразу после загрузки?»

Проверяющий видит в load строку words = shuffle(words) ниже makeTopicButtons() и спрашивает: не понятнее ли перемешать сразу, как только слова пришли? Ответ лучше показать. Переставим строку выше кнопок, обновим страницу три раза и посмотрим на темы:

[...topics.children].map((b) => b.textContent);
// ["все", "еда", "школа", "дом"], потом ["все", "школа", "дом", "еда"], потом ["все", "дом", "школа", "еда"]

Кнопки прыгают. makeTopicButtons собирает темы в том порядке, в каком встречает их в словах, — перемешанные слова перемешивают и кнопки. Кто вчера нашёл кнопку «еда» на одном месте, сегодня найдёт её на другом. Поэтому порядок строк такой:

makeTopicButtons();       // темы — в порядке файла
words = shuffle(words);   // слова перемешиваем уже после
// шесть обновлений подряд:
[...topics.children].map((b) => b.textContent);   // всегда ["все", "школа", "еда", "дом"]

Слова при этом по-прежнему в случайном порядке. Ответ на защите: «Кнопки собираются из порядка слов. Если перемешать раньше, кнопки прыгают при каждом открытии — я проверял. Поэтому сначала кнопки, потом перемешивание». За двумя строками кода — решение, которое можно показать. Вопросы о порядке строк задают часто: у каждого порядка должна быть причина.

8. Если вы проверяющий

На каждой защите вы ещё и слушатель, а на одной — проверяющий. Хороший вопрос помогает докладчику показать, что он знает, а плохой только проверяет нервы:

Плохой вопросХороший вопрос
«Почему так?»«Почему текущая карточка вычисляется, а не хранится?»
«А если всё сломать?»«Что будет, если words.json пустой?»
«Ты уверен, что работает?»«Покажите, где сохраняется выученное»
«Почему не сделал как у меня?»«Какие ещё варианты были и почему выбран этот?»

Хороший вопрос конкретный, на него можно ответить кодом или проверкой, и он о проекте, а не о человеке. Первый вопрос проверяющего лучше взять из своих замечаний дня 35: вы уже знаете, где у проекта слабое место, и можете спросить, что с ним стало.

После защиты проверяющий говорит отзыв из двух частей: одна сильная сторона — с местом в коде и одно предложение — что проверить в «потом». Например: «Хорошо, что данные проверяются в readLearned, — испорченное хранилище не страшно. Проверь две вкладки: у меня прогресс затёрся». Похвала без места и совет без проверки — не отзыв.

9. Как оценивают

Оценивают не число возможностей, а то, насколько обещанное работает и понятно автору. Пять критериев, по каждому от 0 до 2 баллов:

Критерий2 балла1 балл
работаетвсе строки таблицы возможностейкроме одной-двух второстепенных
телефонвсё видно и нажимаетсямелкие неудобства
крайние случаитаблица есть, причины исправлены на входетаблица есть, исправлено не всё
кодпонятные имена, один render, проверки молчатчто-то одно из трёх хромает
ответыместо в коде или проверка в консоличасть ответов — догадки
 
const marks = { works: 2, phone: 2, edges: 1, code: 2, answers: 1 };
Object.values(marks).reduce((sum, m) => sum + m, 0);   // 8 — из 10

Ноль по критерию — когда главное не работает или не проверялось вовсе. Заметьте, чего в таблице нет: «сложность», «сколько строк», «красота». Маленький проект, который работает на телефоне и понятен автору, стоит выше большого, который автор не может объяснить.

Частые ошибки на защите: показывать на компьютере вместо телефона; читать код с экрана строка за строкой; начинать с «я не успел»; спорить с проверяющим вместо проверки в консоли; заполнять паузу словами «ну вот, как-то так». Каждая из них съедает минуты, которых и так семь.

10. Весь курс в одной программе

Тридцать пять дней назад мы открыли консоль. Посмотрите на «Карточки» — в них работает каждый модуль курса:

По строчке из программы на каждый модуль — прочитайте их и вспомните день, где это появилось впервые.

// E1: консоль — не только для вывода, но и для проверок
console.assert(deck().length === 3, "в теме «еда» три слова");
// E2: переменные, сравнение, тернарный оператор
card.textContent = word === null ? "Все слова темы выучены!" : (flipped ? word.translation : word.word);
// E3: условие и исключение — ошибка идёт в catch
if (!response.ok) throw new Error(`сервер ответил ${response.status}`);
// E4: функция без побочных действий — только отвечает
function deck() {
  return words.filter((w) => !learned.includes(w.id) && (topic === "все" || w.topic === topic));
}
// E5: шаблонная строка и случайное целое
counter.textContent = `Выучено: ${learned.length} из ${words.length}`;
const j = Math.floor(Math.random() * (i + 1));
// E6: методы массивов и JSON
learned = learned.filter((id) => words.some((w) => w.id === id));
localStorage.setItem(KEY, JSON.stringify(learned));
// E7: делегирование — один слушатель на все кнопки тем
topics.addEventListener("click", (event) => {
  const button = event.target.closest("button");
  if (!button) return;
  topic = button.dataset.topic;
});
// E8: загрузка с сервера — в load, внутри try
async function load() {
  const response = await fetch("words.json");
  words = await response.json();
}

Последние три строки — сокращённый load: без проверок и без catch, только чтобы было видно, где работает модуль E8. Полная версия — в разделе 11 дня 35. Ни одна из этих строк не была бы понятна на дне 1. Сегодня каждая читается за секунду — вот что изменилось за курс.

13. Что дальше

Курс Essentials закончился, проект — нет. Три шага на ближайшие недели:

1

Покажите проект настоящему человеку — не одногруппнику, а тому, для кого он: кто учит английский, кто хочет список дел. Молча смотрите, куда он нажимает. Каждое «а где тут…» — задача в «потом».

2

Сделайте одну задачу из «потом» в том же ритме: план, код, проверка, отметка минут. Ритм важнее размера задачи.

3

Курс 2, Intermediate: замыкания и this, классы, коллекции Map и Set, регулярные выражения, модули. Всё, чего не хватило «Карточкам» в разделе 11, — там.   1. Чем плоха фраза «Я сделал приложение на JavaScript с fetch и localStorage»?
    Ответ Она о технике, а не о пользе: слушатель не узнаёт, что приложение делает и для кого. Техника — в показе и в ответах на вопросы.
  2. Перед показом удалили ключ хранилища, но выученные слова вернулись. Почему?
    Ответ learned остался в памяти, и первый же render записал его обратно. Удалять ключ — и сразу обновлять страницу, или нажать «Начать сначала».
  3. Почему в рассказе о решении сильнее всего часть «что было бы иначе»?
    Ответ Она показывает, что решение выбрано, а не случилось само. Если её ещё и проверить — как с сохранённой колодой, — это уже не мнение, а факт.
  4. Какой шаг истории об ошибке пропускают чаще всего и почему он важен?
    Ответ Пятый: как проверили, что ошибка не вернётся. Функция-проверка вроде testInput отличает «починил» от «починил навсегда».
  5. Проверяющий спрашивает: «А если открыть в двух вкладках?» Вы не знаете. Что делать?
    Ответ Не гадать, а проверить: открыть две вкладки и посмотреть хранилище. Если поведение плохое — честно сказать, что не предусмотрено, и записать в «потом».
  6. Почему после опыта с десятью тысячами слов нужно «Начать сначала»?
    Ответ render записал в хранилище тысячи номеров. После обновления страницы среди них окажутся номера настоящих слов, и все будут «выучены».
