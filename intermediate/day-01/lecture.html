1. Вопрос, оставшийся от «Карточек»

Курс 2 начинается там, где закончился первый. В конце дня 36 Essentials мы оставили вопрос: почему learned, объявленная в первых строках app.js, видна внутри каждой функции «Карточек»? Вот эти строки — данные дня 33 и функция deck:

const KEY = "cards:learned";
let words = [];                                              // придут с сервера
let learned = JSON.parse(localStorage.getItem(KEY)) ?? [];   // номера выученных слов
let topic = "все";                                           // выбранная тема

function deck() {
  return words.filter((w) => !learned.includes(w.id) && (topic === "все" || w.topic === topic));
}

Внутри deck нет ни одного объявления, а она свободно читает три переменные. В Essentials мы приняли это как факт — «внутрь видно, наружу нет» (дни 4 и 12). Сегодня разберём, как именно это устроено, и это окажется ключом к одной из главных тем языка.

Есть и второй вопрос, который мы тогда не задавали. Проверяя «Карточки», мы писали прямо в консоли:

learned = [1, 2];   // так мы проверяли колоду на дне 33

Для проверки удобно. Но это значит, что любая строка программы и любой человек с консолью могут заменить прогресс ученика чем угодно. В программе на тридцать строк это не страшно. В программе на три тысячи строк какая-нибудь функция однажды сделает learned = [] по ошибке, и искать её придётся долго.

Сегодня ответим на оба вопроса: почему переменная видна и как сделать, чтобы она была видна только тем, кому нужно. Инструмент для второго называется замыканием.

2. Четыре области видимости

Область видимости — часть программы, где имя переменной что-то значит. Три вида вы знаете по Essentials, четвёртый появится в конце курса:

ОбластьЧто её создаётГде видны её переменныеРазбирали
глобальнаявесь скриптвезде, в том числе в других обычных скриптах страницыдень 4
функциикаждый вызов функциитолько внутри этой функциидень 12
блокафигурные скобки { } — у if, for, catch или сами по себевнутри блока; только для let и constдень 4
модуляфайл-модультолько в этом файлекурс 2, день 30

Все три знакомые области в одной функции:

const city = "Мары";                    // глобальная

function greet(student) {                // student — область функции
  if (student) {
    const text = `Салам, ${student}!`;   // область блока if
    return text;
  }
  return `Салам, ${city}!`;
}

console.log(greet("Аман"));   // Салам, Аман!
console.log(greet(""));       // Салам, Мары!
console.log(typeof text);     // undefined — text осталась в блоке

Обратите внимание на последнюю строку. typeof не падает на необъявленном имени — этот приём мы видели на дне 5. Обычное обращение console.log(text) здесь дало бы ReferenceError: text is not defined.

Блок у var не работает: такая переменная видна во всей функции, даже если объявлена внутри if или цикла. Это одна из причин, почему в новом коде пишут let и const (день 4). Сегодня мы увидим ещё одну — в разделе 11.

3. Важно, где написано, а не где вызвано

Главное правило дня. Какие переменные видит функция, определяется местом, где она написана в тексте программы, — а не тем, кто и откуда её вызывает.

const city = "Мары";

function showCity() {
  console.log(city);
}

function trip() {
  const city = "Ашхабад";
  showCity();
}

trip();   // Мары

Многие ждут здесь «Ашхабад»: ведь showCity вызвали изнутри trip, где city — Ашхабад. Но showCity написана на верхнем уровне скрипта, вне trip. Своей city у неё нет, и искать она будет там, где стоит в тексте, — на верхнем уровне. Переменная city из trip ей просто не видна: это чужая область, как и в любом вызове.

Такую область называют лексической (от «лексика» — текст программы) или статической: её можно определить, просто читая код, не запуская его. Так устроено большинство современных языков. Бывает и иначе — функция видит переменные того, кто её вызвал, — это называется динамической областью, и она встречается, например, в командной оболочке bash. В JavaScript её нет.

Функция — как письмо с обратным адресом. Где бы его ни читали, «мой город» в письме означает город отправителя, а не того, кто держит письмо в руках. Адрес вписан, когда письмо писали, — функция «прописана» там, где её объявили.

Функции можно вкладывать друг в друга, и тогда внутренняя видит всё, что видит внешняя, плюс переменные самой внешней:

function report(student) {
  const school = "школа № 5";

  function line(mark) {
    return `${student}, ${school}: ${mark}`;   // три имени из трёх мест
  }

  return line(5);
}

console.log(report("Мерет"));   // Мерет, школа № 5: 5

mark — параметр самой line, student и school — переменные report, вокруг которой line написана. Чтобы понять, что видит функция, достаточно посмотреть, какие фигурные скобки её окружают.

4. Как ищется имя

Когда движок встречает имя, он ищет его по шагам:

1

Сначала — в своей области: среди переменных и параметров текущей функции или блока.

2

Не нашёл — в области, которая окружает её в тексте программы. Потом в той, что окружает эту, и так дальше наружу.

3

Дошёл до глобальной области и не нашёл — ReferenceError: … is not defined. Первая находка останавливает поиск.

Отсюда и затенение из дня 4: если внутри объявлена переменная с тем же именем, что снаружи, поиск остановится на внутренней, и до внешней не дойдёт.

const mark = 5;                    // весь скрипт

function outer() {
  const student = "Сапар";         // вызов outer

  function inner() {
    const mark = 4;                // вызов inner — затеняет внешнюю mark
    console.log(student, mark);
  }

  inner();
  console.log(mark);
}

outer();
// Сапар 4
// 5
Поиск, дошедший до глобальной области, иногда находит то, чего вы не объявляли. У браузера на верхнем уровне есть свои имена, и одно из них — name: 
console.log(name);         // пустая строка, а не ошибка
console.log(typeof name);  // string
Это свойство окна браузера, о нём — на дне 3. Поэтому в примерах этого курса переменные называются student, а не name: опечатка в name не упадёт с понятной ошибкой, а тихо подставит пустую строку.

С присваиванием поиск устроен так же: count = 5 ищет count по той же цепочке и меняет первую найденную. Если не нашлось нигде, обычный скрипт молча создаёт глобальную переменную — ловушку из дня 4. В строгом режиме это ошибка, его разберём на дне 3.

5. Первое чтение спецификации

В Essentials мы опирались на MDN. MDN — пересказ, а то, что пересказывают, называется спецификацией ECMAScript: документ ECMA-262, который пишет комитет TC39. По нему работают движки всех браузеров, и если MDN и браузер в чём-то расходятся, рассудит спецификация. В курсе 2 мы будем открывать её рядом с темой, которую уже знаем по MDN.

Свежая редакция лежит по адресу tc39.es/ecma262/2026/. У каждого раздела есть свой якорь, поэтому ссылка ведёт прямо на нужное место. Сегодняшний раздел — 9.1 Environment Records, «записи окружения». Перескажем его своими словами.

  • Запись окружения — устройство спецификации, которое хранит, какому имени какая переменная или функция соответствует. Записи связаны так же, как вложен текст программы.
  • Новая запись создаётся каждый раз, когда выполняется функция, блок или catch: в неё попадают имена, объявленные в этом коде.
  • У каждой записи есть поле [[OuterEnv]] — ссылка на внешнюю запись, ту, что окружает её в тексте. У самой верхней там null.
  • Это способ описать поведение, а не чертёж движка: браузер может хранить переменные как угодно, лишь бы вёл себя так же. Из программы до записей окружения не добраться.

Двойные квадратные скобки — обозначение спецификации: так пишут внутренние поля и слоты, которых нет в языке. Написать в коде env.[[OuterEnv]] нельзя — это имя для рассуждений.

Виды записей

Раздел 9.1.1 перечисляет виды записей. Они устроены как родословная: есть общее понятие и его частные случаи.

Вид записиКогда создаётсяГде в курсе

Function Environment Record — частный случай предыдущейкаждый вызов функции; может хранить и thisсегодня и день 2
Module Environment Record — тоже частный случайверхний уровень модулядень 30

Там же — таблица общих методов записи. Названия говорят сами за себя: HasBinding (есть ли такое имя), CreateMutableBinding и CreateImmutableBinding (завести изменяемую или неизменяемую привязку — это let и const), GetBindingValue и SetMutableBinding (прочитать и записать).

Поиск имени в спецификации

Раздел 9.1.2 описывает операции над записями. Первая из них, GetIdentifierReference, — ровно тот поиск, что мы разобрали в разделе 4. В пересказе её шаги такие:

  1. если запись — null, имя не найдено (позже это станет ReferenceError);
  2. спросить у записи HasBinding: есть ли у тебя это имя? Если да — нашли;
  3. иначе взять [[OuterEnv]] и повторить всё с ним.

Три строки — и вся цепочка из схемы раздела 4. Остальные операции раздела создают записи разных видов: NewDeclarativeEnvironment, NewFunctionEnvironment, NewObjectEnvironment, NewGlobalEnvironment, NewModuleEnvironment.

Как читать спецификацию, не утонув: не подряд, а от вопроса. Найдите тему на MDN — на страницах справочника внизу есть таблица «Specifications» со ссылкой на раздел — и прочитайте в спецификации только этот раздел. Незнакомые слова вроде Reference Record пропускайте: спецификация определяет их в других местах, и для понимания идеи они не нужны. В старых редакциях этот раздел назывался Lexical Environments — слово «лексическое окружение» до сих пор встречается в статьях и на MDN; это то же самое.

6. Замыкание: функция и её окружение

Теперь главное. Посмотрите на функцию, которая создаёт другую функцию и возвращает её:

function makeCounter() {
  let count = 0;
  return () => {
    count = count + 1;
    return count;
  };
}

const next = makeCounter();
console.log(next());   // 1
console.log(next());   // 2
console.log(next());   // 3

Странная вещь: makeCounter закончила работу ещё на строке const next = …. Её вызов окончен, а переменная count продолжает жить и считать. Почему её не выбросили?

Потому что функция, созданная внутри, держит ссылку на окружение, в котором её создали. В спецификации это внутренний слот функции [[Environment]]: запись окружения, над которой функция «замкнута», — когда функцию вызывают, эта запись становится внешней для её кода (раздел 10.2, подробно — в курсе 3). Пока жива стрелочная функция, жива и запись с count.

Замыкание — это функция вместе со ссылкой на окружение, в котором она создана. Так это формулирует и MDN: функция плюс её лексическое окружение. В JavaScript замыкание получает каждая функция в момент создания — вы ничего для этого не делаете. Особенным его делает только одно: функция пережила вызов, внутри которого родилась, и унесла с собой его переменные.

Вы пользовались замыканиями весь первый курс, не называя их. deck из «Карточек» читает learned через своё [[Environment]] — запись верхнего уровня скрипта. Обработчик клика, объявленный внутри функции, помнит её переменные. Счётчик внутри функции, вызванной сразу, — приём из дня 13, — работал по той же причине; тогда мы пообещали объяснить, почему, и вот объяснение.

7. Каждый вызов — новое окружение

Раз запись окружения создаётся при каждом вызове, два вызова makeCounter дадут две независимые count:

function makeCounter() {
  let count = 0;
  return () => ++count;
}

const a = makeCounter();
const b = makeCounter();

a();
a();
a();
console.log(a());   // 4
console.log(b());   // 1 — у b своя count

В спецификации каждый вызов функции начинается с NewFunctionEnvironment — одной из операций раздела 9.1.2. Отсюда и независимость: у a и b разные записи, хотя код у них один.

Если вынести переменную за пределы фабрики, счётчик станет общим на всех: 
let count = 0;                 // снаружи — одна на всех

function makeSharedCounter() {
  return () => ++count;
}

const x = makeSharedCounter();
const y = makeSharedCounter();
x();
x();
console.log(y());   // 3 — y продолжил чужой счёт
Обе функции созданы в разных вызовах, но count они находят не в своём вызове, а уровнем выше — в общей записи скрипта. Своё у каждого замыкания только то, что объявлено внутри вызова.

8. Помнит переменную, а не значение

Частое заблуждение: будто замыкание сохраняет значения переменных на момент создания функции, как фотографию. Нет — функция держит саму переменную и каждый раз читает её заново:

let lesson = "замыкания";
const show = () => console.log(`Тема: ${lesson}`);

show();               // Тема: замыкания
lesson = "this";
show();               // Тема: this

Функцию show создали, когда темой были замыкания. Но вызвали её второй раз после того, как lesson поменялась, — и она прочитала новое значение. Запись окружения хранит не копию, а саму привязку имени к переменной.

Если нужна именно фотография — значение на момент создания, — его кладут в новую переменную, которая больше не меняется. Проще всего — в параметр фабрики:

function remember(value) {
  return () => value;   // value — своя переменная этого вызова
}

let topic = "еда";
const saved = remember(topic);
topic = "дом";

console.log(saved());   // еда
console.log(topic);     // дом

Вызов remember(topic) скопировал значение «еда» в параметр value — новую переменную в новой записи окружения. Дальнейшие изменения topic её не касаются.

С массивами и объектами осторожнее: в параметр копируется ссылка (день 19), и если поменять содержимое массива, это будет видно через обе переменные. «Фотография» массива — это копия: [...marks] из дня 22.

9. Фабрики функций

Функция, которая создаёт и возвращает другие функции, называется фабрикой. Параметры фабрики становятся настройками созданной функции — «запекаются» в неё:

function makeRangeCheck(min, max) {
  return (n) => n >= min && n <= max;
}

const isMark = makeRangeCheck(2, 5);
const isAge = makeRangeCheck(6, 18);

console.log([5, 9, 3, 0].filter(isMark));   // (2) [5, 3]
console.log(isAge(17), isAge(25));          // true false

Зачем это нужно, если можно написать одну функцию с тремя параметрами inRange(n, min, max)? Посмотрите на filter: он сам вызывает переданную функцию и сам решает, что ей передать, — элемент, его номер и весь массив (день 20). Отдайте ему inRange — и в min попадёт номер элемента, а в max массив. Границы filter не передаёт, а isMark они и не нужны: они уже внутри.

Кстати, вы и раньше делали то же самое, просто короче:

const min = 2;
const max = 5;
console.log([5, 9, 3, 0].filter((n) => n >= min && n <= max));   // (2) [5, 3]

Стрелочная функция внутри filter — тоже замыкание: она читает min и max из окружения, в котором написана. Фабрика лишь даёт такой функции имя и позволяет создать её много раз с разными настройками.

makeCounter()свою countнезависимый счётчик

10. Спрятанные данные

Вернёмся ко второму вопросу из раздела 1: как сделать переменную видимой только тем, кому нужно. Фабрика может вернуть не одну функцию, а объект с несколькими, и все они будут замкнуты на одну и ту же запись окружения:

function makeScore() {
  let points = 0;

  return {
    add: (n) => {
      points = points + n;
    },
    total: () => points,
  };
}

const score = makeScore();
score.add(5);
score.add(4);
console.log(score.total());   // 9
console.log(score.points);    // undefined — снаружи до points не добраться

У объекта score нет свойства points — переменная живёт в записи окружения вызова makeScore, и путь к ней есть только у двух стрелочных функций. Сломать счёт случайной строкой points = 0 где-то в программе теперь нельзя: это имя там просто ничего не значит.

Это тот самый приём, который на дне 13 работал внутри функции, вызванной сразу. Методы объекта здесь — стрелочные функции; другой способ писать методы, с this, разберём завтра.

Спрятанное легко выдать наружу, вернув его самого вместо копии: 
function makeList() {
  const items = [];
  return {
    add: (item) => items.push(item),
    all: () => items,            // отдали сам массив
  };
}

const list = makeList();
list.add("bread");
list.all().push("взлом");
console.log(list.all());   // (2) ['bread', 'взлом']
all вернула ссылку на тот же массив, и снаружи в него дописали. Правило: наружу — только копии: all: () => [...items]. Тогда push изменит копию, а спрятанный массив останется цел.

11. Замыкания в цикле: var и let

Классическая задача с собеседований. Что напечатают два цикла?

for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log("var:", i), 0);
}

for (let j = 1; j <= 3; j++) {
  setTimeout(() => console.log("let:", j), 0);
}
// var: 4
// var: 4
// var: 4
// let: 1
// let: 2
// let: 3

Таймеры срабатывают, когда оба цикла уже закончились (день 30). К этому моменту:

  • var i — одна переменная на весь скрипт: у var нет области блока. Три стрелочные функции замкнуты на неё одну, а она после цикла равна 4 — на этом значении цикл и остановился;
  • let j — своя переменная на каждый проход. Цикл for с let создаёт для каждого прохода новую запись окружения и копирует в неё текущее значение. Каждая стрелочная функция замкнута на свою j.

В спецификации копированием переменной на каждый проход занимается операция CreatePerIterationEnvironment — разберём её в курсе 3. Нам важен вывод: в циклах с функциями внутри — только let.

В старом коде, написанном до появления let, ту же задачу решали фабрикой — теперь вы понимаете, почему это работает:

function makeLogger(n) {
  return () => console.log("фабрика:", n);   // своя n у каждого вызова
}

for (var k = 1; k <= 3; k++) {
  setTimeout(makeLogger(k), 0);
}
// фабрика: 1
// фабрика: 2
// фабрика: 3

Каждый вызов makeLogger(k) скопировал текущее значение в параметр n — в новую запись окружения. Это «фотография» из раздела 8.

12. Замыкания в обработчиках событий

На странице замыкания работают постоянно. Создадим кнопки тем, как в «Карточках», только без data-атрибутов:

const topics = ["школа", "еда", "дом"];
const panel = document.createElement("div");
document.body.append(panel);

for (const topic of topics) {
  const button = document.createElement("button");
  button.textContent = topic;
  button.addEventListener("click", () => {
    console.log(`Выбрана тема: ${topic}`);
  });
  panel.append(button);
}
// нажали «еда»: Выбрана тема: еда

Обработчик сработает когда-нибудь потом, когда цикл давно закончился. Но каждый помнит свою topic: for...of с const, как и for с let, создаёт на каждый проход новую переменную.

В «Карточках» на дне 34 мы сделали иначе — записали тему в data-topic и поставили один слушатель на всю панель. Оба способа правильные:

13. Цена замыкания: память

Пока функция существует, существует и запись окружения, на которую она ссылается, — со всем, что в ней лежит. Обычно это ровно то, что нужно: ради этого замыкания и пишут. Но иногда функция держит больше, чем ей надо.

function showCount(button, words) {
  const count = words.length;             // нужно только число
  button.addEventListener("click", () => {
    console.log(`Слов: ${count}`);
  });
}

Слушатель живёт, пока живёт кнопка. По спецификации он держит запись окружения вызова showCount целиком, вместе с words. Движки умнее: обычно они хранят только те переменные, которые упоминает хоть одна вложенная функция. Здесь функция упоминает лишь count, и массив может уйти из памяти. Если бы внутри было words.length, весь массив жил бы, пока жива кнопка.

Два практических правила. Берите в замыкание то, что нужно, — число, а не весь массив ради его длины. И снимайте слушатели, которые больше не нужны, — removeEventListener из дня 27: вместе со слушателем отпустится и его окружение. Как браузер решает, что можно выбросить из памяти, — тема курса 3.

14. «Карточки»: прогресс в замыкании

Соберём всё вместе и ответим на второй вопрос из раздела 1. Спрячем выученные слова «Карточек» в замыкание: пусть менять их можно только через четыре функции. Данные — те же восемь слов из words.json дня 33, без переводов.

const words = [
  { id: 1, word: "book", topic: "школа" },
  { id: 2, word: "teacher", topic: "школа" },
  { id: 3, word: "lesson", topic: "школа" },
  { id: 4, word: "bread", topic: "еда" },
  { id: 5, word: "water", topic: "еда" },
  { id: 6, word: "apple", topic: "еда" },
  { id: 7, word: "house", topic: "дом" },
  { id: 8, word: "window", topic: "дом" },
];

function makeProgress(saved) {
  const learned = [...saved];          // своя копия: снаружи её не достать

  return {
    learn: (id) => {
      if (!learned.includes(id)) {
        learned.push(id);
      }
    },
    has: (id) => learned.includes(id),
    count: () => learned.length,
    list: () => [...learned],          // наружу — только копия
  };
}

function makeDeck(progress) {
  return (topic) => words.filter((w) => !progress.has(w.id) && (topic === "все" || w.topic === topic));
}

const progress = makeProgress([1, 2]);
const deck = makeDeck(progress);

console.log(deck("все").map((w) => w.word));
progress.learn(4);
progress.learn(4);                     // второй раз ничего не изменит
console.log(deck("еда").map((w) => w.word));
console.log(`Выучено: ${progress.count()} из ${words.length}`);

const copy = progress.list();
copy.push(5);                          // меняем копию, а не прогресс
console.log(progress.list());
console.log(typeof learned);
(6) ['lesson', 'bread', 'water', 'apple', 'house', 'window']
(2) ['water', 'apple']
Выучено: 3 из 8
(3) [1, 2, 4]
undefined

Разберём, что изменилось по сравнению с «Карточками» Essentials.

learned больше не глобальная. Последняя строка это доказывает: на верхнем уровне скрипта такого имени нет. Массив живёт в записи окружения вызова makeProgress, и путь к нему — только через learn, has, count и list. Строка learned = [] по ошибке где-то в программе теперь ничего не сломает — она создаст новую, ни с чем не связанную переменную.

Повтор не попадает в прогресс. learn(4) вызвана дважды, а выучено три слова, не четыре: проверка includes внутри сработала оба раза — первый раз пропустила, второй остановила. На дне 34 повтор был невозможен потому, что выученное слово сразу уходит из колоды; теперь прогресс защищает себя сам, кто бы ни вызвал learn.

Наружу — только копия. copy.push(5) не изменил прогресс: list отдаёт новый массив. Это правило из раздела 10.

makeDeck — фабрика. Колода больше не берёт learned и topic из глобальных переменных: прогресс она получила при создании, тему — параметром. Это правило дня 12 — «всё нужное функция получает через параметры» — доведённое до конца с помощью замыкания.

Три опыта.

Первый. Создайте второй прогресс makeProgress([]), вызовите у него learn(7) и проверьте count() у обоих. Объясните, почему они не мешают друг другу, словами раздела 7.

Второй. Замените в list копию на сам массив: list: () => learned. Посмотрите, что теперь напечатает progress.list() после copy.push(5), и найдите в выводе, какое правило нарушилось.

Третий. Уберите копирование в первой строке makeProgress: const learned = saved;. Создайте прогресс из массива start = [1, 2], выучите слово 4 и посмотрите на start. Почему изменился массив, который вы передали?

15. Что будет завтра

Сегодня методы объекта progress добирались до данных через замыкание. Есть второй способ, которым методы находят свой объект, — слово this. Завтра, на дне 2, разберём, чему оно равно в разных вызовах, почему теряется, когда метод передают в setTimeout или обработчик события, и как его закрепить с помощью call, apply и bind.

А на дне 3 вернёмся к верхней записи цепочки — глобальной: узнаем, что такое глобальный объект, откуда взялась name из раздела 4 и что меняет строгий режим.

  1. Функция showCity объявлена на верхнем уровне, а вызвана внутри функции, где есть своя city. Какую city она увидит?
    Ответ Верхнего уровня. Область видимости лексическая: что видит функция, решает место, где она написана, а не место вызова. Переменная вызывающей функции ей не видна.
  2. Что такое замыкание?
    Ответ Функция вместе со ссылкой на окружение, в котором она создана. В спецификации эта ссылка — внутренний слот [[Environment]]. Замыкание есть у каждой функции; заметным оно становится, когда функция переживает вызов, внутри которого родилась.
  3. Почему два счётчика из makeCounter() считают независимо?
    Ответ Каждый вызов функции создаёт новую запись окружения. У каждого счётчика своя count — в записи своего вызова. Если вынести count за пределы фабрики, счётчик станет общим.
  4. Почему цикл с var и setTimeout печатает 4, 4, 4, а с let — 1, 2, 3?
    Ответ var — одна переменная на весь цикл, и к моменту срабатывания таймеров она равна 4. Цикл с let создаёт новую переменную на каждый проход, и каждый колбэк помнит свою.
  5. Что делает GetIdentifierReference из раздела 9.1.2 спецификации?
    Ответ Ищет имя: если запись — null, имя не найдено; если у записи есть привязка с этим именем — нашли; иначе повторяет поиск во внешней записи [[OuterEnv]]. Это и есть цепочка областей видимости.
