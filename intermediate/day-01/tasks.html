День 1. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 делаем в консоли, дальше — в папке day-01 курса 2. Страницу для задания 7 открывайте через Live Server, как «Карточки»: у страниц, открытых двойным щелчком, одно хранилище на все файлы, и ключ cards:learned смешается с чужими.

Разминка

1. Где видно
Легко7 мин

вспомнить три области видимости из Essentials.

Предскажите три строки вывода, потом проверьте.

const a = "весь скрипт";

function f() {
  const b = "функция";
  if (a) {
    const c = "блок";
    console.log(a, b, c);
  }
  console.log(typeof c);
}

f();
console.log(typeof b);
  • три предсказания записаны до запуска;
  • для каждой из переменных a, b, c записано, какая область её создала;
  • объяснено, почему оба typeof дали undefined;
  • typeof c заменён на c — записан точный текст ошибки.
2. Где написано, а не где вызвано
Легко6 мин

увидеть лексическую область в действии.

const lang = "ru";

function hello() {
  return lang === "ru" ? "Салам" : "Hello";
}

function english() {
  const lang = "en";
  return hello();
}

console.log(english());
  • предсказание записано до запуска;
  • объяснено, какую lang видит hello и почему не ту, что в english;
  • hello переделана так, чтобы english() вернула «Hello», а глобальная lang осталась "ru";
  • записано одним предложением, какое правило дня 12 помогло.
3. Цепочка окружений
Легко7 мин

проследить поиск имени по шагам.

const course = "Intermediate";

function lesson(day) {
  const topic = "замыкания";

  function line() {
    const day = 1;
    return `${course}, день ${day}: ${topic}`;
  }

  return line();
}

console.log(lesson(5));
  • предсказание записано до запуска;
  • нарисована цепочка записей окружения в момент работы line: сколько их и куда ведёт [[OuterEnv]] каждой;
  • для course, day и topic записано, в какой записи нашлось имя;
  • объяснено, почему в строке день 1, а не 5, и что изменится, если убрать const day = 1;.

Основные задания

4. Два счётчика
Средне10 мин

написать фабрику и доказать независимость замыканий.

Напишите makeCounter(start = 0, step = 1). Каждый вызов созданной функции возвращает следующее значение: первый — start + step, дальше с тем же шагом.

const byOne = makeCounter();
const byTen = makeCounter(100, 10);
byOne();   // 1
byOne();   // 2
byTen();   // 110
byOne();   // 3
  • фабрика работает на примере выше, вывод записан;
  • создан третий счётчик, и доказано выводом, что он не сбивает первые два;
  • переменная счёта вынесена за пределы фабрики — записано, что сломалось;
  • объяснено словами «запись окружения», почему в исходной версии счётчики независимы.
5. Фабрики проверок
Средне10 мин

«запечь» настройки в функцию для filter.

Напишите две фабрики: makeRangeCheck(min, max) — проверку, что число в границах, и makeOneOf(list) — проверку, что значение есть в списке.

const isMark = makeRangeCheck(2, 5);
[5, 4, 9, 3, 5, 0, 4, 5].filter(isMark);   // [5, 4, 3, 5, 4, 5]

const isTopic = makeOneOf(["школа", "еда", "дом"]);
["еда", "спорт", "дом"].filter(isTopic);   // ["еда", "дом"]

Затем напишите обычную функцию inRange(n, min, max) и вызовите [5, 4, 9, 3, 5, 0, 4, 5].filter(inRange).

Чтобы увидеть, что filter кладёт в параметры, временно добавьте в начало inRange строку console.log(n, min, max);.
  • обе фабрики дают результаты из примера;
  • записано, что вернул filter(inRange), и что попало в min и max;
  • объяснено, почему фабрике эта беда не грозит;
  • та же проверка записана без фабрики — стрелочной функцией прямо в filter, и отмечено, что это тоже замыкание.
6. var, let и таймеры
Средне12 мин

поймать и починить главную ловушку замыканий.

for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(`проход ${i}`), 100 * i);
}

Предскажите вывод и проверьте. Потом почините тремя способами — так, чтобы печаталось «проход 1», «проход 2», «проход 3»:

  • заменой одного слова;
  • фабрикой makeLogger(n), как в разделе 11 лекции, не трогая var;
  • без цикла for вовсе — методом forEach по массиву [1, 2, 3].
  • предсказание записано до запуска, объяснено, откуда взялось число в выводе;
  • все три починки печатают нужные строки;
  • для способа с forEach объяснено, откуда у каждого колбэка своя переменная;
  • записано, какой способ выбрать в новом коде и почему.
7. Прогресс «Карточек» в замыкании
Средне18 мин

спрятать данные и сохранить их между обновлениями страницы.

Возьмите makeProgress из раздела 14 лекции и сделайте из неё makeProgress(key): при создании она читает выученные номера из localStorage по ключу (или начинает с пустого списка), а каждое изменение сразу сохраняет. Методы: learn(id), has(id), count(), list() и новый reset() — забыть всё и удалить ключ из хранилища.

const progress = makeProgress("cards:learned");
progress.learn(4);
progress.learn(4);
progress.count();                        // 1

// обновили страницу и создали прогресс заново
const again = makeProgress("cards:learned");
again.count();                           // 1 — прогресс сохранился
again.reset();
again.count();                           // 0
localStorage.getItem("cards:learned");   // null
Чтение — как в «Карточках» на дне 33: JSON.parse и ?? []. Запись — JSON.stringify (день 23). Удобно завести внутри фабрики маленькую функцию save() и вызывать её из learn.
  • повторный learn не дублирует номер;
  • после обновления страницы count() прежний;
  • после reset() ключа в хранилище нет — getItem вернул null;
  • typeof learned на верхнем уровне — "undefined";
  • list() отдаёт копию — доказано через push;
  • два прогресса с разными ключами не мешают друг другу.

Со звёздочкой

8. История с отменой
Сложно10 мин

спрятать в замыкание не одно значение, а их историю.

Напишите makeHistory(initial) с методами set(value), undo() и value(). undo возвращает true, если отменил, и false, если отменять нечего.

const theme = makeHistory("светлая");
theme.set("тёмная");
theme.set("синяя");
theme.value();   // "синяя"
theme.undo();    // true
theme.value();   // "тёмная"
theme.undo();    // true
theme.undo();    // false — отменять больше нечего
theme.value();   // "светлая"
Историю удобно хранить массивом: set кладёт в конец, undo снимает с конца (день 19). Подумайте, сколько элементов в массиве должно остаться всегда.
  • пример выше даёт те же ответы;
  • изменить историю можно только через set и undo;
  • две истории независимы — проверено;
  • перечислено, какие переменные живут в записи окружения вызова makeHistory.

Сложно10 мин

прочитать алгоритм спецификации и применить его к своему коду.

Откройте раздел 9.1.2 и в нём операцию GetIdentifierReference.

  • Перескажите её шаги своими словами.
  • Примените к программе из задания 3: запишите по шагам, как ищется course, если начать с записи вызова line.
  • Запишите, чем закончится поиск имени, которого нет нигде, и какую ошибку вы в итоге увидите в консоли.
  • Откройте раздел 9.1.1 и для каждого из пяти видов записей приведите кусок кода из нашего курса, который её создаёт. Для вида, которого в курсе пока не было, напишите, где он будет.
  • шаги пересказаны без копирования английского текста;
  • поиск course расписан по трём записям, у каждой — ответ HasBinding;
  • для несуществующего имени названо, на каком шаге поиск останавливается;
  • все пять видов записей сопоставлены с кодом или с будущим днём.
