## Разминка

<Task title="1. Где видно" level="easy" time="7">
<Goal>вспомнить три области видимости из Essentials.</Goal>

Предскажите три строки вывода, потом проверьте.

```js
const a = "весь скрипт";

function f() {
  const b = "функция";
  if (a) {
    const c = "блок";
    console.log(a, b, c);
  }
  console.log(typeof c);
}

f();
console.log(typeof b);
```

<Criteria>
- три предсказания записаны до запуска;
- для каждой из переменных `a`, `b`, `c` записано,
  какая область её создала;
- объяснено, почему оба `typeof` дали `undefined`;
- `typeof c` заменён на `c` — записан точный текст ошибки.
</Criteria>
</Task>

<Task title="2. Где написано, а не где вызвано" level="easy" time="6">
<Goal>увидеть лексическую область в действии.</Goal>

```js
const lang = "ru";

function hello() {
  return lang === "ru" ? "Салам" : "Hello";
}

function english() {
  const lang = "en";
  return hello();
}

console.log(english());
```

<Criteria>
- предсказание записано до запуска;
- объяснено, какую `lang` видит `hello` и почему не ту, что
  в `english`;
- `hello` переделана так, чтобы `english()` вернула
  «Hello», а глобальная `lang` осталась `"ru"`;
- записано одним предложением, какое правило дня 12 помогло.
</Criteria>
</Task>

<Task title="3. Цепочка окружений" level="easy" time="7">

```js
const course = "Intermediate";

```

<Criteria>
- предсказание записано до запуска;
- нарисована цепочка записей окружения в момент работы `line`: сколько их

- для `course`, `day` и `topic` записано, в какой
  записи нашлось имя;
- объяснено, почему в строке день 1, а не 5, и что изменится, если убрать

</Criteria>
</Task>

## Основные задания

<Task title="4. Два счётчика" level="medium" time="10">
<Goal>написать фабрику и доказать независимость замыканий.</Goal>

Напишите `makeCounter(start = 0, step = 1)`. Каждый вызов созданной функции
возвращает следующее значение: первый — `start + step`, дальше с тем же шагом.

<Example>
```js
const byOne = makeCounter();
const byTen = makeCounter(100, 10);
byOne();   // 1
byOne();   // 2
byTen();   // 110
byOne();   // 3
```
</Example>

<Criteria>
- фабрика работает на примере выше, вывод записан;
- создан третий счётчик, и доказано выводом, что он не сбивает первые два;
- переменная счёта вынесена за пределы фабрики — записано, что сломалось;
- объяснено словами «запись окружения», почему в исходной версии счётчики
  независимы.
</Criteria>
</Task>

<Task title="5. Фабрики проверок" level="medium" time="10">
<Goal>«запечь» настройки в функцию для `filter`.</Goal>

Напишите две фабрики: `makeRangeCheck(min, max)` — проверку, что число
в границах, и `makeOneOf(list)` — проверку, что значение есть в списке.

<Example>
```js
const isMark = makeRangeCheck(2, 5);
[5, 4, 9, 3, 5, 0, 4, 5].filter(isMark);   // [5, 4, 3, 5, 4, 5]

const isTopic = makeOneOf(["школа", "еда", "дом"]);
["еда", "спорт", "дом"].filter(isTopic);   // ["еда", "дом"]
```
</Example>

Затем напишите обычную функцию `inRange(n, min, max)` и вызовите
`[5, 4, 9, 3, 5, 0, 4, 5].filter(inRange)`.

<Hint>
Чтобы увидеть, что `filter` кладёт в параметры, временно добавьте в начало
`inRange` строку `console.log(n, min, max);`.
</Hint>

<Criteria>
- обе фабрики дают результаты из примера;
- записано, что вернул `filter(inRange)`, и что попало в `min`
  и `max`;
- объяснено, почему фабрике эта беда не грозит;
- та же проверка записана без фабрики — стрелочной функцией прямо в `filter`,
  и отмечено, что это тоже замыкание.
</Criteria>
</Task>

<Task title="6. var, let и таймеры" level="medium" time="12">
<Goal>поймать и починить главную ловушку замыканий.</Goal>

```js
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(`проход ${i}`), 100 * i);
}
```

Предскажите вывод и проверьте. Потом почините тремя способами — так, чтобы печаталось
«проход 1», «проход 2», «проход 3»:

- заменой одного слова;
- фабрикой `makeLogger(n)`, как в разделе 11 лекции, не трогая `var`;
- без цикла `for` вовсе — методом `forEach` по массиву
  `[1, 2, 3]`.

<Criteria>
- предсказание записано до запуска, объяснено, откуда взялось число в выводе;
- все три починки печатают нужные строки;
- для способа с `forEach` объяснено, откуда у каждого колбэка своя
  переменная;
- записано, какой способ выбрать в новом коде и почему.
</Criteria>
</Task>

<Task title="7. Прогресс «Карточек» в замыкании" level="medium" time="18">
<Goal>спрятать данные и сохранить их между обновлениями страницы.</Goal>

Возьмите `makeProgress` из раздела 14 лекции и сделайте из неё
`makeProgress(key)`: при создании она читает выученные номера из
`localStorage` по ключу (или начинает с пустого списка), а каждое изменение
сразу сохраняет. Методы: `learn(id)`, `has(id)`, `count()`,
`list()` и новый `reset()` — забыть всё и удалить ключ из хранилища.

<Example>
```js
const progress = makeProgress("cards:learned");
progress.learn(4);
progress.learn(4);
progress.count();                        // 1

// обновили страницу и создали прогресс заново
const again = makeProgress("cards:learned");
again.count();                           // 1 — прогресс сохранился
again.reset();
again.count();                           // 0
localStorage.getItem("cards:learned");   // null
```
</Example>

<Hint>
Чтение — как в «Карточках» на дне 33: `JSON.parse` и `?? []`.
Запись — `JSON.stringify` (день 23). Удобно завести внутри фабрики
маленькую функцию `save()` и вызывать её из `learn`.
</Hint>

<Criteria>
- повторный `learn` не дублирует номер;
- после обновления страницы `count()` прежний;
- после `reset()` ключа в хранилище нет — `getItem` вернул
  `null`;
- `typeof learned` на верхнем уровне — `"undefined"`;
- `list()` отдаёт копию — доказано через `push`;
- два прогресса с разными ключами не мешают друг другу.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. История с отменой" level="hard" time="10">
<Goal>спрятать в замыкание не одно значение, а их историю.</Goal>

Напишите `makeHistory(initial)` с методами `set(value)`,
`undo()` и `value()`. `undo` возвращает
`true`, если отменил, и `false`, если отменять нечего.

<Example>
```js
const theme = makeHistory("светлая");
theme.set("тёмная");
theme.set("синяя");
theme.value();   // "синяя"
theme.undo();    // true
theme.value();   // "тёмная"
theme.undo();    // true
theme.undo();    // false — отменять больше нечего
theme.value();   // "светлая"
```
</Example>

<Hint>
Историю удобно хранить массивом: `set` кладёт в конец, `undo`
снимает с конца (день 19). Подумайте, сколько элементов в массиве должно остаться
всегда.
</Hint>

<Criteria>
- пример выше даёт те же ответы;
- изменить историю можно только через `set` и `undo`;
- две истории независимы — проверено;
- перечислено, какие переменные живут в записи окружения вызова
  `makeHistory`.
</Criteria>
</Task>
