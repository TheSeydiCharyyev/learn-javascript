## 1. От замыкания к this {#question}

Вчера мы спрятали прогресс «Карточек» в замыкание: методы `learn`,
`count` и остальные добирались до массива через запись окружения вызова
`makeProgress`. Это один способ связать данные с действиями над ними.

Второй способ вы видели на дне 21 Essentials — объект, у которого данные лежат в свойствах,
а методы обращаются к ним через слово `this`:

```js
const group = {
  title: "1-А",
  students: [],
  add(student) {
    this.students.push(student);
  },
  size() {
    return this.students.length;
  },
};

group.add("Аман");
group.add("Мерет");
console.log(group.size());   // 2
```

Тогда мы условились: «`this` — объект, у которого метод вызвали», а полный разбор
отложили на курс 2. Отложили не зря. Определение верное, но в нём спрятано слово
«**вызвали**», и сегодня весь день будет о нём.

Вчерашнее главное правило звучало так: *что видит функция, решает место, где она
написана*. У этого правила есть ровно одно исключение, и это `this`.
Его значение решает не место в тексте, а **способ вызова**. Одна и та же
функция при разных вызовах получает разный `this`.

## 2. this — скрытый параметр вызова {#what}

Удобнее всего думать о `this` как о **параметре, которого нет в списке**.
Обычные параметры получают значения из скобок вызова. `this` получает значение
из того, *как* записан вызов:

| Как вызвали | Чему равен `this` | Где разбираем |
| --- | --- | --- |
| `obj.method()` — через точку | объект слева от точки | раздел 3 |
| `f()` — просто по имени | в обычном скрипте — глобальный объект, в строгом режиме — `undefined` | раздел 4, день 3 |
| `f.call(x)`, `f.apply(x)`, `f.bind(x)` | то, что передали: `x` | разделы 7–9 |
| `new F()` | новый, только что созданный объект | день 7 |
| стрелочная функция | своего нет — берётся снаружи, как обычная переменная | раздел 6 |

Таблица — шпаргалка на весь модуль. Строки с глобальным объектом и строгим режимом
дорасскажем завтра; сегодня все примеры — обычные скрипты, как в Essentials. В них
функция, вызванная просто по имени, получает глобальный объект — в браузере это окно,
оно же `globalThis` из дня 4:

```js
function whoAmI() {
  return this === globalThis;
}

console.log(whoAmI());   // true — вызвали без точки
```

В спецификации это отражено прямо: запись окружения вызова функции — та самая
Function Environment Record из вчерашней таблицы — хранит не только переменные,
но и значение `this` этого вызова. Каждый вызов — своя запись, значит, и свой
`this`.

## 3. Метод: объект слева от точки {#method}

Возьмём одну функцию и положим её в два объекта:

```js
function describe() {
  return `${this.student}, оценок: ${this.marks.length}`;
}

const aman = { student: "Аман", marks: [5, 4, 5], describe };
const meret = { student: "Мерет", marks: [3, 4], describe };

console.log(aman.describe());    // Аман, оценок: 3
console.log(meret.describe());   // Мерет, оценок: 2
```

Функция одна, объектов два — и `this` каждый раз свой. Короткая запись
`{ describe }` из дня 21 положила в свойство ссылку на ту же самую функцию:
`aman.describe === meret.describe` — это `true`. Функция не «принадлежит»
ни одному объекту. Она узнаёт, с кем работает, только в момент вызова — по тому,
что стоит **слева от точки**.

<Scheme src="scheme-method.svg">Функция одна, вызовов три — и три разных this</Scheme>

Слева от точки может стоять что угодно, что даёт объект: переменная, элемент массива,
результат другого вызова. Важен **последний** объект перед точкой:

```js
const school = {
  group: {
    title: "1-А",
    show() {
      return this.title;
    },
  },
};

console.log(school.group.show());   // 1-А — this это group, а не school
```

<Analogy>
`this` — как слово «я» в речи. Фразу «я опоздал» может сказать кто угодно,
и «я» каждый раз означает того, кто говорит. Сама фраза не знает, чья она: это решается,
когда её произносят. Метод — такая же фраза, а объект слева от точки — тот, кто её
произносит.
</Analogy>

### Крайние случаи

Правило «слева от точки» работает и там, где точки как будто нет. Четыре записи,
которые встречаются в чужом коде:

```js
const card = {
  word: "bread",
  show() {
    return this.word;
  },
};

const tools = [
  function () {
    return this.length;
  },
];

console.log(tools[0]());         // 1 — this это массив tools
console.log((card.show)());      // bread
console.log(card.show?.());      // bread
console.log((0, card.show)());   // undefined
```

| Запись | `this` | Почему |
| --- | --- | --- |
| `tools[0]()` | массив `tools` | квадратные скобки — такой же доступ к свойству, как точка (день 21) |
| `(card.show)()` | `card` | скобки вокруг только группируют (день 8), метод не отделяется |
| `card.show?.()` | `card` | необязательная цепочка из дня 22 тоже вызывает через объект |
| `(0, card.show)()` | глобальный объект | оператор «запятая» (день 7) вернул голую функцию без объекта |

Последняя запись выглядит как нарочно испорченная — и она действительно нарочная.
Её вставляют программы-сборщики, когда им нужно вызвать функцию **без**
объекта. Если увидите `(0, …)()` в коде, собранном такой программой, — это
не опечатка, а способ сказать «вызвать без `this`».

## 4. Потерянный this {#lost}

Раз `this` решается при вызове, его легко потерять: достаточно вызвать метод
**без точки**.

```js
const progress = {
  learned: [1, 2],
  count() {
    return this.learned.length;
  },
};

console.log(progress.count());   // 2

const count = progress.count;    // взяли метод, объект остался
console.log(count());            // TypeError: Cannot read properties of undefined (reading 'length')
```

Строка `const count = progress.count` скопировала в переменную ссылку на функцию —
и только. Об объекте `progress` функция ничего не помнит: свойство — не замыкание.
Вызов `count()` идёт без точки, `this` становится глобальным объектом,
у окна нет свойства `learned`, получается `undefined`, а у
`undefined` нет `length`. Правило дня 5 Essentials: смотрим влево
от точки, на `this.learned`.

<Important>
Главное, что нужно запомнить сегодня: **метод, отделённый от объекта, теряет
`this`**. Отделяет его любая запись, где после имени метода не стоят
сразу круглые скобки: присваивание в переменную, передача аргументом, запись в массив.
Скобки `progress.count()` — вызов с объектом. Без скобок
`progress.count` — просто функция, без объекта.
</Important>

Бывает и хуже, чем ошибка: метод тихо работает с чужим объектом. Глобальный объект
браузера большой, и в нём есть свойства с самыми обычными именами — `name`
из вчерашнего раздела 4, `status`, `length`. Потерянный
`this.name` не упадёт, а вернёт пустую строку. Поэтому проверять надо
не только «нет ли ошибки», но и «то ли напечаталось».

### Как узнать, чей это this

Когда метод ведёт себя странно, не гадайте — проверьте. Порядок такой.

<Step n="1" numberTag="span">
Напечатайте в начале метода, чем оказался `this`. Сравнения
с ожидаемым объектом и с `globalThis` отвечают сразу и коротко.
</Step>

<Step n="2" numberTag="span">
Найдите **место вызова** — не место, где метод написан, а строку,
которая его вызвала. Её показывает стек вызовов из дня 11.
</Step>

<Step n="3" numberTag="span">
Посмотрите, что стоит слева от точки в этом вызове. Если вызова в вашем коде
не видно — метод вызвал таймер, кнопка или метод массива, значит, его отделили.
</Step>

<Step n="4" numberTag="span">
Выберите лекарство из раздела 11 и снова проверьте шаг 1.
</Step>

```js
const card = {
  word: "teacher",
  show() {
    console.log(this === card, this === globalThis);   // шаг 1
    console.log(`Карточка: ${this.word}`);
  },
};

setTimeout(card.show, 0);
// false true
// Карточка: undefined
```

Первая строка вывода уже всё объяснила: `this` — не карточка, а глобальный
объект. Значит, метод вызвали без точки, и виновник — `setTimeout`.

<ProTip>
То же видно без единой строки кода. Поставьте в методе `debugger` из дня 2
Essentials и откройте инструменты разработчика: в панели **Scope** справа
первой строкой стоит `this` с его текущим значением, а в панели
**Call Stack** — кто вызвал метод. Для `setTimeout(card.show, 0)`
там будет `this: Window`, и в стеке не окажется ни одной вашей строки
с `card.show()`.
</ProTip>

## 5. this в колбэках: таймеры и события {#callbacks}

Чаще всего метод отделяют не руками, а передавая его в чужую функцию — колбэком
из дня 12. Чужая функция потом вызывает его так, как считает нужным, и точки там нет.

### Таймер

```js
const card = {
  word: "teacher",
  show() {
    console.log(`Карточка: ${this.word}`);
  },
};

card.show();                 // Карточка: teacher
setTimeout(card.show, 0);    // Карточка: undefined
```

`setTimeout` получил функцию `show` без объекта и вызвал её с
`this`, равным окну. `window.word` не существует — отсюда
`undefined`. Ошибки нет, просто неправда на экране.

### Метод массива

```js
const quiz = {
  prefix: "Слово:",
  print(word) {
    console.log(this.prefix, word);
  },
};

["bread", "water"].forEach(quiz.print);
// undefined bread
// undefined water
```

`forEach` вызывает колбэк без объекта (день 20), и `this.prefix`
ищется у окна. Для таких случаев у `forEach`, `map`,
`filter` и соседей есть второй аргумент — что использовать как `this`:
`forEach(quiz.print, quiz)`. Но его редко помнят, и чаще пользуются способами
из разделов 6 и 9.

### Обработчик события

Обработчик, переданный в `addEventListener`, вызывается не без объекта,
а с другим объектом: `this` — элемент, на котором висит слушатель, тот самый
`event.currentTarget` из дня 27.

```js
const button = document.createElement("button");
button.textContent = "Знаю";
document.body.append(button);

button.addEventListener("click", function () {
  console.log(this === button);   // true — this это кнопка
});

button.click();
```

Удобно, пока функция написана для кнопки. Но если передать метод объекта, он получит
кнопку вместо своего объекта:

```js
const progress = {
  learned: [],
  learn() {
    this.learned.push(7);
    console.log(this.learned);
  },
};

const known = document.createElement("button");
document.body.append(known);
known.addEventListener("click", progress.learn);
known.click();
// TypeError: Cannot read properties of undefined (reading 'push')
```

У кнопки нет свойства `learned`. Ошибка появится не при запуске программы,
а при первом нажатии — поэтому такие ошибки находят поздно.

## 6. Стрелочные функции: свой this не заводят {#arrow}

На дне 13 мы видели: у стрелочной функции нет своего `this`. Теперь можно
сказать точнее, что это значит. Стрелочная функция ищет `this`
**так же, как вчера искались переменные**: снаружи, по тексту программы.
Её `this` — это `this` той функции, внутри которой стрелочная
написана.

```js
const timer = {
  seconds: 0,
  start() {
    setTimeout(() => {
      this.seconds = this.seconds + 1;   // this — тот же, что у start
      console.log(`Прошло: ${this.seconds}`);
    }, 0);
  },
};

timer.start();   // Прошло: 1
```

`setTimeout` вызвал стрелочную функцию без объекта — но ей это безразлично:
своего `this` она не получает, и слово `this` внутри неё означает
`this` метода `start`. А `start` вызвали как
`timer.start()`, значит, это `timer`.

В спецификации это выглядит так. У записи окружения обычной функции есть привязка
`this`, у записи стрелочной — нет: её `HasThisBinding` отвечает «нет»
(раздел [9.1.1.3](https://tc39.es/ecma262/2026/#sec-function-environment-records)).
Поэтому поиск `this` идёт по `[[OuterEnv]]` наружу, до первой записи,
у которой он есть, — тем же путём, что поиск имени из вчерашнего раздела 5.

<Mistake>
Обратная сторона — стрелочная функция **в роли метода**. Её
`this` берётся не от объекта, а оттуда, где написан сам объект:

```js
const student = {
  marks: [5, 4],
  count: () => this.marks.length,   // this — снаружи объекта
};

student.count();
// TypeError: Cannot read properties of undefined (reading 'length')
```

Фигурные скобки объекта — не функция и не блок со своим `this`. Снаружи
объекта `this` — глобальный объект, и `this.marks` не найдено.
Отсюда правило дня 13: **методом стрелочную не делают, а внутри метода —
делают**.
</Mistake>

И последнее про стрелочные: `this` у них нельзя поменять ничем, даже
`call` и `bind`, которые мы сейчас разберём, — их первый аргумент
стрелочная функция просто не использует.

## 7. call: вызвать с нужным this {#call}

У каждой функции есть три метода, которые позволяют задать `this` явно.
Первый — `call`: вызывает функцию **прямо сейчас**, первым аргументом
принимает `this`, остальные передаёт как обычные аргументы.

```js
function describe(prefix) {
  return `${prefix} ${this.student}, оценок: ${this.marks.length}`;
}

const sapar = { student: "Сапар", marks: [5, 5, 4, 5] };

console.log(describe.call(sapar, "Студент"));   // Студент Сапар, оценок: 4
```

Запись `describe.call(sapar, "Студент")` — то же, что
`sapar.describe("Студент")`, только класть функцию в объект не пришлось.

### Заимствование методов

Главное применение `call` — взять метод у одного объекта и вызвать на другом.
Например, у `arguments` из дня 14 нет методов массива, хотя он похож на массив:
есть номера и `length`. Метод `join` можно одолжить у любого массива,
даже пустого:

```js
function list() {
  return [].join.call(arguments, ", ");
}

console.log(list("школа", "еда", "дом"));   // школа, еда, дом
```

`[].join` — функция `join`, взятая у пустого массива. Вызвав её через
`call` с `arguments` в роли `this`, мы заставили её склеить
чужие элементы. Метод `join` не проверяет, массив ли перед ним: ему хватает номеров
и `length`. Сегодня такой код пишут через `...rest` (день 14), но в чужом
коде старого стиля вы встретите `call` много раз.

## 8. apply: аргументы массивом {#apply}

`apply` делает то же, что `call`, но аргументы принимает
**одним массивом**:

```js
console.log(describe.apply(sapar, ["Студент"]));   // Студент Сапар, оценок: 4
```

Как не перепутать: **A**pply — **A**rray, массив;
**C**all — **C**omma, через запятую.

До появления `...spread` (день 22) `apply` был единственным
способом передать массив как список аргументов. Классический пример — максимум
из массива:

```js
const marks = [5, 4, 9, 3];

console.log(Math.max.apply(null, marks));   // 9 — старый способ
console.log(Math.max(...marks));            // 9 — сегодняшний
```

`Math.max` не пользуется `this`, поэтому первым аргументом передают
`null` — «всё равно что». Сегодня в таких местах пишут `...`,
и `apply` остаётся для одного случая: когда нужно и задать `this`,
и передать готовый массив аргументов.

### Если this — не объект

Что будет, если передать в `call` или `apply` не объект? В обычном
скрипте функция всё равно получит объект: `null` и `undefined`
заменяются глобальным объектом, а число или строка — оборачиваются в объект-обёртку:

```js
function whoAmI() {
  return this === globalThis;
}

function kind() {
  return typeof this;
}

console.log(whoAmI.call(null));   // true — null заменён глобальным объектом
console.log(kind.call(5));        // object — число обёрнуто, а не number
console.log(kind.call("Мары"));   // object
```

Это правило старое и неудобное: передали `null` — получили окно, передали
число — получили не число. В строгом режиме оно отменено, и `this` остаётся ровно
тем, что передали. Как именно — завтра.

## 9. bind: закрепить this {#bind}

`call` и `apply` вызывают функцию сразу. А в разделе 5 нам нужно
было другое: **отдать** метод таймеру или кнопке так, чтобы он не потерял объект,
когда его вызовут потом. Для этого есть `bind`: он **не вызывает**
функцию, а возвращает новую, у которой `this` закреплён навсегда.

```js
const card = {
  word: "teacher",
  show() {
    console.log(`Карточка: ${this.word}`);
  },
};

const showCard = card.show.bind(card);   // новая функция, this = card
setTimeout(showCard, 0);                 // Карточка: teacher
```

<Scheme src="scheme-bind.svg">Привязанная функция — обёртка, которая помнит исходную функцию и её this</Scheme>

Имена в двойных скобках на схеме — внутренние слоты привязанной функции из спецификации
(раздел [10.4.1](https://tc39.es/ecma262/2026/#sec-bound-function-exotic-objects),
курс 3). Из кода их не достать, а в консоли Chrome видны похожие: наберите
`showCard` и раскройте вывод — там будут `[[TargetFunction]]`,
`[[BoundThis]]` и `[[BoundArgs]]`. Chrome называет их чуть короче,
чем спецификация.

### Закреплено навсегда

`this` привязанной функции не меняет уже ничто — ни вызов через точку, ни
`call`, ни второй `bind`:

```js
const card = { word: "teacher", show() { return this.word; } };
const other = { word: "water" };

const showCard = card.show.bind(card);
console.log(showCard.call(other));         // teacher — call не помог
console.log(showCard.bind(other)());       // teacher — второй bind тоже
other.show = showCard;
console.log(other.show());                 // teacher — и точка не помогла
```

### Закрепить и аргументы

Кроме `this`, `bind` может закрепить первые аргументы. Получается
функция с меньшим числом параметров — приём называется **частичным применением**:

```js
function multiply(a, b) {
  return a * b;
}

const double = multiply.bind(null, 2);   // this не нужен, a = 2 навсегда
console.log(double(21));                 // 42
console.log(double.length);              // 1 — остался один параметр
```

Узнали? Это фабрика из вчерашнего раздела 9, только написанная одной строкой: настройка
`2` «запеклась» в новую функцию.

### А где же кнопка?

Привязали метод к объекту и отдали кнопке — теперь `this` внутри обработчика
объект, а не кнопка. Но кнопка часто тоже нужна: прочитать её `data-`атрибут,
поменять текст. Её не теряют: она приходит в объекте события, в
`event.currentTarget` из дня 27.

```js
const progress = {
  learned: [],
  learn(event) {
    this.learned.push(event.currentTarget.dataset.id);   // объект — this, кнопка — event
    console.log(this.learned);
  },
};

const word = document.createElement("button");
word.dataset.id = "4";
document.body.append(word);

word.addEventListener("click", progress.learn.bind(progress));
word.click();   // (1) ['4']
```

Отсюда правило для обработчиков: **элемент берите из `event.currentTarget`,
а не из `this`**. Так код работает одинаково с обычной функцией,
со стрелочной и с привязанной — и не ломается, когда обработчик переписывают из одной
формы в другую.

## 10. bind и removeEventListener {#remove}

У `bind` есть ловушка, которая бьёт именно по обработчикам событий.
На дне 27 мы выяснили: `removeEventListener` снимает обработчик, только если
ему передали **ту же самую** функцию. А `bind` при каждом вызове
создаёт **новую**:

```js
const counter = {
  clicks: 0,
  inc() {
    this.clicks = this.clicks + 1;
  },
};

console.log(counter.inc.bind(counter) === counter.inc.bind(counter));   // false

const plus = document.createElement("button");
document.body.append(plus);

plus.addEventListener("click", counter.inc.bind(counter));
plus.removeEventListener("click", counter.inc.bind(counter));   // не снимет: другая функция
plus.click();
console.log(counter.clicks);   // 1 — обработчик всё ещё висит
```

Лечится так же, как на дне 27 со стрелочными функциями: привязанную функцию
**сохраняют в переменную** и передают и туда, и туда одну и ту же:

```js
const counter = {
  clicks: 0,
  inc() {
    this.clicks = this.clicks + 1;
  },
};

const plus = document.createElement("button");
document.body.append(plus);

const onClick = counter.inc.bind(counter);   // одна функция на оба вызова
plus.addEventListener("click", onClick);
plus.click();
plus.removeEventListener("click", onClick);  // снят
plus.click();
console.log(counter.clicks);   // 1 — второе нажатие уже не посчитано
```

## 11. Три способа не потерять this {#ways}

Соберём вместе. Метод `card.show` нужно отдать таймеру — три рабочих способа:

```js
const card = {
  word: "teacher",
  show() {
    console.log(`Карточка: ${this.word}`);
  },
};

setTimeout(card.show.bind(card), 0);    // 1. bind
setTimeout(() => card.show(), 0);       // 2. стрелочная обёртка: вызов через точку
setTimeout(function () {                // 3. обычная обёртка — то же, длиннее
  card.show();
}, 0);
// Карточка: teacher — трижды
```

| Способ | Как работает | Когда удобен |
| --- | --- | --- |
| `bind` | новая функция с закреплённым `this` | нужна функция, которую можно сохранить и потом снять |
| стрелочная обёртка | внутри обычный вызов через точку | короткий колбэк по месту; можно добавить аргументы |
| стрелочная внутри метода | берёт `this` метода снаружи | колбэк пишется внутри другого метода того же объекта |

<ProTip>
Стрелочная обёртка и `bind` различаются в одной тонкости. Обёртка
`() => card.show()` берёт `card` **в момент вызова**,
через замыкание. Если до срабатывания таймера в переменную `card` положат
другой объект, вызовется метод нового. `bind` запомнил объект
**в момент привязки** и об этой переменной больше не знает.
</ProTip>

## 12. Встроенные методы и чужой this {#incompatible}

Свои методы, потеряв `this`, обычно падают на чтении свойства или тихо врут.
Встроенные ведут себя строже: многие сразу проверяют, на том ли объекте их вызвали,
и выдают ошибку об этом. Например, методы даты:

```js
const date = new Date(2026, 9, 14);
const getYear = date.getFullYear;   // отделили метод от даты

getYear();
// TypeError: this is not a Date object.
```

Методы страницы — ещё короче:

```js
const find = document.querySelector;
find("body");
// TypeError: Illegal invocation
```

И третий вариант, из той же семьи: `bind`, оторванный от своей функции:

```js
function hello() {
  return "Салам";
}

["Аман", "Мерет"].forEach(hello.bind);
// TypeError: Bind must be called on a function
```

`forEach` вызвал `bind` без функции слева от точки — и
`bind` честно сказал, что работать ему не с чем.

На MDN все три — одна страница ошибки, озаглавленная по Firefox: «X.prototype.y called
on incompatible type». В Chrome текст каждый раз свой: `this is not a Date object.`,
`Illegal invocation`, `Bind must be called on a function`. Смысл
одинаковый: **метод вызвали не на том объекте**. Лечится тоже одинаково:

```js
const find = document.querySelector.bind(document);
console.log(find("body") === document.body);   // true
```

## 13. «Карточки»: карточка с методами {#cards}

Соберём день в одну программу. Вместо отдельных переменных `position` и
`flipped`, как на дне 33, сделаем объект-викторину: данные в свойствах, действия —
в методах. Три слова темы «еда» — из того же `words.json`.

```js
const words = [
  { id: 4, word: "bread", translation: "хлеб" },
  { id: 5, word: "water", translation: "вода" },
  { id: 6, word: "apple", translation: "яблоко" },
];

const quiz = {
  position: 0,
  flipped: false,

  current() {
    return words[this.position];
  },
  text() {
    const w = this.current();
    return this.flipped ? w.translation : w.word;
  },
  flip() {
    this.flipped = !this.flipped;
    console.log(`перевернули: ${this.text()}`);
  },
  next() {
    this.position = (this.position + 1) % words.length;
    this.flipped = false;
    console.log(`следующая: ${this.text()}`);
  },
  autoFlip(ms) {
    setTimeout(() => this.flip(), ms);   // стрелочная берёт this у autoFlip
  },
};

const flipButton = document.createElement("button");
flipButton.textContent = "Перевернуть";
document.body.append(flipButton);
flipButton.addEventListener("click", quiz.flip.bind(quiz));

console.log(quiz.text());
quiz.next();
flipButton.click();       // как будто нажали
quiz.autoFlip(0);
```

<ResultBox>
bread\
следующая: water\
перевернули: вода\
перевернули: water
</ResultBox>

Каждая строка вывода показывает одно правило дня.

**`quiz.text()` и `quiz.next()`** — вызовы через точку:
`this` — `quiz` (раздел 3). Методы вызывают друг друга тоже через
`this`: `this.current()`, `this.text()` — тоже вызов через
точку, и `this` передаётся дальше.

**Кнопка** получила `quiz.flip.bind(quiz)`. Без `bind`
внутри `flip` оказалась бы кнопка (раздел 5), и `this.text` не нашлось бы.

**`autoFlip`** отдаёт таймеру стрелочную функцию: своего
`this` у неё нет, она берёт его у `autoFlip`, а `autoFlip`
вызвали как `quiz.autoFlip(0)` (раздел 6). Последняя строка вывода появилась
позже остальных — таймер сработал, когда программа уже закончилась (день 30), — и всё равно
знала свой объект.

## 14. Замыкание или this {#choose}

Вчера прогресс жил в замыкании, сегодня викторина живёт в объекте с `this`.
Оба способа рабочие, и в чужом коде вы встретите оба. Чем они отличаются:

|  | Замыкание, день 1 | `this`, сегодня |
| --- | --- | --- |
| где данные | в записи окружения вызова фабрики | в свойствах объекта |
| видны ли снаружи | нет, только через функции | да: `quiz.position = 99` сработает |
| метод отдали колбэком | работает как есть | нужен `bind` или обёртка |
| сколько функций создаётся | свой набор на каждый вызов фабрики | методы можно сделать общими для многих объектов (день 7) |
| куда ведёт дальше | модули, день 30 | прототипы и классы, дни 7–10 |

Классы, к которым мы придём на дне 8, построены на `this`. Поэтому всё, что
сегодня ломалось — потерянный метод, таймер, обработчик, — будет ломаться у классов точно
так же, и лечиться теми же способами.

## 15. Что будет завтра {#next}

Сегодня строка таблицы «вызов без точки — глобальный объект» прозвучала с оговоркой:
«в обычном скрипте». Завтра, на дне 3, разберём **строгий режим**: в нём
потерянный `this` становится `undefined`, тихая ошибка превращается
в громкую, и ещё десяток правил языка становятся строже. Заодно узнаем, что такое
глобальный объект, откуда у него `name` и чем `globalThis` лучше
`window`.

<Selfcheck>
1. Одна функция лежит в двух объектах. Откуда она узнаёт, с каким работать?
   <Answer>Из вызова: `this` — объект слева от точки в момент вызова.
   Сама функция ни одному объекту не принадлежит.</Answer>
2. Почему `setTimeout(card.show, 0)` печатает `undefined`
   вместо слова?
   <Answer>`card.show` без скобок — просто функция, без объекта. Таймер вызывает
   её без точки, `this` в обычном скрипте становится глобальным объектом,
   у которого нет свойства `word`.</Answer>
3. Чем `call` отличается от `apply`, а оба они — от `bind`?
   <Answer>`call` и `apply` вызывают функцию сразу; `call`
   принимает аргументы через запятую, `apply` — массивом.
   `bind` не вызывает, а возвращает новую функцию с закреплённым
   `this` и, если нужно, первыми аргументами.</Answer>
4. Почему стрелочная функция внутри метода видит объект, а стрелочная функция
   в роли метода — нет?
   <Answer>Своего `this` у стрелочной нет, она берёт его снаружи, по тексту.
   Внутри метода «снаружи» — сам метод с его `this`. В роли метода
   «снаружи» — место, где написан объект, а фигурные скобки объекта своего
   `this` не создают.</Answer>
5. Почему `removeEventListener("click", obj.m.bind(obj))` не снимает
   обработчик, добавленный так же?
   <Answer>Каждый вызов `bind` создаёт новую функцию, а снять можно только
   ту же самую. Привязанную функцию сохраняют в переменную и передают её
   в оба вызова.</Answer>
</Selfcheck>
