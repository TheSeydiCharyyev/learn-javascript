1. Тихие ошибки

За два дня курса мы трижды встретили одну и ту же неприятность: программа делает неправильно и молчит. Соберём их вместе — все они уже знакомы.

let total = 0;
totl = total + 5;                  // день 4 Essentials: опечатка создала глобальную переменную

const marks = Object.freeze([5, 4]);
marks[0] = 2;                      // тоже день 4: запись в замороженный массив пропала

const card = {
  word: "teacher",
  show() {
    return `Карточка: ${this.word}`;
  },
};
const show = card.show;            // вчера: метод отделили от объекта

console.log(total, marks[0], show());   // 0 5 Карточка: undefined

Три строки — три ошибки, и ни одного красного сообщения. Такие ошибки самые дорогие: их не видно в момент, когда они случились, и находят их по последствиям — неверному числу, пустому слову, — часто через неделю.

Почему язык так себя ведёт? В 1995 году JavaScript делали для маленьких скриптов на страницах, и решили: пусть лучше скрипт доработает хоть как-нибудь, чем упадёт. Через десять лет программы выросли, и стало ясно, что тишина вредит. Но поменять поведение уже было нельзя — сломались бы миллионы сайтов. Решение нашли в 2009 году, в редакции ES5: строгий режим, который каждый включает для своего кода сам.

ГодРедакцияЧто произошло
1995первая версия языкатихий режим — единственный
2009ES5появился строгий режим и директива "use strict"
2015ES2015классы и модули — строгие всегда, без директивы
2020ES2020одно имя глобального объекта — globalThis

Отсюда и план дня: сначала строгий режим, потом глобальный объект — та часть языка, где тихий режим наследил больше всего.

2. Как включить строгий режим

Строгий режим включается строкой-директивой — обычной строкой "use strict", стоящей первой инструкцией скрипта или функции:

"use strict";

let total = 0;
totl = total + 5;   // ReferenceError: totl is not defined

Старые движки, не знавшие строгого режима, видели здесь просто строку, которая ничего не делает, и не ломались. Новые понимают её как приказ. Отсюда и странная форма — строка в кавычках, а не новое слово языка.

Третий случай схемы — самая частая ошибка с директивой: её нет смысла ставить посередине. Проверим:

console.log("старт");
"use strict";                 // уже не первая инструкция — просто строка
totl = 5;
console.log(globalThis.totl); // 5 — режим остался обычным

Узнать, строгий ли код в данном месте, проще всего по this вызова без объекта — к нему мы придём в разделе 4:

function isStrict() {
  "use strict";
  return this === undefined;
}

function isSloppy() {
  return this === globalThis;
}

console.log(isStrict(), isSloppy());   // true true

Обычный режим по-английски часто называют sloppy mode — «небрежный режим». Название неофициальное, но вы его встретите в статьях и на MDN.

В консоли Chrome каждая введённая порция кода — отдельный скрипт. Чтобы проверить что-то в строгом режиме, пишите "use strict"; первой строкой в том же вводе, что и проверяемый код: строка, введённая отдельно, на следующий ввод не подействует.

3. Ошибки вместо тишины

Первая группа изменений: то, что в обычном режиме молча не срабатывало, в строгом бросает ошибку.

Что делаемОбычный режимСтрогий режим
присвоить необъявленной: totl = 5создаётся глобальная переменнаяReferenceError: totl is not defined
записать в замороженный объект: o.x = 2молча не записываетсяTypeError: Cannot assign to read only property 'x' of object '#<Object>'
добавить свойство замороженному: o.y = 2молча не добавляетсяTypeError: Cannot add property y, object is not extensible
удалить свойство замороженного: delete o.xвозвращает falseTypeError: Cannot delete property 'x' of #<Object>
переписать undefined или NaNмолча не переписываетсяTypeError: Cannot assign to read only property 'undefined' of object '#<Window>'

Обычный режим для сравнения — все три изменения замороженного объекта проходят без звука:

const o = Object.freeze({ x: 1 });
o.x = 2;
o.y = 3;
console.log(delete o.x, JSON.stringify(o));   // false {"x":1}

И строгий — первая же строка останавливает программу:

"use strict";
const o = Object.freeze({ x: 1 });
o.x = 2;   // TypeError: Cannot assign to read only property 'x' of object '#<Object>'

Последняя строка таблицы любопытна: undefined и NaN — не слова языка, а свойства глобального объекта, защищённые от записи. В обычном режиме undefined = 1 не делает ничего, в строгом — честно отказывает. Глобальный объект разберём в разделе 9.

4. this без объекта

Вчера таблица вызовов сказала: «f() — в обычном скрипте глобальный объект, в строгом режиме undefined». Теперь вторая половина:

"use strict";

function who() {
  return this;
}

console.log(who());                // undefined — вызвали без объекта
console.log(who.call(null));       // null — передали null, его и получили
console.log(typeof who.call(5));   // number — число не обёрнуто

Сравните со вчерашним разделом 8: там call(null) давал глобальный объект, а call(5) — объект-обёртку. В строгом режиме this — ровно то, что передали, без подмен.

Главный практический выигрыш — потерянный метод теперь падает сразу и с понятным текстом. Вчерашний пример с прогрессом:

"use strict";

const progress = {
  learned: [1, 2],
  count() {
    return this.learned.length;
  },
};

const count = progress.count;
count();   // TypeError: Cannot read properties of undefined (reading 'learned')

Вчера в обычном режиме ошибка говорила (reading 'length'): this был окном, this.learned давал undefined, и падение случалось на шаг позже. Сегодня this сам undefined, и текст указывает прямо на learned — на то место, где объект потерялся. А метод, который читал бы this.word и тихо возвращал undefined, теперь тоже упадёт.

Классы, которые придут на дне 8, — строгие всегда. Поэтому метод класса, отделённый от объекта, всегда падает с этой ошибкой, а не врёт молча. Всё, что вчера говорилось о bind и стрелочных обёртках, для классов обязательно.

5. Запреты в самом тексте программы

Вторая группа изменений — запреты, которые проверяются до запуска. Код с таким нарушением не начнёт работать вовсе: SyntaxError, как опечатка в скобках из дня 8 Essentials. Вот семь таких ошибок, у каждой своя страница на MDN:

Что написали в строгом кодеСообщение ChromeПочему запрещено
let eval = 1;, function f(arguments) {}SyntaxError: Unexpected eval or arguments in strict modeэти имена заняты служебными вещами языка
let x = 1; delete x;SyntaxError: Delete of an unqualified identifier in strict mode.delete удаляет свойства, а не переменные
function f(a = 1) { "use strict"; }SyntaxError: Illegal 'use strict' directive in function with non-simple parameter listпараметры по умолчанию разобраны раньше, чем прочитана директива
let package = 1;SyntaxError: Unexpected strict mode reserved wordслово оставлено языку на будущее
label: function f() {}SyntaxError: In strict mode code, functions can only be declared at top level or inside a block.функция с меткой (день 10 Essentials) ничего не даёт
010SyntaxError: Octal literals are not allowed in strict mode.ведущий ноль путали с десятичным числом
"\05"SyntaxError: Octal escape sequences are not allowed in strict mode.тот же ноль, но внутри строки

Несколько пояснений.

Зарезервированные слова. В строгом режиме нельзя называть переменные девятью словами: implements, interface, let, package, private, protected, public, static, yield. Их отложили для будущих возможностей языка, и часть уже пригодилась: let вы знаете, static придёт на дне 9, yield — на дне 12.

Восьмеричные числа. В обычном режиме 010 — это 8, а не 10: ведущий ноль включал восьмеричную систему. Ошибка была слишком частой, поэтому в строгом режиме такая запись запрещена. Восьмеричное число пишут явно — 0o10, запись из дня 3 Essentials. То же внутри строк: вместо "\05" пишут "\x05" или "\u0005".

console.log(010, 0o10);   // 8 8 — в обычном режиме ноль впереди меняет систему счисления

Директива и параметры по умолчанию. Запрет выглядит странно, пока не вспомнишь порядок работы. Параметры с умолчаниями (день 14 Essentials) — это код, и разобрать его нужно раньше тела функции. Директива же стоит в теле. Получилось бы, что выражения в скобках уже прочитаны по одним правилам, а директива задним числом требует других. Чтобы такого спора не было, спецификация разрешает директиву внутри функции только при простых параметрах — без умолчаний, без ...rest и без деструктуризации. Выход простой: директива в начале файла делает строгим всё сразу, включая параметры.

Повтор имён параметров. На дне 14 Essentials мы видели: в обычном режиме function f(a, a) разрешена ради старого кода. В строгом — всегда SyntaxError: Duplicate parameter name not allowed in this context.

with — устаревшая инструкция, которая подмешивает свойства объекта в область видимости. В строгом режиме она запрещена целиком; разберём её в курсе 3, вместе с той самой Object Environment Record из таблицы дня 1.

6. arguments и eval

Строгий режим меняет и две служебные вещи.

arguments в обычной функции связан с параметрами: поменяли параметр — поменялся и arguments. В строгой — это просто копия на момент вызова:

function sloppy(a) {
  a = 10;
  return arguments[0];
}

function strict(a) {
  "use strict";
  a = 10;
  return arguments[0];
}

console.log(sloppy(1), strict(1));   // 10 1

Подробно об arguments — завтра, на дне 4, вместе с его устаревшим свойством callee, которое строгий режим тоже запрещает.

eval — функция, которая выполняет строку как код. В обычном режиме переменные, объявленные внутри такой строки, просачиваются наружу; в строгом — остаются внутри. Саму eval разбираем в курсе 3, и это тот редкий случай, когда хороший совет — не пользоваться ею вовсе.

7. Приложение C спецификации

Все отличия строгого режима собраны в одном месте спецификации — приложении C, «The Strict Mode of ECMAScript». Пометка informative в его заголовке значит «пояснительное»: само приложение правил не устанавливает. Правила записаны в основном тексте, в разделах о присваивании, delete, функциях, а приложение собирает их в список и у каждого пункта даёт номер раздела, где правило записано. Это удобная точка входа.

Перескажем пункты приложения, сгруппировав их по смыслу:

  • слова: девять зарезервированных слов; запрет имён eval и arguments — для переменных, параметров, параметра catch и для присваивания им;
  • числа и строки: нельзя восьмеричные числа с ведущим нулём и восьмеричные escape-последовательности;
  • присваивание: необъявленное имя — ReferenceError вместо новой глобальной переменной; запись в свойство только для чтения, в свойство без сеттера (день 5) или новое свойство нерасширяемого объекта (день 6) — TypeError;
  • delete: удалять имя переменной — SyntaxError; удалять неудаляемое свойство — TypeError;
  • функции: this не подменяется ни на глобальный объект, ни на обёртку; повтор имён параметров запрещён; arguments не связан с параметрами, а его callee бросает ошибку;
  • прочее: with запрещён; eval не объявляет переменных снаружи.

Два пункта вы ещё не можете проверить — свойства без сеттера и нерасширяемые объекты. Они появятся на днях 5 и 6, и тогда строгий режим снова окажется полезным: без него оба случая — опять тишина.

8. Чего строгий режим не ловит

Строгий режим — не проверка всего подряд. Опечатку в имени переменной он ловит, а в имени свойства — нет:

"use strict";

const quiz = { position: 0 };
quiz.positon = 1;               // опечатка в свойстве — ошибки нет
console.log(quiz.position);     // 0
console.log(Object.keys(quiz)); // (2) ['position', 'positon']

Добавлять новые свойства обычному объекту законно, и строгий режим не может знать, что positon — опечатка, а не новое поле. Защитить объект от новых свойств можно, и способов несколько — Object.seal и его соседи, день 6. А редактор с линтером из дня 4 Essentials найдёт и то, и другое ещё до запуска.

Не ловит строгий режим и логических ошибок: неверную формулу, перепутанный порядок аргументов, лишнюю единицу. Он делает громче только то, что язык и так считал подозрительным.

9. Глобальный объект и globalThis

Теперь вторая тема дня. Глобальный объект — объект, который существует до начала любого скрипта и хранит встроенное: Math, JSON, parseInt, undefined, NaN из языка и сотни вещей окружения — в браузере это document, alert, setTimeout, localStorage.

Называется он в разных местах по-разному: в браузере — window, в фоновых потоках браузера (курс 4) — self, в Node.js — global. Код, который должен работать везде, долго подбирал имя на ходу. С 2020 года есть одно имя на все случаи — globalThis:

console.log(globalThis === window, globalThis === self);   // true true
console.log(globalThis.Math === Math);                       // true
console.log(typeof globalThis.setTimeout);                   // function

Имя выбрано не случайно: это значение this на верхнем уровне обычного скрипта. В спецификации у глобальной записи окружения так и есть поле [[GlobalThisValue]] — то, что возвращает this вне всех функций. И здесь строгий режим ничего не меняет: правило раздела 4 касается вызовов функций, а не верхнего уровня.

"use strict";

console.log(this === globalThis);   // true — верхний уровень скрипта

function who() {
  return this;
}
console.log(who());                 // undefined — а вызов без объекта уже строгий

В модулях (день 30) this на верхнем уровне — undefined, поэтому код, которому нужен глобальный объект, пишет globalThis, а не this.

Элементы с id — тоже во дворе

Есть у браузера и совсем неожиданное содержимое глобального объекта: каждый элемент страницы с атрибутом id становится его свойством, и к нему можно обратиться просто по имени:

const box = document.createElement("div");
box.id = "progressBox";
document.body.append(box);

console.log(globalThis.progressBox === box);   // true — элемент стал свойством окна
console.log(progressBox === box);              // true — и виден как глобальное имя

Это наследство самых первых браузеров. Пользоваться им не нужно: элементы ищут через querySelector и getElementById из дня 24 Essentials, чтобы по коду было видно, откуда взялось значение. А помнить о нём стоит из-за ошибок: если опечатка в имени переменной совпала с id на странице, чтение не упадёт с ReferenceError даже в строгом режиме — поиск найдёт элемент, и вместо числа вы получите кусок страницы. Присваивание такому имени строгий режим всё же остановит. Объявленная переменная с тем же именем элемент заслоняет.

Глобальный объект — как общий двор многоквартирного дома. Всё, что вынесено во двор, видно из любой квартиры: скамейка Math, почтовый ящик alert. Но двор общий, и если каждый будет выносить туда свои вещи, однажды кто-то унесёт чужое, приняв за своё. Хороший жилец держит вещи дома.

10. Две половины глобальной области

На дне 4 Essentials мы видели странность: var на верхнем уровне становится свойством глобального объекта, а let — нет. Почему одна и та же «глобальная» переменная живёт по-разному? Ответ — в разделе спецификации 9.1.1.4, Global Environment Records. Перескажем.

Глобальная запись окружения — та, что на самом верху цепочки из дня 1, — устроена из двух частей. Объектная часть хранит имена прямо в глобальном объекте: встроенные, а также всё, что объявлено через var и function. Декларативная часть — обычная запись, как у функции или блока: в ней let, const и class. Поиск имени заглядывает в обе, поэтому для кода разницы почти нет. А для globalThis разница есть: он видит только первую часть.

var a = 1;
let b = 2;
function c() {}

console.log(a, b);                        // 1 2 — из кода видны обе
console.log(globalThis.a, globalThis.b);  // 1 undefined — globalThis видит только var
console.log(typeof globalThis.c);         // function — и объявления function

У декларативной части есть своё следствие: let верхнего уровня видна во всех обычных скриптах страницы, хотя в глобальном объекте её нет. Подключите к странице два скрипта — второй прочтёт переменную первого, а повторный let с тем же именем во втором скрипте даст SyntaxError: Identifier '…' has already been declared. Глобальная область одна на всю страницу, сколько бы файлов ни было.

11. Загадка name разгадана

В первый день мы видели: console.log(name) на верхнем уровне печатает пустую строку. Теперь понятно почему: name — свойство глобального объекта, которое браузер создал заранее (имя окна, в котором открыта страница). Поиск имени дошёл до объектной части глобальной записи и нашёл его там.

А вот что бывает, если объявить своё name:

var name = 5;
console.log(typeof name, name);   // string 5

Мы положили число, а получили строку! var на верхнем уровне записывает в свойство глобального объекта, а свойство name у окна особое: всё, что в него кладут, оно хранит строкой. Наша переменная оказалась не нашей.

Следующий опыт делайте в новой вкладке. Строка var name = 5 записала "5" в имя окна, а окно помнит своё имя даже после обновления страницы: на той же вкладке вместо пустой строки вы увидите "5".

let name = 5;
console.log(typeof name, name);            // number 5
console.log(JSON.stringify(globalThis.name));   // "" — свойство окна не тронуто

С let всё в порядке: переменная легла в декларативную часть, поиск находит её там первой, а свойство окна осталось само по себе. Ещё один довод за let и const.

Некоторые имена глобального объекта заняты так, что объявить своё нельзя даже через let: 
let undefined = 5;
// SyntaxError: Identifier 'undefined' has already been declared
undefined, NaN и Infinity — свойства глобального объекта, которые нельзя ни переписать, ни удалить. Спецификация не даёт заслонить их let на верхнем уровне, и Chrome сообщает об этом как о повторном объявлении. Внутри функции или блока — можно, но лучше никогда.

12. globalThis на практике

Три случая, когда к глобальному объекту обращаются осознанно.

Проверить, есть ли возможность. Старый браузер может не знать какой-то функции. Обращение к несуществующему имени упадёт с ReferenceError, а к свойству глобального объекта — просто даст undefined:

function has(feature) {
  return typeof globalThis[feature] !== "undefined";
}

console.log(has("fetch"), has("surelyNotThere"));   // true false — и никакого ReferenceError

Найти случайную глобальную. Приём дня 4 Essentials: если подозреваете опечатку без строгого режима, наберите globalThis.totl. В строгом режиме этот приём не нужен — опечатка упадёт сама.

Поделиться данными между скриптами. Если двум обычным скриптам страницы действительно нужно общее, заводят одно имя с объектом внутри, а не десяток отдельных переменных:

globalThis.cards = { version: 2, words: [] };   // одно имя на весь проект
console.log(globalThis.cards.version);           // 2

Так меньше шансов столкнуться с чужим config из чужой библиотеки — та беда, о которой говорил день 4. А правильное решение этой задачи — модули, день 30: там у каждого файла своя область, и делиться можно только явно.

13. «Карточки» в строгом режиме

Возьмём кусок «Карточек» с двумя ошибками дня: опечаткой в имени переменной и потерянным this. Обе ловушки поставлены нарочно, а каждая проверка обёрнута в try...catch из дня 11, чтобы увидеть все ошибки за один запуск.

"use strict";

const words = ["bread", "water", "apple"];
let position = 0;

function show(label) {
  console.log(`${label}: ${words[position]}`);
}

function next() {
  positon = (position + 1) % words.length;   // опечатка: positon вместо position
  show("дальше");
}

const quiz = {
  flipped: false,
  flip() {
    this.flipped = !this.flipped;
    console.log(`перевёрнута: ${this.flipped}`);
  },
};

show("сейчас");
try {
  next();
} catch (error) {
  console.log(`next — ${error.name}: ${error.message}`);
}
try {
  const flip = quiz.flip;                     // метод без объекта
  flip();
} catch (error) {
  console.log(`flip — ${error.name}: ${error.message}`);
}
quiz.flip();
сейчас: bread
next — ReferenceError: positon is not defined
flip — TypeError: Cannot read properties of undefined (reading 'flipped')
перевёрнута: true

Теперь уберите первую строку и запустите снова. Вывод станет таким:

СтрокаСтрогий режимОбычный режим
1сейчас: breadсейчас: bread
2next — ReferenceError: positon is not definedдальше: bread — карточка не сдвинулась
3flip — TypeError: … (reading 'flipped')перевёрнута: true — перевернулось окно, а не карточка
4перевёрнута: trueперевёрнута: true

В обычном режиме программа отработала до конца без единой ошибки — и дважды сделала не то. «Дальше» показало то же слово: число записалось в новую глобальную positon. Потерянный flip перевернул не карточку, а окно: после запуска globalThis.flipped равно true, а в глобальном объекте появились два лишних свойства. Строгий режим остановил оба места, и каждое сообщение называет виноватое имя.

Два опыта.

Первый. В обычном режиме после запуска наберите globalThis.positon и globalThis.flipped. Откуда они взялись — по одной строке программы на каждое.

Второй. Почините обе ошибки — опечатку и потерю this (способом из вчерашнего раздела 9) — и убедитесь, что строгий режим молчит, а «дальше» показывает water.

14. Когда писать "use strict"

Где кодНужна ли директива
модуль, <script type="module"> (день 30)нет — модуль строгий сам
класс (день 8)нет — тело класса строгое всегда
обычный скрипт, <script src="app.js">да, первой строкой файла
одна функция в чужом обычном скриптеможно первой строкой функции, если у неё простые параметры

Совет на весь курс: новый обычный скрипт начинайте со строки "use strict";. Это бесплатная страховка: всё, что она ломает, было ошибкой и раньше, только тихой. Старый чужой код включать в строгий режим нужно осторожнее — там тихие ошибки могли стать частью поведения, и «починка» что-нибудь сломает.

Как перевести старый скрипт

Порядок, который работает и на своём проекте, и на чужом.

1

Убедитесь, что у программы есть проверки — хотя бы список действий, которые вы пройдёте руками: «добавить слово», «перевернуть», «обновить страницу». Без них не понять, что сломалось.

2

Если файл большой, начните с одной функции: директива первой строкой её тела. Пройдите проверки, потом следующая функция. Когда строгими стали все — перенесите директиву в начало файла.

3

Читайте ошибки по таблице разделов 3 и 5. Чаще всего всплывают три вещи: случайные глобальные переменные, потерянный this в обработчиках и таймерах, восьмеричные числа с ведущим нулём в старых данных.

4

Каждую ошибку чините по смыслу, а не так, чтобы она замолчала. Случайную глобальную — объявить там, где ей место; потерянный this — bind или стрелочной обёрткой из дня 2; 010 — решить, что имелось в виду: 8 или 10.

Последний пункт важнее, чем кажется. 010 в старом коде мог означать «десять с нулём для красоты» — и тогда программа годами работала с восьмёркой. Строгий режим этот вопрос задаст, но ответ знаете только вы.

// let, const, class → декларативная часть, в globalThis их нет
// var name = 5 → "5" (свойство окна!);  let name = 5 → 5
  1. Почему "use strict" — строка в кавычках, а не новое слово языка?
    Ответ Ради старых движков: для них это просто строка, которая ничего не делает, и код не ломается. Новые движки понимают её как директиву.
  2. Код начинается с console.log("старт");, а второй строкой стоит "use strict";. Строгий ли режим?
    Ответ Нет. Директива действует, только если стоит первой инструкцией скрипта или функции; иначе это обычная строка.
  3. Чему равен this в функции, вызванной без объекта, в обоих режимах?
    Ответ В обычном — глобальный объект (call(null) тоже даст его, а call(5) — объект-обёртку). В строгом — undefined, и вообще ровно то, что передали.
  4. Поймает ли строгий режим строку quiz.positon = 1 с опечаткой?
    Ответ Нет: добавить новое свойство объекту законно. Строгий режим ловит опечатки в именах переменных, а не свойств.
  5. Почему var name = 5 на верхнем уровне даёт строку, а let name = 5 — число?
    Ответ var верхнего уровня пишет в свойство глобального объекта, а свойство окна name хранит только строки. let ложится в декларативную часть глобальной записи окружения и свойство окна не трогает.
