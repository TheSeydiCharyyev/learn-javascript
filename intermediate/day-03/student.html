День 3. Строгий режим и глобальный объект

Выжимка лекции: как включить строгий режим, что он меняет, чего не ловит, и как устроена глобальная область.

Главное

Строгий режим превращает тихие ошибки обычного режима в явные и запрещает несколько опасных записей ещё до запуска. Глобальный объект — объект со встроенными именами; во всех средах его зовут globalThis.

Как включить

"use strict";       // ПЕРВОЙ инструкцией файла — строгий весь файл

function f() {
  "use strict";     // первой инструкцией функции — строгая только f
}
Не первой строкой — просто строка, режим обычный. Модули (день 30) и классы (день 8) строгие всегда. Выключить строгий режим нельзя. В консоли директива действует только в том же вводе.

Потерянный метод в строгом режиме падает сразу: Cannot read properties of undefined (reading 'learned') называет то место, где потерялся объект.

Запреты до запуска (SyntaxError)

eval и arguments как имена — Unexpected eval or arguments in strict mode
delete x — Delete of an unqualified identifier in strict mode.
директива при параметре по умолчанию — Illegal 'use strict' directive in function with non-simple parameter list
implements interface let package private protected public static yield — Unexpected strict mode reserved word
функция с меткой — In strict mode code, functions can only be declared at top level or inside a block.
010 — Octal literals are not allowed in strict mode. (пишите 0o10)
"\05" — Octal escape sequences are not allowed in strict mode.
а ещё: повтор имён параметров, with.
Строгий режим не ловит опечатку в имени свойства (quiz.positon = 1 — законно) и логические ошибки. Полный список его правил — приложение C спецификации ECMA-262, у каждого пункта номер раздела.

Глобальный объект

var a = 1;            // объектная часть: свойство глобального объекта
let b = 2;            // декларативная часть: в globalThis её нет
function c() {}       // объектная часть

console.log(globalThis.a, globalThis.b, typeof globalThis.c);   // 1 undefined function
console.log(globalThis === window);                           // true — в браузере
Глобальная запись окружения (9.1.1.4) — две части: объектная (глобальный объект: встроенное, var, function) и декларативная (let, const, class). Поиск имени смотрит в обе, globalThis — только в первую. let верхнего уровня видна во всех обычных скриптах страницы.
name. Свойство окна. var name = 5 → строка "5"; let name = 5 → число, окно не тронуто. let undefined — SyntaxError: это имя занято навсегда.
Практика. Проверка возможности — typeof globalThis[имя]; общее для скриптов — одно имя с объектом внутри; лучше — модули.
  1. Добавьте "use strict"; первой строкой в app.js своего итогового проекта Essentials и запустите все его проверки. Запишите, что сломалось и почему это было ошибкой и раньше.
  2. Наберите в консоли своего проекта Object.keys(globalThis): имён сотни, ваши — в самом конце списка, они созданы последними. Какие из ваших объявлений туда попали и почему именно они?
  3. Откройте приложение C спецификации и проверьте в Chrome три пункта, которых не было в лекции.
  4. Прочитайте на MDN страницу globalThis и выпишите, как называли глобальный объект до 2020 года в трёх средах.
