1. Функция — тоже объект

На дне 12 Essentials мы выяснили: функция — это значение. Её можно положить в переменную, в массив, передать аргументом. Сегодня следующий шаг: функция — это объект. Особый — его можно вызвать, — но во всём остальном такой же, как объекты дня 21: у него есть свойства, их можно читать и даже добавлять свои.

function greet(student) {
  return `Салам, ${student}!`;
}

console.log(typeof greet);             // function — так typeof отмечает объекты, которые можно вызвать
console.log(greet instanceof Object);  // true — но это объект
console.log(greet.name, greet.length); // greet 1

Три дня этого модуля мы трогали функцию с разных сторон: на дне 1 — её [[Environment]], ссылку на окружение; на дне 2 — методы call, apply и bind; вчера — то, как режим меняет её поведение. Сегодня соберём функцию целиком, как объект.

Методы call, apply, bind и toString не лежат в каждой функции отдельно: они общие и берутся из одного места, которое называется Function.prototype. Как один объект «одалживает» свойства у другого — тема дня 7; пока достаточно знать, что такое общее хранилище есть.

2. name: как функция получает имя

Свойство name — имя функции. У объявления всё просто: какое написали, такое и будет. Интереснее у функций, которые пишут без имени: язык выводит имя из того места, куда функцию положили.

function greet() {}
const sum = function () {};
const add = () => 1;
const named = function inner() {};
const quiz = { show() {}, go: function () {} };

console.log(greet.name, sum.name, add.name, named.name);   // greet sum add inner
console.log(quiz.show.name, quiz.go.name);                 // show go
console.log(greet.bind(null).name);                        // bound greet
console.log(JSON.stringify([() => 1][0].name));           // "" — положили в массив, имени нет
Как созданаname

выражение со своим именем function inner() {}своё имя, "inner"

конструктор Function (раздел 9)"anonymous"

Зачем это нужно? Имя видно в стеке вызовов из дня 11 и в консоли. Ошибка внутри функции с именем deck читается сразу: в стеке стоит at deck. У безымянной функции в стеке остаётся только адрес — файл и номер строки. Поэтому функции, которые передают колбэком, полезно класть в переменную с понятным именем, а не писать прямо в вызове.

Имя выражения function inner() {} из четвёртой строки примера видно и внутри самой функции — так она может вызвать себя, даже если её положили в переменную с другим именем. Снаружи inner не существует. Это удобно для рекурсии из дня 12 Essentials в функциях-выражениях.

3. length: сколько параметров ждёт

length — число параметров, которые функция объявила. На дне 12 Essentials это было просто «число параметров». Точное правило: считаются параметры до первого со значением по умолчанию или остаточного.

const samples = [
  function (a, b) {},
  function (a, b = 1) {},
  function (a = 1, b) {},
  function (a, ...rest) {},
  function (...rest) {},
  function ({ a, b }) {},
  function (a, b, c) {}.bind(null, 1),
];

console.log(samples.map((f) => f.length));   // (7) [2, 1, 0, 1, 0, 1, 2]
ПараметрыlengthПочему
(a, b)2оба обязательные
(a, b = 1)1счёт остановился на умолчании
(a = 1, b)0умолчание первое — до него ничего
(a, ...rest)1остаточный не считается
({ a, b })1деструктуризация — один параметр
bind(null, 1) от трёх2один закреплён, осталось два (день 2)

Не путайте два счёта: length функции — сколько параметров она объявила, arguments.length внутри — сколько аргументов ей передали в этот раз. Язык их не сравнивает (день 12 Essentials), сравнивать можно самому.

Где length пригождается в настоящем коде: библиотеки иногда смотрят на него, чтобы решить, как вызывать переданную функцию. Например, программа, запускающая проверки, может давать второй аргумент только тем проверкам, которые его объявили:

function run(check) {
  if (check.length > 1) {
    return check("слово", "подробно");   // проверка просит второй аргумент
  }
  return check("слово");
}

console.log(run((word) => `проверено: ${word}`));                   // проверено: слово
console.log(run((word, mode) => `проверено ${mode}: ${word}`));     // проверено подробно: слово

4. Только для чтения

Попробуем переименовать функцию:

function greet() {}
greet.name = "hello";
console.log(greet.name);   // greet — запись молча не сработала

Узнаёте вчерашнюю тишину? name и length — свойства только для чтения. В обычном режиме запись в них молча пропадает, а в строгом — честно падает:

"use strict";
function greet() {}
greet.name = "hello";
// TypeError: Cannot assign to read only property 'name' of function 'function greet() {}'

Это строчка из таблицы вчерашнего раздела 3 — «запись в свойство только для чтения». Спецификация описывает оба свойства в разделе 20.2.4 и задаёт им три признака: записывать нельзя, при переборе не показываются, а удалить или переопределить — можно. Что такое эти признаки и как их увидеть в коде, разберём завтра, на дне 5. А пока видно второе следствие: Object.keys(greet) — пустой массив, хотя свойства у функции есть.

5. Свои свойства функции

Раз функция — объект, ей можно добавить своё свойство. Классический пример — счётчик вызовов:

function greet(student) {
  greet.calls = greet.calls + 1;
  return `Салам, ${student}!`;
}
greet.calls = 0;

greet("Аман");
greet("Мерет");
console.log(greet.calls);                // 2
console.log(Object.keys(greet));         // ['calls'] — а name и length не видны

Свойство живёт на самой функции, и функция обращается к нему по своему имени. Удобно для мелочей: сколько раз вызвали, когда последний раз, с какой версией работает.

Но вспомните вчерашнюю таблицу «замыкание или this»: у свойства те же недостатки, что у свойства объекта. Его видно и можно испортить снаружи — greet.calls = 100. Счётчик в замыкании из дня 1 снаружи недоступен.

6. arguments изнутри

На днях 13 и 14 Essentials мы встретили arguments и решили, что в новом коде его заменяет ...rest. Но в чужом коде вы встретите его много раз, и устроен он интереснее, чем кажется. Соберём, что это за объект:

function show() {
  console.log(typeof arguments, Array.isArray(arguments));   // object false
  console.log(arguments.length, arguments[0], arguments[5]); // 2 a undefined
  for (const value of arguments) {
    console.log("перебор:", value);                          // перебор: a, перебор: b
  }
}

show("a", "b");
  • Объект, похожий на массив. У него есть номера 0, 1… и length, но нет методов массива — вспомните arguments.sort is not a function из дня 14.
  • Перебираемый. for...of по нему работает. Что делает объект перебираемым, узнаем на дне 11.
  • Свой на каждый вызов. Как и запись окружения, arguments создаётся при каждом вызове заново и хранит то, что передали именно в этот раз.

Превратить его в настоящий массив можно тремя способами — от нового к старому:

function toArray() {
  const a = [...arguments];               // spread, день 22
  const b = Array.from(arguments);        // Array.from, день 19
  const c = [].slice.call(arguments);     // заимствование, день 2
  return [a, b, c];
}

console.log(toArray(5, 4));   // (3) [Array(2), Array(2), Array(2)]

Третий способ вы видели на дне 14 в виде Array.prototype.slice.call(arguments) — с пометкой «курс 2». Это то же заимствование метода, что на дне 2, только метод slice берут не у пустого массива, а прямо из общего хранилища методов массивов — того самого .prototype, который разберём на дне 7.

7. arguments в двух режимах

Вчера, в разделе 6, мы увидели главное различие: в обычном режиме arguments связан с параметрами — поменяли одно, поменялось другое. В строгом это просто копия. Связь работает в обе стороны:

function sloppy(a) {
  arguments[0] = 99;
  return a;
}

function strict(a) {
  "use strict";
  arguments[0] = 99;
  return a;
}

console.log(sloppy(1), strict(1));   // 99 1

И одна тонкость, которой вчера не было: связь пропадает и в обычном режиме, если у функции сложные параметры — умолчания, ...rest или деструктуризация. Та же граница «простые параметры», что вчера запрещала директиву:

function withDefault(a = 0) {
  a = 5;
  return arguments[0];
}

console.log(withDefault(1));   // 1 — параметр по умолчанию, связи нет

callee и caller

У arguments в обычном режиме есть свойство callee — ссылка на саму функцию. До появления функций-выражений с именем так делали рекурсию в анонимной функции. А у самой функции есть свойство caller — кто её вызвал. Оба давно устарели: они мешают движку оптимизировать код и позволяют одной функции добраться до чужой. В строгом режиме оба запрещены:

function f() {
  "use strict";
  return arguments.callee;
}

f();
// TypeError: 'caller', 'callee', and 'arguments' properties may not be accessed on strict mode functions or the arguments objects for calls to them

Длинное сообщение говорит ровно то, что запрещено: свойства caller, callee и arguments строгой функции и её объекта arguments. На MDN это страница «'caller', 'callee', and 'arguments' properties may not be accessed». В курсе 3, в модуле о наследии языка, эти свойства разберём как историю. В своём коде их не пишут.

8. Стрелочные функции и arguments

На дне 13 Essentials было сказано: «arguments в стрелочной нет вообще». Точнее — своего нет. Точно так же, как с this на дне 2, стрелочная функция берёт arguments снаружи — у обычной функции, внутри которой написана:

function outer() {
  const inner = () => arguments.length;   // arguments функции outer
  return inner(1, 2, 3);
}

console.log(outer(9));   // 1 — не 3: считаются аргументы outer

Стрелочная получила три аргумента, а вернула 1 — длину arguments внешней функции, которую вызвали с одним аргументом. На верхнем уровне скрипта внешней функции нет, и тогда — ReferenceError: arguments is not defined, ровно как на дне 13.

У стрелочной функции нет своих this и arguments. Оба она находит снаружи по тексту программы — тем же поиском, что переменные дня 1. Поэтому стрелочная внутри метода видит this метода, а внутри функции — её arguments.

9. Конструктор Function

Функцию можно создать не только записью в коде, но и из строк — конструктором Function. Последняя строка — тело, остальные — имена параметров:

const plus = new Function("a", "b", "return a + b");

console.log(plus(2, 3));           // 5
console.log(plus.name);            // anonymous
console.log(Function("return 7")());   // 7 — работает и без new

Звучит удобно, но у такой функции три серьёзных недостатка.

Первый — она не видит окружения. Функция, созданная конструктором Function, всегда «живёт» на верхнем уровне: её [[Environment]] — глобальная запись, а не то место, где её создали. Вспомните день 1 — здесь замыкание не работает:

function make() {
  const secret = 42;
  const f = new Function("return typeof secret");
  return f();
}

console.log(make());   // undefined — secret ей не видна

Второй — опасность. Строка становится кодом. Если в строку попадёт текст, пришедший от пользователя или с сервера, его код выполнится со всеми правами страницы — та же беда, что с innerHTML и чужими данными на дне 25 Essentials, только хуже. Многие сайты запрещают конструктор Function настройками безопасности, и там он просто не работает.

Третий — неудобство. Редактор не подсвечивает ошибки внутри строки, а движку приходится разбирать её во время работы программы.

Вывод простой: конструктор Function в своём коде не нужен. Знать его стоит, чтобы узнать в чужом и понимать, почему у функции бывает имя "anonymous". Его близкий родственник — eval из вчерашнего раздела 6.

return вне функции

Тело, переданное в Function, — тело функции, поэтому return в нём законен. А вот на верхнем уровне скрипта return писать нельзя: возвращать неоткуда.

return 5;
// SyntaxError: Illegal return statement

Ошибка синтаксическая — скрипт не запустится целиком. Чаще всего она появляется, когда при правке стёрли строку с объявлением функции, а её тело осталось. На MDN — страница «return not in function», в Chrome — Illegal return statement.

10. toString: исходный текст

Метод toString возвращает текст функции — ровно так, как он записан в исходнике, с отступами и комментариями:

function greet(student) {
  // приветствие
  return `Салам, ${student}!`;
}

console.log(greet.toString());
console.log(Math.max.toString());          // function max() { [native code] }
console.log(greet.bind(null).toString());  // function () { [native code] }

Первая строка вывода — четыре строки исходника целиком, комментарий тоже. Встроенные функции вроде Math.max написаны не на JavaScript, их текста нет, и на его месте стоит [native code]. У привязанных функций исходника тоже нет: это обёртка, созданная движком.

Спецификация разрешает окружению и вовсе скрывать текст функций: на это есть отдельная операция HostHasSourceTextAvailable (раздел 20.2.5). Браузеры текст не прячут, но рассчитывать на него в логике программы нельзя. И уж точно не стоит разбирать его, чтобы, например, узнать имена параметров: после сжатия кода перед выкладкой имена станут a, b, c. Для отладки — пожалуйста, для логики программы — нет.

12. Обёртка once

Теперь применим всё вместе. Обёртка — функция, которая принимает функцию и возвращает новую, с добавленным поведением. Вы уже писали обёртку: свой bind в задании 8 дня 2. Сегодня две классические.

Первая — once: пропускает только первый вызов, а на остальные отвечает результатом первого. Нужна там, где повтор вреден: второе нажатие «Отправить», вторая загрузка данных.

function once(fn) {
  let done = false;
  let result;
  return function (...args) {
    if (!done) {
      done = true;
      result = fn.apply(this, args);
    }
    return result;
  };
}

const start = once((topic) => {
  console.log(`старт: ${topic}`);
  return topic;
});

console.log(start("еда"));   // старт: еда, затем еда
console.log(start("дом"));   // еда — второй старт не состоялся

В четырёх строках работают все три дня модуля:

  • замыкание (день 1): done и result живут в записи окружения вызова once — у каждой обёрнутой функции свои;
  • apply (день 2): передаёт исходной функции и все аргументы массивом, и тот this, с которым вызвали обёртку;
  • обычная функция, а не стрелочная: обёртке нужен свой this, чтобы передать его дальше. Со стрелочной обёрткой метод объекта потерял бы объект.

13. Обёртка memo

Вторая — memo, от «memoization», запоминание: если функцию уже вызывали с таким аргументом, вернуть сохранённый ответ, не считая заново. Полезно для медленных расчётов, которые зовут много раз с одними и теми же данными.

function memo(fn) {
  const cache = {};
  return function (key) {
    if (!Object.hasOwn(cache, key)) {
      cache[key] = fn.call(this, key);
    }
    return cache[key];
  };
}

function square(n) {
  square.calls = square.calls + 1;   // своё свойство: сколько раз считали по-настоящему
  return n * n;
}
square.calls = 0;

const fastSquare = memo(square);
console.log(fastSquare(4), fastSquare(4), fastSquare(5));   // 16 16 25
console.log(square.calls);                                  // 2 — третий вызов взят из памяти
console.log(JSON.stringify(fastSquare.name), square.name);  // "" square — у обёртки своё имя

Память — обычный объект в замыкании: ключ — аргумент, значение — ответ. Object.hasOwn из дня 21 Essentials отличает «ответа ещё нет» от «ответ есть и равен undefined». Счётчик square.calls из раздела 5 доказывает, что работает: три вызова, два настоящих подсчёта.

У такой памяти есть дыра. Ключи объекта — строки (день 21 Essentials), поэтому fastSquare(1) и fastSquare("1") попадут в одну ячейку, и второй вызов получит ответ первого. Для чисел это не страшно, для разных типов — ошибка. Настоящая коллекция, где ключом может быть что угодно, — Map, день 14. Тогда и перепишем memo правильно.

Последняя строка примера показывает общий недостаток обёрток: обёртка — другая функция, со своими name и length. Обёртка из memo безымянная: функцию-выражение вернули из return, и имя взять неоткуда (таблица раздела 2). А у обёртки из once из-за ...args и length равен нулю, сколько бы параметров ни было у исходной. Для программы это неважно, для отладки и для кода, который смотрит на length, как run из раздела 3, — важно. Переименовать обёртку прямым присваиванием нельзя — свойство только для чтения, — но его можно переопределить. Как — завтра, на дне 5.

Третья обёртка: debounce

Функции, которые принимают или возвращают функции, называют функциями высшего порядка. Вы уже знаете несколько: map и filter из дня 20 принимают колбэк, фабрики дня 1 возвращают функции, а bind, once и memo делают и то и другое. Ещё одна классическая обёртка такого рода нужна в каждом интерфейсе с поиском.

debounce — «подождать, пока утихнет»: вызывает функцию только тогда, когда вызовы прекратились на заданное время. Пользователь набирает в поиске «water» — искать на каждую букву незачем, достаточно один раз, когда он остановился.

function debounce(fn, ms) {
  let timer;
  return function (...args) {
    clearTimeout(timer);                                  // прошлый вызов отменён
    timer = setTimeout(() => fn.apply(this, args), ms);   // стрелочная: this обёртки
  };
}

const search = debounce((text) => console.log(`ищем: ${text}`), 300);
search("w");
search("wa");
search("wat");
// через 300 мс — одна строка: ищем: wat

Три вызова — один поиск, с последним текстом. Каждый новый вызов снимает таймер предыдущего через clearTimeout из дня 30 Essentials и ставит свой. Здесь снова работает весь модуль: timer живёт в замыкании; внутри setTimeout стоит стрелочная функция, чтобы взять this обёртки, — ровно приём дня 2; apply передаёт и this, и аргументы.

14. «Карточки»: память и одноразовый старт

Применим обе обёртки к «Карточкам». Подсчёт слов по теме нужен счётчику на каждой отрисовке, но слова не меняются — запомним ответы. А старт приложения, который на дне 35 мог случайно запуститься дважды, сделаем одноразовым.

const words = [
  { id: 1, word: "book", topic: "школа" },
  { id: 2, word: "teacher", topic: "школа" },
  { id: 3, word: "lesson", topic: "школа" },
  { id: 4, word: "bread", topic: "еда" },
  { id: 5, word: "water", topic: "еда" },
  { id: 6, word: "apple", topic: "еда" },
  { id: 7, word: "house", topic: "дом" },
  { id: 8, word: "window", topic: "дом" },
];

function once(fn) {
  let done = false;
  let result;
  return function (...args) {
    if (!done) {
      done = true;
      result = fn.apply(this, args);
    }
    return result;
  };
}

function memo(fn) {
  const cache = {};
  return function (key) {
    if (!Object.hasOwn(cache, key)) {
      cache[key] = fn.call(this, key);
    }
    return cache[key];
  };
}

function countTopic(topic) {
  countTopic.calls = countTopic.calls + 1;
  return words.filter((w) => w.topic === topic).length;
}
countTopic.calls = 0;

const app = {
  title: "Карточки",
  start(topic) {
    console.log(`${this.title}: старт, тема «${topic}»`);
    return topic;
  },
};
app.start = once(app.start);           // метод стал одноразовым, this сохранится

const count = memo(countTopic);

console.log(app.start("еда"));
console.log(app.start("дом"));
console.log(count("еда"), count("еда"), count("школа"), count("еда"));
console.log(`подсчётов по-настоящему: ${countTopic.calls}`);
Карточки: старт, тема «еда»
еда
еда
3 3 3 3
подсчётов по-настоящему: 2

Разберём по строкам вывода.

Первые три строки — once. Старт состоялся один раз, второй вызов вернул первую тему. И главное — this.title нашёлся: вызов app.start(...) дал обёртке this, равный app, а apply передал его исходному методу. Будь обёртка стрелочной, в строке стояло бы undefined: старт.

Четвёртая — memo. Четыре ответа, все верные: в темах «еда» и «школа» по три слова.

Пятая — доказательство. Четыре вызова count, а подсчётов два: «еда» посчитана один раз, «школа» — один раз, остальные ответы взяты из памяти. Свойство функции countTopic.calls пригодилось как раз для такой проверки.

Три опыта.

Первый. Замените в once обычную функцию на стрелочную: return (...args) => { … }. Что напечатает первая строка и почему — словами дня 2 о стрелочных и this?

Второй. Добавьте в конец console.log(count("дом")) и снова посмотрите на счётчик подсчётов. Сколько стало и почему?

Третий. Выведите app.start.name до и после строки app.start = once(app.start). Объясните разницу по таблице раздела 2.

  1. Чему равны name у const sum = () => 1 и у sum.bind(null)?
    Ответ "sum" — имя выведено из переменной; "bound sum" — так bind называет новую функцию.
  2. Чему равен length у function (a, b = 1, c) {}?
    Ответ 1. Счёт идёт до первого параметра со значением по умолчанию; c после него не считается.
  3. Почему greet.name = "hello" не переименовывает функцию?
    Ответ name — свойство только для чтения (раздел 20.2.4 спецификации). В обычном режиме запись молча пропадает, в строгом — TypeError.
  4. Стрелочная функция внутри обычной вызывает arguments.length. Чьи аргументы она посчитает?
    Ответ Внешней обычной функции: своего arguments у стрелочной нет, и она берёт его снаружи, как и this.
  5. Почему обёртка once возвращает обычную функцию, а не стрелочную?
    Ответ Обёртке нужен свой this — тот, с которым её вызвали, — чтобы через fn.apply(this, args) передать его исходной функции. Стрелочная взяла бы this снаружи, и метод объекта потерял бы объект.
