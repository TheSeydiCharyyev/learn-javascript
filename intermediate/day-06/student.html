День 6. Защита объектов, Object.is и логическое присваивание

Выжимка лекции: три уровня защиты, глубокая заморозка, четыре сравнения, ||=, &&=, ??=, общие методы объектов.

Три уровня защиты

ФункциядобавлятьудалятьзаписыватьПроверка
preventExtensionsнетдадаisExtensible → false
sealнетнетдаisSealed → true

seal = запрет расширения + configurable: false всем свойствам; freeze = то же + writable: false свойствам-данным. В спецификации обе — операция SetIntegrityLevel (7.3.15). Все три функции необратимы и возвращают тот же объект.
Нарушение защиты: обычный режим молчит, строгий бросает TypeError (Cannot add property x, object is not extensible). defineProperty и методы массива (push, pop, sort) бросают ошибку в любом режиме. Аксессоры замороженного объекта продолжают работать. 
function deepFreeze(obj) {
  Object.freeze(obj);
  for (const value of Object.values(obj)) {
    if (typeof value === "object" && value !== null && !Object.isFrozen(value)) {
      deepFreeze(value);   // freeze неглубокий: вложенное — рекурсией
    }
  }
  return obj;
}

Объекты все четыре сравнивают по ссылке. -0 дают Math.round(-0.4) и 0 * -5; строка и JSON теряют минус. Object.is нужен редко: для NaN есть Number.isNaN.

== по шагам (IsLooselyEqual, 7.2.13): одинаковый тип — как ===; null равен только undefined; строка рядом с числом становится числом; true и false — числами 1 и 0; объект — примитивом. После каждого превращения — с начала. [] == false: false → 0, [] → "" → 0, итог true.

Логическое присваивание

const options = { timer: 0, title: "", name: "  Аман " };

options.timer ??= 10;                  // a ?? (a = b): 0 остался
options.title ||= "Карточки";          // a || (a = b): "" заменили
options.name &&= options.name.trim();   // a && (a = b): обрезали
Записи может не быть вовсе: правая часть не вычисляется, сеттер не вызывается, заморозка не мешает. ?? с || и && — только в скобках (Unexpected token); унарный минус слева от ** — тоже.
Память в одну строку: return (cache[key] ??= fn.call(this, key)); — но ответ undefined она не запоминает, тогда нужен Object.hasOwn, как на дне 4.

У каждого объекта

toString → "[object Object]"; одолженный через call называет вид: [object Array], [object Null]. valueOf обычного объекта — он сам; toLocaleString вызывает toString. Object(5) — обёртка, Object(null) — {}, Object(obj) === obj. Объект в примитив: сначала valueOf, потом toString; в шаблоне и String — наоборот. Откуда это всё берётся — день 7.
  1. Найдите в своём итоговом проекте Essentials объект с настройками или постоянными данными. Заморозьте его глубоко и проверьте, что программа работает, а случайная запись в строгом режиме даёт ошибку.
  2. Замените в проекте проверки вида if (x === undefined) x = … на ??= и запишите, где ||= был бы ошибкой.
  3. Прочитайте на MDN учебник Equality comparisons and sameness и выпишите из его большой таблицы три строки, в которых == и === расходятся.
  4. Откройте в спецификации раздел 20.1.3 и выпишите все свойства общего объекта. Отметьте, какие вы уже знаете и на каком дне они были.
