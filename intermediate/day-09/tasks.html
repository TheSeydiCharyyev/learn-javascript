День 9. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Все задания делаем в файлах папки day-09 курса 2 с Live Server: консоль DevTools пускает к приватным полям снаружи и спрячет половину ошибок.

Разминка

1. Что видно снаружи
Легко7 мин

предсказывать, что видно у объекта с приватными и статическими элементами.

class Ticket {
  #code;
  static #issued = 0;

  constructor(seat) {
    this.seat = seat;
    this.#code = `T-${seat}`;
    Ticket.#issued++;
  }

  get code() {
    return this.#code;
  }

  static get issued() {
    return Ticket.#issued;
  }
}

const ticket = new Ticket(12);
new Ticket(13);
console.log(ticket.code, Ticket.issued, Object.keys(ticket), JSON.stringify(ticket));
console.log(ticket.issued, typeof Ticket.code, ticket["#code"]);
  • обе строки вывода предсказаны до запуска;
  • каждое undefined второй строки объяснено: где лежит то, что искали;
  • в файле дописано console.log(ticket.#code) — записан текст ошибки и что стало с выводом всего скрипта;
  • та же строка набрана в консоли после запуска — записано, что она показала и почему.
2. Пять ошибок
Легко7 мин

узнавать ошибки приватных элементов.

Запустите каждый кусок отдельным файлом.

class Seat {
  #number = 1;
}
console.log(new Seat().#number);
class Seat {
  #number = 1;
  clear() {
    delete this.#number;
  }
}
class Seat {
  set #number(value) {}
  read() {
    return this.#number;
  }
}
new Seat().read();
class Seat {
  static get #number() {
    return 1;
  }
  set #number(value) {}
}
class Seat {
  #number = 1;
  static read(seat) {
    return seat.#number;
  }
}
Seat.read({ number: 1 });
  • для каждого куска записаны вид ошибки и точный текст Chrome;
  • записано, какие из пяти — синтаксические, а какие случаются при выполнении;
  • для последнего куска объяснено, почему у объекта { number: 1 } нет #number, хотя имя похоже;
  • каждый кусок исправлен.
3. static или нет
Легко6 мин

различать элементы класса и элементы объекта.

class Lesson {
  static minutes = 45;
  static count = 0;
  title;

  constructor(title) {
    this.title = title;
    Lesson.count = Lesson.count + 1;
  }

  static describe() {
    return `уроков: ${Lesson.count}, по ${Lesson.minutes} мин`;
  }

  describe() {
    return `${this.title}: ${Lesson.minutes} мин`;
  }
}

const math = new Lesson("Математика");
new Lesson("Физика");
console.log(Lesson.describe(), "|", math.describe());
console.log(Object.keys(Lesson), Object.keys(math));
  • вывод предсказан до запуска;
  • объяснено, почему два метода describe не мешают друг другу;
  • записано, что дают math.minutes и Lesson.title;
  • счётчик переделан так, чтобы снаружи его нельзя было изменить, — проверено.

4. Счёт с приватным балансом
Средне12 мин

спрятать данные и правила в одном классе.

Напишите BankAccount: приватные #balance и #history (массив операций), приватный метод #check(sum), методы deposit, withdraw и transfer(other, sum), геттеры balance и history.

  • после deposit(100) и withdraw(30) баланс 70, а withdraw(100) бросает RangeError и баланс не меняет;
  • геттер history отдаёт копию: account.history.push("взлом") не меняет историю внутри — проверено;
  • transfer проверяет #balance in other, и перевод на {} бросает понятную ошибку раньше, чем изменится свой баланс;
  • Object.keys(account) — пустой массив, JSON.stringify(account) — {}.

Класс Word: конструктор принимает слово и бросает TypeError, если это не непустая строка. Статическое приватное поле #created, статический геттер created.

  • после трёх удачных new Word(...) и одного неудачного created — 3;

  • записано, в каком месте конструктора стоит Word.#created++ и почему именно там;

6. Статические фабрика и сравнение
Средне10 мин

использовать статические методы как вторые конструкторы и как колбэки.

Класс Student с конструктором (name, marks) и геттером average. Добавьте статические методы: fromJSON(text) — массив студентов из строки JSON с массивом объектов — и compare(a, b) для сортировки по среднему, от большего к меньшему.

const students = Student.fromJSON('[{"name":"Аман","marks":[5,4,5]},{"name":"Мерет","marks":[4,4]},{"name":"Сапар","marks":[5,5]}]');
students.sort(Student.compare);
console.log(students.map((s) => s.name).join(", "));   // Сапар, Аман, Мерет
  • вывод примера совпадает, каждый элемент массива — instanceof Student;
  • compare отдан в sort без bind и работает — объяснено, почему ему не нужен this;
  • fromJSON работает и отделённым: const load = Student.fromJSON;
  • записано, что изменилось бы, если внутри fromJSON писать new this(...).
7. Одинаковые имена — разные клейма
Средне20 мин

увидеть на деле, что приватные имена уникальны.

  • Напишите два класса денег, Manat и Dollar, у обоих приватное поле #amount, метод add(other) и статический is(value) с проверкой клейма.
  • add складывает только деньги своего класса и бросает TypeError для чужих.
  • Сделайте фабрику makeMoney(code), которая возвращает класс, и создайте два класса из одной фабрики.
  • new Manat(5).add(new Manat(3)) работает, add(new Dollar(3)) — TypeError, хотя у обоих есть #amount;
  • Manat.is(new Dollar(1)) — false — объяснено по разделу 9.2;
  • для двух классов из одной фабрики показано, что их клейма тоже разные;
  • записано, чем эта проверка лучше instanceof, на примере Object.create(Manat.prototype).

Со звёздочкой

8. Закрытый конструктор
Сложно10 мин

разрешить создавать объекты только через статический метод.

Конструктор в JavaScript приватным быть не может. Сделайте так, чтобы new Token() снаружи бросал TypeError, а Token.create() работал: статическое приватное поле-флаг, которое create ставит перед new и снимает после.

  • new Token() — TypeError с вашим текстом, Token.create() — объект, instanceof Token;
  • флаг снимается, даже если конструктор бросил ошибку, — проверено;
  • объяснено, почему флаг должен быть статическим и приватным одновременно;
  • записано, как этот приём описан на MDN («Simulating private constructors») и чем ваш код от него отличается.
9. Курсор колоды
Сложно10 мин

дать вложенному классу доступ к приватным данным внешнего.

Класс Deck с приватным #words и методом cursor(), который возвращает объект вложенного класса Cursor. У курсора метод next(): следующее слово колоды или null, когда слова кончились.

  • курсор колоды ["book", "water"] отдаёт book, water, null;
  • два курсора одной колоды идут независимо, курсор другой колоды не видит чужих слов;
  • Cursor читает deck.#words — объяснено через [[OuterPrivateEnvironment]] раздела 9.2;
  • снаружи Deck ни слова, ни позицию курсора нельзя изменить.
