# День 13. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания делаем в файлах папки `day-13` курса 2 с Live Server.</Subtitle>

## Разминка

<Task title="1. Кто первым" level="easy" time="7">
<Goal>предсказывать порядок вызовов в ленивой цепочке.</Goal>

```js
const marks = [5, 2, 4];
const viaArray = marks
  .map((m) => (console.log("массив map", m), m * 10))
  .filter((m) => (console.log("массив filter", m), m > 30));
const viaIterator = marks
  .values()
  .map((m) => (console.log("итератор map", m), m * 10))
  .filter((m) => (console.log("итератор filter", m), m > 30));
console.log("готово");
console.log(viaArray, viaIterator.next().value);
```

<Criteria>
- все десять строк вывода предсказаны до запуска;
- объяснено, почему «готово» напечатано после строк массива, но до строк итератора;
- посчитано, сколько раз вызваны колбэки итератора и сколько вызвал бы второй `next()`;
- записано, сколько массивов создала цепочка массива и сколько — цепочка итератора.
</Criteria>
</Task>

<Task title="2. С массива на итератор" level="easy" time="6">
<Goal>переводить цепочку методов массива на итератор.</Goal>

```js
const marks = [5, 3, 4, 2, 5, 4];
const best = marks.filter((m) => m >= 4).map((m) => m * 10).slice(0, 2);
console.log(best);
```

<Criteria>
- та же цепочка записана на итераторе и даёт тот же массив `[50, 40]`;
- объяснено, чем заменён `slice` и где в цепочке встал `toArray`;
- записано, какой текст ошибки даёт попытка вызвать `take` у самого массива;
- посчитано, сколько значений перебрал вариант на итераторе.
</Criteria>
</Task>

<Task title="3. Безопасно или зависнет" level="easy" time="7">
<Goal>различать методы, которым нужен конец последовательности.</Goal>

Генератор `naturals()` выдаёт 1, 2, 3… без конца. Не запуская, решите для каждого выражения:
вернёт ли оно ответ и какой.

1. `naturals().map((n) => n * 2)`
2. `naturals().find((n) => n > 10)`
3. `naturals().filter((n) => n % 7 === 0).take(3).toArray()`
4. `naturals().take(3).filter((n) => n % 7 === 0).toArray()`
5. `naturals().some((n) => n < 0)`
6. `naturals().every((n) => n < 5)`
7. `naturals().drop(1000).take(1).toArray()`
8. `naturals().reduce((a, b) => a + b)`

<Criteria>
- для каждого выражения записано «ответ» или «зависнет» с объяснением в одну строку;
- запущены только те, что не зависнут, и ответы совпали с предсказанием;
- объяснено, почему первое выражение возвращается мгновенно, хотя источник бесконечный;
- для двух «зависших» дописано по одному звену, после которого они дают ответ.
</Criteria>
</Task>

## Основные задания

<Task title="4. Первые N" level="medium" time="12">
<Goal>брать нужное из бесконечного генератора одной цепочкой.</Goal>

Генератор `counter()` выдаёт 1, 2, 3… без конца. Каждый ответ — одна цепочка без циклов.

<Criteria>
- первые пять чисел — `[1, 2, 3, 4, 5]`; квадраты первых пяти нечётных —
  `[1, 9, 25, 49, 81]`;
- сумма первых десяти через `reduce` — 55;
- первое число, квадрат которого больше 50, — 8;
- для сравнения квадраты нечётных записаны циклом с `break` дня 12 — посчитаны строки
  обоих вариантов.
</Criteria>
</Task>

<Task title="5. Страницы без массивов" level="medium" time="12">
<Goal>сочетать свой генератор с методами итераторов.</Goal>

Возьмите генератор `pages(list, size)` из лекции дня 12 и восемь слов «Карточек»:
`book`, `teacher`, `lesson`, `bread`, `water`,
`apple`, `house`, `window`; страница — три слова.

<Criteria>
- вторая страница получена через `drop` и `take`, без `next()`
  вручную;
- список страниц с номерами — `['1: book teacher lesson', '2: bread water apple', '3: house window']`,
  номер взят из второго аргумента колбэка `map`;
- число слов на всех страницах через `flatMap` и `reduce` — 8;
- через `some` проверено, есть ли `water` хоть на одной странице.
</Criteria>
</Task>

<Task title="6. Правильный итератор" level="medium" time="12">
<Goal>давать методы итератору, у которого есть только `next`.</Goal>

Напишите итератор-объект `plain` с методом `next()`, который выдаёт 0, 1, 2, как
на дне 11, и класс `Countdown extends Iterator`, который считает от n до 1.

<Criteria>
- `typeof plain.map` — `undefined`, а `Iterator.from(plain).map((x) => x * 10).toArray()`
  — `[0, 10, 20]`;
- `new Countdown(5).filter((x) => x % 2 === 1).toArray()` — `[5, 3, 1]`,
  `[...new Countdown(3)]` — `[3, 2, 1]`;
- записан текст ошибки `new Iterator()` и объяснено, почему с `Countdown`
  её нет — словами `new.target`;
- проверено, что `Iterator.from` вернул генератор без обёртки, а `plain` —
  с обёрткой.
</Criteria>
</Task>

<Task title="7. Журнал оценок" level="medium" time="14">
<Goal>отвечать на вопросы о данных цепочками итераторов.</Goal>

```js
const students = [
  { name: "Аман", marks: [5, 4, 5] },
  { name: "Мерет", marks: [3, 4, 2] },
  { name: "Айна", marks: [5, 5, 4] },
  { name: "Сапар", marks: [4, 5, 3] },

```

<Criteria>
- имена учеников со средним не ниже 4,5 — `['Аман', 'Айна']`; первый, у кого есть
  двойка, — Мерет;
- через `every` выяснено, у всех ли есть пятёрка, — нет;
- сумма всех оценок через `flatMap` и `reduce` — 49, пятёрок — 5;
- нумерованный список `['1. Аман', '2. Мерет', '3. Айна', '4. Сапар']` собран через
  `Iterator.zip` с бесконечным счётчиком.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Кто закрывает источник" level="hard" time="10">
<Goal>проверить, когда методы закрывают источник.</Goal>

Генератор `src()` выдаёт 1, 2, 3 внутри `try`, а в `finally` пишет в журнал
«закрыт».

<Criteria>
- для девяти случаев сначала предсказано, будет ли «закрыт», потом проверено:
  `take(2).toArray()`, `toArray()`, `find` со значением 2 и 9,
  `some` → `true`, `every` → `false`, `map`
  без потребителя, `map().return()` сразу, `map` + `next()` +
  `return()`;
- «закрыт» нет ровно в двух случаях — оба объяснены;
- для случая `map().return()` объяснено по разделу 27.1.2 и дню 12, почему источник
  закрыт, но `finally` не выполнился;
- записано, в каких случаях «закрыт» — из-за конца перебора, а не из-за `return()`.
</Criteria>
</Task>

<Task title="9. Свой zip" level="hard" time="10">
<Goal>повторить `Iterator.zip` генератором и сравнить поведение.</Goal>

Напишите генератор `zip(a, b)`, который выдаёт пары значений двух перебираемых объектов
и останавливается на коротком.

<Criteria>
- для `["book", "water", "bread"]` и `["книга", "вода"]` ваш `zip`
  и `Iterator.zip` дают одинаковые пары;
- генератором с `finally` проверено: `Iterator.zip` закрывает длинный итератор,
  когда короткий кончился;
- ваш `zip` исправлен так, чтобы тоже закрывать оставшийся итератор;
- записано, почему `Iterator.zip(["ab", "cd"])` — ошибка и как её обойти через
  `Iterator.from`.
</Criteria>
</Task>
