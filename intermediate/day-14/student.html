День 14. Map и WeakMap

Выжимка лекции: шесть операций Map, ключи по SameValueZero, перебор и порядок, Map против объекта, подсчёт и группировка, WeakMap для кеша и скрытых данных.

Главное

const dict = new Map([["book", "книга"]]);   // из пар [ключ, значение]; только с new
dict.set("water", "вода").set("bread", "хлеб");   // set возвращает словарь
dict.get("book");                                 // "книга"; нет ключа — undefined
dict.has("house");                                // false
dict.delete("bread");                             // true — было что удалять
const total = dict.size;                          // 2 — свойство, не метод

for (const [word, translation] of dict) {}        // пары в порядке вставки
dict.forEach((translation, word) => {});          // сначала ЗНАЧЕНИЕ, потом ключ

const freq = new Map();
for (const w of ["a", "b", "a"]) freq.set(w, (freq.get(w) ?? 0) + 1);   // a → 2, b → 1
Map — словарь, где ключ — любое значение. Ключи сравниваются по SameValueZero: 1 и "1" разные, объект — по ссылке (новый { id: 1 } — другой ключ), NaN находится, -0 = 0. map["x"] = 1 — свойство объекта, а не запись словаря.

Порядок — первой вставки: замена значения место не меняет, удалённый и добавленный заново ключ уходит в конец (в спецификации delete помечает запись empty, set дописывает новую). keys, values, entries — итераторы с методами дня 13.

Map или объект

MapОбъект
ключи неизвестны заранее, приходят извне, не строки; частые добавления и удаления; size; переборнабор полей известен заранее, ключи — строки; JSON сразу
JSON: JSON.stringify(map) — "{}"; сохранять JSON.stringify([...map]), читать new Map(JSON.parse(text)). Из объекта — new Map(Object.entries(obj)), обратно — Object.fromEntries(map). Слияние — new Map([...a, ...b]), последний ключ побеждает.
getOrInsert(k, v) — значение или записать v: groups.getOrInsert(k, []).push(x). getOrInsertComputed(k, fn) вызывает fn, только если ключа нет. Map.groupBy(items, fn) — группы с любыми ключами, в отличие от Object.groupBy.

WeakMap

Держит ключи слабо: когда до объекта-ключа больше не добраться, сборщик мусора забирает и его запись. Ключ — объект или Symbol(), но не Symbol.for(…): иначе Invalid value used as weak map key. Есть set, get, has, delete; нет size, перебора и clear. Для чего: кеш результатов по объекту-аргументу и метаданные чужих объектов — их не видят ни JSON, ни getOwnPropertySymbols.
  1. Найдите в своём проекте объект, который используется как словарь с ключами из данных, и переведите его на Map. Что стало проще, а что — сохранение в JSON?
  2. Посчитайте через Map частоты чего-нибудь в своих данных и выведите три самых частых.
  3. Прочитайте раздел «Why WeakMap?» на странице WeakMap и перескажите две беды словаря на двух массивах.
  4. Найдите в спецификации алгоритм Map.prototype.set (24.1.3.11) и объясните по его шагам, почему замена значения не меняет порядок.
