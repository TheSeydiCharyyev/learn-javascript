День 14. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания делаем в файлах папки day-14 курса 2 с Live Server.

Разминка

1. Объект против Map
Легко7 мин

видеть, во что превращаются ключи.

const marks = {};
marks[1] = "число";
marks["1"] = "строка";
marks[{ name: "Аман" }] = 5;
console.log(Object.keys(marks), marks[1]);

const map = new Map();
map.set(1, "число").set("1", "строка").set({ name: "Аман" }, 5);
console.log(map.size, map.get(1), map.get({ name: "Аман" }));
  • обе строки вывода предсказаны до запуска;
  • объяснено, откуда в объекте ключ '[object Object]' и почему marks[1] — «строка»;
  • объяснено, почему map.get({ name: "Аман" }) — undefined, и код исправлен так, чтобы получить 5;
  • записано, сколько записей в каждой коллекции.
2. Порядок и размер
Легко6 мин

предсказывать порядок записей Map.

const m = new Map([["c", 3], ["a", 1]]);
m.set("b", 2);
m.set("c", 30);
m.delete("a");
m.set("a", 10);
console.log([...m.keys()], m.size, m.get("c"));
console.log(m);
  • вывод предсказан до запуска, вторая строка — в виде, как её покажет консоль;
  • объяснено, почему "c" осталась первой, а "a" стала последней;
  • то же сделано объектом { c: 3, a: 1 } и delete — записан порядок Object.keys;
  • записано, где у объекта оказались бы ключи 10 и 2.
3. WeakMap: можно или нельзя
Легко7 мин

знать, что принимает WeakMap.

Для const wm = new WeakMap(); предскажите, что даст каждая строка: значение или ошибку.

  1. wm.set("a", 1)
  2. wm.set({}, 1)
  3. wm.set(Symbol("x"), 1)
  4. wm.set(Symbol.for("x"), 1)
  5. wm.size
  6. wm.get(1)
  7. wm.has("x")
  8. for (const x of wm) {}
  • для каждой строки записан результат или текст ошибки, потом проверено;
  • ошибок ровно три — для каждой объяснена причина;
  • объяснено, почему Symbol("x") можно, а Symbol.for("x") нельзя;
  • объяснено, почему get(1) не падает, хотя set(1, …) упал бы.

Основные задания

4. Частые ошибки
Средне12 мин

считать частоты через Map.

Неверные ответы ученика: ["вода", "хлеб", "вода", "дом", "вода", "хлеб", "constructor"].

  • словарь частот собран через getOrInsert: вода — 3, хлеб — 2, дом и constructor — по 1;
  • два самых частых ответа найдены через toSorted по значению — вода и хлеб;
  • то же сделано объектом — записано, что получилось у ключа constructor и почему;
  • частоты выведены строкой "вода: 3, хлеб: 2, …" через итератор entries и методы дня 13.
5. Группы и обратный словарь
Средне12 мин

группировать с ключами-объектами и переворачивать словарь.

Ученики: Аман — средний 4,7, Мерет — 3,4, Айна — 4,9, Сапар — 4,1. Словарь: book → книга, water → вода, bread → хлеб.

  • через Map.groupBy с ключами-объектами excellent и good (средний от 4,5 и ниже) отличники — ['Аман', 'Айна'], в группе good — двое;
  • показано, что groups.get({ label: "отлично" }) — undefined, и объяснено почему;

6. memo на Map и WeakMap
Средне12 мин

исправить обёртку memo дня 4.

Перепишите memo дня 4 на Map. Затем напишите memoObject(fn) для функций, чей аргумент — объект: память на WeakMap через getOrInsertComputed.

  • describe(1), describe("1"), describe(1), describe(NaN), describe(NaN) дают number 1, string 1, number 1, number NaN, number NaN, а настоящих вычислений — 3;
  • записано, сколько вычислений было бы со старой памятью-объектом и почему;
  • memoObject для суммы оценок: два вызова с одним объектом и один с копией — тяжёлых вычислений 2;
  • объяснено, почему для ключей-объектов WeakMap лучше Map.
7. Кеш статистики
Средне14 мин

строить кеш на WeakMap и знать его слабое место.

Функция stats(student) возвращает { avg, best } по оценкам ученика и запоминает ответ в WeakMap.

  • для { name: "Аман", marks: [5, 4, 5] } средний — 4.67, лучшая — 5; второй вызов не считает заново — проверено счётчиком;
  • после aman.marks.push(2) кеш возвращает старый средний 4.67 — объяснено почему;
  • после cache.delete(aman) средний пересчитан — 4.00, счётчик — 2;
  • записано, чем грозил бы такой кеш на Map, если учеников тысячи и их удаляют.

Со звёздочкой

8. Словарь на двух массивах
Сложно10 мин

понять, что делает Map за нас.

Напишите класс ArrayMap с приватными массивами ключей и значений и методами set, get, has, delete, геттером size — как в разделе MDN «Why WeakMap?».

  • ключи сравниваются как в Map: get(NaN) находит запись с NaN, get(-0) — запись с 0, has(1) для ключа "1" — false;
  • set возвращает словарь — сцепление работает;
  • объяснено, почему поиск в ArrayMap медленнее, чем требует спецификация от Map;
  • записано, какая вторая беда ArrayMap стала бы утечкой памяти и как её решает WeakMap.
9. Map и JSON
Сложно10 мин

сохранять и восстанавливать Map.

Прогресс new Map([[1, { right: 2 }], [3, { right: 1 }]]) — номер карточки и число верных ответов — нужно сохранить строкой и восстановить.

  • строка — [[1,{"right":2}],[3,{"right":1}]], после восстановления restored.get(1).right — 2, а restored.get("1") — undefined;
  • для сравнения сохранено через Object.fromEntries — записано, какого типа стали ключи и что это меняет;
  • объяснено, почему восстановленные значения — уже другие объекты;
  • записано, почему Map с ключами-объектами нельзя восстановить так, чтобы прежние ключи снова работали.
