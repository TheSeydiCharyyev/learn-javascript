1. Обещания дня 21

День 21 закончился списком претензий к Date: месяцы с нуля, дата меняется на месте, строки разбираются «как решит движок», поясом управляет устройство, а не программа. Справочник MDN называет Temporal полной заменой Date. Первое обещание — «31 января плюс месяц» одной строкой:

const jan31 = Temporal.PlainDate.from("2026-01-31");
const next = jan31.add({ months: 1 });
console.log(next.toString(), jan31.toString(), jan31.month, next === jan31);   // 2026-02-28 2026-01-31 1 false

Вчера на ту же задачу ушла целая функция addMonths, а простой setMonth дал 3 марта. Здесь сразу 28 февраля. Видны и остальные обещания: jan31 осталась 31 января — add не меняет дату, а возвращает новую (неизменяемость дня 8); январь — месяц 1, а не 0. В Chrome Temporal есть с версии 144, в Node 22 его нет — код курса, как всегда, запускаем в Chrome.

2. Temporal: пространство имён и семья классов

console.log(typeof Temporal, Object.prototype.toString.call(Temporal), Object.getOwnPropertyNames(Temporal));
// object [object Temporal] (9) ['Now', 'PlainDate', 'PlainTime', 'PlainDateTime', 'ZonedDateTime', 'Duration', 'Instant', 'PlainYearMonth', 'PlainMonthDay']
new Temporal();   // TypeError: Temporal is not a constructor

Temporal — не конструктор, а пространство имён, как Math дня 18 Essentials. Восемь его свойств — классы, девятое, Now, — пространство имён с функциями «который сейчас час».

Зачем столько классов? По справочнику MDN, Date «носит две шляпы»: это и момент — миллисекунды от эпохи, — и набор частей: год, месяц, число, часы. Поясов у частей только два, местный и UTC; «дата без пояса», как у будильника на 8:00 или дня рождения, невозможна; календарь один; сеттеры меняют объект. Поэтому Temporal написали заново и раздали роли разным классам.

Сегодня — три класса с приставкой Plain: дата, время и то и другое вместе. Момент (Instant) и момент с поясом (ZonedDateTime) — день 24, длительность и «неполные» даты — день 23.

3. PlainDate: как создать дату

const a = Temporal.PlainDate.from("2026-10-12");
const b = Temporal.PlainDate.from({ year: 2026, month: 10, day: 12 });
const c = new Temporal.PlainDate(2026, 10, 12);
const d = Temporal.PlainDate.from(a);
console.log(a.toString(), b.toString(), c.toString(), d.toString(), a.equals(c), a === d);   // 2026-10-12 2026-10-12 2026-10-12 2026-10-12 true false
console.log(a);                                            // PlainDate {era: undefined, eraYear: undefined, calendarId: 'iso8601', year: 2026, month: 10, …}
console.log(new Temporal.PlainDate(2026, 9, 12).toString());   // 2026-09-12

Способов три: from со строкой, с объектом полей или с другой датой (тогда это копия) и конструктор с числами. Справочник советует from. Консоль Chrome показывает дату полями и обрывает их на пятом, поэтому в примерах печатаем toString(). Главная ловушка: месяц здесь с единицы, и привычное по дню 17 Essentials «9 — это октябрь» молча дало 12 сентября.

const tryFrom = (text) => {
  try {
    return Temporal.PlainDate.from(text).toString();
  } catch (e) {
    return e.name;
  }
};
console.log(["2026-10-12", "20261012", "2026-10-12T14:30+03:00", "12.10.2026", "2026-02-30", "12 октября 2026"].map(tryFrom));
// (6) ['2026-10-12', '2026-10-12', '2026-10-12', 'RangeError', 'RangeError', 'RangeError']

Обещание дня 21 о разборе строк. Формат один — RFC 9557, расширение ISO 8601: YYYY-MM-DD или краткое YYYYMMDD; время и смещение дата отбросит. Остальное — RangeError без догадок: «12.10.2026» не станет 10 декабря, «30 февраля» — 2 марта. В одном примере MDN «2021-02-29» становится 28 февраля, но Chrome, как и спецификация, бросает ошибку: строка проверяется строго.

console.log(Temporal.PlainDate.from({ year: 2026, month: 2, day: 30 }).toString(), Temporal.PlainDate.from({ year: 2026, month: 13, day: 1 }).toString());   // 2026-02-28 2026-12-01
Temporal.PlainDate.from({ year: 2026, month: 2, day: 30 }, { overflow: "reject" });   // RangeError: Temporal error: day value is not in a valid range.

С объектом мягче. Настройка overflow во втором аргументе по умолчанию равна "constrain" — «подогнать»: месяц 13 становится 12-м, 30 февраля — последним днём февраля; "reject" вместо подгонки бросает RangeError. Конструктор не подгоняет никогда.

const old = new Date(2026, 9, 12, 14, 30);
const day = Temporal.PlainDate.from({ year: old.getFullYear(), month: old.getMonth() + 1, day: old.getDate() });
console.log(day.toString());   // 2026-10-12
Temporal.PlainDate.from(old);  // TypeError: Temporal error: Invalid PlainDate fields provided.

Для from старая дата — объект без нужных полей, поэтому части переносим руками, не забыв «+ 1» у месяца. Прямой мост — toTemporalInstant дня 24.

4. Поля даты

const d = Temporal.PlainDate.from("2026-10-12");
console.log(d.year, d.month, d.day, d.dayOfWeek, d.daysInMonth);   // 2026 10 12 1 31
console.log(d.dayOfYear, d.daysInYear, d.inLeapYear, d.monthCode, d.weekOfYear, d.yearOfWeek, d.era, d.calendarId);   // 285 365 false M10 42 2026 undefined iso8601
console.log(Temporal.PlainDate.from("2026-10-18").dayOfWeek, new Date(2026, 9, 18).getDay());   // 7 0

5. with: новая дата вместо сеттера

const d = Temporal.PlainDate.from("2026-10-12");
const first = d.with({ day: 1 });
const last = d.with({ day: d.daysInMonth });
console.log(first.toString(), last.toString(), d.with({ month: 2, day: 31 }).toString(), d.with({ year: 2028, month: 2, day: 29 }).toString(), d.toString());
// 2026-10-01 2026-10-31 2026-02-28 2028-02-29 2026-10-12
d.with({ month: 2, day: 31 }, { overflow: "reject" });   // RangeError: Temporal error: day value is not in a valid range.

Справочник называет with «сеттером» Temporal: заменяет указанные поля, остальные копирует и возвращает новую дату; d не изменилась. 31 февраля подогналось к 28-му — та же настройка overflow. Для последнего дня месяца MDN советует with({ day: Number.MAX_VALUE }): в редких календарях номер последнего дня не равен daysInMonth. Календарь меняет withCalendar, а день недели через with не задать — только сдвигом через add.

6. add и subtract

const start = Temporal.PlainDate.from("2026-10-12");
console.log(start.add({ days: 20 }).toString(), start.add({ weeks: 12 }).toString(), start.subtract({ months: 1 }).toString(), start.add({ years: 1, months: 2, weeks: 3, days: 4 }).toString());
// 2026-11-01 2027-01-04 2026-09-12 2028-01-06
const feb = Temporal.PlainDate.from("2026-02-14");
const days = [];
for (let day = feb.with({ day: 1 }); day.month === feb.month; day = day.add({ days: 1 })) days.push(day.day);
console.log(days.length, days.at(-1));   // 28 28

add принимает длительность — объект с ключами во множественном числе: years, months, weeks, days; subtract сдвигает назад. Каждый шаг цикла по дням месяца из примера MDN — новый объект, исходная дата цела. Теперь трудный случай:

const jan31 = Temporal.PlainDate.from("2026-01-31");
console.log(jan31.add({ months: 1 }).toString(), Temporal.PlainDate.from("2028-01-31").add({ months: 1 }).toString(), Temporal.PlainDate.from("2026-05-31").subtract({ months: 3 }).toString());   // 2026-02-28 2028-02-29 2026-02-28
console.log(jan31.add({ months: 1, days: 31 }).toString(), jan31.add({ days: 31 }).add({ months: 1 }).toString());   // 2026-03-31 2026-04-03
console.log(jan31.add({ hours: 25 }).toString(), jan31.add({ hours: 23 }).toString());   // 2026-02-01 2026-01-31
jan31.add({ months: 1 }, { overflow: "reject" });   // RangeError: Temporal error: not a valid ISO date.

Порядок внутри одного add постоянный: годы и месяцы, подгонка числа, недели и дни. Поэтому { months: 1, days: 31 } — 28 февраля плюс 31 день, а два вызова в обратном порядке дают 3 апреля. Date на дне 21 переносил лишние дни в следующий месяц, Temporal их отрезает, а с overflow: "reject" — бросает ошибку. Часы двигают дату только целыми сутками: 25 часов — плюс день, 23 — ничего. Ключ в единственном числе, { month: 1 }, — TypeError; разные знаки в одной длительности — RangeError; строку вида "P1M" разберём на дне 23.

7. since и until: сколько между датами

const start = Temporal.PlainDate.from("2026-10-12");
const end = Temporal.PlainDate.from("2027-01-01");
const left = start.until(end);
console.log(left.days, end.since(start).days, start.since(end).days, String(left));   // 81 81 -81 P81D
const parts = start.until(end, { largestUnit: "months" });
console.log(parts.months, parts.days, start.until(end, { largestUnit: "weeks" }).weeks);   // 2 20 11
const age = Temporal.PlainDate.from("2000-02-29").until("2026-10-12", { largestUnit: "years" });
console.log(age.years, age.months, age.days);   // 26 7 13

Практика плана — сколько дней до конца курса. a.until(b) — «b минус a», a.since(b) — «a минус b». Результат — длительность, Temporal.Duration дня 23; сегодня хватит её полей days, weeks, months, years и строки P81D — «период в 81 день» в записи ISO 8601.

По умолчанию ответ — в днях; largestUnit разрешает единицы крупнее: «2 месяца 20 дней», возраст «26 лет, 7 месяцев, 13 дней». Месяцы и годы бывают разной длины, поэтому, предупреждает справочник, такой ответ имеет смысл только вместе с датой, от которой считали. Часов у PlainDate нет — largestUnit: "hours" даёт RangeError.

const courseEnd = Temporal.PlainDate.from("2027-01-01");
const daysLeft = (today) => today.until(courseEnd).days;
console.log(daysLeft(Temporal.PlainDate.from("2026-10-12")), daysLeft(Temporal.PlainDate.from("2026-12-31")), daysLeft(courseEnd), daysLeft(Temporal.PlainDate.from("2027-01-10")));   // 81 1 0 -9

«Сегодня» функция получает параметром: так её легко проверить на любых датах, а в программе передать Temporal.Now.plainDateISO() (раздел 13). Вчера для разницы мы брали Date.UTC от частей, чтобы не помешал перевод часов; у PlainDate пояса нет, мешать нечему. Ещё одно обещание дня 21 — расписание задания 7, пн/ср/пт на 12 недель:

function lessons(start, weeks) {
  const result = [];
  for (let i = 0; i < weeks * 7; i++) {
    const day = start.add({ days: i });
    if ([1, 3, 5].includes(day.dayOfWeek)) result.push(day);
  }
  return result;
}
const list = lessons(Temporal.PlainDate.from("2026-10-12"), 12);
console.log(list.length, list.slice(0, 3).map((d) => d.day), list.at(-1).toString(), list.at(-1).dayOfWeek, list[0].until(list.at(-1)).days);   // 36 (3) [12, 14, 16] 2027-01-01 5 81

Те же 36 занятий и последнее — пятница 1 января, но без копии даты, без getDay с воскресеньем-нулём и без Date.UTC для разницы.

8. Сравнение и сортировка

const a = Temporal.PlainDate.from("2026-10-12");
const b = Temporal.PlainDate.from("2026-10-20");
console.log(a.equals("2026-10-12"), a === Temporal.PlainDate.from("2026-10-12"), Temporal.PlainDate.compare(a, b), Temporal.PlainDate.compare(b, a), Temporal.PlainDate.compare(a, "2026-10-12"));   // true false -1 1 0
const dates = ["2026-12-31", "2026-10-12", "2027-01-01", "2026-11-05"].map((s) => Temporal.PlainDate.from(s));
dates.sort(Temporal.PlainDate.compare);
console.log(dates.join(", "), `${a}`);   // 2026-10-12, 2026-11-05, 2026-12-31, 2027-01-01 2026-10-12
console.log(a < b);   // TypeError: Do not use Temporal.PlainDate.prototype.valueOf; use Temporal.PlainDate.prototype.compare for comparison.

equals сравнивает значения, === — ссылки. compare возвращает −1, 0 или 1 — ровно то, чего ждёт функция сравнения sort дня 20 Essentials, поэтому его передают прямо. Оба принимают и строки.

А <, - и + не работают: valueOf нарочно бросает TypeError. Без этого a < b молча сравнило бы строки — обычно верно, но не всегда (задание 9). Шаблонная строка работает: ToPrimitive дня 6 для неё зовёт сначала toString. А a + "" начинает с valueOf — и падает.

9. Строки и JSON

const d = Temporal.PlainDate.from("2026-10-12");
console.log(d.toString({ calendarName: "always" }), d.toJSON(), JSON.stringify({ next: d }), d.toLocaleString("ru-RU"));   // 2026-10-12[u-ca=iso8601] 2026-10-12 {"next":"2026-10-12"} 12.10.2026
const back = JSON.parse('{"next":"2026-10-12"}', (key, value) => (key === "next" ? Temporal.PlainDate.from(value) : value));
console.log(back.next.add({ days: 1 }).toString());   // 2026-10-13

toString пишет формат RFC 9557; calendarName решает, добавлять ли пометку календаря: "auto" (не для ISO), "always", "never", "critical". toJSON возвращает то же, и его зовёт JSON.stringify. На дне 21 полночь 12 октября в JSON стала «2026-10-11T19:00Z», а здесь дата остаётся датой. Обратно — reviver дня 23 Essentials. toLocaleString пишет дату для людей, его настройки — день 25.

10. PlainTime: время без даты

const lesson = Temporal.PlainTime.from("09:00");
const bell = lesson.add({ minutes: 45 });
const gap = lesson.until("10:30");
console.log(lesson.toString(), bell.toString(), bell.hour, bell.minute, gap.hours, gap.minutes, new Temporal.PlainTime(14, 30).toString());   // 09:00:00 09:45:00 9 45 1 30 14:30:00
const late = Temporal.PlainTime.from("22:45");
console.log(late.add({ minutes: 90 }).toString(), late.add({ hours: 48 }).toString(), late.with({ minute: 0 }).toString(), late.round("hour").toString());   // 00:15:00 22:45:00 22:00:00 23:00:00
console.log(Temporal.PlainTime.compare("09:00", "10:30"), Temporal.PlainTime.from({ hour: 25 }).toString(), lesson.toString({ smallestUnit: "minute" }));   // -1 23:00:00 09:00
Temporal.PlainTime.from("24:00");   // RangeError: Temporal error: Invalid character while parsing hour value.

PlainTime — время, которое повторяется каждый день: начало урока, звонок, будильник. Строка — "ЧЧ", "ЧЧ:ММ" или "ЧЧ:ММ:СС.ддддддддд", часы двумя цифрами; у конструктора все аргументы необязательны, без них — полночь. Шесть полей, от hour до nanosecond: точность до наносекунды, у Date была миллисекунда.

Время ходит по кругу: 22:45 плюс полтора часа — 00:15, плюс двое суток — снова 22:45. round округляет (22:45 до часа — 23:00), until даёт часы и минуты, час 25 подгоняется к 23-му. Строка «24:00», которую Date на дне 21 читал как конец суток, здесь — ошибка. toString({ smallestUnit: "minute" }) убирает секунды.

11. PlainDateTime: дата и время вместе

const dt = Temporal.PlainDateTime.from("2026-10-12T14:30");
console.log(dt.toString(), dt.toPlainDate().toString(), dt.toPlainTime().toString(), dt.dayOfWeek, dt.hour);   // 2026-10-12T14:30:00 2026-10-12 14:30:00 1 14
const lesson = Temporal.PlainDate.from("2026-10-12").toPlainDateTime("09:00");
console.log(lesson.toString(), lesson.add({ hours: 16 }).toString(), lesson.withPlainTime("18:00").toString(), new Temporal.PlainDateTime(2026, 10, 12, 14, 30).toString());
// 2026-10-12T09:00:00 2026-10-13T01:00:00 2026-10-12T18:00:00 2026-10-12T14:30:00
const a = Temporal.PlainDateTime.from("2026-10-12T09:00");
const b = Temporal.PlainDateTime.from("2026-10-14T10:30");
const gap = a.until(b);
console.log(gap.days, gap.hours, gap.minutes, a.until(b, { largestUnit: "hours" }).hours, Temporal.PlainDateTime.compare(a, b));   // 2 1 30 49 -1

PlainDateTime — PlainDate и PlainTime вместе, с полями обоих. Разобрать — toPlainDate() и toPlainTime(); собрать — date.toPlainDateTime(время), без аргумента это полночь; заменить время — withPlainTime. Сложение здесь не ходит по кругу: 9:00 плюс 16 часов — час ночи следующего дня. Разница — в днях и часах, с largestUnit: "hours" — только в часах.

console.log(Temporal.PlainDateTime.from("2026-10-12T14:30+03:00").toString(), new Date("2026-10-12T14:30+03:00").getHours(), Temporal.PlainDateTime.from("2026-10-12T14:30").round({ smallestUnit: "day" }).toString());   // 2026-10-12T14:30:00 16 2026-10-13T00:00:00
Temporal.PlainDateTime.from("2026-10-12T14:30Z");   // RangeError: Temporal error: UTC designator is not valid for DateTime parsing.

Здесь ловушка. Date пересчитал «14:30 по Москве» в 16:30 по Ашхабаду, а PlainDateTime смещение просто выбросил: нет пояса — нет и пересчёта. Z запрещён вовсе: он означает момент по UTC. Совет справочника: если событие — один момент для всех поясов (созвон Ашхабада и Берлина), берите ZonedDateTime дня 24, а PlainDateTime — для «времени на часах». round до суток округлил 14:30 до полуночи 13 октября: это уже вторая половина дня.

12. Одни методы у трёх классов

14. Календари

const d = Temporal.PlainDate.from("2026-10-12");
const persian = d.withCalendar("persian");
console.log(persian.year, persian.month, persian.day, persian.era, persian.toString(), d.equals(persian), Temporal.PlainDate.compare(d, persian));   // 1405 7 20 ap 2026-10-12[u-ca=persian] false 0
const hebrew = d.withCalendar("hebrew");
console.log(hebrew.year, hebrew.monthsInYear, hebrew.inLeapYear, d.withCalendar("gregory").era, d.era);   // 5787 13 true ce undefined
console.log(Temporal.PlainDate.from("2027-01-01").weekOfYear, Temporal.PlainDate.from("2027-01-01").yearOfWeek);   // 53 2026

Каждая дата знает свой календарь, по умолчанию — ISO 8601: григорианский плюс правила нумерации недель. withCalendar читает тот же день в другом: по персидскому календарю соседнего Ирана 12 октября 2026 года — 20-е число 7-го месяца 1405 года. День один, поэтому compare даёт 0, а equals — false: он сравнивает и календарь. Еврейский 5787 год високосный, в нём 13 месяцев; эры есть у григорианского календаря, у ISO — нет.

Правила справочника: era с eraYear и weekOfYear с yearOfWeek берут только парой — 1 января 2027 года, пятница, по правилу ISO относится к 53-й неделе 2026 года. Не считайте, что в году 12 месяцев, а в неделе 7 дней, — есть monthsInYear и daysInWeek. monthCode отличается от month в календарях с високосным месяцем (день 23), а названия месяцев дают не массивы, а toLocaleString (день 25).

16. Что говорит спецификация

В тексте ECMA-262 2026 Temporal нет: стадию 4, последнюю, предложение получило в марте 2026 года и в выпуск 2026 года не успело. Его текст — на сайте предложения tc39.es/proposal-temporal («Stage 4 Draft»), устроен как обычная глава спецификации:

  • 1 The Temporal Object: обычный объект без [[Construct]] и [[Call]] — отсюда «is not a constructor».
  • 3.1.1 Temporal.PlainDate ( isoYear, isoMonth, isoDay [ , calendar ] ): без new — TypeError; числа обрезаются до целых (new Temporal.PlainDate(2026.9, 10.5, 12.99) — 12 октября 2026); если IsValidISODate говорит «нет», — RangeError.
  • 3.4 Properties of Temporal.PlainDate Instances: внутренние слоты [[ISODate]] (год, месяц, число) и [[Calendar]]; поля читают их через геттеры.
  • 3.5.7 RegulateISODate — подгонка: при constrain месяц зажимается между 1 и 12, потом число — между 1 и длиной месяца; при reject — RangeError.
  • 12.3.7 CalendarDateAdd — порядок схемы 2: годы и месяцы, RegulateISODate для числа, потом дни и недели, умноженные на 7.
  • 3.5.13 CompareISODate: год, потом месяц, потом число; календарь не участвует — отсюда 0 для персидской даты.
  • 3.3.33 Temporal.PlainDate.prototype.valueOf — один шаг: бросить TypeError; примечание: иначе > сравнивал бы строки, и ответ был бы верным лишь «иногда».
  • 13.35 ParseISODateTime: строка разбирается по грамматике формата, несуществующая дата отвергается.
  • 2.2.5 Temporal.Now.plainDateISO через SystemDateTime: текущие наносекунды от эпохи, прочитанные в поясе устройства или в заданном.

17. «Карточки»: повтор по датам

Вчера даты повтора жили в Date и уезжали в JSON на «11 октября, 19:00 по UTC». Дню повтора время и пояс не нужны — это PlainDate. Добавим шаг: после повтора интервал удваивается.

const cards = [
  { word: "book", next: Temporal.PlainDate.from("2026-10-12"), step: 1 },
  { word: "water", next: Temporal.PlainDate.from("2026-10-15"), step: 1 },
  { word: "bread", next: Temporal.PlainDate.from("2026-10-13"), step: 2 },
];
const save = (list) => JSON.stringify(list);
const load = (text) => JSON.parse(text, (key, value) => (key === "next" ? Temporal.PlainDate.from(value) : value));
const review = (card, today) => ({ ...card, next: today.add({ days: card.step * 2 }), step: card.step * 2 });

const text = save(cards);
const back = load(text);
const today = Temporal.PlainDate.from("2026-10-13");
const due = back.filter((c) => Temporal.PlainDate.compare(c.next, today) <= 0);
const after = due.map((c) => review(c, today));
console.log(text);
console.log(due.map((c) => c.word), after.map((c) => `${c.word} → ${c.next}`), today.until(back[1].next).days, today.toString());
[{"word":"book","next":"2026-10-12","step":1},{"word":"water","next":"2026-10-15","step":1},{"word":"bread","next":"2026-10-13","step":2}]
(2) ['book', 'bread'] (2) ['book → 2026-10-15', 'bread → 2026-10-17'] 2 2026-10-13

Строка 1 — сохранение. Replacer больше не нужен: toJSON записал каждую дату как есть, «2026-10-12», без сдвига на пояс.

Строка 2 — повтор. Reviver вернул даты, compare отобрал book (вчерашнюю) и bread (сегодняшнюю). review собирает новую карточку через spread дня 22 Essentials: book придёт через 2 дня, bread — через 4; до water — 2 дня. «Сегодня» не сдвинулось, и копия, как в addDays дня 21, не нужна.

Три опыта.

Первый. Замените Temporal.PlainDate.compare(c.next, today) <= 0 на c.next <= today. Какая ошибка и почему у Date такое сравнение работало?

Второй. Уберите из load второй аргумент JSON.parse и выведите back[0].next.dayOfWeek и отобранные карточки. Почему compare по-прежнему отобрал правильно, а dayOfWeek — undefined?

Третий. Перед filter напишите отдельной строкой today.add({ days: 1 });. Изменится ли список? Как сдвинуть «сегодня» на день по-настоящему?

  1. Что напечатает new Temporal.PlainDate(2026, 9, 12).toString() и почему?
    Ответ «2026-09-12» — 12 сентября. В Temporal месяцы считаются с единицы, 9 — это сентябрь. Привычка «месяц минус один» из Date здесь даёт ошибку на месяц, и молча.
  2. Почему jan31.add({ months: 1, days: 31 }) и jan31.add({ days: 31 }).add({ months: 1 }) дают разные даты?
    Ответ Внутри одного add сначала прибавляются месяцы и число подгоняется: 28 февраля, потом 31 день — 31 марта. Во втором случае сначала 31 день — 3 марта, потом месяц — 3 апреля.
  3. Чем a.until(b) отличается от a.since(b)?
    Ответ until считает от a до b (b минус a), since — наоборот. Если b позже, until положителен, а since отрицателен.
  4. Почему a < b для двух PlainDate — ошибка, а не true или false?
    Ответ valueOf у дат Temporal всегда бросает TypeError. Иначе < сравнил бы строки, и это иногда давало бы неверный ответ. Сравнивают через Temporal.PlainDate.compare или equals.
  5. Когда брать PlainDateTime, а когда ждать ZonedDateTime?
    Ответ PlainDateTime — «время на часах»: урок в 9:00 по местному времени, где бы он ни шёл. Если событие — один момент для всех поясов, например созвон Ашхабада и Берлина, нужен ZonedDateTime (день 24).
