День 22. Temporal: PlainDate, PlainTime, PlainDateTime и Now

Выжимка лекции: классы Temporal без пояса, создание, поля, сдвиг, разница, сравнение, JSON и «сегодня».

Главное

Temporal.PlainDate.from("2026-01-31").add({ months: 1 }).toString();   // "2026-02-28" — без переноса в март
new Temporal.PlainDate(2026, 10, 12).month;                             // 10 — месяц с единицы
Temporal.PlainDate.from("2026-10-18").dayOfWeek;                        // 7 — воскресенье, понедельник — 1
Temporal.PlainDate.from("2026-10-12").until("2027-01-01").days;         // 81
Temporal.PlainDate.compare("2026-10-12", "2026-10-20");                 // -1
JSON.stringify({ next: Temporal.PlainDate.from("2026-10-12") });        // '{"next":"2026-10-12"}'

Объекты Temporal неизменяемы: with, add, subtract возвращают новый объект, а поля — только для чтения. Строка d.add({ days: 1 }); без присваивания не делает ничего. Строка разбирается строго — только формат RFC 9557 (YYYY-MM-DD), иначе RangeError; объект подгоняется настройкой overflow: "constrain" (по умолчанию) или "reject".

Внутри add сначала годы и месяцы, потом число подгоняется к длине месяца, потом недели и дни: 31 января + { months: 1, days: 31 } — 31 марта. a.until(b) — «b минус a», a.since(b) — «a минус b»; { largestUnit: "months" } разбивает ответ на месяцы и дни.
<, - и + с датами Temporal — TypeError: valueOf бросает ошибку нарочно. Сравнивают equals и compare, сортируют list.sort(Temporal.PlainDate.compare). В JSON дата уходит строкой сама, обратно — reviver с Temporal.PlainDate.from.
PlainDateTime выбрасывает смещение из строки («…+03:00») без пересчёта, а Z не принимает: момент с поясом — ZonedDateTime дня 24. Temporal.Now зовите в одном месте, «сегодня» передавайте функциям параметром. Ошибки Chrome начинаются с «Temporal error:».
