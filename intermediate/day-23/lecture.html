1. Обещания дня 22

Вчера until вернул загадочную строку P81D, а в add можно было передать "P1M", и обе обещаны на сегодня. Обещан и подсчёт курса в часах: 36 дней по три урока — 108 уроков по 45 минут.

const course = Temporal.PlainDate.from("2026-10-12").until("2027-01-01");
const lessons = Temporal.Duration.from({ minutes: 45 * 108 });
console.log(course.toString(), course.days, lessons.toString(), lessons.total("hours"));   // P81D 81 PT4860M 81

Оба значения — объекты Temporal.Duration, длительности. Первое — 81 день на календаре, второе — 4860 минут, а метод total перевёл их в часы: ровно 81 час занятий. Совпадение чисел случайное, а сам ответ — практика плана.

2. Duration: как создать и прочитать

const a = Temporal.Duration.from({ hours: 1, minutes: 30 });
const b = Temporal.Duration.from("P1Y2M3W4DT5H6M7.008S");
const c = new Temporal.Duration(0, 0, 0, 0, 1, 30);
const d = Temporal.Duration.from(a);
console.log(a.toString(), b.toString(), c.toString(), d.toString(), a === d, Temporal.Duration.compare(a, c));   // PT1H30M P1Y2M3W4DT5H6M7.008S PT1H30M PT1H30M false 0
console.log(b.years, b.months, b.weeks, b.days, b.hours, b.minutes, b.seconds, b.milliseconds, typeof a.equals);   // 1 2 3 4 5 6 7 8 undefined
console.log(a);   // Duration {years: 0, months: 0, weeks: 0, days: 0, hours: 1, …}

Длительность — не момент и не дата, а набор из десяти чисел: годы, месяцы, недели, дни, часы, минуты, секунды, милли-, микро- и наносекунды. Создают её как даты дня 22: from с объектом (ключи во множественном числе, отсутствующие — ноль), со строкой или с другой длительностью; конструктор принимает те же десять чисел по порядку, поэтому полтора часа — это пять нулей и 1, 30. Справочник советует from. Консоль снова показывает поля, а не строку, — печатаем toString().

Метода equals у длительности нет: «полтора часа» и «90 минут» — разные наборы полей, но одна и та же длина. Сравнивает их Temporal.Duration.compare — раздел 8.

3. Строка длительности ISO 8601

const iso = (text) => Temporal.Duration.from(text).toString();
console.log(["P40D", "PT2H30M", "P1M", "PT1M", "PT0.0021S", "P0D", "-PT1H30M", "p1dt12h", "PT1,5H"].map(iso));
// (9) ['P40D', 'PT2H30M', 'P1M', 'PT1M', 'PT0.0021S', 'PT0S', '-PT1H30M', 'P1DT12H', 'PT1H30M']

Формат ISO 8601 для длительностей начинается с P — «период». Дальше идут числа с буквами: годы Y, месяцы M, недели W, дни D; после T — часы H, минуты M, секунды S. Одна и та же буква M означает месяцы до T и минуты после, поэтому "P1M" из дня 22 — месяц, а "PT1M" — минута. Нулевые части пропускают, но ноль целиком пишется PT0S. Строчные буквы и запятая вместо точки тоже понимаются, а в ответ toString пишет каноническую форму.

Справочник предупреждает: знак в начале и недели вместе с другими частями — расширения стандарта (ISO 8601-2). Другие программы могут не принять -P1M или P3W1D.

4. Знак и целые числа

const late = Temporal.Duration.from({ hours: -1, minutes: -30 });
const zero = Temporal.Duration.from({ hours: 0 });
console.log(late.toString(), late.sign, late.hours, late.abs().toString(), late.negated().toString(), zero.toString(), zero.sign, zero.blank);   // -PT1H30M -1 -1 PT1H30M PT1H30M PT0S 0 true
console.log(Temporal.Duration.from({ hours: 100, minutes: 100 }).with({ minutes: 0 }).toString());   // PT100H
Temporal.Duration.from({ hours: 1, minutes: -30 });   // RangeError: Temporal error: Duration was not valid.

Длительность бывает положительной, отрицательной и нулевой: sign даёт 1, −1 или 0, а blank — «пустая ли она». Знак хранится в каждом поле, и все поля обязаны быть одного знака — отсюда RangeError дня 22 для { months: 1, days: -1 }. abs снимает минус, negated переворачивает знак, with заменяет поля — как у дат, с проверкой знаков.

Числа в полях — только целые: { hours: 1.5 } даёт RangeError «Expected finite integer», в отличие от конструктора PlainDate, который дробь отбрасывал. Полтора часа пишут { hours: 1, minutes: 30 } или строкой "PT1.5H" — в строке дробь у последней части времени разрешена.

5. Перенос и round

const d = Temporal.Duration.from({ hours: 100, minutes: 100, seconds: 100 });
console.log(d.toString(), d.round({ largestUnit: "days" }).toString(), d.round({ largestUnit: "hours" }).toString(), d.round("hours").toString());
// PT100H100M100S P4DT5H41M40S PT101H41M40S PT102H
const work = Temporal.Duration.from({ days: 3, hours: 1, minutes: 41, seconds: 5 });
console.log(work.round({ largestUnit: "hours" }).toString(), Temporal.Duration.from({ hours: 1, minutes: 17 }).round({ smallestUnit: "minutes", roundingIncrement: 15 }).toString(), Temporal.Duration.from({ hours: 2, minutes: 30 }).round({ largestUnit: "minutes" }).toString());
// PT73H41M5S PT1H15M PT150M

Длительность хранит поля такими, какими их дали: «100 часов 100 минут 100 секунд» так и печатается. Справочник называет это несбалансированной записью и объясняет: «полторы минуты» и «90 секунд» равны, и программа не должна решать за вас, как показать. Перенос делает round, причём два дела сразу. Сначала лишнее уходит в старшие единицы — но не выше largestUnit: с "days" выходят 4 дня 5 часов, с "hours" — 101 час. Единицы старше largestUnit, наоборот, раскладываются вниз: 2 часа 30 минут при "minutes" — 150 минут. Потом всё мельче smallestUnit округляется: до часов — 102 часа, до четверти часа (roundingIncrement: 15) — час пятнадцать. Нужна хотя бы одна из двух настроек. Пример MDN «73:41:05» — трое суток, разложенные в часы: PT73H41M5S.

6. total: длительность в число

const d = Temporal.Duration.from({ hours: 1, minutes: 30 });
console.log(d.total("minutes"), d.total("hours"), d.total({ unit: "seconds" }));   // 90 1.5 5400
const lesson = Temporal.Duration.from({ minutes: 45 });
const course = Temporal.Duration.from({ minutes: 45 * 108 });
console.log(course.total("hours"), course.total("days"), course.round({ largestUnit: "days" }).toString(), course.total("minutes") / lesson.total("minutes"));   // 81 3.375 P3DT9H 108

round возвращает длительность, а total — обычное число в одной единице, с дробью: полтора часа — 90 минут или 1,5 часа. Это мост к арифметике чисел: средние, доли, деление. Практика плана — длительность курса: 108 уроков по 45 минут — 81 час, или 3,375 суток, то есть трое суток и девять часов без перерыва. Обратно, 4860 минут на 45 — снова 108 уроков. Справочник предупреждает: результат total — число с плавающей точкой и бывает неточным, как 0.1 + 0.2 дня 6 Essentials.

7. Календарные единицы и relativeTo

const month = Temporal.Duration.from({ months: 1 });
console.log(month.total({ unit: "days", relativeTo: Temporal.PlainDate.from("2026-01-01") }), month.total({ unit: "days", relativeTo: Temporal.PlainDate.from("2026-02-01") }), month.total({ unit: "days", relativeTo: "2028-02-01" }));   // 31 28 29
const gap = Temporal.PlainDate.from("2026-10-12").until("2027-01-01");
console.log(gap.round({ largestUnit: "months", relativeTo: Temporal.PlainDate.from("2026-10-12") }).toString(), gap.round({ largestUnit: "weeks", relativeTo: "2026-10-12" }).toString());   // P2M20D P11W4D
month.total("days");   // RangeError: Temporal error:

Сколько дней в «одном месяце»? Зависит от месяца — 31, 28 или 29. Справочник называет годы, месяцы и недели календарными единицами: их длина зависит от календаря и от того, откуда считать, а сама длительность ни календаря, ни даты не хранит. Поэтому total, round и compare принимают настройку relativeTo — дату-опору, PlainDate или PlainDateTime (строка тоже подойдёт). Без неё перевод календарных единиц в дни — RangeError, причём Chrome оставляет текст пустым: «Temporal error: ». А round до месяцев без опоры пишет и вовсе путаный текст «largestUnit when rounding Duration was not the largest provided unit». Недели тоже календарные: в некоторых календарях неделя не из семи дней. Сутки же считаются ровно по 24 часа — перевод часов появится только с поясами, на дне 24.

Так вчерашние 81 день раскладываются в «2 месяца 20 дней» — как until с largestUnit дня 22, но уже у готовой длительности.

8. Сложение и сравнение длительностей

const a = Temporal.Duration.from({ hours: 1, minutes: 30 });
console.log(a.add({ hours: -1, minutes: -20 }).toString(), a.subtract({ minutes: 45 }).toString(), a.add("PT45M").toString(), Temporal.Duration.from({ minutes: 50 }).add({ minutes: 20 }).toString(), Temporal.Duration.from({ days: 1 }).add({ hours: 30 }).toString());
// PT10M PT45M PT2H15M PT70M P2DT6H
const list = ["PT2H", "PT1H30M", "PT90M", "PT1H45M", "PT1H"].map((s) => Temporal.Duration.from(s));
list.sort(Temporal.Duration.compare);
console.log(list.join(" "), Temporal.Duration.compare("PT3S", "PT1M"), "PT3S" > "PT1M");   // PT1H PT1H30M PT90M PT1H45M PT2H -1 true
Temporal.Duration.from({ months: 1 }).add({ days: 1 });   // RangeError: Temporal error: Largest unit cannot be a calendar unit when adding two durations.

add и subtract складывают длительности и сразу переносят лишнее, но только до самой крупной единицы слагаемых: 50 и 20 минут — 70 минут, а не час с минутами; сутки и 30 часов — двое суток и 6 часов. Знаки выравниваются: полтора часа минус час двадцать — 10 минут. Календарные длительности так не складываются — «месяц плюс день» без даты не посчитать. Справочник советует идти через дату: start.add(a).add(b).since(start).

compare работает как у дат: −1, 0 или 1, поэтому его передают в sort. «1 час 30 минут» и «90 минут» для него равны, и стабильная сортировка оставила их в исходном порядке. А > и + снова под запретом: valueOf бросает TypeError. Пример справочника объясняет, почему это хорошо: как строки, "PT3S" > "PT1M" — true, хотя три секунды меньше минуты. Для календарных длительностей compare тоже просит relativeTo (задание 9).

9. Строки, JSON и toLocaleString

const record = Temporal.Duration.from({ seconds: 9, milliseconds: 580 });
console.log(record.toString(), record.toString({ fractionalSecondDigits: 1 }), record.toString({ smallestUnit: "millisecond" }), `${record}`, JSON.stringify({ time: record }));   // PT9.58S PT9.5S PT9.580S PT9.58S {"time":"PT9.58S"}
const ms = Temporal.Duration.from({ milliseconds: 1000 });
console.log(ms.toString(), Temporal.Duration.from(ms.toString()).milliseconds, Temporal.Duration.from({ hours: 1, minutes: 30, seconds: 15 }).toLocaleString("ru-RU"));   // PT1S 0 1 ч 30 мин 15 с

Пример MDN — мировой рекорд на 100 метров, 9,58 секунды. toString принимает fractionalSecondDigits (сколько цифр после точки; лишние отрезаются) или smallestUnit. toJSON пишет ту же строку, обратно — reviver с Temporal.Duration.from. Одна потеря: доли секунды в строке — одно дробное число, поэтому «1000 миллисекунд» уходят как PT1S и возвращаются «1 секундой». toLocaleString пишет длительность для людей; вид зависит от браузера, а настройки — день 25.

10. PlainYearMonth: месяц года

const ym = Temporal.PlainYearMonth.from("2026-10");
const b = new Temporal.PlainYearMonth(2026, 10);
const c = Temporal.PlainDate.from("2026-10-12").toPlainYearMonth();
console.log(ym.toString(), b.toString(), ym.equals(c), ym.year, ym.month, ym.monthCode, ym.daysInMonth, ym.inLeapYear, typeof ym.day);   // 2026-10 2026-10 true 2026 10 M10 31 false undefined
console.log(ym.toPlainDate({ day: 1 }).toString(), ym.toPlainDate({ day: 1 }).dayOfWeek, ym.toPlainDate({ day: 40 }).toString(), JSON.stringify({ ym }));   // 2026-10-01 4 2026-10-31 {"ym":"2026-10"}

PlainYearMonth — месяц конкретного года без числа: «октябрь 2026», отчёт за месяц, срок оплаты, страница календаря. Строка — "2026-10", конструктор — год и месяц (снова с единицы), из даты — toPlainYearMonth(). Поля — как у даты без дневных: year, month, monthCode, daysInMonth, daysInYear, monthsInYear, inLeapYear, era, eraYear, calendarId; day нет. Обратно в дату — toPlainDate({ day }), число подгоняется: 40 октября — 31-е.

const school = Temporal.PlainYearMonth.from("2026-09");
const end = Temporal.PlainYearMonth.from("2027-05");
console.log(school.add({ months: 4 }).toString(), end.subtract({ years: 1 }).toString(), school.until(end).toString(), end.since(school).months, Temporal.PlainYearMonth.compare(school, end));   // 2027-01 2026-05 P8M 8 -1
const lengths = [];
for (let m = school; Temporal.PlainYearMonth.compare(m, end) <= 0; m = m.add({ months: 1 })) lengths.push(m.daysInMonth);
console.log(lengths.length, lengths.join(" "));   // 9 30 31 30 31 31 28 31 30 31
school.add({ days: 20 });   // RangeError: Temporal error: Can only add years or months to PlainYearMonth.

Учебный год с сентября по май — девять месяцев, разница первого и последнего — P8M. add, subtract, until, since, with, equals и compare — как у даты, но единицы только годы и месяцы. Дни и недели — ошибка, и здесь справочник MDN отстал: страница add обещает, что дни «меньше месяца ничего не меняют», а текст предложения (раздел 16) и Chrome требуют RangeError. Разницу в днях считают через даты: toPlainDate({ day: 1 }) у обоих месяцев.

11. Практика: календарь месяца

function monthGrid(ym) {
  const first = ym.toPlainDate({ day: 1 });
  const cells = Array(first.dayOfWeek - 1).fill("··");
  for (let day = 1; day <= ym.daysInMonth; day++) cells.push(String(day).padStart(2, "0"));
  const rows = [];
  for (let i = 0; i < cells.length; i += 7) rows.push(cells.slice(i, i + 7).join(" "));
  return rows;
}
for (const row of monthGrid(Temporal.PlainYearMonth.from("2026-10"))) console.log(row);

Практика плана. Всё, что нужно для страницы календаря, даёт PlainYearMonth: день недели первого числа (1 октября 2026 года — четверг, 4) и длина месяца. Пустые клетки до четверга — три точки-заглушки, числа дополнены нулём методом padStart дня 16 Essentials, неделя — семь клеток с понедельника. Никаких «нулевых чисел следующего месяца», как на дне 21.

12. PlainMonthDay: день месяца

const md = Temporal.PlainMonthDay.from("10-12");
const b = new Temporal.PlainMonthDay(10, 12);
const c = Temporal.PlainDate.from("2026-10-12").toPlainMonthDay();
const e = Temporal.PlainMonthDay.from({ monthCode: "M10", day: 12 });
console.log(md.toString(), b.toString(), e.toString(), md.equals(c), md.monthCode, md.day, typeof md.month, typeof md.year, md.toString({ calendarName: "always" }));   // 10-12 10-12 10-12 true M10 12 undefined undefined 1972-10-12[u-ca=iso8601]
console.log(md);   // PlainMonthDay {calendarId: 'iso8601', monthCode: 'M10', day: 12}
const leap = Temporal.PlainMonthDay.from("02-29");
console.log(leap.toString(), leap.toPlainDate({ year: 2027 }).toString(), leap.toPlainDate({ year: 2028 }).toString(), Temporal.PlainMonthDay.from({ year: 2027, month: 2, day: 29 }).toString(), typeof Temporal.PlainMonthDay.compare);   // 02-29 2027-02-28 2028-02-29 02-28 undefined

PlainMonthDay — день, который повторяется каждый год: день рождения, праздник. Строка — "10-12" (или "--10-12"), конструктор — месяц и число. Полей всего три: календарь, monthCode и day; даже month нет. Справочник объясняет: номер месяца без года в календарях с високосным месяцем не определён, поэтому день рождения хранят кодом месяца — обещание дня 22. В превью консоли полей мало, и оно впервые читается целиком.

Внутри всё же есть год — опорный 1972-й, первый високосный после эпохи; его видно с calendarName: "always". Поэтому 29 февраля — правильный день месяца. В конкретный год его переносит toPlainDate({ year }) с подгонкой: в 2027 году — 28 февраля, в 2028-м — 29-е. Если год передан сразу в from, подгонка случается тут же. Сравнивать, складывать и вычитать PlainMonthDay нельзя: смысл «раньше» и «на день позже» зависит от года. Есть только equals и with.

13. Практика: дни рождения

function nextBirthday(birthday, today) {
  const thisYear = birthday.toPlainDate({ year: today.year });
  return Temporal.PlainDate.compare(thisYear, today) >= 0 ? thisYear : birthday.toPlainDate({ year: today.year + 1 });
}
const today = Temporal.PlainDate.from("2026-10-12");
for (const text of ["10-20", "10-12", "03-08", "02-29"]) {
  const next = nextBirthday(Temporal.PlainMonthDay.from(text), today);
  console.log(text, next.toString(), today.until(next).days);
}
10-20 2026-10-20 8
10-12 2026-10-12 0
03-08 2027-03-08 147
02-29 2027-02-28 139

Практика плана. Ближайший день рождения — в этом году, если он ещё не прошёл, иначе в следующем. Сегодняшний считается: до него 0 дней. У родившегося 29 февраля в невисокосном 2027 году праздник подогнан к 28-му; кто-то празднует 1 марта — тогда нужна своя проверка inLeapYear. «Сегодня» снова приходит параметром.

16. Что говорит спецификация

Текст — то же предложение tc39.es/proposal-temporal, что на дне 22: в ECMA-262 2026 Temporal нет. Разделы дня:

  • 7.1.1 Temporal.Duration ( … ): без new — TypeError; каждый аргумент проходит ToIntegerIfIntegral — дробь даёт RangeError, а не обрезается, как в конструкторе PlainDate.
  • 7.4 Properties of Temporal.Duration Instances: десять слотов от [[Years]] до [[Nanoseconds]], целые, точно хранимые в обычном числе.
  • 7.5.16 IsValidDuration: все поля одного знака; годы, месяцы и недели меньше 232; всё остальное в секундах меньше 253 — MAX_SAFE_INTEGER дня 21.
  • 7.5.41 AddDurations: самая крупная единица — календарная → RangeError; иначе обе длительности переводятся в наносекунды с сутками по 24 часа, складываются и раскладываются обратно до этой единицы.
  • 7.3.21 Temporal.Duration.prototype.total: три ветки — с опорой-поясом (день 24), с опорой-датой (прибавить к ней и посчитать разницу), без опоры — календарная единица даёт RangeError.
  • 7.2.3 Temporal.Duration.compare: если поля совпадают, сразу 0 — опора не нужна даже для месяцев; иначе календарные единицы требуют relativeTo.
  • 9.5.8 AddDurationToYearMonth: недели, дни или время — RangeError; к месяцу прибавляют от его первого дня.
  • 12.3.13 CalendarYearMonthFromFields: опорный день месяца — 1-е; 12.3.24 CalendarMonthDayToISOReferenceDate: опорный год для ISO — 1972, «первый високосный после эпохи».

17. «Карточки»: время занятий и интервалы

Два новых вопроса к «Карточкам»: сколько ученик занимался за неделю и через сколько повторять каждое слово. Время занятий приходит из журнала строками ISO 8601, интервалы повтора храним длительностями.

const sessions = ["PT12M30S", "PT8M45S", "PT21M10S", "PT6M"].map((s) => Temporal.Duration.from(s));
const sum = sessions.reduce((a, b) => a.add(b));
const average = Temporal.Duration.from({ seconds: Math.round(sum.total("seconds") / sessions.length) }).round({ largestUnit: "minutes" });
const cards = [
  { word: "book", last: Temporal.PlainDate.from("2026-10-10"), interval: Temporal.Duration.from({ days: 2 }) },
  { word: "water", last: Temporal.PlainDate.from("2026-10-12"), interval: Temporal.Duration.from({ weeks: 1 }) },
  { word: "bread", last: Temporal.PlainDate.from("2026-09-28"), interval: Temporal.Duration.from({ weeks: 2 }) },
];
const today = Temporal.PlainDate.from("2026-10-13");
const due = cards.filter((c) => Temporal.PlainDate.compare(c.last.add(c.interval), today) <= 0).map((c) => c.word);
console.log(sum.toString(), average.toString(), sum.round({ smallestUnit: "minutes" }).toString());

Строка 1 — время. reduce дня 20 Essentials сложил четыре длительности через add: 48 минут 25 секунд. Среднее — через total: 2905 секунд на четыре, округлено и разложено до минут, — 12 минут 6 секунд. С точностью до минут — 48 минут.

Строка 2 — повтор. Интервал в JSON — короткая строка P1W. Карточка пора повторять, если «последний повтор плюс интервал» уже наступил: у book — 12 октября, у bread — тоже 12-е (28 сентября плюс две недели), у water — только 19-го.

Три опыта.

Первый. Сложите сессии через reduce((a, b) => a + b). Какая ошибка и какой метод её бросил?

Второй. Выведите cards[1].interval.total("days"). Почему ошибка, хотя в неделе всегда семь дней? Исправьте через relativeTo.

Третий. Поставьте bread интервал { months: 1 }. Почему дату к месяцу прибавить можно, а длительность к месяцу — нет? Попадёт ли bread в список?

  1. Чем "P1M" отличается от "PT1M"?
    Ответ До T буква M означает месяцы, после — минуты. Первая строка — один месяц, вторая — одна минута.
  2. Почему Temporal.Duration.from({ hours: 100, minutes: 100 }) печатается как PT100H100M?
    Ответ Длительность хранит поля как есть, без переноса. Перенос делает round, например round({ largestUnit: "days" }).
  3. Почему Temporal.Duration.from({ months: 1 }).total("days") — ошибка?
    Ответ В месяце 28–31 день, и длительность не знает, о каком месяце речь. Нужна дата-опора: total({ unit: "days", relativeTo: "2026-02-01" }) даст 28.
  4. Как отсортировать массив длительностей по длине?
    Ответ list.sort(Temporal.Duration.compare). Сравнение строк или > не годится: "PT3S" > "PT1M" — true, а > у длительностей бросает TypeError.
  5. Что вернёт Temporal.PlainMonthDay.from("02-29").toPlainDate({ year: 2027 })?
    Ответ 28 февраля 2027 года: 2027-й не високосный, и число подгоняется к последнему дню февраля.
