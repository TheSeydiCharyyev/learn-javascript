# День 25. Intl: NumberFormat, DateTimeFormat и локали

<Subtitle>Выжимка лекции: локаль, числа и цены, даты для людей, сравнение строк и туркменская локаль.</Subtitle>

## Главное

```js
new Intl.NumberFormat("ru-RU", { style: "currency", currency: "TMT" }).format(1250.5);   // "1 250,50 ТМТ"
new Intl.DateTimeFormat("en-US", { dateStyle: "long" }).format(new Date(2026, 9, 12));    // "October 12, 2026"
(0.075).toLocaleString("ru-RU", { style: "percent", minimumFractionDigits: 1 });          // "7,5 %"
(5).toLocaleString("ru-RU", { style: "unit", unit: "hour", unitDisplay: "long" });       // "5 часов"
["Ёлкин", "Абаев"].sort((a, b) => a.localeCompare(b, "ru"));                             // ["Абаев", "Ёлкин"]
new Intl.DateTimeFormat("tk").resolvedOptions().locale;                                  // "ru-RU" в русском Chrome
```

## Шаблон Intl

<Definition>
**Локаль** — тег BCP 47: язык, письменность, регион (`"ru-RU"`, `"en-GB"`) и
расширения после `-u-` (`-u-ca-persian`, `-u-nu-arab`). Форматировщик создают один
раз — `new Intl.NumberFormat(локаль, настройки)` — и зовут `format` сколько угодно.
`toLocaleString(локаль, настройки)` у числа или даты — то же, но объект создаётся при каждом вызове.
</Definition>

| Задача | Настройки |
| --- | --- |
| цена | `{ style: "currency", currency: "TMT" }` — два знака после запятой сами |
| процент | `{ style: "percent" }` — число умножается на 100 |
| единица со склонением | `{ style: "unit", unit: "hour", unitDisplay: "long" }` |
| знаки после запятой | `minimumFractionDigits`, `maximumFractionDigits` |
| «1,2 миллиона» | `{ notation: "compact", compactDisplay: "long" }` |
| дата готовым набором | `dateStyle`, `timeStyle`: `"full" \| "long" \| "medium" \| "short"` |
| дата по частям | `weekday`, `day`, `month`, `year`, `hour`, `minute` — не вместе со стилями |
| пояс и календарь | `timeZone: "Europe/Berlin"`, `calendar: "persian"`, `hour12: true` |

<KeyPoint>
В выводе `Intl` бывают **неразрывные пробелы** (код 160): `"1 250,50 ТМТ"` из
`format` не равна такой же строке в коде. Вывод не сравнивают с готовой строкой; если его надо разобрать
— `formatToParts` отдаёт куски с типами (`integer`, `group`,
`decimal`, `currency`…), `resolvedOptions` — принятые правила.
</KeyPoint>

<Remember>
`a.localeCompare(b, локаль, настройки)` сравнивает по правилам языка: «Ё» рядом с «Е», регистр не
мешает. `{ numeric: true }` — «урок 2» раньше «урока 10»; `{ sensitivity: "base" }` — Gülnar
равна Gulnar. Ждите знак ответа, а не именно −1 или 1.
</Remember>

<NoteBox>
Туркменской локали в Chrome нет: `"tk"` тихо заменяется языком браузера, без ошибки.
`supportedLocalesOf(["tk"])` — пустой массив. Узбекскую Chrome «знает», но пишет «M10». В Node 22 с
полной ICU `tk` есть. Для туркменского сайта — свои названия месяцев и своя функция сравнения по
алфавиту.
</NoteBox>
