Основные задания

4. ValidationError для формы ученика
Средне12 мин

писать свой класс ошибки с полями.

checkStudent(data) проверяет { name, age, group }: имя — непустая строка, возраст — целое число от 14 до 60, группа — "JS-1" или "JS-2". Ошибка — ValidationError с полями field и value.

  • { name: "Аман", age: 17, group: "JS-1" } возвращается как есть;
  • пустое имя — «нужно имя», field "name"; возраст 9 — «возраст 9 вне диапазона 14–60», field "age", value 9; группа PY-1 — «группы PY-1 нет: есть JS-1, JS-2»;
  • String(e) — «ValidationError: возраст 9 вне диапазона 14–60», e instanceof Error и Error.isError(e) — true;
  • JSON.stringify(e) — {"name":"ValidationError","field":"age","value":9}, объяснено, почему нет message;
  • checkStudent(null) даёт TypeError, и код формы его не глотает, а пробрасывает.
5. Семья ошибок программы
Средне13 мин

строить иерархию ошибок и разбирать её в catch.

Классы AppError, ValidationError (с field) и NotFoundError. Функция handle(e) возвращает текст для человека.

  • handle: ValidationError с полем age — «Проверьте поле «age»», NotFoundError("слово «kitap»") — «Не найдено: слово «kitap»», AppError("колода пуста") — «Ошибка программы: колода пуста»;
  • name записан один раз, в AppError, а new NotFoundError("x").stack начинается с «NotFoundError: x»;
  • new AppError("y", { cause: 1 }).cause — 1, и у наследников cause тоже работает;
  • handle(new TypeError("t")) бросает этот же TypeError дальше;
  • объяснено, почему проверка instanceof AppError стоит последней.
6. Цепочка причин
Средне13 мин

оборачивать ошибки через cause и читать цепочку.

readSettings(text) разбирает JSON и при ошибке бросает AppError("настройки не прочитаны") с причиной; startApp(text) оборачивает её в AppError("программа не запущена"); explain(e) склеивает цепочку через « ← ». AppError — из задания 5.

  • startApp('{"theme": "dark"}') возвращает настройки;
  • для startApp("") explain даёт «AppError: программа не запущена ← AppError: настройки не прочитаны ← SyntaxError: Unexpected end of JSON input»;

9. Четыре ловушки
Сложно10 мин

находить ошибки в своих классах ошибок.

class AppError extends Error {
  constructor(message) {
    super(message);
  }
}
class ValidationError extends AppError {
  constructor(message, field) {
    super(message);
    this.field = field;
  }
}
function save(text) {
  try {
    return JSON.parse(text);
  } catch (err) {
    throw new AppError("настройки не сохранены", { cause: err });
  }
}
function handle(e) {
  if (e instanceof AppError) return `ошибка программы: ${String(e)}`;
  if (e instanceof ValidationError) return `поле ${e.field}`;
  return "неизвестно";
}
console.log(handle(new ValidationError("нет имени", "name")));
try { save("{"); } catch (e) { console.log(handle(e), "cause" in e); }
console.log(handle(new TypeError("опечатка")));
  • программа печатает «ошибка программы: Error: нет имени», «ошибка программы: Error: настройки не сохранены false» и «неизвестно» — для каждой строки названа причина;
  • после исправлений: «поле name», «ошибка программы: AppError: настройки не сохранены true»;
  • третий вызов бросает TypeError: опечатка из handle, а не возвращает «неизвестно»;
  • все четыре исправления — в классах и в handle, вызовы внизу не менялись.
