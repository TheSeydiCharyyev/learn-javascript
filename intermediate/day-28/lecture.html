1. Обещания, накопленные за курс

День 30 Essentials записал правило «функция таймера — всегда после текущего кода» и пообещал: «как устроена эта очередь, подробно разбирается в курсе 2». Там же было сказано, что then «никогда не срабатывает посреди вашего кода», даже у готового промиса. День 31 добавил, что async-функция выполняется сразу — до первого await, а потом отдаёт управление. День 27 курса 2 дважды отложил на сегодня вопрос «почему именно в таком порядке». Начнём с задачи — какие номера напечатаются по порядку?

console.log("1: скрипт");
setTimeout(() => console.log("6: таймер"), 0);
Promise.resolve().then(() => console.log("4: then"));
(async () => {
  console.log("2: async до await");
  await null;
  console.log("5: async после await");
})();
console.log("3: скрипт, конец");
1: скрипт
2: async до await
3: скрипт, конец
4: then
5: async после await
6: таймер

Номера идут подряд, хотя строки в коде — нет. Таймер с задержкой 0 оказался последним, then обогнал его, а продолжение после await встало между ними. Чтобы такие ответы получались не угадыванием, нужно знать, где каждая строка ждёт своей очереди. Помощники дня 30 Essentials (wait, later, failLater) стоят в начале app.js, как на дне 27.

2. Один поток и две очереди

У страницы один поток: в каждый момент выполняется что-то одно (день 30 Essentials). Работа приходит порциями — задачами: весь скрипт целиком, сработавший таймер, щелчок. Задача выполняется до конца, никто её не прерывает. А между задачами браузер выполняет микрозадачи — так справочник MDN на странице await называет продолжения промисов. Правило одно:

Отсюда ответ задачи раздела 1: строки 1–3 — сам скрипт, первая задача; 4 и 5 — микрозадачи, они идут сразу после скрипта; 6 — таймер, следующая задача. «Все микрозадачи» означает буквально все, даже появившиеся только что:

setTimeout(() => console.log("таймер"), 0);
let n = 0;
function step() {
  n++;
  if (n < 1000) return Promise.resolve().then(step);
  console.log("микрозадач подряд:", n);
}
Promise.resolve().then(step);
микрозадач подряд: 1000
таймер

Каждый шаг добавлял новую микрозадачу, и таймер ждал, пока не пройдут все тысяча. Бесконечная цепочка микрозадач повесила бы страницу, как бесконечный цикл. Устройство цикла событий целиком описывает страница MDN «Execution model» — это курс 3.

3. Почему then — после текущего кода

Ответ даёт спецификация (раздел 13): then никогда не вызывает функцию сам. Он лишь ставит её в очередь — как задание промиса. Если промис уже выполнен, задание встаёт в очередь сразу; если ждёт — в момент выполнения. А задания начинаются, только когда текущий код закончен, и идут в том порядке, в каком их поставили:

const p = Promise.resolve("готово");
p.then(() => console.log("первый then"));
p.then(() => console.log("второй then"));
console.log("синхронный код");
синхронный код
первый then
второй then

То же касается catch и finally дня 30 Essentials — это тоже then, только с другой функцией. А then вовсе без функции ничего не делает с значением и передаёт его дальше — но тоже через задание:

Promise.resolve(1).then().then((v) => console.log("then() без функции пропустил:", v));
Promise.reject(new Error("x")).then(() => console.log("не будет")).catch((e) => console.log("catch:", e.message)).finally(() => console.log("finally"));
console.log("сначала скрипт");
сначала скрипт
then() без функции пропустил: 1
catch: x
finally

Каждый следующий then цепочки ставится в очередь, только когда выполнился предыдущий. Поэтому две цепочки, начатые рядом, идут вперемешку, по шагу, — справочник называет это «переплетением» (intertwined):

Promise.resolve().then(() => console.log("A1")).then(() => console.log("A2"));
Promise.resolve().then(() => console.log("B1")).then(() => console.log("B2"));
A1
B1
A2
B2

Отсюда и порядок строк дня 27, когда all и race отклонились в одну миллисекунду: кто подписался раньше, тот и напечатал раньше. Но есть тонкость, на которой строить программу нельзя. Если шаг возвращает промис, цепочка ждёт его через два лишних задания (раздел 13 объяснит почему):

Promise.resolve().then(() => { console.log("A1"); return Promise.resolve(); }).then(() => console.log("A2"));
Promise.resolve().then(() => console.log("B1")).then(() => console.log("B2")).then(() => console.log("B3")).then(() => console.log("B4"));
A1
B1
B2
B3
A2
B4

Порядок внутри одной цепочки гарантирован всегда. Порядок между независимыми цепочками зависит от числа шагов в каждой — если он важен, свяжите их явно: then, await или Promise.all.

4. Тело, разрезанное await

Справочник предлагает смотреть на тело async-функции как на куски между await. Код до первого await выполняется сразу, синхронно. Код после каждого await — как будто внутри then: микрозадача. Без await функция работает синхронно целиком. Пример справочника — два вызова одной функции:

async function foo(name) {
  console.log(name, "start");
  console.log(name, "middle");
  console.log(name, "end");
}
foo("First");
foo("Second");
First start
First middle
First end
Second start
Second middle
Second end

Один await всё меняет: первый вызов доходит до него и уступает место второму, а «end» обоих откладывается в микрозадачи.

async function foo(name) {
  console.log(name, "start");
  await console.log(name, "middle");
  console.log(name, "end");
}
foo("First");
foo("Second");
First start
First middle
Second start
Second middle
First end
Second end

Справочник переписывает вторую версию на промисы — так видно, где проходит разрез:

function foo(name) {
  return new Promise((resolve) => {
    console.log(name, "start");
    resolve(console.log(name, "middle"));
  }).then(() => {
    console.log(name, "end");
  });
}
foo("First");
foo("Second");
First start
First middle
Second start
Second middle
First end
Second end

Совет справочника отсюда: пишите await там, где нужно значение промиса, и только там. Каждый лишний await — ещё один разрез, ещё одна микрозадача и лишняя возможность для гонки между функциями.

5. await ждёт всегда

Даже если ждать нечего. await 5 или await уже выполненного промиса всё равно отдаёт управление и продолжает функцию микрозадачей — справочник: «выполнение не вернётся в функцию, пока не будут обработаны все уже поставленные микрозадачи».

async function g() {
  console.log("g: до await");
  await 5;
  console.log("g: после await");
}
Promise.resolve().then(() => console.log("then 1")).then(() => console.log("then 2"));
g();
console.log("скрипт");
g: до await
скрипт
then 1
g: после await
then 2

Продолжение g встало в очередь после «then 1» — его поставили раньше — и перед «then 2», который поставят, только когда выполнится «then 1». await ждёт и любой «thenable» дня 27: его then вызывается тоже не сразу, а отдельным заданием:

const thenable = { then(resolve) { console.log("then вызван"); resolve(7); } };
(async () => {
  console.log("ждём thenable");
  console.log("получили", await thenable);

console.log("скрипт");

6. Что возвращает async-функция

Всегда новый промис — день 31 Essentials. return его выполняет, брошенная ошибка — отклоняет. Важное следствие: ошибка в async-функции не вылетает из вызова, даже брошенная до первого await. Её увидит только тот, кто ждёт промис:

async function broken() {
  throw new Error("сразу");
}
let thrown = "нет";
let result;
try {
  result = broken();
} catch {
  thrown = "да";
}
console.log("бросила при вызове:", thrown, "| вернула промис:", result instanceof Promise);
result.catch((e) => console.log("промис отклонён:", e.message));
бросила при вызове: нет | вернула промис: true
промис отклонён: сразу

Без catch такая ошибка станет красным «Uncaught (in promise)» дня 27, и только. Справочник сравнивает async function foo() { return 1; } с Promise.resolve(1), но предупреждает, что это не одно и то же: Promise.resolve(p) возвращает сам p (день 27), а async-функция — всегда новый промис.

const p = Promise.resolve(1);
async function asyncReturn() { return p; }
function basicReturn() { return Promise.resolve(p); }
console.log(p === basicReturn(), p === asyncReturn());
// true false

И самая частая ловушка — return промиса внутри try. Функция возвращает его, не дожидаясь, и try уже закончен, когда промис откажет. Чтобы catch поймал отказ, его нужно дождаться здесь же — return await:

async function withoutAwait() {
  try {
    return failLater("нет связи", 100);
  } catch {
    return "запасной ответ";
  }
}
async function withAwait() {
  try {
    return await failLater("нет связи", 100);
  } catch {
    return "запасной ответ";
  }
}
withoutAwait().then((v) => console.log("return:", v), (e) => console.log("return: отклонён —", e.message));
withAwait().then((v) => console.log("return await:", v));
return: отклонён — нет связи
return await: запасной ответ

Справочник добавляет второй довод за return await — стек дня 26. Без await промис отклоняется, когда внешняя функция уже вернулась, и в стеке её нет. С await ошибка проходит через неё, и V8 пишет в стеке строку «at async» с её именем:

async function lastAsyncTask() {
  await null;
  throw new Error("failed");
}
async function noAwait() {
  return lastAsyncTask();
}
async function withAwait() {
  return await lastAsyncTask();
}
const frames = (e) => e.stack.split("\n").slice(1).map((line) => line.trim().split(" (")[0]).join(" | ");
noAwait().catch((e) => console.log("return:", frames(e)));
withAwait().catch((e) => console.log("return await:", frames(e)));
return: at lastAsyncTask
return await: at lastAsyncTask | at async withAwait

Вопреки распространённому мнению, пишет справочник, return await не медленнее return, и, кроме соображений стиля, он почти всегда предпочтительнее.

7. Выражение async function

День 31 Essentials писал async перед объявлением функции и стрелкой. Есть и третья запись — выражение async function, как функция-выражение дня 13 Essentials. Имя у выражения необязательно, а если есть, видно только внутри — для рекурсии:

const load = async function loadDeck(attempt) {
  return attempt < 3 ? loadDeck(attempt + 1) : `попытка ${attempt}`;
};
load(1).then((text) => console.log(text, "|", load.name, "|", typeof loadDeck));
// попытка 3 | loadDeck | undefined

Главное применение выражения — сразу вызванная функция (IIFE), как в задаче раздела 1. В обычном скрипте await на верхнем уровне нельзя (раздел 10), а внутри (async () => { … })() — можно. Пример справочника показывает и цену лишнего ожидания из дня 27: функция add ждёт два числа по очереди, а сразу вызванная — запускает оба ожидания до первого await:

const start = Date.now();
const since = () => `${Math.round((Date.now() - start) / 100) * 100} мс`;
const add = async function (x) {
  const a = await later(20, 200);
  const b = await later(30, 200);
  return x + a + b;
};
add(10).then((v) => console.log("add:", v, since()));
(async function (x) {
  const p1 = later(20, 200);
  const p2 = later(30, 200);
  return x + (await p1) + (await p2);
})(10).then((v) => console.log("IIFE:", v, since()));
IIFE: 60 200 мс
add: 60 400 мс

Одно правило записи: строка кода не может начинаться со слов async function без имени — движок примет их за объявление и потребует имя. Поэтому сразу вызванную функцию берут в скобки. Кроме трёх записей, бывают async-методы объекта и класса (день 8): async load() { … }, static async create() { … }.

8. Практика: предскажите порядок

Практика плана. Запишите буквы по порядку, прежде чем читать разбор под кодом:

console.log("A");
setTimeout(() => console.log("B"), 0);
const p = new Promise((resolve) => {
  console.log("C");
  resolve();
});
p.then(() => console.log("D"));
(async () => {
  console.log("E");
  await p;
  console.log("F");
  setTimeout(() => console.log("G"), 0);
  await null;
  console.log("H");
})();
Promise.resolve().then(() => console.log("I")).then(() => console.log("J"));
console.log("K");
КогдаБуквыПочему
задача «скрипт»A, C, E, Kсинхронный код; исполнитель промиса (C) и начало async-функции (E) — тоже синхронно (день 30 Essentials, раздел 4)
микрозадачиD, F, Iв порядке постановки: p.then, потом await p, потом then с I — p уже выполнен, поэтому все три встали в очередь ещё во время скрипта
микрозадачи, добавленные по ходуH, JH поставил await null внутри F, J — выполненный I; F был раньше I, значит, и H раньше J
задачи-таймерыB, GB поставлен в начале скрипта, G — внутри F, позже

Итог: A C E K D F I H J B G. Алгоритм на любой такой задаче: сначала выпишите весь синхронный код, включая начала async-функций до первого await и исполнители new Promise; затем микрозадачи в порядке постановки, дописывая новые в конец; таймеры — в самом конце, по времени, а при равном — по порядку setTimeout.

Щелчок мышью и click()

Вторая задача — со слушателями дня 27 Essentials. У кнопки два слушателя, и каждый ставит микрозадачу:

document.body.innerHTML = "<button>Ответить</button>";
const button = document.querySelector("button");
button.addEventListener("click", () => {
  Promise.resolve().then(() => console.log("микрозадача 1"));
  console.log("слушатель 1");
});
button.addEventListener("click", () => {
  Promise.resolve().then(() => console.log("микрозадача 2"));
  console.log("слушатель 2");
});
button.click();
console.log("после click()");
слушатель 1
слушатель 2
после click()
микрозадача 1
микрозадача 2

button.click() вызывает слушателей прямо внутри скрипта, как обычные функции, — микрозадачи ждут, пока скрипт закончится. Уберите две последние строки и щёлкните кнопку мышью: порядок станет «слушатель 1, микрозадача 1, слушатель 2, микрозадача 2». Щелчок человека — своя задача (день 26: стек кончается на обработчике), и после каждого слушателя стек пуст — а при пустом стеке браузер сразу выполняет микрозадачи. Один и тот же код, два порядка: программа, которая на это опирается, будет вести себя по-разному в проверке и в жизни.

9. Практика: по очереди и все сразу

Практика плана. День 27 сравнил время: три await подряд — 600 мс, Promise.all — 300. Взгляд со стороны очереди объясняет почему: важно, когда начинается каждая загрузка.

const start = Date.now();
const since = () => `${Math.round((Date.now() - start) / 100) * 100} мс`;
function load(name, ms) {
  console.log(`начали «${name}»`, since());
  return later(name, ms);
}
async function oneByOne() {
  const slow = await load("медленное", 200);
  const fast = await load("быстрое", 100);
  console.log("по очереди:", slow, fast, since());
}
oneByOne();
начали «медленное» 0 мс
начали «быстрое» 200 мс
по очереди: медленное быстрое 300 мс

Второй вызов load стоит в коде после await — значит, в куске, который выполнится микрозадачей, когда первая загрузка закончится. Пока она шла, вторая даже не начиналась.

const start = Date.now();
const since = () => `${Math.round((Date.now() - start) / 100) * 100} мс`;
function load(name, ms) {
  console.log(`начали «${name}»`, since());
  return later(name, ms);
}
async function allAtOnce() {
  const [slow, fast] = await Promise.all([load("медленное", 200), load("быстрое", 100)]);
  console.log("все сразу:", slow, fast, since());
}
allAtOnce();
начали «медленное» 0 мс
начали «быстрое» 0 мс
все сразу: медленное быстрое 200 мс

Оба вызова — в одном куске до await, оба начались сразу. Правило выбора то же, что на дне 27: если вторая загрузка зависит от результата первой (например, по номеру группы — её расписание), — по очереди; если нет — все сразу.

10. Где можно писать await

Страница справочника «await is only valid in async functions, async generators and modules» объясняет запрет: await никогда не блокирует программу, он приостанавливает только свою асинхронную задачу. Поэтому в синхронной функции и на верхнем уровне скрипта ему нечего приостанавливать.

Текст V8 — «await is only valid in async functions and the top level bodies of modules». Ошибка синтаксиса, а значит, по дню 26 не выполнится весь скрипт. Последняя строка таблицы — самая коварная: «починить» её словом async у колбэка легко, а работать правильно это не будет (раздел 14).

11. AsyncFunction

Каждая async-функция — объект AsyncFunction, наследника Function. Глобального имени у него нет — конструктор достают из любой async-функции:

const AsyncFunction = async function () {}.constructor;
const sum = new AsyncFunction("a", "b", "return a + b;");

Конструктор устроен как Function() дня 4: строки становятся кодом, окружения функция не видит, и справочник предупреждает о той же опасности — new AsyncFunction в обычном коде не пишут. 13. Что говорит спецификация

Подробно — раздел 27.2.2 Promise Jobs, ради которого этот день и стоит в плане. Задание (Job) — в спецификации то, что браузер выполняет как микрозадачу.

  • PerformPromiseThen (27.2.5.4.1) — шаги then. Промис ждёт — реакция дописывается в его список. Промис уже выполнен или отклонён — сразу NewPromiseReactionJob и HostEnqueuePromiseJob. Ветки «вызвать сейчас» нет вовсе — это и есть ответ на вопрос дня. Когда ожидающий промис выполнится, TriggerPromiseReactions (27.2.1.8) ставит задания для всех его реакций по списку — в порядке, в каком вызывали then.
  • 27.2.2.1 NewPromiseReactionJob — задание, которое вызывает функцию then со значением, а её результат передаёт в resolve (или ошибку — в reject) промиса, который вернул then. Нет функции — значение просто проходит дальше.
  • 27.2.2.2 NewPromiseResolveThenableJob — когда промис решают объектом с then, этот then зовут отдельным заданием; примечание объясняет: чтобы он выполнился после окружающего кода. Отсюда «then вызван» после «скрипт» в разделе 5 и два лишних задания в разделе 3: одно — вызвать then возвращённого промиса, второе — его реакция.
  • 9.5 Jobs и 9.5.5 HostEnqueuePromiseJob: задание начинается, только когда стек выполнения пуст; выполняется одно за раз и до конца; задания промисов идут в том порядке, в каком их ставили. Как именно встраивать их между прочей работой, решает «хозяин» — примечание говорит, что браузеры и Node.js ставят задания промисов выше остального. Это и есть «все микрозадачи — до следующей задачи».
  • 27.7.5: AsyncFunctionStart и AsyncBlockStart запускают тело и по его концу вызывают resolve (обычный конец или return) или reject (брошенная ошибка) — поэтому ошибка не вылетает из вызова (раздел 6). Await (27.7.5.3) — схема ниже.
  • 27.7 AsyncFunction Objects кратко: 27.7.1 — конструктор %AsyncFunction%, работает как Function; 27.7.2 и 27.7.3 — его свойства и прототип с Symbol.toStringTag; 27.7.4 — экземпляры не конструкторы и без prototype.

14. «Карточки»: сохранить всю колоду

Ученик закончил занятие, и «Карточки» сохраняют прогресс каждой карточки на сервер. Сохранение одной — later с её временем. Первая мысль — forEach с async-колбэком, раз await в обычном колбэке запрещён:

const cards = [{ word: "cat", ms: 100 }, { word: "kitap", ms: 200 }, { word: "suw", ms: 100 }];
const saveCard = (card) => later(card.word, card.ms);
async function saveWithForEach() {
  const saved = [];
  cards.forEach(async (card) => {
    saved.push(await saveCard(card));
  });
  console.log("forEach: сохранено", saved.length);
}
async function saveOneByOne() {
  const start = Date.now();
  const saved = [];
  for (const card of cards) saved.push(await saveCard(card));
  console.log("for...of: сохранено", saved.length, "за", Math.round((Date.now() - start) / 100) * 100, "мс");
}
async function saveAllAtOnce() {
  const start = Date.now();
  const saved = await Promise.all(cards.map(saveCard));
  console.log("Promise.all: сохранено", saved.length, "за", Math.round((Date.now() - start) / 100) * 100, "мс");
}
(async () => {
  await saveWithForEach();
  await saveOneByOne();
  await saveAllAtOnce();
})();
forEach: сохранено 0
for...of: сохранено 3 за 400 мс
Promise.all: сохранено 3 за 200 мс

Строка 1. forEach вызвал три колбэка; каждый дошёл до своего await и вернул промис, а forEach эти промисы выбросил — он не умеет ждать. «Сохранено 0» напечатано раньше, чем закончилось первое сохранение. Строка 2. for...of с await внутри — по очереди: 100 + 200 + 100. Строка 3. map запускает все сохранения сразу и отдаёт массив промисов, а Promise.all ждёт их: время самого долгого. Выбор между двумя последними — правило раздела 9: по очереди, если важен порядок или сервер не любит одновременных запросов.

Три опыта.

Первый. Уберите async у колбэка forEach. Что напечатается и почему не выполнилась даже строка про for...of?

Второй. Поставьте await перед cards.forEach(…). Стало ли «сохранено 3»? Что вернул forEach и чего дождался await?

Третий. Сделайте сохранение «kitap» неудачным: saveCard для неё — failLater("kitap: нет связи", 200). Какие слова успеет сохранить for...of и что увидит консоль?

// then не вызывает функцию сразу даже у готового промиса; await ждёт всегда, даже await 5

// try { return await p } — чтобы catch поймал отказ p
// const f = async function name() {}; (async () => { await … })(); async-методы: async m() {}
// await — только в async-функциях, async-генераторах и модулях; не в forEach-колбэке
// по очереди: for...of + await; все сразу: await Promise.all(items.map(f)); forEach не ждёт
  1. Почему setTimeout(f, 0) срабатывает позже Promise.resolve().then(g), написанного ниже?
    Ответ Таймер — следующая задача, а then — микрозадача. Все микрозадачи выполняются сразу после текущей задачи, раньше следующей.
  2. Что напечатает async function f() { console.log(1); await null; console.log(3); } f(); console.log(2);?
    Ответ 1, 2, 3: до await — синхронно, после — микрозадачей, когда скрипт закончится.
  3. Вылетит ли ошибка из вызова broken(), если async function broken() { throw new Error() }?
    Ответ Нет. AsyncBlockStart превращает брошенную ошибку в отказ промиса; её увидит только тот, кто ждёт промис.
  4. Чем try { return p } отличается от try { return await p }?
    Ответ Первый возвращает промис не дожидаясь, и его отказ проходит мимо catch. Второй ждёт p внутри try, и отказ попадает в catch.
  5. Почему items.forEach(async (x) => await save(x)) не ждёт сохранений?
    Ответ forEach вызывает колбэки и выбрасывает их промисы. Ждать нужно в for...of или через Promise.all(items.map(save)).
