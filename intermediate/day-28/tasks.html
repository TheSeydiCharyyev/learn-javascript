День 28. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания делаем в файлах папки day-28 курса 2 с Live Server, в Chrome; в начале app.js — помощники дня 30 Essentials (wait, later, failLater). Порядок вывода сначала записывайте на бумаге, потом проверяйте.

console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
(async () => {
  console.log(4);
  await null;

})();
new Promise((resolve) => {
  console.log(6);
  resolve();
}).then(() => console.log(7));
console.log(8);

  • объяснено, почему 6 печатается сразу, а 7 — после 5.

3. Где можно await
Легко6 мин

  1. async function load() { await later(1, 100); }
  2. function load() { await later(1, 100); }

  4. async function all(items) { await Promise.all(items.map(async (x) => await later(x, 100))); }

Основные задания

4. Цепочка — в async-выражение
Средне12 мин

переписывать цепочки then через выражение async function.

Цепочка: later("5 4 9", 100).then((text) => text.split(" ").map(Number)).then((marks) => Math.max(...marks)).then((max) => console.log("лучшая оценка:", max)).catch((e) => console.log("ошибка:", e.message)).

  • то же через сразу вызванное async-выражение с try...catch: «лучшая оценка: 9»;
  • то же через именованное выражение const best = async function bestMark(text) { … }, имя bestMark снаружи недоступно;
  • с failLater("нет связи", 100) вместо later обе версии печатают «ошибка: нет связи»;
  • записано, почему строка не может начинаться с async function () {.
5. Ответ по умолчанию
Средне13 мин

ловить отказы в async-функции правильно.

loadOr(fn, fallback) — async-функция: вызывает fn() и возвращает её результат, а при любой неудаче — fallback.

  • loadOr(() => later("слова", 100), []) — «слова»;
  • loadOr(() => failLater("нет связи", 100), []) — [];
  • loadOr(() => { throw new Error("сразу"); }, []) — тоже [], без ошибки в консоли;
  • версия с return fn() вместо return await fn() на втором вызове даёт отказ «нет связи» — проверено и объяснено.
6. Дайте таймеру слово
Средне12 мин

видеть, что микрозадачи задерживают задачи.

Функция count(n) — async: считает от 1 до n, и после каждого шага делает await null. Перед её вызовом поставлен setTimeout(() => console.log("таймер"), 0).

  • count(300) печатает «досчитали до 300» раньше, чем «таймер», — объяснено почему;
  • версия, которая каждые 100 шагов делает await wait(0) вместо await null, печатает «таймер» до «досчитали до 300»;
  • записано, после какого шага сработал таймер во второй версии и почему именно тогда.
7. Оценки на сервер
Средне13 мин

выбирать между «по очереди» и «все сразу».

Оценки [{ name: "Аман", ms: 100 }, { name: "Мерет", ms: 300 }, { name: "Сапар", ms: 200 }] отправляются функцией send(item) = later(item.name, item.ms).

  • sendOneByOne на for...of: «Аман, Мерет, Сапар» за 600 мс;
  • sendAll на Promise.all: тот же порядок имён за 300 мс;
  • версия с forEach печатает «отправлено 0» — объяснено, что именно она не дождалась;
  • записано, какую из двух рабочих версий выбрать, если сервер принимает только по одной оценке.

Со звёздочкой

8. Без async
Сложно10 мин

видеть async-функцию как промисы.

Функция: async function greet(name) { console.log(name, "1"); await null; console.log(name, "2"); await null; console.log(name, "3"); }. Вызовы: greet("A"); greet("B");.

Код до первого await — в исполнителе new Promise, каждый следующий кусок — в своём then.
  • порядок записан заранее: A 1, B 1, A 2, B 2, A 3, B 3;
  • версия greetPromise без async и await печатает те же шесть строк в том же порядке;
  • обе функции возвращают промис, выполненный значением undefined.
9. Не больше двух сразу
Сложно10 мин

ограничивать число одновременных задач.

mapLimit(items, limit, fn) выполняет fn для каждого элемента, но одновременно не больше limit штук, и возвращает результаты в порядке элементов.

Запустите limit «работников» — async-функций, каждая в цикле берёт следующий номер элемента, пока они не кончатся, — и дождитесь всех через Promise.all.
  • для четырёх элементов по 100 мс: limit 1 — 400 мс, 2 — 200 мс, 4 — 100 мс;
  • результаты — в порядке элементов, даже если элементы разной длительности (300, 100, 100, 100 мс при limit 2 — 300 мс);
  • одновременно никогда не идёт больше limit вызовов — проверено счётчиком.
