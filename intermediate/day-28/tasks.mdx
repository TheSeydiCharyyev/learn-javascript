# День 28. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания делаем в файлах папки `day-28` курса 2 с Live Server, в Chrome; в начале `app.js` — помощники дня 30 Essentials (`wait`, `later`, `failLater`). ## Разминка

<Task title="1. Порядок вывода" level="easy" time="7">
<Goal>предсказывать порядок синхронного кода, микрозадач и таймеров.</Goal>

```js
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
(async () => {
  console.log(4);
  await null;
  console.log(5);
})();
new Promise((resolve) => {
  console.log(6);
  resolve();
}).then(() => console.log(7));
console.log(8);
```

<Criteria>
- порядок записан до запуска;
- в Chrome: 1, 4, 6, 8, 3, 5, 7, 2 — расхождения разобраны;
- объяснено, почему 6 печатается сразу, а 7 — после 5.
</Criteria>
</Task>

<Task title="2. Что вернёт" level="easy" time="7">
<Goal>знать устройство async-функций.</Goal>

1. `typeof (async () => 1)`
2. `(async () => 1)()` — что за значение и в каком состоянии сразу после вызова
3. `(async () => { throw new Error("x"); })()` — бросит ли вызов ошибку
4. `Object.prototype.toString.call(async function () {})`
5. `"prototype" in async function () {}`
6. `new (async function () {})()`
7. `(async function loadDeck() {}).name`
8. `typeof AsyncFunction`

<Criteria>
- все ответы записаны до проверки, ошибки разобраны;
- для строки 2 объяснено, почему промис уже выполнен, хотя `then` ещё не сработал;
- для строки 3 объяснено, где искать ошибку;
- для строки 8 записано, как всё же достать `AsyncFunction`.
</Criteria>
</Task>

<Task title="3. Где можно await" level="easy" time="6">
<Goal>знать, где `await` разрешён.</Goal>

1. `async function load() { await later(1, 100); }`
2. `function load() { await later(1, 100); }`
3. `async function all(items) { items.forEach((x) => { await later(x, 100); }); }`
4. `async function all(items) { await Promise.all(items.map(async (x) => await later(x, 100))); }`
5. `await later(1, 100);` первой строкой обычного `app.js`
6. то же в `<script type="module">`

<Criteria>
- для каждой строки записано: можно или `SyntaxError`;
- для строк 2, 3 и 5 текст ошибки Chrome совпал с записанным;
- для строки 3 объяснено, почему мало дописать `async` у колбэка.
</Criteria>
</Task>

## Основные задания

<Task title="4. Цепочка — в async-выражение" level="medium" time="12">
<Goal>переписывать цепочки `then` через выражение `async function`.</Goal>

Цепочка: `later("5 4 9", 100).then((text) => text.split(" ").map(Number)).then((marks) =>
Math.max(...marks)).then((max) => console.log("лучшая оценка:", max)).catch((e) => console.log("ошибка:",
e.message))`.

<Criteria>
- то же через сразу вызванное `async`-выражение с `try...catch`: «лучшая оценка: 9»;
- то же через именованное выражение `const best = async function bestMark(text) { … }`, имя
  `bestMark` снаружи недоступно;
- с `failLater("нет связи", 100)` вместо `later` обе версии печатают «ошибка: нет связи»;
- записано, почему строка не может начинаться с `async function () {`.
</Criteria>
</Task>

<Task title="5. Ответ по умолчанию" level="medium" time="13">
<Goal>ловить отказы в async-функции правильно.</Goal>

`loadOr(fn, fallback)` — async-функция: вызывает `fn()` и возвращает её результат, а при
любой неудаче — `fallback`.

<Criteria>
- `loadOr(() => later("слова", 100), [])` — «слова»;
- `loadOr(() => failLater("нет связи", 100), [])` — `[]`;
- `loadOr(() => { throw new Error("сразу"); }, [])` — тоже `[]`, без ошибки в консоли;
- версия с `return fn()` вместо `return await fn()` на втором вызове даёт отказ «нет
  связи» — проверено и объяснено.
</Criteria>
</Task>

<Task title="6. Дайте таймеру слово" level="medium" time="12">
<Goal>видеть, что микрозадачи задерживают задачи.</Goal>

Функция `count(n)` — async: считает от 1 до `n`, и после каждого шага делает
`await null`. Перед её вызовом поставлен `setTimeout(() => console.log("таймер"), 0)`.

<Criteria>
- `count(300)` печатает «досчитали до 300» раньше, чем «таймер», — объяснено почему;
- версия, которая каждые 100 шагов делает `await wait(0)` вместо `await null`, печатает
  «таймер» до «досчитали до 300»;
- записано, после какого шага сработал таймер во второй версии и почему именно тогда.
</Criteria>
</Task>

<Task title="7. Оценки на сервер" level="medium" time="13">
<Goal>выбирать между «по очереди» и «все сразу».</Goal>

Оценки `[{ name: "Аман", ms: 100 }, { name: "Мерет", ms: 300 }, { name: "Сапар", ms: 200 }]`
отправляются функцией `send(item)` = `later(item.name, item.ms)`.

<Criteria>
- `sendOneByOne` на `for...of`: «Аман, Мерет, Сапар» за 600 мс;
- `sendAll` на `Promise.all`: тот же порядок имён за 300 мс;
- версия с `forEach` печатает «отправлено 0» — объяснено, что именно она не дождалась;
- записано, какую из двух рабочих версий выбрать, если сервер принимает только по одной оценке.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Без async" level="hard" time="10">
<Goal>видеть async-функцию как промисы.</Goal>

Функция: `async function greet(name) { console.log(name, "1"); await null; console.log(name, "2"); await
null; console.log(name, "3"); }`. Вызовы: `greet("A"); greet("B");`.

<Hint>
Код до первого `await` — в исполнителе `new Promise`, каждый следующий кусок — в своём
`then`.
</Hint>

<Criteria>
- порядок записан заранее: A 1, B 1, A 2, B 2, A 3, B 3;
- версия `greetPromise` без `async` и `await` печатает те же шесть строк в том
  же порядке;
- обе функции возвращают промис, выполненный значением `undefined`.
</Criteria>
</Task>

<Task title="9. Не больше двух сразу" level="hard" time="10">
<Goal>ограничивать число одновременных задач.</Goal>

`mapLimit(items, limit, fn)` выполняет `fn` для каждого элемента, но одновременно не больше
`limit` штук, и возвращает результаты в порядке элементов.

<Hint>
Запустите `limit` «работников» — async-функций, каждая в цикле берёт следующий номер элемента, пока они не
кончатся, — и дождитесь всех через `Promise.all`.
</Hint>

<Criteria>
- для четырёх элементов по 100 мс: `limit` 1 — 400 мс, 2 — 200 мс, 4 — 100 мс;
- результаты — в порядке элементов, даже если элементы разной длительности (300, 100, 100, 100 мс при
  `limit` 2 — 300 мс);
- одновременно никогда не идёт больше `limit` вызовов — проверено счётчиком.
</Criteria>
</Task>
