# День 30. Модули: import и export

<Subtitle>Выжимка лекции: type="module", формы export и import, живые привязки, отличия от обычного скрипта, порядок выполнения.</Subtitle>

## Главное

```html
<!-- index.html — открывать через Live Server -->
<script type="module" src="main.js"></script>
```

```js
// counter.js
export let count = 0;
export function increment() {
  count++;
}
export default "счётчик";
```

```js
// main.js
import title, { count, increment } from "./counter.js";
import * as counter from "./counter.js";
increment();
console.log(title, count, counter.count);   // счётчик 1 1 — живая привязка
```

## Формы

| Отдать | Принять |
| --- | --- |
| `export const a = 1;`, `export function f() {}` | `import { a, f } from "./m.js"` |
| `export { x as y };` | `import { y as z } from "./m.js"` |
| `export default выражение;` — один на модуль | `import любоеИмя from "./m.js"` |
| всё сразу | `import * as m from "./m.js"` — объект модуля |
| ничего | `import "./m.js"` — только выполнить |
| `export * from "./m.js"`, `export { default as x } from "./m.js"` | пересылка без своих переменных |

<Definition>
**Модуль** — файл со своей областью верхнего уровня: наружу выходит только то, что помечено
`export`. **Живая привязка** — импорт не копирует значение, а смотрит в переменную
модуля-владельца: владелец меняет, импортёр видит; присвоить импорт — `TypeError: Assignment to constant
variable.` Экспорт по умолчанию — для одного значения, которое представляет весь модуль; именованные — когда
значений несколько. `import { x } from` — не деструктуризация объекта по умолчанию.
</Definition>

<KeyPoint>
Путь начинается с `./`, `../` или `/` и кончается `.js`; «голое» имя
работает только с картой импорта `<script type="importmap">`. С адреса `file://` модули не
загрузятся (ошибка CORS) — нужен сервер.
</KeyPoint>

<Remember>
Модуль всегда строгий, `this` на верхнем уровне — `undefined`, его `var` не
попадает в `window`, `await` и `for await` разрешены наверху. Выполняется он один
раз, после разбора страницы. Импорты поднимаются: зависимости выполняются первыми, обходом в глубину. Если
`main.js` импортирует `a.js` и `b.js`, а оба — `c.js`, порядок такой:
`c`, `a`, `b`, `main`. Объект модуля — с прототипом `null`,
запечатан, ключи по алфавиту; записать в него нельзя — `TypeError`.
</Remember>

<NoteBox>
Три этапа (ECMA-262, 16.2): загрузка и разбор (404, CORS, `SyntaxError`), связывание («does not provide an
export named …», «conflicting star exports»), выполнение. Ошибка на первых двух — не выполнится ни один модуль.
`import { … }` не на верхнем уровне модуля — `Unexpected token '{'`, в обычном скрипте —
`Cannot use import statement outside a module`. Цикл, где переменную читают до объявления, —
`ReferenceError`.
</NoteBox>
