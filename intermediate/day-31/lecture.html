1. Обещания, накопленные за курс

День 30 оставил три долга: загрузку модуля по условию (import внутри if давал SyntaxError), сведения о самом модуле — import.meta — и JSON модулем. День 21 записал, что большое число в JSON округляется, а дни 14, 15 и 22 сохраняли Map, Set и даты Temporal обходными путями. День 23 Essentials дал основы: что теряет JSON.stringify, отступы, список полей, reviver. Сегодня — то же изнутри. Начнём с первого долга. В скобках слово import работает как вызов:

// quiz.js
console.log("quiz.js выполняется");
export const questions = ["book", "water", "bread"];
// main.js
const wantQuiz = true;
if (wantQuiz) {
  const quiz = await import("./quiz.js");
  console.log("вопросов:", quiz.questions.length);
}
quiz.js выполняется
вопросов: 3

Это import() — динамический импорт. Справочник подчёркивает: он похож на вызов функции, но import — ключевое слово, а не функция. Модуль грузится, только когда до этой строки дошло выполнение.

2. Практика: модуль по кнопке

Практика плана, по примеру справочника «загрузка в ответ на действие пользователя». Викторина нужна не каждому ученику — пусть её код грузится, только когда нажали кнопку. Нажмём её дважды:

До щелчка браузер даже не запрашивал quiz.js. Первый щелчок загрузил и выполнил модуль, второй взял его из кеша: модуль выполняется один раз (день 30), и справочник подчёркивает, что повторный импорт не делает даже сетевого запроса. await import() отдал объект модуля раздела 8 дня 30 — экспорт по умолчанию в нём лежит под ключом default. Справочник показывает и деструктуризацию: const { default: start, questions } = await import("./quiz.js") — default приходится переименовать, это зарезервированное слово.

3. Что возвращает import()

Всегда промис — того же объекта модуля, что дал бы import * as. Справочник обещает, что import() никогда не бросает синхронно: любая неудача — отклонённый промис. Модуль, упавший при выполнении, запоминается с ошибкой; модуль, который не загрузился, браузер может попробовать загрузить снова:

// broken.js
console.log("broken.js выполняется");
throw new Error("модуль сломан");
// main.js
for (const path of ["./broken.js", "./broken.js", "./missing.js"]) {
  try {
    await import(path);
  } catch (e) {
    console.log(path, "—", e.name, e.message);
  }
}
broken.js выполняется
./broken.js — Error модуль сломан
./broken.js — Error модуль сломан
./missing.js — TypeError Failed to fetch dynamically imported module: http://127.0.0.1:5500/missing.js

broken.js выполнился один раз, а ошибка пришла дважды — вторая из записи модуля, без повторного выполнения. Для missing.js консоль покажет ещё и сетевое сообщение о 404. И предупреждение справочника: не экспортируйте функцию с именем then. Объект модуля с ней станет «thenable» дня 27, и await import() вызовет её вместо того, чтобы отдать сам модуль.

Путь может быть любым выражением, а сам import() работает даже в обычном скрипте без type="module". Пример справочника со строкой-шаблоном и Promise.all дня 27 — языки интерфейса по выбору:

// lang/tk.js
export default { hello: "Salam" };
// classic.js
const code = "tk";
import(`./lang/${code}.js`).then((module) => console.log("обычный скрипт:", module.default.hello));
Promise.all(["ru", "tk"].map((c) => import(`./lang/${c}.js`))).then((modules) => console.log(modules.map((m) => m.default.hello).join(", ")));
обычный скрипт: Salam

Справочник перечисляет, когда нужен import(), и советует брать его, только если без него не обойтись:

Кеш нельзя очистить. Справочник показывает обходной приём — параметр в адресе: import(`./quiz.js?t=${Date.now()}`). Для браузера это другой адрес, а значит, другой модуль: он загрузится и выполнится заново. Но старые модули из памяти уже не уйдут, поэтому в долгоживущей программе так делать не стоит.

5. import.meta

import.meta — объект со сведениями о текущем модуле. Справочник: его создаёт «хозяин», у браузера в нём два свойства — url, полный адрес модуля, и resolve, который превращает путь в адрес так же, как import, но ничего не загружает:

// lib/words.js
export const here = import.meta.url;
export const dataPath = import.meta.resolve("./data/cards.json");
// main.js
import { here, dataPath } from "./lib/words.js";
console.log(import.meta.url);
console.log(here);
console.log(dataPath);
console.log(Object.getPrototypeOf(import.meta), Object.keys(import.meta));
http://127.0.0.1:5500/main.js
http://127.0.0.1:5500/lib/words.js
http://127.0.0.1:5500/lib/data/cards.json
null (2) ['url', 'resolve']

У каждого модуля свой import.meta: путь ./data/cards.json из lib/words.js разрешился относительно lib/. Файла cards.json нет, но resolve это не проверяет — справочник поэтому и называет его синхронным. Прототип null, свойства можно добавлять. Вне модуля import.meta — SyntaxError: Cannot use 'import.meta' outside a module; во встроенном <script type="module"> url — адрес самой страницы. Справочник отмечает: resolve не входит в ECMAScript, его определяет стандарт HTML, а new URL("./x.js", import.meta.url) даёт похожий адрес, но карту импорта не знает.

6. Практика: данные из JSON-модуля

Практика плана. Данные в отдельном файле words.json — комментария в первой строке у него нет, JSON комментариев не знает:

// main.js

with { type: "json" } — атрибут импорта. Справочник объясняет, зачем он: браузер узнаёт тип файла по ответу сервера, а не по расширению. Без атрибута сервер, отдавший «JSON» с типом JavaScript, заставил бы выполнить чужой код. С атрибутом файл обязан прийти как application/json. У JSON-модуля только экспорт по умолчанию — разобранное значение. Это один и тот же массив для всех импортёров, и он не заморожен: изменение увидят все.

7. JSON.parse изнутри

Раздел 25.5.2 начинается с проверки: текст должен точно соответствовать стандарту JSON (ECMA-404), расширять его запрещено. Потом текст выполняется как выражение JavaScript — JSON его подмножество. Два следствия, которые видно сразу:

// main.js
console.log(JSON.parse('{"a": "первое", "a": "второе"}').a);
const fromJSON = JSON.parse('{"__proto__": {"admin": true}}');
const literal = { "__proto__": { admin: true } };
console.log(Object.keys(fromJSON), fromJSON.admin, "|", Object.keys(literal), literal.admin);
второе
(1) ['__proto__'] undefined | (0) [] true

Повтор ключа не ошибка — побеждает последний (примечание 2 раздела). А ключ "__proto__" в литерале объекта меняет прототип (день 7), но в JSON становится обычным собственным свойством: спецификация отключает особое правило для разбора JSON. Чужие данные не подменят прототип. Проверка по ECMA-404 идёт первой, поэтому всё, чего нет в JSON, отвергается, даже если это верный JavaScript: JSON.parse("[1, 2,]") — SyntaxError: Unexpected token ']', хотя [1, 2,] в коде — обычный массив из двух элементов (висячая запятая дня 23 Essentials).

Теперь reviver дня 23 Essentials. Спецификация оборачивает результат в объект { "": значение } и обходит его так: сначала внутренности, потом сам объект; корень с ключом "" — последним:

// main.js
const order = [];
const text = '{"name": "Аман", "marks": [5, 4], "group": {"title": "JS-1"}}';
JSON.parse(text, function (key, value) {
  order.push(key === "" ? '""' : key);
  return value;
});
console.log(order.join(" → "));
name → 0 → 1 → marks → title → group → ""

Когда reviver видит marks, обе оценки уже прошли через него, — поэтому можно «оживлять» снизу вверх. this в нём — объект-хозяин свойства (у стрелочной функции своего this нет, день 2). Вернуть undefined — удалить свойство; в массиве останется дырка дня 11. А в редакции 2026 года у reviver есть и третий аргумент — context. У примитива, которого reviver ещё не трогал, в нём есть source — исходный текст значения:

// main.js
const text = '{"id": 12345678901234567890, "score": 4.50}';
console.log(JSON.parse(text).id);
const exact = JSON.parse(text, (key, value, context) => (key === "id" ? BigInt(context.source) : value));
console.log(exact.id, exact.score);
JSON.parse(text, (key, value, context) => {
  console.log(JSON.stringify(key), JSON.stringify(context));
  return value;
});
12345678901234567000
12345678901234567890n 4.5
"id" {"source":"12345678901234567890"}
"score" {"source":"4.50"}

Это ответ дню 21: число 12345678901234567890 в JSON не помещается в Number и округляется ещё при разборе, а context.source хранит его цифры как текст — BigInt получается точным. У объектов и массивов source нет.

8. JSON.stringify изнутри

Раздел 25.5.4 тоже оборачивает значение в { "": значение }, но обходит его в обратном порядке: сначала объект, потом то, что внутри. И у каждого свойства сначала зовёт toJSON, а уже потом replacer:

// main.js

const calls = [];

  calls.push(key === "" ? '""' : key);
  if (key === "when") console.log("replacer видит:", typeof value, "| в объекте:", this[key] instanceof Date);
  return value;

console.log(calls.join(" → "));

9. JSON.rawJSON и большие числа

Раздел 7 точно прочитал большое число. Записать его обратно помогает JSON.rawJSON(текст) — «сырой JSON»: объект, который stringify вставит в результат дословно. Тот же приём предлагает страница ошибки «BigInt value can't be serialized in JSON» — replacer, который превращает BigInt в сырой JSON:

// main.js
const raw = JSON.rawJSON("12345678901234567890");
console.log(JSON.stringify({ id: raw }), JSON.stringify({ id: 12345678901234567890 }));
console.log(raw.rawJSON, Object.getPrototypeOf(raw), Object.isFrozen(raw), JSON.isRawJSON(raw), JSON.isRawJSON({ rawJSON: "1" }));
const big = { id: 12345678901234567890n };
const text = JSON.stringify(big, (key, value) => (typeof value === "bigint" ? JSON.rawJSON(String(value)) : value));
const back = JSON.parse(text, (key, value, context) => (key === "id" ? BigInt(context.source) : value));
console.log(text, back.id === big.id);
try {
  JSON.rawJSON("[1, 2]");
} catch (e) {
  console.log(e.name, e.message);
}
{"id":12345678901234567890} {"id":12345678901234567000}
12345678901234567890 null true true false
{"id":12345678901234567890} true

Круг замкнулся без потерь: BigInt → сырой JSON → текст → context.source → BigInt. Справочник объясняет устройство: прототип null, объект заморожен, у него одно свойство rawJSON и внутренняя метка. По метке его и узнаёт JSON.isRawJSON, поэтому подделка с таким же свойством — false. Сырым бывает только примитив: строка в кавычках, число, true, false, null. Объекты и массивы — SyntaxError, пробел по краям — тоже.

10. Практика: Map и даты Temporal в JSON

Практика плана. Map в JSON становится пустым объектом: собственных перечисляемых свойств у неё нет. Дата Temporal — строкой через свой toJSON (день 22), и обратно её не узнать. Модуль storage.js записывает их помеченными объектами и оживляет при разборе:

// storage.js
export function save(data) {
  return JSON.stringify(data, function (key, value) {
    const original = this[key];
    if (original instanceof Map) return { $map: [...original] };
    if (original instanceof Temporal.PlainDate) return { $date: value };
    return value;
  });
}
export function load(text) {
  return JSON.parse(text, (key, value) => {
    if (value !== null && typeof value === "object" && "$map" in value) return new Map(value.$map);
    if (value !== null && typeof value === "object" && "$date" in value) return Temporal.PlainDate.from(value.$date);
    return value;
  });
}
// main.js
import { save, load } from "./storage.js";
const journal = {
  group: "JS-1",
  lastLesson: new Map([
    ["Аман", Temporal.PlainDate.from("2026-10-23")],
    ["Мерет", Temporal.PlainDate.from("2026-10-26")],
  ]),
};
console.log(JSON.stringify(journal));
const text = save(journal);
console.log(text);
const back = load(text);
console.log(back.lastLesson instanceof Map, back.lastLesson.get("Мерет").dayOfWeek, back.lastLesson.get("Аман").until(back.lastLesson.get("Мерет")).toString());
{"group":"JS-1","lastLesson":{}}
{"group":"JS-1","lastLesson":{"$map":[["Аман",{"$date":"2026-10-23"}],["Мерет",{"$date":"2026-10-26"}]]}}
true 1 P3D

Здесь работают оба порядка разделов 7–8. replacer — обычная функция, а не стрелка, чтобы this[key] дал хозяина: value даты уже стал строкой. Reviver идёт снизу вверх, поэтому к моменту, когда он видит $map, даты внутри уже оживлены, и new Map получает настоящие PlainDate. Метки $map и $date — договор, как $bigint дня 21: обычные данные с такими ключами разбор примет за свои.

12. Что говорит спецификация

Подробно — JSON.parse и JSON.stringify; оба алгоритма разобраны в разделах 7–8, здесь — шаги одной строкой каждый.

  • 25.5.2 JSON.parse: ToString(text) — отсюда «"undefined" is not valid JSON» дня 23 Essentials; ParseJSON (25.5.2.1) — проверка по ECMA-404 и выполнение как выражения; если reviver — функция, корень кладётся в объект под ключом "", CreateJSONParseRecord (25.5.2.3) запоминает исходный текст каждого значения, InternalizeJSONProperty (25.5.2.4) идёт рекурсией: сначала свойства, потом Call(reviver, holder, «name, val, context»); undefined — удалить, иначе CreateDataProperty. context.source дают, только если значение — примитив и всё ещё то же (SameValue), что разобрано.
  • 25.5.4 JSON.stringify: replacer-функция или список (строки и числа, повторы отброшены); space — min(10, число) пробелов или первые 10 символов строки; корень в обёртке; JSON Serialization Record (таблица 76) с полем [[Stack]] для поиска циклов; SerializeJSONProperty (25.5.4.2) — схема раздела 8; QuoteJSONString (25.5.4.3) экранирует кавычку, обратную черту, управляющие символы и одинокие половинки пар.
  • Кратко: 25.5 — объект JSON обычный, ни конструктор, ни функция, формат — ровно ECMA-404 без расширений; 25.5.1 isRawJSON — проверка внутреннего слота [[IsRawJSON]]; 25.5.3 rawJSON — пустая строка и неподходящий первый или последний символ сразу SyntaxError, затем ParseJSON, объект с прототипом null заморожен (SetIntegrityLevel дня 6); 25.5.5 — [object JSON].
  • 13.3.10 Import Calls: EvaluateImportCall (13.3.10.2) сразу создаёт промис, и каждая неудача — неверный второй аргумент, атрибут не строкой, неизвестный ключ (16.2.1.12), ошибка ToString пути — отклоняет его (IfAbruptRejectPromise дня 29). Поэтому import() не бросает.
  • 13.3.12 Meta Properties: import.meta создаётся при первом обращении — объект без прототипа, свойства даёт хозяин (HostGetImportMetaProperties, 13.3.12.1.1; по умолчанию — ни одного), — и запоминается в записи модуля.
  • 16.2.1.8.2 ParseJSONModule: JSON-модуль — синтетическая запись модуля с одним экспортом по умолчанию — значением ParseJSON. Спецификация требует от хозяина поддержать type: "json"; "text" в тексте 2026 года нет.

  1. Чем import("./m.js") отличается от import * as m from "./m.js"?
    Ответ Статический импорт грузит модуль при открытии страницы и только на верхнем уровне модуля. import() — выражение: грузит, когда до него дошло выполнение, путь может вычисляться, работает и в обычном скрипте, возвращает промис того же объекта модуля.
  2. Почему без with { type: "json" } JSON-файл не импортируется?
    Ответ Браузер по умолчанию ждёт JavaScript и проверяет тип ответа сервера. Атрибут говорит: здесь JSON — и файл обязан прийти как application/json, так что выполнить чужой код под видом данных нельзя.
  3. В каком порядке reviver видит ключи {"a": {"b": 1}}?
    Ответ b, a, "": снизу вверх, корень последним (InternalizeJSONProperty).
  4. Replacer получил дату строкой. Как узнать, что это была дата?
    Ответ Посмотреть this[key]: this — объект-хозяин, в нём лежит исходная дата. toJSON сработал раньше replacer. Replacer должен быть обычной функцией.
  5. Как прочитать и записать число 12345678901234567890 из JSON без потерь?
    Ответ Читать — reviver с BigInt(context.source), записывать — replacer, который превращает BigInt в JSON.rawJSON(String(value)).
