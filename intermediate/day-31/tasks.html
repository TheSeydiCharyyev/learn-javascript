2. Порядок обхода
Легко7 мин

знать, в каком порядке работают reviver и replacer.

// main.js
const text = '{"a": [1, {"b": 2}], "c": 3}';
const reviverKeys = [];
const data = JSON.parse(text, function (key, value) {
  reviverKeys.push(key === "" ? '""' : key);
  return value;
});
const replacerKeys = [];
JSON.stringify(data, function (key, value) {
  replacerKeys.push(key === "" ? '""' : key);
  return value;
});
console.log(reviverKeys.join(" "));
console.log(replacerKeys.join(" "));
  • обе строки записаны до запуска;
  • в Chrome: 0 b 1 a c "" и "" a 0 1 b c — расхождения разобраны;
  • нарисовано дерево данных, и на нём проставлены оба порядка, как на схеме раздела 12 лекции.

Основные задания

4. Язык по выбору
Средне12 мин

загружать модули по вычисленному пути.

В папке lang — ru.js, tk.js, en.js: каждый первой строкой печатает своё имя и экспортирует по умолчанию { hello: … } («Привет», «Salam», «Hello»). loadLang(code) — async-функция: загружает ./lang/${code}.js, а если такого нет — печатает «нет языка код» и загружает ru.

  • (await loadLang("tk")).hello — «Salam»;
  • loadLang("de") печатает «нет языка de» и отдаёт «Привет»;
  • после трёх вызовов loadLang("tk") строка tk.js напечатана один раз;
  • Promise.all по ["ru", "tk", "en"] — «Привет, Salam, Hello».
5. Журнал из JSON
Средне13 мин

брать данные из JSON-модуля и помнить, что он общий.

[
  { "name": "Аман", "marks": [5, 4, 5] },
  { "name": "Мерет", "marks": [3, 4, 4] },
  { "name": "Айна", "marks": [5, 5, 5] }
]

Модуль report.js импортирует students.json и экспортирует report() — строки «имя: средний» с двумя знаками. Модуль bonus.js импортирует тот же JSON и всем добавляет оценку 5.

  • без bonus.js: «Аман: 4.67», «Мерет: 3.67», «Айна: 5.00»;
  • если main.js импортирует bonus.js, отчёт меняется: «Аман: 4.75», «Мерет: 4.00», «Айна: 5.00» — объяснено почему;
  • bonus.js переписан так, что работает с копией (JSON.parse(JSON.stringify(…)) дня 23 Essentials), и отчёт снова как в первом пункте;
  • без with { type: "json" } записан текст ошибки Chrome.
6. Точные номера
Средне12 мин

читать и писать большие числа JSON без потерь.

С сервера приходит '[{"id":9007199254740993,"score":4.5},{"id":18014398509481985,"score":5}]'.

  • обычный JSON.parse даёт id 9007199254740992 и 18014398509481984 — проверено;
  • parseExact(text) с reviver и context.source отдаёт BigInt 9007199254740993n и 18014398509481985n, а score — обычные числа;
  • stringifyExact(data) с JSON.rawJSON возвращает строку, равную исходной;
  • записано, почему reviver не может взять source у самого массива.
7. Set и длительности

Со звёздочкой

8. Свой обход для reviver
Сложно10 мин

повторить InternalizeJSONProperty.

revive(value, reviver) принимает уже разобранные данные и обходит их, как JSON.parse: оборачивает в { "": value }, рекурсией идёт по свойствам и элементам, потом зовёт reviver.call(holder, key, value); undefined удаляет свойство.

  • на тексте задания 2 порядок ключей совпадает с JSON.parse: 0 b 1 a c "";
  • reviver, удаляющий все числа 2, даёт тот же результат, что и в JSON.parse: {"a":[1,{}],"c":3};
  • this в reviver — объект-хозяин, проверено для ключа b;
  • записано, чего ваш обход не умеет по сравнению с настоящим (context).
9. Уроки по номеру
Сложно10 мин

сочетать import() и import.meta.

В папке lessons — 1.js и 2.js, одинаковые по коду: модуль печатает «урок N загружен» и экспортирует number, который вычисляет из import.meta.url — из имени своего же файла. open(n) загружает ./lessons/${n}.js и печатает «урок N»; если файла нет — «урока N нет».

  • open(1), open(2), open(1), open(5) печатают: «урок 1 загружен», «урок 1», «урок 2 загружен», «урок 2», «урок 1», «урока 5 нет»;
  • код 1.js и 2.js одинаковый — номер берётся только из адреса;
  • import.meta.resolve("./lessons/5.js") не бросает ошибку, хотя файла нет, — объяснено.
