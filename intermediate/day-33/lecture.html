2. Идея: как выбрать

Четыре условия хорошей идеи — из дня 33 Essentials: есть список данных, человек с ними что-то делает, что-то запоминается между загрузками, вам самим интересно. Курс 2 добавляет пятое — в идее есть место курсу 2. Классы, модули и асинхронная загрузка найдутся в любом приложении с данными в файлах, а Map/Set, регулярные выражения или Temporal/Intl зависят от идеи:

ИдеяДанныеЧто делает человекЧто из курса 2 просится
карточки словколоды по темампереворачивает, отмечает выученноеMap прогресса, даты повтора на Temporal

справочникрастения, животные, страныищет, фильтруетрегулярные выражения, Map по номеру

Можно и переписать свой проект Essentials инструментами курса 2, как лекция делает с «Карточками». Слишком маленькая идея узнаётся по-прежнему — нет ни поиска, ни выбора, ни памяти — и по новому признаку: ей не нужны модули. «Часы с поясами трёх городов» — упражнение на тему дня 24; со списком городов в JSON и избранным выйдет проект.

3. Замысел одним предложением

Замысел снова проверяют одним предложением: кому, что, зачем.

«Карточки 2.0» — для ученика, который учит английский: слова разложены по колодам-темам, колода приходит с сервера, когда её выбрали; по щелчку карточка показывает перевод; «Знаю» откладывает слово на несколько дней, и чем лучше оно выучено, тем дольше пауза; «Повторить» оставляет его на сегодня; прогресс не пропадает после обновления страницы.

В Essentials выученное слово уходило навсегда, здесь оно возвращается после паузы — и появились даты, правило паузы и хранилище для дат. Остальное так же становится планом: «колода приходит, когда её выбрали» — это import() по кнопке (день 31), «чем лучше выучено, тем дольше пауза» — правило «Карточек» дня 22, шаг удваивается. Классов и модулей в предложении нет: ученик их не видит, это устройство кода.

Потом, если останется время: поиск по слову с RegExp.escape (день 19), режим «перевод → слово», подписи на английском через Intl (день 25). В Essentials данные проверяли в консоли. С модулями так не выйдет: консоль не видит переменных модуля (день 30), а набранное руками пропадает при каждом обновлении. Поэтому проверки сразу пишут файлом — страницей проверок, второй страницей проекта:

Шаг 2. Три ошибки — три симптома. Колода без файла — щелчок по «городу» даст ошибку загрузки. translaton с опечаткой — у apple нет перевода, и перевёрнутая карточка будет пустой. Шаг 3. Чиним — и ставим сторожей. В Essentials сторожем была функция checkData. В курсе 2 сторож — конструктор класса: объект с неверными данными не создаётся, как оценка 7 в журнале дня 16. Ошибка — свой класс (день 26), карточка — класс с приватными полями (день 9). Number.isInteger (день 17 Essentials) не пропустит ни undefined, ни строку "6":

// errors.js
export class CardsError extends Error {
  constructor(message, options) {
    super(message, options);
    this.name = "CardsError";
  }
}
// card.js
import { CardsError } from "./errors.js";

export class Card {
  #id;
  #word;
  #translation;

  constructor({ id, word, translation }) {
    if (!Number.isInteger(id)) throw new CardsError(`у карточки «${word}» нет номера`);
    if (!word || !translation) throw new CardsError(`у карточки ${id} нет слова или перевода`);
    this.#id = id;
    this.#word = word;
    this.#translation = translation;
  }

  get id() {
    return this.#id;
  }

  get word() {
    return this.#word;
  }

  get translation() {
    return this.#translation;
  }
}

Но сторож в классе видит только то, что ему дали. Card поймает опечатку в поле, колода из раздела 10 — повтор номера в своём файле, а повтор между файлами не увидит никто: колоды грузятся порознь. Его ловит только страница проверок. Сторожей два: класс — на каждой загрузке, страница проверок — после каждой правки файлов. Возвращаем DIR, временные строки удаляем:

Map и даты JSON хранить не умеет, поэтому в хранилище их кладёт storage.js дня 31 — копируем его в папку без изменений. Начало main.js — все решения таблицы в переменных:

Заглушка в Essentials возвращала значение того же типа. У модуля есть второе условие — то же имя экспорта. Вот load.js, где забыли export:

// load.js — заглушка без export
import { Deck } from "./deck.js";

async function loadDeck(info, progress) {
  return new Deck([], progress);
}
Uncaught SyntaxError: The requested module './load.js' does not provide an export named 'loadDeck'

Это ошибка связывания (день 30): браузер не выполняет ни одного модуля графа — ни main.js, ни console.assert раздела 9, — и «Загрузка…» висит. Неверный тип ломает одно место, пропавший экспорт — всю страницу.

Загрузка почти слово в слово повторяет loadGroup дня 32: любой отказ — нет файла, неверный JSON, сторож Card или Deck — становится CardsError с причиной:

// load.js
import { Card } from "./card.js";
import { Deck } from "./deck.js";
import { CardsError } from "./errors.js";

// колода из data/<id>.json; ошибку загрузки заворачивает в CardsError с причиной
export async function loadDeck(info, progress) {
  try {
    const { default: list } = await import(`./data/${info.id}.json`, { with: { type: "json" } });
    return new Deck(list.map((item) => new Card(item)), progress);
  } catch (cause) {
    throw new CardsError(`Не удалось загрузить колоду «${info.name}»`, { cause });
  }
}

render пока минимальный — первая карточка на сегодня и счётчик:

// main.js: настоящие render и openDeck
function render() {
  const deck = opened.get(chosen);
  const cards = deck.due(today);
  card.textContent = cards.length > 0 ? cards[0].word : "На сегодня всё";
  counter.textContent = `На сегодня: ${cards.length} из ${deck.size}`;
}

async function openDeck() {
  try {
    if (!opened.has(chosen)) opened.set(chosen, await loadDeck(decks.find((d) => d.id === chosen), progress));
  } catch (err) {
    error.textContent = `${err.message}: ${err.cause.message}`;
  }
  loading.hidden = true;
  if (opened.has(chosen)) render();
}

В try — только загрузка, её ошибки всегда CardsError с cause. render стоит после try: его ошибка — ошибка программы, и пусть её будет видно в консоли. Открытую колоду второй раз не грузим — её отдаёт opened. Проверка шага — по разметке, её консоль видит:

Разбор: путь import() считается от модуля

Модули переложили в папку js, данные остались в data. Пути в index.html и main.js поправили — иначе страница не запустилась бы, — а load.js забыли:

// js/load.js — модули в папке js, данные в data
const { default: list } = await import(`./data/${info.id}.json`, { with: { type: "json" } });

Страница пишет: Не удалось загрузить колоду «школа»: Failed to fetch dynamically imported module: http://127.0.0.1:5500/js/data/school.json. Путь import() считается от адреса модуля (день 31, раздел 5), а fetch в Essentials — от страницы, поэтому с ним такого не было. Лечение — ../data/, а адрес в сообщении — заслуга CardsError с причиной.

  1. Что курс 2 добавляет к четырём условиям хорошей идеи?
    Ответ Место для курса 2: классы, модули, асинхронную загрузку и хотя бы одно из Map/Set, регулярных выражений, Temporal/Intl. Если программе не нужны модули, идея слишком мала.
  2. Почему проверки в курсе 2 пишут на отдельной странице, а не в консоли?
    Ответ Консоль не видит переменных модулей, а набранное руками пропадает при обновлении. Страница проверок перезапускается сама и берёт классы без main.js.
  3. Какую ошибку данных поймает конструктор Card, а какую — только страница проверок?
    Ответ Card поймает опечатку в поле и номер-строку: она видит одну карточку. Повтор номера в двух файлах видит только проверка всех данных сразу.
  4. Чем заглушка модуля без export хуже заглушки, которая возвращает не тот тип?
    Ответ Это ошибка связывания: не выполняется ни один модуль, страница висит на «Загрузке…». Неверный тип ломает только место, где значением пользуются.
  5. Почему import(`./data/…`) из js/load.js ищет файл в js/data/?
    Ответ Путь import() считается от адреса модуля, а модуль лежит в js/. fetch считает путь от страницы.
  6. Чем плоха задача «сделать на классах»?
    Ответ Её нельзя закрыть: это способ, а не результат. Задачу записывают поведением и проверкой: «Deck.due: проверки tests.js молчат».
