## 1. Четыре дня итогового проекта {#why}

Темы курса закончились на дне 31, мини-проекты дней 16 и 32 позади. За четыре оставшихся дня каждый соберёт
своё приложение — от идеи до защиты, тем же путём, что в итоговом проекте Essentials. Меняются инструменты: у
приложения теперь классы, модули и данные в нескольких файлах.

| День | Что делаем | Что готово в конце |
| --- | --- | --- |
| 33 | замысел, данные, макет, каркас из модулей, план | страница показывает первую карточку, страница проверок молчит |
| 34 | реализация по плану | все возможности из таблицы работают |
| 35 | доработка, проверка на телефоне, чтение чужого кода | приложение, которое не стыдно показать |
| 36 | защита: показ и разбор решений | вы объясняете любую строку своего кода |

На защите смотрят то же, что в Essentials: обещанное работает, данные живут в данных, код читается, автор
понимает решения и сам называет, что не успел. Новая строка одна — **курс 2 в коде**: классы, модули,
асинхронная загрузка и хотя бы одно из `Map`/`Set`, регулярных выражений,
`Temporal`/`Intl`. Автор показывает, где каждое.

Пример лекции — знакомый. Essentials закончился на дне 36 таблицей «Чего в «Карточках» нет». Вот она, а справа —
где курс 2 примерял каждую строку к «Карточкам»:

| Хочется | Чего не хватало | Где в курсе 2 |
| --- | --- | --- |
| быстро находить слово по номеру | `Map` | день 14, «номера, темы, попытки» |
| быстрая колода на тысячах слов | `Set` | день 15, «выученное как множество» |
| разнести `app.js` по файлам | `import` / `export` | день 30, «Карточки» на модулях |
| искать слова по шаблону | регулярные выражения | день 17, «поиск и проверка слова» |
| карточка как объект со своим поведением | классы | день 8, «класс Card» |

Пройдены все пять строк, а ещё даты повтора (дни 21–22) и колода из JSON (день 31). Но каждый раз это был кусок,
приложенный к теме дня. Сегодня соберём из кусков одно приложение — **«Карточки 2.0»** — по плану, с
пустой папки. На днях 34–35 пример растёт дальше как образец, а вы строите своё. Шаги дня — те же семь, что на дне
33 Essentials, и код снова появляется только на шестом.

## 2. Идея: как выбрать {#idea}

Четыре условия хорошей идеи — из дня 33 Essentials: есть список данных, человек с ними что-то делает, что-то
запоминается между загрузками, вам самим интересно. Курс 2 добавляет пятое — **в идее есть место курсу
2**. Классы, модули и асинхронная загрузка найдутся в любом приложении с данными в файлах, а
`Map`/`Set`, регулярные выражения или `Temporal`/`Intl` зависят от
идеи:

| Идея | Данные | Что делает человек | Что из курса 2 просится |
| --- | --- | --- | --- |
| карточки слов | колоды по темам | переворачивает, отмечает выученное | `Map` прогресса, даты повтора на `Temporal` |
| меню кафе | блюда и цены | ищет, собирает заказ | поиск регулярным выражением, суммы через `Intl.NumberFormat` |
| афиша | события и даты | фильтрует по дню, отмечает «пойду» | `Temporal`, `Intl.DateTimeFormat`, `Set` отметок |
| викторина | вопросы по темам | отвечает на время | `Temporal.Duration`, тема через `import()` по выбору |
| справочник | растения, животные, страны | ищет, фильтрует | регулярные выражения, `Map` по номеру |
| трекер привычек | свои привычки | отмечает дни | `Temporal.PlainDate`, `Set` отмеченных дней |

Можно и переписать свой проект Essentials инструментами курса 2, как лекция делает с «Карточками». Слишком
маленькая идея узнаётся по-прежнему — нет ни поиска, ни выбора, ни памяти — и по новому признаку: **ей не
нужны модули**. «Часы с поясами трёх городов» — упражнение на тему дня 24; со списком городов в JSON и
избранным выйдет проект.

## 3. Замысел одним предложением {#sentence}

Замысел снова проверяют одним предложением: **кому**, **что**, **зачем**.

<Important>
«Карточки 2.0» — для ученика, который учит английский: слова разложены по колодам-темам, колода приходит с
сервера, когда её выбрали; по щелчку карточка показывает перевод; «Знаю» откладывает слово на несколько дней, и
чем лучше оно выучено, тем дольше пауза; «Повторить» оставляет его на сегодня; прогресс не пропадает после
обновления страницы.
</Important>

В Essentials выученное слово уходило навсегда, здесь оно возвращается после паузы — и появились даты, правило
паузы и хранилище для дат. Остальное так же становится планом: «колода приходит, когда её выбрали» — это
`import()` по кнопке (день 31), «чем лучше выучено, тем дольше пауза» — правило «Карточек» дня 22, шаг
удваивается. Классов и модулей в предложении нет: ученик их не видит, это устройство кода.

## 4. Что должно уметь приложение {#spec}

Возможности — таблицей, у каждой строки проверка для человека, не видевшего код. Новый столбец показывает, какая
тема курса отвечает за строку:

| № | Возможность | Как проверить | Из курса 2 |
| --- | --- | --- | --- |
| 1 | загрузить колоду | «Загрузка…», затем первая карточка колоды «школа» | JSON-модуль, `import()` (31) |
| 2 | сообщить об ошибке загрузки | файл колоды переименован — название колоды и причина | свой класс ошибки, `cause` (26) |
| 3 | перевернуть карточку | щелчок — перевод, ещё щелчок — слово | — |
| 4 | «Знаю» | карточка уходит до дня повтора: через 2 дня, потом 4, потом 8 | `Temporal.PlainDate` (22), `Map` (14) |
| 5 | «Повторить» | следующая карточка; эта вернётся в конце круга | — |
| 6 | выбрать колоду | кнопки из списка колод; файл колоды запрашивается один раз | `import()` по кнопке (31), `Map` открытых колод |
| 7 | счётчик «На сегодня: N из M» | меняется после каждого «Знаю» | — |
| 8 | помнить прогресс | обновили страницу — отложенных нет; «сегодня» стало 28 октября — вернулись | `storage.js`: `Map` и даты в JSON (31) |
| 9 | начать сначала | все карточки снова на сегодня | — |

Классы `Card` и `Deck` и модули стоят не в одной строке, а под всеми. Прочерк справа —
тоже честный ответ. **Потом, если останется время:** поиск по слову с `RegExp.escape`
(день 19), режим «перевод → слово», подписи на английском через `Intl` (день 25). **Не делает
совсем:** не добавляет слова, не произносит их (Web Speech — курс 4), не переносит прогресс на другое
устройство — для этого нужен свой сервер.

## 6. Страница проверок {#check-data}

В Essentials данные проверяли в консоли. С модулями так не выйдет: консоль не видит переменных модуля (день 30),
а набранное руками пропадает при каждом обновлении. Поэтому проверки сразу пишут файлом — **страницей
проверок**, второй страницей проекта:

```html file="test.html"
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Проверки «Карточек 2.0»</title>
  <script type="module" src="tests.js"></script>
</head>
<body>
  <p>Проверки идут в консоли (F12).</p>
</body>
</html>
```

Её держат открытой в соседней вкладке, `http://127.0.0.1:5500/test.html`. Live Server обновляет и её,
так что проверки перезапускаются при каждом сохранении. Первые проверки — данных:

```js page="test.html"
// tests.js
const DIR = "./data";

async function readDecks(dir) {
  const { default: decks } = await import(`${dir}/decks.json`, { with: { type: "json" } });
  const files = await Promise.all(decks.map((deck) => import(`${dir}/${deck.id}.json`, { with: { type: "json" } })));
  return decks.map((deck, i) => ({ ...deck, cards: files[i].default }));
}

const all = await readDecks(DIR);
const cards = all.flatMap((deck) => deck.cards);
console.log(all.map((deck) => `${deck.name}: ${deck.cards.length}`).join(", "));   // для глаз, потом удалить
console.assert(cards.every((c) => Number.isInteger(c.id) && c.word && c.translation), "у карточки не хватает поля");
console.assert(new Set(cards.map((c) => c.id)).size === cards.length, "номера повторяются");
```

<ResultBox>
школа: 3, еда: 3, дом: 2
</ResultBox>

`readDecks` читает список, потом все файлы колод разом — `Promise.all` (день 27) над
`import()` с `with` (день 31). `console.assert` из дня 2 Essentials молчит, если
условие верно. Вторая проверка короче, чем в Essentials: номеров в `Set` (день 15) столько же, сколько
карточек, только если повторов нет.

`tests.js` одну строку:

```js page="test.html"

```

**Шаг 1. Что не так?** Первая ошибка нашлась раньше проверок: файла для колоды «город» нет, и
`Promise.all` отклонился на первом же отказе (день 27). Уберём «город» из списка:

```js file="data-bad/decks.json"
[
  { "id": "school", "name": "школа" },
  { "id": "food", "name": "еда" },
  { "id": "home", "name": "дом" }
]
```

Теперь срабатывают проверки. Какие карточки виноваты, подскажут две временные строки. Повтор — это номер с двумя
карточками, а собрать карточки по номеру умеет `Map.groupBy` (день 14):

```js page="test.html"
// в конец tests.js — на время разбора
console.log("без перевода:", cards.filter((c) => !c.translation).map((c) => c.word).join(", "));
const twins = [...Map.groupBy(cards, (c) => c.id)].filter(([, list]) => list.length > 1);
console.log("повторы:", twins.map(([id, list]) => `${id} — ${list.map((c) => c.word).join(" и ")}`).join(", "));
```

<ResultBox>
школа: 3, еда: 3, дом: 2\
Assertion failed: у карточки не хватает поля\
Assertion failed: номера повторяются\
без перевода: apple\
повторы: 3 — lesson и water

**Шаг 2. Три ошибки — три симптома.** Колода без файла — щелчок по «городу» даст ошибку загрузки.
`translaton` с опечаткой — у apple нет перевода, и перевёрнутая карточка будет пустой. Номер 3 у water
совпал с lesson из другого файла. Прогресс общий и знает только номер, поэтому «Знаю» у lesson в колоде «школа»
отложит и water в колоде «еда»: ученик её ещё не видел, а она пропала.

**Шаг 3. Чиним — и ставим сторожей.** В Essentials сторожем была функция `checkData`. В
курсе 2 сторож — конструктор класса: объект с неверными данными не создаётся, как оценка 7 в журнале дня 16. Ошибка
— свой класс (день 26), карточка — класс с приватными полями (день 9). `Number.isInteger` (день 17
Essentials) не пропустит ни `undefined`, ни строку `"6"`:

```js
// errors.js
export class CardsError extends Error {
  constructor(message, options) {
    super(message, options);
    this.name = "CardsError";
  }
}
```

```js
// card.js
import { CardsError } from "./errors.js";

export class Card {
  #id;
  #word;
  #translation;

  constructor({ id, word, translation }) {
    if (!Number.isInteger(id)) throw new CardsError(`у карточки «${word}» нет номера`);
    if (!word || !translation) throw new CardsError(`у карточки ${id} нет слова или перевода`);
    this.#id = id;
    this.#word = word;
    this.#translation = translation;
  }

  get id() {
    return this.#id;
  }

  get word() {
    return this.#word;
  }

  get translation() {
    return this.#translation;
  }
}
```

Но сторож в классе видит только то, что ему дали. `Card` поймает опечатку в поле, колода из раздела
10 — повтор номера в своём файле, а повтор *между* файлами не увидит никто: колоды грузятся порознь. Его
ловит только страница проверок. Сторожей два: класс — на каждой загрузке, страница проверок — после каждой правки
файлов. Возвращаем `DIR`, временные строки удаляем:

```js
// tests.js: замена строки
const DIR = "./data";
```

## 8. Где что живёт {#state}

| Данные | Где | Почему |
| --- | --- | --- |
| список колод | сервер: `data/decks.json`, `import` наверху | нужен сразу, он маленький |
| карточки колоды | сервер: файл колоды, `import()` при выборе | грузим только то, что выбрали |
| прогресс: номер → день повтора и шаг | `localStorage` через `storage.js` | личный, нужен и завтра; в нём `Map` и даты |
| открытые колоды | `Map` в `main.js` | второй выбор той же колоды — без запроса |
| сегодня, выбранная колода, карточка на экране, перевёрнута ли | переменные `main.js` | нужны только сейчас |

Прогресс хранит не «выучено», а день следующего повтора и шаг — по правилу дня 22: «Знаю» откладывает карточку
на шаг × 2 дней, и шаг удваивается. `Map` и даты JSON хранить не умеет, поэтому в хранилище их кладёт
`storage.js` дня 31 — копируем его в папку без изменений. Начало `main.js` — все решения
таблицы в переменных:

```js
// main.js
import decks from "./data/decks.json" with { type: "json" };
import { save, load } from "./storage.js";

const KEY = "cards2:progress";
const today = Temporal.PlainDate.from("2026-10-26");            // учебное «сегодня»; в жизни — Temporal.Now.plainDateISO()
const progress = load(localStorage.getItem(KEY)) ?? new Map();  // номер карточки → { next, step }, на все колоды
const opened = new Map();                                        // id колоды → Deck: каждая грузится один раз
let chosen = decks[0].id;                                        // id выбранной колоды
let position = 0;                                                // какая карточка колоды на экране
let flipped = false;                                             // виден ли перевод
console.log(decks.length, progress.size, opened.size, chosen);   // проверка шага, потом удалить
```

<ResultBox>
3 0 0 school
</ResultBox>

При первом открытии `getItem` вернёт `null`, и `JSON.parse(null)` — тоже
`null`; отсюда `?? new Map()`, как `?? []` в Essentials. «Сегодня» зафиксировано,
как «сейчас» в расписании дня 32. `save`, `position` и `flipped` понадобятся
завтра, но объявлены сейчас: так видно, что замысел целиком помещается в данные.

## 9. Макет и рама страницы {#mockup}

Макет — узкий, как экран телефона, с подписями: из каких данных и методов строится каждая часть:

<Scheme src="scheme-mockup.svg">Макет: у каждой части страницы подписаны данные и методы, из которых её строит код</Scheme>

В подписях появились методы — `due`, `know`, `size`: макет заодно сочиняет
класс `Deck` раньше, чем он написан. По макету — рама без данных:

```html file="index.html"

<head>
```

```js
export async function loadDeck(info, progress) {
```

```js
    const { default: list } = await import(`./data/${info.id}.json`, { with: { type: "json" } });
    return new Deck(list.map((item) => new Card(item)), progress);
  } catch (cause) {

}
```

```js
// main.js: настоящие render и openDeck

async function openDeck() {
  try {

}
```

<Selfcheck>
1. Что курс 2 добавляет к четырём условиям хорошей идеи?
   <Answer>Место для курса 2: классы, модули, асинхронную загрузку и хотя бы одно из `Map`/`Set`,
   регулярных выражений, `Temporal`/`Intl`. Если программе не нужны модули, идея
   слишком мала.</Answer>
2. Почему проверки в курсе 2 пишут на отдельной странице, а не в консоли?
   <Answer>Консоль не видит переменных модулей, а набранное руками пропадает при обновлении. Страница проверок
   перезапускается сама и берёт классы без `main.js`.</Answer>
3. Какую ошибку данных поймает конструктор `Card`, а какую — только страница проверок?
   <Answer>`Card` поймает опечатку в поле и номер-строку: она видит одну карточку. Повтор номера в двух
   файлах видит только проверка всех данных сразу.</Answer>
4. Чем заглушка модуля без `export` хуже заглушки, которая возвращает не тот тип?
   <Answer>Это ошибка связывания: не выполняется ни один модуль, страница висит на «Загрузке…». Неверный тип
   ломает только место, где значением пользуются.</Answer>
5. Почему ``import(`./data/…`)`` из `js/load.js` ищет файл в `js/data/`?
   <Answer>Путь `import()` считается от адреса модуля, а модуль лежит в `js/`.
   `fetch` считает путь от страницы.</Answer>
6. Чем плоха задача «сделать на классах»?
   <Answer>Её нельзя закрыть: это способ, а не результат. Задачу записывают поведением и проверкой:
   «`Deck.due`: проверки `tests.js` молчат».</Answer>
