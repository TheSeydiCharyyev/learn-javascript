# День 33. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Сегодня каждый планирует **свой** итоговый проект по шагам лекции. Задание 3 — на примере «Карточек 2.0» (папка `day-33/cards`), остальные — в папке вашего проекта (`day-33/project`), через Live Server. Записи ведите в `plan.md` рядом с кодом: на дне 36 он понадобится на защите.</Subtitle>

## Разминка

<Task title="1. Идея одним предложением" level="easy" time="6">
<Goal>выбрать идею, в которой есть место курсу 2, и сформулировать её.</Goal>

Возьмите идею из таблицы раздела 2, свою или свой итоговый проект Essentials. Проверьте её по пяти условиям и
запишите замысел одним предложением: кому, что делает, зачем. Под ним — где будут классы, модули, асинхронная
загрузка и что из трёх на выбор.

<Hint>
Не влезает в две строки — замысел велик. Модули не нужны, нет ни выбора, ни памяти — мал: добавьте фильтр,
избранное, ещё один вид данных.
</Hint>

<Criteria>
- против каждого из пяти условий записано, чем идея ему отвечает;
- в предложении видны три части: кому, что, зачем;
- сосед пересказал ваш замысел своими словами — и не ошибся;
- у каждой обязательной темы курса 2 есть место в проекте, из трёх на выбор названа хотя бы одна.
</Criteria>
</Task>

<Task title="2. Таблица возможностей" level="easy" time="7">
<Goal>записать обещания так, чтобы их можно было проверить.</Goal>

Составьте таблицу «№ — возможность — как проверить — из курса 2», как в разделе 4 лекции, и две строки под
ней: «потом, если останется время» и «не делает совсем».

<Hint>
Хорошая проверка — действие и видимый результат: «выбрали колоду „еда“ — три карточки». Не забудьте загрузку,
ошибку и «пусто».
</Hint>

<Criteria>
- от 6 до 10 строк, у каждой проверка, которую выполнит человек, не видевший код;
- есть строка про ошибку загрузки или пустой результат;
- в «потом» не меньше двух пунктов, в «не делает» — не меньше одного;
- тема курса 2 из задания 1, кроме классов и модулей, нашлась хотя бы в одной строке.
</Criteria>
</Task>

<Task title="3. Проверки данных на примере" level="easy" time="7">
<Goal>научиться ловить ошибки в данных до кода.</Goal>

В папке `day-33/cards` создайте `data`, `test.html` и `tests.js` из
разделов 5–6 лекции, затем копию `data-bad` с тремя ошибками раздела 7. Проверьте её, поменяв строку
`DIR`.

<Hint>
Колода без файла прячет остальные ошибки: `Promise.all` отклоняется раньше проверок.
</Hint>

<Criteria>
- на `data` — одна строка «школа: 3, еда: 3, дом: 2», проверки молчат;
- на `data-bad` с «городом» — одна красная строка с адресом `city.json`;
- без «города» — две строки *Assertion failed*, «без перевода: apple» и «повторы: 3 — lesson и water»;
- для каждой из трёх ошибок записан её симптом в готовом приложении.
</Criteria>
</Task>

## Основные задания

<Task title="4. Свои данные и страница проверок" level="medium" time="12">
<Goal>подготовить данные проекта и проверить их на своей странице.</Goal>

Разложите данные по JSON-файлам в папке `data`: 6–10 объектов, у каждого `id`. Если
данные создаёт человек, сделайте файл образцов или каталога, из которого он выбирает. Напишите
`test.html` и `tests.js`.

<Example>
```js
// tests.js
const { default: items } = await import("./data/items.json", { with: { type: "json" } });
console.log(`объектов: ${items.length}`);
console.assert(items.every((x) => Number.isInteger(x.id) && x.name), "не хватает поля");
console.assert(new Set(items.map((x) => x.id)).size === items.length, "номера повторяются");
console.log([...Map.groupBy(items, (x) => x.category)].map(([category, list]) => `${category}: ${list.length}`).join(", "));
```
</Example>

<Hint>
Каждое поле чем-то пользуется. Категорий не меньше двух, иначе фильтр нечем проверить. Файлов несколько —
номера проверяйте во всех сразу, как `readDecks`.
</Hint>

<Criteria>
- для каждого поля записано, какая возможность им пользуется;
- проверки полей и номеров молчат;
- выведены категории и сколько объектов в каждой — через `Map.groupBy`;
- нарочно испорчен один объект — проверка его поймала, объект исправлен.
</Criteria>
</Task>

<Task title="5. Где что живёт и карта модулей" level="medium" time="12">
<Goal>превратить решения в переменные и модули программы.</Goal>

Составьте таблицу «данные — где — почему», как в разделе 8, и таблицу «модуль — задача — импортирует», как в
разделе 10. Начните `main.js`: импорт данных, переменные с комментариями, ключ хранилища с приставкой
проекта.

<Hint>
`Map`, даты `Temporal` или `Set` в хранилище — это `storage.js` дня
31; для `Set` его дополняют, как в задании 7 дня 31.
</Hint>

<Criteria>
- у каждой строки таблицы «где что живёт» есть причина выбора;
- у каждого модуля одна задача, а стрелки «импортирует» не образуют цикла;
- временная строка проверки шага печатает все переменные при первом открытии — значения «пусто»;
- каждой возможности из задания 2 соответствует переменная или модуль.
</Criteria>
</Task>

<Task title="6. Макет и рама" level="medium" time="13">
<Goal>увидеть страницу до кода и собрать её раму.</Goal>

Нарисуйте макет узким, как экран телефона, и подпишите каждую часть: из каких данных и методов она строится.
По макету напишите `index.html` без данных, а в `main.js` — поиск элементов и
`console.assert` «ни одного `null`».

<Hint>
Места для данных в разметке пустые: `<ul></ul>`, `<p></p>`.
«Загрузка…» видна сразу.
</Hint>

<Criteria>
- у каждой части макета есть подпись; частей без данных нет;
- в подписях названы методы будущих классов — как `due` и `know` у колоды;
- нарочно сделана опечатка в селекторе — красная строка *Assertion failed*, опечатка исправлена;
- фото или рисунок макета лежит в папке проекта.
</Criteria>
</Task>

<Task title="7. Каркас и первый шаг" level="medium" time="13">
<Goal>получить работающую страницу с первыми данными.</Goal>

Напишите модули по своей таблице заглушками, слушатели — с планом внутри. Для одного главного метода сначала
допишите проверки в `tests.js`, потом сам метод. В конце — загрузка со своим классом ошибки и
`render` первых данных.

<Hint>
Заглушка экспортирует то же имя и возвращает тот же тип: `[]`, `0`, `""`.
Проверки подбирайте так, чтобы заглушка их проваливала.
</Hint>

<Criteria>
- страница с каркасом открывается без красных строк в консоли;
- на заглушке — хотя бы две красные строки и «проверки закончены», на настоящем методе — только «проверки закончены»;
- после обновления страница показывает первые данные;
- при переименованном файле данных — понятное сообщение: что не загрузилось и почему.
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. План на дни 34–35" level="hard" time="10">
<Goal>разложить работу по дням и уложить её во время.</Goal>

Запишите план массивом, как в разделе 13: день, задача, минуты, отметка «потом». Посчитайте сумму по каждому
дню через `Map.groupBy` и сумму без задач «потом».

<Example>
```js
const plan = [
  { day: 34, task: "поиск по названию", minutes: 20 },
  { day: 35, task: "сортировка", minutes: 20, later: true },
];
console.log([...Map.groupBy(plan, (t) => t.day)].map(([day, tasks]) => `${day}: ${tasks.reduce((sum, t) => sum + t.minutes, 0)}`).join(", "));
```
</Example>

<Criteria>
- каждая заглушка каркаса стала задачей плана;
- сумма по каждому дню не больше 90 минут;
- у каждой задачи есть проверка — строка таблицы возможностей или проверка на странице проверок;
- объяснено, почему первая задача дня 34 — именно эта.
</Criteria>
</Task>

<Task title="9. Чужой план и чужая карта модулей" level="hard" time="10">
<Goal>читать чужой замысел так, как его прочтут на защите.</Goal>

Обменяйтесь с соседом файлами `plan.md` и проверьте план по чек-листу конспекта. Запишите три
замечания — что непонятно, что нельзя проверить, что не влезет во время — и одно к таблице модулей. Потом
исправьте свой план по замечаниям соседа.

<Hint>
Замечание полезно, когда в нём есть «что» и «почему»: «`app.js` и грузит данные, и рисует — у
модуля две задачи».
</Hint>

<Criteria>
- соседу отдано четыре замечания, у каждого есть «почему»;
- по своим замечаниям план исправлен, и видно, что поменялось;
- у соседа найдена каждая обязательная тема курса 2 или записано, какой не хватает;
- объяснено, почему проверять чужой план проще, чем свой.
</Criteria>
</Task>
