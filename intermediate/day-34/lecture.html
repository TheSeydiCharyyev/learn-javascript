3. Сначала — карточка на экране

В Essentials текущую карточку возвращала функция current в app.js. В курсе 2 её место — в классе: колода знает, какие карточки показать сегодня, а main.js знает только номер места position. Метод получает место и дату и ничего не меняет:

// deck.js: новый метод после due
  // карточка на месте position, по кругу; null — на сегодня карточек нет
  cardAt(position, today) {
    const cards = this.due(today);
    return cards.length === 0 ? null : cards[position % cards.length];
  }

Остаток от деления — тот же, что в Essentials: position растёт без конца, а карточки идут по кругу. null — честный ответ «на сегодня всё». И раз это метод класса, его проверяют на странице проверок, без main.js и без щелчков:

10. Разбор: сброс, который не сбросил

Почему clear(), а не новый пустой Map? Попробуем:

// main.js: так НЕ надо
resetButton.addEventListener("click", () => {
  if (!confirm("Забыть весь прогресс?")) return;
  progress = new Map();
  position = 0;
  flipped = false;
  render();
});

Шаг 1. Симптом. «Знаю», «Начать сначала», OK — на странице «teacher», «На сегодня: 2 из 3», а в консоли Uncaught TypeError: Assignment to constant variable. (день 4 Essentials): progress объявлен через const.

Шаг 2. Заменим const на let. Ошибки нет, но на странице всё те же «teacher» и «2 из 3». А после обновления — снова все три карточки: сброс «сработал», но не сразу. Подсказку даёт хранилище: сразу после сброса localStorage.getItem("cards2:progress") — {"$map":[]}, пусто, а экран по-прежнему считает book отложенной. Хранилище и экран разошлись — значит, у них разные источники.

Шаг 3. Причина. Map один, а держат его несколько: имя progress в main.js и #progress каждой открытой колоды — его передали им в конструкторе.

progress = new Map() перевешивает только имя в main.js. Колоды по-прежнему смотрят на старый Map, и render показывает старый прогресс, а save пишет новый, пустой, — поэтому сброс виден только после обновления. clear() очищает тот самый Map, который видят все. Правило: общий объект меняют, а не подменяют, — и const это правило сторожит. Ошибка шага 1 была подсказкой, а не помехой.

  const deck = opened.get(chosen);
  const word = current();
  card.textContent = word === null ? "На сегодня всё" : (flipped ? word.translation : word.word);

}

// открыть выбранную колоду; с сервера — только в первый раз
async function openDeck() {
  try {
    if (!opened.has(chosen)) opened.set(chosen, await loadDeck(decks.find((d) => d.id === chosen), progress));
  } catch (err) {
    error.textContent = `${err.message}: ${err.cause.message}`;
  }
  loading.hidden = true;
  if (opened.has(chosen)) render();
}

  1. Почему текущую карточку выбирает метод cardAt колоды, а не функция в main.js?
    Ответ Тогда её проверяет страница проверок — без разметки, щелчков и main.js. В main.js остаётся только номер места position.
  2. Почему «Знаю» с state.next.add(…) не откладывает карточку?
    Ответ Даты Temporal не меняются: add возвращает новую дату, а результат никуда не записан. Нужно положить в прогресс новый объект с новой датой.
  3. Почему проверки know пишут String(progress.get(4)?.next)?
    Ответ Пока прогресса нет, ?. даёт undefined, и проверка проваливается, а не падает. Иначе страница проверок остановилась бы на первой строке.
  4. Без % в cardAt страница не падает. Что она показывает и почему?
    Ответ После трёх «Повторить» — «На сегодня всё» при счётчике «3 из 3». cards[3] — undefined, а ?? null в current выдал его за «карточек нет».
  5. Почему сброс через progress = new Map() виден только после обновления?
    Ответ Колоды держат старый Map — его передали им в конструкторе. Присваивание перевешивает одно имя: экран показывает старый прогресс, а save пишет новый, пустой.
  6. Задачи дня заняли на 10 минут больше плана. Что делать?
    Ответ Не ускоряться, а пересчитать следующий день: задача «потом» уходит в запас, и главное помещается. Новые идеи — тоже в «потом».
