День 34. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Разминка — на примере «Карточек 2.0»: скопируйте папку day-33/cards в day-34/cards и доведите её по лекции. Основные задания — в вашем проекте, по вашему плану. После каждой задачи — вкладка проверок, проверка руками и отметка минут в plan.md.

Разминка

1. Текущая карточка и переворот
Легко6 мин

сделать первую задачу плана по шагам лекции.

Добавьте cardAt и его проверки из раздела 3, current, новый render и слушатель переворота из раздела 4.

Слушатель только меняет flipped; что показать — слово или перевод, — решает render.
  • вкладка проверок пишет только «проверки закончены»;
  • щелчок по карточке — «книга», ещё щелчок — «book»;
  • слушатель на время переписан как flipped = true — записано, что сломалось;
  • в плане отмечена задача и настоящие минуты.
2. «Знаю» и «Повторить»
Легко7 мин

отложить карточку по датам и пройти колоду по кругу.

Сначала проверки know из раздела 5, потом сам метод и оба слушателя из разделов 5–6.

Даты Temporal не меняются: результат add нужно куда-то записать.
  • на заглушке know — четыре красные строки, на настоящем методе — ни одной;
  • «Знаю» на book — «teacher» и «На сегодня: 2 из 3»;
  • потом два «Повторить» — снова «teacher»;
  • cardAt на время без % — записано, какая проверка покраснела и что показала страница.
3. Колоды, сохранение, сброс
Легко7 мин

довести пример до конца и пройти таблицу возможностей.

Добавьте кнопки колод, запись в хранилище, окончательный render и «Начать сначала» из разделов 7–9. Пройдите сценарий раздела 12 с чистого прогресса.

  • все строки сценария раздела 12 совпали;
  • на вкладке Network food.json — одна строка после трёх выборов «еды»;
  • после «Знаю» на book в хранилище — строка раздела 8;
  • main.js сверен с разделом 11 — различий нет.

Основные задания

4. Первая задача своего плана
Средне12 мин

начать с того, на что опираются остальные задачи.

Возьмите первую задачу своего дня 34. Если несколько слушателей говорят об одном и том же — текущем вопросе, выбранном товаре, — вынесите это в метод класса, как cardAt, и проверьте его на странице проверок.

Метод, который только отвечает и ничего не меняет, проверяется без страницы. «Ничего нет» пусть будет null.
  • у метода хотя бы три проверки, одна из них — «пусто»;
  • задача проверена так, как записано в плане, — на вкладке и руками;
  • до правки сделана копия папки проекта;
  • в плане отмечены задача и настоящие минуты.
5. Следующие задачи — проверки раньше кода
Средне13 мин

двигаться по плану и не ломать сделанное.

Выполните следующие задачи плана по одной. Для каждого нового метода сначала допишите проверки и убедитесь, что заглушка их проваливает.

Проверка должна проваливаться, а не падать: ?. и String(…) там, где значения ещё нет.
  • у каждой закрытой задачи в плане есть отметка и минуты;
  • для каждого нового метода записано, сколько красных строк было на заглушке;
  • хотя бы раз вкладка поймала поломку, которую не было видно на странице, — или записано, почему таких не было;
  • в слушателях, которые меняют «текущее», сброшены зависимые переменные.
6. Пустое состояние
Средне12 мин

сделать так, чтобы «ничего нет» выглядело как задумано.

Найдите в проекте все места, где что-то может оказаться пустым: пустой список, ничего не найдено, всё сделано. Для каждого — понятный текст, спрятанные бесполезные кнопки и защита в слушателях.

Кнопку прячут, а слушатель всё равно защищают первой строкой. Проверка из консоли — document.querySelector("#…").click().
  • выписаны все пустые состояния проекта и как до каждого дойти;
  • в каждом — понятный текст вместо пустоты;
  • click() по спрятанной кнопке из консоли не даёт красных строк;
  • пустые состояния добавлены в таблицу возможностей.
7. Сохранение и проверка по таблице
Средне13 мин

убедиться, что обещанное работает целиком.

Если в проекте есть что помнить — запись в конце render (с storage.js, если там Map или даты), чтение при объявлении. Потом пройдите таблицу возможностей строка за строкой и отметьте каждую: работает, с оговоркой, не сделано.

Если объект с данными передан в классы, сброс — это clear() или правка на месте, а не новый объект: разбор раздела 10.
  • после обновления страницы сохранённое на месте;
  • сброс — если он есть — виден сразу и не возвращается после обновления;
  • у каждой строки таблицы есть отметка, у «с оговоркой» — сама оговорка;
  • всё «не сделано» перенесено в план дня 35 или в «потом».

Со звёздочкой

8. Три жалобы на «Карточки 2.0»
Сложно10 мин

искать ошибку по симптому.

Одноклассник собрал «Карточки 2.0» и прислал три жалобы: «после трёх „Повторить“ пишет „На сегодня всё“, а счётчик — „3 из 3“»; «нажал „Знаю“ на перевёрнутой карточке — следующая сразу с переводом»; «„Начать сначала“ ничего не сбрасывает, а после обновления — сбрасывает». От программы раздела 11 его код отличается тремя местами, и progress у него объявлен через let:

// в cardAt
return cards.length === 0 ? null : cards[position];
// в слушателе «Знаю» — нет одной строки
opened.get(chosen).know(word.id, today);
render();
// в слушателе «Начать сначала»
progress = new Map();
  • каждая жалоба воспроизведена в копии «Карточек 2.0» и сопоставлена со своим местом;
  • для первой записано, какая проверка на вкладке покраснела, а на странице ничего красного нет;
  • для третьей записано, что лежит в хранилище сразу после «Начать сначала»;
  • все три места исправлены, жалобы не повторяются.
9. План и факт
Сложно10 мин

сравнить прикидку с делом и спокойно пересчитать завтра.

Допишите к задачам своего дня 34 настоящие минуты массивом actual, как в разделе 13, и посчитайте перерасход кодом. Пересчитайте день 35; новые идеи — в «потом», с минутами.

  • для каждой задачи — план и факт, сумма посчитана кодом;
  • для задачи с самым большим перерасходом записано, куда ушло время;
  • день 35 без задач «потом» помещается в 90 минут;
  • объяснено, почему выбросить решили именно эту задачу.
