# День 34. Задания

<Subtitle>Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Разминка — на примере «Карточек 2.0»: скопируйте папку `day-33/cards` в `day-34/cards` и доведите её по лекции. Основные задания — в вашем проекте, по вашему плану. После каждой задачи — вкладка проверок, проверка руками и отметка минут в `plan.md`.</Subtitle>

## Разминка

<Task title="1. Текущая карточка и переворот" level="easy" time="6">
<Goal>сделать первую задачу плана по шагам лекции.</Goal>

Добавьте `cardAt` и его проверки из раздела 3, `current`, новый `render` и
слушатель переворота из раздела 4.

<Hint>
Слушатель только меняет `flipped`; что показать — слово или перевод, — решает `render`.
</Hint>

<Criteria>
- вкладка проверок пишет только «проверки закончены»;
- щелчок по карточке — «книга», ещё щелчок — «book»;
- слушатель на время переписан как `flipped = true` — записано, что сломалось;
- в плане отмечена задача и настоящие минуты.
</Criteria>
</Task>

<Task title="2. «Знаю» и «Повторить»" level="easy" time="7">
<Goal>отложить карточку по датам и пройти колоду по кругу.</Goal>

Сначала проверки `know` из раздела 5, потом сам метод и оба слушателя из разделов 5–6.

<Hint>
Даты `Temporal` не меняются: результат `add` нужно куда-то записать.
</Hint>

<Criteria>
- на заглушке `know` — четыре красные строки, на настоящем методе — ни одной;
- «Знаю» на book — «teacher» и «На сегодня: 2 из 3»;
- потом два «Повторить» — снова «teacher»;
- `cardAt` на время без `%` — записано, какая проверка покраснела и что показала страница.
</Criteria>
</Task>

<Task title="3. Колоды, сохранение, сброс" level="easy" time="7">
<Goal>довести пример до конца и пройти таблицу возможностей.</Goal>

Добавьте кнопки колод, запись в хранилище, окончательный `render` и «Начать сначала» из разделов
7–9. Пройдите сценарий раздела 12 с чистого прогресса.

<Criteria>
- все строки сценария раздела 12 совпали;
- на вкладке Network `food.json` — одна строка после трёх выборов «еды»;
- после «Знаю» на book в хранилище — строка раздела 8;
- `main.js` сверен с разделом 11 — различий нет.
</Criteria>
</Task>

## Основные задания

<Task title="4. Первая задача своего плана" level="medium" time="12">
<Goal>начать с того, на что опираются остальные задачи.</Goal>

Возьмите первую задачу своего дня 34. Если несколько слушателей говорят об одном и том же — текущем вопросе,
выбранном товаре, — вынесите это в метод класса, как `cardAt`, и проверьте его на странице проверок.

<Hint>
Метод, который только отвечает и ничего не меняет, проверяется без страницы. «Ничего нет» пусть будет
`null`.
</Hint>

<Criteria>
- у метода хотя бы три проверки, одна из них — «пусто»;
- задача проверена так, как записано в плане, — на вкладке и руками;
- до правки сделана копия папки проекта;
- в плане отмечены задача и настоящие минуты.
</Criteria>
</Task>

<Task title="5. Следующие задачи — проверки раньше кода" level="medium" time="13">
<Goal>двигаться по плану и не ломать сделанное.</Goal>

Выполните следующие задачи плана по одной. Для каждого нового метода сначала допишите проверки и убедитесь,
что заглушка их проваливает.

<Hint>
Проверка должна проваливаться, а не падать: `?.` и `String(…)` там, где значения ещё
нет.
</Hint>

<Criteria>
- у каждой закрытой задачи в плане есть отметка и минуты;
- для каждого нового метода записано, сколько красных строк было на заглушке;
- хотя бы раз вкладка поймала поломку, которую не было видно на странице, — или записано, почему таких не было;
- в слушателях, которые меняют «текущее», сброшены зависимые переменные.
</Criteria>
</Task>

<Task title="6. Пустое состояние" level="medium" time="12">
<Goal>сделать так, чтобы «ничего нет» выглядело как задумано.</Goal>

Найдите в проекте все места, где что-то может оказаться пустым: пустой список, ничего не найдено, всё
сделано. Для каждого — понятный текст, спрятанные бесполезные кнопки и защита в слушателях.

<Hint>
Кнопку прячут, а слушатель всё равно защищают первой строкой. Проверка из консоли —
`document.querySelector("#…").click()`.
</Hint>

<Criteria>
- выписаны все пустые состояния проекта и как до каждого дойти;
- в каждом — понятный текст вместо пустоты;
- `click()` по спрятанной кнопке из консоли не даёт красных строк;
- пустые состояния добавлены в таблицу возможностей.
</Criteria>
</Task>

<Task title="7. Сохранение и проверка по таблице" level="medium" time="13">
<Goal>убедиться, что обещанное работает целиком.</Goal>

Если в проекте есть что помнить — запись в конце `render` (с `storage.js`, если там
`Map` или даты), чтение при объявлении. Потом пройдите таблицу возможностей строка за строкой и
отметьте каждую: работает, с оговоркой, не сделано.

<Hint>
Если объект с данными передан в классы, сброс — это `clear()` или правка на месте, а не новый
объект: разбор раздела 10.
</Hint>

<Criteria>
- после обновления страницы сохранённое на месте;
- сброс — если он есть — виден сразу и не возвращается после обновления;
- у каждой строки таблицы есть отметка, у «с оговоркой» — сама оговорка;
- всё «не сделано» перенесено в план дня 35 или в «потом».
</Criteria>
</Task>

## Со звёздочкой

<Task title="8. Три жалобы на «Карточки 2.0»" level="hard" time="10">
<Goal>искать ошибку по симптому.</Goal>

Одноклассник собрал «Карточки 2.0» и прислал три жалобы: «после трёх „Повторить“ пишет „На сегодня всё“, а
счётчик — „3 из 3“»; «нажал „Знаю“ на перевёрнутой карточке — следующая сразу с переводом»; «„Начать
сначала“ ничего не сбрасывает, а после обновления — сбрасывает». От программы раздела 11 его код отличается
тремя местами, и `progress` у него объявлен через `let`:

<Example>
```js
// в cardAt
return cards.length === 0 ? null : cards[position];
// в слушателе «Знаю» — нет одной строки
opened.get(chosen).know(word.id, today);
render();
// в слушателе «Начать сначала»
progress = new Map();
```
</Example>

<Criteria>
- каждая жалоба воспроизведена в копии «Карточек 2.0» и сопоставлена со своим местом;
- для первой записано, какая проверка на вкладке покраснела, а на странице ничего красного нет;
- для третьей записано, что лежит в хранилище сразу после «Начать сначала»;
- все три места исправлены, жалобы не повторяются.
</Criteria>
</Task>

<Task title="9. План и факт" level="hard" time="10">
<Goal>сравнить прикидку с делом и спокойно пересчитать завтра.</Goal>

перерасход кодом. Пересчитайте день 35; новые идеи — в «потом», с минутами.

<Criteria>
- для каждой задачи — план и факт, сумма посчитана кодом;
- для задачи с самым большим перерасходом записано, куда ушло время;
- день 35 без задач «потом» помещается в 90 минут;
- объяснено, почему выбросить решили именно эту задачу.
</Criteria>
</Task>
