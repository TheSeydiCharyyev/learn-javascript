**Шаг 2. Найти место — и не поверить ему сразу.** Стек начинается с `deck.js:23` —
`this.#progress.get(card.id)` в `due`, ниже `Deck.due`, `Deck.cardAt`,

`main.js`, строка 8 — `const progress = load(…) ?? new Map()`.

**Шаг 3. Проверить догадку.** `load("{}")` вернул объект, а не `null`, — и
`?? new Map()` промолчал. С `"5"` и `"[]"` — то же. С `"сломано"`
`JSON.parse` бросает ошибку в самой строке 8 (стек: `JSON.parse` → `load` в
`storage.js:11` → `main.js:8`), и модуль останавливается, не дойдя до кнопок колод.

**Шаг 4. Исправить на входе.** Чтение — в функцию, которая всегда возвращает `Map`, как
`readLearned` Essentials — массив. Но `Map` может быть настоящим, а запись в нём — нет: с
`{"$map":[[1,{"next":5,"step":2}]]}` `due` падает на `Temporal.PlainDate.compare` —
`Temporal error: Date argument must be object or string.` Поэтому проверяем и записи:

```js
// main.js, перед «const today»
// прогресс из хранилища: всегда Map с датой и шагом в каждой записи; испорченное — с нуля
function readProgress() {
  try {
    const saved = load(localStorage.getItem(KEY));
    if (!(saved instanceof Map)) return new Map();
    return new Map([...saved].filter(([, state]) => state?.next instanceof Temporal.PlainDate && Number.isInteger(state.step)));
  } catch {
    return new Map();
  }
}
```

```js
// main.js: замена строки
const progress = readProgress();                                 // номер карточки → { next, step }, на все колоды
```

Испорченная строка или плохая дата — `catch` вернёт пустой `Map`. Не `Map`
(`{}`, `5`, `[]`) — `instanceof` (день 7) скажет `false`.
Ключа нет — `load(null)` даёт `null`, тоже не `Map`, и `?? new Map()`
больше не нужен. Негодную запись отбросит `filter` по парам `[...saved]` (день 14), а
`?.` спасёт от `null` на месте записи.

## 7. Читаем чужой код {#review}

Три прохода — из Essentials: запустить, карта, одно действие. Курс 2 добавляет к ним страницы проверок, его и
вашу. У соседа тоже «Карточки 2.0»: всё как у нас на дне 34, кроме `deck.js` и `catch` в
`load.js`:

```js
// deck.js соседа
export class Deck {
  constructor(cards, progress) {
    this.cards = cards;
    this.progress = progress;
  }

  get size() {
    return this.cards.length;
  }

  due(today) {
    return this.cards.filter((c) => !this.progress.has(c.id) || this.progress.get(c.id).next <= today);
  }

  cardAt(position, today) {
    const cards = this.due(today);
    return cards.length === 0 ? null : cards[position % cards.length];
  }

  know(id, today) {
    const step = this.progress.get(id)?.step ?? 1;
    this.progress.set(id, { next: today.add({ days: step * 2 }), step });
  }
}
```

```js
// load.js соседа: catch
  } catch {
    return new Deck([], progress);
  }
```

## 10. Разбор: поиск на Promise.all {#bug-all}

Первая версия `openAll` часто короче:

```js
// main.js: так НЕ надо
async function openAll() {
  const closed = decks.filter((d) => !opened.has(d.id));
  const loaded = await Promise.all(closed.map((d) => loadDeck(d, progress)));
  loaded.forEach((deck, i) => opened.set(closed[i].id, deck));
}
```

**Шаг 1. Симптом.** Пока файлы на месте, разницы нет. Переименуем `food.json` и наберём
«w»: список пуст, хотя window лежит в «доме», а в консоли — `Uncaught (in promise) CardsError: Не удалось
загрузить колоду «еда»`. Набираем дальше — снова пусто и снова красная строка.

**Шаг 2. Причина.** `Promise.all` отклоняется на первом отказе (день 27, разбор
`data-bad` дня 33): «дом» загрузился, но до `forEach` дело не дошло. «in promise» — ошибка
вылетела из `async`-слушателя, и поймать её некому.

<Scheme src="scheme-bug-all.svg">Одни и те же две загрузки: all теряет и удачную, allSettled оставляет её</Scheme>

**Шаг 3.** С `allSettled` отказ «еды» — строчка в отчёте: «w» находит window, а water —
нет, её колода не открылась. Правило дня 27: независимые задачи ждут
через `allSettled`, если неудача одной не должна отменять остальные.

<Selfcheck>
1. На телефоне длинный перевод вылез за рамку, а `document.documentElement.scrollWidth ===
   innerWidth` — `true`. Почему?
   <Answer>`innerWidth` на телефоне растёт вместе со страницей: оба числа 376. Сравнивать нужно с
   шириной экрана, `screen.width`.</Answer>
2. На компьютере проект работает, а на телефоне «Загрузка…» висит. Что подозревать первым?
   <Answer>Браузер телефона не знает новинки, например `Temporal`, и `main.js` падает на
   первой строке с ней. Обновить браузер.</Answer>
3. В хранилище `"{}"`. Почему ошибка вылетает в `deck.js`, хотя виноват
   `main.js`?
   <Answer>`load("{}")` вернул объект, и `?? new Map()` не сработал. Упало там, где
   объектом воспользовались. Стек читают до конца и спрашивают, откуда пришли данные.</Answer>
4. Зачем `readProgress` проверяет ещё и записи `Map`?
   <Answer>`Map` с записью `{"next":5}` проходит проверку на `Map`, а
   `due` падает. Негодные записи отбрасываются, годные остаются.</Answer>
5. Файл колоды вернули на место. Откроется ли колода без обновления страницы?
   <Answer>В Chrome 156 — да, по второму щелчку: `import()` снова спрашивает сервер. Chrome 155
   запоминал отказ до обновления: справочник обещает только «может загрузить снова».</Answer>
6. Почему `openAll` — на `allSettled`, а не на `all`?
   <Answer>`all` отклоняется на первом отказе, и в `opened` не попадёт ни одна колода.
   `allSettled` отдаёт отчёт о каждой.</Answer>
</Selfcheck>
