Хронометр на асинхронном генераторе

В Essentials хронометр ставил шесть setTimeout разом. В курсе 2 это одна функция, которая отдаёт части по очереди и между ними ждёт, — асинхронный генератор дня 29:

// в консоли
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// части защиты по очереди: сообщение о начале части, потом её минуты
async function* chronometer(parts, msPerMinute = 60000) {
  let at = 0;
  for (const p of parts) {
    yield `${at} мин: ${p.part}`;
    await wait(p.minutes * msPerMinute);
    at += p.minutes;
  }
  yield `${at} мин: время вышло`;
}

На защите — for await (const line of chronometer(defense)) console.log(line);. Второй аргумент — сколько миллисекунд в минуте: с 1000 вся защита проходит за семь секунд, это репетиция:

// в консоли
for await (const line of chronometer(defense, 1000)) console.log(line);

2.5 мин: курс 2 в коде
3.5 мин: одно решение

Ожидания идут одно за другим, и опоздания таймеров складываются (день 29): на семи секундах репетиции — несколько сотых. Консоль, как и модуль (день 30), разрешает for await на верхнем уровне.

4. Одно решение

Минута на одно место в коде, которым вы довольны: что решали, как сделали, что было бы иначе, чем проверили. Пример — сброс прогресса. Прогресс один на все колоды, и колоды держат его с конструктора. Поэтому «Начать сначала» очищает тот же Map, а не создаёт новый:

// так НЕ надо — «Начать сначала» с новым Map (и let progress)
progress = new Map();

«Что было бы иначе» сильнее всего, если его показать, — разбор 10 дня 34. «Знаю», «Начать сначала», OK — на экране по-прежнему teacher и «На сегодня: 2 из 3», а в хранилище уже {"$map":[]}. Колоды смотрят на старый Map, save пишет новый. Вот как это звучит за минуту:

«Прогресс один на все колоды, и колоды получают его в конструкторе. Поэтому сброс — clear(): новый Map перевесил бы одно имя, и экран разошёлся бы с хранилищем — я проверял. const не даёт так ошибиться».

Второй пример: колоды — из данных

Кнопки колод строятся из decks.json (день 34). «Что было бы иначе» здесь показывают наоборот — добавляют колоду. Строка { "id": "city", "name": "город" } в decks.json и файл data/city.json с карточкой { "id": 9, "word": "street", "translation": "улица" } — после обновления есть кнопка «город», в ней street, «На сегодня: 1 из 1», вкладка проверок молчит. Ни разметку, ни код не трогали. Кнопки, написанные в разметке, этого бы не умели.

5. Одна ошибка

Ещё минута — история одной ошибки, той, что научила. Пять шагов, как в Essentials:

Шаг«Карточки 2.0», день 35

2. как нашлистек до конца: #progress колоде дал main.js, строка 8
3. причинав хранилище "{}", load вернул объект, и ?? new Map() промолчал
4. исправлениеreadProgress: всегда Map, записи проверены

Шаг 5 в курсе 2 — проверки на вкладке. Но readProgress живёт в main.js, а его вкладка импортировать не может: он запускает всё приложение. Поэтому функцию переносят в модуль без страницы — storage.js — и отдают ей строку, а не ключ:

// storage.js, продолжение
// прогресс из строки хранилища: всегда Map с датой и шагом в каждой записи; испорченное — с нуля
export function readProgress(text) {
  try {
    const saved = load(text);
    if (!(saved instanceof Map)) return new Map();
    return new Map([...saved].filter(([, state]) => state?.next instanceof Temporal.PlainDate && Number.isInteger(state.step)));
  } catch {
    return new Map();
  }
}
// main.js: от «const KEY» до «const progress»
const KEY = "cards2:progress";
const today = Temporal.PlainDate.from("2026-10-26");            // учебное «сегодня»; в жизни — Temporal.Now.plainDateISO()
const progress = readProgress(localStorage.getItem(KEY));       // номер карточки → { next, step }, на все колоды
// main.js: импорты
import decks from "./data/decks.json" with { type: "json" };
import { save, readProgress } from "./storage.js";
import { loadDeck } from "./load.js";
import { matcher } from "./search.js";
// tests.js, после «import { matcher }»
import { readProgress } from "./storage.js";
// tests.js, перед «проверки закончены»
console.assert(readProgress("сломано").size === 0, "испорченная строка — пустой Map");
console.assert(readProgress("{}").size === 0, "не Map — пустой Map");
console.assert(readProgress('{"$map":[[1,{"next":5,"step":2}]]}').size === 0, "запись без даты отброшена");
console.assert(readProgress('{"$map":[[1,{"next":{"$date":"2026-10-28"},"step":2}]]}').get(1)?.step === 2, "годная запись осталась");
проверки закончены

Проверки не трогают хранилище: функция берёт строку. Сравните с testInput Essentials, который сохранял ключ и возвращал его на место. Вернём на время старое поведение — вкладка кричит:

// storage.js: так НЕ надо
export function readProgress(text) {
  return load(text) ?? new Map();
}
Uncaught SyntaxError: Unexpected token 'с', "сломано" is not valid JSON

Вкладка остановилась на первой проверке, и «проверки закончены» нет. Кто однажды вернёт старую строку, узнает об этом раньше человека с телефоном.

показтелефон в руке. «Колода „школа“, book. Тап — книга. „Знаю“ — book ушла до 28 октября, на сегодня 2 из 3. Колода „еда“ — bread. Ищу „w“ — water и window, с колодами. Обновляю — прогресс на месте»

вопросына «что будет, если…» — вкладка проверок или консоль; на незнакомое — «не проверял, запишу в „потом“»

Чего здесь нет: пересказа кода строка за строкой, «я не успел» в начале, «ну вот как-то так». Свою защиту напишите так же — таблицей из шести строк — и прочитайте вслух под хронометр. Если выходит больше семи минут, режут показ, а не вопросы.

7. Вопросы проверяющего

Три вида вопросов и три хода — как в Essentials. Новое одно: на «что будет, если» в курсе 2 часто отвечает вкладка проверок, а не консоль.

«В каком файле сохраняется прогресс?»

Ответ — два файла, и граф модулей дня 33 подсказывает, какие. main.js читает один раз и пишет в конце render, storage.js превращает Map и даты в строку и обратно:

// main.js, две строки прогресса
const progress = readProgress(localStorage.getItem(KEY));
localStorage.setItem(KEY, save(progress));

«А карточка точно вернётся через два дня?»

Не ждать двух дней и не спорить — показать проверку, которая стоит на вкладке с дня 33:

// tests.js, проверка дня 33
console.assert(new Deck(school, later).due(today.add({ days: 2 })).length === 3, "28 октября book вернулась");

Вкладка молчит — значит, вернётся. Хотите увидеть на странице — учебное «сегодня» на "2026-10-28", как в разделе 8 дня 34.

«Что будет, если в двух колодах один номер?»

Поставим на время в food.json номер 3 у water — как в data-bad дня 33. Вкладка проверок отвечает сразу:

Assertion failed: номера повторяются
проверки закончены

А на странице: в «школе» «Повторить» два раза, «Знаю» у lesson — и в «еде» «На сегодня: 2 из 3», water пропала. Прогресс знает только номер. Ответ: «Номер — имя карточки на все колоды. Повтор ловит вкладка, а сторож одной колоды его не видит — колоды грузятся порознь».

«Почему карточка — класс, а не объект из JSON?»

Консоль не видит переменных модуля, зато может сама импортировать модуль — тот же, что у страницы: второго запроса за card.js нет (день 31). Значит, класс можно спросить напрямую:

// в консоли страницы
const { Card } = await import("./card.js");
try { new Card({ id: "6", word: "apple", translation: "яблоко" }); } catch (err) { console.log(err.name, err.message); }
CardsError у карточки «apple» нет номера

Ответ: «Объект из JSON принял бы что угодно. Конструктор — сторож: карточка с неверными данными просто не создаётся (день 33). А приватные поля и геттеры (день 9) не дают поправить её потом, в обход сторожа».

«Паузы растут без конца?»

Вопрос с подвохом: шаг удваивается — а потолок есть? Тем же приёмом: своя колода из одной карточки, свой прогресс и десять «Знаю», каждое в свой день повтора:

Шаг 1024, следующий повтор — летом 2032 года: потолка нет. Честный ответ: «Не предусмотрено — записал в „потом“ потолок паузы». Опыт не тронул страницу: progress здесь — переменная консоли, а не прогресс приложения, и хранилище осталось прежним.

«А если быстро нажать „Знаю“ десять раз?»

Консоль может то, что не успеет палец. Только knowButton.click() здесь не сработает — Uncaught ReferenceError: knowButton is not defined: переменная модуля консоли не видна. Кнопку берут из разметки:

Три щелчка отложили три карточки, остальные семь упёрлись в if (word === null) return; — красных строк нет. Опыт оставил следы в хранилище: после него — «Начать сначала».

«Почему колоды не грузятся все сразу?»

Показать вкладку Network: при открытии запрошен только school.json, food.json — когда выбрали «еду» или впервые что-то искали. Ответ: «Грузим то, что выбрали. Поиску нужны все — он и открывает их, один раз и через allSettled».

На одной защите вы проверяющий у соседа, чей проект читали на дне 35. Хороший вопрос конкретный, на него отвечают кодом или проверкой, и он о проекте, а не о человеке:

Отзыв после защиты — из двух частей: одна сильная сторона с местом в коде и одно предложение — с проверкой для его вкладки. Например: «Хорошо, что readProgress проверяется на вкладке.   1. Сколько частей в защите курса 2 и какая из них новая?
    Ответ Шесть: фраза, показ, курс 2 в коде, решение, ошибка, вопросы. Новая — «курс 2 в коде»: где в проекте классы, модули, загрузка и другие темы курса.
  2. Чем хронометр на асинхронном генераторе удобнее шести setTimeout?
    Ответ Он отдаёт части по очереди и ждёт между ними, а второй аргумент ускоряет его: с 1000 миллисекунд в минуте репетиция проходит за семь секунд.
  3. Перед показом удалили ключ хранилища, а прогресс вернулся. Почему?
    Ответ progress остался в памяти модуля, и первый же render записал его обратно. Удалить ключ и сразу обновить страницу — или «Начать сначала».
  4. Зачем readProgress перенесли из main.js в storage.js?
    Ответ Чтобы её видела страница проверок: main.js она импортировать не может, он запускает всё приложение. А раз функция берёт строку, проверки не трогают хранилище.
  5. knowButton.click() в консоли даёт ReferenceError. Почему и как нажать кнопку?
    Ответ knowButton — переменная модуля, консоль её не видит. Кнопку берут из разметки: document.querySelector("#know").click().
  6. Что будет, если в двух колодах окажется один номер, и кто это поймает?
    Ответ «Знаю» у одной карточки отложит и другую: прогресс знает только номер. Сторож колоды повтор между файлами не видит — ловит страница проверок: «номера повторяются».
