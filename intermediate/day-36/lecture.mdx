### Хронометр на асинхронном генераторе

В Essentials хронометр ставил шесть `setTimeout` разом. В курсе 2 это одна функция, которая отдаёт части
по очереди и между ними ждёт, — асинхронный генератор дня 29:

```js
// в консоли
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// части защиты по очереди: сообщение о начале части, потом её минуты
async function* chronometer(parts, msPerMinute = 60000) {
  let at = 0;
  for (const p of parts) {
    yield `${at} мин: ${p.part}`;
    await wait(p.minutes * msPerMinute);
    at += p.minutes;
  }
  yield `${at} мин: время вышло`;
}
```

На защите — `for await (const line of chronometer(defense)) console.log(line);`. Второй аргумент —
сколько миллисекунд в минуте: с 1000 вся защита проходит за семь секунд, это репетиция:

```js
// в консоли
for await (const line of chronometer(defense, 1000)) console.log(line);
```

0.5 мин: показ по сценарию\
2.5 мин: курс 2 в коде\
3.5 мин: одно решение\
4.5 мин: одна ошибка\
5.5 мин: вопросы\
7 мин: время вышло
</ResultBox>

Ожидания идут одно за другим, и опоздания таймеров складываются (день 29): на семи секундах репетиции — доли
секунды. Консоль, как и модуль (день 30), разрешает `for await` на верхнем уровне.

## 4. Одно решение {#decision}

Минута на одно место в коде, которым вы довольны: что решали, как сделали, что было бы иначе, чем проверили.
Пример — сброс прогресса. Прогресс один на все колоды, и колоды держат его с конструктора. Поэтому «Начать сначала»
очищает тот же `Map`, а не создаёт новый:

```js
// так НЕ надо — «Начать сначала» с новым Map (и let progress)
progress = new Map();
```

«Что было бы иначе» сильнее всего, если его показать, — разбор 10 дня 34. «Знаю», «Начать сначала», OK — на
экране по-прежнему teacher и «На сегодня: 2 из 3», а в хранилище уже `{"$map":[]}`. Колоды смотрят на
старый `Map`, `save` пишет новый. Вот как это звучит за минуту:

<KeyPoint>
«Прогресс один на все колоды, и колоды получают его в конструкторе. Поэтому сброс — `clear()`: новый
`Map` перевесил бы одно имя, и экран разошёлся бы с хранилищем — я проверял. `const` не даёт
так ошибиться».
</KeyPoint>

### Второй пример: колоды — из данных

Кнопки колод строятся из `decks.json` (день 34). «Что было бы иначе» здесь показывают наоборот —
добавляют колоду. Строка `{ "id": "city", "name": "город" }` в `decks.json` и файл
`data/city.json` с карточкой `{ "id": 9, "word": "street", "translation": "улица" }` — после
обновления есть кнопка «город», в ней street, «На сегодня: 1 из 1», вкладка проверок молчит. Ни разметку, ни код не
трогали. Кнопки, написанные в разметке, этого бы не умели.

Другие решения курса 2, о которых стоит рассказать, если они есть в вашем проекте:

| Решение | Что было бы иначе | Где разбирали |
| --- | --- | --- |
| логика — в методах класса (`cardAt`, `know`) | проверять пришлось бы щелчками по странице | день 34 |
| колода грузится при выборе | страница ждёт все файлы сразу | день 33 |
| данные проверяются на входе | проверки в каждом методе | день 35 |
| поиск открывает колоды через `allSettled` | одна сломанная колода — пустой поиск | день 35 |

## 5. Одна ошибка {#bug}

Ещё минута — история одной ошибки, той, что научила. Пять шагов, как в Essentials:

| Шаг | «Карточки 2.0», день 35 |
| --- | --- |
| 1. симптом | после обновления пустая карточка, красная строка в `deck.js` |
| 2. как нашли | стек до конца: `#progress` колоде дал `main.js`, строка 8 |
| 3. причина | в хранилище `"{}"`, `load` вернул объект, и `?? new Map()` промолчал |
| 4. исправление | `readProgress`: всегда `Map`, записи проверены |
| 5. как проверили, что не вернётся | проверки на вкладке |

Шаг 5 в курсе 2 — проверки на вкладке. Но `readProgress` живёт в `main.js`, а его вкладка
импортировать не может: он запускает всё приложение. Поэтому функцию переносят в модуль без страницы —
`storage.js` — и отдают ей строку, а не ключ:

```js
// storage.js, продолжение
// прогресс из строки хранилища: всегда Map с датой и шагом в каждой записи; испорченное — с нуля
export function readProgress(text) {
  try {
    const saved = load(text);
    if (!(saved instanceof Map)) return new Map();
    return new Map([...saved].filter(([, state]) => state?.next instanceof Temporal.PlainDate && Number.isInteger(state.step)));
  } catch {
    return new Map();
  }
}
```

```js
// main.js: от «const KEY» до «const progress»
const KEY = "cards2:progress";
const today = Temporal.PlainDate.from("2026-10-26");            // учебное «сегодня»; в жизни — Temporal.Now.plainDateISO()
const progress = readProgress(localStorage.getItem(KEY));       // номер карточки → { next, step }, на все колоды
```

```js
// main.js: импорты
import decks from "./data/decks.json" with { type: "json" };
import { save, readProgress } from "./storage.js";
import { loadDeck } from "./load.js";
import { matcher } from "./search.js";
```

```js
// tests.js, после «import { matcher }»

```

```js page="test.html"
// tests.js, перед «проверки закончены»
console.assert(readProgress("сломано").size === 0, "испорченная строка — пустой Map");
```

этом раньше человека с телефоном.

## 7. Вопросы проверяющего {#questions}

Три вида вопросов и три хода — как в Essentials. Новое одно: на «что будет, если» в курсе 2 часто отвечает вкладка
проверок, а не консоль.

### «В каком файле сохраняется прогресс?»

Ответ — два файла, и граф модулей дня 33 подсказывает, какие. `main.js` читает один раз и пишет в
конце `render`, `storage.js` превращает `Map` и даты в строку и обратно:

```js
// main.js, две строки прогресса
const progress = readProgress(localStorage.getItem(KEY));
localStorage.setItem(KEY, save(progress));
```

### «А карточка точно вернётся через два дня?»

Не ждать двух дней и не спорить — показать проверку, которая стоит на вкладке с дня 33:

```js
// tests.js, проверка дня 33
console.assert(new Deck(school, later).due(today.add({ days: 2 })).length === 3, "28 октября book вернулась");
```

Вкладка молчит — значит, вернётся. Хотите увидеть на странице — учебное «сегодня» на `"2026-10-28"`,
как в разделе 8 дня 34.

### «Что будет, если в двух колодах один номер?»

Поставим на время в `food.json` номер 3 у water — как в `data-bad` дня 33. Вкладка проверок
отвечает сразу:

```plain-out
Assertion failed: номера повторяются
проверки закончены
```

А на странице: в «школе» «Повторить» два раза, «Знаю» у lesson — и в «еде» «На сегодня: 2 из 3», water пропала.
Прогресс знает только номер. Ответ: «Номер — имя карточки на все колоды. Повтор ловит вкладка, а сторож одной колоды
его не видит — колоды грузятся порознь».

### «Почему карточка — класс, а не объект из JSON?»

Консоль не видит переменных модуля, зато может сама импортировать модуль — тот же, что у страницы: второго
запроса за `card.js` нет (день 31). Значит, класс можно спросить напрямую:

```js
// в консоли страницы
const { Card } = await import("./card.js");
try { new Card({ id: "6", word: "apple", translation: "яблоко" }); } catch (err) { console.log(err.name, err.message); }
```

<ResultBox>
CardsError у карточки «apple» нет номера
</ResultBox>

Ответ: «Объект из JSON принял бы что угодно. Конструктор — сторож: карточка с неверными данными просто не
создаётся (день 33). А приватные поля и геттеры (день 9) не дают поправить её потом, в обход сторожа».

### «Паузы растут без конца?»

Вопрос с подвохом: шаг удваивается — а потолок есть? Тем же приёмом: своя колода из одной карточки, свой
прогресс и десять «Знаю», каждое в свой день повтора:

```js
// в консоли страницы
const { Deck } = await import("./deck.js");
const progress = new Map();
const deck = new Deck([new Card({ id: 1, word: "book", translation: "книга" })], progress);
let day = Temporal.PlainDate.from("2026-10-26");
for (let i = 0; i < 10; i++) {
  deck.know(1, day);
  day = progress.get(1).next;
}
console.log(progress.get(1).step, String(day));
```

потолок паузы». Опыт не тронул страницу: `progress` здесь — переменная консоли, а не прогресс приложения,
и хранилище осталось прежним.
